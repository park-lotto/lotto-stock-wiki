# 해외HOT — 자막 없는 썸네일 우선 (설계)

- 날짜: 2026-07-29 / 트랙: 해외HOT
- 한 줄: **썸네일에 자막이 없는 영상을 목록 맨 위로 올린다.** 자막이 많으면 내용도 지저분하다는
  사장님 관측에서 출발.

## 1. 문제

지금 해외HOT 목록엔 소재로 쓸 수 없는 영상이 섞여 올라온다. 사장님이 지목한 유형은 두 가지 —
**주제 무관**, **사람 얼굴·토크**. 그리고 이 둘을 눈으로 가려내는 가장 빠른 신호가
**썸네일에 자막이 얼마나 박혀 있느냐**다.

원인은 두 겹이다.

**(a) 판정은 하는데 안 쓴다.** `video_analysis.text_level_vision`은 이미 썸네일을
`none`(글자 거의 없음) / `light`(작은 워터마크) / `heavy`(큰 자막이 화면 가림) 3단계로 판정한다.
그런데 `overseas_funnel.passes_caption_clutter`는 **`heavy`만 잘라낼 뿐** `none`을 우대하지 않는다.
정렬은 여전히 참여지표(`score`)순이다. 그래서 "자막 없는 게 먼저"가 성립하지 않는다.

**(b) 판정 커버리지가 낮고, 대상 선정도 틀렸다.**

```python
_TEXT_CLUTTER_CAP = 15
kept = _annotate_text_level(kept, _TEXT_CLUTTER_CAP)
```

`_annotate_text_level`은 리스트 앞에서부터 `cap`개만 본다. 주석엔 "생존자 상위만"이라 적혀 있으나
이 시점의 `kept`는 **아직 `build_overseas_items`/`apply_grades`를 거치기 전이라 `score`가 없다**.
즉 실제로는 점수 상위가 아니라 **수집된 순서대로 앞 15개**다. 나머지는 판정 없이 통과하므로
자막 여부를 알 수 없고, 알 수 없는 것은 줄 세울 수도 없다.

여기에 어제(2026-07-28) 샤오홍슈 검색 정렬을 **인기순 → 최신순**으로 바꾼 변경이 겹친다.
인기순일 때는 좋아요가 암묵적 품질 필터 노릇을 했는데, 최신순에는 그게 없다. 체감상
"이상한 게 늘었다"는 시점과 맞아떨어진다.

## 2. 목표 / 비목표

**목표**
- 자막 없는 썸네일(`none`)이 목록 위로 오고, `light`는 뒤로 간다.
- 목록에 뜬 항목은 **판정이 끝난 상태**여야 한다(모름 상태로 섞이지 않는다).
- 비전 호출이 매 수집마다 처음부터 다시 들지 않는다.

**비목표**
- 주제 적합성(제품이냐 아니냐)의 의미 판정 — 이번엔 안 한다. 2026-07-26에 허용어 매칭으로
  정상 꿀템 74%를 날린 전례가 있어, 텍스트 기반 주제 필터는 다시 손대지 않는다.
- 인스타 랭킹의 CN 원본 찾기(2부) — **실측 결과 구글 렌즈로는 불가**하므로 이 설계에서 제외한다.
  (2026-07-29 실측: 제품형 인스타 영상 5건 → 렌즈 4건 성공, 샤오홍슈·도우인 결과 **0건**.
  구글이 CN 플랫폼을 인덱싱하지 않는다. `handoff/렌즈유사영상.md`의 기존 실측과 일치.)

## 3. 사장님 결정사항 (2026-07-29)

| 질문 | 결정 |
|---|---|
| 판정 범위 | **생존자 전부 판정** (앞 15개 제한 폐기) |
| `light` 처리 | **뒤로 밀기** (컷 아님) |
| `heavy` 처리 | 지금처럼 컷 유지 |

## 4. 설계

파이프라인의 모양은 그대로 두고 **판정 범위**와 **정렬 키**만 바꾼다.

```
수집(샤오홍슈)
  → 형식·숏폼·차단어·조회수상한 컷            (변경 없음)
  → 썸네일 자막 판정                          ← 앞 15개  ⇒  생존자 전부 + 캐시
  → heavy 컷                                  (변경 없음)
  → build_overseas_items / apply_grades       (변경 없음)
  → 정렬: 자막등급 → score                    ← 신규
```

### 4.1 캐시 (`store.py`)

비전 호출은 Gemini 쿼터를 쓴다. 이 프로젝트엔 **쿼터 소진으로 검열 성공률이 29%까지 떨어진
전례**(`gemini_audit.py` 주석: 497→33건)가 있어, 커버리지를 올리면서 캐시를 같이 넣는다.

```sql
CREATE TABLE IF NOT EXISTS thumb_text_level (
    shortcode  TEXT PRIMARY KEY,
    level      TEXT,          -- 'none' | 'light' | 'heavy'
    created_at TEXT
)
```

- `get_thumb_text_level(shortcode) -> str | None` — 미조회는 `None`.
- `save_thumb_text_level(shortcode, level)`.
- 실패는 저장하지 않는다(다음 수집에서 재시도되게). 성공만 캐시한다.

해외HOT 피드는 `_merge_rotate`로 최대 120건을 유지하며 겹치는 항목을 재사용하므로, 캐시가 있으면
**매 수집에서 새로 들어온 항목만** 판정하면 된다. 첫 1회만 비싸고 이후는 증분이다.

### 4.2 판정 (`overseas_hot_jobs.py`)

`_annotate_text_level(items, cap)` → `_annotate_text_level(items, store)`:

- `cap` 인자 제거. 생존자 전부를 돈다.
- 각 항목마다 먼저 캐시 조회 → 있으면 그 값 사용(비전 호출 없음).
- 없으면 `fetch_thumb_bytes` → `text_level_vision` → 성공 시 캐시에 저장.
- 판정 실패·썸네일 없음은 `text_level`을 안 붙인다(기존 과필터 방지 철학 유지).

`_TEXT_CLUTTER_CAP` 상수는 삭제한다.

### 4.3 정렬 (`overseas_funnel.py` + `overseas_hot_jobs.py`)

`overseas_funnel`에 순수함수를 하나 더한다:

```python
CAPTION_RANK = {"none": 0, "light": 1}

def caption_rank(item):
    """자막 적을수록 앞. 판정 없는 항목(실패·썸네일없음)은 light와 heavy 사이."""
    return CAPTION_RANK.get(item.get("text_level"), 2)
```

`ranking.sort_by`는 유튜브·인스타 랭킹도 함께 쓰는 공용 함수라 **건드리지 않는다.**
대신 해외HOT 경로에서만 정렬한다 — `_merge_rotate`의 정렬 키를 바꾼다:

```python
sorted(out, key=lambda i: (overseas_funnel.caption_rank(i), -(i.get("score") or 0)))[:cap]
```

즉 **1차 자막등급 오름차순, 2차 score 내림차순**. 로테이션 상한(`_CAP=120`)을 자를 때도 같은
기준이 적용되므로, 자막 없는 항목이 우선 살아남는다.

### 4.4 화면

프론트는 이미 서버가 준 순서대로 그린다(`/api/overseas/feed`는 저장된 배열을 그대로 반환).
따라서 **정렬만 바꾸면 화면은 자동으로 따라온다.** 이번 페이즈에서 `static/index.html`은
건드리지 않는다.

## 5. 비용

- **첫 수집 1회**: 생존자 전부 판정. 카테고리 6 × 키워드당 최대 40건이므로 상한은 수백 건.
  Gemini Flash 비전 1건은 저렴하지만 건수가 늘어난다.
- **이후**: 캐시 적중분은 0원. 새로 들어온 항목만.
- **관측**: 판정 건수/캐시적중을 잡 로그에 남겨(`_JOB["phase"]`) 실제 증가폭을 사후 확인한다.
  예상보다 크면 상한을 다시 도입한다(그때는 `score` 계산 뒤에 걸어 진짜 "상위"가 되게).

## 6. 테스트

- `caption_rank`: none/light/heavy/미판정 4케이스 → 0/1/2/2.
- `_merge_rotate` 정렬: 자막등급이 score를 이기는지, 같은 등급 안에서는 score 순인지.
- `_annotate_text_level`: 캐시 적중 시 비전 호출이 **일어나지 않는지**(mock 호출 카운트),
  캐시 미스 시 저장되는지, 판정 실패 시 저장 안 되는지.
- `store`: 저장·조회 왕복, 미조회 `None`.
- 회귀: 기존 `passes_caption_clutter`(heavy 컷) 동작 불변.
