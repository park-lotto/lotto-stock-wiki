## ② 재렌더 — 판정 기준이 틀렸다 (원인 확정)

`scene_lab.html applyServer`가 08-25에 이런 코드를 받았다:
```js
const _hadConfirm = !!confirmBody.innerHTML.trim();
if (_hadConfirm) clearConfirm();      // 저장이 성공하면 무조건 완성본을 버린다
```
**"편성이 달라졌나"가 아니라 "저장이 돌았나"**로 판정한다. autoApply는 1.2초 디바운스로
수시로 도니, 아무것도 안 바꾸고 탭만 오가도 완성본이 지워지고 **20초짜리 유료 렌더**가
다시 시작됐다.

→ 렌더에 들어간 편성의 지문(`RENDERED_SIG`)을 대조해 **진짜 달라졌을 때만** 버린다.
  - 지문은 렌더 **출발 시점**에 찍는다(`PENDING_SIG` → 완료 시 확정). 완료 시점에 찍으면
    렌더가 도는 20초 사이의 편집까지 "들어간 것"으로 오기록돼 낡은 영상을 최신으로 본다.
  - payload는 `_editPayload()` 한 곳에서만 만든다(0순위-B). 저장과 판정이 각자 조립하면
    언젠가 어긋나고, 그러면 안 바뀌었는데 지우거나(재렌더) 바뀌었는데 옛 영상을 남긴다.
  - 반대 방향 회귀(08-25 "소재 바꿨는데 옛 영상 그대로")도 테스트로 묶었다.

## ③ 탐색바 — 만들었는데 **잘려서 안 보였다** (★브라우저로만 잡힌다)

`showConfirmVideo`에 ⏸ / 🔇 / 시크바 / 시간표시를 붙였다. 정적 테스트 11건 통과.
**그런데 화면엔 막대가 없었다.** 라이브에서 재보니:
```
#playerhost  700px, overflow:hidden
#confirmPane flex:1 → 658px        (여기까진 정상)
#confirmBody 805px                 ← video의 9:16 강제 높이(768px)가 밀어냄
.cfbar       y=817                 ← 틀 밖. 잘림
```
**첫 수정은 틀렸다** — aspect-ratio를 통째로 뺐다가 게이트(`test_preview_size_single_source`)에
막혔다. 그 테스트가 지키는 계약은 08-20 사고의 처방이다: 미리보기 크기·비율을 여러 곳이
각자 정해 작업할 때마다 다른 크기(340 vs 440)로 나오던 것을 `scene_play.js PV_W/PV_AR`
한 곳으로 모았다. **비율을 빼는 건 그 정의처를 다시 가르는 짓이다.**

→ 제대로 된 해법: 비율은 두고 **넘칠 때만 줄어들게**.
```css
aspect-ratio:var(--shorts-pv-ar,9/16); width:auto; max-height:100%;
flex:0 1 auto; min-height:0; margin:0 auto
```
높이를 틀에 맞춰 깎으면 폭은 비율이 따라온다. `.cfLoad`도 같은 방식.

## ① 전체재생 멈춤 — 여는 단계에만 안전핀이 없었다

`scene_play.js step()`:
```js
if (v.readyState >= 1) go(); else v.onloadedmetadata = go;   // ← 이 한 줄
```
이 이벤트가 안 오면 `go()`가 영영 안 불리고 `schedStep`도 안 걸려 **그 컷에서 통째로 멈춘다.**
안 오는 경우는 실제로 있다 — 소재 요청 실패(404·403·끊김), 같은 재생기의 src 교체 타이밍.
컷 **안**의 시크에는 `cutWaitMs` 안전핀이 이미 있었는데(08-16·09-02 수정) **여는 단계만
맨몸**이었다. 두 번의 수정이 다 이 줄을 안 봤다.

→ `onerror` + 안전핀(`cutWaitMs`) + 중복 실행 가드(`opened`).
⚠️**컷을 건너뛰지 않는다** — 빼면 화면이 음성보다 빨라져 싱크가 통째로 어긋난다.
  썸네일을 깔고 그 컷 시간은 그대로 쓴 뒤 다음 컷으로 간다.
