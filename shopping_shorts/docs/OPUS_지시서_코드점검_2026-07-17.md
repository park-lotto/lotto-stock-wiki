## 0. 이 문서를 받은 Opus에게 (작업 규칙)

1. **아래 항목을 순서대로 처리한다.** P0(보안·돈) → P1(데이터 유실·안정성) → P2(품질) → P3(구조 리팩터). P0를 건너뛰고 P3부터 손대지 말 것.
2. **각 항목은 "재현 → 수정 → 실측 검증" 순.** 정적 검토로 "고쳤다" 선언 금지. 서버 라우트는 실제 요청으로, 렌더는 실제 ffmpeg 산출물로, 프론트는 실제 렌더러로 관찰한다. (CLAUDE.md 그라운딩 규칙)
3. **트랙격리 규칙 준수** (`handoff/README.md`): 동시 세션이 같은 워킹트리를 쓴다. 자기 트랙 파일만 수정하고, 이 지시서 항목이 여러 트랙에 걸치면 착수 전 사장님께 트랙 배정을 확인한다.
4. **아래 3건은 교차검증 완료** — 두 개의 독립 리뷰 에이전트가 같은 줄번호를 짚었고, 지시서 작성자가 실제 소스로 재확인함(신뢰도 최상): DASH_SECRET(1707), SSRF 부분문자열(1622·1643), mix_jobs 테넌시(customer_id 컬럼 부재). 나머지는 단일 에이전트 발견이므로 착수 시 각자 재현부터.
5. **이 지시서 전체는 "발견 목록"이지 "확정 스펙"이 아니다.** 각 수정은 사장님 승인 후 착수하고, 도메인 의도(예: 유저스크립트 무인증 허용은 의도된 것)를 존중한다.

## P0 — 보안·돈 (즉시. 라이브가 공개도메인이라 실피해 가능)

### P0-1. 세션 시크릿 하드코딩 → 인증 전면 우회 【Critical, 교차검증됨】
- **위치**: `app.py:1707` `DASH_SECRET = os.environ.get("DASH_SECRET", "shopping-shorts-local-secret")`
- **문제**: 세션쿠키를 이 시크릿으로 HMAC 서명(`_sign_session`). 운영에서 `DASH_PASS`만 넣고 `DASH_SECRET`을 빠뜨리면(env 한 줄 누락) 소스에 박힌 공개 기본값으로 누구나 `customer_id:expiry:sig`를 위조 → 관리자(cid=0) 포함 임의 고객 사칭. `_AUTH_ON`은 DASH_PASS 유무만 보므로 시크릿 누락을 감지 못함.
- **수정**: `_AUTH_ON`(=DASH_PASS 설정됨)인데 DASH_SECRET이 기본값이면 **기동 거부(raise)**. 또는 최초 기동 시 `secrets.token_hex(32)` 생성해 `data/` 밑 파일에 영속화하고 이후 재사용.
- **검증**: DASH_PASS만 설정하고 기동 → 거부되는지. 정상 env로 로그인 → 쿠키 위조 시도가 401인지.

### P0-2. 썸네일·영상 프록시 SSRF 우회 → 메타데이터 크리덴셜 탈취 【Critical, 교차검증됨】
- **위치**: `app.py:1622`(`/api/thumb`), `app.py:1643`(`/api/video`). 둘 다 `any(h in url for h in _ALLOWED_THUMB_HOSTS)` — 호스트가 아니라 **URL 문자열 전체 부분일치**.
- **문제**: `http://169.254.169.254/latest/meta-data/...?x=cdninstagram.com` 이 화이트리스트를 통과, 서버가 AWS 메타데이터로 GET 보내고 응답 본문을 그대로 반환. 서버가 Lightsail/Lightsail류라 IAM 크리덴셜 직결.
- **수정**: 이미 있는 `_reject_ssrf`(app.py:2082)를 재사용 + `urllib.parse.urlparse(url).hostname`을 뽑아 `host == h or host.endswith("." + h)` 정확 매칭. 두 라우트 모두.
- **검증**: 메타데이터 URL·내부IP로 요청 → 400. 정상 인스타/유튜브 CDN URL → 200.

### P0-3. SSRF 검증이 다운로드 라우트 대부분에 누락 【High】
- **위치**: `_reject_ssrf`가 `/api/scene/save/prepare`(2118)에만 걸림. `/api/produce/extract_from_url`(≈657), `/api/produce/save_to_wiki`(≈784), `/api/mix/start`(URL 리스트, ≈1225), `/api/wiki/save`(≈507)는 임의 URL을 `download_any`/`download_video`로 그대로 fetch.
- **수정**: `_reject_ssrf`를 URL 입력받는 모든 다운로드 라우트의 공통 전처리(FastAPI Depends 또는 헬퍼)로 승격.

### P0-4. 전역 설정 쓰기 라우트에 관리자 체크 부재 → 무인가 변조·비용 폭주 【High】
- **위치**: `POST /api/tiktok/settings`(≈164, month_budget=킬스위치), `POST /api/settings/vmake_key`(≈1240, 전역 VMake 키 평문·고객분리 없음), `/api/seeds` 추가·삭제(209-224), `/api/prune/remove`(455), `/api/discover/add`(420), `/api/voice-tune/profile/{preset_id}`(1517).
- **문제**: 공개 회원가입(비번 4자, 레이트리밋 없음)만 하면 아무 고객이나 전역 상태 변경 — 예산가드 무력화, 전역 VMake 키 덮어쓰기, 전 고객 음성 프로파일 변조.

### P0-5. 최종 렌더에 중복예약 가드 없음 → VMake 유료 이중과금 【Critical】
- **위치**: `app.py:1322` `/api/mix/render`, `mix_pipeline.py:284` `run_render`.
- **문제**: 더블클릭/폴링 재시도 시 `run_render` 2개가 같은 `work/final.mp4`에 동시 기록 → 잘린 mp4가 `status='done'`으로 통과, subtitle_removal 켜지면 VMake 유료 호출 2회. **preview에는 TOCTOU 가드(1368-1374)를 넣었으면서 돈 나가는 최종 렌더엔 없음.**
- **수정**: 라우트에서 동기적으로 `status='rendering'` 선기록 + preview의 `_preview_render_is_stale` 상당 stale 타임아웃을 최종 렌더에도.
- **검증**: 같은 job에 render 2연타 → 두 번째가 즉시 거부되는지, VMake 호출 로그 1회인지.

### P0-6. Apify 실패 전파가 전 토큰(최대 30개)으로 유료 run 재시작 【High】
- **위치**: `apify_client.py:95-113`.
- **문제**: (a) FAILED/ABORTED(입력오류·액터 스키마 변경 등 토큰 무관 원인)도 다음 토큰으로 "전체 재시도" → 토큰 수만큼 유료 run 반복. (b) TimeoutError 시 기존 run을 abort 안 하고 새 run 시작 → 이중 과금. `fetch_reels` 15워커 병렬과 곱해짐.
- **수정**: 401/402/429(소진)만 로테이션, FAILED/400은 즉시 포기, 타임아웃 시 `POST .../abort` 후 로테이션.

### P0-7. 프론트 저장형 XSS — 외부 채널 표시명·URL 미이스케이프 【High】
- **위치**: `index.html:347,348,356,362,363,608,616,617`(name/category/url/shortcode raw innerHTML·onclick 보간), `discover.html:245,246`(esc 함수 자체 없음), `find.html`(video_url raw src).
- **문제**: 인스타/틱톡 채널 표시명은 임의 문자열. `<img src=x onerror=...>`나 URL 내 `'`가 랭킹/발굴에 잡히면 대시보드를 연 사장님·타 고객 브라우저에서 실행 → 세션쿠키 탈취. `esc()`가 index.html:420에 이미 있는데 메인 카드 렌더만 누락. outreach.html은 `ITEM_MAP[sc]` 우회로 이미 고침 — 같은 패턴 적용.
- **수정**: 외부 유래 텍스트 전부 `esc()` 경유, onclick엔 shortcode/index만 넘기고 데이터는 맵 조회, URL은 encodeURI/속성분리. discover.html엔 공용 esc 도입.

### P0-8. 비용 유발 라우트 무제한 — 공개가입 + 인스타/Gemini 가드 부재 【High】

## P1 — 데이터 유실·안정성

### P1-1. mix/produce job이 테넌트 무격리 【Medium, 교차검증됨】

### P1-2. Store 요청마다 재생성 + 스키마 초기화 매번 실행 【High, 교차검증됨】
- **위치**: `store.py:16-19,123`. app.py에서 **`Store(DB_PATH)` 86회 인스턴스화**(한 요청에 3번 만드는 곳도), 생성자가 매번 `_init_schema()`(DDL 30여 개 + '홈템' UPDATE/DELETE 마이그레이션) 실행.
- **문제**: 매 요청이 쓰기 트랜잭션을 열어 백그라운드 렌더·수집 스레드와 겹치면 일반 GET에서도 `database is locked`. 성능도 요청당 수십 SQL 낭비.
- **수정**: 스키마 초기화·마이그레이션을 `@app.on_event("startup")` 또는 별도 migrate 스크립트로 1회 분리(`PRAGMA user_version` 버전테이블 도입), Store는 FastAPI Depends 싱글턴 주입.

### P1-3. SQLite WAL·busy_timeout 미설정 【High, 교차검증됨】
- **위치**: `store.py:21-22`. `journal_mode`/`busy_timeout` grep 결과 0건 = 기본(rollback) 저널.
- **문제**: 기본 저널은 쓰기 하나가 모든 읽기를 막음. 스레드풀 + BackgroundTasks + 믹스렌더 동시 실행 구조라 락 대기 초과 시 OperationalError. `with self._conn()`은 커밋만 하고 close 안 함(연결 누적).
- **수정**: `_conn()`에 `PRAGMA journal_mode=WAL; PRAGMA busy_timeout=5000` + `contextlib.closing` 명시 close.

### P1-4. 렌더 작업폴더·소스·TTS가 어디서도 삭제 안 됨 → 디스크 고갈 【Critical】

### P2-1. AI 재분류 최대 카테고리 '홈템'이 검증집합에 없어 전부 버려짐 【High】
- **위치**: `ai_categorize.py:22` `_CATS = set(CATEGORIES)`가 `config.py:96`의 구 분류를 씀. 프롬프트(29)는 '홈템'을 요구하는데 `if cat in _CATS`에서 탈락 → Gemini 비용은 쓰고 가장 흔한 카테고리 재분류가 조용히 무효.
- **수정**: `_CATS`를 `categorize.KEYWORDS.keys() + ["기타"]`로 통일(structure_analyze.py:19가 이미 이 방식), config.CATEGORIES 갱신/폐기.

### P2-2. 오독경보가 normalize_reading을 재사용한다는 계약이 미배선 【High】
- **위치**: `asr_check.py`가 `normalize_reading`을 import조차 안 함. `narration_naturalize.py:157` 주석은 "Whisper가 '삼 점 오'를 '3.5'로 표기하니 양쪽 정규화 필수(2026-07-15 실측)"라 명시했으나 두 호출부(asr_ranker, 작업대 diff)가 hyp를 정규화 안 함.
- **문제**: 숫자·단위 든 모든 대본에서 작업대 오독경보가 늘 울리는 늑대소년, N-best 랭커도 상수 노이즈에 묻힘.
- **수정**: `diff_words` 진입 시 ref·hyp 양쪽에 `normalize_reading` 적용.

### P2-3. 한국어 나레이션 읽기 규칙 결함 【High/Medium】
- 고유어 수사 미지원(`narration_naturalize.py:63-131,169`): "3개"→"삼개"(정: 세 개), **"2번"→"이번"(의미 변질)**, "3시"→"삼시". 조수사(개/번/명/살/시/마리…) 표 + 1~99 고유어 변환 분기 추가. 【High】
- `_SPOKEN_MAP` 일괄치환이 모음조화 무시(201-206): "받습니다"→"받어요"(정: 받아요), "사과입니다"→"사과이에요"(정: 사과예요). 어간 모음·받침 분해로 분기. 【Medium】

### P2-4. Gemini 재시도 루프 8중 복붙 + 정책 불일치 【Medium】
- **위치**: comment_gen/script_extract/similarity/product_identify/structure_analyze/ai_categorize/topic_grouper/script_generate(3벌). 앞 4개는 429에 sleep 재시도, **뒤 4개는 순간 429·503에 즉시 포기**(`return {}/[]`) → 분당 쿼터에 잠깐 걸린 것만으로 배치 분류·구조분석이 통째 스킵.

- **수정**: `run_gemini(prompt, schema, *, parts=None)` 공통 실행기 하나로 추출(소진마킹·quota sleep·503 백오프·폴백모델 포함, 라운드로빈 키선택). 각 모듈은 프롬프트+파서만 소유.

### P2-5. 외부 텍스트 프롬프트 인젝션 【Medium】

## P3 — 구조 리팩터 (P0~P2 안정화 후)

> **주의**: P0 보안결함 상당수가 "가드가 어떤 라우트엔 있고 어떤 라우트엔 없음"(SSRF·업로드상한·관리자체크·예외마스킹)이며, 이는 단일파일 복붙의 구조적 결과다. 리팩터는 근본 재발방지책이지만, 먼저 P0로 구멍을 막고 그 다음 구조로 굳힌다.

### P3-1. app.py(2391줄) 분할
- `APIRouter`로 도메인 분리: routers/{collect, outreach, wiki, mix, scene, find}.py + auth.py(로그인/가입/미들웨어/세션) + deps.py(`get_store`, `require_admin`, `current_cid`).
- 로그인·가입 HTML(1749-1791) → static 또는 Jinja 템플릿.
- 횡단 관심사를 Depends/미들웨어로 승격: SSRF 검증, 업로드 크기제한, 전역 예외핸들러(마스킹 일원화).
- **`body: dict` 60여 곳을 Pydantic 모델로** — 지금 FastAPI 검증·문서화가 전부 무력화 상태, 수동검증 누락이 곧 500/뒷문.

### P3-2. store.py(1500줄) 분할
- `migrations.py`로 스키마·데이터이관 분리(P1-2와 연동, `PRAGMA user_version` 버전관리).
- 도메인별 리포지토리로: RankingStore / OutreachStore / WikiStore / MixStore / SceneStore / AccountStore. 공통 연결관리는 `Database` 헬퍼 하나.

### P3-3. 계층 침범 정리
- app.py가 `_edit_plan._build_inventory`·`_ground_ref`·`_DEFAULT_TYPE` 등 프라이빗 멤버 직접 호출(34,1273,1306). edit_plan에 `ground_segment(extract, seg_id)` 공개 API 만들어 라우트는 그것만.

### P3-4. 중복 코드
- 프론트: produce.html 대본생성 모달이 library.html을 접두어만 바꿔 복붙(경합가드 이미 갈라짐) → 공용 `script_gen_modal.js`.
- 랭킹: `build_youtube_items`/`build_tiktok_items` ~45줄 복제(ranking.py:101 vs 151) → `build_view_items(raw, platform, field_map)`.
- 플랫폼 search 보일러플레이트 4벌(tiktok/douyin/xiaohongshu/instagram) → `_apify_search(actor, payload, normalize_fn)`.
- 프론트 하드코딩 상수(MOTION_PACKS, VIDEO_W, whisper 기본값)가 서버값 수동 미러링 → 서버가 내려주는 API로 단일소스화.
