# 믹스 게이트 교정 루프 — 설계

_작성: 2026-07-25 / 트랙: 부품은행 / 상태: 설계 승인_

## 배경 — 왜 이걸 하는가

숏폼 믹스 영상에서 **"장면 반복 / 원본을 그대로 트는 연속재생"** 이 반복적으로 재발한다.
이 부류는 이미 5~6번 고쳤다(`f87436224` 전역반복해소 · `52fd266a7`/`3deee741e` 컷리듬 감점 ·
`4d712d7d1` 동일장면 반복 "재발" 뿌리 · `3376f50da` 연속재생 · `2f868057f` "쳇바퀴 구조 차단").
매번 재발한 이유는 **한 표면씩 땜질**했기 때문이다.

### 실증 (job `57ec653ba579`, 2026-07-24 21:25 서버 로그)

```
plan_gate 위반: 컷 없이 이어지는 구간 1곳 — 원본을 그대로 트는 느낌 (s0-4~s0-5(4.8초))
              / 길이가 21.3초로 목표 30초보다 많이 짧습니다
```

- **`scene_first 폴백` 로그 없음** → 레거시 폴백이 아니라 개선된 생성기를 정상적으로 탔다.
- **소스는 2개(s0 33.9초 + s1 24.0초 = 58초, 목표의 2배)** — footage 부족이 아니다.
  s1의 24초가 그 자리에서 **안 쓰였다**. 즉 "쓸 게 없어서"가 아니라 **잘못 골랐고 아무도 안 끊었다**.
- 근본 공백: `is_continuous` 연속재생 가드가 **alternates(B롤)에만** 걸려 있다
  (`dedup_clips_global`). **primary 비트 간 연속은 막는 코드가 없다.** `dedup_and_balance`는
  seg_id 중복만 본다. `plan_gate`는 잡고도 **경고만** 하고 교정하지 않는다.

### 핵심 통찰

**`plan_gate`만이 "모든 변형(refill·conform)이 끝난 최종 계획"을 본다.** 지난 땜질은 전부
*앞 단계*(생성·dedup)에서 고쳐서, 뒷 단계가 되돌리면 재발했다. 그러므로 **교정은 게이트
자리에서** 해야 구조적으로 닫힌다.

## 목표 / 비목표

**목표**
- 장면 반복·연속재생·파편·소스편중을 **게이트 통과 시점에** 구조적으로 종결한다.
- 재픽은 **결정적·무과금·나레이션 불변**(TTS 재합성 없음)이어야 한다.
- 끝 자막 두 줄 겹침 / CTA 미완결 마감을 함께 고친다.

**비목표 (딴 세션/딴 건)**
- 길이 부족 시 **Gemini 대본 재생성** → 대본·자막 퀄리티 파라다임 세션(별도).
- 생성시점 가드(예방) → 나중에 "루프가 자주 돈다"가 실측되면 최적화로 추가.

## 접근 (승인: A)

게이트를 "경고만 하는 감시자"에서 **"통과시키는 관문"**으로 바꾼다. 위반이 있으면 재픽 →
재검사를 통과할 때까지(상한 3회) 반복하고, 못 고친 잔여는 역할별로 마감한다.

## 설계

### § 1. 루프 위치·흐름

[`mix_pipeline._plan_and_tts`](../../../shopping_shorts/mix_pipeline.py)의 현재 1회성 게이트
검사(4.9단계, refill·conform 뒤)를 루프로 교체한다.

```python
MAX_REPICK = 3
for _ in range(MAX_REPICK + 1):
    gate = plan_gate.check_plan(beats, target_seconds, pool_video_count)
    fixable = _repickable_violations(gate)      # 아래 §2 분류
    if not fixable:
        break
    new_beats = repick_for_gate(beats, source_scripts, gate)
    if new_beats == beats:                      # 더 못 고침 → 무한루프 방지
        break
    beats = new_beats
plan["gate"] = gate                             # 최종 결과 항상 저장
plan["repick_rounds"] = 돈 횟수                  # 진단용(로그·관리자 표시)
```

- **나레이션 불변 → TTS 재합성 없음.** 렌더는 통과 후 1회(지금과 동일).
- 순수 계산이라 실패해도 job은 안 죽인다(기존 게이트와 동일 방어).

### § 2. 위반 분류 — 재픽 가능 / 불가능

`plan_gate.check_plan`이 내는 `violations`(사람이 읽는 한 줄) + 구조화 지표
(`continuous_runs`, `repeat_segs`, `sources_used`, `seconds`)로 판정한다.

| 위반 | 재픽? | 처리 |
|---|---|---|
| 연속재생(`continuous_runs` long) | ✅ | 런 끊기 (§3) |
| 반복(`repeat_segs`) | ✅ | 중복 seg 스왑 |
| 파편(over_clip_beats) | ✅ | 상한 초과 alternates 드롭 |
| 소스편중(1개만/pool>1) | ✅ | 미사용 소스로 스왑 |
| 길이 짧음/너무 김 | ❌ | 생성 영역 → §4 역할별 마감 |
| 비트 수 부족 | ❌ | 생성 영역 → §4 |

### § 3. `repick_for_gate(beats, pool_sources, gate)` — 신규 순수함수

최종 beats + 풀 + 게이트 결과를 받아 **재픽 가능한 위반만** 교정한다. 원본 mutate 안 함.
위치: `backbone.py`(기존 `is_continuous`·`dedup_*`·`pick_clips_for_action`과 같은 곳, 재사용).

- **연속재생**: 각 long run에 대해, 런의 2번째+ 클립을 **같은 행위 + 비연속 + 미사용 소스
  우선**(예: 놀던 s1) 클립으로 스왑. **`is_continuous`를 primary 비트 간에도 적용**(빠졌던 절반).
  - **포인트 비트 primary는 불가침**(결정적 투입 장면). 런에 포인트 비트가 끼면 **반대쪽**을 끊는다.
- **반복**: 중복 seg를 미사용 같은 행위 클립으로(기존 `dedup_and_balance` 로직 + 연속성 인지 확장).
- **파편**: 비트당 클립 상한(`MAX_CLIPS_PER_BEAT`) 초과분 드롭(기존 `dedup_clips_global`).
- **소스편중**: 일부 비트 클립을 미사용 소스로 스왑.
- **후보가 없으면 그 위반은 그대로 둔다** → 루프가 §1의 `new_beats == beats`로 종료 → §4가 처리.

### § 4. 못 고쳤을 때 마감 — 역할별

재픽 불가 위반(길이·비트수) 또는 재픽으로 못 없앤 잔여는 **정보성**으로 남긴다.
백엔드는 `plan["gate"]`를 **항상 저장**한다. 프론트가 역할로 분기한다.

- **관리자 화면**: 빨간 경고 배너 — `gate.violations` 그대로(연속구간 X곳·소스 더 필요·짧음 등).
  사장님이 보고 판단(다시 매칭 권장 등).
- **일반 사용자**: 경고 숨김. 최선안 그대로 마감. 짧으면 짧은 대로 깔끔히 —
  **억지 패딩 없음**(현재도 목표초로 강제 늘리진 않음. 자연 길이 유지).

> 구현 시: 백엔드는 지금도 `plan["gate"]`를 저장한다. 이 스펙은 **프론트 표시를 역할로
> 게이팅**하는 것이 핵심 변경(백엔드는 저장만 보장).

### § 5. 끝 자막 겹침 / CTA 마감

두 캡션 레이어가 존재: (1) 비트별 나레이션 자막(`_caption_drawtexts`), (2) `headcopy`
(`_headcopy_drawtext_parts`) — **enable 창 없으면 영상 전체에 표시**([video_assemble.py:1136]).

**구현 1번 태스크에서 이 job 프레임으로 실제 범인 확정 후 고친다**(systematic-debugging):
- **가설 (a)**: headcopy가 전체 구간에 깔려 끝 CTA 나레이션과 상·하 두 줄 충돌.
  → **headcopy를 훅 구간으로 제한**(`_headcopy_enable` 경로를 기본 동작으로 승격) → 끝에서 사라짐.
- **가설 (b)**: 마지막 세그먼트(CTA)가 비트 경계 + 1초 여운(runout)에서 먼저 사라져 미완결.
  → **마지막 나레이션 세그먼트를 runout까지 홀드**(여운 동안 CTA 유지) → 툭 끊김 대신 자연 마감.
- 둘 중 실제 범인만 고친다(둘 다면 둘 다).

### § 6. 테스트 (TDD)

**재픽**
- 연속 primary 런을 **미사용 s1로 끊음** — 픽스처: s0-4·s0-5 연속 + s1 사용가능 →
  교정 후 `continuous_runs` 위반 0 · s1 사용됨.
- 포인트 비트 primary 불변(런에 끼어도 반대쪽만 끊음).
- 얇은 풀(대체 후보 없음)은 위반 남기고 **정상 종료**(무한루프 없음, `new_beats==beats`).
- 재픽이 **나레이션·`tts_path` 안 건드림**(TTS 재합성 없음 검증).
- 루프가 3회 내 수렴(고칠 수 있는 픽스처).

**끝 자막**
- headcopy enable 창이 끝 비트 전에 닫힘 / 마지막 세그먼트 end가 runout 포함까지 = 여운 중 CTA 유지.

**회귀**
- `test_plan_gate` · `test_continuous_playback` · scene_first 스위트 · caption 스위트 green.
- 기준선(문서화된 baseline) 대비 **신규 실패 0**.

**그라운딩(사장님)**
- 서버에서 이 2소스 재믹스 → `continuous_runs` 0 · s1 사용 · 끝 자막 안 겹침 육안 확인.

## 리스크 / 주의

- **무한루프**: 재픽이 같은 결과를 내면(`new_beats == beats`) 즉시 종료. 상한 3회 이중 방어.
- **포인트 비트 침범**: 포인트 primary를 바꾸면 결정적 장면이 깨진다 → 불가침 규칙 필수.
- **역할 판정 오류**: 관리자/일반 분기를 프론트에서 잘못하면 사용자에게 경고가 새거나
  관리자가 경고를 못 본다 → 표시 게이팅 테스트로 방어.
- 재픽은 **B롤뿐 아니라 primary도** 손대므로, primary 스왑이 행위 매칭을 깨지 않는지
  (같은 행위 후보만 고름) 확인 필요.
