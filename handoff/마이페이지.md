## 왜 시작했나 (사장님 원문)

> "상단 내계정에 합쳐서 하자. 이름은 마이페이지로하고 / 추가할키는 서프api있자나.
>  이건 랜즈검색용이고 1회당 지금 3개씩 차감이라 하루 검색한도를 10회로 제한했고

직전 제보는 **"어디?"** — 키 등록표를 못 찾으셨다. 사이드바에 `⚙️ 내 설정`(/settings)이
있었는데 사장님은 `👤 내 계정`(/account)을 누르셨다. **이름이 갈려 있던 게 원인.**

## ✅ 이번에 한 것 (main 병합·서버 반영 확인 완료)

커밋 `a564d677d` → main 병합 → 서버 `535670198`, `systemctl is-active` = active (실측)

### 1. 화면 통합 — 마이페이지
| 전 | 후 |
|---|---|
| `/account` = 플랜·한도 (app.py 인라인 `_ACCOUNT_TMPL`) | **삭제 안 함.** `/settings`로 307 |
| `/settings` = 포인트·키등록 (settings.html) | **마이페이지** — 탭 3개 |
| 사이드바 `설정 > ⚙️ 내 설정` + 계정카드 `⚙️ 내 계정` | 진입점 **하나**: `👤 마이페이지` |

- 탭: **내 계정**(플랜·하루 한도·로그아웃) / **포인트** / **키 등록**
- 계정 탭은 `/api/me`를 **그대로** 쓴다 — 데이터를 새로 만들지 않았다(0순위-B)
- `_ACCOUNT_TMPL`은 일부러 남겼다 → **되돌리려면 `_account_page()` 함수만** 되돌리면 된다

### 2. ★무료 등급 구멍을 하나 막았다 (합치다가 발견)
`/account`는 `_FREE_EXACT_GET`에 있어 무료 등급이 들어왔는데 **`/settings`는 없었다.**
사이드바는 `free:true`로 열어놓고 서버는 402로 막던 상태 = 화면과 서버가 어긋나 있었다.
그대로 합쳤으면 무료 등급이 자기 계정을 못 보게 된다. → `/settings`,
`/api/settings/points`, `/api/settings/keys`의 **GET만** 열었다. **POST(키 등록)는 그대로 차단.**

### 3. SerpApi 키 등록 (렌즈 검색)
- `keyroute.SVC_SERPAPI` 신설. 사장님 키 = `config.SERPAPI_KEYS`(env `SERPAPI_KEY`~`_30`)
- **"저장만 되고 안 쓰이는" 상태를 만들지 않았다** — 이게 TTS·유튜브(키등록포인트 ⏭6번)의
  현재 문제다. `app.py _lens_api_keys(cid)` **한 곳**에서 키를 정하고 렌즈 호출부 2곳
  (`app.py:5090`·`5251` 부근)에 배선. 사용자 키로만 나가는지 테스트로 고정했다
- **렌즈 과금 기준을 `SVC_GEMINI` → `SVC_SERPAPI`** 로 바꿨다.
  화면 문구("내 키 등록하면 0P")와 실제를 맞추기 위함. 회원 0명이라 지금이 안전한 시점
- **환불도 같은 서비스로 맞췄다** — 원래 차감은 gemini 기준, 환불도 gemini 기준이었는데
  차감 기준만 serpapi로 바꾸면 **차감은 되고 환불은 스킵**된다. 짝으로 움직여야 하는 값
- 키 확인(`_probe_user_key`)은 `serpapi.com/account.json` — **검색을 돌리면 안 된다.**
  '확인' 버튼 한 번이 월 250회 무료분을 3회씩 깎는다

### 4. 화면 문구는 전부 코드 실측값
| 문구 | 근거 |
|---|---|
| 검색 1번 = **3회** | `lens_discover.py` `_LENS_LOCALES` 3벌(ko/en/zh-cn) × `_MAX_CALLS_PER_SEARCH=3` 하드캡 |
| 월 250회 = **약 83번** | 250÷3. 부풀리지 않는다 |
| 하루 **10회** 제한 유지 | `app.py _CREDIT_DEFAULTS{"lens":10}` — 프로도 10 |

→ 그 숫자를 바꾸면 `test_lens_call_count_matches_the_ui_copy`가 **먼저 깨진다**(문구도 같이 고치게)

### 5. 부수 수정
- `freeOp`가 `desc`를 **통째로 덮어쓰던 것** → 한 줄 덧붙이기.
  렌즈처럼 desc에 꼭 필요한 설명("검색 1번에 3회")이 있으면 사라졌다 (0순위-B 그 모양)
- 탭 2개 전제의 `isPoints ? A : B` 이분법 → 목록 순회 (탭 3개가 되면서)

### 검증

  과금이 serpapi 키를 따라감 / **실제 HTTP params.api_key가 사용자 키뿐** / 3회 상수 고정

## ✅ 종단 실측 (2026-08-17, 서버·실제 키·실제 SerpApi 호출)

사장님 지시 "실제 내키를 등록해서 실제 완료뜨는것까지 테스트해봐" — 서버에서 실제
코드 경로로 돌렸다(화면은 로그인 게이트라 못 봄, 그래서 엔드포인트 본문을 그대로 실행).

| 단계 | 결과 |
|---|---|
| 등록 `add_customer_key(12,'serpapi',실키)` | True |
| 확인 `_probe_user_key` → status | **ok** (= 화면 "● 정상") |
| `keys_for(12)` | 사용자키 True, 사장님 키 안 섞임 |

### ★여기서 함정 하나를 잡았다 (안 잡았으면 사장님이 겪었을 것)

처음 등록한 키가 **이번 달 250회를 이미 다 쓴 키**였다(`plan_searches_left: 0`).
그런데 `account.json`이 **200을 준다** → 화면엔 **"● 정상"**. 검색을 걸면 첫 호출에서
소진 판정이 나 **0건**이고, 폴백이 없어(설계상 의도) 사장님 키로도 안 넘어간다.
= "정상이라며 왜 결과가 없냐". 키 자체는 멀쩡하니 `bad`("키가 틀렸습니다")도 거짓.

→ `_key_status()` 신설(ok/empty/bad를 정하는 **유일한 곳**), 화면에
`empty` = **"● 이번 달 무료분을 다 썼습니다"** 추가. 잔량 조회가 실패하면 ok 유지
— 확인 못 한 것을 소진으로 단정하지 않는다.
서버 실측: 소진키 → `empty`, 125회 남은 키 → `ok`.

### ⚠️ 지금 DB에 남아 있는 것 (사장님 판단 필요)

`cid 12`(parklotto20@gmail.com)에 **`SERPAPI_KEY_2`가 등록된 채로 남아 있다.**
- 좋은 점: 그 계정은 렌즈가 포인트 0P고, 화면에서 "● 정상" 배지를 바로 볼 수 있다

- 지우는 법: 마이페이지 > 키 등록 > 그 줄 [삭제]

## 함정 기록

| 함정 | 실제 |
|---|---|
| **PowerShell `Set-Content -Encoding UTF8`은 BOM을 붙인다** | app.py 첫 줄이 `U+FEFF`가 돼 파이썬이 통째로 `SyntaxError`. 정규식 치환으로 파일을 다시 쓸 땐 `[System.IO.File]::WriteAllText(..., UTF8Encoding($false))` |
| **테스트 스텁은 진짜 시그니처를 따라와야 한다** | `search_similar_videos`에 인자를 하나 넘겼더니 스텁 `lambda url, source_caption=...`가 전부 TypeError. 스텁 8개를 실제 모양으로 고침 |
| **소스 문자열을 세는 테스트가 있다** | `test_all_eight_sites_wired`가 `_charge_or_402(` **등장 횟수**를 센다. 주석에 그 문자열을 쓰면 카운트가 늘어 깨진다 |
| **`keycrypt._fernet`은 import 시점에 굳는다** | 테스트에서 `monkeypatch.setenv("BYOK_MASTER_KEY")`는 안 먹는다. `_fernet`을 직접 갈아끼워야 한다 |
| **차감과 환불은 같은 서비스를 봐야 한다** | 한쪽만 바꾸면 차감은 되고 환불은 스킵 = 잔액이 조용히 갉힌다 |
| **키 '확인' 버튼이 돈을 쓰면 안 된다** | SerpApi 검증에 검색을 쓰면 확인 한 번이 무료분 3회. `account.json`은 검색이 아니다 |
