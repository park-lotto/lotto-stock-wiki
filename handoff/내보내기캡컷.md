# 트랙: 내보내기캡컷 (최종렌더 다운로드 + 캡컷 내보내기)

## 2026-08-25 — ✅ .bat이 한 번도 제대로 돈 적 없었다 (인코딩) + 진단 강화 (Opus)

**고객 제보(이준연)**: 자동설정 .bat을 실행하면 검은 창에 한글이 전부 깨진 채
`'而룹쓌'은(는) 내부 또는 외부 명령... 이 아닙니다`가 쏟아지고 **폴더가 안 만들어짐**.

### 원인 — UTF-8 배치파일 + chcp 65001 + LF (실측·재현 완료)

라이브에서 받은 파일이 **UTF-8 + LF 개행**인데 파일 안에서 `chcp 65001`을 했다.
cmd.exe는 실행 도중 코드페이지가 바뀌면 **바이트 오프셋 기준으로 되감아 다시 읽는다**
→ 멀티바이트 글자 중간에서 줄이 쪼개져 파편이 명령어로 파싱된다. 515자짜리
powershell 한 줄이 특히 심하게 쪼개졌다(고객 캡쳐의 `$c`·`?echo` 파편이 그 줄).
깨진 줄에 `mkdir`도 있어서 폴더가 안 만들어진 것.

**왜 한 달 넘게 안 보였나**: 로컬 워킹트리 사본은 CRLF라 우연히 통과했다.
`.gitattributes`의 `* text=auto`가 저장소를 LF로 정규화 → **서버 체크아웃만 LF**가
되어 라이브에서만 터졌다. 로컬에서 아무리 돌려도 재현이 안 되는 구조였다.
(핸드오프 07-20의 "⏭ .bat 실제 더블클릭 동작 사장님 확인"이 한 달째 미확인이던
진짜 이유 = 확인했어도 로컬은 통과했을 것)

### 검증 (실제 cmd 실행)

- 라이브에서 받은 파일 md5 = 커밋본 일치, CP949+CRLF 유지 확인
- 정상 분기 → `[O] 설정 완료!` + `확인된 저장 위치: currentCustomDraftPath=C:\capcutproject\CapCut Drafts`
- 미설치·로그인전 분기 → `LOCALAPPDATA`를 임시폴더로 바꿔치기해 둘 다 재현 확인
- setup.html은 로컬·라이브 둘 다 실브라우저로 버튼 노출 확인

### 사장님이 답해주신 운영 규칙 (문서에 반영 필요)

**캡컷을 꺼야 하는 건 .bat 실행 때뿐이다. 보내기 때는 켜져 있어도 된다.**
- `.bat` 실행 → 캡컷 **반드시 종료**. 캡컷이 종료할 때 globalSetting을 자기 값으로 덮어쓴다
- `🎬 캡컷으로 보내기` → 폴더에 파일만 쓴다(`sendToCapCut()` produce.html:9273). 설정 안 건드림.
  **껐다 켜야 하는 건 "보낸 후"** — 캡컷은 켤 때 프로젝트 목록을 한 번 읽고 만다
