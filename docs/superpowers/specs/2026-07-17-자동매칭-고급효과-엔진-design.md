# 자동매칭 고급효과 엔진 — 설계

작성 2026-07-17 · 트랙 모션효과 · 상태: 승인됨(사장님 "고")

## 1. 목적

제작소에서 만든 릴스(대본+TTS+조립 클립)에 **리모션 모션그래픽 효과를 자동으로 배치**해
"짜깁기가 못 넘는" 완성도를 낸다. 지금은 배치 플랜(어느 비트에 무슨 효과)을 사람이 손으로
짜는데, 이를 자동화한다.

**핵심 성격**: 리모션 효과는 **선택사항인 고급효과(프리미엄)** — 기본 꾸미기는 그대로 무료이고,
고급효과를 켜서 렌더하면 **포인트를 정액 차감**한다.

## 2. 확정된 결정 (브레인스토밍)

1. **작업 흐름 = 단계형 위저드** — 대본확인 → 효과추천 → 배치 미리보기 → 고급 렌더. 스텝이
   독립이라 나중에 스텝/기능 추가가 쉽다.
2. **효과 대상 = 제작소에서 만든 내 릴스** — 대본과 비트 타이밍이 믹스 잡에 **이미 있다**(TTS
   길이 기준). 따라서 **Gemini 추출도 Whisper 단어싱크도 불필요**. 이게 "가벼움"의 핵심.
3. **렌더 아키텍처 = A(리모션이 마무리 렌더)** — 믹스는 클립+TTS만 조립, 리모션이 그 위에
   효과+작은 자막+채널 크롬을 얹어 최종 렌더. 작은 자막·크롬은 이 방식이라야 나온다.
   서버에 리모션 설치가 필요하며, 렌더는 **독립 백그라운드 스텝**으로 분리한다.
4. **포인트 = 렌더 1회당 정액 차감** — 그 영상에 효과를 몇 개 넣든 고급 렌더 한 번에 정액.
5. **장르 → 테마**는 기존 `category`로 자동 매핑(레시피=warm 확정, 나머지는 §7 표).
6. **매칭 판단 = Haiku(또는 Max 무과금)** — 대본이 짧아 릴스당 ~1,300토큰. 규칙 폴백 있음.
7. **퀄리티 폴리싱은 범위 밖** — 이번엔 엔진+통합까지.

## 3. 전체 흐름

```
믹스 잡(대본+비트+TTS+조립 mp4)
  └─▶ 꾸미기 › 고급효과 ✨ 위저드 (선택)
        1) 대본·비트 확인    — 믹스잡에서 자동 로드(타이밍 이미 있음)
        2) 효과 추천         — Haiku가 비트별 효과+테마 제안 → 사용자 토글/수정
        3) 배치 미리보기     — 플랜을 정적 프레임(들)로 미리보기
        4) 고급 렌더         — 포인트 정액 차감 → 백그라운드 리모션 렌더 → 다운로드
                              (렌더 실패 시 포인트 환불)
```

## 4. 컴포넌트 (각각 독립 유닛)

| 유닛 | 역할 | 의존 | 입력 → 출력 |
|---|---|---|---|
| `effect_match.py` | 비트+카테고리 → **플랜 JSON** | 없음(순수)+Haiku 래퍼 | (beats[], category) → plan |
| `remotion_render.py` | 플랜+조립본 → 최종 mp4 | node/Remotion(subprocess) | (plan, video_path) → mp4 |
| 라우트 `/api/produce/fx/suggest` | 매칭 실행 | effect_match | job_id → plan(초안) |
| 라우트 `/api/produce/fx/render` | 포인트 차감 + 백그라운드 렌더 예약 | points, remotion_render | job_id, plan → render_job |
| 라우트 `/api/produce/fx/status` | 렌더 진행/결과 | store | render_job → 상태·url |
| `points.py` | `deduct/refund` 최소 원장 | store(신규 테이블) | (user, amount) |
| produce.html 패널 | 꾸미기에 "고급효과 ✨" 토글 → 위저드 | 위 라우트 | — |

**단일 책임 근거**: `effect_match`는 렌더도 DB도 모르는 순수 변환이라 단위 테스트·뮤테이션이
쉽다. `remotion_render`는 node 호출만 담당. 포인트는 별도라 과금 정책이 바뀌어도 매칭/렌더 불변.

## 5. 데이터 계약

- **플랜 JSON = FullReel props** (이미 정의·검증됨):
  `{videoSrc, durationInFrames, themeName, sections[], beats[], fx[]}`.
  엔진은 이 스키마만 생산하면 되고, 렌더는 이 스키마만 소비한다.
- **effect_match 입력 비트**: 믹스 잡의 비트(대사 text + start/end초). 타이밍은 TTS 기준 확정값.
- **fx 카탈로그**: 각 효과의 {키, 설명, 필요 props, 발동 신호}를 한 곳(`EFFECT_CATALOG`)에 둠.
  Haiku 프롬프트도 이걸로 생성 → 효과 추가 시 한 곳만 고치면 됨.

## 6. 매칭 로직 (effect_match)

1. **규칙 1차(무과금)**: 숫자→count, "N가지/재료"→list, 명백한 강조어→impact, 훅/CTA→callout.
2. **Haiku 2차(애매한 것만)**: 규칙이 안 잡은 비트에 효과 넣을지·어떤 단어로. 릴스당 소량.
3. **테마**: category → themeName 매핑(§7).
4. **밀도 정책**: "짧은 시간 시각 임팩트 극대화" — 비트마다 의미 있으면 촘촘히, 무의미한 비트는 비움.
5. **폴백**: LLM 실패 시 규칙 결과만으로 플랜 생성(효과 적더라도 진행). 완전 실패 시 빈 fx(무과금 경고).

## 7. category → theme 매핑 (초안 — 채워야 함)

| category | theme | 비고 |
|---|---|---|
| 레시피 | warm | 확정 |
| 홈템 | (미정) | warm 계열? |
| 주식/데이터 | tech | 스탁브레인 재사용 |
| 그 외 | warm(기본) | |

## 8. 에러/엣지

- 매칭 LLM 실패 → 규칙 폴백 또는 빈 플랜(효과 없음, 무과금).
- 렌더 실패/타임아웃 → **포인트 환불** + 상태=실패.
- 서버 리모션 미설치 → 고급효과 토글 **비활성**(기본 꾸미기는 정상 = 그레이스풀 저하).
- 포인트 부족 → 렌더 예약 거부(차감 전 검사).
- 더블클릭/중복 예약 방어(대본믹스 1단계 미리보기 선례 따름).

## 9. 서버 인프라 (A안의 비용)

shopping-shorts 서버에 **node + Remotion + 헤드리스 크롬** 설치. 렌더는 백그라운드 잡이라 웹
응답을 안 막는다. 최초 렌더 시 크롬 헤드리스 셸 자동 다운로드(수백 MB) — 배포 스크립트에 선반영.

## 10. 확장성

- **새 효과** = Remotion 컴포넌트 + `EFFECT_CATALOG` 한 줄 → 위저드·매칭에 자동 반영.
- **새 테마/팔레트** = `theme.ts` 프리셋 한 개.
- **새 스텝** = 위저드가 스텝 배열이라 끼워넣기 가능.

## 11. 테스트 전략

- `effect_match` **순수함수 단위** + **뮤테이션**(규칙 분기·테마 매핑을 뒤집어 죽는지).
- `remotion_render` **통합 1회**: 실제 node 렌더 산출물 mp4의 프레임을 확인(이 저장소는
  "테스트 통과 = 동작"이 아님 — ffmpeg/렌더는 가짜화되기 쉬우니 실산출물 관측).
- 포인트 **차감/환불 계약** 테스트(렌더 실패 시 잔액 원복).
- 라우트는 게이트와 같은 pytest 조건으로(‑s 금지).

## 12. 범위 밖 (YAGNI)

- 퀄리티 폴리싱(효과 디테일 고도화) — 사장님 명시 제외.
- 외부 릴스(남의 완성본) 대상 — 나중 스텝(Gemini/Whisper 경로).
- 라인차트·새 컴포넌트 — 확장 지점만 열어두고 이번엔 기존 5종.

## 13. 성공 판정

제작소에서 만든 실 릴스 1편에 고급효과 위저드를 돌려 → 효과가 자동 배치된 최종 mp4가 나오고
(프레임으로 확인) → 포인트가 정액 차감되고 → 렌더 실패 시 환불된다.
