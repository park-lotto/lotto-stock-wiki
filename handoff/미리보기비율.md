# 미리보기비율 — 핸드오프

## 2026-08-19 (회사PC) — 쇼츠 미리보기 9:16 통일

### 사장님 제보
"유튜브는 미리보기 재생할때 크기가 안맞는것같은데 미리보기 사이즈를 조정해야하나? 쇼츠 내용도 잘안보임"

### 원인 (추측 아님 — 코드 실측)
`shopping_shorts/static/index.html`에서 **같은 값(height:220px)을 네 군데가 각자 적고 있었다**
(CLAUDE.md 0순위-B: 같은 판단이 두 곳에 적히면 반드시 어긋난다).

쇼츠는 9:16(세로)인데 카드 폭이 210~250px라 220px는 **거의 정사각**이다. 그래서 두 증상이 갈렸다:

| 요소 | 옛 값 | 증상 |
|---|---|---|
| `.card img` (목록 썸네일) | 220px + `object-fit:cover` | 세로 영상 위아래를 **잘라냄** → 쇼츠 훅 문구가 잘려 "내용이 안 보임" |
| `.thumb-video` (mp4 재생) | 220px + `object-fit:cover` | 같이 잘림 |
| `_embedYoutube` iframe | 220px 하드코딩 | 유튜브 플레이어는 잘라내는 대신 **레터박스** → "크기가 안 맞음" |
| `_embedTiktok` iframe | 220px 하드코딩 | 같은 문제 |

★사장님 스크린샷의 검은 여백 + 작은 영상 + 하단 YouTube 로고 = **iframe 폴백**이다.
즉 두 카드 다 `/api/media` mp4 해석에 실패해 embed로 떨어진 상태였다.

★**인스타는 크기 문제가 아니었다.** 인스타·유튜브는 같은 CSS를 쓴다(플랫폼 분기 없음).
다만 인스타는 재생 실패 시 **새 탭으로 나가서**(`_embedInstagram`) iframe 레터박스가
드러날 일이 없었을 뿐이다. 썸네일 잘림은 인스타도 똑같이 겪고 있었다.

### 고친 것
`:root{--shorts-ar:9/16;}` 변수 하나로 모으고 네 곳이 그걸 따라가게 했다.
`aspect-ratio`라서 **카드 폭이 달라져도 항상 9:16**이다(고정 px가 아니다 → 모바일도 자동).

- `index.html:23`  `--shorts-ar` 신설
- `index.html:56`  `.card img` → `aspect-ratio:var(--shorts-ar);height:auto`
- `index.html:61`  `.thumb-video` → 동일
- `index.html:2324` 유튜브 iframe 폴백 → 동일
- `index.html:2331` 틱톡 iframe 폴백 → 동일

### ★예외 하나 — 트렌드 주제 카드
`.card img`는 랭킹 전용이 아니다. 실측으로 5곳이 이 CSS를 쓴다:

| 화면 | 위치 | 처리 |
|---|---|---|
| 랭킹 카드 | `:1699` | 9:16 (세로 영상) |
| 채널 지난 한 달 | `:1804` | 9:16 (세로 영상) |
| 숏템내부검색 모달 | `:1867` | 9:16 (세로 영상) |
| 렌즈 결과 카드 | `:3147` | 9:16 (세로 영상) |
| **트렌드 주제 카드** | `:2953` | **220px 유지** ← 영상 미리보기가 아니라 '주제 대표 이미지' |

트렌드만 `.trend-card` 클래스를 붙여 `aspect-ratio:auto;height:220px`로 되돌렸다.
특이도 (0,2,1) > (0,1,1)이고 뒤에 와서 확실히 이긴다(실측 확인).

### 검증 (실측)
헤드리스 크로미움으로 **실제 `render()`에 항목을 흘려** 그려보고 쟀다:

```
PC(1100px)   랭킹썸네일 300x533 = 1.777 | 재생video 300x533 = 1.777 | 유튜브iframe 300x533 = 1.777
모바일(430px) 랭킹썸네일 208x370 = 1.779 | 재생video 208x370 = 1.779 | 유튜브iframe 208x370 = 1.779
트렌드카드   300x220 (예외 유지) ✓
실제 render() 경유 카드 245x435 = 1.778   (9:16 = 1.778)
```

`node --check` rc=0. ★문법검사만으론 부족하다(TDZ는 통과시킨다 —
`reference_render죽으면_전화면공백`) → 실제 페이지를 브라우저에 띄워
`render`·`playYoutube`가 살아있는 함수인지, `--shorts-ar`가 `9/16`으로 풀리는지 확인했다.
남은 콘솔 오류 4건은 전부 `file://`라 API가 없어서 나는 것(코드 문제 아님).

### 부작용
카드가 길어져 **스크롤이 약 1.4배** 늘어난다(카드 560→784px). 사장님이 9:16을 선택하심.
잘림·레터박스를 완전히 없애려면 이 비율이어야 한다(320px 절충안은 얇은 띠가 남는다).
