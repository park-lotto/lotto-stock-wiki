# 성우검색401 — "검색 실패 (HTTP 401)"의 진짜 이유는 권한 한 칸이었다

## 2026-09-02 사장님 제보

제작소 목소리 단계에서 **"마음에 드는 목소리 찾기" → 검색 실패 (HTTP 401)**.

## 진짜 원인 (서버 로그 실측)

일레븐랩스는 **무엇이 잘못됐는지 정확히 말해주고 있었다**:
```
The API key you used is missing the permission voices_read to execute this operation.
```
= **키는 멀쩡하고 `voices_read` 권한이 꺼져 있었다.**

그런데 우리 코드는 그 본문을 버렸다:
- `eleven_voices.search_shared` → `f"검색 실패 (HTTP {r.status_code})"` (사장님이 본 화면)
- `app._explain_key_failure` → `code in (401,403)`이면 무조건
  "키를 새로 만들어 다시 넣어주세요" ← **틀린 안내다.** 새 키를 만들어도 권한을 안 켜면
  똑같이 실패한다. 고객은 고칠 수 없는 쳇바퀴를 돈다.

## 고친 것

`eleven_voices.explain_error(code, body)` 신설 — **판단은 여기 한 곳뿐이다**(0순위-B).
`app._explain_key_failure`의 일레븐랩스 분기도 이걸 부른다(전엔 같은 판단이 두 벌이었고
실제로 어긋나 있었다).

권한 부족이면 **어떤 권한인지 이름을 그대로** 말하고 어디서 켜는지 안내한다:
> 키는 정상인데 **목소리 보기(voices_read) 권한**이 꺼져 있습니다.
> ElevenLabs → 내 프로필 → API Keys에서 그 키를 편집해 이 권한을 켜주세요
> (키를 새로 만들어도 권한을 안 켜면 똑같이 실패합니다).

`voices_read` 말고 다른 권한(`text_to_speech` 등)도 본문에서 이름을 뽑아 쓴다 —
한 개만 특별대우하면 다음 권한에서 또 막힌다.

## 검증
- 새 테스트 6건 통과(`test_eleven_permission_message.py`) — 실제 401 본문 그대로 사용
- 기존 관련 테스트 298건 통과(`-k "eleven or key_fail or voice or byok"`)

## ⏭ 사장님이 하실 것 (코드로 못 고친다)
ElevenLabs → 내 프로필 → **API Keys** → 쓰고 계신 키 편집 → **voices_read 권한 켜기**.
그러면 성우 검색이 바로 됩니다. (타입캐스트 쪽 "검색 결과가 없어요"는 별건 —
권한 문제가 아니라 그 서비스 검색 결과가 비어 있는 것으로 보임, 미확인)
