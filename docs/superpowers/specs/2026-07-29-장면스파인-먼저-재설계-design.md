# 장면 스파인 먼저 — 대본 나중 재설계 (설계문서)

> 작성: 2026-07-29 · 트랙: 모션레벨훅 · 대상: shopping_shorts 대본/믹스 생성(edit_plan)

## 1. 문제
믹스 결과가 **장면↔멘트 싱크·비트 순서**가 깨진다(사장님 실측 e5840bfe): "건강한 간식이 완성돼요" 멘트에 화면은 기계 뚜껑 잠그는 중간동작, CTA가 5초 한복판, 설거지 장면이 뜬금없이 삽입. 훅 비주얼은 별도로 고쳐졌으나 **전체 흐름이 뒤죽박죽**이다.

## 2. 근본 원인 (코드 실측)
라이브 경로(`edit_plan._scene_first_candidates` → `_ground_score`)는 이름만 "scene_first"이고 실제론 **narration-first**다:
1. `_scene_first_candidates`: 제미니가 **멘트(대본)를 비트로 쓰면서** 각 비트에 인벤토리 장면(seg_id)을 **골라 붙인다**. → 대본이 운전대, 장면은 딸려온다.
2. `ping_pong_reconcile`/`order_by_backbone`: 대본 생성 **후에** 장면을 사후 재정렬. 뒤집힌 순서를 억지로 바로잡으려다 어긋남이 남는다.

즉 **장면 뼈대(스파인)를 먼저 확정하지 않아** 대본이 장면을 끌고 다닌다.

또한 `VIDEO_TYPES`는 현재 **2개뿐**(`recipe_secret`, `product_reveal`)이고, 각 타입은 **"말투 전략 텍스트"만** 들고 있을 뿐 **장면 순서(스파인)를 정의하지 않는다**. `shot_role` 어휘도 `조리/완성/기타` 3개로 요리 편향이라 뷰티·제품·청소 장면을 슬롯에 못 꽂는다.

## 3. 목표
순서를 뒤집는다:
```
지금:  대본 먼저 쓴다 → 장면을 억지로 붙인다 → 사후 재정렬   (어긋남)
목표:  ①카테고리 감지 → ②카테고리 스파인 템플릿 선택
       → ③태깅된 장면을 스파인 슬롯에 배치(장면 순서 확정)
       → ④그 슬롯 순서에 맞춰 대본(멘트·표현·스토리) 작성
```
장면 뼈대가 먼저 고정되고, 대본이 그 위에 얹힌다. **장면이 운전대를 잡는다.**

### 확정 결정 (2026-07-29 사장님 "고")
- 접근 **C(하이브리드)**: 카테고리별 스파인 템플릿이 난간(슬롯 순서), 제미니가 그 안에서 장면 배치·미세순서·대본을 채운다. (A 순수템플릿의 경직 / B 순수LLM의 들쭉날쭉 둘 다 회피.)
- 카테고리는 **5개로 시작**(아래 §5).

## 4. 비목표 (YAGNI)
- 영상 재업로드/Gemini 영상 재분석 — 추출이 이미 `shot_role`/`is_key`/`scene_desc` 태깅함(재사용).
- 컷 분할 로직 변경 — `scene_cut`(ffmpeg) 그대로.
- 5개를 넘는 카테고리 세분화 — 효과 실측 후 추가.
- 후보 3안·심사위원·음성/렌더 파이프라인 — 이번 범위 밖(스파인 배치와 대본 순서만).

## 5. 컴포넌트

### ① 카테고리 확장 (`VIDEO_TYPES`)
현재 2개 → **5개**. 각 타입에 기존 `label`·`strategy`(말투)에 더해 **`spine`(슬롯 순서 배열)** 필드 신설.

| key | label | spine (슬롯 순서) |
|---|---|---|
| `recipe` | 🍳 요리/식품 | 완성훅 → 재료 → 과정 → 완성샷 → CTA |
| `kitchen_tool` | 🧰 살림템/주방 | 실물훅 → 문제상황 → 기능실증(before→after) → 결과 → CTA |
| `beauty` | 💄 뷰티 | 완성룩훅 → 고민/before → 사용 → after대비 → CTA |
| `cleaning` | 🧼 청소/생활 | 더러운before훅 → 사용 → 깨끗after → 반전강조 → CTA |
| `generic` | ✨ 범용 | 강한장면훅 → 핵심실증 → 결과 → CTA |

- `_DEFAULT_TYPE = "generic"`(현재 `product_reveal` → 폐기하되 detect 하위호환 매핑 유지).
- 기존 `recipe_secret`/`product_reveal` key는 **에일리어스**로 새 key에 매핑(옛 캐시·job 호환, fail-open).

### ② `shot_role` 어휘 확장 (`script_extract`)
현재 enum `["조리","완성","기타"]` → **`["before","사용중","after","완성","문제","기타"]`**로 확장. 스파인 슬롯이 이 어휘로 장면을 찾는다.
- ⚠️ **`scene_desc` 문자열 불변**(`_claim_key` 토큰 오염 방지) — 역할은 별도 필드로만.
- **fail-open**: 옛 추출본(`조리`/구 enum)은 매핑 테이블로 흡수(`조리→사용중` 등), required 아님.

### ③ 스파인 배치기 (신규 `_build_scene_spine`)
`edit_plan`에 신규 함수. 입력=태깅된 인벤토리(seg_map)+선택된 spine 템플릿. 출력=**슬롯별 배정 장면 리스트(순서 확정)**.
- 각 슬롯이 요구하는 `shot_role`/`is_key`에 맞는 seg를 인벤토리에서 뽑아 배치.
- 슬롯에 맞는 장면이 없으면 **인접 슬롯 병합 또는 generic 폴백**(빈 슬롯로 렌더 깨짐 금지).
- 훅 슬롯은 `is_key`/`완성` 우선(기존 훅 비주얼 규칙 흡수).

### ④ 대본을 스파인에 얹기 (`_scene_first_candidates` 개편)
`_build_scene_spine` 결과(**고정된 슬롯 순서+각 슬롯 장면**)를 프롬프트에 **하드 제약**으로 전달:
- "아래 슬롯 순서·장면은 **고정이다. 순서를 바꾸지 마라.** 각 슬롯의 장면에 **맞는 멘트만** 써라(장면에 없는 걸 지어내지 마라)."
- 제미니는 **비트 순서를 새로 정하지 않고**, 슬롯마다 멘트·표현·어미·형용사만 채운다.
- 사후 `order_by_backbone`/`ping_pong` **재정렬 제거**(스파인이 이미 순서를 소유 → 이중처리·어긋남 근원 제거).

## 6. 데이터 흐름
```
추출(이미 있음): mp4 → Gemini vision → seg[scene_desc, shot_role(확장), is_key, motion]
                         │
detect_video_type ──────→ category(5중 1)
                         │
_build_scene_spine ─────→ [슬롯1:seg_a, 슬롯2:seg_b, ...] (순서 확정)
                         │
_scene_first_candidates → 슬롯별 멘트 채움(순서·장면 고정 제약)
                         │
video_assemble ─────────→ 렌더 (재정렬 없음)
```

## 7. 검증 (exit proof)
- 단위: `VIDEO_TYPES`에 5키·각 `spine` 존재. `_build_scene_spine`이 카테고리별로 올바른 슬롯 순서 반환(빈 인벤토리·슬롯 미스 폴백 포함). `_scene_first_candidates` 프롬프트에 "순서 고정" 제약+슬롯 장면 실림. `shot_role` 옛 enum 매핑 fail-open.
- 실측: 새 렌더의 자막을 순서대로 이어 **스토리가 말이 되는지** + **CTA가 마지막 슬롯**인지 + 멘트-장면 싱크 육안. (현재=뒤죽박죽 → 목표=완성훅→…→CTA 일관.)
- 게이트: 기준선(13건) 대비 신규 회귀 0.

## 8. 위험/함정
- `scene_desc` 문자열 오염 금지(§5-②).
- 프롬프트 과적재 주의(2026-07-26 17제약 충돌 교훈) — 스파인 제약은 린하게.
- 옛 job/캐시 호환: 새 shot_role·category key는 반드시 fail-open 매핑(안 그러면 기존 job 재생성이 깨짐).
- 사후 재정렬 제거 시 다른 후처리(dedup_and_balance 등)와 충돌 없는지 확인 — 순서는 스파인 소유, dedup은 순서 불변으로 유지.
