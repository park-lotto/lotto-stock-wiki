brainbulb 설계 논쟁 — 페이블 × 아스트라

뇌전구(볼케이노) 규격 숏폼을 서버 없이 로컬에서 만드는 파이프라인. 분업이 아니라 각자 의견을 내고 논쟁해 수렴했다. 3라운드 뒤 코드 12모듈·테스트 48개.

2026-09-12 페이블 = Claude Fable 5.1 아스트라 = Codex gpt-6-astra (reasoning high) 근거: 8편 역분석 · 실제 5편 산출물 fixture · 숏템메이커 코드 원본: docs/superpowers/specs/2026-09-12-brainbulb-design.md
페이블 발언 아스트라 발언 맞았다 틀렸다 반쯤 = 상대가 파일로 검증한 결과

0. 목표

텍스트/기사 소재 하나 → 뇌전구 규격 숏폼(1080×1920, 34~57초)을 사람 개입 없이. 1단계 MVP = 검은 배경 + 제목 + 카드 + 자막 + 나레(TTS) + 효과음. 이미지·밈은 2단계.

1라운드 — 페이블 안, 아스트라 독립 의견

페이블 · 안
  • 구조는 볼케이노식 단계 배열 하나. STEPS = [setup, script, lint, voice, timing, subtitle, sfx, render]. 단계마다 계약 4칸(들어갈 것/실행/재는 것/넘길 것). 판정은 반려만 하고 데이터를 고치지 않는다.
  • 규칙은 표 하나에서 지시문과 판정을 둘 다 생성. 숏템메이커의 "시켜놓고 벌주기" 재발 방지.
  • 디자인은 상수(spec.py). 채널 추가 = spec 교체.
  • 검증은 실제 5편 산출물과 diff. PIL 금지(libass보다 1.3배 크게 나옴, 실측).
  • 확신 못 하는 5가지를 논쟁에 부침: 줄나눔 주체 / 줄 폭 한도(실측 하한 808) / TTS 컷별 vs 통짜 / 렌더 프레임 나열 vs 단일 배경 / 상태 sqlite vs json.
아스트라 · 1라운드

동의: 단계 배열, 상태 단일화, 판정 비수정, 규칙표 구조, libass 실측, 검은 배경 MVP.

반대 ① gate_feedback() 재사용 금지 맞았다 — over 없는 모든 실패에 "분량이 모자라다"를 붙인다. 구두점 위반에 분량 처방이 나간다.

반대 ② 표본을 무조건 정답으로 삼지 마라 맞았다 — 박수홍 6번 밈이 payload는 025, timing.json은 013. 단계별 정본 필드를 정하고 그것만 대조하라.

5가지 답: (1) 줄나눔은 별도 배치 함수, LLM lines는 버린다 (2) 808은 임시, 최종은 실제 좌표에서 100%·108% 경계 검사 (3) 컷별 합성 + 파일 실측 (4) 단일 배경 (5) 작업폴더 json + 원자 저장·락·해시.

놓친 것: 효과음 "12주기"는 표본과 다르다 — cut 13이 click이 아니라 r3_click 맞았다. 그리고 단계 배열에 최종 검수가 없다 맞았다.

2라운드 — 페이블 검증·재반박, 아스트라 수렴

페이블 · 파일로 검증한 뒤 재반박
  • 효과음 — 아스트라가 맞다. 그런데 진짜 규칙을 찾았다. 5편이 접미사까지 동일하고, 구조는 4칸 틀 × 계열별 주기다. 32컷 전부 공식 일치. 
    i%4==0 → pop4
i%4==1 → [click, r3_click, x_click, r3_click, x_click]  (주기 5)
i%4==2 → [boing, hit, r3_hit]                           (주기 3)
i%4==3 → [ding, r3_ding, x_ding]                        (주기 3)
  • 밈 025/013 — 맞다. timing.json은 밈 확정 전 산출물이라 stale. 정본: 시각=timing / 밈=render_frames / 줄=sub.ass.
  • gate_feedback — 맞다. 자체 feedback(): 규칙 사유만 나열.
  • 줄 폭 — 반쯤 동의, 그런데 한도는 정해진다. 앵커가 \an8\pos(636,y)라 우측 여유 444 → 100%에서 888, 108% 등장 순간 822px. 통과 최대 808이 그 안. 좌표 검사로 구현하면 상수가 필요 없다 — 808 정책 철회.
  • 줄나눔·TTS·렌더·상태·검수 단계: 전부 동의. 되묻는 질문엔 "고정값(스타일·좌표·타이밍·효과음)만 완전 일치 요구, 서버 함수가 정하는 값은 우리 정책을 명시".
  • 남은 질문: review는 규칙 검사만(MVP)인가, 모델 검수까지인가.
아스트라 · 2라운드

822 확정 한도 반대, 좌표 검사 동의 반쯤 — 산술은 맞지만 앵커 양쪽 대칭을 가정한 값이고 Outline=4가 있다. 화면 밖까지 잴 수 있는 여백에서 렌더해 외곽선 포함 경계를 100%·108% 둘 다 검사하라.

효과음 공식 직접 검증: 135/135컷 일치. 남은 건 33컷 이후 접미사 규칙.

review = MVP는 규칙 검사만. 단 "무음 없음"은 수정 — 끝에 0.1초 꼬리가 있으니 의도한 꼬리와 음성 누락을 구분하고, 나레 트랙을 따로 검사.

STEPS에 layout을 명시 단계로. 검사 단계는 입력을 수정하지 않는다. 재작성 최대 3회, 바뀐 입력의 후속 산출물은 무효화.

미합의 4건: 33컷 이후 파일명 · 카드 54→46 경계 · 무음 임계 · 비용 상한 구체값.

3라운드 — 아스트라 코드 리뷰: "커밋 보류"

아스트라 · 코드를 읽고 일부 테스트를 직접 돌린 뒤

커밋 보류. ① 효과음 합성이 실제로 실패하고 ② 재작성 뒤 옛 음성이 남으며 ③ 반려·검사 실패가 후속 진행이나 성공으로 처리된다.

된 것

  • shopping_shorts/brainbulb/ 12모듈, 볼케이노식 단계 배열 하나가 상태기계
  • 실제 5편과 대조: 스타일 바이트 동일 · 효과음 135컷 동일 · 타이밍 동일 · ASS 줄 동일(±1cs) · 줄배치 135/135 · 제목 ±1pt

  • 이미지·밈은 2단계. 효과음·밈 팩은 저작권 미확인이라 커밋 제외(없으면 베드 생략)
