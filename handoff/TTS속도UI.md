# TTS속도UI

## 완료

- 장면 편집의 선택한 멘트 칸에만 `속도 0.8×~1.4×` 선택기를 표시했다. 1.0× 기본 칸은 선택하지 않으면 숨겨 화면 밀도를 유지한다.
- `sync_speed` 하나를 음성 재합성, 브라우저 미리보기, 최종 FFmpeg 렌더, 캡컷 draft가 함께 읽게 했다.
- 속도 변경 뒤 성우·톤을 다시 골라도 배속이 풀리거나 중복으로 곱해지지 않게 칸별 음성 설정을 보존한다.
- 속도 변경 시 기존 완성본 연결과 VMake 청소조각 캐시를 무효화한다.
- 이미 배속이 적용된 청소조각을 캡컷으로 보낼 때는 `sync_speed`를 제거해 이중 가속을 막는다.
- 마지막 비트의 1초 여운이 빠른 장면을 다시 슬로모션으로 만드는 문제를 실제 MP4 프레임 검사에서 발견해 수정했다.

## 검증

- 로컬 실제 장면 편집 화면에서 선택 칸만 작은 속도 선택기가 보이고 기본 칸은 숨는 것을 브라우저로 확인했다.
- 1.4× 실제 FFmpeg 렌더에서 출력 0.6초가 원본 약 0.84초 프레임까지 진행하는 것을 색상 프레임으로 확인했다.
- 캡컷 draft 영상 소재에 `speed=1.2`가 기록되고 오디오는 재합성본 1.0×로 유지되는 것을 검사했다.
- 최신 main의 구절 맞춤·수동 컷·미리보기 합본과 통합 후 관련 테스트 127개 통과.

## 배포 관문 보완 (2026-09-20)

- `planClips` 단독 회귀 검사에서도 속도 값을 자체적으로 읽게 해 브라우저와 검사 환경의 실행 차이를 없앴다.
- 속도가 전혀 지정되지 않은 기존 작업은 TTS에 `speed=1.0`을 새로 주입하지 않게 해 기존 공급자 기본 음색을 유지한다.
- 음성 설정 병합 테스트를 실제 API 계약(대상 비트 존재, 키 검사 격리)에 맞게 보완했고 관련 검사 15개가 통과했다.

## 라이브 실측 후 수정 (2026-09-20)

- 작업 `4be37aa74d3d`(mix `fdbdf33c16cb`)에서 1.4× 선택 후 음성이 그대로라는 제보를 실측했다.
- 저장과 재합성은 됐지만 음성 스냅샷이 없는 작업에서 기본 1.6에 곱하지 않고 절대 1.4로 바뀌어, TTS가 약 6.3초에서 6.55초로 오히려 길어졌다.
- `base_voice_for_beat`가 실제 합성과 같은 `_DEFAULT_VOICE`를 정본으로 쓰게 하고, 첫 배포가 남긴 `{speed: sync_speed}` 형태도 복구하게 했다. 관련 검사 13개 통과.

## 배속 왕복 시 음색 고정 (2026-09-20)

- 작업 `a8caaca16bcb`(mix `616ee19b6187`)에서 1.4× 후 다시 낮춰도 원래 발화로 돌아오지 않는 현상을 확인했다.
- 원인은 배속을 움직일 때마다 TTS 공급자에게 문장을 새로 읽혀 같은 파일을 덮어쓴 구조였다. 숫자는 맞아도 생성 때마다 억양·톤이 달라질 수 있었다.
- 이제 기준 음성을 한 번 별도 보관하고, 배속 변경은 그 동일 파일에 FFmpeg `atempo`만 적용한다. 1.0×로 돌아오면 기준 파일을 그대로 복사하므로 원음이 정확히 복원된다.
- 대본·성우·톤을 바꿀 때만 기준 음성을 다시 만들고, 이후 배속 왕복은 추가 TTS 비용 없이 같은 발화를 사용한다. 관련 검사 14개 통과.
