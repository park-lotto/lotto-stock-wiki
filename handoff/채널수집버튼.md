- **쓰레드는 담기도 불가능했다** — 서버는 이미 지원(`_GRAB_DOMAINS`에 threads,
  `media_download._download_threads`)하는데 **유저스크립트 `@match`·확장 manifest에
  threads 도메인이 없어** 스크립트 자체가 안 돌았다.
- 로직 원본은 `shopping_shorts/userscript/grab_logic.js`다(서버 `/grab_logic.js`가 이걸
  서빙, zip도 이걸 담는다). `extension/grab_logic.js`는 **오래된 사본**(2026-08-03) —
  건드리지 마라. 실수로 고쳤다가 되돌렸다.

## 2026-08-18 (3) — 즐겨찾기 분석 버튼·신호등

사장님: "즐겨찾기에 넣어두고 분석버튼 만들고 다 되면 분석완료로. 확인해서 제작소로
보내고 안 된 건 제작소에서 기다리면 되니까. 미리 담아두면 천천히 되니까."

- 서버: `_analysis_state(store, sc)` 신설 — **분석 상태 판정을 한 곳으로**. 제작소
  1단계 `source_brief`도 이걸 쓰게 바꿨다(두 화면이 같은 영상을 다르게 말하면 안 된다).
- 신설 API: `GET /api/basket/analysis_status?shortcodes=a,b,c`(비용 0원, 카드 20개면
  1번 호출) / `POST /api/basket/analyze {shortcodes:[]}` — 걸기는 담기예열과 **같은**
  `_enqueue_prewarm`. 이미 done이면 다시 안 건다.
- 화면(collection.html): 카드마다 ✅분석완료 / ⏳분석 중 / ⚠분석 실패(사유 툴팁) /
  ·분석 전 배지 + 카드별 `🔎 분석`(실패면 '다시 분석'), 툴바에 `🔎 분석 시작`과
  `✅ 분석완료만 선택`. 도는 중일 때만 20초 폴링(끝나면 멈춤).

## 2026-08-18 (4) — 즐겨찾기→제작소: 어디로 보낼지 고르기

사장님 제보: "레퍼런스에서 담아 제작소로 보내면 작업 중이던 곳으로 합쳐진다."

- 원인(코드 확인): `_consumeProduceHandoff`가 신규 핸드오프를 **진행 중 작업에 무조건
  누적**한다. 2026-07-18 "두 번 보내면 앞 것이 지워짐" 버그의 처방이라 규칙 자체는 맞지만,
  새 묶음을 보낼 때까지 옛 작업에 섞였다.
- ★같이 드러난 것: `?work=<id>` 경로(_restoreWork)는 서버 작업으로 HANDOFF를 **통째
  덮어써** 방금 보낸 영상을 조용히 버렸다. 이걸 안 고치면 "이 작업으로 보내기"가 무동작이다.
- 처방: 즐겨찾기에서 보낼 때 **새 작업(기본) / 이어서 할 작업**을 고르는 모달.
  새 작업=`?new=1`, 이어서=`?work=<id>` — 둘 다 이미 있던 길이라 새 기전 없음.
  합치기는 `_mergeHandoffItems` 한 곳으로 모으고 `_restoreWork`도 그걸 쓴다(+합친 뒤 saveWork).
- 함정 기록: produce.html은 **테스트가 함수를 앵커로 잘라 node로 돌린다**. 헬퍼를
  슬라이스 범위 밖에 두면 옛 하네스가 ReferenceError로 깨진다(실제로 12개 깨졌다) —
  헬퍼는 범위 안에 두고, 호출부엔 `typeof` 가드를 쓴다(이 파일의 기존 관례).
- 검증: 관련 402건 통과(깨진 것 0), 신규 테스트 8건.

### ⏭ 미검증
- 실브라우저: 모달에 진행 중 작업 목록이 실제로 뜨는지, '이어서' 보낸 뒤 그 작업에
  영상이 남아 있는지(새로고침 포함).

## 2026-08-18 (5) — 한 재료로 여러 편(다채널)

사장님: "다채널이라 같은 주제로 2개 이상 만들고 싶다. 복사해서 내 작업에 붙여넣는 것
말고 좋은 방법 없나? 대본 여러 개로 하고 싶어."

- 종전: A안·B안 중 **하나만 확정**, 나머지는 버려짐. 손복사는 소스·장면이 안 따라와 반쪽.
- 처방: `s2ConfirmToNewWork(i)` — 지금 작업을 **손대지 않고**(확정 안 함) `_workState()`를
  그대로 복제해 `POST /api/produce/works`(work_id 미전송=새 작업)로 새 작업 생성 →
  `?work=<새 id>`로 이동. 대본만 그 안으로 교체, `title_manual`은 지운다.
- ★job_id는 물려주지 않는다(믹스 결과는 작업마다 따로). 지금 작업은 `_pushWorkNow()`로
  먼저 확정 저장 — 디바운스 대기 중 페이지가 넘어가면 초안이 날아간다.
- 버튼 위치: 좌우 보기=카드 밑(.s2-dfoot), **탭 보기=확정 바 옆**(#s2NewWorkBtn).
  .s2-dfoot는 탭 모드에서 `display:none`이라 카드 밑에만 두면 사장님 화면엔 안 보인다.
- 테스트 8개 신규 + 관련 384건 통과.

### ⏭ 미검증
- 실브라우저: 새 작업이 실제로 생기고 소스·장면이 따라오는지, 원래 작업의 A안이 그대로인지.
