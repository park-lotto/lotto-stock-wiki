# 담은 영상 — 미리보기 재생 수리 + 카드 지표(댓글·팔로워·조회수)

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development 또는 executing-plans.

**Goal:** ①1단계 '담은 영상' 카드에서 ▶를 눌러도 아무 일 없이 사라지던 것을 고친다 ②즐겨찾기가 이미 갖고 있는 조회수·댓글·팔로워를 카드에 띄운다.

**Architecture:** ①은 **렌즈 해시를 진짜 영상 ID로 착각**해서 생긴다(`lens_instagram_quypyf`를 서버에 보냄 → 못 찾음 → 실패). 이 저장소가 이미 아는 함정이고(`mix_pipeline._cache_keys_for_url`·메모리 `★캐시키_URL추론금지`), 처방도 같다 — **추론 말고 URL에서 뽑되, 해시는 ID로 쓰지 않는다.** ②는 표시 코드(`_poolStat`)와 데이터 원천(즐겨찾기)이 **둘 다 이미 있고** 넘기는 줄에서만 빠졌다.

**Tech Stack:** 바닐라 JS (produce.html / collection.html), pytest + node JS 하네스

## 실측 근거 (전부 서버 실데이터로 확인)

### ① 재생 실패 — 원인 확정

사장님 제보: "미리보기가 이쪽 화면에서 안 나오네" → ▶를 누르면 "**사라짐**"

서버 DB의 실제 작업(`57043b8fc843` 면도기):
```
shortcode = 'lens_instagram_quypyf'          ← 렌즈가 만든 내부 해시
url       = instagram.com/reel/DcNGvmCT_JX/  ← 진짜 ID는 여기 있다
```

`produce.html:5449`:
```js
const id = it.shortcode || _poolVideoIdOf(it.url);   // ★해시가 "있으니까" 그걸 쓴다
```

서버 핸들러 직접 호출로 대조(실측):
```
lens_instagram_quypyf  → {'ok': False, 'url': ''}    ← 지금 보내는 것
DcNGvmCT_JX            → {'ok': True,  'url': mp4}   ← URL에서 뽑으면 정상
```

**규모**: 최근 작업 300건의 handoff 중 shortcode 있는 항목 **59개 → 43개(73%)가 lens_/grab_ 해시**.
43개 전부 url을 갖고 있다 = **고치면 전부 살아난다.**

**왜 "사라진" 것처럼 보이나**: `_poolFallback`이 유튜브·틱톡만 임베드 폴백을 주고
**인스타는 없다** → 썸네일로 되돌아가는데 ▶ 배지는 이미 `badge.remove()`로 지운 뒤라
누를 것도 없이 조용히 원상복구된다.

⚠️ **아닌 것으로 확인된 가설들**(다시 파지 마라):
- CDN 차단? **아니다** — 서버가 준 mp4를 다른 IP에서 열어도 `206`, `Access-Control-Allow-Origin: *`
- 권한(402/401)? **아니다** — `/api/media`는 `_FREE_EXACT_GET`에 있다. 비로그인 curl의 401은 로그인 안 해서지 이 문제와 무관
- 서버 해석 실패? **아니다** — 진짜 ID를 주면 3.5초에 정상 응답

function _poolPlayId(it){
  if (!it) return '';
  const sc = String(it.shortcode || '');
  const isHash = /^(lens|grab)_/.test(sc);
  if (sc && !isHash) return sc;                  // 진짜 shortcode — 그대로 쓴다

  if (fromUrl) return fromUrl;                   // ★url에서 뽑은 것이 우선

  const tail = sc.replace(/^(lens|grab)_[a-z]+_/, '');
  return /^\d{6,}$/.test(tail) ? tail : '';
