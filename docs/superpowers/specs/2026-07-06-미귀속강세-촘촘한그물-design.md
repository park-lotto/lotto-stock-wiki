# 촘촘한 그물 — 미귀속 강세 포착 엔진 (Unattributed Strength Net)

- 날짜: 2026-07-06
- 브랜치: `feat/briefing-engine`
- 상태: 설계 승인 대기 → (승인 시) writing-plans

## 한 줄

히트맵 상위에 뜬 섹터·종목 중 **이유를 못 찾은 강세를 절대 조용히 통과시키지 않는** 이중망. 설명된 강세는 이미 아는 것이고, **이유를 못 찾은 강세가 진짜 알파**라는 전제 위에 선다.

## 문제 정의

기존 브리핑/캘린더는 "뉴스에서 종목명을 직접 매칭"하는 방식이라 두 부류를 놓친다.

1. **연계형 강세** — 뉴스엔 "메타", "삼성"만 나오지만 실제 강세는 삼성 납품 소부장·후공정·기판 종목. 사건→수혜종목 **추론(그래프 연결)**이 있어야 잡힌다.
2. **미귀속 강세** — 히트맵 1등인데 뉴스·공시 어디에도 이유가 안 보이는 종목. 대부분 시스템은 이유를 찾은 것만 리포트하고 못 찾은 건 **조용히 누락** → 가장 값진 신호가 그물을 통과한다.

핵심 요구(사용자): **"히트맵 상위권에 뜨는 섹터·종목에 별다른 이슈가 안 잡히는 건 그냥 지나가면 안 된다."**

## 설계 원칙

- **침묵 금지(No Silent Omission):** 원인 매칭 실패는 "보고할 것 없음"이 아니라 "우리가 뒤처졌으니 파라"는 최우선 경보다.
- **정렬 반전:** 설명된 강세 → 아래로. 설명 안 되는 강세 → 맨 위로.
- **환각 차단:** LLM은 "관계 추출 / 근거 인용"에만 쓴다. 근거 원자 없는 종목 지어내기 금지.
- **루머 ≠ 사실:** 원인을 어디서 찾았든 소스의 신뢰등급 라벨과 출처를 반드시 함께 표기.
- **측정 가능한 촘촘함:** "촘촘함"을 감이 아니라 지표로 만들어 튜닝한다.

## 아키텍처 — 4개 부품

### 1. 이중망 (Dual Net)

- **예측망 (A):** 사건 발생 → 연결그래프 타고 수혜종목 자동 점화. "먼저 알고 기다림."
- **포착망 (B):** 원인 불명 강세를 이상감지(등락률·거래량·상대강도)로 먼저 포착. "놓친 걸 주움."
- **자가학습 루프:** B가 잡은 미상 강세 → 사후 원인 귀속 → 그 관계를 새 원자로 그래프에 편입 → 다음엔 A가 잡는다. 시간이 갈수록 그물이 저절로 촘촘해진다.

### 2. 연결엔진 (하이브리드 관계 그래프)

- 이미 크롤하는 원자(리포트·텔레그램·뉴스·유튜브 자막)에서 **"A→B 관계 원자"**(납품/지분/테마/경쟁)를 저가모델로 지속 추출·누적.
- 관계 원자는 항상 **출처(원자 id)에 묶임** → "왜 이 종목?"에 답 가능.
- LLM 역할은 관계 추출 + 근거 인용으로 한정. 종목 생성 금지 → 환각 차단.
- 정적 사전구축(DART 지분/납품)의 정확성 + 온더플라이 추론의 유연성을 **원자 누적**으로 합친 형태.

### 3. 미귀속 강세 = 최우선 경보 ⭐ (심장)

- 매 스캔 주기: 히트맵 상위 N(섹터·종목) 스캔 → 연결그래프에서 귀속 이슈 조회.
- **매칭 실패 → 침묵 금지.** 경보 등급을 올려 상단 고정: `⚠️ 원인 미상 강세 — 추적 요망`.
- 리포트 정렬 반전(설명된 것 아래 / 미상 위).

### 4. 원인 추적 캐스케이드 (실시간 병렬 팬아웃)

미귀속 강세 임계 초과 시, 저가모델(Gemini/Haiku) 대군이 아래 소스를 **병렬 동시 수색**:

| 단계 | 소스 | 특성 | 신뢰등급 |
|---|---|---|---|
| 1 | 공시(DART) | 느림·확정 | 🟢 확정 |
| 2 | 뉴스 | 중간 | 🟢 사실 |
| 3 | 텔레그램 | 빠름·정보성 | 🟡 미확인·속보 |
| 4 | 네이버 종토방 | 가장 빠름·소음 | 🟠 루머·심리 |
| 5 | LLM 추론(+근거 원자 인용) | 즉시 | 🔵 추론 |

- 찾은 원인 = **신뢰등급 라벨 + 출처**와 함께 카드로 상단 표기.
  - 예: `가온칩스 강세 — 🟢 296억 ASIC 계약 공시확정` vs `○○ 강세 — 🟠 종토방發 인수설(미확인)`
- 5단계 추론도 반드시 근거 원자 인용: "삼성 납품사(출처: △△리포트)".
- 전 소스 침묵 시 → `⚠️ 전 소스 침묵 — 최우선 추적` (가장 위험·가장 값진 상태로 잔류).

## 실행 구조

- **주기:** 장중 실시간, 5~10분 스캔 주기(튜닝 대상).
- **동시성:** Gemini/Haiku 대군 병렬 팬아웃. 다종목을 동시에 처리 — 넓게 던지고 슬롯이 비면 소진.
- **키:** 기존 다세션 공유 `key_vault`(Vertex Express Gemini 키) 로테이션으로 동시성 확보.
- **비용:** 저가모델 기반이라 부담 낮음 → 그물을 최대한 넓게.

## 촘촘함 측정 지표 (성공 기준)

"얼마나 촘촘한가"를 숫자로 만든다. 이 지표들이 튜닝 대시보드의 축이 된다.

- **귀속률 (Coverage):** 히트맵 상위 강세 종목 중 원인이 붙은 비율. ↑ 목표.
- **미귀속 놓침 = 0:** 미상인데 경보 없이 조용히 통과한 건수. **반드시 0** (침묵 금지 규칙이 지켜졌는지의 척도).
- **속도 (Latency):** 강세 발생 → 원인 카드 생성까지 시간. ↓ 목표.
- **정밀도 (Precision):** 붙인 원인이 사후 검증에서 실제로 맞은 비율. 신뢰등급별로 분리 집계(공시>뉴스>텔레>종토방>추론).
- **자가학습 이득:** 미상→귀속으로 그래프에 편입된 관계 수, 그로 인해 다음번 예측망(A)이 선점한 건수.

## 범위(초판) / 비범위

- **초판 포함:** 이중망 골격, 관계 원자 추출·그래프, 미귀속 경보+정렬반전, 캐스케이드(공시·뉴스·텔레·종토방·추론) + 신뢰등급 라벨, 촘촘함 지표 수집.
- **비범위(후속):** 자동 매매 연동, 예상 트리거/사가(캘린더 Phase 3와 별도), 지표 튜닝 자동화(초판은 수동 관측).

## 열린 질문(구현 계획에서 확정)

- 히트맵 상위 N과 "미귀속 강세" 임계값(등락률/상대강도/거래량) 초기값.
- 네이버 종토방·텔레그램 크롤의 기존 인제스트 파이프라인 재사용 범위.
- 스캔 주기(5분 vs 10분)와 팬아웃 동시성 상한(키 쿼터 대비).
