# 채널필터네비

## 2026-07-29 — 채널 보기 나가기(카테고리·뒤로가기)

### 무엇이 문제였나
레퍼런스 랭킹에서 카드의 채널명을 누르면 그 채널 영상만 보이는데(`searchChannel`),
이게 **검색어(`STATE.q`)에 아이디를 넣는 방식**이라 빠져나갈 길이 없었다.
- `setCtype`/`setCat`이 `STATE.q`를 안 지움 → 카테고리를 눌러도 그 채널 안에서 카테고리만 바뀜
- `history.pushState`가 아예 없음 → 브라우저 뒤로가기로 못 나감
- (새로고침은 원래도 전체 목록으로 갔다 — 검색어를 어디에도 저장하지 않으므로)

### 고친 것 (`static/index.html`만)
- `CHANNEL_VIEW` 플래그 + `exitChannelView()` 추가 (검색어·입력칸·'지난 한 달' 영역 정리)
- `searchChannel` 진입 시 `history.pushState` — **URL은 안 바꾼다**(같은 주소).
  주소에 채널을 박으면 새로고침이 채널 화면을 되살리는데, 원한 건 "새로고침하면 전체"다.
- `setCtype`/`setCat` → `exitChannelView({silent:true})`
- `popstate` → `exitChannelView({fromPopstate:true})`
- `setSearch`에서 검색어를 직접 고치면 플래그만 내림(히스토리 건드리면 치던 글자가 날아감)

### 검증 (실측)
- 브라우저 실동작(로컬 :8902): 진입 3→1장 / 카테고리 클릭 → 홈템 2장·검색어 비움 /
  뒤로가기 → 3장 복귀 / 새로고침 → 전체 / 일반 검색 중 카테고리 클릭 시 검색어 유지. 콘솔 에러 0
- 신규 `test_channel_view_nav_js.py` 3건 통과, UI/JS 서브셋 389 passed
- 남은 실패 4건(tiktok_search 2 · edit_plan_build 2)은 index.html과 무관한 기존 baseline

### 함정
- ⚠️ `test_ranking_search_js`는 `matchesSearch`~`// ── 검색 끝 ──` 구간을 node로 잘라 돌린다.
  그 안에 `window.addEventListener`를 넣으면 **window 미정의로 5건이 터진다**(이번에 한 번 밟음).
  DOM/전역 배선은 반드시 `// ── 검색 끝 ──` **밖**에.
- ⚠️ `exitChannelView`는 `fromPopstate`가 아니면 `history.back()`을 부른다. popstate에서 또 부르면
  한 칸 더 나가 페이지를 떠난다.
