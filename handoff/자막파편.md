### 실측 재현 (수정 전)
칸 4.4초, "요거트, 계란, 전분으로 만드는 일본식 요거트 식빵, 지금 확인해보세요!"
```
0.40s  요거트        ← 못 읽는다
0.27s  계란         ←
2.13s  전분으로 만드는 일본식 요거트
0.27s  식빵         ←
1.33s  지금 확인해보세요!
```
4번 칸 "끝!"도 0.25초.

### 원인 두 겹
1. **쉼표에서 무조건 끊었다** (`video_assemble.py` `sent_break`)
   `cur[-1].endswith((".", "?", "!", "…", ",", "、"))` — 나열형("A, B, C")에서 1~2자 파편 양산.
   ★연결어미(`_CAP_LEAD_MINCHARS=4`)·머리단어(`_CAP_HEAD_MINCHARS=4`)에는 **같은 방식의
   최소 글자수 방어가 이미 있었는데 쉼표에만 빠져 있었다.**
2. **`_CAP_MIN_DUR = 0.25초`** — 사람이 읽을 수 있는 하한이 아니라 사실상 없는 값.

### 고친 것 (①②를 같이 — ①만 하면 "느려졌는데 여전히 이상한" 상태가 된다)
| | 전 | 후 |
|---|---|---|
| `_CAP_MIN_DUR` | 0.25초 | **0.7초** (env `CAPTION_MIN_DUR`) |
| 쉼표 끊기 | 무조건 | **앞 구절 6자 이상일 때만** (`_CAP_COMMA_MINCHARS`, env `CAPTION_COMMA_MINCHARS`) |

문장 끝(`. ? ! …`)은 **짧아도 끊는다** — 문장 경계는 지켜야 하므로 쉼표와 분리(`hard_break`).

## 2026-08-17 2차 — 나열이 **중간에서** 잘리던 것 + 하한 1.0초 (A+B)

### 지시
사장님: "CTA쪽 바바 / 아침/빵/퐁신 다 따로따로 너무 휙휙 지나가"

### 1차가 불충분했던 이유 (내 앞 보고 정정)
1차에서 "근본 해결"이라고 했는데 **짧은 나열만** 해결됐다. 항목이 4개 이상이면 여전히 깨졌다:
```
0.87s  아침, 풍신        ← 누적 6자(_CAP_COMMA_MINCHARS)에 닿는 순간 끊긴다
1.45s  빵, 나도 중 댓글
0.72s  남겨주시면
```
`_CAP_COMMA_MINCHARS`는 **누적 글자수** 기준이라, 나열이 길면 중간에서 두 동강 난다.
게다가 통과해도 `_CAP_TARGET(14자)`·`_CAP_MAX_WORDS(4어절)`가 **대신 끊는다**.

### 고친 것
| | 1차 | 2차 |
|---|---|---|
| `_CAP_MIN_DUR` | 0.7초 | **1.0초** (B) |
| 나열 처리 | 최소 글자수만 | **나열 이어가기** 추가 (A) |

**(A) 나열 이어가기** — 구절이 '짧은 항목들이 쉼표로 이어진 나열'이면(항목 2개 이상,
각 항목 `_CAP_LIST_ITEMCHARS(4자)` 이하) 한 줄 폭 `_CAP_LIST_MAXCHARS(18자)`까지 계속 붙인다.
★**이때 `room`·`under_cap`도 함께 풀어준다** — 안 그러면 글자수·어절수 상한이 대신 끊어
같은 자리에서 잘린다(실측으로 발견. 이걸 빼먹으면 A가 통째로 무력화된다).
