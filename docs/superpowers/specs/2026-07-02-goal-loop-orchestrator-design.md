# 골-루프 오케스트레이션 시스템 설계

- 작성일: 2026-07-02
- 대상 하네스: 로또의 주식 (주식 리서치 + 유튜브 제작)
- 첫 구현 골: **아침 시장 브리핑**
- 상태: 설계 확정 (구현계획 대기)

---

## 1. 목적

"목표(골)를 주면 스스로 루프를 돌며 스킬·서브에이전트를 오케스트레이션해 결과물까지
만들어내는 상위 시스템"을 만든다. 한 번에 만능 시스템을 만들지 않고 **하나의 골-루프를
완성해 증명**한 뒤, 같은 골격으로 다른 골(유튜브·투경)로 확장한다.

이 문서는 **첫 골 = 아침 시장 브리핑**의 골-루프를 정의하되, 재사용 가능한 골격으로
설계한다.

### 사전 감사 결론 (2026-07-02 스킬 스프롤 감사)
- 데이터·리서치·퍼블리시 스킬(ingest-pipeline·report-pipeline·market-analyze·daily_scenario)은
  이미 원자적·멱등이라 오케스트레이터 도구 노드로 바로 활용 가능.
- 영상제작 3인방(yt-make-video·yt-gemini-pipeline·yt-planner)은 오케스트레이션+생성+정책판단+HITL이
  뭉쳐 있어 "유튜브 골"을 얹기 전 해체 필요. (본 문서 범위 밖, 후속)

## 2. 확정된 핵심 결정

| 항목 | 결정 |
|------|------|
| 첫 골 | 아침 시장 브리핑 (데이터 스킬이 이미 원자적이라 최단 증명) |
| 자율성 경계 | **하이브리드 게이트** — 평소 자동 발행, 이상징후 시에만 멈추고 사장님 확인 |
| 루프 의미 | **품질루프 + 복원력** — 자기검증→미달이면 개선 반복 + 단계 실패 시 재시도·우회 |
| 실행 방식 | **서버 파이썬 오케스트레이터 데몬 + Gemini 품질루프** (2026-07-02 수정) — 무인 08:00 잡은 Claude 세션 의존 불가라 항상 켜진 Lightsail 서버에서 기존 데몬패턴(_summary_prewarm)으로 실행. 브리핑 생성은 이미 있는 `studio_pipeline.generate_briefing` 재사용. Claude는 설계·구현만, 매일 실행은 서버가 자율 |

> **런타임 변경 사유(2026-07-02)**: 초안은 "Cron→Claude Workflow"였으나, 무인 아침 잡은 그 시각 Claude 세션이 켜져 있어야만 동작해 신뢰성 부족. Lightsail 서버는 24h 가동 + 이미 `_news_loop`·`_summary_prewarm`·`_ingest_worker` 데몬 스레드 패턴 보유 → 서버 파이썬 오케스트레이터로 결정. 품질 자기검증은 Gemini가 담당(Claude 토큰 0). 조사 결과 브리핑 생성기가 이미 3개(generate_briefing·morning_briefing.py·daily_scenario.py) 존재 → v1은 "생성"이 아니라 그 위의 **오케스트레이션 껍데기**(검증·품질루프·게이트·스케줄·수동발행)만 구현.

## 3. 아키텍처 (3층)

```
[골 스펙]  goals/morning_brief.yaml        ← 목표를 데이터로 정의
   · trigger: 평일 08:00 (KST)
   · deliverable: 브리핑 카드(PNG) → 텔레 채널
   · quality_bar: 수치+명확판단 / 양면론·관망 금지 / 날짜검증 V1~V5 / 출처인용 / 차별화인사이트
   · anomaly_rules: 지수 ±3%↑ 급변 / 데이터 최신일≠전일(공백) / 날짜검증 실패 / 수치 모순
   · escalation: 사장님 개인 텔레 미리보기 + 대시보드 "대기 브리핑" 수동 발행
        │
[오케스트레이터]  workflows/morning_brief.js   (Cron이 호출)
   Stage0  데이터수집 + 1차 드래프트   → Python/Gemini (daily_scenario.py 재사용)  [토큰0]
   Stage1  검증 (날짜 V1~V5·신선도·모순) → Claude 서브에이전트 → 이상플래그[]
   Stage2  품질루프                    → Claude: 채점→미달항목만 개선 재생성, 최대 3회
   Stage3  게이트                      → 이상플래그 有→에스컬레이션 / 無→Stage4
   Stage4  발행                        → 브리핑카드 생성(studio_pipeline) → 텔레 전송
        │
[루프 엔진]  Cron(평일 08:00) 발화 + 단계 실패 시 재시도·우회(복원력)
```

**설계 원칙**: 무거운 Stage0은 기존 Python 자산 재사용 → 토큰 0. Claude는 판단이 필요한
Stage1~3에만 투입. (사장님 토큰절약 원칙과 일치)

## 4. 컴포넌트 상세

### 4.1 골 스펙 `goals/morning_brief.yaml`
목표를 코드가 아닌 데이터로 선언. 필드:
- `trigger`: cron 표현식 + 요일 필터(평일·장 열리는 날)
- `deliverable`: 산출물 유형(브리핑 카드) + 목적지(텔레 채널 ID)
- `quality_bar`: 체크리스트 항목 배열 (§4.4)
- `anomaly_rules`: 이상징후 규칙 배열 (§4.3)
- `escalation`: 에스컬레이션 채널(사장님 개인 텔레) + 대기 큐 위치
- `loop`: 최대 반복 횟수(기본 3), 단계별 재시도 횟수

### 4.2 오케스트레이터 `workflows/morning_brief.js` (Workflow 스크립트)
결정론적 제어흐름. 각 Stage는 순수 함수처럼 입력→출력 계약.
- **Stage0** (Python subprocess): `daily_scenario.py` 호출 → `{data_bundle, draft}` 반환.
  데이터 소스: atoms.db·wisereport·KIS·텔레·블로그(기존 파이프라인).
- **Stage1** (Claude 서브에이전트, schema): draft+data → `{anomaly_flags[], date_check, freshness}`.
- **Stage2** (Claude, while 루프): draft → 채점(§4.4) → 미달항목 개선 재생성 → 통과 or maxIter.
- **Stage3** (게이트, 순수 로직): anomaly_flags 비었으면 Stage4, 아니면 escalate().
- **Stage4** (발행): `studio_pipeline.generate_briefing` → 카드 PNG → 텔레 전송.

### 4.3 게이트 + 에스컬레이션 (HITL)
```
이상징후 無 → 채널 자동 발행 (완전 자율)
이상징후 有 → 채널 발행 중단
            → 사장님 개인 텔레로 초안 + ⚠️이상사유 전송
            → 대시보드 "대기 브리핑" 1건 등록 → 사장님 검토 후 [발행] 수동 클릭
```
- 이상징후 초기값: 코스피/코스닥 ±3%↑ 급변 · 데이터 최신일≠전일 · 날짜검증 실패 · 수치 모순 플래그
- v1 승인 방식: 복잡한 봇 리플라이 플로우 대신 **대시보드 발행 버튼**(딸깍 스튜디오에 "대기 브리핑 발행" 액션 추가). 오발송 0.

### 4.4 품질 루프 채점표 (Stage2)
사장님 기존 원칙을 기계 채점표로 (`feedback_briefing_card_quality`, `feedback_briefing_date_verification` 기반):
- ☐ 수치 포함 (막연한 서술 금지)
- ☐ 명확한 판단 (**양면론·"관망" 금지**)
- ☐ 날짜검증 V1~V5 통과
- ☐ 출처 인용
- ☐ 차별화 인사이트 (유저 오실레이터·수급빈집 데이터 활용)
루프: 생성→채점→미달 항목만 개선 재생성→최대 3회→통과분을 게이트로.

### 4.5 루프 엔진 (스케줄 + 복원력)
- **정기 루프**: Cron(평일 08:00 KST) → 오케스트레이터 발화.
- **복원력**: 각 Stage 실패 시 재시도(기본 2회)·우회. 최종 실패 시 사장님 에스컬레이션(품질 미달과 동일 경로).

## 5. 확장 (일반화)
- `goals/*.yaml` + `workflows/*.js`는 **재사용 템플릿**.
- 후속 골: **유튜브 영상 골**(영상 3인방 해체 선행), **투경 모니터링 골**.
- Cron + 게이트 + 품질루프 + 에스컬레이션 엔진은 골 간 공통 골격으로 재사용.

## 6. 범위 (YAGNI)
### 이번 범위 (v1)
- 아침 브리핑 골 1개 end-to-end (Stage0~4)
- 하이브리드 게이트 + 대시보드 수동 발행 버튼

- 골 간 우선순위/자원 배분
