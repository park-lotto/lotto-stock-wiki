## ✅ P2 완료 (2026-07-29, 집PC — subagent-driven development, Task1~5)
**설계서 §3 P2 원안("whisper 세그먼트를 시각컷으로 재베이스")을 재조정**했다 — 실측 결과 대본 생성 단계(`edit_plan.py:_build_inventory`)엔 영상 파일 경로가 없어 그 자리서 ffmpeg를 못 돌린다. 대신 **추출 단계(`script_extract.py:extract_script`, 이미 video_path 보유)에서 컷+모션을 계산해 seg마다 `motion_level` 필드를 미리 박아 DB(`segments_json`)에 저장**하는 방식으로 바꿨다. 인벤토리 seg_id 체계는 완전 불변.

- **T1** `scene_cut.map_segments_to_motion_levels(segments, cuts_labeled, fps)` — seg-컷 교집합 최대 매핑 순수함수. 동률은 먼저 나온 컷(시간순 앞쪽) 채택.
- **T2** `script_extract._assign_seg_ids(video_id, raw_segments, motion_map=None)` — motion_map(`{seg_id: level}`)을 받아 `motion_level` 필드 주입. 기본값 `None`이라 하위호환.
- **T3** `_boundary_hint` 반환형을 `str`→`(hint, cuts, fps)`로 확장(detect_cuts 중복 호출 방지) + `_compute_motion_map` 신설 + `extract_script` 배선. frame_motion은 별도 1회 더 돈다(총 ffmpeg 2패스 — 3패스에서 줄인 것).
- **T4** `edit_plan._build_inventory`가 `seg_map`과 프롬프트 라인(`| 모션:{level}`)에 motion_level 노출. **`scene_desc` 문자열 자체는 완전 불변** — `_claim_key`가 scene_desc를 토큰화해 앵커 dedup 키로 쓰므로, 모션 정보를 문자열에 섞으면 무관한 세그먼트끼리 오염될 위험이 있었음(설계 단계에서 발견, 코드로 격리).
- **T5** `_dedup_anchors`가 motion_level 필드에 영향받지 않음을 회귀 테스트로 고정.
- **게이트**: 커밋 `23eb1e388`~`f39e38970`. `python -m pytest shopping_shorts/ -q` 전체 실행 결과 14 failed(apify_client 6·tiktok_search 2·mix_pipeline 4·edit_plan_build 2) + 2540 passed. **14건 전부 base(35598ce86, P2 시작 전)에서 `.env` 실키로 대조 재현 — 사전 존재 결함, P2발 신규 회귀 0건** 확인(worktree로 직접 대조).
- **각 태스크 spec-reviewer + code-quality-reviewer 통과**(Ready to merge: Yes, Critical/Important 0건 — 리뷰가 짚은 사소한 docstring 문구는 즉시 반영).

## ⚠️ 함정(다시 밟지 말 것)
- `_apply_hook_inpoint`는 반드시 try/except·유출0(소스 밖 금지)·실패시 원위치 — 렌더 안 죽인다.
- produce.html의 `_renderMixReviewBody`는 리프레시 회귀테스트(node로 함수 부분집합 평가)를 타므로 **외부 함수 의존 금지**(인라인).
- 추출 파이프라인은 인스타수집·AI픽자동적재 세션이 동시 수정 → **트랙 격리 + 어댑터 최소침습** 필수.
- **`_build_inventory`류 함수를 건드릴 때 `scene_desc` 문자열에 아무것도 섞지 마라** — `_claim_key`/`_is_face_seg`가 그 문자열을 그대로 읽는다. 새 메타데이터는 항상 별도 dict 키로.
- **`python -m pytest shopping_shorts/` 전체 게이트는 `.env`(실키) 유무에 따라 결과가 달라진다** — `test_edit_plan_build.py::test_build_edit_plan_exhausted_returns_empty`처럼 `_current_key_and_idx`만 monkeypatch하고 `key_vault` 캐스케이드(`_vault_call`이 쓰는 `get_live_keys_cascade`)는 안 막는 테스트가 있어, 실키가 있으면 진짜 API 호출이 나가 실패한다. 이건 **P2가 만든 게 아니라 원래 있던 결함** — 회귀 판정 시 `.env` 유무를 맞춰서 base와 대조할 것(이번엔 worktree로 직접 검증함).
