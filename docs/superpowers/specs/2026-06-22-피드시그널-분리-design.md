# 스탁브레인 — 피드 / 시그널 2서비스 분리 설계

- **작성일**: 2026-06-22
- **상태**: 설계 합의 → 구현 계획 인계 대기
- **기반**: 2026-06-21-stockbrain-saas-dashboard-design.md (MVP 배포 완료분 위에 얹음)
- **목적**: 기존 단일 대시보드를 성격이 다른 **2개 서비스**로 분리한다. 정보 소비형(`/feed`)과 매매 판단형(`/signal`). feed는 소스 단계별 잠금 해제(Tier), signal은 독립 접근권한으로 판매한다.

---

## 1. 분리 결정의 근거

| | `/feed` (정보 소비) | `/signal` (매매 판단) |
|---|---|---|
| 목적 | "오늘 뭐가 있었나" — 읽고 끝 | "오늘 사도 되나" — 행동 결정 |
| 사용 시점 | 수시 (퇴근 후·점심 등) | 아침 장 시작 전 1회 |
| 데이터 | 5소스 텍스트 흐름 | 태린이 엑셀 수치 + 수급 신호 |
| 성격 | 정보성 | 비정보성 (의사결정 도구) |
| 판매 | 소스 단계 Tier 1~5 | 독립 접근권한 (별도 상품) |

→ 한 화면에 억지로 합치면 둘 다 어중간해진다. **별도 페이지**로 분리하되, 같은 서버·같은 로그인(JWT 1세트)·같은 DB를 공유한다.

## 2. URL / 페이지 구조

```
같은 서버 (3.39.179.148:8080), JWT 1세트, DB 공유

/feed    — 정보 소비 대시보드 (기존 MVP 발전형)
           소스 단계별 Tier 잠금 해제
/signal  — 매매 판단 도구 (신규, 별도 페이지)
           태린이 3단 깔때기 + 향후 확장
```

- 코드베이스 1개, 로그인 1번. 상단에서 `/feed` ↔ `/signal` 전환.
- 잠긴 영역은 흐리게 + 🔒 → 클릭 시 업그레이드 안내(FOMO).

## 3. 권한 모델

유저 DB에 컬럼 2개만 추가:

| 컬럼 | 값 | 의미 |
|------|-----|------|
| `feed_tier` | 1~5 | feed 소스 단계 잠금 해제 수준 |
| `signal_access` | bool | signal 페이지 접근 여부 (독립 상품) |

**feed_tier 단계 (누적 잠금 해제):**

```
Tier 1  ─ 뉴스
Tier 2  ─ + 블로그
Tier 3  ─ + 유튜브
Tier 4  ─ + 텔레그램
Tier 5  ─ + 리포트   (= feed ALL)
```

**signal_access:** feed와 독립. signal만 구독 / feed만 구독 / 둘 다 모두 가능.

- 설정은 기존 수동 등록(B안) 그대로 — 관리자 패널에서 유저별 `feed_tier`·`signal_access` 지정.
- 잠긴 탭도 화면엔 보임(흐림+🔒) → 상위 상품 유도.

## 4. `/feed` — 정보 소비 대시보드

기존 MVP의 피드 탭을 발전. 어제 합의한 3컬럼 레이아웃 채용(2026-06-22 NEXT_SESSION 트랙 A).

- **왼쪽** = 소스 아이콘 탭(📰뉴스/📝블로그/▶️유튭/💬텔레/📊리포트) + 하위 분류(키워드·블로거·채널·섹터별), 키워드 대표 1개 + 아코디언. 안읽음 카운트, 신호순/시간순 정렬.
- **가운데** = 본문 상세 + AI 요약. 소스별 본문 성격 다름(뉴스=채널묶음, 유튭=타임스탬프, 리포트=목표가 전→후 카드). 버튼 = **복사만**.
- **오른쪽** = 5소스 섹터별 종합(객관 정보만: 섹터명+총신호수, 5소스 점 카운트, 1줄 요약, 최다언급 종목). ※ 목업 미완 — 작게 분할 제작.

**핵심 원칙 (어제 확정, 유지):**
- 위키 = 100% 백엔드. 화면에 "위키" 노출 없음 → AI 요약 품질 재료로만.
- 비용 = 인제스트 시점 선생성(Gemini 건당 1회 → DB insight 캐시 → 유저 클릭은 DB읽기, API 0원). `atom_pipeline.py STEP7 insight_generate` 추가.
- 요약 = 액션형("그래서 뭘 사라는데?"). 출력 core/stocks(매수·관망·회피)/watch/risk. **우리 판단 아니라 "출처가 한 말" 추출**.
- 단순·객관만. 확증/반증·과열 등 주관 판정 전부 폐기.

소스별 Tier 잠금 = 왼쪽 소스 탭에서 `feed_tier` 미만 소스는 🔒.

## 5. `/signal` — 매매 판단 도구 (신규)

어제 합의한 **3단 깔때기** = 톱다운 의사결정 스토리.

```
STAGE 1.  오늘 투자해도 되는 날?   → GO / ⚠️경계 / 🔴NO
STAGE 2.  GO라면 — 어떤 섹터로?    → 미장선행 × 태린이주도 교집합 = 1~3개
STAGE 3.  그 섹터 안 — 어떤 종목?   → 9점표(수급빈집+RS+컨센+가속화)
+ 사이드: 환율·금리·유가·구리·비트코인 (보조 컨텍스트 위젯)
```

### STAGE 1 — GO 판정 룰 (결정: B 채택)

태린이 매뉴얼 반영 룰:
```
GO    = 미장 +0.5%↑  AND  VIX<18  AND  악재 없음  AND  TGA 안정  AND  Fed D-30 외  AND  오실레이터 과매도 아님
⚠️경계 = 일부 조건 미달 (조건별 사유 표시)
🔴NO  = 미장 급락 OR VIX 급등 OR 명확한 악재
```
판정 근거를 조건별로 펼쳐 표시(블랙박스 금지 — 왜 GO인지 보임).

### STAGE 2 — 섹터 교집합

미장 11섹터 강세 × 태린이 소르티노 주도섹터 = 교집합 1~3개.
⚠️ **섹터 매핑 테이블 정의 필요**(구현 단계 작업): 미장 "Semiconductors" = 태린이 "반도체" = wiki "L5_섹터/반도체". 셋 이름 다름 → 매핑 1회 정의.

### STAGE 3 — 종목 (펼침: a 채택)

STAGE 2 **1순위 섹터만 자동 펼침**. 나머지 섹터는 클릭 시 펼침.
9점표(태린이 매뉴얼 v1 그대로): 수급빈집 2점(필수) + 수출🔴/판가/어닝서프/컨센신고가/미국커플링/정책/D-30 각 1점.

### 종목 클릭 드릴다운 4섹션
A. 9점 스코어보드 시각화 → B. 60일 추이 차트(등급/RS/컨센/주가) → C. 태린이 멘트 타임라인 → D. 위키 자동 인사이트

### 데이터 출처 (자산 거의 보유)
- STAGE 1 → `wiki/L1_글로벌유동성/` + `wiki/L2_미국시장/` + 뉴스 ingest
- STAGE 2 → L2 미국 11섹터 × 태린이 소르티노 × `wiki/L5_섹터`
- STAGE 3 → 태린이 엑셀 5종(빈집/RS/컨센/가속화/일정), `scripts/ingest_excel.py`(07:50 자동)
- 검색 안 되는 데이터(소르티노·ETF비중·일정/수주잔고) → 메인 검색 대상 X, **상단/사이드 위젯**

## 6. 아키텍처

**원칙 유지: 기존 크롤링봇·main_v2 무수정, 신규 파일만.** 기존 `dashboard_server.py`(FastAPI:8080) 위에 라우트 추가.

```
dashboard_server.py (FastAPI :8080, JWT 1세트)
 ├─ GET /feed             → feed_tier 기준 소스 잠금 적용 SPA
 ├─ GET /api/feed/*       → 5소스 필터 콘텐츠 (insight 캐시 DB읽기)
 ├─ GET /signal           → signal_access 검증 SPA
 ├─ GET /api/signal/stage1  → GO 판정 (매크로+뉴스 집계)
 ├─ GET /api/signal/stage2  → 섹터 교집합
 ├─ GET /api/signal/stage3  → 종목 9점표
 ├─ GET /api/signal/stock/{code}  → 드릴다운 4섹션
 └─ /api/admin/*          → feed_tier·signal_access 지정
```

- 빌드 도구 없음(순수 HTML/JS/CSS, 검정+골드+Instrument Serif).
- signal 데이터는 엑셀 인제스트(07:50) 결과 DB를 읽기만. 무거운 AI 호출은 인제스트 시점 선생성·캐시.

## 7. 범위 / 단계

**이번 범위:**
- 권한 컬럼 2개 추가(`feed_tier`, `signal_access`) + 관리자 패널 지정 UI
- `/feed` 소스 단계 잠금(🔒) + 3컬럼 레이아웃
- `/signal` 3단 깔때기 골격 + STAGE 1 GO룰(B) + STAGE 3 펼침(a)

**범위 밖 / 후순위:**
- feed 오른쪽 5소스 종합 패널 목업 (작게 분할 제작)
- 섹터 매핑 테이블 실데이터 정의 (구현 단계)
- 요약 프롬프트 날카롭게 튜닝 (구현하며 실데이터)
- 결제 자동화 (수동 등록 유지)

## 8. 테스트 (검증 항목)
- `feed_tier`별 소스 잠금이 정확히 적용(Tier 2 유저는 유튜브~리포트 🔒).
- `signal_access=false` 유저가 `/signal`·`/api/signal/*` 접근 차단.
- feed / signal 권한 독립(signal만 구독한 유저가 feed 막힘, 반대도).
- STAGE 1 GO 판정이 조건별 근거와 함께 반환.
- STAGE 3가 1순위 섹터만 자동 펼침.
- 격리: 고객A 키워드/콘텐츠가 고객B에 미노출(기존 검증 유지).

## 9. 확정 요약

| 항목 | 결정 |
|------|------|
| 구조 | 1서버·1로그인·1DB / 2페이지 `/feed` `/signal` |
| 권한 | `feed_tier 1~5` (소스 단계 잠금) + `signal_access` (독립 상품) |
| feed | 3컬럼, 액션형 AI요약, 위키=백엔드, 비용=선생성 캐시 |
| signal | 3단 깔때기 / GO룰=B(태린이 매뉴얼) / 펼침=a(1순위 자동) |

| 판매 | feed 단계 사다리 + signal 별도 = 가격 조합 자유 |
