## ✅ 완료 — 생성 순응 검열 (빼쓰기 쪽) 라이브 배포

넣기(수집) 검열에 이어 **빼서 쓸 때 은행이 실제로 대본을 형성했는지** 매 job 관측하는 검열을
설계→구현→배포까지 완료. origin/main 병합 확정(`b0f9128c9 Merge branch 'track/수집검열'`, 신규 실패 0).

- **스펙**: `docs/superpowers/specs/2026-07-23-생성순응검열-design.md`
- **플랜**: `docs/superpowers/plans/2026-07-23-생성순응검열.md` (SDD 8태스크, 전부 리뷰 통과)
- **구현 (전부 라이브)**:
  1. `bank_assemble.bank_usage_snapshot` — 생성 시 은행 주입 내역 계측(스파인·부품 수·`empty`).
  2. `bank_usage_audit.py`(신규) — `structural_conformance`(강오프너·CTA·비트·표절, 결정적)·
     `judge_snapshot`(judge 점수)·`compute_usage_audit`·`usage_health`(신호등 🟢🟡🔴).
  3. `bank_compliance.py`(신규) — `judge_compliance` 샘플 LLM 순응 채점(아크/부품 따랐나).
  4. `store.append_bank_usage` — `bank_usage_recent` 링버퍼(최근 K=50).
  5. `mix_pipeline` 배선 — 은행 주입된 job 중 **N=10에 1편** LLM 샘플, 집계→`bank_usage_audit_last`.
     **회귀 0**: `bank_enabled != "1"`이면 완전 no-op.
  6. `app.py` `/api/bank/ingest_report` payload에 `usage_audit` 첨부.
  7. `static/index.html` `_renderBankPanel`에 "🎬 생성 순응" 섹션.
- **검증**: 로컬 42 passed(신규 4파일+회귀 3파일), 대시보드 node grounding 관측, 최종 whole-branch
  리뷰(opus) READY TO MERGE(4 seam·생산/소비 키 일치·회귀0 확인), finish 게이트 통과(기준선8 그대로).

### ★ 사장님 라이브 육안 (3분 뒤)
수집 화면에서 **'지금 수집'** 후 은행 패널에 `🎬 생성 순응(최근 N편) 🟢/🟡/🔴 …` 줄이 뜨는지.
⚠️ **생성 이력이 있어야** usage_audit가 채워짐(영상 믹스를 1편+ 만든 뒤라야 데이터가 쌓임).

## ⏭ NEXT — 흡수 성공률 개선 (넣기 쪽, 별개 이슈)

이번 스코프에서 뺀 후속:
- `ingest_collected` top_n=100 상한 상향 검토.
- 검열 metric에서 **키실패 vs 빈추출(비한국어·짧은 캡션)** 분리 → 신호 정확도 상승.
- 서버 전용키 16개중 11 라이브(5 일일소진). 로테이션 켜졌으니 페이싱(호출 간격)만 주면 더 오를 여지.

### 알려진 한계 (생성 순응 검열)
- `usage_audit` 패널은 수집 폴링(status done)에 얹혀 렌더 → 수집 안 하면 생성 순응만 따로는 안 보임.
  항상노출 원하면 별도 폴링/엔드포인트로 분리(후속).
- judge는 `backbone_base` 모드에서만 켜져 `judge_avg`는 그 모드 job에서만 채워짐(None-safe, 설계 의도).
