# 장면꾸미기 정밀 프리셋 연속 제작 계획

## 1. 목표

레퍼런스 랭킹에서 확보한 훅·본문 캡처를 단순 이미지 썸네일이 아니라 문구를 바꿀 수 있는 정밀 프리셋으로 전환한다.

- 기본 상태: 원본 캡처와 픽셀 단위로 동일하게 표시
- 편집 상태: 채널명·훅 제목·보조 제목·자막 등 실제 존재하는 요소만 편집
- 자동 적용: 대본 분석 결과를 템플릿 슬롯에 배치
- 사용자 화면: 프리셋 선택 → 문구 확인 → 완성
- 고급 위치·폰트·효과 설정은 접어서 숨김

## 2. 현재 실측 자산

| 항목 | 수량 | 상태 |
|---|---:|---|
| 측정 스타일 | 102개 | `final_styles.json` |
| 훅 프레임 | 102장 | 확보 |
| 본문 프레임 | 101장 | 확보 |
| 완전한 훅+본문 페어 | 101개 | 제작 대상 |
| 훅만 있는 불완전 페어 | 1개 | 본문 확보 전 보류 |
| 로컬 폰트 | 41개 | 우선 자동 대조 |
| 정밀 구현 완료 | 1개 | 숏템 기본형 |
| 별도 초안 | 1개 | 이븐쇼핑 정밀 작업판 |

## 3. 핵심 원칙

1. 프리셋별 CSS를 손으로 101벌 만들지 않는다.
2. 원본 좌표·색·폰트·효과는 하나의 프리셋 JSON에만 기록한다.
3. 훅과 본문은 같은 프리셋 안의 서로 다른 프레임 규칙으로 관리한다.
4. 템플릿에 없는 문구 슬롯은 만들지 않고 빈값으로 둔다.
5. 기본 미리보기는 원본 픽셀을 보존하고, 문구 변경 시 편집 레이어를 활성화한다.
6. 검수 전 상태는 `draft`, 검수 통과는 `verified`, 실제 사용자 노출은 `published`로 분리한다.

## 4. 제작 파이프라인

### 단계 A — 공용 정밀 프리셋 엔진

- `preset.schema.json`을 실제 101개 변환에 맞게 확정한다.
- 훅/본문별 슬롯을 데이터로 선언한다.
  - `channel`
  - `hook_title_1`
  - `hook_title_2`
  - `support_title`
  - `body_title`
  - `caption`
  - 템플릿별 추가 슬롯
- 좌표는 360×640 기준 정규화 값과 실제 픽셀값을 함께 저장한다.
- 단색, 다중 그라데이션, 외곽선, 다중 그림자, 글자 간격, 행간을 공용 렌더러가 처리한다.
- 프레임별 `fields` 목록으로 오른쪽 편집 패널을 자동 생성한다.

### 단계 B — 자동 측정

각 훅·본문 프레임에서 아래 값을 자동 추출한다.

- 영상 시작 Y 좌표
- 상단 밴드·본문 밴드 경계
- 대표 RGB와 행별 색 변화
- 선형 그라데이션 정지점
- 텍스트 바운딩박스
- 글자색·외곽선색·외곽선 두께
- 그림자 방향·거리·번짐·불투명도
- 정렬, 행간, 자간
- 로고·아이콘·프로필 이미지 영역

### 단계 C — 폰트 대조

1. 보유한 41개 폰트를 먼저 전수 렌더한다.
2. 글자 외곽 실루엣과 폭·높이를 원본과 비교한다.
3. 일치도가 낮은 템플릿만 웹에서 폰트를 추가 확보한다.
4. 확보한 폰트는 파일명·라이선스·SHA-256을 프리셋에 기록한다.
5. 정확한 폰트를 찾지 못한 경우 임의로 완료 처리하지 않고 `font_unresolved`로 남긴다.

### 단계 D — 편집 가능 레이어 생성

- 원본에서 고정 영역과 편집 영역을 분리한다.
- 채널명·제목·자막 배경을 실제 RGB/그라데이션으로 복원한다.
- 원본 문구로 렌더했을 때 캡처와 겹쳐지는 좌표를 확정한다.
- 문구가 길어지면 템플릿별 규칙에 따라 축소, 줄바꿈, 말줄임, 경고 중 하나를 적용한다.
- 채널명처럼 한 프레임에 여러 번 등장하면 모든 인스턴스를 한 입력값에 연결한다.

### 단계 E — 자동 검수

각 프리셋은 360×640에서 훅과 본문을 렌더하고 원본과 비교한다.

- 영역 경계 오차: 2px 이하
- 주요 RGB 채널 오차: 3 이하
- 텍스트 바운딩박스 오차: 2px 이하
- 누락 슬롯: 0개
- 브라우저 콘솔 오류: 0개
- 훅/본문 전환, 프리셋 전환, 모든 입력 필드 수정 테스트 통과

오차가 기준을 넘으면 자동으로 `draft` 유지하고 다음 검수 목록에 남긴다.

## 5. 실행 순서

### 1차 — 엔진 고정 및 대표 6개

현재 UI에 노출된 대표 프리셋부터 완성한다.

1. 숏템 기본형 — 완료 기준 재검수
2. 신비아이템
3. 부시리
4. 지식배송
5. 사길잘했다
6. 헤븐쇼핑

대표 6개로 서로 다른 헤더·폰트·본문 띠·강조색 유형을 공용화한다.

### 2차 — 유형별 10개 배치

- 정보형
- 리뷰형
- 쇼핑형
- 이슈형
- 채널 헤더형
- 헤더 없는 자막형

한 번에 10개씩 변환하고 자동 검수 결과를 남긴다. 사용자 컨펌을 기다리지 않고 통과한 프리셋은 다음 배치로 계속 진행한다.

### 3차 — 전체 101페어 완주

- 검수 통과 순서대로 `verified` 누적
- 폰트 미확정·본문 누락·구조 인식 실패만 별도 예외 목록으로 분리
- 실패 때문에 전체 배치를 멈추지 않는다.

### 4차 — 실제 장면꾸미기 연결

- A 3단 편집기를 사용자 기본 화면으로 연결
- B 페어 갤러리를 전체 프리셋 탐색 화면으로 연결
- C 검수 스튜디오는 관리자 전용으로 분리
- 대본 분석 결과를 프레임별 슬롯에 자동 배치
- `published` 프리셋만 실제 사용자에게 노출

## 6. 무컨펌 진행 규칙

사용자 확인 없이 다음 작업을 연속 진행한다.

- RGB·좌표·폰트·효과 측정
- 프리셋 JSON 생성
- 폰트 다운로드와 로컬 보관
- 훅/본문 편집 레이어 구현
- 브라우저 렌더와 자동 비교
- 실패 프리셋 분리 후 다음 항목 계속 진행
- 트랙 브랜치 커밋과 푸시

다음 경우에만 전체 진행을 멈춘다.

- 원본 프레임 자체가 없어서 복원이 불가능한 경우
- 폰트 라이선스상 서비스 사용이 불가능한 경우
- 실제 서비스 데이터 계약을 바꿔야 하는 경우
- 배포 또는 main 병합처럼 별도 운영 판단이 필요한 경우

## 7. 작업 산출물

- 정밀 프리셋 JSON 101개
- 훅/본문 편집 레이어 정의
- 사용 폰트와 해시·라이선스 목록
- 자동 측정 결과
- 원본 대비 차이 이미지와 검수 점수
- 실패·보류 목록
- 사용자용 페어 갤러리
- 관리자용 검수 스튜디오

## 8. 완료 기준

- 완전한 101개 페어가 모두 `verified` 또는 사유가 기록된 `blocked` 상태
- 사용자 화면에는 검수 통과한 프리셋만 표시
- 모든 프리셋에서 실제 존재하는 문구 필드만 표시
- 채널명·제목·자막 수정이 미리보기에 즉시 반영
- 대본 분석 결과가 훅과 본문 장면에 자동 배치
- 실제 브라우저에서 프리셋 선택부터 완성까지 끝까지 검증
