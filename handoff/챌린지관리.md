## 무엇을·왜

1기 멤버 100명이 **하루 2영상 업로드 챌린지**를 시작(08-24 오픈). 멤버가 올린 영상을
링크로 제출받고, 사장님이 달성현황과 영상을 한 화면에서 확인한다.

**사장님 결정**: 멤버가 링크 직접 제출(자동 채널 크롤 아님) / 영상 정보는 자동 수집 /
관리 화면은 달성현황+영상 탭 2개 / 참가 자격은 1기 멤버만 / 인스타·유튜브·틱톡 /
기간은 admin 설정 / 하루 기준은 **제출한 날짜**(KST).

## 주소

```
멤버   shoppingshorts.duckdns.org/challenge        ← 단톡방에 이 링크를 공유
관리   shoppingshorts.duckdns.org/challenge/admin  ← 관리자만
```

## 설계의 핵심 — 저장 먼저, 수집 나중

링크가 들어온 순간 `challenge_submission` 행이 생기고 **달성 카운트가 확정**된다.
썸네일·조회수는 백그라운드(`BackgroundTasks`)로 나중에 채운다.

**수집 결과에 카운트를 묶지 않는 이유**: 인스타 수집은 수십 초 걸리고 간헐적으로
실패한다. 거기에 카운트를 묶으면 **"멤버는 올렸는데 미달성으로 찍히는"** 사고가 난다.
수집은 장식이고, 카운트의 진실은 `submit_day` 한 곳이다.

`fetch_status`: `pending`(수집 전) · `ok` · `failed`(실패—링크는 남음) · `skipped`(틱톡)

### 2. 가입 즉시 체험 3일 + [확인] 한 번
사장님: "가입되면 승인대기중 쪽에 체험3일 자동, 확인 누르면 고객관리로. 일일이 버튼 누르니 안 좋아."

- `create_customer`의 `trial_event_hours` 기본값 **0 → 72시간**.
  서버 `settings`가 미설정이라 **배포만으로 켜진다**. 0으로 되돌리면 옛 동작.
- `ack_customer` 신설 + `POST /api/admin/ack` — **클릭 한 번**.
  `approve_customer`(프롬프트 3번·결제 기록)와 **분리**했다.
- ★★**가장 중요한 함정**: `access_level`은 체험창(`trial_ends_at`)을
  **`approved_at`이 비어 있을 때만** 본다. `ack`가 `approved_at`만 채우면
  **확인을 누르는 순간 체험이 끊긴다**(사장님 지시와 정반대).
  → 남은 시간을 `full_access_until`로 **이관**한다. 줄이지 않는다(`max`).
- admin 대기 행: `[✅확인]`(체험유지) · `[💳결제승인]`(기간부여) 두 버튼.

실측: 가입 3.0일 → 확인 → 대기실서 사라지고 **3.0일 유지** → 만료 시
`ranking_only`로 잠김 → 중복 클릭 안전. 구글 가입 경로도 동일(게이트가 잡아줌).

### ★핸드오프에 적혀 있던 것이 틀렸다 — 실측으로 정정

이 파일의 "알고 가는 한계"에 **"틱톡은 링크만 저장(단건 조회 함수가 없다)"** 이라고
적혀 있었지만 **사실이 아니었다.** `probe_grab_meta`는 **이미 틱톡 oEmbed 폴백을
갖고 있다**(`media_download.py:104` `if "tiktok.com" in u`). 챌린지 수집부가
스스로 `platform == "tiktok"`을 가로막아 `skipped`로 떨어뜨리고 있었을 뿐이다.

실측(`@tiktok/video/7106594312292453675`): thumbnail ✅ · title ✅ · channel ✅ · views ❌(None)
→ 차단 4줄을 지우니 썸네일·제목·채널이 채워진다. **조회수만 안 나온다**(yt-dlp가
틱톡을 못 뚫는다). 조회수가 없다고 `failed`로 떨어뜨리지 않는다 — meta가 **빈손일
때만** failed다.

> 교훈: 기록은 쓸 당시의 사실이다. "함수가 없다"는 문장을 믿지 말고 **그 함수를 열어
> 봐라.** 이 건은 4줄 삭제로 끝날 일을 "단건 수집기를 새로 만들어야 한다"로 오해하고
> 있었다.

### 영상을 나가지 않고 본다 — 모달 재생

카드를 누르면 플랫폼으로 튕겨 나가 100명을 훑으면 **탭이 100개** 열렸다.
→ 모달에서 바로 재생 + `←` `→` `ESC` 이동 + `1 / N` 표시 + [원본 열기].

- 임베드 주소는 **`challenge.embed_url` 한 곳**에서만 만든다(프론트가 각자 만들면
  플랫폼 판단이 두 벌 — 0순위-B). DB에 저장된 `shortcode`를 넘겨 재사용한다.
- 임베드가 없으면(틱톡 단축링크 `vt.tiktok.com`) **원래대로 링크로 폴백**한다.
- **브라우저 실측**: 틱톡 영상 **실제 재생 확인**(좋아요 98.8K·댓글 1282 표시),
  유튜브·인스타 임베드 로드 확인, ←→ 이동 정상, **콘솔 에러 0건**.

★**예전 '임베드 폐지' 결정에 겁먹지 마라**(memory `project_쇼핑쇼츠_자동화`).
그것은 **검색 결과**를 긁어 보여주는 건이었고 관련성 30~50%가 문제였다.

### `alert()`를 쓰지 않는다

모달이 뜨는 동안 화면이 통째로 멈추고(자동화도 CDP 타임아웃으로 죽는다),
100명을 훑는 흐름에서 매번 확인을 눌러야 해 손이 더 간다 → 상태 문구로 알린다.

### 검증하다 밟은 함정 (다음 세션이 또 밟는다)

| 함정 | 진실 |
|---|---|
| `openapi.json`으로 라우트 확인 | **0바이트다.** 라우트 유무를 못 가른다 |
| HTTP 상태코드로 라우트 확인 | 인증이 먼저 잡아 **없는 경로도 401**이다. 판별 불가 |
| 그럼 뭘로 확인하나 | **`app.py` mtime < 웹 프로세스 기동시각** 이면 새 코드다 |
| `node --check <(...)` | Windows에서 **프로세스 치환이 안 먹는다**. `MODULE_NOT_FOUND`가 나는데 뒤 `&& echo OK`가 붙으면 **거짓 통과**로 보인다 → 임시파일로 검사하라 |
| 배포 후 "왜 안 바뀌나" | `auto_deploy.sh`가 **고객 접속 중이면 웹 재시작을 미룬다**(최대 30분, 그 뒤 강제). 정적파일(HTML/JS)만 먼저 반영되고 **파이썬은 옛 코드**인 구간이 생긴다 |

날짜도 본인들 볼수있게 / 3개 넣는 건 몇 분 늦어도 닫히니까 / 다음날 입력해도
등록시간을 기록해줘 / 연장은 없어 / 영상 내가 지울수있게 권한".

### 무엇이 바뀌었나

| | 전 | 후 |
|---|---|---|
| 화면 | 제출한 것만 목록 | **달력 탭**(기간 30일 전부) + 목록 탭 |
| 한 날짜 | 낸 개수만큼 | **3칸**(목표 2 + 여분 1). 더 내면 늘어남 |
| 빈칸 | 없음 | 누르면 **그 날짜로** 등록되는 입력창이 그 자리에 |
| 시각 | 안 보임 | 🕓 `08-28 21:40 저장` / ⏰ `08-29 14:20 등록 (늦게)` |
| 삭제 | 불가(영영 막힘) | 멤버=자기 것, **사장님=전부** |
| 연속 | 없음 | 🔥 N일 연속 |

### ★핵심 — 날짜가 두 개다. 헷갈리면 카운트가 깨진다

```
submit_day    어느 칸에 들어가나   ← 달성 카운트의 진실. 여기 하나뿐이다
submitted_at  실제로 누른 시각     ← 절대 안 바뀐다. 사장님이 보셔야 하는 값
target_day    빈칸 클릭으로 지정   ← **표시 전용**. 카운트에 절대 쓰지 마라
```

`submit_day` ≠ 등록한 날 → ⏰ '늦게' 배지. **감추지 않는다** — 그날 올린 사람과
나중에 몰아 채운 사람이 구별돼야 한다는 게 이 표시의 존재 이유다.

### 기간 — 서버 DB를 만지지 마라

`challenge_start`/`challenge_end` 입력칸은 **관리 화면 설정에 이미 있다**
(`admin.html:216`). 08-28 ~ 09-26, 연장 없음(사장님 확정).
기간이 비면 달력 탭이 **숨고** 목록 탭만 쓴다(제출은 계속 된다).

⚠️ **기간 밖 제출은 달력에 안 보인다**(목록 탭엔 보인다). 08-28 전 데이터가
있으면 달력에서 사라진 것처럼 보이는데 정상이다.

**설계 골자**

- 저장은 기존 그대로 — **카운트에 절대 안 묶는다**(수집은 장식, 진실은 `submit_day`).
- `challenge_submission`에 컬럼 4개: `comment_text` · `comment_status`
  (none/pending/approved/rejected) · `comment_model` · `commented_at`. **새 테이블 없음.**
- `settings.challenge_comment_auto` = 자동공개 스위치(기본 0). 1로 바꾸면 생성 즉시
  approved → **재배포 없이** 자동공개 전환.
- `video_analysis.coach_comment(thumb_bytes, title, platform)` 신설.
  `subject_tags_vision`과 같은 패턴(lite 모델 `gemini-3.1-flash-lite`·키풀 공유).
- 프롬프트: 칭찬 2 : 조언 1, 3~4문장, **점수·순위·비교 금지**, 못한 점 나열 금지.
- **재료 없으면 생성 자체를 건너뛴다**(썸네일 없음 또는 제목 5자 미만 → `none`).
  재료 없이 지어내는 게 최악이다.
- 관리 화면: 「코멘트 검수」 탭 — 썸네일+제목+**수정 가능한 코멘트 칸**+
  [승인]/[고쳐서 승인]/[버림], 위에 **[보이는 것 전부 승인]**, 기본 정렬 미검수 먼저.
  ★**재생 모달 안에 넣으면** 영상 보면서 바로 승인 = 두 일이 한 동작이 된다.
- 멤버 화면: 자기 제출 목록에 **승인된 코멘트만** 말풍선. 새 화면 없음.

**★키 예산 (이것 때문에 썸네일 방식을 골랐다)**

서버 키 **12개**(`/etc/shopping-shorts.env` 실측). 영상 통째 분석 모델
`gemini-3.5-flash`는 **키당 하루 20건** → 12키 = **240건/일**이 천장인데
챌린지만 200건(100명×2)이면 **제작소·태깅이 통째로 마른다**(태거가 키를 소진해
제작소 EDL이 죽은 실사고 전례 있음). lite 모델은 **키당 500건/일** → 6,000건이라
본업과 안 부딪힌다.

⚠️ **알고 가는 한계**: 썸네일+제목만 보므로 코멘트가 **"썸네일이 시원하네요" 수준으로
