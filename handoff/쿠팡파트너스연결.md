### 결론부터

  | 경로 | 결과 |
  |---|---|
  | httpx / curl_cffi(chrome124 위장) | 403 (홈페이지조차) |
  | Playwright **헤드리스**, 로컬 | 403 |

Webshare 유저명에 `-KR`·`-country-kr`을 붙여 국가지정을 시도했지만 이 플랜은 **고정 독일 출구**라
무시되거나 인증 실패(빈 응답)였다. → 서버에 한국 출구가 없으면 서버는 영영 못 긁는다.

**추가 실측: 쿠팡은 403 말고 "소프트 차단"도 건다.** 몇 분 새 15회쯤 검색하자 status 200에
"사용권한이 제한된 페이지" 안내를 주기 시작했고, **몇 분 쉬니 그냥 풀렸다**. 이걸 "결과 없음"으로
뭉뚱그리면 사장님이 검색어를 바꿔가며 더 두들기게 되므로 문구를 따로 판별한다.

### 그래서 만든 것 — 방향을 뒤집었다(서버가 PC에게 물어본다)
```
[브라우저] ─검색─> [서버 /api/coupang/search] ─큐─> (대기) <─롱폴링─ [사장님 PC 릴레이]
                                                              └ 로컬 크롤 → 결과 POST
```
**PC가 서버로 나간다** — 포트포워딩·공인IP 불필요, 공유기 뒤에서도 그냥 된다.

| 파일 | 내용 |
|---|---|
| `coupang_relay.py` (신규) | 메모리 대기열(`submit`/`take`/`complete`). 타임아웃이면 흔적까지 지운다 |
| `app.py` | `/api/coupang/relay/next`(롱폴링) · `/result` · `/status`. 검색 엔드포인트가 mode=relay면 큐로 |
| `scripts/coupang_relay_client.py` + `쿠팡도우미.bat` (신규) | 사장님 PC에서 켜두는 도우미 |
| `coupang_search.py` | **프로필 유지**(`.coupang_profile`, 쿠키·PCID) + **홈 워밍업** + 키워드 캐시 10분 + 호출간격 3초 + 소프트차단 판별 |
| 테스트 | 릴레이 9건 + 검색 12건 + 엔드포인트 2건 |

### 검증한 것 (실측)
- 릴레이 전 구간: `주방 가림막` → **4.3초 / 23건**, 같은 키워드 재검색 **0.3초**(캐시)
- 소프트 차단 후 3분 쉬고 프로필 유지 경로로 재시도 → 정상 복구 확인
- 실브라우저(produce.html) 카드 그리드·클릭 확정은 앞선 세션에서 확인 완료

### ⏭ 켜는 법 (다음 세션/사장님)
1. **서버** `/etc/shopping-shorts.env`:
   ```
   COUPANG_SEARCH_ENABLED=1
   COUPANG_SEARCH_MODE=relay
   COUPANG_RELAY_TOKEN=<아무 긴 랜덤 문자열>
   ```
   → `sudo systemctl restart shopping-shorts`
2. **사장님 PC**: `setx COUPANG_RELAY_TOKEN "<같은 값>"` 한 번 → 이후 **`쿠팡도우미.bat` 더블클릭**.
   창을 켜둔 동안만 검색이 된다(닫으면 서버가 타임아웃 후 수동 안내로 되돌아간다 — 안 깨진다).
3. 확인: `GET /api/coupang/relay/status` → `online:true`.

### 함정
- ⚠️ 큐는 **메모리**다. 서버 워커를 여러 개로 늘리면 릴레이도 그만큼 붙어야 한다(지금은 단일 워커).
- ⚠️ 릴레이 클라이언트는 내부에서 반드시 `COUPANG_SEARCH_MODE=local`로 강제한다 — 안 그러면
  자기 자신에게 다시 물어보는 무한루프가 된다.
- ⚠️ `.coupang_profile/`은 gitignore. 지우면 "처음 온 손님"이 되어 차단 임계가 낮아진다.
- ⚠️ 파트너스 최종승인이 나면 이 크롤·릴레이는 **통째로 필요 없어진다**(공식 API가 정답).
