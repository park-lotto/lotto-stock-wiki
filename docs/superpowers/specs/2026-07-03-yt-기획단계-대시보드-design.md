# 영상제작 대시보드 — ①기획 단계 (design)

날짜: 2026-07-03

## 배경 / 목표

유튜브 영상제작 전체(기획→대본→리모션→녹음→자막→렌더)를 하나의 대시보드로 묶는 게 최종 목표다.
`scripts/yt_agents/pipeline.py`에 6단계 CLI 파이프라인이 이미 완성돼 있고(체크포인트/재개,
자동 QC 재작업 루프까지 구현됨), 웹 UI만 없다.

이번 스펙은 **①기획 단계만 실제로 동작하게 만드는 것**이 범위다. 나머지 5단계(대본·리모션·녹음·
자막·렌더)는 이후 별도 스펙에서 같은 패턴으로 확장한다. "이 기획페이지에서 어떻게 되는지 이것부터
완성하면서 다음단계 넘어가자"는 사용자 지시에 따른 것.

## 전체 아키텍처 (다음 단계들에도 적용될 큰 틀)

- **완전 독립 페이지** `dashboard/yt.html` (`/yt` 라우트). STOCK BRAIN 공통 네비바에 탭으로 안 넣는다 —
  사용자가 명시적으로 "단독 대시보드"라고 확정함.
- 데이터 저장은 새 DB 없이 기존 `out/yt_pipeline_{pid}/state.json` 그대로 재사용.
- 짧은 단계(기획·대본·자막)는 SSE 실시간 진행바 — `dashboard/studio.html`의 기존 SSE 패턴
  (`data: {type:"step",id,status}` → `setStep()`) 재사용.
- 긴 단계(리모션·녹음·렌더, 최대 1시간)는 백그라운드 잡 + 폴링 — 이번 스펙 범위 밖(기획은 SSE로 충분히 빠름).
- STOCK BRAIN 다크/골드 디자인 시스템 그대로 사용 (`--bg:#0a0a0a`, `--gold:#d4af37`, `--card:#16161a` 등).

## ①기획 페이지 — 화면 흐름 (6단계, 위→아래)

1. **아이디어 입력** — 텍스트 인풋 하나
2. **터진 영상 위젯 (선택사항, 안 써도 기획 진행 가능)**
3. **생성 버튼** — "이 아이디어 + 담긴 레퍼런스로 기획 생성"
4. **생성 진행상황** — `agent_plan.run/qc`의 QC 재작업 루프(`MAX_RETRY=3`)를 SSE로 실시간 표시
   (`시도 N/3 · 점수 X/9 · feedback 텍스트`)
5. **완성된 기획서** — `plan.md` 렌더(marked.js). 제목/씬구조/인용레퍼런스/QC점수 표시
6. **확정** — 3버튼: `✅ 이 기획으로 대본 진행` / `✏️ 기획서 직접 수정` / `🔁 다시 생성`

## 터진 영상 위젯 — 상세 스펙

### 범위 (명시적으로 확정됨)

**영상 검색(기여도·성과도)만.** 다음은 이번 스펙에서 제외한다:
- 채널 찾기/채널 분석 (채널 단위 지표: 구독전환·성장속도 등)
- 수집한 영상 폴더/컬렉션 관리
- 핫비디오 날짜별 전체 브라우징
- 검색내역 태그 클라우드

이유: ViewTrap(`app.viewtrap.com`) 실제 화면을 참고 자료로 확인한 결과 훨씬 큰 툴이었음(영상/채널/
컬렉션/트렌드 4개 대탭 규모). 우리 대시보드에서는 기획 카드 안 위젯 하나로 충분 — 필요해지면 별도
스펙으로 확장.

### 계산 방식 (ViewTrap 실측 근거 기반)

기존 CLI의 `agent_plan.search_hot_clips()`는 Google Search grounding + Gemini 추정이라 숫자가
부정확할 수 있음(사용자 지적). **유튜브 Data API로 교체**해서 실제 조회수·좋아요·댓글·구독자 수치를
가져온다 (`mcp__claude_ai_PlayMCP__YouTubeData-*` 도구 활용 가능).

ViewTrap 실제 화면(사용자가 스크린샷 6장 공유, 로그인 필요해 WebFetch/Firecrawl로는 직접 확인 불가했음)에서
확인한 핵심 근거: 영상 상세 화면에 "조회수 30.7만 ⓘ **평소보다 높음(7,572.49%)**", "좋아요 1,196
ⓘ평소보다 높음(306,905.07%)"라고 표시됨 — 즉 **단순 조회수÷구독자 비율이 아니라, 그 채널 자체의
평소(baseline) 대비 이번 영상이 몇 % 더 나왔는지**를 계산하는 방식.

우리 구현:
- **기여도** = 이 영상 조회수 ÷ 그 채널 최근 N개 영상 평균조회수 → "채널 자체 대비 몇 %"
- **성과도** = 좋아요/댓글 등 참여지표를 같은 방식으로 → 조회수만 튄 건지 진짜 반응이 좋은 건지 구분
- 화면 표시는 숫자(예: ↑210%)와 등급(Good/Great, ViewTrap 스타일 5칸 도트) 둘 다 — 스캔하기 쉽게

N(최근 영상 몇 개를 "평소"로 볼지), Good/Great 등급 임계값(예: 3배↑Good, 8배↑Great)은 구현 단계에서
실측 데이터로 튜닝 — 이번 스펙에서 고정값으로 못 박지 않는다.

### 위젯 UI

검색창 + "🔥 실시간 탐지" 버튼 → 결과 테이블(체크박스·제목·채널·조회수(+%)·기여도·성과도·담기버튼)
→ 체크한 영상 "담기" → 담긴 레퍼런스 목록 표시 → 기획 생성 시 프롬프트에 자동 반영
(`agent_plan.run()`의 `bank`/`transcripts` 컨텍스트에 담긴 레퍼런스 추가).

레퍼런스는 **선택사항** — 안 담아도 기존 `content_bank.md` + `wiki/외부인사이트/주식_레퍼런스/`
데이터만으로 기획 생성 가능(기존 로직 그대로).

## API 필요 사항 (구현 단계에서 상세화)

- `GET /yt` — `dashboard/yt.html` 서빙
- `POST /yt/hot_clips?q=...` — 유튜브 Data API 검색 + 기여도/성과도 계산, 결과 JSON 반환
- `POST /yt/generate` (SSE) — `pipeline.run(idea, references=[...], start_from='plan')`을 이벤트
  스트림으로 감싸서 진행상황 전달 (studio_generate 패턴 재사용)
- 기존 `out/yt_pipeline_{pid}/state.json` 스키마에 `references` 필드 추가 필요(담긴 레퍼런스 기록용)

## 리스크 / 미해결

1. **유튜브 Data API 쿼터.** 검색+영상통계+채널통계 조합은 API 유닛 소모가 큼 — 실시간 탐지 버튼
   클릭당 얼마나 쓰는지 구현 단계에서 측정 필요.
2. **"평소" 기준선(N개) 산정 시 API 호출 추가.** 채널별 최근 N개 영상 통계도 가져와야 해서 검색
   결과 하나당 추가 API 호출 발생 — 배치 처리 방식 고려 필요.
3. **`pipeline.run()`이 현재 `references` 파라미터를 안 받음.** `agent_plan.run(idea, feedback)`
   시그니처에 레퍼런스 컨텍스트 주입 지점을 새로 만들어야 함 — 최소 침습으로 처리(기존 `bank`/
  `transcripts` 문자열에 이어붙이는 방식 권장, 시그니처 변경 최소화).
4. **`print` → SSE 이벤트 계측.** `pipeline.py`의 기존 `_step`/`_pass`/`_info` 콜을 이벤트 emit으로
   바꾸는 리팩터가 필요 — `pipeline.py` 레벨에서만 계측(개별 agent 파일은 안 건드림, 최소 침습 원칙).

## 다음 단계 (이번 스펙 범위 밖)

①기획 실제 동작 확인 후 → ②대본(씬 편집 UI) → ③리모션 → ④녹음(업로드 UI) → ⑤자막 → ⑥렌더
순서로 같은 패턴(SSE 재사용, state.json 확장) 적용. 각각 별도 스펙 문서로 분리.
