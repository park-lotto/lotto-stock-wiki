# 여행 숏폼 공방 — 숙소 하나 → 숏폼 여러 편 · 롱폼 · 꿀팁 가이드북

> 사장님 원칙(2026-10-20): **"공장에서 찍어낸 자동화가 아니라 사람이 공들여 한 땀 한 땀 만든 것 — 디테일이 핵심."**
> 우리는 **직접 가 본 사람이 아니라 소개하는 사람**이다 → 근거는 실제 투숙객 후기·사진, 출처를 밝힌다.
> 핵심은 **댓글(후기)** — 시설 소개를 넘어 "어떻게 하면 제대로 누리나"를 사용자 입장에서.

## 깔때기(무엇을 위해 만드나)

```
숏폼 여러 편(꼴마다 다르게) ─ 마지막 컷에 가이드북 살짝 → 관련 롱폼 → 고정댓글 링크(쿠팡파트너스·여행 예약)
→ "핵심 꿀팁노트(가이드북)"를 드린다
```

## 숏폼과 롱폼의 관계(2026-10-20 사장님)

```
숏폼 = 영상. 공식 사진 Veo 클립 + 손님 사진 장면(폴라로이드·액자…) + 모션그래픽을 섞어 다채롭게
       모션: 사진이 한 장씩 날아와 붙기·테이프 붙기·천천히 확대·자막 톡 튀기·후기 수 올라가기
롱폼 = 숏폼 재료를 다시 쓰되 숏폼을 그대로 이어 붙이지 않는다
       숏폼마다 첫 줄 훅("제발 ~하지 마세요")·끝 줄 유도가 있어 이어 붙이면 같은 말이 편마다 반복된다
       → 숏폼 한 편 = 롱폼 한 장(章). 훅·유도를 빼고 본문 장면을 쓰고, 사진·후기를 더 많이·더 길게 넣는다
       → 숏폼 고정댓글은 롱폼의 그 장 시간(타임스탬프)으로 보낸다
```
장면 틀은 모션을 위해 **한 장 그림이 아니라 층(배경·사진마다·손글씨·자막)으로** 내야 한다(다음 할 일).

## 순서 — 각 단계의 판단 주인 함수(한 곳에만 있다)

| # | 단계 | 주인 | 확인할 것(결과물로) |
|---|---|---|---|
| 1 | 숙소 상세(사진·소개·문답) | `travel_source.fetch` → `_yeogi_story_facts` | 사진 수·소개·문답 개수 |
| 2 | **후기 전부** + 손님 사진 주소 | `travel_source.yeogi_reviews` (STAY_DOMESTIC, 20개씩) | 후기 수 = 사이트 표시 수 |
| 3 | 후기 분석 6범주 | `travel_build.review_insights` (1차 제미나이→끊기면 하이쿠, 합치기 오푸스) | `tools/travel/collect_reviews.py` → insights.html 눈으로 |
| 4 | 소구점·와우포인트 | `travel_build.extract_points` / 빠짐 검사 `points_issues` | **시리즈 전체**에서 빠짐 0(한 편에 다 넣으면 나열이 된다 — 실측) |
| 5 | 대본 — 꼴별 | 꿀팁 가이드형·주의형 `write_script_format` / 이야기형 `write_script_transplant`(히트작 틀) | 금지 검사(이름·지역·가격) + 사람 눈. **AI 채점은 품질 잣대가 아니다**(`judge_calibrate.py`: 터진 25.2 vs 안 터진 24.0) |
| 6 | 장면 사진 — 손님 사진 여러 장 | `travel_scene.scene_photos` (120장 → 제미나이 격자 거르기 → 오푸스 고르기, 한 후기 한 장) | 주제가 실제로 보이나·얼굴 없나·콜라주 없나 |
| 7 | 사진 옆 손님 말 | `travel_scene.photo_quotes` (원문 글자 그대로 검사) | 뜻이 통하나("…짬뽕을…" 같은 토막 금지) |
| 8 | 장면 틀 | `travel_scene.make_scene` + `STYLES`(폴라로이드·전시회 액자·손글씨 메모·스크랩북·후기 말풍선) | 1080×1920 한 장, 겹침 없나 |
| 9 | 예능 자막 | `travel_build.variety_lines`(원문 구절 그대로 + 편집자 한마디) → `variety_caption_png` | 손님 말과 편집자 말이 색으로 갈리나 |
| 10 | 후기 카드 | `travel_build.review_card_png` | 사이트 화면 흉내 아님·출처 |
| 11 | 표기 | `video_assemble.disclosure_texts/disclosure_layer_png`(광고·AI 콘텐츠·출처) | 렌더+캡컷 둘 다(`check_disclosure.py`) |
| 12 | 가이드북 | `travel_build.guidebook_source` → `tools/travel/make_guidebook.py` | **슬라이드만**(인포그래픽은 한글·숫자 깨짐). 원고와 장마다 대조 |

## 한 숙소를 돌리는 명령

```
py tools/travel/collect_reviews.py <여기어때 숙소 주소> <작업폴더>        # 2·3단계 (약 6분)
py tools/travel/make_travel_short.py pick <숙소 주소> <작업폴더>          # 공식 사진 판정·7장·검토 화면
py tools/travel/make_guidebook.py <state.json> <출력폴더>                 # 12단계 (약 10분, nlm 로그인 필요)
```
장면·대본은 아직 단계별 함수 호출(도구 하나로 묶기 = 다음 할 일).

## 디테일 기준(사장님이 짚을 것 → 먼저 잰다)

```
□ 장면마다 사진이 그 말과 맞나(짬뽕 자막 = 짬뽕 사진). 객실 사진 위 짬뽕 자막 = 실패(실측)
□ 사진은 여러 손님 것(한 후기 한 장) — 신뢰. 출처 '실제 투숙객 사진 · 출처: 여기어때'
□ 손님 말은 글자 그대로. 편집자 위트는 따로(말풍선·다른 색)
□ 손글씨·테이프·종이결·그림자 — 평평한 단색·정렬된 격자는 공장 티가 난다
□ 겹침 0: 자막·도장·이모지·말풍선(실측으로 세 번 고쳤다)
□ 숫자는 후기 분석 그대로(가이드북·카드·자막 모두). 지어낸 말 0
```

## 하지 않는 것

- 블로그·검색 사진을 좌우반전·효과로 가공해 쓰기(저작권은 그대로 남는다). 쓰려면 CC(상업적 이용·수정 허용) 필터 사진만.
- 한 편에 소구점 전부 넣기(나열·사진 어긋남 — 실측). 시리즈로 나눠 담는다.
- AI 점수로 대본 고르기(조회수를 못 가른다 — 실측). 사람이 고른다.
- NotebookLM 인포그래픽(한글·숫자 깨짐).
