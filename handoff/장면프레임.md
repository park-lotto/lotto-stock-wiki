# 장면프레임

## 목표

`verify_beat_screens`가 선택 장면의 텍스트 설명(`scene_desc`)이 아니라 실제 대표 프레임 1장을 Gemini에 보내 화면 적합성을 검증하게 한다.

## 구현

- `frame_extract.extract_segment_thumb`: 세그먼트 시작 직후 대표 프레임을 `seg_thumbs/{seg_id}.jpg`에 생성·재사용하는 단일 함수.
- `app._seg_strip_thumb`: 위 공용 함수를 사용해 UI 카드와 AI 검증이 같은 프레임을 보게 함.
- `edit_plan._vault_call_image`: JPEG 바이트를 `types.Part.from_bytes`로 싣고 기존 `_vault_call` 키 회전 경로 재사용.
- `verify_beat_screens`: 프롬프트에서 `scene_desc` 제거, 선택 세그먼트의 실제 프레임 1장 전달. 프레임이 없으면 기존처럼 fail-open.
- `mix_pipeline`: 다운로드된 소스 경로와 job의 `seg_thumbs` 디렉터리를 `build_edit_plan`까지 전달. 원본이 정리된 옛 재타이핑 job은 이미지 검증만 건너뜀.
- 실제 설정명은 `verify_screens_enabled`; 기본 OFF 유지.

## 검증

- 직접 관련·배선 테스트: 48 passed 후 회귀 보정, 최종 관련 묶음 31 passed.
- 전체 테스트 최초: 17 failed, 7337 passed, 30 skipped. 이 중 이번 변경 회귀 2건을 수정.
- 실패군 동일 파일 비교: main 15 failed / track 14 failed. 새 실패 없음(기존 비결정 대본 테스트 1건이 실행별로 갈림).
- 실제 ffmpeg 2초 MP4 → `seg_thumbs/s0-0.jpg`, MJPEG 320×240 생성 확인.

## 남은 일

- 라이브 플래그를 켜지 않았다. 제한된 내부 job에서 `verify_screens_enabled=1`로 관찰 실험 후 승격한다.
- 같은 job의 기존 텍스트 판정과 이미지 판정이 갈린 비트만 사람 블라인드 비교한다.
- 이 트랙은 검증 시점의 primary 한 장만 바꾼다. 검증 뒤 `_fill_beat_screen_time`과 store 출구에서 추가되는 컷 전체 검증은 별도 과제다.
