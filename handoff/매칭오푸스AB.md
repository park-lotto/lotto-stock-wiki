## ★결론 (실측 완료 — 실험1 150건 + 실험2 50건, rc=0)

### 처방: **모델 교체가 아니라 fit 판정 수정** (원가 0)

실험2가 문턱만 바꿔 재픽시킨 결과 — **이게 이번 조사의 답이다**:

```
fit=5, 4  →  모델 호출 0/5회.  어긋남 3.0 → 3.0   ← 라이브가 여기
fit=3,2,1 →  모델 호출 5/5회.  어긋남 3.0 → 0.0   ← 양쪽 모델 다
```

재픽(`_repick_weak_beats`)은 **fit≤3 또는 forced**만 고치는데 라이브는 전 비트가 `fit=5`다.
→ **오푸스를 붙여도 부르질 않으니 소용이 없다.** 문턱만 넘기면 **제미니도 어긋남 0**.

### 모델 성능 (문을 똑같이 열어준 상태)

| | 제미니 | 오푸스 |
|---|---|---|
| 교정률 | 47% (135→72) | **52%** (135→65) |
| **CTA** 잔존 어긋남 | 41% (28/69) | **26%** (18/69) |
| **훅** 잔존 어긋남 | 22% (15/69) | **17%** (12/69) |
| problem | 42% (29/69) | 48% (33/69) ← 여기만 제미니 우세 |
| result·solution | 0% | 0~3% |
| 속도(중앙) | 2.5초 | 11.4초 |

**훅·CTA는 오푸스가 확실히 낫다.** 단 문턱을 고치면 제미니로도 0이 되므로
**지금 돈 쓸 이유는 없다.** 순서: ①fit 판정 수정(0원) → ②그래도 훅·CTA 부족하면 그 두 자리만 오푸스.

### ⚠️ 내가 중간에 틀렸던 것 (정정)

"나빠짐 0건"이라고 보고했으나 **표본이 커지자 오푸스 13건**으로 드러났다.
원인은 채점 방식이었다 — `blank`·`pad`처럼 **출발이 '화면 없음'인 비트는 채점축이 판정을
보류해 어긋남 0(만점처럼 보임)**이 되고, 채우는 순간 무엇을 골라도 "나빠짐"이 된다.
→ 집계에서 분리하고 별도 표로 보이게 고쳤다(`make_report.py`).

### ★조사 중 찾은 진짜 코드 결함 (아직 안 고침)

`_want_shots_for_role(role, available=)`는 available을 주면 재고 없는 결에서 **차선으로
내려간다**(problem: `before·문제` → `사용중·조리`). 그런데 **호출 2곳 중 하나만 넘긴다**:

| 위치 | available | 결과 |
|---|---|---|
| `edit_plan.py:3861` | ✅ 전달 | 정상 |
| **`edit_plan.py:3978`** (재픽) | ❌ 미전달 | **재고 0건인 `before·문제`를 그대로 지시** |

3861에는 이 함정을 막는 주석까지 있다("없는 결을 1순위로 걸어두면 모델이 억지로 아무거나
집는다"). **같은 판단이 두 곳, 한쪽만 고쳐진 0순위-B.** 08-17·08-18에 이어 네 번째다.

⚠️ **단 이걸 고쳐 재실측했더니 오푸스 선택은 안 바뀌었다**(monkeypatch 짝비교 3쌍 전부 동일,
프롬프트가 `결 사용중·조리 우선`으로 바뀐 것은 로그로 확인). **힌트 누락은 진짜지만
problem 증상의 원인은 아니다.** 그 대사가 "맛보더니 집에 가져가도 되냐고 매달려서"라
실제로 문제 상황이 아니고 완성샷이 대사엔 더 맞는다 → **채점축이 problem에 요구하는 결과
대사가 어긋난 경우**로 보인다. (`verify_fix.py`로 재현 가능)

### ★이번에 나온 가장 중요한 단서

**`live_asis`(라이브 그대로)는 두 모델 다 "미호출"이었다.**
5비트 전부 `fit=5`라 `_repick_weak_beats`(대상: fit≤3 또는 forced)가 **아무도 안 부른다.**

그런데 문을 열어주면(`all_open`, fit=1) **제미니도 어긋남 3→0**을 만들었다.

→ 라이브에서 훅에 '사용중'이 붙는 진짜 원인은 **모델의 판단력이 아니라 fit 문턱**일 수 있다.
   이게 08-18 핸드오프의 진단(`fit=5 자기신고 37건 중 26건이 실제로는 어긋남`)과 정확히 맞는다.
   그래서 **실험2(`run_gate.py`)를 추가**했다 — 처방이 100배 다르기 때문:

   · 모델이 문제 → 오푸스 전환 (원가 상승 + 서버 배선 불가)
   · **문이 문제 → fit 판정 수정 (제미니 그대로, 원가 0)**
