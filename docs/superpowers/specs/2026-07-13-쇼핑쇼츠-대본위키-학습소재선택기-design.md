# 쇼핑쇼츠 자동화 — 대본 위키 학습소재 선택기 + 디벨롭 루프 설계

날짜: 2026-07-13
상태: 설계 확정 대기
선행: 대본 위키(도서관, `library.html`), `script_generate.py`(유지/변형 토글 생성), `structure_analyze.py`

---

## 1. 목적 (What & Why)

지금 대본 위키 생성 모달의 "유지할 요소"(주변인물/발상전환/전개방식/훅/어필포인트/말투)는
체크 여부만으로 "원본 그대로 유지" 또는 "AI가 자유롭게 즉흥 변형" 둘 중 하나였다. 사용자
요청은 이 사이에 **"학습된 다양한 소재 중에서 고르기"**를 추가하는 것 — 예를 들어 주변인물을
"변형"할 때 AI 즉흥이 아니라 "가족관계/지인동료/전문가/소재맞춤 인물" 같은, **실제로 쌓인
잘 써진 대본들에서 통계적으로 뽑아낸** 카테고리 중에서 고르거나(미선택 시 랜덤) 쓸 수 있게
한다.

추가로, 생성된 초안을 그 자리에서 끝내지 않고 **개별 수정 + 프롬프트 지시로 반복 디벨롭**할
수 있는 기능도 필요하다.

이 스펙은 두 개의 독립 서브프로젝트를 다룬다:
- **A) 학습소재 선택기** — 통계 기반 카테고리 옵션 선택 UI+백엔드
- **B) 디벨롭 루프** — 생성 후 개별수정·프롬프트 재생성·버전 이력

서로 의존관계 없음. 구현은 A → B 순서 추천(A가 기반 데이터 파이프라인을 다루고, B는 기존
생성 흐름에 저장 레이어만 얹는 상대적으로 단순한 작업).

---

## 2. 확정된 설계 결정 (사용자 승인)

브레인스토밍 중 답변받은 내용:

1. **통계 범위**: 위키(S급 저장 항목)만이 아니라, **대본 추출된 모든 항목**(`script_extracts`
   전체)을 표본으로 쓴다 — 표본이 훨씬 커짐.
2. **카테고리 분리 단위**: 전체 공통이 아니라 **영상 카테고리(레시피/뷰티/생활용품 등)별로
   따로** 통계·옵션을 만든다.
3. **모드 개수**: 기존 "AI 자유즉흥" 옵션도 유지 — 총 **4가지 모드**: 원본유지 / 카테고리
   지정 / 카테고리 중 랜덤 / AI 자유즉흥.
4. **통계 재계산 주기**: **자동으로 매일 새벽** 재계산(수동 버튼 없음).
5. **디벨롭 재생성 범위**: 전체 재작성 + 부분 선택 수정 **둘 다** 구현.
6. **버전 관리**: **이력을 저장**해서 이전 버전으로 되돌릴 수 있게 한다(덮어쓰기 아님).

## 3. A) 학습소재 선택기

### 3-1. 배치 파이프라인 (서버 크론, 매일 새벽)

**단계 1 — 구조분석 백필**: 지금은 `analyze_structure()`가 위키 저장(`/api/wiki/save`)
시에만 호출된다. 이를 확장해, `script_extracts` 중 아직 구조분석 안 된(`structure_json`
NULL) 행을 찾아 `analyze_structure(full_text)`를 돌려 채운다. `key_vault` 캐스케이드로
쿼터 분산(기존 패턴 재사용). 한 번에 너무 많이 돌리지 않도록 배치당 처리 건수 상한 필요
(예: 회당 100건 — 구현 단계에서 실측 후 조정).

**단계 2 — 카테고리 통계 생성**: `product_category × element` 조합마다(예: 레시피×주변인물),
그 카테고리에 쌓인 구조 데이터에서 해당 요소의 자유서술 값(예: 등장인물의 `role` 텍스트들)을
모아 Gemini에게 "비슷한 것끼리 2~6개 카테고리로 묶고, 각 카테고리에 라벨(짧은 이름)+설명
(1문장)+대표 예시 2~3개를 붙여줘"라고 요청한다. 결과를 `element_category_stats`에
저장(기존 값 덮어씀 — 이력 불필요, 통계는 항상 "최신"이 맞음).

**표본 부족 안전장치**: 특정 `product_category × element` 조합의 표본 수가 임계값(예: 20건)
미만이면 그 조합은 카테고리를 만들지 않고 건너뛴다. 프론트는 옵션이 없는 요소에 대해
드롭다운을 아예 안 띄우고 "AI 자유즉흥"으로 자동 폴백한다 — 데이터 부족한데 억지로 옵션을
만들어내지 않는다.

### 3-2. 데이터 모델 (신규/확장)

```sql
-- script_extracts 테이블에 컬럼 추가 (기존 테이블 확장)
ALTER TABLE script_extracts ADD COLUMN structure_json TEXT;      -- analyze_structure() 결과
ALTER TABLE script_extracts ADD COLUMN structure_analyzed_at TEXT;
ALTER TABLE script_extracts ADD COLUMN category TEXT;            -- 통계 그룹핑용(레퍼런스의 category 복사)

-- 학습된 카테고리 통계 (요소별 옵션 목록, 배치가 매일 재계산해 덮어씀)
CREATE TABLE element_category_stats (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  product_category TEXT NOT NULL,   -- 레시피/뷰티/생활용품 등
  element TEXT NOT NULL,            -- characters/twist/development/hook/appeal/tone
  category_label TEXT NOT NULL,     -- "가족관계", "전문가" 등
  description TEXT,                 -- 1문장 설명
  example_snippets_json TEXT,       -- 대표 예시 2~3개
  sample_count INTEGER,             -- 이 카테고리에 속한 원본 표본 수
  computed_at TEXT,
  UNIQUE(product_category, element, category_label)
);
```

### 3-3. API 엔드포인트 (신규)

- `GET /api/wiki/element_options?category={product_category}` → 요소별 카테고리 옵션 목록
  `{characters: [{label, desc}], twist: [...], development: [...], hook: [...], appeal: [...], tone: [...]}`.
  옵션 없는 요소는 빈 배열(프론트가 드롭다운 숨김 처리).

### 3-4. 화면 (`library.html` 생성 모달)

각 요소 줄이 체크박스+드롭다운 조합으로 바뀐다:

```
👥 주변인물   [✓ 원본유지]
              (체크 해제 시) ▾ 🎲 랜덤(기본) / 가족관계 / 지인동료 / 전문가 / 소재맞춤 인물 / ✨ AI 자유즉흥
```

- 체크(원본유지) 상태에선 드롭다운 숨김.
- 체크 해제 시 드롭다운 노출, 기본 선택값은 **🎲 랜덤**.
- 옵션이 없는 요소(표본 부족)는 드롭다운 없이 바로 AI 자유즉흥으로 동작(안내 문구 표시).
- 모달을 열 때 해당 대본의 `category`로 `/api/wiki/element_options`를 호출해 드롭다운 채움.

### 3-5. 생성 백엔드 연동

`script_generate._elem_lines()`에 분기 추가:
- 원본유지: 기존과 동일(원본 값 그대로 살리라고 지시)
- 카테고리 지정: 선택된 `category_label`의 `description`+`example_snippets`를 프롬프트
  제약으로 삽입 ("이 요소는 반드시 '전문가' 유형으로 — 설명: ..., 예: ...")
- 카테고리 중 랜덤: 서버가 해당 요소의 옵션 중 하나를 랜덤 추출해 위와 동일하게 삽입
- AI 자유즉흥: 기존 로직 그대로(변경 없음)

## 4. B) 디벨롭 루프

### 4-1. 생성 흐름 변경

지금 `/api/wiki/generate`는 초안을 만들어 화면에만 렌더링하고 저장하지 않는다(새로고침하면
사라짐). 이를 바꿔 **생성된 각 초안을 즉시 `script_drafts`에 저장**하고 응답에 `draft_id`를
포함한다. 이후 모든 수정 작업은 `draft_id` 기준으로 이뤄진다.

### 4-2. 데이터 모델 (신규)

```sql
CREATE TABLE script_drafts (
  draft_id TEXT PRIMARY KEY,          -- uuid
  customer_id INTEGER NOT NULL DEFAULT 0,
  source_shortcode TEXT,              -- 원본 위키 대본
  parent_draft_id TEXT,               -- 이전 버전(NULL=최초 생성)
  hook TEXT,
  script_text TEXT NOT NULL,
  edit_instruction TEXT,              -- 이 버전을 만들 때 쓴 지시문(직접편집이면 NULL)
  edit_mode TEXT,                     -- 'generate'|'rewrite'|'partial'|'manual'
  created_at TEXT
);
```

### 4-3. API 엔드포인트 (신규)

- `POST /api/wiki/draft/refine` — body: `{draft_id, mode: "rewrite"|"partial", instruction, selected_text?}`.
  - `rewrite`: 현재 버전 전체 + 지시문을 Gemini에 넣어 통째로 재작성.
  - `partial`: 현재 버전 전체를 컨텍스트로 주되 "`{selected_text}` 부분만 지시대로 바꾸고
    나머지는 토씨 하나 그대로 유지"로 프롬프트 구성.
  - 결과를 새 `script_drafts` 행으로 저장(`parent_draft_id`=현재 draft_id), 새 `draft_id` 반환.
- `POST /api/wiki/draft/edit` — body: `{draft_id, script_text}`. 사용자가 텍스트박스에서
  직접 고친 내용을 AI 호출 없이 새 버전으로 저장(빠르고 무료).
- `GET /api/wiki/draft/history?draft_id=...` — `parent_draft_id` 체인을 따라 전체 버전
  목록 반환(최신이 어디부터 시작했는지 포함).

### 4-4. 화면 (생성 결과 카드)

```
초안 1  [편집 가능한 텍스트박스로 표시, 직접 타이핑 가능]
🔧 지시문: [________________]  [전체 재작성]  [선택 부분만 수정]
📜 버전(3) ▾  ← 펼치면 이전 버전들 나열, 클릭 시 그 버전 내용을 다시 활성 버전으로
```

- "선택 부분만 수정"은 텍스트박스에서 드래그 선택한 구간을 `selected_text`로 전송.
- 텍스트박스에서 직접 타이핑 후 벗어나면(blur) 자동으로 `draft/edit` 호출해 새 버전 저장.
- 버전 이력에서 과거 버전 클릭 → 텍스트박스 내용을 그 버전으로 교체(새 버전 생성이 아니라
  단순 조회/복사 — "되돌리기"를 누르면 그 내용으로 다시 `draft/edit` 호출해 최신 버전화).

## 5. 알려진 리스크

- **구조분석 백필 비용**: `script_extracts`가 커지면(레퍼런스 랭킹 규모 상 수백~수천 건
  가능) 전체 백필에 상당한 Gemini 호출이 필요 — 배치당 처리 건수 상한 + key_vault
  캐스케이드로 완화하지만, 초기 1회 백필은 여러 날에 걸쳐 점진적으로 끝날 수 있음.
- **카테고리 통계 품질**: Gemini 클러스터링 결과가 실제로 유용한 카테고리로 나오는지는
  구현 후 실데이터로 검증 필요 — 카테고리가 너무 뭉뚱그려지거나(2개뿐) 너무 잘게
  쪼개지면(6개 넘게 요청해도 무의미한 것들) 프롬프트 튜닝 필요할 수 있음.
- **표본 부족 카테고리 다수 가능성**: 초기엔 대부분의 `product_category × element` 조합이
  표본 20건 미만이라 옵션이 거의 안 뜰 수 있음 — 정상 동작(안전장치)이지만 사용자 기대와
  다를 수 있어 "데이터가 더 쌓이면 옵션이 늘어납니다" 안내 필요.
- **부분 수정(`partial`)의 정확도**: "나머지는 토씨 하나 그대로"를 Gemini가 완벽히 지키지
  않을 가능성 — 결과에서 선택 부분 밖이 바뀌었는지 간단 diff로 확인하는 검증 로직을 두거나,
  최소한 사용자가 눈으로 바로 확인 가능하게 변경분을 하이라이트하는 것도 고려(이번 스펙
  범위에서는 diff 하이라이트는 선택사항으로 남김).

## 6. 단계적 구현 순서 (계획 문서에서 세분화 예정)

**A) 학습소재 선택기**
1. `script_extracts` 스키마 확장(`structure_json` 등) + 구조분석 백필 배치 함수
2. `element_category_stats` 테이블 + 카테고리 클러스터링 배치 함수(표본 부족 안전장치 포함)
3. 매일 새벽 크론 등록(1+2 순차 실행)
4. `GET /api/wiki/element_options` 엔드포인트
5. `library.html` 생성 모달 UI(체크박스→드롭다운 확장)
6. `script_generate._elem_lines()` 분기 추가(카테고리 지정/랜덤)

**B) 디벨롭 루프**
7. `script_drafts` 테이블 + `/api/wiki/generate`가 결과를 저장하도록 수정
8. `/api/wiki/draft/refine`(rewrite/partial 2모드) + `/api/wiki/draft/edit` + `/api/wiki/draft/history`
9. 생성 결과 카드 UI(편집가능 텍스트박스 + 지시문 입력 + 버전 이력)
