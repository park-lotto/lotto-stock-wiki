# 대본 프롬프트 단순화 (Gemini 종합) — 설계

- 날짜: 2026-07-26
- 트랙: 대본프롬프트단순화
- 대상: `shopping_shorts/edit_plan.py` `_scene_first_candidates()` 프롬프트

## 문제 (진단 결과)

영상대본MIX 생성 프롬프트가 매일 패치로 **★필수 제약 17개**가 누적돼 서로 충돌.
30초 대본 하나에 (8비트 드라마 아크 + 반전 2번 + 따옴표 2번 + 정확히 171자 + 은행훅 거의
그대로 + 최근6개 회피 + 은행부사 + few-shot…)를 동시 강제 → 모델이 가장 약하게 걸린
**제품 충실도**를 먼저 버려 주제이탈·페르소나 뒤죽박죽·훅 이상·문장 반복 발생.
"만질(매일 업데이트)수록 이상해진다"의 정체 = 제약 과적재. 백업: `바탕화면/대본생성_전체프롬프트.txt`.

## 결정

- ① 은행(부품·스파인·우승 few-shot·novelty) 주입 = **완전 OFF**. 데이터는 보존, 주입만 제거.
- ② 길이 = **30초 / 160~180자 목표**(하드 반려 제거, 목표로만).

## 설계 — 무엇을 유지/교체/제거

| | 내용 |
|---|---|
| **유지** | 출력 스키마(`_SCENE_FIRST_SCHEMA`) 그대로 — candidates[].{hook, story_person, cta_line, cta_keyword, beats[].role/narration/caption_lines/seg_ids/fit/forced}. 다운스트림(장면배치·TTS·자막·기록) 무변경 |
| **유지** | 3후보 생성 / seg_id 팔레트 바인딩 / 레퍼런스(제품)·benefits·order 블록 |
| **교체** | 거대 지시 → **5단계 스파인**(훅→문제→해결→결과→CTA) + **훅 4패턴**(부정/손실회피/권위/결과선공개, 후보별 다른 패턴) + **소스 교차 믹스 + 접착어(브릿지)** |
| **격상** | 레퍼런스(제품)를 "참고용 흐름 감"에서 **"중심, 벗어나지 마라"로** |
| **제거** | 은행 주입, 8비트 아크, 반전 2번 강제, 정확히 171자 하드반려, 은행부사 강제 |

### 스키마 정합 (중요)
- 스키마 `beats` **minItems:6**. 5단계를 5비트로 넣으면 검증 실패 → 생성 죽음.
  → **6~7비트로 나누되 5단계를 배분**(문제·해결 단계는 1~2비트). 각 beat `role`에 단계명.
- 첫 비트 `narration` = 훅(강한 오프너)로 시작(현행 유지).

### 은행 OFF 구현
- `_scene_first_candidates`가 `bank_context`를 **프롬프트에 append하지 않음**(서버 setting이
  bank_enabled=1이어도 물리적으로 OFF 보장). 파이프라인 배선(record_script_usage 등)은
  건드리지 않아 데이터·호환 유지. 재도입 지점은 주석으로 명시.

## 범위 밖 (YAGNI)
- 스키마 변경, 파서/판정/TTS/자막 로직 변경, 은행 데이터 삭제, UI 변경 — 하지 않음.

## 검증
- 문법 컴파일 + `import shopping_shorts.edit_plan` + 관련 pytest(있으면).
- 실제 생성 1회로 육안 확인(사장님) 후에만 `finish`(배포). 생성 전엔 라이브 반영 안 함.
