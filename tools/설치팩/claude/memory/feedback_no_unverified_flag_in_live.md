**검증 없이 실험 기능을 라이브 플래그로 켜지 마라.** 라이브 밖(실데이터 실측)에서 먼저 검증하고, 좋을 때만 켠다.

**Why**: 2026-07-29 모션레벨훅 트랙 — B1(프레임 태깅 추출)을 코드+단위테스트만 그린인 상태로 서버 `frame_extract_enabled='1'`로 켰다. 하필 제미니가 503(과부하) 스파이크였고, B1의 프레임 태깅엔 기존 추출에 있는 **503 폴백이 없어서** 태깅이 죄다 실패 → scene_desc 전부 빈칸 → 제작소에 "추출은 됐으나 원본 대본·구조가 비어 새 대본을 만들 수 없습니다" 에러. 사장님이 "왜 자꾸 거꾸로 일을 하냐, 계속 안 좋아진다"고 지적. 단위테스트 통과 ≠ 실환경 동작.

**How to apply**:
- 새 추출/생성 경로는 **플래그 뒤 + 기본 off**로 배포까지만. 켜는 건 별도 결정.
- 켜기 전 반드시 **라이브 밖 실측**(같은 소재로 실제 돌려 품질·속도·실패율 관측). 특히 외부 API(제미니/GROQ) 의존 경로는 **503/429/타임아웃 폴백**을 옛 경로 수준으로 갖췄는지 확인.
- 문제 나면 **즉시 플래그 off로 롤백**(코드 되돌림보다 빠르고 안전) — B1 사고 때 플래그만 끄니 옛 검증경로로 즉복구됐다.
- 오진·과다배포 주의: 하루에 같은 트랙을 여러 번 finish하면 게이트가 seam 회귀를 여러 라운드 잡아 검증이 못 따라간다. 한 번에 한 태스크.
- 관련: [[project_scene_spine_first]](스파인은 실측검증 성공), [[feedback_verify_with_real_data]], [[feedback_verify_before_claim_and_act]].

**B1 상태**: 코드는 라이브(플래그 off), `frame_script.py`+`extract_auto`. 재점화는 라이브 밖 실측 후에만. 애초에 영상 통째 시청(옛 방식)이 품질 상위라 B1 자체가 최선인지도 재평가 대상.
