## §텔레화면 — 채널별 세로 컬럼 (2026-08-15 사무실PC, 완료)

`dashboard/insights2.html` + `dashboard/server.py`. 유튜브 화면은 **한 줄도 안 건드렸다**
(`CAT==='telegram'`일 때만 분기). 유튜브 탭 정상 동작 브라우저 확인함.

### 모양
- **채널 = 세로 한 줄**, 위→아래 시간순. 가로로 15개 채널을 세워 같은 시각에
  누가 뭐라 했는지 훑는다(`.tlw` 가로 스크롤)
- 컬럼 안에 **장 전 / 장중 / 마감 후 / 시각 없음** 구분선(sticky)
- 위쪽 칩으로 시간대 필터 — 실측 `전체 302 · 장 전 77 · 장중 59 · 마감 후 121`
  (+시각없음 45 = 302 ✓). 마감 후 누르면 채널 12개·15:32~23:22만 남는 것 확인
- 컬럼 머리에 건수·시간범위·부호 스파크라인

### ★머리말을 문자열로 걷어내지 않고 **필드로 쪼갰다** (`_ins2_split_head`)
핸드오프엔 "`목표가 None None` 패턴은 렌더링 때 걷어낼 것"이라 적혀 있었지만,
실제로 보니 그 머리말은 **쓰레기가 아니라 구조 정보**였다:

```
"[중계:신한투자증권] 목표가 18,000원 매수 / 12MF BPS 15,743원에 …"
                └ relay      └ tp    └ opinion  └ 본문
```

걷어내기만 하면 목표가·의견을 통째로 버린다 → **쪼개서 값 있는 것만 배지로** 띄운다
(🎯 18,000원 매수 / ↻ 신한투자증권). 값이 없을 때(`None`·`null`)는 배지가 안 뜨니
'None None'도 자연히 사라진다. 실측 971건 중 **None/null 잔존 0**.

- 빈값 판정은 `_ins2_blank` 한 곳에서만 한다 — 실측상 `None` 60건 / **`null` 8건**이
  섞여 있었다. 한쪽만 막으면 반드시 샌다(0순위-B)
- 부호 접두어도 **두 모양**이다: `[긍정] …` 과 `긍정: …`. 둘 다 걷는다
  (부호는 화면의 점이 이미 보여주므로 글자로 반복하지 않는다)

### 중복 접기 (표시만)
같은 채널·같은 시각에 **같은 문장이 여러 번** 들어온다(실측 신한리서치 08:09
"사상 최대 실적…" ×5). 원자화가 긴 메시지를 쪼개며 생긴 데이터층 문제지만 화면을
잡아먹으므로 **한 줄 + `×N` 배지**로 접는다(`tlDedupe`).
⚠️ **접는 건 표시뿐** — 위 판세 집계(sectors/stocks)는 원본 건수 그대로다.

### ⏱ 값의 뜻을 API가 알려준다 — `ts_kind`
`ts` 칸 하나에 유튜브는 `yt_timestamp`(재생위치), 텔레는 `msg_ts`(발송시각)를 담고,
**뜻은 `ts_kind`('play'/'clock')로 전달**한다. 화면이 `▶01:53`(딥링크) / `🕘09:58`(글자)로
갈라 그린다. 딥링크가 없어도 시각 자체는 정보라 `—`로 죽이지 않는다.

### 로컬에서 화면을 볼 수 있게 고쳤다
`_ins2_require_admin`이 `_AUTH_ON`을 안 봐서 **인증 OFF인 로컬에서도 403**이었다
(핸드오프의 "로컬에선 이 테스트가 무의미하다"가 사실은 화면 자체를 못 본다는 뜻).
다른 관리자 경로(`server.py:744, :818`)와 같이 `if not _AUTH_ON: return False` 추가.
**라이브는 `DASH_PASS`·`GOOGLE_CLIENT_ID`가 설정돼 `_AUTH_ON=True` → 잠금 그대로.**

로컬 확인 방법:
```
cp pipeline/atoms/atoms.db .tracks/인사이트2/pipeline/atoms/   # main 폴더에 실DB 있음
cd dashboard && DASH_PASS= GOOGLE_CLIENT_ID= py -m uvicorn server:app --port 8099
→ http://127.0.0.1:8099/insights2
```

### 남은 것(텔레 화면)
- `speaker` 0건 — 채널=발신자라 채널명으로 대체했다. 데이터층에서 채울 필요 없음
- 판세 '섹터' 칸 정렬이 **부호 있는 건수 우선**이라 `IT 26건`이 `반도체 2건` 아래로
  간다(막대도 빈 채). 유튜브부터 있던 기존 동작이라 이번엔 안 건드렸다 — 손볼지 결정 필요

### 왜 API를 새로 팠나
기존 `/api/insights/*` 는 **"카테고리→소스→문서→상세" 드릴다운용**이라 화면 하나
그리는 데 4번 호출해야 한다. 인사이트2는 **전부 제자리에서 펼치는** 구조라
판세 3칸(시장·섹터·종목) + 문서별 발언을 **한 방에** 주는 모양이 필요했다.

`/api/insights2/daily?category=youtube` →
`{date, counts, market, sectors[], stocks[], videos[], atoms[]}`
- `atoms[].video` 인덱스로 발언↔문서를 연결한다(프론트에서 join)
- `sectors[]`/`stocks[]` = `{name, plus, minus, n}` ← 막대그래프 그대로 그림
- `asset` 은 `"삼성전자, SK하이닉스"` 처럼 한 칸에 여럿 → 쉼표로 쪼개서 집계

### 화면 원칙 (사장님 피드백으로 확정)
사장님 지적: **"내용·구성은 좋은데 난독이고 텍스트가 많아 읽기 힘들다."**
원인은 ①설명박스 11개 ②글자가 전부 같은 크기 ③정보를 문장으로 씀.
→ **"읽는 화면"이 아니라 "보는 화면"** 으로 재설계:
- 설명 텍스트 전부 제거. 위계는 **크기**로 준다(26px 헤드라인 → 29px 판세 → 13px 발언)
- 섹터·종목은 문장이 아니라 **막대 + 숫자**. 의견 갈리면 `2·1` 금색
- **페이지 이동 0** — 시장/섹터/종목/문서 전부 제자리 펼침, ESC로 닫힘, 한 번에 하나만
- 문서 카드 **아래에 결론 요약을 항상 노출**(클릭 없이 읽히게) ← 사장님이 명시 요청

### 날짜 처리
`오늘`을 고집하지 않고 **데이터가 있는 최근 날짜**를 쓴다(`_ins2_latest_date`).
크롤이 아직이면 화면이 통째로 비는 걸 막는다. 실측상 소스마다 최신일이 다르다.

### 접근제어 (★중요)
`/insights2` 와 `/api/insights2/` 를 `_USER_PAGES`·`_USER_API_PREFIX` 에 **일부러 안 넣었다**

### ① ⏱ 타임스탬프가 전 소스 0건 → 시각 링크 전부 비활성(`—`)
**수집 문제가 아니라 배선 문제다.**
- `raw/yt/*.md` 947개 중 **847개에 `[mm:ss] 화자: 발언`이 이미 있다 (총 11,105개)**
- 그런데 DB엔 72개뿐 → **원자화가 버린다**
- 원인: 유튜브 경로가 **두 벌**인데 타임스탬프를 채우는 쪽이 고아
  - **A(실제로 돎)**: `atom_pipeline.py` STEP3.7 → `post_ingest.py` → `POST_PROMPT`
    ← **텔레그램용 프롬프트를 재활용**. `ts`가 *메시지 시각*이라 `msg_ts`로 감
    (`telegram_questionnaire.py:112,153`). `db.py:69` `setdefault(...,None)`이 조용히 None
  - **B(아무도 안 부름)**: `pipeline/atoms/youtube_ingest.py` — `_YT_PROMPT`에
    `timestamp: mm:ss` 명시, 딥링크까지 만든다(`atomizer.py:207`, 순수 산수).
    2026-06-29 커밋 `b51969114`에서 컬럼 마이그레이션과 **같이 만들어졌는데
    파이프라인에 연결을 안 했다.** 게다가 `CRAWL_ROOT`가 집PC 경로 하드코딩(:18)
- **비용은 0** — API·재다운로드 불필요. 딥링크는 `_ts_to_seconds` 산수
- 화면은 `with_ts=0`이면 **안내 배너**를 띄우고 정상 동작한다(깨지지 않음)

### ★텔레는 예외 — 시각이 이미 잘 뽑히고 있다 (2026-08-15 실측)

사장님 질문: *"텔레그램 원자도 지금 타임스탬프처럼 뽑고 있는 건가?"* → **예. 그리고 유튜브보다 훨씬 낫다.**

```
텔레 원자 6,285 | msg_ts 있음 4,421 (70%) | speaker 0 | deeplink 0
유튜브   4,644 | yt_timestamp 72 (1.5%)
```

**단 성격이 다르다 — 헷갈리지 말 것:**

| | 유튜브 `yt_timestamp` | 텔레 `msg_ts` |
|---|---|---|
| 값 | `01:53` = **영상 재생위치** | `06:36` = **메시지 발송 시각** |
| 딥링크 | `...&t=113` 로 그 순간 재생 | **없음**(0건) — 텔레는 링크 개념이 없음 |
| 용도 | 영상 안 보고 그 지점만 확인 | **시간순 정렬**, 장 전/장중/마감 구분 |

**이게 유튜브가 깨진 이유이기도 하다.** `POST_PROMPT`의 `ts`는 원래 **텔레용(메시지 시각)**으로
설계됐는데 유튜브가 그 프롬프트를 빌려 쓰면서 `msg_ts`로 들어가 `yt_timestamp`가 빈 것.
**텔레 입장에선 원래 자기 것이라 정상 작동 중** → 텔레는 고칠 게 없다.

→ **그래서 텔레 화면은 지금 데이터로 바로 만들 수 있다.** 예:
```
07:40 [신한리서치] 반도체 업종 비중확대 유지        ← 장 전
09:58 [잠실개미]   외국인 수급 반도체 재유입        ← 장중
15:40 [태린이아빠] 장 마감 특징주 — 로봇·조선 강세  ← 마감
```

**텔레도 문제 2개는 있다(화면 만들 때 감안):**
1. `speaker` 0건 — 채널명(`source_name`)만 있고 발언자는 없다. 텔레는 채널=발신자라 큰 문제 아님.
2. 내용에 쓰레기 — `"[중계:신한] 목표가 None None / ..."` 가 그대로 박혀 있다.
   같은 시각(06:36)에 7건이 몰린 걸 보면 **긴 메시지 하나를 쪼갠 것**. 화면에 그대로 내면 지저분하니
   `목표가 None None` 같은 패턴은 렌더링 때 걷어낼 것.

### ② 📉 시장 칸이 0
`sector='시장'` 원자가 해당일에 없다. 판세 3칸 중 하나가 비어 보인다.

### ③ 🎯 종목명 자리에 문장이 들어온다
`asset`에 `"회사 내 주도적 위치 확대"`, `"성장을 커리어 확보"` 같은 값.
원자화 품질 문제 — 8월 원자는 `"야생 근육 배양"` 같은 **단어 조각**이고
같은 문장이 `"긍정: ..."` 로 **중복**되기도 한다. 6월(타임스탬프 있던 것)은
`speaker`도 살아있고 온전한 문장이었다.

> 셋 다 **크롤링 전면 재설계 때 같이 잡기로** 사장님과 정리됨. UI 결정과는 분리.
