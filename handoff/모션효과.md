(사용자는 처음에 "상시 분석기"를 원했으나, 그릇 먼저·자동갱신 나중으로 합의)

**확정된 설계 결정 4가지**:
1. **팩은 완성스타일 카드에 내장** — 별도 카드벽 안 만든다. `FULL_PRESETS[i].motion = pack_id` → 카드 하나 = 글씨+모션 딸깍. 피팅룸 철학 유지.
2. **레이어는 저장이 아니라 렌더 시점 생성** — 비트 경계는 TTS 실길이가 확정되는 렌더 때 정해진다. **DB엔 `pack_id`만** 저장. (저장 시점에 박으면 대본 바뀔 때마다 전환이 어긋남 = 이 설계의 중심축)
3. **텍스트 모션은 drawtext 재사용** — 서버 실측 RAM 가용 830MB라 런타임 헤드리스 크롬 렌더는 위험. 팩은 **새 텍스트를 만들지 않고** 기존 자막 effect + 헤드카피 노출정책(`hook_only`)만 규정. 진짜 Remotion 키네틱은 2b.
4. **팩 값은 지어내지 않는다** — 스펙은 스키마·엔진만 확정. 실제 팩 3~4종 값은 **구현 Task7**에서 레퍼런스 랭킹 상위영상 관찰로 채운다(계획서 하단 "관찰 로그"에 근거 기록 → 2b 분석기가 이걸 자동화).

**서버 실측(2026-07-15)**: Node v22.22.2 · google-chrome · chromium **전부 설치돼 있음**. 그러나 **RAM 총 1.9GB / 가용 830MB** → Remotion은 빌드타임 자산생성기로만.
