## 3. 아키텍처

```
[서버] checks.timer(5분) · checks-daily.timer(06:10 KST)
   shopping_shorts/checks/run_checks.py  ← 진입점 하나, flock 1개
      ├─ L0 자가진단  기동·코드 최신성·타이머 스로틀·로그인·카나리·pytest 기준선
      ├─ L1 전수 훑기  페이지 라우트 자동 발견 → DOM 요소 자동 발견 → hit-test → 클릭 → 터졌나
      ├─ L2 흐름       checks/flows/*.py 자동 발견 → STEPS 주행 → 불변식(개수·왕복·삭제재읽기·시간축·폴백)
      ├─ L3 운영 건강  checks/health/*.py 자동 발견 → due인 항목만 measure() → 정상범위 판정
      ├─ 증거          스크린샷·콘솔·네트워크·trace.zip / L3는 수치+표본 URL
      ├─ 저장          checks.db (check_runs · check_results · health_samples · pytest_baseline)
      └─ 보고          /admin/checks 관리점검표 + ops_alert(2회 연속 빨강 / 회색 즉시)
```

- L0~L2는 미리보기 인스턴스가 필요하다(브라우저). **L3는 라이브 DB를 읽기 전용으로 직접 본다**(`file:…?mode=ro`, preview.sh와 같은 방식) — 운영 상태는 라이브 것이어야 의미가 있고, 읽기만 하므로 안전하다.
- 초록/빨강/**회색(판정 불가)** 셋을 가른다. L0가 실패하면 L1·L2는 회색이고, L3는 소스(DB·api_events)를 못 읽을 때 회색이다.
- 서비스 축은 `check_runs.service='shopping-shorts'` 한 값.

## 4. 구성요소

### 4.1 `run_checks.py`
- `python3 -m shopping_shorts.checks.run_checks --trigger deploy|daily|health`. `deploy`=L0+L1(제작소만)+L2(렌더·워커 불필요 흐름만), `daily`=전부+렌더, `health`=L3 due 항목만(5분 타이머가 매번 부름, 미리보기 안 띄움).
- 의존: `deploy/preview.sh`, playwright, `/etc/shopping-shorts.env`, `Store`, `api_health`, `capacity_watch`, `ops_alert`.

### 4.2 미리보기 하네스 (`preview.sh` 확장 2건)
- `start <sha>`(브랜치 대신 라이브 HEAD sha) + `--worker 1`(같은 워크트리 cwd에서 `python3 -m shopping_shorts.worker`). `stop`이 둘 다 내린다.
- 미리보기 워커는 `prewarm`·`durfill`(인스타 세션 독점, `_EXCLUSIVE_TASKS`)을 **받지 않아야** 한다 — 라이브와 DB가 달라 락을 공유하지 않는다. `worker.py:35-55 TASKS`를 환경변수(`SHORTS_WORKER_TASKS`)로 거르는 한 줄 필요(현재 없음, 실측).
- 실키를 쓴다(Gemini·TTS 실비용, §10). 비상주.

### 4.3 L0 자가진단
| 검사 | 방법 | 실패 |
|---|---|---|
| 기동 | `GET :8850/pricing` 200(비로그인 허용) | 회색, 이후 생략 |
| 코드 최신성 | 워크트리 HEAD == 라이브 HEAD **및** 브라우저가 받은 `produce.html`·`scene_lab.html`·`filmroll.js` 본문 해시 == 파일 해시 | 회색 (실사고: iframe 캐시버스터) |
| 타이머 스로틀 | 페이지에서 `setInterval(100ms)` 3초 → 25회 미만 | 회색+알림. 헤드리스는 스로틀 없을 것으로 **예상, 확인 필요**(첫 구현에서 실측값 기록) |
| 로그인 | `/api/login` → `/api/me` cid 0 | 회색 |
| 카나리 | 에러를 던지는 인라인 페이지가 L1 판정기에서 **반드시 빨강** | 아니면 점검기 고장 → 알림 |
| pytest 기준선 | 워크트리에서 `pytest -q -n auto` → 실패 id 집합 저장, 전일 대비 ± | 늘면 노랑 |

### 4.4 L1 전수 훑기
- 페이지: `app.py`의 `@app.get("…", response_class=HTMLResponse)` 라우트를 긁어 자동 발견(비로그인 전용 제외 패턴 하나). 제작소는 10패널을 `jump(o)` 칩으로 열어가며.
- 발견: `button, [onclick], input, select, textarea, a[href^="/"]` 중 가시·활성.
- **hit-test**: 요소 중앙 `elementFromPoint`가 그 요소(자손)가 아니면 "가려짐". 스위치는 클릭 전후 `checked`/`aria-checked` 변화 확인.
- 판정: pageerror/콘솔 error/`client_error` 송신/5xx·4xx(401·402·403 제외)/백지/이동 후 로드 실패 = 빨강. confirm 뜸·차단됨(의도)·외부링크 = 기록만.
- 서명 = `tag + data-check|id|onclick 함수명|텍스트 20자` → 같은 버튼의 이력을 잇는다.
- 규모 ≈ 500요소 × 2초 ≈ 15~20분 **예상(확인 필요)**. `--quick`=제작소만.

### 4.5 L2 흐름 시나리오 — 표준 패턴 3개와 첫 사례
파일 `checks/flows/<이름>.py`. 형식(의사 코드):
```
META = dict(name="장면편집에서 앞단계로 가면 편집이 사라짐", needs_worker=False, timeout_s=300)
STEPS = [ Step("…", do=…, check=[…]), … ]
```
**표준 패턴(`checks/patterns.py`, 모든 흐름이 빌려 씀)**
1. `roundtrip(step, edit, away=+2)` — ① step 진입 → edit 적용 → 값 A 기록 ② `jump(step+2)` → `jump(step)` → 값 == A ③ `page.reload()`(`?work=` 복원) → 값 == A ④ **1.5초 대기**(scene_lab 1.2초 autoApply 창) 후 서버 재조회 → 값 == A. 넷 중 하나라도 다르면 빨강 + "어느 단계에서 사라졌나"를 사유에. (사장님 ①)
2. `delete_then_reload(target)` — 삭제 클릭 → 서버 재조회에 없음 → `reload()` 후 화면에 없음 → 개수 = 전−1. (사장님 ②)
3. `count_preserved(from_step, to_step)` — 확정 대본 줄 수(`s2ScriptLines` L17971) == 3단계 칸 수 == scene_lab 칸 수 == TTS 문장 수. (실사고: 8줄 통짜)

**첫 사례 목록(Phase별)**
| 파일 | 일상어 이름 | 워커 | Phase |
|---|---|---|---|
| `flow_script_roundtrip.py` | 대본 고친 뒤 뒷단계 갔다 오면 대본이 그대로인가 | 불필요 | 1 |
| `flow_deco_roundtrip.py` | 꾸미기(머리카피·틀·폰트) 고친 뒤 갔다 오면 그대로인가 | 불필요(꾸미기 설정은 `_workState`) | 1 |
| `flow_tts_delete.py` | TTS 문장 지우면 정말 지워지는가(`vpDeleteBeat` → `/beat/{idx}/delete`) + 성우 카드 빼기 | **필요**(매칭 job) | 2 |
| `flow_scene_roundtrip.py` | 장면편집 컷 조정 → 꾸미기 → 돌아오면 컷·`film_*` 조각이 그대로인가(자동저장 1.2초 뒤에도) | 필요 | 2 |
| `flow_produce_roundtrip.py` | 제작소 한 바퀴: 담기(로컬 샘플 업로드)→대본 8줄→매칭→장면편집→꾸미기→미리보기→**렌더**→완성본 | 필요 | 2(미리보기까지)·3(렌더) |
| `flow_source_external.py` | 외부 URL 담기(인스타·유튜브·틱톡 1건씩) | 불필요 | 4 |

- `do`는 `data-check` 요소를 **클릭만** 한다(`page.evaluate`로 앱 함수 호출 금지 — `checks/` 안 `evaluate(` grep 자기검사). 폴링 상태는 사본 DB `job_queue`로 대조해 "화면 멈춤"과 "워커 멈춤"을 가른다.
- 완성본 불변식(Phase 3): `final.mp4` 존재·길이 ≈ target±15%·렌더 스냅샷 `plan.json` 편성 서명 == 렌더 직전 편성·이 job_id의 `api_events`에 silent/fallback 0건.
- 트랙 세션이 흐름을 추가하는 절차 = 파일 하나 복사해 `META`·`STEPS`를 고친다. 등록·설정 없음. 예상 10~20분.

### 4.6 L3 운영 건강 — 파일 하나 = 항목 하나
파일 `checks/health/<이름>.py`. 형식(의사 코드):
```
META = dict(name="유튜브 랭킹 수집이 26시간 넘게 없음", every="1h", source="reference.db settings last_run::youtube")
def measure(ctx) -> Sample(value, ok: bool, detail: str, evidence_url: str|None)
```
- 러너는 `every`가 지난 항목만 돈다(`health_samples`의 마지막 시각 대조). 항목이 자기 주기를 선언한다.
- **첫 항목(사장님 ③④⑤ + 뼈대 유지용)**

| 파일 | 일상어 이름 | 지표·정상범위 | 출처(재사용) | 주기 |
|---|---|---|---|---|
| `h_ranking_fresh.py` | 랭킹 수집이 멈춘 플랫폼 | 플랫폼별 `collected_at` 경과 < **26h** & items ≥ 1. 7플랫폼은 `Store.load_last_run_platform`(settings `last_run::*`), 인스타는 `last_run` 테이블 | store.py:2637 / 491 | 1h |

| `h_queue_health.py` | 제작 실패율·멈춘 워커 | 24h `job_queue` failed/(done+failed) < 15% & running인데 heartbeat 5분 초과 0건 | reference.db job_queue(ro) | 15m |

- 판정은 `ok`이면 초록, 아니면 빨강, `measure`가 예외를 내면 회색. "정상 범위" 숫자는 파일 안 `META`에 있고, 첫 운영 2주 동안 `health_samples` 분포를 보고 조정한다(문서가 아니라 파일이 정본).
- 항목 추가 = 파일 하나. 예상 10분.

### 4.7 안전 그물 (D10)
- `page.route`에서 POST/PUT/DELETE는 `checks/allow_mutations.py` 허용 목록에 있을 때만 통과(로그인·works·picks·mix·preview·render·seo·thumb·업로드·scene_lab apply·beat delete). 그 밖(`works/*/delete`, `buffer/schedule`, `voice-library/add`, `/api/admin/*` 변경, `DELETE *`)은 abort → "차단됨(의도)".
- `window.confirm=()=>false`, dialog 자동 닫기.
- 허용 목록 자기검사: `buffer|voice-library/add|kakao` 패턴이 허용 목록에 있으면 기동 거부.
- L3는 라이브 DB **읽기 전용**(`mode=ro`) — 쓰기 코드가 있으면 코드 리뷰에서 막는다(`checks/health/` 안 `execute("INSERT|UPDATE|DELETE` grep 자기검사).

