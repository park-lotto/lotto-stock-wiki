# 소스화질 — yt-dlp 선택자가 세로 1080p를 걸러내던 버그 (2026-09-18)

## 무엇을
- `media_download.py` `_download_ytdlp` 포맷 선택자 `height<=1080` → `_Q_CAP="[width<=1920][height<=1920]"`.
  세로 숏폼 1080p는 높이 1920이라 종전 조건에 걸러져 유튜브 608x1080 / 틱톡 576x1024를 받았다.
- 실측(서버 최근 job 소스 350개): 유튜브 33건 중 27건 608x1080, 틱톡 130건 중 112건 576x1024, 도우인만 1080x1920.
- 검증: 유튜브 쇼츠 7pX0L18nEyg / 틱톡 7499106489882234134 실제 다운로드 → 둘 다 1080x1920. 4K(GhBaFe-99RU)는 1920x1080으로 막힘.

## 왜
- 이윤정님(cid 505) "스마트 프로로 지운 영상이 흐리다" 제보. 자막제거·렌더는 SSIM으로 무손실 확인, 뿌리는 소스 해상도.

## 2차(같은 날) — 인스타·샤오홍슈까지
- 인스타: `_download_instagram` 맨 앞에 ⓪ `_download_ytdlp`(DASH 영상+음성 병합) 추가. 종전 ①·①-b는 합쳐진 단일 스트림만 골라 720p 천장.
  실측(로컬, 릴스 DdShJZpJqr5): 실제 함수 호출 → 1080x1920. 실패 시 종전 경로 폴백(회귀 0). 테스트 4건 통과.
- 샤오홍슈: 로그인 세션(rednote 쿠키)으로 노트 페이지 → `originVideoKey` → CDN(`sns-video-bd`(키에 '/' 있을 때)·`sns-video-qn`·`sns-bak-v1`)에서 **업로드 원본**.
  yt-dlp·검색 API는 720p 재인코딩본만 준다(-F 실측). 실측(서버, 실제 download_any): 6a975f43 → 1080x1920 hevc 70MB → h264 5Mbps 30초 /
  6a997ff0 → 1080x1920 113MB → h264 11Mbps 120초. 긴 변 1920 초과면 원본 안 받고 720p 경로.
  ⚠️ 서버 rednote_session.json(08-17)이 만료되면 키를 못 뽑아 조용히 720p로 돌아간다 — "샤오 화질 다시 떨어졌다" 제보엔 세션부터.

## 남은 것
- ⏭ 핀터레스트(12건, 576x1024 이하 섞임)·틱톡 hevc→h264 변환 비용은 미조사.
- ⏭ 샤오홍슈 원본은 hevc라 매번 h264 변환(30~120초). 정규화를 렌더 직전으로 미루거나 병렬화 검토.
- ⏭ 유튜브가 vp9(616)를 골라 _normalize가 h264 변환을 한 번 더 한다(시간 비용). 필요하면 vcodec 우선순위 조정.
- ⏭ 장면편집 전체재생 프록시(360p CRF30)가 체감 화질을 깎는다 — 고객 안내 또는 화질 상향 검토.
