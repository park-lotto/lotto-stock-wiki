## 4. 이사 절차 (새벽에 실행)

### ① 사전 복사가 끝났는지 확인
```bash
ssh -i <옛키> ubuntu@43.200.48.69
pgrep -f "rsync.*shopping_shorts/data" && echo "아직 진행 중" || echo "끝남"
du -sh /home/ubuntu/lotto-stock-wiki/shopping_shorts/data          # 옛
ssh -i ~/.ssh/migrate_key.pem ubuntu@3.35.251.172 "du -sh /home/ubuntu/lotto-stock-wiki/shopping_shorts/data"   # 새
```
두 숫자가 비슷하면 준비 완료. 아직이면 ②로 가도 되지만 중단 시간이 길어진다.

### ② 옛 서버 정지 — **여기서부터 서비스가 끊긴다**
```bash
# 옛 서버에서
sudo systemctl stop shopping-shorts stockbrain crawlingbot
sudo systemctl stop 'shopping-shorts-worker@*'
crontab -l > ~/crontab_backup_$(date +%Y%m%d).txt && crontab -r   # 크론도 멈춘다
```

### ③ 그동안 바뀐 것만 다시 복사
```bash
# 옛 서버에서 (--delete 주의: 새 서버에만 있는 파일을 지운다. 최종 동기화라 맞다)
rsync -a --delete --info=progress2 \
  -e "ssh -o StrictHostKeyChecking=no -i ~/.ssh/migrate_key.pem" \
  /home/ubuntu/lotto-stock-wiki/shopping_shorts/data/ \
  ubuntu@3.35.251.172:/home/ubuntu/lotto-stock-wiki/shopping_shorts/data/
```

### ④ 새 서버에서 최신 코드 받기 + 크론·서비스 되살리기
```bash
# 새 서버에서
cd /home/ubuntu/lotto-stock-wiki && git pull --ff-only origin main

crontab /home/ubuntu/migrate_backup_20260827/crontab_ubuntu_ORIGINAL.txt   # 크론 복구
crontab -l | wc -l                                                          # 19줄 확인

sudo systemctl enable --now shopping-shorts stockbrain crawlingbot
sudo bash /home/ubuntu/lotto-stock-wiki/deploy/worker_autoscale.sh          # 워커 자동 조정
```

> 💡 워커 수는 `/etc/shopping-shorts.env`의 `SHORTS_WORKERS`가 정한다. 지금 8로 박혀
> 있는데 **16코어에서는 지우거나 늘려도 된다**(지우면 자동으로 코어-2 = 14, 상한 규칙 적용).
> ffmpeg 스레드 배분은 08-27 수정으로 이 값을 제대로 따라간다.

| ① durfill·prewarm은 워커를 늘려도 1개만 돈다 | ℹ️ 동시성 확인은 **mix·render로** 하라. durfill로 재면 "안 는다"고 오진한다 |

## 10. 주의사항

- **옛 서버를 먼저 지우지 마라.** 며칠 지켜본 뒤에 판단한다.
- **키를 git·메일·카톡으로 보내지 마라.**
- ③의 `--delete`는 최종 동기화에서만 쓴다. 사전 복사 때는 쓰지 않았다.
- 새 서버 크론을 되살리기 전에 **옛 서버 크론이 멈췄는지** 반드시 확인한다

  고객이 죽은 서버로 간다.

## 절차

### 0. 사전
```bash
bash deploy/verify_server.sh > /tmp/before.txt   # 지금 상태를 떠둔다(대조용)
git -C /home/ubuntu/lotto-stock-wiki status --porcelain   # 비어 있어야 한다
```
워킹트리가 더러우면 새 서버에서 자동배포가 pull 실패로 **조용히 멈춘다**.
진행 중 렌더가 없는 시간(새벽)에 한다.

### 1. 스냅샷
Lightsail 콘솔 → 인스턴스 → Snapshots → **스냅샷 생성**. 73GB 기준 10~30분.

### 2. 새 인스턴스
스냅샷 → 새 인스턴스 생성 → **$160 (8vCPU/32GB/640GB)** · **같은 리전·가용영역**.

### 3. ★새 인스턴스 SSH 열기 (1차 때 밟은 함정)
Networking → SSH 규칙이 `Lightsail browser SSH` 전용으로 생성된다 →
Preset **Anywhere IPv4(0.0.0.0/0)** 로 바꿔야 우리 키로 접속된다. 80·443도 확인.
(8849·8090은 아파치가 앞단이라 **열지 않는다** — localhost만 듣는다)

### 4. ★유령 워커 치우기 (1차 때 밟은 함정)

유닛 목록을 보고 쓰지 않는 것은 **유닛 파일 자체를 치운다.**
