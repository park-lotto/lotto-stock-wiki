## ⏭ 사장님이 하실 일 (이것만 하면 봇이 돕니다)

```
① 텔레그램에서 @BotFather 에게 /newbot → 봇 이름 정하기 → 토큰 받기
② 만든 봇에게 아무 말이나 걸기
③ 아래 명령으로 chat_id 확인
④ .env 에 두 줄 넣기
⑤ 봇켜기.bat 더블클릭
```

**③ chat_id 확인:**

```bash
py -c "
import requests
token = input('봇 토큰: ').strip()
r = requests.get(f'https://api.telegram.org/bot{token}/getUpdates', timeout=20).json()
ids = {str(u.get('message', {}).get('chat', {}).get('id')) for u in r.get('result', [])}
ids.discard('None')
print('chat_id:', ', '.join(ids) if ids else '없음 — 봇에게 먼저 말을 거세요')
"
```

**④ `.env` 에 넣기** (gitignore라 git에 안 들어간다):

```
SHORTS_TELEGRAM_TOKEN=<①의 토큰>
SHORTS_TELEGRAM_CHAT_ID=<③의 chat_id>
```

⚠️ `DASH_USER` / `DASH_PASS` 도 `.env` 에 있어야 한다 — 서버 조회에 쓴다.
없으면 봇이 켜질 때 **어느 값이 없는지 이름으로** 말해준다.

## 무엇을 만들었나

사장님이 카톡에서 고객 질문을 복사해 텔레그램 봇에 넘기면, 봇이 **서버를 직접 조사해**
원인·고객께 보낼 문구를 돌려준다. 복붙이 2번에서 1번으로 준다.

```
[사장님 폰]          [사장님 PC]                    [서버]
텔레그램에 붙여넣기 → poller  수신
                     context 주소에서 job_id 추출
                     probe   ─────────HTTPS────────→ /api/login
                                                     /api/mix/status/{id}
                     reply   답변 조립  ←────────────┘
답변 받음        ←─── poller  발송
```

| 파일 | 책임 |
|---|---|
| `tg_bot/context.py` | 메시지 → job_id·주소 (순수 함수) |
| `tg_bot/probe.py` | 서버 API 조사 (로그인 + 상태조회) |
| `tg_bot/reply.py` | 조사 결과 → 답변 문자열 |
| `tg_bot/poller.py` | 텔레그램 수신·발송 |
| `tg_bot/run.py` | 묶어서 돌린다 |
| `봇켜기.bat` | 더블클릭 시작 |

## 설계에서 중요한 것 4가지

**① 비용이 0원이다.** 사장님 PC에서 `claude` CLI를 쓰므로 **구독**으로 동작한다.
서버 상주(Agent SDK)로 만들면 API 종량 과금이 된다 — 구독 크레딧 제도는 2026-06-15에
발표됐다가 **같은 날 보류**됐다(확인함). 그래서 PC 방식을 골랐다.

**② SSH를 안 쓴다.** 조사는 전부 HTTPS API다.
- 포트 22가 막혀도 돈다(2026-09-02 실측: SSH 전부 실패, 443은 200/307 정상)
- 서버 파일을 안 건드려 **배포가 멈추지 않는다**(auto_deploy는 워킹트리가 더러우면 조용히 스킵)

**③ 고객 문구를 지어내지 않는다.** `app.py`의 `_user_facing_error`를 **그대로 부른다**.
베껴 적으면 저쪽이 바뀔 때 어긋난다(0순위-B). 그 표는 2026-09-01에 실패 100건을 분석해
갱신된 것이라 우리가 새로 만들 이유가 없다.
- ⚠️ **함정**: `app.py`(18,011줄)를 통째로 import하면 부작용이 있어 **소스에서 필요한 4개만
  떼어 exec** 한다. 발췌가 실패하면 조용히 일반 문구로 폴백하므로 `table_loaded()` 가드
  테스트가 그걸 잡는다(사보타주로 빨개지는 것 확인함).

**④ 남이 봇에 말을 걸 수 없다.** 사장님 `chat_id` 외의 메시지는 버린다.
차단 코드를 빼면 테스트 2건이 빨개진다(확인함).

## 구현 중 잡은 것 (계획이 틀렸던 부분)

1. **API 경로가 달랐다** — 계획엔 `/api/produce/mix/status/`로 적었으나 실제는
   **`/api/mix/status/{job_id}`**(`app.py:4036`). 추측했으면 전부 404였다.
2. **모든 `/api/`가 401이다** — 코드에 `_require_admin`이 없어 "인증 불필요"로 보였으나,
   미들웨어(`app.py:10016`)가 로그인 없는 `/api/`를 통째로 막는다. 실제로 불러보고 알았다.
3. **변환표 규칙이 3개 더 있었다** — 계획엔 3종만 적었는데 실제는 6종(apify/인스타·
   unauthorized·ffmpeg 추가). 베끼지 않고 import하는 방식으로 바꿔 이 문제를 없앴다.
4. **발췌 정규식이 자기 줄에 걸렸다** — `rest[1:]`로 한 글자만 건너뛰니 같은 줄이 다시
   매칭돼 상수가 **1글자로 잘렸다**. 줄 단위로 건너뛰게 고쳤다.
5. **로컬 DB는 못 쓴다** — `reference.db`에 mix_jobs가 **1건뿐**. 서버 API를 봐야 한다.
