# 뉴스 인제스트 — 설계 (post 겸용 확장)

- **날짜**: 2026-06-21
- **배경**: 소스 확장 4번째. 겸용 `post_ingest`에 뉴스를 추가. 사용자 자리비움 중 자동진행 —
  추천안으로 결정.
- **범위**: 뉴스 인제스트(post 소스 추가). 겸용화 자산 재사용.

## 1. 뉴스 데이터 특성 (실데이터)
`raw/news/{date}_{seq}_{제목}.md` — 기사/묶음 1개 = 파일. 두 형식:
- **개별기사**: `**출처**`(아시아경제)·날짜·링크·키워드·관련종목 + [핵심내용]/[시장영향] 요약
- **묶음 [묶음]키워드**: `**키워드**`(호르무즈)·날짜·수집건수 + 종합요약 + 기사목록

블로그/유튜브와 차이: 헤더 라벨이 둘(출처/키워드), 뉴스는 **사실(event) 중심**(스탠스·방법론 거의 없음 — Gemini가 market/sector로 라우팅해 FACT 원자 생성).

## 2. 결정 (자동)
| 항목 | 결정 |
|---|---|
| 방식 | post 소스 추가(겸용 재사용) |
| 헤더 | `header_label`을 **리스트 허용**(출처→키워드 순서 시도). 작은 일반화 |
| source_name | 출처(개별=언론사) 또는 키워드(묶음) |
| 신뢰등급 | news_registry.json, 기본 C (언론사·키워드는 채널 아님) |
| 2층 | 뉴스는 FACT 위주 — 스탠스/방법론 자연 미생성(라우팅이 market/sector) |

## 3. 변경 (최소)
1. `post_sources.py`: `"news"` 엔트리 `{source_type:"news", dir:"raw/news", header_label:["출처","키워드"], registry:"news_registry.json"}`.
2. `_parse_post_header(md_path, header_label)`: header_label이 str 또는 list 허용 — 리스트면 순서대로 첫 매치 사용. (blog/youtube str 그대로 동작.)
3. `news_registry.json`: `{}` (기본 C).
4. `atom_pipeline.py`: STEP3.8 = `post_ingest --source news`.

## 4. 검증
- source_config("news"), _parse_post_header 리스트(출처 있으면 언론사 / 키워드만 있으면 키워드), blog/youtube str 회귀.
- 라이브: 개별기사 1 + 묶음 1 인제스트 → source_type=news, 섹터 분류.

## 5. 범위 밖
- `관련종목` 필드 활용(현재 본문 라우팅으로 종목 추출) — 후속 강화 후보.
