## 2. 개선방향 — 실행 태스크 (우선순위순)

### P0-1. 헌장 동적화 = 훅 로테이션 (반복 체감을 가장 크게 줄임)

`_STORY_RULES_CORE`를 정적 문자열 → **빌드 함수** `story_rules(hooks=None, persons=None)`로.
- 훅 블록: 승인 hook 부품에서 **매 호출 랜덤 샘플 k=5** (perf 가중 샘플링; 은행 비면 기존
  8문구 폴백 = 회귀0). 매 job 다른 훅 조합이 주입된다.
- 인물 예시도 소량 풀에서 로테이션(시어머니·남편만 반복 금지).
- ⚠️ 함정: 헌장은 `.format()`을 탄다 — 주입 문구는 반드시 `bank_assemble._sanitize`(중괄호 소독)
  통과. 기존 브레이스 가드 테스트에 케이스 추가.
- `edit_plan.py:428-432`(scene_first의 중복 예문)와 `_STRONG_OPENER_TOKENS`도 같은 소스에서
  파생시켜 하드코딩 3곳(헌장·scene_first·토큰)을 **한 곳**으로.

### P0-2. 믹스 경로에 은행 배선 (은행이 영상을 바꾸게)

`_scene_first_candidates`에 `bank_context` 인자 추가 → `build_scene_first_plan` →
`_plan_and_tts`에서 `assemble_bank_context(store, category)` 호출해 관통.
스위치는 ping_pong처럼 전역 설정(`bank_enabled`) — 기본 off·회귀0, 켜면 훅·어미·부사·
스파인 charter가 실제 영상 대본 프롬프트에 실린다. F5 네거티브도 이때 같이:
`store.list_pattern_items(is_negative=1)` → "[쓰지 마라 — AI냄새 문구]" 블록.

### P0-3. novelty 메모리 (job 간 반복 차단) ★획기적 핵심

- mix job 완료 시 그 대본의 (훅 오프너, story_person, cta_keyword, 사용 부품 id)를
  경량 테이블(예: `recent_usage`)에 기록.
- 생성 프롬프트에 "최근 영상에서 이미 쓴 것 — 다르게 써라: {최근 훅 5개·인물·CTA}" 블록 주입.
- 사후 게이트: 후보 훅이 최근 훅과 `_ngram_overlap>0.5`면 `_score_candidate` 감점
  (기존 n-gram 유틸 재사용, `edit_plan.py:216-227`).

### P1-1. scene_first 품질 게이트

`_score_candidate`(현재 fit·forced·diversity만)에 `tone_score.score_conversational` +
`fun_intensity.has_strong` 결합 → 추천안이 "대화체+재미장치 있는" 후보가 되게.
negatives 인자에 F5 뱅크 전달.

### P1-2. 서브 의무삽입 (기존 ⏭ ★)

백본 흐름에 s0/s2를 강제 1회 이상 끼움 — dedup으론 못 잡는 "아예 안 씀" 해소.

### P1-3. CTA·구조 변주

- CTA 문구 은행화: 댓글형이라도 문구 로테이션(cta 버킷 승인부품에서 샘플).
- 스파인 charter를 scene_first에(P0-2에 포함) — 승인 아크가 2개 이상이면 로테이션 = 구조 다양화.
- 훅 taxonomy: pattern_item.tags에 hook_type(타깃콜아웃/충격/발견/극찬/경고/자기고백/질문…)
  태깅, 추출 프롬프트(`pattern_bank._PROMPT`)에 유형 분류 지시 추가. **"자~ OO하시는 분들
  주목하세요"류 타깃 콜아웃형을 유형으로 신설**하고 시드로 몇 개 넣기.

### P2. 수확·확장

- **훅 자동 수확 강화**: 크롤 우승작 중 대본 전체 추출이 없어도 캡션/첫 문장에서 훅 후보만
  뽑아 hook 버킷 pending으로(커버리지 낮은 문제의 우회). 목표 훅 100개+.
- **훅 성과 역전파** ★획기적: job이 쓴 훅 부품 id 기록(P0-3의 테이블) → 업로드 영상 성과가
  들어오면 그 훅 부품 perf에 반영 → perf 가중 샘플(P0-1)이 자동으로 "먹히는 훅"을 더 자주
  뽑는 자기강화 루프. perf 배관은 Phase1에 이미 있음 — 연결만.
- F1 action_dict 상품군 확장(뷰티·수납·청소·의류), 백본-베이스 배선, UI 토글
  (ping_pong·bank·백본 지정 — produce.html, ⚠️JS 문법 깨지면 제작소 안 열림 → node --check 필수).

## 3. 실행 순서 제안 (오푸스)

1. **P0-1 + P0-2를 한 묶음**으로 (헌장 동적화 + 믹스 배선) — 훅 단조·말투·구조 반복이 한 번에 풀림.
   기본 off 스위치로 회귀0 유지, 서버에서 켜고 실측.
2. **P0-3 novelty 메모리** — job 간 반복 차단. 이게 "거의 반복된다" 체감의 직접 해법.
3. P1 셋(품질 게이트·서브 의무삽입·CTA 변주).
4. P2는 각각 독립 — 훅 수확은 야간배치에 얹기.

**전부 TDD**(기존 관례: call 주입점으로 실 Gemini 안 침). 헌장 변경은 전 생성 경로 공유라
