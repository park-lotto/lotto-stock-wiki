# 11 팩 대응 — 판 `packs` 칸 + 벤치 측정값→팩 항목 대응 `pack_map.py` + 칼카피 길 모션팩·짤팩 연결 (표준 §10-1·§10-2 · 02 뒤)

## 목표
프리셋 = "팩에서 고른 기본 선택의 묶음"이 **판 칸에 적힌다**. 15 요소마다 어느 팩의 어느 항목을 쓰는지(`packs.*`)·벤치 측정값에서 그 항목을 고른 근거(`from`)·팩에 없는 것(`gap` + 팩 요청)을 자동으로 채운다. 칼카피 길(render_bench)이 모션팩·짤팩을 못 쓰는 결손을 메운다.

## 실측 배경(10-25)
- 자막팩 CAPTION_PACKS 최상위 12키(칼카피 6: kitchit·kkultemnote·starpick·recipe·goodletter·ititemlog) · 모션팩 2(`assets/motion/packs.json`) · 효과음팩 20(`sfx_packs/packs.json` slots 7) · BGM 24(`bgm_lib/catalog.json`) · 짤 = 서버 `/api/meme/pack`+prefs(회원별) ↔ 칼카피 로컬 `C:/숏템_칼카피/packs/meme`(두 벌).
- `render_bench.snapshot(pack)`(721~725): `captionPack` 만 판에서, **`motionPack:"off"` 고정** · 효과음은 판 `sfx_files{kind: '팩01/pop.wav'}` 파일 경로 직접 · BGM `bgm.id`.
- 벤치 측정 → 팩 항목을 잇는 함수 없음(사람이 판 파일에 손으로 적음 — 키치잇판 `caption.pack:"kitchit"` 등).
- 신호 도구: `engine/sound/sfx_fp.py·sfx_ncc.py`(효과음 지문·상관) · `bgm_fp.py` · `kal_analyze.enter_key`(등장 어휘) · `frame_metrics`(글자 높이·ΔE).

## 설계
1. `pack_map.map_all(slug, style) -> packs` — 요소별 거리: `cap_look`(판 frame/caption 실측·팔레트 ↔ 자막팩 look: 글꼴 일치·px ±10%·ΔE<5) · `cap_enter`(규칙빈도 `enter` 분포 → 팩 enter/variants 이름표, `enter_key` 어휘) · `transition`(03 의 `transitions` 종류 → 모션팩 항목 이름표; 없으면 gap) · `sfx`(벤치 `_kal/sfx_events.json` 지문 ↔ 팩 파일 `sfx_fp` NCC ≥0.6 → slot, 없으면 종류 이름표 pop→뽁·ding→띠링·whoosh→휙) · `bgm`(02 `bgm_pick.recommend` 후보 3 → `candidates`, `id` 는 사람이 — 기존 값 유지) · `meme`(규칙빈도 meme k/n → `rate`·`tone`, 0 이면 pack none). 결과 `packs.*.from` 에 "측정값 → 항목(거리)" 한 줄.
2. `styles.load(name, patch=None)`: `packs` 있으면 정본 → 옛 칸을 채움(`caption.pack = packs.caption.pack`, `sfx_files = {kind: 팩/파일}` 를 packs.json slot 에서 풀어 씀, `bgm.id`). 둘 다 있고 다르면 **오류**(조용히 덮지 않음). `patch` 인자는 12 가 쓴다(여기서는 자리만).
3. `render_bench.snapshot()`: `motionPack = packs.motion.pack`(off 포함) · 짤은 `placed.stickers kind=meme` 가 `packs.meme.pack` 에 따라 로컬 팩/서버 prefs 중 어디서 파일을 받는지 — **파일 고르기는 03 의 placement**, 여기선 경로 해석만.
4. 카드 레코드 `pack_item`(01 생성기가 `packs` 를 읽어 채움 — 01 에 쪽지로 키 이름만 알림).
5. 요청서: gap 마다 `channel/<slug>/_kal/팩요청.md`(요소·벤치 실측값·프레임 경로·원하는 항목 꼴) — 지침서 §4-2 요청서 꼴.

## 합격 검사(사보타주 먼저)
1. 8개 판에 `packs` 가 채워지고 `styles.load` 가 옛 칸과 **같은 값**을 낸다(변환 전후 `caption.pack`·`sfx_files`·`bgm.id` diff 0) — 사보타주: `packs.caption.pack` 을 다른 키로 바꾸면 load 가 '두 벌 불일치' 오류.
2. `pack_map` 거리: 키치잇 벤치 자막 실측(스타일분석 §1 글꼴·px·색) → 자막팩 후보 1위가 `kitchit`(6개 칼카피 판 전부 자기 팩이 1위) · 효과음: 스타픽룸 `sfx_events` 지문 ↔ 팩01 파일 NCC 표(≥0.6 몇 개, 미만은 이름표) · 없는 항목(줌블러 모션)은 `gap` + 팩요청.md 생성.
3. `motionPack` 을 `dynamic_pop` 으로 둔 시험 판으로 렌더하면 훅 자막에 모션이 **실제로** 보인다(0.1초 띠 잉크 변화) · off 판은 고치기 전과 프레임 평균차 <1.0.
4. 카드 `pack_item` 이 15 요소 중 팩 있는 10 요소에 채워진다(01 과 합쳐 확인).
