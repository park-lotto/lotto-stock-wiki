# 자막↔음성 싱크 자동교정 (1단계, 엔진) — 설계

**날짜**: 2026-07-18 · **트랙**: 자막싱크 (`track/자막싱크`) · **BASE**: origin/main

## 한 줄

한 비트 안 자막 조각의 표시 시간을 **글자 수 추정**이 아니라 **실제 말한 타이밍(ASR 워드 타임스탬프)**으로
찍어, "자막이 음성보다 약간씩 빠르거나 느린" 어긋남을 뿌리에서 없앤다. 화면 변경 없음.

## 문제 (코드 추적으로 확정, 라이브 미재현)

- 비트(장면) **단위**로는 자막이 이미 **실측 음성 길이**에 맞는다 — `_beat_timeline`이
  `dur = _probe_duration(tts)`로 t0/dur를 쌓음(`video_assemble.py:657,665`). 여기선 안 밀린다.
- 어긋남은 비트 **안**에서 난다. `_caption_segments`가 대본을 2~3어절 호흡 구절로 쪼갠 뒤
  (`video_assemble.py:169`), `_caption_durations`가 각 구절 표시 시간을 **글자 수 비례**
  (`weights = len(chars)`, `video_assemble.py:240-242`)로 추정한다. 실제 말은 글자 수대로 고르게
  나오지 않고(쉼·강조·음절 속도), 특히 `audio_post`의 `silenceremove`가 문장 내 침묵을 잘라
  글자수 가정을 더 깨뜨린다 → 구절 2·3이 음성보다 앞서거나 처짐. 비트 경계마다 재동기되므로
  누적은 안 되고 **"약간씩"** 진동한다 = 사장님 증상과 일치.

## 목표 / 비목표

**목표**
1. 자막 구절 표시 시간을 실제 음성 타이밍으로 → 어긋남 대부분 자동 소멸.
2. **미리보기와 최종 영상이 똑같은 값**을 쓴다(들은 것 ≠ 나온 것 seam 차단 — 2026-07-15 10건 교훈).
3. **ASR 불가 시(GROQ 키 없음·실패) 현행 동작 그대로** = 회귀 0.

**비목표(2단계·YAGNI)**
- 음성 프리뷰 화면·재생·비트별 딸깍(당기기/밀기) → **꾸미기 단계의 공용 프리뷰 UI를 재사용**(모션효과 트랙 소유).
- 비트 경계 타이밍(이미 맞음)·자막 문구/줄바꿈·조각 분할 규칙(`_caption_segments`) 변경 — 손대지 않는다.

## 핵심 난관 — 말한 것 ≠ 자막

자막은 **원본 대본**(`b["narration"]`)으로 그린다(`_caption_drawtexts` 인자). 그런데 TTS가 실제
읽는 건 **자연화된 텍스트**다 — `narration_naturalize`가 추임새(`와,`·`음,`)를 넣고, 감정태그
(`[excited]`)를 붙이며(ElevenLabs가 태그는 발화 안 함), 구어체로 살짝 바꾼다. 따라서 ASR이 받아쓴
단어열(=말한 것)과 자막 구절의 단어열(=원본)이 **서로 다르다**. 단순 인덱스 매칭은 깨진다.

**정렬 방식(결정)**: 기존 `asr_check.diff_words`(difflib 단어 단위 정렬, equal/sub/del/ins,
`asr_check.py:22`)를 **재사용**한다.
1. ASR을 워드 타임스탬프까지 받아온다(아래 §A).
2. `원본 대본 단어열` vs `ASR 단어열`을 `diff_words`로 정렬 → 원본 각 단어가 어느 ASR 단어(=시각)에
   대응하는지 얻는다. 추임새 같은 ASR-only 단어(ins)는 인접 구절의 간격으로 흡수, 못 받아쓴 단어(del)는
   앞뒤 시각을 선형 보간.
3. `_caption_segments`가 만든 각 구절(원본 단어들의 연속 span)의 **첫 단어 시작 시각 ~ 마지막 단어 끝
   시각**을 그 구절의 표시 구간으로 삼는다 → 구절별 실제 dur.

**신뢰도 폴백(비트 단위)**: 정렬 불일치가 과하면(예: `mismatch_score`가 임계 초과, 또는 매칭된 원본
단어 비율이 낮음) 그 비트만 **현행 글자수 비례로 폴백**한다. ASR이 엉뚱하게 받아쓴 비트가 오히려
자막을 망치는 걸 막는다. 임계값은 구현 때 실데이터로 정하고, 못 정하면 보수적으로(불일치 조금만 있어도
폴백) 잡는다 — 안 고치는 게 잘못 고치는 것보다 안전.

## 아키텍처

경계가 분명한 순수 함수 위주로, 렌더 경로엔 **읽기만** 얹는다.

### A. `asr_check` — 워드 타임스탬프 받기 (`asr_check.py`)
- `transcribe(path)`는 지금 텍스트만 반환(`asr_check.py:51`). **새 함수 `transcribe_words(path)`**
  추가: Whisper를 `response_format=verbose_json`, `timestamp_granularities=["word"]`로 호출해
  `[{"word","start","end"}, …]` 반환. 키 없음·실패·형식오류면 `None`(현행 `except: return None` 관례 유지).
- 기존 `transcribe`·`asr_ranker`(N-best)는 **불변**. (선택 최적화: N-best가 고른 take를 워드까지
  한 번에 받아 재사용 — v1은 안 함, 최종 mp3를 한 번 더 받아쓰는 단순 경로로.)

### B. 정렬 → 구절 dur (**신규 모듈 `caption_sync.py`** — 순수 함수)
> 신규 파일로 뺀다: 정렬 로직은 결정적 순수 함수라 독립 테스트가 쉽고, 비대해진 `video_assemble.py`를
> 더 키우지 않는다. `video_assemble`·`mix_pipeline`이 import해서 쓴다.
- `phrase_durs_from_words(narration, words, total_dur) -> list[float] | None`
  - `segs = _caption_segments(narration)` (기존 재사용)
  - `diff_words`로 원본↔ASR 정렬 → 각 원본 단어의 (start,end) 부여(보간 포함)
  - 각 seg의 실제 구간 길이 리스트 반환. 신뢰도 미달이면 `None`(→ 호출부가 폴백).
  - **결정적·부수효과 없음** = 단위 테스트로 자물쇠 가능(워드열·대본 주면 dur 나옴).

### C. `_caption_durations` 최소 변경 (`video_assemble.py:230`)
- 시그니처에 선택 인자 `real_durs=None` 추가. `real_durs`가 오면 그걸 쓰고(하한·총합 보정 로직은
  그대로 재사용), 없으면 **지금 코드 그대로**(글자수 비례). → ASR 경로/폴백이 한 함수로 합류, 분기 최소.

### D. 계산·저장 위치 (단일 경로, seam 차단)
- 비트별 최종 mp3가 디스크에 존재하는 지점 = `mix_pipeline._synthesize_beats`
  (`mix_pipeline.py:78`, atempo+silence-trim 끝난 뒤). 여기서 비트마다 `transcribe_words` →
  `phrase_durs_from_words` → 결과를 **beat에 저장**(`beat["cap_durs"]`), edit_plan_json에 실림.
- 렌더(자막 드로우)는 `beat.get("cap_durs")`를 읽어 `_caption_durations(..., real_durs=cap_durs)`에
  넘긴다. **저장 위치 = 읽기 위치**, 미리보기·최종이 같은 `_synthesize_beats`를 타므로 같은 값을 본다.
  - ⚠️ 구현 체크포인트: 미리보기(run_preview)와 최종 렌더가 **둘 다** 이 저장값을 읽는지 실측 확인
    (한쪽만 읽으면 그게 곧 seam). 재합성 없이 재사용될 때도 `cap_durs`가 살아있는지 확인.

## 회귀·안전

- **키 없음/실패** → `transcribe_words`=None → `cap_durs` 미설정 → `_caption_durations`가
  기존 분기 = **바이트 동일 출력**. (로컬 키 0개라 실개발은 이 경로.) 테스트로 잠금.
- 신뢰도 폴백 비트도 동일.
- 자막 **문구/줄바꿈/조각 경계**는 안 바뀐다 — 오직 **각 조각의 표시 시간**만 바뀐다.

## 테스트

1. **순수 정렬 함수**: (대본, 가짜 워드타임, total_dur) → 기대 dur. 추임새 ins/미전사 del/치환 sub
   케이스 각각. 뮤턴트(정렬 무시하고 글자수로) → 죽는지.
2. **폴백**: `transcribe_words`가 None이면 `_caption_durations` 출력이 기존과 **바이트 동일**.
3. **신뢰도 폴백**: 불일치 큰 ASR → 그 비트만 글자수 폴백.
4. **seam e2e**: 저장된 `cap_durs`가 미리보기·최종 양쪽 자막 enable 시각에 동일 반영(저장≠읽기면 실패).
5. 총합·하한 보정이 `real_durs` 경로에서도 유지(총 dur 초과 없음).

## 미확정(구현 때 실데이터로 확정, 임의단정 금지)
- 신뢰도 폴백 임계값(구체 수치).
- Whisper 한국어 워드 분절이 우리 어절과 얼마나 어긋나는지(diff가 흡수하는 범위) — 실 mp3로 관측.
- N-best take 재사용 최적화 도입 여부(v1 제외).
