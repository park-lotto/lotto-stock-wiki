# 레퍼런스 영상 출처·정보 표시 — 설계

- 날짜: 2026-07-22
- 트랙: 레퍼런스정보
- 상태: 설계 승인됨 (사장님 "고")

## 문제

렌즈 유사영상 패널과 제작소 "넘어온 영상(재료)" 리스트의 카드는 지금
**platform · title · thumbnail · 원본url**만 들고 있다(구글 렌즈 visual_matches가
link/title/thumbnail만 주고, `mix_basket`도 url·thumbnail·name·caption만 저장).
그래서 "이 레퍼런스가 어느 채널 건지, 얼마나 터졌는지, 사람들이 뭐라 댓글 다는지"를
카드에서 볼 수 없다. 매번 원본을 새 탭으로 열어 확인해야 한다.

## 목표

담은/넘어온 영상 카드마다 아래를 **상시 표시**한다. 두 화면 모두(렌즈 유사영상 패널 +
제작소 재료 리스트).

- **채널 정보**: 채널명 · 채널 URL · 구독자 수
- **영상 지표**: 조회수 · 좋아요 · 댓글수 · 업로드일
- **인기 댓글**: 상위 3~5개(반응·후킹 포인트 파악용)
- **원문 캡션 전체**: 카드에 잘려 나오는 설명/해시태그 전문

## 범위 (비용 통제)

- **유튜브: 자동**. YouTube Data API v3 무료 쿼터 내에서 카드 렌더 시 자동 조회.
- **틱톡·인스타·샤오홍슈·도우인: 수동**. 무료 API가 없어 Apify 유료 호출이 필요하므로,
  카드의 **"ℹ️ 정보 채우기" 버튼**을 눌렀을 때만 조회한다(호출 비용 통제).

## 아키텍처

### ① 데이터 소스 층 — `shopping_shorts/youtube_client.py` 확장

기존에 `_stats(video_ids, token)`(views/likes/comments 수)과 키 로테이션이 이미 있다.
여기에 추가:

- `video_id_from_url(url) -> str|None`
  - `youtube.com/watch?v=`, `youtu.be/`, `youtube.com/shorts/` 3형태 파싱.
- `enrich_youtube(url) -> dict|None`
  - `videos.list(part=snippet,statistics, id=<vid>)` → 제목·설명(캡션)·채널ID·조회/좋아요/댓글수·업로드일
  - `channels.list(part=snippet,statistics, id=<channelId>)` → 채널명·구독자수·채널 URL
  - `commentThreads.list(part=snippet, videoId=<vid>, order=relevance, maxResults=5)` → 인기 댓글 상위 N
  - 반환: `{platform:"youtube", channel_name, channel_url, subscribers, views, likes,
    comment_count, upload_date, top_comments:[{author,text,likes}], caption}`
  - **기존 `YOUTUBE_API_KEYS` 로테이션 재사용**(쿼터 초과 시 다음 키).

비유튜브 플랫폼은 별도 모듈에서:

- `shopping_shorts/lens_enrich.py`(신규, 얇은 디스패처)
  - `enrich(platform, url, force) -> dict|None`
  - platform이 youtube면 `enrich_youtube`, 아니면(force일 때만) Apify 경로.
  - Apify 경로는 기존 `xiaohongshu_search.py`/`douyin_search.py`의 Apify 호출 패턴 재사용.
    틱톡=clockworks/tiktok-scraper, 인스타=인스타 액터. **지표 0으로 오는 경우 있음(메모리
    실측)** → 있는 필드만 채운다.

### ② 저장/캐시 — 신규 테이블 `source_enrichment`

```sql
CREATE TABLE IF NOT EXISTS source_enrichment (
    url TEXT PRIMARY KEY,
    platform TEXT,
    channel_name TEXT,
    channel_url TEXT,
    subscribers INTEGER,
    views INTEGER,
    likes INTEGER,
    comment_count INTEGER,
    upload_date TEXT,
    top_comments_json TEXT,
    caption TEXT,
    status TEXT,        -- ok | no_data | quota | error
    fetched_at TEXT
)
```

- 키 = **url**. 렌즈 카드는 `mix_basket`에 없는 일시적 결과라, url 캐시 하나가 렌즈·재료
  두 화면을 동시에 커버한다. `mix_basket`에는 컬럼을 추가하지 않는다(격리).
- **7일 TTL**: `fetched_at`이 7일 이내면 캐시 반환, 지나면 재조회. 지표가 살짝 낡아도
  레퍼런스 용도라 허용.
- store.py에 `get_enrichment(url)` / `upsert_enrichment(row)` 메서드 추가.

### ③ 백엔드 — `shopping_shorts/app.py`

- `POST /api/enrich` `{url, platform, force?:false}` → dict
  1. `store.get_enrichment(url)` 캐시 확인(7일 이내면 즉시 반환).
  2. 없거나 만료: 유튜브면 자동 조회. 비유튜브는 **force=true일 때만** 조회, 아니면
     `{status:"needs_manual"}` 반환(프론트가 버튼 노출).
  3. 결과 `upsert_enrichment` 후 반환.
- 응답에 `status` 포함 → 프론트가 상태별 UI 분기(ok/no_data/quota/needs_manual).
- 페이월/인증은 기존 미들웨어 정책을 그대로 따른다(신규 우회 없음).

### ④ 프론트 — `find.html`(렌즈), 제작소 재료 리스트

각 카드에 정보 영역 추가:

- **채널명 · 구독자** (채널 URL 링크)
- **조회 · 좋아요 · 댓글 · 업로드일**
- **인기 댓글**(접기/펼침, 기본 접힘)
- **원문 캡션 전체**(접기/펼침)

동작:

- **유튜브 카드**: 뷰포트 진입 시 lazy 자동 `POST /api/enrich`(IntersectionObserver).
  한 화면 카드 수가 많으니 스크롤 진입분만 조회해 쿼터 절약.
- **비유튜브 카드**: `status:"needs_manual"`이면 **"ℹ️ 정보 채우기" 버튼** 노출 →
  클릭 시 `force=true`로 재요청, 로딩 스피너 후 채움.
- 실패해도 카드 본체(썸네일·제목·버튼)는 그대로. 정보 영역만 "정보 없음" 표시.

### ⑤ 에러 처리

- 쿼터 소진: `status:"quota"` → "정보 없음(쿼터)" 표시, 카드는 정상.
- Apify 0지표: 있는 필드만 채우고 없는 건 숨김.
- URL 파싱 실패(video_id 못 뽑음): `status:"no_data"`.
- **카드 렌더는 어떤 경우에도 막지 않는다.**

## 테스트

- `youtube_client.video_id_from_url`: 3형태 URL + 잘못된 URL 파싱(순수 함수, mock 불필요).
- `enrich_youtube`: HTTP mock으로 videos/channels/commentThreads 합성 → 반환 dict 형태 검증.
- `store`: upsert→get 라운드트립, 7일 TTL 만료 판정.
- `/api/enrich`: 캐시 히트(재조회 안 함) / 유튜브 자동 / 비유튜브 force 없으면 needs_manual.
- 실 API는 쿼터·비용 때문에 CI에서 돌리지 않음(mock). 라이브 확인은 서버 배포 후 실카드 1장.
