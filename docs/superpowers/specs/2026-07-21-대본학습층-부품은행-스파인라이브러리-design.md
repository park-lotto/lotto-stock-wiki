# 대본 학습층 — 스파인 라이브러리 + 8버킷 부품 은행 (설계)

작성: 2026-07-21 (Opus 4.8, 사장님 브레인스토밍) · 검토: 페이블 예정
발주 맥락: 사장님 "대본을 계속 학습하고 개선하는 페이지/시스템을 만들고, 거기서 좋은 점을 계속 뽑아나가고 싶다."
계기: 잘되는 IG 릴스 3개(다이소 기미크림) vs 우리 생성물 비교 → **우리 생성물이 원본의 승리 요소(길이·비트·CTA반복·대화체 어미)를 압축하며 날려버림** 확인.

## 0. 진단 — 이미 있는 것과 없는 것

**이미 있다 (재활용):**
- `structure_analyze.py` — S급 대본 1개를 Gemini로 해부: `hook_type·characters·storyline·development·twist·appeal·tone·cta·beats·devices·one_line_why`.
- `element_stats.py` — 요소를 Gemini 클러스터링(`MIN_SAMPLES=20` 게이트) → `element_category_stats` 캐시.
- `daily_batch.py` — 야간 배치(요소 통계 갱신). *A4 원격 crontab 등록은 미완.*
- `build_scene_first_plan`(edit_plan.py) — **2트랙 모델**: 소스 대본들을 장면 팔레트로 읽고 + reference_text + 스토리 헌장(`_STORY_RULES_CORE`+`_STORY_DECLARE`) → 후보 3개(story{인물·사건·결말·CTA} + 비트별 seg_ids 매칭 + fit·forced + 점수·추천). 출력은 기존 EDL 포맷 → 렌더 무변경.
- 2트랙 규칙 이미 박힘: **"인물 1·사건 1·결말 1 정하고, 다른 대본에선 표현·훅·말투만 빌리고 인물·사건은 절대 섞지 마라."**
- `script_drafts` 디벨롭 루프(refine·edit·version history).
- 크롤러(tiktok/instagram/douyin/xiaohongshu) + 성과 수치(조회·좋아요·저장·댓글) 확보됨.

**없다 (이 스펙이 짓는 것):**
- 스토리 아크가 **손으로 쓴 고정 헌장**(`_STORY_RULES_CORE`)에 갇혀 있음 → 매일 터지는 스토리를 **배우지 않는다**.
- "표현·훅·말투 빌리기"를 제미니가 **즉흥으로** 함 → 검증·성과가중된 **부품 은행이 없다**.
- 문장 조립 단위의 **마이크로 부품**(어미·담화부사·감정표현 등)이 데이터로 안 잡힘 → 우리 생성물이 요약체("확인하셨어요")로 죽는 근본 원인.

**핵심 통찰:** 스토리 스파인 기계(2트랙 + scene-first)는 이미 돈다. 이 스펙은 **그 기계의 고정 손잡이 2개를 "매일 배우는 데이터"로 바꾸는 학습층**이다. 새로 짓는 건 학습·저장·큐레이션·선택이고, 생성·믹스·렌더는 그대로 재활용한다.

## 2. 데이터가 많아질수록 좋아지는 원리 (4축)

1. **일화 → 법칙**: 3개="추측", 300개="상위 성과의 87%가 수다체 어미" 법칙. `MIN_SAMPLES` 게이트가 노이즈 차단.
2. **성과 상관 → 가중치**: 부품마다 출처영상 성과 부착 → "CTA 3회 반복 대본이 댓글 2.1배" 계산 → 생성이 그쪽으로 가중.
3. **조합·세분화**: 개별 부품이 아니라 **같이 터지는 조합**과 **제품군별 승리 아크**가 드러남(화장품↔안전용품 훅이 다름).
4. **폐루프 자기개선**: 우리 생성 영상 성과도 회수 재투입 → 요약체가 성과 깎으면 **네거티브 학습(가드레일)** → 최근 가중치로 낡은 훅 감쇠·뜨는 훅 부상.

### 3-1. 큐레이션 페이지 (핵심 UI)
- 상단: **대본 붙여넣기 입력창** → 붙이면 즉시 AI 분해 → '대기(pending)'로 은행에 쌓임.
- 좌: 버킷 탭(마이크로 8 + 매크로 스파인).
- 각 부품 카드: 문구 · 빈도 · 성과점수 · 출처 예문 · **[승인][기각][수정]** · 태그.
- 정렬: 성과순 / 빈도순 / 최신.
- 스파인 탭: 아크 카드(이름·비트체인·감정아크·적합 제품군·성과·출처 대본 수).

### 3-2. 생성 반영 (적재적소)
1. 새 제품 입력(제품군 + 셀링포인트) → 시스템이 **제품군·셀링·성과 가중으로 스파인 후보 랭크** → 최고안 추천(사장님 최종선택).
2. 선택 스파인의 비트체인을 `build_scene_first_plan`에 **비트 뼈대로 주입**(현재의 정적 `_STORY_RULES_CORE` 자리에 학습된 아크 삽입).
3. 각 비트를 **승인 부품 은행**에서 성과가중 샘플링해 voicing. **스타일 부품=자유조합, 내용 부품=선택 스파인의 인물·상황과 일치할 때만**(D9).
4. **대화체 스코어러**: 생성문을 승인 코퍼스와 대조 — 어미 다양성·감정어 밀도 측정 + 요약체 페널티. 임계 미달이면 재생성(D6 집행).

### 3-3. 믹스 도너 같은 스파인 우선 (D10)
- `run_mix_job`의 도너 선택 시, 후보 소스에 스파인 태그를 붙여 **목표 스파인과 일치하는 소스를 우선** 채택.
- 효과: 3영상의 장면들이 *한 아크의 같은 비트*에 호환 → 화면 튐 방지(현재는 장면 시간순만 보고 스파인 일치는 안 봄).
- 일치 소스가 부족하면 기존 방식으로 폴백(안전).

## 4. 데이터 모델 (신규 전용 스키마)

**`pattern_source` (원본 대본)**
`id · source(tiktok/ig/douyin/xhs/manual) · url · full_text · product_category · perf{views,likes,saves,comments} · structure_json(structure_analyze 출력 재활용) · spine_id(FK, 클러스터 배정) · is_winner(사람 승인) · collected_at`

**`pattern_item` (마이크로 부품)**
`id · bucket(enum 8) · text(문구/템플릿) · canonical(정규화 dedup 키) · slot_role · source_ids[] · freq(등장 대본 수) · perf_score(출처 성과 가중 집계) · status(pending/approved/rejected) · tags[] · note · created/updated`

**`spine` (매크로 상황 스파인)**
`id · name(제3자의심→인정 …) · situation_type · character_roles[] · beat_chain[{label, role, anchor|free}] · emotion_arc · appeal · fit_categories[] · source_count · perf_score · status · created/updated`

- 매크로 층은 `structure_analyze` JSON을 `pattern_source.structure_json`으로 저장해 재활용하고, 클러스터 결과를 `spine`으로 승격.
- `perf_score` 산식은 상수로 노출(구현 중 실데이터로 조정). 초안: 정규화 성과의 로그 가중 평균 × 최근성 감쇠.

## 8. 싱크 사다리 + 백본-인터리브 + 차별화 엔진 (팩토리 경로)

계기: 실제 릴랜턴 영상(youtube shorts 0Fd2ObhVuqw) 분석 — 나레이션 매 문장이 화면 행위를 1:1 지목("이걸 쫙 땡기는" ↔ 손이 줄 당김). 우리 2트랙(앵커만)보다 한 단계 위.

### 8-1. 싱크 3레벨
| 레벨 | 정의 | 예시 | 필요 소스 |
|---|---|---|---|
| **L1 무매칭** | 장면 나열 + 대본 얹기 | 초기 버그(given_script) | 아무 클립 |
| **L2 앵커싱크** | 2트랙, 앵커 비트만 스냅 | 요리·홈에디터·기미크림 IG릴 | 과정 footage |
| **L3 데모락트** | 매 비트가 화면 행위 지목 | 릴랜턴 영상 | 그 제품 실사용 데모 |

**전략: 제품군이 목표 레벨을 정한다.** 행위·기믹이 파는 제품(릴랜턴·주방·청소)=L3 필요 / 감성·효능(기미크림)=L2로 충분(L3 과잉). 이 스펙(부품은행+스파인)은 **L2를 완성**하고, 아래 백본-인터리브로 **L3에 저비용 근접**한다.

### 8-2. 백본-인터리브 방식 (사장님 제안)
- **입력 계약**: 최소 2개 — **메인=백본**(구조·과정순서·싱크 상속) / **서브 ≥1=같은 제품 풀**(b-roll + 행위 스왑용).
- 정석 L3(모든 행위 클립 독립 소싱)는 비쌈. 대신 **잘된 영상 1개를 백본으로 물려받아 싱크를 "상속"**한다(백본 나레이션은 이미 백본 화면과 맞아있음).
  1. 백본을 잘게 쪼개 **논리적 과정 순서를 스파인으로 고정**(재배열 금지).
  2. **앵커 비트 = 백본은 순서·논리·싱크 앵커만 담당**, 실제 화면은 §8-6 비트별 best-of-N으로 채움(백본 픽셀 독점 아님).
  3. **자유 비트·전환 = 서브 b-roll 삽입**(다양성·길이·중복회피, 복잡한 재조립 아님).
  4. **나레이션 = 백본 차용 후 L2 변주** — 부품은행이 스타일만 바꾸고 각 비트의 행위는 스파인에 고정(D9).
- 레시피 동일: 백본 레시피 단계 순서 유지, 같은 요리 b-roll 삽입, 나레이션 풍부화. 결과물·앵커 컷은 **같은 요리 소스**여야 연속성 유지.
- 배선: `build_scene_first_plan`에 **`backbone_source` 옵션** 추가(그 소스=원순서 스파인, 나머지 same-product=자유비트 insert/스왑 풀). 앵커/자유 분류(2트랙, 있음) 재사용.

### 8-3. 차별화 엔진 (D11 — "티 안 나게" 고도화)
동의어 치환("땡기는"→"당기니까")은 원작자·중복탐지·시청자가 감지 → 3층 + 측정 게이트.
- **1층 화면**: 앵커 행위를 **백본이 아닌 풀(서브)의 같은 행위 클립으로 스왑** → 순서·싱크는 백본, 픽셀은 다른 소스. 풀에 없는 행위만 백본 클립 + **시각변형**(크롭·리프레임·속도램프·좌우반전·색보정·오버레이).
- **2층 나레이션**: ①**화자 POV 전환**(남편→아내→지인 선물→후기, 같은 제품·행위·스토리 래퍼 교체) ②**훅 교체**(후킹 은행) ③**등장인물 스왑**(스파인 라이브러리) ④**비트 재분할 + 부품은행 골격 재조립**(동의어 아님).
- **3층 구조**: 과정 순서는 고정(싱크), **진입만 변주**(결과-먼저 콜드오픈 ↔ 문제-먼저), 훅·CTA 프레이밍 교체.
- **차별화 게이트(측정·강제)**: `score = 화면중첩% + n-gram중첩 + 훅유사도 + POV동일 + 진입동일`. 임계 미달이면 **변형 자동 증량**(픽셀 더 스왑·POV 재전환·훅 재교체)해 통과할 때까지. 텍스트 표절가드의 확장.
- **이질감없게(연속성)**: 서브 클립을 **조명·세팅 태그**로 골라 끼우고 안 맞으면 색보정 통일(장면 인벤토리에 조명/세팅 태그 추가).
- **⚠️ 리스크**: footage 재사용 = 재업로드/저작권·플랫폼 중복탐지 리스크. 차별화 게이트가 품질(중복 억제 회피)과 권리 리스크 완화를 겸함. 백본 사용권 확인 필요.

### 8-4. 팩토리 큐 (D12 — 목표 UX)
목표: **하루 수십 개 winner를 1번부터 찍어내듯.** "생각 안 하고 빠르게, 잘된 영상과 다를 바 없이."
- **일일 랭킹 = 작업 큐.** 항목마다 **[만들기]** 버튼.
- 사장님 동작 = **메인+서브 던지기 → 추천안 승인.** 나머지(스파인 선택·b-roll 스왑·차별화·렌더) 자동.
- 부품은행이 미리 배워놔서 think-free. 데이터↑ = "생각 없이 빠르게"가 강해짐.
- **처리량 병목 = 서브 풀 확보 + 연속성 매칭**(최소 2개 계약이 이를 흡수). 서브 자동수집 시 무인 근접.

### 8-6. 비트별 베스트 장면 (D13 — 백본은 순서만, 화면은 best-of-N)
- 백본은 **스파인(비트·순서·논리·싱크 앵커)만** 정한다. **각 비트의 화면은 전 소스 풀(메인+서브들)에서 품질로 골라 채운다.**
- 레시피 예: 조리 과정 비트에서 1번을 메인 순서로 쓰되, **2·3번의 조리 컷이 더 좋으면 그걸 쓰거나 1+2+3 조합.** 제품 사용 영상도 동일.
- 배선: `build_scene_first_plan`의 `primary/alternates`를 **전 소스 풀에서 품질 랭크**하도록 확장(현재 fit + 신규 scene_quality 점수). 백본 클립이라고 우선권 없음 — 순서·싱크 제약만 백본이 건다.
- 연속성: best-of-N 후보는 **같은 요리/같은 제품 풀**에 한정(D10 강화) + 조명·세팅 매칭(§8-3).
- 차별화 1층(행위 스왑)과 동일 엔진 — best-of-N이 곧 화면 차별화를 겸한다.

### 8-7. 재미 강도 필수 (D14 — 일반 스토리 금지)
- 스토리 형식이 **일반 서술이면 반려.** before/after·반전(twist)·극적 대비 등 **강한 재미 장치를 반드시** 넣는다.
- 스파인 선택이 **강한 devices(비포애프터·반전·극적대비·손실회피)를 가진 아크를 가중·강제.** structure_analyze의 `twist`·`devices` 필드가 근거.
- **재미 강도 게이트**: 생성안에 강한 장치가 최소 1개 없으면 재생성(북극성 §6 스토리 축의 하드 기준). 대화체 스코어러와 병렬.

## 9. 페이블 검토용 열린 질문

1. 스파인 클러스터링 세분도 — 몇 개 상황유형으로 수렴시킬지, `MIN_SAMPLES` 유사 게이트를 스파인에도 둘지.
2. `perf_score` 산식 — 크롤 성과가 플랫폼마다 스케일이 달라 정규화 기준(플랫폼 내 백분위 vs 절대치) 확정 필요.
3. 대화체 스코어러 구현 — 규칙기반(어미 사전·요약체 블랙리스트) vs Gemini 판정 vs 혼합. 재생성 루프 상한.
4. D9 내용/스타일 부품 경계 — 감정·공감 부품이 내용성이 강할 때 스파인 종속을 어디까지 엄격히 볼지.
5. 큐레이션 부하 — 자동 대기 항목이 폭증할 때 사람 승인 병목. 자동 승인 임계(성과·빈도 상위 자동 통과) 도입 여부.
6. 차별화 게이트 화면중첩% — 지각해시(pHash) vs 임베딩 유사도 중 무엇으로 측정할지, 임계값 초기치.
7. 행위 스왑 실현성 — 서브 풀이 앵커 행위를 실제로 얼마나 커버하는지(커버 못 하면 백본+시각변형 폴백 비율↑). 행위단위 태깅 정확도가 관건.
8. 백본 사용권 — footage 재사용의 법적/플랫폼(중복탐지) 경계. 차별화 임계를 "안전선"으로 쓸 수 있는지, 아니면 원천 소스 확보 방식 필요한지.
9. 이 스펙 범위 경계 — 8절(백본-인터리브+차별화+팩토리)을 이 스펙에 포함할지, 별도 후속 스펙으로 뺄지(부품은행+스파인 = 코어, 8절 = 그 위 응용).
