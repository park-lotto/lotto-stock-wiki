# 신호등고착 — '분석 중' 영구 고착과 끝없는 조회 (관제 172)

## 2026-10-10 (PC: CH) — 상태: 트랙 브랜치에 커밋, **미병합(사장님 확인 대기)**

### 무엇을·왜
관제 171(신호등 조회 CPU) 조사 중 페이블 전수 조사가 찾음. 화면(`collection.html`)은 '분석 중'이 하나라도
있으면 20초마다 다시 묻는데, 서버 판정이 "시도 흔적만 있고 아무도 안 도는" 영상을 시한 없이 '분석 중'으로 돌려준다.
→ 새벽 02~07시에도 조회가 시간당 약 1,950건(페이블 저널 집계).

### 라이브 실측(2026-10-10, reference.db 읽기 전용)
- 대본 없는 시도 흔적 928개 중 **675개가 지금 '분석 중'** — 전부 마지막 시도 뒤 10분 넘음, 대기줄 0건.
  (오류 없음 35 / 오류 남김·시도 1~2회 640. 오류 상위: 인스타 받기 실패 156, 샤오홍슈 72, 틱톡 56, 네이버 미지원 55, 재료 없음 49)
- 이 코드를 즐겨찾기에 가진 고객 55명(415행).

### 판단 주인·결과물 검사
- 주인: `shopping_shorts/app.py:_analysis_state` 한 곳. 화면엔 별도 시한을 두지 않는다.
- 검사: 위 675개를 신호등 API로 물어 pending 0 + 새벽 조회 수 시간당 200건 이하.

### 고친 것
- `_analysis_state`: 대기줄에 없고 시도 흔적이 있으며 `_AUTOLOAD_STALL_SEC`(600초) 지났으면 gave_up(사유: 남은 오류, 없으면 "도중에 끊겼어요").
- `collection.html`: 안 보이는 탭은 다시 묻기를 예약하지 않는다(다시 보면 기존 visibilitychange 가 바로 읽음).
- `tests/test_analysis_stuck_pending_172.py` 7건 — 수리 전 4건 실패 확인. 관련 45건 통과.

### 고객에게 달라지는 것
55명 화면에서 675개가 '⏳ 분석 중' → '⚠ 분석 실패 / 다시 분석'. 제작소 1단계는 그 영상을 '실패'로 보여 주고 기다리지 않는다
(제작소를 열면 서버 자동 재시도는 종전대로 시도 3회까지 돈다 — `api_produce_autoload`는 횟수로 판단).
