# TTS 성우 추가 지연·기존 미리듣기 중단 근본 수정

## 제보와 운영 실측

- 제보: ElevenLabs 성우 추가가 약 3분 뒤 반영되고, 그동안 기존 즐겨찾기 성우의 ▶가 무음.
- 2026-09-18 운영 로그: 14:48 검색 뒤 추가 요청 3건이 14:49:37~14:51:04에 순차 완료.
  같은 사용자가 누른 기존 샘플 GET 요청들은 전부 대기하다 14:51:04에 한꺼번에 200 응답.
- 원인: `async` 라우트 안에서 동기 ElevenLabs 담기와 톤 4종 샘플 합성을 직접 실행해 단일
  uvicorn 이벤트 루프를 막았다. 이미 등록된 Yura도 다시 4종을 구워 시간·크레딧이 중복됐다.

## 수정

- 카드 메타데이터는 즉시 저장하고, 샘플 4종은 FastAPI 응답 뒤 동기 BackgroundTask로 실행.
- 동기 ElevenLabs HTTP 호출은 `run_in_threadpool`로 분리.
- `(owner_customer_id, voice_id)`별 작업 잠금 + 전체 동시 굽기 2개 제한.
- DB 조회 결과에 `owner_customer_id`를 복원해 같은 고객의 같은 성우를 정확히 판정.
- 이미 4톤 파일이 있으면 재등록·재합성하지 않고, 일부만 없으면 없는 샘플만 재생성.
- 카드에는 `samples_pending`을 내려 재생 버튼을 `샘플 준비 중`으로 비활성화하고, 화면은
  3초 간격으로 완료를 확인해 자동으로 재생 버튼을 살린다.
- 서버 재시작·일시 실패로 일부 샘플이 남으면 계정/관리자 목록에서 `샘플 준비 재시도` 제공.
- 관리자 사전 미리듣기 합성도 스레드풀로 옮겨 웹 이벤트 루프를 막지 않게 함.

## 검증

- 신규 단위 테스트 `test_voice_add_nonblocking.py` 6건 통과.
- 관련 API·Store·성우·인라인 JS 회귀 테스트 통과.
- 브라우저 실화면:
  - 기존 즐겨찾기 ▶ 클릭 시 `■`로 전환되고 음원 GET 206 확인.
  - 샘플 없는 라이브러리 QA 카드가 즉시 나타나며 버튼 disabled + title=`샘플 준비 중` 확인.

## 배포 후 실확인
