# 위키 종합엔진 설계서 (Wiki Synthesis Engine)

> 작성: 2026-06-22 | 상태: 설계 확정 대기 (사용자 검토 중)
> 목표: 정보의 홍수를 **질문하면 답이 나오는 고품질 도서관**으로 자동 증류

---

## 0. 한 줄 정의

매일 들어오는 원자(news·report·telegram·youtube·blog 추출본)를 **종목 페이지 골드 포맷에 자동으로 녹여 넣는 엔진.** 출처는 실존 파일만, 주장은 검증등급을 달고, 모르면 "없다"고 답한다.

---

## 1. 왜 만드나 (문제)

현재 파이프라인은 `크롤링 → Gemini추출 → DB → wiki_update(파이썬 덤프) → 섹터파일`.
- **병목**: `wiki_update.py`에 LLM 호출 0개. 날짜+이모지 붙여 append하는 멍청한 덤프.
- **증거**: 섹터 파일에 같은 리포트가 06-21/06-19 중복, 잘린 인용("…"), 종합·검증 전무.
- **결과**: 품질을 만드는 지능(Claude)이 자동 루프 밖에 있음. 골드 종목페이지(SK하이닉스 등 176개)는 06-09에서 방치.

→ **덤프 스크립트 자리에 지능(Sonnet 종합)을 앉힌다.** 토대(종목 215페이지·원자DB·5소스·딥리서치)는 다 살린다.

---

## 2. 성공 기준 = 질문 7종 테스트 (합격/불합격 판정)

반도체에서 아래 7개 질문에 **추적가능하고 검증된 답**이 나오면 합격.

| # | 질문 유형 | 예시 | 답하는 페이지 구조 |
|---|----------|------|-----------------|
| 1 | 현재 상태 | "SK하이닉스 지금 어때?" | 종합 스토리 |
| 2 | 히스토리 | "TP 어떻게 변해왔어?" | 컨센서스·리포트논거 롤링표 |
| 3 | 근거·검증 | "최태원 머스크 회동 근거가?" | 출처 + 검증등급 |
| 4 | 횡단 테마 | "HBM 밸류체인 대장은?" | 테마 롤업 페이지 |
| 5 | 횡단 섹터 | "반도체 vs 2차전지 누가 세?" | 섹터 인덱스 |
| 6 | 맥락 주입 | "오늘 이 단독뉴스 무슨 맥락?" | ChromaDB 검색 → 종목 연결 |
| 7 | 충돌 | "하나 175만 vs 전진 320만 왜?" | 충돌·모순 섹션 |

**8번째 메타 규칙(정직한 공백)**: 위키에 없는 걸 물으면 **"위키에 없음 — 자료 추가 필요"**라고 답해야 한다. 지어내면 즉시 불합격.

## 3. 아키텍처

```
[1. 입력QC]  원자 정제
    · 중복제거(같은 리포트 멀티날짜 통합)
    · 깨진 추출 폐기 (예: "38만원"→"380만 달러" 오추출 차단)
    · 종목명 정규화 (asset → 표준 종목명)
    ↓
[2. 종합엔진]  차분-병합 (Sonnet)
    · 입력: (현재 종목페이지 + 그 종목의 신규 원자)
    · 출력: 바뀐 섹션만 재작성 (이벤트표·컨센서스·논거·종합스토리)
    · 기존 골드 내용 보존, 신규만 녹임
    ↓
[3. 검증게이트]  하이브리드
    · 모든 주장 = 실존 출처파일 + 검증등급 필수
    · report(A) → 자동 반영
    · 파트너십·납품·고위험 주장 → WebSearch 교차확인 통과 시만 🔴 승격, 아니면 ⚠️미검증
    · 충돌 → 충돌·모순 섹션에 양쪽 보존 (덮어쓰기 금지)
    · 저신뢰(blog/youtube)·미검증 → 스테이징(staging/)에 모아 사람/Opus 승인 후 반영
    ↓
[4. 롤업]  종목 → 상위
    · 섹터 인덱스 = 오늘 주도·대장·신호 요약 (종목들에서 자동 집계)
    · 테마 페이지 = HBM·유리기판 등 횡단 묶음 (종목들에서 자동 집계)
    ↓
[5. 쿼리]  ChromaDB 벡터 + 구조화 페이지
    · 7종 질문 → 해당 페이지 섹션 검색·결합
    · 없으면 "위키에 없음" 정직 응답
```

## 4. 컴포넌트 (각각 단일 책임)

### 4.1 입력QC (`atom_qc`)
- **무엇**: 종합 직전 원자 묶음을 정제.
- **인터페이스**: `clean(atoms: list) -> list` — 중복통합·깨진것폐기·종목정규화.
- **의존**: 기존 `stock_resolve`(종목명), DB.
- **판정 규칙**: content 동일/유사 → 1개로 병합(출처는 다중 보존). 숫자 깨짐 휴리스틱(단위 모순) → 격리 로그.

### 4.2 종합엔진 (`stock_synth`)
- **무엇**: 종목 1개의 페이지를 신규 원자로 갱신.
- **인터페이스**: `synth(page_path, new_atoms) -> updated_markdown` (Sonnet 호출).
- **의존**: 골드 포맷 스펙(§5), 검증게이트.
- **원칙**: 섹션별 갱신 규칙 준수 — 이벤트표(7일 롤링), 컨센서스(증권사당 1행 덮어쓰기), 리포트논거(30일 롤링·WHY보존), 종합스토리(최신 단락 추가). **출처는 입력 원자의 실존 raw_file만 인용. 합치거나 날조 금지.**

### 4.3 검증게이트 (`verify_gate`)
- **무엇**: 종합 결과를 신뢰도로 분류해 자동/스테이징 결정.
- **인터페이스**: `gate(claim) -> {grade, route}` — route ∈ {auto, staging}, grade ∈ {검증완료, 미검증, 설}.
- **의존**: 소스 신뢰도(§6), WebSearch(고위험 주장).
- **규칙**: report A=auto. 파트너십/납품/M&A/실적 주장 = WebSearch 확인. blog/youtube 해석 = staging. 충돌 = 보존.

### 4.4 롤업 (`rollup`)
- **무엇**: 종목 페이지들 → 섹터 인덱스·테마 페이지 자동 생성.
- **인터페이스**: `roll(sector) -> index_md, theme_mds`.
- **의존**: 종목 페이지(소스 오브 트루스). 섹터 멤버십 = `반도체/stock/` 폴더(1단계) / Excel 매핑(2단계).

### 4.5 쿼리 (`wiki_query`)
- **무엇**: 질문 → 페이지 검색·결합 답변.
- **인터페이스**: `ask(question) -> answer + sources` 또는 "위키에 없음".
- **의존**: ChromaDB(기존), 구조화 페이지.
- **범위 주의**: 1단계는 *새 쿼리 도구를 짓지 않는다.* 기존 경로(ChromaDB 검색 + 세션에서 Claude가 구조화 페이지 읽기)로 7종 질문을 검증한다. 즉 1단계 쿼리 테스트는 **쓰기 품질**을 검증하는 수단이지 별도 빌드 타깃이 아니다. 전용 쿼리 도구·대시보드 연동은 2단계.

## 5. 골드 포맷 스펙 (종목 페이지 = SK하이닉스 기준)

합격 페이지가 반드시 갖출 섹션 (이미 176개가 보유):
1. **탑픽 스코어** (선택) — 빈집/수출/판가 등 (수치는 태린이 파일 연동)
2. **종합 스토리** — 최신 단락 누적, 각 항목 출처+날짜
3. **최신 이벤트** — 7일 롤링, 표(날짜·내용·출처·신호)
4. **일정** — 촉매·정기 이벤트
5. **증권사 컨센서스** — 증권사당 1행 덮어쓰기 (최신 TP·의견·직전TP·방향)
6. **리포트 핵심 논거** — 30일 롤링, 증권사당 최신 1건, WHY 보존
7. **뉴스 반응 패턴** — 어떤 뉴스에 얼마나 움직이나 (저빈도 갱신)
8. **미국 커플링** — 페어 종목·반응 강도·브리핑 로직
9. **충돌·모순** — 상반 정보 양쪽 보존
10. **관련 페이지** — 섹터/테마 링크

**강제 규칙**: 모든 사실 행에 **실존 raw 파일명 + 날짜**. 검증등급(`⚠️미검증`/`(설)`) 명시.

## 8. 범위 / 롤아웃

- **1단계 (지금)**: 반도체 1섹터로 증명. 멤버십 = `반도체/stock/` 폴더 63종목(매핑 이미 됨). 7종 질문 테스트 통과 목표.
- **2단계**: 검증되면 전 섹터 확장. 이때 사용자 Excel 매핑(택소노미·종목→섹터) 투입 — **병렬 준비 중, 설계를 막지 않음**.
- **구멍 처리**: 빈약 39페이지 채우기 / 섹터덤프 6개 제거 / 입력QC로 추출노이즈 차단.

---

## 9. 범위 밖 (명시)

- **빈집/주도 강도 계산** = 태린이 파일(오실레이터) 담당. 위키 엔진은 그 수치를 *연동*만.
- **종목→섹터 Excel 매핑** = 사용자가 별도 제공. 1단계는 폴더 멤버십으로 충분.
- **딥리서치(Q1~Q10)** = 분기/반기 정적 토대. 유지하되 일상 엔진과 별개 레이어.

---

## 10. 합격 정의 (Definition of Done — 1단계)

1. 반도체 63종목 페이지가 신규 원자로 자동 갱신됨 (06-09 방치 → 최신).
2. 모든 신규 행이 **실존 출처 + 검증등급** 보유 (날조 0).
3. 섹터 인덱스·HBM 테마 페이지 자동 롤업.
4. **질문 7종 + 정직한 공백** 테스트 전부 통과.
5. 섹터 덤프 6개 제거, 골드 페이지 무오염 유지.

## 부록 A — 검증으로 발견한 실패 사례 (재발 방지 명세)

설계 중 Claude가 SK하이닉스 페이지를 수동 갱신했을 때 실제 발생한 결함 — 엔진이 반드시 막아야 함:
- **출처 날조**: 두 파일(`태린이아빠 주식투자.md`+`하나반도체.md`)을 `·`로 합쳐 실존 안 하는 파일명 생성 → 추적 붕괴. **규칙: 실존 raw_file만, 다중출처는 각각 나열.**
- **미검증 주장의 사실화**: 텔레 단일출처 "최태원-머스크 회동"을 🔴 사실로 기록 → 소문이 사실로 둔갑. **규칙: 고위험 주장은 교차확인 전까지 ⚠️미검증·🟠 이하.**
