### ★핵심 교훈 — 런타임 코드 로드는 '전부' 막혀 있다 (3연속 실패 후 결론)
처음엔 유저스크립트 로더처럼 **서버에서 로직을 받아 실행**하게 만들었다. 유튜브에서
📥가 아예 안 떴고, 원인을 세 번 잘못 짚었다. 실측으로 확인된 차단 벽:

| 시도 | 결과 |
|---|---|
| 페이지 월드 `<script src="우리도메인">` | ❌ 유튜브 CSP `script-src`에 우리 도메인 없음 |
| 페이지 월드 Blob URL `<script>` | ❌ 유튜브 CSP는 `blob:`도 차단 |
| 격리 월드에서 `eval(받아온 코드)` | ❌ **확장 CSP가 `unsafe-eval` 금지** |
| + 유튜브는 Trusted Types까지 켜져 있어 `script.src` 문자열 대입 자체가 차단 | |

→ **확장에 로직을 동봉하는 것이 크롬이 허용하는 유일한 길.**
   MV3 '원격 코드 금지' 정책과도 맞아 웹스토어 심사에도 유리하다.
   ⚠️ "격리 월드는 페이지 CSP를 안 탄다"는 맞지만, **확장 자신의 CSP가 eval을 막는다**.
   이걸 몰라서 한 바퀴 더 돌았다.

### 구조 (지금)
```
shopping_shorts/extension/
  manifest.json     content_scripts.js = ["content.js", "grab_logic.js"]  ★순서 중요
  content.js        GM_xmlhttpRequest 대체 브리지(격리 월드). 주입 안 함.
  grab_logic.js     ← 개발 편의용 사본. **원본은 userscript/grab_logic.js**
  background.js     설치 직후 /grab 안내 1회 오픈
  popup.html        아이콘 클릭 시 안내
  icons/            16·48·128 (PIL 생성, 민트 다운로드 아이콘)
```
- **로직 원본은 `userscript/grab_logic.js` 한 곳뿐.** `/grab_extension.zip` 라우트가
  zip을 만들 때 **원본을 담는다**(extension/ 사본은 안 담김). 두 벌 수동관리 금지.
- 유저스크립트 사용자는 종전대로 **자동 반영**. 확장 사용자만 **재설치 필요**
  (popup.html 문구를 사실대로 "새 기능 나오면 다시 받아 설치" 로 수정해둠).

### 실측 검증 (playwright 설치 후 실제 크롬에 확장 로드)
| 사이트 | 결과 |
|---|---|
| 유튜브 | ✅ 📥 담기 1개 · 에러 없음 · **스크린샷 육안 확인** |

**최종**: 라이브 zip(19,593 bytes)을 사용자와 동일하게 받아 → 압축해제 → 크롬 설치 →
유튜브·인스타 **둘 다 📥 확인 = PASS**.

(인스타 `media_stats` 401 CORS 에러는 **비로그인 테스트 브라우저** 탓이다 —
조회수·댓글수는 로그인 사용자 기능이라 정상 동작이다. 버그 아님.)
