2026-09-08 사장님 화면 실측: `21649455asd` 계정에 인스타 조치가 걸려 있었다.
**"여러 세션을 만들 수 없습니다"**(2026-08-31 조치, 9/1 종료), 사유는
"민감한 정보를 수집하거나 악성 소프트웨어를 공유… 사이버 보안 커뮤니티 규정 위반".

서버 레퍼런스 세션 파일 10개가 **전부 8/31 20:41**에 만들어졌다 — 같은 날이다.
수집할 때는 `slot_proxy`가 계정↔IP를 1:1로 붙이지만, **로그인하는 순간의 IP는
그 PC 것**이라 한 기계에서 여러 계정을 연달아 로그인하면 인스타가 묶어 본다.
(인과는 날짜 일치와 제재 문구에 근거한 **추정**이다 — 인스타 내부 판정은 확인 불가)

→ **세션을 되살릴 때는 하루 1~2개씩 나눠라.** 한 세션에 몰아서 하지 마라.

복구 절차(2026-09-08 실측, 슬롯 1개 → 8개):
1. `py tools/ig_session_from_firefox.py <프로필이름> <출력경로>` — 첫 줄이 ALIVE|<uid>|200|N
2. `scp <출력경로> ubuntu@<서버>:/home/ubuntu/ig_sessions/reference/<uid>.json`
   ★기존 파일명 규칙을 지켜라(z1_·z2_ 접두사가 붙은 것은 그대로 덮어써야 슬롯이 안 늘어난다)
3. `live_slots(session_slots(POOL_REFERENCE))` 길이로 검증

- 파이어폭스 프로필은 계정별로 이미 나뉘어 있다(신규1~8·default·4·2번 등, profiles.ini).
- 띄우기: `firefox.exe --profile "<프로필 폴더 절대경로>" -no-remote <URL>`
  (`-P <이름>`은 창이 안 뜨는 경우가 있었다 — 경로 지정이 확실하다)
- ★생사 판정은 `session_alive`와 동일하게 하라. api/v1 엔드포인트로 하면 429가 떠서
  13개 전부 '오류'로 나온다(실측) — 판정 자체가 무효가 된다.
