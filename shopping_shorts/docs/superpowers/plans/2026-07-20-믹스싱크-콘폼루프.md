# 믹스 싱크 콘폼루프 — 구현 계획 (2026-07-20)

설계: `docs/superpowers/specs/2026-07-20-대본영상싱크-콘폼루프-design.md` (루트)
구현: Fable 세션. 원리 — 서사=대본 / 시간=영상 / 표면=콘폼(초과 문장만 리라이트→그 비트만 재TTS).

## 코드 검증으로 확정된 배선

- 삽입점: `mix_pipeline._plan_and_tts` — `_synthesize_beats` 직후·`update_mix_job(edit_plan=...)` **직전**.
  저장 전이라 preview·final 렌더 모두 자동 적용, 저장은 기존 1회 그대로.
- 재TTS 선례: `resynth_one_beat`(같은 mp3 덮어쓰기 + ASR 자막 재동기) — 그 블록 그대로.
- 예산: `Σ(primary+alternates의 end-start) × _MAX_SLOWMO(1.15)`. `_plan_beat_clips`가 세그먼트를
  전부 소진한 뒤에만 얼리므로 이 예산이 "영상으로 채울 수 있는 최대"다.
- API `**b` 스프레드 → `sync_gap`·`conformed` 필드가 프론트로 자동 전달.
  `cap_segments`는 API 시점 narration에서 재계산 → 콘폼된 자막 자동 일치.
- 여운(-t): `assemble` mux가 `-t tts_dur`로 비트를 자름(양 분기) → 마지막 비트만 `+runout`.

## 태스크

- **T2** `edit_plan.conform_narration(narration, target_seconds)` — `_vault_call` 재사용,
  스키마 `{"narration"}`. 게이트: 공백제외 글자수/5.7 추정초가 목표의 0.8~1.2 아니면 None(폴백).
- **T3** `mix_pipeline._conform_beats(beats, tts_dir, *, voice)` — gap>0.8s인 비트만:
  리라이트 성공 시 재synth(성공 후에만 narration 교체)→cap_durs 재동기→sync_gap 갱신→
  target_seconds 재계산. 실패는 조용히 통과(freeze 폴백, sync_gap 플래그 잔존). 비트당 1회.
- **T4** `video_assemble` — `_LAST_RUNOUT=1.0`, `_extend_last_clip_for_runout(plan, segs, runout)`
  (실프레임 여유만큼 1배속 연장, 부족분은 기존 slowmo/freeze 기계가 흡수) + 마지막 비트 `-t`에 +runout.
- **T1** `produce.html _renderMixReviewBody` — `⏱ 길이 맞춤`(conformed) 배지,
  `sync_gap>0.8` 경고 1줄.
- **T5** `tests/test_mix_conform.py` — 게이트 수락/거절, 콘폼 패스(초과 비트만·실패 폴백·
  cap_durs 재동기), 여운 확장 3케이스(여유충분/부족/없음), UI 배지 소스 앵커.

## 설계 대비 조정 (물리 제약)

- 스펙 §1-③ "freeze ≤0.8s **상한**"은 하드컷 불가 — 오디오와 길이가 어긋난다(desync).
  → 콘폼으로 gap을 없애는 게 본선, 잔존 gap은 `sync_gap` 플래그로 노출(UI 경고)이 가드.
- 알려진 한계: 예산은 편집안의 세그먼트 명목 길이 기준. 매칭이 소스 실길이 밖을 잡은 경우
  (assemble이 클램프) 예산이 과대해 콘폼이 덜 걸릴 수 있음 — 드묾, 후속.
