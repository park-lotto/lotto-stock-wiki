# 제작소 mix 탭 — 대본 "그대로 쓰기" → 재생성 배선 (2026-07-16)

트랙: `대본믹스통합` / 상태: 설계 승인됨(사장님, 2026-07-16)

## 문제

영상제작소 1단계(`/produce`) mix 탭에서 대본을 1개 고르면 `useSingleScript()`가
그 대본을 **그대로 복사**해 확정한다(`produce.html:1161`). 사장님 지적:

> 선택 1개 그대로 쓰기는 원본영상이랑 그대로 쓴다는건데 의미가 없는거고

맞다. 원본 영상에 원본 대본을 그대로 얹으면 리메이크가 아니라 재업로드다.
제작소는 **원본 대본을 재료로 새 대본을 만드는 자리**여야 한다.

## 정찰 결과 — 만들 게 아니라 배선할 것이었다

즐겨찾기(`library.html`)의 "🎬 이 구조로 대본 생성" 패널은 **이미 제작소에 이식돼 있다**
(`produce.html:396` `pmModal`, 2026-07-15 작업). 요소 7개 토글 · 리메이크/이식 모드 ·
초안별 전체재작성/부분수정/버전이력이 전부 있다.

다만 그게 **왼쪽 "넘어온 영상 → 📝뽑기"** 경로에만 배선돼 있고, 오른쪽 **mix 탭 대본 목록**에는
안 붙어 있어서 거기만 복사로 남았다.

백엔드도 이미 준비돼 있다. `/api/wiki/generate?shortcode=`(`app.py`)는 위키에 항목이 있으면
구조를 알아서 읽고, 없으면 body의 `structure`/`base_script` 폴백을 쓴다.
**→ 백엔드 신규 작업 0.**

## 설계

### ① mix 탭 1개 선택 → pmModal (핵심)

- `useSingleScript()` **삭제**. 버튼 문구 `✅ 선택 1개 그대로 쓰기` → `♻️ 선택 1개로 새 대본 생성`
- 새 함수가 `window._mixItems`에서 항목을 찾아 pm 상태를 채우고 `pmModal`을 연다:
  | pm 상태 | 값 | 비고 |
  |---|---|---|
  | `PM_SHORTCODE` | `w.shortcode` | 백엔드가 이걸로 위키 구조 로드 |
  | `PM_CATEGORY` | `w.category` | 요소 드롭다운 학습 필터 |
  | `PM_BASE_SCRIPT` | `w.full_text` | 폴백용 |
  | `PM_BASE_STRUCT` | `null` | 위키에서 읽으므로 안 보냄 |
  | `PM_IDX` | `null` | HANDOFF 유래가 아님 → ④ 참조 |
- **추출 단계를 건너뛴다.** 위키 대본이라 텍스트가 이미 있고 구조는 백엔드가 읽는다.
  (뽑기 경로의 `/api/produce/extract_from_url` 10~30초 대기가 여기선 불필요)
- `/api/produce/picks` 항목이 위키에 없을 수 있으므로 body에 `base_script`·`category`를
  폴백으로 동봉한다. 위키에 있으면 백엔드가 위키 걸 우선하므로 무해하다.
- **2개+ 조합 생성(`genMix`)은 그대로 유지.**

### ② 소재칸 이식 — 구멍 메우기

즐겨찾기엔 소재 자동감지 칸(`genSubject` + `/api/wiki/subject`)이 있는데 `pmModal`엔 **없다**.
`pmRunGen`이 `subject`를 아예 안 보낸다(`produce.html:1326`) — 백엔드는 받을 준비가 돼 있는데도.
소재고정 리메이크 트랙의 작업이 `library.html`에만 반영된 것으로 보인다.
**지금 제작소 리메이크는 소재가 고정되지 않는다.**

- `pmModal`에 소재 입력칸 + 힌트 추가 (library의 `subjectRow` 이식)
- 리메이크 모드(`pmmode=A`)일 때만 표시 — `pmToggleTopic()` 확장
- 모달 열 때 `/api/wiki/subject?shortcode=`로 프리필.
  **경합 가드 필수**: library의 `window._genSC===mySC` 패턴 그대로 — 모달을 빨리 두 번 열면
  먼저 띄운 요청이 늦게 도착해 남의 소재를 덮어쓴다.
- `pmRunGen`이 `subject` 전송
- 같은 모달이라 **왼쪽 뽑기 경로에도 소재 고정이 생긴다**(이득). shortcode 없는 직행 URL은
  프리필만 스킵하고 손입력은 열어둔다.

### ③ 제미니 자동 제거 (뿌리째)

셋은 서로만 쓰고 다른 데선 안 쓴다:
- `produce.html`: 탭 `data-mode="gemini"` · `SCRIPT_MODE_HTML.gemini` · `genGemini()`
- `app.py:1761`: `POST /api/produce/script/gemini`
- `script_generate.py:118`: `generate_from_topic()`

mix 목록이 재생성 경로가 되면 "주제만 넣고 처음부터"는 즐겨찾기의 🔀이식 모드와 겹친다.

### ④ 위키담기 오귀속 차단 — 배선하다 발견한 기존 버그

현재 `useSingleScript()`는 `STATE.script_src_idx`를 안 남긴다. 그래서 위키 대본을 확정하면
`_currentSrcItem()`(`produce.html:1447`)이 **엉뚱한 HANDOFF 영상으로 폴백**한다:

```js
return byIdx || HANDOFF.find(h=>h.pickScript) || HANDOFF.find(h=>h.useFootage) || HANDOFF[0] || null;
```

`⭐이 원본 영상 위키에 담기` 버튼은 `STATE.script`만 있으면 뜨므로(`:1477`), 그 엉뚱한 영상이
학습 재료로 담긴다. 코드 주석의 I-1이 잡으려던 바로 그 오귀속인데 mix 경로만 안 막혀 있다.

- `STATE.script_from_wiki` 추가 — 위키 유래 대본을 확정할 때 shortcode 기록
- `refreshFinalPeek()`에서 `script_from_wiki`면 `saveWikiBtn` **숨김**
  (이미 위키에 있는 원본이라 담을 게 없다)
- 직접작성/뽑기로 대본이 바뀌면 초기화 — 안 하면 stale 플래그가 정상 경로의 버튼을 숨긴다

### 판단 — mix에서는 pmUseRaw를 안 그린다

`pmModal`의 "원본 대본 그대로 확정" 버튼(`pmUseRaw`)은 `openScriptModal`이 `pmResults`에
동적으로 그린다(`:1289`). mix 경로는 **그 버튼 없이** 안내만 그린다 — 그게 사장님이 지적한
바로 그 무의미 동작이기 때문이다.

왼쪽 뽑기 경로의 `pmUseRaw`는 성격이 다르다(방금 영상에서 뽑은 날것이라 그대로 쓸 여지가 있다).
**이번 범위 밖 — 그대로 둔다.**

## 데이터 흐름

```
mix 목록(위키 shortcode)
  → pmModal (요소 7토글 · 리메이크/이식 · 소재)
  → POST /api/wiki/generate?shortcode=  [body: mode, subject, my_topic, elem_modes, n,
                                          base_script·category(폴백)]
  → drafts (draft_id 포함)
  → 초안 편집 / 전체재작성 / 부분수정 / 버전이력
  → pmUseDraft → STATE.script 확정 (+ script_from_wiki)
  → 2~7단계 (자막제거 · TTS · 꾸미기 …)
```

## 범위 밖 (여기서 하지 말 것)

- 2개+ 조합 생성 엔진 손대기 — 유지
- 왼쪽 뽑기 경로의 `pmUseRaw` 제거
- `library.html` 수정 — 이식은 produce 쪽으로만
- 요소 토글·모드의 UX 재설계

## 검증

- 배선 테스트: mix 1개 선택 → pmModal 상태가 그 항목으로 채워지는가 / `subject`가 payload에 실리는가
- 오귀속 회귀: 위키 유래 대본 확정 시 `saveWikiBtn`이 숨는가 / 뽑기 경로에선 여전히 뜨는가
- 제거 확인: `gemini` 참조가 코드에 안 남는가
- 게이트: `py tools/track.py finish 대본믹스통합` (문법 → import → pytest, 기준선 대비)
