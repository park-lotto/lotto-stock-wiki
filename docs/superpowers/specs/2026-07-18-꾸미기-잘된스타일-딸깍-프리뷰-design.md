# 꾸미기 "잘된 스타일 딸깍" + 공용 장면 프리뷰 — 설계

**작성:** 2026-07-18 / 트랙: 모션효과 / 대상: `shopping_shorts/static/produce.html` 꾸미기(4단계) + 서버 라우트 1개 신규

## 목표 (한 줄)
꾸미기에 들어오면 **제일 잘된 스타일이 이미 입혀져** 있고, 다른 잘된 영상 스타일을 **딸깍 한 번**으로 갈아끼우면 되며, **오른쪽 큰 미리보기에서 ◀▶로 장면을 넘겨가며** 내 자막이 어떻게 나오는지 바로 확인한다.

## 북극성
**60대도 쓸 수 있게 — 딸깍·직관.** 슬라이더·전문용어는 기본 화면에서 감춘다(직접 다듬기는 접힘 유지). 사용자는 "잘된 거 하나 고르고 ◀▶로 확인"만 한다.

## 확정된 사용자 의도 (대화 근거)
- "잘된 걸 클릭하면 거의 비슷하게 카피되고 딸깍으로 스타일" → 스타일은 **검증된 잘된 영상**에서 온다.
- "스타일은 그냥 레퍼런스 채널" / "레퍼런스가 많이 있어야" / "잘된것 기본 세팅" → 잘된 영상 스타일 = 프리셋, 많을수록 좋고, 제일 잘된 것이 기본값.
- 방식 ㉯ 확정(스타일 모음 딸깍). ㉮(그 영상 AI 정밀추출)는 v1 범위 밖.
- 목업(scratchpad/preview_mockup.html) 두 번 확인 "맞아 / 딸깍 이렇게 직관적 형태가 맞아".

## 컴포넌트 (4조각)

### 1) 잘된 스타일 갤러리 (딸깍 프리셋) — 왼쪽
- **v1은 큐레이션 6개**. 각 프리셋 = 잘된 영상 look을 우리가 style params로 세팅한 것:
  `{key, name, source_tag, source_views, source_eng, headcopy{color,outline_color,outline_w,y,weight}, caption{color,box,box_color,box_opacity,y,effect}}`.
- 카드 = **스타일 미리보기(그 스타일이 적용된 작은 화면) + 원본 지표(조회·참여밀도)**. 맨 앞 1개에 **⭐ 기본(가장 잘된 것)** 배지.
- 실제 인스타 CDN 썸네일은 **만료되므로 v1에서 안 씀**(카드=스타일 스와치). 실 썸네일 연동은 v2.
- 클릭 → 그 프리셋을 현재 헤드카피·자막 스타일에 적용 + 오른쪽 프리뷰 갱신 + `STATE.headcopy/captionStyle` 갱신 + `STYLE_TOUCHED=true`.

### 2) 기본값 = 1등 스타일
- 꾸미기 첫 진입 시 사용자가 아직 안 건드렸으면(`STYLE_TOUCHED=false`) **프리셋[0](가장 잘된 것)을 자동 적용**.
- **기존 `applyDefaultStyleOnEntry`(step5 진입 자동 스타일)를 이 프리셋[0] 적용으로 대체**한다(새 진입 훅을 만들지 않음).
- 대본믹스통합 트랙의 스타일 복원(작업 다시 열기)과 충돌 금지: **복원 대기 플래그(PENDING_STYLE_RESTORE)가 있으면 기본 적용을 건너뛴다**(그 트랙이 이미 심은 가드 재사용).

### 3) 공용 장면 프리뷰 스테이지 — 오른쪽 (★재사용 부품)
- 9:16 세로 화면 하나. 입력 = `renderBeat(i)`. 그림 = **그 비트의 영상 프레임(배경) + 헤드카피(모든 비트 공통, 고정) + 그 비트 자막**.
- 아래 컨트롤 = **◀ i/total ▶ 장면 스텝**(무음, 정지 프레임). (레퍼런스의 "격자" 토글은 v2 옵션.)
- **이 스테이지는 페이지에 독립적**: 그리는 함수는 하나, 컨트롤(◀▶ vs 재생)은 페이지가 갈아끼움. 자막싱크 트랙(TTS 재생 프리뷰)·장면라이브러리(검수판)가 **같은 스테이지를 재사용**한다(각자 다시 만들지 않음 = seam 방지).
- 현재 `hcPreviewText`/`실장면 배경`(단일 poster) 구조를 확장: 배경 이미지를 **비트별 프레임으로 교체**.

### 4) 서버 라우트 1개 신규 — 장면별 미리보기 데이터
- `GET /api/produce/mix/beats_preview/{job_id}` → `{beats:[{i, total, frame_url, caption}]}`.
  - `caption` = `edit_plan.beats[i].narration`(그 비트 대본 문장). 헤드카피는 비트 공통이라 안 보냄.
  - `frame_url` = 그 비트 `primary` 클립에서 **한 프레임 추출**(비트 start 시각). `data/mix_jobs/{job}/beatframes/{i}.jpg`에 **캐시**(있으면 재사용). 서빙 라우트 `GET /api/produce/mix/beatframe/{job}/{i}`.
  - 프레임 추출은 **기존 프레임 추출 헬퍼 재사용**(신규 ffmpeg 경로 만들지 않음). `stdin=DEVNULL` 필수(repo 함정).

## 데이터 흐름
꾸미기 진입 → `beats_preview` 1회 fetch(장면 목록 캐시) → 프리셋[0] 자동 적용 → 프리뷰가 비트 i=0 그림 → 사용자가 스타일 카드 딸깍(오른쪽 즉시 갱신) / ◀▶로 장면 넘김 → 고른 스타일은 `STATE`에 있고 [렌더]·작업저장 시 job에 저장(기존 저장 경로 그대로).

## 재사용·조율 (seam 방지)
- **공용 프리뷰 스테이지는 이 트랙이 소유·최초 구현**. 다른 트랙(자막싱크 2단계, 장면라이브러리 검수판)은 이걸 재사용(대시보드에 "모션효과 공용프리뷰 재사용"으로 이미 예약됨).
- **새 렌더 경로 금지**: 프리뷰의 헤드카피·자막 그리기는 최종 렌더(_segmented_drawtext)와 **같은 규칙**을 따르되(색·위치·줄바꿈), 프리뷰는 DOM/CSS로 근사(픽셀 완전일치 아님, 스타일 판단용).
- produce.html은 4트랙 동시편집 중 → **꾸미기 스타일 갤러리·프리뷰 블록에 국한**해 편집(장면라이브러리 scene-cutaway, 자막싱크 음성프리뷰 영역과 겹치지 않게).

## 에러 처리
- 비트/edit_plan 없음(매칭 전) → 프리뷰는 **기존 단일 poster + 흰 배경 폴백**, ◀▶ 비활성. "2단계에서 영상 매칭 먼저" 안내.
- 프레임 추출 실패 → 그 비트만 흰 배경(조용히), 나머지는 정상.
- 프리셋 적용은 순수 프론트라 실패 없음.

## 테스트
- **서버**: `beats_preview`가 edit_plan.beats에서 caption·total을 정확히 뽑나(스텁), 프레임 캐시가 재추출 안 하나(mtime), 비트 없으면 빈 목록/폴백. 프레임 추출은 실 ffmpeg 1건(stdin=DEVNULL).
- **프론트(JS 문자열 파싱 테스트)**: 프리셋 6개 존재·[0]에 기본 배지, 카드 클릭 핸들러가 STATE.headcopy/captionStyle 갱신, 진입 자동적용이 STYLE_TOUCHED·PENDING_RESTORE 가드 존중.
- **라이브 육안(진짜 게이트)**: 실제 job으로 꾸미기 진입 → 기본 스타일 적용됨 / 카드 딸깍 시 프리뷰 스타일 바뀜 / ◀▶로 장면·자막 바뀜. (produce.html은 pytest 없음 = 사장님/브라우저 확인이 최종.)
