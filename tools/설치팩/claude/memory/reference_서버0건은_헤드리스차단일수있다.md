**서버에서 0건인데 코드·세션·IP가 다 멀쩡하면, 대상 사이트가 헤드리스와 서버 환경 자체를 걸러내는 것이다.**

2026-09-08 틱톡 실측 — 4가지 환경을 갈라서 재야 답이 나온다:

| 환경 | 결과 |
|---|---|
| 내 PC + 창 띄움 | **영상 24개 정상** |
| 내 PC + 헤드리스 | 0개 |
| 서버 + 창(xvfb) + 프록시 | 0개 |
| 서버 + 창(xvfb) + 직결 | 0개 |

세션(쿠키 28개 생존·로그인 상태)·프록시·IP는 전부 멀쩡했다. **xvfb로 창을 띄워도
서버에서는 안 된다** — 헤드리스만의 문제가 아니라 서버 환경 전체다.

**샤오홍슈는 더 노골적이다**: 헤드리스로 접속하면 `安全限制 / IP存在风险`
(보안 제한 / IP에 위험이 있습니다)이 뜬다. 창을 띄우면 그건 사라진다.

## 왜 못 찾았나

`pw_tiktok`이 `except Exception: return []`로 원인을 통째로 삼켰다.
겉으로는 "세션이 없나?"로만 보였다. 도우인 `DouyinBusy`와 같은 함정
([[reference_douyin_download_headless]]).

## 처방

**PC 릴레이** — 쿠팡이 한국 IP 때문에 이미 그 길을 쓴다. 큐·인증·롱폴링을
다시 짜지 말고 `kind`만 추가하면 된다(쿠팡 릴레이는 이미 kind 분기가 있다).

```
coupang_relay.QUEUE.submit(q, limit, timeout, kind="tiktok", payload={...})
```

★반환값은 **None과 []를 갈라라**. 섞으면 "릴레이가 없어 0건"과 "정말 0건"이
구별되지 않아 원인 추적이 또 하루 걸린다.

★릴레이 창은 화면 밖으로(`--window-position=-32000,-32000`). 헤드리스는 막히고,
창이 매번 뜨면 사장님이 일을 못 한다.

## 곁가지 교훈

- **세션 유무를 볼 땐 변수 이름을 확인하고 봐라.** `XHS_SESSION_PATH`로 물어
  "세션 없음"이라 오판했는데 진짜 이름은 `XIAOHONGSHU_SESSION_PATH`였고
  서버에 파일이 있었다.
- 코드 주석의 "무료로 돌고 있다"는 **쓸 당시의 사실**이다. 샤오홍슈가 그랬는데
  실제로는 로그인이 죽어 있었다.
- 틱톡 검색 카드에는 **조회수와 링크뿐**이다(제목·계정 없음) → 계정은 주소에서 뽑는다.
