# 필름검은칸 — "가만있으면 썸네일이 만료되듯 검게 변한다" 수리 (배포 트랙)

## 2026-08-29 (회사) — ✅ 완료·라이브

- 증상(사장님 캡쳐): 3단계 팔레트에서 가만있으면 검은 칸이 하나씩 늘어난다("만료되듯").
- **정체는 만료가 아니라 미리듣기 잔해**: 검은 칸 라벨이 전부 `N-0 미리듣기 a~b초`.
  필름 스페이스 재생·스크럽마다 `playRange`(scene_lab.html)가 `_pv_` 임시조각을
  `DATA.segments`에 넣기만 하고 아무도 안 지웠다 → `pollPhash`가 4초마다 `render()`를
  불러 팔레트 카드로 떠오름 → 서버 `seg_thumb`은 `film_`만 파싱해 `_pv_`는 404 →
  깨진 이미지 = 검은 칸. 재생 횟수만큼 늘어나 "가만있으면 변한다"로 보였다.
- 고침(판정은 `isPvSeg` 하나 — 0순위-B): ①`playRange`가 새 조각 전에 이전 `_pv_` 삭제
  (재생 중인 것만 남김) ②팔레트 빌드 `_pv_` 스킵 ③"고를 수 있는 장면 N개" 개수 제외.
- 검증: HEAD 3파일 하네스(http.server+Playwright) — 미리듣기 3번 → `_pv_` 잔존 1개·
  팔레트 검은 카드 0개·일반 카드 무변 PASS.
- 배포: main 529ac661d 병합, 서버 md5 `d38d1c35…` = 로컬 일치. 라우트가 매 요청
  `read_text`+`no-cache`라 재시작 없이 즉시 서빙(웹 재시작 연기는 무관).

## ⚠️ 왜 별도 트랙인가 (필름박스좌표와 같은 패턴)

`.tracks/필름롤러` 폴더에서 세션 3개가 동시 작업 중이었고, 그 브랜치엔 사장님 확인 전
F22(✂ 쓰는 구간 다듬기)가 실려 있어 **finish 금지** 상태. 그래서 수리 커밋(bccee6c2a)만
`track/필름검은칸`으로 체리픽해 단독 배포했다. 브랜치의 bccee6c2a와 내용 동일 →
나중에 필름롤러 finish 시 충돌 없음. BUILD_TAG는 F22 줄과 충돌 안 나게 일부러 안 올림
(이 라우트는 no-cache라 캐시 판별용 태그 없이도 반영 확인 가능 — md5로 대조했다).

## 배운 것

- **같은 트랙 폴더 동시세션은 `.git/index`도 공유한다** — `git add`만 해둔 남의 파일이
  내 `git commit`에 그대로 실린다(2e658e1b6에서 실제로 남). `git add` 직후가 아니라
  **`git commit -- <경로>`로 커밋 대상을 못 박는 게** 안전하다.
- 검은 카드 = 깨진 `<img>`일 수 있다 — "썸네일 만료"로 단정 말고 **라벨·URL부터** 봐라.
  이 화면 비로그인 curl은 307이라 grep 0건이 "옛 코드" 증거가 아니다(이미 기록된 함정).
