# 볼케이노 원클릭 원리 → 숏템메이커가 가져올 것 (2026-09-12)

근거(전부 실측):
- 볼케이노 서버 응답 원문 — 오늘 이 PC에서 `setup` 3회 호출 결과 · `handoff/볼케이노MCP.md` · `뇌전구_역분석_2026-09-11.md`
- 숏템메이커 코드 — `shopping_shorts/auto_run.py`(143줄) · `script_gate.gate_feedback` · `static/produce.html`(18,393줄) · `app.py` `/api/auto/start`
- 숏템메이커 사고 기록 — memory 14건 (`reference_미리보기만바뀌고_저장안됨` 외)
- 사장님 철학 — memory `feedback_꾸미기_딸깍프리셋철학`: "딸깍 하나로 완성, 조정은 옵션"

목적: 뇌전구를 베끼는 게 아니다. **볼케이노가 왜 소재 하나로 끝까지 가는지**를 뽑아, 숏템메이커가 이미 겪은 문제에 대응시킨다.

## 0. 볼케이노 원클릭의 실체 — 사용자가 하는 일은 딱 하나

```
사용자:  소재(URL/텍스트) + 채널명
서버:    next_step 한 걸음씩 지시 → 클라이언트(AI/실행기)가 그대로 실행 → 결과를 되돌림 → 다음 걸음
사람 자리: script(대본) · prompts(그림 지시) · memes(감정 선택)  ← 이 3곳만. 그것도 AI가 채운다
```

10단계 화면이 없다. 버튼이 없다. **화면 대신 "다음 한 걸음"이 있다.**

## 1. 원리 11개 (서버 응답에서 그대로 읽은 것)

| # | 원리 | 서버 응답의 실제 모양 |
|---|---|---|
| 1 | **서버가 다음 한 걸음만 지시한다** | `next_step`, `do[]`(실행할 명령), `measure[]`(재서 넣을 것), `then_call_with[]`(다음 호출 규칙). 클라이언트는 "임의로 해석하거나 개선하지 마라" |
| 2 | **상태는 한 곳, 명시적으로 넘긴다** | `carry: [review_policy, review_client, env, source_kind]` + `next_payload`를 **그대로** 되돌려야 함. "한 글자라도 다르면 반려" |
| 3 | **돈 나가기 전에 전부 확인** | `setup`이 파이썬·모듈·ffmpeg·키를 **실측**(env_probe 스크립트를 이 PC에서 돌려 결과 JSON을 보냄). 키는 있는지만 본다. 채널별 필요 키표(`channel_needs`)로 **안 쓸 키는 안 묻는다** |
| 4 | **규칙은 판정으로만 존재한다** | 대본 반려 30건 → 2건 → 통과. 반려마다 **원문 사유**("제목에는 구두점을 쓰지 않습니다"). 프롬프트가 아니라 린터가 지킨다 |
| 5 | **디자인 결정은 상수다** | `sub.ass` 스타일 블록이 3편 **바이트 단위 동일**. 사용자가 조정할 게 없다. 길이 따라 크기만 자동 축소 |
| 6 | **사람 자리는 3곳, 나머지는 기계** | script·prompts·memes만 모델이 채움. 실행기 `volcano_drive.py`가 나머지 12단계를 서버와 직접 주고받음 |
| 7 | **멈추면 재개 지점을 파일로 남긴다** | 실행기가 사람 자리에서 멈추며 `next_payload.json` 저장. `--step <멈춘단계> --payload next_payload.json`으로 이어감 |
| 8 | **검수도 AI가 실물을 읽고 답한다** | `review_client: claude`, `review_replies`. 렌더 결과 판정을 사람이 안 본다 |
| 9 | **실패 문구가 원인·처방·위치를 다 말한다** | 키 없음 → "어느 채널에만 필요 / 안 쓰면 발급 안 해도 됨 / 발급 URL / 저장 경로 / 저장 명령 / 왜 필요한지(정렬 단계에서 멈춘다)" |
| 10 | **자산은 팩이다** | sfx·pepe·fonts·runner·framevision 5종을 서명 URL로. 환경에 흩어진 파일에 의존하지 않는다 |
| 11 | **피드백 통로가 내장** | `step=feedback, {kind: request\|bug, text}` — "관리자가 매일 아침 읽는다" |

## 4. 숏템메이커에 얹는 설계 (최소 변경, 있는 것 재사용)

### 4-1. 서버 상태기계 하나 — `/api/produce/next`

```
요청:  {job_id, step, payload}          ← 볼케이노 volcano_video와 같은 모양
응답:  {status: ok|need_input|execute|failed,
        next_step, need: [...],          ← 사람이 채울 것만
        next_payload: {...},             ← 그대로 되돌릴 것
        fail: {where, why, fix, retry_ok}}
```

- 지금 `produce.html`이 들고 있는 10단계 순서·조건 분기가 **서버로** 온다. 화면은 이 응답을 그리기만 한다.
- `mix_jobs`가 이미 job 저장소다. `status` 12종을 `next_step`으로 쓰면 된다.

### 4-2. `auto_run.py`를 살린다 (이미 있음)

| 지금 | 바꿀 것 |
|---|---|
| `default_judge` = 무조건 pass | `script_gate` 판정으로 교체 (**"트랙5 자리"라고 코드에 적혀 있음**) |
| S1·S2·S3 세 단계 | 10단계 어댑터로 확장. 어댑터는 **엔진 호출만** (배선이 한 곳) |
| `waiting_human` 멈춤 | 멈출 때 `need`(뭘 채우면 되는지)를 같이 저장 → 볼케이노 `next_payload.json` |
| 화면 호출 0곳 | 제작소 첫 화면에 "소재 + 프리셋 → 시작" 버튼 하나 |

### 4-3. 규칙표 한 곳 → 지시와 판정을 둘 다 생성

```python
RULES = [
  {"id": "no_comma", "prompt": "자막에 쉼표를 쓰지 마라", "check": lambda cut: "," not in cut.text,
   "reason": "이 채널 자막에 쓰지 않는 부호입니다 [',']"},
  ...
]
prompt_block = "\n".join(r["prompt"] for r in RULES)        # 프롬프트로
verdict      = [r for r in RULES if not r["check"](x)]        # 게이트로 → gate_feedback
```

"시켜놓고 벌주기"가 구조적으로 불가능해진다. `bank_assemble.genre_block`이 이미 이 방향이다.

### 4-4. 실패 응답 표준

모든 `status="failed"` 대입(11곳)이 `{where, why, fix, retry_ok}`를 채운다. "키 소진 또는 응답 오류"가 못 나온다.

### 4-5. 프리셋 = 완성묶음 상수

헤드카피+자막+효과+모션팩을 하나의 JSON 상수로. 화면 컨트롤 25개는 그 상수 위에 덧씌우는 **옵션**이 되고, 저장은 "상수 + 덧씌운 값"을 단계 넘김 때 한 번.

### 4-6. 사람 자리 3곳

```
① 소재 고르기  (S1 후보 5개 중 선택 — 러너가 `candidates`를 이미 남긴다)
② 대본 확인    (S2 초안 3개 중 선택·수정)
③ 최종 확인    (렌더 결과 보고 승인)
```
나머지(분석·EDL·TTS·자막·효과음·렌더)는 게이트가 통과시키면 사람이 안 본다.

| 순 | 할 일 | 푸는 사고 | 고치는 곳 |

## 6. 볼케이노가 안 하는 것 (우리가 더 잘할 수 있는 자리)

- 볼케이노는 **채널이 10개로 고정**이고 스타일이 상수라 사용자가 못 바꾼다. 우리는 프리셋을 상수로 두되 **덧씌우기**를 남긴다(사장님 철학 "완성본에서 미세조정").
- 볼케이노는 실행기가 **로컬 파이썬**을 요구한다(venv·키 파일·팩 다운로드). 우리는 서버가 다 돌리니 사용자 PC에 아무것도 안 깐다.
- 볼케이노는 사람 자리가 **AI(Claude)** 다. 우리는 사람 자리 3곳을 **고객**이 누른다 — 고객이 고른 기록(`log_pick_event`가 이미 있음)이 다음 자동화의 학습 데이터가 된다.

| 7 | `decorate` | 6 · 장면꾸미기 | `mix/settings` · `overlay` · `bgm` · `beatframe` | | 프리셋 상수 + 덧씌운 값 → 렌더 설정 |
| 8 | `render` | 9 · 완성본 (미리보기는 6) | `rendering → done` | | 전부 → mp4 |
| 9 | `thumb` | 7 · 썸네일 | `thumb/*` | | 프레임 → 썸네일 |
| 10 | `seo` | 8 · 제목·태그 | `seo/generate` | | 대본 → 제목·태그 |
| 11 | `review` | 9 · 완성본 | 없음 | **○** | mp4+썸네일+제목 → 승인 |
| 12 | `publish` | 10 · SNS 예약 발행 | `works` | | 승인본 → 예약 |

- 사람 자리: 볼케이노 3곳 / 우리 지금 10곳 전부 → ○ 세 곳만 남긴다
- 서버 상태 `downloading→extracting→planning→tts→ready_for_review→rendering→done`은 **3단계 안의** 전이일 뿐. 배열 전체는 서버가 아니라 화면 `goStep`에 있다 → 서버로 옮긴다
- `auto_run.STAGE_ORDER = ["S1","S2","S3"]`가 배열 자리. 3개 → 13개로 늘린다
- 볼케이노에만 있는 단계: `setup`(돈 나가기 전 점검) · `review`(AI 실물 검수). 우리에만 있는 단계: `clean` · `thumb` · `seo` · `publish`
