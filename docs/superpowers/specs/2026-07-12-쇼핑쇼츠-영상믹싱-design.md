날짜: 2026-07-12 (rev.2 — 대본↔장면 통합·표절회피·구조모드 반영)

## 1. 목적 (What & Why)

기능③(제품 찾기)이 "같은 제품/주제를 다루는 여러 플랫폼 영상 링크"를 찾아주는 데까지였다면,
이 기능은 **그렇게 찾은(또는 사용자가 직접 고른) 동일 주제 레퍼런스 영상 2~5개를 실제로
믹스(짜집기)해서 하나의 새 쇼핑 숏폼 영상을 만들어내는 단계**다. 8단계 위저드 전체 중
**1~2단계(영상 분석 · 영상 선택/믹스)만** 이번 스펙 범위. 3~8단계(스타일/썸네일/SEO/내보내기)는
별도 스펙으로 이후 진행.

### 믹스의 정의 (사용자 확정)
- 입력: 동일 주제·비슷한 내용을 다루는 레퍼런스 영상 2~5개 URL + 목표 길이(초)
  + **구조 모드(템플릿 / 자유)**
- 각 레퍼런스 영상에서 **대본**(나레이션 음성 또는 화면 자막 — 구현 편의상 더 빠른 쪽을
  Gemini 멀티모달 1콜로 통합 추출, 둘을 구분하지 않는다)을 세그먼트(타임코드+장면묘사)로 추출
- **핵심(rev.2):** "다음에 할 말"과 "그 순간 쓸 소스 장면"을 **따로 결정하지 않는다.**
  여러 레퍼런스의 강점(후킹·셀링포인트·구조)을 분석하면서 **문장·소스구간·순서·길이·효과를
  하나의 편집결정목록(EDL)으로 동시에 생성**한다. 대본을 먼저 확정한 뒤 장면을 끼워맞추면
  "억지 매칭"이 생긴다는 게 확정된 요구사항 — 그래서 합성과 매칭을 단일 단계로 합친다.
- **표절회피 필수:** 원본 문장·구절을 그대로 베끼지 않고 의미·구조만 계승(새벽 실측 스파이크
  `out/shopping_shorts/텀블러_믹스대본.md`에서 검증된 패턴). 프롬프트 규칙 + 사후 n-gram 가드로 강제.
- **구조 모드 2종(둘 다 지원, 사용자 확정):**
  - 템플릿 모드: 훅→페인포인트→반전→실용→CTA 같은 고정 비트 스켈레톤을 채운다.
  - 자유 모드: Gemini가 비트 수·구조를 스스로 결정한다.
  두 모드 모두 **동일한 EDL 스키마**를 산출한다(하류 파이프라인 공통).
- 새 대본을 **ElevenLabs TTS로 새 나레이션 음성 생성**(원본 목소리 재사용 안 함)
- 자동 EDL 결과를 화면에서 확인 → **마음에 들면 그대로, 아니면 비트별로 사람이 다른
  소스구간(대체 후보)으로 교체**(완전자동 우선, 사람 확인은 안전판 — B안) → 최종 렌더

## 2. 전체 흐름

```
1. 입력: 레퍼런스 URL 2~5개 + 목표 길이(초) + 구조 모드(템플릿/자유) [mix.html]
      ↓
2. [백그라운드 job 시작] 각 영상 다운로드 (기존 download_video 재사용)
      ↓
3. 영상별 Gemini 멀티모달 1콜: 대본 세그먼트 추출 (병렬)
   {segments:[{seg_id,start,end,text,scene_desc}], full_text}
      ↓
4. ★통합 편집결정(EDL) 생성 — script_synth+clip_match를 하나로 합친 단계★
   모든 소스의 세그먼트 인벤토리 + 목표길이 + 구조모드를 Gemini에 한 번에 입력 →
   비트마다 {새 문장(원문 회피) · 지목한 소스구간(seg_id) · 대체후보 · 목표길이 · 효과}를
   동시 결정. 사후검증으로 seg_id를 실제 타임코드로 그라운딩 + 표절 n-gram 가드.
      ↓
5. 비트별 ElevenLabs TTS 생성 (EDL의 문장 단위)
      ↓
6. [결과 확인 화면] 비트×지목구간×대체후보×TTS 미리듣기 표시
   → 사람이 비트별로 대체 후보(또는 인벤토리 내 다른 구간)로 교체 가능(B안).
     안 건드리면 자동 EDL 그대로
      ↓
7. [최종 렌더] ffmpeg: 지목 구간을 비트 TTS 길이에 맞춰 트림/배속보정 후 컷 편집 +
   원본음소거 + 새 TTS 오디오 합성 → 완성 mp4
```

## 3. 신규 모듈 (`shopping_shorts/`, 기존 순수함수 패턴 유지)

> **키 풀 규칙(전 모듈 공통, 필수):** 모든 신규 Gemini 호출은 **전용 풀
> `SHORTS_GEMINI_KEYS`만** 사용하고 공유 풀(`pipeline.atoms.key_vault`의 그룹 풀)로
> **폴백하지 않는다**(2026-07-09 확정: 공유 풀은 인제스트·브리핑과 하루 종일 같이
> 소모돼 예고 없이 소진되는 사고가 있었음). 로테이션은 `comment_gen._current_key_and_idx()` /
> `comment_gen._mark_key_exhausted()` / `comment_gen._client_for_key()`를 재사용하고,
> 소진 판정(`key_vault.is_daily_exhausted_error` 등 순수 함수)만 key_vault에서 빌려 쓴다
> (video_analysis.py·product_identify.py·similarity.py와 동일 컨벤션).
>
> ⚠️ 오늘 새벽 커밋된 `transcribe_gemini.py`는 `key_vault.get_client("general")`(공유 풀 +
> 크로스그룹 폴백)을 써서 이 규칙을 **위반**한다. → §3-1이 이를 흡수·대체하며 폐기한다(§3-0).

### 3-0. `transcribe_gemini.py` 처리 (컨벤션 위반 정리)
- **권고: `script_extract.py`(§3-1)로 흡수하고 `transcribe_gemini.py`는 폐기.**
  기능이 겹친다(둘 다 Gemini 멀티모달 전사). 단, `script_extract`는 (a) 전용 풀 사용,
  (b) `response_schema`로 세그먼트 구조 강제, (c) 타임코드·장면묘사까지 추출 — 세 가지가
  더 엄격하다. 새벽 스파이크의 프롬프트 문구(의역 금지·나레이션 우선)는 §3-1 프롬프트에
  녹인다. `__main__` CLI가 필요하면 `script_extract.py`에 동일하게 남긴다.

### 3-1. `script_extract.py` (대본 세그먼트 추출)
- `extract_script(video_path: str, caption: str = "") -> dict`
  → `{"segments": [{"seg_id": str, "start": float, "end": float, "text": str, "scene_desc": str}], "full_text": str}`
- Gemini 멀티모달 1콜(영상 파일 직접 입력, `video_analysis.py`와 동일 File API 패턴) —
  나레이션과 화면 자막을 구분하지 않고 통합해 세그먼트별 텍스트+타임스탬프+장면 설명 추출.
- `response_schema` 강제(2026-07-10 zh/ja/ru 빈배열 버그 때 도입 패턴 재사용) — `segments`
  배열 `minItems: 1`로 빈 응답 방지. `seg_id`는 추출부에서 `{video_id}-{n}`로 부여(모델이
  아니라 코드가 발번 → 하류 EDL의 참조 무결성 보장).
- 전용 키 풀 로테이션(§3 공통 규칙). 실패 시 빈 세그먼트 반환(호출부가 처리).
- 여러 영상은 app.py에서 `ThreadPoolExecutor`로 병렬 추출(product_identify의 병렬화 선례).

### 3-2. `edit_plan.py` (★ script_synth + clip_match 통합 — rev.2 핵심)
- 공개 함수:
  ```python
  def build_edit_plan(
      source_scripts: list[dict],   # [{"video_id", "segments":[...], "full_text"}] (§3-1 출력들)
      target_seconds: int,
      structure: str = "template",  # "template" | "free"
      n_alternates: int = 2,        # 비트당 대체 소스구간 후보 개수
  ) -> dict:
      """반환:
      {
        "structure": "template"|"free",
        "beats": [
          {
            "beat_idx": int,
            "role": str,            # 템플릿: 훅/페인포인트/반전/실용/CTA · 자유: 모델이 라벨
            "narration": str,       # 새로 합성된 문장(원문 회피)
            "target_seconds": float,
            "primary": {"video_id","seg_id","start","end"},   # 실제 타임코드로 그라운딩됨
            "alternates": [{"video_id","seg_id","start","end"}, ...],  # 길이 n_alternates
            "effect": "cut"         # 기본 cut (효과 확장은 이후 스펙)
          }, ...
        ],
        "plagiarism_flags": [{"beat_idx": int, "max_overlap": float}]  # 가드 결과(있으면 UI 경고)
      }
      """
  ```
- **왜 통합인가(설계 판단):** 대본을 먼저 확정하면 확정 문장에 장면을 억지로 맞춰야 한다.
  대신 소스 세그먼트 인벤토리를 프롬프트에 함께 넣고, 모델이 **비트마다 "무슨 말을 할지"와
  "그 말에 맞는 실제 소스구간(seg_id)"을 동시에** 정하게 한다(footage-first: "쓸 그림이 있는
  말"을 쓴다). 이로써 매칭이 사후 끼워맞추기가 아니라 대본 생성의 제약조건이 된다.
- **그라운딩 가드(단일 거대콜의 환각 방지 — 필수):**
  1. `_build_inventory(source_scripts)` — 전 소스 세그먼트를 `seg_id·start·end·(길이)·text·
     scene_desc`의 플랫 목록 + 프롬프트용 압축 텍스트 블록으로. 모델에는 **seg_id로만 지목**
     하게 하고 start/end 숫자를 새로 지어내지 못하게 한다.
  2. `_validate_and_ground(plan, inventory)` — 모델이 돌려준 primary/alternates의 seg_id가
     인벤토리에 없으면 제거·보정, **start/end는 모델 값이 아니라 인벤토리의 실제 타임코드로
     되붙인다.** 유효 후보가 부족한 비트는 같은 role 인근 세그먼트로 채운다.
  3. `_plagiarism_guard(beats, source_full_texts)` — 각 `narration`과 소스 `full_text`
     합본의 문자 n-gram(예: 6-gram) 최대 겹침률 계산. 임계 초과 시 해당 비트만 재프롬프트
     (1회) 후에도 높으면 `plagiarism_flags`에 기록해 UI에서 재작성 유도. (스파이크가 이미
     "의미만 계승" 산출을 실증 → 가드는 회귀 방지용 안전망.)
- **구조 모드 처리:** `structure="template"`이면 `_REQUIRED_ROLES=["훅","페인포인트","반전",
  "실용","CTA"]`를 "반드시 이 순서·이 역할의 비트를 채우라"로 프롬프트에 주입. `"free"`면
  비트 수·구조를 모델이 결정(단 목표길이·표절회피·seg_id 지목 규칙은 공통). 출력 스키마는 동일.
- **길이 예산:** 인벤토리에 각 세그먼트 실제 길이를 함께 주고, 비트 `target_seconds`는 지목
  구간이 감당 가능한 범위(또는 배속보정 허용범위) 내로 잡도록 지시 → §3-4 렌더 단계의
  길이 불일치를 사전 축소.
- 단일 Gemini 콜(전용 풀 로테이션), `response_schema` 강제. 모델은
  `video_analysis._MODEL`(비디오 불필요하므로 텍스트 대형 모델도 가능 — 초기엔 동일 모델로
  통일 후 실측). 프롬프트 설계 방향:
  1) 역할: 숏폼 편집 감독. 2) 입력: 목표길이·구조모드(+템플릿이면 필수 비트)·소스별 세그먼트
  인벤토리(id/시간/텍스트/장면). 3) 지시: 문장을 한꺼번에 다 쓰지 말고 비트 단위로 "이 순간
  할 말 + 그 말에 맞는 seg_id + 대체 후보 2개 + 예상길이 + 효과"를 함께 결정. 4) 표절회피:
  원문 문장·구절 그대로 금지, 후킹·구조만 계승해 새 표현으로. 5) 출력은 스키마 JSON만.

### 3-3. `tts.py` (ElevenLabs TTS)
- `synthesize_tts(text: str, out_dir: str, voice_id: str | None = None) -> str` — 문장(비트)당 1콜, mp3 경로 반환.
- 신규 설정: `ELEVENLABS_API_KEY`(`config.py`에 추가, **로컬/서버 모두 미설정 확인됨 — 구현
  착수 전 사용자가 키 발급/전달 필요**). 키 없으면 개발용 무음/모의 클립 반환(파이프라인
  E2E는 키 없이도 돌게). voice_id는 고정 1종 기본값, 인자로 열어둠(UI 노출은 범위 밖).
- ElevenLabs는 Gemini와 무관한 별도 API — 전용/공유 키풀 규칙과 무관(로테이션 대상 아님,
  단일 키). 429/실패 시 짧은 백오프 재시도.

### 3-4. `video_assemble.py` (ffmpeg 렌더)
- `assemble(edit_plan: dict, tts_paths: dict[int, str], source_video_paths: dict[str, str]) -> str`
- ffmpeg subprocess 패턴(`frame_extract.py`와 동일 스타일): 각 비트의 `primary` 구간을 해당
  비트 TTS 길이에 맞춰 트림(구간이 더 길면 잘라내고, 더 짧으면 배속보정 한도 내에서 느리게
  재생 — 한도 초과 시 `alternates`의 다음 후보로 자동 대체) → concat → 원본 오디오 제거 →
  비트별 TTS를 이어붙인 오디오 트랙으로 교체 → mux → 최종 mp4 경로 반환.
- 배속 보정 한도(예: 0.8~1.2배)는 상수로 두고 실측 후 튜닝.

## 4. 데이터 모델 (신규 테이블, `store.py`에 추가)

```sql
CREATE TABLE mix_jobs (
  job_id TEXT PRIMARY KEY,
  urls_json TEXT NOT NULL,        -- 입력 레퍼런스 URL 목록
  target_seconds INTEGER NOT NULL,
  structure TEXT NOT NULL,        -- 'template' | 'free'
  status TEXT NOT NULL,           -- downloading|extracting|planning|tts|ready_for_review|rendering|done|failed
  error TEXT,                     -- status=failed일 때 사유
  extract_json TEXT,              -- §3-1 결과 캐시(소스별 세그먼트 인벤토리) — 수동교체가 재추출 없이 대체후보 접근
  edit_plan_json TEXT,           -- §3-2 결과(EDL). 사람이 비트 교체하면 이 컬럼만 in-place 갱신
  video_path TEXT,                -- 최종 렌더 결과(완료 후)
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL
);
```

- rev.1의 `script_json` + `matches_json`(대본/매칭 분리 저장)을 **단일 `edit_plan_json`**(EDL)으로
  통합 — §3-2 통합에 대응. `extract_json`을 별도 캐시로 둬 수동교체 시 세그먼트 인벤토리에
  재추출 없이 접근한다.
- 기존 `source_candidates`/`source_pool`(임베드 검색 시절 유물, 죽은 코드)은 이 기능과 무관 — 손대지 않는다.

## 5. API 엔드포인트 (신규)

오래 걸리는 작업(다운로드+Gemini 멀티콜+TTS+ffmpeg, 수 분)이라 **백그라운드 job + 폴링** 패턴:

- `POST /api/mix/start` `{urls:[...], target_seconds:int, structure:"template"|"free"}` →
  `{job_id}` 즉시 반환. `BackgroundTasks`로 다운로드→추출(병렬)→EDL 생성→TTS 순차 실행하며
  `mix_jobs.status` 갱신.
- `GET /api/mix/status/{job_id}` → `{status, error?}` — 프론트 폴링.
- `GET /api/mix/result/{job_id}` → `{structure, beats:[{beat_idx, role, narration,
  target_seconds, primary, alternates, tts_preview_url, plagiarism_flag?}]}` — status가
  `ready_for_review` 이상일 때만 유효.
- `POST /api/mix/adjust` `{job_id, beat_idx, video_id, seg_id}` — 해당 비트의 primary를
  지정 구간(대체 후보 또는 인벤토리 내 임의 구간)으로 교체, `edit_plan_json` in-place 갱신
  (start/end는 서버가 `extract_json` 인벤토리에서 되붙임 — 클라이언트 숫자 신뢰 안 함).
- `POST /api/mix/render` `{job_id}` → 최종 ffmpeg 렌더 시작(백그라운드, status→`rendering`→`done`).
- `GET /api/mix/video/{job_id}` → 완성 mp4 서빙(기존 `/api/find/frame/*` 프록시 패턴).
- (선택) `GET /api/mix/tts_preview/{job_id}/{beat_idx}` → 비트 TTS mp3 서빙.

## 6. 화면 (`shopping_shorts/static/mix.html`, 사이드바 "영상 믹싱" 메뉴 추가)

1. **입력:** URL 필드 2~5개(+소스 추가), 목표 길이 슬라이더(초), **구조 모드 토글(템플릿/자유)**,
   "믹스 시작" 버튼.
2. **진행 중:** 단계별 상태 텍스트(다운로드 → 대본 추출 → **편집안 생성** → 음성 생성) —
   `status` 폴링 갱신.
3. **결과 확인(EDL 리뷰):** 비트 리스트. 비트마다 { 역할 배지 · 새 나레이션 문장 · 지목 구간의
   대표 썸네일 1장 + "어느 영상 몇초~몇초" · TTS 미리듣기 }. 마음에 안 드는 비트만 드롭다운
   (대체 후보 2~3개 또는 소스 인벤토리)에서 교체. `plagiarism_flag`가 있으면 해당 비트에
   "원문과 유사 — 재작성 권장" 경고 배지. 전부 만족하면 "최종 렌더".
4. **완료:** 완성 mp4 미리보기(`<video>`) + 다운로드 링크.

## 7. 알려진 리스크

- **ElevenLabs API 키 미확보** — 로컬/서버 모두 미설정. 구현 착수 전 사용자 발급 필요
  (그전까지 mock/무음으로 개발·E2E).
- **통합 EDL 콜의 타임코드 환각** — 단일 거대 콜이 존재하지 않는 구간을 지어낼 수 있음.
  §3-2 그라운딩 가드(seg_id 지목 강제 + 실제 타임코드 되붙임 + 유효성 검증)로 방어. 초기
  구현 직후 실제 레퍼런스로 "지목한 구간이 나레이션과 실제로 맞는가" 실측 필수 — 품질 낮으면
  프롬프트 튜닝 / 대체후보 개수 확대 / (최후) EDL을 2패스(초안→비트별 재검토)로 분할.
- **표절회피 회귀** — 프롬프트만으로 원문 베낌이 새어나올 수 있어 n-gram 가드를 반드시 둔다
  (스파이크는 통과했으나 입력 영상에 따라 달라짐).
- **구간 길이-TTS 길이 불일치** — 배속보정 한도 초과 시 차순위 후보 자동 대체(§3-4). §3-2가
  길이 예산을 footage 길이 인지 상태로 잡아 사전 축소.
- **ffmpeg 처리 시간** — CPU 바운드, 서버 사양 따라 대기 큼. 실측 후 필요시 큐잉/동시실행 제한.
- **저작권** — 타 크리에이터 원본을 컷 편집해 재사용하는 것이 사업 방향(경쟁사 공통) — 이
  스펙에서 별도 처리 안 함(기존 합의).

## 8. 단계적 구현 순서

1. `mix_jobs` 테이블 + `script_extract.py`(전용 풀·response_schema·seg_id 발번) — 레퍼런스
   1개로 실측 검증. **동시에 `transcribe_gemini.py` 흡수·폐기**(공유풀 위반 제거).
2. `edit_plan.py`(★통합 EDL) — 2~3개 영상으로 실측: (a) 지목 구간이 나레이션과 맞는지,
   (b) 표절 가드 동작, (c) 템플릿/자유 두 모드 모두. **가장 리스크 큰 단계이므로 여기서
   품질 게이트** — 통과 못 하면 프롬프트/2패스 분할 결정.
3. ElevenLabs 키 확보 후 `tts.py` 연동 + 실측(키 전이면 mock으로 파이프라인만 관통).
4. `video_assemble.py`(ffmpeg 렌더) — 배속 보정/차순위 자동대체 포함.
5. `/api/mix/*` 엔드포인트 + `mix.html`(폴링 + EDL 리뷰 + 비트 교체 + 최종 렌더).
6. 전체 파이프라인 E2E 실측(레퍼런스 2~3개, 실제 mp4 산출까지).
