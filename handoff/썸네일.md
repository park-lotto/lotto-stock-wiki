## 상태 (2026-08-04 — ★페이즈2: 저장한 썸네일 → 최종렌더 배치 + 카톡 한 번에 전송)

사장님 요청: "썸네일 페이지에서 작성된 거 저장하면 최종랜더 쪽으로 배치하고 카톡으로 보낼 때
한 번에 보낼 수 있게." → **아래 ⏭3 "selected의 소비자가 없다"가 바로 이거였다. 이번에 배선했다.**
트랙 `썸네일카톡동봉`(신규 — 기존 썸네일 트랙 재사용은 흡수 위험이라 안 씀).

**뭘 했나**
1. **8단계 최종렌더에 썸네일 카드** — 완성 영상(9:16) **옆에 나란히**(사장님 선택). `#finalThumb`.
   ⚠️`THUMB_STATE`는 페이지 메모리라 새로고침하면 빈다 → **DB를 진실로** 삼는 신규 라우트
   `GET /api/produce/thumb/selected/{job}`를 8단계가 조회한다(안 골랐으면 200+`name:null`,
   **404 아님** — 404면 프런트가 오류로 오인해 카드가 깨진다). 안 골랐으면 '6단계에서 고르기' 버튼.
2. **카톡 전송에 영상+썸네일 동봉** — `navigator.share({files:[mp4, png]})` **한 번의 호출**로.
   - PC 제작소 `shareVideo()` / 폰 공유페이지 `/s/{sid}` 둘 다.
   - 기기가 다중 파일을 거절하면 `canShare`로 먼저 물어보고 **영상만**으로 자동 강등(기존 동작 보존).
     무조건 2개로 부르면 통째로 실패한다. 취소(AbortError)는 폴백 금지 — 공유창이 두 번 뜬다.
3. **신규 공개 라우트** `GET /api/share/t/{sid}` = 선택 썸네일 PNG. `?dl=1`은 첨부.
   ★**미들웨어 allowlist에 `/api/share/t/` 추가가 필수**다 — 폰은 쿠키가 없어 이 한 줄이 빠지면
   썸네일만 조용히 죽는다(테스트 `test_share_thumb_path_is_public_allowlisted`가 이 줄을 지킨다).
4. `_selected_thumb_path()` 헬퍼 — `selected`는 DB를 통과한 문자열이라 basename 봉인을 한 번 더.

**검증(실측)**
- 신규 계약 테스트 **14건 전원 통과**(`test_share_thumb_bundle.py`). **뮤턴트 2종으로 진짜 잡는지 확인**:
  ① `/s/` 치환을 옛 단일 replace로 되돌림 → 2건 FAIL ② allowlist 한 줄 제거 → 1건 FAIL.
- **브라우저 실구동**(playwright, 로컬 :8877). `navigator.share`를 가로채 **실제 넘어간 인자**를 관측:
  `files=[shopping_short.mp4(64B), shopping_short_thumb.png(70B)]`, `title='완성 영상 + 썸네일'`
  = **한 번의 공유에 2개 파일**이 실린 직접 증거. 다중 거절 기기 시뮬 → 영상 1개만, 호출 1회(중복 없음).
  썸네일 미선택 job → `T=""`·썸네일 UI `display:none`·영상만 = **회귀 0**.
  ⚠️`MIX_JOB`은 렉시컬 바인딩이라 `window.MIX_JOB=`으론 안 바뀐다(처음에 이걸로 "카드가 안 뜬다"고
  오판했다 — 하네스 탓이었다). 간접 eval로 실제 바인딩에 대입해야 한다.
- 회귀: share/thumb/produce 전체 **306 passed·0 failed**. 전체 스위트 15 failed는 **clean baseline에서도
  똑같이 15건**(apify·tiktok·edit_plan·mix_pipeline·xiaohongshu = 외부 API 계열) → **증가 0**.
  `test_sub_region.py`는 numpy 미설치로 수집 에러(선존재, 무관).

⏭ **다음**: 라이브에서 실제 폰 카톡으로 2개 파일이 한 대화방에 가는지 사장님 육안 확인

## 상태 (2026-07-19 갱신 — 제목 줄바꿈·위치 개편 배포)

사장님 제보: 썸네일 제목에 **줄바꿈·위치 조정이 안 됨**. "60대도 손 거의 안 가게" 방향으로 개편해 배포(`111825574` → main `8bca2a688`).

1. **자동 줄바꿈 + 자동 크기맞춤** — `drawThumb`이 단일 `fillText`에서 다줄 렌더로. 안전 가로폭(W×0.88) 안에
   들어가게 어절→(안 되면)글자 단위로 쪼개고, 그래도 넘치면 폰트를 2px씩 줄여 **항상 안 넘치고 안 잘림**.
   신규 `thumbWrapLines`/`thumbFit`. 다줄은 앵커(L.x,L.y) 기준 세로 중앙 정렬.
2. **수동 줄바꿈** — 입력칸 `<input>`(한 줄)→`<textarea>`. Enter로 원하는 위치 줄바꿈.
3. **위치 = 큰 버튼 3개** `⬆위(y=0.16)/⏺가운데(0.5)/⬇아래(0.84)` `setThumbPos`. x는 0.5로 리셋. 드래그도 유지.

**검증**: 기존 계약 테스트 16개(`test_produce_thumb_ui/wire`) 전부 통과 — 비율좌표·폰트배율·박스패딩·외곽선·
회전복원·N레이어=정확히 N fillText 계약 보존. 신규 동작(2줄 자동줄바꿈/수동\n 2줄 크기유지/긴단어 글자쪼갬
안전폭 이내/짧은문구 1줄 크기유지)은 pytest와 **같은 slice+node 하네스**로 실측. 서버 pull 배포(3분).

⏭ **다음**: 라이브 실사용 관측 — 자동축소가 min(12px×s)까지 갔을 때 가독성, 박스형 프리셋에서 다줄 박스 겹침.

## 상태 (2026-07-18 갱신 — 사장님 실사용 제보 4건 배포)

사장님이 라이브에서 실제로 써보며 제보한 4건을 순서대로 잡아 배포·검증했다:

1. **드래그가 글자를 못 잡던 것** — hit-test가 없어 캔버스 아무 데나 누르면 선택 글자가
   그 지점으로 순간이동했다. → 누른 지점 가장 가까운 글자를 잡고(반경 0.28 밖이면 안 잡음)
   간격 유지한 채 끈 만큼만 이동(상대이동). (`54ae16c4`)
2. **드래그 시 글자가 겹겹이 쌓이던 것** — `drawThumb`이 매 렌더에서 캔버스를 안 지워, 배경
   영상이 없을 때(job 없음) 드래그 경로마다 잔상이 쌓였다. → `ctx.clearRect` 첫 줄에 추가. (`d1f275ed`)
3. **매칭 끝냈는데 5단계서 "믹스 영상 없음"** — thumb/frames가 `video_path`(7단계 최종 렌더
   산출물)만 봤다. 그 전 단계(5단계)엔 없다. → 최종 렌더(app.py:3164)와 같은 우선순위
   `video_path → clean_video_path → preview_path`로 폴백. **라이브 검증: 수박 작업에 프레임
   10장 뜸.** (`bd7c6491`)
4. **꾸미기 미리보기 자막이 문장 통째로** — 실제 영상은 `_caption_segments`로 2~3어절 쪼개는데
   미리보기(beats_preview)는 narration 통째를 줬다(미리보기가 거짓말). → 서버가 실제 렌더와
   같은 구절 분할(segs)+실제 표시시간(durs)을 주고, 미리보기 `showBeat`이 `_playBeatCaptions`로
   그 장면 안에서 구절을 순차 재생. **사장님 A안(순차 재생).** (`780dde2a`)

### ⚠️ 이번 세션 교훈 두 개
- **로컬 서버 크기 대조를 매번 먼저 하라.** 유령 프로세스가 옛 `produce.html`(175737, THUMB_STATE
  없음)을 서빙하는 걸 크기 대조 안 하고 30분 헤맸다. `서빙본 wc -c == 디스크 wc -c` 먼저.
- **검증 스크립트가 페이지 상태를 주입하고 있지 않나 확인하라.** `STATE.job_id`를 손으로 심어
  "실증했다"고 착각한 전례(memory `feedback_harness_invented_contract`).

### ⚠️ finish의 "Aborting"은 내 배포와 무관
`finish`가 매번 main 폴더 로컬 정리(pull) 단계에서 `error: ... test_style_use_js.py ... Aborting`을
낸다. 이건 **모션효과 트랙이 남긴 untracked 파일 + main 폴더 미완료 병합**(MERGE_HEAD=36566cd9)
때문이고, **origin/main push는 매번 성공**한다(코드 grep으로 확인). 여러 트랙이 같은 증상을
겪었다(대시보드 렌즈·장면라이브러리). main 폴더 정리는 그 병합을 만든 세션 소관 — 함부로
commit/abort 안 함(크롤 데이터 uncommitted가 섞여 있어 위험).

## ⚠️ 이 트랙에서 반드시 지킬 것

1. **테스트는 `-s`** — 빼면 유령 실패 33건(`OSError: WinError 6`). 코드 결함 아님(실측).
2. **콘솔이 cp949** — 스크립트에서 비ASCII print는 `UnicodeEncodeError`로 죽는다.
   **뮤턴트 심는 스크립트가 그렇게 죽으면 뮤턴트 없이 "초록"이 나와 확인했다고 착각한다.**
   `PYTHONIOENCODING=utf-8` 쓰거나 ASCII만 찍어라.
3. **`produce.html`은 3개 트랙이 동시에 만진다**(대본믹스통합·모션효과). 태스크 단위로 짧게 병합.
   실제로 이번에 부팅 자리에서 충돌 났다 — 해소는 원장 참조(순서가 답이었다: TDZ).
4. **★검증 스크립트가 페이지 상태를 대입하고 있지 않나 확인하라.**
   `STATE.job_id = '...'`를 손으로 심어놓고 "실증했다"고 3번 착각한 전례가 있다(원장 참조).
   대입하는 줄이 있으면 **그 값을 페이지가 진짜로 넣는지 grep으로 확인**할 것.
