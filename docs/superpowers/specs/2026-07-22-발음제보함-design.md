# 발음 제보함 (제작소→작업대) — 설계

- 날짜: 2026-07-22
- 트랙: 보이스
- 상태: 설계 승인됨(제보함 모델, 2026-07-22) → 이 문서 → writing-plans
- 선행: `2026-07-22-발음교정-전역사전-작업대-design.md`(라이브). 이 기능은 그 작업대로 제보를 흘려보낸다.

## 1. 문제

발음교정 작업대(`/voice_tune`)는 별도 페이지라 제작소에서 링크가 없고, 어색한 문장을 다시
타이핑해야 한다. 사장님은 **제작소 TTS 단계에서 어색한 비트를 듣는 그 자리에서** "이거
잘못됐어 + 코멘트"를 바로 보내고, 나중에 작업대에서 몰아 처리하고 싶다. 전부 관리자 전용.

## 2. 아키텍처 — 제보함(inbox) 모델

### A. DB + Store (서버 DB, 기존 발음사전과 동일 이유로 git 파일 금지)
- 새 테이블 `pron_reports(id INTEGER PK AUTOINCREMENT, text TEXT, comment TEXT,
  created_at TEXT, resolved INTEGER DEFAULT 0)`.
- Store 메서드:
  - `add_pron_report(text, comment) -> int`(id 반환)
  - `list_pron_reports(include_resolved=False) -> [{id, text, comment, created_at}]`(최신순)
  - `resolve_pron_report(report_id) -> None`(resolved=1)

### B. 엔드포인트 (전부 `_require_admin` first)
- `POST /api/pron/report` {text, comment} → `{ok, id}`. text 비면 400. comment는 선택(빈 문자열 허용).
  created_at은 서버가 `datetime.now(timezone.utc).isoformat()`로 찍는다.
- `GET /api/pron/reports` → `{reports:[{id, text, comment, created_at}]}`(미처리만, 최신순).
- `POST /api/pron/reports/{id}/resolve` → `{ok}`.

### C. produce.html — 제작소 (관리자만 노출)
- 이미 있는 `window.IS_ADMIN`(`/api/me`의 customer_id===0에서 세팅됨)로 노출 판별.
- **각 비트 카드에 `🩺 발음 이상해요`** 버튼(관리자만). 클릭 → 그 자리에 인라인 미니폼
  (작은 코멘트 input + `보내기`)이 펼쳐짐 → `보내기` → `POST /api/pron/report
  {text: 비트 narration, comment}` → 성공 시 버튼이 `✓ 제보됨`으로 바뀜.
  - **인라인 폼(프롬프트 아님)**: JS `prompt()`는 자동화 그라운딩을 막고 UX도 투박하다. 작은
    input+버튼을 인라인으로 편다.
- **TTS 단계 상단에 `🩺 발음교정 작업대 열기`** 버튼(관리자만) → `/voice_tune` 새 탭
  (`window.open('/voice_tune','_blank')`).
- 비트 문장(narration)은 프론트가 이미 들고 있는 값을 그대로 보낸다(서버 재조회 불필요).

### D. voice_tune.html — 작업대에 `📥 제보함` 섹션
- 발음교정 카드 위(또는 아래)에 제보함 카드 추가. `GET /api/pron/reports`로 목록 로드.
- 각 항목: 문장 + 코멘트 + `[이 문장 교정]`(클릭 → `pl_text`에 문장 채우고 발음교정 카드로
  스크롤) + `[✓ 처리됨]`(→ `POST /api/pron/reports/{id}/resolve` → 목록에서 제거).
- 기존 안전장치 재사용: `esc()` 이스케이프 + **인덱스 기반 onclick**(`plReportPick(i)`/
  `plReportResolve(i)`가 module 배열 `plReports[i]` 참조) — Task6 리뷰의 인젝션 교훈 유지.
- 작업대 진입 시 `plLoadReports()`도 `init()`에서 호출.

### E. 관리자 전용 (이중)
- 엔드포인트 3개 전부 `_require_admin`(비관리자 403).
- 프론트 버튼은 `window.IS_ADMIN`일 때만 DOM에 추가(비관리자는 아예 안 보임).
- voice_tune.html은 이미 페이지 자체가 관리자 게이트(선행 spec Task5).

## 3. 데이터 흐름
```
[제작소 비트] 🩺발음이상해요 → 코멘트 인라인 → POST /api/pron/report
   → Store.add_pron_report → DB(pron_reports)
[작업대] 📥제보함 ← GET /api/pron/reports ← DB
   항목 [이 문장 교정] → pl_text 채움 → (기존)AI제안→A/B→전역사전 저장
   항목 [✓처리됨] → POST /api/pron/reports/{id}/resolve → DB resolved=1
```
제보 처리와 전역사전 저장은 **분리**(제보=할 일 목록, 전역사전=실제 교정). 처리됨 표시는 수동
(저장했다고 자동 resolve 안 함 — 한 제보가 여러 교정을 낳을 수 있고, 판단은 사장님).

## 4. 에러 처리
- report POST에 text 없으면 400. 저장 실패는 프론트에 실패 메시지(버튼 원복).
- reports 목록/ resolve 실패는 조용히 무시(제보함은 부가기능, 작업대 본기능 안 죽인다).
- 비관리자가 어찌 버튼을 눌러도 엔드포인트 403(이중 방어).

## 5. 테스트
- `test_pron_reports_api.py`: report 저장→목록 라운드트립 / text 없으면 400 / resolve가
  목록에서 빼는지 / 비관리자 403(기존 test_pron_api.py 인증 패턴 복제).
- Store 단위: add→list(미처리만)→resolve→list(빠짐).
- UI(produce/voice_tune)는 정적검증(node --check·grep·id/handler 정합) + 배포후 라이브 그라운딩.

## 6. 범위 밖 (YAGNI)
- 제보에 오디오 첨부(텍스트+코멘트로 충분).
- 제보 자동→전역사전(사람이 교정 판단해야 함).
- 처리됨 이력/통계 화면.
