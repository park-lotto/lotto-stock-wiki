## 2026-08-16 (회사PC) — 렌즈 체감 지연의 진짜 원인 제거

### 발단

사장님: **"렌즈검색 속도 회사에서 개선했는데 바뀐 게 없는 것 같다"**

### 먼저 배제한 것 (전부 라이브 실측 — 여기서 시간 아꼈다)

19:19 커밋 `1b3cef01b`("렌즈 20초 지연 제거 — 비전 선발사 + 이벤트루프 차단 해소")는
**정상적으로 배포돼 있었다.** 아래를 다 확인하고서야 코드로 넘어갔다.

| 의심 | 실측 | 판정 |
|---|---|---|
| 배포 안 됨 | index.html MD5 서버=로컬 `2c412362…` 일치, 22:35 재시작(파일 갱신 이후) | ❌ |
| 키 소진 | `shorts_gemini_state.json` = `{"date":"2026-08-16","exhausted":[]}` → 12/12 생존 | ❌ |
| 재시도 루프 | 85초 걸린 회차도 **키를 1번만** 집음 = 429·재시도 아님 | ❌ |

⚠️ 비로그인 `curl /`는 **19KB 랜딩페이지**를 준다(로그인 게이트, `app.py:6731`).
   그걸로 "배포 안 됐다"고 판정하면 오진이다 — 파일 MD5로 대조할 것.

### 진짜 원인 3개

**① 렌즈가 영상용 무거운 모델을 쓰고 있었다** (주범)

`video_analysis.py`의 `_MODEL = "gemini-3.5-flash"`는 **영상 입력**을 받으려고 무거운
모델인데, 렌즈는 **정지 이미지 1장**만 보낸다. 같은 파일에 있다는 이유로 딸려 썼다.

| | 3.5-flash | 3.1-flash-lite |
|---|---|---|
| 속도 | 26.2초 (3회 평균) | **3.0초** |
| 비용 | 1.0122원/회 | **0.5208원/회** |
| 입력 토큰 | 1,308 | 1,308 (동일) |
| 무료한도 | 하루 **20건**/키 | 하루 **500건**/키 |
| 결과 | 에어프라이어 감자칩 / 空气炸锅薯片 | **동일** |

**② 같은 프레임으로 비전을 2번 불렀다**

`/api/lens/yt` → `cn_search_keyword_vision`
`/api/lens/cn/keywords` → `cn_search_candidates`
→ 그런데 `cn_search_candidates` 응답에 **이미 `product`가 들어있다.**

**③ 단일 왕복이 이따금 통째로 멈췄다**

같은 프레임 6회: `85.1s / 8.9s / 2.1s / 15.0s / 8.9s / 3.2s`
85초짜리도 키를 1번만 집었다 = **재시도가 아니라 호출 자체가 멈춘 것**.
SDK 기본값이 무한대기라 사장님은 그걸 그대로 기다리고 있었다.

### 고친 것 (전부 `shopping_shorts/video_analysis.py`)

- `_LENS_MODEL = "gemini-3.1-flash-lite"` 신설 — 영상용 `_MODEL`과 **분리**
  (`_TRANSLATE_MODEL`이 같은 이유로 이미 분리돼 있던 선례를 따름)
- 프레임 해시 캐시(TTL 180초) — `cn_search_candidates`가 채우고
  `cn_search_keyword_vision`이 읽는다 → 비전 호출 2회 → **1회**
  - 키 만드는 곳은 `_frame_cache_key()` **한 함수뿐** (캐시키 불일치 함정 차단)
  - `exclude`(🔄 다른 검색어) 요청과 빈 결과는 **저장 안 함**
- `_LENS_TIMEOUT_S`(기본 20초, env `LENS_VISION_TIMEOUT`) + `_is_timeout_error()`
  - 타임아웃이면 **다른 키로 즉시 재시도**(sleep 없이). 안 그러면 조용한 빈 값이 된다
  - ⚠️ google-genai `HttpOptions.timeout`은 **밀리초**다

### 검증 (라이브 Gemini 실호출)

```
① 렌즈 모델 = gemini-3.1-flash-lite  (영상용 _MODEL = gemini-3.5-flash 유지)
② cn_search_candidates    : 5.8초  product='에어프라이어 감자칩' cands=4
   cn_search_keyword_vision: 0.0초  ✅ 캐시 적중 — 비전 호출이 실제로 사라짐
③ 타임아웃 1ms 강제 → 0.3초에 복귀 (무한대기 없음)
   판정: httpx.ReadTimeout→True / TimeoutError→True / ValueError→False (오탐 없음)
정상경로 회귀: 2.3초·11.3초 정상, exclude 요청 후 캐시 크기 0
```

**회귀 테스트** `shopping_shorts/tests/test_lens_vision_speed.py` 14개 —
네트워크 안 탄다(가짜 클라이언트). **3건 각각 되돌려서 실제로 빨간불 나는 것 확인**
(가짜 green 아님). 기존 렌즈·비전 테스트 125 passed / 0 failed.

## 2026-08-16 (2차) — 유튜브만 화면을 도배하던 문제

### 발단

사장님 스크린샷: **유튜브 43 / 틱톡 5 / 인스타 1 / 샤오홍슈 0 / 도우인 1**
"유튜브는 쓸데없는 게 너무 많이 뜬다"

### 원인 (코드 실측)

**① 유튜브 검색에 필터가 하나도 없었다** — `youtube_search.py`가
`{part, q, type, maxResults, key}`만 보냈다. 길이·언어 제한이 없어 일반 롱폼·
외국어 영상까지 그대로 딸려왔다.

**② 유튜브만 유사도 채점을 안 받았다** — `app.py:5248`이 `match=None`을 무조건
박았다. 프론트의 '⚠️ 다른주제 숨기기'는 `match!==false`만 거르므로(`index.html:2553`)
**체크박스를 켜도 유튜브는 한 개도 안 걸러졌다.**
샤오홍슈·도우인(`/api/lens/cn/search`)엔 원래 채점이 있었다 →
CLAUDE.md **0순위-B**("같은 일 하는 코드가 갈라지면 언젠가 어긋난다")의 실제 사례.

**③ 40개는 그냥 너무 많았다** — 틱톡 5·인스타 1과 눈높이가 안 맞는다.

### 고친 것

- `youtube_search.search(...)`에 `duration` / `language` **선택 인자** 추가
  → 렌즈는 `duration="short"`(4분 미만) + `language="ko"`로 호출.
  **기본값 None이라 `gap_check` 등 기존 호출부는 동작 불변.**
  API가 공짜로 주는 파라미터 — 쿼터·비용 안 늘어난다(검색 1회 = 100유닛 동일).
- `/api/lens/yt`에 `judge_same_product` 채점 추가 —
  샤오홍슈·도우인과 **같은 함수**를 그대로 쓴다(중복 판정 안 만듦). `same` 우선 정렬.
- 개수 40 → **12**. 프론트(`index.html`)와 서버(`app.py`) **양쪽** —
  서버에서 자르지 않으면 캐시된 옛 화면이 계속 40을 보낸다.

### 실측 — 기대와 달랐던 것도 그대로 적는다

라이브 YouTube A/B (`'피규어 진열'`):

| | 결과 |
|---|---|
| 필터 전후 개수 | **40 → 40** (안 줄어듦) |
| 실제 변화 | **10건 교체** (롱폼 브이로그 → 숏폼) |
| 채점 결과 | `same=40, similar=0, no=0` |

⚠️ **필터는 개수를 안 줄인다** — API가 `maxResults`만큼 채워서 준다. 품질만 오른다.
⚠️ **채점도 이 검색어에선 걸러낼 게 없었다** — 40건이 죄다 진짜 피규어 진열이라
   전부 `same`이 맞다. 채점기 자체는 정상(무관 제목 섞으니 `no` 정확히 판정:
   "코스피 시황"→no, "손흥민 골"→no, 오탐 없음).

→ **사장님이 느낀 "쓸데없다"는 주제가 틀려서가 아니라 양이 많아서였다.**
   실질 해법은 ③(개수 축소)이었다. ①②는 품질·보험.

최종 확인(12개 요청):

```
'피규어 진열' → 12건, 채점 same=8 similar=4, 전부 숏폼·주제 일치
'전세집'      → 12건, 채점 same=12
```

### ⚠️ 남은 약점 — '전세집' 사례

`'전세집'`처럼 **넓은 단어**가 검색어로 나오면 12건이 전부 뉴스·부동산 강의로
채워진다(채점은 `same`이 맞다 — 전세 얘기가 맞으니까). 이건 필터·채점 문제가
아니라 **비전이 뽑은 검색어가 너무 넓은 문제**다. 개선하려면
`_CN_VISION_PROMPT`가 '제품/소재'를 더 좁게 뽑도록 손봐야 한다 —
이번엔 범위 밖이라 안 건드렸다.

### 테스트

`shopping_shorts/tests/test_lens_yt_relevance.py` 9개 신규(네트워크 안 탄다).
개수 상한은 **실제 `/api/lens/yt`를 태워** `youtube_search`가 몇 개로 불렸는지 본다
(숫자 계산을 테스트에 베끼면 가짜 green이 된다).
되돌리기 검증: 필터 제거·파라미터 무시·상한 60 복원 각각 **빨간불 확인**.
기존 `test_app_lens.py::test_lens_yt_returns_youtube_items`는 목 시그니처가
바뀌어 깨졌으므로 갱신 + 채점 케이스 1개 추가. 렌즈 전체 **189 passed, 0 failed**.
