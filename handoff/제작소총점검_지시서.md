04:16:58 worker 작업 완료 qid=1008 task=durfill     ← 정상

아니면 임계 2분이 너무 짧은지 갈라라. 오탐이면 **화면에 가짜 실패가 뜨는 문제**다.

## 7-A. [완료] EDL 빈 원인을 4가지로 갈랐다

`mix_pipeline.py` `_edl_empty_reason()` 신설 + 실패 지점에 배선.
종전 한 문구 → `no_source` / `extract_empty` / `extract_thin` / `plan_empty`.
실측 데이터로 검증:
```
extract 9091자 + plan 0  →  plan_empty   "대본은 9091자 뽑혔는데 편집안(EDL)이 비었습니다
                                          [생성기=scene_first] — Gemini 응답이 비었거나…"
extract 40자             →  extract_thin
전량 빈 문자열           →  extract_empty  "…(키 소진과는 다른 문제)"
소스 0편                 →  no_source
```
로그에도 `[EDL빈원인] code=... sources=N chars=N generator=...`을 남긴다.
**⏭ 남은 일(페이블)**: 이제 원인이 갈리니, `plan_empty`가 실제로 왜 나는지

## 7-C. [완료] 다운로드 실패를 '사람 말'로 번역한다

`mix_pipeline.py _download_fail_hint()` 신설 → 실패 상세에 힌트를 **덧붙인다**(원문 보존).

**★여기서 내가 한 번 틀렸다 — 페이블은 이 함정을 밟지 마라.**
처음엔 `/search_result` 같은 경로를 "영상 주소가 아니다"로 보고 **담기에서 막으려** 했다.
그런데 기존 테스트 `test_grab_accepts_rednote_search_result`가 깨졌고, 읽어보니
**`rednote.com/search_result/<id>`는 정상 담기 경로**였다(한국 로그인 도메인이
rednote.com이라 카드가 거기서 뜬다). 내 차단은 **멀쩡한 기능을 죽이는 것**이었다.

실패 원문을 끝까지 읽으니 진짜 원인이 나왔다:
```
Unsupported URL: https://www.rednote.com/404?source=/404/sec_PukRxsmn&redirectPath=…
                                          ↑ 404로 넘겨졌다
```
= 주소는 정상인데 **그 글이 지워졌거나 로그인벽**에 막힌 것.
→ 막지 말고 **왜 안 됐는지 알려주는 것**이 맞다. 차단 코드는 통째로 되돌렸다.

번역 예(실측 문구로 검증):
```
/404 리다이렉트     → "원본이 지워졌거나 로그인해야 볼 수 있는 글이에요(주소는 정상)"
cookies/browser     → "이 영상은 로그인 쿠키가 있어야 받을 수 있어요"
Video unavailable   → "원본이 삭제됐거나 더 이상 볼 수 없는 영상이에요"
403/Forbidden       → "플랫폼이 접근을 막았어요(지역제한·차단)"
timed out           → "받는 데 너무 오래 걸려 중단됐어요"
모르는 오류         → ""(지어내지 않는다)
```

**교훈(페이블도 지켜라)**: 오류 문구의 **앞부분만 보고 원인을 단정하지 마라.**
"Unsupported URL"만 보면 주소 탓 같지만, 그 뒤 `/404?source=`가 진짜 원인이었다.
그리고 **기존 테스트가 막아섰을 때는 대개 테스트가 옳다** — 지우지 말고 왜 있는지 읽어라.
