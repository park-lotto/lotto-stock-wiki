## 2026-09-03 — ★"파일 손상됨 22개": ffmpeg가 rc=0으로 빈 껍데기를 남긴다

고객 캡컷 화면에 **파일 손상됨 22개**. 전부 `cut_*.mp4`이고 `beat_*.mp3`는 멀쩡했다
(사장님은 "tts라는데"라고 전달받았지만, 화면을 보면 깨진 건 **영상 조각**이다.
음성 트랙 beat_00~04는 파형이 정상으로 그려져 있다).

### 이 한 가지가 원인을 갈랐다 — mp3는 멀쩡, mp4만 전멸
같은 폴더·같은 URL·같은 fetch를 지나는데 한쪽만 깨졌다. 차이는 **만드는 방법**뿐이다:
`beat_*.mp3`는 `shutil.copy`(그대로 복사), `cut_*.mp4`만 `_cut_clip`(ffmpeg 재인코딩).
→ 범인은 네트워크·인증·경로가 아니라 **컷을 만드는 자리**다.

### 범인
```python
return out_path.exists() and out_path.stat().st_size > 0   # ← 크기만 봤다
```
ffmpeg는 **소스 끝 너머를 `-ss`로 잡아도 오류를 안 낸다.** rc=0으로 정상 종료하면서
스트림이 하나도 없는 껍데기 mp4를 남긴다.

실측(로컬 ffmpeg 8.1.2, 5초 소스):
| 요청 | rc | 크기 | 프레임 |
|---|---|---|---|
| `-ss 1` 2초 (정상) | 0 | 53,007바이트 | 60 |
| `-ss 4.5` 2초 (끝에 걸침) | 0 | 21,320바이트 | 15 (0.5초, 정상) |
| **`-ss 20` 2초 (범위 밖)** | **0** | **262바이트** | **없음 / duration=N/A** |

262바이트는 0이 아니라 `size > 0`을 통과했다. 서버는 그걸 **200 OK**로 내보냈고,
09-02에 넣은 프론트 2048바이트 가드도 **못 잡는다** — 조각이 부분적으로 겹쳐 조금만
커지면 문턱을 넘는다. 그래서 캡컷에서야 "파일 손상됨"으로 드러났다.
09-02의 `res.ok`·2048 가드는 **401/404를 막는 것**이라 이 경로와 무관하다(둘 다 필요).

### 고친 것 (`shopping_shorts/export_bundle.py`)
- `_playable()` 신설 — ffprobe로 **화면 스트림이 실제로 있는지** 묻는다.
  ffprobe가 없거나 판정 실패면 **True**(못 가리는 걸 실패로 몰면 멀쩡한 조각까지 버린다)
- `_cut_clip`이 크기 대신 재생 가능 여부로 판정하고, 껍데기면 **파일을 지우고** False.
  남겨두면 캡컷 보관함이 그걸 집어간다. 왜 비었는지 stderr에 사람이 읽게 남긴다
- 호출부는 이미 `if not _cut(...): continue` — 깨진 조각만 빠지고 나머지는 그대로 나간다
- ZIP 내보내기도 같은 `_cut_clip`을 쓰므로 **한 번에 같이 고쳐진다**(0순위-B)

### 검증
| 무엇 | 결과 |
|---|---|
| `test_cut_clip_broken_output.py` 신설 3건 | 고치기 전 1건 실패(True is False) → 고친 뒤 3건 통과 |
| 범위 밖 컷 | False + 파일 삭제 |
| 정상 컷 / 끝에 걸친 부분 컷 | 그대로 통과(0.5초짜리도 살린다) |
| 캡컷 회귀 78건 | 전부 통과 |
| **실제 assemble_draft_folder E2E** | 범위 밖 `cut_01_0_problem.mp4` 제외, 정상 `cut_00_0_hook.mp4`(60프레임)만 보관함 등재, **깨진 파일 0개** |

## 2026-09-02 — ★진짜 원인: 응답 상태를 안 봐서 에러 본문을 mp4로 저장했다

사장님 추가 제보: **"캡컷 가면 폴더만 있고 빈 통이래"** — 이 한마디로 원인이 갈렸다.

```js
const buf = await (await fetch(a.url)).arrayBuffer();   // ← 401·404여도 그냥 진행
```

`fetch`는 401·404에 **예외를 던지지 않는다.** 그래서 에러 본문(24바이트 JSON)을
`cut_00_0_hook.mp4`라는 이름으로 그대로 썼다. 캡컷은 그 파일을 읽지 못하니
**폴더는 있는데 빈 통**이 되고, 우리 화면엔 `✅ 캡컷으로 보냈어요`가 떴다.
69K짜리 00:00 프로젝트도 이걸로 설명된다 — draft JSON + 24바이트 쓰레기 수십 개.

실측: `curl /api/mix/capcut_asset/76665d680876/beat_00.mp3` → **401, 24바이트**.
(비로그인 curl이라 401 자체가 고객 원인이라고 단정하진 못한다. 게이트는 로그인 세션이
있으면 통과시킨다 — 세션 만료·디스크 정리로 인한 404도 같은 증상을 낸다.
어느 쪽이든 **조용히 성공이라 말하던 것**이 버그다.)

### 고친 것
