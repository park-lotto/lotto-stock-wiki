# 영상제작 5·썸네일 — 설계

작성: 2026-07-17 · 상태: 승인 · 트랙: `썸네일`

## 목적

`/produce` 위저드 5단계(현재 스텁 — `produce.html:382` "Phase 4 예정")를 구현한다.
2단계 믹스 결과 영상에서 프레임을 골라 텍스트를 얹어 **1080×1920 PNG 썸네일**을 만든다.

레퍼런스는 쇼핑팩토리의 썸네일 단계(프레임 그리드 → 텍스트 레이어 → 생성 → 결과 갤러리).
레이아웃은 참고하되 아래 결정들은 우리 코드 실측에 근거해 다르게 간다.

## 확정 결정 4건

| # | 결정 | 근거 |
|---|------|------|
| **Q1** | 배경 프레임은 **2단계 믹스 결과 영상**(`mix_jobs.video_path`, 자막 없음)에서 추출 | 썸네일 텍스트는 위에 새로 얹으므로 배경 자막은 방해. 렌더는 7단계라 미리 렌더하면 위저드 흐름이 수분씩 끊긴다 |
| **Q2** | **수동 편집만**. AI 생성은 범위 밖 | 꾸미기에 썸네일형 프리셋 11종이 이미 있어 수동은 배선에 가깝다. AI는 "잘한 썸네일"의 기준이 서야 프롬프트가 나오는데, 그 기준은 수동으로 몇 장 만들어 봐야 드러난다 |
| **Q3** | 합성은 **브라우저 canvas** → PNG 업로드 | 썸네일은 프리뷰 화면 자체가 최종 산출물이라 WYSIWYG가 구조적으로 보장된다. ffmpeg `drawtext`는 **회전이 불가능**(레퍼런스엔 회전 슬라이더 있음). 꾸미기에서 프리뷰(HTML)와 실렌더(freetype)가 어긋난 전례를 반복하지 않는다 |
| **Q4** | **`mix_jobs.thumbnail_json` 컬럼 1개** + 파일은 `data/thumbs/<job_id>/` | 썸네일은 job에 딸린 부속물이지 독립 조회 대상이 아니다. 기존 `headcopy_json`·`clean_video_path`와 동일 패턴(`store.py:254-270`) |

## ★ 설계를 바꾼 실측 — 프레임 추출은 등분이다

기존 `extract_frames()`(`frame_extract.py:21`)는 장면전환 감지(`select='gt(scene,0.3)'`)라
썸네일 후보로 **부적합**하다. 셋 다 코드에 이미 적혀 있는 사실이다.

1. **빈 리스트가 나올 수 있다** — docstring 명시: *"감지된 장면전환이 max_frames보다 적으면
   있는 만큼만 반환(빈 리스트일 수도 있음)"*. 그리드가 0장이 되는 경우가 생긴다.
2. **타임스탬프를 안 돌려준다** — 파일 경로만 반환. 레퍼런스 그리드엔 초 배지가 있다.
3. **한계가 이미 기록돼 있다** — `frame_extract.py:45-48`: *"장면전환 감지는 제품이 잘 보이는지와
   무관하게 화면이 바뀌는 순간을 뽑아서, 얼굴·손·배경 같은 프레임이 섞여 Lens 역검색이
   헛도는 경우가 있었다(2026-07-13)"*. 썸네일 후보로도 같은 이유로 못 쓴다.

그리고 레퍼런스의 프레임 간격은 **정확히 균등**하다:
2.4 / 4.7 / 7.1 / 9.4 / 11.8 / 14.1 / 16.5 / 18.8 / 21.2 / 23.5 (≈2.35초 등간격).
장면전환이 아니라 **등분**이다.

→ **신규 `extract_grid_frames(video_path, dest_dir, n=10)`** → `[(path, ts), ...]`
검증된 `extract_frame_at()`을 등분 시각마다 호출한다. 항상 n장이 나오고, 시각을 우리가
알고 있으니 그리드에 그대로 표시된다. 빈 리스트 케이스가 구조적으로 사라진다.

⚠️ `-ss`에 초를 쓰는 건 결함이 아니다 — ffmpeg엔 `-start_frame`이 없어 seek은 본질적으로
시간 기반이고, 길이를 `-frames:v 1`로 잡으므로 정확하다(장면라이브러리 트랙이 md5 대조로 실증).

## 데이터 흐름

```
mix_jobs.video_path (2단계 믹스 결과, 자막 없음)
  → [서버] 균등 n등분 추출 → data/thumbs/<job_id>/frame_00.jpg … + ts
  → [화면] 프레임 그리드에서 1장 선택
  → [화면] 텍스트 레이어 얹기 → canvas 실시간 합성 (= 최종 픽셀)
  → [화면] "썸네일 생성" → canvas.toBlob(PNG) 업로드
  → [서버] data/thumbs/<job_id>/thumb_<n>.png 저장 + thumbnail_json.results 추가
  → [화면] 결과 갤러리에서 최종 1장 선택 → thumbnail_json.selected
```

## 서버 API

| 엔드포인트 | 역할 | 비고 |
|---|---|---|
| `POST /api/produce/thumb/frames` | `job_id` → 균등 10장 추출, `[{url, ts}]` 반환 | 이미 있으면 재사용(재추출 안 함) |
| `POST /api/produce/thumb/save` | PNG 업로드 → 파일 저장 + `results`에 추가 | 파일명은 서버가 부여(`thumb_<n>.png`) |
| `POST /api/produce/thumb/select` | 최종 1장 지정 → `selected` | |
| `GET /api/produce/thumb/file/{job_id}/{name}` | 프레임·썸네일 파일 서빙 | 기존 `/api/find/frame/` 패턴 |

**보안**: `job_id`는 uuid, 파일명은 서버가 부여하거나 `os.path.basename`으로 강제한다.
클라이언트가 준 경로를 그대로 쓰지 않는다(모션효과 트랙 Task5에서 `videoSrc` 경로순회로
임의파일 덮어쓰기가 잡힌 전례 — 같은 구멍을 만들지 않는다).

## 저장 스키마

`mix_jobs`에 `thumbnail_json TEXT` 컬럼 추가(기존 행은 NULL = 하위호환).

```json
{
  "frame_ts": 4.7,
  "layers": [
    {"text": "요즘 강남언니들", "font": "TmonMonsori.ttf", "size": 124,
     "color": "#FFE100", "outline": {"color": "#000000", "w": 4},
     "box": null, "rot": 0, "x": 0.5, "y": 0.18}
  ],
  "results": ["thumb_1.png", "thumb_2.png"],
  "selected": "thumb_2.png"
}
```

**좌표는 비율(0~1)로 저장한다.** 미리보기가 270px든 실제가 1080px든 같은 자리에 찍힌다.
크기(`size`)도 1080 기준 px로 두고 미리보기에서 배율만 곱한다.

⚠️ **레퍼런스의 쿠키런 폰트는 우리에게 없다**(실측: `static/fonts/` 22종에 미포함).
화면을 그대로 베끼지 말 것 — 우리 폰트로 대응한다(임팩트체 = `TmonMonsori.ttf`,
`BMJUA.ttf`, `BMDOHYEON.ttf`).

**재사용**: 꾸미기의 폰트 드롭다운(hover 실시간 프리뷰, 22종), **썸네일형 프리셋 11종**
(`produce.html:969-979` — 화이트 임팩트/옐로 팝/블랙박스 화이트 등), `나의 프리셋`
localStorage 방식.

**출력 규격**: 1080×1920 PNG. 미리보기는 축소 표시하되 canvas는 실측 해상도로 그려
업로드한다(별도 canvas 2개가 아니라, 하나를 CSS로 축소 표시).
