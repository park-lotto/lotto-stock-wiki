# 자막싱크 2단계 — 제작소 음성 프리뷰 (화면·딸깍) 설계

**날짜**: 2026-07-18 · **트랙**: 자막싱크 (`track/자막싱크`) · **BASE**: origin/main(422a00a8, 1단계 병합 뒤)

## 한 줄

제작소 **3단계(TTS)**에서 "이 음성으로 전체 생성" 뒤, 지금 밋밋한 음성 재생바(`#ttsBeats`)를
**음성 프리뷰**로 바꾼다 — 비트별 **프레임+실음성+자막을 같이** 재생해 ① TTS가 대본을 **자연스럽게
읽나** ② 자막이 음성과 **맞나** 를 여기서 확인하고, 이상하면 **딸깍**으로 고쳐 **뒤 단계에서 되돌아오지
않게** 한다.

## 문제

- 지금 TTS 단계는 (a) 위쪽 성우 **샘플**(6초, 내 대본 아님) 고르기 + (b) "전체 생성" 후 `#ttsBeats`에
  **비트별 음성 재생바만** 뜬다. **자막도 화면도 안 보이고, "자연스럽나·맞나"를 확인할 방법이 없다.**
- 그래서 사장님은 꾸미기·썸네일·SEO·최종렌더까지 다 한 뒤에야 이상을 발견하고 **처음으로 되돌아온다**.
  이 프리뷰는 **일 벌이기 전에 거르는 관문**이다.

## 목표 / 비목표

**목표**
1. "전체 생성"으로 만든 **실제 대본 음성**을, 비트별 프레임+자막과 **같이 재생**해 확인.
2. **자연스러움**(귀)과 **자막 싱크**(눈)를 한 화면에서. 이상하면 **딸깍**으로 그 자리에서 교정.
3. **프리뷰 = 최종 영상과 같은 값**(WYSIWYG) — 여기서 OK면 완성본도 OK.

**비목표(YAGNI / 다음 파도)**
- 구절 하나씩 미세 타이밍 조정(비트 통째 ±0.1초로 시작).
- 새 단계 추가(3단계 안에서 완성 — 시니어 혼란 방지).
- 성우를 비트마다 다르게(성우 변경은 **전체 재생성**으로만 = 목소리 일관성).
- 새 렌더 경로(기존 `assemble`/`_burn_captions` 단일 경로 유지 — 1단계 seam 원칙 연장).

## 핵심 원칙 — 프리뷰 = 최종 (두 번 일 방지의 뿌리)

브라우저 프리뷰의 자막은 **최종 ffmpeg 자막(`_caption_drawtexts`)과 같은 값으로** 그려야 한다:
- **같은 구절 분할** = `_caption_segments(narration)` 결과.
- **같은 타이밍** = 그 비트의 `cap_durs`(1단계가 넣음) + 수동 보정값(아래 §D).
- **같은 위치·줄바꿈** = 자막바 하단 고정, `_CAP_WRAP` 폭.
안 맞으면 "프리뷰선 좋았는데 완성본이 다름" = 최악의 재작업. **이게 스펙의 하드 요구.**

## 아키텍처

### A. 자리·데이터 원천 (전부 기존, 새 라우트 최소)
- **자리**: 3단계 `#ttsBeats`(produce.html) — "전체 생성"(`applyVoice`) 완료 후 렌더.
- **프레임**: 기존 `GET /api/produce/mix/beatframe/{job}/{i}` (JPG).
- **음성**: 기존 `GET /api/mix/tts/{job}/{beat_idx}` (mp3).
- **비트 데이터**: 기존 `GET /api/mix/result/{job}` — 이미 비트별 `narration`·`cap_durs`·`tts_preview_url`
  통째로 내려줌. **프론트가 여기서 다 읽는다**(새 조회 라우트 불필요).
- **신규 라우트 2개만**:
  - `POST /api/mix/tts/{job}/{beat_idx}/regen` — 그 비트만 **톤 바꿔 재생성** → 재합성 → **1단계
    재동기(ASR→cap_durs 갱신)** → 갱신된 비트 반환. (성우 전체 재생성은 기존 `applyVoice` 재사용.)
  - `POST /api/mix/caption_offset/{job}/{beat_idx}` — 그 비트 자막 **수동 보정값(±초)** 저장.

### B. 자막 싱크 상태 (🟢/🟡) — 정직하게 "싱크 자신도"만
- `cap_durs`가 **있으면 🟢맞음**(ASR로 실음성에 맞춤), **없으면 🟡불확실**(글자수 폴백).
- ⚠️ **음성이 어색한지는 시스템이 모른다**(사람 귀만). 🟡는 자막 힌트일 뿐 — 자연스러움은 전체 재생으로.
  화면 문구도 "🟡 = 자막 자동맞춤 불확실(들어보세요)"로 정직히.

### C. 재생 (자연스러움 확인의 주 도구)
- **▶ 전체 재생**: 비트 순서대로 프레임 자동 전환 + 그 비트 음성 재생 + 자막 구절이 말에 맞춰 켜짐
  (노래방). 완성본 미리 보는 느낌 → **이어 들어야 잡히는 어색함**을 잡는다.
- 비트 목록에서 아무 비트나 눌러 그 지점으로 점프(개별 ▶도 제공).
- 자막 켜짐 타이밍 = 그 비트 `cap_durs`(+보정값)를 **초 단위로** 계산해 JS 타이머로 구절 표시.
  같은 `_caption_segments` 분할을 프론트도 써야 함(§E).

### D. 딸깍 교정 (지금 보는 비트에 대해)
1. **자막 당기기 / 밀기** = 그 비트 자막 **통째 ±0.1초** 이동. 누를 때마다 미리보기 즉시 반영.
   저장 = `POST caption_offset` → 비트에 `cap_offset`(초, 기본 0) 저장.
   **↩︎ 되돌리기** = `cap_offset=0`(자동값 복귀).
2. **🔁 톤 바꿔 다시**(드롭다운: 안정·자연·표현·속삭임) = `POST regen` → 그 비트만 재생성 +
   **자막 재동기**(새 음성으로 cap_durs 다시). 예상 차감(그 비트 글자 수) 표시.
3. **🔁 성우 바꿔 전체 다시** = 위쪽 성우 바꿔 기존 `applyVoice` 재호출(영상 전체). 예상 차감(총 글자 수) 표시.

### E. 최종 렌더가 보정값을 읽는다 (seam)
- `cap_offset`는 비트에 저장(edit_plan_json) → `_beat_timeline`이 실어 나름 → `_burn_captions`/
  `_caption_drawtexts`가 **자막 시작 시각에 +cap_offset** 적용. **저장=읽기**, 프리뷰·최종 같은 값.
- `cap_offset` 없으면(기본 0) 1단계 동작과 **바이트 동일**(회귀 0).
- ⚠️ 프론트 자막 분할은 반드시 `_caption_segments`와 **같은 규칙**이어야 한다(포팅 or 서버가 구절
  리스트를 `/api/mix/result`에 함께 내려주기 — **후자 채택**: 서버가 진실의 원천, 프론트 재구현 안 함).
  → `/api/mix/result`의 각 비트에 `cap_segments`(구절 문자열 리스트) 추가.

### F. 게이트 (되돌아오지 않게)
- "다음 단계(꾸미기)" 누를 때 **안 들어본 🟡가 남아 있으면** 한 번만 부드럽게 확인
  ("🟡 N개 아직 안 들어봤어요. 그냥 갈까요?"). **막지 않음**(시니어가 갇히지 않게).
- "들어봤다" = 그 비트를 한 번 재생함(프론트 로컬 플래그).

## 회귀·안전
- `cap_offset` 미설정/키 없음 → 1단계와 **바이트 동일**(테스트로 잠금).
- `regen` 실패 → 기존 음성·cap_durs 유지(그 비트 안 망가짐).
- 새 렌더 경로 없음 — `assemble`/`_burn_captions` 단일 경로에 `cap_offset`만 더함.
- produce.html은 4트랙 동시편집 → **`#ttsBeats` 블록 + 신규 함수/라우트로만** 국한.

## 테스트
1. **cap_offset seam**: 저장한 offset이 `_beat_timeline`→`_caption_drawtexts` 자막 시각에 반영
   (저장≠읽기면 실패). offset 0 = 1단계 바이트 동일.
2. **regen 재동기**: 톤 재생성 후 그 비트 `cap_durs`가 **새 음성 기준으로** 갱신되는지(옛 값 잔류=실패).
3. **cap_segments 일치**: `/api/mix/result`가 내려주는 구절 리스트가 `_caption_segments(narration)`와 동일.
4. **🟢/🟡 판정**: `cap_durs` 유무로만 색이 갈리는지.
5. **게이트**: 안 들어본 🟡 있으면 확인 1회, 없으면 바로 통과.
6. **프론트 JS**: showBeat에 오디오+구절 타이머 얹어도 기존 프레임/자막 전환 안 깨짐(회귀).

## 미확정(구현 때 확정, 임의단정 금지)
- 노래방 구절 켜짐을 `cap_durs`로 계산할 때 오디오 `currentTime`과의 동기 방식(오디오 timeupdate 기준).
- `regen`의 재동기가 서버에서 동기(응답 지연) vs 비동기 폴링 — 그 비트 재생성 시간에 따라 결정.
- 로컬 GROQ/ElevenLabs 키 0개 → regen·재동기 **실경로는 서버에서만 관측**(1단계와 같은 한계).
