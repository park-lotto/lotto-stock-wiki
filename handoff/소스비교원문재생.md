# 소스비교원문재생 — 핸드오프

## 2026-08-17 (회사PC) — 제작소 1단계 담은 영상 "그 자리 재생"

### 무엇을·왜

사장님 요청 2건:
1. "여기 페이지에서도 썸네일 누르면 그 상태에서 미리보기 재생이 될 수 있게"
   (제작소 **1단계 · 영상추출/분석**의 `🎬 담은 영상` 그리드 = `#poolList`)
2. "**레퍼런스 페이지 영상들 재생이랑 똑같은방식**"

→ 오버레이를 띄우는 게 아니라 **썸네일 칸 안에서 `<img>`를 `<video>`로 교체**해
   화면을 안 떠나고 재생한다(= 레퍼런스 랭킹 `/` = `index.html`의 `playInline` 방식).

### 클릭이 겹치는 문제 — ▶ 배지로 갈랐다

`#poolList` 카드 클릭은 이미 `pickFootage(i)`(AI PICK 메인 지정)가 쓰고 있었다.
썸네일 클릭을 재생으로 바꾸면 그 기능이 죽는다 → 사장님 확인 후 **▶ 배지 추가** 선택:

```
카드 본체 클릭  = pickFootage (종전 그대로)
▶ 배지 클릭     = poolPlay    (stopPropagation)
```

아래 `🔎 담은 영상 뜯어보기` 카드(`.cmp-card`)가 이미 같은 관례(`.cmp-play` ▶ +
`previewMaterial`)를 쓰고 있어 조작이 일관된다. 단 저쪽은 **오버레이**,
이쪽은 **인라인**이다(사장님이 인라인을 지정).

### 재생 3단 — 랭킹·렌즈가 실사용으로 정정한 순서를 그대로 따랐다

| 순서 | 조건 | 경로 | 왜 |
|---|---|---|---|
| ① | `play_url` 있음 | `/api/video` 프록시 | CDN이 리퍼러·IP를 따져 직접재생 차단 |
| ② | 틱톡 | **`/api/play`** | `/api/media`가 준 mp4를 서버가 재요청하면 403(IP·세션 바인딩, 2026-08-17 렌즈 실측). 직접재생도 프록시도 안 된다 |
| ③ | 그 외 | `/api/media` → **직접** 재생 | ★프록시를 무조건 씌우면 안 된다 |
| 폴백 | mp4 실패 | 유튜브·틱톡 = embed(iframe) / 그 외 = 안내+원본링크 → 4초 뒤 ▶ 복구 | |

**★③이 핵심 함정**: `/api/video`는 화이트리스트(`app.py:4964 _ALLOWED_VIDEO_HOSTS`
= 인스타·틱톡·도우인만)라 **유튜브(googlevideo.com)를 400 "invalid host"로 통째로
막는다**. 처음에 무조건 프록시를 씌웠다가 이걸 발견했다. 랭킹도 같은 이유로
`_playViaMedia(viaProxy 기본 false)`로 직접 재생한다.

### ★내가 만들었다가 실측으로 잡은 버그 — 썸네일 없는 항목

`renderPool`은 `thumbnail`이 빈 항목에 `<img>`를 **아예 안 그린다**. 그런데
`poolPlay`가 `const img = card.querySelector('img'); if(!img) return;`으로 img를
필수로 잡아 → **조용히 아무 일도 안 일어났다**(배지만 사라지고 끝).

**URL 직접 추가로 담은 영상이 정확히 그 모양이다**(`confirmMixUrls`가
`thumbnail:''`로 push). 브라우저 실측이 아니었으면 못 잡았다 —
"video 태그가 생겼나"만 봤어도 놓쳤고, `videoMade:false`가 나와서 드러났다.

→ 교체 대상을 `put()`으로 뽑았다: img 있으면 그 자리, 없으면 카드 맨 앞에 삽입.
   `_poolFallback`도 같은 이유로 `el`이 null일 수 있어 `el.replaceWith` 직접 호출을
   버렸다(TypeError로 죽는다).

유튜브 mp4 실패           → embed iframe 폴백 확인

상대경로(`/__pptest.mp4`)를 넣어 화이트리스트에 걸린 것. 직접 200 / 프록시 400으로
