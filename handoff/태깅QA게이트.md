# 태깅QA게이트 — handoff

## 왜 하는 일인가

`script_extract`는 Gemini가 준 태깅을 **스키마만 통과하면 무조건 채택**했다. 프롬프트엔
실사고로 쌓인 지침이 많은데(0초 훅 강제·받아쓰기·오인 금지·change/is_key/shot_role)
그게 지켜졌는지 확인하는 코드가 한 줄도 없었다. 슬롯 기반 화면조합(대본퀄v3)이 이 태깅
위에 전부 서 있으므로, 여기가 틀리면 위층이 아무리 정교해도 결과물이 나쁘다.

설계 전문(3층 구조): `scratchpad/태깅QA게이트_솔루션설계_2026-08-01.md`
※ scratchpad는 세션 임시폴더다 — 내용이 필요하면 아래 요약으로 충분하다.

## 📏 기준선 규칙 — ★다음 세션이 제일 먼저 읽을 것

**이걸 어기면 다음 측정이 통째로 무의미해진다.** 코드 머리말(`tools/tag_audit.py`)에도
같은 내용이 박혀 있다.

1. **기준선은 서버 DB로 잡는다** (`ubuntu@3.39.179.148:/home/ubuntu/lotto-stock-wiki`).
   회사PC·집PC 로컬 DB는 데이터가 달라 숫자가 다르다. 한 번 서버로 잡았으면 **이후 측정도
   계속 서버에서**. 로컬 값을 서버 기준선과 비교하지 마라 — 개선/악화가 아니라 딴 표본이다.
2. **코호트 A와 B를 섞지 마라.** 점수 체계가 다르다:
   - **A** = `tag_qa`가 결과에 박힌 것(Layer 1 배포 후). 영상 길이를 알고 매긴
     **커버리지 포함** 점수. → **이게 진짜 기준선이다.**
   - **B** = 레거시(배포 전). DB엔 영상이 없어 재계산할 수밖에 없는데, `validate_extract`는
     duration이 None이면 **커버리지 검사(가중 0.20)를 건너뛴다**(`tag_qa.py:48` fail-open).
     그래서 **최대 0.20 후하게** 나온다. 실측 데모에서 B는 평균 1.0이 떴다.
   → 도구는 절대 안 합치지만, **사람이 보고서를 쓸 때 합치는 실수**를 조심해라.
3. 출력 머리말의 `측정 기준` 4줄(DB경로·DB갱신·측정시각·표본수)을 **숫자와 함께 남겨라.**
   "이 숫자 어느 DB였지?"가 되면 그 기준선은 버리는 수밖에 없다.
4. **A가 0건이면 그 회차는 기준선이 아니다.** Layer 1 배포 후 추출된 영상이 아직 없다는
   뜻이라, 영상 몇 건을 새로 담아 추출을 태운 뒤 다시 돌려야 한다(도구가 경고를 띄운다).
5. **필드 도입일보다 오래된 행은 그 검사에서 자동 감점된다.** 최빈 flags가 갑자기 한 항목으로
   쏠리면 라이브 결함으로 단정하기 전에 `extracted_at`으로 갈라봐라 — 첫 측정에서 실제로
   'change 전멸 41/50(82%)'이 떴는데, `change`는 **07-31 도입** 필드라 40건은 그냥 옛 행이었다
   (도입 후인 07-31만 보면 7/10=70% 충족). 표본을 최근순으로 뽑아도 이 함정은 안 사라진다.

```
서버:  cd /home/ubuntu/lotto-stock-wiki && python3 tools/tag_audit.py --n 50
```

## ✅ 완료 (2026-08-01, 이어서) — 저장 누락 수정 + 관측성

**A코호트가 영원히 0건이 될 뻔한 구멍을 막았다.** `_attach_qa`가 tag_qa를 붙여도 저장부가
`{"full_text":…, "segments":…}`를 손으로 다시 만들어 **저장 순간 버리고 있었다**. 검사 코드는
멀쩡한데 결과가 안 쌓이는, 눈에 안 띄는 종류의 구멍이다.

- **`script_extract.storable()` 신설** — DB에 남길 필드 화이트리스트(`full_text`/`segments`/
  `tag_qa`). 저장부가 각자 dict를 만들던 구조 자체가 재발 원인이라 한 곳으로 모았다.
  새 필드는 여기 한 줄만 추가하면 전 경로에 반영된다.
- **저장부 3곳 교체**: `prewarm.py`(담기 예열 = 라이브 주경로) / `app.py` 도서관 저장
  캐시미스 분기 / `app.py` 자동적재 캐시미스 분기.
- **읽기 전용 3곳은 안 건드렸다**(실측으로 갈랐다): `app.py` 1829(캐시히트 분기엔 save_script
  호출 자체가 없다) · 6548(소스 빌더, DB 미기록) · 6747(자동적재 캐시히트, save_script
  플래그를 안 세운다). **되쓰지 않으므로 tag_qa를 덮어쓰지 않는다.**
- **관측성**: `prewarm._log_tag_qa` — `tag_qa {shortcode}: 0.82 (재시도 X, flags: …)` 한 줄.
  로그 실패가 예열을 죽이지 않게 통째로 감쌌다(예열은 보조작업).
- **재발 차단**: `test_tag_qa_persist.py` 5건. 마지막 1건은 AST로 소스를 훑어 **'그 두 키만 든
  축약 dict'가 새로 생기면 실패**시킨다(허용 3곳은 근거와 함께 목록화). 실제 회귀를 주입해
  fail → 원복해 pass까지 확인했다(가드가 무는지 실측).
- 관련 스위트 35건 green. `test_mix_pipeline::test_voice_params_extracts_pace_mode` 1건 실패는
  **기준선**(내 변경을 stash한 상태에서도 동일하게 실패 — 대조 확인).

⚠️ `product_benefits`(추출 결과 최상위)는 storable에 안 넣었다 — **종전 저장부도 안 담고
