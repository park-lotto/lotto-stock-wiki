### ① 고객 찾기가 "풀로 다 쳐야" 걸린다 → 몇 자만 쳐도

- 파일: `shopping_shorts/static/admin.html` (`_subseq` / `_custMatch`)
- 기존: `hay.indexOf(q)` 한 방 → 이메일을 **연속으로 정확히** 다 쳐야 나옴
- 지금: 글자 **순서만** 맞으면 걸리는 퍼지 매칭
  - `the` / `tbk` / `black001` → `theblackart001@gmail.com`
  - 전화는 숫자만 남긴 형태도 봐서 `01012345678` 로 쳐도 걸림
- ★**한 칸(필드) 안에서만** 순서를 잇는다. 이름·이메일을 가로질러 이어붙이면
  `sdw` 같은 입력에 무관한 고객이 우수수 걸린다. 칸을 합쳐 검색하면 그렇게 된다.
- 공백으로 띄어 치면 조각마다 각각 어느 칸에든 걸려야 통과(AND).

### ② 가입할 때 이름·전화 받기

**진짜 원인은 가입폼이 아니라 구글 로그인이었다.** 폼엔 이미 이름·전화 칸이
있었는데(필수가 아니었을 뿐), `get_or_create_by_google`이 email만 넘겨서
구글 가입은 이름·전화가 **아예 안 들어온다** → 179명 대부분이 빈칸이었다.

- 새 컬럼 `customers.welcome_due` (기본 0)
  - 구글 신규가입 / 아이디 가입을 빈칸으로 낸 경우에만 1
  - ★**기본이 0이라 기존 고객은 화면이 안 바뀐다**(갑자기 안 붙잡힌다)
- `/welcome` — 이름·전화 입력 화면(전화 자동 하이픈). 미들웨어가 대기실보다 **먼저** 보낸다
  - ⚠️ `/welcome`·`/api/welcome`은 **pending 게이트도 통과**시켜야 한다.
    안 그러면 위에서 /welcome으로 보내놓고 아래 pending이 대기실 HTML을 돌려줘
    **입력칸이 영영 안 보인다**(실측으로 잡음)
- 아이디 가입폼: 이름·전화 `required` + **서버에서도 검증**(required는 브라우저 힌트일 뿐)
- 저장은 관리자 '정보수정'과 **같은 `update_customer_info` 재사용**(0순위-B)
