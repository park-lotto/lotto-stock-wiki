층을 갈라 확인한 결과:

| 층 | 결과 |
|---|---|
| 서버에서 `fetch_profiles(['momo.ring._','sua_play'])` | `{}` (빈 dict) |
| 프로필 페이지 graphql 응답 | **0건 캡처** |

**로그아웃**돼 프로필 페이지가 로그인 선택 화면으로 떨어졌고, 인스타가 부르는
user graphql이 아예 안 나가 팔로워 캡처가 0건이 됐다.

A/B 실측 — 같은 계정 파일만 바꿔 대조:

```
/home/ubuntu/instagram_session.json   → 캡처 실패 (계정선택 화면)  ← 구 코드가 쓰던 것
ig_sessions/36259840846.json          → follower_count 1,846 정상
ig_sessions/37488247878.json          → follower_count 1,846 정상
ig_sessions/41170560843.json          → 실패(로그아웃)
```

⚠️ **발굴이 실제로 쓰는 계정은 위 3개가 아니다.** `_discover_session_proxy()`는
`POOL_REFERENCE`(=`ig_sessions/reference/`) 하위만 본다 — 실측:

```
slots: ['/home/ubuntu/ig_sessions/reference/46434153567.json']   (1개뿐)
proxy: bhkvcxfo-kr-11@p.webshare.io  (reference 풀 오프셋 10 + 1)
```

즉 상위 폴더의 3계정은 아카이브·수집용이고, 발굴은 **reference 풀의 단일 계정**을
돈다. 그래서 이 계정이 죽으면 발굴 팔로워가 통째로 빈다(슬롯이 1개라 대체가 없다).
