# 도서관 → 영상제작소 다리 설계

**트랙**: 대본믹스통합 · **날짜**: 2026-07-15 · **상태**: 사용자 승인됨

## 1. 문제

도서관(`library.html`)에서 구조분석·생성·디벨롭으로 대본을 만들어놓고도, 제작소로 가져갈 길이 없다.
지금은 **📋 복사 버튼으로 사장님이 손수 옮겨야** 한다.

카드에 `🎬 영상제작으로 보내기`(`sendToProduce`)가 있긴 하나 **"담기"만 하고 이동하지 않는다**
(`/api/produce/picks/toggle` → picks 목록에 추가). 그래서 제작소에 들어가 "📥 담긴 대본" 탭에서
다시 골라야 한다 — 사장님 지적: *"제작소 안에 들어가야만 위키목록에서 2개 선택 가능"*.

반면 즐겨찾기(`collection.html`)는 `sessionStorage` + `location.href='/produce'`로 **바로 넘긴다**.
이 검증된 방식을 도서관에도 적용한다.

## 2. 만드는 것 (3가지)

### ① 초안 → 제작소 (구조 동반)
`library.html` 초안 카드에 **"🎬 이 대본으로 영상 만들기"** 버튼(현재 `📋 복사`만 있음).

클릭 시:
1. 초안 텍스트를 **구조분석 1회**(`analyze_structure`) — 사용자 결정: 원본 구조 재사용이 아니라 **초안 재분석**.
   *근거*: 초안은 요소별 유지/변형으로 만들어져 원본과 다르다(주변인물을 "요리 고수 언니"로 바꿔 생성했다면
   원본 구조의 주변인물과 어긋남). 뒷단계가 틀린 구조를 쓰면 안 된다. Gemini 1회(수 초) 비용은 감수.
2. `sessionStorage`에 `{handoff, script, script_structure}` 저장
3. `location.href='/produce'`

제작소는 **확정 대본이 이미 꽂힌 상태**로 열린다.

### ② 원본 영상 동반
버튼 옆 체크박스 **"원본 영상도 화면에 쓰기"**(기본 ON).
켜져 있으면 그 카드의 원본 영상이 재료풀에 **🎬담김(`useFootage=true`)** 상태로 함께 넘어간다.

### ③ 도서관 카드 체크 2개 → 영상믹스
도서관 카드에 체크박스 + 상단에 **"🧬 선택 N개로 영상믹스"** 버튼.
고른 영상들이 재료풀에 `useFootage=true`로 담긴 채 제작소로 이동
(제작소가 이미 "1개=순서편집 · 2개+=믹스"를 판별하므로 별도 분기 불필요).

## 3. 구조의 종착지 — **다리만** (사용자 결정)

구조를 제작소까지 옮기고 **MIX job에 실어 보관**한다. 뒷단계(TTS·자막·꾸미기·모션)가 꺼내 쓰는 배선은
**각 트랙이 나중에** 한다.

*근거*: `edit_plan.py`는 지금 보이스·모션효과 트랙이 동시 편집 중이라, 여기서 role 고정까지 하면 충돌이 크다.
구조는 DB에 남으니 나중에 붙여도 버려지는 작업이 없다.

### ⚠️ 최대 함정 — `structure` 이름 충돌 (반드시 지킬 것)

**기존 `structure`는 구조분석 dict가 아니다.** 전부 확인함:
- `edit_plan.build_edit_plan(structure="template")` → `_TEMPLATE_INSTR if structure == "template" else _FREE_INSTR`
  = **템플릿/자유 모드를 고르는 플래그(문자열)**
- `mix_jobs.structure TEXT NOT NULL` → 같은 플래그
- `store.create_mix_job(job_id, urls, target_seconds, structure, ...)` → 같은 플래그

여기에 구조분석 dict(`hook_type`·`hook_line`·`narrator`·`characters`·`storyline`·`tone`·`beats`·`devices`)를
넣으면 **template/free 분기가 조용히 깨진다.**

→ **새 이름을 쓴다**: `script_structure`(프론트/`sessionStorage`/API body), `script_structure_json`(DB 컬럼 신규).
기존 `structure`는 **읽지도 쓰지도 않는다.**

## 4. 데이터 흐름

```
[library.html 초안]
  "🎬 이 대본으로 영상 만들기" 클릭
        ↓ (초안 텍스트)
  POST /api/wiki/draft/analyze   ← 신규. 초안 → 구조분석 dict
        ↓
  sessionStorage:
    produce_handoff      = [{url, shortcode, name, thumbnail, caption, useFootage:true}]  ← ②가 켜졌을 때만
    produce_script       = "초안 텍스트"
    produce_script_struct= {구조분석 dict}
        ↓ location.href='/produce'
[produce.html loadHandoff()]
  STATE.script = produce_script          → 확정 대본 칸에 꽂힘
  STATE.script_structure = produce_script_struct
  HANDOFF = produce_handoff (useFootage 유지)
        ↓ "🎬 영상 매칭 시작"
  POST /api/produce/mix/start  body에 script_structure 추가
        ↓
  store.create_mix_job(..., script_structure=…)  → mix_jobs.script_structure_json
        ↓
  (뒷단계가 꺼내 쓰는 배선 = 후속 트랙)
```

## 6. 재사용 (새로 만들지 않는다)

- **핸드오프**: 즐겨찾기의 `sessionStorage`(`produce_handoff`) 방식 그대로. `loadHandoff`는 이미
  "1순위 신규 핸드오프 / 2순위 작업상태 복원" 구조라 키 2개만 더 읽으면 된다.
- **구조분석**: `structure_analyze.analyze_structure` 기존 것.
- **캐시**: 초안 구조는 `script_drafts`에 draft_id가 있으니 거기 붙일지, 매번 분석할지는 구현 시 판단
  (초안은 편집·재생성되므로 캐시가 stale될 수 있음 — 단순함을 우선해 매번 분석해도 무방).
- **picks(`sendToProduce`)**: 그대로 둔다. "담아두기"는 이동과 다른 용도라 공존.

## 7. 에러 처리

- 구조분석 실패(Gemini 키 소진 등) → **대본만 넘기고 구조는 null**. 이동 자체를 막지 않는다.
  (오늘 C-1 교훈: 대본을 잃는 게 최악. 구조는 있으면 좋은 것.)
- 원본 영상 URL 만료 → 재료풀엔 들어가되 제작소에서 실패 메시지(기존 동작).
- ③에서 0개 선택 후 클릭 → 안내만.

## 8. 테스트

- `POST /api/wiki/draft/analyze`: 텍스트 → 구조 dict 반환 / Gemini 실패 시 `structure=null`이어도 200
- `create_mix_job(script_structure=…)` → `mix_jobs.script_structure_json`에 저장, **기존 `structure` 컬럼 불변**(회귀가드)
- `api_produce_mix_start`가 body의 `script_structure`를 job에 전달
- 프론트: `loadHandoff`가 `produce_script`/`produce_script_struct`를 복원하는 회귀 테스트

## 9. Grounding (실렌더 검증 — 정적 점검 불가)

라이브에서 **실제 경로**로:
1. 도서관 초안에서 "이 대본으로 영상 만들기" → 제작소가 확정 대본 꽂힌 채 열리는지
2. "원본 영상도" 켠 경우 재료풀에 🎬담김으로 들어오는지
3. 카드 2개 체크 → 믹스로 넘어가 "화면 2개 담김(믹스)"이 뜨는지
4. MIX 시작 후 서버 DB에서 `mix_jobs.script_structure_json`에 구조가 실제로 들어갔는지
5. **기존 `structure` 컬럼이 여전히 template/free 플래그인지**(이름 충돌 회귀가드)

⚠️ 가짜 데이터로 검증 금지. 오늘 이 트랙에서 가짜 핸드오프로 검증해 배선 버그를 통째로 놓친 전례가 있다.

- 도서관 UI 재설계
- 구조 뷰어/편집기
