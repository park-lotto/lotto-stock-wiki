트랙(작업 폴더)에서 만든 코드가 고객 사이트에 올라가기까지의 길. 2026-10-15 기준 실측.

1. 큰 그림 — 4단계

각자 동시에① 합쳐보기임시 폴더에 내 코드 + 최신 main 을 합친다
→
각자 동시에② 관문 검사시험(pytest) · 관제 검사 · 영상/캡컷/소리 대조
→
한 줄로③ main 에 올리기커밋 + push, 몇 초. 한 번에 하나만
→
서버④ 라이브 반영서버가 3분마다 받아감 → 웹 재시작
핵심: 오래 걸리는 ①②는 트랙마다 동시에 해두고, ③만 줄을 선다. 사장님이 말씀하신 "내 할 일까지 해두고 기다리기"가 원래 설계다.

2. 그런데 왜 오래 걸렸나

문제 A — 줄 섰더니 남이 먼저 들어가 있으면, 해둔 검사를 버리고 처음부터

②를 끝내고 ③에 섰는데 그사이 다른 트랙 코드가 main 에 들어갔다면, "그 코드와 같이 돌려도 괜찮나" 다시 재야 한다. 그런데 내 파일과 전혀 상관없어도 시험 전체(약 20분)를 다시 돌았다.

실측: finish 165건 중 재시험 83회 · 다시 돈 시험 약 700분

문제 B — 시험 자리가 모자라 멍하니 대기

PC 메모리 때문에 시험은 동시에 몇 개만 돌 수 있다. 재시험하는 트랙은 줄 맨 뒤로 다시 섰고, 같은 트랙을 두 번 거는 일(오늘 2건)도 자리를 이중으로 차지했다.

실측: 최근 3일 전체 시간의 33%(712분)가 이 대기

문제 C — 라이브 반영이 새벽으로 미뤄짐

서버는 낮에 받은 코드를 새벽 2~6시에 반영하도록 돼 있다. 낮에 바로 올리려면 즉시배포 표시(DEPLOY_NOW)가 필요하고, 그래도 고객이 접속·렌더 중이면 재시작을 최대 30~40분 미룬다(고객 작업 보호).
