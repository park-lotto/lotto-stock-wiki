# 쇼핑쇼츠 자동화 — 영상 믹싱 (기능 ④ 짜집기) 설계

날짜: 2026-07-12
상태: 설계 확정 대기
선행: 기능 ① 레퍼런스 랭킹, 기능 ② 소통 큐, 기능 ③ 소스매칭(제품 찾기) — 전부 완성, `shopping_shorts/`
벤치마킹 대상: 사용자가 제시한 "쇼핑팩토리" 8단계 위저드 스크린샷(레퍼런스 영상 분석 → 영상 선택 →
스크립트&음성 → 스타일 → 음성 프리뷰 → 썸네일 → SEO → 내보내기)

---

## 1. 목적 (What & Why)

기능③(제품 찾기)이 "같은 제품/주제를 다루는 여러 플랫폼 영상 링크"를 찾아주는 데까지였다면,
이 기능은 **그렇게 찾은(또는 사용자가 직접 고른) 동일 주제 레퍼런스 영상 2~5개를 실제로
믹스(짜집기)해서 하나의 새 쇼핑 숏폼 영상을 만들어내는 단계**다. 8단계 위저드 전체 중
**1~2단계(영상 분석 · 영상 선택/믹스)만** 이번 스펙 범위. 3~8단계(스타일/썸네일/SEO/내보내기)는
별도 스펙으로 이후 진행.

### 믹스의 정의 (사용자 확정)
- 입력: 동일 주제·비슷한 내용을 다루는 레퍼런스 영상 2~5개 URL + 목표 길이(초)
- 각 레퍼런스 영상에서 **대본**(나레이션 음성 또는 화면 자막 — 구현 편의상 더 빠른 쪽을
  Gemini 멀티모달 1콜로 통합 추출, 둘을 구분하지 않는다)을 추출
- 여러 대본을 비교해 **강점(후킹 문장·핵심 셀링포인트·구조)을 분석** → 목표 길이에 맞는
  **완전히 새로운 대본**을 합성
- 새 대본을 **ElevenLabs TTS로 새 나레이션 음성 생성**(원본 목소리 재사용 안 함)
- 새 대본 문장마다 레퍼런스 영상들 중 가장 잘 어울리는 구간을 매칭해 **컷 편집**
- 자동 매칭 결과를 화면에서 확인 → **마음에 들면 그대로, 아니면 문장별로 사람이 다른
  구간으로 교체**(완전자동 우선, 사람 확인은 안전판) → 최종 렌더

## 2. 전체 흐름

```
1. 입력: 레퍼런스 URL 2~5개 + 목표 길이(초) [mix.html]
      ↓
2. [백그라운드 job 시작] 각 영상 다운로드 (기존 download_video 재사용)
      ↓
3. 영상별 Gemini 멀티모달 1콜: 대본 세그먼트 추출
   {segments: [{start, end, text, scene_desc}], full_text}
      ↓
4. 여러 영상의 대본을 모아 Gemini 강점 분석 + 새 대본 합성 (목표 길이 맞춤)
   {sentences: [{text, est_seconds}]}
      ↓
5. 새 대본 문장별 ↔ 소스 구간 자동 매칭 (Gemini, 3번 결과 재사용)
   [{sentence_idx, source_video, start, end}]
      ↓
6. 문장별 ElevenLabs TTS 생성 (문장 단위 — 5번 매칭 결과와 길이 맞추기 위함)
      ↓
7. [결과 확인 화면] 문장×매칭구간×TTS 미리듣기 표시
   → 사람이 문장별로 "다른 후보 구간으로 교체" 가능(B안) — 안 건드리면 자동 결과 그대로
      ↓
8. [최종 렌더] ffmpeg: 매칭 구간을 TTS 길이에 맞춰 트림/속도조절 후 컷 편집 +
   원본음소거 + 새 TTS 오디오 합성 → 완성 mp4
```

## 3. 신규 모듈 (`shopping_shorts/`, 기존 순수함수 패턴 유지)

### 3-1. `script_extract.py`
- `extract_script(video_path, caption="") -> {"segments": [...], "full_text": str}`
- Gemini 멀티모달 1콜(영상 파일 직접 입력, `video_analysis.py`와 동일 패턴) — 나레이션과
  화면 자막을 구분하지 않고 통합해서 세그먼트별 텍스트+타임스탬프+장면 설명 추출.
- `response_schema` 강제(2026-07-10 zh/ja/ru 빈배열 버그 때 도입한 패턴 재사용) — segments
  배열 `minItems:1`로 빈 응답 방지.
- 전용 키 풀(`SHORTS_GEMINI_KEYS`) 재사용, 에러 분류(`key_vault.is_*_error`) 그대로 재사용.

### 3-2. `script_synth.py`
- `synthesize_script(source_scripts: list[dict], target_seconds: int) -> {"sentences": [{"text": str, "est_seconds": float}]}`
- 여러 영상의 `full_text`(+ segments 요약)를 Gemini에 한 번에 입력 → 공통 강점/차별화
  포인트를 뽑아 목표 길이에 맞는 새 대본 합성. 문장별 예상 발화 길이도 함께 산정(TTS
  글자수/속도 기반 추정 + Gemini 판단 보정).

### 3-3. `clip_match.py`
- `match_clips(new_sentences, source_scripts_with_segments) -> [{"sentence_idx": int, "source_video": str, "start": float, "end": float}]`
- 새 대본 문장마다 3-1에서 뽑은 세그먼트(scene_desc 포함) 중 가장 어울리는 구간을 Gemini가
  선택. 후보를 1개만 고르지 않고 상위 2~3개를 같이 반환(§3-5 수동교체용).

### 3-4. `tts.py`
- `synthesize_tts(sentence_text) -> audio_file_path` — ElevenLabs API 1콜/문장.
- 신규 설정: `ELEVENLABS_API_KEY`(`config.py`에 추가, 로컬/서버 모두 미설정 상태 확인됨 —
  **구현 착수 전 사용자가 키 발급/전달 필요**), 음성(voice_id)은 고정 1종으로 시작(설정
  가능하게 인자로 열어둠, UI 노출은 이번 스펙 범위 밖).

### 3-5. `video_assemble.py`
- `assemble(matches, tts_paths, source_video_paths) -> final_video_path`
- ffmpeg subprocess 패턴(`frame_extract.py`와 동일 스타일): 각 매칭 구간을 해당 문장 TTS
  길이에 맞춰 트림(구간이 더 길면 잘라내고, 더 짧으면 최대 재생속도 보정 한도 내에서 느리게
  재생 — 한도 초과 시 다음으로 긴 후보 구간으로 자동 대체) → concat → 원본 오디오 제거 →
  문장별 TTS를 이어붙인 오디오 트랙으로 교체 → mux.

## 4. 데이터 모델 (신규 테이블, `store.py`에 추가)

```sql
CREATE TABLE mix_jobs (
  job_id TEXT PRIMARY KEY,
  urls_json TEXT NOT NULL,        -- 입력 레퍼런스 URL 목록
  target_seconds INTEGER NOT NULL,
  status TEXT NOT NULL,           -- downloading|extracting|synthesizing|matching|tts|ready_for_review|rendering|done|failed
  error TEXT,                     -- status=failed일 때 사유
  script_json TEXT,               -- 3-2 결과 (합성된 새 대본)
  matches_json TEXT,              -- 3-3 결과 (문장↔구간 매칭, 사람이 교체하면 갱신됨)
  video_path TEXT,                -- 최종 렌더 결과 (완료 후)
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL
);
```

기존 `source_candidates`/`source_pool` 테이블(임베드 검색 시절 유물, 현재 죽은 코드)은
이번 기능과 무관 — 손대지 않는다.

## 5. API 엔드포인트 (신규)

오래 걸리는 작업(다운로드+Gemini 멀티콜+TTS+ffmpeg, 수 분 소요 가능)이라 기존 동기식
엔드포인트(`/api/find/analyze`)와 달리 **백그라운드 job + 폴링** 패턴 채택:

- `POST /api/mix/start` `{urls: [...], target_seconds: int}` → `{job_id}` 즉시 반환,
  `BackgroundTasks`(FastAPI)로 2~6단계 순차 실행하며 `mix_jobs.status` 갱신.
- `GET /api/mix/status/{job_id}` → `{status, error?}` — 프론트가 폴링.
- `GET /api/mix/result/{job_id}` → `{script, matches, candidates_per_sentence}` — status가
  `ready_for_review` 이상일 때만 유효한 데이터.
- `POST /api/mix/adjust` `{job_id, sentence_idx, source_video, start, end}` — 특정 문장의
  매칭 구간을 후보 중 하나(또는 3-3이 반환한 후보 목록 내)로 교체, `matches_json` 갱신.
- `POST /api/mix/render` `{job_id}` → 최종 ffmpeg 렌더 시작(역시 백그라운드, status→`rendering`→`done`).
- `GET /api/mix/video/{job_id}` → 완성 mp4 서빙(기존 `/api/find/frame/*` 프록시 패턴).

## 6. 화면 (`shopping_shorts/static/mix.html`, 사이드바에 "영상 믹싱" 메뉴 추가)

1. **입력**: URL 필드 2~5개(+ 소스 추가), 목표 길이 슬라이더(초), "믹스 시작" 버튼.
2. **진행 중**: 단계별 상태 텍스트(다운로드 중 → 대본 추출 중 → 대본 합성 중 → 구간 매칭 중
   → 음성 생성 중) — `status` 폴링으로 갱신.
3. **결과 확인**: 새 대본 문장 리스트. 문장마다 매칭된 구간의 대표 썸네일 1장 + "어느 영상
   몇초~몇초" 표기 + TTS 미리듣기 버튼. 마음에 안 드는 문장만 드롭다운(후보 2~3개 중 선택)
   으로 교체. 전부 마음에 들면 그대로 "최종 렌더" 클릭.
4. **완료**: 완성 mp4 미리보기(`<video>` 태그) + 다운로드 링크.

## 7. 알려진 리스크

- **ElevenLabs API 키 미확보** — 로컬/서버 모두 미설정 확인됨. 구현 착수 전 사용자가 발급·
  전달해야 실제 TTS 테스트 가능(그전까지는 mock/스킵으로 개발).
- **3-3 자동 매칭 품질이 전체 결과물의 체감 품질을 좌우** — Gemini가 "이 문장에 이 장면"을
  잘못 고르면 나레이션과 화면이 따로 노는 영상이 나옴. §3-5의 "사람이 문장별 교체" 확인
  단계가 안전판이지만, 자동 매칭 정확도 자체는 실제 레퍼런스 영상으로 초기 구현 직후
  실측 검증 필요(품질 낮으면 프롬프트 튜닝 또는 후보 개수 확대로 대응).
- **구간 길이-TTS 길이 불일치**: 매칭된 원본 구간이 TTS 문장 길이보다 짧으면 재생속도를
  느리게 조정하는데, 과하게 느려지면 부자연스러움 — 배속 보정 한도(예: 0.8~1.2배)를 넘으면
  차순위 후보 구간으로 자동 대체하는 안전장치 필요(§3-5에 반영됨).
- **ffmpeg 처리 시간**: 영상 편집(트림+concat+오디오믹스)은 CPU 바운드라 서버 사양에 따라
  체감 대기시간이 클 수 있음 — 초기 구현 후 실측해서 필요하면 큐잉/동시실행 제한 검토.
- **저작권**: 타 크리에이터 원본 영상을 컷 편집해 재사용하는 것 자체가 사업 방향(경쟁사
  tubefactory류 서비스 공통 방식)이라 이 스펙에서 별도 처리하지 않음 — 기존 합의 범위.

## 8. 단계적 구현 순서 (계획 문서에서 세분화 예정)

1. `mix_jobs` 테이블 + `script_extract.py`(대본 추출) — 레퍼런스 영상 1개로 실측 검증
2. `script_synth.py`(새 대본 합성) — 2~3개 영상 대본으로 실측 검증
3. `clip_match.py`(구간 매칭) — 3-3 결과 품질 실측, 프롬프트 튜닝
4. ElevenLabs 키 확보 후 `tts.py` 연동 + 실측
5. `video_assemble.py`(ffmpeg 렌더) — 배속 보정/자동대체 로직 포함
6. `/api/mix/*` 엔드포인트 + `mix.html`(진행상태 폴링 + 결과확인 + 수동교체 + 최종렌더)
7. 전체 파이프라인 E2E 실측(레퍼런스 2~3개, 실제 mp4 산출까지)
