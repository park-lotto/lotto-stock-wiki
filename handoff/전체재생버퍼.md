### 원인 2건 (둘 다 전체 재생에서만 나타난다)

**① 칸이 넘어갈 때 음성을 그 자리에서 처음 받는다 — 주범**

```js
function playTts(a, i){ a.src = SL.tts(i); ... }   // ← 이음매에 도달해서야 요청
```
`runAllFrom`이 앞 칸 음성이 끝나는 순간(`a.onended`) 다음 칸으로 넘어가며 `playTts`를 부른다.
화면은 `warmVideos()`가 소스마다 A/B 두 벌을 미리 열어둬서 안 막히는데 **음성만 예열이 없었다.**
게다가 `curT()`가 `audio().currentTime`을 시계로 쓰므로, 음성이 로드되는 동안
**진행바·자막이 통째로 멈춰** 버퍼처럼 보였다.

→ **음성도 A/B 두 벌**(`ttsEl`)로 두고, 칸 `i`를 트는 동안 **다음 칸 음성을 숨은 쪽에 미리
받아둔다**(`seatTts(i+1, (i+1)%2)`). 바깥 코드는 여전히 `audio()` 하나만 본다.

**② 다음 칸 미리 앉히기가 재생 중인 화면을 건드릴 수 있었다**

```js
if (ncl[0]){ ncl[0]._slot = 0; seat(ncl[0]); }   // 슬롯 0 고정
```
그런데 `startSeq`도 현재 칸 컷들에 `_slot = k % 2`를 줘서 **컷 0번이 똑같이 슬롯 0**이다.
다음 칸 첫 컷이 현재 칸과 **같은 소스**면 `vidFor()`가 **지금 화면에 보이는 그 엘리먼트**를
돌려주고, `seat()`가 거기에 `currentTime`을 꽂는다 → 재생 중인 화면이 튀거나 시크 대기.

→ **칸 넘김 전용 슬롯**(`handoffSlot(i) = 2 + (i % 2)`)을 따로 두고 칸마다 교대.
0·1과도, 이웃 칸과도 절대 안 겹친다.

**③ 보완** — 전체 재생의 **첫 칸**은 미리 앉힌 게 없다. `warmVideos`가 데운 건 0·1뿐이라
첫 칸부터 새 슬롯을 쓰면 첫 화면이 되레 늦다 → `preSeated`로 갈라 첫 칸만 예전대로 슬롯 0.

## ⚠️ 함정

- **`let`/`const` 최상위 선언은 `window`에 안 붙는다.** 브라우저 도구로 `DATA`·`MAX_SHOT`을
  읽으려다 `undefined`가 나온다 → `iframe.contentWindow.eval("...")`로 그 프레임 스코프에서 읽어라.
- **`a.onended`를 재사용 엘리먼트에 남기지 마라.** A/B로 번갈아 쓰면 앞서 붙은 핸들러가 살아
  있다. `runAllFrom`은 `playTts` **직후 동기적으로** 새 `onended`를 덮어쓰므로 안전하고,
  `stopPlay`는 **양쪽 슬롯 다** 끊는다.
- 오디오 키는 `SL.job + '#' + i` — 잡이 바뀌면 옛 음성을 재사용하지 않는다.
