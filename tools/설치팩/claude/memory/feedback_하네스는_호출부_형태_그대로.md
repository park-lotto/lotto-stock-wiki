함수를 떼어내 검증할 때 **하네스가 실제 호출 형태와 다르면 통과해도 의미가 없다.**
2026-08-21 하루에 라이브 500을 **두 번** 냈고, 두 번 다 내 검증은 초록불이었다.

| 사고 | 하네스가 한 것 | 서버 실제 | 결과 |
|---|---|---|---|
| `NameError: sys is not defined` | exec 네임스페이스에 **내가 `sys`를 넣어줌** | 그 함수 스코프에 `sys` 없음 | 대본 생성 전면 500 |
| `ValueError: not enough values to unpack (expected 3, got 2)` | 반환값을 **2개로 언팩** | 호출부는 `a, b, c =` 3개 | 대본 생성 전면 500 |

두 번째는 docstring이 "(조립본 목록, 조립 못 한 스파인 목록)"이라 2개처럼 적혀 있어 믿은 탓이다.
**docstring은 낡는다. 호출부가 계약이다.**

## 하네스를 만들기 전에

```
□ 호출부를 grep한다        grep -n "함수명(" *.py | grep -v "def "
□ 그 줄의 **언팩 형태·인자 개수**를 그대로 베낀다
□ 네임스페이스에 없는 이름을 **채워주지 마라** — 없는 채로 돌려야 진짜 조건이다
□ 마지막엔 **서버의 실제 파일**을 읽어 같은 방식으로 한 번 더 돌린다
```

라이브를 만지는 변경이면 배포 전에 **서버에서 그 파일을 직접 실행**해보는 게 가장 확실하다
(`ssh … python3 -c "src=open('app.py').read(); ..."`).

라이브가 죽었을 때는 **설정 원복이 코드 수정보다 빠르다** — 되돌릴 스위치를 함께 만들어 두면
사고가 나도 1분 안에 복구된다(실제로 `assemble_off=0` 한 줄로 복구했다).
