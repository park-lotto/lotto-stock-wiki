# 보이스 프리셋 라이브러리 — 설계 (Design)

- 날짜: 2026-07-14
- 상태: 승인됨(설계) → 구현계획 대기
- 관련: `shopping_shorts/tts.py`, `mix_pipeline.py`, `store.py`, `static/produce.html`
- 선행 완료: ElevenLabs TTS API 연결(키·`Text to Speech` 권한·`.env` 자동로드) — 실제 한국어 음성 E2E 검증됨(2026-07-14)

---

## 1. 목적 / 한 줄 정의

빅채널 나레이션의 *느낌*을 **페르소나 이름 + 한줄설명 + 튜닝된 감도값**으로 굳혀,
produce 4단계에서 카드로 골라 쓰는 **보이스 프리셋 라이브러리**.

유저는 "이 느낌" 하나만 누르면 성우·속도·감도가 한 번에 세팅된다.

## 2. 확정된 방향 결정 (브레인스토밍 2026-07-14)

| 결정 | 선택 | 함의 |
|------|------|------|
| 레퍼런스 반영 방식 | **하이브리드** (MVP=스톡매칭, 클로닝은 확장) | Phase 1은 클로닝 없음. 타인음성 무단복제 회피 |
| 라이브러리 채우는 방식 | **라이브러리 먼저 → 생성도구 나중** | Phase 1 큐레이션, Phase 2 앱 내 생성도구 |
| 감도 노출 | **프리셋 + '고급' 접기** | 기본은 심플(속도·무음삭제만), 고급 접기에 슬라이더 |

## 3. 정직한 한계 명시 (설계의 핵심 전제)

- Claude(나)는 **두 오디오의 음색을 귀로 A/B 비교하지 못한다.**
- 내가 할 수 있는 것: 레퍼런스 오디오를 **측정**(피치·발화속도·에너지·무음비율)하고,
  매핑 규칙표로 **후보 스톡보이스 + 감도값을 산출**하는 것까지.
- **최종 "비슷하다" 판단은 사용자(사장님)의 귀.** 샘플 생성 → 사용자 확인 → 승인 시 등록.
- 이 협업 구조를 UI·문서·프리셋 생성 절차 전반에 명시한다. 눈속임 금지.

## 4. 데이터 모델

### 4-1. `voice_presets` (라이브러리)

| 필드 | 타입 | 예 | 비고 |
|------|------|-----|------|
| `preset_id` | TEXT PK | `kr-calm-info-seulgi` | slug 고유 |
| `name` | TEXT | `슬기` | 페르소나명(Claude 작명) |
| `one_liner` | TEXT | `차분한 여성 나레이션. 정보전달에 적합.` | 유저 노출 |
| `lang` | TEXT | `KR` | KR 우선 / JP·EN 자리만(Phase2) |
| `archetype` | TEXT | `차분정보` | 차분정보·하이텐션·친근수다·신뢰전문 |
| `base_voice_id` | TEXT | ElevenLabs voiceID | |
| `model_id` | TEXT | `eleven_multilingual_v2` | |
| `voice_settings` | JSON | `{stability,similarity_boost,style,use_speaker_boost}` | 감도 |
| `default_speed` | REAL | `1.1` | 0.8~1.5 |
| `default_silence_trim` | TEXT | `mid` | off/약/중/강 |
| `sample_path` | TEXT | `assets/voice_samples/seulgi.mp3` | ▶미리듣기 |
| `source_ref` | TEXT | `벤치마크 채널 참고 메모` | **내부 전용, 유저 미노출** |
| `origin` | TEXT | `curated` / `generated` | |
| `created_at` | TEXT | ISO | |

> `source_ref`는 유저에게 "○○채널 복제"로 노출하지 않는다(오해·법적 소지). 내부 관리용.

### 4-2. `mix_jobs.voice_json` (선택 스냅샷 — 마이그레이션 ADD COLUMN)

```json
{ "preset_id": "kr-calm-info-seulgi", "voice_id": "...",
  "settings": {"stability":0.65,"similarity_boost":0.75,"style":0.0,"use_speaker_boost":true},
  "speed": 1.1, "silence_trim": "mid" }
```
프리셋이 나중에 바뀌어도 그 job은 선택 당시 값으로 고정(스냅샷).

## 5. 저장·배포 구조

- **큐레이션 자산**: `assets/voice_presets.json`(git추적) + `assets/voice_samples/*.mp3`(git추적)
  - `data/`는 `.gitignore` → 서버로 안 감. 그래서 **git추적되는 `assets/`에 둔다.** git push로 서버 자동반영(3분 크론).
- **기동 시 seed**: JSON → DB `voice_presets` upsert(origin=curated). 파일이 소스오브트루스.
- **유저 생성분**(Phase2): DB에만(origin=generated).
- **샘플 서빙**: `assets/voice_samples/`를 정적 서빙 경로로 마운트(또는 `/api/voice-preset/{id}/sample` 프록시). produce에서 `<audio src>`로 미리듣기.

## 6. 프리셋 생성(튜닝) 절차 — Phase 1은 Claude 수동 큐레이션

```
① 레퍼런스 오디오 확보
   - 이미 수집된 소스영상에서 ffmpeg로 오디오 추출, 또는 URL 지정 다운로드
② 측정 (오디오 분석 유틸)
   - 피치 f0 중앙값       → 성별/연령대 후보 필터
   - 발화속도(음절/초)     → speed
   - 에너지 변동(표준편차)  → stability / style 힌트
   - 무음 비율            → silence_trim
③ 매핑규칙표 → 후보 스톡보이스 + 감도값 산출
④ 샘플 생성 → 🎧 사용자 확인 → 승인 시 라이브러리(JSON) 등록 + 샘플 mp3 저장
```

### 매핑 규칙 (측정 → ElevenLabs 설정)

| 측정 | 규칙 |
|------|------|
| 피치 f0 | 성별/연령대 후보 voice 필터 |
| 발화속도 느림/보통/빠름 | speed 0.9 / 1.1 / 1.3 |
| 에너지 일정(정보전달) | style 0.0, stability 0.65 |
| 에너지 변동 큼(감정적) | style 0.4, stability 0.35 |
| similarity_boost | 기본 0.75 |
| 무음비율 높음 | silence_trim 중/강 |

## 7. 코드 변경

- **`tts.py`**: `synthesize_tts(text, out_path, voice_id=None, voice_settings=None, speed=None, model_id=None, max_retries=3)`
  - payload에 `voice_settings` 병합. 무음 mock fallback 유지.
  - **speed**: ElevenLabs `voice_settings.speed` 지원 범위(문서 확인 — 대략 0.7~1.2) 내면 API로, 초과분(≤1.5)은 렌더/후처리 `ffmpeg atempo`로 보정. (계획단계에서 context7로 API 스펙 확인)
- **`mix_pipeline.py`**: `_plan_and_tts`가 job의 `voice_json`을 읽어 비트별 `synthesize_tts`에 전달.
- **무음삭제**: 비트 mp3 생성 후 `ffmpeg silenceremove`(레벨별 파라미터)로 후처리. off면 스킵.
- **`store.py`**: `voice_presets` 테이블 + `mix_jobs.voice_json` 마이그레이션 + JSON seed 로더(upsert).
- **`app.py`**: `GET /api/voice-presets?lang=KR` (목록) / 샘플 서빙 / produce job에 voice 저장·TTS 재생성 엔드포인트.

## 8. UI — produce 4단계 개편 (스크린샷1 방향)

- 언어탭: KR(활성) / JP·EN(Phase2 자리)
- **프리셋 카드 리스트**: 이름 · 한줄설명 · ▶미리듣기(sample) · [선택]
- 선택 시: **속도**(0.8~1.5 버튼) · **무음삭제**(OFF/약/중/강)
- **`고급 ▾` 접기**: stability / similarity / style 슬라이더 + speaker boost 토글 (프리셋 기본값 프리필, 유저 오버라이드 가능)
- **"이 대본으로 다시 듣기"**: 첫 비트만 현재 설정으로 재생성 미리듣기(크레딧 절약 — 전체 아님)
- **자막/음성 없이 진행** 토글(스샷1): 켜면 TTS·자막 스킵하고 영상만 내보냄

## 9. 범위 (YAGNI)

- **Phase 1 (이번 스펙 · 구현 대상)**: KR 큐레이션 6~8개 + 선택UI + 감도(고급접기) + tts 연동 + 무음삭제 + "이 대본으로 다시 듣기"
- **Phase 2 (다음 스펙)**: 앱 내 생성도구(URL→측정→자동제안→저장), JP/EN 확장, (동의된) 보이스 클로닝

## 10. 테스트

- `tts.py` voice_settings/speed payload 병합 — monkeypatch 단위테스트
- seed 로더(JSON→DB upsert) — 신규/갱신 케이스
- 측정 유틸(pitch/rate/energy) — 합성 오디오 순수함수 테스트
- `mix_jobs.voice_json` 마이그레이션 — 기존 DB에 컬럼 추가 검증
- 무음삭제 후처리 — silenceremove 호출/스킵 분기

## 11. 미해결 / 진행 중 수정 여지 (사용자: "일단 진행 보고 수정")

- 큐레이션 개수(6~8) 및 아키타입 목록 — 구현 중 조정 가능
- speed API 지원범위 실측 후 atempo 보정 경계 확정
- 샘플 데모 문장 문구(공통 1문장) 확정
