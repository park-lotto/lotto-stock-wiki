# 추출 속도 3종 묶음 — 설계문서

> 작성: 2026-07-29 · 트랙: 모션레벨훅 · 대상: shopping_shorts 추출/제작소

## 1. 문제
제작소 대본추출이 느리다(사장님 실측: 1단계 분석 5분, 2단계 매칭 5분+). 사용 시점에 추출이 몰려 체감 대기가 크다. 실측으로 확인: **캐시 히트면 추출 0초**(d70ab210 job 1.5분 = 캐시 덕). → 대기를 사용 시점에서 **앞당기고**, 추출 자체를 **가볍게**, 실측으로 검증.

## 2. 세 레버 (사장님 확정, 묶어서)
### ① 즐겨찾기 시 사전분석 (체감 대기 제거 — 제일 큼)
즐겨찾기(도서관 저장, `api_wiki_save`) 시 **백그라운드로 추출을 미리 돌려 캐시에 저장**. 나중에 제작소로 보내면 캐시 히트 → 추출 0초. 사장님이 고른 것만 분석하므로 낭비 적음.
- 배선: `api_wiki_save`가 `store.enqueue("extract", {shortcode, url, caption, customer_id})`. 워커 `TASKS`에 `"extract"` 추가 → 다운로드→추출→`save_extract` 캐시.
- 중복 방지: 이미 `get_extract`에 유효 캐시(segments+seg_id)면 스킵. 실패는 조용히(사전작업이라 무해).

### ② B1을 1단계 추출에도 배선 (사전분석·autoload도 빠르게)
지금 `frame_extract_enabled` 플래그는 `mix_pipeline`(2단계)에만. 1단계 추출(autoload·wiki_save·①의 사전분석)은 `extract_script`(영상 통째)를 직접 부른다.
- 배선: `script_extract`에 **`extract_auto(video_path, video_id, caption)`** 신설 — 플래그 on이면 `frame_script.extract_script_frames`, off·빈결과면 `extract_script` 폴백. **모든 1단계 호출부(app.py 1292/1460/1572/1651/6425)를 `extract_auto`로 교체.** → 플래그 하나로 전 추출경로가 B1.

### ③ B1 실측·승격 (이미 구현·플래그 on)
새(캐시 없는) 영상으로 매칭 → 추출 시간·나레이션·대본 길이 실측. 좋으면 플래그 기본값 승격, 나쁘면 끄고 재분석.

## 3. 데이터 흐름 (합친 그림)
```
즐겨찾기 클릭 → api_wiki_save → enqueue("extract")           [①]
   워커: 다운로드 → extract_auto(플래그면 B1 프레임+오디오)  [②]
       → save_extract 캐시
제작소로 보냄 → get_extract 캐시히트 → 추출 0초 → 바로 대본
(캐시 없으면 그때 extract_auto로 B1 추출)                    [②③]
```

## 4. 비목표 (YAGNI)
- 하이브리드 트랙(모션레벨·인벤토리 재베이스·OCR)은 안 건드림.
- 사전분석 대량 배치·예열 스케줄 — 즐겨찾기 트리거만(사장님 곡선에 맞음).
- 캐시 만료/무효화 정책 변경 — 기존 `get_extract` 유효성 검사 재사용.

## 5. 검증 (exit proof)
- 단위: 워커 `TASKS["extract"]` 존재·중복 캐시 스킵. `extract_auto` 플래그 분기·빈결과 폴백. 1단계 호출부가 `extract_auto` 사용.
- 실측: (①) 즐겨찾기 직후 캐시 채워짐 → 제작소 진입 시 추출 0초. (②) autoload 로그에 B1 흔적(groq·프레임, 영상 upload 없음). (③) 새 영상 추출시간 단축·나레이션 채워짐·대본 목표 길이.
- 게이트: 기준선(13) 대비 신규 회귀 0. 플래그 off면 전부 기존 동작.

## 6. 위험/함정
- **사전분석 낭비/과금**: 즐겨찾기 남발 시 추출 비용. 중복 캐시 스킵 + 실패 무해로 상한. 필요시 호출당 상한.
- **워커 큐 포화**: 사전분석이 믹스 job과 큐 경쟁(1GB 1개씩). extract를 낮은 우선순위로(믹스 먼저) — 지금은 FIFO라 후속 튜닝 여지.
- **①의 이중 캐시 키**: `save_extract`는 shortcode 키, 제작소 `get_extract`도 같은 키여야 히트. 배선 시 키 일치 확인(불일치면 히트 0).
- **②의 호출부 누락**: 1단계 추출 호출부가 5곳 — 하나라도 `extract_auto`로 안 바꾸면 그 경로만 옛 추출. 전수 교체 확인.
