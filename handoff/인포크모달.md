## ❌ 2026-08-18 (최종) — **iframe 방식은 폐기했다. 다시 시도하지 마라**

사장님 제보: *"인포크에는 로그인 안 풀려있고 계속 되고있는데, 로그아웃 후 다시 해도 안 된다."*

### 진짜 원인 — 쿠키다 (아래 CORS 진단은 원인의 일부일 뿐이었다)

```
인포크 쿠키 11개 = 전부 SameSite=Lax    /    SameSite=None = 0개   (실측)
```

**Lax는 크로스사이트 iframe에 아예 안 실린다.** 그래서 인포크 탭에서는 로그인 상태인데
틀 안에서만 "로그인 정보가 만료되었습니다"가 뜬다. **재로그인해도 새 쿠키도 Lax라 소용없다.**

★**내가 어제 틀린 지점**: 프레임 삽입이 안 막힌다는 것(X-Frame-Options·CSP·프레임버스팅 없음)만
확인하고 **쿠키를 확인하지 않았다.** 그때 관리화면이 뜬 건 사실이지만 그걸 "iframe에서 세션이
유지된다"로 일반화한 게 잘못이다. 구조상 처음부터 안 되는 것이었다.

→ **우리가 고칠 수 있는 게 아니다.** 인포크가 `SameSite=None; Secure`로 바꾸지 않는 한 불가능.
   새 탭이 유일한 방법이고, **원래 있던 `인포크링크 열기 ↗`가 옳았다.**

### 지금 상태 (커밋 `77d074d47`)

- iframe 모달 통째 제거(`#inpockModal`·`#inpockFrame`·`.gen-box-wide`).
  **왜 안 되는지 코드 주석과 테스트로 못 박았다** — 안 그러면 다음 사람이 또 만든다.
- `📦 링크 복사 + 인포크 열기 ↗` = 링크 복사 + 새 탭 열기를 한 번에
- 손으로 할 길 유지: `📋 링크만 복사` · `인포크만 열기 ↗` · 등록완료 체크

### ⚠️ 함정 — `window.open(..., 'noopener')`는 성공해도 null이다

반환값으로 성공을 판정했더니 **창이 멀쩡히 열렸는데 "팝업이 차단됐습니다"**가 떴다(실측).
→ `rel=noopener`를 단 `<a>`를 만들어 클릭한다. 보안은 그대로, 차단 판정은 브라우저에 맡긴다.
테스트가 `window.open(` 재도입을 막는다.

## ⚠️ 2026-08-18 — (중간 진단, 참고용) 로그인 API도 CORS로 막힌다

사장님 제보: 모달 안에서 "로그인 정보가 만료되었습니다" → 로그인해도 **"네트워크 오류 💦"**.

### 원인 (실측으로 확정 — 계정 문제가 아니다)

인포크 로그인 API(`link-rest.inpock.co.kr`)는 **자기 도메인 Origin만** 허용한다.

| Origin | `Access-Control-Allow-Origin` |
|---|---|
| `https://shoppingshorts.duckdns.org` | **없음 → 브라우저가 차단** |
| `https://link.inpock.co.kr` | 허용 (+`credentials: true`) |

틀 안에서 로그인 요청을 보내면 CORS에서 막히고, 인포크 코드가 그걸 "네트워크 오류"로
표시한다. **가짜 계정으로 프로브하면 같은 자리에 "가입하지 않은 아이디입니다"가 뜬다**
— 문구가 다르다는 것이 CORS 차단의 증거다(요청이 서버까지 갔는지 여부).

★**어제 "세션 유지 확인"은 맞지만 만료됐을 때는 확인하지 못했다.** 로그인된 상태로 여는
  것과, 틀 안에서 새로 로그인하는 것은 다른 문제였다. 여기서 내가 놓쳤다.

### 해결 = 뚫지 않고 내보낸다 (사장님 지시)

새 탭(인포크 자기 도메인)에서 로그인하면 **쿠키가 도메인 단위로 공유돼 틀에도 적용된다.**
- 바에 `🔑 로그인 만료 시 새 탭에서 로그인 ↗`(`target=_blank`) + `↻ 새로고침`
- `inpockFrameReload()` — 크로스오리진이라 `contentWindow.location`을 못 만진다 →
  **src 재대입**. 같은 URL이면 캐시된 로그인화면이 다시 뜰 수 있어 `?_=Date.now()`로 가른다.
- ⚠️ **크로스오리진이라 "지금 로그인 화면인가"를 코드가 알 수 없다** → 안내는 **항상** 띄운다.
  조건부로 띄우려면 프레임 내부를 읽어야 하는데 그게 원천 차단이다.

### 사장님이 쓰는 법

```
모달에서 "로그인 정보가 만료되었습니다"가 뜨면
  ① 바의 [🔑 로그인 만료 시 새 탭에서 로그인 ↗] 클릭
  ② 새 탭에서 인포크 로그인
  ③ 모달로 돌아와 [↻ 새로고침]  → 관리화면이 뜬다
```

- ⚠️ **복사 성공을 가정하지 마라.** `clipboard`는 비보안 컨텍스트·권한 거부에서 **조용히**
  실패한다. 실패했는데 "복사됨"이라 띄우면 빈 클립보드로 붙여넣게 된다 →
  `inpockCopyChecked`가 성공/실패를 갈라 돌려주고 `execCommand`로 한 번 더 시도한다.
- ⚠️ **`final_link`는 상품이 있어도 빌 수 있다.** `url`·`partner_url`이 둘 다 비면 빈 문자열
  (`coupang_partners.final_link`) → 버튼은 그려지고 링크만 없다. 검증 중 발견해 가드를 넣었다.
- ⚠️ **닫을 때 `frame.src`를 비우지 마라.** 비우면 다시 열 때마다 재로그인 흐름을 탄다.
- ⚠️ `iframe`에 `src`를 마크업으로 박지 마라 — 제작소를 열 때마다 인포크를 부른다.
- ⚠️ **이 기능은 인포크가 프레임을 안 막는다는 전제 위에 있다.** 저쪽이 나중에
  `X-Frame-Options`를 걸면 모달이 빈 화면이 된다. 그때는 Playwright 자동등록(아래 ⏭2)로 간다.

### 인스타와의 관계 (사장님 "인스타는 꼭 필요한 건데")

내 인스타 프로필 링크는 **인포크 하나**이므로, 영상마다 생기는 쿠팡 상품은 전부 인포크 안에
쌓여야 한다. 그래서 이 등록 단계가 인스타 수익화의 목줄이다. 영상 설명란·고정댓글에는
인포크 프로필 링크 하나만 넣는 구조(`refreshInpock` 안내문에 그대로 적혀 있다).
