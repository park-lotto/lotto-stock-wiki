# 컷편집경합 — 3단계 컷 편집이 완성본에 안 들어가던 것

> 2026-09-02 (회사PC) · 사장님 제보로 시작, 라이브 재현·수정·검증 완료

## 제보
"영상 편집 중에 구간편집 체크 해제 후, 각 섹션마다 1초 단위로 세밀하게 컷편집을 조정한 뒤에
왼쪽 상단에 완성본 미리보기를 클릭해서 영상을 확인하면 해당 컷 편집이 적용되어있지 않음."

## 뿌리 — 저장보다 렌더가 **먼저 출발**했다 (타이밍)

라이브에서 요청 순서를 재보니 정확히 거꾸로였다:

```
    0ms   렌더시작   POST /api/produce/mix/preview
  901ms   편집저장   POST /api/mix/scene_lab/<job>/apply
```

`autoApply`가 **1.2초 디바운스**(scene_lab.html)라, 컷을 조정하고 그 안에
[완성본 만들기]를 누르면 서버는 **옛 편성으로** 렌더를 시작한다.
0.9초 뒤 도착한 편집은 이미 늦었다.

### ★데이터·배선은 멀쩡했다 (따로 확인)
- 화면 배지 `✋1.0` + `3.5` (합 4.5 유지)
- 서버 저장 `fixed_lens: {"14d95dbf8729-6": 1}`
- **천천히** 렌더하면 실제 컷 경계도 ≈1.0초(프레임 실측: 1.1초부터 정지)

즉 **타이밍만** 틀렸다 → "될 때도 있고 안 될 때도 있다"로 보인다.
(천천히 누르면 되고, 바로 누르면 안 된다)

## 고침 (커밋 `7917fa60c` · `0d513d0e1`)

`_askRender`가 `flushApply()`를 **await 한 뒤** `startPreview()`를 부른다.

- `flushApply` = 예약된 디바운스 취소 + 즉시 `applyServer` 실행
  + 전송 중(`_autoApplyBusy`)이면 재전송 예약(`_autoApplyAgain`)까지 대기
  (⚠️`applyServer`는 전송 중이면 **즉시 return**하므로 이 대기가 없으면 마지막 편집이 빠진다)
- **디바운스는 유지** — 슬라이더·연속 편집마다 POST가 나가면 안 된다. "지금 비우기"만 추가
- 저장이 실패해도 렌더는 진행(막으면 아무것도 못 만든다)
- 기다리는 동안 "⏳ 편집 내용 저장 중…" 표시
- 9단계 `renderFinal`에도 같은 flush 추가 — 가장 비싼 작업이라 "혹시"를 안 남긴다

### 라이브 검증 (배포 후 같은 조작)
```
수정 전:  0ms 렌더시작 → 901ms 편집저장   ❌
수정 후:  0ms 편집저장 →  34ms 렌더시작   ✅
```
서버 `fixed_lens 1.5` / 화면 `✋1.5` 일치 확인.

가드: `test_render_flushes_edits_js.py` 6건 — 특히 **flushApply가 startPreview보다 앞**인지를
위치로 검사(await 없이 부르면 같은 버그가 재발하므로 await도 확인).
수정 전 코드에서 4건 FAIL 확인.
