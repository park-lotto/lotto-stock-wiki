### scene_lab UI 개편 (미커밋)
`tools/scene_lab/build.py` 한 파일. 사장님 피드백을 여러 라운드로 반영:
- **버튼 전멸 → 드래그 중심**: 담기=끌어다 놓기(+더블클릭), 빼기=왼쪽 팔레트로 끌기(+더블클릭),
  재생=썸네일 클릭. 썸네일에 붙은 조작 버튼 0개.
- **좌우 두 칸 → 한 칸으로 합침**(사장님 "최대한 심플하게"). 나올 화면 정보는 카드 위 칩으로.
- **자르기(✂)**: 장면 가운데 구간 빼기. `TRIMS={sid:[a,b]}` → `trimPieces()`가 두 토막으로
  갈라 `planClips`에 **재료로만** 먹인다. ★분배 규칙(라운드로빈·MAX_SHOT 2.2·MIN_CLIP 0.8·
  shortfall)은 한 글자도 안 건드렸다.
- 미리보기: 화면 클릭 정지/재생, 진행바 구간이동, 창 드래그 이동.

⚠️ **자르기 UI가 안 보인다는 지적** — 트림바는 `playKey`가 `seg:`일 때(썸네일 클릭으로 장면
하나 미리보기)만 뜨고 칸 재생(`beat:`) 중엔 숨는다. 발견성 문제로 남아 있음.

### 실측해둔 사실 (다음 세션이 다시 재지 않도록)
```
칸  멘트    담은장면 원본합   상태
1   6.1초   5.2초           부족 → 마지막 컷 2.3초로 늘어남
2   5.8초   6.2초           남음(2장 잘려 쓰임)
3   4.8초   7.5초           많이 남음
4   7.3초   7.8초           남음 → 첫 장면이 끝에 1.4초 또 나옴(유일한 진짜 되풀이)
5   4.9초   8.7초           많이 남음
```
★`planClips`는 **되돌아가지 않는다**. 재료를 다 쓰면 부족분을 **마지막 컷에 더한다**
(`clips[last].dur += short`). 칸1·5의 "0.9초/0.5초"는 되풀이가 아니라 **마지막 컷 연장**이다.
칸4만 첫 장면에 남은 용량이 있어 진짜 4번째 컷으로 되풀이된다.

★**자르면 부족이 커진다**(멘트 시간은 안 줄어들므로). 실측: 칸1에서 0.6초 자르면
부족 0.9→2.5초, 마지막 컷 2.3→3.9초. 잘라낸 조각이 0.8초 미만이면 그 조각은 아예 안 나온다.
→ **자르기는 "장면 더 담기" 또는 "늘려 채우기"와 세트여야 한다.**

### 구조 — UI 원본은 한 파일 (0순위-B)
- **`shopping_shorts/static/scene_lab.html`(신규)** = UI 유일 원본. build.py의 HTML 문자열을
  통째로 이관. 인라인 JSON 태그(`#scene-lab-data`)가 null이면 서버 모드(`?job=` → API),
  채워져 있으면 로컬 모드. `SL` 어댑터(thumb/src/tts/applyUrl)만 모드를 안다.
- `tools/scene_lab/build.py` = 이 파일을 읽어 data.json만 인라인(HTML 없음). serve.py·fetch.py

  테마가 제작소 6천줄 JS와 충돌하지 않게. 기존 `#mixReview`(문장별 상세)는 접힌 채 그대로 보존.

### 서버 배선 (app.py)
- `/api/mix/segments` — **shot_role·is_key·phash 추가**(기존 키 불변).
- `GET /api/mix/scene_lab/{job}` — fetch.py data.json과 1:1 같은 모양(캡션은 라이브 함수
  `_caption_segments/_caption_durations/_adjust_caps_for_trim` 호출 결과).
- `GET /api/mix/scene_lab/{job}/phash` — 늦채움 폴링. **phash는 seg_thumb이 썸네일을 만들 때
  함께 계산해 `work/seg_thumbs/phash.json`에 캐시**(락으로 직렬화, ffmpeg timeout 20s).
  fetch.py와 같은 8x8 평균해시 — 실측 해밍거리 0(비트 동일), s3-2↔s3-20 거리 0 재현.
  캐시 없으면 ""/{} 폴백(UI는 중복접기만 꺼짐, 안 깨짐).
- `GET /api/mix/src/{job}/{vid}` — 소스 mp4(FileResponse=Range 206, 시크 됨).
- `POST /api/mix/scene_lab/{job}/apply` — `{payload}`/`{revert:true}` → `apply_scene_lab`/

## 1단계 렌더에 대한 사실 (사장님 질문 "한 번은 필요한 거지?")
**필요하다. 단 그건 렌더가 아니라 재료 만들기다.**
- `/api/mix/start` → `run_mix_job`(mix_pipeline.py:528) = **다운로드 → 대본추출 → EDL → TTS**.
  영상 합성을 하지 않는다. 소스 영상·장면목록·대본·음성을 만든다 —
  **이게 없으면 실험실에 보여줄 데이터 자체가 없다.**
- 실제 영상 합성은 `/api/produce/mix/preview`(2단계 미리보기)와 `/api/mix/render`(8단계) 둘뿐.
- → **실험실은 렌더 횟수를 줄인다**: 예전엔 장면을 바꿀 때마다 미리보기 렌더를 돌려야
  확인됐는데, 실험실은 소스 구간을 그대로 잘라 이어 재생해 **합성 없이** 컷·자막을 확인한다.
  렌더는 하루 횟수 제한(`check_and_count(cid,"render")`)이 걸려 있어 실질 이득이다.
- ⚠️ 단 실험실 미리보기는 **근사**다. 모션효과·자막꾸미기·효과음·속도감모드는 안 보인다.
  "장면 배치가 맞나"는 실험실로 충분, "예쁘게 나오나"는 결국 렌더 1회가 필요하다.
