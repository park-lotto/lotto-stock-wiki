## 오늘 한 것 (2026-07-26)

### ✅ 1. 인스타 "지금 수집" 403 즉사 — 근본해결·라이브 검증 완료 (트랙 `수집403로테이션`, main 병합됨)
- **원인**: Apify FREE 계정들이 월 $5 하드리밋 초과 → 유료 렌탈 액터(apidojo)가 **403 "Monthly usage hard limit exceeded"**. 코드가 403에선 토큰 로테이션을 안 해(`_EXHAUSTED_STATUSES={401,402,429}`) 살아있는 STARTER($60) 토큰을 써보지도 못하고 전체 즉사.
- **수정**: `apify_client._EXHAUSTED_STATUSES`에 **403 추가** + 0건을 성공 아닌 경고로 표시.
- **검증**: 라이브 실수집 **345건 done** 실측(before=403 error 0건). 레딧/해외HOT과 **완전 무관**이었음.
- **충전 불필요**: STARTER 예산 남음. FREE는 다음 달 리셋되면 로테이션 복귀.

### ✅ 2. 제작소 계정 크로스기기 싱크 (이 트랙, 커밋 `1fc878ee6`, finish 게이트 통과 시 병합)
- **문제**: 모바일에서 제작소로 영상 보내 작업해도 PC에 안 뜸 — 작업상태가 기기별 sessionStorage 격리라 영영 안 맞았다. (서버 produce_works엔 계정별 저장되지만 로드는 로컬만 봄)
- **수정**: `produce.html` `_bootAccountLatestOrLocal()` — `?work=`·`?new` 없이 그냥 `/produce` 열면 **계정 최신작업(list_produce_works updated_at DESC [0])을 자동 로드**. 방금 보낸 재료 우선 / 로컬이 최신이면 유지 / 유실 0 / 핑퐁 없음(_restoreWork는 saveWork 안 부름).
- **검증**: node 슬라이스 5시나리오(A~E) + 전체 38테스트 통과.

## ⏭ 회사에서 이어서 할 일
1. **finish 병합 확인 후 라이브 검증**: 모바일에서 제작소 작업 → PC에서 `/produce` 열어 그 작업이 자동으로 뜨는지 실측. (finish가 아직 안 끝났으면 `py tools/track.py finish 제작소계정싱크` 재실행)
2. ⚠️ **인앱브라우저 캐시는 별개 문제** — 서버는 이미 `Cache-Control: no-cache, must-revalidate`+ETag를 produce.html에 정상 전송(관리자 세션으로 실측 확인). 카톡 인앱브라우저가 이를 무시해 옛 UI를 붙잡음 → **크롬/사파리로 열거나 인앱 캐시 삭제**하면 최신. 서버 코드로는 못 고침.
3. (선택) **"빠른 수집"** — 지금 "지금 수집"은 활동성 생존 **192채널** 전부 긁어 ~28분·회당 ~$1. 활동성 상위 N채널만 긁는 옵션 추가 검토(사장님 제안).
4. (선택) 제작소에 **"내 작업" 계정 목록 UI**(서버 `/api/produce/works` GET, 전 기기 공통) 노출 — 밀려난 작업 클릭 복구용. 자동싱크의 보완.
5. **해외HOT UI/카테고리 개편**은 **다른 세션 담당** — 이 트랙에서 손대지 말 것.
