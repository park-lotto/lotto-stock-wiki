# 장면 라이브러리 — 효과음(sfx) 역할 매칭 & 렌더 믹스 (설계)

- 날짜: 2026-07-22
- 트랙: 장면라이브러리
- 선행: 페이즈2-A(소재매칭·컷어웨이·검수판, main `2066c41c`) + 페이즈2-B(역할매칭, 커밋 `ccea63e9a`~`7e0ee6a0b`) 완성·라이브.
- 상위 설계: `2026-07-18-장면라이브러리-페이즈2A-매칭-컷어웨이-검수판-design.md` §1(sfx는 명시적 비범위로 남겨둔 부분), `2026-07-18-장면라이브러리-페이즈2B-역할기분매칭-design.md`(역할 매핑표 재사용 대상)

## 0. 왜 필요한가

사장님이 효과음 파일을 직접 준다("이 소리 좋으니 나중에 써야겠다"). **뱅크(업로드·저장)는 이미 됨** — `/api/scene/upload`(app.py:4857)가 mp3/wav/m4a/aac를 받아 `scene_assets`에 `asset_type="sfx"`로 저장한다. 안 되는 건 그 다음 두 단계뿐이다: ① 대본 비트에 맞춰 AI가 자동으로 고르는 매칭, ② 렌더에서 실제 오디오로 섞어 넣는 것. 이 스펙은 그 두 가지만 다룬다.

## 1. 목표 (범위 확정)

**하는 것**: 비트 역할 → sfx 역할 **결정적 매칭**(Gemini 미사용) + 비트 안 **결정적 타이밍 규칙**(첫/마지막 세그먼트) + 최종 렌더에서 **고정볼륨 믹스** + 검수판 배지·빼기 토글.

**안 하는 것(비범위)**: 소재(대본 단어) 기반 sfx 매칭 · 덕킹(sidechain) · 영상 내 중복 사용 금지 · 비트당 2개 이상 sfx · 사용자 수동 드래그 배치 · sfx 자체 페이드인/아웃 · 부분 비트(비트 중간) 타이밍.

## 2. 아키텍처 · 데이터 흐름

기존 클립 매칭(`match_scene_assets`)과 나란히, **새 함수 한 개**를 같은 삽입 지점에 추가한다.

```
run_mix_job:
  build_edit_plan
    → match_scene_assets(plan, assets)   # 기존, clip 전용
    → match_sfx(plan, assets)            # ★신규, sfx 전용, beat["sfx"]에 씀
    → status=ready_for_review
run_render:
  job에서 plan 로드 → assemble(plan, ...)
    → beat["cutaway"] 있으면 컷어웨이 오버레이 (기존)
    → beat["sfx"] 있으면 오디오 믹스에 추가 (★신규, _burn_captions 확장)
```

- `beat["cutaway"]`와 `beat["sfx"]`는 **서로 다른 키** — 한 비트가 장면짤+효과음을 동시에 가질 수 있고, 서로 안 건드린다.
- 매칭(`match_sfx`)은 **초 단위 타이밍을 계산하지 않는다.** "첫 세그먼트"/"마지막 세그먼트"라는 **위치 이름만** `beat["sfx"]["position"]`에 적어두고, 실제 몇 초인지는 렌더 쪽(`_burn_captions`)이 계산한다 — 캡션 타이밍(`_caption_segments`/`_caption_durations`, cap_durs 등)을 이미 그쪽이 소유하고 있어서, 초 단위 계산을 매칭까지 끌고 오면 같은 계산이 두 곳에 생겨 나중에 어긋난다(트랙 교훈 — "저장위치=읽기위치 일치" 원칙의 연장).

## 3. 컴포넌트 A — `scene_match.py` 확장 (신규 함수, 기존 파일)

### 3.1 인터페이스
```python
def match_sfx(plan: dict, assets: list[dict]) -> dict
```
- 순수함수. `plan`을 복사해 반환. Gemini 호출 없음(§2B의 역할 패스와 동일 철학).

### 3.2 후보 필터
```python
def _sfx_candidates(assets):
    return [a for a in assets if a.get("asset_type") == "sfx" and a.get("role") in _ROLES]
```
- 표절 게이트(`source_origin`)는 **적용 안 함** — sfx 직접업로드 경로(`/api/scene/upload`)엔 그 필드 자체가 없다(클립처럼 "화면에 남의 촬영분이 박히는" 리스크가 아니라 소리 파일이라 검사 대상이 다름).
- **역할이 통제어휘(`scene_assets._ROLES`) 안에 있는 것만** 후보. 지금 `/api/scene/upload`가 role을 자유텍스트로 받으므로(§6에서 드롭다운으로 막음), 방어적으로 여기서도 한 번 더 거른다.

### 3.3 역할 매핑 (재사용, 신규 표 없음)
`scene_match._ROLE_FALLBACK`(비트 역할 → 호환 자산 역할, 2-B에서 이미 정의)를 **그대로** 쓴다. 이 표는 "비트 자리에 뭐가 어울리나"를 말하는 것이라 화면짤/소리 어느 쪽에도 적용된다.

### 3.4 후보 선택 — 클립 역할 패스와 다른 점
```python
def match_sfx(plan, assets, *, position_rule=None):
    plan = copy.deepcopy(plan)
    cands = _sfx_candidates(assets)
    by_role = {}
    for a in cands:
        by_role.setdefault(a["role"], []).append(a)
    for beat in plan["beats"]:
        compatible = _ROLE_FALLBACK.get(beat.get("role") or "")
        if not compatible:
            continue
        pool = [a for role in compatible for a in by_role.get(role, [])]   # ★중복 허용 — used 세트 없음
        if not pool:
            continue
        chosen = _pick_role_asset(pool, beat.get("narration") or "")       # 기존 헬퍼 재사용
        beat["sfx"] = {"asset_id": chosen["id"], "match_type": "role",
                        "position": _sfx_position(beat.get("role"))}
    return plan
```
- `_pick_role_asset`(2-B에 이미 있음)을 그대로 재사용 — 나레이션 키워드 겹침 우선, 없으면 결정적 순서.
- **중복 허용**이 클립 역할 패스와의 유일한 알고리즘 차이. 클립의 `_role_pass`를 복사·수정하지 않고 신규 함수로 분리한 이유 — `used` 세트 유무 하나 때문에 조건분기를 넣느니, 짧은 함수 두 개가 낫다(YAGNI/단순성).

### 3.5 타이밍 위치 규칙
```python
_SFX_POSITION = {"hook": "first"}          # 명시 안 된 역할은 전부 "last"

def _sfx_position(beat_role):
    return _SFX_POSITION.get(beat_role, "last")
```
- **훅**: 비트 시작하자마자(첫 자막 세그먼트) — 시선을 즉시 붙잡는 용도.
- **그 외 전부**(반전/비법공개/반응/전환/본문/CTA로 매핑되는 비트): **마지막 자막 세그먼트 시작 시각** — 문장이 몇 토막으로 쪼개질 때 마지막 토막이 대개 포인트/펀치라인이라 자연스러운 타점.
- 세그먼트가 1개뿐인 비트는 first==last, 결과가 같다(자동으로 안전).

## 4. 컴포넌트 B — 렌더 (`video_assemble.py` 확장)

### 4.1 초 단위 오프셋 계산 (`_burn_captions` 안에서)
`_beat_timeline`이 이미 만드는 `timeline` 항목마다, `beat.get("sfx")`가 있으면:
1. 그 비트의 narration을 캡션과 **동일한 함수**(`_caption_segments` + `_caption_durations(…, real_durs=cap_durs)`)로 세그먼트 길이 리스트(초)를 구한다 — 캡션이 쓰는 계산을 그대로 재사용(별도 계산 금지, §2의 "저장위치=읽기위치" 연장).
2. `position=="first"` → 오프셋 0.0. `position=="last"` → `sum(seg_durs[:-1])`(세그먼트 1개면 0.0).
3. 절대 시각 = `beat["t0"] + offset`.

### 4.2 오디오 믹스 확장
지금 BGM만 처리하는 블록(`video_assemble.py:1110-1117`)을 "여러 오디오 트랙을 모아 한 번에 섞는" 구조로 일반화한다:

```python
mix_labels = ["0:a"]                       # 나레이션(항상 있음)
if has_bgm:
    fc.append(f"[{idx}:a]aloop=loop=-1:size=2000000000,volume={vol:.3f}[bg]")
    mix_labels.append("bg"); idx += 1
sfx_vol = max(0.0, min(1.0, (deco.get("sfx_volume", 60)) / 100.0))
for i, (sfx_path, offset_sec) in enumerate(sfx_events):
    inputs += ["-i", sfx_path]
    ms = round(offset_sec * 1000)
    fc.append(f"[{idx}:a]adelay={ms}:all=1,volume={sfx_vol:.3f}[sfx{i}]")
    mix_labels.append(f"sfx{i}"); idx += 1
if len(mix_labels) > 1:
    ins = "".join(f"[{lb}]" for lb in mix_labels)
    fc.append(f"{ins}amix=inputs={len(mix_labels)}:duration=first:dropout_transition=2[a]")
    amap = "[a]"
```
- `has_sfx`를 `has_bgm`/`has_overlay`/`has_motion`과 같은 목록에 추가해, sfx만 있어도(BGM 없이도) `filter_complex` 경로를 타게 한다(지금은 셋 다 없으면 단순 복사 경로로 빠짐 — video_assemble.py:1086).
- **`-ar`/`-ac` 사전 규격 고정 불필요**: 예전 설계문서가 우려한 건 `concat -c copy`(클립을 스트림카피로 이어붙일 때) 얘기다. sfx는 콘캣이 아니라 BGM과 똑같이 `amix` 필터로 최종 한 번만 섞이고, ffmpeg 필터그래프는 입력 포맷이 달라도 자동으로 맞춰 섞는다(BGM이 지금 이 방식으로 이미 실동작 중 — 별도 `-ar`/`-ac` 지정 없이).
- `deco.get("sfx_volume", 60)` — BGM의 `volume`(0~100 스케일)과 같은 패턴으로 전역 1개 값. 자산별 개별 볼륨은 v1 비범위(YAGNI, 필요해지면 나중에 자산 필드로 추가).

### 4.3 sfx가 비트보다 길 때 (알려진 한계, v1에서 안 고침)
sfx 오디오는 트림하지 않는다 — 파일이 비트 길이보다 길면 다음 비트 오디오 위로 흘러넘친다. 효과음은 보통 1~2초 내외라 실사용에서 잘 안 만날 문제지만, 정직하게 한계로 남긴다. 필요해지면 업로드 시 길이 상한 검증이나 렌더 시 자르기를 추가.

## 5. 컴포넌트 C — 업로드 폼 역할 드롭다운

- 지금 `/api/scene/upload`(app.py:4858)의 `role`은 자유 텍스트라 클립처럼 통제어휘(훅·반전·CTA·비법공개·반응·전환·본문)로 강제되지 않는다. `scene_library.html`의 sfx 업로드 폼에 **드롭다운**을 추가하고, 서버 쪽에도 `_validate_render_mode`와 나란히 `_validate_role(asset_type, role)` 같은 헬퍼를 둬서 sfx/overlay 업로드 시 role이 통제어휘 밖이면 422로 거부한다(기존 clip 자동태깅이 이미 이 어휘로 강제되는 것과 대칭).

## 6. 컴포넌트 D — 검수판 (`produce.html`)

- 자동배치된 sfx가 있으면 비트에 **배지**: 🔊 + 자산 제목 + "역할 매칭(반전 자리)" — 클립의 "소재 매칭 0.95" / "역할 매칭" 배지와 같은 표기 패턴, 다른 아이콘(🎞 vs 🔊)으로 구분.
- **"이 효과음 빼기" 토글** — 끄면 `beat["sfx"]` 제거. 클립의 "이 짤 빼기"와 동일한 컴포넌트 재사용(토글 대상 키만 다름).
- 저신뢰 "제안" 개념 없음(역할 매칭은 점수가 없어 자동배치 아니면 그냥 빈 채로) — 클립의 `asset_suggestions` 같은 별도 큐 불필요.

## 7. 신뢰·비용

- Gemini 호출 0 — 매칭·타이밍 전부 결정적 규칙. 비용 걱정 없음.
- 오배치 리스크: 역할 어휘가 틀리게 태그된 sfx가 있으면 엉뚱한 자리에 들어갈 수 있음 — §5의 드롭다운 강제로 예방(자유텍스트 오타·이형태 원천 차단).

## 8. 테스트 (TDD)

- **`_sfx_position`(순수함수)**: hook → "first" / 나머지 어떤 역할이든 → "last" / 매핑표에 없는 역할도 "last"(기본값이 안전측).
- **`match_sfx`(순수함수)**: ① 후보 0(호환 역할 없음) → sfx 없음 ② 역할 불일치 후보 배제 ③ 역할 통제어휘 밖 자산 배제(§3.2) ④ **중복 허용** — 같은 asset_id가 서로 다른 두 비트에 배치될 수 있음을 명시적으로 검증(클립 역할 패스 테스트와 대조되는 케이스) ⑤ 나레이션 키워드 겹침 시 그 자산 우선.
- **오프셋 계산(순수함수 또는 얇은 헬퍼)**: position="first" → 0.0 / "last" → 세그먼트 1개면 0.0, 2개 이상이면 마지막 세그먼트 직전까지의 합.
- **렌더 통합(실 ffmpeg)**: ① sfx 오버레이 후에도 비트 클립·최종 영상 길이가 불변(싱크 자물쇠, 클립 컷어웨이 테스트와 같은 패턴) ② BGM+sfx 동시 존재 시 `amix` 입력 개수가 기대대로(3개: 나레이션+bg+sfx1) ③ sfx 없는 기존 영상(회귀) — 지금처럼 `amix inputs=2`(나레이션+bg) 그대로 동작.
- **엔드투엔드(seam)**: `match_sfx`가 `beat["sfx"]`에 쓴 `asset_id`+`position`을 렌더가 그대로 읽어 그 자산을 정확한 오프셋에 섞는지.

## 10. 미해결·정직하게 남김

- **sfx_volume 기본값(60)은 추정치** — 실 재료(사장님이 준 실제 효과음 파일)로 들어보고 조정 필요(트랙 교훈: 합성 fixture 통과 ≠ 완료).
- **"last 세그먼트" 타이밍 규칙이 모든 역할에 자연스러운지**: 반전/비법공개/CTA는 그럴듯하지만, 실 대본으로 몇 개 렌더링해 귀로 확인 필요.
- **역할 어휘가 sfx 카테고리를 다 커버하는지**: 클립용 7개 어휘(훅·반전·CTA·비법공개·반응·전환·본문)가 효과음에도 그대로 맞는지, 실담기에서 확인(2-B가 요소짤에서 겪은 것과 같은 종류의 질문).
