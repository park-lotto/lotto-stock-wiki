# 페이블 검토 요청 — 회사운영플랫폼 착수 권한

> 작성: 2026-09-11 · 요청자: 아스트라 세션
> 사용자 지시: "여기에 페이블이랑 같이 이문제 논의해봐"
> 상태: 검토 요청 작성. 페이블 전달·열람·답변은 아직 확인하지 못함.

## 목적

회사 운영 플랫폼 구현을 사용자가 승인했다. 구현 전 필수 트랙 생성이 현재 Codex 실행 환경에서 막힌다. 사용자에게 정확한 설정 방법을 안내하고, 승인된 범위에서 구현을 재개할 수 있는지 공동 검토하고자 한다.

사업·조직 기준은 [회사 운영규칙](../wiki/rules/회사운영규칙.md), 착수 기록은 [회사운영규칙 핸드오프](회사운영규칙.md)를 참조한다.

## 직접 확인한 사실

- 현재 세션 정책: `workspace-write`, 승인 정책 `never`.
- 전달된 파일시스템 정책에서 저장소 루트는 쓰기 허용이나 `.git`, `.agents`, `.codex`는 명시적 읽기 전용이다.
- 위키 문서 작성·수정과 Git 읽기 명령은 실행 가능했다.
- 문서 Git 저장 시 `.git/index.lock: Permission denied`로 실패했다.
- `tools/track.py start 회사운영플랫폼`은 새 브랜치 생성에서 다음 오류로 실패했다.

```text
Preparing worktree (new branch 'track/회사운영플랫폼')
fatal: cannot lock ref 'refs/heads/track/회사운영플랫폼': Unable to create 'C:/Users/CH/Desktop/로또의 주식/.git/refs/heads/track/회사운영플랫폼.lock': Permission denied
```

- 사용자 "권한허용" 메시지 후 같은 명령을 다시 실행했지만 동일 오류였다. 실행 정책 자체가 바뀌었다는 증거는 없다.
- 기존 다른 작업 트랙을 차용하거나 루트 코드를 변경하지 않았다. 구현 코드는 아직 없다.
- 현재 협업 에이전트 목록에는 아스트라 세션 `/root`만 있다. 페이블 세션을 직접 호출하는 연결 도구는 찾지 못했다.

## 아스트라의 판단과 수정할 수 있는 부분

- 오류는 현재 세션의 `.git` 읽기 전용 정책과 일치한다. 일반 Windows 사용자 권한 자체가 고장났다는 진단은 하지 않았다.
- 사용자에게 앱 권한 메뉴의 `Full access`를 안내했다. 그러나 실제 앱 화면·선택 가능한 정책은 보지 못했으므로 정확한 UI 위치와 적용 가능성은 미확인이다.
- 전체 접근은 광범위한 권한이므로 필요한 Git 작업만 허용하는 정책이 실제 환경에서 가능한지 먼저 검토할 가치가 있다.
- `handoff/코덱스세팅.md`에는 과거 `approval_policy = "never"` 설정과 샌드박스 실측 기록이 있다. 현재 설치·정책과 일치하는지는 미확인이다. 과거 'codex exec는 항상 read-only'라는 기록을 일반 제품 사실로 확대하면 안 된다.
- 공식 문서 확인: https://learn.chatgpt.com/docs/permissions 및 https://learn.chatgpt.com/docs/windows/windows-sandbox . 기본 작업공간 정책의 Git 보호와 관리형 정책 제약을 참고했다.

## 페이블에게 요청하는 검토

1. 사용자에게 현재 UI에서 무엇을 눌러야 하는지, 실제 화면·설정 근거로 안내할 수 있는가? 앱·CLI를 먼저 구분하고 추정 경로를 사실처럼 말하지 말 것.
2. 현재 관리형 정책에서 사용자 선택으로 변경 가능한 범위는 무엇인가? 대화 속 승인과 실제 실행 정책 변경을 구분할 것.
3. 광범위한 전체 접근 외에 Git 작업에 필요한 제한된 승인 방식이 이 환경에서 지원되는가?
4. 정책 변경을 사용자가 실제로 완료했을 때 어떤 확인으로 적용 여부를 검증해야 하는가?

이 요청은 권한 제한 우회, Windows ACL 변경, 별도 프로세스로 금지된 Git 쓰기를 대신 수행하라는 지시가 아니다. 진단과 정식 설정 경로 검토만 요청한다.
