# 컷길이수동 — 컷 길이 직접 정하기 (캡컷 대체 2번)

## 2026-08-24 (커밋 `c2ed375ff`)

캡컷 대체 3벽 중 **2번**. 지금까지 컷 길이는 자막 시간에서 **자동 계산**만 됐다.

### 규칙 (사장님 선택)
**정한 컷은 그대로, 나머지 컷이 비례로 줄어든다.**
- ★칸 전체 길이는 **못 바꾼다** — 자막이 `t0` 누적으로 자리를 잡아, 칸이 길어지면
  **뒤 자막이 통째로 밀린다**. 그래서 총합은 항상 `tts_dur` 그대로.

### 쓰는 법
컷 썸네일의 **초 배지를 누르면** 길이 입력칸이 열린다.
정한 컷은 `✋` 표시 + 색이 바뀐다. **다시 누르면 자동으로 되돌아간다.**
- ★`prompt()`는 안 썼다 — 브라우저 모달은 화면을 통째로 멈춘다(자동화·확장에서 특히).

### ★화면과 서버가 같은 규칙
| | |
|---|---|
| 화면 | `scene_play.js` `applyFixedLens()` |
| 서버 | `video_assemble.py` `_apply_fixed_lens()` |

**실측 대조** — 6초 칸 `2.2/2.2/1.6`에서 s0을 3초로 고정:
- 화면 `3.0 / 1.74 / 1.26` (합 6.0)
- 서버 `3.0 / 1.74 / 1.26` (합 6.0) → **완전 일치**

규칙이 갈리면 미리보기와 결과가 어긋난다 — 그게 이 시리즈를 시작한 이유다(0순위-B).

### 저장 경로 (끝까지 이었다)
```
FIXLEN(화면) → payload.fixlen → edit_plan: beat["fixed_lens"] → 렌더 _apply_fixed_lens
```
안 보내면 **미리보기에만 살고 결과가 달라진다**. `plan["scene_lab"]["fixlen"]`에도 남긴다.

### ★내가 낸 버그
`planClips`를 **잘라 도는 하네스**에서 `applyFixedLens`를 못 찾아
`test_beat_fill_label` 4건이 깨졌다 → `typeof` 가드로 해결.
(메모리 `reference_슬라이스하네스_window금지`에 있던 그 함정 — 또 밟았다)

### 검증
- 고정 3초 유지 / 나머지 비례 축소 / **합계 6.0 불변**
- 과대입력(6초 칸에 10초) → 4.4초로 눌리고 나머지 0.67초 확보, 합계 6.0
- 전부 지정(2+2+2) 그대로 / 되돌리면 자동값 복귀
- `beatIdx` 안 넘기는 옛 호출부는 종전 동작(**하위호환**)
- UI 왕복: 배지 클릭 → 패널 → 적용 → ✋ 표시 → 재클릭 해제
