# 모바일공유 — 폰 [공유] → 숏템메이커 ⭐나만의 채널등록

> **소유 트랙**: 모바일공유 — 이 파일은 이 트랙 세션만 수정한다.

## 2026-09-27 — 1단계 구현 (트랙 커밋만, 라이브 미배포)

사장님: "폰으로 채널 보다가 레퍼런스로 저장하거나 페이지에 넘겨서 관리" → 안드로이드,
**지금은 숏템메이커 나만의 채널등록으로**, 나중에 페이지 하나 따로 신설. "형식은 레퍼런스랭킹 UI".

### 구조 (0순위-C)
- 판단의 주인: `app.py _fav_channel_register(cid, url, username, thumb)` — PC 확장(`/api/fav_channel/grab`)과
  폰 공유(`POST /api/fav_channel/share`)가 둘 다 부른다. 주소 고르기는 `_shared_link(url,text,title)` 한 곳.
- 입구: `static/manifest.webmanifest`에 `share_target`(GET /share) → `static/share.html`이 API 호출 후 결과 표시.
- 권한: `/share`=_FREE_EXACT_GET, `/api/fav_channel/share`=_FREE_EXACT_ANY (볼채널등록과 같은 급).
- 검사: `shopping_shorts/tests/test_mobile_share.py` (13개, 수정 전 코드에선 실패 확인).

### 고친 기존 버그
- `_FAV_CH_PATTERNS` 인스타 식이 `reel/코드/?igsh=…Rx`의 **끝 글자 'x'를 채널로** 잡았다(9-02 생성 이후).
  PC 확장은 username을 넘겨 피해갔고, 라이브 fav_channel 129건 중 오염 0건(서버 읽기 확인).
- `_resolve_uploader`: 빈 결과 1회 재시도 + 실패 이유 stderr 기록(조용히 삼키던 것) + utf-8 디코딩.
- `youtu.be` 짧은 주소를 유튜브로 인식.

### 실측 (로컬 서버 :8871, 인증 OFF=cid0)
- 인스타 릴스/게시물(igsh)·프로필, 유튜브 youtu.be/쇼츠, 틱톡(@주소) → 전부 담김, 목록 5건 일치
- 주소없음→nolink / 뉴스→notfound(0초, yt-dlp 안 돌림) / PC grab 팝업 정상
- 크롬(Pixel 7 에뮬) CDP: 설치 가능(오류 0), share_target 파싱됨. /share 화면 캡처 확인.

### ⏭ 남은 것
1. **라이브 배포 — 사장님 승인 필요**(A1c). 승인 후 finish → 폰에서 [홈 화면에 추가] → 인스타 앱 공유로 실측.
2. 실폰 미검증: 공유 목록에 뜨는지(WebAPK 설치 필요), 틱톡 앱 `vt.tiktok.com` 짧은 주소(실주소 없어 못 돌림).
3. "레퍼런스랭킹 UI 형식" — 채널카드 그대로인지, 신설 페이지에 적용인지 사장님 확인 대기.
4. `/api/fav_channel/add`(화면 붙여넣기)는 아직 프로필 주소만 받는다 — 주인 함수로 합칠지 결정.
