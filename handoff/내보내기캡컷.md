### 실측
- 서버 조립본은 정상: `mix_jobs/76665d680876/capcut/영양사 친구가…/`에
  beat_00~07.mp3 + cut_*.mp4 = 합 65MB, 2026-09-02 16:43 생성 (SSH 확인)
- 내 PC `C:\capcutproject\CapCut Drafts` 에는 오늘 만들어진 draft 0건 → 고객 PC 얘기가 맞음
- 코드(`produce.html` `sendToCapCut()`): JSON을 먼저 쓰고, 그 뒤 에셋 수십 개를
  한 개씩 fetch→write. **그 동안 화면에 아무 표시가 없었다.** 완료 alert만 맨 끝에.

### 한 것
`sendToCapCut()`에 진행표시·이탈방지 배선 (`produce.html`)
- `#btnCapCut` / `#ccProgress` 신설, 버튼은 진행 중 스피너+비활성
- `📤 영상 재료 보내는 중… 12 / 47` + 진행바 + "창 닫지 마세요" 안내
- `beforeunload`로 완료 전 이탈 경고
- **에셋 0개면 성공이라 하지 않고 중단**(작업번호까지 노출) — 빈 프로젝트 원인 후보 하나를 봉인
- 실패 시 "중간에 끊겼습니다" + 에러 원문을 화면에 남김
- `finally`의 `renderExport()`가 exportBox를 다시 그려 표시가 날아가므로 결과 문구를 복원

### 검증 (2026-09-02, 실제 크롬에서 실행)
로컬 `python -m http.server 8777`로 produce.html을 띄우고, `showDirectoryPicker`·`fetch`를
가짜로 바꿔(형태는 실제 File System Access API 그대로) `sendToCapCut()`을 **onclick과 같은
형태로** 호출해 관찰. `alert`은 스텁으로 막았다(진짜 alert이 뜨면 자동화가 통째로 멈춘다).

### 함정 기록
`produce.html`은 **CRLF와 LF가 섞여 있다**(전체 CRLF 17,074줄인데 `sendToCapCut` 구간은 LF).
여러 줄 문자열로 치환할 때 개행을 확인하고 맞춰라.
또 Bash heredoc이 `\n`을 `\n`으로 줄여 파이썬 소스에 도달하므로, JS 소스의 리터럴 `\n`을
치환 대상으로 쓸 땐 `chr(92)+'n'`으로 조립해야 한다.
