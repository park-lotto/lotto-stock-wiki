# 코덱스세팅 — Codex CLI를 이 저장소에 붙이기 (2026-09-09, 사장님 PC)

## 왜
Claude Code 옆에서 **Codex(OpenAI CLI)** 를 같이 쓰기 위해. 트랙을 나눠 쓰면 두 도구를
동시에 돌려도 흡수 사고가 안 난다(흡수를 막는 건 창이 아니라 **파일이 어느 폴더에 있느냐**).

---

## 새 PC(집)에서 그대로 따라 하기

git에 담기는 것과 **PC마다 따로 해야 하는 것**이 갈린다. 아래 4개만 하면 끝난다.

### 1. 설치 (PC마다)

```powershell
npm install -g @openai/codex
codex --version        # 실측 확인: codex-cli 0.153.4
```
사전 조건은 Node뿐(실측: node v24.15.0 / npm 11.12.1).

### 2. 로그인 (PC마다) — ★사장님이 직접

```powershell
codex login            # 브라우저가 열린다 → ChatGPT 계정으로 로그인
codex login status     # "Logged in using ChatGPT" 가 떠야 한다
```
**요금제는 따로 설정할 게 없다.** 그 계정이 Pro면 Codex도 Pro 한도로 돈다.
건당 과금이 아니라 **사용 한도**를 먹는 방식이다(`/usage`로 남은 한도 확인).

### 3. 저장소 받기

```powershell
git pull                # AGENTS.md · 코덱스.bat · tools/track_open.py 가 따라온다
```

### 4. 샌드박스 승인 (PC마다, 한 번)

`codex`를 처음 띄우면 묻는다 → **`1. Set up default sandbox`** 선택(관리자 권한 창 뜸).
`Sandbox ready`가 뜨면 파일 수정·명령 실행이 된다.

## git에 담긴 것 (pull 하면 따라옴)

| 파일 | 하는 일 |
|---|---|
| `AGENTS.md` | Codex가 자동으로 읽는 규칙. **CLAUDE.md 통째로 읽기** + **트랙을 스스로 만들기** |
| `코덱스.bat` | 열린 트랙 목록에서 번호로 골라 그 폴더에서 Codex 실행 |
| `tools/track_open.py` | 여는 절차 **한 곳**(`--agent claude|codex`) — 도구마다 베끼지 않는다(0순위-B) |

## PC마다 따로 해야 하는 것 (git에 없음)

| 것 | 위치 | 비고 |
|---|---|---|
| 로그인 토큰 | `~/.codex/auth.json` | `codex login` |
| 모델·승인 설정 | `~/.codex/config.toml` | 아래 참고 |
| cmd 자동 실행 | `~/.codex-autorun.cmd` + 레지스트리 AutoRun | 아래 참고 |
| 바탕화면 바로가기 | `Desktop\코덱스.lnk` | `cmd /k cd /d "<저장소>" && codex` |
| 스킬 머리말 수정 | `.agents/` | gitignore라 안 따라온다(아래) |

### `~/.codex/config.toml` (사장님 PC 실측값)

```toml
model = "gpt-5.6-sol"          # 평소 쓰는 두뇌. 어려운 일만 /model 로 gpt-6-astra
model_reasoning_effort = "medium"
approval_policy = "never"      # 승인 창 끄기. 샌드박스는 그대로라 폴더 밖은 여전히 못 건드린다
```

### cmd 켜면 바로 Codex (선택)

`~/.codex-autorun.cmd` 를 만들고 레지스트리에 등록한다.

```powershell
New-Item -Path 'HKCU:\Software\Microsoft\Command Processor' -Force
New-ItemProperty -Path 'HKCU:\Software\Microsoft\Command Processor' `
  -Name AutoRun -Value '"C:\Users\<사용자>\.codex-autorun.cmd"' -PropertyType String -Force
```

`.codex-autorun.cmd` 안에 **반드시** 이 두 줄을 먼저 둔다 —
없으면 다른 프로그램이 내부적으로 쓰는 `cmd /c ...`에서도 Codex가 떠서 git·설치기가 깨진다.

```bat
echo %CMDCMDLINE% | find /i "/c" >nul && goto :eof
if defined CODEX_AUTORUN_DONE goto :eof
```

끄기: `reg delete "HKCU\Software\Microsoft\Command Processor" /v AutoRun /f`

## 확인된 것 (실측)

- **AGENTS.md를 실제로 읽는다** — "app.py 자막 코드를 고쳐달라면 뭘 먼저 하나" 물었더니
  ① CLAUDE.md·wiki/rules 읽기 ② find_work.py ③ track list, **없으면 내가 트랙을 만든다**
  ④ 실제 화면에서 결과 확인 ⑤ `git -C`로 커밋 ⑥ 끝났을 때만 finish — 순서대로 답했다.
- **`codex exec`(비대화형)는 항상 `sandbox: read-only`** 다. `--sandbox workspace-write`를 줘도,
  `-c sandbox_mode=`로 줘도 안 바뀐다(둘 다 실측). 대화형은 별개다.
- **스킬 로딩 경고**: `.agents/skills/market-analyze/SKILL.md`에 YAML 머리말(`---` name/description)이
  없어서 Codex가 못 읽었다 → 머리말 추가로 경고 0건(재실행 확인). `.agents/`는 gitignore라
  **새 PC에서도 같은 경고가 나면 그 PC에서 똑같이 고쳐야 한다**.

## 함정

- **브라우저는 따로다.** Codex는 `chrome@openai-bundled` 플러그인 + 크롬 확장이 있어야 화면을 본다
  (`codex plugin add chrome@openai-bundled`로 플러그인은 깔았으나, **확장 설치는 사람이 직접 눌러야 한다**).
  Claude Code는 `~/.claude.json`에 `claude-in-chrome`이 이미 있어서 되는 것이다 — "안 깔아도 된다"가 아니다.
- **Codex와 Claude Code가 같은 트랙을 동시에 만지면 안 된다.** 트랙을 갈라 쓴다.
- 커밋만으로는 라이브에 안 간다 — **`py tools/track.py finish <트랙>`** 까지 해야 배포된다.
