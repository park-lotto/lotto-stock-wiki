# 02 공용 렌더러 장치 — `render_bench.py` 결손 A1·A4·B1 (표준 §3-3)

## 목표
공용 렌더러 하나가 모든 형식을 그릴 수 있게 세 장치를 넣는다: **A1 장면 전환 효과**(줌블러·검은 1프레임 — 흰 번쩍은 이미 있음) · **A4 배경음 나레 덕킹**(+곡 추천 자리) · **B1 게시글형·전체화면 틀**(`frame.kind`). 전부 **판 설정 칸으로만** 켜진다 — 코드에 채널 이름 금지.

## 실측 배경(10-24, `tools/calcopy/hybrid/render_bench.py` 687줄)
- 흰 번쩍: `render_base`(444~461) 가 `placed.flashes` 를 `frame.flash_sec`(0.1) 동안 흰 바탕으로 그림. 줌블러·검은 프레임 없음. 컷 조각 = `clip()`(385~) → `render_window()`(410~)이 조각을 concat.
- 소리: `audio()`(515~569) — BGM `db_below_voice`, 덕킹은 **원음 구간만**(`duck_orig_db`, `volume='if(between(t,…))'`). 나레 구간 덕킹 없음(이븐쇼핑 벤치 실측 '말할 때 줄어듦' — 카드 evenshopping sound). 곡은 `bgm.id`(사람이 고름).
- 틀: `frame_png()`(190~257) — bg·window·title(줄마다 font·px·center/ink_top/box·shear·color·hi)·logo(text|spr_gold|null)·credit·watermark·comment·product_tag·ps_line(굿레터). **게시글형**(방구석·yummyknow·재밌쇼: 머리띠·작성자 줄·본문 상자·조회수 줄·반응 짤 자리)과 **전체화면 가운데 자막**(두유노·이븐쇼핑 = 숏템 t11)은 못 그린다 → 그 채널들이 `preset_make`(설명서 frame.json) 를 쓰는 이유.
- 효과음: `sfx_files`+`placed.sfx` 로 섞음(gain_db). 전환 효과음은 별개가 아니라 `placed.sfx kind=whoosh` 로 이미 가능.

## 설계(판단 주인 — 전부 render_bench 안, 칸 이름은 03·04 와 같은 글자)
1. **전환(A1)**: `placed.transitions:[{t, kind:cut|flash|zoomblur|black, ms}]` 를 받아(03 이 만든다) `render_window()` 가 컷 경계에 그린다. `flash` 는 지금 `flashes` 와 **같은 길**로 통일(두 벌 금지 — `flashes` 는 `transitions kind=flash` 로 읽히게 하고 옛 키는 변환만). `zoompan`+`gblur` 또는 `xfade=transition=…` 로 0.1~0.25초. 판 칸 `cuts.transition{kinds:{cut:…,flash:…,zoomblur:…,black:…}, ms, why}` 기본 `_common` = `{kinds:{cut:1.0}, ms:0}`.
2. **BGM 덕킹(A4)**: `bgm.duck_narr_db`(기본 0 = 없음) — 나레 조각 구간(`T["lines"]` tts) 에서 `volume` 식에 더한다. 곡 추천 `bgm_pick.py recommend <판|벤치 src>` = 벤치 소리의 템포·밝기(`engine/sound/bgm_fp.py` 신호) ↔ `shopping_shorts/assets/bgm_lib`(25곡) 거리 상위 3 — **판 `bgm.id` 는 사람이 적는다**(추천은 `bgm.candidates` 칸에).
3. **틀 종류(B1)**: `frame.kind` = `window`(지금 꼴, 기본) · `post`(게시글: `post{head_bar, author_line, body_box, views_line, meme_slot}` 좌표·색·글꼴) · `full`(전체화면 + 가운데 자막 띠, 창 = 전체). `frame_png` 가 kind 로 갈린다. 좌표 출처는 설명서 frame.json(`channel/banggu/preset/게시글형/frame.json` 등) — 07 의 `frame_import.py` 가 옮긴다. 여기서는 그릴 수 있게만.
4. `render_info.json` 에 `devices:{transition, duck_narr, frame_kind}` 표식 + `style_sha`(판 파일 sha) — 04 의 표식 검사가 읽는다.


## 합격 검사(사보타주 먼저)
1. 전환: 시험 판(`styles/_test_transition.json`, base 키치잇판, `cuts.transition.kinds.zoomblur:1.0 ms:200`)으로 렌더 → 컷 경계 ±0.2초 0.1초 띠에서 **블러·확대가 실제로 보인다**(프레임 라플라시안 분산이 경계에서 ≥30% 떨어짐) · 같은 판 kinds cut:1.0 이면 변화 0. 고치기 전 코드로 같은 판을 돌리면 차이 0 이어야 한다(= 검사가 잡는다).
2. 덕킹: `duck_narr_db:-8` 켜고 렌더 → 나레 구간 BGM 대비가 끈 판보다 7~9dB 낮다(`ffmpeg ebur128` 구간 측정, 나레 wav 를 뺀 BGM 트랙만 따로 뽑아 잰다 — mix 에서 재지 마라).
3. 틀: `frame.kind:post` 로 0초 프레임 PNG → `kal_analyze framecmp` 로 `channel/banggu/preset/게시글형` 설명서 렌더(preset_make loo) 와 머리띠·본문 상자 좌표 ±4px·ΔE<5.
4. 회귀: 키치잇판 성시경을 고치기 전/후 렌더해 `final.mp4` 프레임 10장(1초 간격) 평균 절대차 <1.0(장치를 안 켠 판은 그림이 바뀌면 안 된다) + `bench_check` 10/10 그대로.
5. `render_info.json` 에 `devices`·`style_sha` 가 있다.
