# 🆕 발굴 축 노출 + 레시피 매칭 개선 (2026-08-21, 회사PC)

## 한 줄
발굴이 축별로 모은 채널을 **랭킹·채널관리 두 화면에서 볼 수 있게** 하고, 레시피 축의
오탐 원인('만들기')을 잡았다. 전부 라이브.

## ✅ 한 것

### 1. 랭킹에 '발굴 축' 줄 (유튜브 전용)
`레퍼런스 랭킹 → ▶️유튜브 → 발굴 축` — `✨전체 · 🎬썰쇼핑 · ⭐연예인 · 🍳레시피`
- **Phase 2를 만들 필요가 없었다.** 처음엔 "유튜브 채널 기반 수집이 없어 못 본다"고
  판단했으나 **틀렸다**(refs.html의 낡은 경고와 조회수 스냅샷만 보고 말한 것).
  실제 수집분 9,499건에 채널 정보가 그대로 있었다 — `username`이 곧 `channel_id`다.
  **데이터는 있었고 이름표만 없었다.**
- `store.channel_style_map()` 한 곳에서만 조회(0순위-B)
- **이번 목록에 실제로 있는 축만** 버튼으로 낸다(눌러도 0건인 버튼은 고장으로 보인다)
- 플랫폼을 바꾸면 축을 비운다(안 비우면 인스타에서 목록이 통째로 빈다)

### 2. 채널관리(/refs)에 스타일 배지 + 채널명
유튜브 시드는 값이 URL이라 화면에 ID만 떴다. 발굴이 저장해 둔 채널명·스타일을 함께 준다.
검색창에 `신기템`을 치면 그 축만 모인다.

### 3. ★신기템 탭은 숨김 (사장님 지시)
`STYLE_LABELS` → `STYLE_HIDDEN`으로 옮김. **판정·수집은 그대로 돈다.**
되살리려면 `index.html`의 `STYLE_HIDDEN`에서 `STYLE_LABELS`로 한 줄 옮기면 된다.
(지우지 않은 이유: 지우면 나중에 왜 없는지 아무도 모른다)

### 4. 레시피 매칭 개선 — 범인은 `"만들기"`
```
실측: 레시피 축 311건 중 실제 레시피 87건(28%) · 홈템 127 · 기타 90
범인: _FOOD의 '만들기' → 슬라임·캔디백·스퀴시 공예가 통째로 유입(키포kipo 채널)
처방: _MAKE 분리 + _CRAFT(슬라임·스퀴시·asmr·배너·도안…) 있으면 요리로 안 침
결과: 286 → 136건, 공예 오탐 0
```
★`_KITCHEN`과 **같은 성격**이었다 — 08-19에 '주방'으로 같은 사고를 겪고 "단독으로는
신호가 못 된다"고 고쳤는데 '만들기'는 그대로 뒀다. **한 번 배운 교훈은 같은 모양의
다른 단어에도 적용해야 한다.**
판정은 `yt_style.is_food_title()` 한 곳에서만 — 채널 발굴과 랭킹이 같은 잣대를 쓴다.

## ⚠️ 배운 것 — 측정 방식을 두 번 틀렸다
1. 레시피 정확도를 `category='홈템'`으로 쟀는데 **열어보니 대부분 진짜 요리**였다
   ("Greek 요거트 반값"·"깍두기레시피"). 해시태그 `#살림 #꿀템` 때문에 **자동 카테고리가
   잘못 준 것**이지 필터 문제가 아니었다. → 정확도를 category로 재면 안 된다.
2. 신기템 영상도 채널과 같은 기준(기능 관형어+제품)으로 재검사했더니 **진짜가 잘렸다**
   ("나만 몰랐던 불편 해결 쿠팡 아이디어템"엔 기능 관형어가 없다). → **채널을 고르는
   문턱과 영상을 거르는 문턱은 성격이 다르다.** 채널은 "공식이 있는 편이 몇 편인가",
   영상은 "명백히 딴 장르인 것만" 뺀다(재현율을 안 깎는다).
