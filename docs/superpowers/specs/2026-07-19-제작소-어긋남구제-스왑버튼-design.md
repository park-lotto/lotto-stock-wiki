# 제작소 어긋남 구제 — ①[다른 화면으로] 스왑 버튼 (design)

**작성:** 2026-07-19 / 트랙 `제작소어긋남구제`
**범위:** 우선순위 1번(스왑 버튼)만. 2~5번(완성도 신호등·글자카드·역할패스 카테고리·라이브러리 채우기)은 후속 스펙.

---

## 1. 목표

대본(비트)의 바탕영상이 말과 어긋날 때(`fit ≤ 2`), 60대 사용자가 **대본을 다시 쓰거나 소스 영상을 찾지 않고**, 그 비트에 어울리는 **다른 소스 구간을 썸네일 보고 한 번 눌러 교체**하게 한다.

## 2. 문제 (지금 왜 안 되나)

`produce.html:2339`의 `fit ≤ 2` 안내는 이렇게 뜬다:

> ⚠️ "이 문장에 맞는 영상이 부족합니다 — 대본을 살짝 **바꾸거나** 소스 영상을 **추가하세요**."

해결을 전부 사용자 수작업(대본 재작성·소스 추가)으로 떠넘긴다. 캡컷 못 쓰는 60대(시니어 북극성)에겐 불가능한 두 가지다. 반면 **소스 인벤토리 안에는 안 쓴 구간이 많이 남아 있다** — 그중 더 맞는 걸 고르기만 하면 되는데, 그 UI가 없다.

## 3. 이미 있는 것 (새로 만들지 말 것)

| 조각 | 위치 | 재활용 |
|---|---|---|
| **스왑 백엔드** `/api/mix/adjust` | `app.py:1426` | `{job_id, beat_idx, seg_id}` → 전체 extract 인벤토리에서 seg 되붙여 `beat.primary` 교체. seg_id만 신뢰(클라 video_id/시각 위조 방지). **그대로 씀** |
| **fit 신호(1~5)** | `edit_plan` 계산 → `produce.html:2338` 표시 | 스왑 대상 비트 식별에 씀 |
| **프레임 추출** `extract_frame_at(video, dir, sec, filename)` | `frame_extract.py`, 사용례 `app.py:976`(wiki poster: 추출 1회→jpg 캐시→서빙) | seg 썸네일에 **같은 패턴** 재사용 |
| **소스 영상 파일** | 믹스 잡 work dir(미리보기·렌더가 이미 씀) | seg 썸네일 추출 소스 |
| 결과 서빙 `/api/mix/result` | `app.py:1388` | `beats`만 내려줌 — **후보 seg 목록은 안 내려줌**(이게 빠진 배선) |

즉 **스왑 동작 자체는 완성돼 있다.** 빠진 건 (a) 후보 seg 목록 노출 (b) seg 썸네일 (c) 프런트 버튼·피커뿐.

## 4. 설계

### 4-1. 백엔드 (작음, 2개 추가 + 1개 재활용)

**(A) 후보 seg 인벤토리 노출** — 신규 `GET /api/mix/segments/{job_id}`
- `job["extract"]`의 모든 세그먼트를 `_build_inventory`의 `seg_map`으로 만들어 배열 반환:
  `[{seg_id, video_id, start, end, dur, scene_desc, thumb_url}]`
- `thumb_url = /api/mix/seg_thumb/{job_id}/{seg_id}`
- 이미 어느 비트의 primary로 쓰인 seg_id는 `used:true` 플래그(피커에서 흐리게).
- (대안: `/api/mix/result`에 `segments` 키를 얹기. 별 엔드포인트가 더 깔끔 — result는 이미 크고 여러 트랙이 만짐.)

**(B) seg 썸네일** — 신규 `GET /api/mix/seg_thumb/{job_id}/{seg_id}`
- `seg_map`에서 seg의 `video_id·start·end` → 소스 mp4 경로 → `extract_frame_at(mp4, _THUMB_DIR, (start+end)/2, filename=f"{job_id}_{seg_id}.jpg")`
- 캐시 존재하면 바로 `FileResponse`(api_wiki_poster와 동일 구조). seg_id 인벤토리에 없으면 404.

**(C) 스왑** — 기존 `POST /api/mix/adjust` 그대로. 추가 작업 없음.

### 4-2. 프런트 (`produce.html`, `renderMixReview`/`renderSceneCutaway` 영역 ~2333–2397)

각 비트 카드에 버튼 하나. `fit ≤ 2` 비트는 강조(빨강 테두리 + 자동 펼침), 나머지는 접힌 상태.

```
[비트 카드]
 🎞 바탕: (현재 primary scene_desc)   · 매칭 2/5 ⚠️
 [ 다른 화면으로 ▾ ]     ← 큰 버튼. 누르면 피커 열림
   └ 피커: 후보 seg 썸네일 그리드(가로 스크롤)
       각 칸 = 썸네일 + scene_desc 1줄 + 길이
       칸을 '탭' 하면 → POST /api/mix/adjust → 이 비트만 갱신
       (이미 쓴 seg = 흐리게 'used' 배지)
```

**시니어 UX 원칙(못박음):**
- **탭 = 선택.** 슬라이더·드래그·타이핑 없음(자막싱크 트랙의 "버튼만" 원칙과 동일).
- 썸네일이 주(主), 글자(scene_desc)는 보조 — Gemini scene_desc는 모호할 수 있어 그림으로 판단하게.
- 교체 즉시 그 비트 카드만 다시 그린다(공용 프리뷰 `mixPreview`/`hcPreview`는 안 건드림 — 기존 주석 `produce.html:2360` 규율 준수).
- 교체 후 그 비트는 **사람이 고른 것**이므로 `fit` 경고를 지운다(`match_type` 흐름의 '직접 넣음'과 같은 신뢰 처리) — 스왑된 primary에 `swapped:true` 표식, 렌더 무관 메타.

### 4-3. 스왑 후 fit 재계산은? → 안 한다(의도적)
`fit` 재계산엔 Gemini 콜이 든다. 사용자가 **썸네일을 눈으로 보고** 고른 것이므로 사람 판단을 신뢰하고 경고만 해제한다. (자동 fit 재산정은 YAGNI — 필요해지면 후속.)

## 5. 확정한 결정 (묻지 않고 진행)

1. 썸네일 = `extract_frame_at` 중간지점 프레임, `_THUMB_DIR` 캐시. (텍스트-only 아님 — 시니어에겐 그림 필수.)
2. 후보 목록 = 별 엔드포인트 `/api/mix/segments/{job_id}`. (result에 안 얹음 — 공유 파일 충돌 축소.)
3. 스왑 후 fit 경고 해제, 재계산 없음.
4. 버튼은 모든 비트에 있되 `fit ≤ 2`만 자동 펼침·강조.
