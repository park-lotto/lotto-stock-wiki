# 칼카피 소재창고 API (관제 097, 2026-10-16)

> 판단 주인: `shopping_shorts/calcopy_topics.py` **하나**. 화면(보드)·워커(실행기)·사람 검수는 전부 아래 API만 부른다.
> 원장: `DATA_DIR/calcopy/topics.db`(sqlite, git 밖) · 산출물: `DATA_DIR/calcopy/topics/<id>/`.
> `DATA_DIR` = 환경변수 `CALCOPY_DATA_DIR`가 있으면 그것, 없으면 `shopping_shorts/data`(calcopy_board 보관함과 같은 곳).
> 전부 **관리자 전용**(`_require_admin`, 아니면 403). 화면은 숫자를 계산하지 않는다 — KPI·끊김·상한 판정은 서버가 준다.

## 1. 상태기계

```
found ─bench→ benched ─score→ scored ─assign→ assigned ─script→ scripted ─source→ sourced ─plan→ plan_review(사람)
   ─통과→ producing ─produce→ produced ─check→ final_review(사람) ─통과→ passed
                                             (어느 검수든) ─반려→ rejected(사유, back_to)
```

| 지금 상태 | 다음 일(step) | 누가 | 끝나면 |
|---|---|---|---|
| found | `bench` | 워커 | benched |
| benched | `score` | 워커 | scored |
| scored | `assign` | 워커 | assigned |
| assigned | `script` | 워커 | scripted |
| scripted | `source` | 워커 | sourced |
| sourced | `plan` (계획.md 제출) | 워커 | plan_review |
| **plan_review** | `review` | **사람만** | 통과 → producing / 반려 → rejected |
| producing | `produce` | 워커 | produced |
| produced | `check` (규칙표·판정 사유 제출) | 워커 | final_review |
| **final_review** | `review` | **사람만** | 통과 → passed / 반려 → rejected |
| rejected | back_to 상태의 step | 워커 | claim 하는 순간 상태가 back_to 로 돌아감(rework_n+1) |
| passed | — | — | 끝 |

- 워커는 검수 두 자리를 **못 넘는다**: plan_review·final_review 에서 claim/advance 하면 409 `{"error": "사람 검수 자리(plan_review) — 워커는 넘지 못합니다"}`.
- 반려에 `back_to` 를 안 주면(null) **폐기**(rejected 에 머묾, 다음 일 없음).
- `back_to` 는 `found|benched|scored|assigned|scripted|sourced|producing|produced` 중 하나.

### step 마다 advance 에 꼭 있어야 하는 것 (없으면 400, 이유를 적어 거절)

| step | 필수 |
|---|---|
| bench | `data.bench` (비어 있지 않은 객체. 새 소재면 `{"skipped": "새 소재 — 벤치 영상 없음"}`도 됨) |
| score | `data.score.criteria` 에 **5기준** 각각 `{score, why}` |
| assign | `data.assign.channel` · `data.assign.preset` |
| script | 산출물 `script` |
| source | `data.rights` (재료별 출처 종류, 비어 있지 않음) |
| plan | 산출물 `plan` (계획.md) |
| produce | 산출물 `final` (완성본) |
| check | 산출물 `verdict` (판정 사유) |

산출물 = 토픽 폴더 안 파일 이름. advance 의 `files` 로 글(텍스트)을 같이 보내면 서버가 먼저 쓰고, 큰 파일은 `upload` 로 먼저 올린다. **폴더에 실제로 없는 이름은 거절**(가짜 산출물 금지).

## 2. 잠금·heartbeat·끊김

- claim 하면 그 토픽은 `worker` 가 잠근다(`lock.owner/step/at/heartbeat_at`). 다른 워커의 claim 은 409 `잠김`.
- 워커는 30초~수 분마다 `heartbeat`. **마지막 신호가 11분 넘으면 끊김** — 다음 claim·board 조회 때 서버가 잠금을 풀고 이력에 `expire` 로 남긴다(`last_error = "끊김 해제: <워커> <step> 마지막 신호 <시각>"`).
- advance·release 는 잠근 워커만(다르면 409). advance 하면 잠금이 풀린다.
- 일을 못 하겠으면 `release` 에 `error` 를 **반드시** 적는다(상태는 그대로, 보드에 빨강).

## 3. 비용 상한(하루, KST 날짜)

- 종류: `gemini`(제미나이 호출 수) · `typecast`(타입캐스트 생성 횟수). 기본 상한 gemini 500 · typecast 30 (임시값, `caps` 로 바꿈).
- step 이 쓰는 종류: bench·score·script·source·check = gemini / produce = typecast / assign·plan = 없음.
- 오늘 사용량이 상한 이상이면 그 종류를 쓰는 step 의 claim 을 429 로 거절: `{"error": "하루 상한: typecast 30/30 (2026-10-16) — produce 멈춤"}`. 보드 `caps.blocked_steps` 에 뜬다.
- 사용량은 advance 의 `cost: {"gemini": 3, "typecast": 1}` 로 적는다(토픽 누적 + 하루 장부).

## 4. 라우트

공통 오류 모양: `{"error": "<한국어 이유>"}` + 상태코드(400 입력 틀림 · 404 없는 토픽 · 409 상태·잠금 충돌 · 429 비용 상한).
성공 응답의 `topic` 은 §5 의 토픽 모양.

### POST /api/admin/calcopy/topics — 소재 추가
```json
{"name": "LED 세면대 수도꼭지", "category": "홈템", "track": "discover",
 "source": {"via": "douyin", "url": "https://…", "found_at": "2026-10-16T08:00:00+09:00", "expires": "2026-10-23"},
 "by": "topic_find@TheRose", "note": "선택"}
```
→ `{"ok": true, "topic": {…state: "found"…}}`. `track` 은 `bench|discover`. `name`·`category` 필수. 같은 이름+카테고리가 passed/rejected(폐기) 아닌 채로 있으면 409(중복 소재).

### POST /api/admin/calcopy/topics/claim_next — 워커가 다음 일 하나 집기
```json
{"worker": "TheRose-1", "steps": ["bench", "score", "script"]}
```
→ 집을 게 있으면 `{"ok": true, "topic": {…}, "step": "bench"}`, 없으면 `{"ok": true, "topic": null, "reasons": ["produce: 하루 상한 typecast 30/30", "잠김 2건"]}`(왜 없는지).
오래된 토픽부터. rejected(back_to 있음)는 back_to 의 step 으로 집힌다.

### POST /api/admin/calcopy/topics/{id}/claim
```json
{"worker": "TheRose-1", "step": "bench"}
```
→ `{"ok": true, "topic": {…}, "step": "bench"}`.
거절 예: 409 `{"error": "지금 상태(scored)의 다음 일은 assign 입니다 — bench 아님"}` · 409 `잠김: TheRose-2 가 script 중(마지막 신호 14:31:07, 42초 전)` · 409 사람 검수 자리 · 429 하루 상한.

### POST /api/admin/calcopy/topics/{id}/heartbeat
```json
{"worker": "TheRose-1", "doing": "대본 3/6줄"}
```
→ `{"ok": true, "heartbeat_at": "…"}`. 잠근 워커가 아니면 409.

### POST /api/admin/calcopy/topics/{id}/advance
```json
{"worker": "TheRose-1",
 "data": {"bench": {"videos": [{"url": "…", "views": 120000, "points": ["…"], "comments": ["…"]}]}},
 "outputs": {"plan": "계획.md"},
 "files": {"계획.md": "# 계획\n…"},
 "cost": {"gemini": 3},
 "note": "선택"}
```
- `data` 칸: `source · bench · score · assign · rights` (객체, 그 칸을 통째로 바꿈).
  - score 예: `{"criteria": {"공감": {"score": 4, "why": "…"}, "…5개"}, "overlap_penalty": -1, "overlap_with": ["…"], "showable": true, "total": 17}`
  - assign 예: `{"channel": "sseolpulda", "style": "A_흰바탕창", "preset": "channel/sseolpulda/preset/A_흰바탕창/창아래_검정"}`
  - rights 예: `{"컷1.mp4": "자체촬영", "컷2.jpg": "도우인 원본(참고)", "bgm": "무료 라이브러리"}`
- `outputs` 이름표: `plan·script·materials·final·rules·verdict` 등 자유, 값은 토픽 폴더 안 파일 이름.
→ `{"ok": true, "topic": {…state: 다음 상태…}}`. 잠금 해제.

### POST /api/admin/calcopy/topics/{id}/release — 워커가 손 뗌(실패 보고)
```json
{"worker": "TheRose-1", "error": "yt-dlp 차단: Sign in to confirm …(원문 200자)"}
```
→ `{"ok": true, "topic": {…last_error…}}`. `error` 없으면 400(조용한 실패 금지).

### POST /api/admin/calcopy/topics/{id}/reject — 관리자 반려(검수 자리 밖에서도)
```json
{"reason": "소재가 이미 3주 전 같은 채널에 나옴", "back_to": "found", "by": "fable"}
```
→ `{"ok": true, "topic": {…state: "rejected", back_to…}}`. `reason` 필수. 잠금이 있으면 같이 풀림.

### POST /api/admin/calcopy/topics/{id}/review — 사람 검수
```json
{"stage": "plan_review", "verdict": "pass", "by": "사장님", "reason": "선택(반려 땐 필수)", "back_to": "scripted"}
```
- 지금 상태 == `stage` 가 아니면 409.
- pass: plan_review → producing / final_review → passed.
- reject: rejected + back_to(검수 기록에 남고 KPI 통과율에 들어감).
→ `{"ok": true, "topic": {…}}`

### GET /api/admin/calcopy/topics/{id} — 상세
→ `{"topic": {…}, "files": [{"name": "계획.md", "size": 2048, "url": "/api/admin/calcopy/topics/7/file/계획.md"}], "history": [{"at": "…", "by": "…", "kind": "claim|advance|heartbeat 제외|release|expire|reject|review|add", "from": "…", "to": "…", "step": "…", "note": "…"}], "reviews": [{"stage": "plan_review", "verdict": "reject", "reason": "…", "back_to": "scripted", "by": "…", "at": "…"}], "cost_log": [{"day": "…", "kind": "gemini", "n": 3, "step": "bench"}]}`

### GET /api/admin/calcopy/topics/{id}/file/{name} — 산출물 받기
`_send_media` 로 내보냄(형식은 확장자로). 폴더 밖 이름(`..`·`/`)은 400.

### POST /api/admin/calcopy/topics/{id}/upload/{name} — 큰 산출물 올리기
요청 본문 = 파일 바이트 그대로. → `{"ok": true, "name": "완성본.mp4", "size": 12345678}`. 이름 규칙은 위와 같다. 이것만으로는 상태가 안 바뀐다 — advance 의 `outputs` 로 이름을 넘긴다.

### POST /api/admin/calcopy/topics/caps — 하루 상한 바꾸기
```json
{"gemini": 800, "typecast": 40}
```
→ `{"ok": true, "caps": {"gemini": 800, "typecast": 40}}`. 0 이상 정수.

## 6. 보완 (10-16, 보드·워커 실측 요청 — `2026-10-16-소재창고-보드-워커-design.md` §7 "규격 차이" 1~4)

### 6-1. claim_next 거르기
```json
{"worker": "FOOD-1", "steps": ["bench", "score"], "category": "식품", "track": "discover", "channel": "yummyknow"}
```
- `category`·`track`·`channel` 각각 문자열 또는 문자열 목록(선택). `channel` 은 `assign.channel` 로 거른다 — **배정 전 소재(found~scored)는 channel 을 주면 안 잡힌다**.
- 없으면 `reasons` 끝에 거른 조건이 붙는다: `"['bench'] {\"category\": [\"식품\"]} 할 소재 없음"`.

### 6-2. 실패 뒤 대기·멈춤(stalled)
- `release` 에 `retry_after_min`(기본 30) — 그동안 **claim_next 가 그 행을 건너뛴다**(reasons `"실패 뒤 다시 시도 대기 N건"`). 직접 `{id}/claim` 은 대기를 무시한다(id 를 찍어 부르는 것은 의도).
- 실패 횟수 `error_count` 는 release 와 **11분 끊김(expire)** 둘 다 센다. 끊김은 죽은 워커 몫이라 대기 없이 곧바로 다른 워커가 인수한다.
- `error_count` 3 이면 `stalled: true` — claim_next 는 건너뛰고(reasons `"멈춤(stalled) N건 — 사람이 unstall"`), 직접 claim 도 409. 보드 `stalled` 칸에 고정.
- advance 성공하면 `error_count=0`, `retry_at=null`. 관리자 reject 도 실패 기록을 지운다.
- **POST /api/admin/calcopy/topics/{id}/unstall** `{"by": "사장님", "note": "쿠키 갈았음"}` → `{"ok": true, "topic": {…stalled: false, error_count: 0, last_error: null…}}`. 실패 기록이 없으면 409. 이력에 `unstall`(지난 실패 횟수·마지막 오류)이 남는다.

### 6-3. 워커 맥박
**POST /api/admin/calcopy/workers/heartbeat**
```json
{"worker": "FOOD-1", "category": "식품", "track": "discover", "channel": null, "doing": "find", "idle_reason": "find 실패: 도우인 로그인벽", "last_error": null}
```
→ `{"ok": true, "worker": "FOOD-1", "seen_at": "…"}`. `worker` 없으면 400. claim·heartbeat·advance·release·claim_next 도 같은 표를 갱신한다.

보드 `workers` 한 줄 모양(잡은 일이 있으면 소재마다 한 줄, 없으면 쉬는 워커 한 줄 — 마지막 맥박 24시간 안만):
```json
{"worker": "FOOD-1", "status": "working|idle|stale", "topic_id": null, "name": null, "step": null,
 "heartbeat_at": "…", "age_sec": 42, "stale": false, "doing": "find", "category": "식품", "track": "discover",
 "channel": null, "idle_reason": "find 실패: 도우인 로그인벽", "last_error": null}
```
`stale` = 마지막 신호 11분 넘음(잡은 일이면 그 소재 잠금의 신호, 쉬는 워커면 맥박).
보드에 `stalled: [{"id", "name", "state", "error_count", "error"}]` 칸이 생겼다('멈춘 이유').

### 6-4. 비용 `seconds`
- `advance` 의 `cost` 에 `seconds`(그 단계에 실제로 든 초) — 토픽 `cost.seconds` 누적, 하루 장부 `caps.used.seconds`. **상한은 없다**(`caps` 에 seconds 를 주면 400).
- KPI `work_min_per_passed: {"n", "avg", "median"}`(분) — passed 소재의 seconds 합. 벽시계 `hours_per_passed`(추가→통과)와 따로 둔다. `cost_per_passed` 에도 `seconds` 가 붙는다.
- 토픽 모양에 `cost.seconds` · `error_count` · `retry_at` · `stalled` 가 추가됐다(§5).
