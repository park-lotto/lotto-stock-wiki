# 수집 흡수 배선 재편 + 제미니 일일 검열 — 설계

- 날짜: 2026-07-23
- 트랙: `수집검열`
- 승인: 사장님 (2026-07-23, "진행")

## 배경 / 문제

"정말 좋은 영상에서 훅 + 스토리구조 대본을 통째로 계속 은행에 업그레이드"가 핵심 가치인데:

1. **은행 적재가 밤 4시 크론에 묶여 있다는 오해** — 실제로는 수집 버튼(`/api/collect`)이
   이미 `_bank_ingest_collected_bg → ingest_collected`를 부르지만, 사장님 수집 때 실행 이력이
   없어(`bank_ingest_last` 비어 있음) "수집해도 은행이 안 찬다"고 느낌. 훅수확은 4시 크론에만 있음.
2. **훅 오염** — 오늘 흡수 실측: 훅 46개 중 12개(26%)가 실제 훅이 아니라 인스타 참여유도 멘트
   ("댓글에 남겨주세요/프로필 링크/팔로우 후 DM").
3. **제미니 품질 무감지** — 오늘 497편 심사 중 33편만 흡수(93% 실패). 원인은 제미니 429
   (무료티어 분당 15). 이걸 매일 감지하는 장치가 없어 조용히 실패해도 모름.
   ※ 사장님: 제미니 키 여분 많음 → 429는 쿼터 부족이 아니라 **키풀 로테이션 부하분산 문제**일 개연성.

## 목표

- 은행에 새 대본·훅 넣는 일은 **수집 버튼**에서 즉시. 밤 4시는 **유지보수만**.
- **스팸성 훅**을 결정적 필터로 차단.
- **제미니 검열**을 매일 대시보드 패널로: 가동 성공률 · 산출 완성도 · 산출 품질.

## 비목표 (YAGNI)

- 유료키 전환 자동화 — 검열이 근거 데이터를 쌓으면 사람이 판단.
- 텔레그램 알림 — 이번엔 대시보드 패널만.
- 키풀 로테이션 로직 수정 — 별도 조사/트랙. (검열이 신호만 제공)

## 컴포넌트

### A. 흡수 배선 재편

| 위치 | 변경 |
|---|---|
| `app.py::_bank_ingest_collected_bg` | `ingest_collected` 뒤에 `daily_batch.harvest_hooks(store)` 호출 추가. 반환 카운트를 리포트에 합침. |
| `daily_batch.py::run` | `harvest_hooks` 호출 제거(버튼으로 이관). backfill·stats·ingest_crawl_winners·perf·spine 유지. |
| crontab | **변경 없음** — 4시 크론은 유지보수용으로 계속. |

`ingest_crawl_winners`는 4시에 유지(낮에 대본추출된 우승작을 줍는 청소 성격 · 수집 직후엔 대본
미추출이라 0건).

### B. 스팸성 훅 필터

`hook_harvest.py`에 순수함수 `is_engagement_bait(text) -> bool` 신설. 판별 키워드(부분일치):
`댓글`, `프로필`, `팔로우`, `DM`, `디엠`, `남겨주`, `정보 전송`, `정보 보내`, `링크 No`, `아무 글자`,
`아무글자`, `두 글자`, `두글자`, `요청함`, `숨김함`. 하나라도 걸리면 True.

적용 두 곳:
1. `hook_harvest.harvest_hooks_from_crawl` — 캡션 첫 줄이 bait면 pending 추가 스킵.
2. `pattern_bank.ingest_script` — structure_json의 `hook` 부품을 `add_pattern_item("hook", ...)`
   하기 직전 bait면 스킵. (오늘 26% 오염이 여기서 발생.)

차단 건수는 검열 리포트 `hook_bait_blocked`로 집계.

### C. 제미니 일일 검열 — `gemini_audit`

`pattern_bank.ingest_collected`가 반환하는 리포트에 검열 필드를 추가로 계산. 기존 반환에는
`considered/added_sources/added_items/skipped_dup/skipped_short/by_bucket`가 있음. 추가:

- **가동 성공률**: `attempted`(중복·짧은 것 제외 후 실제 제미니 호출한 수), `succeeded`(=added_sources),
  `failed`(= attempted − succeeded, 대부분 429/에러). `success_rate = succeeded/attempted`.
  → 이를 위해 `ingest_script`가 성공/실패를 구분해 반환하거나, `ingest_collected`가
  ingest 결과 None/무-source_id를 `failed`로 카운트(현재 조용히 버려짐).
- **산출 완성도**: 성공한 소스의 `structure_json`을 파싱해 `hook` 있고 `spine.beat_chain`(길이≥3)
  있고 부품 버킷 총합≥5인 비율 = `completeness_rate`.
- **산출 품질**: `hook_spam_ratio`(차단 전 훅 중 bait 비율), `spine_valid_ratio`(beat_chain이
  리스트이고 길이≥3인 비율).

신호등 규칙(순수함수 `audit_health(metrics) -> {level, reasons[]}`):
- `success_rate < 0.5` → 🔴, reason "쿼터/에러로 대량 실패".
- `completeness_rate < 0.7` → 🟡.
- `hook_spam_ratio > 0.15` → 🟡.
- 아무것도 안 걸리면 🟢.

검열 결과는 `_bank_ingest_collected_bg`가 `gemini_audit_last` 설정에도 저장(리포트와 분리해
검열만 따로 읽기 쉽게).

### D. 대시보드 패널

`/api/bank/ingest_report`(이미 존재)의 payload를 확장: 기존 흡수 리포트 + `gemini_audit`.
수집 화면 프론트에 패널 1개 추가:

```
📦 오늘 은행 흡수: 우승영상 {added_sources}편 · 부품 {added_items}개
   (훅 {hook} · 스토리구조 {conflict+emotion+evidence+spine} · 스타일 {adverb+cta+ending+price})
🤖 제미니 검열: {🟢/🟡/🔴}
   성공률 {success_rate}% ({succeeded}/{attempted}) · 완성도 {completeness}% · 훅스팸 {spam}%(차단 {blocked})
   {reasons를 ⚠️ 줄로}
```

패널은 수집 후 폴링으로 갱신(기존 폴링 재사용).

## 데이터 흐름

```
[수집 버튼] /api/collect
  └ background: _bank_ingest_collected_bg(items)
       ├ ingest_collected(items)         → 부품 적재 + 검열지표 계산 + 스팸훅 차단
       │    └ (내부) ingest_script × N   → structure_json 분해, bait 훅 스킵
       ├ harvest_hooks(store)            → 우승작 훅 수확(bait 스킵)
       ├ auto_approve_style_buckets()
       ├ set_setting("bank_ingest_last", 흡수리포트)
       └ set_setting("gemini_audit_last", 검열)
[수집 화면] /api/bank/ingest_report 폴링 → 패널 렌더
[밤 4시] daily_batch.run → 유지보수만(harvest 제외)
```

## 에러 처리

- 부가기능이라 개별 실패는 삼키고 계속(기존 정책 유지). 검열 계산 실패 시 `gemini_audit`=null,
  패널은 "검열 데이터 없음" 표기.
- `ingest_script`의 제미니 429는 이미 삼켜짐 — 이제 `failed` 카운트로 **가시화**만 한다(재시도 로직
  변경 없음).
