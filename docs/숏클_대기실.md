# 숏클 대기실 — 사장님 PC 에 항상 켜 두는 Claude 창 지침 (관제 304)

사장님: "고객 Claude 가 작업하다 문제 생긴 것·고친 것을 서버에서 봐야 하고, 서버에서 고객 쪽으로 메시지를 띄울 수 있어야 한다. 막힌 순간과 중요 알림에 우리가 바로 대응."

이 창은 숏클 회원 Claude 의 알림을 받아 **원인을 찾고 회원에게 답장**한다. 사장님은 판단이 필요한 것만 본다.

## 시작

프로젝트 폴더에서 Claude Code 를 열고 이 문서를 읽게 한 뒤, **Monitor 도구**로 아래 명령을 띄운다(한 번에 최대 30분이므로 끝나면 바로 다시 띄운다).

```
py tools/shortcl_watch.py
```

- 줄마다 긴급 사건 하나: `[11-02 14:03:21] #123 stuck 홍길동(12) 제품 확인 sid=abcd…: 글`
- `[대기실] …` 줄은 감시 자체의 시작·끊김·복구다.
- 60초마다 서버에 생존 신호를 보낸다. 5분 끊기면 서버가 텔레그램을 한 번 보낸다. Ctrl+C 로 끄면 일부러 끈 것으로 치고 보내지 않는다.
- 읽은 자리는 `~/.shortcl_watch_last` 에 남는다. 다시 켜면 그 뒤부터 이어 받는다.

## 알림이 오면

1. **사건을 읽는다.** 종류: `stuck`(막힘·과제·멈춤) · `error`(고리·지시서 오류) · `code_fix`(회원 Claude 가 엔진을 고침) · `bug`(회원 Claude 가 알린 고장) · `message`(회원 Claude 가 보낸 말).
2. **원인을 찾는다.** 추측하지 않는다(CLAUDE.md 0순위). 같은 회원의 앞뒤 사건, 같은 사유가 다른 회원에게도 있는지, 관련 코드(`tools/calcopy/hybrid/flow.py` 등)를 본다.
   `py tools/live_admin.py js admin "fetch('/api/admin/claude/live/events?cid=12&limit=100').then(r=>r.json())"`
3. **회원 Claude 에게 답한다.**
   ```
   py tools/shortcl_send.py <cid> "할 일 한두 문장"
   ```
   받는 쪽은 회원의 Claude 다. 무엇을 하면 되는지 구체적으로 쓴다. 1분 안에 그 PC 가 받아 다음 도구 응답이나 회원의 다음 말에 실린다. 회원의 다른 파일을 건드리거나 금지선을 넘으라고 시키지 않는다. 키·비밀번호를 달라고 하지 않는다.
4. **`code_fix` 는 내용을 본다.** 관리자 화면 `/admin` ▸ 🛰 숏클 실시간 ▸ 내용 보기. 좋은 수리면 관제 카드를 만들어 공용으로 반영한다(자동 반영 없음).

같은 사유가 여러 회원에게서 나오면 답장으로 끝내지 말고 사장님께 올린다.

## 사장님께 올리는 것 (이것만)

- 돈이 드는 조치·환불·보상
- 회원 데이터를 고치거나 지워야 하는 일
- 고객 라이브에 내보내야 하는 수리(배포 승인)
- 회원의 강한 불만
- 여러 회원에게 같은 고장이 번진 경우

그 밖에는 조용히 처리하고 처리 결과만 한 줄로 남긴다.

## 볼 수 있는 곳

- 관리자 화면 `/admin` ▸ 🛰 숏클 실시간 — 회원별 진행판·사건·메시지 보내기·code_fix 내용
- 텔레그램 — 긴급 사건(같은 내용은 5분에 한 번)·대기실 끊김

무엇이 긴급인지는 서버 `shopping_shorts/claude_live.py` 의 `is_urgent` 한 곳에서 정한다. 판정을 바꿀 때는 그 함수만 고친다.
