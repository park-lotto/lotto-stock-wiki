yt-dlp를 직접 돌려 **잘리지 않은 stderr 전문**을 보니:

```
OSError: [Errno 28] No space left on device
  at yt_dlp/cookies.py:1305  (쿠키 파일 쓰기)
```

서버 디스크가 **100% (여유 0바이트)**였다. `df -h /` 실측.
yt-dlp가 쿠키 파일을 쓰려다 죽은 것이고, 유튜브는 우리를 막은 적이 없다.

### 앞뒤가 전부 맞는다

| 관찰된 증상 | 디스크로 설명 |
|---|---|
| 같은 요청이 5회 중 1회만 성공(20%) | 디스크가 찼다 비었다 반복 |
| **쿠키 쓰면 실패 / 안 쓰면 성공** | 쿠키 경로만 `_cookie_scratch_copy`로 **파일을 쓴다** → 디스크 차면 그쪽만 죽음 |
| 40분 뒤 재측정 18/18 성공 | 그 사이 공간이 확보됨 |
| `android`·`ios`가 죽은 것처럼 보임 | 그냥 그때 디스크가 찼던 것 |

## ★왜 세 번이나 오진했나 (같은 실수 반복)

| 내 진단 | 반증 | 왜 틀렸나 |
|---|---|---|
| "android·ios 클라이언트가 죽었다" | 반복 측정하니 기본도 됐다 안 됐다 | **한 번 재고** 단정 |
| "쿠키가 범인이다" | 40분 뒤 쿠키로도 18/18 성공 | **한 시점만** A/B (시간 효과를 쿠키 효과로 착각) |
| "24시간 43건 실패" | 실제 yt-dlp 실패는 **2건** | `grep -c 'rate-limit'`이 **제미니 429 43건**을 물어온 걸 안 열어봄 |

★**증상이 확률적이면 한 번 재고 판정하면 반드시 틀린다.** 반복·시간차 측정이 필수.
