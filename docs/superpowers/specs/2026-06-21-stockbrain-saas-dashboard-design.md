# 로또의 스탁브레인 — SaaS 구독형 인사이트 대시보드 설계

- **작성일**: 2026-06-21
- **상태**: 설계 승인 대기 → 구현 계획
- **목적**: 현재 AWS Lightsail에서 돌아가는 크롤링봇 위에, 구독자가 로그인해서 자기 맞춤 콘텐츠를 소비하는 웹 대시보드를 추가한다. Kmong·유튜브 채널에서 월구독으로 판매한다.

---

## 1. 제품 정의

- **유형**: 고객 로그인형 SaaS (구독자가 직접 사용)
- **핵심 가치**: 정보 소비·인사이트. 구독자가 자기 키워드·채널로 필터된 뉴스·리포트·유튜브·텔레그램·블로그를 한 화면에서 보고, AI 일간 브리핑과 시각화로 투자 인사이트를 얻는다.
- **참고 UI(블로그 포스팅 GUI)의 "AI 초안 편집·블로그 발행"은 범위에서 제외** — 이번 제품은 콘텐츠 생산이 아니라 소비·인사이트 도구다.
- **판매 채널**: Kmong("월 구독 서비스" 등록), 유튜브 채널(가입 유도)
- **전달 경로**: 텔레그램 개인 봇(기존) + 웹 대시보드(신규) 병행

## 2. 사용자 & 권한

| 역할 | 설명 | 접근 |
|------|------|------|
| 구독자 | 결제 후 관리자가 등록한 일반 유저 | 브리핑·피드·통계·설정 |
| 관리자(운영자) | 본인 | 위 전부 + 관리자 패널 |

- **가입·결제는 수동(B안)**: 결제 확인 후 관리자가 관리자 패널에서 계정 생성·만료일 설정. 결제 자동화는 이번 범위 밖 (구조만 나중에 붙일 수 있게 설계).

## 3. 화면 구성 (정보 구조)

상단 탭: `🏠 브리핑` · `📰 피드` · `📊 통계` · `⚙️ 설정` (+ 관리자에게만 `👑 관리자`)

| 탭 | 기능 | 수정/추가 동작 |
|----|------|----------------|
| 🏠 브리핑 | 오늘의 AI 종합 브리핑(수급빈집·주도섹터 등). "다시 생성" 버튼. 홈 화면. | 브리핑 재생성 |
| 📰 피드 | 내 키워드/채널로 필터된 뉴스·리포트·유튜브·텔레·블로그. 카테고리 서브탭 + 검색. 항목 클릭 시 상세+요약. | 즐겨찾기·읽음표시 |
| 📊 통계 | 키워드 트렌드·수집량·섹터 강도 차트. 기간 필터. | 기간 선택 |
| ⚙️ 설정 | 키워드/채널 추가·삭제, 수신 ON·OFF | ✅ 핵심 편집 영역 |

**레이아웃**: 홈은 "브리핑 먼저(결론형)" — 상단에 오늘의 AI 종합 브리핑, 그 아래 근거가 된 개별 피드. 피드 탭으로 들어가면 2패널(좌: 필터/카테고리, 우: 피드 카드 리스트+요약) 상세 뷰.

**⚙️ 설정 하위:**
- 🔑 키워드 — [+추가] [삭제]
- 📡 텔레채널 — URL 입력 → 등록 / 삭제
- 📺 유튜브 — URL 입력 → 등록 / 삭제
- ✍️ 블로그 — URL 입력 → 등록 / 삭제
- 🔔 수신설정 — 뉴스/리포트/유튜브/텔레/블로그 ON·OFF 토글

기존 텔레그램 봇 명령어(`/addkw`, `/addtg` 등)와 **동일 동작을 웹 클릭으로** 제공한다. 텔레봇 명령어도 병행 유지.

**👑 관리자 패널:** 구독자 목록 / 계정 생성·만료 설정 / 봇토큰 등록 / 발송 이력 조회.

## 4. 아키텍처 (접근법 B 채택)

**원칙: 기존 크롤링봇·file_server·main_v2를 일절 수정하지 않는다.** 대시보드는 새 파일로만 추가한다.

```
[크롤링봇 main_v2.py]  ──수집──▶  output/md/{날짜}/{카테고리}/*.md   (기존, 무손상)
                                          │  (읽기 전용)
[신규] dashboard_server.py (FastAPI, 포트 8080)
   ├─ 인증: user_store + JWT
   ├─ GET  /api/feed       → 로그인 유저 키워드로 MD 필터 → JSON
   ├─ GET  /api/briefing   → 오늘 유저 콘텐츠 AI 종합요약 (캐싱)
   ├─ GET  /api/stats      → 수집량·키워드 빈도 집계
   ├─ GET/POST/DELETE /api/settings/*  → 키워드/채널 추가·삭제 (user_store 호출)
   └─ /api/admin/*         → 구독자 관리 (관리자 전용)
        │
        ▼
   정적 대시보드 (HTML/JS/CSS, 검정+골드+Instrument Serif)
   접속: http://3.39.179.148:8080  (테스트) → 추후 도메인
```

- **빌드 도구 없음**: 순수 HTML/JS/CSS. node·번들러 불필요. 서버에서 바로 띄우고 즉시 수정.
- **데이터 소스 재사용**: `output/md/`(콘텐츠), `api/user_store.py`(유저·키워드·채널·수신설정).
- **쓰기 범위**: 설정 변경만 user_store에 기록. 콘텐츠(MD)는 읽기 전용.
- **수집 모델(이미 구현됨)**: 합집합 수집 → 개인별 필터 발송. 구독자가 키워드/채널을 추가하면 user_store에 저장되고, `main_v2._v2_get_config()`가 다음 사이클에 전체 합집합을 자동 수집. 운영자 수동 개입 불필요. 같은 키워드는 한 번만 수집해 여러 구독자에게 분배.

## 5. 인증 / 보안

- 로그인 방식 2종 병행:
  1. **아이디 + 비밀번호** — 관리자가 계정 생성 시 발급, 비밀번호는 해시 저장(bcrypt/passlib).
  2. **텔레그램 링크 로그인** — 구독자 개인 봇이 1회용 인증코드/매직링크 발송 → 클릭 시 자동 로그인.
- 로그인 성공 → **JWT 발급** → 이후 API 요청 헤더에 첨부. 만료 시 자동 로그아웃.
- `user_store` 스키마 확장: `username`, `password_hash`, `is_admin`, `expires_at`(구독 만료일), `login_token`(텔레 매직링크용, 1회성).
- `expires_at` 경과 시 로그인/토큰 거부 → 만료 안내.
- 경로 탈출·권한 상승 방지: 모든 `/api/*`는 JWT 검증, `/api/admin/*`는 `is_admin` 추가 검증.

## 6. 에러 처리 & 안정성

- 대시보드 프로세스가 죽어도 크롤링봇은 무영향(완전 분리).
- API 실패 → 화면 토스트 안내, 재시도 유도.
- AI 브리핑 생성 실패 → 캐시된 직전 브리핑 표시.
- JWT 만료 → 로그인 화면 리다이렉트.
- 잘못된 채널/블로그 URL 등록 → 형식 검증 후 거부 메시지.

## 7. 확장성 & 운영

- **MVP**: 순수 HTML/JS + FastAPI + SQLite.
- **성장 시**: 프론트만 React로 교체(백엔드 유지), SQLite → PostgreSQL.
- `dashboard_server.py`를 **systemd 서비스**로 등록 → 서버 재부팅 시 자동 시작.
- AI 브리핑 등 무거운 호출은 **결과 캐싱**으로 중복 방지(유저별·일자별 1회).

## 8. 테스트 (검증 항목)

- 로그인(아이디/PW, 텔레링크), JWT 발급·만료.
- 키워드/채널 추가·삭제가 user_store에 정확히 반영.
- 피드가 로그인 유저 키워드로만 필터되는지.
- **격리 테스트**: 고객A가 추가한 키워드/콘텐츠가 고객B에게 노출되지 않음.
- 권한 분리: 일반 유저가 `/api/admin/*` 접근 차단.
- 브리핑 캐싱: 같은 날 재요청 시 캐시 반환(강제 재생성 버튼은 예외).

## 9. 범위 밖 (이번 MVP 제외)

- 결제 자동화(PG 연동) — 수동 등록으로 시작, 구조만 확장 가능하게.
- 블로그/유튜브 콘텐츠 발행 기능(참고 이미지의 생산 도구) — 소비형 제품에 불필요.
- 도메인 연결 — IP 테스트 후 별도 진행.
- 모바일 전용 앱 — 웹 반응형으로 충분.
