# 렌즈 CN 후보검색 — 샤오홍슈·도우인 인앱 클릭검색 (60대용)

- 날짜: 2026-07-19
- 트랙: 렌즈CN검색
- 관련 메모리: project_lens_cn_search
- 파일: shopping_shorts/{video_analysis.py, app.py, xiaohongshu_search.py, douyin_search.py, static/index.html}

## 1. 문제 (실측 근거)

렌즈 유사영상 모달의 "🔗 다른 플랫폼에서 찾아 담기" 링크가 **4개 플랫폼 전부 하나의 한국어
검색어**(`st.keyword`)로 외부 사이트를 연다(`index.html:908`). 이 한국어 검색어는
`/api/lens/yt`가 비전의 `product`(한국어 제품명)만 돌려준 값이다 — 비전이 **함께 계산한
중국어 검색어 `zh`는 버려진다**(`app.py:2246`).

그 결과 샤오홍슈/도우인 링크를 눌러 들어가면 **중국 플랫폼에 한국어가 들어가** 무관한 결과가 뜬다.

### 서버 실측 (2026-07-19, 같은 소재 = 에어프라이어 감자칩)

| 검색어 | 결과 | 품질 |
|---|---|---|
| `풍선감자` (한국어 한 단어) | 8건 | ❌ 완전 무관 (장난감·汤饭·에어컨) |
| `풍선감자 에어프라이어` (한국어 제품+방식) | 8건 | ✅ 관련 (气泡土豆) |
| `风琴土豆` (중국어 좁은 제품명) | 8건 | ⚠️ 다른 요리(하셀백) |
| `空气炸锅土豆片` (중국어 제품+방식) | 8건 | ✅✅ 관련·고참여 |
| `空气炸锅薯片` (중국어 변형) | 8건 | ✅ 관련 |
| `土豆片` (중국어 넓게) | 8건 | ⚠️ 너무 넓음 |

**결론 3가지:**
1. 한국어 한 단어만 무관 쓰레기. → "한국어로 안 맞게 나온다"가 실증됨.
2. 0건이 아니라 **무관/빗나감**이 진짜 문제. → "한 개가 별로면 다음 검색어" 처방이 정확.
3. **검색어마다 다른 좋은 영상**이 나옴(하셀백/버블/감자칩). → 후보 여러 개를 클릭해보게 하는 게 핵심 가치.

## 2. 목표 / 비목표

**목표**: 60대도 **클릭만으로** 샤오홍슈·도우인에서 유사영상을 찾아 담는다.
외부 중국 사이트로 내보내지 않고, 렌즈 모달 안에서 후보 검색어 버튼을 눌러 그 자리에서 결과를 채운다.

**비목표**:
- 유튜브/틱톡/인스타 링크 동작 변경 (그대로 둔다 — 한국어 `product`가 맞는 플랫폼).
- 도우인 미리보기 CDN 프록시 개선 (기존 한계 유지, 원본 링크 폴백).
- 후보 검색어 자동 학습/랭킹 (이번엔 비전이 넓은→좁은 순 고정 제안).

## 3. 설계

### 3.1 백엔드 — 후보 검색어 생성

`video_analysis.cn_search_candidates(image_bytes, caption)` **신설**(기존
`cn_search_keyword_vision`은 유튜브 경로가 아직 쓰므로 남겨둔다). 반환:

```json
{ "product": "에어프라이어 감자칩",
  "candidates": [
    {"ko": "공기튀김 감자칩", "zh": "空气炸锅土豆片"},
    {"ko": "버블 감자",     "zh": "气泡土豆"},
    {"ko": "풍금 감자",     "zh": "风琴土豆"}
  ] }
```

- 비전 프롬프트: 화면 글자·생김새·캡션으로 제품 특정 후, **넓은 제품+방식 → 좁은 제품명 순으로
  3~4개** 중국어 검색어 + 각 한국어 뜻(ko)을 만든다. `response_schema`로 JSON 강제(기존 규칙).
- 실패/키없음 → `candidates: []` (프론트는 기존 링크 폴백).
- 비용: 모달 열 때 Gemini 비전 1회 (기존과 동일, 후보만 여러 개).

### 3.2 백엔드 — 엔드포인트 2개 분리

기존 `/api/lens/cn`(프레임 → 검색어추출+검색 한 번에)을 두 개로 나눈다. 검색어별 재검색이 필요하기 때문.

- **`POST /api/lens/cn/keywords`** — `frame`(+`source_caption`) → `{ok, product, candidates:[{ko,zh}]}`.
  Gemini 비전만. Apify 안 부름.
- **`POST /api/lens/cn/search`** — `keyword`(중국어 문자열, `max_results`) →
  `{ok, items, count, keyword}`. 샤오홍슈+도우인 Apify 병렬(기존 `_run` 재사용). Gemini 안 부름.
  - `judge_same_product`(장치2)는 **선택**: 후보를 사람이 직접 고르므로 정렬 판정은 생략 가능.
    1차엔 생략(비용·지연↓), 필요하면 후속. `match`는 None으로 둔다.

기존 `/api/lens/cn`은 당장 제거하지 않되 프론트에서 더 안 부른다(죽은 코드 정리는 후속).

### 3.3 프론트 — 시니어 친화 UI (렌즈 모달 안)

`lensSearch()` 흐름에 CN 후보검색을 붙인다:

1. 렌즈 열면 기존대로 구글렌즈+유튜브 자동. **동시에** `/api/lens/cn/keywords` 비동기 호출.
2. 후보가 오면 모달 상단(플랫폼 칩 아래)에 **큰 후보 버튼 줄** 렌더:
   ```
   📕🎬 중국 앱에서 찾기 — 눌러보세요
   [ 🥔 공기튀김 감자칩 ]  [ 🫧 버블 감자 ]  [ 🎹 풍금 감자 ]
        空气炸锅土豆片          气泡土豆          风琴土豆
   ```
   - 버튼 크게(터치 타깃 큼), **한국어 큰 글씨 + 중국어 작은 글씨**(Q1=표시 확정).
3. **첫 후보는 자동 검색**(Q2 확정) → `/api/lens/cn/search`로 결과를 격자에 채움. 빈 화면 방지.
4. 사용자가 다른 후보 버튼을 누르면 그 검색어로 재검색 → CN 결과만 교체(유튜브 등은 유지).
   누른 버튼은 활성 표시, 로딩 중 "…".
5. 결과 ≤2건이면 그 버튼에 "다른 것도 눌러보세요" 힌트/회색 처리.
6. 결과 카드·담기는 **기존 렌즈 격자/담기 UI 그대로**(60대가 이미 쓰던 흐름 재사용).

CN 결과의 `savesc` 키·`_lensMeta`·미리보기(`<video no-referrer>`)는 기존과 동일.

### 3.4 비용 가드

- 비전: 렌즈 1회당 1회(모달 열 때). 기존과 동일.
- Apify: 후보 버튼 클릭마다 2런(~$0.01). **렌즈 1회당 CN 검색 클릭 상한 6회**(프론트 카운터).
  상한 도달 시 버튼 비활성 + "이번 검색은 여기까지" 안내.
- 기존 렌즈 월 100회(SerpApi) 상한이 상위 가드로 이미 있음.

## 4. 에러 처리

- 후보 0개(비전 실패/키없음): CN 후보줄 숨김 + 기존 외부 링크 폴백 유지.
- Apify 실패/토큰없음: 해당 버튼 아래 "지금 중국 앱 검색이 안 돼요" 1줄, 다른 후보/링크는 정상.
- 검색 결과 0건: "이 검색어는 없네요 — 다른 버튼 눌러보세요" (실측상 드물지만 대비).
