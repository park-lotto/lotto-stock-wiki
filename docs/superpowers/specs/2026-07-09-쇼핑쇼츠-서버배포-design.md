# 쇼핑쇼츠 서버 배포 + 도메인 + 로그인 — 설계

날짜: 2026-07-09
목적: `shopping_shorts/` (레퍼런스 랭킹 + 소통 큐)를 회사 직원 여러 명이 접속할 수 있도록
고정 도메인 + 로그인이 있는 상시 서버로 배포한다. 지금까지는 로컬 PC에서만 실행되고,
어제 임시로 cloudflared 터널로 잠깐 공유했지만 PC/세션이 꺼지면 같이 죽고 URL도 매번 바뀐다.

## 배경 / 제약

- stockbrain 대시보드가 이미 같은 Lightsail 서버(3.39.179.148)에서 systemd + nginx +
  DuckDNS + certbot SSL 조합으로 운영 중이다 (`deploy/nginx-stockbrain.conf`,
  `deploy/stockbrain.service`, `deploy/auto_deploy.sh`, `deploy/README.md`).
- stockbrain은 주식 위키 전용이라 shopping_shorts와 완전히 분리해야 한다 (다른 목적,
  다른 이해관계자, 코드도 다른 디렉터리).
- 회사 직원 여러 명이 접속하지만 개인별 계정 구분은 필요 없음 (Apify 비용 관리 목적의
  최소 게이트면 충분 — "직원 테스트용이라 수집 버튼 추가 제한은 필요 없다"고 확인됨).
- `shopping_shorts/config.py`의 `EXCEL_PATH`(채널 리스트 443개)는 로컬 카카오톡 다운로드
  파일이라 git에 없다 — 서버에 별도로 올려야 한다.
- Apify 토큰 4개(계정 로테이션, 2026-07-09 구현 완료)와 `SHORTS_EXCEL` 등은 비밀/로컬
  값이라 git에 커밋하지 않는다 (stockbrain의 `/etc/stockbrain.env` 패턴과 동일하게 처리).

## 결정된 사항 (사용자 확인 완료)

1. **서버**: 새 VPS를 만들지 않고 같은 Lightsail 서버에 포트만 다르게 올린다.
2. **도메인**: DuckDNS 무료 서브도메인 신규 등록 (예: `shoppingshorts.duckdns.org`).
3. **로그인**: 공유 계정 1개(아이디+비번 하나) — 직원별 개별 계정 아님.
4. **수집 버튼 제한**: 없음 — 로그인 게이트만으로 충분 (테스트 단계).

## 아키텍처

```
직원 폰/PC → https://shoppingshorts.duckdns.org
           → nginx (443, certbot SSL, stockbrain과 다른 server_name)
           → 127.0.0.1:8849 (shopping_shorts, 새 systemd 서비스)
```

- stockbrain(8090)과 shopping-shorts(8849)는 **포트/systemd 유닛/nginx server 블록이 전부
  분리**된 완전 독립 프로세스. 한쪽이 죽어도 다른 쪽에 영향 없음.
- 인증은 `dashboard/server.py`에 이미 있는 **HMAC 서명 쿠키 + 공유 비밀번호** 방식을
  그대로 shopping_shorts/app.py로 포팅한다 (새로 설계하지 않고 검증된 코드 재사용):
  - `DASH_PASS`/`DASH_SECRET` 환경변수 (비어있으면 인증 OFF — 로컬 개발 시 편의)
  - `/login` GET(폼) + `/api/login` POST(쿠키 발급) + 미들웨어에서 쿠키 검증, 없으면
    `/login`으로 리다이렉트
  - `/healthz`, 정적 리소스 등은 인증 예외 목록에 유지

## 컴포넌트 변경 목록

| 파일 | 변경 |
|---|---|
| `shopping_shorts/app.py` | 로그인 미들웨어·`/login`·`/api/login` 라우트 추가 (dashboard/server.py 포팅) |
| `deploy/nginx-shoppingshorts.conf` (신규) | `nginx-stockbrain.conf` 복제, `server_name`/`proxy_pass` 포트만 교체 |
| `deploy/shopping-shorts.service` (신규) | `stockbrain.service` 복제, `WorkingDirectory`/`ExecStart`/설명만 교체 |
| `deploy/shopping-shorts.env.example` (신규) | `DASH_PASS`, `DASH_SECRET`, `SHORTS_EXCEL`, `APIFY_TOKEN`~`APIFY_TOKEN_4` 템플릿 |
| `deploy/auto_deploy.sh` | `shopping_shorts/` 경로 변경 감지 시 `shopping-shorts` 서비스도 재시작하도록 조건 추가 |
| `deploy/README.md` | shopping_shorts 배포 절차 섹션 추가 (또는 별도 `deploy/README-shoppingshorts.md`) |

## 데이터 흐름 / 운영

- 배포: 로컬 → `git push origin main` → 서버 크론(`auto_deploy.sh`, 3분마다)이 pull +
  `shopping_shorts/` 변경 시 `shopping-shorts` 서비스 재시작. stockbrain과 같은 자동배포
  파이프라인 재사용, 추가 인프라 없음.
- 엑셀 파일: git 추적 안 함 → 최초 배포 시 1회 `scp`로 서버에 업로드, 이후 채널 리스트
  바뀔 때만 수동 재업로드. (자동 동기화는 이번 스코프 밖 — 필요해지면 별도 논의)
- 로그: `journalctl -u shopping-shorts -f` (stockbrain과 동일 관례)

## 에러 처리

- `DASH_PASS` 미설정 시 인증 OFF로 로컬 개발 편의 유지 (stockbrain과 동일 안전장치) —
  단, 서버 배포판 `.env`에는 반드시 설정해야 함(체크리스트에 명시).
- nginx 헬스체크: `curl -s localhost:8849/healthz` → `app.py`에 `/healthz` 엔드포인트가
  없으므로 최소 `{"ok": true}` 응답 라우트 추가.

## 테스트

- 로컬에서 `DASH_PASS` 환경변수 설정 후 `/login` 폼 제출 → 쿠키 발급 → 인증 필요 페이지
  접근 확인, 쿠키 없이 접근 시 `/login` 리다이렉트 확인 (기존 dashboard 테스트가 있으면
  같은 패턴으로 shopping_shorts에도 유닛 테스트 추가).
- 서버 배포 후: nginx 통해 실제 도메인으로 접속 → 로그인 → 「지금 수집」 동작 확인.
