## 1. 구성 요소 (다섯이 한 세트)

### 1-1. 입구 — 관제 카드
- 위치: `관제/cards/<번호>-<제목>.md` (트랙 `관제`가 소유, main에서만 갱신)
- 필드: 요청(원문·제보자·날짜) / **판단 주인**(지도 참조) / 분배(트랙·담당) / **됐다의 기준**(숫자·측정 도구) / 고객 화면·과금·데이터 변화 여부(→ 승인 칸) / 상태 파이프라인 / 라이브 실측 결과 / 재발 이력 링크
- 상태: `등록 → 분배 → 수리 → 로컬검증 → 병합 → 서버반영(시각) → 라이브실측(숫자) → 완료` / 예외 `승인대기`·`회귀`
- 강제: `track.py start <트랙> --card <번호>` 없이는 폴더를 만들지 않는다. `finish`는 카드 번호가 커밋 메시지·핸드오프에 있어야 병합.

### 1-2. 소유권 지도 — 판단마다 주인 한 곳
- `wiki/rules/판단소유권.md`: 표 `판단 | 주인 함수 | 파일 | 소비처 | 검사 도구 | 과금 관여`. 첫 판은 메모리 `reference_판단주인함수_결과물검사도구_지도`(12개)에서 시작.
- 검사 `tools/ownership_check.py`(finish 게이트): (a) 주인 함수의 **특징 시그니처**(예: `atempo`·`amix`·`setpts`·컷 길이 식·`beat_idx` 키 생성)가 지도 밖 파일에 새로 나타나면 빨강 (b) 주인 함수를 import/호출하지 않고 같은 이름 규칙의 값을 만드는 함수 → 경고+카드 요구. 오탐은 지도에 예외 사유와 함께 적어야 통과(사유 없는 예외 금지).

### 1-3. 영향 지도 — 한 번에 분배
- `tools/impact.py <함수|파일>`: 호출 그래프(정적 분석: import·호출·`exec` 슬라이스 포함)로 **소비처 목록**과, 소유권 지도의 "결과물 노드"(미리보기 영상·완성본·캡컷·ZIP·썸네일·화면 표시·매일 점검)를 붙여 **수리 명세서**를 낸다:
  `수리 지점 / 같이 바뀌어야 할 소비처 N(담당) / 다시 재야 할 검사 M / 승인 필요 여부 / 함께 병합할 묶음`
- 강제: finish가 명세서와 diff를 대조 — 소비처 중 손대지 않은 곳은 카드에 "영향 없음 — 이유"가 있어야 통과(부분 수리 차단, 0순위-A1a의 구조적 판).
- 신선도: 지도에 없는 새 소비처(주인 함수를 새로 import하는 파일)가 생기면 검사가 지도 갱신을 요구.

### 1-4. 라이브 실측 파이프라인 — 됐다의 정의
- 카드의 병합·서버 반영 시각은 `finish`·배포 로그가 자동 기입.
- **[라이브 실측 실행]**: 관리자 페이지(고객 비노출) 버튼 + 같은 CLI(`tools/live_check.py --card N`) — 카드의 층에 맞는 도구(영상·소리·자막·캡컷·…)를 반영 뒤 생긴 실제 job에 돌려 숫자·눈 확인 사진을 카드에 붙인다.
- 완료 조건: 실측 숫자가 "됐다의 기준"을 채웠을 때만 `완료`. 그 전엔 `반영됨·미검증`. 반영 뒤 첫 고객 job이 생기면 자동 1회 실측 → 미달이면 관리자 쪽지 + `회귀`.

### 1-5. 승인 표식
- diff가 `static/*.html|js`(고객 화면), 과금 함수(`_charge_*`·서명·`clean_charge_plan`), 고객 데이터 쓰기(`mix_jobs`·`clean_base.json` 등)에 닿으면 카드에 `승인 필요` 배지 자동, 승인 전 finish 거부. 승인은 사장님이 카드에 한 줄(`승인: 2026-..`).

### 1-6. 트랙 간 충돌 통제
- `track.py claim <파일|함수>`: 선점 신고 표(`관제/claims.json`). 다른 트랙이 같은 함수를 건드리면 finish 경고 + 관제 판단 요구. 같은 카드의 여러 에이전트는 파일 단위로 나눠 신고.

3. **"됐다" = 설계가 뿌리까지 끝났고 라이브 실물 숫자가 기준을 채운 상태.** 그 전 이름은 "진행 중 / 반영됨·미검증". "됐다" 뒤 "다만·솔직히·아직"은 위반.
