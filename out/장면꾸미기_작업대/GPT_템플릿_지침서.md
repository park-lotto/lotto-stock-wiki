## 0. 왜 10번이나 걸렸나 (되풀이하지 말 것)

| 회차 | 잘못된 것 | 진짜 원인 |
|---|---|---|
| v1 | 제목 뒤에 흰 판을 깔았다 | 배경을 안 알려줬다 |
| v4 | 글자가 알록달록 | "외곽선"을 색으로 오해 |
| v5 | 제목이 3줄로 깨짐 | 줄바꿈 금지를 안 말했다 |
| v6 | 폰트가 가늘다 | 글꼴 이름을 안 줬다 |
| v8 | **획이 들러붙어 안 읽힘** | ★내가 "여백 3%"를 지어냄 (실측은 7.8%) |
| v9 | 여전히 뭉갬 | ★`font-weight:900` + Black Han Sans = 획 부풀림 |
| v10 | — | 실측 px를 그대로 준 뒤에야 맞음 |

### ★가장 큰 교훈 세 가지

1. **눈대중 값을 주면 안 된다.** "3퍼센트", "훨씬 크게" 같은 말은 반드시 틀린다.
   → 원본 이미지를 **픽셀로 재서** px과 %를 함께 준다.
2. **말로 설명하지 말고 이미지를 기준으로 하라고 시켜라.**
   "내 말 따라오지 말고 이미지를 직접 재서 맞춰"라고 하면 GPT가 스스로 픽셀을 잰다(실측: 1분 21초 걸려 v7이 크게 좋아짐).
3. **이미 굵은 글꼴에 `font-weight:900`을 주면 획이 메워진다.** Black Han Sans·Gmarket·TmonMonsori는 전부 굵은 글꼴이라 `normal`로 둔다.

## 2. 실측 스크립트 (이 값을 GPT에 준다)

```python
from PIL import Image
im = Image.open('hook.png').convert('RGB'); px = im.load(); W, H = im.size

# ① 영역 경계 — 가로줄의 대표색으로 띠/박스/영상 경계를 찾는다
def kind(y):
    cs = [px[x, y] for x in range(6, W-6, 3)]; n = len(cs)
    if sum(1 for c in cs if min(c) > 205)/n > .7: return 'WHITE'
    if sum(1 for c in cs if max(c) < 50)/n > .7: return 'BLACK'
    return 'mix'

# ② 글자 크기 — 그 색 픽셀이 있는 y 범위 = 글자 높이
def rows(y0, y1, test):
    return [y for y in range(y0, y1)
            if sum(1 for x in range(4, W-4) if test(px[x, y])) > 3]

# ③ 좌우 여백 — 그 색 픽셀이 있는 x 범위
def cols(y0, y1, test):
    return [x for x in range(W)
            if sum(1 for y in range(y0, y1) if test(px[x, y])) > 1]
```

**뽑아야 할 값 목록** (이게 다 있어야 한 번에 맞는다):

```
□ 각 영역의 y 시작~끝 (px과 %)     : 띠 / 제목 / 흰박스 / 영상
□ 각 영역의 배경색 (#RRGGBB)       : ★"영상이 비친다"인지 "불투명 박스"인지 반드시 구분
□ 글자마다 높이 (px과 %)           : 제목 1줄 / 2줄 / 흰박스 / 채널명
□ 글자마다 좌우 x 시작~끝 (여백 %)
□ 글자 색 (#RRGGBB)
□ 외곽선 유무 ★대개 없다 — 있다고 지레짐작 금지
```

## 3. GPT에 보낼 첫 메시지 틀

> 아래를 **그대로 복사**해 값만 채운다. 이미지 2장(훅·본문)을 함께 첨부한다.

```
첨부한 두 장은 같은 쇼츠 영상(9:16, <W>x<H>)의 실제 프레임이야.
1장=훅 구간, 2장=본문 구간. 이 두 개가 한 세트인 HTML 템플릿을 만들어줘.

★중요: 내 설명을 따라오지 말고 첨부 이미지를 직접 재서 그것과 구분이 안 갈 정도로
똑같이 만들어. 아래는 내가 픽셀로 잰 값이니 지어내지 말고 이대로 써.

[훅 — <W>x<H> 기준]
상단 띠      : y 0~<N>px (<N>%) · 배경 <#색> · 가운데 채널명 "<이름>" <#색> 높이 <N>px
제목 영역    : y <N>~<N>px · 배경 <#색> ← ★불투명 박스인지 영상이 비치는지 명시
  1줄 "<문구>" : 글자높이 <N>px (<N>%) · 색 <#색> · x <N>~<N> (좌여백 <N>% 우 <N>%)
  2줄 "<문구>" : 글자높이 <N>px (<N>%) · 색 <#색>
흰 한줄박스  : y <N>~<N>px · 배경 <#색> · 글자 <#색> 높이 <N>px · x <N>~<N>
영상         : y <N>px부터 화면 끝까지

[본문 — 같은 크기]
상단 띠      : y 0~<N>px · 배경 <#색>
흰 블록      : y <N>~<N>px — 채널로고 + 채널명 + 조회수·댓글 + 제목(<#색>, <N>px)
자막띠       : y <N>~<N>px · 배경 <#색> · 글자 <#색> <N>px
영상         : y <N>px부터 끝까지

[글꼴]
<글꼴이름> 을 구글폰트로 불러와 쓴다.
★font-weight 는 normal 로 둔다 — 이미 굵은 글꼴이라 900을 주면 자음·모음 사이 구멍이
  메워져 글자가 검은 덩어리가 된다.
★글자 외곽선(text-stroke·text-shadow)은 넣지 마라. 원본에 없다.
letter-spacing 은 -0.02em 정도로 살짝 좁힌다.

[요구사항]
1) 훅·본문 각각 9:16 한 장씩, 한 파일에 나란히 (상단 탭으로 전환)
2) 모든 문구·색·글자크기를 오른쪽 편집 패널에서 바꿀 수 있게.
   ★문구칸마다 크기 증감(＋－) 버튼을 붙일 것
3) 영상 자리는 VIDEO AREA 로 비워두고 파일 선택으로 교체 가능하게
4) 글자가 길어지면 글자를 줄이지 말고 줄이 늘어나게.
   단 제목 2줄은 각 줄이 쪼개지지 않게 nowrap 으로 고정
5) 단일 HTML 파일 하나로. 설명 말고 파일로 줘
```

## 4. 결과가 나오면 — 대조 체크리스트

미리보기를 **확대해서** 원본과 나란히 놓고 본다. 축소본으로 판정하면 틀린다
(실측: 축소 카드에서 "파란 박스"로 봤던 게 실제로는 하늘색 `#AAECF9`였다).

```
□ 글자가 뭉개지지 않고 자음·모음 구멍이 보이나   ← ★가장 자주 틀림
□ 외곽선이 안 들어갔나
□ 제목이 정확히 2줄인가 (3줄로 깨지지 않았나)
□ 색이 1줄/2줄 각각 맞나
□ 배경이 불투명 박스인가 영상인가
□ 각 영역 사이에 빈 여백이 안 생겼나
□ 흰박스 글씨가 제목보다 확실히 작은가 (실측 22px vs 53px)
□ 본문 제목·자막이 검은 글씨인가 (하늘색은 훅 2줄 전용)
```

## 5. 우리 화면으로 옮길 때

GPT는 구글폰트만 쓰지만 **우리는 실제 폰트 파일 41종을 갖고 있다**
(`shopping_shorts/static/fonts/`). 실측 19채널이 쓰는 7종이 전부 있다:

| 글꼴 | 채널 수 |
|---|---|
| Pretendard-ExtraBold.otf | 5 |
| GmarketSansBold.otf | 4 |
| TmonMonsori.ttf | 3 |
| SpoqaHanSansNeo-Bold.otf | 2 |
| BlackHanSans.ttf / Pretendard-Bold.otf / NotoSansKR-Bold.otf | 각 1 |

⚠️ **woff2 금지** — ffmpeg·PIL이 못 읽어 경고 없이 기본폰트로 나간다(memory `reference_폰트추가_woff2_렌더3경로`).
라이브 렌더(`deco_frame`)도 같은 ttf/otf를 쓰므로 미리보기와 완성 영상의 글꼴이 일치한다.

## 6. 알려진 제약

- **GPT가 만든 파일을 자동으로 못 받는다.** 확장 샌드박스가 다운로드를 차단하고,
  코드 텍스트도 보안 필터(`[BLOCKED]`)에 막힌다. 5가지 방법 전부 실패.
  → 사장님이 ⤓ 버튼을 눌러주셔야 한다.
- 입력칸에서 **줄바꿈이 전송으로 잡힌다.** 여러 줄을 보낼 땐 한 문단으로 이어 쓰고
  `find`로 "프롬프트 보내기" 버튼을 찾아 누른다(Enter는 앞 텍스트만 보낸다).
- `~` 문자는 마크다운 취소선으로 해석된다. 범위는 `0~12%` 대신 `0-12%` 또는 "0부터 12퍼센트".

## 7. 대량 수집 파이프라인 (2026-09-09 추가)

한 개씩 손으로 하면 20개에 며칠 걸린다. 자동화했다.

```
scratchpad/
  wide.json      485채널 (서버 reel_history 에서 제목 공식으로 추출)
  batch20.py     실측 함수 (measure / text_lines / fmt) — ★정의처 하나
  run_all.py     전체 순회 + 스타일 중복 제거
  styles/        결과 (프레임 png · 지시문 txt · state.json)
```

### ★핵심 1 — 채널 목록으로는 썰쇼핑형을 못 거른다

"활용법·꿀템"으로 485채널을 뽑았더니 **상단 띠도 흰 박스도 없는 일반 살림 영상이
대거 섞였다**(하루살림·마샤홈·리빙홈…). 그런 화면에는 베낄 틀 자체가 없다.

→ **프레임 구조로 판정한다**(`is_sul`):
```
① 상단에 단색 띠가 화면 높이의 3~22% 있다
② 그 아래 화면 폭의 절반 이상을 차지하는 큰 글자 줄이 있다
③ 흰 한줄박스가 있거나, 큰 글자가 2줄 이상
```
정답 5건으로 검증했다(숏팡·숏템 통과 / 하루살림·마샤홈·리빙홈 걸러짐 = 5/5).

### ★핵심 2 — 1줄과 2줄을 색으로 가르면 안 된다

숏팡 2줄은 하늘색인데 `min(c)>200`을 통과한다. 색으로 가르려 하면 1줄(54px)과
2줄(48px)이 뭉쳐 **130px**로 잘못 잰다(실측). → **빈 줄로 덩어리를 가른다**(`_groups`).

### ★핵심 3 — 글자 색은 밝은 픽셀만 세라

글자 사각 영역에는 배경·외곽선이 섞여 있어 그냥 최빈색을 쓰면 **검정**이 뽑힌다
(실측: 하늘색 2줄이 `#000000`으로 나왔다). 밝은 픽셀만 세니 `#A7EFFC`로 맞았다.

### 스타일 중복 제거

같은 디자인을 두 번 만들 필요가 없다. 지문으로 묶는다:
```
지문 = 띠색 | 제목배경 | 글자색들 | 흰박스유무 | 줄수     (색은 32단계로 뭉갠다)
```
압축 차이로 1~2 다른 색이 같은 스타일로 묶이게 하려고 색을 뭉갠다.

### 돌리는 법

```bash
py run_all.py            # 전체
py run_all.py 50         # 앞 50개만
py run_all.py 50 100     # 100번째부터 50개
```
`styles/state.json`에 진행이 계속 저장되므로 **중간에 멈춰도 이어서** 돌면 된다.
영상 본체는 프레임을 뽑은 뒤 지운다(485개면 디스크가 찬다).
