## 🎯 v4 = 후보 3개를 **진짜로** 다르게 (설계 대기)

### 문제 (2026-08-02 실측으로 확정)

**후보 3개가 같은 이야기를 한다.** 훅만 다르고 나머지가 같다.

짐벌 job(`8712570702b8`, 소스 2개) 실측:
```
후보0:  s1-1 → s1-5 → s1-9 → s0-9      (B B B A)
후보1:  s1-1 → s1-5 → s1-9 → s0-10     (B B B A)
후보2:  s1-1 → s1-6 → s1-9 → s0-10     (B B B A)
```
소스1이 앞 3컷을 다 차지하고 **소스0은 마지막 1컷만** 쓰인다
(프롬프트의 "영상마다 최소 한 세트"라는 최소조건만 겨우 만족).

### 왜 그런가 — 원인 확정

**이야기 뼈대가 하나뿐이다.** 슬롯 단계에서 Gemini가 세트 7개 중 4개를 골라
**스토리 하나**를 짜고, 그 위에 대사 3벌이 얹힌다. 그러니 순서도 요점도 같다.

그리고 **대본은 원본 이야기를 따라간다**(설계 의도이기도 하다 — "대사를 창조하지 마라"):

| 화면 | 원본이 한 말 | 우리 대본(후보1) |
|---|---|---|
| s1-1 | 친구가 유튜브 한다면서 | 제발 무거운 짐벌 들고 다니지 마세요 ← **훅만 창작** |
| s1-5 | 흔들림 방지 기능이 따로 있는 거라면서 | 카메라가 다 비슷할 줄 알았는데, 흔들림 방지 기능이 |
| s1-9 | 아무리 흔들어도 각도가 그대로 유지되고 | 걷거나 움직여도 각도가 딱 유지되고 화질도 미쳤는데 |
| s0-10 | 들고 다니기에도 진짜 편할 것 같다고 | 짐벌 일체형이라 들고 다니기도 진짜 편하거든요 |

→ 표절은 아니지만 독립 창작도 아니다. **원본 순서·요점을 따라가며 말투만 바꾼다.**
→ 그래서 **뼈대가 같으면 후보도 같을 수밖에 없다.** 대사 프롬프트만 만져선 표현만 바뀐다.

### v4 방향 — 슬롯을 **3벌** 뽑는다

**재료가 이미 있다.** 짐벌 job은 세트 7개 중 4개만 썼고 **3개가 남았다**(대부분 s0).
그리고 s0에는 **완전히 다른 이야기가 통째로** 있다:
> "인플루언서 형이랑 박람회 갔는데 사람들이 줄을 길게 서 있더라 → 촬영 전문가용 초신상 →
>  헐리우드 카메라 넣어서 화질이 미쳤다"  ← 지금은 이게 통째로 버려진다

```
v4 후보A = s1 뼈대 (친구 이야기)     ← 지금 나오는 것
v4 후보B = s0 뼈대 (박람회 이야기)   ← 완전히 다른 영상·다른 이야기
v4 후보C = 섞기
```

**바꾸는 것**: `_set_seq_prompt`(edit_plan.py:545)에 "서로 다른 스토리 3개를 짜라"를 요구하고,
`_pick_slot_groups`(:644)가 3벌을 돌려주게. 후보마다 다른 슬롯을 받는다.

**안 바꾸는 것**(★중요 — 여기서 헷갈렸다):
- **장면 → 대사 순서 그대로.** 대본에 장면을 맞추는 게 아니다.
- 세트를 쪼개지 않는다(통째로 쓰거나 안 쓰거나).

- Gemini 호출 횟수 1회 그대로(한 번에 3벌 요구) → 과금 거의 안 는다.

### ⚠️ v4의 제약 — 기대치를 미리 낮춰둘 것 (2026-08-02 정리)

**구조상 확정된 한계**
1. **여유가 없으면 못 갈른다.** 실측 10건 중 1건은 세트를 다 써서 남는 게 없다 → 후보가 똑같이 나온다.
