# 채널 전략 분석 → 대본 스타일 강제선택 (2026-08-15)

## 한 줄

대박 채널을 해부해 **성공 공식을 '스타일'로 뽑고**, 대본 생성 때 사장님이 그 스타일을 골라
**코드가 칸을 박고 게이트가 검사**한다. "AI에게 부탁" → "코드가 강제 + 검사"로 바꾼 것.

## 왜 (기존 대본이 복불복이던 진짜 이유 — 코드 실측)

프롬프트는 오히려 정교했다(`script_generate._STORY_RULES_CORE`에 고조연결어·종결어미
다양화·CTA 받는것 명시·킥 감추기까지 전부 있다). 문제는 딴 데 있었다:

1. **규칙이 전부 부탁이고 지켜졌는지 검사하는 코드가 0개**였다 → 실패를 실패로 알 수 없었다
2. **구조를 AI가 정했다** — 칸을 코드가 안 박았다
3. `_MIX_PROMPT`의 "좋은 부분만 골라 녹여라"가 모호 — 무엇이 좋은지 AI가 판단
4. 부품은행이 "양념"으로만 들어가고 **"그대로 베끼면 반려"**라 성공 훅이 못 들어갔다
   (`script_engine._bank_block`, 2026-07-26 드리프트 사고의 흉터 — 건드리지 않았다)
5. ★아무도 몰랐던 것: **말 밀도가 히트작의 1/3**. 규칙 위반이 아니라 경고도 안 떴다
   (일반 기준 4.5자/초 → 30초 135자 / 채이홈 히트작 실측 **264~377자**)

## 채이홈(chae2home) 실측 — 스타일의 근거

448편·2025-11 시작. 첫 터짐은 7번째(344만)지만 8~14번이 1~2만으로 복귀 = 공식 못 찾음.
**진짜 전환은 17번(12/05, 631만)** — 여기부터 중앙값 1.4만 → 14.6만으로 10배 점프해 유지.
선별 12편을 실제 전사(806.9초)해 대조하니 히트작이 전부 같은 뼈대였다:

> 가족이 나를 혼냈다(훅) → 무엇이 문제였나 → **제3자 권위가 알려준 물건**(반전) → 결과 → 단어 CTA

- 훅 4종을 소재만 바꿔 재사용(631만·536만·347만·294만)
- 결정적 증거: 같은 주 업로드 #447(갈등훅 O, 36만) vs #440(정보형, 5.3천) = **70배**
- 현재는 하락세(2월 32만 → 8월 7.2만)인데 월 편수는 14→88. 댓글률은 0.9%→3.1%
  = 팬은 끈끈한데 신규 유입이 준다(다작으로 하락을 막으려다 편당 밀도 희석)

## 게이트 오탐 4건 — 전부 라이브에서 잡아 고침 (재발 방지용 기록)

1. `re.escape`를 통째로 걸면 `{`가 `\{`가 되고 치환 뒤 백슬래시가 남아 **리터럴 점**이 된다 → 절대 안 맞음
2. 빈칸 뒤 조사는 받침 따라 바뀐다(`{제품}이라고` → "세제라고") → 조사 분리. **다글자 조사**(한테·에게·이라고)도 떼야 한다("한테"가 붙어 어구가 통째로 튕겼다)
3. 어미 표기 흔들림(하더라**구**요 / 하더라**고**요) → `norm()`에서 통일
4. ★**CTA는 기존 헌장이 옳았다** — "남겨주세요"로 끝내면 실패, "남겨주시면 [받는 것] 드릴게요"가 규칙(2026-08-04 사장님 확정)인데 내 틀이 그걸 FAIL로 잡았다 → 어간 "남겨주"로 판정 + 시드 교정

또한 **문장틀은 통짜 일치를 요구하면 안 된다.** 모델은 앞머리를 소재에 맞게 바꾸고 중간에
살을 붙이면서 서명 어구는 지킨다("주방 청소하다가 시어머니한테 **기름때 다 안 지워졌다고**
욕 바가지로 먹을 뻔했어요"). 판정은 "고정 어구가 순서대로 절반 이상 + 최장 어구 필수"다.

## ★오늘 찾아낸 핵심 — 사장님 모델이 맞았다

**사실과 표현을 갈라야 한다.**
```
사실 = "녹는다"            ← 제품 특징. 재료(대본·리뷰·상세페이지)에서 온다
표현 = "사르르 / 퐁신퐁신"   ← 채널 말버릇. 스타일이 갖는다. 어느 제품에나 쓴다
결과 = "사르르 녹는데 퐁신퐁신해서"
```
내가 처음엔 `sensory: ["입에서 사르르 녹는"]`을 **재료**로 뽑았는데, 그건 이미 합쳐진
**완제품**이라 그대로 베끼게 된다. 사장님이 이걸 짚어주셨다.

### 3안 실측 (계란+요거트 빵 3편 · 가족갈등 반전형 · 2026-08-16)

| | 말버릇 | 게이트 | 글자수(목표 300) |
|---|---|---|---|
| A 대본 3편 통째(지금 라이브) | 4개 (**원본에서 베낌**) | 통과 | 383 (128%) |
| B 사실만, 표현사전 없음 | 1개 | **실패**(고조) | 254 (85%) |
| **C 사실 + 표현사전** | **8개** | 통과 | **323 (108%)** |

같은 사실이 이렇게 갈렸다:
- B: "입에서 **살살** 녹는데" (밋밋)
- C: "입에 넣자마자 **사르르** 녹는데 식감이 **퐁신퐁신**해서"

★A의 말버릇 4개는 **원본 문장을 그대로 가져온 것**이다(원본에 "사르르 녹으니까"가 있다).
  C는 원본에 없던 "퐁신퐁신·쫙"을 스타일 사전에서 가져와 **새로 만들었다**. 이 차이가 핵심.
★표현 사전이 **밀도 문제도 같이 풀었다**(사장님 지적) — 억지로 늘린 게 아니라 말맛이
  살면서 자연히 붙는다. A가 383자로 넘친 건 원본 800자에 끌려간 흔적이다.

## 그래서 최종 구조 (칸이 줄었다)

```
재료(사실)  : 대본 N편 + 쿠팡 상세·리뷰 + 영상분석   → "녹는다·단백질·오븐 불필요"

              ↓ 인물·상황·말투를 스타일이 100% 결정 = 원본을 안 베낌
```

⚠️ **씨앗(대본 1편 지정)은 없애는 방향이다.** 사장님 지적: *"하나의 대본을 지정하면
편협하게 나온다. 한국 대본이 2개면 2개를 보고, 리뷰나 상세정보 분석하듯 정보를 쭉 모아서
스타일 지정된 걸로 뽑아내는 거지."* + *"사용자는 뭐가 좋은 대본인지 모르고 잘못 고르면 낭패"*

★**실측으로 확인한 배선 문제**(`app.py:2256`):
```python
_src = [{...}]   # ← 대괄호 안에 하나뿐. 씨앗 1편만 넘긴다
```
바로 아래 `_mix_source_block`은 **3편까지 받게 돼 있다**(`sources[:3]`).
즉 3개 그릇에 1개만 넣고 있었다. 편협하게 나온 게 아니라 **편협하게 넣고 있었다.**
