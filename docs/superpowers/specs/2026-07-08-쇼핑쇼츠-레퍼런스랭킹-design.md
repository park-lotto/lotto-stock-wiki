# 쇼핑쇼츠 자동화 — 레퍼런스 랭킹 (기능 ①) 설계

날짜: 2026-07-08
상태: 설계 확정 대기

---

## 1. 목적 (What & Why)

정리해둔 인스타 레퍼런스 채널(443개)의 **최신 릴스를 매일 훑어서, 실제로 "터진" 영상만
댓글수 랭킹으로 뽑아주는** 도구. 목적은 **바로 벤치마킹할 쇼핑쇼츠 소재 발굴**.

- 소스: `벤치마킹시트 신규.xlsx` (채널명 / 인스타주소 / 팔로워 / 인포크링크, 443행)
- 큰 그림: 이 레퍼런스 랭킹은 전체 "쇼핑쇼츠 자동화 프로그램"의 **첫 번째 기능**.
  이후 소통보조(기능 ②) 등이 같은 웹앱에 메뉴로 추가됨. (이 스펙 범위는 기능 ①만.)

### 참고: 벤치마킹 대상 UI (shopping.tubefactory.kr — 타인 제작, 코드 접근 불가)
다크 테마 / 좌측 사이드바(트렌드 리서치·채널&콘텐츠·내 도구 그룹) / 상단 헤더(포인트·프로필) /
메인 영역(제목+설명 → 탭 → 필터 → 결과). **이 레이아웃을 복제한 내 전용 웹앱을 새로 만든다.**

## 2. 핵심 규칙 (확정된 필터·정렬)

| 항목 | 값 | 근거 |
|------|-----|------|
| 시간 창 | **48시간 이내** | 24h는 댓글 쌓일 시간 부족 → 터졌는지 판별 불가. 48h면 검증됨 |
| 댓글 하한 | **댓글수 ≥ 500** | "터진 영상" 기준 |
| 정렬 | **댓글수 내림차순** | 단순명료. (참여율 정렬은 후속 확장) |
| 채널당 상한 | **최신 3개** | 하루 1~3개 업로드 채널 커버. 안전장치 |
| 중복 처리 | **유지 + 어제 대비 증가량(Δ) 🔥 표시** | 신규 발굴 + 떡상 감지 동시 |

**중복 = 낭비가 아니라 신호**: 같은 영상이 이틀 연속 잡히면 댓글 증가량(Δ)으로 "지금 떡상 중"을 감지.
매일 수집분을 DB에 저장하고 어제치와 비교.

## 3. 데이터 수집 (Apify)

- **스크래퍼**: Apify `apify/instagram-reel-scraper` (또는 동급 저가 스크래퍼)
- **과금**: 긁은 건수당 (~$0.0005/건). Apify 무료 크레딧 $5/월로 시작.
- **입력**:
  - `username`: 443개 채널 URL 배열 (엑셀에서 로드)
  - `onlyPostsNewerThan: "2 days"` — 48h 창 + 여유. **오래된 것 안 긁어 비용 절약**
  - `resultsLimit` (채널당): 3
  - `skipPinnedPosts: true`
- **검증된 출력 필드** (2026-07-08 WebFetch 확인):
  `commentsCount`, `likesCount`, `videoViewCount`, `videoPlayCount`, `timestamp`,
  `videoUrl`, `displayUrl`(썸네일), `caption`, `sharesCount`, `videoDuration`
- **예상 비용**: 443채널 × 실제 업로드분(창 안 몇 건)만 과금.
  최악(채널당 3건 다) = 1,329건 × $0.0005 ≈ **$0.66/회**. 실제로는 창 안 영상만이라 그 이하.
  무료 크레딧으로 **최소 7~15회/월** 가능.

## 4. 아키텍처 (로컬 웹앱)

너 혼자 쓰는 **로컬 웹앱** (localhost). 서버 배포 없음. 수집은 **수동 버튼 트리거**.

```
┌─────────────────────────────────────────────────────────┐
│  브라우저 (localhost)  —  다크 사이드바 레이아웃 복제        │
│  사이드바 > "레퍼런스 랭킹" 메뉴                             │
│   ├ [지금 수집] 버튼                                        │
│   ├ 랭킹 테이블/카드 (썸네일·채널·댓글수·Δ🔥·업로드시각·링크) │
│   └ 필터 컨트롤 (카테고리·기간·최소댓글수 등 후속)           │
└───────────────┬─────────────────────────────────────────┘
                │ (수집 버튼 → 백엔드 호출)
┌───────────────▼─────────────────────────────────────────┐
│  로컬 백엔드 (Python)                                      │
│   1. 엑셀 로드 → 443 채널 usernames 추출                    │
│   2. Apify Reel Scraper 호출 (48h·상한3·pinned제외)         │
│   3. 필터: timestamp ≤ 48h AND commentsCount ≥ 500         │
│   4. DB 저장 + 어제분과 대조하여 Δ(댓글 증가량) 계산         │
│   5. 댓글수 내림차순 정렬 → 웹앱에 반환                      │
│   6. 엑셀(벤치마킹시트)에도 날짜별 자동 누적                 │
└───────────────┬─────────────────────────────────────────┘
                │
        ┌───────▼───────┐   ┌──────────────────────────┐
        │  로컬 DB       │   │ 벤치마킹시트 신규.xlsx     │
        │ (수집 이력·Δ)  │   │ (날짜별 랭킹 누적)         │
        └───────────────┘   └──────────────────────────┘
```

### 구성 요소 (각 하나의 책임)
1. **채널 로더** — 엑셀 읽어 유효한 인스타 username 배열 반환. (URL 정규화·중복 제거)
2. **Apify 클라이언트** — 스크래퍼 호출, 결과 원본 반환. (API 키·재시도·에러 처리)
3. **필터/랭킹 엔진** — 48h·댓글500+ 필터, 댓글수 정렬, 어제분 대조 Δ 계산.
4. **저장소** — 로컬 DB(수집 이력) + 엑셀 누적 기록.
5. **웹앱 (프론트)** — 다크 레이아웃, 수집 버튼, 랭킹 표시.

## 5. 결과 화면 (랭킹 항목 컬럼)

| 컬럼 | 소스 |
|------|------|
| 순위 | 정렬 결과 |
| 썸네일 | `displayUrl` |
| 채널명 | 엑셀 매칭 |
| 댓글수 | `commentsCount` |
| Δ (어제 대비) | DB 대조 → 예: `+800 🔥` |
| 좋아요 | `likesCount` |
| 조회수 | `videoViewCount` / `videoPlayCount` |
| 업로드 | `timestamp` (상대시간 "N시간 전") |
| 링크 | 게시물 URL (클릭 시 인스타로) |

## 6. 에러 처리

- 엑셀 없음/형식 오류 → 명확한 메시지, 중단.
- Apify 크레딧 소진/API 실패 → 부분 결과라도 저장 + 경고 표시. 재시도 1회.
- 채널 비공개/삭제/0건 → 스킵하고 로그, 전체 중단 안 함.
- 어제 DB 없음(첫 실행) → Δ는 "신규" 표기.

## 7. 범위 밖 (YAGNI — 이번엔 안 함)

- ❌ 자동 스케줄 수집 (지금은 수동 버튼. 잘 돌면 후속에 Task Scheduler)
- ❌ 서버 배포/멀티유저
- ❌ 소통보조(기능 ②) — 자동 댓글·좋아요·팔로우. 별도 스펙.
- ❌ 참여율(engagement) 정렬 — 후속 확장
- ❌ TikTok·유튜브 소스 — 인스타 먼저
