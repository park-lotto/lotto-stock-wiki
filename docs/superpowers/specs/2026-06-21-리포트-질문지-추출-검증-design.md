# 리포트 질문지 추출 + 자동 검증 시스템 — 설계

- **날짜**: 2026-06-21
- **작성 배경**: 위키의 가치는 "오늘 뭐 올랐나"(웹서칭으로 충분)가 아니라
  **시간을 가진 검증된 판단**에 있다. 그 1차 재료가 증권사 리포트인데,
  현재 추출(`pipeline/atoms/pdf_ingest.py`)이 "중요한 걸 골라라"는 방식이라
  리포트마다 말투가 다르면 제미니가 핵심을 놓친다.
- **이 문서의 범위**: 증권사 **리포트** 추출만. 텔레/유튜브/뉴스는 후속(소스별 질문지 C안).

---

## 1. 문제 정의 (현재 막힌 지점)

`pdf_ingest.py`의 프롬프트가 제미니에게 **"투자 판단에 쓸 수 있는 중요한 정보를 골라서 원자화하라"**
고 시킨다. 판단을 LLM에 위임하므로:

- 리포트 표현이 다르면 "중요"의 기준이 흔들려 **핵심을 누락**한다.
- 면책조항만 요약된 MD(예: "안녕하세요 데일리")는 **쓰레기를 원자화**한다.
- 네이버 `카테고리`가 부정확해(종목 리포트가 `산업분석`으로 분류됨) **타입 오분류**된다.
- 증권사명이 크롤링 단계에서 깨져(제목으로 들어옴) **출처 불명**이 된다.

### 실데이터로 확인된 사실 (2026-06-19 리포트 39종 중 3종 검증)
- 3종 모두 `카테고리=산업분석`이나 실제로는 종목형/섹터형/시황형으로 제각각.
- 3종 모두 MD `증권사` 필드 = 제목 (파싱 버그).
- "안녕하세요 데일리"의 MD AI요약 = 면책조항이 전부.

---

## 2. 핵심 전환: "골라라" → "정해진 칸을 채워라"

증권사 리포트는 말투가 달라도 **항상 같은 질문에 답한다.** 그 고정 질문지(슬롯)를
제미니에게 주고 *"각 칸을 채워라, 없으면 null, 수치는 축자, 면책문구 무시"* 시킨다.
→ 표현 변동과 무관하게 일관 추출, 누락 없음.

## 3. 아키텍처

```
리포트 MD (PDF URL 포함)
   │
   ├─ STEP 0  라우터 (내용 기반, 카테고리는 힌트만)
   │            target_kind ∈ {stock, sector, market}
   │            판별: 특정 종목 목표가 있으면 stock /
   │                  단일 업종이면 sector / 시장·매크로·멀티테마면 market
   │
   ├─ STEP 1  공통 헤더 (broker·analyst·report_date)
   │            ※ 증권사명은 MD가 깨졌을 수 있으므로 PDF 표지에서 추출
   │
   ├─ STEP 2  타입별 질문지 채우기 (제미니, JSON 1장)
   │            stock  → 종목별 슬롯 (목표가·실적전망·추정·촉매·thesis·리스크·수급)
   │            sector → 섹터의견·thesis·timeline·top_picks·리스크
   │            market → 시장방향·매크로·recommended_sectors·이벤트캘린더·top_picks
   │
   ├─ STEP 3  fan-out (코드, 결정론적)
   │            sector.top_picks  → 각 종목 원자 (강도 낮음: "거론" 레벨)
   │            market.recommended_sectors → 각 섹터 원자
   │            market.top_picks  → 각 종목 원자
   │            ※ 한국 상장사만 필터 (해외 업체 제외)
   │
   ├─ STEP 4  질문지 → 원자 변환 (코드, taxonomy.py 스키마로 매핑)
   │
   └─ STEP 5  자동 검증 게이트 (아래 §5) → 신뢰점수 부여 → atoms DB 저장
```

### 라우팅 규칙
- 1순위: 본문에 **특정 종목 목표가**가 있으면 `stock`.
- 없고 **단일 업종** 전망이면 `sector`.
- 시장/매크로이거나 **2개 이상 섹터를 묶은 데일리·위클리**면 `market`.
- 네이버 `카테고리`는 참고만 (신뢰 불가, 실데이터로 확인됨).

## 4. 질문지 슬롯 정의 (검증 완료본)

### 공통 헤더
`broker`, `analyst`, `report_date`

### [stock] — 종목별 배열 `stocks[]`
| 슬롯 | 설명 |
|---|---|
| name / code | 종목명 / 코드(PDF에 있으면, 없으면 null → 코드테이블 백필) |
| rating / rating_changed | 투자의견 / 직전 대비 변경 |
| tp_new / tp_prev / tp_direction | 신규·직전 목표가 / up·down·flat |
| earnings_outlook | 이번·차기 분기 실적·판매량·매출·영익 전망. **컨센/YoY/QoQ 수치 하나라도 있으면 반드시 채움** |
| estimate_revision | 추정치 상향/하향 + % |
| next_catalyst | 다음 촉매 + 날짜 |
| thesis | 핵심 투자포인트 최대 3개 |
| valuation_basis | PER/PBR 등 산출근거 |
| risk | 리스크 (구체 조건) |
| supply_comment | 외국인·기관 수급 언급 |
| quote | 핵심 판단의 근거 원문 (검증용) |

### [sector]
`sector_name`, `sector_view`(비중확대/중립/축소), `thesis[]`, `timeline[]`,
`top_picks[]`(name·reason·tp) — **본문에 거론된 종목명을 빠짐없이. 단 하나도 없을 때만 null**,
`risk`, `quote`

### [market]
`market_direction`, `macro_vars[]`, `recommended_sectors[]`(sector·stance·reason),
`style`, `event_calendar[]`(date·event), `top_picks[]`, `risk`, `quote`

### 공통 철칙 (프롬프트에 명시)
1. 없으면 null. 절대 지어내지 않음.
2. 수치·날짜·종목명 축자 (반올림·재서술 금지).
3. 핵심 슬롯에 `quote` 짝꿍 (할루시네이션 감사용).
4. 면책조항·독립성·보유율·법적경고 문구 **완전 무시**. 요약 전부가 면책이어도 본문에서 실내용을 찾음.
5. 증권사·애널은 PDF 표지/머리글에서 추출.

## 5. 자동 검증 게이트 (전수 검사 안 함 — 의심분만 사람에게)

### 1단 — 자동, 전수, 무료
- **㉠ 인용 대조**: 모든 수치(목표가·%·날짜)와 `quote`가 PDF 원문 텍스트에 실제 존재하는지
  코드로 검사. 없으면 = 할루시네이션 🚩.
- **㉡ wisereport 대조 (공짜 정답지)**: 종목형의 `tp_new`/`rating`을
  `raw/wisereport/{date}_parsed.json`의 동일 종목+증권사 행과 대조. 불일치 🚩.
- **㉢ 구조 룰**: `tp_direction=up`인데 `tp_new<tp_prev` 모순 🚩 / `stock`인데 목표가 없음 🚩 /
  null 비율 80%↑ 🚩 / 핵심 슬롯 quote 없음 🚩.

### 2단 — 🚩된 것만, 저렴
다른 모델로 2차 판정: "PDF를 충실히 옮겼나? 빠진 핵심 있나?" → 신뢰점수 + 누락목록.

### 3단 — 사람, 🚩 + 무작위 샘플만 (하루 수 분)
대시보드에 **PDF원문 ↔ 추출JSON 나란히** 표시. 플래그 전부 + 무작위 3개만 눈검사.

### 골든셋 회귀
손으로 검증한 정답 N개 고정. **프롬프트 수정 시마다 재실행 → diff.**
기존 케이스 깨지면 즉시 적발. (이번 스파이크 3종이 골든셋 씨앗)

### 신뢰점수 → strength_score
1단 통과율로 추출별 신뢰점수 산출. 낮으면 `strength_score`를 깎아 **약한 신호로 저장**
(버리지 않음 — 충돌보존 철학).

## 6. 기존 시스템과의 통합

| 기존 자산 | 이 설계에서 역할 |
|---|---|
| `pipeline/atoms/pdf_ingest.py` | 프롬프트를 질문지 방식으로 교체, fan-out·검증 단계 추가 |
| `pipeline/atoms/taxonomy.py` | 원자 스키마 유지. 질문지 슬롯 → 이 스키마로 매핑 (변경 없음) |

| `raw/wisereport/*_parsed.json` | 검증 1단 ㉡의 공짜 정답지 |
| Remotion "골든레퍼런스" 패턴 | 골든셋 회귀 검증에 동일 개념 차용 |
