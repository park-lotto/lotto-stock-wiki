## 1. 문제와 근본 판단

**증상**: TTS 문장 이어발음(연음)이 계속 어색하게 나온다. 사장님이 매번 다른 문장에서
같은 종류의 피드백을 줘야 하는 두더지잡기 구조.

**왜 앞선 시도들은 근본이 아닌가**
- best-of-2(N-best 오독 자동회피, `f01d003a4`): 랭커(Whisper)가 **단어 정확도**만 채점한다.
  연음 어색함은 단어가 "맞게" 읽혀서 ASR이 못 잡는다 → 연음엔 무의미.
- 자동 한국어 G2P(모든 문장을 규칙으로 연음 재표기): 이론상 가장 근본이나 **과교정이 새 버그**가
  된다. 한국어 G2P는 어렵고 잘못 고치면 전 영상이 망가진다 — 이 프로젝트가 프리즈 두더지잡기로
  데인 바로 그 패턴(`reference_freeze_whackamole_root`). **범위에서 제외.**

**근본 판단**: 어색한 구절을 **재표기해 전역 발음사전에 영구 등록**한다.
- 엔진에 이미 `pronunciation` 스테이지("연음/발음", `_pronunciation`)가 있고, dict은 **구절(여러
  글자) 키**를 긴 키 먼저 치환한다. 즉 `{"좋은데요": "조은데요"}`처럼 구절→재표기가 그대로 된다.
- **정직한 한계**: 발음사전은 "다신 어색한 문장을 안 듣는다"가 **아니다**. 처음 보는 새 문장은
  여전히 어색할 수 있다. 근본인 이유는 다른 데 있다 — **한 번 잡은 건 영원히 안 돌아온다**.
  best-of-2가 매 렌더 주사위를 다시 굴리는 것과 정반대. **끝없는 루프 → 점점 줄어드는 유한한
  루프**로 바꾼다. 반복 패턴이 빠르게 덮이고 남는 건 진짜 새 문장뿐.
- **근본으로 만드는 결정적 조건: 사전은 전역(global)**. 연음 재표기는 *한국어 텍스트*의 성질이지
  *보이스*의 성질이 아니다. 보이스마다 따로 저장하면(현재 per-preset 구조) 같은 교정을 성우
  수만큼 반복 = 두더지잡기 재발. **전역 사전 하나 → 모든 보이스·모든 렌더 적용.**

## 2. 아키텍처 (4개 유닛)

### A. 전역 발음교정 사전 (엔진 · 단일 소스)

- **저장**: 서버 Store(DB). 기존 per-preset `naturalize_profile`과 같은 DB에 산다.
  - **왜 git 파일이 아닌가**: 사장님은 라이브 서버(소리 나는 곳)에서 교정한다. 서버가 git-tracked
    파일에 쓰면 `git status`가 더러워져 `auto_deploy.sh` pull이 조용히 스킵된다(CLAUDE.md 사고 #9).
    DB(gitignore `data/`)는 배포 pull에 안 지워지고 서버 편집이 안전하다 — 기존 프로파일과 동일 모델.
  - 테이블 `global_pron_corrections(phrase TEXT PRIMARY KEY, respelling TEXT, created_at TEXT)`.
    per-entry 행이라 목록·삭제·정렬이 자연스럽다.
  - Store 메서드: `list_pron_corrections()` / `upsert_pron_correction(phrase, respelling)` /
    `delete_pron_correction(phrase)`.
- **주입(단일 지점)**: 새 모듈 `pron_corrections.py`의 `overlay(profile, store)` — 전역 사전
  항목을 `profile["pronunciation"]["dict"]` 위에 병합해 새 profile을 반환(원본 불변).
  - **충돌 규칙**: per-preset dict 항목이 명시돼 있으면 그게 이긴다(더 구체적). 전역은 나머지를 채운다.
    실제로 per-preset dict UI는 이번에 안 만드므로 대개 전역만 존재.
- **호출부(작업대=렌더 일치 보장)**:
  1. `mix_pipeline.synthesize_line`(공유 단일 경로) — 실제 렌더 + 작업대 synth 둘 다 여기를 탄다.
     `merge_profile` 직후 `overlay`. → 저장 즉시 모든 렌더에 반영.
  2. voice-tune preview 엔드포인트(`/api/voice-tune/preview`) — 화면 변환텍스트에도 반영해
     "작업대에서 본 것 = 실제 소리"를 유지.

### B. 관리자 전용 발음교정 작업대 (캡처 통로)

기존 `voice_tune.html`을 관리자 게이트 뒤로 넣고, 발음교정 캡처 UI를 추가한다.

- **게이트**: voice_tune.html 라우트 + voice-tune·pron API 전부 `_require_admin`(access_level=full).
  인프라 존재(`app.py:3881`). 비관리자는 404/403.
- **UI 흐름**(작업대 상단 새 카드):
  1. `textarea`: 어색한 문장 붙여넣기.
  2. `[합성]` → 기존 `/api/voice-tune/synth`로 원본 합성(듣기).
  3. `[AI 교정 제안]` → `POST /api/pron/suggest {text}` → Gemini가 연음/발음 문제 구절과
     재표기안 제안 → 화면에 후보 목록.
  4. 편집칸: 사장님이 `{구절 → 재표기}`를 직접 손질(AI안 채택/수정).
  5. `[원본 vs 교정 A/B]` → 원본 텍스트 / 교정 적용 텍스트 각각 synth → 오디오 2개 나란히.
  6. `[전역 사전에 저장]` → `POST /api/pron/global {phrase, respelling}`. 즉시 목록 갱신.
  7. **현재 전역 사전 목록**: 항목 보기 / 삭제(`DELETE /api/pron/global/{phrase}`).
- **새 엔드포인트**(전부 admin 게이트):
  - `POST /api/pron/suggest` {text} → {suggestions:[{phrase, respelling, reason}]}. Gemini 호출
    (key_vault 기존 규칙). 키 없거나 실패 → {suggestions:[]}(graceful, 수동 입력 폴백).
  - `GET /api/pron/global` → {entries:[{phrase, respelling}]}.
  - `POST /api/pron/global` {phrase, respelling} → {ok:true}.
  - `DELETE /api/pron/global/{phrase}` → {ok:true}.

### C. produce.html 보이스 패널 접기

- 이미지의 보이스 프리셋 패널(안정/자연/표현/속삭임 · 하나/주하/캘릭…)을 `<details>`로 감싸
  **기본 접힘**. `<summary>`에 "🎙 보이스 선택 (평소엔 접어둠)" 정도. 열면 지금 그대로.
- 기능·핸들러 변경 없음 — 순수 래핑(회귀 위험 최소).

### D. 영속성·회귀 방어 (정직한 버전)

- **영속성 = DB**: 전역 사전은 서버 DB에 있어 배포 pull에 안 지워진다(기존 프로파일과 동일).
  이게 "한 번 잡으면 영원히"의 실체 — git-locked 테스트가 아니라 **DB 영속 + 결정적 적용**.
- **메커니즘 회귀 테스트**: `_pronunciation`이 (긴 키 먼저·유령매칭 차단·no-op 배제)로 구절을
  치환한다는 불변식 + `overlay`가 전역 항목을 profile에 올바로 병합한다는 불변식을 테스트로 고정.
  개별 항목이 아니라 **장치**를 잠근다(항목은 DB가 지킨다).
- **백업(선택)**: `GET /api/pron/global`이 곧 export다 — 필요하면 사장님이 JSON으로 받아
  수동 백업/커밋. 주 메커니즘 아님(서버는 git 커밋 안 함 — 사고 #9).

## 3. 데이터 흐름

```
[작업대] 어색문장
   │  AI 제안(선택) → 사장님 손질 → {phrase: respelling}
   ▼
POST /api/pron/global ──► Store.upsert_pron_correction ──► DB(global_pron_corrections)
                                                              │
[렌더/작업대 synth] narration                                 │ overlay()
   │  merge_profile → overlay(profile, store) ◄──────────────┘
   ▼  profile.pronunciation.dict += 전역항목
naturalize → _pronunciation(구절 치환) → synthesize_best(TTS)
   ▼
교정된 음성 (이후 모든 영상에 자동 적용)
```

## 4. 에러 처리

- Gemini 실패/무키 → suggest는 빈 목록, 수동 입력으로 진행(작업대 안 죽음).
- `overlay`는 순수·방어적: 전역 사전 조회 실패(DB 없음 등) → 원본 profile 그대로 반환
  (교정 부가기능이라 죽이면 안 됨 — 기존 `_synthesize_beats` probe 폴백과 같은 원칙).
- 빈 phrase/respelling, phrase==respelling(no-op) → 저장 거부(400).
