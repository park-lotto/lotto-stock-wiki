파생물(AI 리메이크·요약·재작성)을 **원본과 같은 키에 저장하지 마라.** 원본이 소실되고,
그 원본을 학습에 쓰던 코퍼스가 **자기 출력을 다시 학습하는 루프**가 된다.

**Why**: 2026-07-15 쇼핑쇼츠 실사고. 제작소 ⭐위키저장이 확정된 리메이크 대본을 원본 영상의
shortcode에 그대로 썼다(`app.py` `api_produce_save_to_wiki`). 결과:
- `script_extracts`(원본 캐시) 덮임 → `extract_from_url`이 캐시히트 시 재추출을 안 해 **복구 불가**
- `script_wiki`(S급 레퍼런스 창고)에 우리 출력이 섞임
- `element_raw_values` = script_wiki ∪ script_extracts → **자기출력 재학습**

내 라이브 검증 클릭 한 번으로 실제 1건 파괴됨(원본 "…맛은 미쳤어요 친구가 맨날 해달래요"
→ 리메이크 "…맛은 끝내줘요. 요리 고수 언니가"). 더 나쁜 건, 그 직후 `element_category_stats`
24→23 변화를 내가 **"학습 반영 실동작 증명"이라고 사장님께 보고**했다는 것 — 실은 오염된
코퍼스를 학습한 결과였다. 개별 태스크 리뷰 4번과 라이브 grounding이 전부 통과시켰고
**whole-branch 리뷰만 잡았다**([[feedback_whole_branch_review_catches_seams]] 재현).

**How to apply**:
1. 쓰기 전에 물어라 — **"이 키의 주인은 원본인가 파생물인가?"** 파생물은 자기 테이블/키에
   (여기선 이미 `script_drafts`가 있었다. 즉 잃을 게 없었는데도 원본을 덮었다).
2. 같은 일을 하는 **기존 경로와 의미를 맞춰라**. 도서관 `/api/wiki/save`는 항상 원본을
   저장하는데 제작소 다리만 파생물을 썼다. 새 경로가 기존과 다르게 굴면 그게 신호다.
3. **캐시가 복구 경로를 지운다.** "캐시히트면 재계산 안 함" + "캐시를 덮어씀" = 원본 영구소실.
4. UX가 뿌리일 때가 있다 — 버튼이 "위키에도 저장"이라 **내 대본이 저장된다**고 읽혔다.
   문구를 "이 원본 영상 위키에 담기"로 바꾸는 게 수정의 일부였다.
5. 학습 코퍼스에 쓰는 코드는 **자기출력 유입 경로가 있는지** 별도로 점검하라.
