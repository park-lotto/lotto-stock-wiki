# 대문·로그인·브랜딩 — 브레인스토밍 진행 중

> 트리거: "대문로그인 브랜딩 이어서" / "쇼핑쇼츠 이름·대문 이어서"
> 상태: **브레인스토밍(superpowers:brainstorming) 중** — 이름 후보 제시까지 완료, 사용자 선택 대기.

## 무엇을 만드나 (사용자 요청, 2026-07-20)
판매용 SaaS(현 내부명 "쇼핑쇼츠")의 **① 멋진 브랜드 이름 ② 대문(랜딩) 페이지 ③ 로그인 페이지**.
- 참고: 사용자가 보여준 레퍼런스는 **"Shopping Factory"** 로그인(다크·로고·구글버튼·"멤버십은 가입한
  아이디의 구글 로그인으로 진행해주세요"). **UI를 베끼지 말고 그 "구조"로, 우리 브랜딩으로** 만들 것.
- 지금 앱엔 공개 대문이 없다. `/`=로그인 뒤 레퍼런스 랭킹, 로그인=app.py `_LOGIN_HTML`("🛍️ 쇼핑쇼츠").
- 제품 본질: 레퍼런스 링크 넣으면 팔리는 쇼츠가 나오는 자동 제작(레퍼런스 랭킹·렌즈·대본추출·제작소·보이스).
- 기존 브랜드 토큰(계승): **민트×블랙** — `--grad:linear-gradient(135deg,#6ff0d6,#1f9e7a)`, `--sel-fg:#6ff0d6`,
  panel `#111722` (sidebar.js). 대문·로그인도 이 톤을 잇는다.

## ⏭ 다음 (회사 PC에서)
1. **이름 확정** — 위 5안 중 택1 또는 혼합/신규. (사용자가 아직 안 고름)
2. 확정 이름으로 **대문(랜딩) 목적·구조** 브레인스토밍 → 대문 디자인(민트×블랙 계승).
3. **로그인 페이지** 재디자인(레퍼런스 "구조", 우리 브랜드). app.py `_LOGIN_HTML` 교체.
   - ⚠️ 문구 주의: 레퍼런스의 "멤버십은 가입한 아이디로"는 **기존 구매자 로그인 톤** — 우리는 **무료 체험 신규
     유입**이 목표라 "처음이면 무료 체험 시작" 톤이 맞다(현 _LOGIN_HTML이 이미 그 톤).
4. brainstorming → 디자인 승인 → spec(`docs/superpowers/specs/`) → writing-plans → 구현.
   - 구현 시엔 이 브랜딩 전용 트랙을 새로 파는 게 깔끔(현재는 유료게이트 트랙에 브레인스토밍 노트만 얹음).

## 참고 — 유료게이트(직전 작업, 라이브 완료)
설계 재검토 4보강 + 페이블 리뷰 버그수정까지 main 반영됨(`handoff/유료게이트.md`). 구글 로그인 코드·서버키
완료로 로그인 단계는 작동. 남은 운영건: /admin 연락처 입력, OAuth 동의화면 게시(테스트→프로덕션).
