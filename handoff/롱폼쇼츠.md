## 실측으로 확인된 것 (2026-08-15)
- 12분(741초) 통째 전사 → **Gemini 504 DEADLINE_EXCEEDED로 사망**.
  150초 x 5조각 병렬 + 오프셋 병합 → **139구간 정상**. 조각내기가 기본 경로다.
- 선별 결과 5편이 겹치지 않고 영상 전체에 분산됨(0:00/1:42/4:53/5:52/10:23).
- 콜드오픈: 제약 없이 시키면 **구간 시작과 같은 지점**을 고른다(5편 중 2편).
  프롬프트에 "시작 +8초 이후" 명시 → 재실행 시 5편 모두 준수. `_fix_cold_open`은
  그래도 어길 때를 위한 계산 안전망(발동 시 `cold_open_fixed: true`로 표시).
- 키: `SHORTS_GEMINI_KEYS[0]`만 쓰다 **429**(무료 등급 모델당 일일 20건). 로테이션 추가 → 12키.
- ★키 위치 함정: `SHORTS_GEMINI_KEY`는 repo `.env`에 **없다**. `/etc/shopping-shorts.env`
  (systemd EnvironmentFile)에만 있다. 로컬·서버 repo .env로는 3번 실패했다.

## 정정 기록 (내 진단이 틀렸던 것)
"자막 시각이 5초 균등분배라 어긋난다"고 봤는데, 실측하니 **전사가 촘촘한 구간에서는
LLM이 이미 실제 경계를 그대로 쓴다**(9개 자막 전부 일치). 어긋난 건 전사가 성긴 구간
(572~602에 경계가 572/582/600뿐)이었다. 즉 뿌리는 자막이 아니라 **그 구간 전사 성김**.
`snap_captions`는 무해한 안전망으로 남겨뒀다(붙일 경계가 없으면 원래 값 유지).

## 2026-08-15 추가 — 영상 앞부분 구조(사장님 지적)
"0초부터 화면이 곧바로 움직여 **재생 오류처럼 보인다**" → 앞에 정지 카드를 세웠다.
확정 순서: **하이라이트 카드(정지 1.5초) → 하이라이트(콜드오픈) → 로고 범퍼(0.8초) → 본문**

- `HOLD_SECONDS=1.5` — 그 장면의 첫 프레임을 정지시켜 세운다. 검은 화면이 아니라 정지
  프레임인 이유: 검은 화면은 "로딩 중"으로, 정지 프레임은 "멈췄다가 시작"으로 읽힌다.
- `BUMPER_SECONDS=0.8` — 하이라이트가 본문에서 곧 다시 나오므로, 사이에 아무것도 없으면
  "되감겼나?"로 읽힌다. 로고 이미지(`logo_path`)가 있으면 그걸, 없으면 채널명 카드.
- ★함정: `_hold`를 한 번에 만들려고 `-frames:v 1`을 출력 옵션에 걸었더니 **결과가
  1프레임**이 돼 홀드가 사실상 0초였다(실측: 0.3초와 1.0초 프레임이 서로 달랐다).
  프레임을 png로 뽑고 → `-loop 1 -t dur`로 영상화하는 2단계로 고쳤다.
- 검증: hold.mp4 길이 1.500, 0.2초=1.3초 화면 동일(정지 확인), 2.0초부터 배지 등장.
  최종 37.3초 = 1.5 + 7.0(하이라이트) + 0.8(범퍼) + 28.0(본문).

용어: 우리가 `cold_open`으로 부르는 것 = Alphacut UI의 "하이라이트 훅"(설정에 훅 길이
3~7초·전환 페이드). 방송에서 부르는 이름이 cold open이라 코드 필드명은 그대로 두었다.
