## 1. 왜 이 구조인가 — 실측이 길을 정했다 (두 번 바뀜)

**① 서버는 쿠팡을 못 긁는다**

| 경로 | 결과 |
|---|---|
| 서버 직결 (AWS 서울 = **한국 IP**, `ipinfo.io/country` → KR) | **403** |
| 서버 + 독일 주거용 프록시(기존 기록) | 403 |
| 사장님 PC + 헤드풀 Chrome | 200 |

한국 IP인데도 막힌다 → **IP가 아니라 브라우저 지문**을 본다. `collect_raw`가 Playwright로
실제 Chrome을 띄우는 이유다. 그래서 기존 릴레이(PC가 서버에 롱폴링)를 쓴다.

**② PC가 분석까지 하려니 키가 없다**

처음엔 PC가 제미니 분석까지 하게 짰는데 돌려보니 `제미니 키 0개`로 멈췄다 —
분석 키(`SHORTS_GEMINI_KEY`)는 **서버 `/etc/shopping-shorts.env`에만** 있다.
키를 PC로 복사하면 관리 지점이 둘이 된다(0순위-B) → **PC는 긁기만, 분석은 서버**.

## 2. 흐름 (전 구간 실동작 확인 완료)

```
1단계 담기 → 영상 분석 끝
   ↓ (홈템·기타만) 제품명으로 큐잉        ← app.py _queue_product_prefetch
릴레이(PC)가 물어감
   ↓ 쿠팡 검색 → 1위 상품 → 상세·리뷰 Playwright 수집
   ↓ 이미지 긴 변 1400px JPEG로 축소 → base64 전송(상한 12MB, nginx 20m)
서버
   ↓ _analyze_relay_raw → product_facts.analyze (제미니)
   ↓ 캐시 저장  product_facts_<shortcode>
2단계 대본 생성 → _prefetched_facts_for_job이 꺼내 프롬프트에 실음
```

**검색어**: 1단계 태깅의 `source_brief.product`. 3단계 `affiliate_target`을 기다릴 필요가
없다 — 태깅이 이미 제품명을 뽑는다(`script_extract.py:92`).

**렌즈 승격**(유료 SerpApi, **한 번만**): 이름을 못 잡았거나 검색이 **빈손**일 때만
화면 역검색으로 이름을 다시 잡는다. 상품은 찾았는데 분석만 빈 경우는 이름 문제가
아니므로 재시도하지 않는다.

**무자막 해외영상도 대상**: 전사가 비면 적재가 `failed_empty`로 끝나지만(빈 대본 캐시
방지 — 그 판정은 옳고 안 건드렸다) **화면 분석은 됐다**. 재료가 제일 아쉬운 게 그런
영상이라 포함한다. 영상 자체를 못 받은 상태(`failed_download`·`skipped_latched`·
`failed_limit`)만 제외.

## 4. 이 작업에서 잡힌 진짜 버그 3건

1. **`app.py`에 `import json`이 아예 없었다.** `NameError`가 `except`에 삼켜져 **조용히
   빈 값**이 나오고 있었다 — 테스트가 잡았다.
2. **릴레이가 윈도우 콘솔에서 시작하자마자 죽었다.** cp949가 `—`를 못 찍어 첫 `print`에서
   `UnicodeEncodeError`(exit 1). → 출력 스트림 UTF-8 + `errors="replace"`.
   (특수문자를 빼는 건 답이 아니다 — 상품명·리뷰에 어떤 글자가 올지 모른다)
3. **릴레이를 배포 후 재시작 안 해 옛 코드로 돌았다**(내 실수). 그 탓에 첫 실측이
   `제미니 키 0개`로 헛돌았다 → 그 계기로 **재시도 API**를 만들었다(아래).

## 5. 운영 도구

**선수집 재시도** — 선수집은 담기 때 한 번만 걸린다(쿠팡 소프트 차단 방지).
릴레이가 꺼져 있었거나 실패한 건은 이걸로 되살린다.

```
curl -X POST http://127.0.0.1:8849/api/coupang/relay/prefetch_retry \
  -H 'Content-Type: application/json' \
  -d '{"shortcode":"<코드>","token":"<COUPANG_RELAY_TOKEN>"}'
```

⚠️ 경로가 `/api/coupang/relay/` 아래인 이유: 그 접두사가 미들웨어 인증 예외이고
**엔드포인트가 토큰을 검사**하는 기존 규칙이 있다. 인증 방식을 새로 만들지 않았다.

**상태 확인**
```python
Store(DB_PATH).get_setting("product_prefetch_<코드>")   # queued|lens|done|empty
Store(DB_PATH).get_setting("product_facts_<코드>")      # {"facts":…, "product":…}
```

### ★뿌리 — 왜 "고쳤는데 안 된다"가 반복됐나 (다음 세션 반드시 읽을 것)
1. **iframe 캐시**: `produce.html`이 `/scene_lab.html?job=` 만으로 iframe을 로드하고
   `if(src!==u)`라 재로드조차 안 해, 배포해도 브라우저가 **처음 받은 옛 문서**를 계속 썼다.
   하드리프레시도 안 통했다. 같은 파일 `_relabelSceneLab`은 이미 `&t=`를 붙이고 있었다(0순위-B).
2. **포인터 캡처**: 아침에 넣은 밴드 드래그 팬이 `pointerdown` 즉시 `setPointerCapture`를 걸어
   **모든 click이 자식으로 안 갔다**. JS dispatch는 되고 진짜 마우스만 안 되는 모양이라
   코드만 봐서는 절대 안 잡힌다 → **브라우저에서 실제로 눌러봐야 잡힌다**.
