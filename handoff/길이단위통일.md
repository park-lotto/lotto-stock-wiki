## 뿌리 — 예산은 raw, 판정은 norm

이 시스템의 길이는 전부 **norm(공백·문장부호 제외)**이다:

| 자리 | 단위 | 근거 |
|---|---|---|
| `est_seconds()` 화면 "N초" | norm | 코드 |
| `check()` 말 밀도 판정 | norm | 코드 |
| `_SYLLABLES_PER_SEC` 5.7 | norm | 주석: **"한글 1글자 ≈ 1음절"** (공백은 음절이 아니다) |
| ~~`_beat_len_cap`의 per~~ | **raw** | ← 어긋난 곳 ① |
| ~~`chars_per_30s`(DB)~~ | **raw** | ← 어긋난 곳 ② |

실측(히트작 전사 693편): **norm/raw = 0.7395** (p10~p90 0.715~0.776)

### ① [바꾸기]가 길어진다
예산 raw 70자 / 판정 norm 52자 → 곱하기 1.35 전에 이미 26%가 공짜.
**실효 상한 1.8배 = 2026-08-22에 조이기 전과 같은 값.** 62% 긴 문장이 통과했다.

### ② 스타일별 밀도가 통째로 죽어 있었다 (더 큰 문제)
raw 밀도(270~327)가 norm 천장(222)을 **항상** 넘어 매번 잘렸다:
```
밀도 240 → 창 155~222자
밀도 327 → 창 155~222자     ← 서로 다른 창이 1종류뿐
```
**승인 스타일 11개가 100% 같은 창.** 천장 222가 히트작 norm 229와 우연히 가까워
결과가 그럴듯해 안 들켰다.

## 고침 — 경계를 한 곳으로 (0순위-B)

- `script_gate.norm_chars_per_30s()` = DB(raw) → 판정(norm) 경계 **단 하나**
- `script_generate.beat_len()` = 칸 길이 재는 함수 하나. 예산·판정·최종방어 셋이 공유
- 프롬프트가 말하는 수 = 게이트가 거부하는 수
  (종전엔 "(공백 제외)"라 적어놓고 raw를 말해 **지킨 문장이 벌받았다**)

### ★DB 값은 안 고쳤다 — 왜
환산해 넣으면 **저장된 수의 뜻이 조용히 바뀐다.** 다음에 누가 전사에서 밀도를
다시 재 넣으면(그게 자연스러운 동작) raw가 되돌아와도 아무도 모른다.
값은 잰 그대로 두고 **쓰는 자리에서 한 번** 환산한다.
