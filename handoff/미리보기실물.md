## 2026-08-23 — 3번 1단계: 재생 자막에 실제 스타일 (커밋 `fdb995cf2`)

**원인**: 재생 자막 `#subbox`가 CSS에 **흰색 17px·bottom 64px 고정**.
자막 꾸미기를 아무리 해도 재생 화면엔 안 보였다 → 렌더를 돌려야만 결과를 알 수 있었다.

**고침**: `applyPlaySubStyle(box)` 공용 함수. `tickSub`가 그릴 때마다 호출.
- ★규칙을 새로 안 만든다 — `updateCaption`이 정한 `STATE.captionStyle`을 그대로 읽는다(0순위-B)
- 함수 없는 화면(scene_lab 단독)은 `typeof`로 걸러 조용히 넘어간다

### ★내가 낸 버그 2건(둘 다 실측으로 잡음)
1. **`window.STATE`는 항상 undefined** — `STATE`는 최상위 `const`라 window에 안 붙는다.
   (`MIX_JOB`·`WORK_ID`에서 **이미 두 번 밟은 함정**) → `typeof STATE`로 교체.
2. 재생기가 안 열렸을 때 `clientWidth=0` → 배율 0 → 글씨 사라짐. 0이면 `PREVIEW_W`로 폴백.

### 검증
노랑#ffe100·88px·세로42%·민트박스90% → 재생 자막이 `rgb(255,225,0)` /
`rgba(11,143,122,.9)` / `top:42%`로 **그대로 반영**. 46.4px = 380/720 배율 환산값.
pytest **782 passed**.

## 2026-08-23 (2) — 3번 2단계: 재생 화면에 꾸미기 겹치기 (커밋 `b2a688f43`)

**원인**: 재생 화면(`#vidbox`)엔 **영상만** 나왔다. 헤드카피·템플릿 틀·워터마크·로고는
정지 미리보기(`#hcPreview`)에만 있어서, 재생으로 흐름을 보는 동안엔 최종 모습을 몰랐다.

**고침**: `syncPlayDeco()` — `#hcPreview`의 레이어를 **복제해** 재생 상자에 얹는다.
- ★새로 그리지 않는다(0순위-B). 같은 9:16이라 %좌표가 그대로 맞는다.
- 겹침 순서 유지: 틀 → 헤드카피 → 로고 → 워터마크
- id는 `pd-` 접두사로 복제 — **원본 id를 가리키는 코드가 많아** 중복되면 그쪽이 깨진다
- `pointer-events:none` — 재생 중 클릭(일시정지)을 막지 않는다
- 켜기: `startSeq`(재생 시작) + `tickSub`(자막 갱신마다) / 끄기: `stopPlay`

### ★내가 낸 버그: JS 하네스는 진짜 DOM이 아니다
`stopPlay`에서 `_pd.remove()`를 불렀는데 **테스트 스텁엔 `remove`가 없어**
`test_preview_no_audio_clock` 4건이 깨졌다 → `typeof` 검사로 막았다.
**하네스에서 DOM 메서드를 부를 땐 있는지 먼저 볼 것.**

### 알게 된 것(고칠 것 아님)
워터마크(88%)와 자막(80%)이 겹친다 — **원본 미리보기에서도 같고 실제 렌더도 그렇다.**
내 오버레이가 만든 문제가 아니라 **기본 자리 자체가 겹치는 것**. 사장님이 불편하시면
워터마크 기본 위치를 손보면 된다(별건).

### 검증
`#playDeco`가 `#vidbox` 안에 생성 / 자식=헤드카피·워터마크 복제본 / `pointer-events:none` /
정지 시 걷힘 / 스크린샷으로 세 요소 동시 표시 확인 / **pytest 845 passed**
