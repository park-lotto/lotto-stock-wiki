## 무엇을 고치는 작업인가

유튜브 레퍼런스 랭킹이 짜깁기 쇼핑쇼츠 소재를 못 보여준다. 실측(2026-07-29):
6,062건 중 '기타' 3,009건(절반), delta 상위 12개 중 10개가 연예·아이돌 클립.

**뿌리**: 자동 수집이 계정 시드 수집과 **키워드 검색**을 함께 돌린다. 유튜브 시드 464개는
전부 `kind='account'`라 잡음의 유일한 출처는 `preset_keywords()` 검색 경로다.
(처음엔 "등록 채널이 수집에 안 쓰인다"고 판단했으나 코드 확인 결과 **틀렸다** — 설계문서에 정정 기록)

## ⚠️ 지금 상태 — seed_only는 구현됐지만 **꺼져 있다**

`scripts/daily_youtube_collect.py`는 아직 `seed_only` 없이 부른다(기본 False).
**의도적이다.** 켜면 키워드 경로가 빠져 등록 시드만 남는데, 랭킹에 등장하는 채널 715개 중
시드 등록분은 464개뿐이라 **미등록 우량 채널을 먼저 넣지 않고 켜면 수집량이 급감한다**
(설계 §T3이 §T4보다 먼저인 이유). 그래서 라이브 동작은 오늘 이전과 **완전히 동일**하다.

## ⏭ 남은 일

1. **T4 — 적합도 0% 채널 일괄 삭제 UI** (계획 Task 4, 미구현)
   - 기존 `DELETE /api/seeds`를 채널마다 순차 호출. 새 API 만들지 않는다.
   - ★행의 영상 수 키는 `total`이 아니라 **`video_count`** 다(계획서엔 `total`로 적혀 있으니 주의).
   - ★**수집이 안 된 채널도 적합도 0%로 보인다**(데이터 없음 ≠ 나쁨). 반드시 `video_count >= 3`
     조건으로 걸러야 멀쩡한 채널을 안 지운다. 리뷰어도 같은 지적을 했다.
   - 삭제는 되돌릴 수 없으니 개수·예시 채널명을 보여주고 확인받는다.

2. **T5 — `scripts/register_good_youtube_channels.py`** (계획 Task 5, 미구현)
   - 적합도 100% + 영상 3건 이상인 **미등록** 채널을 시드에 넣는다.
   - ★`--dry-run` 먼저. 실행 전 items에 `channel_id`가 있는지 확인(없으면 `ranking.py`에서 실어야 함).

3. **T6 — seed_only 켜고 실측** (T5 실행 완료 후에만)
   - `scripts/daily_youtube_collect.py`의 `service.collect(platform="youtube")` →
     `service.collect(platform="youtube", seed_only=True)` 로 바꾸고,
     `shopping_shorts/tests/test_daily_youtube_collect.py:15`의 단언도 `is False` → `is True` 로 뒤집는다.
   - 배포 후 1회 수집 강제 실행 → 판정: **'기타' 비율 20% 미만**(현재 49.6%),
     **수집 1,000건 이상**(경로 전환 실패 감지), 상위 12개에 연예 클립 0.
   - 실패 시 `seed_only`를 즉시 되돌려 배포.

4. **실브라우저 육안 확인** (아직 못 함)
   - 로컬 DB에 유튜브 시드가 0개라 보드가 비어 렌더 확인이 불가능했다. pytest로만 검증된 상태.
   - 라이브에서 `레퍼런스 랭킹 → 유튜브 → 📊 채널 지표·관리 열기` 를 열어
     적합도 컬럼·정렬·배지 색이 제대로 뜨는지 봐야 한다.

## 이월된 리뷰 지적 (Important, 이번 범위 밖)

- `service.py:67` — 적합도 매칭이 **채널명 문자열** 기준이라 채널이 개명하면 어긋나 0%로 빠질 수 있다.
  희귀 케이스이고 `channel_fitness`의 기존 설계라 이번엔 손대지 않았다.
- 미수집 채널의 적합도 0%가 "적합도 낮음"(빨강)과 시각적으로 구분되지 않는다. T4에서 `collected`
  플래그나 `video_count`로 갈라야 한다.
