# 소재창고 — 보드 페이지 + 카테고리 워커 (설계, 2026-10-16, 관제 097)

> ★정식 서버 규격 = `2026-10-16-소재창고-api.md`(커밋 cf47e8af3, 구현 c7b158235 `shopping_shorts/calcopy_topics.py`).
> 보드·워커는 **그 규격에 맞춰 다시 짰다**(이 문서 §7). 아래 §3 은 규격 확정 전 초안이라 **역사 기록**일 뿐 — 따르지 마라.

## 7. 정식 규격에 맞춘 뒤의 모습 (최종)

| 쪽 | 부르는 것 |
|---|---|
| 워커 `worker.py` | `claim_next{worker,steps}` → 단계 → `upload/{name}`(원시 바이트) → `advance{data,outputs,cost{gemini,typecast}}` / 실패 `release{error}` · 잡은 동안 `{id}/heartbeat{doing}` · 할 일 없으면 `POST topics`(find 결과, 중복 409 는 건너뜀) |
| 워커 인증 | 관리자 세션 쿠키 `dash_auth` — 라이브는 `tools/live_admin.admin_cookie()` 재사용(403 이면 한 번 재발급), 로컬은 `--cookie`/인증 꺼진 로컬 앱 |
| 단계 산출 `worker_steps.py` | bench=`data.bench`+벤치.md · score=`data.score.criteria`(근거 있는 기준 5개 이상, 없으면 StepError) · assign=`data.assign{channel,preset}` · script=`outputs.script=대본.json` · source=`data.rights`(재료 후보 영상별) · plan=`outputs.plan=계획.md` · produce=`outputs.final=final.mp4`+`cost.typecast` · check=`outputs.verdict=verdict.json`(+sheet_1s·diff·side_by_side·original) |
| 보드 `admin_calcopy_topics.html` | `GET /api/admin/calcopy/topics`(kpi·caps·workers.stale·errors·decide·grid 를 서버 판정 그대로) · `GET {id}` 상세 · `POST {id}/review{stage,verdict,reason,back_to}` · 서빙 `GET /admin/calcopy/topics`(app.py API 블록 끝 1줄) |

### 규격 차이·요청 (API 담당에게)

1. **claim_next 에 카테고리·트랙 거르기가 없다** — `--category 식품` 워커가 홈템 소재(#3 다이소)를 집었다(로컬 HTTP 실측). `claim_next{worker,steps,category?,track?}` 요청.
2. **release 된(last_error) 소재를 claim_next 가 곧바로 다시 준다** — 같은 행 script 실패가 다음 tick 에 바로 다시 잡혔다(실측). 워커는 실패 뒤 쉬는 것으로 막아 뒀지만(loop), 서버에서 `last_error` 행은 사람이 풀 때까지(또는 N분) 건너뛰는 게 맞다.
3. **쉬는 워커는 보드에 안 보인다** — workers 는 잠금 주인만. find 실패처럼 행이 없는 멈춤도 둘 곳이 없다(지금은 워커 로그만). 워커 맥박 표(`POST workers/heartbeat{worker,category,track,step,last_error,done_today}`) 요청.
4. 비용 종류가 gemini·typecast 둘뿐이라 편당 **시간**(advance 의 seconds)을 못 보낸다 — KPI hours_per_passed(추가→통과)로 대신.
5. 워커 인증이 관리자 세션 쿠키(2시간)라 밤샘 워커는 SSH 로 재발급한다(`live_admin.admin_cookie`). SSH 가 막히면 워커도 멈춘다 — 전용 키 경로가 필요해지면 그때.
6. claim_next 는 비용 상한이면 429 가 아니라 `reasons` 로 알려 준다(규격 §4) — 워커는 reasons 를 로그에 남기고 다른 일을 한다(시험 `test_비용상한이면_그단계는_건너뛰고_다른행`).

## 1. 상태기계 (사장님 10-16)

```
found → benched → scored → assigned → scripted → sourced → plan_review → producing → produced → final_review → passed | rejected
```

| 워커 단계(step) | 받는 상태 | 끝나면 | 엔진 |
|---|---|---|---|
| `find` (행 없음) | — | 새 행 `found` | `topic_find.run` |
| `bench` | found | benched | `topic_find.bench` (후보 1개) |
| `score` | benched | scored | `topic_find.score` + `_clean_scores`·`overlap`·`total` |
| `assign` | scored | assigned | 워커의 `--channel` 프리셋을 붙인다(추천 기준은 서버가 거른 행만 줌) |
| `script` | assigned | scripted | `script_engine.run` |
| `source` | scripted | sourced | `remake.py` 후보 모드(--materials 없이) → 재료후보 시트·재료_뼈대.json |
| `plan` | sourced | **plan_review** | `remake.py --plan-only` → 계획.md·접촉 시트 |
| (사람) 선검수 통과 | plan_review | producing | 보드 결정 줄 |
| `produce` | producing | produced | `remake.py` 전체 → final.mp4 |
| `check` | produced | **final_review** | `compare.compare` → 차이표.md·side_by_side.jpg·1초 시트 |
| (사람) 최종 통과 | final_review | passed | 보드 결정 줄 |
| (사람) 반려 | plan_review·final_review | rejected 또는 `back_to`(되돌아갈 상태) | 사유 필수 |

★검수 둘(plan_review·final_review)은 **사람 자리**. 워커가 그 상태를 넘기는 advance 를 보내면 서버가 409 `review_gate` 로 거절해야 한다.

## 3. API 규격 초안 (API 담당에게 요청 — 이대로 맞추면 워커·보드가 고칠 것 없음)

### 3-1. 워커 쪽 (PC 실행기 — 로그인 쿠키 없음)

- 경로 접두사 `/api/calcopy_worker/` — 로그인 게이트 `_AUTH_ALLOW` 예외 + 자체 키(`CALCOPY_RELAY_KEY`, 진행판 설계 §5-2 와 같은 키).
  키는 헤더 `X-Calcopy-Key`. 키 미설정이면 항상 403(yt_relay 와 같은 원칙).
- 모든 응답 JSON. 실패는 `{"error":"<코드>","detail":"<사람이 읽는 이유>"}`.

| 메서드·경로 | 몸 | 응답 |
|---|---|---|
| `POST claim` | `{worker, category, track, channel, exclude_steps:[…]}` | 200 `{topic:<row>, step:"script", lease_until}` · 200 `{topic:null, step:"find"}`(이 카테고리 후보가 모자람 = 찾으러 가라) · 200 `{topic:null, step:null, reason:"…"}`(할 일 없음) · **429** `{error:"budget", step:"produce", which:"tts", detail}`(그 단계 비용 상한) |
| `POST topics` | `{worker, category, track, rows:[{topic, source, bench?, scores?, rights?}]}` | 200 `{ids:[…]}` — find 결과를 found 로 넣는다(서버가 겹침 중복 거름) |
| `POST topics/{id}/advance` | `{worker, step, artifacts:{name:{local, url?}}, cost:{llm_calls, tts_calls, seconds}, data:{…}, error?:"이유"}` | 200 `{ok:true, topic}` · **409** `{error:"lock"}`(잠금 내 것 아님/만료) · **409** `{error:"review_gate"}`(검수 자리 넘기기) · `error` 가 있으면 상태 그대로 + `row.error` 기록 + 잠금 해제(같은 행을 바로 다시 주지 않음) |
| `POST topics/{id}/file` | multipart `name`, `file` | 200 `{url}` — 보드에서 볼 작은 산출물(md·jpg·mp4 ≤ 40MB) |
| `POST heartbeat` | `{worker, category, track, channel, step, topic_id, host, done_today}` | 200 `{ok:true}` — 잡고 있는 행의 `lease_until` 을 지금+11분으로 늘린다 |

- 잠금: claim 이 `lease_until = 지금+11분`. heartbeat 가 없으면 11분 뒤 다른 워커가 claim 할 수 있다(잠금 충돌 시험 대상).
- `data` 는 단계가 행에 남길 값(score → `scores`, bench → `bench`, assign → `assign`). 서버가 단계별로 받을 키를 정한다.

### 3-2. 보드 쪽 (관리자 세션, `_require_admin`)

| 메서드·경로 | 응답·몸 |
|---|---|
| `GET /admin/calcopy/topics` | `static/admin_calcopy_topics.html` 서빙(★API 담당이 기존 `/admin/calcopy` 옆에 1줄 라우트 추가) |
| `GET /api/admin/calcopy/topics/board?category=` | `{states:[…11개], categories:[…], topics:[row 요약], workers:[…], meter:{…}, stops:[…], gallery:[…], now}` — 한 번에(10초 갱신이 요청 1개) |
| `GET /api/admin/calcopy/topics/{id}` | row 전체(+history) |
| `POST /api/admin/calcopy/topics/{id}/review` | `{decision:"pass"|"reject", reason, back_to?}` → `{ok, topic}`. reject 는 reason 필수(없으면 400). `back_to` 없으면 rejected |
| `GET /api/admin/calcopy/topics/{id}/file/{name}` | 올린 산출물 |

`workers[]` = `{worker, category, track, channel, step, topic_id, host, last_heartbeat, age_sec, done_today}` — `age_sec` 는 서버가 잰다(보드는 660초 넘으면 빨강).

`meter` =
```json
{"candidates_today":12,
 "plan_pass":{"pass":3,"total":5},"final_pass":{"pass":1,"total":2},
 "per_piece":{"seconds_median":1830,"won_median":420},
 "llm":{"used":37,"cap":200},"tts":{"used":2,"cap":10}}
```
`stops[]` = `{topic_id, topic, step, error, at, worker}` — advance(error=…) 로 멈춘 행 전부(조용한 실패 금지). 비용 상한 거절도 `{step, error:"비용 상한: tts 10/10"}` 로 넣는다.
`gallery[]` = passed 행 `{id, topic, channel, final_url, thumb_url, at}`.

## 4. 워커 (`tools/calcopy/engine/worker.py`)

```
py tools/calcopy/engine/worker.py --category 식품 --track bench --channel yummyknow [--once|--loop]
     [--server https://shoppingshorts.duckdns.org] [--out C:/숏템_칼카피/worker] [--name pc-식품-bench]
```
- 키: 환경변수 `CALCOPY_RELAY_KEY`. 서버 기본: `CALCOPY_SERVER` 또는 shoppingshorts 도메인.
- `tick()` 한 번 = claim → (429 budget 이면 exclude_steps 에 넣고 다시 claim, 최대 단계 수만큼) → 단계 실행 → 산출물 업로드 → advance.
- 단계 예외·엔진 없음(`NotImplementedError`)·엔진 실패 = **advance(error="<단계>: <예외 원문 300자>")** — reject 가 아니다(사람 판정 자리를 워커가 쓰지 않는다).
- heartbeat = 별도 스레드 60초. 단계가 오래 돌아도 잠금이 유지된다.
- `--loop` 는 할 일 없으면 60초 쉬고 다시. `--once` 는 tick 1회.

## 5. 보드 (`admin_calcopy_topics.html`)

- 상태 11칸 칸반 × 카테고리 필터 · 행 클릭 → 상세(산출물 링크·계획.md 미리보기·1초 시트·완성본/원본 나란히·판정 사유·이력).
- 워커 패널(heartbeat 11분 넘으면 빨강) · 결정 줄(plan_review·final_review 행만, 통과/반려+사유+되돌아갈 상태) · 계기판 · 멈춘 이유 · 통과작 갤러리.
- 10초 갱신. 폰 폭(≤640px)에서 칸반은 가로 스크롤 띠 대신 세로로 접힌다.
- 벤더명 금지(기존 admin 화면 관례: AI 호출 → "글 AI 호출", 음성 → "나레 음성 생성"). 썸네일 `loading="lazy"` 금지(test_no_lazy_thumbs).
- 링크는 루트 마운트(`/static/` 접두사 금지, test_static_link_paths).

## 6. 미확인·열린 질문 (API 담당과 맞출 것)

1. `assign` 을 워커가 할지(지금 초안) 사람이 할지 — topic_find 주석은 "고르는 건 사람/오푸스 자리". 서버가 assign 을 사람 자리로 정하면 워커는 그 단계를 안 받을 뿐 코드 변경 없음.
2. 정적 마운트가 루트라 `/admin_calcopy_topics.html` 은 로그인 게이트만 거친다(기존 `admin_calcopy.html` 과 같음). 데이터는 관리자 API 라 비관리자에겐 빈 화면.
3. 산출물 업로드 상한(40MB 제안) · 서버 저장 위치.
4. 실제 엔진(topic_find·script_engine) 실행은 무료 제미나이 쿼터(16:00 KST 리셋) 뒤에 시험 — 이 문서 시점엔 가짜 단계로만 돌렸다.
