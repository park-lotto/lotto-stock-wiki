# 장면 기반 대본 교정 출구 설계

## 목표

영상 재료가 한 편이라도 있으면 대본 생성 API는 초안을 최소 1개 반환한다. 검사는 결과를 없애는 차단기가 아니라 문제 문장을 고치는 교정기로만 사용한다.

## 고정 규칙

- 인증·소유권·재료 없음은 기존처럼 요청을 거절할 수 있다.
- 재료가 있으면 AI 생성 실패, 판정기 장애, 사실 근거 실패, 다른 제품 혼입과 관계없이 대본을 0개로 반환하지 않는다.
- 사실 근거가 없는 문장은 그대로 통과시키지 않는다. 해당 문장만 재작성한다.
- 다른 제품이 중심인 초안은 사용자에게 노출하지 않고 고정 제품으로 전체 재작성한다.
- 자동 교정까지 실패하면 장면 관측문과 원본 발화만으로 최소 안전 대본을 조립한다.

## 처리 흐름

1. 기존 `claim_evidence()`가 원본 발화·장면 관측·검증된 상품 사실을 한 벌로 만든다.
2. 기존 스타일 생성기가 첫 초안을 만든다.
3. 공용 의미 검사가 문장별 지원 여부와 다른 제품 혼입 여부를 반환한다.
4. 사실 근거만 실패하면 실패 문장과 실제 근거를 생성기에 주고 그 문장만 교체한다.
5. 다른 제품이 섞이면 고정 제품과 실제 근거만 주고 전체를 다시 쓴다.
6. 제한된 교정 횟수 안에 통과하지 못하거나 AI·판정기가 장애이면 `grounded_fallback`이 실제 장면 설명과 원본 발화를 순서대로 사용해 최소 1안을 만든다.
7. API는 통과본을 우선 반환한다. 최소 안전 대본에는 `fallback_reason`을 붙여 화면에서 이유를 알린다.

## 최소 안전 대본

- 장면 또는 원본 발화에서 실제 제품을 설명하는 문장을 최대 5개 고른다.
- 가격·인기도·품절·시간·효능을 새로 만들지 않는다.
- 제품명이 근거에 있으면 첫 문장에 제품을 밝힌다.
- 마지막에는 성능 주장이 없는 중립적인 댓글 CTA를 붙인다.
- 스타일의 칸 순서는 가능한 범위에서 유지하되, 근거보다 스타일을 우선하지 않는다.

## 오류 처리

- 재료 있음 + 생성/검사 실패: HTTP 200, 초안 1개 이상.
- 재료 없음: 기존 HTTP 422와 구체적 안내 유지.
- 다른 제품 초안: 원본 후보 폐기 후 자동 교정 또는 최소 안전 대본.
- 판정기 장애: 사용자 요청을 막지 않고 최소 안전 대본.
- 내부 예외: 서버 로그에는 원인을 남기되 사용자에게는 빈 배열을 반환하지 않는다.

## 검증 기준

- 사실 검사만 실패한 후보가 문제 문장 교정 후 반환된다.
- 다른 제품 후보는 노출되지 않고 고정 제품 대본으로 대체된다.
- 생성기 빈 응답과 판정기 예외에서도 장면 재료가 있으면 HTTP 200과 1안 이상이다.
- 재료가 없을 때만 422다.
- 정상 통과본이 있을 때는 폴백이 끼어들지 않는다.
- 실제 얼음정수기와 차량용 변기 자료로 생성 결과를 읽어 제품·장면 일치 여부를 확인한다.

## 범위
