# 레퍼런스 랭킹 5플랫폼 확장 — 설계

- 날짜: 2026-07-24
- 트랙: 레퍼런스랭킹개편
- 상태: 실증 완료 → 설계 승인 대기 → writing-plans

## 1. 목표와 제약 (사장님 확정)

지금 레퍼런스 랭킹은 **인스타 전용**이다. 이를 **인스타·유튜브·틱톡·샤오홍슈·도우인** 5개
토글로 확장한다. 사장님이 못박은 제약 3가지:

1. **랭킹 방식으로 수집** — 검색결과 나열이 아니라, 같은 강도 지표로 줄 세워야 한다.
2. **숏폼만** — 유튜브 롱폼 제외, 릴스/쇼츠/틱톡/단편만.
3. **과금 없는 구조(Apify 금지)** — 현재 렌즈·틱톡검색이 쓰는 Apify 건당과금을 새 확장엔 안 쓴다.

## 2. 실증 결과 (2026-07-24, 실제 실행)

추측 금지 원칙에 따라 yt-dlp를 **실제로 돌려** 확인했다.

| 플랫폼 | 채널 목록 | 목록에 딸려오는 지표 | 판정 |
|---|---|---|---|
| 유튜브 | 공식 Data API(무료 쿼터) | 조회수·좋아요·댓글 | ✅ 자동 가능 |
| **틱톡** | **`tiktok:user` 실행 성공** | **view_count·like_count·comment_count·timestamp·duration 전부 1회 호출에** | ✅ **자동 가능(무료)** |
| 샤오홍슈 | ❌ 전용 프로필 extractor 없음(`[generic]` 폴백) | 개별 영상은 추출 가능 | ⚠️ 자동 불가 |
| 도우인 | ❌ `Unsupported URL` | 개별 영상은 추출 가능 | ⚠️ 자동 불가 |
| 인스타 | 현행 Apify(유료) | — | 현행 유지 |

실측 원문(틱톡 @tiktok, flat-playlist 3건): `view_count=519700, like_count=3805,
comment_count=220, timestamp=1784838608, duration=47`.

**주의(실측된 불안정성)**: `--playlist-end 1`에서 `entries=None` 빈 응답이 1회 발생했다(3건은
정상). 채널 수십 개를 연속 호출하면 레이트리밋도 예상된다 → **재시도·간격·부분실패 허용이 필수**.

## 3. 아키텍처 — 두 레인

플랫폼 성격이 다르므로 **하나의 랭킹 화면, 두 개의 수집 레인**으로 간다.

### 레인 A — 자동 채널 랭킹 (인스타·유튜브·틱톡)
"채널을 등록해두면 시스템이 훑는다" = 지금 인스타와 같은 사용감.
1. 플랫폼별 **레퍼런스 채널 등록**
2. `지금 수집` → 각 채널의 **최근 48시간 숏폼** 목록 + 지표 수집
3. 강도 계산 → 랭킹

- **인스타**: 현행 그대로(Apify `fetch_reels`). 변경 없음.
- **유튜브**: 공식 Data API로 채널의 최근 업로드 → **Shorts만**(duration ≤ 60s). 기존
  `_collect_youtube()`는 **키워드 시드 기반**이라, 채널 기반으로 **바꾼다**(사장님 "인스타처럼").
  기존 키워드 시드 경로는 삭제하지 않고 남긴다(발굴 용도).
- **틱톡**: **신규** — yt-dlp `tiktok:user` 채널 목록. 기존 Apify 키워드 수집(`_collect_tiktok`)은
  **자동 랭킹 경로에서 제외**(과금). 삭제는 안 하고 관리자 발굴 용도로만 남긴다.

### 레인 B — 담기 랭킹 (샤오홍슈·도우인)
채널 목록이 불가하므로 "사람이 고르고 시스템이 재는" 구조.
1. 기존 **딥링크 검색**(`https://www.xiaohongshu.com/search_result?keyword=` 등)으로 그 플랫폼
   검색창을 새 탭에 연다 — API 아님, **0원**
2. 사장님이 보고 **담기**(기존 기능) → URL 저장
3. 시스템이 담긴 URL을 **yt-dlp로 지표 추출**(조회수·좋아요·댓글·시각·길이) — 0원
4. **담긴 것들 안에서** 같은 강도 로직으로 랭킹

## 4. 강도 지표 매핑 (플랫폼 간 비교 가능하게)

지금 인스타 강도는 **댓글 기반**이다(속도=댓글÷경과시간, 가속=Δ의 Δ, 참여밀도=댓글÷팔로워).
플랫폼마다 얻는 숫자가 달라 **주신호를 플랫폼별로 지정**한다.

| 지표 | 인스타(현행) | 유튜브·틱톡·CN |
|---|---|---|
| **속도** | 댓글 ÷ 경과시간 | **조회수 ÷ 경과시간** (가장 신뢰 가능한 신호) |
| **가속** | 이번 Δ − 직전 Δ | 동일(스냅샷 2회 필요) |
| **참여밀도** | 댓글 ÷ 팔로워 | **(좋아요+댓글) ÷ 조회수** = 반응률 (팔로워 없이 계산) |

- 참여밀도를 반응률로 두면 **팔로워 수를 못 얻는 플랫폼에서도** 작은 채널이 상위로 올 수 있다
  (원래 참여밀도의 취지 보존).
- **탭 라벨은 그대로**(전체·속도·가속·참여밀도) 두되, 툴팁에 플랫폼별 계산식을 표기한다 —
  같은 이름이 다른 뜻이면 사장님이 오독한다.
- 도우인은 `playCount`가 0으로 오는 사례가 실측돼 있다 → **조회수 0이면 좋아요 기준으로 폴백**하고
  화면에 "조회수 미제공" 표시.

## 5. 숏폼 필터
- 유튜브: duration ≤ 60초(또는 Shorts 판정) — 롱폼 제외
- 틱톡: yt-dlp `duration` 사용(목록에 이미 옴)
- 인스타: 릴스만(현행)
- 샤오홍슈·도우인: 담을 때 사람이 숏폼만 담음 + duration으로 2차 필터

## 6. 안정성 (실측 기반)
- yt-dlp 호출은 **채널 간 간격**(예: 1~2초)과 **재시도 2회**를 둔다 — 빈 응답 실측됨.
- **부분 실패 허용**: 채널 하나 실패해도 나머지로 랭킹을 만든다(전체 실패로 죽이지 않음).
- 실패 채널 수를 화면 상태에 표시(관리자 전용 시스템 상태 패널 활용).

## 7. UI
- 숨겨진 `#platformTabs`(인스타·유튜브·틱톡)를 **되살리고 5개로 확장**. `switchPlatform()`·`PLATFORM`
  로직이 이미 보존돼 있어 그 위에 얹는다.
- 플랫폼별로 보이는 컨트롤이 갈린다:
  - 레인 A: `채널 등록` + `지금 수집`
  - 레인 B: `딥링크 검색 버튼들` + `담긴 항목 지표 새로고침`
- 저장은 이미 플랫폼별(`save_last_run_platform`/`load_last_run_platform`)이라 그대로 쓴다.

## 8. 단계 (한 번에 다 하지 않는다)
- **Phase 1 — 틱톡 자동 랭킹**: 실증이 끝났고 신규 가치가 가장 크다. 토글 노출(인스타/틱톡) +
  틱톡 채널 등록 + yt-dlp 수집 + 지표 매핑 + 재시도.
- **Phase 2 — 유튜브 채널 기반 전환**: 공식 API로 채널 최근 Shorts. 토글에 유튜브 추가.
- **Phase 3 — 샤오홍슈·도우인 담기 랭킹**: 딥링크 + 담긴 URL 지표 추출 + 랭킹.

Phase 1만으로도 "인스타 외 플랫폼이 자동으로 랭킹된다"는 목표가 실물로 선다.
