## ✅ 이번 세션 완료 (전부 main 병합·라이브 배포됨)

1. **수집 버튼 배선** — `/api/collect` → `_bank_ingest_collected_bg`가 `ingest_collected`(캡션 상위100 흡수)
   **+ `harvest_hooks`(훅수확 4시크론→버튼 이관)** 실행. 4시 크론(`daily_batch.run`)은 유지보수만.
2. **스팸훅 필터** — `hook_harvest.is_engagement_bait`(댓글/프로필/DM류 차단). harvest·ingest_script 양쪽 적용.
3. **제미니 일일 검열** — `gemini_audit.py`: 3지표 신호등(🟢🟡🔴) = 가동 성공률 · 산출 완성도 · 훅 스팸율.
   `ingest_collected`가 attempted/succeeded 계측(예전 조용한 실패 가시화). 결과는 `bank_ingest_last` +
   `gemini_audit_last` 설정에 저장, `/api/bank/ingest_report`로 수집화면 패널이 폴링 렌더.
4. **키풀 로테이션 수정(진짜 병목)** — `comment_gen._next_live_key_and_idx`(라운드로빈) +
   `pattern_bank._default_call`가 분당429(is_quota_error, PerMinute)를 영구제외 말고 **다른 키로 재시도**.
   기존은 `is_daily_exhausted_error`(PerDay만)라 분당429=즉시None → 45키중 live[0] 하나만 때려 성공률 7%.

## ⏭ NEXT (회사에서 이어서) — 검열을 "빼서 쓰는 쪽"까지 확장

사장님 요구(2026-07-23): 검열이 넣기(수집·정리)뿐 아니라 **은행에서 빼서 대본 만들 때 제미니가
진짜 은행을 따르는지**까지 감지해야 한다. 4갈래: ①어떻게 가져오는지 ②어떻게 정리하는지
③뭐가 제일 좋은지 판단 ④**빼서 쓰는 로직 + 제미니 순응 감지**.

### 빼서 쓰는 로직 (이미 매핑함 — `bank_assemble.py`)
- `assemble_bank_context(store, category, k)` → `spine_charter`(승인 스파인 아크·비트) +
  `parts_block`(STYLE_BUCKETS 승인부품 상위perf 풀에서 랜덤 k) + (호출부에서 `avoid_block` novelty).
- 이게 `edit_plan._scene_first_candidates`의 **bank_context**로 프롬프트에 주입됨(edit_plan.py:417).
- 즉 은행→생성은 "승인부품·스파인을 프롬프트에 넣고 제미니에게 참고하라"는 구조.

### 설계할 감지(검열 확장) — 미결
- **사용 감지**: 생성 시 bank_context가 비었나/찼나(승인부품 0이면 은행 무용). 카테고리별 스파인 유무.
- **순응 감지**: 제미니 산출 대본이 주입 스파인 비트/부품 결을 실제로 따랐나 vs 무시했나.
  (표절금지라 그대로 베끼면 안 되지만, 아크/비트는 따라야 함 — "따름"의 판정 기준 설계 필요.)
- **판단 감지**: `candidate_judge`(후보 3개 중 best 선택)가 잘 작동하나 — 점수 분포·일관성.
- 전달: 대시보드 검열 패널에 "생성 순응" 섹션 추가.
- ⚠️ 설계는 `superpowers:brainstorming`으로 — 스펙 `docs/superpowers/specs/2026-07-23-수집흡수배선-제미니검열-design.md` 이어서.

### 흡수 성공률 추가 개선(남음)
- top_n=100 상한에 걸려 멈춤 → 상한 상향 검토. 남은 실패엔 키문제 외 **빈추출(비한국어·짧은 캡션)**도
  섞임 → 검열 metric에서 "키실패 vs 빈추출" 분리하면 신호가 정확해짐.
- 서버 전용키 16개중 11 라이브(5 일일소진). 로테이션 켜졌으니 페이싱(호출 간격)만 주면 더 오를 여지.
