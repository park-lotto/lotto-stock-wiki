# 장면 우선 대본 모드 (Scene-First Script Mode) 설계 — 2026-07-20

## 배경 · 스파이크 증거

**문제**: 제작소가 대본을 먼저 확정(`given_script`)하고 장면을 나중에 매칭 → 대사↔화면 어긋남(실측 job 2c9db3e2c337·454169a1b828, 둘 다 given_script). 벤치 릴처럼 딱딱 맞으려면 **장면을 보며 대본을 써야** 한다.

**스파이크로 증명(서버 실키·실영상, 양파 보관법 소스 2개)**:
- scene_cut이 영상당 다수 조각+scene_desc = 장면 팔레트(2영상 28조각). *(scene_cut ⓪은 이미 라이브)*
- **맨몸 프롬프트 → 대본 퀄 낮음**(스토리 밋밋). **진짜 스토리 헌장(`script_generate._STORY_RULES_CORE`+`_STORY_DECLARE`)을 팔레트와 결합 → 퀄 급상승**: 훅 한 방·인과 사슬·비법 킥 감추기·키워드 CTA 다 살고, 동시에 각 비트가 장면(seg_ids)에 매칭(fit 4~5).
- 비트당 다중컷(seg_ids 2~4)으로 속도감 확보(5비트 17컷).

**결론**: 정답 = **기존 대본 엔진(퀄) + 장면 팔레트(매칭) 결합**. 대부분 코드가 이미 있고, 둘을 잇는 신규 생성함수 1개 + 후보 UI가 실제 신규 작업.

## 확정 결정 (2026-07-20, 사장님 "끝까지 묻지말고" 위임 — 합리적 기본값)

- **신규 모드로 추가**, 기존 given_script 흐름은 안 깬다(안전).
- **후보 3개** 생성 → 점수로 **최고안 추천 배지**, 최종 선택은 사장님(UI).
- **출력을 기존 EDL 포맷**(`build_edit_plan` 반환형)으로 만들어 render·respine·conform·produce.html 스왑UI 전부 **그대로 재사용**(신규작업 최소화).
- 다국어 레퍼 → 한국어 대본, 원본과 내용 안 겹침(표절 n-gram 가드 재사용).
- 억지/약한 매칭(forced 또는 fit≤2)은 **페이즈1의 빨간불+[다른 화면으로] 스왑 UI에 자동 연결**(이미 라이브).

## 아키텍처

### 신규 핵심 함수 — `build_scene_first_plan` (edit_plan.py)
```
build_scene_first_plan(source_scripts, reference_text, target_seconds,
                       n_candidates=3, video_type=None) -> dict
```
- `source_scripts`: run_mix_job이 이미 만드는 것(scene_cut 반영된 extract_script 결과들). 각 세그먼트에 seg_id·scene_desc.
- `reference_text`: 지정 레퍼 영상의 full_text(훅·구조 계승용, "대본 뽑기" 모달 유지).
- 반환: `{candidates: [ {plan, story, score, recommended} ], detected_type}`
  - `plan`: **기존 EDL 포맷** — `{structure, beats:[{beat_idx, role, narration, target_seconds, primary, alternates, effect, fit, forced}], affiliate_target, plagiarism_flags}` (build_edit_plan 반환형과 호환 → 하류 렌더 무변경)
  - `story`: `{story_person, story_event, story_resolution, cta_line, cta_keyword}`
  - `score`: 추천 정렬용(아래 §채점)

**내부 단계**:
1. `_build_inventory(source_scripts)` → seg_map + 팔레트 텍스트(기존 함수 재사용).
2. Gemini 1콜: 프롬프트 = `_STORY_RULES_CORE` + `_STORY_DECLARE`(script_generate에서 import) + 팔레트 + reference_text + "각 비트에 narration + seg_ids(2~4 다중컷) + fit + forced". 스키마로 후보 3개 강제.
3. 각 후보 grounding: 비트의 `seg_ids[0]`→primary, 나머지→alternates, 전부 `_ground_ref`로 실 타임코드 되붙임(환각제거·scene_desc 포함). target_seconds는 narration 글자수 기준 재계산(기존 로직).
4. 표절 가드(`_plagiarism_flags`) + 스토리 자기검증(`script_generate._verify_and_fix` 재사용, 선택).
5. 채점·추천.

### 채점 · 추천 (§)
후보별 `score = 0.5*avg(fit) + 0.3*(1 - forced비율) + 0.2*장면다양성(고유 seg_id수/총컷)`. 스토리검증 통과가 우선 게이트. 최고 score에 `recommended=True`. (가중치는 구현 중 실데이터로 조정 가능 — 상수로 노출)

### 배선 — mix_pipeline.py
- `run_mix_job`에 **scene_first 플래그**(job 필드). True면 `build_edit_plan(given_script=...)` 대신 `build_scene_first_plan(...)` 호출.
- 후보 3개를 job에 저장(`candidates_json`). 기본은 recommended를 edit_plan으로 세팅해 바로 미리보기/렌더 가능. 사용자가 UI에서 다른 후보 고르면 그 후보의 plan으로 교체(기존 `/api/mix/retype`·`adjust`와 같은 갱신 경로).

### UI — produce.html
- "우리 시스템으로 믹스" 경로에 **장면 우선 토글**(기본 ON) — given_script 안 넘기고 scene_first 모드로 시작.
- 매칭 리뷰 화면 위에 **후보 3개 탭/카드**(추천 배지) → 탭 클릭 시 그 후보의 비트·미리보기로 교체. 각 후보에 story_person/hook 요약 표시.
- 비트별 억지(forced)·fit≤2 → 기존 빨간불+스왑 그대로.
