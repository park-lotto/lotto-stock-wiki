# 다중 PC 관제·분배 — 설계 (카드 046)

> 한 줄: **PC마다 텔레그램 관제창 하나가 지시를 받고, 트랙 폴더에 이름 붙은 창을 열어 일을 내리며, 모든 Claude 창은 앱 Code 목록에 "PC·계정·용도"로 뜬다.**
> 사장님 결정: 2026-09-30 텔레그램·터미널 대화 (A 관제 고정 → PC마다 봇 따로로 변경 · 분배 C → 우편함 불가로 B · 계정 A · 두 PC 동시).

## 1. 결정 사항

| 항목 | 결정 | 이유 |
|---|---|---|
| 관제 위치 | **PC마다 따로** — 집 PC(`DESKTOP-OPUR9P6`)는 집 봇, 회사 PC는 회사 봇 | 텔레그램 봇 1개 = 수신자 1명(getUpdates 409). PC 간 전달이 필요 없어진다 |
| 창 표시 | 모든 Claude 창이 원격 조종 켜짐 + 이름 `PC·계정·용도[·카드N]` | 앱 Code 목록 하나에 두 PC 창이 섞여도 이름으로 구분 |
| 분배 | **항상 새 창** (그 트랙의 지난 대화 이어받기 `--continue`) | 열린 창에 끼워 넣기(개발용 채널)는 `--dangerously-load-development-channels` + 매 시작 확인 키 → 자동 불가, 보안 검사 거절 |
| 트랙 창이 이미 열려 있음 | 두 번째 창을 안 연다 → 텔레그램으로 "작업 중 — 앱에서 이어 지시 / 끝나면 보낼까" | 같은 대화를 두 창이 잡으면 꼬인다 |
| 계정·도구 | 기본 이 PC·1번. 말로 "2번으로 / 코덱스로 / 페이블로" | 사장님 A안 |
| 코덱스 | 새 창만, 앱 목록 안 뜸, 보고는 텔레그램 | Codex는 Claude 앱 세션이 아니다 |
| 창 닫힘 | 앱에 "연결 해제됨"으로 남는다 (앱 동작, 못 바꿈) → 앱 필터로 가림 | 공식 동작 확인(remote-control 문서) |

범위 밖: 고객 오류 실시간 신호·회원 쪽지 — **카드 042**로 따로 설계(고객 문구는 사장님 텔레그램 승인 후 발송).

## 2. 구조

```
텔레그램(PC별 봇) ──► [관제창]  관제창.bat · 이름 "집·관제" · 텔레그램 유일 수신자
                         │  py tools/dispatch.py <트랙> "<지시>" [--account 2] [--agent codex] [--model fable] [--card N]
                         ▼
               트랙 창 살아 있나? (.tracks/<트랙>/.session.json 의 pid)
                 ├─ 예 → 열지 않음, exit 3 → 관제가 텔레그램으로 물어봄
                 └─ 아니오 → track_open 이 새 창: 트랙 폴더 · --continue · --remote-control "집·1·<트랙>·카드N" · 첫 지시
                         ▼
               트랙 창이 끝나면 py tools/tg_notify.py "<결과>"  (Bot API sendMessage — 수신과 안 겹친다)
```

## 3. 구성품 (저장소에 두어 두 PC가 git으로 공유)

1. **`tools/track_open.py` — 창 여는 곳 한 곳(기존 확장).** 새 인자 `--account 1|2|3`, `--model`, `--prompt`, `--card`, `--new-window`. 하는 일: 계정별 `CLAUDE_CONFIG_DIR`(1번은 **지우기** — 거는 순간 빈 설정이 생긴다, 프로필 주석 2026-09-21 실측), 원격 조종 이름 조립, 텔레그램 끄기(`--settings %USERPROFILE%\claude-remote-settings.json`), `.session.json` 기록. 트랙.bat·코덱스.bat·`%USERPROFILE%\claude-remote.ps1` 은 이것을 부르는 얇은 껍데기가 된다.
2. **`tools/dispatch.py` — 분배(신설).** 트랙 존재 확인 → 카드 연결(`control.py link`) → 살아 있는 창 검사 → `track_open --new-window` 호출. 종료 코드: 0 열림 · 3 이미 작업 중 · 1 오류. 첫 지시 끝에 보고 규칙을 붙인다: "끝나면 `py tools/tg_notify.py`로 결과 한 단락".
3. **`tools/tg_notify.py` — 보고(신설).** 이 PC의 `~/.claude/channels/telegram/.env` 토큰 + `access.json` 의 `allowFrom[0]` 으로 sendMessage. 토큰을 출력·로그에 남기지 않는다.
4. **`tools/pc_label.py` — PC 이름 한 곳.** `%USERPROFILE%\.claude-pc.json` `{"label":"집"}` 을 읽는다(없으면 컴퓨터 이름). 프로필·track_open·dispatch 가 이 한 곳만 쓴다.
5. **`tools/pc_setup.ps1` — 새 PC 설치(회사 PC용, 사장님이 그 PC에서 1회 실행).** `.claude-pc.json` 작성, `claude-remote-settings.json`·`claude-telegram-on.json`·`telegram-guard.ps1`·`관제창.bat`·프로필 계정 메뉴(창 이름 질문 포함) 설치, 전역 `settings.json` 에 텔레그램 플러그인 끔 + `remoteControlAtStartup` 켬(설치 스크립트가 무엇을 바꾸는지 먼저 보여주고 Y/N). 끝나면 "회사 봇 토큰을 `/telegram:configure` 로 등록" 안내.

오늘 이미 집 PC에 손으로 깔린 것(텔레그램 전역 끔·감시기·관제창.bat·프로필 창 이름)은 5번이 만드는 결과와 같아야 한다 — 집 PC에서 `pc_setup.ps1` 을 다시 돌려도 바뀌는 것 0(멱등)이 시험 기준.

## 4. 오류 처리

- 트랙 없음 → dispatch exit 1 + "만들까요? (카드 N으로 track start)" 를 관제가 텔레그램으로.
- `.session.json` pid 가 죽었거나 claude.exe 가 아님 → 낡은 기록으로 보고 새 창.
- 새 창이 30초 안에 claude.exe 로 안 뜸 → exit 1, 창 콘솔 로그 경로를 보고.
- tg_notify 실패(토큰 없음·네트워크) → 트랙 창 화면에 결과를 남기고 0 이 아닌 코드; 관제는 모른다(한계로 명시).
- 텔레그램 가로채기 → 감시기(`telegram-guard.ps1`) 가 15초 안에 떼어낸다(오늘 설치분 유지).
