## ✅ 한 것

`shopping_shorts/static/sidebar.js` — NAV의 '🎬 숏템 제작소' 항목에 `go` 필드 신설.

```js
{ icon: "🎬", text: "숏템 제작소", href: "/produce", go: "/produce?new=1", free: true },
```

- **원인**: 메뉴가 쿼리 없는 `/produce`로 보냈다 → `_bootRestore`가
  `_bootAccountLatestOrLocal()`을 타서 로컬 WORK_ID(있으면 서버본까지 재복원)나
  계정 최신작업을 이어받는다. 2026-07-26 크로스기기 싱크의 **의도된 동작**이지
  버그가 아니다 — 다만 "새로 시작"에는 안 맞는다.
- **수정**: 클릭 목적지만 `?new=1`로. 이건 '+ 새 작업'이 이미 쓰던 검증된 경로다
  (`clearWork()` → 빈 작업 → URL에서 new 제거, cad0e7b0의 작업복제 방지 유지).

### ★href를 안 바꾼 이유 (여기서 실수하기 쉽다)
`href`에 `?new=1`을 박으면 안 된다. 실제로 해보고 실측했다:

| 무너지는 것 | 이유 |
|---|---|
| 제작소에서 메뉴 활성표시(`active`) 사라짐 | 판정식이 `it.href === path`인데 `path`는 **쿼리 없는 pathname** (sidebar.js:186) |
| `data-ss-href`가 유료게이트 화이트리스트와 어긋남 | 서버 `_FREE_EXACT_GET`은 쿼리 없는 경로 |

→ `href`는 매칭·게이트용(쿼리 없음), `go`는 이동용. 없으면 `href`로 폴백이라 다른 항목 무영향.

또 **active여도 `go`가 있으면 onclick을 살렸다** — 제작소를 보고 있을 때도 이 버튼으로
빈 작업에 가야 한다(종전엔 같은 경로라 onclick이 아예 안 붙었다).

## 안 건드린 것 (일부러)
- **랭킹의 '제작소로 보내기'** (`static/index.html:3531`) — 재료를 sessionStorage에 담고
  **쿼리 없는 `/produce`**로 가야 `_consumeProduceHandoff`가 집는다. `?new=1`을 붙이면
  `clearWork()`가 돌지만 `_consumeProduceHandoff`는 그대로 불리므로 재료는 살긴 한다.
  그래도 불필요한 변경이라 손대지 않았다.
- **기존 작업 접근로** — 사이드바 '내 작업'(`?work=<id>`)에 그대로 남는다. 유실 0.
  `clearWork()`는 로컬 `sessionStorage['produce_work']`만 지우고 서버 레코드는 안 건드린다.
