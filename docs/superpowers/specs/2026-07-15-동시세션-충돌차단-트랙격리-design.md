### 1.2 실제로 사고가 난 계층

기록(`wiki/log.md`, `NEXT_SESSION.md`)에 남은 사고를 분류하면:

- **git 계층**: `git add -A`가 남의 hunk 흡수 / 반쪽 커밋으로 origin ImportError / spec 커밋 dangling / 서버 staged 잔재로 `auto_deploy` 조용히 정지 (2026-07-14 실사고)
- **문서 계층**: `NEXT_SESSION.md`·`wiki/log.md`·대시보드 카드가 서로 덮임. 2026-07-15 이 세션에서 stash pop이 옛 `log.md`를 되살려 타세션 기록 24줄을 지울 뻔함.
- **편집 계층**: **사고 기록 없음.**

> **핵심 관찰**: 공유 워킹트리는 각 세션이 항상 남의 최신 편집 위에서 파일을 읽고 고치게 만들어, 편집을 사실상 계속 통합(continuous integration)시키고 있다. 공유트리가 잘하고 있는 유일한 일이며, **건드리면 안 된다.**

### 1.3 대시보드 카드 덮어쓰기의 기계적 원인

- `stop_hook.py:match_category()` — cwd로 카테고리를 정한다. 6세션 cwd가 동일 → 전원 `스탁브레인`.

- `render_dashboard.py:_latest_entry()` — 카테고리당 카드 1개만 렌더.

## 4. 설계

### 4.0 토대 — 트랙 정체성

모든 문제의 뿌리는 **세션이 자기가 누군지 모른다**는 것. cwd가 같아 대시보드도 못 나누고 훅도 커밋 주인을 판정할 수 없다.

세션이 작업 시작 시 트랙을 선언한다:

```
py tools/track.py claim --track 꾸미기 --paths "shopping_shorts/static/produce.html" "docs/superpowers/specs/*꾸미기*"
```

`.sessions/꾸미기.json`:
```json
{
  "track": "꾸미기",
  "paths": ["shopping_shorts/static/produce.html", "docs/superpowers/specs/*꾸미기*"],
  "started_at": "2026-07-15T11:20:00+09:00"
}
```

부가 명령: `track.py list` (활성 트랙 조회), `track.py release --track X`, `track.py add-paths --track X --paths ...`.

`.sessions/`는 git 추적 대상(다른 PC에서도 누가 뭘 잡았는지 보임). 단, 오래된 claim은 `list`가 경고만 하고 자동 삭제하지 않는다(남의 작업을 임의로 지우지 않는다).

#### 제약: Bash 툴은 호출 간 환경변수를 유지하지 않는다

Claude Code의 Bash 툴은 `Shell state (env vars, functions) does not persist`. 따라서 훅이 `$TRACK` 같은 환경 상태로 "누가 커밋 중인지"를 알 수 **없다.**

→ **커밋 메시지에 `Track: <트랙명>` 트레일러를 강제**하고 `commit-msg` 훅이 그것을 읽는다. 상태 무의존이라 6창 동시에도 깨지지 않는다.

### 4.1 기존 훅 실측 (설계 제약)

```
$ git config core.hooksPath
C:\Users\TheRose\Desktop\로또의 주식\.git\hooks     # 절대경로로 이미 박혀 있음

$ ls .git/hooks   # (sample 제외)
post-commit
pre-commit

$ cat .git/hooks/post-commit
#!/bin/sh
git push

$ cat .git/hooks/pre-commit
#!/bin/sh
# CRLF 재정규화 (2026-07-09 사고 대응)
git diff --cached --name-only --diff-filter=d -z | xargs -0 --no-run-if-empty git add --renormalize --
```

**두 가지 결정적 함의:**

1. **이 저장소는 커밋 = 즉시 push = 3분 뒤 라이브**다. 따라서 claim 검증은 반드시 **push 이전인 `commit-msg`에서** 끝나야 한다. 커밋 후 검증은 이미 라이브로 나간 뒤라 늦다.
2. `core.hooksPath`를 `deploy/githooks/`로 바꾸면 **위 두 훅이 조용히 죽는다** → CRLF phantom modified 사고 재발 + 배포 정지. **절대 바꾸지 않는다.**

→ 훅 본체는 버전관리되는 `deploy/githooks/`에 두고, `.git/hooks/commit-msg`는 그것을 호출하는 shim 한 줄로 설치한다. 기존 훅은 보존.

```sh
# .git/hooks/commit-msg (shim)
#!/bin/sh
exec "$(git rev-parse --show-toplevel)/deploy/githooks/commit-msg" "$@"
```

`tools/install_hooks.py`가 shim을 설치하며, **기존 훅 파일을 덮어쓰려는 경우 거부하고 보고**한다.

### 4.2 git 계층 — 섞임·유실 차단

**`deploy/githooks/commit-msg`** 가 매 커밋(=push 직전)을 검사:

1. `Track:` 트레일러 없으면 **거부** (안내: 메시지에 `Track: <트랙명>` 추가)
2. 트레일러의 트랙에 `.sessions/<트랙>.json`이 없으면 **거부** (안내: `track.py claim` 먼저)
3. staged 경로가 그 트랙 claim 밖이면 **거부**. 범인 경로 목록과 `git restore --staged <경로>` 안내를 출력.
4. **denylist**: `raw/**`, `pipeline/atoms/*.json`, `data/**` 등 봇 런타임 데이터는 누가 claim하든 **거부**. (오늘 `add -A` 사고의 실체이자 서버 pull을 막는 원인)

denylist는 `deploy/githooks/denylist.txt`로 분리해 훅 코드 수정 없이 조정.

**`tools/safe_commit.py --track X -m "..."`** — 커밋 구간 직렬화:

```
락 획득(.git/lotto-commit.lock, 스테일 5분 자동해제)
  → git pull --rebase   # 커밋 전에! (post-commit이 즉시 push하므로)
  → git commit          # commit-msg 훅이 claim 검증, post-commit이 push
  → 락 해제
```

> **순서 주의**: 기존 `post-commit`이 커밋 직후 무조건 push하므로, rebase를 커밋 **뒤**에 두면 push가 non-fast-forward로 실패한다. 반드시 **pull --rebase → commit** 순.

> **pull --rebase와 봇 데이터**: 워킹트리에 크롤봇이 쓴 dirty 파일이 상시 수백 개라 raw `pull --rebase`가 막힌다. `safe_commit`은 `--autostash`를 쓰되, **denylist 경로만** 대상이 되도록 사전 검사한다. (오늘 수동 stash가 `wiki/log.md`를 옛 버전으로 되살린 사고의 재발 방지 — 4.3에서 log.md가 트랙별로 쪼개지면 이 위험 자체가 크게 준다.)

### 4.3 상태 계층 — 덮임 원천 차단

**원칙: 여러 세션이 쓰는 공유 단일 파일을 없앤다.** 락으로 순서를 정해도, 전원이 같은 파일 맨 위에 append하면 rebase 충돌이 100% 난다.

| 현행 (덮임) | 변경 후 (트랙 소유) |
|---|---|
| `NEXT_SESSION.md` 한 장에 6트랙 | `handoff/<트랙>.md` — 트랙별 소유. 루트 `NEXT_SESSION.md`는 목록만 생성 |
| `wiki/log.md` 맨 위 append | `wiki/log.d/<트랙>.md` 조각 + 생성된 뷰 |
| 대시보드 카테고리당 카드 1개 | `log.json`에 `track` 필드, 카테고리 안에 트랙별 카드 |

**대시보드 변경 (`C:\Users\TheRose\.claude\dashboard\`)**
- `dashboard_cli.py:add_entry(category, track, summary, next)` — dedup 키를 `(date, category)` → **`(date, category, track)`**.
- `render_dashboard.py` — 카테고리 섹션 안에 트랙별 서브카드. `_mini_log`도 트랙 단위.
- `stop_hook.py` — 안내 문구에 `--track <당신 트랙>` 포함. 훅은 트랙을 모르므로, `.sessions/`의 활성 트랙 목록을 읽어 후보로 제시.
- `log.json` 동시 쓰기 → 원자적 write(temp+replace) + 짧은 파일 락.
- **하위호환**: 기존 `log.json` 엔트리에는 `track`이 없다. `track` 누락 시 `"(미지정)"`으로 취급해 렌더가 깨지지 않게 한다.

### 4.4 배포 계층

1. `deploy/auto_deploy.sh` — `git pull --ff-only` → **`git fetch && git reset --hard origin/main`**. 서버는 pull 전용이므로 로컬 변경이 있을 이유가 없고, `raw/`는 봇이 재생성하므로 손실 무해(이 결론은 `wiki/log.md` 🅐 섹션에 이미 기록됨).
2. **배포 스킵 경보** — pull/reset 실패 시 조용히 넘어가지 말고 로그에 명시 + 알림.
3. **origin import 게이트** — push 후 origin/main을 임시 체크아웃해 `python -m compileall shopping_shorts` + `import shopping_shorts.app` 검증. 반쪽커밋 크래시(memory `feedback_origin_main_broken_by_half_commit`) 차단.

## 5. 롤아웃 (가장 위험한 부분)

훅은 설치 즉시 저장소 전체에 걸린다. **지금 돌고 있는 5개 세션이 갑자기 커밋 실패하면 그것대로 사고다.**

| 페이즈 | 내용 | 타 세션 영향 |
|---|---|---|
| **1** | 상태 계층(4.3) — 문서 분리, 대시보드 트랙 카드 | **없음** (남의 코드 무접촉). 즉시 착수 가능 |
| **2a** | `track.py` + 훅을 **경고 전용**으로 설치 (거부 안 함, 위반만 출력) | 없음. 하루 관찰 |
| **2b** | 경고 로그 검토 후 **거부 모드** 전환 + `safe_commit.py` | 있음 — **전환 전 사용자가 전 세션에 공지** |
| **3** | 배포 게이트(4.4) | 서버측. 재배포 타이밍 주의 |

페이즈 2b 전환은 **사용자 명시 승인 후**에만.

## 6. 에러 처리

- **훅 거부** — 종료코드 1 + 한국어 안내(범인 경로, 정확한 복구 명령). Claude가 읽고 스스로 고칠 수 있는 문구여야 한다.
- **락 스테일** — 세션이 죽어 락이 남으면 5분 후 자동 해제. 해제 시 로그에 이전 소유 트랙 기록.
- **claim 없음** — 거부하되 `track.py claim` 예시를 그대로 출력.
- **훅 설치 충돌** — 기존 `pre-commit`/`post-commit`을 덮으려 하면 설치 거부 + 보고.
- **대시보드 log.json 손상** — 파싱 실패 시 덮어쓰지 말고 `.bak`으로 보존 후 보고.

## 7. 테스트

- `track.py` — claim/list/release, 경로 glob 매칭, 중복 claim, 손상된 json.
- `commit-msg` 훅 — 임시 저장소 픽스처에서: 트레일러 없음→거부 / claim 밖 경로→거부 / denylist 경로→거부 / 정상→통과. **`git add -A`로 남의 파일을 쓸어담은 상황을 재현하는 회귀 테스트 필수** (이게 실제 사고 형태).
- `safe_commit.py` — 락 획득/스테일 해제/경합(두 프로세스 동시).
- 대시보드 — `(date, category, track)` dedup, 트랙 2개 이상 카드 렌더, `track` 없는 옛 엔트리 하위호환.
- **실환경 grounding** — 실제 6세션 상황을 흉내내 두 트랙이 동시에 커밋 시도 → 섞임 0 확인. 합성 픽스처 통과만으로 완료 처리하지 않는다(memory `feedback_verify_with_real_data`).

## 8. 미해결·후속

- `produce.html` 모듈 분해(C안) — 본 체계 정착 후 별건 스펙.
- 트랙 claim의 경로 소유가 겹칠 때(두 트랙이 정당하게 `produce.html`을 봐야 할 때)의 정책: 현 설계는 **겹침 허용**(claim은 "내가 커밋해도 되는 범위"이지 배타적 락이 아님). 배타 락이 필요하다는 게 관측되면 후속.
- `.sessions/` 자체가 git 추적 대상이라 그 파일들끼리 충돌할 수 있음 → 트랙별 파일로 나눠 실질 충돌 없음. 관찰 후 재검토.
