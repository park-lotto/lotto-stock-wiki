# 원클릭 제작 흐름 재설계 — 설계문서

> 작성: 2026-07-29 · 트랙: 모션레벨훅 · 대상: shopping_shorts(숏템메이커) 제작소 1단계

## 1. 문제 (현재 상태)

제작소 1단계에서 영상 3개를 담아도 **원클릭이 아니다**. 사장님이 겪는 3가지 불편:

1. **수동 단계가 많다** — 담아도 자동 분석이 안 뜨고(`renderNoScriptState`), "📝 대본 뽑기" 버튼을 소스마다 눌러야 분석된다.
2. **대본 생성기가 둘로 뒤섞여 순서가 어긋난다** — 앞단에 뜨는 "대본·구조 분석 생성" 모달은 **단일 소스 리메이크**(영상 1개 구조만 베낌)로, 조각 인벤토리·백본 스파인을 안 거친다. 반면 올바른 순서(3개 분석 → 인벤토리 테킹 → 백본 스파인 → 대본)는 **뒤 믹스 단계(`build_edit_plan`)에서만** 돈다.
3. **비교해서 백본을 고르는 화면이 약하다** — 백본 클릭 선택(pickFootage)은 이미 되지만, 구조분석을 3개 나란히 비교할 화면이 앞단엔 없다(2026-07-29 소스 구조 비교 카드로 일부 착수, 단 분석 완료 후에만 뜸).

## 2. 목표 흐름

제작소 1단계 안에서 전부 끝낸다:

```
제작소 진입(영상 3개)
 ├─① [자동] 3개 동시 분석 — 대본추출 + 구조 + 조각 인벤토리(테킹)
 ├─② [비교 UI] 3개 나란히(비트구조·훅·설득장치) → 카드 클릭 = 백본 선택(기본=완성도 1위 자동)
 ├─③ [버튼1 "이 백본으로 대본 만들기"] → 백본 스파인 기반 대본 3안 생성(build_edit_plan, n=3) → 3안 카드
 ├─④ [대본 3안 중 1개 클릭] = 확정
 └─⑤ [버튼2 "믹스 시작"] = 확정 대본으로 믹스
```

### 확정된 결정 (2026-07-29 사장님)
- **자동분석 타이밍**: 진입 즉시 3개 **동시** 분석.
- **대본 선택**: 3안을 카드로 보여주고 사장님이 1개 골라 믹스.
- **단일 리메이크 모달 폐기**: 메인 흐름에서 제거. "직접 쓰기(대본 붙여넣기)"만 고급 옵션으로 존치.
- **대본 생성 통일**: 전부 `build_edit_plan`(인벤토리 → 백본 스파인 → 3안) 경로로. → 문제 2의 순서 어긋남 근원 제거.
- **비용**: job당 최대 3회 Gemini 감수. 기존 안전장치(DB 래치 `produce_autoload`·크레딧 게이트 `check_and_count`·호출당 상한 `_AUTOLOAD_MAX_PER_CALL`·시도상한 `_AUTOLOAD_MAX_ATTEMPTS`) 그대로 재사용.
- **배포**: 단계별 트랙 병합(아래 §5)으로 쪼개 각 조각이 라이브 검증되며 쌓임.

## 3. 비목표 (YAGNI)
- 대본 생성 로직 자체(스파인·훅 4패턴·부품은행 주입 등)는 **손대지 않는다** — 이미 `build_edit_plan`에 있다. 재배선만.
- 믹스 렌더 로직(`video_assemble`) 변경 없음.
- 소스 개수 3개 고정 아님 — N개 그대로(비교 카드는 N개 렌더).
- 업스케일·마스킹·OCR 등 타 트랙 범위는 제외.

## 4. 컴포넌트 (무엇을 앞으로 당기고 무엇을 폐기하나)

### ① 자동 분석 (앞으로 당김)
- **현재**: `refreshStep0`이 `autoloadFootageScripts`를 페이지당 1회 시도하지만, 실패/미시도 시 `renderNoScriptState`(수동 버튼)로 떨어진다.
- **변경**: 진입 시 담긴 소스 전부에 대해 자동적재(추출+구조+인벤토리 캐시)를 확실히 돌리고, 완료까지 진행 상태(스피너 + "n/3 분석 완료")를 보인다. 기존 `autoload` 엔드포인트·안전장치 재사용. **재귀 금지 규칙(_autoloadTried, revert cb8c0fa1d 교훈) 준수.**
- **인터페이스**: 입력=담긴 소스 목록 / 출력=각 소스 `structure` 캐시 확보 + AI PICK `pick_id` 확정.

### ② 비교 UI (2026-07-29 착수분 확장)
- **현재**: `renderCompareCards`(pick 있을 때만). candidates에 캐시 구조 실림(`build_aipick`).
- **변경**: 분석 완료 후 항상 노출. 카드 클릭 = `pickFootage`(백본 지정). 기본=완성도 1위 자동선정.
- **의존**: `build_aipick` candidates(구조·이름·썸네일) — 이미 있음.

### ③ 버튼1 "이 백본으로 대본 만들기" (신규 배선)
- **현재**: `startFromAiPick`이 pick의 원본 대본을 씨앗으로 매칭을 시작(단일 대본).
- **변경**: 버튼1 = 백본 스파인 기반 **대본 3안** 생성 요청 → `build_edit_plan`(n=3 candidates) 경로. 결과를 3안 카드로 렌더.
- **의존**: `build_edit_plan(source_scripts, target_seconds, ...)` — 이미 인벤토리→백본 order_block→n=3 candidates 순서로 동작. 백본은 §2 선택값(backbone_main/forced) 사용.
- **폐기**: 단일 리메이크 모달(openGen/runGen "대본·구조 분석 생성")을 메인 흐름 진입점에서 제거. 함수는 "직접 쓰기" 고급옵션 뒤로만 남긴다(즉시 삭제 아님 — 회귀 위험 최소화).

### ④ 대본 3안 선택 (신규 UI)
- 3안을 카드로(각 훅·문체 요약) 표시, 1개 클릭 = 확정(STATE.script 세팅) + 저장.

### ⑤ 버튼2 "믹스 시작" (기존 재사용)
- 확정 대본으로 `startProduceMix`/믹스 경로. 대본 게이트 통과 상태를 ④가 만들어 둠.

## 5. 배포 단계 (트랙 병합 단위)

각 단계는 독립 라이브 검증 후 다음으로. 트랙 격리(추출 파이프라인 타 세션과 충돌 주의).

- **P1 — 자동분석 확정**: 진입 시 3개 자동적재 확실화 + 진행 UI. (①)
- **P2 — 비교 UI 상시화**: 분석 완료 후 비교카드 항상 노출 + 백본 클릭. (②, 2026-07-29 착수분 마감)
- **P3 — 버튼1 3안 생성**: build_edit_plan n=3 배선 + 3안 카드 + 단일 리메이크 모달 메인동선 제거. (③④)
- **P4 — 버튼2 믹스 원클릭**: 확정 대본 → 믹스 버튼 정리. (⑤)

## 6. 에러 처리 / 안전
- 자동분석 실패(다운로드 만료·전사 불가): 해당 소스만 "분석 실패" 표시, 나머지는 진행. `autoload_mark_error` 기존 경로.
- 무한루프 방지: `_autoloadTried` 페이지당 1회 래치 + 서버 DB 래치. **refreshStep0 재귀 호출 금지**(사고 교훈).
- 크레딧 소진: `check_and_count` 실패 시 그 소스는 수동 대체 안내, 렌더/흐름은 죽지 않음.
- 대본 생성 실패: 3안 중 유효한 것만 표시, 0개면 "직접 쓰기" 폴백.

## 7. 테스트
- P1: 자동적재가 미분석 소스 전부에 대해 시도되고 래치가 재시도를 막는지(단위·기존 autoload 테스트 확장).
- P2: candidates 구조로 비교카드가 N개 렌더·클릭 시 backbone_main 세팅(JS 함수 + 백엔드 회귀, 2026-07-29 착수분).
- P3: build_edit_plan n=3 결과가 3안 카드로 매핑·1개 선택 시 STATE.script 확정.
- P4: 확정 대본으로 믹스 게이트 통과.
- 게이트: 기준선 실패건수 대비 신규 회귀 0.
