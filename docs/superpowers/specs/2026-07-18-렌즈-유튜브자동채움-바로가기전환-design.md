# 렌즈 유사영상 — 유튜브 무료 자동채움 + 나머지 4개 바로가기 전환

- 날짜: 2026-07-18
- 트랙: 렌즈유튜브자동
- 관련 파일: `shopping_shorts/app.py`, `shopping_shorts/static/index.html`, `shopping_shorts/youtube_search.py`, `shopping_shorts/userscript/grab.user.js`, `shopping_shorts/search_links.py`

## 배경 / 문제

렌즈 유사영상 모달에서 플랫폼별 결과 개수가 크게 불균형하다(실측 2026-07-18:
유튜브 3 / 틱톡 0 / 인스타 3 / 샤오홍슈 40 / 도우인 40).

원인은 결과가 두 파이프라인 합본이기 때문:
- **유튜브·틱톡·인스타** = SerpApi Google Lens의 `visual_matches`만 사용 → 적게 잡힘.
- **샤오홍슈·도우인** = `/api/lens/cn`(Gemini 비전으로 중국어 키워드 생성 → Apify 검색)
  으로 40개씩 자동수집 → **Apify 과금**.

사장님 결정: **Apify 자동수집(과금)을 없앤다.** 유튜브만 무료(YouTube Data API)로
키워드 자동채움하고, 나머지 4개(틱톡·인스타·샤오홍슈·도우인)는 이미 구현된
**바로가기 + 담기(grab)** 흐름으로만 채운다.

## 목표

1. 유튜브를 키워드 검색으로 자동 40개 채운다(무료).
2. 중국 플랫폼 자동수집(`/api/lens/cn`, Apify 과금)을 프론트에서 더 이상 호출하지 않는다.
3. 나머지 4개 플랫폼은 렌즈 visual_matches로 잡힌 개별 카드 + 바로가기 버튼으로만.

## 비목표 (YAGNI)

- 틱톡·인스타의 무료 키워드 검색 신규 개발 안 함(무료 경로 없음 — grab으로 대체).
- 샤오홍슈·도우인 인앱 미리재생 유지 안 함(자동수집 제거로 카드가 사라지는 건 수용).
- SerpApi 렌즈 역이미지 검색 자체는 그대로 유지.
- grab 유저스크립트/`/api/grab`은 이미 5개 플랫폼 지원 → 변경 없음.

## 설계

### 1. 백엔드: `/api/lens/yt` 신설 (`app.py`)

`/api/lens/cn`의 검증된 구조를 그대로 본떠 유튜브용 엔드포인트를 만든다.

```
POST /api/lens/yt   (frame? , source_caption)
```

- 검색어 확보: 프레임이 있으면 기존 `cn_search_keyword_vision(raw, caption)`이
  반환하는 `product`(한국어/영어 제품명)를 우선 사용. 없으면 캡션 키워드(`_cn_keyword`
  또는 기존 캡션 토큰 추출)로 폴백. **중국어(zh)가 아니라 한/영 키워드를 쓴다.**
  - ⚠️ 구현 시 확인: `cn_search_keyword_vision`이 `product`를 한/영으로 주는지 실측.
    아니면 `source_caption`에서 키워드를 직접 뽑는 경량 경로를 쓴다(비전 호출을 아껴도 됨).
- `youtube_search.search(keyword, max_results=40)` 호출 → 각 항목에
  `platform:"youtube"`, `match:None` 부여.
- 반환: `{ok, items, count, keyword}`.
- **무료(YouTube Data API)** → 월 호출가드(`bump_lens`/429) 불필요.
- 키 없음/실패 시 `{ok:True, items:[], count:0}` (cn과 동일한 방어).

### 2. 프론트: `fetchLensCn` → `fetchLensYt` 교체 (`index.html`)

`startLensSearch`(라인 ~628)에서 `fetchLensCn(...)` 호출을 `fetchLensYt(...)`로 교체.

- `fetchLensYt`는 `fetchLensCn`을 그대로 복제:
  - `/api/lens/yt`에 frame+caption POST.
  - 결과 항목에 `savesc='lens_'+platform+'_'+_lensHash(url)` 부여, 중복 savesc 제외 후
    `st.items`에 push, 로딩 플래그 해제, `renderLens` 재호출.
- `fetchLensCn` 함수 및 `cnLoading` 상태 관련 참조 정리(로딩 문구 유튜브용으로 조정).

### 3. 바로가기 버튼 (렌즈 모달 헤더/각 플랫폼)

렌즈 모달에서 틱톡·인스타·샤오홍슈·도우인은 자동수집이 없으므로, 사용자가 직접
그 플랫폼에서 찾아 담도록 **바로가기 버튼**을 제공한다.

- 검색어는 위 `keyword`(유튜브 검색에 쓴 것)를 재사용.
- `search_links.py`의 URL 빌더(`_URL_BUILDERS`) 이미 5개 플랫폼 검색 URL 보유
  → 프론트에서 플랫폼별 "🔗 {플랫폼}에서 찾기" 버튼으로 새탭 오픈.
- 담기는 기존 grab 유저스크립트가 그 페이지에서 처리(변경 없음).
- 배치: 렌즈 모달 상단 플랫폼 토글 줄 근처 또는 각 플랫폼 섹션 헤더. (구현 시 UI 확정)

### 4. `/api/lens/cn` 엔드포인트 처리

프론트가 더 이상 호출하지 않으므로 과금은 즉시 0이 된다. 엔드포인트 코드 자체는
**남겨둔다**(삭제 시 테스트·다른 참조 영향 확인 부담). 주석으로 "프론트 미사용, 과금
경로라 비활성" 명시. 완전 삭제는 별도 정리 태스크로.

## 데이터 흐름

```
[렌즈 아이콘 클릭]
  → 프레임 캡처(canvas)
  → POST /api/lens/search (SerpApi)  → visual_matches (5플랫폼 개별 카드)  [유지]
  → 렌더 + fetchLensYt 비동기
        → POST /api/lens/yt  → youtube_search 40개  → 유튜브 카드 합류  [신규, 무료]
  → 바로가기 버튼(틱·인·샤·도) → 그 플랫폼 검색페이지 새탭 → 담기(grab)  [기존]
```

## 테스트

- `tests/test_app_lens.py`에 `/api/lens/yt` 케이스 추가:
  - `youtube_search.search`를 목킹 → 40개 반환 시 items 40, platform 전부 youtube, match None.
  - 키 없음/예외 시 빈 리스트·ok:True.
- 기존 `/api/lens/cn` 테스트는 유지(엔드포인트 남기므로).
- 프론트는 라이브 육안 검증: 렌즈 실행 → 유튜브 카운트 3→40 근처, 카드 썸네일·▶미리보기 동작,
  바로가기 버튼 클릭 시 올바른 검색페이지 오픈.

## 검증 (완료 기준)

1. pytest 신규/기존 그린.
2. 라이브(트랙 finish 후 배포)에서 렌즈 실행 시 유튜브 40개 근처, 인앱 미리재생 정상.
3. 네트워크 탭에 `/api/lens/cn` 호출 없음(과금 경로 차단 확인).
4. 바로가기 버튼 4개 → 각 플랫폼 검색 URL 정확.

## 리스크

- `cn_search_keyword_vision`의 `product`가 한/영이 아니면 유튜브 검색어 품질 저하
  → 구현 첫 단계에서 실측 후 캡션 기반 키워드로 대체 여부 결정.
- 유튜브 Data API 일일 쿼터(10,000유닛) — search.list는 호출당 100유닛이라
  하루 100회. 렌즈 사용 빈도 낮아 현실적 문제 아님(키 로테이션도 있음).
