## 상태 (2026-07-18 갱신 — 사장님 실사용 제보 4건 배포)

사장님이 라이브에서 실제로 써보며 제보한 4건을 순서대로 잡아 배포·검증했다:

1. **드래그가 글자를 못 잡던 것** — hit-test가 없어 캔버스 아무 데나 누르면 선택 글자가
   그 지점으로 순간이동했다. → 누른 지점 가장 가까운 글자를 잡고(반경 0.28 밖이면 안 잡음)
   간격 유지한 채 끈 만큼만 이동(상대이동). (`54ae16c4`)
2. **드래그 시 글자가 겹겹이 쌓이던 것** — `drawThumb`이 매 렌더에서 캔버스를 안 지워, 배경
   영상이 없을 때(job 없음) 드래그 경로마다 잔상이 쌓였다. → `ctx.clearRect` 첫 줄에 추가. (`d1f275ed`)
3. **매칭 끝냈는데 5단계서 "믹스 영상 없음"** — thumb/frames가 `video_path`(7단계 최종 렌더
   산출물)만 봤다. 그 전 단계(5단계)엔 없다. → 최종 렌더(app.py:3164)와 같은 우선순위
   `video_path → clean_video_path → preview_path`로 폴백. **라이브 검증: 수박 작업에 프레임
   10장 뜸.** (`bd7c6491`)
4. **꾸미기 미리보기 자막이 문장 통째로** — 실제 영상은 `_caption_segments`로 2~3어절 쪼개는데
   미리보기(beats_preview)는 narration 통째를 줬다(미리보기가 거짓말). → 서버가 실제 렌더와
   같은 구절 분할(segs)+실제 표시시간(durs)을 주고, 미리보기 `showBeat`이 `_playBeatCaptions`로
   그 장면 안에서 구절을 순차 재생. **사장님 A안(순차 재생).** (`780dde2a`)

### ⚠️ 이번 세션 교훈 두 개
- **로컬 서버 크기 대조를 매번 먼저 하라.** 유령 프로세스가 옛 `produce.html`(175737, THUMB_STATE
  없음)을 서빙하는 걸 크기 대조 안 하고 30분 헤맸다. `서빙본 wc -c == 디스크 wc -c` 먼저.
- **검증 스크립트가 페이지 상태를 주입하고 있지 않나 확인하라.** `STATE.job_id`를 손으로 심어
  "실증했다"고 착각한 전례(memory `feedback_harness_invented_contract`).

### ⚠️ finish의 "Aborting"은 내 배포와 무관
`finish`가 매번 main 폴더 로컬 정리(pull) 단계에서 `error: ... test_style_use_js.py ... Aborting`을
낸다. 이건 **모션효과 트랙이 남긴 untracked 파일 + main 폴더 미완료 병합**(MERGE_HEAD=36566cd9)
때문이고, **origin/main push는 매번 성공**한다(코드 grep으로 확인). 여러 트랙이 같은 증상을
겪었다(대시보드 렌즈·장면라이브러리). main 폴더 정리는 그 병합을 만든 세션 소관 — 함부로
commit/abort 안 함(크롤 데이터 uncommitted가 섞여 있어 위험).

## ⏭ 미결 (다음 세션이 볼 것)

### 1. ★사장님이 아직 실제로 눌러본 적이 없다
라이브 배포는 됐지만, 제가 확인한 건 **로컬 서버에서 playwright로 태운 것**이다.
볼 것: 5단계에 프레임 10장이 뜨나 / 글자를 얹고 "썸네일 생성"을 누르면 갤러리에 뜨나 /
폰트를 바꾸면 진짜로 글씨체가 바뀌나(폰트 22종이 통째로 죽어 있던 결함이 있었다).

### 2. 새로고침하면 갤러리·레이어가 빈다 (범위 판단 필요)
DB엔 `results`·`selected`·`layers`가 **다 있는데** 라우트(`app.py:1701-1703`)가 `frames`만
복원해 주고 나머지를 버린다. 단, **`MIX_JOB` 자체가 새로고침에 복원 안 되는 앱 전반의
선존재 한계**라 썸네일만의 문제가 아니다 → 대본믹스통합의 작업파일(`_restoreWork`가
`MIX_JOB`을 되살린다)과 물려야 의미가 생긴다. **그 트랙과 함께 판단할 것.**

### 3. `selected`의 소비자가 없다
`app.py:1813`에서 쓰기만 하고 읽는 곳이 0곳이다. 최종 썸네일을 골라도 그걸 **업로드·렌더에
쓰는 배선이 아직 없다**(설계상 이 트랙 범위 밖 = 다음 페이즈). 페이즈2 후보.

### 4. Minor 롤업 (병합 전 처리 불필요로 판단됨)
- **T2-m1**: ffprobe 바이너리가 없으면 `_probe_duration`이 `FileNotFoundError`를 전파해
  502가 아니라 **500**이 난다. 선존재 패턴. → 라이브에서 프레임이 안 뜨면 **여기부터 의심**.
- **T2-m2**: `extract_frame_at`(`frame_extract.py:58`)의 `subprocess.run`에 `stdin=DEVNULL`이
  없다 = 로컬 pytest 유령 실패 33건의 근원. 고치면 유령이 준다.
- **T1-m1**: `thumbnail=None` NULL-클리어 분리 실패모드는 현 구현상 존재하지 않음.

## ⚠️ 이 트랙에서 반드시 지킬 것

1. **테스트는 `-s`** — 빼면 유령 실패 33건(`OSError: WinError 6`). 코드 결함 아님(실측).
2. **콘솔이 cp949** — 스크립트에서 비ASCII print는 `UnicodeEncodeError`로 죽는다.
   **뮤턴트 심는 스크립트가 그렇게 죽으면 뮤턴트 없이 "초록"이 나와 확인했다고 착각한다.**
   `PYTHONIOENCODING=utf-8` 쓰거나 ASCII만 찍어라.
3. **`produce.html`은 3개 트랙이 동시에 만진다**(대본믹스통합·모션효과). 태스크 단위로 짧게 병합.
   실제로 이번에 부팅 자리에서 충돌 났다 — 해소는 원장 참조(순서가 답이었다: TDZ).
4. **★검증 스크립트가 페이지 상태를 대입하고 있지 않나 확인하라.**
   `STATE.job_id = '...'`를 손으로 심어놓고 "실증했다"고 3번 착각한 전례가 있다(원장 참조).
   대입하는 줄이 있으면 **그 값을 페이지가 진짜로 넣는지 grep으로 확인**할 것.
