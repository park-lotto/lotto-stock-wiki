- 미리보기 크기 보정이 **한 번도 적용 안 된 채** "맞춤"이라고 보일 뻔했다: `treat()`가 `style.cssText`를 통째로 갈아서 앞에 넣은 `font-size`가 지워짐(전 글꼴 16px). 실제 `getComputedStyle`을 찍어서 잡았다. → 검사 도구에 "맞춤 켬/끔 높이 편차·칸 넘침" 항목으로 박아둠.

### ★함정·발견
1. **을지로체는 문장부호가 통째로 없다**(`! ? , '` 등). 실제 채널 제목 93개 중 41개에 걸린다 → 같은 집안 **을지로10년후의 부호만 `unicode-range`로 빌림**(`BORROW`). CSS만으로 해결, 편집기 코드 무관.
2. **쿠키런 Black은 공백 글리프가 없다.** Chromium은 다음 글꼴 공백을 써서 띄어쓰기는 정상(실측 35px). PIL·ffmpeg였다면 08-26 사고 재발 — 그래서도 fonts.json에 넣으면 안 된다.
3. 글리프 2,400~4,200자 글꼴 4종(을지로체·산토끼·파셜산스·프리젠테이션): 실제 제목 93개의 한글은 전부 덮는다. `뷁` 같은 드문 글자는 빠진다(기본 글꼴로 대체됨).
4. ★**검사 오탐 1건 잡음**: 폴백 판정을 "글자 폭 비교"로 했더니 잘난체 2종이 폴백으로 떴다 — 한글은 글꼴이 달라도 전각 폭이 같다. **그려진 픽셀 비교**로 바꾸고, 없는 글꼴(`없는글꼴XYZ`)에서 실패하는 것까지 확인(다른 픽셀 0 → 폴백 / 실제 글꼴 7,000+).
