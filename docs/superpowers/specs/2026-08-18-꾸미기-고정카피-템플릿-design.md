## 1. ★핵심 발견 — 템플릿 렌더 배관은 이미 다 있다

**새로 만들 게 아니라 연결만 하면 된다.** 손대기 전 실측:

| 필요한 것 | 현재 | 근거 |
|---|---|---|
| PNG를 영상에 합성(위치·크기·투명도) | ✅ 있음 | `video_assemble.py:1621` `has_overlay` 분기 |
| **시간 제한** 합성(첫 장면만) | ✅ 있음 | `_motion_layer_filters` — `dur=None`이면 전체, `dur=N`이면 `enable='between(t,...)'` |
| 알파(투명) 처리 | ✅ 해결됨 | `format=rgba,colorchannelmixer` + 메모리 `ffmpeg_alpha_overlay` |
| PNG 업로드·저장 | ✅ 있음 | `app.py:9228` `/api/produce/mix/overlay` |
| **PNG 파일 12종** | ❌ 0개 | 이번에 Pillow로 생성 |
| **고르는 UI** | ❌ 없음 | 이번에 신설 |

⚠️ **그래서 "전체/첫장면 둘 다"가 공짜다** — 두 경로가 이미 있고 `vcur`로 순차 합성되므로
템플릿이 사장님이 올린 로고 오버레이와 **충돌하지 않는다**(둘 다 얹힌다).

## 3. 파트 ① 고정카피

### 흐름
```
6단계 진입 → 확정 대본(STATE.script) → [캐시 확인] → Gemini 1회 → 후보 4개
   └ 캐시 적중이면 API 호출 0회
```

### 화면
```
헤드카피 문구
[#1 짧은 훅형] [#2 숫자형] [#3 반전형] [#4 질문형] [✏️ 직접 입력]
┌──────────────────────────────┐
│ (textarea — 빈칸으로 시작)      │
└──────────────────────────────┘
```

### ★지켜야 할 것
- **헤드카피는 여전히 빈칸으로 시작한다.** 2026-07-19에 "자동 재채움"을 **일부러 제거**했다
  (지우고 뒤로 갔다 와도 유지되도록). 후보는 **누를 때만** textarea에 들어간다 —
  자동으로 밀어넣으면 그때 고친 버그가 되살아난다.
- **캐시가 필수다.** 자동 생성인데 캐시가 없으면 6단계를 오갈 때마다 과금된다.
  키 = 대본 해시(`_script_hash`가 이미 있다 — 새로 만들지 않는다, 0순위-B).
  같은 대본이면 **다시 안 뽑는다**. 대본이 바뀌면 자동으로 새로 뽑힌다.
- 생성 실패는 **조용히 넘기지 않는다** — 후보 자리에 "문구를 못 뽑았어요(직접 입력하세요)"를
  표시한다. 빈 카드가 뜨면 사장님은 고장인지 준비중인지 구분 못 한다.

### 데이터
- 서버: `POST /api/produce/headcopy/suggest` `{job_id|work_id, script}` → `{ok, copies:[{label,text}]}`
- 저장: 캐시는 서버(작업 기준). 고른 문구는 기존 `STATE.headcopy.text` 그대로 — **새 저장 형식을 만들지 않는다.**

## 4. 파트 ② 템플릿

### PNG 12종 (1080×1920 RGBA)
| # | 모양 | 비고 |
|---|---|---|
| 1~4 | 상단 색띠 | 색 4종 |
| 5~8 | 상단+하단 색띠 | 색 4종 |
| 9~12 | 테두리 프레임 | 색 4종 |

- `shopping_shorts/static/templates/tpl_01.png` … `tpl_12.png` + 카드용 축소 미리보기
- 생성 스크립트 `tools/make_deco_templates.py`를 **커밋한다** — 나중에 색·모양을 바꿀 때
  손으로 다시 그리지 않는다(PNG만 커밋하면 어떻게 만든 건지 아무도 모른다).

### 화면
```
🖼 템플릿
[없음] [tpl1] [tpl2] … [tpl12]      ← 축소 카드
표시 구간:  (•) 영상 전체   ( ) 첫 장면만
```

### 렌더 배선
- **전체** → 기존 `deco.overlay` 경로 그대로(추가 공사 0)
- **첫 장면만** → `deco.motion.layers`에 `{start:0, dur:<첫 비트 길이>}`로 얹는다
  (`_motion_layer_filters`가 이미 처리)
- ⚠️ 사장님이 **직접 올린 오버레이(로고)와 템플릿은 별개 슬롯**이다. 템플릿이 그 자리를
  덮어쓰면 로고가 사라진다 → `deco.template`을 따로 두고, 렌더에서 **둘 다** 얹는다.

## 5. 파트 ③ UI 개선

### 지금 (세로로 계속 쌓임)
```
문구 → 완성스타일 → 내프리셋 → 강조단어 → 고급효과 → 직접다듬기(접힘)
```

### 바꿀 것
```
┌ [✍ 문구] [🎯 스타일] [🖼 템플릿] [✨ 효과] ┐   ← 탭
│  (고른 탭만 표시)                          │
└────────────────────────────────────────┘
```
| 탭 | 담을 것 |
|---|---|
| ✍ 문구 | 고정카피 후보 + textarea + 강조 단어 |
| 🎯 스타일 | 완성 스타일 카드 + 내 프리셋 + 직접 다듬기(접힘 유지) |
| 🖼 템플릿 | 템플릿 12종 + 표시 구간 + 이미지 오버레이(업로드) |
| ✨ 효과 | 고급효과(리모션) |

### ★지켜야 할 것
- **좌측 미러(미리보기)는 안 건드린다.** 탭은 우측 컨트롤만 가른다.
- **기능을 지우지 않는다** — 옮기기만 한다. 지금 되는 것이 하나라도 안 되면 회귀다.
- `id`를 바꾸지 않는다. `updateHC`·`applyConfig`·`renderStyleCards` 등이 전부 `getElementById`로
  잡고 있어, id를 건드리면 **조용히 안 되는 자리**가 생긴다.

## 6. 검증 계획 (이 화면은 미검증 배포로 사고 이력이 있다)

- **회귀가 최우선**: 탭으로 옮긴 뒤 기존 기능(스타일 적용·프리셋 저장/불러오기·강조단어·
  고급효과·직접다듬기·드래그 이동)이 **전부 그대로 동작**하는지 실브라우저로 확인
- 고정카피: 캐시 적중 시 **API 호출 0회**를 실측(호출 수를 세서 확인 — 짐작 금지)
- 템플릿: 전체/첫장면 각각 **실제 렌더**로 확인. 로고 오버레이와 **같이** 얹히는지도 확인
- 테스트: 기존 `test_style_use_js.py` 계열 + 신설(카피 캐시·템플릿 배선)
- 전체 pytest **기준선 대조**("전부 green"이 아니라 "실패가 늘지 않았나")

## 7. 안 하는 것 (YAGNI)

- 템플릿 사용자 업로드/저장(레퍼런스의 "템플릿 저장하기") — 기본 12종부터 쓰고 판단
- 템플릿 안에 글자 넣기 — 글자는 헤드카피·자막이 담당(두 곳이 같은 일 하면 어긋난다)
- 고정카피 문구 편집 이력·즐겨찾기

## 8. 위험

| 위험 | 대비 |
|---|---|
| 탭 개편이 기존 기능을 깬다 | id 보존 + 실브라우저 회귀 확인. **이게 가장 큰 위험** |
| 자동 카피 생성이 돈을 샌다 | 대본 해시 캐시. 적중 시 호출 0회를 실측 |
| 템플릿이 로고 오버레이를 덮는다 | `deco.template`을 별도 슬롯으로. 렌더에서 둘 다 얹기 |
| 미리보기와 실제 렌더가 다르다 | 프리뷰 스케일 `VIDEO_W=720` 규약 준수(2026-07-19 이력) |
