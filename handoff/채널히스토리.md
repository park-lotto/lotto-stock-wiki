# 핸드오프 — 채널히스토리 트랙

## 2026-07-22 (사무실 PC)

오늘 이 트랙에서 **6건 라이브 배포 완료**(전부 finish 게이트 통과 → main 병합):

1. **관리자 전용 3버튼** — 수집·전수조사·레퍼런스등록을 화면 숨김 + 백엔드 `_require_admin`(pro도 403). `/api/me` cid0일 때만 노출.
2. **채널 '지난 한 달' 히스토리** — `reel_history` 테이블(shortcode upsert·30일 정리)+`/api/channel/history`. 검색이 한 채널로 수렴하면 랭킹 아래 섹션. ⚠️배포 후 수집분부터 쌓임(소급 없음).
3. **숏템검색 통합** — 검색창 하나로 채널명·소재·링크(링크는 엔터→traceByUrl). placeholder 갱신.
4. **사이드바 계정 패널** — 로고 아래 구글아이디·등급뱃지·오늘 사용량·가입일·로그아웃. `/api/me`에 email·usage·member_days·is_admin 추가. 전 6페이지 공통. 사이드바 큼직하게(270px).
5. **썸네일 배경 자막 제거** — `assemble`에 `burn_captions` 플래그. `assemble_clean_video`가 `burn_captions=False`로 clean 배경 생성(자막0·더빠름). 원인=clean_preview.mp4에 우리 나레이션 캡션이 구워지던 것. 서버서 해당 job 재생성+프레임 실측 확인.
6. **썸네일 이전작업 제목 잔존** — MIX_JOB 교체 시 THUMB_STATE 안 비워 생긴 프론트 상태누수. `initThumb`에서 job 바뀌면 리셋.

## ⏭ 미결 — 집에서 결정/진행

**렌즈 샤오홍슈·도우인 "0"** (사용자 문의, 오늘 진단만 함):
- **버그 아님·설계**. 서버 실측: Apify토큰 17개 정상 / xiaohongshu·douyin search 모듈 각 3건 정상 / cn/keywords 생성 정상("自制巧克力布朗尼").
- 렌즈는 **비용 때문에 CN 자동검색을 의도적으로 끔**(`index.html:1053` 주석). SerpApi는 유튜브·틱톡·인스타만 자동, 샤오홍슈·도우인은 **중국어 키워드 버튼**(사이트 열기)으로 대체. 그래서 그 두 탭은 항상 0.
- 백엔드에 자동검색 경로는 **이미 존재**: `app.py` `_lens_cn_search`(~2977)·`api_lens_cn_search`(~3069, Form). 프론트가 안 부를 뿐.
- **사용자 결정 대기** — 3안 제시했으나 사용자가 "더 확인하고 싶다"며 보류:
  1. 현행 유지 + 빈 탭에 "아래 키워드 버튼으로 열기" 안내만 개선(비용 0)
  2. 유튜브처럼 자동검색 켜기(렌즈 1회마다 Apify 과금)
  3. "샤오홍슈·도우인도 검색" 버튼 눌렀을 때만 Apify 검색(비용 선택적 제어)
- 집에서: 사용자가 물어본 "비용 얼마/키워드 버튼 위치" 등 먼저 답하고 방향 확정 후 진행.
