# 레퍼런스 등록 — 수집분과 같은 포맷으로

> **소유 트랙**: 레퍼런스등록포맷 — 이 파일은 이 트랙 세션만 수정한다. 다른 트랙은 읽기만.

## 2026-08-19 — 착수·구현·라이브

사장님 제보: "인스타 페이지에서 레퍼런스로 등록 기능을 만들었는데, 등록해도 기존 영상들이랑
동일한 포맷으로 저장되고 보이게 해줘." (채이홈 카드만 조회수·팔로워당댓글이 없고 채널명도 달랐음)

### 착수 전 실측 (추측 아님 — 라이브 DB에서 직접 확인)

`reference.db` → `last_run` 테이블, 162건 중 **manual=True는 1건**(shortcode `DcIrfnOzHre`):

```
caption = 'Video by chae2home'   views     = 0        grade    = None
name    = '채이홈'                followers = 0        duration = None
username= '채이홈'  ← ★계정명 자리에 표시명이 들어가 있었다
```

**화면(index.html)은 값이 있을 때만 줄을 그린다** — 그래서 그 카드만 다르게 보였다:

| 안 보이던 것 | 렌더 조건(index.html) | 실제 값 |
|---|---|---|
| 조회수 | `${i.views? ...}` (1699행) | 0 |
| 조회수당댓글 | `${i.views? ...}` (1702행) | 0 |
| 팔로워 | `${i.followers? ...}` (1698행) | 0 |
| 팔로워당댓글 | `${i.fan_density? ...}` (1704행) | 0 |
| 채널명 옆 `—` | `${i.grade\|\|''}` (1697행) | None |

★**화면 코드에 `manual` 분기는 한 줄도 없다**(grep 확인). 즉 포맷이 다른 게 아니라
**데이터가 비어서** 줄이 안 그려진 것 — 고칠 곳은 화면이 아니라 데이터였다.

### 근본 원인

`adopt`가 `probe_grab_meta`(yt-dlp)만 썼다. yt-dlp는 **로그인 없이** 인스타를 읽어
조회수·팔로워·캡션을 못 가져온다(제목이 'Video by {계정}'인 게 그 증거).
2026-08-18에 넣은 화면파싱 폴백(`_pageStats`)도 그때 같이 실패했다.

정규 수집은 `instagram_playwright.fetch_reels`(세션 로그인 + 로테이션)로 읽어
`videoViewCount`·`ownerFollowers`·`caption`을 전부 받는다. **경로가 달라서 값이 달랐다.**

### 한 일 (전부 `shopping_shorts/app.py`)

1. **`_enrich_instagram_meta(url, meta)` 신설** — 인스타는 **정규 수집이 쓰는 그
   `fetch_reels`를 그대로 태운다**(0순위-B: 같은 판단을 두 번 적지 않는다).
   프로필을 열어 **shortcode가 일치하는 릴스만** 골라 값을 가져온다
   (남의 영상 지표가 붙는 걸 막는다 — `렌즈썸네일 구글짝지음`과 같은 함정).
   실패하면 meta를 그대로 두고 등록은 살린다.
2. **`_ig_username_from_url`** — `/{계정}/reel/CODE/` 형태면 주소만으로 계정을 안다
   (예약어 reel/reels/p/tv는 계정이 아니다). 없으면 yt-dlp가 준 channel을 쓴다.
3. **`_adopt_into_ranking`**:
   - `name`(표시명)과 `username`(계정명)을 **따로** 담는다. 예전엔 둘 다 표시명이라
     카드의 "이 채널 영상만 보기"가 0건이 됐다.
   - **`apply_grades(merged)`** — 합친 스냅샷 전체를 놓고 등급을 매긴다.
     ★1건만 놓고 부르면 자기가 최대값이라 무조건 최고등급이 나온다(정규화 방식).
     안 부르면 grade=None이라 카드에 등급 자리가 빈 채로 남는다.
   - `set_reel_duration` — 🎬 길이는 `last_run`에 안 담기고 조회 때
     `_attach_durations`가 `reel_durations` 캐시에서 붙인다. 값이 있으면 그 캐시에
     넣어둬야 등록 직후에도 뜬다(안 하면 durfill 백필 최대 1시간 대기).
4. **엔드포인트 순서**: ①수집 스크레이퍼(정본) → ②화면파싱값(빈 칸만) → ③yt-dlp.
   서버가 제대로 읽은 값을 근사치가 밀어내지 않게 종전 규칙을 그대로 뒀다.

**카테고리도 같이 고쳐진다** — `_category_of`가 캡션으로 판정하는데, 캡션이
'Video by chae2home'이면 무조건 '기타'였다. 실캡션이 들어오니 '홈템'·'뷰티'로 잡힌다(실측).

### ⏭ 다음 (사장님 확인 필요)

- **이미 등록된 채이홈 카드는 그 URL로 한 번만 다시 ⭐등록하면 고쳐진다**
  (같은 shortcode는 덮어쓰므로 중복이 안 쌓인다 — 실측 확인). 자동 소급은 안 했다:
  옛 항목을 서버가 임의로 다시 긁으면 인스타 요청이 늘어난다(계정 한도).
- **실브라우저 미검증**: 실제 인스타에서 ⭐등록을 눌렀을 때 `fetch_reels`가 그 프로필을
  정상적으로 열어주는지(세션·프록시 상태에 달렸다). 계정이 막혀 있으면 종전처럼
  화면파싱값으로 폴백한다 — 그 경우 조회수는 뜨지만 캡션·등급은 여전히 빌 수 있다.
- 인스타 외 플랫폼(유튜브·틱톡·쓰레드)은 yt-dlp가 통계를 주므로 손대지 않았다.
