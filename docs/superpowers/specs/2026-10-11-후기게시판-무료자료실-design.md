# 회원 후기 게시판 + 무료 자료실 설계 (관제 179)

2026-10-11 · 트랙 `후기게시판` · 사장님 승인 설계

## 1. 무엇을 만드나

`/board` 한 페이지에 칸 두 개.

| 칸 | 누가 쓰나 | 누가 보나 | 내용 |
|---|---|---|---|
| 회원 후기 (`review`) | 로그인 회원 전부(무료 포함) | 사장님 승인 뒤 누구나(비로그인 포함) | 자랑글 + 영상 파일 1개 + 사진 여러 장 |
| 무료 자료실 (`free`) | 관리자만 | 목록·미리보기는 누구나, **내려받기는 로그인 회원** | 팩 4종(자막·짤·효과음·배경음악) 파일 + 강의·분석 글 |

목적: 후기는 예비 고객 설득, 자료실은 무료 가입의 이유.

## 2. 사장님이 정한 것

- 공개 범위: 회원이 쓰고 누구나 본다
- 1차 범위: 후기 게시판 + 무료 자료실 (보상·등업·댓글·좋아요는 뺀다)
- 자료실 주력: 팩 4종. 출처 구분 없이 파일로 올린다(관리자가 즉시 내릴 수 있다)
- 후기 영상: 파일 업로드만 (링크 없음)
- 후기 공개 시점: 사장님 승인 후

## 3. 기본값

- 작성자 표시는 **닉네임**. `customers` 표에는 `username`·`email`뿐이라 그대로 쓰면 공개 페이지에 로그인 아이디가 샌다. 닉네임은 첫 글 쓸 때 정하고 게시판 쪽 표에 둔다(회원 표는 안 건드린다). 2~12자, 중복 불가.
- 후기 첨부: 영상 1개(mp4·mov, 200MB 이하) + 사진 최대 5장(png·jpg·webp, 장당 12MB 이하).
- 글쓰기 때 "승인되면 로그인하지 않은 사람에게도 공개됩니다" 체크 필수. 체크 없이 온 요청은 서버가 422로 거절한다.
- 승인 대기 글은 작성자와 관리자에게만 "승인 대기" 표시와 함께 보인다.
- 작성자는 자기 글을 삭제할 수 있다. 수정하면 다시 승인 대기로 돌아간다.
- 관리자: 승인·숨김·삭제·상단 고정. 새 후기가 오면 관리자 쪽지함 알림.
- 자료실 파일: 글당 여러 개, 개당 1GB 이하. 미리보기(썸네일 사진, 미리듣기 음원)는 첨부 사진·음원으로 따로 올린다.
- 메뉴: 사이드바 "소통" 묶음에 `후기·무료자료`(`free: true`). 랜딩 링크는 2차.

## 4. 판단의 주인 (0순위-C)

새 파일 `shopping_shorts/board.py` 하나에 판단을 모은다. 라우트는 이 함수들을 부르기만 한다.

| 판단 | 주인 함수 | 부르는 곳 |
|---|---|---|
| 이 글을 이 사람이 볼 수 있나 | `board.can_view(post, viewer)` | 목록 · 글 보기 · 첨부(영상·사진·파일) 서빙 |
| 이 파일을 이 사람이 받을 수 있나 | `board.can_download(post, viewer)` | 자료 내려받기 |
| 이 칸에 이 사람이 쓸 수 있나 | `board.can_write(board, viewer)` | 글쓰기 · 수정 |
| 올린 파일을 받아 줄 것인가(종류·크기·전체 용량) | `board.accept_upload(kind, name, size, used_bytes)` | 업로드 3종 |

`viewer`는 `{cid: int(0=비로그인), admin: bool}`. 판정 규칙:

- `can_view`: 관리자 → 참. `free` 칸 → `status == 'approved'`. `review` 칸 → 승인됐거나 작성자 본인.
- `can_download`: `can_view` 이고 `cid > 0`.
- `can_write`: `free` → 관리자. `review` → `cid > 0`.

첨부 서빙도 반드시 `can_view`를 거친다. 승인 전 후기의 영상 주소를 아는 사람이 직접 열어도 404가 나와야 한다. 그래서 첨부는 도움말 업로드처럼 "내용 해시 = 공개 주소"로 두지 않고, 첨부 id로 찾아 글의 판정을 거친 뒤 내준다.

## 5. 데이터

`reference.db`(라이브 DB)에 표 세 개를 `Store`에 추가한다.

```
board_post(id, board, author_cid, title, body, status, pinned,
           consent, created_at, updated_at, approved_at)
    board  = 'review' | 'free'
    status = 'pending' | 'approved' | 'hidden'     (free 칸은 관리자 글이라 바로 approved)
board_file(id, post_id, kind, orig_name, stored_name, size, created_at)
    kind   = 'video' | 'image' | 'audio' | 'file'
board_nick(cid PRIMARY KEY, nickname UNIQUE, created_at)
```

파일은 `shopping_shorts/data/board_media/<stored_name>`. `stored_name`은 서버가 지은 무작위 이름 + 확장자(클라이언트 문자열을 경로로 쓰지 않는다). 삭제는 글 삭제 때 파일도 같이 지운다.

## 6. 화면과 주소

| 주소 | 메서드 | 열림 | 하는 일 |
|---|---|---|---|
| `/board` | GET | 누구나 | 화면(`static/board.html`). 칸 전환, 카드 목록, 글 보기, 글쓰기 |
| `/api/board/list?board=&page=` | GET | 누구나 | `can_view` 통과 글만. 고정 글 먼저, 최신순, 20개씩 |
| `/api/board/post/{id}` | GET | 누구나 | 글 + 첨부 목록(`can_view` 실패 = 404) |
| `/api/board/media/{file_id}` | GET | 누구나 | 영상·사진·미리듣기 재생(Range 지원). `can_view` |
| `/api/board/download/{file_id}` | GET | 로그인 | `kind='file'` 내려받기. `can_download`, 비로그인은 401 + 가입 안내 |
| `/api/board/nick` | GET·POST | 로그인 | 닉네임 조회·정하기 |
| `/api/board/post` | POST | 로그인 | 글 생성(제목·본문·동의) |
| `/api/board/post/{id}` | POST·DELETE | 작성자·관리자 | 수정·삭제 |
| `/api/board/upload` | POST | 로그인 | 첨부 1개 올리기(post_id, kind) |
| `/api/board/admin/pending` | GET | 관리자 | 승인 대기 목록 |
| `/api/board/admin/act` | POST | 관리자 | approve · hide · pin · unpin |

게이트 등록은 세 곳이 한 세트다(한 곳만 넣으면 한쪽 사람만 못 본다).

- `_AUTH_ALLOW`(비로그인 허용): `/board`, `/api/board/list`, 그리고 `/api/board/post/`·`/api/board/media/` 접두사의 GET
- `_FREE_EXACT_GET` / `_FREE_EXACT_ANY` / `_ranking_only_blocked`의 접두사 분기: 위 전부 + 글쓰기·업로드·내려받기·닉네임(무료 등급도 써야 한다)
- 공개 경로에서는 미들웨어가 `request.state.customer_id`를 안 채운다(`app.py` 도움말 주석에 적힌 함정). 게시판 핸들러는 세션 쿠키를 직접 검증해 `viewer`를 만든다 — 이 변환도 `_board_viewer(request)` 한 곳.

관리 화면은 `/board` 안에서 관리자에게만 보이는 "승인 대기" 탭으로 둔다(별도 페이지 없음).

## 7. 디스크

서버 실측(2026-10-11): `/` 619G 중 104G 여유(84%). `scene_assets`(짤 포함) 441M.

- `board_media` 전체 상한 30GB. 넘으면 `accept_upload`가 413 + "지금은 올릴 수 없어요, 운영자에게 알렸어요" 를 주고 관리자 경보를 한 번 올린다.
- 후기 영상은 재인코딩하지 않는다(1차). 목록 카드용 썸네일만 ffmpeg로 첫 장면 1장을 뽑아 `kind='image'` 숨김 첨부로 둔다. 실패하면 썸네일 없이 올리고 사유를 로그에 남긴다(조용한 실패 금지).

## 8. 오류 처리

- 종류·크기 위반 → 422/413과 사람이 읽는 문구.
- 업로드 중 끊김 → 임시 이름으로 받고 끝나면 이름을 바꾼다. 반쯤 받은 파일이 글에 붙지 않는다.
- 승인 전·숨김 글의 주소를 직접 열면 404(존재 여부를 알리지 않는다).
- `except: pass` 없음. 썸네일·알림 실패는 로그에 사유를 남긴다.

## 9. 결과물 검사

`tools/board_check.py` — 기능과 같은 커밋.

네 신분(비로그인 · 무료회원 · 작성자 · 관리자)으로 실제 서버에 요청해 아래 표를 실물 응답으로 대조한다. `--local`은 로컬 서버, 기본은 라이브(`tools/live_admin` 세션 사용).

| 대상 | 비로그인 | 무료회원(타인) | 작성자 | 관리자 |
|---|---|---|---|---|
| 승인 전 후기: 목록에 뜸 / 글 / 영상 | ✗ / 404 / 404 | ✗ / 404 / 404 | ○ / 200 / 200 | ○ / 200 / 200 |
| 승인 후기: 목록 / 글 / 영상 | ○ / 200 / 200 | 동일 | 동일 | 동일 |
| 숨김 후기 | 404 | 404 | 404 아님(본인 글, "숨김" 표시) | 200 |
| 자료 글 / 미리보기 | 200 / 200 | 200 / 200 | — | 200 |
| 자료 내려받기 | 401 | 200(바이트 수 = 올린 크기) | — | 200 |
| 후기 쓰기 | 401 | 200 | — | 200 |
| 자료실 쓰기 | 401 | 403 | — | 200 |
| 동의 체크 없이 쓰기 | — | 422 | — | — |

- 영상은 상태코드만 보지 않고 **받은 바이트의 md5가 올린 파일과 같은지** 본다.
- 검사가 진짜 재는지 확인: `can_view`를 "항상 참"으로 바꾼 상태에서 이 검사가 실패해야 한다(0순위-A1c).
- 단위 테스트 `tests/test_board.py`: 판정 함수 4개의 신분 × 상태 표, 게이트 3곳 등록 여부, 닉네임 중복.

화면 확인: 라이브에서 직접 후기 글을 영상과 함께 올리고 → 승인 전 비로그인 창에서 안 보이는 것 → 승인 → 비로그인 창에서 보이고 영상이 재생되는 것 → 자료실 글에 파일을 올려 무료 계정으로 내려받는 것까지 본다.

## 10. 1차에서 뺀 것

댓글 · 좋아요 · 후기 보상(과금) · 등업 · 히트작 분석 자동 초안 · 랜딩 노출 · 영상 재인코딩. `board` 값과 `can_*` 규칙을 늘리면 칸을 더 얹을 수 있다.
