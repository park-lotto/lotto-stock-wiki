## 0. 한 줄 결론

페이지는 **채널 보관함**이다 — 후보·진행 중·끝남·보류 채널을 저장·분류(태그·우선순위)·메모하고, 저장하면 기본 수치(구독·편수·조회 중앙·업로드 빈도)가 자동으로 채워져 주기 갱신된다. 채널을 "칼카피 시작"하면 1·2단계는 채널 단위, **갈래 나누기**(자동 제안+사람 확정) 뒤 3~7단계는 갈래마다 돈다. 2단계는 갈래마다 **화면 틀·자막·컷·그래픽·소리·대본·말투·스토리**를 재사용 자산 묶음(`assets/`)으로 뽑고, 재현 검사는 우리 엔진으로 같은 틀을 렌더·같은 자로 대본을 뽑아 **원본과 같은 자로 재서 차이 표**로 낸다. 원장은 서버 데이터 폴더 한 장(쓰기 주인 `set_step` 하나), PC 실행기는 서버 큐를 받아 가고 단계마다 결과를 돌려준다. 화면은 계산하지 않는다.

**사장님 답(10-15)**: 첫 채널 = **썰풀다** / 갈래 확정 처음 두 채널은 사장님 / 시험 3편 중 **2편 합격**이면 등록 / 채널 중앙 이상 갈래만 자동, 나머지는 버튼 / 실행기 = **이 PC(TheRose)**.

### 1-3. 서버 데이터센터 IP에서 유튜브가 되는 것·안 되는 것

| 일 | 경로 | 근거 |
|---|---|---|
| 채널 쇼츠 **목록·조회수·구독자** | YouTube Data API(서버) | `channel_survey` 주 1회 실측 돌고 있음(205채널 7분). 쿼터 = 채널당 (쇼츠÷50)×2 호출 |

## 3. 데이터 모델

### 3-1. 개체

```
보관함 채널(calcopy_channel, DB 1행)  ── status: 후보 | 진행 중 | 끝남 | 보류 | 삭제됨
   ├─ 기본 수치(stats): 구독·편수·조회 중앙·10만↑·하루 편수·마지막 업로드  ← 서버 Data API, 주기 갱신
   ├─ 태그(컨셉 분야: 정치/연예/뷰티/썰/홈템/…, 여러 개) · 우선순위(1~5) · 메모 · 담당 · 넣은 날
   └─ 칼카피 원장(calcopy/<slug>.json, 데이터 폴더 1장) — "칼카피 시작"을 눌렀을 때 생김
        ├─ 채널 단계: 1 선정 · 2 채널 공통 자산(틀·자막 형태·소리) · split 갈래 나누기
        └─ 갈래(style) N
             ├─ 갈래 단계: 2′ 갈래 자산 추출 · 3 스토리·대본·말투 자산 · 4 소재 방식 · 5 프리셋 · 6 시험 3편 · 7 판정·등록
             ├─ assets/manifest.json  (§6의 자산 묶음 — 틀·자막·컷·그래픽·소리·대본규칙)
             ├─ reproduce/report.json (§7 재현 검사 — 항목별 원본 vs 우리 차이)
             ├─ trials[3] · concept(프리셋 파일 경로+sha)
영상(videos.json): id·views·upload_date·title·group(top/bottom/pool)·style·style_by·style_conf
```

- 갈래가 하나뿐이어도 `기본` 1갈래. 모양이 하나라야 화면·실행기·검사가 한 벌(0순위-B).
- 층 분담: 채널 공통(L 배치·S 자막 형태·A 소리 바탕·C 채널)은 2단계에 한 번, 갈래마다 달라지는 것(T 시간·W 말·K 훅·H 헤드라인·M 소재·그래픽·효과음 사용 자리)은 2′·3단계에서 그 갈래 표본으로.

## 5. 자동 실행 흐름

### 5-1. 서버→PC 전달 후보와 결정

| 후보 | 판정 | 이유 |
|---|---|---|
| A. git만(지금) | 기각 | 서버가 일감을 못 보냄 · 진행 중 안 보임 · 서버가 원장 쓰면 워킹트리 오염 → auto_deploy 멈춤(배포 규칙 9) |
| **B. HTTP 큐 폴링** | **채택** | 라이브 선례 2벌(`yt_relay` 801~833 · `coupang relay` 6126~6160), hmac 키, PC가 바깥에서 안 보여도 됨, 진행 보고가 같은 길 |
| C. SSH→PC / D. 공유 폴더 | 기각 | PC 공인 주소 없음 / 충돌·누가 썼는지 모름 |

### 5-2. 흐름

```
[보관함] 채널 저장(URL) ─ 서버: resolve → 행 생성 → survey 1회 → 기본 수치 채움(status 후보)
[보관함] "칼카피 시작" ─ 서버: 원장 생성 + 큐 {slug, upto:"split"}
[PC 실행기(TheRose)] autorun --serve: 롱폴 GET /api/admin/calcopy/jobs/next (55초)
   단계마다  POST progress {state:"doing", note:"mp4 7/20"}  (+30초 heartbeat)
   끝        git add channel/<slug>/… → commit → push(트랙 브랜치) → POST progress {state:"done", files, sha}
   실패      POST progress {state:"blocked", note:"<예외: 원문 200자>", log_tail} → 그 채널 멈춤, 다음 일감
   split     propose → split_proposal.json → state waiting_human
[보관함] 갈래 확정 → 큐 {slug, styles:[auto=true만], upto:6}
[PC] 갈래마다 2′ 자산 추출 → 3 대본 규칙 → 재현 렌더+재현 대본 → 비교 표 → 4 → 5 프리셋 → 6 시험 3편(라이브 job) → waiting_human
[보관함] 시청 판정(3편 중 2편 통과) → 7 등록 → 채널 status 끝남(모든 auto 갈래 등록 시)
```

- 큰 파일(mp4·잘라 낸 짤·효과음 견본·재현 렌더)은 저장소 밖 `CALCOPY_RAW/<slug>/`(PC) → 자산 중 **작은 것**(png 짤·wav 효과음 1~3초·틀 json·규칙 json·프레임 시트 jpg)만 `channel/<slug>/styles/<id>/assets/`에 커밋(상한: 갈래당 20MB, 넘으면 D 외장 + 경로). 서버 페이지는 커밋된 것만 보여 준다.
- 인증 `CALCOPY_RELAY_KEY`(hmac, 없으면 큐 잠김).

## 7. 3단계 = 스토리·대본·말투·자막·시간 자산 → `rules.json`(대본 생성기가 그대로 읽음)

입력 = 갈래 표본 **전 편 받아쓰기**(스피치매틱스, 단어 시각) + 화면 자막 판독(제미니, `read_subs.py`) + `videos.json`(조회). 주인 `tools/calcopy/script_rules.py:build()`. 각 항목은 **규칙(숫자·범위) + 예문(원본 문장 id)** 쌍이다.

| 묶음 | 무엇 | 자/도구 | rules.json 칸 |
|---|---|---|---|
| 스토리 흐름 | 박자 구성(방구석 6박자 선례: 제목 낭독→소개→의문→해답→덤→결말+댓글) · 박자별 시간 비율 · 전환 위치 %(15/28/45~70/80/93 선례) · 훅→전개→반전→결말 꼴 · 마지막 처리(댓글 유도·되묻기·여운) · **터진 편 vs 안 터진 편 차이**(상위10/하위10 박자 비율·전환 위치 대조, V층) | `script_structure.py`(전환 표지 위치·말 속도) + 새로: 박자 라벨링(제미니, 문장→박자) → 비율 | `story:{beats:[{name, share_pct:{med,min,max}, markers:["하지만","사실"]}], transitions_pct:[…], ending:{kinds:{comment_bait:..,question:..}}, top_vs_bottom:{…}}` + 예문 |
| 대본 | 문장 수·글자 수·말 속도(자/초)·쉼 중앙 · 자주 쓰는 표현 목록(2편 이상 되풀이, §13-2 "발견해버렸는데" 꼴) · 첫 줄 훅 꼴 목록(사실/인용/의문/명령 + 조회 중앙, hook56 선례 사실 565k vs 인용 51k) · 대사(역할극) vs 나레 비율·화자 수 | `script_text_stats.py`(구절 길이·전언) + `asr`(cps·쉼) + 새로: 되풀이 표현 n-gram(3편↑) · 훅 꼴 판독 | `script:{sentences:{med,range}, chars:{med,range}, cps:{med,range}, pause_s, phrases:[{text, n, where}], hooks:[{kind, template, example, median_views}], dialog_share, speakers:{n, roles:[…]}}` |
| 말투 | 종결어미 분포(~음/~다고/~요/~는데/명사) · 존댓말/반말 비율 · 1·2인칭 횟수 · 감탄·의성어(ㄷㄷ·ㅋㅋ·헐) · 전언(~다고 함) 비율 | `script_text_stats.py`(문장 끝 꼴·전언) — 있음, `banggu/spec.py FLAT_END` 정규식 재사용 | `tone:{endings:{"는데":.31,"다고":.25,…}, polite_ratio, person_1st, person_2nd, interjections:{…}, hearsay_ratio}` |
| 자막 | 자막 문장 = 나레 일치율(글자 겹침) · 줄 나눔 규칙(글자수·조사 뒤·구절 단위) · 강조 낱말 고르는 규칙(숫자·제품명·감정어·부정어 비율) | 판독 자막 ↔ asr 정렬(새로, 시각 기준) + captions mark 데이터 | `caption_text:{match_ratio, line_break:{max_chars, at:["조사뒤","쉼표"]}, mark_kinds:{숫자:.4,고유명사:.3,…}}` |
| 영상 시간 | 길이 분포(갈래별) · 첫 컷·첫 자막 시점 · 훅 길이(첫 전환까지) · 결말 시점(마지막 박자 시작 %) | `bench T.duration·first_cut` + 박자 라벨 | `timing:{duration:{med,p10,p90}, first_cut_s, first_caption_s, hook_s, ending_from_pct}` |

**형식 결정**: `rules.json` 한 장 + `examples/`(문장 id → 원문·편·시각). `seedflow.load_rules(path)`가 이걸 읽어 ①write 프롬프트에 범위·예문을 넣고 ②problems가 같은 칸으로 검사한다(`banggu/spec.py`의 상수들은 이 파일에서 **생성**되도록 — 손으로 적은 상수와 측정 파일이 두 벌 되지 않게. 생성 스크립트 `tools/calcopy/rules_to_spec.py`, spec.py 머리에 "생성됨 — 손대지 마라" 표식).

**재현 검사(대본)**: 같은 씨앗으로 우리 대본 5편을 뽑아 **같은 자**(`script_text_stats`·`script_structure`·cps)로 재서 표 — 칸마다 원본 범위(p10~p90) 안/밖, 종결어미 분포 거리(L1), 박자 비율 차, 첫 줄 훅 꼴 분포. 범위 밖 칸이 3개 넘으면 그 갈래 5단계 못 감(관문). 선례: 10-06 말맛 진단(고정 문장 2% vs 18%, 설명서 낱말 0.5 vs 1.8/100자)이 이 표의 두 행이다.
