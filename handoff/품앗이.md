## ⏭ 다음에 할 것 (재개점)

### 관문 1 — "상대가 꼭 갚게" 강제 방식 (선택지 확정 필요)
- **(A)** 투명 장부 = 빚 공개 (사회적 압박만) — 약함, 먹튀 가능
- **(B) 선불 구조 = 먼저 갚아야 받음** ← 유력. 신규 채널이 기존 N개에 먼저 댓글/구독해야 "받기 목록"에 오름. 콜드스타트 자연 해소(등록 순서=받는 순서)
- **(C)** 에스크로 1:1 매칭 — 먹튀 원천봉쇄지만 규모·매칭대기 문제
- **Claude 추천**: **(B) 선불 = 강제엔진 + (A) 장부 = 무임승차 색출**. 둘이 역할 달라 충돌 안 함.
- **아직 물어본 하위 결정**: 선불 크레딧 비율 = 1:1(순환 딱 맞음) vs 1:N 부양(트래픽 인위증폭이나 후발주자 손해). ← **여기서 사장님 답 대기 중이었음**

### 관문 2 — "봇 아닌 실제 유저" 판별 기준
- (1) 계정 나이 + 구독자 수 (봇=신규·0명)
- (2) 본인 OAuth 연동 (봇 대량계정은 로그인 번거로움)
- (3) 댓글 내용 품질 (복붙/이모지 vs 진짜 댓글, 자동 판별)
- **Claude 추천**: 보통 (2)+(3) 조합. 확정 필요.

## 확정된 것 (다시 논의 X)

- **목적 = 트래픽 확보** (유저 성공 아님). 품앗이는 미끼로 최적, 초보 유튜버 계속 유입돼 총 트래픽 유지.
- **시청 지속시간 = 검증 안 함**, 신의·약속에 맡김 (개인별 시청량은 기술적 불가).
- **구독+댓글 = 자동 검증**, 봇 아닌 실제 유저만. 댓글이 가장 강한 축(공개 API로 검증됨).
- **핵심 제품 = "진짜 서로 해줬는지 투명하게 보이는 장부" 그 자체** (보상엔진 없음). 무임승차자 색출이 1등 니즈.
- **플랫폼 = 하이브리드 C**: 유튜브 자동 / 인스타 수동(API 막힘).

## 리스크 (잊지 말 것)
1. 유튜브/인스타 약관이 sub4sub 금지 → OAuth 앱 심사 거절 위험. 트래픽 목적이면 감수 or 포지션 조정.
2. 맞구독은 알고리즘이 저품질로 깎음(성장엔 밑빠진 독) — 단 트래픽 목적이면 무관.
3. 봇의 장부 farming → 실제 유저 판별 필수(관문 2).
