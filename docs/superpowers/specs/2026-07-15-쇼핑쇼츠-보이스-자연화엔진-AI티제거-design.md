# 쇼핑쇼츠 보이스 자연화 엔진 (AI티 제거) — 설계

- 날짜: 2026-07-15
- 트랙: 쇼핑쇼츠 자동화 SaaS / 보이스 프리셋 라이브러리 후속
- 선행: `docs/superpowers/specs/2026-07-14-보이스-프리셋-라이브러리-design.md` (프리셋·ElevenLabs 연결·v3 검증 완료)

## 1. 목적 / 성공 기준

ElevenLabs v3 한국어 TTS 나레이션을 **"1%도 AI로 들리지 않는" 실제 서울 20대 여성 목소리**로 만든다.

핵심 통찰: AI티의 병목은 "감정 부족"이 아니라 **① 문어체 종결(낭독체) ② 문장마다 리셋되는 콜드스타트 억양 ③ v3 특유의 take 편차**다. 따라서 감정태그 2~3개 삽입이 아니라, 텍스트를 다듬는 **규칙 엔진** + 성우별로 귀로 완성하는 **튜닝 작업대** + 편차를 무인 처리하는 **N-best/연속성/seed** 시스템이 결과물이다.

**성공 기준**: 성우(변형)당 **회귀 코퍼스로 1회 튜닝 → 프로파일 동결**하면, 이후 **어떤 대본이 들어와도** 같은 규칙이 자동 적용되어 사람 목소리로 나온다. 사장님의 반복 노동은 "성우 새로 추가할 때"뿐.

**비목표(YAGNI)**: 앱내 레퍼런스URL→프로파일 자동생성, JP/EN, 보이스 클로닝, v2/v3 하이브리드 모델선택, 튜닝 프로파일 버전이력 UI — 전부 이후 Phase.

## 2. 아키텍처 (3조각)

```
[1] narration_naturalize.py   순수 규칙 엔진 (텍스트 → TTS용 텍스트). Gemini·API 무호출.
       │  프로파일(dict)이 구동. 8스테이지 순서 적용. 결정적.
       ↓
[2] 튜닝 작업대 (voice_tune.html + API 4개)   성우별 프로파일을 귀로 완성.
       │  코퍼스 입력 → 규칙토글/강도 → 미리보기 → 합성(N-best) → ASR diff → A/B → 동결
       ↓
[3] 프로덕션 통합   동결된 프로파일을 mix_pipeline이 TTS 직전 조용히 적용 + 연속성/N-best.
```

**격리 3원칙 (설계의 뼈대):**
1. **엔진은 순수함수** — `naturalize(text, profile, ...) -> text`. API·Gemini 안 부름. 결정적, 유닛테스트 100%.
2. **작업대만 실합성** — 튜닝 중에만 ElevenLabs 호출. 프로덕션은 동결 프로파일 읽기만 → 튜닝이 프로덕션 안 흔듦.
3. **프로파일 = 데이터(JSON)** — 규칙별 on/off + 강도(0~1) + 사전 + 감도 + seed. 코드 아님. 성우 변형(stable/natural/expressive)마다 하나.

**데이터 흐름:**
```
튜닝:  raw ──naturalize(profile)──> 태그드텍스트 ──synth(N-best,seed)──> mp3 ──[귀+ASR]──> profile 조정 반복
동결:  profile → voice_presets.json[preset].naturalize_profile  (+ 통과표식)
프로덕션: beat.narration ──naturalize(preset.profile)──> synth(연속성,N-best) ──audio_post──> beat.tts_path
```

## 3. 자연화 규칙 엔진 (8스테이지)

시그니처: `naturalize(text, profile, *, beat_role=None, beat_index=None, beat_total=None) -> str`

프로파일의 각 스테이지는 `{on: bool, intensity: 0~1, ...}`. **intensity 기본값 전부 낮게(0.2~0.4)** — "오버금지"가 기본, 귀로 올려가며 튜닝.

**적용 순서 (중요 — 태그를 마지막에 얹어 앞 규칙이 태그문자열을 안 건드리게):**

| # | 스테이지 | 하는 일 | v3 레버 | 강도 의미 | 맥락 필요 |
|---|---------|--------|--------|----------|:--:|
| ① | **normalize** (정규화) | 숫자·단위·기호·영어 발음화 | 2,000원→이천 원 / 3.5kg→삼 점 오 킬로 / %→퍼센트 / SNS→에스엔에스 / 날짜 | (사전+규칙, 강도무관) | |
| ② | **spoken_style** (구어체) | 문어체 종결→서울말 구어체 | ~합니다→~해요/~거든요, ~됩니다→~되더라고요 등 매핑(강도=변환 비율) | 문어↔구어 정도 | |
| ③ | **pronunciation** (연음/발음) | 오독 교정 | 프로파일 사전 치환(브랜드·희귀 한자어). **전역 사전**(성우무관) | (사전, 강도무관) | |
| ④ | **phrasing** (끊어읽기/호흡) | 호흡 지점 삽입 | 어절·조사 경계·서술어 앞 쉼표, 긴 문장 줄바꿈 | 쉼 밀도 | |
| ⑤ | **endings** (끝음) | 종결부 뚝-떨어짐 완화 | 종결부 앞 미세쉼/`…`, 마침표↔`~`↔`…` 매핑 | 부드럽게 처리할 종결 비율 | |
| ⑥ | **fillers** (추임새) | 사람다움 결정타 | 비트 시작·전환부에 필러(음/아/그/뭐/자) 극소량, 프로파일 뱅크 | 삽입 빈도 | (위치용) |
| ⑦ | **emotion_arc** (감정곡선) | 은은한 감정 흐름 | v3 태그를 비트 위치별 곡선으로: 훅[궁금/설렘]→빌드[중립따뜻]→페이오프[만족]→CTA[따뜻] | 태그 붙는 비트 수·세기 | ✅ 비트역할·위치 |
| ⑧ | **intonation** (억양) | 평판 억양 탈피 | `?` 보존(상승), 강조 극소수 | 강조 빈도 | |

**엔진 하드캡 (가드레일 — "오버"를 코드로 구조적 차단):**
- 비트당 v3 태그 ≤ 1, 나레이션 전체 태그 ≤ 3 (emotion_arc)
- 추임새 밀도 상한 (fillers) — intensity=1이어도 도배 불가
- 강도는 상한 안에서만 밀도를 조절

**단일문자열 vs 비트맥락**: ①②③④⑤⑥⑧은 단일 문자열만으로 동작 → 작업대에서 한 줄 붙여 즉시 튜닝. ⑦(emotion_arc)만 비트 역할·위치 필요 → 파이프라인은 넘겨주고, 작업대 단일모드는 역할 수동선택.

**결정성**: 같은 (text, profile) → 같은 출력(⑦의 태그위치까지 결정적). seed는 합성(TTS)측 파라미터로 엔진과 별개.

## 4. 튜닝 작업대 (voice_tune.html + API)

성우당 1회 튜닝의 현장. 로컬 HTML + 튜닝 전용 API 4개(프로덕션과 분리).

**레이아웃:**
```
┌─ 좌: 회귀 코퍼스 (고정 10~15줄) ──────────┬─ 우: 프로파일 컨트롤 ──────┐
│ 줄마다 카드: 원문 → 변환텍스트(펼침)      │ 성우/변형 선택 [켈릭·natural▾]│
│   → N-best 픽 mp3 [▶] → ASR diff(오독빨강)│ ①정규화 [ON]  ②구어체 ▓▓░ 0.4│
│   → [이 줄만 재롤]                         │ ③연음+사전  ④끊어읽기 ▓▓░ 0.3│
│ [전체 재합성] [A/B: 이전프로파일 vs 현재] │ ⑤끝음 ⑥추임새 ⑦감정곡선 ⑧억양│
│                                            │ 감도 원노브(차분↔생생)       │
│                                            │ seed[42] N-best[3] [💾동결]  │
└────────────────────────────────────────────┴────────────────────────────┘
```

**동작:**
- 규칙 토글/강도 조작 → **변환텍스트 즉시 미리보기**(순수엔진이라 합성 없이 공짜). [전체 재합성] 눌러야 실 TTS.
- 각 줄: 원문 → 변환텍스트 → N-best 중 픽된 mp3 → **ASR diff**(Whisper 재전사가 원문과 다르면 그 단어 빨강 = 오독/탈락 자동경보).
- **재롤**: 그 줄만 N-best 다시. **A/B**: 직전 저장 프로파일 vs 현재를 같은 줄로 나란히 재생.
- **캐싱(v1 필수)**: `(변환텍스트, seed, settings)`→mp3 재사용. 안 바뀐 줄은 재합성 안 함(크레딧·시간).
- **💾 동결**: 현재 프로파일을 `voice_presets.json[preset].naturalize_profile`에 기록 + 통과표식. 이후 프로덕션이 적용.

**튜닝 전용 API (프로덕션 경로와 분리):**
- `POST /api/voice-tune/preview` — {text, profile} → 변환텍스트만(합성X, 공짜)
- `POST /api/voice-tune/synth` — {text, profile, seed, n} → N-best mp3 + 픽 + ASR diff
- `GET/POST /api/voice-tune/profile/{preset_id}` — 프로파일 로드 / 동결
- `GET /api/voice-tune/corpus` — 회귀 코퍼스(고정 JSON)

**회귀 코퍼스** (`assets/tune_corpus.json`, 10~15줄): 훅·제품설명·CTA·숫자많은문장·감탄문·긴문장·짧은문장 등 대표 유형 망라. 한 줄이 아니라 **전 코퍼스가 사람같을 때 동결** → 미지의 대사 일반화 보증(과적합 방지).

## 5. 프로덕션 통합 + 기존 코드 수정

**동결 프로파일을 조용히 적용:**
- `mix_pipeline._plan_and_tts`([mix_pipeline.py:113-119](../../../shopping_shorts/mix_pipeline.py)) TTS 루프에서 `synthesize_tts` **직전에** `naturalize(beat["narration"], profile, beat_role, beat_idx, total)`. 프로파일은 job voice 스냅샷(동결 프리셋)에서.
- **연속성**: 루프가 `previous_text`(직전 비트 원문)·`next_text`(다음 비트)를 `synthesize_tts`에 전달 → 콜드스타트 제거. (v3 지원범위는 배선 전 API 확인.)
- **N-best**: `synthesize_tts`를 N회→랭킹→최선 선택하는 얇은 래퍼. 프로덕션 N=1~2(크레딧), 작업대 N=3~5. 랭킹은 v1에서 ASR diff 최소(오독 적은 take) + 길이 sanity 기준.
- `resynth_tts_job`([mix_pipeline.py:208](../../../shopping_shorts/mix_pipeline.py))도 동일 경로 타게 TTS 루프를 헬퍼로 추출(중복 제거).

**tts.py 수정 (하위호환):**
- `synthesize_tts`에 `seed`·`previous_text`·`next_text` 추가 → payload 조건부 삽입. 없으면 기존 동작 동일.
- **speaker_boost 버그**: 프리셋 45개 전부 `use_speaker_boost: true`인데 v3 비호환 → **model_id가 v3면 payload에서 자동 drop**(코드 방어) + JSON 정리.

**호흡 vs 무음삭제 재조정**: `audio_post`([mix_pipeline.py:118](../../../shopping_shorts/mix_pipeline.py))의 `silenceremove`가 자연 호흡·문장 사이 쉼을 깎아 오히려 기계적일 수 있음 → 자연화 프로파일에 `silence_trim` 기본을 약하게/off로, 의도된 호흡 보존.

**신규/수정 파일:**
```
신규: shopping_shorts/narration_naturalize.py   (8스테이지 순수엔진)
      shopping_shorts/asr_check.py              (Whisper 재전사 diff, GROQ)
      shopping_shorts/assets/tune_corpus.json   (회귀 코퍼스)
      shopping_shorts/static/voice_tune.html    (작업대)
      (라우트) app.py에 /api/voice-tune/* 4개 (또는 voice_tune_api.py 분리)
수정: shopping_shorts/tts.py                    (seed·연속성·speaker_boost drop·N-best 래퍼)
      shopping_shorts/mix_pipeline.py           (TTS직전 naturalize + 연속성 + 헬퍼추출)
      shopping_shorts/assets/voice_presets.json (naturalize_profile 필드 + speaker_boost 정리)
      shopping_shorts/store.py                  (프로파일 저장 — voice_json에 얹음)
```

## 6. 테스트 전략

- **엔진(핵심)**: 8스테이지 각각 독립 유닛테스트 — 결정성(같은 입력→같은 출력), 하드캡(intensity=1이어도 태그≤3·추임새상한), 순서(pronunciation이 태그문자열 불건드림), 각 규칙 off면 무변경.
- **하위호환**: `synthesize_tts`를 profile/seed 없이 호출 시 기존 payload와 동일(회귀).
- **speaker_boost drop**: v3 model_id면 payload에 `use_speaker_boost` 없음 검증.
- **통합 스모크**: mock TTS(키 없이 무음)로 `_plan_and_tts`가 naturalize 거쳐 관통.
- **ASR check**: 정상문/오독문 픽스처로 diff 로직 검증(Whisper 모킹).
- **실합성 게이트(수동, 진짜 게이트)**: 작업대에서 코퍼스 전체 합성 → 사장님 귀 통과해야 동결. 자동테스트가 대신 못 함.

## 7. 확정 설계 결정 (요약)

1. 접근 = 규칙엔진 + 전용 튜닝작업대 (프로덕션 위험 없이 정교 튜닝).
2. 규칙 = LLM 삽입이 아니라 **결정적 8스테이지**. 감정태그는 감정곡선 스테이지의 한 부분(하드캡).
3. AI티 4차원+2 전부 다룸: 끝음·끊어읽기·연음·억양 + 감정곡선·추임새. 최상위 레버는 **구어체 변환**.
4. 편차는 재튜닝이 아니라 **N-best(대본단위)** + **연속성** + **seed**로 무인 처리.
5. 일반화 보증 = **회귀 코퍼스**(대표 10~15줄 동시판정, 과적합 방지).
6. 성우당 튜닝 1회 → 동결 → 전 대본 자동. 예외는 발음 사전 전역 추가뿐(톤 재튜닝 아님).
7. speaker_boost는 v3 비호환 → 코드에서 자동 drop.
8. v1 스코프 = 핵심5(구어체·연속성·N-best·정규화·호흡) + 회귀코퍼스 + 하드캡 + **ASR검증**. v2 = 하이브리드모델·프로파일 자동생성·JP/EN·클로닝.
