# 대본 스타일 → 장면꾸미기 카피 계열 연결 설계

## 목표

대본 스타일을 선택해 생성한 대본이 장면꾸미기로 넘어갈 때 스타일 정보가 사라지지 않게 하고,
큰 제목·흰 띠 보조문구·업로드 제목을 해당 플랫폼 화법에 맞는 한 세트로 생성한다.

## 지원 계열

### `youtube_reveal` — 유튜브 썰쇼핑 첫 후킹형

- 결과·사건을 먼저 말하고 제품 정체는 감춘다.
- 큰 제목은 3인칭 관찰자 화법의 두 줄이다.
- 보조문구는 정체를 밝히지 않는 질문·미스터리다.
- 나라·천재·개발자·돈방석·주문 폭주·업계 반응 같은 극적 포장을 허용한다.

### `instagram_story` — 인스타 관계썰형

- 사람·관계·상황을 첫 문장에 놓는다.
- 큰 제목은 대화하듯 자연스러운 관계 사건 또는 반전 전조다.
- 보조문구는 다음 상황이 궁금해지는 짧은 목격담·질문이다.
- `~했다는데`, `~했더니`, `알고 보니`처럼 썰을 이어가는 말투를 허용한다.
- 제품의 정체·작동 방식·핵심 효익은 대본과 다르게 바꾸지 않는다.

### `demo_direct` — 직접 시연·고정형

- 제품이 무엇을 해결하는지 첫 문장에 직접 말한다.
- 큰 제목은 사용 전후·행동·효과 중심이며 과도한 관계 서사를 만들지 않는다.
- 보조문구는 사용법·비교·핵심 기능을 짧게 받친다.
- 제품 정체를 숨기는 것보다 화면에서 바로 이해되는 것을 우선한다.

## 데이터 흐름

1. 사용자가 대본 스타일을 선택하면 서버에 `style_ids`가 전달된다.
2. 생성 초안의 `style_id`와 스타일 플랫폼 정보를 확정 시 작업 상태에 보존한다.
3. 스타일 플랫폼을 카피 계열로 한 곳에서 변환한다.
   - 유튜브형 → `youtube_reveal`
   - 인스타형 → `instagram_story`
   - 픽업영상 구조·직접시연형 또는 플랫폼 미지정 → `demo_direct`
4. 장면꾸미기 제목 API에는 확정 대본과 결정된 `copy_family`를 전달한다.
5. 생성 결과는 `text`, `subline`, `upload_title`, `why` 한 세트로 유지한다.

## 우선순위

- 사용자가 장면꾸미기 템플릿을 직접 바꾼 경우 템플릿의 `copy_family`가 최우선이다.
- 직접 바꾸지 않은 초기 진입에서는 확정한 대본 스타일의 카피 계열을 사용한다.
- 옛 작업처럼 스타일 정보가 없으면 현재 기본값 `youtube_reveal`을 사용해 하위호환한다.

## 저장과 복원

- 작업 저장 상태에 확정 초안의 `script_style_id`, `script_copy_family`를 저장한다.
- 새로고침과 작업 재진입에서도 두 값을 복원한다.
- 이전 저장 데이터에 필드가 없어도 오류 없이 기본값으로 동작한다.

## 오류 처리

- 알 수 없는 카피 계열은 `youtube_reveal`로 정규화한다.
- 한 계열 생성이 실패해도 기존 직접 입력 문구를 덮지 않는다.
- 서로 다른 계열은 같은 대본이라도 서버 캐시를 공유하지 않는다.

## 검증

- 각 계열의 프롬프트 규칙과 세트 필드 보존을 단위 테스트한다.
- 대본 확정 시 스타일 계열이 작업 상태에 남는지 UI 회귀 테스트한다.
- 템플릿 직접 선택이 대본 스타일보다 우선하는지 테스트한다.
- 세 계열을 같은 예시 대본으로 브라우저에 주입해 큰 제목과 보조문구가 함께 적용되고
  9:16 화면에서 잘리지 않는지 확인한다.

## 범위 밖

- 모델 미세학습, 썰쇼핑 원장 검색 주입, 새 장면꾸미기 시각 템플릿 제작은 이번 작업에 포함하지 않는다.
