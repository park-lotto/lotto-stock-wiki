# 인사이트 리디자인 + 이벤트·트리거 캘린더 — 설계 스펙

- 작성일: 2026-07-04
- 브랜치: `feat/briefing-engine`
- 상태: 설계 확정 대기 (사용자 리뷰 전)
- 디자인 시안: `.superpowers/brainstorm/*/content/insights-apple-light-v5.html`, `insights-catalyst-v6.html`

---

## 1. 목표와 핵심 가치

투자자가 **"내가 담은 종목·섹터에 앞으로 어떤 일정과 트리거가 있는지"**를 한 화면에서 받아본다.
학습된 AI로는 지식 컷오프 때문에 불가능하지만, 우리는 **매일 크롤링해 누적한 원자(atoms)**로 가능하다.

**해자(왜 우리만):**
- 일반 AI: 지식 컷오프 — "캐나다 잠수함이 지금 어느 단계인지" 모름
- 증권사 캘린더: 국내 실적발표일만
- 네이버/인베스팅: 파편적, 해외 연관 트리거 안 묶임
- **우리: 리포트·텔레·뉴스·유튜브를 매일 크롤 → 원자로 누적 → 종목에 연결·투영.** 어디서도 한 판에 못 보는 것을 차려줌

**접근 원칙:** 검색은 보조. **자동 노출(push/ambient)이 주력.** 사용자가 모르는 촉매까지 열자마자 차려져 있어야 한다.

## 2. 범위

두 트랙. 의존 관계: Track B의 데이터가 Track A의 "촉매" 섹션을 채운다 (초기엔 placeholder로 UI 선행 가능).

- **Track A — 인사이트 페이지 리디자인** (frontend): 시안(v5/v6)을 실제 `dashboard/insights.html`에 이식
- **Track B — 이벤트·트리거 캘린더 시스템** (backend + data + wiki): 누적 원자에서 이벤트를 뽑아 캘린더로 투영

**범위 밖(이번 아님):** 실시간 시세 연동, 로그인/멀티유저, 모바일 앱, 유료화.

## 3. Track A — 인사이트 페이지 리디자인

### 3.1 디자인 시스템 (Apple Store 라이트)
- **색:** 캔버스 `#ffffff`/`#f5f5f7`, 잉크 `#1d1d1f`/`#6e6e73`/`#86868b`, 헤어라인 `#e5e5e7`/`#d2d2d7`. 색은 **의미에만** — 등락 up `#1d8a3f` / down `#d70015`, 링크 `#0066cc`. 무채색 UI, 원색 타일 금지
- **타이포:** Pretendard (CDN, `-apple-system` 폴백). 헤드라인 800/거대(clamp 44~76px), 라벨 12~13px — 극단적 스케일 대비
- **레이아웃:** 넓은 여백, 둥근 카드(radius 20~28px), soft shadow, 계단식 페이드업(reduced-motion 존중)
- **데이터=이미지:** 제품 사진 대신 **주가 스파크라인**(area+line)을 카드의 시각 요소로

### 3.2 페이지 구조 (위→아래)
1. 프로스티드 스티키 내비 (로또의 주식 · 딸깍 · 섹터맵 · 인사이트 · 소스)
2. 거대 헤드라인 히어로 ("인사이트." + 우측 태그라인)
3. **브리핑 바 (최상단 주역)** — 검색 입력 + 브리핑 시작 + 스코프 줄(소스 칩 + 기간 세그먼트)
4. **소스 라이브러리** (카테고리 아이콘 줄 = 소스 라이브러리, 아코디언 펼침)
5. **📅 다가오는 촉매** (Track B가 채움) + 내 종목 watchlist
6. **오늘의 신호** 카드 캐러셀 (D-배지 부착)

### 3.3 핵심 인터랙션 (모두 시안에서 검증됨)
- **브리핑(pull):** 종목·테마 입력 → 선택 소스·기간으로 정리·분석. 시그널 카드/소스/촉매 클릭 시 검색창 자동 입력 + 실행
- **스코프:** 소스 칩 **기본 전부 OFF**(눌러 하나씩 켬), 기간 세그먼트(전체/오늘/7일/30일). 0개 선택 시 안내
- **소스 라이브러리(타입별):**
  - 텔레/유튜브/블로그 = **채널 목록** → 특정 채널 선택 "이 채널 분석 →" 즉시 브리핑 / 다중선택 "선택 채널 함께 브리핑"
  - 리포트 = **오늘 발간분 나열** + **언급 종목별** 탭 + 체크 선택 "선택 리포트 브리핑"
  - 뉴스 = 최근 문서 리스트
- **실시간 카운트:** "오늘 수집된 N개 소스" — 크롤 건수에 바인딩, 계속 변함
- **브랜드 아이콘:** 유튜브/텔레그램/네이버블로그 실제 로고 SVG, 리포트/뉴스/리서치 앱아이콘식 글리프

### 3.4 이식 작업
- 대상: `dashboard/insights.html` (현행 다크·골드 테마)
- 방식: 디자인 토큰(CSS 변수) 교체 → 컴포넌트(카드·칩·스코프·라이브러리) 재작성 → 기존 데이터 바인딩(server.py 엔드포인트) 연결 유지
- 국기 이모지는 Windows 미지원 → 국가 라벨칩 or SVG 국기로 대체

## 4. Track B — 이벤트·트리거 캘린더 아키텍처

### 4.1 데이터 모델 — 이벤트 원자
기존 `pipeline/atoms/atoms.db` `atoms` 테이블 재사용. 대부분 필드 이미 존재(`event_type`, `signal='catalyst'`, `validity_type='date'`, `validity_until`, `structured_fields` JSON).

**추가/활용:**
- **신규 컬럼 1개:** `event_date` (YYYY-MM-DD, 미래 발생일) + 인덱스 (`idx_atoms_event_date`, 기존 `idx_atoms_validity` 패턴 미러). ※ `validity_until`은 "유효기한"이라 "발생일"과 의미 다름 → 별도 필요
- **`structured_fields` JSON 페이로드:**
  ```json
  {
    "event_date": "2026-07-15",
    "event_kind": "실적발표|공시|락업해제|투경|IR|옵션만기|배당락|정책|전시|수주|트리거|해외실적",
    "entity": "삼성전자",
    "entity_scope": "domestic|foreign|policy",
    "event_form": "point|saga",
    "affected_stocks": ["삼성전자","SK하이닉스"],
    "confidence": 1,            // 1확정 2높음 3관측 4추정
    "confirmed": true,
    "source_key": "..."         // event_merge 중복제거 키
  }
  ```

### 4.2 두 개의 공급원
- **확정 일정 (deterministic, confirmed=true):**
  - `fetch_sector_calendar.py` 출력(`raw/캘린더/{date}_섹터캘린더.json`) — 실적·IR·정책·전시·수주 (이미 생산, 현재 dead-end)
  - 투경 해제 예측(`pipeline/투경_관리.json` + 예측공식) — 스케줄 이벤트
  - `pipeline/etf_events.json` — ETF 편입/리밸런스
  - **신규 크롤:** 락업해제·옵션만기·배당락 (공시/거래소 기반)
- **예상 트리거 (extracted, confidence<1):**
  - atomizer가 이미 다는 `signal='catalyst'` 태그 원자 중 미래 날짜 함의가 있는 것 → `event_date` 파싱
  - 예: "ADA학회 6/5~8 GLP-1 데이터 발표 예정"

### 4.3 확정도 4단계
| 단계 | 값 | 근거 |
|---|---|---|
| ● 확정 | 1 | 공시·거래소·일정표 |
| ◐ 높음 | 2 | 여러 소스 반복 언급(날짜 有) |
| ○ 관측 | 3 | 단일 소스 예정 언급 |
| · 추정 | 4 | 날짜 애매 |
- **산정기:** `pipeline/atoms/event_merge.py`가 이미 여러 채널의 같은 이벤트를 `_event_key`로 묶어 `mention_count`/`mention_channels`를 올림 → 이 값을 확정도 2/3 판정에 재사용

### 4.4 진행형 사가 (event_form=saga)
일정이 계속 바뀌는 장기 사업(캐나다 잠수함, 폴란드 오르카 등)은 단일 날짜가 아니라 **마일스톤 타임라인**으로 추적.
- 기존 `wiki/L5_섹터/테마이벤트/` 구조 확장 (테마·발동일·소멸예상 필드 이미 존재)
- 상태: `현재 단계` + `다음 예상 촉매(D-N or 미정)` + `수혜 종목` + 마일스톤 배열 `[[라벨, done|next|""], ...]`
- 매일 크롤에서 새 언급 감지 시 현재 단계·다음 촉매 갱신

### 4.5 해외·정책 주체 + 교차연결
- `entity_scope=foreign`: 마이크론·인텔·TSMC·엔비디아·캐나다 국방부 등 = "트리거 주체". 이들의 이벤트가 국내 종목 촉매(예: 마이크론 실적 → 하이닉스 선행지표)
- `entity_scope=policy`: 금통위·FOMC·수출규제 시한 등
- **교차연결:** 이벤트 1개 → `affected_stocks` 여러 개. 위키 **밸류체인 이미 매핑됨**(캐나다 잠수함 → 한화오션·HD현대) → 이를 참조해 매핑

### 4.6 일일 루프 (투경 패턴 복제)
투경 시스템(`관리목록 JSON + 유형별 예측 + 매일 크롤/검증/백테스트 + 텔레 푸시 + 위키 페이지`)을 이벤트용으로 일반화.
1. `pipeline/atoms/calendar_ingest.py` — `raw/캘린더/*.json` + catalyst 원자 → 이벤트 원자(event_date·structured_fields) 적재
2. `pipeline/atoms/calendar_build.py` — `event_date>=오늘` 원자 조회 → D-N 투영 → 위키 보드 + 종목별 롤업 생성
3. 텔레 푸시: "오늘 기준 이번 주 내 종목 촉매 N건"

### 4.7 위키 구조
- **신규:** `wiki/이벤트캘린더/캘린더_index.md` — D-정렬 보드 (날짜|D-N|종목·섹터|이벤트|종류|확정도|방향) + `사가_{테마}.md` 개별 타임라인
- **기존 활용:** L6 종목페이지 "📅 일정 (D-30)" 섹션을 이 인덱스에서 자동 채움 (단일 진실원천)

### 4.8 접근 모델 (UI 노출)
- **① 자동 노출(주력):** 인사이트 홈 "📅 다가오는 촉매" 섹션 상시 + 시그널 카드 D-배지 + 아침 텔레 푸시
- **② 브라우즈:** 캘린더 뷰 (섹터/날짜/D-N 정렬)
- **③ 검색·브리핑(보조):** "조선 캐나다 잠수함 현황" 딥다이브
- **개인화:** "내 종목" watchlist(투경 관리목록 패턴) → 그 종목 촉매만 상단 고정. watchlist 변경 시 촉매 즉시 재정렬

## 6. 신규 구현 항목 (빌드 리스트)

**Track B (backend):**
1. DB 마이그레이션: `event_date` 컬럼 + 인덱스 (`pipeline/atoms/db.py`)
2. `calendar_ingest.py`: `raw/캘린더/*.json` + catalyst 원자 → 이벤트 원자 적재 (entity_scope/event_form/confidence 부여)
3. 확정도 매핑: `event_merge` mention_count → confidence 1~4
4. `calendar_build.py`: 미래 이벤트 조회 → D-N 투영 → 위키 보드/롤업 + 텔레 푸시 (투경 루프 복제)
5. 사가 추적: 테마이벤트 확장 스키마 + 갱신 로직
6. 신규 크롤(락업/옵션/배당락) — *데이터 소스 확정 필요(공개질문)*
7. server.py 엔드포인트: `/api/catalysts?watchlist=&sector=&days=` (UI 공급)
8. watchlist 상태: `pipeline/watchlist.json` (투경 관리목록 패턴)

**Track A (frontend):**
9. `insights.html` 디자인 토큰 라이트 테마 교체
10. 컴포넌트: 브리핑 바·스코프·소스 라이브러리(타입별 아코디언)·시그널 카드(스파크라인+D배지)
11. 촉매 섹션 + watchlist UI (v6 이식) → `/api/catalysts` 바인딩
12. 브랜드 SVG 아이콘 세트, 국기 라벨칩

## 7. 구현 순서 (제안)

- **Phase 0 — 데이터 파이프 연결(핵심):** ①②③ + `fetch_sector_calendar` 재가동 → 이벤트 원자가 매일 쌓이기 시작 (UI 없이도 위키 보드 생성 검증)
- **Phase 1 — 투영·노출:** ④⑦⑧ + ⑨⑩ (라이트 UI 이식) → 캘린더 API + 인사이트 페이지
- **Phase 2 — 촉매 섹션·개인화:** ⑪ watchlist·촉매 섹션·D배지
- **Phase 3 — 심화:** ⑤ 사가 추적, ⑥ 락업/옵션/배당락, 텔레 푸시 자동화

각 Phase 끝에 **검증 게이트**: 실제 데이터로 위키 보드/화면 구동 확인 (fablize 그라운딩).

## 8. 공개 질문 / 결정 필요

1. **락업해제·옵션만기·배당락 데이터 소스** — KRX 공개 데이터? 공시(DART)? 별도 크롤? (Phase 3)
2. **event_date 파싱 신뢰도** — "다음 달쯤" 같은 애매 표현 → confidence=4로 흡수 vs 제외
3. **사가 마일스톤 갱신** — 자동 감지 vs 반자동(주 1회 확인)
4. **텔레 푸시 시점·대상** — 아침 몇 시? 전체 vs watchlist만?
5. **국기 표기** — SVG 국기 vs 국가 라벨칩(`🇺🇸`→`美`/`US`)

## 9. 성공 기준

- 매일 자동으로 이벤트 원자가 쌓이고, 위키 `이벤트캘린더/` 보드가 D-정렬로 갱신됨
- 인사이트 페이지를 열면 **검색 없이** 내 종목의 다가오는 촉매가 D-정렬로 보임
- 국내·해외·정책·사가가 종목에 연결되어, 증권사 캘린더에 없는 "캐나다 잠수함 D-45" 같은 항목이 실제로 표시됨
- 확정도로 확정 일정과 예상 트리거가 시각적으로 구분됨
