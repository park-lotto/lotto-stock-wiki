# 쓰레드(Threads) 수집 축 — 설계

- 작성일: 2026-08-17
- 트랙: `쓰레드수집`
- 상태: 설계 승인 대기

---

## 1. 왜 하는가

숏템메이커의 다음 버전. 쓰레드 한 게시물 안에 **우리가 지금 세 군데서 따로 긁는 재료가 한 세트로** 들어있다.

| 재료 | 지금 | 쓰레드 |
|---|---|---|
| 화면(영상) | 인스타·틱톡·도우인에서 수집, 구운자막 제거가 골칫거리 | 무음소거·구운자막 없는 원본이 대부분 |
| 한국어 말맛 | 인스타 축 하나에서만 나옴(중국 소스는 중국어) | 캡션이 곧 말맛 ("나 지금까지 헛고생함") |
| 제품 특정 | 소스에서 못 찾아 헤맴 | 이어진 글(2/2)에 쿠팡파트너스 링크 |

카테고리도 홈템으로 정확히 겹친다(실측 표본: 식세기·샤워기·행거·발마사지·버터·토스트).

## 2. 실측으로 확정된 사실 (2026-08-17, 브라우저)

**이 절은 추정이 아니라 관측이다. 코드 판단의 근거는 여기다.**

| 항목 | 결과 | 근거 |
|---|---|---|
| 로그인 | **불필요** (2026-08-17 정정) | 브라우저 헤더(UA + `Accept` + `Accept-Language` + `Sec-Fetch-*`)를 갖춘 익명 GET이 200 / 1,080,480바이트 / `like_count` 18 · `video_versions` 19 · `link.coupang.com` 26 |
| SSR 데이터 | **있다** (2026-08-17 정정) | 위와 같음. 게시물 데이터가 HTML 안 Relay 페이로드(`__bbox`, `thread_items`)에 인라인으로 들어온다 |
| 엔드포인트 | **필요 없음** — 프로필 URL을 그냥 GET 한다 | 로그인 세션이 있으면 SPA가 `POST /api/graphql`로 받아오지만, 로그아웃 뷰는 첫 HTML에 다 실어준다 |
| 영상 파일 | **통짜 mp4 — 인스타보다 쉽다** | `content-type: video/mp4`, 매직 `ftypisom`, Range 요청에 206. **blob/MSE 아님** |
| 영상 도달 경로 | **`/@{계정}/post/{코드}/media`** | 이 URL로 들어가면 `<video>`가 뜬다. 클릭 흉내 불필요 |
| CDN | `scontent-*.cdninstagram.com` — **인스타와 동일** | 우리 `/api/video` 허용호스트·Referer 처리 그대로 재사용 |
| 캡션+쿠팡링크 | **한 번에 옴** | 프로필 1회 로드에 `link.coupang.com` 18건. 본문(1/2)과 이어진 글(2/2)이 같은 목록에 |
| yt-dlp | **못 씀** | `threads extractor: NONE`, generic 폴백도 `Unsupported URL` |
| 인페이지 JS 후킹 | **안 걸림** | 메타 코드가 부팅 시 원본 `fetch`/`XHR`을 선점. **Playwright 레벨 후킹이 맞다**(우리 인스타 코드가 그런 이유) |

### 표본 지표 (문턱 설계의 근거)

관측된 실제 값: 좋아요 4 / 9 / 15 / 1.3천, 조회 5,013회(상세에서만 노출).
**인스타 문턱(댓글 1천~1만+)을 그대로 대면 전량 탈락한다.** §5 참고.

## 3. 핵심 설계 원칙 — 새로 짜지 않는다

0순위-B(같은 판단 두 곳 금지)에 따라, **이미 있는 계약에 얹는다.**

| 필요한 것 | 새로 만들까 | 결론 |
|---|---|---|
| 씨앗(계정·키워드) 저장 | ❌ | `platform_seeds(platform, kind, value)` 재사용 — 이미 샤홍·인스타 블랙리스트가 쓰는 일반 표 |
| 증가분(delta) 계산 | ❌ | `platform_snapshots(platform, run_date, shortcode, base, delta)` 재사용 |
| 랭킹 아이템 변환 | ❌ | **`ranking.build_overseas_items`** 재사용. 이건 "조회수를 안 주는 플랫폼은 참여(좋아요+댓글+수집+공유)로 통일"하는 일반 계약이고, 쓰레드가 정확히 그 모양이다 |
| 담기 라우팅 | ❌ | `_GRAB_DOMAINS`에 한 줄 추가 |
| 영상 프록시 | ❌ | CDN이 인스타와 같아 `/api/video` 그대로 |
| **게시물 저장** | ⭕ | **여기만 새로 만든다** (아래) |

### 저장을 새로 만드는 이유

`channel_archive`·`reel_history`는 **인스타 전용**이다(플랫폼 컬럼 없이 `PK=shortcode` 또는 `(username, shortcode)`). 여기에 쓰레드를 섞으면:

- 20만 행에 의미 없는 빈 컬럼이 생기고,
- `hits_since`는 `platform` 인자를 받지만 **SQL에서 쓰지 않는다**(store.py:2187, 실측). 즉 지금 섞으면 인스타 랭킹에 쓰레드가 조용히 흘러든다.

→ **`threads_posts` 신설.** 인스타 표는 손대지 않는다.

```sql
CREATE TABLE IF NOT EXISTS threads_posts (
    code TEXT PRIMARY KEY,        -- DcIknZjEQVW
    username TEXT NOT NULL,
    caption TEXT,                 -- 본문 = 말맛 재료
    tail_caption TEXT,            -- 이어진 글(2/2) = 쿠팡링크가 붙는 자리
    coupang_url TEXT,
    media_kind TEXT,              -- video | image | mixed
    video_url TEXT,               -- mp4 직링크(만료됨 — §6)
    thumb TEXT,
    likes INTEGER, comments INTEGER, reposts INTEGER, shares INTEGER,
    views INTEGER,                -- 상세에서만 나옴. 없으면 0
    posted_at TEXT,
    first_seen TEXT, last_seen TEXT,
    quality INTEGER DEFAULT 0,    -- §5 재료 점수
    source TEXT                   -- account | keyword:<말>
);
CREATE INDEX IF NOT EXISTS idx_threads_quality ON threads_posts(quality DESC, first_seen DESC);
```

## 4. 구성 요소

### 4-1. `threads_playwright.py` (신설)

인스타 모듈과 **같은 뼈대**: 브라우저를 띄우고 GraphQL 응답을 가로챈다.

- 세션·프록시는 **짝으로** 정한다 — `_discover_session_proxy()` 패턴 그대로.
  (계정↔IP를 따로 정하면 어긋나 챌린지가 뜬다. 2026-08-09 실사고)
- 두 진입:
  - `collect_account(username)` → `https://www.threads.com/@{username}`
  - `search_keyword(word)` → 검색 진입(경로는 구현 시 실측 확정)
- 영상은 목록에서 안 나온다(실측: 프로필의 `<video>` 0개). **`/post/{code}/media`로 한 번 더 들어가 mp4를 회수**한다.

### 4-2. 이어진 글 묶기

쓰레드는 한 사람의 연속 글이 1/2, 2/2로 나뉘고 **쿠팡링크는 2/2에 있다.** 같은 계정의 인접 글을 묶어 `tail_caption`·`coupang_url`로 접는다. 묶는 판단은 **한 곳(`threads_parse.py`)에서만** 한다.

### 4-3. 랭킹 탭 · 담기

- 랭킹: `build_overseas_items`에 태워 `platform="threads"` 뱃지로 노출.
- 담기: `_GRAB_DOMAINS`에 `("threads", ("threads.com", "threads.net"))` 추가.
- 캐시 키: **`grab_threads_{code}`** — 접두사를 반드시 붙인다.
  (틱톡에서 `lens_tiktok_` 접두사 불일치로 태깅 캐시가 통째로 불발한 전례가 있다)

## 5. 재료 품질 판정 (사장님 확정: 지표가 아니라 재료로 가른다)

`quality` 점수 = 아래 합. 지표는 **동점일 때 순서만** 가른다.

| 조건 | 점수 | 왜 |
|---|---|---|
| 영상이 붙어 있다 | +3 | 없으면 화면 재료가 안 된다 |
| 쿠팡링크가 있다 | +2 | 제품이 특정되고, 이미 "파는 글"로 검증됨 |
| 캡션 40자 이상 | +2 | 말맛 재료가 되는 최소 길이 |
| 구운자막이 없다 | +1 | 기존 `thumb_text_level` 재사용 |
| 세로 영상 | +1 | 숏폼 재단 손실 없음 |

**하드 차단은 두지 않는다.** 0점도 저장하되 뒤로 민다(하드 차단이 재사용 폴백보다 나쁘다는 전례).

**문턱은 지금 정하지 않는다.** 200~300건 모은 뒤 분위수로 정한다 — 표본 4건으로 정하면 틀린다.

## 6. 함정 (미리 박아둔다)

1. **mp4 URL은 만료된다.** `video_url`을 영구 주소로 믿지 마라. 담을 때 그 자리에서 받거나, 만료 시 `/post/{code}/media`로 재회수하는 폴백을 둔다(인스타 썸네일 oembed 복구와 같은 방식).
2. **인페이지 JS 후킹으로 검증하지 마라** — 메타가 원본 XHR을 선점해 안 걸린다. 반드시 Playwright 레벨.
3. **`hits_since`의 `platform` 인자는 지금 SQL에서 안 쓰인다.** 쓰레드를 여기 태우려면 그 인자를 실제로 쓰게 고치거나(인스타 회귀 위험) 별도 경로로 간다. **별도 경로를 택한다.**
4. **문자열 검사로 성패를 판정하지 마라.** "데이터가 실제로 나왔는가(건수)"로 판정한다.
5. **타입 확인 전 `.strip()` 금지.** 캡션·이어진 글은 dict/None으로 올 수 있다.

## 7. 범위 밖 (지금 안 한다)

- 조회수 수집 — 상세를 한 번 더 열어야 해서 느리다. 필요해지면 그때.
- 쓰레드 자동 업로드 — 공식 API는 publishing 전용이라 가능하지만 별건.
- 내 피드(추천란) 수집 — 재현·누락 관리가 어렵다.

## 8. 검증 방법

- 계정 3개 × 키워드 3개로 1회 수집 → **건수·실패율·소요시간 실측표**.
- 그중 영상 있는 것 5건을 실제로 받아 **재생 확인**(무음·구운자막 유무 육안).
- 담기 1건을 제작소까지 태워 **대본 재료로 실제 쓰이는지** 종단 확인.
