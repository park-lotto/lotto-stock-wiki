# 장면꾸미기 자막 구절별 위치

- 제보: `이 자막만`을 선택해 화면에 보이는 자막을 끌었는데, 같은 자막 비트의 다른 구절까지 함께 움직였다.
- 실측: 라이브 작업 `667ffd60408e`에서 3번 장면 첫 구절을 `(47%, 52%) → (68%, 37%)`로 옮기자 같은 비트의 4번 장면 구절도 이동했고, 다음 비트인 5번 장면은 그대로였다. 확인 뒤 원래 좌표로 복구했다.
- 원인: 저장 모델이 비트당 `cap_xy` 하나뿐이었다. 한 비트가 여러 자막 구절·컷으로 나뉘어도 전부 같은 좌표를 읽었다.
- 수정: `cap_xy_segs`에 구절 번호별 좌표를 저장한다. 화면은 드래그 시작 순간의 비트와 구절 번호를 고정하고, API·미리보기·최종 FFmpeg 자막 렌더가 같은 값을 사용한다.
- 호환: 기존 `cap_xy` 요청과 데이터는 계속 비트 전체 좌표로 동작한다. 우선순위는 `cap_xy_segs[현재 구절] > cap_xy > cap_pos > 전체 설정`이다.
- 정리: 위/중간/아래 버튼은 해당 자막 묶음 전체 설정이므로 구절별 좌표를 지운다. `모든 장면` 적용도 비트·구절별 덮어쓰기를 전부 지운다.
- 검증: 핵심 회귀 23개 + 화면 JS 문법·초기화 8개 통과. 전체 테스트는 7,420개 통과, 기존 환경·데이터 의존 실패 후보 14개이며 `track.py finish`의 main 기준선 비교로 신규 실패 여부를 최종 판정한다.
- 게이트·배포: 기준선 실패 13개와 동일하여 신규 실패 없이 `main` 병합. 낮 시간창 제한 때문에 서버에서 `git pull --ff-only origin main` 후 `shopping-shorts`만 재시작했고, `active`, HEAD `7abd5c14d` 확인.
- 라이브 실증: 작업 `667ffd60408e`의 4번째 구절 `기차 케이크임`만 `(47%,52%) → (84%,60%)`로 이동했을 때 같은 비트의 3번째 구절 `개떡상한 움직이는`은 `(47%,52%)` 유지. 테스트 구절·적용 범위·장면을 원래 상태로 복구했다.
