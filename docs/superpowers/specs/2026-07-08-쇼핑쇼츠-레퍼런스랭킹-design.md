# 쇼핑쇼츠 자동화 — 레퍼런스 랭킹 (기능 ①) 설계

날짜: 2026-07-08
상태: 설계 확정 대기

---

## 1. 목적 (What & Why)

정리해둔 인스타 레퍼런스 채널(443개)의 **최신 릴스를 매일 훑어서, 실제로 "터진" 영상만
댓글수 랭킹으로 뽑아주는** 도구. 목적은 **바로 벤치마킹할 쇼핑쇼츠 소재 발굴**.

- 소스: `벤치마킹시트 신규.xlsx` (채널명 / 인스타주소 / 팔로워 / 인포크링크, 443행)
- 큰 그림: 이 레퍼런스 랭킹은 전체 "쇼핑쇼츠 자동화 프로그램"의 **첫 번째 기능**.
  이후 소통보조(기능 ②) 등이 같은 웹앱에 메뉴로 추가됨. (이 스펙 범위는 기능 ①만.)

### 참고: 벤치마킹 대상 UI (shopping.tubefactory.kr — 타인 제작, 코드 접근 불가)
다크 테마 / 좌측 사이드바(트렌드 리서치·채널&콘텐츠·내 도구 그룹) / 상단 헤더(포인트·프로필) /
메인 영역(제목+설명 → 탭 → 필터 → 결과). **이 레이아웃을 복제한 내 전용 웹앱을 새로 만든다.**

## 2. 핵심 규칙 (확정된 필터·정렬)

| 항목 | 값 | 근거 |
|------|-----|------|
| 시간 창 | **48시간 이내** | 24h는 댓글 쌓일 시간 부족 → 터졌는지 판별 불가. 48h면 검증됨 |
| 댓글 하한 | **없음 (전부 랭킹)** | 500 이하도 포함. 하한으로 자르지 않고 랭킹·강도로 판단 |
| 채널당 상한 | **최신 3개** | 하루 1~3개 업로드 채널 커버. 안전장치 |
| 중복 처리 | **유지 + 어제 대비 증가량(Δ) 표시** | 신규 발굴 + 떡상 감지 동시 |

**중복 = 낭비가 아니라 신호**: 같은 영상이 이틀 연속 잡히면 댓글 증가량(Δ)으로 "지금 떡상 중"을 감지.
매일 수집분을 DB에 저장하고 어제치와 비교.

### 2-1. 강도 지표 & 랭킹 탭 (관점별 4개 탭)

같은 48시간 수집 데이터를 **4가지 관점으로 정렬**해서 탭으로 전환하며 본다.
댓글 하한이 없으므로 "얼마나 많나"뿐 아니라 "얼마나 빠르게/폭발적으로 크나"를 지표화한다.

| 탭 | 정렬 기준 | 의미 | 작동 시점 |
|----|----------|------|----------|
| **📊 전체** | 댓글수 내림차순 | 절대 반응량 (500 이하 포함 전부) | 첫날부터 |
| **⚡ 속도** | 댓글수 ÷ 업로드 후 경과시간 | 시간당 댓글 유입 = 지금 막 터지는 중 | 첫날부터 |
| **📈 가속** | 오늘 Δ − 어제 Δ (증가폭의 변화) | 어제보다 더 빨라졌나 = 계속 커지는 중 | 이틀째부터 (첫날 "수집 중") |
| **💥 참여밀도** | 댓글수 ÷ 팔로워 (엑셀 팔로워값) | 팔로워 대비 반응 = 콘텐츠 자체 힘 | 첫날부터 |

**강도 등급 뱃지**: 각 항목에 위 지표를 종합한 등급 표시
`🔥🔥🔥 폭발 / 🔥🔥 급상승 / 🔥 상승 / — 평범`.
등급 산정은 속도·가속·참여밀도를 정규화해 합산(가중치는 구현 시 튜닝, 기본 균등).
등급으로도 필터 가능(예: 🔥🔥 이상만 보기).

## 3. 데이터 수집 (Apify)

- **스크래퍼**: Apify `apify/instagram-reel-scraper` (또는 동급 저가 스크래퍼)
- **과금**: 긁은 건수당 (~$0.0005/건). Apify 무료 크레딧 $5/월로 시작.
- **입력**:
  - `username`: 443개 채널 URL 배열 (엑셀에서 로드)
  - `onlyPostsNewerThan: "2 days"` — 48h 창 + 여유. **오래된 것 안 긁어 비용 절약**
  - `resultsLimit` (채널당): 3
  - `skipPinnedPosts: true`
- **검증된 출력 필드** (2026-07-08 WebFetch 확인):
  `commentsCount`, `likesCount`, `videoViewCount`, `videoPlayCount`, `timestamp`,
  `videoUrl`, `displayUrl`(썸네일), `caption`, `sharesCount`, `videoDuration`
- **예상 비용**: 443채널 × 실제 업로드분(창 안 몇 건)만 과금.
  최악(채널당 3건 다) = 1,329건 × $0.0005 ≈ **$0.66/회**. 실제로는 창 안 영상만이라 그 이하.
  무료 크레딧으로 **최소 7~15회/월** 가능.

## 4. 아키텍처 (로컬 웹앱)

너 혼자 쓰는 **로컬 웹앱** (localhost). 서버 배포 없음. 수집은 **수동 버튼 트리거**.

```
┌─────────────────────────────────────────────────────────┐
│  브라우저 (localhost)  —  다크 사이드바 레이아웃 복제        │
│  사이드바 > "레퍼런스 랭킹" 메뉴                             │
│   ├ [지금 수집] 버튼                                        │
│   ├ 탭(전체·속도·가속·참여밀도) + 카테고리 필터             │
│   ├ 랭킹 카드/테이블 (썸네일·채널·댓글수·Δ·강도🔥·링크·인포크)│
│   └ 강도등급 필터 (🔥🔥 이상만 등)                          │
└───────────────┬─────────────────────────────────────────┘
                │ (수집 버튼 → 백엔드 호출)
┌───────────────▼─────────────────────────────────────────┐
│  로컬 백엔드 (Python)                                      │
│   1. 엑셀 로드 → 443 채널 usernames + 팔로워·인포크링크     │
│   2. Apify Reel Scraper 호출 (48h·상한3·pinned제외)         │
│   3. 필터: timestamp ≤ 48h (댓글 하한 없음, 전부 유지)      │
│   4. DB 저장 + 어제분 대조 → Δ·속도·가속·참여밀도·강도등급   │
│   5. 4개 정렬본(전체/속도/가속/밀도) 웹앱에 반환            │
│   6. 수집분을 날짜별 CSV로 export (아카이브)                │
└───────────────┬─────────────────────────────────────────┘
                │
        ┌───────▼───────┐   ┌──────────────────────────┐
        │  로컬 DB       │   │ data/rankings/날짜.csv     │
        │ (수집 이력·Δ)  │   │ (날짜별 랭킹 아카이브)     │
        └───────────────┘   └──────────────────────────┘

> **엑셀 누적 방식 변경**: 소스 엑셀(`벤치마킹시트 신규.xlsx`)에 직접 쓰면 원본 손상 위험이
> 있어, 수집 결과는 **별도 CSV**(`data/rankings/YYYY-MM-DD.csv`)로 아카이브한다. 소스 엑셀은
> 읽기 전용. 이력·Δ는 SQLite가 담당.
```

### 구성 요소 (각 하나의 책임)
1. **채널 로더** — 엑셀 읽어 유효한 인스타 username 배열 반환. (URL 정규화·중복 제거)
2. **Apify 클라이언트** — 스크래퍼 호출, 결과 원본 반환. (API 키·재시도·에러 처리)
3. **필터/랭킹 엔진** — 48h 필터(댓글 하한 없음), 어제분 대조로 Δ·속도·가속·참여밀도·강도등급
   계산, 4가지 정렬본 생성, 카테고리·강도 필터 적용.
4. **저장소** — 로컬 DB(수집 이력) + 엑셀 누적 기록.
5. **웹앱 (프론트)** — 다크 레이아웃, 수집 버튼, 4개 탭·카테고리 필터, 랭킹 표시.

## 5. 결과 화면

### 5-1. 랭킹 항목 컬럼

| 컬럼 | 소스 |
|------|------|
| 순위 | 활성 탭 정렬 결과 |
| 썸네일 | `displayUrl` |
| 채널명 | 엑셀 매칭 |
| 댓글수 | `commentsCount` |
| Δ (어제 대비) | DB 대조 → 예: `+800` (신규는 "신규") |
| 강도 | 종합 등급 뱃지 `🔥🔥🔥/🔥🔥/🔥/—` |
| 좋아요 | `likesCount` |
| 조회수 | `videoViewCount` / `videoPlayCount` |
| 업로드 | `timestamp` (상대시간 "N시간 전") |
| 카테고리 | 채널 카테고리 (§5-3) |
| 게시물 링크 | URL (클릭 시 인스타로) |
| **인포크링크** | 엑셀 `인포크링크` — 그 채널 판매채널 바로가기 |

> **인포크링크 이유**: 채널이 뭘 파는지 즉시 확인 → "이 영상은 이 제품으로 터졌다"
> 소재-제품 연결. 조회수뿐 아니라 **실제 커머스로 연결한 레퍼런스**만 골라보기 쉬움.

### 5-2. 랭킹 탭 (§2-1 지표 4개)

`📊 전체` · `⚡ 속도` · `📈 가속` · `💥 참여밀도` — 탭 전환 시 같은 데이터가 해당 기준으로 재정렬.

### 5-3. 카테고리 필터

엑셀에 카테고리 컬럼이 **아직 없다.** 다음 순서로 도입:
1. **자동 태깅(1차)**: 채널명 + 캡션 키워드로 카테고리 자동 분류
   (예: 인테리어/셀프DIY, 레시피/맛집, 생활용품/살림템, 가전, 뷰티, 기타).
   규칙 기반 매핑 테이블 사용, 미매칭은 `기타`.
2. **수동 보정(선택)**: 자동 분류가 틀린 채널은 엑셀에 `카테고리` 컬럼 추가해 덮어쓰기 가능.
3. 화면 상단에서 카테고리 멀티선택 필터 → 각 탭 랭킹에 함께 적용.

> 카테고리 목록·키워드 매핑은 사용자가 나중에 확정(지금 미정). 초기엔 위 6분류로 시작.

## 6. 에러 처리

- 엑셀 없음/형식 오류 → 명확한 메시지, 중단.
- Apify 크레딧 소진/API 실패 → 부분 결과라도 저장 + 경고 표시. 재시도 1회.
- 채널 비공개/삭제/0건 → 스킵하고 로그, 전체 중단 안 함.
- 어제 DB 없음(첫 실행) → Δ는 "신규" 표기.

## 7. 범위 밖 (YAGNI — 이번엔 안 함)

- ❌ 자동 스케줄 수집 (지금은 수동 버튼. 잘 돌면 후속에 Task Scheduler)
- ❌ 서버 배포/멀티유저
- ❌ 소통보조(기능 ②) — 자동 댓글·좋아요·팔로우. 별도 스펙.
- ❌ TikTok·유튜브 소스 — 인스타 먼저
- ❌ 카테고리 수동 대량 라벨링 UI — 초기엔 자동 태깅 + 엑셀 덮어쓰기로 충분
