# 컨셉 스튜디오 — 설계 (2026-10-15, 관제 213, 트랙 `컨셉스튜디오`)

## 0. 사장님 확정 사항
- 숏템메이커 안의 새 페이지 + 별도 상품. 컨셉(정치·연예인·뷰티·픽션 썰…)은 **우리가 프리셋으로 세팅**해 계속 늘린다.
- 고객은 웹 스튜디오에서 **컨셉 고르기 + 내 팩 저장**. 사람 확인은 **대본 1회**뿐.
- 실행 방식 두 가지:
  - **Claude형** — 고객 Claude 데스크톱 + 설치팩. 렌더·AI 전부 고객 PC/고객 구독. 우리 서버는 설정·지시만.
  - **버텍스형** — 우리 서버 렌더 + **고객 제미니 키**. 우리는 **서버비 편당 1,000원**만 받는다.
- TTS·이미지 검색 키는 **키 등록 페이지**에서 고객이 넣는다.
- 칼카피(채널 분석 → 프리셋 한 장)는 다른 창(트랙 `칼카피숏템엔진`, 관제 097). 두 창은 **프리셋 한 장**으로만 만난다.

## 2. 전체 구조
```
[웹: 컨셉 스튜디오]  컨셉 진열 · 내 팩 · 키 등록 · 작업 목록
        │  (서버 = 설정 보관 + 단계 지시 + 버텍스형 렌더)
        ├─────────────── Claude형 ────────────────┐
        │  고객 Claude 데스크톱 + 설치팩(.mcpb)       │
        │  "스튜디오 설정대로 정치 한 편"              │
        │  설치팩 = 지휘 도구(MCP) + 실행기(렌더)      │
        │  대본 = 고객 Claude, 렌더 = 고객 PC         │
        │                                          │
        └─────────────── 버텍스형 ─────────────────┘
           웹 [만들기] → 우리 서버 대기열 → 렌더
           대본·판정 = 고객 제미니 키, 서버비 1,000원 차감
```

## 3. 판단의 주인 (0순위-C — 한 판단 = 한 함수)
| 판단 | 주인 | 부르는 곳 |
|---|---|---|
| 컨셉 정의 읽기·검증 | `shopping_shorts/concept_studio.py:load_concept` | 웹·MCP·서버 렌더·설치팩 |
| 고객 설정 합치기 (컨셉 기본값 ⊕ 내 팩) | `concept_studio.resolve_settings` | 같음 |
| 다음 단계 결정 | `concept_studio.next_step` | MCP 지시·서버 대기열 둘 다 |
| 대본 검사 (반려 기준) | 컨셉 프리셋의 검사 규칙 → `concept_studio.check_script` | 두 방식 |
| 완성본 검사 (내용 관문) | `channelkit/review.content_gate` 재사용 | 두 방식 |
| 편당 1,000원 차감·환불 | `concept_studio.charge_render` (버텍스형만) | 서버 대기열 |
| 고객 키 보관·조회 | `concept_studio.customer_keys` (암호화, 끝 4자만 표시) | 서버 렌더·설치팩 내려받기 |

★ Claude형과 버텍스형이 **같은 함수를 부른다.** 다른 것은 "대본을 누가 쓰나 / 렌더를 어디서 하나" 두 가지뿐.

## 4. 컨셉 프리셋 한 장 (칼카피 창이 채우는 형식)
```
concept_presets/<이름>/concept.json
  id, 이름, 설명, 견본영상, 공개여부, 상품(구매자만)
  source_kind: product_url | person | news_url
  steps: [seed, script, confirm_script, footage, voice, decorate, render, review]
  script: {writer: claude|gemini, rules: [...], length, 말투}
  footage: {where: shopping|broadcast|news_image, 검사: {...}}
  defaults: {frame, headcopy, caption, voices{나레,배역…}, sfx_pack, meme_pack, bgm}
  customer_can_change: [frame, headcopy, caption, voices, sfx_pack, meme_pack, bgm]
  review: {content_gate 기준 숫자}
  keys_needed: [typecast, naver_hub_id, …]
```
1호 = 픽션 썰(제품 링크형), 2호 = 뜨거운사람들(인물형). 칼카피 창은 이 형식으로 프리셋을 넘긴다.

## 5. 사람 확인 자리
- **대본 확정 1회** (두 방식 공통, `confirm_script` 단계에서 멈춤)
- 자동 검사 실패 → 사람 대신 **멈춤** + 이유 표시 (완성본 안 만듦)

## 6. 결과물 검사 (이 기능과 같은 커밋에 들어간다)
| 무엇 | 어떻게 |
|---|---|
| Claude형 | 이 PC Claude 데스크톱에 `.mcpb` 설치 → "설정대로 한 편" → 고객 PC 폴더에 mp4 생성, ffprobe 길이·해상도, 프레임 시트로 팩(틀·자막) 반영 확인 |
| 버텍스형 | 관리자 계정으로 웹 [만들기] → 완성본 mp4 + 고객 키 사용 기록(`gemini_usage.auth=customer`) + 1,000원 차감 행 |
| 같은 설정 = 같은 결과 | 같은 컨셉·팩으로 두 방식을 돌려 틀·자막·목소리가 같은지 프레임 대조 |

| P6 | 상품 분리·고객 공개 | **사장님 승인** | |

## 8. 위험·미확인
- `.mcpb` 실행기에서 ffmpeg 같은 무거운 바이너리를 묶는 크기·백신 경고 — P0에서 잰다.
- Claude 데스크톱 MCP 도구 호출 시간 제한 — 렌더(수 분)는 백그라운드로 돌리고 상태 조회 도구로 나눈다(볼케이노의 run/status/deliver 와 같은 꼴).
- 고객 Claude 사용량 한도 — 대본 단계에 몇 번 호출하는지 재서 컨셉 설명에 적는다.
- 정치·연예인 방송 영상 저작권 — 상품 공개 전 정리.
- 실행기 코드는 고객 PC에 남는다 → 컨셉 규칙은 서버 `next_step`이 단계마다 내려준다.
- 서버 월 요금은 미확인 → 손익분기 = 월 서버비 ÷ 1,000원.
