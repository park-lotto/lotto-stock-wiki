## 1. 무엇을 고치나

**증상**: 대본 품질이 복불복이다. 잘 나오는 날과 안 나오는 날이 있는데 왜 갈리는지 모른다.

**원인**(2026-08-15 코드 실측 — 추측 아님):

| # | 사실 | 근거 |
|---|---|---|
| ① | 규칙이 전부 **부탁**이고, 지켜졌는지 **검사하는 코드가 0** | `script_generate._STORY_RULES_CORE`에 CTA·어미·고조 규칙이 상세히 있으나 출력 검증 없음 |
| ② | **구조를 AI가 정한다** — 칸을 코드가 안 박는다 | `_MIX_PROMPT`는 "좋은 부분만 골라 하나의 이야기로 녹여라"까지만 지시 |
| ③ | 성공 문장을 **일부러 못 넣게** 막아 뒀다 | `script_engine._bank_block` = "뼈대가 아니라 감각 참고", "그대로 베끼면 반려된다" (2026-07-26 드리프트 사고의 흉터) |
| ④ | **말 밀도가 히트작의 1/3**인데 아무 경고가 없다 | 프롬프트 기준 4.5자/초 → 30초 135자 / 채이홈 히트작 실측 **264~377자** |
| ⑤ | 같은 프롬프트를 n번 굴려 운 좋은 걸 고른다 | `app.py:7415` `generate_mix(..., n=body.get("n") or 3)` |

**핵심**: 지시는 훌륭했다. **지켜졌는지 아무도 안 봤다.** 그래서 실패를 실패로 알 수조차 없었다.

## 3. 설계 — 4개 조각

### 3-1. 스타일 = 지금의 `spine` + 3개 컬럼

`spine`에 이번에 필요한 것만 더한다(마이그레이션 3줄):

```
beat_roles_json   TEXT   -- ["hook","before","reveal","after","cta"] — 게이트가 대조할 칸 이름
templates_json    TEXT   -- {"hook":["이것 때문에 {가족}한테 욕 바가지로 먹을 뻔했어요", …]}
chars_per_30s     INTEGER-- 이 스타일 히트작의 실측 말 밀도(채이홈 시월드형 = 300)
```

기존 `beat_chain_json`은 사람이 읽는 설명, 새 `beat_roles_json`은 **기계가 대조하는 키**다.
둘을 합치지 않는 이유: 기존 31행이 이미 자연어 문장이라 파싱하면 깨진다.

`perf_score`는 이미 있으나 **전부 0**이다 → 3-4에서 채운다.

### 3-2. 스타일 추출 (채널 분석 → spine 행)

```
채널 선정(기준 3개)          → 100만+ 반복히트 · 최근 생존 · 초창기 데이터 보유
  ↓ 메타(비용 0)
변곡점 판정                  → 중앙 조회수가 계단식으로 뛴 지점 앞뒤
  ↓ 선별 25~30편
전사(편당 67초 실측)          → media_download → script_extract (기존 경로 재사용)
  ↓ 제미니 1회
스타일 추출                  → {name, beat_roles, templates, chars_per_30s, fit_categories}
  ↓
spine INSERT (status='pending') → 사람이 승인해야 노출
```

- 채널 1개 = **34분 · 프록시 200MB · 제미니 31회**(실측 기반).
- 채널 1개당 스타일 1~3개. `source_count`는 그 스타일을 뒷받침한 영상 수.
- **승인 게이트 유지**: `status='pending'` → 사장님이 보고 승인. 자동 노출 금지.

### 3-3. 생성 — 고르고, 박고, 검사한다

**UI**(제작소 대본 단계):

```
스타일 ①  [시월드형 ▼]   (chae2home · 631만·347만·294만)
스타일 ②  [실패담형 ▼]   (실적 없음 · 가설)
        ↓  n=2
A안(시월드형)   B안(실패담형)   ← 구조가 서로 다름이 보장됨
```

- 드롭다운은 **소재 카테고리에 맞는 스타일만** 보여준다(`fit_categories_json`).
  실측 근거: 무선 이어폰에 시월드형을 씌우니 구조 검사는 6/6 통과했는데 읽으면 어색했다
  ("남편한테 욕 바가지" + "음향 전문가 추천"). **게이트로는 못 잡으므로 목록에서 막는다.**
- 정렬은 `perf_score` 내림차순, 최근 사용분은 뒤로.

**프롬프트**: `bank_assemble`에 스타일 블록을 추가한다(신규 함수 1개, 기존 조립 흐름 유지).

```
[스타일: 시월드형]
  1) role="hook"   — 가족에게 혼난 상황을 첫 3초에
       문장틀(빈칸만 채워라): "이것 때문에 {가족}한테 욕 바가지로 먹을 뻔했어요" / …
  2) role="before" — 무엇이 문제였는지
  …
- 전체 30초에 300자 안팎, 칸당 평균 60자. 짧게 끝내지 마라.
- 각 beat의 role 값을 위와 똑같이 돌려줘라(게이트가 검사한다).
```

출력 스키마에 `role`을 넣어 **되돌아온 것을 코드가 대조**한다.

**게이트**(`script_gate.py` 신규, 순수함수 — DB·네트워크 없음):

| 검사 | 판정 |
|---|---|
| 구간 순서 | `[b.role for b in beats] == beat_roles` |
| 문장틀 준수 | 빈칸을 `.{0,16}`으로 바꾼 정규식 매칭 |
| CTA 단어유도 | "남겨주세요" 포함 |
| 말 밀도 | `chars_per_30s`의 70~140% |

**실패 시 자동 재작성**(최대 2회): 실패한 검사 항목을 **그대로 지시문에 실어** 재요청.
2회 후에도 실패면 **실패로 표시**하고 화면에 이유를 띄운다 — 조용히 통과시키지 않는다.

> 실측: 밀도 미달을 프롬프트로 부탁만 했을 때 117자 → 203자로 여전히 미달.
> 칸당 글자수까지 지정하니 **269자로 1회 통과**. 재작성 루프는 그 뒤 안전망으로 남는다.

**문장틀 검사의 함정 2개**(실험실에서 실제로 밟음, 이식 시 반드시 가져올 것):
- `re.escape`를 통째로 걸면 `{`가 `\{`가 되고 치환 시 백슬래시가 남아 **절대 안 맞는다**.
  → 빈칸으로 먼저 쪼갠 뒤 **조각만** 이스케이프.
- 빈칸 뒤 조사는 받침에 따라 바뀐다(`{제품}이라고` → "세제라고").
  → 빈칸 다음 조각의 **맨 앞 조사 한 글자는 있으나 없으나 통과**.

### 3-4. 실적 되먹임

렌더 완료 시 `script_usage`에 **어느 스타일을 썼는지**를 남긴다(현재 `hook·person·cta`만 있음 → `spine_id` 추가).
나중에 그 영상의 조회수가 붙으면 `spine.perf_score`를 갱신 → **남의 성공으로 시작해 우리 데이터로 정렬**.

이번 범위에서는 **기록만** 한다(점수 계산은 표본이 쌓인 뒤).

## 4. 안 하는 것 (YAGNI)

- 부품 랜덤 조합 — 사장님 지시로 폐기. 스타일 단위로만 고른다.
- 스타일 자동 승격 — `status='pending'` 사람 승인 유지.
- 톤 자동 판정 — 카테고리 잠금(목록 제한)으로 갈음. AI에게 "어울리나?"를 묻지 않는다.
- `_bank_block`(양념 주입) 제거 — **건드리지 않는다.** 스타일 블록은 별도로 얹고,
  드리프트가 관찰되면 그때 조정한다(2026-07-26 사고 재발 방지).

## 5. 작업 순서

| # | 내용 | 확인 방법 |
|---|---|---|
| 1 | `spine` 3컬럼 추가 + 채이홈 시월드형 1행 실제 INSERT | DB에서 조회해 값 확인 |
| 2 | `script_gate.py` — 순수함수 4검사 + 문장틀 매처 | 단위테스트(통과/오탐 각 케이스) |
| 3 | `bank_assemble.style_block()` — 스타일 → 프롬프트 블록 | 문자열 스냅샷 테스트 |
| 4 | 생성 경로에 스타일 2개·게이트·재작성 배선(`n=2`) | 실제 잡 1건 생성해 두 안의 role 배열이 다름을 확인 |
| 5 | 제작소 UI — 스타일 2개 드롭다운(카테고리 필터·실적 표기) | 브라우저로 직접 열어 확인 |
| 6 | `script_usage.spine_id` 기록 | 렌더 후 행 조회 |

각 단계는 **라이브에 안전**하다 — 1~3은 읽기·신규 파일, 4~5는 플래그 뒤에서 기본 off,
실측 후 켠다(교훈: `feedback_no_unverified_flag_in_live`).

## 6. 미해결·위험

- **톤 불일치**: 카테고리 잠금으로 줄이지만 완전히 못 막는다. 같은 "살림청소" 안에서도
  어색한 조합이 나올 수 있고, 게이트는 이를 못 잡는다. → 사람이 보는 2안 비교로 흡수.
- **스타일 다양성 부족**: 지금 실측 스타일은 채이홈 1개뿐. 최소 3채널을 더 돌려야
  카테고리별 선택지가 생긴다.
- **드리프트 재발**: 문장틀을 강제하므로 여러 영상이 같은 훅으로 열릴 수 있다.
  → 최근 사용 스타일·훅을 뒤로 미는 회전이 필요(3-3의 정렬에 포함).
