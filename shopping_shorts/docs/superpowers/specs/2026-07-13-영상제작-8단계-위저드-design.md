# 영상제작 8단계 위저드 — 설계 (v1 골격)

작성: 2026-07-13 · 상태: 승인(골격-먼저, 반복수정 전제)

## 목적

레퍼런스 릴스에서 대본을 확정하고, 그 대본 장면에 영상을 맞춰 편집·꾸미고,
썸네일·SEO까지 붙여 최종 영상을 만드는 **단일 파이프라인 위저드**.
쇼핑팩토리 흐름을 참고하되 우리 강점(도서관·대본믹스)을 살려 다듬는다.

## 범위/원칙

- **골격 먼저**: 8단계 껍데기 + 스텝 네비 + 상태저장을 먼저 세우고, 단계별로 심화.
- **기존 영상믹싱 흡수**: 사이드바 "영상 믹싱" → "🎬 영상제작"으로 대체. 기존
  `mix.html`/`mix_pipeline`은 이 위저드의 2단계로 편입.
- **반복수정 전제**: 한 번에 완성 안 됨. Phase별로 붙이고 사용자 피드백으로 다듬는다.

## 페이지/상태

- 새 페이지 `/produce` (사이드바 "🎬 영상제작", `sidebar.js`에서 기존 "영상 믹싱" 교체).
- 상단 8스텝 진행바 + 스텝 콘텐츠 + 하단 이전/다음.
- 상태 = **produce_job** 단일 레코드(서버 저장 → 새로고침·PC간 이어하기).
  기존 `mix_jobs` 테이블을 확장(스텝별 산출물 컬럼/JSON) 또는 상위 `produce_jobs` 신설.
- 각 스텝은 자기 산출물을 produce_job에 저장하고 다음 스텝이 읽는다(느슨한 결합).

## 8단계

| # | 단계 | 핵심 | 재활용 | 신규 |
|---|------|------|--------|------|
| 1 | **대본** | 3탭 모드 + 실시간 예상 음성길이 안내 | script_wiki·script_extract·script_generate | 대본믹스(Feature B) |
| 2 | **영상믹스** | 소스영상 선택 → 대본장면 자동매칭 EDL | mix_pipeline·edit_plan | **given_script 모드** |
| 3 | **자막제거** | VMake(옵션) | vmake_client | — |
| 4 | **TTS** | 음성·속도, 장면길이 맞춤 자동조절, 프리뷰 | tts.py | 장면맞춤 속도조절 |
| 5 | **꾸미기** | 헤드카피 디자인에디터(폰트/색/크기/위치/외곽선)+실시간 프리뷰 | video_assemble(자막굽기) | **디자인 에디터 UI** |
| 6 | **썸네일** | 영상 프레임 선택 + 텍스트 오버레이 | frame_extract | **썸네일 생성** |
| 7 | **SEO** | 제목/설명/태그/해시태그, AI 전체생성 | Gemini | **SEO 생성** |
| 8 | **최종검수** | 전체 미리보기 → 렌더 + 내보내기(MP4/CapCut/대본/TTS) 한곳에서 | run_render | **CapCut export** |

### 1단계 대본 — 3탭 (확정)

쇼핑팩토리 "스크립트 모드" 레이아웃(3탭 + 우측 실시간 프리뷰/길이안내) 채용.

1. **직접작성** — 빈 편집창에 대본 직접 입력.
2. **우리 시스템으로 믹스** — 도서관 S급 대본 2~3개의 강점(훅=A·전개=B·주변인물=C)
   조합 + 필요시 URL 대본추출로 소스 확보 → 새 대본 생성. (Feature B)
3. **제미니 자동** — 주제/제품 입력 → Gemini가 대본 자동 생성.

공통 스마트 디테일:
- **실시간 예상 음성 길이** 안내(글자수→초 추정).
- 렌더 시 **TTS 속도가 장면 길이에 맞춰 자동 조절**(4단계와 연동).

### 2단계 영상믹스 — given_script 모드 (핵심 신규)

- 소스영상: 담기 바구니(mix_basket) / URL 직접 / 파일 업로드.
- 기존 mix_pipeline은 나레이션을 내부 자동생성하지만, 여기선 **1단계에서 확정된
  대본을 받아**(given_script) 나레이션을 새로 쓰지 않고 대본을 비트로 분할해
  각 장면에 소스영상 구간만 매칭한다.
- `build_edit_plan(source_scripts, ..., given_script=None)` 에 `given_script`
  파라미터 추가. 있으면 대본→비트 분할 후 세그먼트 매칭만 수행.
- 매칭: 자동(EDL 유사도) → 검토 단계에서 장면별 교체(기존 adjust 재사용).

## 골격-먼저 빌드 순서(Phase)

- **Phase 1** — 위저드 껍데기 + 스텝 네비 + produce_job 상태 + 1단계(대본 3탭) +
  2단계(믹스 given_script) 실동작 연결. (사이드바 교체 포함)
- **Phase 2** — 3·4단계(자막제거·TTS) 배선.
- **Phase 3** — 5단계(꾸미기 디자인 에디터).
- **Phase 4** — 6·7단계(썸네일·SEO).
- **Phase 5** — 8단계(내보내기/CapCut export).

각 Phase는 실동작+브라우저 검증 후 커밋·배포. 사용자 피드백으로 다듬고 다음 Phase.

## 열린 항목(진행하며 확정)

- produce_jobs 신설 vs mix_jobs 확장 — Phase 1 착수 시 데이터모델 확정.
- CapCut export 포맷(draft_content.json 구조) — Phase 5에서 조사.
- 꾸미기 헤드카피가 "자막"과 별개 디자인 요소인지(쇼핑팩토리처럼) — Phase 3에서 확정.
