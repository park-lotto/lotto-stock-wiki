# 훅·본문 정밀 템플릿 디자인 시스템

## 목표

레퍼런스 영상의 훅 프레임과 본문 프레임을 한 쌍으로 보존하고, 대본에서 추출한 문구만 교체해도 원본과 같은 결과가 나오게 한다. “비슷한 스타일”이 아니라 실제 캡처와의 픽셀 대조를 통과한 템플릿만 사용자에게 제공한다.

## 절대 규칙

1. 훅과 본문은 같은 프리셋 안의 독립 프레임이다. 훅 변경이 본문 값을 덮어쓰지 않는다.
2. 캡처에서 측정한 `baseline`은 수정하지 않는다. 사용자의 변형은 `overrides`에 별도로 저장한다.
3. 색은 이름이 아니라 8자리 RGBA 값으로 저장한다. 그라데이션은 각 정지점과 각도를 모두 기록한다.
4. 폰트는 family 이름만 저장하지 않는다. 실제 에셋 경로와 SHA-256을 함께 고정한다.
5. 외곽선과 그림자는 “없음”도 명시적으로 `0` 값으로 저장한다. 브라우저 기본값에 기대지 않는다.
6. `verified` 이전 상태는 제작자 화면에만 보인다. 사용자 프리셋 목록에는 `published`만 노출한다.
7. 자동 문구 바인딩은 레이아웃을 재설계하지 않는다. 허용된 슬롯의 텍스트만 교체한다.

## 제작·검수 흐름

```text
레퍼런스 영상 선택
  → 훅/본문 시점의 원본 프레임 캡처 및 해시 고정
  → 영역, 색, 그라데이션, 폰트, 외곽선, 그림자 측정
  → HTML/CSS 기준 템플릿 구현
  → 원본 크기와 1080×1920으로 결정론적 렌더
  → 원본/렌더 오버레이 및 픽셀 차이 확인
  → 폰트 에셋·문자 경계·줄바꿈 검수
  → verified
  → published
  → 대본 분석값을 슬롯에 바인딩
```

## 상태 게이트

| 상태 | 의미 | 사용자 노출 |
|---|---|---|
| `draft` | 캡처만 등록 | 아니오 |
| `measured` | 좌표·색·폰트 후보 입력 | 아니오 |
| `rendered` | HTML/CSS 렌더 생성 | 아니오 |
| `verified` | 원본 대조 통과 | 아니오 |
| `published` | 서비스용 승인 | 예 |

## 자동 바인딩 슬롯

- `channel_name`
- `hook_title_1`
- `hook_title_2`
- `hook_subtitle`
- `body_title`
- `body_caption`
- `view_count`
- `comment_count`

문구가 슬롯의 최대 줄 수를 넘으면 무조건 임의 축소하지 않는다. 프리셋별 `overflow.strategy`에 따라 짧은 대체 문구를 요청하거나 수동 검수로 보낸다.

## UI 원칙

- 기본 화면에는 완성된 훅+본문 페어, 큰 9:16 미리보기, 문구 필드만 보인다.
- 폰트, 좌표, 색, 효과는 `고급 설정` 한 곳에 접는다.
- 템플릿 카드는 훅과 본문을 항상 같이 보여준다.
- 현재 편집 중인 장면이 훅인지 본문인지 한눈에 구분한다.
- 제작자용 원본 대조와 일반 사용자용 편집 UI를 분리한다.

구조 검증 기준은 [`preset.schema.json`](./preset.schema.json), UI 공통값은 [`ui-tokens.css`](./ui-tokens.css)를 사용한다.
