# 텔레그램 인제스트 시스템 — 설계

- **날짜**: 2026-06-21
- **배경**: 리포트 질문지 인제스트(Plan A/B)의 다음 단계. 여러 텔레그램 채널이 한
  얘기를 분석해 위키에 **계속 누적**한다. 뉴스·리포트에 없는 고유 정보(개인 인사이트·
  단독·수급단서)가 핵심 가치.
- **범위**: 텔레그램 **인제스트만**. 유튜브/뉴스는 후속.
- **선행 자산**: `questionnaire.py`(질문지·fan-out), `verify_questionnaire.py`(검증),
  `codemap.py`(종목명→코드), `report_ingest.py`(오케스트레이터), atoms DB·ChromaDB.

---

## 1. 핵심 통찰 — "한 번 박을 것" vs "계속 튜닝할 것"

텔레그램은 리포트와 본질이 다르다. 리포트는 *1 PDF = 시점 고정 판단(목표가)*이지만,
텔레그램은 **연속되는 의견 스트림**이다. 그래서 **데이터 구조를 처음에 틀리면 쌓인
데이터가 영구 오염**된다(재인제스트만이 답). 반면 사전·파라미터는 데이터를 버리지
않고 계속 개선된다. 이 둘을 분리하는 것이 설계의 중심.

| 구분 | 항목 | 이유 |
|---|---|---|
| 🔩 스키마(처음에 박음) | 2층 모델 · timestamp · 슬롯별 validity · 미매칭로그 · quote/메타 분리 · 외국주 분기 · 이벤트 병합키 | 틀리면 영구 오염 |
| 🔧 튜닝(계속 개선) | 별칭사전 · recency 가중치 · 채널 신뢰등급 값 · quote 길이 · 이미지 참조 | 데이터 안 버리고 개선 |

---

## 2. 가장 중요한 설계: 2층 모델

텔레그램 한 채널의 하루치에는 **성격이 다른 3종**이 섞여 있다. 각각 수명(validity)이
다르므로 저장 방식도 달라야 한다.

| 층 | 내용 | 저장 방식 | validity | 예시 |
|---|---|---|---|---|
| **L-FACT (사실/이벤트)** | 일어난 일 | **append** (타임라인 영구) | permanent/event | "SK하이닉스 HBM4E 출하", "미·이란 MOU 체결" |
| **L-STANCE (현재판단)** | 채널의 현재 뷰 | **갱신** (최신값 + 변경이력) | 다음 스탠스가 나오면 만료 | "태린이아빠 반도체뷰: 긍정 (6/19)" |
| **L-METHOD (방법론)** | 종목 무관 매매규칙 | append (영구, 별도 공간) | permanent | "10일선 이탈 시 매도" |

### 의견 만료(stance change) 처리 — 위키가 썩지 않는 핵심
- 스탠스 원자의 키 = `(채널, 종목/섹터)`. 같은 키로 새 스탠스가 들어오면 기존 것을
  `is_active=0`으로 내리고 신규를 `is_active=1`로. 과거는 **삭제하지 않고** changelog로 보존.
- 쿼리 시 기본은 `is_active=1`만 → "지금 뷰"가 깨끗. "언제 마음 바꿨나"는 history 조회.
- **이것이 리포트엔 없던 텔레그램 고유 설계.** append-only면 죽은 판단이 계속 튀어나와
  "의미 없는 위키"가 된다.

## 3. 채널 레지스트리 (채널별 고정 타입 + 신뢰등급)

채널은 정체성이 고정이므로 **한 번 매핑**해둔다. `pipeline/atoms/telegram_channels.json`.

```json
{
  "하나반도체":        {"type": "sector",       "sector": "반도체", "trust": "B"},
  "삼성반도체":        {"type": "sector",       "sector": "반도체", "trust": "B"},
  "다올조선방산":      {"type": "sector",       "sector": "조선",   "trust": "B"},
  "하나차이나":        {"type": "sector",       "sector": "중국",   "trust": "B"},
  "한화철강":          {"type": "sector",       "sector": "철강",   "trust": "B"},
  "대신시황":          {"type": "market",       "trust": "B"},
  "미래시황":          {"type": "market",       "trust": "B"},
  "유안타시황":        {"type": "market",       "trust": "B"},
  "키움시황":          {"type": "market",       "trust": "B"},
  "그로스리서치":      {"type": "report_relay", "trust": "B"},
  "신한리서치":        {"type": "report_relay", "trust": "B"},
  "한투글로벌":        {"type": "report_relay", "trust": "B"},
  "요약하는 고잉":     {"type": "report_relay", "trust": "C"},
  "잠실개미고급수집":  {"type": "stock_tips",   "trust": "C"},
  "주공고급수집":      {"type": "stock_tips",   "trust": "C"},
  "독학주식첵터정리":  {"type": "stock_tips",   "trust": "C"},
  "태린이아빠 주식투자": {"type": "insight",    "trust": "B"}
}
```

- **제외**: `리포트요약`(완전요약 무가치), `투경현황`(투경봇 발송본), 이미지/스크린샷 파일.
- **신뢰등급(trust)**: 증권사계열=B, 검증된 개인(태린이아빠)=B, 익명수급=C.
  → 정적 시작, 수동 조정(🔧 튜닝). 적중률 추적은 데이터만 남겨 후속.
- 레지스트리에 없는 신규 채널 = `unknown` 타입으로 로그만, 인제스트 보류(사람 확인).

## 4. 타입별 질문지 (5종)

스파이크(2026-06-19, 4채널)로 검증 완료. flash-lite가 5만자 개인채널도 1콜로 노이즈
제거 → **2단계 전처리 불필요**.

### 공통 철칙 (프롬프트)
1. 없으면 null, 지어내지 않음.
2. 수치·종목명·날짜 축자. 잡담·인사·이미지설명·외부링크 버림.
3. **각 항목에 `ts`(원문 메시지 시각 HH:MM)와 `quote`(원문 그대로) 짝꿍.**
4. `comment`/`reason`은 재서술 허용하되 **약한 신뢰**. `quote`는 원문 = 강한 신뢰.

### [sector] 섹터 채널
`sector_name`, `sector_view`(긍정/중립/부정), `points[]`(코멘트),
`stocks_mentioned[]`({name, comment, ts, quote}), `events[]`({fact, ts, quote}), `quote`

### [market] 시황 채널
`market_direction`, `macro_events[]`({fact, ts, quote}),
`sectors_mentioned[]`({sector, stance, comment}), `quote`

### [stock_tips] 수급·단독 채널
`stocks[]`({name, signal, reason, ts, quote}), `news_items[]`({fact, ts, quote}), `quote`

### [insight] 개인 인사이트 채널
`leading_sectors[]`, `stance[]`({target(종목/섹터), view, ts, quote}),
`methods[]`({rule, quote})  ← L-METHOD, `stocks_mentioned[]`({name, comment, ts, quote}),
`noise_ratio`, `quote`

### [report_relay] 리포트 중계 채널
`reports[]`({broker, stock, rating, tp, ts, quote})  — 리포트 인제스트와 중복 OK(교차신호)

## 5. fan-out (질문지 → 원자, 결정론적 코드)

### 라우팅 규칙
| 질문지 항목 | → 원자 | 층 | 비고 |
|---|---|---|---|
| events / macro_events / news_items | 사실 원자 | L-FACT | append, validity=event |
| sector_view / market sectors / insight stance | 스탠스 원자 | L-STANCE | (채널,대상)키 갱신 |
| methods | 방법론 원자 | L-METHOD | asset_level="method" |
| stocks_mentioned / stocks | 종목 원자 | L-FACT | **한국주만**(아래) |
| report_relay reports | 종목 원자(약함, "거론"레벨) | L-FACT | 리포트 중복 OK→mention_count로 교차신호 |

### 종목 분기 (외국주 정보 손실 방지)
- `is_korean_stock(name)` True → 종목 원자 생성(종목페이지行).
- False(마이크론·ARM·TSMC 등) → **종목 원자 안 만듦**. 대신 그 코멘트를 소속 **섹터 원자
  본문에 보존**(맥락 유지). 외국주 자체 페이지는 없음.
- 매칭 실패(한국주인데 codemap에 없음, 예 "삼전") → **미매칭 로그**(`raw/telegram_unmatched.log`)
  에 `{날짜, 채널, 원문종목명}` 기록. 조용한 드롭 금지. 별칭사전으로 주기 보강(🔧).

### 종목명 정규화
- `codemap.code_for()` 호출 전 **별칭 사전**(`pipeline/atoms/stock_aliases.json`) 통과:
  `{"삼전":"삼성전자","하이닉스":"SK하이닉스","에코프로비엠":"에코프로비엠"}`.
- 별칭 사전은 미매칭 로그를 보며 사람이 계속 추가(🔧 튜닝).

### quote만 종목페이지, signal/comment는 메타 (오염 차단)
- 종목 원자의 `content` = **quote(원문) 중심**. `signal`·`comment`는 약한 메타 필드로만.
- 방향 판단은 저장 시 확정하지 않고 **쿼리타임에 Claude가** 여러 quote 보고 종합.
  (잠실개미 "삼성전자 bear"가 사실 질문이었던 케이스 → 영구 오염 방지)

### 이벤트 병합 + 채널 카운트 (중복 → 교차신호)
- 사실 원자는 `event_key = normalize(fact)` (핵심명사+날짜 해시)로 그룹핑.
- 같은 event_key가 여러 채널에서 나오면 **원자 1개 + `mention_channels=[채널…]`, `mention_count=N`**.
- `mention_count`가 높을수록 strength 가산 → "N채널 동시 언급 = 강한 신호" 교차검증 지표.

### strength_score (채널 신뢰등급 차등)
`base(trust: B=3, C=2)` × 층 가중(FACT=1.0, STANCE=0.8, METHOD=0.7) + `mention_count` 가산.
리포트 목표가(4)를 넘지 않게 상한.

## 6. 검증 (텔레그램은 정답지가 없다)

리포트의 wisereport 같은 정답지가 **없으므로** quote 원문대조가 유일한 1차 검증.

- **㉠ quote 원문 대조**: 각 `quote`가 해당 채널 원문 .md에 실제 존재하는지 코드 검사.
  없으면 🚩(할루시네이션) → 해당 원자 strength 감점. (`verify_questionnaire.check_quotes` 재사용)
- **㉡ 구조 룰**: signal 있는데 quote 없음 🚩 / stance 대상 누락 🚩 / noise_ratio>0.8 🚩.
- **comment/reason은 검증 안 함** — 재서술 허용 필드라 약한 신뢰로만 저장.
- 골든셋: 스파이크 4종(하나반도체·잠실개미·대신시황·태린이아빠)을 회귀 기준으로 보존.

## 7. 오케스트레이터 & 파이프라인

`pipeline/atoms/telegram_ingest.py` (report_ingest.py 패턴 차용):

```
telegram_ingest --all [--date YYYY-MM-DD] [--limit N] [--dry-run]
  └ raw/telegram/{date}_{채널}.md 미처리 탐색 (digest·제외채널 스킵)
  └ 레지스트리에서 타입·신뢰등급 조회 (unknown이면 로그+스킵)
  └ extract_questionnaire(.md, 타입질문지)  ← Gemini flash-lite
  └ run_verification (quote 대조 + 구조룰)
  └ questionnaire_to_atoms_telegram (fan-out, 2층, 병합, 정규화)
  └ insert_atom + embed_and_store
  └ 질문지 아티팩트 보존: raw/telegram_q/{date}/{채널}.json
```

`scripts/atom_pipeline.py`에 STEP3.5로 추가(리포트 STEP3 다음). 7AM 스케줄러가 자동 실행.

## 8. 쿼리 → 인사이트 (산출물 시연)

기존 `pipeline.atoms.query`(벡터+SQL 하이브리드)가 재료를 모으고 **Claude가 합성**
(CLAUDE.md 3단계: 원자DB→WebSearch→결합).

**"반도체 지금 어때?" 예시 (스파이크 데이터 기준):**
```
재료(원자DB):
  [하나반도체/섹터] HBM4E·필라델피아 6.4%급등 (B)
  [잠실개미/SK하이닉스] quote: 최태원-머스크 회동 (C)
  [대신시황/시장] 반도체 주도주 쏠림 (B)
  [태린이아빠/스탠스] 반도체 1티어, 30~50% 베팅 (B)
  [리포트/SK하이닉스] 목표가 상향 (A)
합성(Claude):
  "5개 소스 중 5개 일치 = 강한 주도. 모멘텀=SK하이닉스 HBM4E.
   단 삼성전자는 시총 우려(잠실개미) → 하이닉스 비중 우위 시그널."
```
시간 누적 시: "SK하이닉스 6/15부터 4채널 동시 bull 전환", "태린이아빠 반도체뷰
6월 내내 일관 → 적중 추적" 등 **웹서칭 불가 인사이트**.
