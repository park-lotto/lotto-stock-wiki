# 제작소 문장별 트림(끝/앞 조용한 부분 자르기) — 설계

- 날짜: 2026-07-22
- 트랙: `제작소트림`
- 대상 화면: 제작소 검토 페이지(`shopping_shorts/static/produce.html`)의 문장(비트) 카드

## 배경 / 문제

캡컷으로 내보내기 전, **웹 안에서 시니어(60대)가 캡컷을 안 열고도 끝낼 수 있게** 하는 것이 북극성.
현재 웹 검토 페이지에서 문장 단위로 되는 것은 화면 교체(스왑)·컷어웨이·효과음 빼기·무음 전역삭제까지고,
**한 장면의 뒷부분을 조금 잘라내는 기능은 없다**(지금은 캡컷 몫).

사장님이 캡컷을 여는 **가장 흔한 이유** = "목소리는 끝났는데 화면이 잠깐 더 머무는(정지) 어색한 꼬리"를
잘라내는 것. 이걸 웹 버튼으로 해결한다.

## 핵심 발견(코드 근거)

- 비트(문장) 길이는 **TTS 음성 길이에 묶여 있다**: `video_assemble._beat_timeline`에서
  `dur = _probe_duration(tts)`. 이 `_beat_timeline`이 자막(`_burn_captions`)·모션·전환의
  **단일 출처**다(코드 주석 명시). → 여기서 비트 길이만 줄이면 **영상·자막·다음 비트 시작이 자동으로 함께** 줄어든다.
  즉 사장님이 원한 "음성·자막·영상 한 번에"가 구조적으로 이미 보장된다.
- "목소리 끝난 뒤 화면만 머문다" = **TTS mp3 끝의 무음 꼬리**(말은 끝났는데 오디오에 조용한 뒷부분이 남고
  그동안 화면이 정지). ffmpeg `silencedetect`로 자동 감지 가능.
- 문장 하나만 재생성하는 배관이 이미 있다: `POST /api/mix/tts/{job}/{beat}/regen` → `resynth_one_beat`.
  트림도 같은 계층(비트별 조작 + 미리보기 무효화)에 얹는다.

## 선택한 방식 — A. 비트별 트림값 저장 → 렌더 때 적용(비파괴)

각 비트에 `head_trim` / `tail_trim`(초, 기본 0)만 저장한다. 원본 TTS mp3는 **건드리지 않는다**.

- **단일 출처에서 빼기**: `_beat_timeline`의 `dur = _probe_duration(tts) − head_trim − tail_trim`
  (하한 가드). 영상 conform·자막·모션·다음 비트 t0가 전부 이 값을 읽으므로 자동으로 함께 줄어든다.
- **오디오 트랙**: 비트 오디오를 이어붙이는 단계에서 그 비트에 `atrim=start=head_trim:end=(len−tail_trim)` 적용.
- **캡컷 내보내기**: `capcut_draft`도 같은(트림된) dur/오디오를 쓰게 해 캡컷 프로젝트에도 반영.
- **되돌리기 = 값 0**. 원본이 그대로라 언제든 원복.

### 왜 A인가(대안 대비)

- **B. mp3를 물리적으로 잘라 교체(파괴적)**: 되돌리기용 원본 별도 보관 필요 + 반복 트림 누적 관리가 복잡.
  성우·톤 재생성(`resynth_one_beat`)이 원본을 다시 읽는데 파괴적 트림과 충돌 소지.
- **C. 기존 전역 무음삭제(`silence_trim`) 강화만**: 문장별·미세조정이 안 됨 → 요구 미충족.

→ **A 채택**: 되돌리기·원본 보존이 시니어 UX의 핵심이고, 단일 출처(`_beat_timeline`)가 이미 있어 배선이 최소.

## UI 설계(문장 카드마다)

```
[🎬 다른 화면으로]  [✂ 끝 조용한 부분 자르기]      ← 자동 1버튼(기본 노출)
   (트림이 걸리면 아래가 나타남)
   뒤 −0.3초 ▸    ◂ 되돌리기            ← 미세조정(누적) + 되돌리기
   ◂ 앞 −0.3초                          ← 앞부분도 동일(선택)
   현재: 끝 0.6초 잘림                    ← 상태 표시
```

- **자동 버튼 `✂ 끝 조용한 부분 자르기`**: 그 비트 TTS 끝 무음을 감지해 `tail_trim`에 넣고 미리보기 재생성.
  무음이 없으면 "자를 조용한 부분이 없어요" 안내(거짓 성공 금지).
- **미세조정 `뒤 −0.3초 ▸`**: 누를 때마다 `tail_trim += 0.3`, 매번 미리보기. `앞 −0.3초`는 `head_trim`.
- **되돌리기 `◂ 되돌리기`**: 해당 엣지 값 0으로 → 원상복구.
- **하한 가드**: 트림 합이 음성 실제 길이(말 구간)를 침범하면 막고 경고("더 자르면 말이 잘려요").
  최소 잔여 길이 하한(예: 0.4초)도 둔다.

시니어 원칙(메모리 `feedback_ttalkkak_senior_northstar`): **슬라이더 대신 버튼**. 자동 1버튼으로 대부분 끝나고,
미세조정은 필요할 때만.

## 백엔드 설계

- **엔드포인트**: `POST /api/mix/{job_id}/{beat_idx}/trim`
  - body: `{ edge: "tail"|"head", mode: "auto"|"nudge"|"reset", step?: 0.3 }`
  - `auto`: `silencedetect`로 해당 엣지 무음 길이 산출 → 그 값을 trim에 설정.
  - `nudge`: 현재값에 `step` 누적(하한 가드 적용).
  - `reset`: 해당 엣지 0.
  - 렌더 중(`rendering`/`removing_subtitles`)이면 409 거부(regen과 동일 규율).
  - 성공 시 트림값 저장 + 미리보기 무효화(스왑과 동일하게 `loadMixReview`/미리보기 재생성 경로).
- **무음 감지 유틸**: `audio_post`(또는 신규 소모듈)에 `detect_edge_silence(path, edge) -> float`.
  ffmpeg `silencedetect`(noise 임계·최소 무음길이 파라미터) 출력 파싱.
- **길이 계산(순수함수)**: `effective_dur(probe, head_trim, tail_trim, floor) -> float` — 하한 가드 포함.
  `_beat_timeline`이 이걸 호출.
- **오디오 조립**: 비트 오디오 concat 지점에서 trim값으로 `atrim` 적용.
- **저장 위치**: 비트 dict에 `head_trim`/`tail_trim`(edit_plan 안). 저장/복원(새로고침)도 이 필드 따라감.
- **캡컷**: `capcut_draft.build_draft`가 timeline의 트림된 dur/오디오를 쓰게 확인(이미 timeline을 받으므로
  timeline만 트림 반영되면 자동).

## 테스트 계획

- 순수함수 `effective_dur`: 정상 트림 / 과트림 하한 가드 / 음수 방지.
- `detect_edge_silence` 파서: silencedetect 샘플 출력 → 초 변환(앞/뒤).
- 회귀(seam): 트림 후 `_beat_timeline`의 dur·다음 비트 t0·자막 구간이 **함께** 줄어드는지
  (기존 `test_beat_timeline` 확장).
- 되돌리기: reset 후 원본 dur 복원.
- 엔드포인트: 렌더 중 409, auto/nudge/reset 동작, 잘못된 edge 방어.
- (로컬 TTS 무음 mock 함정 주의 — 메모리 `reference_local_tts_silent_mock_trap`: 실제 무음 길이로
  검증할 땐 config 키·mean_volume 확인. 순수함수·파서 테스트는 fixture로.)
