## 2026-08-27 — 2단계 자막제거를 완성본 1편 청소로 (완료·라이브)

사장님 제보: "자막제거가 우리 어제 수정하고나서 더 오래걸려", "3단계 완성본 30초만
짤라서 돌리는건데 소스별로 안하고".

### 원인 (서버 워커 로그 실측)
`journalctl -u 'shopping-shorts-worker@*' | grep vmake-ai` 에 전부 찍혀 있다.
(웹 서비스 로그가 아니라 **워커** 로그다 — 여기서 한참 헤맸다)

- 08-26에 만든 완성본 1편 청소(`_final_clean_fn`)를 **`run_render`(3단계)에만** 달았다.
  `run_clean_sources`(2단계 버튼)는 `_FINAL_CLEAN`을 보지도 않고 늘 소스별/합본을 청소.
- 2단계를 누르면 `clean_sources`가 채워지고 → 3단계는 `already=True`로 완성본 경로를
  **건너뛴다**. 즉 2단계를 쓰는 사람에겐 08-26 개선이 통째로 없었다.
- 08-25 커밋 `3a573e381`(과금 1회로 맞추려 소스를 이어붙임)이 2단계에 그대로 걸려
  ① 병렬(ThreadPoolExecutor) → 직렬, ② 최대 해상도 업스케일로 파일이 부풂.

실측: `join_all.mp4` 569MB → **595초(10분)** / 27MB → 139초 / 37MB → 200초

### 고친 것
- `run_clean_sources`: 소스를 안 건드리고 **조립한 완성본 1편**을 `clean_fn` 자리에서 청소.
  `clean_sources`를 **일부러 비워 둔다** → 3단계가 같은 완성본 경로를 타고, 편성이 같으면
  `final_clean_{sig}.mp4` 재사용으로 재과금 0 (2·3단계 work 경로가 같음을 확인).
- `assemble_clean_video(clean_fn=...)`: 청소된 소스가 없어도 원본으로 조립해 그걸 청소.
  clean_fn을 쓸 땐 예외를 **안 삼킨다** — 삼키면 유료 청소 실패가 ready로 남는다.
- `_clean_strategy(job)` 하나로 판단 단일화(0순위-B). `_FINAL_CLEAN`을 직접 읽는 곳이
  늘면 테스트가 잡는다(grep 계약).
- 서버 env `MT_AI_POLL_EXTEND_STEP_MS=10000` — 완료를 늦게 알아채던 손해 30초 → 10초.

커밋: `93cc90e98`(본체) · `cb2f12b00`(판단 단일화) → main 병합, 워커 10:03:06 재시작 확인.

### 실측 결과 (배포 후)
**30.5초 완성본 → 130.2초(2분 10초).** 569MB 합본 595초 대비 **4.6배**.
★"VMake 1초당 9초"(08-26 커밋 기재)는 **틀린 값**이다 — 실측은 **1초당 약 4.3초**.
★VMake는 동시 요청에 줄서기 없음(00:46~00:49 두 건이 51초 겹쳐 돌고 둘 다 완료).
