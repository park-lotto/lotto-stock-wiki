- 날짜: 2026-07-04
- 대상: 대시보드 `/market` "실시간 브리핑" 패널 (`_insight_run_synthesis` 경로 전면 교체)
- 상태: 설계 확정, 구현 계획 대기

## 1. 목적 / 문제

**현재**: 15분 고정 타이머로 그 순간 시장 스냅샷을 백지에서 재묘사 → 시세를 "묘사"만 하고 "판단"이 없음. 입력이 얕고(지수 15분봉 + 순위 abs(등락률) 상위4 + 최신 원자5) 매번 처음부터 써서, 시장이 잔잔하면 거의 같은 글이 반복됨. 주말/KIS장애 시 마지막 장중 스냅샷에 고착돼 며칠째 같은 걸 재방출.

**재설계 목적**: 자기 관심종목만 보느라 시야 좁은 투자자(초보~전업)에게, **지금 시장 전체에 돈이 들어오는지 / 외인·기관 스탠스가 어디로 트는지 / 외부충격·S급뉴스가 떴는지 / 미선물·나스닥이 뭘 하는지를, 아침부터 지금까지 흐름의 연속선상에서** 계속 종합해주는 "장중 시장 날씨 예보". 단순 나열이 아니라 "그래서 지금 분위기가 어떻다"는 판단까지. **이 패널은 객관 데이터 위주인 대시보드에서 유일하게 AI가 판단을 내리는 지점** — 품질 최우선.

### 패널이 매 순간 답해야 하는 체크리스트 (운영자 요구)
- 시장에 돈이 들어오고 있나
- 외부충격·시장에 좋거나 나쁜 이슈가 나왔나
- 빠지고 있다면 분기점(반전점)이 왔나
- 오르고 있다면 외인/기관이 다시 팔기 시작하나
- 프로그램 스탠스는 지금 어떤가
- 미국 선물지수에 특이점이 있나
- 우리 시장이 나스닥선물과 같이 빠지다가 나스닥이 먼저 돌려주고 있나(디커플링)

## 2. 출력 모양 (확정: "판정 + 진화형 내러티브 + 전환점")

```
🟢 위험선호 지속 · 외인 순매수 유지            14:07   ← 한줄 판정 배지 (verdict)
──────────────────────────────────────
오전 약세를 딛고 외인·기관 쌍끌이로 방향을 잡았다.       ← 아침→지금 흐름 명시
9:45 저점 이후 프로그램이 매수로 돌아서며 지수를 끌어올리는 중.  진화형 내러티브
⚡ 미선물 나스닥 +1.1%, 우리 시장이 먼저 반등 — 디커플링 우호적.

오늘의 전환점                                   ← turning-point 타임라인
09:45  지수 저점, 프로그램 매도 정점
11:20  외인 순매도→순매수 전환 ★
13:50  삼성전자 8조 기판 투자 공시, 전력↑
```

- **매 갱신은 "무엇이 바뀌었나"에 초점** — 직전 상태를 프롬프트에 넣어 델타를 강제, 반복 차단.
- 주말/장마감 시 배지에 "지난 장 기준" 라벨, 내러티브는 얼리고 뉴스만 갱신.

## 4. 세션 페이즈 (`briefing_phase.py`)

시각(+요일)으로 판정. 프레이밍과 데이터 기대치를 바꿈:

| 페이즈 | 시각 | 프레이밍 | KIS 라이브 기대 |
|---|---|---|---|
| premarket | 평일 08:00~08:50 | "오늘 볼 것 (미선물·간밤 뉴스)" | 지수 X, 미선물 O |
| intraday | 평일 08:50~15:30 | "지금 벌어지는 것" | 전부 O |
| closed | 평일 15:30~ | "오늘 정리 + 내일 관전 포인트" | 종가 고정 |
| weekend | 토·일·휴장 | "지난 장 기준" (얼림) | 뉴스만 |

- 페이즈 전환 시 강제 1회 종합(프레이밍 갱신).
- weekend/closed에서는 지수/수급 이벤트 디텍터 끄고, S급 뉴스 도착만 갱신 트리거 → **오늘 겪은 주말 고착 구조적 해결.**

## 5. 이벤트 디텍터 (`briefing_events.py`) — 정밀 명세

핵심 원칙: **모든 임계는 단위 명시 상수. 첫런/동결/0값/거래일전환 전부 가드. 이벤트타입별 쿨다운으로 flip-flop 차단. 실데이터 리플레이로 검증.**

### 5.1 기준 스냅샷 (매 틱 성공 시 저장)
```python
snap = {
  "ts": "14:07",
  "idx":   {"J": {"rate":.., "price":..}, "Q": {..}},   # get_index_price
  "hi_lo": {"J": {"day_high":.., "day_low":..}, "Q":{..}},  # bars 러닝 고/저
  "inv":   {"J": {"외인":.., "기관":..}, "Q": {..}},     # get_market_investor, 백만원
  "prog":  {"J": <합계>, "Q": <합계>},                   # get_program_trade, 백만원
  "nq":    {"rate":..},                                  # global_api.get_nasdaq_futures
  "sect":  {"반도체": <avg_rate>, ...},                  # build_heatmap sectors[].avg_rate
}
```
실제 필드 출처(검증됨):
- 지수: `kis_api.get_index_price` → `{price, change_rate}`, bars = `get_index_minutebar` → `[{t, price}]`
- 투자자: `get_market_investor(J/Q)` → `{외인, 기관, 개인, ts}` (백만원, 당일 누적순매수)
- 프로그램: `get_program_trade(J/Q)` → `{차익, 비차익, 합계, ts}` (백만원)
- 미선물: `global_api.get_nasdaq_futures()` → `{price, change_rate, bars[]}`
- 섹터: `sector_heatmap.build_heatmap()` → `sectors:[{name, avg_rate, stocks:[{name,code,change_rate,price}]}]`

### 5.2 디텍터별 판정 (단위 상수 명시)

```python
MIN_INVESTOR_TURN_MW = 30_000   # 300억 (백만원)
PROG_JUMP_MW         = 50_000   # 500억
PROG_FLIP_MIN_MW     = 30_000   # 300억
IDX_NEWHIGH_MARGIN   = 0.0005   # 0.05%
IDX_REBOUND_PCT      = 0.006    # 저점 대비 +0.6%p
IDX_PULLBACK_PCT     = 0.006    # 고점 대비 -0.6%p
NQ_DELTA_PP          = 0.4      # 미선물 %p 변화
NQ_ABS_LEVELS        = [1.0, 2.0]  # 절대 돌파
DECOUPLE_MIN_SLOPE_PP= 0.15     # 슬로프 유의 임계
SECTOR_SURGE_PP      = 2.0      # 섹터 직전대비 +2.0%p
SECTOR_LEAD_ABS      = 3.0      # 절대 +3% & 순위상승
EVENT_RECOOLDOWN_S   = 600      # 같은 타입 재발동 최소간격(강도 급증 시 예외)
```

| # | 이벤트 | 조건 | 노이즈 가드 |
|---|---|---|---|
| 1 | 투자자 부호전환 | `sign(prev)≠sign(curr)` AND `|curr|≥MIN_INVESTOR_TURN_MW`. J/Q × 외인/기관 4쌍 | 새 방향 300억 미만이면 0근처 흔들림 무시 |
| 2 | 프로그램 급변 | `|curr−prev|≥PROG_JUMP_MW` OR 부호전환+`|curr|≥PROG_FLIP_MIN_MW` | — |
| 3a | 지수 신고/신저 | `price > day_high×(1+MARGIN)` / `< day_low×(1−MARGIN)` | 러닝고저는 당일 bars에서만 |
| 3b | 지수 반등 | `price ≥ day_low×(1+REBOUND_PCT)` AND 이 leg 미발동 | leg당 1회 (마지막 극값 방향 추적) |
| 3c | 지수 되돌림 | `price ≤ day_high×(1−PULLBACK_PCT)` AND leg 미발동 | leg당 1회 |
| 4 | 미선물 특이 | `|nq−prev|≥NQ_DELTA_PP` OR 절대 `±1%/±2%` 돌파 | — |
| 5 | 디커플링 | 우리지수 slope 부호 ≠ NQ slope 부호, 둘 다 `|slope|≥DECOUPLE_MIN_SLOPE_PP`. "미선물↑ 코스피↓" / "NQ 선반전" 구분 | slope=마지막 3~4봉 회귀, 미미하면 무시 |
| 6 | **섹터 급변(신규)** | `Δavg_rate≥+SECTOR_SURGE_PP`(급등) 또는 `≤−`(급락). OR `avg≥SECTOR_LEAD_ABS` & 순위상승 | build_heatmap이 price=0 제외 → KIS다운 시 네이버폴백 값→Δ≈0→오발동 안 함 |

### 5.3 섹터 급변의 "왜" — payload에 근거 동봉
```python
{"type":"sector_surge", "sector":"반도체", "delta":+2.1, "avg":+3.4,
 "top_movers":[{"name":"한미반도체","rate":+8.2}, {"name":"이수페타시스","rate":+6.1}],  # 그 섹터 상위 상승
 "news":["한미반도체 HBM 장비 수주 공시"]}   # top_movers 종목명으로 news_feed/atoms 매칭
```
→ 종합엔진이 "반도체 직전 대비 +2%p, 한미반도체(+8%)가 HBM 수주로 견인" 식 판단. **"섹터 올랐다"가 아니라 "무엇이 왜".**

### 5.4 오류 방지 4중 장치
1. **첫런/재시작**: baseline=None → 저장만, 발동 안 함 (기존 `detect_alerts` 패턴)
2. **데이터 동결(KIS 다운)**: 핵심필드가 prev와 전부 동일 또는 ts 미변 → skip. 전필드 0 → skip.
3. **거래일 전환**: 장 시작 시 baseline·러닝고저·스토리 리셋
4. **이벤트타입 쿨다운**: 같은 타입 `EVENT_RECOOLDOWN_S` 내 재발동 금지(강도 유의 급증 시 예외)

## 8. 종합 엔진 (`briefing_weather.py`) — Opus via Max 구독

### 8.1 모델 호출 (API 아님 — 구독 인증)
검증 완료(2026-07-04): 서버에 claude CLI 2.1.201 설치 + `~/.claude/.credentials.json`(Max OAuth) 복사 → 헤드리스 Opus 호출 성공(`modelUsage: claude-opus-4-8`, 2.5초).

```bash
claude -p "<브리핑 프롬프트>" --model opus \
  --output-format json --permission-mode bypassPermissions
```
- **전용 최소 작업디렉토리**(`/home/ubuntu/briefing_agent/`, 큰 CLAUDE.md 없음)에서 실행 → Claude Code 기본 컨텍스트만 로드(오염·토큰 최소화).
- 출력 JSON의 `.result`를 파싱(프롬프트에서 JSON 객체 출력 강제).
- **인증**: 서버에 `ANTHROPIC_API_KEY` 없음 → OAuth(Max) 사용 → **API 과금 아님, Max 한도 차감.** `total_cost_usd`는 참고표시일 뿐.
- 토큰 자동갱신: accessToken 만료 시 refreshToken으로 CLI가 자동 재발급·파일 갱신.

### 8.2 입력(프롬프트) 구성
- **시스템 파트(고정)**: 운영자 관점·판단 기준·§1 체크리스트·출력 JSON 스키마 — 반복 호출이라 안정 프리픽스.
- **변동 파트**: 계산된 사실(지수 시가/고저/현재·수급·프로그램·미선물, `compute_index_shape` 방식으로 환각 방지) + 감지된 새 이벤트 + 스토리-so-far(직전 verdict/전환점/내러티브) + S급 뉴스 후보 + 페이즈.
- 출력: `{verdict:{tone,line}, narrative, new_turning_points:[..], used_news_ids:[..]}`.

### 8.3 폴백
`claude -p` 실패/타임아웃(예: 90초)/미설정 시 → 기존 `_gemini_text`로 같은 프롬프트 재시도 → **무중단.** Gemini도 실패 시 직전 스토리 유지.

## 9. 오케스트레이터 (기존 `_insight_run_synthesis` 대체)

30초 틱:
1. 세션 페이즈 계산. 페이즈 변화 → 강제 종합.
2. 스냅샷 수집(market_flow 캐시 + build_heatmap) → `output/weather_snaps/`에 덤프.
3. 디텍터 실행(현재 vs baseline).
4. S급 뉴스 후보 수집.
5. **이벤트 OR 새 S급뉴스 OR 페이즈변화 OR 심박(30분) 중 하나라도 → 종합 실행 → 스토리 갱신·영속.**
6. baseline 갱신.

가드: Claude 호출 **최소간격 90초** + **하루 하드캡 60회**(비용/한도 보호). 캡 도달 시 심박만.

- Max 구독 한도 차감(API 과금 아님). **주의: Max 5시간 창 한도를 운영자의 평소 Claude Code 사용과 공유** — 장중 브리핑이 몰리면 코딩 한도와 경쟁. 하드캡·심박floor로 완화.

## 12. 검증 (실데이터 필수 — 합성 통과 = 완료 아님)

- **디텍터별 단위테스트**: 발동해야 할 스냅샷쌍 / 침묵해야 할 쌍(노이즈·None·동결·첫런) 각각.
- **하루치 실스냅샷 리플레이**: `output/weather_snaps/` 하루치를 순서대로 흘려 "언제 몇 번 발동, 헛발동 0" 확인.
- **섹터 디텍터**: 네이버폴백/주말 상황에서 Δ≈0 → 오발동 없음 명시 검증.
- **종합엔진**: 서버 실호출로 JSON 파싱·폴백 경로 실측(집PC 아님, 서버에서).
- 임계값(300억·0.6%·2%p 등)은 초기값 → 리플레이 데이터 보고 튜닝.

## 13. Phase 0 — 관측·보정 (Calibration, 실운영 전 며칠)

라이브 패널에 붙이기 전, **섀도우로 먼저 돌려 얼마나 잡히고 노이즈가 끼는지 운영자가 직접 보고 피드백 → 튜닝**하는 단계. "초반에 돌려보며 감 잡기" 요구 반영.

### 13.1 무엇을 돌리나
1. **디텍터 + 스냅샷 덤프**를 장중 30초틱으로 서버에서 실데이터로 가동. **라이브 패널에도 바로 반영** — 단일 사용자(운영자만 봄) 베타라 '실험중' 태그 불필요, 실제 렌더까지 보며 판단.
2. 트리거 발동 시 종합엔진을 **Opus/Sonnet 번갈아** 실행(각 출력에 모델·레이턴시 라벨). **major(★) 이벤트엔 둘 다 돌려 직접 A/B**(패널엔 Opus 표시, 다이제스트에 둘 다).
3. 출력 3곳:
   - `output/weather_calib/YYYY-MM-DD.jsonl`: 매 트리거 `{ts, fired_events:[{type,값}], model, verdict, narrative, latency_ms, noise_flag}`
   - **텔레그램 다이제스트**(BOT_TOKEN+CHAT_ID): **major(★) 즉시 발송**, **minor는 15분마다 묶어서** 한 번. 형식 `🔔[11:20] 외인 순매도→매수 전환·반도체+2.1%p\n[Opus] {verdict} — {내러티브 1문장}`. 폰에서 보고 답장으로 피드백.
   - **일일 요약**(장마감 후): `오늘 N회 발동(타입별 분해) / 의심노이즈 M건 / Opus vs Sonnet 레이턴시·체감`.

### 13.2 잡힘·노이즈·의미 3지표
- **잡힘**: 발동 횟수(타입별), 큰 시장 이벤트를 놓쳤나(사후 육안).
- **노이즈(자동 추정)**: 이벤트 발동 후 X분 내 해당 지표가 임계 아래로 되돌아가거나 곧바로 반대전환 → `noise_flag=의심`. 최종 판단은 운영자.
- **의미**: 운영자가 다이제스트에 "볼 가치 있음/없음" 라벨 → 임계·타입 튜닝 근거.

### 13.3 피드백 루프
운영자가 다이제스트/요약 보고 "이건 노이즈 / 이 임계 너무 민감 / 여기선 Opus 우세" → 반영해 **임계값·모델 튜닝** → 반복. 충분히 안정되면 Phase 1로.

## 14. 범위 / 단계 (YAGNI)

- **Phase 0 (관측·보정)**: §5 디텍터 + §7 스토리상태 + §9 오케스트레이터 + §8 Opus/Sonnet 번갈아 종합 + §10 라이브 패널(배지·내러티브·전환점) + 텔레 다이제스트/일일요약 + 노이즈 자동플래그. **패널까지 실제 반영**(단일 사용자 베타)하되 모델은 번갈아·임계는 초기값. → 며칠 돌려 튜닝·모델선정.
- **Phase 1 (확정)**: 관측 결과로 **승자 모델 고정 + 임계 튜닝 확정** + 다이제스트 정리(major만 유지 등). 파이프라인 자체는 Phase 0에서 이미 섰으므로 값 고정 위주.
- **Phase 2 (나중)**: 수급빈집·컨센상향 등 위키 엣지 데이터 주입, 개인화 알림, 임계 자동튜닝.

## 15. 미결 / 리스크

- 임계값 초기치는 트레이더 직관으로 시작 → Phase 0 관측으로 튜닝.
- 서버에 Max 토큰 저장(보안 트레이드오프, 운영자 승인함). 서버 침해 시 계정 노출.
- Max 레이트리밋 공유 — Phase 0은 major 이벤트 A/B로 호출이 더 많음(Opus+Sonnet 둘 다) → 코딩 한도 잠식 주의, 하드캡으로 완화.
