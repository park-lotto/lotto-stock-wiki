# 레퍼런스 랭킹 Phase 1 — 틱톡 자동 랭킹 노출 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 이미 구현돼 있으나 화면에 숨겨진 **무료 틱톡 계정기반 랭킹**을 플랫폼 토글로 노출하고, 유료(Apify 키워드) 경로를 자동 수집에서 분리하며, 화면 문구를 플랫폼별 실제 기준에 맞춘다.

**Architecture:** 신규 수집기를 만들지 않는다. `service._collect_tiktok()`(yt-dlp 무료 계정시드) + `#platformTabs`(숨김) + `switchPlatform()`이 이미 존재 — 노출·정책·정합만 손본다.

**Tech Stack:** FastAPI, vanilla JS, yt-dlp(무료), 기존 `ranking.build_tiktok_items`.

## Global Constraints

- 코드 작업은 전부 `.tracks/레퍼런스랭킹개편/...` 절대경로. main 폴더 코드 금지. git은 `git -C .tracks/레퍼런스랭킹개편`. `git stash` 금지(워크트리 공유).
- **과금 금지**: 자동 수집 경로에 Apify가 들어가면 안 된다. 틱톡 무료=계정 시드(`kind='account'` → `tiktok_client.fetch_account_videos`, yt-dlp). 유료=키워드 시드(`_TIKTOK_LANG_KINDS` → `tt_search_full`, Apify).
- 기존 코드 **삭제 금지**: 키워드 경로·Apify 호출은 남기되 자동 경로에서만 뺀다(관리자 수동 옵션으로 보존).
- 실측된 불안정성 반영: yt-dlp 채널목록은 **간헐 빈 응답**이 난다(2026-07-24 실측) → 재시도·부분실패 허용.
- 관리자 전용 컨트롤은 기존 패턴(`window.IS_ADMIN` + 백엔드 `_require_admin`)을 따른다.

키워드 시드는 Apify 유료라 기본 자동 경로에서 빠지고, 명시 옵션일 때만 돈다."""
from shopping_shorts import service


def _seeds(monkeypatch, rows):
    class S:
        def list_seeds(self, p): return rows
        def prev_base_platform(self, p, sc): return None
        def prev_delta_platform(self, p, sc): return None
        def save_run_platform(self, *a, **k): pass
        def save_last_run_platform(self, *a, **k): pass
        def get_setting(self, k, d=None): return d
    monkeypatch.setattr(service, "Store", lambda *a, **k: S())


def test_default_skips_paid_keyword_search(monkeypatch):
    _seeds(monkeypatch, [{"kind": "account", "value": "@a"}, {"kind": "ko", "value": "살림꿀팁"}])
    called = {"acc": 0, "paid": 0}
    monkeypatch.setattr(service, "tt_fetch", lambda acc: (called.__setitem__("acc", called["acc"] + 1), [])[1])
    monkeypatch.setattr(service, "tt_search_full",
                        lambda kw, max_results=None: (called.__setitem__("paid", called["paid"] + 1), [])[1])
    monkeypatch.setattr(service, "build_tiktok_items", lambda *a, **k: [])
    monkeypatch.setattr(service, "apply_grades", lambda items: None)
    service._collect_tiktok()
    assert called["acc"] == 1          # 무료 계정 경로는 돈다
    assert called["paid"] == 0         # 유료 키워드 경로는 안 돈다(기본)


def test_opt_in_runs_paid_keyword_search(monkeypatch):
    _seeds(monkeypatch, [{"kind": "ko", "value": "살림꿀팁"}])
    called = {"paid": 0}
    monkeypatch.setattr(service, "tt_fetch", lambda acc: [])
    monkeypatch.setattr(service, "tt_search_full",
                        lambda kw, max_results=None: (called.__setitem__("paid", called["paid"] + 1), [])[1])
    monkeypatch.setattr(service, "build_tiktok_items", lambda *a, **k: [])
    monkeypatch.setattr(service, "apply_grades", lambda items: None)
    service._collect_tiktok(include_paid_keywords=True)
    assert called["paid"] == 1         # 명시 옵션일 때만 유료 경로
```

- [ ] **Step 1: 실패 테스트 작성**

# shopping_shorts/tests/test_tiktok_client_retry.py
"""yt-dlp 채널목록은 간헐적으로 빈 응답을 준다(2026-07-24 실측: --playlist-end 1에서 entries=None,
3건은 정상). 한 번 비었다고 그 채널을 버리면 랭킹에 구멍이 나므로 재시도한다."""
from shopping_shorts import tiktok_client as tc


def test_retries_on_empty_then_succeeds(monkeypatch):
    calls = {"n": 0}
    def fake_run(*a, **k):
        calls["n"] += 1
        class R:
            returncode = 0
            stdout = '{"entries": []}' if calls["n"] == 1 else '{"entries": [{"id": "x"}]}'
            stderr = ""
        return R()
    monkeypatch.setattr(tc.subprocess, "run", fake_run)
    monkeypatch.setattr(tc.time, "sleep", lambda s: None)
    out = tc.fetch_account_videos("@a")
    assert calls["n"] == 2            # 첫 빈 응답 → 재시도
    assert len(out) == 1


def test_gives_up_after_retries_returns_empty(monkeypatch):
    calls = {"n": 0}
    def fake_run(*a, **k):
        calls["n"] += 1
        class R:
            returncode = 0
            stdout = '{"entries": []}'
            stderr = ""
        return R()
    monkeypatch.setattr(tc.subprocess, "run", fake_run)
    monkeypatch.setattr(tc.time, "sleep", lambda s: None)
    out = tc.fetch_account_videos("@a")
    assert out == []                  # 끝내 비면 빈 리스트(그 채널만 스킵, 전체는 계속)
    assert calls["n"] <= 3            # 무한 재시도 금지
```

### Task 3: 플랫폼 토글 노출 (인스타·유튜브·틱톡) + 플랫폼별 안내문구

**Interfaces:**

- [ ] **Step 1: 토글 노출**

`#platformTabs`의 `display:none`을 제거해 되살린다(마크업·핸들러는 이미 존재, 주석이 "display:none만 지우면 된다"고 명시). 리디자인된 상단과 어울리게 `.ctypes/.ctype` 기존 네온 칩 스타일을 그대로 쓴다.

- [ ] **Step 2: 플랫폼별 안내문구 (오독 방지)**

지금 `.desc`는 **인스타 기준으로 "443개 채널의 48시간 이내"** 라고 고정돼 있는데, 틱톡·유튜브는 **시드 계정/키워드 + 14일 창**이라 그대로 두면 거짓 설명이 된다. `switchPlatform()`에서 `.desc`를 플랫폼별로 갈아끼운다:
```javascript
const DESC_BY_PLATFORM = {
  instagram: '등록한 레퍼런스 채널의 <b>48시간</b> 이내 릴스를 강도별로 랭킹합니다.',
  tiktok:    '등록한 <b>시드 계정</b>의 최근 <b>14일</b> 숏폼을 조회수 기반 강도로 랭킹합니다. (무료 수집)',
  youtube:   '<b>키워드 시드</b>로 발굴한 최근 <b>14일</b> Shorts를 조회수 기반 강도로 랭킹합니다.',
};
```
`switchPlatform` 안에서 `document.querySelector('.desc').innerHTML = DESC_BY_PLATFORM[p] || ...` 로 갱신(기존 로직은 건드리지 말고 한 줄 추가).

- [ ] **Step 3: 지표 툴팁 플랫폼별 표기**

탭(전체/속도/가속/참여밀도)의 `title` 속성이 **댓글 기준**으로 고정돼 있다(인스타 기준). 틱톡·유튜브는 조회수 기반이므로, `switchPlatform`에서 탭 title도 갈아끼운다:
```javascript
const TAB_TIP = {
  instagram: {speed:'댓글수 ÷ 경과시간', density:'댓글수 ÷ 팔로워수'},
  tiktok:    {speed:'조회수 ÷ 경과시간', density:'(좋아요+댓글) ÷ 조회수 = 반응률'},
  youtube:   {speed:'조회수 ÷ 경과시간', density:'(좋아요+댓글) ÷ 조회수 = 반응률'},
};
```
해당 `.tab[data-tab="speed"|"density"]`의 title만 갱신(라벨 텍스트는 그대로 — 같은 이름이 다른 뜻이면 툴팁으로 알린다).

`node --version` 후 `<script>` 추출해 `node --check`. `grep -n "DESC_BY_PLATFORM\|TAB_TIP\|platformTabs"`로 참조 정합 확인. Python `html.parser` 파싱 0 에러. **브라우저 미검증 명시**(배포 후 그라운딩).
