# 썸네일프리셋 — 핸드오프

## 2026-09-02 · 만든 썸네일을 프리셋으로 저장

사장님 요청: "썸네일 만들어진것 프리셋으로 저장하는것 만들어줘.
자리는 썸네일 단계에서 좌측 썸네일 미리보기쪽 썸네일 생성 바로 아래"

### 무엇을 만들었나

7단계(썸네일) 좌측 미리보기 칼럼, **[썸네일 생성] 버튼 바로 아래**에
"🖼 내 프리셋" 칸을 신설했다. 지금 만든 썸네일의 **구성**(글자·스티커·도형·배지)을
담아두고, 다음 영상에서 카드 한 번 누르면 그대로 얹힌다.

### 왜 이렇게 정했나 (사장님 확인함)

- **배경은 안 담는다.** 프리셋을 쓰는 곳은 **다른 영상**이라, 그 영상에서 고른
  배경 프레임 위에 얹혀야 한다. 배경까지 담으면 남의 영상 장면이 딸려온다.
- **문구는 담는다.** 얹은 뒤 문구만 고치면 끝나게 — 얹자마자 글자 레이어가
  선택된 상태로 둔다.
- **서버 저장(계정별).** PC에서 담고 모바일에서 꺼내 쓴다. localStorage면
  기기가 바뀌면 사라진다.

### ★기존 '🖼 프리셋'(HC_PRESETS)과 다른 물건이다 — 섞지 마라

같은 7단계 안에 이름이 비슷한 칸이 둘이다. **판단을 한쪽에만 둔다(0순위-B)**:

| | 위쪽 `#thumbPresets` (기존) | 아래쪽 `#myThumbPresets` (신설) |
|---|---|---|
| 대상 | 고른 **글자 레이어 1개**의 색·스타일 | **화면 구성 전체**(레이어 배열) |
| 출처 | 코드에 박힌 HC_PRESETS | 사장님이 담은 것(DB) |
| 함수 | `applyThumbPreset(i)` | `applyMyThumbPreset(pid)` |

### 파일

| 파일 | 무엇 |
|---|---|
| `shopping_shorts/store.py` | `thumb_presets` 테이블 + CRUD 5종. customer_id를 WHERE에 항상 낀다 |
| `shopping_shorts/app.py` | 라우트 5개(`/api/produce/thumb/presets` 계열) + `_THUMB_PRESET_DIR` |
| `shopping_shorts/static/produce.html` | 생성 버튼 아래 UI + JS 6함수(`saveThumbPreset` 등) |

- 그림은 `data/thumb_presets/`에 **따로** 둔다 — job 폴더는 disk_cleanup이 지우는데
  프리셋은 그 job보다 오래 살아야 한다.
- 파일명은 서버가 uuid로 부여(경로순회 차단). 지우면 그림도 같이 치운다.
- 1인당 60개 상한.

### 실측 검증 (문자열 검색 아님 — 실제로 돌렸다)

```
Store CRUD        add/list/get/rename/delete + 남의 계정(cid 다름) 전부 차단 확인
라우트 등록       5개 전부 등록 확인(GET·POST·POST rename·DELETE·GET image)
HTTP 왕복         담기→목록→그림200→이름변경→삭제→그림404(고아 PNG 안 남음)
가드 7종          빈layers·dict layers·깨진json·빈이름·PNG아님·경로순회·없는id → 전부 400/404
테넌시            cid999 프리셋이 내 목록에 안 뜨고, rename/delete 시도 404, 원본 살아있음
상한              60개에서 400 + 안내문구
JS 문법           node --check rc=0 (page의 모든 <script> 이어붙여)
renderMyThumbPresets  실제 실행 — 빈안내·카드2개·XSS이스케이프·그림/폴백·stopPropagation 4개
applyMyThumbPreset    실제 실행 — 깊은복사(중첩까지) 원본 무오염, 재적용 복원, 없는id 안전
```
