## ★원인 확정 — 「말 밀도」 창이 모델의 실제 출력과 안 맞는다

### 증거 1. 실패 사례의 tries는 **전부 말 밀도**다
요청 2안 → 1안이 된 작업에서 **살아남은 안**의 4회 시도 기록(실측):
```
e2cab3730aa1 사회증거형   257 → 210 → 218 → 202(재단)  전부 말 밀도 실패
608fa54a9f77 단정 명령형  245 → 219 → 225 → 208(재단)  전부 말 밀도 실패
ae6638e0dcbf 물건 발견형  205 → 222 → 210 → 203(재단)  전부 말 밀도 실패
0f8195864ed9 가족갈등반전  218 → 198 → 196 → 188(재단)  전부 말 밀도 실패
```
**살아남은 안조차 게이트를 못 넘고 fail-open으로 나간다.** 옆 스타일은 같은 조건에서 빈손이 된다.

### 증거 2. 모델은 창을 구조적으로 넘는다
저장된 안 764개의 **첫 시도** 글자수: 중앙 **203자** / p75 225 / 최대 314.
**창 상한 185 초과가 522/764 = 68%.**
→ 창(129~185)이 모델이 실제로 쓰는 길이(중앙 203)와 안 맞는다.

### 증거 3. 실패 사유는 말 밀도가 압도적
저장된 안 764개의 재시도 실패 사유:
| 사유 | 횟수 |
|---|---|
| **말 밀도** | **1,521회** |
| 고조 심화 | 291회 |
| 수치 근거 | 152회 |
| 말끝 | 112회 |
| 사실 근거 | 59회 |

### 증거 4. 다른 원인들은 전부 **배제**됐다
- **키 소진/429**: 9/15 이후 로그 **0건** → 키 문제 아님
- **게이트 정식 반려**(`[script_gate] ... 반려`): 하루 **5건**뿐(소재 일치) → 치명 반려 아님
- **스타일 순서**: 첫번째 생존 19건 vs 두번째 생존 16건 → **순서와 무관**
- **grounded 차이**: 관리자도 1안 비율 59%(고객 76%) → 주원인 아님
- **재료·스타일 조합**: 실패 사례 재료로 재현 시도 → **2/2 나옴**(그날 조건 문제)

## ★2층 — 왜 8번이나 못 찾았나: **사유가 버려진다**

`app.py:3630`의 `_gen_reasons`는 **0안일 때만** 화면으로 나간다:
```python
if not _styled:
    return JSONResponse(status_code=502, content={
        "ok": False, "error": _gen_fail_message(_gen_reasons, _asm_why),
        "reasons": _gen_reasons})      # ← 0안일 때만
# 1안이면 그대로 아래로 내려가며 _gen_reasons가 **버려진다**
```
`generate_by_styles`는 빈손 스타일마다 사유를 `reasons`에 담아 돌려주는데
(`script_generate.py:1419` — kind/keys/detail), **1안일 땐 아무 데도 안 남기고 200 OK**를 준다.
→ 서버는 어느 스타일이 왜 빠졌는지 **알고 있으면서 말하지 않는다.**
   그래서 매번 처음부터 조사했고 매번 다른 답이 나왔다(08-17 이후 8번 재발).

### 치명 검사 가설도 기각됐다
`best`는 `fatal_fail`이 없을 때만 채워지므로 치명 실패 시 스타일이 사라질 수 있다.
그러나 실측: **1안으로 끝난 39건 중 치명흔적 8% vs 2안 나온 220건 중 10%** — 차이 없다.
또 `사실 근거`는 `FATAL_CHECKS`엔 있지만 `active_fatal_checks()`엔 없어(스위치로 꺼짐)
59회 실패해도 안 죽인다. 실제 active = 소재 일치 · 주제 단일성 · 재료 밖 판매처.
