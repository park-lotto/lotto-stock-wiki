### ★실측 원인 — 컴퓨터 문제가 아니었다

`mousedown`은 멀쩡했다. 문제는 `move`의 끝이다:

```
move → frUpdate() → renderTemplatePreview() → el.src = frameUrl(...)
                 └→ saveHeadcopy()          → POST /api/produce/mix/settings
```

마우스는 한 번 끄는 동안 `mousemove`를 수십~수백 번 쏜다. 그래서 **1px마다**
frame.png를 새 URL로 다시 받았고, 브라우저는 진행 중이던 요청을 버리고 다시
시작한다 → 끄는 내내 그림이 **한 번도 안 앉는다**. 손잡이는 실제로 움직이고
있었는데 배경 그림이 안 따라와 "이동이 안 된다"로 보였다.
= 사장님이 뒤에 말한 "너무 느리게 로딩"과 **같은 원인 하나**다.

`saveHeadcopy`엔 디바운스가 없어 POST도 픽셀마다 나갔다(같은 파일 `saveWork`는
1초 디바운스를 쓰는데 이쪽만 빠져 있었다).

### 고친 것 (produce.html)

- `bindFrameHandle`의 `move`: 서버를 때리는 `frUpdate()`를 뺐다. 대신 입력칸 값 ·
  라벨 · `syncFrameHandles()`(손잡이 위치)만 즉시 갱신 → 손끝을 따라온다.
  실제 반영(`frUpdate`)은 `up`에서 **딱 한 번**.
- `saveHeadcopy(now)` 400ms 디바운스 + `_pushHeadcopy()` 분리.
- ★**짝 보정**: `renderFinal`의 `await saveHeadcopy()`는 디바운스에 걸리면 안 기다리고
  렌더가 먼저 출발해 **옛 설정으로 구워진다** → `saveHeadcopy(true)`로 즉시 저장.
  (디바운스를 넣을 때 반드시 같이 봐야 하는 자리다)
- 모바일: `move`에서 `preventDefault` — 끌 때 화면이 같이 스크롤되는 것 방지.

### ⚠️ 다음 세션이 알아야 할 것

- **이 저장소 pytest는 `pytest-randomly`로 순서가 매번 섞인다.** 랜덤 순서에선
  내 변경과 무관한 테스트가 간헐 실패한다(실측: `test_find_frame_rejects_path_traversal`,
  `test_mix_accepts_youtube_url`). 둘 다 단독·고정순서에선 통과하고, 내가 만진 건
  `produce.html`(프론트)뿐이라 `mix_pipeline.py`(파이썬·완전 mock)와 닿지 않는다.
  → **게이트가 빨갛다고 바로 내 탓이라 보지 말고, 고정순서(`-p no:randomly`)로 갈라라.**
- ★`finish`는 **exit 0이어도 병합이 안 됐을 수 있다**(실제로 이번에 그랬다).
  판정은 반드시 `git branch -r --contains <커밋>`.
