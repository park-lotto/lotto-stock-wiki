## ✅ 실렌더 grounding — 부분 완료 (2026-07-15, 컨트롤러 직접 관측)

**① ffmpeg 실구동 + 규격 = 통과.** 1920x1080/30fps 소스를 실제로 잘라 `ffprobe`로 찍음:
`width=720 / height=1280 / codec=h264 / pix_fmt=yuv420p / r_frame_rate=30/1` — 페이즈2 `concat -c copy` 호환.
crop이 실제로 동작(가로 소스를 세로로 통일). 길이도 유효구간(1.0~3.5) 요청 시 **정확히 2.5초**.
(구간이 소스 끝을 넘으면 조용히 짧아짐 — 소스 5초에 3.0~5.5 요청 시 2.015초. UI는 재생중 영상에서
찍으므로 실사용에선 발생 안 하지만, 알아둘 것.)

**② Gemini autotag 실호출 = 통과.** 캐스케이드 키 14개 살아있음(`pipeline.atoms.key_vault`).
실제 이미지를 넣어 실응답 받음 — 스키마 5키 완비, `role`이 통제어휘 안.
**설계의 심장이 적대적 조건에서 버팀**: 일부러 거짓 맥락(`category="레시피"`, `caption="이거 한 스푼이면 끝"`)을
넣었는데 이미지엔 숟가락도 요리도 없었다. Gemini는 **낚이지 않고 보이는 것만 서술**:
> "정장을 입은 중년 남성이 검은 배경 앞에서 손을 주머니에 넣고 미소를 지으며 서 있고 주변에 금융 그래프와 차트 아이콘들이 떠 있다."
> subject="중년의 남성 비즈니스맨" / role="훅" / tone="전문적인·자신감 있는"

사람이 눈으로 본 것과 대조해 정확·무환각 확인. "보이는 것만, 추측·해석 금지" 규칙이 작동.

**③ 중요 부수확인**: 이 PC엔 `SHORTS_GEMINI_KEYS`(좁은 단일 키풀)가 **0개**다.
계획서가 `_vault_call`의 캐스케이드를 쓰라고 못박지 않았으면 autotag가 로컬에서 아예 안 돌았다.

**④ "가루↔액체↔세제" 유사물 변별 = 통과 (2026-07-15 추가 관측).** 서버의 도서관 영구보관 실 릴스
2편을 내려받아(`wiki_media/`, 읽기전용 scp) 실제로 잘라 태깅했다. 스펙 §1.1이 지목한 바로 그 함정:

| 영상 | 사람이 본 것 | AI `scene_desc` / `subject` |
|---|---|---|
| 감자전(레시피, "부침가루 넣지 마세요") | 팬에 채썬 감자, 손이 뒤집개로 누름 | "프라이팬에 담긴 채 썰린 감자를 뒤집개로 꾹꾹 눌러 펴고 있다" / **"채 썰린 감자"** |
| 생활용품 | 흰 대야에 **뿌연 흰 물**, 장갑 낀 손이 젓는 중 | "흰색 싱크대 볼에 담긴 물을 휘젓고 있다" / **"물, 투명한 비닐 장갑"** |

둘 다 사람 관측과 일치. **"흰 것"으로 뭉뚱그리면 세제↔음식이 섞이는 정확한 상황인데 소재가 완전히
갈렸다**(채 썰린 감자 vs 물). 게다가 AI는 뿌연 물을 보고 **"세제"라고 추측하지 않았다** — 화면에
세제 자체는 안 보이므로 "보이는 것만·추측 금지" 규칙에 충실. `category`(레시피/생활용품)까지
더하면 페이즈2 §6 1차 필터가 이 둘을 섞을 수 없다.
(실 릴스 원본은 이미 720x1280/30fps — 인스타 릴스 표준. 잘린 클립도 동일 규격 유지 확인.)

## ⚠️ 다른 트랙·나중으로 넘긴 것 (여기서 하지 말 것)

1. **SSRF는 이 저장소의 계통적 문제 — 별도 트랙 필요.**
   `/api/scene/save/prepare`엔 1차 방어(scheme 검사 + 사설/루프백/링크로컬 IP 차단)를 넣었지만, `extract_script_by_url` 등 **기존 엔드포인트에 같은 구멍이 그대로** 있다. `/api/thumb`(app.py:1385-1390)만 호스트 allowlist로 막힌 상태 = 방어가 라우트마다 제각각.
   넣은 1차 방어도 **불완전**: TOCTOU, 리다이렉트 추적(302→내부망), IPv6 매핑 우회가 남는다. 서버가 AWS Lightsail이라 `169.254.169.254` 메타데이터가 실제 표적.
   → 공용 헬퍼로 뽑아 전 엔드포인트 일괄 적용 + `allow_redirects=False`.

2. **페이즈2로 넘긴 것** (계획서 "페이즈2로 미루는 것" 섹션에 상세):
   - AI 매칭·자동배치(`match_scene_assets`, `mix_pipeline`의 asset_match 스텝)
   - 렌더 4처리(replace/cutaway/sfx/overlay) — **cutaway 자막 t0 싱크가 최대 리스크**. 비트의 실제 화면 길이는 `primary.end - primary.start`가 아니라 나레이션에서 재계산된 `target_seconds`(`edit_plan.py:365-367`, 4.5자/초)임을 반드시 반영.
   - **오디오 규격 미고정**: `make_clip`과 `video_assemble` **둘 다** `-ar`/`-ac`가 없어 소스값이 상속된다. `concat -c copy`는 오디오 파라미터도 일치해야 안전 → **한쪽만 고치면 오히려 어긋난다. 양쪽 함께** + 실파일 concat 스모크로 먼저 재현할 것.
   - 믹스 검수 배치 패널
   - **영상제작소(produce) 저장 다리** — `produce.html` 대본믹스 통합 트랙이 끝난 뒤

## 📌 이 트랙에서 얻은 교훈

- **서브에이전트 보고를 그대로 믿으면 안 된다.** Task4 수정 때 `asset_type` 검증을 지시했는데 반영 안 된 채 "이탈 없음" 보고가 올라왔다. 컨트롤러가 직접 프로브를 날려서야 발견(악성 문자열이 200으로 저장됨). 보고는 반드시 실행으로 검증할 것.
- **파일을 파이썬 스크립트로 통째 재작성하지 말 것.** Windows에서 LF→CRLF로 바뀌어 phantom-modified가 되고 공유 워킹트리의 다른 세션 pull을 막는다. Edit로 부분 수정만.
- **`git commit -- <경로> -m "msg"`는 실패한다.** `--` 뒤는 전부 pathspec이라 `-m`과 메시지를 파일명으로 읽는다(`error: pathspec '-m' did not match`). **`-m`이 먼저, `--`가 마지막.**
- `.git/hooks/post-commit`이 무조건 `git push`다 → **커밋 = 즉시 라이브 배포.** `app.py`를 건드리는 커밋은 반드시 `python -c "from shopping_shorts import app"` 게이트를 먼저 통과시킬 것.
