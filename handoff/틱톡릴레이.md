# 틱톡릴레이 — 레퍼런스 발굴 자동화

> 2026-09-08 (회사PC) · 라이브 반영 완료

## 오늘 한 것 (전부 라이브)

### 1. 틱톡 자동검색이 늘 0건이던 원인 — 헤드리스·서버 환경 차단

사장님 제보: *"틱톡은 아까 파이어폭스로 했으면 자동검색으로 나와야 하는거 아니냐"*

체인(`kw_search._CHAIN`)에는 `pw_tiktok`이 들어 있는데 **항상 0건**이었다.
4가지 환경을 갈라 재서 원인을 확정했다:

| 환경 | 결과 |
|---|---|
| 내 PC + 창 띄움 | **영상 24개 정상** |
| 내 PC + 헤드리스 | 0개 |
| 서버 + 창(xvfb) + 프록시 | 0개 |
| 서버 + 창(xvfb) + 직결 | 0개 |

세션·프록시·IP는 **전부 멀쩡**했다(로그인 상태 확인, 쿠키 28개 생존).
틱톡이 헤드리스와 서버 환경 자체를 걸러낸다. 화면에는
`죄송합니다. 서버에서 문제가 발생했습니다`가 뜬다.

⚠️ `pw_tiktok`이 `except Exception: return []`로 원인을 삼켜서, 겉으로는
"세션이 없나?"로만 보였다. 도우인에서 겪은 것과 같은 함정.

**해결**: 쿠팡 릴레이 큐를 그대로 탄다(`kind="tiktok"`). 큐·인증·롱폴링·
타임아웃을 다시 적지 않았고(0순위-B), **쿠팡도우미 창 하나**가 쿠팡과 틱톡을
함께 처리한다.

- `kw_backends._tiktok_via_relay` — **None과 []를 갈라서** 돌려준다.
  섞으면 "릴레이가 없어 0건"과 "정말 0건"이 구별되지 않는다.
- 릴레이가 꺼져 있으면 종전 경로로 내려가 0건(회귀 없음).
- 창은 화면 밖(`--window-position=-32000,-32000`)이라 안 보인다.
- 검색 카드에는 **조회수와 링크뿐**(DOM 실측) → 계정은 주소에서 뽑는다.

**전 구간 실측 완료**: 사장님이 「자동 모으기」를 누르자 릴레이 로그에
`[틱톡] 오타마톤 … → [결과] 12건`, 이어서 `[틱톡] Otamatone …`(영어 회차).

### 2. 세션이 조용히 죽지 않게

사장님: *"세션이 끊기면 어쩌나 주기적으로"*

- `_tiktok_session_health()` — 로그인 쿠키(`sessionid`·`sid_tt`) 남은 일수
- 죽었으면 **브라우저를 아예 안 띄운다**(어차피 0건, 시간만 버린다)
- 7일 미만이면 미리 경고, **도우미를 켤 때도** 한 번 알린다
- 갱신: `py tools/tiktok_session_from_firefox.py`
- 실측(09-08): `sessionid`·`sid_tt` **180일**(2027-03-07), `ttwid` 365일, `msToken` 10일

### 3. 「⚡ 5곳 전부」 — 개별 클릭을 5분의 1로

사장님: *"언어 하나 고르고 틱톡 인스타 찾고 키워드별로 또 해야되니 시간이 엄청 걸린다"*

검색어 줄에서 한 번 누르면 샤오홍슈·도우인·틱톡·인스타·핀터레스트가
고른 언어로 한꺼번에 열린다. 팝업이 막히면 **몇 개 열렸는지 세어 안내**한다.

## ⏭ 다음 할 일

### A. 샤오홍슈 세션 (사장님이 고른 우선순위)

**진행하다 막힌 지점** — 사장님이 파이어폭스로 로그인을 시도했으나 쿠키를 뽑아
확인하니 여전히 미로그인이었다:

- `web_session` 값이 **38자**(로그인 세션치고 짧다 = 게스트 쿠키로 보인다)
- 창을 띄워 접속하면 `登录后查看搜索结果`(로그인 후 검색결과 보기)
- 휴대폰 번호는 **`+86` 중국 번호만** 받는다 → **QR(`扫码`)로 폰 앱 스캔**이 유일한 길

★그리고 **로그인해도 서버에서는 못 쓸 가능성이 크다**:
헤드리스로 접속하면 `安全限制 / IP存在风险`(IP 위험)으로 통째 차단된다(실측).
즉 샤오홍슈도 **틱톡과 똑같이 PC 릴레이**로 가야 한다 —
`scripts/coupang_relay_client.py`에 `kind="xiaohongshu"` 분기 하나만 더하면 된다.

⚠️ 세션 유무를 볼 때 **변수 이름을 확인하고 보라**. 오늘 `XHS_SESSION_PATH`로
물어 "세션 없음"이라고 오판했다 — 진짜 이름은 `XIAOHONGSHU_SESSION_PATH`이고
서버에 파일이 **있었다**(`/home/ubuntu/rednote_session.json`, 08-17).

### B. 도우인

세션 파일이 **정말로 없다**(`/home/ubuntu/douyin_session.json` 부재 — 실측).
QR 로그인이 필요하고, 없으면 Apify 유료뿐이다.

### C. 인스타

프록시 GB 과금이라 `KW_SEARCH_INSTAGRAM=0`으로 꺼져 있다.
**PC 릴레이로 돌리면 비용 0**이 된다(틱톡과 같은 길). 세션은 이미 있다.

### D. 자동 모으기가 도는 곳 (현재)

유튜브 · 핀터레스트 · 네이버클립 · **틱톡**(오늘 살림) = 4곳, 전부 무료.
샤오홍슈 · 도우인 · 인스타가 합류하면 손으로 누를 일이 거의 없어진다.

## 릴레이 켜는 법

`쿠팡도우미.bat` 하나면 쿠팡·틱톡 둘 다 돈다.
`COUPANG_RELAY_TOKEN`이 서버 `/etc/shopping-shorts.env`와 같아야 한다.
틱톡 세션 경로는 `TIKTOK_SESSION_PATH`(기본: 프로젝트 루트 `tiktok_session.json`).
