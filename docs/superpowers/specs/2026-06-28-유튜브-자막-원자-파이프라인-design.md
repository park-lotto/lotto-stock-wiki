# 유튜브 자막 → 원자 + 발언카드 파이프라인 설계 (2026-06-28)

## 배경 / 문제
현재 유튜브 크롤은 Gemini가 영상 URL을 보고 **요약만** 생성한다.
- 전체 자막 원문 저장 안 함 / 타임스탬프 없음
- 요약본으로 원자를 뽑으면 손실된 2차 가공물에서 추출 → 품질 미달
- 영상 제작에 필요한 "발언 시간·딥링크·캡쳐" 불가

## 사용자 워크플로우 (목표)
주제(예: "지금 반도체 고점인가") → 여러 전문가 영상에서 **누가 무슨 핵심 발언을 했는지**
인용(90%) + 내 인사이트(10%)로 영상 제작. + 원자DB 분석용 추출도 병행.

## 전체 아키텍처
```
[서버 크롤] 영상 → 타임스탬프 자막 원문 + 요약(미리보기)   ← A
   ↓ 받아오기
[로컬] 자막 원문 → atomizer.py → 원자DB                  ← B
                → 발언카드(화자·인용·시간·딥링크)         ← C
                → /영상기획 {주제}                        ← C 활용
[선택] 발언 시간 → ffmpeg 프레임 캡쳐 (ffmpeg 설치 필요)  ← D
```
- 추출 위치: **로컬** (atomizer·원자DB가 로컬). 서버는 자막 원문만 저장.

## A단계 (완료 — 피벗됨)
> ⚠️ **피벗**: yt-dlp 자막은 서버(데이터센터 IP)에서 YouTube 봇차단("Sign in to confirm")으로 **불가**.
> → **Gemini(영상 직접 시청)에게 타임스탬프 발언을 받는 방식**으로 변경. 차단 없음 + 더 정확.
> 변경 파일: `processors/gemini_summarizer.py` (프롬프트만). save_youtube/yt-dlp 원복.
> 결과: `## 주요 발언`이 `- [mm:ss] 화자: 발언원문` 8~16개로 채워짐 (검증 완료 2026-06-28).

**목표(원안)**: 유튜브 크롤 시 타임스탬프 있는 전체 자막을 md에 저장.

**변경 (서버 `crawlers/youtube_crawler.py`, `processors/md_writer.py`)**
- `_get_subtitle` (yt-dlp VTT, ko→en, 자동자막) 재활용 → 타임스탬프 보존판 `_get_transcript_ts()` 추가
- VTT 파싱: `[mm:ss] 대사` 한 줄씩, 중복 제거 (정밀 — 발언→시간 매핑 정확)
- `run()`: 영상마다 자막 받아 `transcript`로 전달 (Gemini 요약은 미리보기로 유지)
- `save_youtube(...)`에 `transcript` 인자 추가 → md에 `## 전체 자막 (타임스탬프)` 섹션

**저장 포맷 (md)**
```
## 핵심 요약
{Gemini 요약 — 미리보기}
## 전체 자막 (타임스탬프)
[00:00] ...
[01:23] SK하이닉스는 ADR로 ...
```

**엣지/폴백**: 자막 없는 영상 → "자막 없음" 표기 + 기존 요약만. 크롤 안 깨짐.
**검증**: moneyinthetrap 영상 크롤 → md에 `[시간] 대사` 확인 → 받아오기 → 로컬 확인.

## B단계 (로컬 원자)
받아온 자막 원문을 atomizer.py로 원자화. (화자·stance·숫자 보강 검토)

## C단계 (로컬 발언카드 + 영상기획)
- 발언카드: speaker / 입장 / 핵심발언(인용) / 근거 / 시간 / 딥링크(`&t=Ns`)
- `/영상기획 {주제}`: 주제별 발언카드 모아 [화자|입장|인용|근거] 표 + 70/20/10 대본골격

## D단계 (선택)
서버 ffmpeg 설치 → 발언 시간으로 프레임 캡쳐 (선택 발언만).
