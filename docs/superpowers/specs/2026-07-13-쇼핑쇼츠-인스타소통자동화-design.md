# 쇼핑쇼츠 인스타 소통 — 댓글 자동채우기 버튼 (유저스크립트) — Design

**작성일**: 2026-07-13
**작업 폴더**: `shopping_shorts/`
**관련 기능**: 기능 ② 소통 큐 확장 (기존 `outreach.py`·`outreach.html` 위에 얹음)

---

## 목표

소통 큐에서 **"게시물 열기 + 댓글 자동채우기"** 버튼 하나를 누르면, 열린 인스타그램 게시물 페이지의 **댓글 입력창에 미리 생성된 댓글이 자동으로 채워지는** 도구를 만든다. **전송(게시)과 팔로우는 사용자가 직접 클릭**한다. 사용자가 매번 붙여넣기하는 수고만 없앤다.

---

## 왜 이 범위인가 (탐지 위험 분석 결과)

설계 과정에서 봇 탐지 위험을 축별로 검토한 결론:

| 탐지 축 | 이 설계의 처리 |
|---------|----------------|
| **isTrusted(이벤트 신뢰)** | 결정적 행동인 **전송·팔로우를 사용자가 진짜 클릭** → `isTrusted=true`. 완전 해결. |
| **합성 입력(자동채우기)** | 댓글칸 자동채우기는 **Ctrl+V 붙여넣기와 행동적으로 동일**. "텍스트가 한 번에 나타남"은 사람이 늘 하는 정상 행동이라 봇 신호 아님. |
| **자동화 지문** | 유저스크립트는 사용자의 실제 크롬·쿠키·기기지문에서 동작. `navigator.webdriver`·CDP 흔적 없음. |
| **계정 행동 패턴**(볼륨·타겟·댓글유사성) | 사용자가 매 건 눈으로 보고 직접 전송·팔로우 → **수동 소통과 사실상 동일한 위험**. |

**결론**: 자동화되는 부분은 "댓글칸에 텍스트 채우기" 하나뿐이고, 이는 붙여넣기와 구분 불가하다. 남는 위험은 **수동으로 해도 존재하는 기본 위험(모르는 계정에 댓글·팔로우를 과다·고속으로 하는 볼륨/패턴)**뿐이며, 이는 사용자의 소통량 판단에 맡긴다(스크립트가 강제하지 않음).

### 대안 기각 근거

- **완전 자동(타이핑→게시→팔로우 전부 유저스크립트)**: 게시·팔로우 클릭이 `isTrusted=false` 합성 이벤트라 이벤트 층 탐지 여지. 기각.
- **Playwright**: CDP로 트리거하는 이벤트는 `isTrusted=true`지만, `navigator.webdriver`·CDP 자동화 지문을 새로 떠안고(인스타가 전용 탐지), 별도 브라우저=세션 신뢰 저하, 반자동 UX 붕괴(백엔드가 딴 창 조종→무인 배치로 흐름). 한 축 얻고 두 축 잃는 측면 이동이라 기각.
- **동일출처정책**: `outreach.html`(localhost) JS는 열린 instagram.com 탭을 제어 불가. 따라서 인스타 페이지 위에서 도는 코드(유저스크립트)가 반드시 필요.

## 아키텍처

```
소통큐(localhost)  ──window.open(url#페이로드)──▶  instagram.com 탭
                                                      │
                                       Tampermonkey 유저스크립트가 해시 감지
                                                      │
                                    댓글 입력창 탐색·포커스 → 댓글 자동채우기
                                                      │
                                   "채워둠 — 확인 후 직접 전송·팔로우" 토스트
                                                      │
                                    (사용자가 직접 전송·팔로우 클릭)
```

두 조각:

1. **소통큐 프론트 (`outreach.html`)** — `게시물 열기+복사` 버튼을 **`게시물 열기 + 댓글 채우기`**로 바꿔, 선택 댓글 + shortcode를 URL 해시 페이로드로 인코딩해 인스타 탭을 연다. (클립보드 복사는 폴백으로 유지)
2. **유저스크립트 (`insta_fill_comment.user.js`)** — instagram.com 게시물/릴스 페이지에서만 작동. 해시 페이로드를 디코딩해 댓글칸을 채우고 **멈춘다**. 전송·팔로우는 건드리지 않는다.

## 컴포넌트 상세

### C1. 페이로드 전달 (소통큐 → 인스타)

`outreach.html`의 `openAndCopy(sc)` 수정:

- 선택 댓글(`SELECTED[sc]` 또는 첫 draft) + shortcode를 JSON으로 인코딩:
  `payload = { c: 댓글텍스트, sc: shortcode }`
- `window.open(item.url + "#lotto_fill=" + encodeURIComponent(btoa(unescape(encodeURIComponent(JSON.stringify(payload))))))`
  - base64(UTF-8 안전) 인코딩으로 한글·이모지 안전 전달.
- 클립보드 복사는 **폴백 유지**(유저스크립트 미설치 시 기존 수동 붙여넣기 흐름 그대로).
- 버튼 라벨: `🔗 열기+댓글채우기`.

### C2. 유저스크립트 본체 (`insta_fill_comment.user.js`)

`@match https://www.instagram.com/*`. `@grant` 불필요(완료통보 안 함 — 완료표시는 기존 소통큐 `완료` 버튼 유지).

실행 순서:

1. **게이트**: URL이 `/p/{code}/` 또는 `/reel/{code}/` 패턴인지 확인. 아니면 종료.
2. **페이로드 파싱**: `location.hash`에서 `lotto_fill=` 추출·디코딩. 없으면 종료(평소 사용 무해). 파싱 실패 시 조용히 종료.
3. **중복 발사 가드**: 파싱 직후 해시를 즉시 소거(`history.replaceState`). 세션 플래그로 동일 shortcode 재실행 차단.
4. **댓글창 대기·탐색**: 댓글 입력창이 DOM에 나타날 때까지 짧게 폴링/`MutationObserver`(모달·지연 렌더 대비). 못 찾으면 에러 토스트 후 종료.
5. **채우기**: 댓글칸 포커스 → 네이티브 value setter + `InputEvent(inputType:'insertText')`로 텍스트 주입(React 인식). 붙여넣기와 동일하게 **한 번에** 채움.
6. **정지**: "댓글 채워둠 — 확인 후 **직접 전송·팔로우** 하세요" 토스트 표시하고 종료. **전송·팔로우 버튼은 절대 건드리지 않음.**

> 참고: 사용자가 직접 전송하므로 정교한 "사람처럼 타이핑" 엔진은 불필요(붙여넣기 = 정상). `HUMANLIKE_TYPING` 플래그를 남겨 원하면 한 글자씩 타이핑도 켤 수 있게 하되 **기본값 off**(단순 채우기).

### C3. CONFIG 블록 (셀렉터·플래그)

유저스크립트 최상단에 몰아둠. 인스타 DOM 변경 시 여기만 수선.

- 댓글창 셀렉터 후보(복수, 우선순위): `textarea[aria-label*="댓글"], textarea[aria-label*="comment"], div[contenteditable][role="textbox"]`.
- `HUMANLIKE_TYPING`(기본 **false**): true면 한 글자씩 랜덤 딜레이 타이핑, false면 즉시 채움.
- `COUNTDOWN_MS`(기본 0): 채우기 전 대기(0=즉시). 필요 시 취소 여지용.

## 데이터 흐름

```
소통큐 카드 클릭(열기+댓글채우기)
  └▶ openAndCopy: payload 인코딩 → 클립보드 복사(폴백) + window.open(url#payload)
       └▶ 인스타 탭 로드 → 유저스크립트
            ├ URL/해시 게이트 통과
            ├ payload 디코딩 → 해시 소거(중복가드)
            ├ 댓글창 대기·탐색·포커스
            ├ 댓글 텍스트 주입(붙여넣기 동일)
            └ "확인 후 직접 전송·팔로우" 토스트 → 종료
                 └▶ (사용자) 직접 전송·팔로우 클릭 → 소통큐에서 완료 버튼
```

## 에러 처리

| 상황 | 처리 |
|------|------|
| 해시 없음/오류 | 조용히 종료. 평소 인스타 사용 무영향 |
| 게시물/릴스 페이지 아님 | 종료 |
| 댓글창 못 찾음(폴링 타임아웃) | 에러 토스트 + 종료. 클립보드에 이미 복사돼 있어 수동 붙여넣기 폴백 가능 |
| 유저스크립트 미설치 | 기존 흐름(클립보드 복사 + 수동 붙여넣기)로 자연 폴백 |

## 테스트 전략

1. **순수 헬퍼**: 페이로드 인코딩/디코딩 함수(한글·이모지 라운드트립)는 분리해 콘솔/노드에서 검증.
2. **셀렉터 수동 검증**: 실제 인스타 게시물에서 댓글창 셀렉터가 정확히 잡히는지 콘솔 로그 확인.
3. **엔드투엔드 수동 1건**: 소통큐 버튼 → 인스타 탭 열림 → 댓글칸 자동 채워짐 확인 → 직접 전송·팔로우 → 정상. 새로고침 시 재채우기 없음(해시 소거) 확인.

> 유저스크립트는 실제 인스타 DOM·세션 의존이라 자동화 유닛테스트 한계. 위 수동 검증 + 헬퍼 유닛으로 커버.

## 완료 기준

- [ ] 소통큐 버튼이 `열기+댓글채우기`로 바뀌고, 인스타 탭을 해시 페이로드와 함께 연다.
- [ ] 유저스크립트 미설치 시 기존 클립보드 복사 + 수동 붙여넣기로 폴백.
- [ ] 유저스크립트 설치 시 인스타 게시물/릴스에서 댓글칸이 자동으로 채워짐(전송·팔로우는 자동 안 함).
- [ ] 새로고침·SPA 재렌더 시 재채우기 없음(해시 소거 가드).
- [ ] 해시 없이 인스타 사용 시 스크립트 무동작.
- [ ] README에 설치·사용법 + "전송·팔로우는 직접" + 소통량 리스크 경고 명시.

## 미결/향후 (이번 범위 밖)

- 전송·팔로우 자동화: 이번 범위에서 의도적으로 제외(isTrusted·행동패턴 위험). 필요 시 별도 검토.
- 소통량 자동 제한(하루 상한·쿨다운): 이번엔 사용자 수동 판단.
- 완료 자동통보(GM_xmlhttpRequest → /api/comment/done): 이번엔 기존 수동 완료버튼 유지. 후속 편의 기능.
