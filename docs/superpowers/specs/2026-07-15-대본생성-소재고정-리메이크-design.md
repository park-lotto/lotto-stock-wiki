# 대본생성 모드 재편 — "소재 고정 리메이크" 설계

- 작성일: 2026-07-15
- 대상: 쇼핑쇼츠 대본 즐겨찾기(도서관, `library.html`) 생성 모달 + `script_generate.py` + `app.py`
- 관련 워크플로우: 원본 영상 재사용(중복 회피 변형), 같은 소재 2영상 믹싱

---

## 1. 배경 / 문제

도서관에 저장한 S급 대본에서 "🎬 이 구조로 대본 생성"을 누르면 지금 두 모드가 섞여 있다:

- **모드 A "같은 주제로 신선하게 변주"** — 프롬프트가 `"내용은 새롭게 신선하게 변주"`라 지시 → **소재(내용)가 의도적으로 드리프트.**
- **모드 B "내 주제/제품으로 이식 (구조만 빌림)"** — 구조만 빌리고 사용자가 입력한 새 제품으로 갈아끼움.

두 모드 다 **소재를 바꿔버린다.** 그런데 운영자의 실제 워크플로우는:

1. **원본 영상 재사용 + 중복 회피**: 원본 영상으로 대본을 뽑고 → 그 **원본 영상 자체**를 순서 재배열·좌우반전·줌 등으로 변형해 "완전 새 영상"처럼 만든다. 장면은 **순서만** 바뀌지 내용이 교체되는 게 아니므로 → **대본 소재는 원본과 같아야** 화면과 결이 맞는다.
2. **같은 소재 2영상 믹싱**: 같은 소재의 두 영상 중 **좋은 쪽의 대본을 먼저 구성** → 그 대본으로 두 영상의 장면을 믹싱한다.

즉 이 기능이 뽑아야 할 대본은 "새 내용"이 아니라 **같은 소재를 표현만 새로(중복 회피) 리라이트한 것**이어야 한다. 현재 모드 A가 정확히 정반대로 작동하는 게 핵심 결함이다.

또한 모드 B에서 좋은 결과를 얻으려면 "원본 영상에 나오는 단어·문장을 직접 찾아 넣어야" 하는데, 그 **수동 앵커 추출이 노가다("일")**다.

---

## 2. 목표

- **두 모드를 명확히 구분**한다: (1) 원본 소재 그대로 리메이크, (2) 내 제품으로 이식.
- 리메이크 모드에서 **소재를 사용자가 입력하지 않아도** 원본 대본에서 **자동 감지**한다(수동 앵커 추출 제거).
- 감지된 소재를 **한 줄로 보여주고 수정 가능**하게 해 투명성·오감지 보정을 제공한다.
- 생성 대본이 원본의 **제품·사실·장면을 유지**하되 표현(훅·문장·순서·말투)만 새로 써서 **중복 콘텐츠를 회피**하도록 한다.

### 비목표 (YAGNI)

- 애매하던 모드 A("같은 주제로 신선하게 변주")는 **삭제**한다(유지하지 않음).
- 2영상 믹싱 자체는 **신규 작업 없음** — 기존 대본용/화면용 핸드오프(`produce.html`)가 이미 커버한다. 이 설계는 그 핸드오프에 들어갈 "좋은 영상 대본"의 품질만 고친다.
- 실제 영상 프레임(product_identify 등)으로 소재를 보강하는 것은 이번 범위 밖. 소재 감지는 추출된 대본 원문(`full_text`) 기반으로 충분하다.
- 리메이크 결과를 원본 장면 순서에 강제 매핑하지 않는다(믹싱에서 대본이 편집 순서를 정의하므로).

## 3. 설계

### 3.1 UI — `library.html` 생성 모달

기존 "주제" 섹션(모드 A/B 라디오 + `#genTopic`)을 **명확한 2모드**로 교체한다.

```
[주제/소재]
◉ ♻️ 원본 소재 그대로 · 표현만 새로 (중복 회피)          ← 기본 선택
     감지된 소재: [ 무선 가습기 물때 청소 꿀팁              ]  (수정 가능)
     └ 원본 영상 재사용·2영상 믹싱용. 제품·사실·장면은 그대로, 훅·문장·순서만 새로.
○ 🔀 내 제품으로 이식 (구조만 빌림)
     내 주제/제품: [ 예: 여름 결로 방지 커튼                ]
```

- 라디오 `name="genmode"` 값: `remake`(기본) / `transplant`.
- `remake` 선택 시: **감지 소재 입력칸** 표시(`#genSubject`), `#genTopic` 숨김.
- `transplant` 선택 시: 기존 `#genTopic`(내 제품) 표시, 감지 소재칸 숨김.
- **유지/변형 요소 토글 7개는 그대로 유지** — 구조/스타일 축이라 리메이크에서도 유효하며 중복 회피에 오히려 도움. 소재 축과 독립적으로 동작.
- 모달을 열 때(`openGen`) 리메이크가 기본이므로 **소재 자동 감지 API를 호출**해 `#genSubject`를 프리필한다. 로딩 중엔 "소재 감지 중…" placeholder, 실패 시 빈 칸(사용자 직접 입력 가능).

### 3.2 소재 감지 헬퍼 — `script_generate.py`

신규 함수 `detect_subject(full_text) -> str`:

- 원본 대본 원문(`full_text`)을 받아 **소재 한 줄**(제품/장면 요약, 약 15~30자)을 Gemini 1콜로 요약.
- 키풀은 기존 `_generate_drafts`와 동일한 `key_vault` 캐스케이드(`general`) 재사용.
- 무키·실패·빈 입력이면 `""` 반환(UI는 빈 칸으로 폴백, 사용자 직접 입력).
- 프롬프트 예: `"다음 숏폼 대본이 다루는 '소재'(제품/장면/주제)를 한 줄 명사구로만 요약해라. 표현·기법 말고 무엇에 관한 영상인지. 예: '무선 가습기 물때 청소'. 출력은 그 한 줄만."`
- 온디맨드(리메이크 모달 열 때만) 호출이라 비용·지연 최소.

### 3.3 생성 로직 — `generate_variations` (`script_generate.py`)

`mode` 값을 `remake` / `transplant`로 명확화(기존 `A`/`B` 대체). 하위호환: `A`→`remake`, `B`→`transplant`로 매핑(구버전 호출·저장된 흔적 대비).

`topic_line` 분기를 다음으로 교체:

- **remake** (소재 고정):
  ```
  주제: 아래 '소재'를 그대로 유지한 리메이크다. 원본의 제품·사실·장면·정보는 바꾸지 말고,
  표현(훅 문장·어휘·문장 순서·말투)만 새로 써서 원문을 그대로 베끼지 않게(중복 회피) 리라이트하라.
  없던 내용·다른 제품을 지어내지 마라.
  소재(고정): {subject}
  ```
  - `{subject}` = UI에서 넘어온(수정 가능) 감지 소재. 비면 `full_text` 기반으로만 잠금.
  - 프롬프트엔 이미 `full_text`가 통째로 들어가므로 소재는 이중 잠금.
- **transplant** (내 제품 이식): 기존 모드 B 문구 유지 —
  ```
  주제: 구조만 빌리고 아래 '내 주제/제품'에 맞춰 새로 써라.
  내 주제/제품: {my_topic}
  ```

시그니처: `generate_variations(structure, full_text, elem_modes, category_lookup, mode="remake", my_topic="", subject="", n=3, ...)` — `subject` 파라미터 추가.

### 3.4 API — `app.py`

- 신규 `GET /api/wiki/subject?shortcode=`: 해당 위키 항목의 `full_text`로 `detect_subject` 호출 → `{ok, subject}`. 항목 없거나 원문 없으면 각각 404/빈 문자열.
- 기존 `POST /api/wiki/generate` body 확장:
  - `mode`: `"remake"`(기본) | `"transplant"` (구 `A`/`B` 하위호환 매핑).
  - `subject`: 리메이크 모드에서 UI가 넘기는 감지/수정 소재 줄.
  - `my_topic`: 이식 모드 기존대로.
  - `generate_variations(..., mode=mode, my_topic=my_topic, subject=subject, n=n)`로 전달.

### 3.5 데이터 흐름 (2영상 믹싱 케이스)

신규 작업 없음. 좋은 영상 1개에서 **remake로 대본 확정** → 기존 **대본용/화면용 핸드오프**(`produce.html`)로 두 영상 믹싱. 이 설계는 그 핸드오프에 들어가는 대본의 소재 정합성만 보장한다.

## 4. 컴포넌트 경계 / 책임

| 단위 | 책임 | 의존 |
|------|------|------|
| `detect_subject(full_text)` | 원문 → 소재 한 줄 | key_vault 캐스케이드 |
| `generate_variations(..., mode, subject)` | 모드별 프롬프트 조립·초안 생성 | detect 결과(문자열)만, 헬퍼 비의존 |
| `GET /api/wiki/subject` | 모달 프리필용 소재 감지 노출 | Store, detect_subject |
| `POST /api/wiki/generate` | 모드/소재/이식주제 받아 초안 저장 | generate_variations |
| `library.html` 생성 모달 | 2모드 UI·소재칸 프리필·수정 | 두 API |

각 단위는 독립 테스트 가능: `detect_subject`는 무키/정상 입력, `generate_variations`는 mode별 프롬프트 분기(소재 주입 여부), API는 라우팅·하위호환 매핑.

---

## 5. 에러 처리

- 소재 감지 실패(무키·오류): 빈 문자열 → UI는 빈 소재칸, 사용자 직접 입력 가능. 생성은 `full_text` 잠금으로 여전히 동작.
- 생성 실패: 기존대로 502 + "생성 실패(Gemini 키 소진 또는 오류)".
- 위키 항목 없음/원문 없음: 기존 404/422 유지.
- 구버전 `mode="A"|"B"` 들어오면 `remake`/`transplant`로 매핑(조용히 정상 처리).

---

## 6. 테스트 계획

- `detect_subject`: 무키 → `""`; 정상(모킹) → 한 줄 반환·개행/따옴표 정리.
- `generate_variations` remake: 프롬프트에 소재 고정 문구 + `subject` 포함, "변주/신선" 지시 부재.
- `generate_variations` transplant: 기존 내 제품 문구 유지.
- 하위호환: `mode="A"`→remake, `mode="B"`→transplant.
- API `GET /api/wiki/subject`: 정상/404/빈원문.
- API `POST /api/wiki/generate`: `subject` 전달 경로, 기본 mode=remake.
- UI: 모달 열면 소재칸 프리필, 라디오 토글 시 소재칸/제품칸 상호 표시, 유지/변형 토글 유지 동작(브라우저 육안 grounding).

---

## 7. 배포

- 순수 `library.html` + `script_generate.py` + `app.py` 변경. 서버는 `main` push 후 3분 크론 자동배포.
- 실렌더 grounding: 라이브에서 실제 S급 항목 하나로 remake 생성 → 소재 유지·표현 변형 육안 확인.
