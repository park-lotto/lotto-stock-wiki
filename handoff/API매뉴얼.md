### ★ 공개 페이지를 로그인된 브라우저로 검증하면 안 된다 (2026-08-23 실사고)

`notice_1gi.html`·`api_manual.html`을 만들고 **브라우저로 열어 "정상"이라고 보고했다.**
실제로는 **둘 다 `307 → /login`** 이었다. 내 브라우저에 세션 쿠키가 있어서 보였을 뿐,
**외부인(=고객)은 로그인 화면만 봤다.** 사장님이 직접 눌러보고 알려주지 않았으면
공지를 뿌린 뒤에야 알았을 것이다.

```bash
# 공개 페이지는 반드시 쿠키 없는 요청으로 확인한다
curl -s -o /dev/null -w "status=%{http_code} redirect=%{redirect_url}\n" <url>
```

**게이트는 두 겹이다. 둘 다 넣어야 완전히 열린다**(`app.py`):
| 목록 | 막는 대상 |
|---|---|
| `_AUTH_ALLOW` | **비로그인** → 307 /login |
| `_FREE_EXACT_GET` | **로그인한 무료·체험만료 등급** → 402 |

한쪽만 넣으면 한쪽 사람만 못 본다. 새 공개 페이지를 만들 때마다 이 둘을 같이 본다.

### charset 없으면 한글이 깨진다 (같은 날)

`<meta charset="utf-8">`가 없으면 **라이브(FastAPI StaticFiles)에선 멀쩡한데
로컬 파일·다른 정적서버로 열면 통째로 깨진다.** 브라우저로 열어야 보인다.
⚠️ `capcut_manual.html`에도 아직 charset이 **없다** — 같은 함정이 남아 있다.

### ★결제 버튼은 설정값으로 자동 전환된다 (`app.py _with_pay`)

```
pay_url 있음      → "💳 결제하기 →"  (외부 카드 결제링크)
bank_account 있음 → "💳 결제 안내"   → /pay   ← ★지금 이 상태

**카드가 열리면 admin의 `결제 링크(URL)` 한 칸만 넣으면 된다.** 코드 수정·배포 불필요.
`/pay` 내용도 전부 admin 설정(`bank_name`·`bank_account`·`bank_holder`·`deposit_note`·
`contact_kakao`)에서 요청마다 읽는다 → **재시작 없이 즉시 반영.**

### 현재 결제 흐름 (③④가 수동)

```
① 안내/요금 페이지의 [💳 결제 안내] 클릭
② /pay 에서 계좌 확인 → 계좌이체
③ 고객이 카톡으로 "입금했습니다"      ← 수동
④ 사장님이 /admin 에서 승인 → Pro 전환  ← 수동
