### ① 한 컷 = 한 자막 구절 — 예외 없음

컷별 대표 프레임을 뽑아 **화면에 박힌 자막**을 육안 확인:

| 컷 | 시각 | 화면 자막 | 화면 |
|---|---|---|---|
| 1 | 0.77s | 다이소 가시면 | 창문 |
| 2 | 1.68s | 무조건 사오세요 | 세탁기 |
| 3 | 2.80s | 퇴근하고 들어왔는데 | 가스레인지 |
| 4 | 3.77s | 집이 갑자기 | 후드 |
| 5 | 4.47s | **엄청** | 문틀 |
| 6 | 5.28s | 반짝반짝한 거예요 | 침대 |

**150만 히트작(`6f0Kay3jOfE`)도 완전히 동일** — 훅 문구까지 글자 그대로 같다("다이소 가시면" /
"이건 무조건 사오세요"). 이 채널은 템플릿을 돌린다.

★**컷5 = "엄청" 두 글자가 0.6초 독립 컷.** 짧은 구절도 안 묶는다. 그게 리듬이다.

### ② 컷 길이 — 485개 실측

```
평균 1.33s   중앙값 1.13s
10% 0.70  25% 0.87  75% 1.50  90% 2.20  최대 8.77
1.5초 이하 76.5%
```

★**우리 `MAX_SHOT` 2.2초가 정확히 이 채널의 90퍼센타일이다.**
즉 우리는 이 채널이 *가장 길게 끄는* 컷을 **기본값**으로 쓰고 있다.

### ③ 영상 규격이 일정하다

```
길이 17.7~26.6초 (평균 22.0초) · 자막 편당 12.4구절 · 컷 편당 16.2개
```

### ④ ⚠️ 틀린 가설 — "히트작일수록 잘게 끊는다"는 **성립 안 함**

| | 조회 평균 | 컷 중앙값 |
|---|---|---|
| 상위 10편 | 407,900 | **1.40s** |
| 하위 10편 | 7,640 | **1.24s** |

히트작이 오히려 약간 **길다**. → **컷 속도는 조회수를 만들지 않는다.**
컷 리듬은 이 채널의 *기본 품질 기준*이지 히트 요인이 아니다(히트는 소재가 가른다).

**이 작업의 목적은 "조회수 상승"이 아니라 "아마추어처럼 안 보이게"다.** 과대평가 금지.

### ⑤ ★함정 — 자동자막으로 분석하면 틀린다

YouTube 자동자막은 **음성인식**이라 화면 자막과 다르다:
```
자동자막: 0.00s "여러분 다이소 가시면 이건 무조건"   ← 한 덩어리
         1.88s "사오세요. 퇴근하고 들어왔는데 집이"  ← 문장 중간에서 끊김
화면자막: "다이소 가시면" / "무조건 사오세요" / "퇴근하고 들어왔는데"  ← 의미 단위 3개
```
자동자막 기준 컷/구절 = 1.30이지만 **화면자막 기준은 거의 1.0**이다.
→ 분석은 반드시 **프레임 추출 + 육안**으로. 자동자막 수치를 근거로 쓰지 마라.

### 재현 방법

측정 스크립트는 세션 스크래치패드라 사라진다. 다시 만들 때:
- 목록: `yt_dlp` `extract_flat` → `/channel/<id>/shorts`
- 컷 검출: **우리 코드 `shopping_shorts.scene_cut.detect_cuts`** (0순위-B — 새로 짜지 마라)
  ⚠️ 반환은 **(start_frame, end_frame) 튜플 리스트**. 초로 쓰려면 `video_fps`로 나눠라.
- 화면 자막: 각 컷 **중간 지점** 프레임을 ffmpeg로 뽑아 육안(전환 찌꺼기 회피)

### 없는 것 — 진짜 격차

**컷 경계가 자막 구절 경계를 전혀 모른다.**

`_plan_beat_clips`(`video_assemble.py:521`) / `planClips`(`scene_play.js:289`)가 컷을 정하는 기준:
- `MAX_SHOT`(2.2초)까지 잘라 **라운드로빈**으로 장면 번갈아 재생
- `MIN_CLIP` 하한 미만 조각 안 만듦
- 모자라면 소스 뒷부분 실프레임으로 이어붙임

즉 전환 시점이 **"2.2초마다"**로 정해지지 **"이 구절이 끝나는 지점"**으로 정해지지 않는다.

### 시도된 적 있나 → **없다. 문제로 인식된 적조차 없다**

- `자막싱크` 트랙(08-06)은 **자막↔음성**만 다뤘다. 자막↔화면은 주제가 아니었다.
- "캡컷 대체 3벽"에도 이 항목이 없다 (①컷 전환 ②컷 길이 수동 ③미리보기 정확도).
- 오히려 **반대 전제**가 박혀 있다 — `handoff/컷길이수동.md`:
  > "지금까지 컷 길이는 자막 시간에서 **자동 계산**만 됐다"
  > "★칸 전체 길이는 못 바꾼다 — 자막이 `t0` 누적으로 자리를 잡아, 칸이 길어지면 뒤 자막이 통째로 밀린다"

  방향(자막이 주인)은 맞다. 단 **비트 전체 길이**에만 맞추고 **비트 안 구절 경계**는 모른다.

### 2. 설계 방향 (합의 전 초안)

- `applyFixedLens` / `_apply_fixed_lens`가 **이미 "이 컷은 이 길이" 배관**이다.
  지금은 사람이 배지 눌러 넣는 값 → 여기에 **자막 구절 길이를 자동으로** 넣으면 된다.
  → 새 배관 안 깔아도 된다. 깔린 배관에 다른 물을 흘리는 쪽.
- ★**화면·서버 두 벌을 짝으로** 고쳐야 한다(0순위-B). 한쪽만 고치면 미리보기≠결과물.
- 기본 OFF 토글. 꺼지면 기존과 **바이트 동일**.
- 제약: 총합은 `tts_dur` 못 넘는다(뒤 자막이 밀린다). 구절 길이 합과 비트 길이가
  어긋날 때 누가 양보하는지가 설계 지점.
