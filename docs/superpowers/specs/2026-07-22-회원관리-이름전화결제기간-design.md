# 회원관리 고도화 — 이름·전화·결제이력·서비스기간 (설계)

- 날짜: 2026-07-22
- 트랙: `회원승인` (기존 화이트리스트/대기실 위에 얹음)
- 대상: shopping_shorts (숏템박스, shoppingshorts.duckdns.org)
- 선행: 2026-07-21 회원승인 화이트리스트(Task1~8 라이브) + logout CSRF 보강
- 범위(이번 스펙): **A+B+C**. D/E(무료체험 이벤트)는 별도 후속 스펙.

## 배경 / 문제

현재 회원승인은 "가입→대기실→사장님 [승인]→7일 자동체험"까지 구현돼 라이브다. 그러나:
1. 가입 시 **이름·전화를 안 받아** 누가 누군지 admin에서 식별 불가.
2. 결제(카톡 입금 기반, 자동결제 없음)를 **기록할 곳이 없음** — 언제/얼마/어떻게가 안 남음.
3. 서비스 **시작일·마감일**이 admin에 안 보임.
4. 승인 시 자동 7일 체험이라, 사장님이 **결제 일수만큼** 열어줄 수 없음.

## 사장님 결정 (2026-07-22)

- '구글폼' = **앱 가입폼 확장** (외부 Google Forms 아님). 데이터는 우리 DB에.
- 결제 = **admin에서 수동 입력**, **여러 건 누적**(결제이력).
- **[승인] 누를 때 결제(금액·수단·이용일수)를 같이 입력** → 그 즉시 계정 열림.
- **자동 7일 체험 제거** — 승인은 사장님이 입력한 일수만큼만 연다.
- 서비스 시작일 = **기존 `approved_at` 재활용** / 마감일 = **기존 `full_access_until` 재활용**.
- 결제이력 표시 = 최근 1건 요약 + 클릭 시 전체 펼침.

### 후속(D/E, 이번 범위 아님 — 방향만 기록)
- 무료체험 **이벤트**를 실시간 열면 → **레퍼런스 채널 페이지만** 열고 → **24시간** 유지.
- 현 구조가 이를 잘 받는다: `ranking_only` 등급이 이미 "레퍼런스 랭킹 조회만"이라, 24h 체험 = "가입 후 24h는 ranking_only 접근 허용"으로 나중에 얹기 쉽다.

## 데이터 모델

### customers 확장 (ALTER ADD COLUMN, 기존 계정 NULL 백필)
- `name` TEXT — 이름 (구글 가입자는 구글에서 취득, 아이디 가입자는 폼 입력)
- `phone` TEXT — 전화번호
- (재활용) `approved_at` = 서비스 시작일 / `full_access_until` = 서비스 마감일(epoch초)

### payments 신규 (결제이력, 여러 건 누적)
```sql
CREATE TABLE IF NOT EXISTS payments (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    customer_id INTEGER NOT NULL,
    amount INTEGER NOT NULL DEFAULT 0,      -- 금액(원)
    method TEXT,                            -- 수단(계좌/카드/현금/카톡 등 자유 텍스트)
    period_days INTEGER NOT NULL DEFAULT 0, -- 이 결제로 부여한 이용일수
    paid_at INTEGER NOT NULL,               -- 결제일(epoch초)
    note TEXT,                              -- 비고
    created_at INTEGER NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_payments_customer ON payments(customer_id);
```

## 컴포넌트 / 흐름

### 1. 가입폼 (아이디 가입)
`_SIGNUP_HTML`에 `이름`·`전화번호` 입력칸 추가. `POST /api/signup`이 name·phone을 받아 `create_customer(..., name=, phone=)`로 저장. 구글 가입은 이름 자동, 전화는 나중에 admin 입력(빈 값 허용).

### 2. store 레이어
- `create_customer(..., name=None, phone=None)` — 컬럼 저장.
- `list_customers()` — name·phone·approved_at·full_access_until + **최근 결제 요약**(마지막 payment의 amount·paid_at·건수) 포함.
- `add_payment(customer_id, amount, method, period_days, paid_at=now, note=None)` — payments 1건 삽입 + **멱등 아님**(연장은 새 건). 반환: 삽입된 payment.
- `list_payments(customer_id)` — 그 고객 결제 전체(최신 먼저).
- `approve_customer(cid, period_days, amount, method, note=None)` **시그니처 변경**:
  - 기존 `trial_days=7` 자동체험 → 제거.
  - approved_at=now(시작일), full_access_until=now + period_days*86400(마감일).
  - `add_payment(...)` 호출로 결제 기록.
  - **멱등성**: 이미 승인된(approved_at 있음) 계정에 다시 호출하면? → 승인은 최초 1회만 approved_at 세팅, 이후 호출은 "결제추가/연장"으로 동작(full_access_until을 **현재 만료일 기준으로 연장**, 이미 만료면 now 기준). payment는 매번 새 건.
- `extend_service(cid, period_days)` — full_access_until 연장 헬퍼(만료 안 지났으면 기존 만료일+, 지났으면 now+).

### 3. API
- `POST /api/admin/approve` **본문 확장**: `{customer_id, amount, method, period_days, note?}`. 승인+결제기록+기간설정 원자적. 기존 필드 없이 오면(하위호환) 400 또는 기본값? → **명시 요구**(amount·period_days 필수). admin UI가 항상 채워 보냄.
- `POST /api/admin/payment` **신규**: 이미 승인된 고객에 결제 추가+연장. `{customer_id, amount, method, period_days, note?}`.
- `GET /api/admin/payments?customer_id=` **신규**: 그 고객 결제 전체.

### 4. admin.html
- **대기명단**: ID / 이름 / 전화 / 이메일 / 가입일 / [승인]. [승인] 클릭 → 입력 폼(금액·수단·이용일수) → 확인 → `POST /api/admin/approve`.
- **고객 목록**: ID / 이름 / 전화 / 이메일 / 등급 / 시작일 / 마감일 / 최근결제(금액·일자, N건) / [결제추가]·[무료로].
  - 최근결제 칸 클릭 → 그 고객 payments 전체 펼침(GET /api/admin/payments).
  - [결제추가] → 같은 입력 폼 → `POST /api/admin/payment`.
- 입력 폼: 인라인 모달 or 간단 prompt 조합. 금액·수단(select+자유)·이용일수 3필드. 이용일수 기본값 없이 사장님 입력(요구: "일수 확정되면").

## 에러 처리
- approve/payment에 amount<0·period_days<0·비고객 cid → 400.
- 없는 customer_id 승인 → 404(현재 200 None 반환하던 것 교정, Task6 리뷰 Minor 반영).
- payments는 append-only. 삭제 API 없음(오기입 정정은 후속).
