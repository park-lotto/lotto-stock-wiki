# 체험판 접근 개방 — 랭킹·즐겨찾기·렌즈를 열고, 제작소는 소개만

작성: 2026-08-20 / 트랙: `체험판개방`

## 목적

내일(2026-08-21) 체험 사용자에게 서비스를 연다. 사장님 지시는
**"레퍼런스랭킹만 사용하게"** + **"영상 즐겨찾기"** + **"숏템제작소는 열어두되 사용
자체가 안 되게"** + **"렌즈 하루 10회"**.

부차 목적: 체험 사용자가 **어떤 영상을 좋아하고 분석하는지** 관찰한다. 다만 그
관찰 도구(사용자별 보관함)는 이번 범위가 아니다 — 아래 '안 하는 것' 참조.

## 착수 전 실측 (추측 아님 — 라이브 코드·DB 직접 확인)

| 확인한 것 | 결과 | 근거 |
|---|---|---|
| `ranking_only` 등급 | **이미 존재** = "랭킹만" | `app.py:7586` `access_level()` |
| 허용 경로 판정 | **deny-by-default 화이트리스트** | `app.py:6185` `_ranking_only_blocked()` |
| 랭킹 조회 | 이미 무료 개방 | `_FREE_EXACT_GET`에 `/`, `/api/reference`, `/api/thumb`, `/api/video`, `/api/channel/history` |
| 즐겨찾기 담기 | **402 차단** | `/api/mix/basket/toggle`이 화이트리스트 밖 |
| 제작소 | **402 JSON 날것** | `/produce`가 화이트리스트 밖 (화면이 아니라 `{"error":...}`가 뜬다) |
| 렌즈 일일 상한 | **이미 하루 10회** | `_CREDIT_DEFAULTS={"lens":10}` (`app.py:7627`), DB 덮어쓰기 **없음**(실측 `limit_lens=None`) |
| SerpApi 월 용량 | **1,250회** (5키 × 250) | 서버 `SERPAPI_KEY` 5개 실측, `_LENS_MONTH_LIMIT_PER_KEY=250` |

★ `app.py:7665` 주석의 "SerpApi 월 100회"는 **낡은 값**이다(실제 키당 250 × 5키).
이 설계는 실측값 1,250을 기준으로 한다.

## 설계 원칙

**여는 것만 명시한다.** `_ranking_only_blocked`가 화이트리스트 방식이라, 목록에
없는 경로는 자동으로 402가 된다. 새 유료 엔드포인트가 나중에 추가돼도 깜빡 열릴
일이 없다. 이 구조를 깨지 않는다.

## 무엇을 만드나

| | 지금 | 바꾼 뒤 | 개발량 |
|---|---|---|---|
| ① 레퍼런스랭킹 | ✅ 열림 | 그대로 | 없음 |
| ② 영상 즐겨찾기 | ❌ 402 | ✅ 담기·모음집, **인스타 요청 0** | 화이트리스트 + 크롤 스킵 |
| ③ 숏템제작소 | ❌ 402 JSON | ✅ **소개 페이지** | 정적 HTML 1장 + 라우트 분기 |
| ④ 렌즈 | ❌ 402 | ✅ **하루 10회** | 화이트리스트만 |

### ② 영상 즐겨찾기

화이트리스트에 추가:
- `_FREE_EXACT_ANY` += `/api/mix/basket/toggle` (POST라 ANY 목록)
- `_FREE_EXACT_GET` += `/collection`, `/api/mix/basket`

**담기 시 백그라운드 메타 크롤을 건너뛴다.** 즐겨찾기는 *랭킹에 이미 뜬* 영상을
담는 것이라 조회수·팔로워·캡션이 수집 때 이미 들어와 있다 — 다시 긁을 게 실제로
없다. 프론트가 보내는 `url·thumbnail·name·caption`으로 충분하다.

판정은 **한 곳에서만** 한다(0순위-B): `access_level(cid) != "full"`이면 크롤을 안
돈다. 사장님·pro는 종전과 완전히 동일하게 동작한다.

왜 중요한가: 크롤이 사람 수만큼 늘면 인스타 429가 나고, 그건 **본 수집을 망가뜨린
전례가 있다**(2026-07-30, 수집 80건으로 급감).

### ③ 숏템제작소 = 소개 페이지

`/produce`는 지금 클린URL 루프(`app.py:11975`)에서 **게이트 없이** 등록된다.
이걸 `voice_tune`·`refs`가 쓰는 **명시 라우트 패턴**으로 바꾼다(있는 패턴 재사용).

```
access_level == "full"  → produce.html      (지금과 완전히 동일)
그 외                    → produce_intro.html (신규)
```

⚠️ **`/produce.html` 직접 접근도 같이 막아야 한다.** StaticFiles 마운트가 확장자를
그대로 서빙하므로 `/produce`와 `/produce.html` **둘 다** 명시 라우트로 등록한다.
안 하면 뚫린다 — `app.py:11988`에 이 함정이 실사고로 기록돼 있다.

소개 페이지는 **API를 하나도 안 부르는 정적 HTML 1장**이다. 기능 설명 + "결제하면
열려요" + 결제 링크. API를 안 부르니 402 에러가 화면에 뜰 여지가 없다.

★ `/api/produce/*`는 **화이트리스트에 넣지 않는다.** HTML만 열고 API는 그대로 막아,
영상제작·과금 기능이 구조적으로 샐 수 없게 한다.

### ④ 렌즈 하루 10회

`/api/lens/*`를 화이트리스트에 추가한다. **상한 로직은 새로 만들지 않는다** —
`check_and_count(cid, "lens")`가 이미 실행 전에 하루 10회를 강제한다.

용량 계산: 체험 5명 × 10회 = 하루 50회, 월 1,500회. 월 용량 1,250회에 근접하므로
**키를 더 확보하면 여유가 생긴다**(사장님: "더 받으면 되니까"). 전역 상한
`global_cap_lens=200/일`은 그대로 둬 폭주를 막는다.

## 데이터 흐름

```
담기:   랭킹 카드 → toggleMix → /api/mix/basket/toggle → mix_basket 저장
        (인스타 왕복 없음)
제작소: /produce → access_level → full? produce.html : produce_intro.html
렌즈:   /api/lens/* → check_and_count(lens, 10/일) → 초과면 402
```

## 안 하는 것 (YAGNI)

- **사용자별 보관함** (`⭐ 내가 담은 영상` 탭, `customer_id`별 분리, 관리자만
  사람별 전환) — 2단계로 미룬다. 내일 마감에 불필요하고, 담기 권한·인스타 요청
  한도·확장 수정이 한꺼번에 걸린다. 설계 논의는 끝나 있으니 그대로 이어받으면 된다.
- **크롬 확장 수정** — 체험 사용자는 랭킹 화면에서 담으므로 불필요.
- **`⭐등록`(`/api/reference/adopt`) 개방** — 관리자 전용 유지.

## 검증

체험 계정(`ranking_only`)으로 **실제 브라우저에서** 확인한다(정적 검토는 관찰이 아니다):

```
□ 랭킹 보인다 / 썸네일·영상재생 된다
□ 📥 즐겨찾기 눌러 담긴다 → /collection에 뜬다
□ 담을 때 인스타 요청이 안 나간다 (서버 로그로 확인)
□ /produce → 소개 페이지 (402 JSON 아님)
□ /produce.html 직접 접근 → 소개 페이지 (뚫리지 않음)
□ 렌즈 10회까지 되고 11회째 막힌다
□ 그 외 유료 API(/api/produce/*, /api/render 등)는 여전히 402
```

관리자 계정으로 **회귀 0** 확인:
```
□ /produce가 종전과 완전히 동일 (진짜 제작소 화면)
□ 담기 시 메타 크롤이 종전대로 돈다
□ 렌즈 무제한 유지
```

테스트:
```
□ pytest shopping_shorts/tests/ — 기준선 대비 실패가 늘지 않았는지 대조
   (기준선: test_edit_plan_build.py::test_build_edit_plan_exhausted_returns_empty 1건은
    이 작업 전부터 실패한다 — 무관)
```

## 위험

**가장 위험한 곳은 ③에서 화이트리스트를 넓게 여는 것.** `/produce`를 열면서 실수로
`/api/produce/*`를 함께 열면 영상제작·렌즈 같은 실과금 기능이 새 나간다.
→ **HTML 라우트만 등급 분기하고 API 화이트리스트는 손대지 않는다.**

**차선 위험은 ②의 크롤 스킵이 사장님 경로까지 끄는 것.** `access_level`로 갈라
`full`은 종전과 동일하게 크롤이 돌아야 한다 → 관리자 회귀 검증 항목에 포함.
