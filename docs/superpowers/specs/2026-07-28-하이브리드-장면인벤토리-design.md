## 0. 한 줄
대본 배치 인벤토리를 **whisper 세그먼트 → ffmpeg 시각 컷 기준**으로 재베이스하고, 각 컷을
**로컬(STT+모션[+OCR])로 풍부하게 텍스트화**한 뒤, **Gemini Vision은 훅·무자막 컷에만 선택 호출**해
싱크 정확도↑·비용↓를 동시에 얻는다.

## 2. 목표 / 비목표

**목표**
- G1. 대본-화면 싱크 오차 감소: 배치 단위를 **시각 컷**에 정렬.
- G2. Gemini Vision 비용 절감: 컷 전량 이미지 전송 금지 → **훅 후보·무자막 B롤만**(영상당 2~3장) 이미지, 나머지 텍스트만.
- G3. 로컬 무료 텍스트화로 scene_desc 품질↑: STT + 모션레벨 (+ 선택적 OCR).
- G4. **Peak Event Detection**: 모션 급증 지점을 훅 In-Point(0.0초)로.

**비목표(이번 범위 밖)**
- Shadowban 마스킹(좌우반전·크롭·색조) — 효과 불확실·화질/자막 리스크. **별건**.
- AI 업스케일 — 렌더화질 트랙 별건.
- 슬롯 시간 하드코딩(0-3/3-6/…15-18) — 우리는 비트 기반 유지.

## 3. 단계 설계 (P1→P4, 각 단계 독립 배포 가능)

### P1 — 모션레벨 + Peak Event Detection  ★먼저, 싸고 즉효
- `scene_cut`에 **컷별 모션에너지 → LOW/MED/PEAK 라벨**(ffmpeg `select='gt(scene,…)'`/프레임 diff, cv2 불필요).
- 각 컷 시작 부근 **모션 급증 프레임 = 훅 In-Point** 후보. 훅 컷 선정에 PEAK 가중.
- 산출: 컷 리스트 `[{start,end,motion_level,peak_at}]`.
- 통합 지점: 훅 비트 primary 선정 시 PEAK 컷 우선.
- 게이트: 기존 pytest 기준선 유지 + 모션 라벨 단위테스트.

### P2 — 인벤토리 시각 컷 재베이스  ★핵심 통합
- `_build_inventory`가 **whisper 세그먼트 대신 scene_cut 컷**을 단위로 쓰게(또는 컷↔세그먼트 교집합 매핑).
- 각 컷에 STT(교집합 텍스트)+모션레벨을 붙여 `scene_desc` 조립: `[STT]…/[Motion]…`.
- seg_id 체계 호환 유지(하위 `_ground_ref`·`_plan_beat_clips`가 seg_id·start/end에 의존 → **인터페이스 보존**).
- ⚠️ 회귀 위험 최상: scene_first·grounding·assemble 전 구간이 인벤토리 형태에 묶임 → **어댑터로 감싸 기존 반환형 유지**.

### P3 — 로컬 OCR 화면텍스트  (수요 확인 후)
- 무자막 B롤·화면 자막 컷에 OCR(`easyocr` 또는 경량 대안) → `scene_desc`에 `[OCR]…` 추가.
- ⚠️ 의존성 무겁고(모델 수백MB) 프레임당 느림 → **키프레임 1장/컷·서버 부하 측정 후** 켠다. 옵션 플래그.

### P4 — Selective Vision 룰 정식화
- 지금 `_VISION_TAG_CAP`(전량 상한) → **룰 기반**: Rule A(텍스트 있는 컷)=이미지 미전송 / Rule B(PEAK 훅 후보·무자막 B롤, 영상당 ≤3)=이미지 전송.
- 기대: 이미지 전송량 대폭↓(명세 주장 85~90% 절감은 **실측으로 검증**, 과장 배제).

## 8. P1 실행계획 (writing-plans)

**범위**: 컷별 모션레벨(LOW/MED/PEAK) + 훅 In-Point 자동 + 프리뷰 0.2초 오버라이드. OCR·재베이스 없음.

- **T1 — 모션 측정·분류(순수 함수)** · `scene_cut.py`
  - `frame_motion(path)`: ffmpeg 1패스로 프레임별 시간차 모션(signalstats YDIF, metadata=print) → `{frame_no: energy}`.
  - `classify_motion(values)`(★ffmpeg 불필요, 단위테스트 대상): 값 분포의 상대 컷오프로 LOW/MED/PEAK.
  - `cut_motion(cuts, motion)`: 컷별 `{level, peak_frame}`(peak=구간 내 최대 energy 프레임).
  - 게이트: `classify_motion` 순수 단위테스트(합성값). ffmpeg 의존부는 `_HAS_FF` 가드.
- **T2 — 훅 In-Point 자동 적용(백엔드)** · 훅 비트 primary 선정 시 **PEAK 컷 우선 + start를 peak_frame 시각으로**. seg 메타에 `peak_at` 실어 나름.
  - 게이트: 훅 선정이 PEAK 있으면 그걸 고르는 단위테스트. 없으면 기존 동작(회귀0).
- **T3 — work.state에 훅 오버라이드 저장** · `hook_inpoint_override`(초) 필드. 있으면 render가 자동 peak_at 대신 이 값 사용.
- **T4 — 프리뷰 UI 0.2초 미세조정** · `produce.html` 훅 클립에 [◀0.2s][0.2s▶] 버튼 → override 저장·미리보기 갱신.
- **T5 — 렌더 반영** · 훅 클립 start = override or peak_at. 유출 0 유지(소스 밖 금지).

**비회귀 원칙**: `_ground_ref`/`_plan_beat_clips`가 기대하는 seg 필드(seg_id·start·end·scene_desc)는 불변. peak_at은 **추가 필드**로만.
