화면 구성안: 탭 6개

펄스카드의 "탭 4개, 순서대로" 구조가 가장 단순했고, 판매 서비스들은 여기에 편집기·브랜드·자동을 더했습니다. 두 가지를 합쳐 탭 6개로 잡았습니다. 각 칸 아래에 어느 서비스에서 가져온 것인지 적었습니다.

탭 1

소재

  • 오늘 뜨는 이슈 목록: 점수·출처·분야

  • 저장해 둔 아이디어
  • 줄마다 카드로 만들기 버튼 → 만들기 탭으로 넘어감

만들기

수동 모드: 회원이 한 편씩

소재 or 주제→설정→개요 확인→생성·자동 검사→편집→점검표→다운로드

분홍 칸이 사람이 보는 자리입니다. 개요 확인에서 크레딧이 차감됩니다(망고보드 방식). 그래서 확인 전에 그만두면 돈이 들지 않습니다.

자동 모드: 규칙대로 매일

규칙→소재 자동 선택→생성·자동 검사→승인 대기함→보관함→(나중) 게시

서버 크론이 돌리므로 회원 PC가 꺼져 있어도 됩니다. 강의 2·4의 "PC가 켜져 있어야 한다" 문제를 피합니다. 검사를 통과하지 못한 카드는 승인함에 표시만 하고, 다시 쓰기를 한 번 더 시도합니다.

캐러셀은 최대 10장사진·영상 섞어도 10개. 캐러셀 1개 = 게시물 1건
24시간에 100건같은 문서 안에 "50건"이라는 문장도 있어 어긋남. 보수적으로 50으로 잡는다
이미지는 JPEG만PNG로 뽑으면 그대로 못 올린다. 렌더 결과를 JPEG로 저장
공개 URL에 있어야 함메타 서버가 그 주소에서 가져간다. 영상 6은 공개 GitHub 저장소를 썼다
첫 장 비율로 전부 잘림캐러셀은 첫 이미지 크기에 맞춰 나머지를 자른다. 장마다 1080×1350으로 통일
2단계 게시장마다 컨테이너 → 묶음 컨테이너(CAROUSEL) → 상태가 FINISHED가 되면 게시. 상태는 1분 간격, 5분 이내로 조회 권장. 컨테이너는 24시간 뒤 만료
필요 권한인스타 로그인 방식: instagram_business_basic + instagram_business_content_publish
계정 조건프로페셔널 계정. 비공개 계정은 토큰이 안 나온다(영상 6). 인스타 로그인 방식은 페이스북 페이지가 필요 없다(영상 6 실측)

스킬은 샘플 하나로 먼저 맞춘다원하는 결과가 나올 때까지 한 샘플로 반복(A 테스트), 그 뒤 여러 샘플(A/B). 평가 기준(글자 수·문장부호·어투)을 적어 둔다 (영상 7)

우리 프로그램

설계 기틀

10편에서 공통으로 통한 것만 남겼습니다. 글자는 HTML 템플릿으로 정확하게 그리고, 배경 그림만 선택적으로 이미지 모델에 맡기고, 공식 API로 올리고, 서버에서 상시로 돌리는 구조입니다. 우리 규칙(0순위-C)에 따라 판단마다 주인 함수를 하나씩 정하고, 결과물 검사를 처음부터 같이 둡니다.

판단 주인 — 판단 하나에 함수 하나

plan.build_slides()장수(2~10), 장별 역할(표지·본문·마무리), 장별 글자 수 상한. 이 규칙은 여기에만 둔다
brand/<계정>.json계정의 목적·톤·금지어(영상 1의 brand-facts)와 색·폰트·여백(영상 5의 DESIGN.md)을 한 파일에
render.render_carousel()JSON + 템플릿 → 1080×1350 JPEG. 화면 미리보기도 이 함수 결과를 그대로 보여 준다
check.check_carousel()결과물 검사의 주인. 아래 "결과물 검사"를 모두 여기서
caption.write()캡션·해시태그. 직전 게시물들과 겹침률을 재서 반복을 막는다
publish.publish_carousel()공개 URL 업로드 → 장별 컨테이너 → 묶음 → 상태 조회 → 게시. 재시도·실패 기록 포함

영상 3·8·10이 모두 이 모양(장별 배열 + 캡션)을 썼습니다. rule_version은 어떤 규칙으로 만든 파일인지 남기는 표식입니다. bg_prompt가 있을 때만 배경을 이미지 모델로 생성합니다.

결과물 검사 — 계산이 아니라 나온 파일을 잰다

  • 렌더된 화면에서 글자 칸마다 넘침을 잰다(내용 높이 > 칸 높이면 실패). 영상 6의 "제목 잘림"을 사람보다 먼저 잡는다
  • 파일이 JPEG, 1080×1350이고, 장수가 2~10장인지
  • 장마다 빈 화면·검은 화면이 아닌지(픽셀 분산)
  • 캡션이 직전 10건과 얼마나 겹치는지
  • 게시 뒤 게시물 ID로 실제 올라간 장수를 다시 조회해 맞춰 본다
  • 검사 도구는 처음 만드는 커밋에 같이 넣고, 일부러 망가뜨린 샘플에서 실패가 뜨는지 먼저 시험한다

아직 정할 것

1. 숏템 안의 탭인가, 별도 서비스인가숏템 안에 두면 로그인·결제·버텍스 등록(vertex_route)·사용량 기록(usage_meter)을 그대로 쓴다. 별도면 새로 만든다
2. 버텍스 요금은 누가 내나지금 숏템은 회원이 자기 버텍스를 등록하는 방식이다. 배경 그림도 회원 버텍스로 할지, 사장님 버텍스로 그리고 크레딧을 팔지
3. 값을 얼마로경쟁 월 요금대는 약 2만~5만 원. 첫 1회 무료와 단가 공개를 할지
4. 첫 디자인 팩 3종의 방향예: 뉴스·정보형(다크), 상품 홍보형(사진 중심), 생활 팁형(밝은 색). 새 계정의 주제와 맞춘다
조사 자료: 각 영상 자막 전문(yt-dlp 자동 자막)과 설명란, 영상당 30컷 화면 모음. 영상 속 매출·팔로워·조회수 같은 성과 수치는 출연자 주장이고 확인하지 않았습니다. 10편 모두 강의·커뮤니티·유료 도구로 이어지는 홍보 성격이 있습니다.
