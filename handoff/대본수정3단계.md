# 대본수정3단계 — 3단계에서 대본을 그 자리에서 고치기

## 2026-08-17 (회사PC) — ✏대본수정 신설 · 라이브 반영 완료

### 지시
사장님: "이럴때 3단계에서 대본 몇글자 수정하려고 2단계로가서 한다음에 다시 3단계 매칭을
새롭게 하는방법밖에 없나?" → (조사 후) "비우기 옆에 화살표들은 필요없는 기능이고 그자리에
대본수정 만들고 누르면 썸네일아래 대본 수정되게" → "화살표 빼고 1번(A안: 서버저장+TTS재생성) 바로"

### ★원인 — 기능이 없어서가 아니라 **저장할 곳이 없었다**
- `scene_lab.html`엔 편집 장치가 **이미 다 있었다**(`NARR`/`editNarr`/`narrChanged`/`retts`)
- 그런데 라이브에선 `SL.server`로 `contenteditable=false`로 **잠겨** 있었고,
  안내는 "대본 수정은 위 ① 새 대본 고르기에서"를 가리켰다
- 그 UI(`produce.html` `#mixScriptPick`)는 9단계 개편에서 **`display:none`**
  (주석: "2단계 세션이 이 요소를 그리로 옮긴다" — **그 이관이 아직 안 됐다**)
- → **앱 어디에서도 대본을 못 고치는 상태.** 사장님 질문("2단계 왕복밖에 없나")의 답은 그때까진 "그렇다"가 맞았다.
- ⚠️내가 처음에 "3단계 카드 하단에 ✏대본 고치기가 있습니다"라고 답한 건 **틀렸다**
  (코드만 보고 화면 상태를 안 봤다). 사장님이 "안보임"으로 바로잡아 주셨다.

### 만든 것 — 저장구멍 하나뿐
**`POST /api/mix/scene_lab/{job}/narration/{beat}`** (`app.py`)
- `narration` 저장 + 옛 문장 기준 자막 잔재(`cap_durs`·`cap_lead`·`caption_lines`) **전부 버림**
  ★안 버리면 구절 수가 안 맞아 zip이 잘려 **자막이 중간에서 끊긴다**
- 음성·자막 재생성은 **이미 있던 `resynth_one_beat`**을 예약(새로 안 만듦, 0순위-B).
  자막 분할도 서버가 라이브와 같은 코드로 계산 — JS로 다시 나누지 않는다.
- `voice`는 job 스냅샷을 물려준다(통째로 새 dict면 이 비트만 소리가 달라진다 — `tts_regen`과 같은 이유)
- 가드는 기존과 동일: 생성·렌더 중 **409** / 빈 문장 **422** / 없는 비트·작업 **404**
  / 같은 문장이면 **unchanged**(헛돈·헛시간 방지)

**`scene_lab.html`**
- 썸네일 줄의 `◀▶`(move) 제거 → 그 자리에 **`✏ 대본수정`**
- 누르면 **썸네일 아래 대본이 편집칸**이 된다(커서 자동 진입, `Ctrl+Enter` 저장 · `Esc` 취소)
- 저장하면 **`tts_ver`(단조증가)를 폴링**해 완료를 알고 자막·길이를 서버 값으로 갈아끼운다
  (mp3는 같은 경로라 겉으로 구분이 안 된다 — `resynth_one_beat`이 올려주는 신호를 쓴다)
- ※세로목록의 `↑↓`는 **남겼다**(사장님이 지목한 자리는 썸네일 줄). `move()`는 계속 쓰인다.

### ⚠️ 실측으로 바로잡은 것 3건 — 짐작하면 조용히 깨지는 자리
| 내가 쓴 것 | 실제 |
|---|---|
| `say()` | `makeTts` **안의 지역 클로저**라 밖에서 못 쓴다 → `nsay()` 신설 |
| `renderThumbs()` | **없는 이름**. 실제 함수는 `renderBand()` |
