- 트랙: `바꾸기길이`

## 사장님 요구 (최종)

> "복잡하니까 원본 그대로 올려주고, 라이브러리 그쪽에 조각 영상들 불러올 수 있게 되나"

앞서 논의한 **다중 트랙(완성본 + 계단식 조각)은 폐기**한다 — 사장님이 "복잡하다"고 판단.
타임라인은 지금처럼 두고, **조각은 캡컷 미디어 보관함에만** 넣는다.

## 만들 것

### 1. ★단일 출처로 되돌리기 (이번 작업의 절반 — 이게 더 중요하다)

라이브 job 실측(2026-08-23, `reference.db`):

| job | 실제 화면 조각 | 캡컷으로 가는 것 |
|---|---|---|
| `ec39cd92d2bd` | **19** | **7** |
| `3fae04098b00` | **18** | **8** |
| `44a9a90d2c96` | **13** | **6** |

원인: 비트 하나에 화면이 여러 개인데(`primary` + `alternates`, 장면실험실 `scene_override`)
**`primary` 하나만** 트랙에 올린다.

- `capcut_draft.py:174` — `prim = beat.get("primary") or {}`
- `export_bundle.py:117` — `prim = (beat or {}).get("primary") or {}`

코드베이스엔 화면 재료를 한 곳에서 정하는 함수가 **이미 있다**:
`video_assemble._beat_material(beat)` (`video_assemble.py:396`). 실제 렌더는 이걸 쓴다.
**내보내기 두 곳만 안 쓴다 = CLAUDE.md 0순위-B 위반** → 캡컷에서 연 것과 완성본이 다른 영상.

⚠️ **그냥 `_plan_beat_clips`를 부르면 안 된다.** 렌더 호출부(`video_assemble.py:1055~1076`)는
그 함수 앞뒤로 판단을 더 한다:

```
segs = _beat_material(beat) 중 소스 실재 + _src_dur > 0.05 인 것만   # 손상 소스 제외
_max_shot = None if is_point_beat(beat) else config.MAX_SHOT_SECONDS  # 포인트 비트는 홀드
_one     = config.ONE_CLIP_PER_SEGMENT                                # 1장=1컷 모드
plan = _plan_beat_clips(segs, tts_dur, src_durs=..., max_shot=_max_shot, one_per_seg=_one)
if beat.get("stretch_fill"): _spread_stretch(plan)                    # 실험실 칸별 토글
if idx == _runout_idx: _extend_last_clip_for_runout(plan, segs, runout)  # 마지막 여운
```

이 6줄을 내보내기에 다시 적으면 **또 두 벌**이 된다(0순위-B를 고치면서 어기는 셈).
→ **블록을 함수 하나로 뽑는다**: `plan_beat_clips_for(beat, idx, ...)`.
   렌더도 그 함수를 부르게 바꾸고(동작 불변), 캡컷·ZIP도 같은 함수를 부른다.
   **합격 조건: 렌더 결과가 1바이트도 안 바뀐다** — 테스트로 못박는다.

### 2. 조각 파일 만들기

`_beat_material` 기준으로 구간마다 **원본에서 잘라** draft 폴더에 넣는다.
`export_bundle._cut_clip`(ffmpeg 재인코딩 컷)이 이미 있으므로 재사용한다.

- 이름: `cut_00_첫말.mp4` — 비트 순서대로 정렬되게 번호를 앞에.
- **자막·효과가 안 구워진 깨끗한 화면**(사장님 선택 ②). 갈아끼워도 자막 트랙이 그대로라 안 어긋난다.

### 3. 미디어 보관함에 등록

`build_meta`의 `draft_materials`를 채운다. 담을 것:

- **조각 전부** (`cut_NN_역할.mp4`)
- **완성본** (`final.mp4`) — 있으면. 참고용으로 보관함에만, 타임라인엔 안 올린다.
- 이미 복사 중인 소스 원본(`src_*.mp4`)·TTS(`beat_NN.mp3`)도 함께 등록하면 보관함에서 바로 쓸 수 있다.

### 4. 타임라인 — 지금 그대로

비디오 1 + 음성 1 + 자막 1. **구조를 바꾸지 않는다.** (다중 트랙 안은 폐기)
단 1번 수정으로 비디오 트랙에 **빠졌던 조각들이 채워진다** — 완성본과 같은 화면이 된다.

## 장면 교체 시 (사용자 흐름)

1. 캡컷 타임라인에서 바꿀 장면을 고른다
2. **보관함에서 다른 조각을 끌어다** 그 자리에 놓는다
3. 길이를 그 자리에 맞춘다 ⚠️
4. 자막·TTS는 **트랙이 따로라 그대로 남는다** — 새로 안 해도 된다

| | 새로 해야 하나 |
|---|---|
| 자막 | ❌ 트랙이 따로 |
| TTS 음성 | ❌ 트랙이 따로 |
| 장면 길이 | ⚠️ 넣을 때 맞춰야 한다 |

대사 자체를 바꾸는 건 대본 수정이라 제작소에서 한다(범위 밖).

## 검증

- **조각 수 대조**: 실제 job으로 draft를 만들어 `조각 수 == _beat_material 합`인지.
  `ec39cd92d2bd` 기준 **19개**여야 한다(지금 7개).
- **보관함 등록 수** = 조각 + 완성본 + 소스 + TTS.
- **렌더 회귀 0**: 1번 리팩터링 후 `_plan_beat_clips` 결과가 리팩터링 전과 동일.
- 기존 테스트(`test_capcut_draft` · `test_export_bundle`) 회귀 0.
- ⏭ **사장님 육안 확인 필수**: 캡컷에서 열어 ①보관함에 조각이 다 있나 ②끌어다 놓으면
  갈아끼워지나 ③그때 자막·TTS가 남아있나. **코드로 대신할 수 없다.**

## 안 하는 것 (YAGNI)

- **다중 트랙(완성본 + 계단식 조각)** — 사장님이 "복잡하다"고 폐기. 타임라인은 그대로.
- 대체 후보(안 쓴 장면) 넣기 — 실제 쓰인 조각만.
- 완성본을 자른 조각 — ②(깨끗한 원본 컷)를 골랐다.
- 캡컷 자막 스타일 튜닝 — 기존 그대로.
