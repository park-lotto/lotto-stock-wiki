# 실행 모델 → 아스트라 검수 절차

## 책임과 전달

실행 모델은 구현·테스트·수정·증거 취합을 담당한다. 아스트라는 설계 변경과 최종 경험을 검수한다. 구현자와 독립된 검수자가 요구사항 검수 후 코드 품질을 검토한다. 아스트라의 실질적 검토 없이 이름만 승인자로 적지 않는다. 대표님께 일상 코드 결정·테스트·모델 간 전달을 시키지 않는다.

같은 활성 스레드에서 상위 아스트라가 있으면 실행 모델이 collaboration.send_message로 실제 상위 id에 요청한다. 세션/도구 목록을 먼저 확인하고 /root가 언제나 아스트라라고 가정하지 않는다. 새 세션에서는 지원되는 모델 선택·delegation 도구에 gpt-6-astra가 실제 제공될 때 독립 검수자로 요청할 수 있다. 사용자 이번 지시는 이러한 업무 분배와 검수 요청을 허용하지만 환경의 비용·권한 제한을 변경하지 않는다.

원래 아스트라 세션 자동 재개는 보장되지 않는다. 호출 도구/상위 세션이 없으면 아래 요청서를 저장하고 REVIEW_PENDING으로 둔다. 문서 저장은 전송·열람·승인이 아니다. 안전한 독립 작업은 계속하되 게이트를 건너뛰어 최종 통과를 선언하지 않는다. 사용자가 잠든 동안 새 권한이 필요한 외부 조치는 실행하지 않는다.

## 게이트

| 게이트 | 시점 | 제출물 | 통과 조건 |
|---|---|---|---|
| G1 설계 이탈 | API/저장/보안/핵심 UX 변경 전. 준수 구현은 기존 설계로 진행 | 원래 규격, 변경 이유, 대안, 영향, 시험안 | 아스트라가 변경을 구체적으로 승인. 편의만을 위한 범위 확장 거절 |
| G2 기능·품질 | API/프론트 통합 후 | 실제 diff, 테스트 결과, 재현 명령, DB 보존 증거 | 독립 요구 검수 통과 후 품질 검수, 중요 결함 0 |
| G3 최종 경험 | 실제 브라우저 E2E 후 | 데스크톱/모바일 캡처, 실제 조작 결과, 연결상태, 남은 한계 | 아스트라가 핵심 경험·사실성·최종 판본 검토하고 명시적 승인 |

최종 제출물의 기능 동작을 검수자가 직접 실행하거나 산출물을 직접 열어 확인한다. 구현자 보고, 테스트 건수, AI 간 동의만으로 승인하지 않는다. 문자열 reviewer 입력은 이 프로토콜의 승인 증거가 아니다.

## 검수 요청서 양식

트랙 handoff/reviews/회사운영플랫폼-G2-001.md처럼 게이트/번호를 포함한 새 파일 사용. 서로의 요청/답변을 덮어쓰지 않는다.

```markdown
# 회사운영플랫폼 G2-001
status: REVIEW_PENDING
requester: 실제 모델/세션 id
requested_reviewer: 실제 상위 모델/세션 id 또는 미연결
created_at: 실제 ISO 시각
scope: 검수할 작업과 제외 범위
base_commit: git rev-parse HEAD 실제 결과 (변경이 미커밋이면 명시)
files: 변경 파일 전체 목록
fingerprints: 각 변경 파일 SHA256

## 요구사항별 증거
요구 id / 수행 명령 또는 조작 / 기대 / 관측 / 로그·스크린샷 경로
## 구현 판단
규격에서 달라진 부분, 이유, 대안, 비용·안전 영향
## 알려진 한계
미연결, 미검증, 실패, 미배포를 구분
## 검수자가 재현할 방법
작업 경로, 시험 DB 경로, 실행 명령, URL, 조작 순서
## 요청할 판단
구체적인 승인/반려 대상
## 검수자 답변
실제 검수자가 작성: APPROVED / CHANGES_REQUIRED / BLOCKED
검토 판본, 직접 확인한 근거, 결함, 재검수 조건, 시각
```

승인 뒤 동작 영향 파일이 바뀌면 관련 게이트를 다시 연다. 동일 파일 hash를 증거와 대조한다. 자동 테스트 실패·증거 누락을 known limitation으로 눙쳐 통과시키지 않는다. 동일 문제 두 차례 수정 후에도 실패하면 재현/시도/원인 가설을 상위 검수자에게 올리고 무한 재시도하지 않는다.

## 대표님께 보내는 최종 보고

진입 URL/실행 방법, 실제 되는 기능, 실제 확인한 증거, 미연결·미배포 범위를 짧게 전달한다. 검수 미수신이면 완성품으로 보고하지 않고 차단 사실만 정확히 알린다. 공개·결제·고객 데이터·실서버 배포를 새로 결정해야 할 때만 필요한 판단을 대표에게 요청한다. '최종 결과만'은 실패·권한 문제 은폐 지시가 아니다.
