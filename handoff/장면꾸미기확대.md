### ② 장면 확대 (부분확대)

**조작은 셋뿐이고 전부 같은 상태(ZOOM/ZOX/ZOY)로 모인다**(0순위-B):
- 보고 싶은 곳을 **그냥 누른다** → 그 지점이 원점이 되어 한 단계 확대 (1→1.5→2→2.5→3→1)
- 슬라이더·＋－ → 배율만
- ↩ 원래대로 / `Alt+Shift+Z`

확대 중엔 **배경을 끌면 볼 곳이 움직이고(패닝), 글자를 끌면 자막이 옮겨진다.**

## ★왜 transform:scale인가 (다른 방법은 전부 틀린다)

컨테이너 폭(`--pvw`)을 키우면 **배경만 커지고 글자는 안 커진다.** 글자 px은
`PREVIEW_W=380` 상수로 계산되는데(**12곳**), 이 상수는 서버 렌더(`_UI_REF_W=720`)와
짝이라 **절대 못 바꾼다**(produce.html:3281 주석 — 2026-07-24에 여기서 실제 사고가 났다).

`transform:scale`은 자식 전부를 같은 비율로 확대하므로 그 12곳을 **한 줄도 안 건드린다.**

실측 증거: 확대 1.5배에서 14px 점 → 화면상 **21.00px**(정확히 1.5배)인데
`font-size`는 **20px 그대로**. 즉 실제 렌더와 어긋날 위험이 없다.

## ★기존 드래그와 왜 안 부딪히나

- 글자 드래그는 `#hcPreviewText`/`#capPreviewText` **자신에게** 걸려 있다(bindHCDrag/bindCapDrag).
  컨테이너 빈 배경은 **원래 아무도 안 잡고 있었다**(실측).
- 좌표 계산이 전부 `pv.getBoundingClientRect()` 기준인데 **scale이 rect에 반영**되므로
  비율(%)이 확대 상태에서도 그대로 맞는다. **드래그 코드는 한 줄도 안 고쳤다.**
- 실측 4건 전부 기대값 일치: 확대OFF (x50,y30)·(x25,y60) / **확대2배** (x50,y30)·(x75,y80)

## ★패닝 계수는 유도해서 넣었다 (짐작하면 6배 틀린다)

transform-origin이 o일 때 화면상 위치는 `p' = o + (p-o)*Z`, 따라서 `d(p')/do = 1-Z`.
화면을 dr만큼 끌려면 **Δo = -dr/(Z-1)**.

처음엔 `÷ZOOM*(ZOOM-1)`로 짐작해 적었는데 실측하니 **Z=1.5에서 6배 적게** 움직였다
(정답 -20 vs 코드 -3.33). node로 수식을 대조해 잡았다.

## 캡컷 조사 결과 (2026-08-30 실측, 서브에이전트)

공식 출처로 확인된 것만:
- **캡컷엔 배율 퍼센트 UI가 없다** — 널리 퍼진 "Fit·25%·50%·100% 드롭다운"은 화면
  실측으로 **반증**됨(비공식 포럼 AI 답변이 복제된 것). 플레이어 바엔 돋보기·Ratio·전체화면뿐.
- **단축키(공식 확인)**: `Alt+Shift + +/−` 확대·축소, `Alt+Shift+Z` 맞춤,
  `Ctrl+Shift+F` 전체화면. → **같은 키를 그대로 채택**했다(손에 익은 키를 지어내지 않는다).

# 2차 (2026-08-30 오후) — 끌어서 이동 제대로 + 자막 고정

사장님 지적: "확대하면 안 보이는 부분이 생기잖아 / 마우스로 화면을 잡고 다른 부분으로
이동할 수 있게" + "확대해도 자막 비율과 위치는 고정"

## ★1차 구현이 틀렸던 이유 (transform-origin 방식)

사장님 스샷이 정확히 **130%**였는데, 그 배율에서 두 가지가 동시에 망가진다:

| 문제 | 실측 |
|---|---|
| 가장자리까지 못 간다 | Z=1.3에서 원점을 0%까지 밀어도 **하단 23%는 영영 안 보임**. 자막이 거기 있는데 갈 수가 없다 |
| 이동 감도 폭주 | Δorigin = -dr/(Z-1) → Z=1.3이면 **333배**. 조금만 끌어도 튄다 |

**→ translate 방식으로 교체.** 끈 만큼 1:1로 움직이고(감도가 배율과 무관),
한계는 유도해서 넣었다: `|t| <= W*(Z-1)/(2Z)`
검산 결과 모든 배율에서 **원본 0%에 정확히 닿는다**(모서리까지 전부 보인다).

## ★자막 고정은 "확대 대상"을 바꿔 해결했다

`#hcPreview`(자막 포함) 통째가 아니라 **`#hcPreviewBg`(배경 이미지)에만** scale을 건다.
자막·헤드카피·워터마크는 형제 레이어라 **저절로** 제자리·같은 크기로 남는다 —
**자막 코드는 한 줄도 안 건드렸다.**

덤: PREVIEW_W(=380, 서버 렌더와 짝) 문제가 애초에 안 생긴다. 자막은 확대와 무관하게
늘 실제 비율이라, 완성본에서 어떻게 보일지를 그대로 확인할 수 있다.

## 곁들인 것

- 배율을 바꿔도 보던 자리가 안 튀게 이동거리 환산(`t*prev/z`)
- 끄는 중엔 transition 해제(손가락보다 화면이 늦어 미끄러지는 것 방지)
- 창 크기 변경 시 한계 재적용(빈 자리 노출 방지)
- **배경이 꺼져 있으면** "실장면 배경을 켜세요" 안내 — 확대해도 안 변해 고장으로 보인다

## ⚠️ 게이트가 잡아낸 함정 (다음에 또 밟는다)

`test_preview_seat_js`는 **"#mixPreview의 display를 `_pvShow` 밖에서 만지지 마라"**를
**파일 전체 문자열 검색**(`"pv.style.display" not in outside`)으로 지킨다.

배경 켜짐을 확인하려고 쓴 `pv.style.display`가 **전혀 다른 요소(#hcPreviewBg)를
읽기만 하는데도** 그 검사에 걸렸다. **주석에 적은 같은 문자열도 걸린다.**

→ 테스트를 고치지 않고 **내 변수명을 `bgEl`로 비켰다**. 그 규약은 정당하고
   (2026-08-18 0×0 재발 방지) 침범한 쪽이 나다.
   **교훈: 이 파일에서 `pv`라는 변수명은 #mixPreview 전용이다. 다른 데 쓰지 마라.**

# 3차 (2026-08-30) — UI 정돈 + 모든 장면 같은 배율

사장님: "장면 확대 기능인 걸 모르겠고 짧고 직관적으로 설명하고 잘 보이게"
       "해당 장면을 확대했으면 다른 전체 장면도 같은 비율로 적용할지 말지 체크버튼"

## ①무슨 기능인지 안 읽혔다 → 상자 + 제목

종전엔 회색 hint 두 덩이(화면에선 **4줄**)가 흘러 있어 **기능 이름이 어디에도 없었다**.

```
┌───────────────────────────────┐
│ 🔍 장면 확대  ⓘ          160% │  ← 제목·툴팁·상시 배율
│ [－ ▭▭▭▭ ＋] [↩ 원래대로]     │
│ ✋ 끌어서 안 보이는 곳 보기     │  ← 설명은 한 줄
│ ☑ 모든 장면에 같은 배율        │
└───────────────────────────────┘
```

긴 설명(보기 전용·자막 고정)은 **ⓘ 툴팁**으로 접었다 — 필요한 사람만 본다.
배율은 제목 줄에 **상시** 표시(미리보기 위 뱃지는 확대 때만 뜬다).
