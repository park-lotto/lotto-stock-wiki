# 쇼핑쇼츠 원클릭 오케스트레이터 — 설계 (2026-07-18)

> 작성: 페이블(계획 전담) 세션 / 구현: 오푸스 세션들에게 트랙 단위로 핸드오프
> 근거: 핸드오프 8종 + `mix_pipeline.py`/`edit_plan.py` 시그니처 + `app.py` 라우트 실측 조사 (2026-07-18)

## 0. 한 줄 요약

지금의 단계별 수동 위저드(D버전)를 유지한 채, 그 뒤에 **백엔드 러너 + 단계별 자동 심사**를 얹어
"애매할 때만 사람을 부르는" C버전으로 진화시키고, 최종적으로 **딸깍 + 최종 승인 1회**(A버전)에 도달한다.
완전 무인(B)은 목표가 아니라 **A의 승인률 지표(90%+ 지속)가 증명하면 열리는 문**이다.

## 1. 버전 정의와 로드맵

| 버전 | 정의 | 사람 개입 |
|---|---|---|
| **D (현재)** | produce.html 위저드, 단계마다 사람이 픽·클릭 | 매 단계 |
| **C** | 러너가 자동 진행, 심사가 `unsure` 판정한 단계만 사람 호출 | 0~2회/편 |
| **A** | 딸깍 1번 → 완성본, 최종 승인만 | 1회/편 |
| **B-lite** | 무인 생산 → "업로드 대기함" → 하루 1번 훑어 ✔/✖ | 1회/일 |
| **B** | 업로드까지 무인 | 0 |

전환 조건: D→C = 하드블로커 해소 + 러너 뼈대 / C→A = unsure 발생률이 충분히 낮아짐 /
A→B-lite = 운영 판단 / B-lite→B = **최종 승인 통과율 90%+ 지속** (pick_events로 측정).

## 2. 사장님 확정 결정 (2026-07-18)

1. **VMake 결제한다** — 실연동 트랙의 전제 해소.
2. **unsure 알림 = 텔레그램** — 기존 텔레 인프라 재사용.
3. **자동픽 안전선 = 레퍼런스 풀 큐레이션** — 직접촬영형 채널은 사장님이 레퍼런스에서 삭제,
   **짜집기 채널만 남긴다**. 즉 안전선은 심사 코드가 아니라 **데이터 계층(등록 채널 = 이미 안전)**.
   러너는 "등록된 레퍼런스 채널 외 소스 금지"만 지키면 된다.
4. **편당 원가 상한 = 1,000원** — 러너에 원가 미터 필수. 상한 도달 시 진행 중단(=unsure 승격).

## 3. 아키텍처

```
auto_run.py (신규, 백엔드 전용)          produce.html (기존, 최소 수정)
┌───────────────────────────────┐       ┌────────────────────────┐
│ S1 랭킹픽 → S2 대본 → S3 믹스 →  │ unsure │ 기존 위저드 = 검수판     │
│ S4 VMake → S5 TTS(믹스내) →     │ ─────→ │ 해당 step 딥링크로 열림  │
│ S6 꾸미기 → S7 썸네일 → S8 SEO  │ 텔레알림│ "계속" 누르면 러너 재개  │
│ 각 단계: 실행 → 심사 → 3판정     │ ←───── │                        │
└───────────────────────────────┘  재개   └────────────────────────┘
```

**설계 원칙**
- **화면을 새로 만들지 않는다.** produce.html은 4개 트랙이 동시 편집 중(seam 사고 이력).
  러너 관련 프론트 수정은 ①픽로그 훅 ②"계속(재개)" 버튼, 딱 2가지로 제한.
- **기존 엔진을 부수지 않는다.** `run_mix_job`·`build_edit_plan`·썸네일 프레임추출 등을
  어댑터가 **호출만** 한다. D(수동)와 C(러너)가 같은 엔진 공유 — 결과물이 갈라지면 안 된다.
- **러너 v1은 동시 1 job.** MIX_JOB이 전역 싱글톤 성격(새로고침 미복원)이라 병렬은 실측 후.

## 4. 단계 어댑터 — 통일 계약

```python
@dataclass
class StageResult:
    output_ref: str      # DB row id 또는 파일 경로
    metrics: dict        # 심사가 볼 숫자들 (ffprobe 값, ASR 일치율, 비용 등)
    candidates: list     # N-best일 때 후보 목록 (없으면 빈 리스트)

def run_stage(job, stage) -> StageResult     # 기존 함수 래핑 (엔진 호출만)
def judge(job, stage, result) -> Verdict     # "pass" | "unsure" | "fail" + reasons
```

## 5. 판정 정책

```
pass   → 다음 단계로 자동 진행
fail   → 변주 재시도 (최대 2회: 다른 초안·다른 시드) → 여전히 fail이면 unsure로 승격
unsure → job.status = waiting_human, 텔레그램 알림 + produce.html 해당 step 딥링크
비용상한(1,000원) 도달 → 즉시 unsure (재시도 금지)
```

**심사기는 2층.** v1 = 기계 게이트만(숫자, 코드 판정 — 싸고 확실).
v2 = LLM 심사(Gemini + pick_events 취향 예시 주입) — **픽로그 데이터가 쌓인 뒤에** 얹는다.

## 6. 단계별 기계 게이트 (v1)

| 단계 | 합격 기준 (코드로 재는 것) |
|---|---|
| S1 랭킹 | 48h 필터 + 강도점수 1등 자동픽. **등록 레퍼런스 채널 외 소스 금지**(결정 3) |
| S2 대본 | 스키마 검증(훅 존재·비트 수·금칙어), 소재고정 자물쇠 통과 |
| S3 믹스 | ffprobe 720×1280/30fps, 장면 수 ≥ N, 총 길이 허용범위 |
| S4 VMake | 처리 전후 길이·fps 동일, 자막영역 프레임 diff > 임계치, 오디오 보존 |
| S5 TTS | **ASR 재전사 일치율 ≥ 임계**, **무음 검출**(키 소진 시 무음mp3 함정 — tts.py:51), 자막싱크 오차 ms |
| S6 꾸미기 | 기본스타일(applyDefaultStyleOnEntry) 적용 확인 |
| S7 썸네일 | 프레임 선명도·밝기 하한, 텍스트 렌더 확인, `selected` 기록 |
| S8 SEO | 제목 길이·태그 20개·스키마 검증 |
| 전역 | 파일 존재+크기 > 0, 단계 누적 비용 ≤ 1,000원 |

임계치 수치는 구현 트랙에서 실데이터로 캘리브레이션 (스펙에 박아두면 근거 없는 상수가 됨 — SEO 트랙의 교훈).

S5 품질이 바닥이면 unsure만 쏟아진다. 자막싱크·장면라이브러리 페이즈2도 S3·S5 품질에 직결.

## 9. 리스크 (구현자가 부딪힐 것, 미리 명시)

1. **MIX_JOB 전역상태** — 새로고침 미복원·싱글톤 성격. 러너 v1은 동시 1 job 제한. 병렬화는 별도 설계.
2. **TTS 무음 함정** — ElevenLabs 키 0개면 조용히 무음mp3(tts.py:51). S5 게이트의 무음 검출이 마지막 방어선.
3. **비용 폭주 구조** — 재시도 2회 × N-best 3배 × Gemini 심사가 곱으로 늘어남. 원가 미터가 없으면 상한(1,000원)을 지킬 수 없다. 미터는 러너 뼈대(트랙 4)에 처음부터.
4. **produce.html seam** — 4트랙 동시 편집 중. 프론트 수정은 픽로그 훅 + "계속" 버튼만. 새 화면 금지.
5. **VMake 첫 실전** — mock으로만 검증된 코드. 실스펙 교체 후 첫 렌더는 반드시 사람 눈으로.
6. **썸네일 `selected` 소비자 부재** — 업로드 배선(트랙 6)까지는 selected가 죽은 데이터. 트랙 6에서 배선.

## 10. 성공 지표

- **C 가동**: 텔레 알림 → 딥링크 → 재개가 실편 1개에서 끝까지 관통
- **C 품질**: 편당 unsure 횟수 (목표: 평균 2회 이하 → A 전환 검토)
- **A 전환 후**: 최종 승인 통과율 (**90%+ 지속 = B-lite→B 전환 근거**), 편당 원가 ≤ 1,000원
- 모든 지표는 auto_jobs + pick_events에서 쿼리로 산출 가능해야 함 (별도 측정 장치 금지)
