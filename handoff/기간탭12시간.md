# 레퍼런스 기간 탭 — '12시간 히트작' 추가 (2026-09-10)

## 사장님 제보
"이거 12시간탭도 만들어서 작동되게 가능한가?" / **"유튜브가 꼭 되어야 해"**

## 무엇을 했나
`shopping_shorts/static/index.html` 한 파일. **서버 변경 0 · 추가 크롤 0.**

- 기간 탭에 `⚡ 12시간 히트작` 추가. `data-span="0"` + **`data-hours="12"`**
  (48시간 탭에도 `data-hours="48"`) — 서버 요청은 두 탭이 완전히 같다(`days=0` → `load_last_run`).
  자르는 건 화면 한 곳(`SPAN_HOURS`)뿐이다.
- 컷을 **`ageHoursNow()`로 통일**(종전 raw `age_hours`).
- 0건일 때 이유·대안을 화면에 적는다. 12시간 탭은 **원래 자주 빈다** — 고장이 아니다.

## ★왜 A안(화면 컷)이고 B안(hits_since 시간축)이 아닌가
`hits_since()`의 기준 `first_seen`은 **우리가 수집한 시각**이다.
`scripts/daily_youtube_collect.py:15` `daily_collect_done::youtube` — **유튜브는 하루 1회만 수집**한다
(타이머 6회는 실패 시 재시도용). 값이 하루 1개뿐이라 12시간 창이 **통째로 빈다.**
게다가 `store.py:3316`이 `f"-{int(days)} day"`라 0.5를 넣으면 `0 day` → **조용히 0건**.

## ★왜 raw age_hours를 쓰면 안 되나
`age_hours`는 **수집한 순간 찍힌 스냅샷**이다. 하루 1회 수집이면 최대 24시간이 통째로 빠져
"12시간 탭인데 30시간 전 영상"이 남는다. `ageHoursNow()`가 수집 이후 흐른 시간을 더해준다.

## 서버 실측 (last_run::youtube, 수집 2026-09-09T23:10Z, 9,983건, drift 3.3h)
```
12h  →   80건        24h  →  596건        48h  → 1,315건
age_hours 없는 건 0  (전부 시간을 안다 → 유튜브도 진짜 '올라온 지' 기준으로 갈린다)
```

## ⚠️ 알고 있어야 할 한계
유튜브는 하루 1회 수집(08:10 KST) → **수집 후 12시간이 지나면 12시간 탭이 0건에 수렴한다.**
오전~저녁은 보이고 밤에는 빈다. 이건 데이터의 한계지 버그가 아니다.
정말 하루 종일 채우려면 **유튜브 수집 횟수를 늘리는 것**이 유일한 길이다(별건).
