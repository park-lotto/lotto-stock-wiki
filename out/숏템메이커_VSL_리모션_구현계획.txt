숏템메이커 VSL — Remotion 구현 계획 (2026-07-30)
설계 방향(사장님): 배경엔 프로그램이 계속 돌아가고, 그 위에 Remotion 그래픽이 나레이션에
붙는다. 실제 조작(튜토리얼) 구간만 정확히 매칭한다.
======================================================================


■ 1. 레이어 구조 — 4층이면 끝난다
----------------------------------------------------------------------
  4층  자막(캡션)        나레이션 워드 타임스탬프로 자동 싱크
  3층  그래픽 오버레이    딤·중앙자막·클릭카운터·좌우대결·카드  ← Remotion
  2층  배경 = 화면녹화    프로그램이 계속 흐른다(끊지 않음)
  1층  나레이션 오디오    씬별 mp3 (일레븐랩스 v2 감정톤판)
  0층  BGM(작게, 선택)

  ★핵심: 배경은 **자르지 않는다.** 길이는 배속으로 맞춘다.
    (경쟁사 실측: 데모 구간 컷이 분당 1~2개뿐 — 컷을 안 쓰는 게 정답이었다)


■ 2. 싱크는 두 모드로만 나눈다 (이게 이 계획의 핵심)
----------------------------------------------------------------------
  ① 느슨 모드 — 나레이션이 '개념'을 말하는 구간
     예) "원리는 간단합니다. 지금 터지는 영상을 찾아주고…"
     → 배경은 아무 데나 흘러도 된다. 배속으로 길이만 맞춘다. 정밀 싱크 불필요.

  ② 정밀 모드 — 나레이션이 '지금 이걸 누릅니다'를 말하는 구간 ★튜토리얼
     예) "카테고리만 고르고, 렌즈 검색만 누릅니다"
     → 그 말이 끝나는 프레임에 **클릭이 화면에 보여야 한다.**

  앵커는 챕터당 2~3개면 충분하다. 전체를 맞추려 하면 무너진다.

  앵커 파일 (사람이 손으로 적는다, 10줄이면 끝)
  ┌ anchors.json ────────────────────────────────────────────┐
  │ [                                                        │
  │  {"scene":"S5-1", "say":"렌즈 검색만 누릅니다",           │
  │   "video":"clipB.mp4", "at": 41.8},   ← 녹화상 클릭 시각  │
  │  {"scene":"S5-1", "say":"담기만 누르면 끝입니다",         │
  │   "video":"clipB.mp4", "at": 58.1}                        │
  │ ]                                                        │
  └──────────────────────────────────────────────────────────┘
  · "say"의 발화 시각은 **자동으로 구한다** → asr_check.transcribe_words(mp3)
    (이미 있는 함수. GROQ Whisper 워드 타임스탬프)
  · "at"은 녹화 파일에서 그 클릭이 일어난 시각 → 찍고 나서 눈으로 한 번 적는다
  · 나머지는 계산: 두 앵커 사이 배속 = (video구간) ÷ (나레이션구간)
    → 앵커 사이만 배속이 달라지고, 앵커에서는 정확히 만난다


■ 3. 이미 있는 것 재사용 (새로 만들 게 적다)
----------------------------------------------------------------------
  shopping_shorts/motion/src/
    CountCard.tsx    → **클릭 카운터** ("클릭 12") 그대로 쓸 수 있다
    ListReveal.tsx   → **좌우 대결 체크리스트** (항목 순차 등장)
    ImpactText.tsx   → **딤 + 중앙 대형 자막** (훅 구간)
    CalloutCard.tsx  → **오퍼/페인 카드**
    theme.ts         → 색·폰트 통일(브랜드 톤 유지)
  remotion-stock/src/LongformComposition.tsx → 16:9 롱폼 베이스

  ⚠️ motion/ 부품은 720x1280(세로)용이다. VSL은 1920x1080(가로)라
     크기·여백만 조정하면 로직은 그대로 쓴다.


■ 4. 새로 만들 컴포넌트 — 3개뿐
----------------------------------------------------------------------
  ① <ScreenTrack>   배경 화면녹화 재생기
     props: src, segments=[{from, to, speed}]
     · 구간별 배속을 받아 재생. 대기 구간은 speed를 크게 주거나 잘라낸다.
     · 결과물 재생 구간은 speed=1 고정(정점이라 배속 금지)

  ② <Versus>        좌우 대결
     왼쪽=ListReveal(옛 방식 체크리스트) / 오른쪽=ScreenTrack(우리 화면)
     오른쪽이 끝난 뒤에도 왼쪽이 계속 켜지는 게 포인트

  ③ <ScriptMatch>   대본↔화면 일치 증명 ★우리 최대 차별점
     위: 대본 문장 한 줄 / 아래: 그 장면
     문장이 넘어갈 때 장면도 같이 넘어가는 걸 3~4회 연속으로


■ 5. 파이프라인 (순서대로 하면 된다)
----------------------------------------------------------------------
  1) 나레이션 mp3 뽑기        일레븐랩스, v2 감정톤판, 씬 단위로
  2) 워드 타임스탬프          asr_check.transcribe_words(mp3) → words.json
  3) 화면 녹화               촬영시트 B·C를 끊지 않고 한 번에
  4) 앵커 적기               anchors.json (챕터당 2~3줄)
  5) 배속 자동 계산           앵커 사이 구간 speed 산출 → segments 생성
  6) Remotion 미리보기        씬 하나씩 눈으로 확인 ← 여기서 대부분 고친다
  7) 렌더                    씬별 → 합치기

  ※ 6번을 건너뛰면 반드시 어긋난다. 씬 하나 확인에 1분이면 된다.


■ 6. 태스크 순서 (심플하게, 4개)
----------------------------------------------------------------------
  T1  16:9 VSL 컴포지션 스캐폴드 + <ScreenTrack>
      → 화면녹화 하나를 배속 구간으로 재생만 되면 성공
  T2  나레이션 + 자막 배선 (words.json → 자막 자동)
      → 소리와 자막이 맞으면 성공
  T3  앵커 싱크 계산 (anchors.json → segments 자동 생성)
      → "렌즈 검색 누릅니다" 말이 끝날 때 클릭이 보이면 성공 ★이게 본체
  T4  오버레이 3종 (<CountCard> 카운터 · <Versus> · <ScriptMatch>)
      → 기존 부품 크기만 맞추는 작업

  T1~T3이 되면 나머지는 장식이다. T4는 없어도 영상이 성립한다.


■ 7. 함정 (미리 박아둠)
----------------------------------------------------------------------
  · **배속을 균등하게 걸면 망한다.** 대기는 크게, 조작은 1~1.5배, 결과는 1배.
  · **타이머는 넣지 않는다.** 렌더 시간이 서버 부하로 흔들려 숫자가 배신한다
    (오늘 실측 8~10분). "10분"은 나레이션으로만 말한다.
  · 클릭 카운터 숫자는 **찍으면서 센 실제 값**을 쓴다. 추정치 쓰면 세다 틀린다.
  · 나레이션을 화면에 맞추려고 늘리거나 줄이지 않는다 → 톤이 깨진다.
    항상 오디오가 기준, 화면이 따라간다.
  · 경쟁사 영상 화면을 그대로 쓰지 않는다(저작권). 옛 방식은 우리 화면으로 찍거나
    체크리스트 애니메이션으로 대체.
