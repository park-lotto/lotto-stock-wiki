# CTA 잘라낸 버전 만들기 — 구현 계획 (2026-09-05)

## 사장님 요청
> "CTA 있는 걸로 만들고 유튜브 올릴 때 뒷부분만 잘라내고 싶은데 렌더 시 그 기능을 추가할 수가 있나"
> "잘라내는 건 렌더가 한 번 더 해야 하나" → **아니오. `-c copy`로 1초 내.**

확정 답변(AskUserQuestion):
- 형태: **렌더 후 "뒷부분 잘라내기" 버튼** (9단계 완성본 패널)
- 기준: **CTA 비트(칸) 단위로 자동**
- 자막: 그냥 잘라내면 끝 (CTA 자막도 같이 사라짐 — 추가 작업 없음)
- 범위: **A+B** (새 영상은 프레임 정확, 옛 영상은 TTS mp3 폴백)

## 실측으로 확인된 사실 (추측 아님)

| 사실 | 근거 |
|---|---|
| 최종본 = `data/mix_jobs/{job_id}/final.mp4` | mix_pipeline.py:3240, DB 확정 3317 |
| 렌더 파이프라인 이미 `-c copy` concat 사용 | video_assemble.py:1702, 2655 |
| 재인코딩은 2GB 서버서 수십 초 → 피하는 게 이 코드베이스 원칙 | video_assemble.py:2634 주석 |
| **`-g`/keyint 설정 코드 전체 0건** (libx264 기본 ≈8초) | grep 결과 0건 |
| `_burn_captions`가 최종본을 통째 재인코딩 → 비트 경계 키프레임 소멸 | video_assemble.py:104 주석, 2502/2563 |
| **비트별 t0(절대 시작초)가 DB·파일 어디에도 저장 안 됨** | 조사 결과. `_beat_timeline`이 계산 후 버림 |
| t0 계산 단일 출처 = `_beat_timeline` | video_assemble.py:2214 |
| CTA 판정 단일 출처 = `_is_cta` | edit_plan.py:3034 (`_CTA_ROLES` 3027) |
| 작업폴더는 청소 대상(asm_ 321개=21GB 사고) | video_assemble.py:2579, disk_cleanup.py |

→ **B(버튼 누를 때 계산)만으로는 시간이 지나면 조용히 죽는다.** 그래서 A를 기본, B를 폴백.

## 설계 (0순위-B 준수: 같은 판단을 두 번 적지 않는다)

### T1. CTA 시작초를 렌더 시 DB에 저장 + 그 지점에 키프레임 강제

- **판정처 하나**: `video_assemble.py`에 `cta_cut_sec(timeline)` 신설.
  - `edit_plan._is_cta`를 **재사용**(새 판정 금지). 순환import 주의 → 지역 import.
  - 마지막 CTA 비트의 `t0` 반환. CTA 없으면 `None`.
- **키프레임**: `_burn_captions` 내부는 이미 `timeline`을 갖고 있다(2433) → 인자 추가 불필요.
  - 옵션 생성 헬퍼 `_keyframe_args(cut_sec)` 하나 → `["-force_key_frames", f"{cut_sec:.3f}"]`
  - 인코딩 갈래 **2곳**(2502, 2563)에 같은 헬퍼를 끼운다(값 정의는 한 곳).
- **저장**: `mix_pipeline.run_render`에서 `assemble` 후 `store.update_mix_job(job_id, cta_cut_sec=...)`
  - ⚠️ 썸네일 인트로(prepend_still, 3305)가 앞에 붙으면 **모든 시각이 intro_sec만큼 밀린다** → 저장 값에 반영 필수.
  - 스키마: `mix_jobs`에 `cta_cut_sec REAL` 컬럼 추가 (store.py:879 인근) + `update_mix_job` 화이트리스트(4959 인근) + `get_mix_job` SELECT(4848).

### T2. 잘라내기 API

- `@app.post("/api/mix/trim_cta/{job_id}")` (app.py)
  - ⚠️ **`_USER_ERROR_RULES`~`_script_hash` 슬라이스exec 구간에 라우트 넣지 말 것** (메모리: app 슬라이스exec).
  - 절차: job 조회 → `cta_cut_sec` 있으면 사용(A) / 없으면 `_beat_timeline` 재계산 폴백(B, TTS mp3 필요)
  - 둘 다 실패 → 사유가 갈라지는 명확한 에러(메모리: 오류표본·뭉갠사유). "CTA 칸이 없습니다" / "옛 영상이라 원본 음성이 지워졌습니다"를 구분.
  - `ffmpeg -y -i final.mp4 -t {cut} -c copy final_nocta.mp4` → `ensure_faststart`
  - 캐시: 이미 있고 final.mp4보다 새것이면 재생성 안 함(mtime 비교)
- `@app.get("/api/mix/video_nocta/{job_id}")` — `?dl=1` 첨부. 기존 `api_mix_video`(app.py:6971) 패턴 그대로.

### T3. 완성본 패널 버튼

- `static/produce.html` `renderExport()` 안(14548 다운로드 버튼 옆)
  - `✂ 뒷부분(CTA) 잘라낸 버전` 버튼 → POST → 성공 시 다운로드 링크 노출
  - CTA 없는 대본이면 버튼 자체를 숨김(서버가 알려준 `cta_cut_sec`으로 판단)

## 검증 (0순위-A1 — 실제로 돌려보고 확실할 때만 "됐다")

```
□ 단위: cta_cut_sec가 CTA 비트 t0를 맞게 뽑나 (CTA 없음/여러개/인트로 있음 케이스)
□ 실렌더: 실제 job 하나를 렌더 → final.mp4 생성 → 버튼 눌러 final_nocta.mp4 생성
□ ffprobe로 실측: nocta 길이 == cta_cut_sec (±1프레임=0.033초)
□ 눈으로: 잘린 영상 마지막 프레임이 CTA 직전인가 (스크린샷)
□ 폴백(B): cta_cut_sec 없는 옛 job에서도 되나
□ 게이트: py tools/track.py finish CTA잘라내기 — 기준선 대비 실패 안 늘었나
```

⚠️ 정적 검토·문법 통과는 확인이 아니다. 실제 mp4를 만들어 ffprobe로 재고 눈으로 본다.
