# 칸 타임라인 — 자막·TTS·컷을 한 시간축에 (캡컷 대체) 설계

- 날짜: 2026-08-29 (회사PC) · 트랙: `칸타임라인`
- 결정자: 사장님 (A안 확정 — 칸마다 타임라인, 시안 HTML 육안 확인 후)
- 시안: scratchpad `타임라인_시안.html` (A/B/C 비교, 재생선 동작 포함)

## 목적

"대본+TTS 싱크가 먼저, 장면 매칭은 그 다음"이라는 파이프라인 순서를 **화면으로** 만든다.
칸(비트)마다 자막 구절·TTS 음성·담긴 컷이 한 시간축에 정렬돼 보이고, 구절이 1.2초면
필름에서 1.2초 오렌지박스를 잘라 올리면 딱 맞는다 — 캡컷 없이 여기서 끝낸다.

**건드리지 않는 것(사장님 확정)**: AI 매칭(픽) 로직은 이번에 1도 안 바꾼다.
지금 잘 되고 있고, 과거 실측(프롬프트 과적재 "만질수록 이상해짐"·스타일감점·참고훅 주입
부작용)이 "잘 되는 것에 축 추가 = 회귀 위험"을 증명했다. 화면·편집·측정만 만든다.

## 이미 있는 재료 (2026-08-29 실측 — 새 배선 최소화의 근거)

| 재료 | 위치 | 쓰임 |
|---|---|---|
| 칸별 TTS mp3 | `tts/beat_N.mp3` | 음성 트랙·재생 |
| 구절 시간표(실발화 초) | `DATA.captions[i]` {start,end,text} — 렌더와 같은 함수로 계산 | 자막 블록 폭·초 배지 |
| 칸 음성 길이 | `DATA.tts_dur[i]` | 시간축 길이 |
| 워드 타임스탬프 | 믹스 때 `_beat_words()`(TTS 제공 → ASR 폴백), `mix_pipeline.py:57` | 구절 경계 재계산(⑥⑨) |
| 구절 경계 통로 | `caption_lines`(preset) → `_caption_segments` | 사용자 경계 저장(⑥) — 렌더·연구소 동일 경계 |
| 칸 재생(화면+음성+자막) | `scene_play.js` `playBeat(i)`·`previewTimeNow()`·`capAt()` | ② 재생선 |
| 필름 프레임 추출·캐시 | `filmroll.js` fillVisible/CACHE | ④ 컷 필름 펼침 |
| 구절 초→[+구간] 입력 | F21 배선(filmroll `setBoxLen`) | ③ |

## 설계 (①~⑨ + 로그)

### ① 배치
선택된 칸("여기에 담깁니다")의 머리줄 아래에 3줄 타임라인:
```
컷 필름  [카드1 1.9s   ][카드2 2.2s    ][0.2s 비었음(점선)]
자막     [마침 파티플래너인 친구가 1.9s][구데 … 추천해 주는데 2.2s]
음성     ▶━━━━🔴━━━━━━━━━━ beat_1.mp3 · 4.1s
```
- 다른 칸은 기존 그대로, 칸을 선택하면 타임라인이 그 칸으로 옮겨간다.
- 배율: 칸 길이(tts_dur)가 타임라인 폭을 채우도록 자동(pps = 폭/초).
- 기존 카드줄·삭제·병합·✂펼치기·늘려채우기 전부 유지 — 타임라인은 위에 얹는 층.

### ② 재생·재생선
- ▶ = 기존 `playBeat(i)` 호출(새 재생 경로 금지 — 0순위-B).
- 재생선은 rAF로 `previewTimeNow()`를 따라가고, 지금 읽는 구절 블록이 켜진다(`capAt`).

### ③ 자막 블록 상호작용
- 클릭 → 그 구절 초를 열린 필름의 [+구간] 길이칸에 자동 입력(F21 재사용).
- (구현 중 확정) "그 구절 시작으로 시크"는 뺐다 — 재생 엔진(seq)이 칸 중간 진입을
  지원하지 않아, 화면·음성이 어긋난 채 흉내만 내게 된다. 필요해지면 seq 오프셋
  지원과 함께 2단계.
- 모자란 구간(예: 3.4/3.6의 0.2초)은 컷 lane 끝에 점선 빈 블록 — 어느 구절 자리가
  비는지 눈에 보인다.

### ④ 컷 블록 — 카드 ↔ 필름식 펼침
- 기본 = 지금처럼 **대표 썸네일 1장**(어떤 카드인지 식별) + 길이 배지. 폭 = 길이×pps.
- 블록 클릭 = 같은 폭 안에서 실제 프레임들이 시간순으로 깔리는 **필름식 펼침**(캡컷식),
  다시 클릭하면 카드로. 프레임 추출은 filmroll의 추출·캐시 부품 재사용(브라우저 시크,
  이미 라이브 검증된 방식). 1.9초 ≈ 6~8프레임, 최초 1초 안팎·이후 캐시 즉시.
- 블록 안 ✂ = 기존 필름롤 열기(자르기 작업은 종전대로 아래에서).

### ⑤ 이번 범위 밖 (2단계)
- 타임라인 위에서 컷 가장자리 직접 드래그 트리밍(지금도 필름롤 오렌지박스로 가능).
- 전체(칸 이어붙임) 타임라인 — C안 2단계.

### ⑥ 구절 경계 편집 (재TTS 없음)
- 자막 블록에서 **어절(단어) 사이**를 눌러 끊기/합치기. 단어 중간은 애초에 못 끊게 한다
  (워드 타임스탬프가 단어 단위 — 중간 절단은 비례 추정으로 떨어져 부정확).
- 저장은 기존 `caption_lines`(preset) 한 통로 → 연구소·타임라인·최종 렌더가 같은 경계.
- 서버가 저장된 워드 타임스탬프로 각 구절 초를 재계산해 반환(재합성 없음).
  기존 `caption_sync.phrase_durs_from_words(narration, words, dur, preset)` 재사용.

### ⑦ 싱크 감사 + 폴백 표면화
왜: 타임스탬프는 3단 사다리(TTS 정밀 → ASR → 글자수 추정)인데 어느 단으로 만들어졌는지
표시가 없어, 조용히 3단으로 떨어진 작업이 "안 맞는 작업물"이 된다. 끝단 실측도 없어
수리 여부를 눈·귀로만 판정해 왔다(2026-08-06·08-10·08-22 사고 이력).
- (a) cap_durs 산출 단계를 job에 저장(`precise|asr|estimate`) → 타임라인 칸에 표시.
  추정이면 "🔊 다시 뽑기 한 번이면 정밀로 올라갑니다" 안내.
- (b) 감사: 최종 음성 기준 구절 전환 시각 오차를 job마다 수치로 기록, 오차 큰 칸에 ⚠.
  (측정 먼저 — 몇 %가 실제로 어긋나는지 숫자로 나온 뒤에 다음 수리를 정한다)

### ⑧ 다 채움 + 고정길이 박스 장면 교체
- AI 믹스가 배치를 끝내면 타임라인은 "다 채움" 상태(컷들이 구절 초에 맞물려 꽉 참).
- 컷 교체: 그 컷 길이로 **길이가 잠긴 오렌지박스**가 소스 필름 위에 떠 있고, 필름을
  영상1→2→3으로 갈아끼워도 박스는 유지된다. 마우스로 박스만 좌우로 옮겨 맞는 장면을
  찾고 [올리기] → 그 자리 컷 교체(길이 잠금이라 초가 항상 맞음).
- 구현: filmroll의 BOXES에 "길이 잠금 + 영상 전환 시 유지" 모드 추가(기존 부품 확장,
  새 자르기 UI 금지 — 0순위-B).

### ⑨ 구절 경계 변경의 연쇄 자동 갱신
진실은 구절 시간표 하나. 경계를 바꾸면:
구절 초 재계산(⑥) → 자막 블록 폭·배지 갱신 → 컷 자리 목표 초·모자람/남음 재표시 →
⑧ 고정길이 박스의 잠긴 길이도 자동 갱신. 손으로 따라 고치는 곳이 0이어야 한다.

### 교체 로그 (⑩ 축소판 — 기록만)
- ⑧로 장면을 바꿀 때마다 "AI 픽 seg → 사람 교체 seg + 구절 텍스트·초"를 서버에 기록.
- 픽 로직·프롬프트에는 **주입하지 않는다**. 로그가 "어디서 반복적으로 손이 가는지"를
  숫자로 보여준 뒤에만, 그 한 축을 토글 뒤에서 바꿔 육안 대조한다(회귀 방지 —
  사장님 확정).

## 하지 않는 것 (명시)

| 항목 | 이유 |
|---|---|
| 매칭을 구절 단위로 변경 | 픽 로직 수술 — 회귀 위험, 근거 없음 |
| 길이 적합도 감점 추가 | 픽 점수 변경 — 스타일감점 사고 부류 |
| 손교체 예시 프롬프트 주입 | 참고훅 부작용 전례 — 기록만 |
| 자동 재픽 루프 / 판정축 증설 | 로그·감사 숫자가 나온 뒤 별도 트랙 |
| 타임라인 직접 트리밍·전체 타임라인 | 2단계 |

## 서버 변경(신규 최소)

1. `POST /api/mix/scene_lab/{job}/caption_lines/{beat}` — 사용자 경계 저장 +
   `phrase_durs_from_words` 재계산 결과(captions 시간표) 반환. (⑥⑨)
2. cap_durs 산출 단계 저장·노출(기존 fetch 응답에 필드 추가). (⑦a)
3. 교체 로그 저장 엔드포인트(간단 append). (로그)
4. 감사 배치(⑦b)는 별도 태스크 — 화면과 독립이라 뒤로 뺄 수 있다.

프론트는 scene_lab.html에 타임라인 부품 1개(칸 렌더에 삽입), filmroll.js에
길이잠금 박스 모드. 좌표 규약은 "층은 translate, 자식은 절대"(2026-08-29 off
이중차감 사고의 규약)를 따른다.

## 검증 계획 (로컬 = 라이브처럼)

- 서버에서 실제 job 하나(`mix_jobs` 폴더: tts mp3·시간표·소스 mp4)를 scp로 복사 →
  로컬 uvicorn(DASH_PASS 비움)에서 실데이터로 화면·재생·재계산 전부 확인 →
  사장님 육안 확인 후에만 finish. (file:// 하네스는 썸네일 불가 — 실서버 방식 필수,
  필름롤 트랙 실측)
- 재생선 정확도는 필름롤 때 만든 Playwright 하네스 방식(픽셀↔초 대조)으로 실측.
- 게이트: 기존 pytest + 신규 엔드포인트 테스트(경계 저장→재계산 왕복, 잠금 박스 유지).

## 단계 (구현 순서 제안)

1. **T1 타임라인 뷰**(①②③④, 읽기 전용+재생) — 매칭·저장 무변경, 회귀 0.
2. **T2 구절 경계 편집**(⑥⑨ + 서버 1·2번).
3. **T3 고정길이 박스 교체**(⑧ + 교체 로그).
4. **T4 싱크 감사 배치**(⑦b) — 독립.
