인스타 수집의 `classify_channel_result`는 `error도 아니고 nodes도 없고 로그인벽 URL도
아니면` 전부 한 통에 넣는데, 그 이름이 **`not_found`(채널이 없다)** 였다. 채널 존재를
확인하는 코드는 어디에도 없다.

이 이름 하나로 **같은 오독이 두 번** 났고, 두 번 다 원인은 우리 코드였다:
- 2026-08-09: 관문 URL이 목록에 빠져 199채널 전부 not_found → "채널이 다 없어졌다" →
  "계정 한도소진"이라는 엉뚱한 결론. 진짜 원인은 계정↔IP 불일치.
- 2026-08-17: 61채널 not_found → 나도 "죽은 채널 정리 필요"로 보고할 뻔했다.
  진짜 원인은 `instagram_playwright.py`의 **고정 2.5초 대기**(응답을 기다리는 게 아니라
  2.5초 자고 일어나 없으면 빈손). 실측: 같은 14채널 2.5초 5/14 → 10초 14/14,
  수확 0이던 30채널은 15초에서 **30/30 전부 회수**. 죽은 채널은 0개였다.
  → `unknown`으로 개명 + 도달 URL·채널별 판정 기록 추가.

**결정적이었던 판단 근거**: `instagram_playwright.py:14` 주석에 잘 돌던 때 실측이
박혀 있었다 — "192채널 ok187·not_found5" = **실패율 2.6%**. 이번 55%는 20배다.
이 대조가 없었으면 "인스타 긁다 보면 그럴 수 있지"로 넘어갔을 것이다.

**그래서 지킬 것**
- 실패 통계를 볼 땐 **코드·문서에 남은 기준선과 먼저 대조**한다. 대조 없이는 회귀를 못 본다.
- 실패가 정상값으로 반환되는 자리(`else`·기본값·나머지 통)는 이름이 원인을 단정하면 안 된다.
  모르면 `unknown`이라 적어야 다음 사람이 원인을 찾으러 간다.
- **집계 숫자만 남기지 마라.** 61개가 실패한 건 알아도 어느 채널인지 복구가 불가능했다
  (등급 재계산이 329로 나와 실제 런 110과 안 맞았다). 목록으로 남겨야 재시도할 수 있다.
- **재시도를 처방으로 먼저 붙이지 마라.** 55%를 회수해 돈은 줍지만 20배 회귀를 덮는다.
  원인을 고친 뒤 남는 몇 %에만 붙인다.
