## 절차

### 0. 사전
```bash
bash deploy/verify_server.sh > /tmp/before.txt   # 지금 상태를 떠둔다(대조용)
git -C /home/ubuntu/lotto-stock-wiki status --porcelain   # 비어 있어야 한다
```
워킹트리가 더러우면 새 서버에서 자동배포가 pull 실패로 **조용히 멈춘다**.
진행 중 렌더가 없는 시간(새벽)에 한다.

### 1. 스냅샷
Lightsail 콘솔 → 인스턴스 → Snapshots → **스냅샷 생성**. 73GB 기준 10~30분.

### 2. 새 인스턴스
스냅샷 → 새 인스턴스 생성 → **$160 (8vCPU/32GB/640GB)** · **같은 리전·가용영역**.

### 3. ★새 인스턴스 SSH 열기 (1차 때 밟은 함정)
Networking → SSH 규칙이 `Lightsail browser SSH` 전용으로 생성된다 →
Preset **Anywhere IPv4(0.0.0.0/0)** 로 바꿔야 우리 키로 접속된다. 80·443도 확인.
(8849·8090은 아파치가 앞단이라 **열지 않는다** — localhost만 듣는다)

### 4. ★유령 워커 치우기 (1차 때 밟은 함정)
스냅샷 시점에 돌던 구 유닛이 `disabled`인데도 새 서버에서 같이 뜬다.
유닛 목록을 보고 쓰지 않는 것은 **유닛 파일 자체를 치운다.**

### 5. 데이터 델타 맞추기 ★빠뜨리기 쉬움
스냅샷 이후 들어온 작업·수집분은 새 서버에 없다.
**서버끼리는 SSH 키가 없어 직접 rsync가 안 된다(1차 실측) → 로컬 PC를 경유한다.**
```bash
# ① 옛 서버 쓰기 정지
sudo systemctl stop shopping-shorts shopping-shorts-worker@{1,2,3} stockbrain
# ② 로컬 PC로 내렸다가 새 서버로 올린다 (DB는 무결성 검사 후 교체)
#    sqlite3 reference.db "PRAGMA integrity_check;"  → ok 확인
```

### 6. 고정 IP 재부착 → DNS 무변경
네트워킹 → **StaticIp-2(43.200.48.69)** 를 옛 인스턴스에서 분리 → 새 인스턴스에 연결.
1차 때 이 방식으로 **duckdns·인증서 손 안 대고** 넘어갔다.
같은 IP라 SSH 호스트키 경고가 뜨는데 정상이다 → `ssh-keygen -R 43.200.48.69`.

### 7. 워커 3 → 6 (증설의 목적)
```bash
sudo systemctl enable --now shopping-shorts-worker@{4,5,6}
systemctl list-units 'shopping-shorts-worker@*' --no-legend | wc -l    # 6
```
⚠️ **동시성 테스트는 mix·render로 한다.** durfill·prewarm은 `store._EXCLUSIVE_TASKS`라
워커를 늘려도 1개만 돈다(인스타 세션 공유 보호). 그걸로 재면 "안 늘었다"고 오진한다.

### 8. 검증
```bash
bash deploy/verify_server.sh > /tmp/after.txt && diff /tmp/before.txt /tmp/after.txt
```
vCPU 8 · 메모리 32GB · 서비스 4개 · 워커 6개 · HTTPS 2개 · DB/env/인증서 존재.
그다음 **실제로 영상 1편을 끝까지 만들어 본다** — 화면이 뜨는 것과 렌더가 도는 건 다르다.
다음 날 아침 크론(8:20·8:30·8:35·9:10·9:12)이 도는지까지 봐야 진짜 검증이다.

### 9. 옛 인스턴스 처리
1~2일 지켜본 뒤 **Stop이 아니라 Delete**. ⚠️ 1차 기록: *"인스턴스는 삭제될 때까지
요금이 발생한다. 중지 상태에서도."* 정지만 해두면 돈이 계속 나간다.
스냅샷은 원본을 지워도 남으니 안전망은 유지된다.

## 되돌리기

## ⚠️ 다음에 밟지 말 함정

1. **durfill·prewarm은 워커를 늘려도 1개만 돈다** — `store._EXCLUSIVE_TASKS`.
   인스타 세션 공유라 동시에 붙으면 계정이 플래그된다(의도된 안전장치).
   **동시성 테스트는 mix·render로** 해야 한다. durfill로 하면 "안 된다"고 오진한다.
2. **새 인스턴스는 SSH가 막혀 있다** — 방화벽 SSH 규칙이 `Lightsail browser SSH` 전용으로 생성됨.
   Networking → SSH 편집 → Preset **Anywhere IPv4(0.0.0.0/0)**.
3. **구 단일 워커가 유령으로 부활** — 스냅샷 시점 실행 중이던 유닛이 새 서버에서 같이 뜬다
   (`disabled`인데도). 유닛 파일 자체를 치워야 한다.
4. **스냅샷 이후 변경분은 따로 옮겨야 한다** — 구 서버 정지(동결) → DB를 **로컬 PC 경유** scp
   (서버끼리는 SSH 키가 없어 직접 rsync 불가) → 무결성 검사 후 교체.
5. **같은 IP에 새 서버 = SSH 호스트키 경고**는 정상. `ssh-keygen -R 43.200.48.69` 한 번.

**백업 위치**: 새 서버 `/home/ubuntu/migrate_backup/` (env·크론·유닛목록·기준선),
