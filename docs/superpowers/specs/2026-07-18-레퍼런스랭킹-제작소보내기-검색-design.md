# 레퍼런스 랭킹 개편 — 제작소로 보내기 · 담긴 대본 관리 · 랭킹 검색

**날짜:** 2026-07-18
**트랙:** 레퍼런스랭킹개편

## 목표

레퍼런스 랭킹(`static/index.html`, 홈 `/`)에서 마음에 든 영상을 **한 번에 영상 제작소로**
보내고, 랭킹을 **키워드로 검색**한다. 제작소의 **담긴 대본**에 **선택 삭제**를 붙인다.

경쟁사 흐름은 "영상 보고 → 대본 뽑고 → 제작소 열고 → 붙여넣기"로 끊긴다. 이걸 카드 버튼 한
번으로 잇는다.

## 배경 — 이미 있는 통로 (새로 안 만든다)

조사로 확인한 재사용 지점:

- **제작소 핸드오프**: `collection.html`이 이미 `sessionStorage.produce_handoff`에 담고
  `location.href='/produce'`. 제작소의 `_consumeProduceHandoff`가 이걸 읽어 `HANDOFF` 배열
  (`[{url,shortcode,name,thumbnail,caption,pickScript,useFootage}]`)로 복원한다.
- **영상풀 카드**: 대본믹스통합 트랙(`fd61d10e`)이 만든 것. `HANDOFF[i].useFootage=true`면
  1단계에서 썸네일 카드로 뜬다 → 사장님이 "영상은 썸네일 같이 나와서 확인되게"라고 한 그 화면.
- **대본 추출**: `POST /api/produce/extract_from_url` (`app.py`, `{url, caption?, shortcode?,
  category?, name?}`) — 영상 URL로 대본을 뽑는다. 이미 존재.
- **담긴 대본**: 제작소 확정대본의 `📥 담긴 대본` 탭. `GET /api/produce/picks`에서 읽는데,
  그 목록은 **`wiki_list`(S급 위키 저장본)에 있으면서 pick된 shortcode만** 보여준다
  (`app.py:2249` `[w for w in store.wiki_list() if w["shortcode"] in picks]`). 각 카드에
  체크박스(`.mixPick`)가 이미 있다.

## 설계 결정 (사장님 확정)

1. **버튼 1개로 묶는다.** 카드마다 `🎬 제작소로 보내기` 하나 → 영상(화면소재)과 대본을
   **둘 다** 보내고, 제작소에서 필요한 쪽만 쓴다("하나는 안 써도 되니").
2. **대본 추출은 랭킹에서.** 버튼 누르면 그 자리에서 추출(10~30초 로딩) 후 이동 → 제작소가
   깔끔하고 담긴 대본에 바로 들어와 있다. 이미 추출된 영상은 즉시.
3. **대본은 '임시로 담기'.** S급 위키를 안 거친다. 담긴 대본 목록이 **`위키 S급 pick` +
   `랭킹에서 임시로 보낸 것`을 합쳐** 보여준다. 랭킹에서 보낸 영상이 S급 도서관을 지저분하게
   만들지 않는다.
4. **랭킹 검색은 카테고리 + 캡션**, 지금 로드된 카드를 **클라이언트에서 즉시** 필터(서버 안 감).

## 아키텍처

### 기능 ① 제작소로 보내기 (랭킹 카드 버튼)

```
[랭킹 카드] 🎬 제작소로 보내기
    │  clip = {url, shortcode, name, thumbnail, caption, category}
    ├─ (대본 미추출이면) POST /api/produce/extract_from_url  → script 텍스트  [10~30초]
    ├─ sessionStorage.produce_handoff = [{ ...clip,
    │        useFootage:true,          // 영상풀 카드로 뜸(썸네일 확인)
    │        pickScript:true,          // 담긴 대본으로 뜸
    │        script:<추출대본> }]       // ★임시 대본을 핸드오프에 실어 나른다(위키 안 거침)
    └─ location.href = '/produce'
          │
          └─ _consumeProduceHandoff: HANDOFF 복원(script 필드 보존)
               담긴 대본 렌더 = 서버 picks(위키 S급) + HANDOFF 중 script 있는 항목  ← 합침
```

- **새 필드 `script`**를 `HANDOFF` 항목에 추가한다(기존 스키마에 옵셔널 추가, 기존 항목은
  `script` 없음 = 위키/URL 유래라 서버에서 뽑음, 하위호환).
- 담긴 대본 렌더(`loadWikiForMix`의 `picks` 분기)를 고쳐 **서버 picks 목록 + HANDOFF의
  임시 대본**을 합친다. 중복(같은 shortcode)은 하나로.
- 로딩 표시: 버튼을 `⏳ 대본 추출 중…`으로 바꾸고 비활성(더블클릭 방지).

### 기능 ② 담긴 대본 — 전체선택 / 해제 / 선택삭제

담긴 대본 탭 상단에 버튼 3개. 각 카드의 `.mixPick` 체크박스를 대상으로:

- **전체선택 / 해제**: 보이는 체크박스 전부 on/off (순수 DOM).
- **선택삭제**: 체크된 항목을 담긴 대본에서 뺀다.
  - 위키 S급 유래(서버 pick) → `POST /api/produce/picks/toggle`로 pick 해제.
  - 임시 유래(HANDOFF script) → `HANDOFF`에서 그 항목의 `pickScript=false` (또는 script 제거).
  - 삭제 후 목록 다시 그림. **영상풀(useFootage)은 안 건드린다** — 대본만 빼는 것이지 영상까지
    빼는 게 아니다(사장님이 "담긴대본에서 삭제"라고 한 범위).

### 기능 ③ 랭킹 검색

랭킹 상단(카테고리 필터 줄 근처)에 검색 입력창. 입력 시:

- 지금 로드된 랭킹 아이템을 `category` + `caption`(대소문자·공백 무시 부분일치)으로 필터.
- 서버 호출 없음 — `renderCards`가 이미 가진 배열을 거른다.
- 빈 검색어면 전체 표시. 카테고리 필터(`setCat`)와 **AND**로 결합(카테고리 고른 뒤 그 안에서 검색).

## 테스트

프론트가 핵심이라 **produce.html·index.html 실소스를 앵커로 잘라 Node로 구동**한다
(이 저장소 관례: `test_produce_preview_gate.py`·`test_seo_tag_edit_js.py` 방식).

- **index**: `sendToProduce(clip)`가 `sessionStorage.produce_handoff`에 `useFootage:true·
  pickScript:true·script` 실린 항목을 넣고 `/produce`로 가나 / 이미 추출된 영상은 재추출 안 하나 /
  검색 필터가 category·caption 둘 다 걸고 빈 검색은 전체 통과하나.
- **produce**: `_consumeProduceHandoff`가 `script`를 안 버리나 / 담긴 대본 렌더가 서버 picks +
  HANDOFF 임시대본을 합치고 중복 제거하나 / 전체선택→선택삭제가 임시대본은 HANDOFF에서,
  S급은 picks/toggle로 빼고 **영상풀(useFootage)은 남기나**.
- ⚠️ `subprocess`는 `encoding="utf-8"` 필수(한글 출력에서 cp949 리더 스레드가 죽으면 예외가
  삼켜져 returncode=0·stdout=None — SEO 트랙 실측).
- 실 추출 grounding: 로컬 Gemini 키 있으면 랭킹 카드 1개로 실제 추출→핸드오프→담긴대본 관측.
  없으면 "미관측" 정직 보고.

## 범위 밖 (YAGNI)

- 대본을 S급 위키에 자동 저장(사장님이 '임시로 담기' 선택 — 안 함).
- 검색 서버화(전체 DB 검색) — 지금은 로드된 것만.
- 영상풀 카드 자체의 삭제(대본믹스통합 트랙이 이미 함, 중복 안 만듦).

## 리스크

1. **produce.html 4트랙 동시편집**(모션효과·장면라이브러리·자막싱크·대본믹스통합). 담긴 대본
   렌더(`loadWikiForMix`)와 `_consumeProduceHandoff` 근처만 최소로 건드린다. 앵커 문자열
   (`test_produce_preview_gate.py`가 자르는 것들) 보존.
2. **HANDOFF `script` 필드가 저장 왕복에서 유실**되면 새로고침 시 담긴 대본이 빔.
   `_workState()`·`saveWork()`가 HANDOFF를 통째로 저장하는지 확인하고, 안 하면 script도 실어야 함
   (구현 때 grep으로 확정).
3. **담긴 대본 합침의 중복**: 같은 shortcode가 S급 pick에도 있고 임시로도 왔을 때 하나만.
