# 캡컷 완전 이관 — 완성본 + 장면 조각 전부 옮기고, 캡컷에서 장면 갈아끼우기

- 날짜: 2026-08-23
- 선행 설계: `2026-07-20-내보내기캡컷-design.md` (T1 ZIP · T2 draft 자동생성)
- 트랙: `바꾸기길이`

## 사장님 요구

> "마지막에 캡컷으로 보낼 때 완성본 조각들이 그대로 옮겨지고, 그다음에 장면 분할된
> 조각들도 다같이 보내게 할 수 있나"
> "완성본으로 쭉 깔고 영상 소스 1 2 3 4 이런 식으로 아랫줄로 한 칸씩 만들어줄 수 없나? 조각된 걸로"
> "소리 꺼두고" · 조각은 **원본에서 자른 깨끗한 화면**(②)

## ★먼저 — 지금은 화면의 3분의 1만 나간다 (이번 작업의 진짜 핵심)

라이브 job 실측(2026-08-23, `reference.db`):

| job | 실제 화면 조각 | 캡컷으로 가는 것 |
|---|---|---|
| `ec39cd92d2bd` | **19** | **7** |
| `3fae04098b00` | **18** | **8** |
| `44a9a90d2c96` | **13** | **6** |

원인: 비트 하나에 화면이 여러 개인데(`primary` + `alternates`, 그리고 장면실험실이
편성한 `scene_override`) **`primary` 하나만** 트랙에 올린다.

- `capcut_draft.py:174` — `prim = beat.get("primary") or {}`
- `export_bundle.py:117` — `prim = (beat or {}).get("primary") or {}`

그런데 코드베이스엔 **화면 재료를 한 곳에서 정하는 함수가 이미 있다**:
`video_assemble._beat_material(beat)` (`video_assemble.py:396`) — `scene_override`가 있으면
그것을, 없으면 `primary + alternates`를 준다. 실제 렌더는 이 함수를 쓴다.

**내보내기 두 곳만 이 함수를 안 쓰고 각자 판단한다 = CLAUDE.md 0순위-B 위반.**
그래서 "캡컷에서 연 것"과 "완성본"이 다른 영상이 된다.

→ **이번 작업의 절반은 이 단일 출처로 되돌리는 것이다.** 화면 트랙 구조를 바꾸는 것보다
   이쪽이 사장님 체감에 더 크다(빠진 장면이 채워진다).

## 만들 것

### 캡컷 타임라인 구조

```
트랙1 (맨 위) │████████ final.mp4 완성본 통째 (음소거) ████████│
트랙2         │조각0│      │조각2│      │조각4│                 ← 짝수 조각
트랙3         │     │조각1│      │조각3│                        ← 홀수 조각
음성          │ beat_00 │ beat_01 │ beat_02 │ ...   (기존 그대로)
자막          │  대사1  │  대사2  │  대사3  │ ...   (기존 그대로)
```

- **완성본 트랙**: 참고·눈금자용. **음소거**(TTS와 겹쳐 두 번 들리는 것 방지).
  `last_nonzero_volume=1.0`이라 캡컷에서 되살릴 수 있다. 편집이 끝나면 이 트랙만 지우고 내보내면 된다.
- **조각 트랙 2줄 번갈아**: 조각이 19개여도 트랙은 2줄이다.
  · 계단식(조각당 1트랙)은 20줄이 되어 캡컷에서 스크롤만 하다 끝난다.
  · 1줄이면 조각을 갈아끼울 때 앞뒤와 붙어 다루기 나쁘다.
  · **2줄 번갈아**면 이웃 조각이 서로 다른 트랙이라 잡기 쉽고 줄 수도 안 늘어난다.
- **조각 = 원본에서 자른 깨끗한 화면**(사장님 선택 ②). 자막·효과가 안 구워져 있어
  장면을 갈아끼워도 자막이 어긋나지 않는다(자막은 별도 트랙에 그대로 있다).

### 조각 파일

미리 잘라 draft 폴더에 넣는다: `cut_00_첫말_4.6초.mp4`

- **미리 자르는 이유**: 캡컷이 컷 계산을 다시 안 해도 되고, 사장님이 파일 하나만
  바꿔 끼울 수도 있다.
- **파일명에 길이를 박는 이유**: 장면을 갈아끼울 때 **새 영상의 길이를 그 자리에 맞춰야**
  자막·TTS와 안 어긋난다. 파일명만 보고 "여긴 4.6초짜리" 를 알 수 있게 한다.

### 장면 교체 시 사용자가 할 일 (설계 전제)

| | 새로 해야 하나 |
|---|---|
| 자막 | ❌ 트랙이 따로라 그대로 남는다 |
| TTS 음성 | ❌ 트랙이 따로라 그대로 남는다 |
| 장면 길이 | ⚠️ **넣을 때 맞춰야 한다** — 파일명의 초 표기가 그 안내다 |

대사 자체를 바꾸는 건 장면 교체가 아니라 대본 수정이므로 제작소에서 한다(범위 밖).

## 구현

### 1. 단일 출처로 되돌리기 (선행 — 이것부터)

`capcut_draft.build_draft` · `export_bundle._beat_source_clips` 둘 다
`video_assemble._beat_material(beat)`를 쓰도록 바꾼다. `primary` 직접 참조를 없앤다.

⚠️ 한 비트에 구간이 여러 개가 되므로 **시간 배분**이 필요하다. 실제 렌더와 **같은 규칙**을
써야 한다 — 여기서 따로 계산하면 또 어긋난다(지금 병을 다른 자리에 옮기는 꼴).

**실측(2026-08-23) — 그냥 `_plan_beat_clips`를 부르면 안 된다.** 렌더의 호출부
(`video_assemble.py:1055~1076`)는 그 함수 앞뒤로 판단을 더 한다:

```
segs = _beat_material(beat) 중 소스 실재 + _src_dur > 0.05 인 것만   # 손상 소스 제외
_max_shot = None if is_point_beat(beat) else config.MAX_SHOT_SECONDS  # 포인트 비트는 홀드
_one     = config.ONE_CLIP_PER_SEGMENT                                # 1장=1컷 모드
plan = _plan_beat_clips(segs, tts_dur, src_durs=..., max_shot=_max_shot, one_per_seg=_one)
if beat.get("stretch_fill"): _spread_stretch(plan)                    # 실험실 칸별 토글
if idx == _runout_idx: _extend_last_clip_for_runout(plan, segs, runout)  # 마지막 여운
```

이 6줄을 내보내기에서 다시 적으면 **또 두 벌이 된다**(0순위-B를 고치면서 0순위-B를 어기는 셈).

→ **이 블록을 통째로 함수 하나로 뽑는다**: `plan_beat_clips_for(beat, idx, ...)`.
   렌더는 그 함수를 부르도록 바꾸고(동작 불변), 캡컷·ZIP도 같은 함수를 부른다.
   **렌더 결과가 1바이트도 안 바뀌는 것**을 테스트로 못박는다(이 리팩터링의 합격 조건).

### 2. 조각 파일 만들기

`export_bundle._cut_clip`(ffmpeg 재인코딩 컷)이 이미 있다 — 재사용한다.
캡컷 draft 조립(`assemble_draft_folder`)에서 조각을 잘라 draft 폴더에 넣는다.

### 3. 트랙 구성

`build_draft`가 비디오 트랙을 **3개** 만든다: 완성본 1 + 조각 2(번갈아).
`tracks` 리스트에 순서대로 넣는다(캡컷은 리스트 순서가 곧 위→아래).

### 4. 완성본 전달

`assemble_draft_folder`에 `final_video` 인자를 추가해 `final.mp4`를 복사한다.
완성본이 아직 없으면(렌더 전) **그 트랙만 건너뛴다** — 500을 내지 않는다(기존 스킵 원칙).

## 검증

- **조각 수 대조**: 실제 job으로 draft를 만들어 `조각 수 == len(_beat_material(beat)) 합`인지
  확인. 실측 기준 `ec39cd92d2bd`는 **19개**여야 한다(지금 7개).
- **시간 정합**: 조각들의 (t0, dur)가 실제 렌더 타임라인과 일치하는지 대조.
- **트랙 구조**: 비디오 트랙 3개, 완성본 트랙 `volume=0.0`, 조각이 두 트랙에 번갈아.
- 기존 테스트(`test_capcut_draft` · `test_export_bundle`) 회귀 0.
- ⏭ **사장님 육안 확인 필수**: 캡컷에서 실제로 열어 ①계단으로 뜨는지 ②재생되는지
  ③조각을 갈아끼워도 자막·TTS가 남는지. **이건 코드로 대신할 수 없다.**

## 안 하는 것 (YAGNI)

- 대체 후보(안 쓴 장면) 넣기 — 사장님이 "조각된 걸로"라고 했다. 실제 쓰인 것만.
- 완성본을 자른 조각 — 사장님이 ②(깨끗한 원본 컷)를 골랐다.
- 캡컷 자막 스타일(위치·크기·폰트) 튜닝 — 기존 그대로. 선행 설계의 ⏭ 항목이나 이번 범위 밖.
