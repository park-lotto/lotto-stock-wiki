# 제작소재료다운로드 — 유튜브/틱톡 다운로드 실패 수정

## 2026-07-20 완료

**증상**: 제작소에서 유튜브 쇼츠·틱톡 URL로 영상을 담으면 다운로드 실패
(스크린샷: yt-dlp가 "쿠키/브라우저 인증 필요" 에러).

**원인 2겹 (유튜브는 3겹)**:
1. 유튜브·틱톡이 비로그인 요청을 봇으로 보고 차단 시작 → 쿠키 필요.
2. (유튜브만 추가) 쿠키로도 메타데이터는 되는데 실제 다운로드는 "No video formats
   found!"(유명 공개영상도 재현) — 유튜브 URL 서명 난독화("n challenge")를 yt-dlp가
   못 풀어서. 외부 JS 런타임(Deno)+해독 스크립트가 있어야 실제 포맷이 나온다.

**수정**:
- `config.py`: `YTDLP_COOKIES_YOUTUBE` / `YTDLP_COOKIES_TIKTOK` env var 추가
  (파일 없으면 빈 문자열 → 기존처럼 무쿠키 시도, 회귀 없음).
- `media_download.py`: `_cookies_arg(url)` 헬퍼로 3개 yt-dlp 호출부
  (`probe_grab_meta`·`_download_ytdlp`·`resolve_media_url`) 전부에 플랫폼별
  `--cookies` 배선. 유튜브는 `--remote-components ejs:github`도 상시 포함
  (캐시 있으면 빠르게 스킵, 캐시 없는 새 환경에서 자동 복구).
- 로컬 PC: Deno 설치(winget, `DenoLand.Deno`), User PATH에 영구 반영됨.
- 쿠키 파일: `C:\Users\TheRose\Desktop\로또의 주식\cookies\{youtube,tiktok}_cookies.txt`
  (사장님이 브라우저에서 직접 내보낸 것, gitignore).

**검증(실측)**: 원래 실패했던 두 URL 모두 실제 다운로드 성공
(유튜브 쇼츠 2.2MB mp4, 틱톡 3.9MB mp4). 회귀: 관련 테스트 72 passed / 1 failed
(그 실패는 `test_run_render_happy_path` — 내가 안 건드린 `mix_pipeline.py`의
`assemble()` 호출부 시그니처 변경과 낡은 테스트 mock의 불일치, 이 트랙 무관).

## ✅ 서버 배포 완료 (2026-07-20 22:43 KST)

1. 서버 yt-dlp 2026.3.17→2026.7.4 업그레이드 완료
2. Deno 설치(`~/.deno/bin/deno`) + `/usr/local/bin/deno` 심볼릭 링크
   (systemd 서비스 PATH엔 홈디렉터리가 없어 `/usr/local/bin`으로 연결 필요했음)
3. 쿠키 파일 2개 scp로 `/home/ubuntu/cookies/`에 전송(git 아님, chmod 600/디렉터리 700)
4. `/etc/shopping-shorts.env`에 `YTDLP_COOKIES_YOUTUBE`·`YTDLP_COOKIES_TIKTOK` 경로 추가
5. `systemctl restart shopping-shorts` → 실제 프로세스(`/proc/<pid>/environ`)로
   env var 로드 확인 → 유튜브·틱톡 둘 다 실제 다운로드 성공(로컬과 동일 파일크기 일치)

⚠️ SSH 쉘은 `/etc/shopping-shorts.env`를 자동 로드 안 함(systemd만) — 서버에서
수동 재현 테스트할 땐 `export $(grep '^YTDLP_COOKIES' /etc/shopping-shorts.env | xargs)` 먼저.

⚠️ **쿠키는 만료된다**(보통 며칠~몇 주). 재발급 필요해지면 사장님이 같은 방법으로
다시 내보내 `cookies/` 폴더 파일만 교체하면 된다(코드 재작업 불필요).

⚠️ **Deno 해독 스크립트는 유튜브가 계속 바꿀 수 있다** — 이번엔 됐지만 유튜브가
방식을 또 바꾸면 최신 yt-dlp로 업그레이드가 최우선 조치.
