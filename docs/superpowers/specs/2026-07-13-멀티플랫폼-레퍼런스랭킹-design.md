# 설계 — 레퍼런스 랭킹 멀티플랫폼 확장 (인스타 / 틱톡 / 유튜브)

**날짜**: 2026-07-13
**대상**: `shopping_shorts/` (쇼핑쇼츠 레퍼런스 랭킹)
**상태**: 설계 승인됨 → 스펙 검토 대기

## 1. 목적 / 배경

현재 레퍼런스 랭킹은 **인스타그램 전용**이다. 소스 수집·다운로드가 모두 Apify(유료 STARTER $29/월)에 묶여 있고, 믹스도 `instagram.com` URL만 허용한다.

여기에 **틱톡·유튜브**를 추가한다. 핵심 원칙:
- **무료 우선**: 유튜브·틱톡 다운로드는 `yt-dlp`(무료). 인스타만 Apify 유지.
- **채널 목록 없음 → 발굴부터**: 유튜브는 키워드 자동 발굴(Data API), 틱톡은 시드 계정 방식.
- **인스타는 완성이므로 무변경** — 어댑터로 감싸기만 한다.

### 실측 근거 (2026-07-13)
- yt-dlp로 유튜브 영상 **실제 mp4 다운로드 성공**(무료).
- yt-dlp로 틱톡 **계정 영상 목록 훑기 성공**(무료). 단 키워드/트렌드 **검색 발굴은 미지원**.
- → 틱톡은 **시드 계정 방식(A안)** 확정: 사용자가 벤치마킹 계정을 등록하면 그 계정 신규 영상을 무료 수집. 초기 시드만 사람이 고르고 이후는 무료·자동.

## 2. 랭킹 지표 (인스타 프레임 그대로, 기준 숫자만 플랫폼별)

UI는 **속도 / 가속 / 참여율** 3열로 완전히 동일. 기준 숫자만 플랫폼에 맞춘다.

| 지표 | 인스타 (현행 유지) | 유튜브 / 틱톡 |
|---|---|---|
| **base_count** (속도·가속의 기준) | 댓글수 | **조회수(view_count)** |
| **속도** | base ÷ 경과시간(h) | 동일 |
| **가속** | 이번 Δ − 직전 Δ | 동일 (snapshots 재사용) |
| **참여율** | 댓글수 ÷ 팔로워 | **(좋아요+댓글) ÷ 조회수** |

랭킹 계산부(속도/가속/참여율/score)는 **`base_count`·`views`로 일반화**하여 한 곳에서 계산하고, 플랫폼별 fetcher가 base만 주입한다.

## 3. 아키텍처 — 플랫폼 어댑터

```
service.collect(platform)
   └─ platform_fetcher(platform, seeds/keywords)  →  공통 item[] 반환
        ├ instagram → apify_client.fetch_reels        (기존, 무변경)
        ├ youtube   → youtube_client.search/channel    (신규, YouTube Data API)
        └ tiktok    → tiktok_client.fetch_account       (신규, yt-dlp flat playlist)
   └─ 공통 랭킹 계산(속도/가속/참여율/score) — platform 무관
   └─ store.save_last_run(platform, items) + snapshots(platform, ...)
```

각 fetcher는 **동일한 item dict** 를 반환한다(플랫폼 은닉).

### 공통 item 스키마
```
platform      : "instagram" | "youtube" | "tiktok"
shortcode     : 플랫폼 내 고유 id (yt=videoId, tiktok=video id, ig=shortcode)
url           : 원본 시청 URL
name          : 채널/계정 표시명
username      : 계정 핸들
thumbnail     : 썸네일 URL
video_url     : 인라인 재생용(있으면)
caption/title : 제목·설명
followers     : 구독자/팔로워 (없으면 null)
views         : 조회수 (ig=null 가능)
likes         : 좋아요
comments      : 댓글수
base_count    : 랭킹 기준 숫자 (ig=comments, yt/tiktok=views)
age_hours     : 경과시간
speed/accel/density : 계산 결과
category      : 분류(선택)
```

## 4. 컴포넌트 (신규/변경)

### 신규
- **`youtube_client.py`** — YouTube Data API 어댑터
  - `search_videos(keywords, published_after)` → 키워드로 인기 Shorts 발굴 → item[]
  - `fetch_channel_videos(channel_id)` → 특정 채널 최근 영상
  - 통계(조회수·좋아요·댓글)는 `videos.list(part=statistics)` 로 채움
  - 키: 기존 YouTube Data 연동/`key_vault` 재사용
- **`tiktok_client.py`** — yt-dlp 어댑터
  - `fetch_account_videos(username, limit)` → `yt-dlp --flat-playlist` 로 계정 최근 영상 목록 → 각 영상 메타(조회수·좋아요) 채움 → item[]
  - 실패(비공개·차단) 시 해당 계정 스킵

### 변경
- **`service.collect(platform=...)`** — 플랫폼 분기 + 공통 랭킹 계산 일반화
- **`store`** — `last_run`·`snapshots`·발굴 시드에 `platform` 차원 추가
  - 시드 저장: `platform_seeds(platform, kind, value, added_at)` (yt=keyword/channel, tiktok=account)
  - `snapshots`·`last_run`은 platform 스코프로 조회
- **`mix_pipeline`** — 다운로드 분기: `instagram.com`=Apify(기존) / `youtube.com`·`tiktok.com`=yt-dlp
- **`index.html`** — 상단 플랫폼 탭(📷인스타 / 🎵틱톡 / ▶️유튜브), 탭별 "지금 수집"·카드
- **발굴 UI** — 유튜브 키워드 입력 / 틱톡 시드 계정 입력

## 5. 데이터 흐름

```
[발굴/시드 등록] → [지금 수집(platform)] → [fetcher] → [스냅샷 저장(가속)]
       → [공통 랭킹 계산] → [카드 렌더(속도/가속/참여율)]
       → [담기 → 믹스 바구니] → [믹스: URL별 yt-dlp/Apify 다운로드 → 편집 → 자막]
```

- 믹스 바구니(이미 구현)는 platform 무관하게 그대로 재사용. 믹스 다운로드 단계에서만 URL로 분기.

## 6. 단계화 (구현 순서)

- **Phase 1 — 유튜브** (완전 무료 자동 발굴, 패턴 확립)
  - youtube_client + item 스키마 일반화 + 랭킹 계산 일반화 + 플랫폼 탭 UI + yt-dlp 믹스 분기
- **Phase 2 — 틱톡** (시드 계정)
  - tiktok_client + 시드 계정 발굴 UI
- 각 Phase: TDD(테스트 먼저) → 로컬 검증 → 서버 배포

## 7. 에러 처리 / 비용

- **yt-dlp 실패**(비공개·삭제·차단): 해당 항목만 스킵, 전체 수집 계속.
- **YouTube Data API 쿼터 초과**: 대기/다음 키 회전(key_vault), 사용자에게 명시.
- **서버 준비**: `yt-dlp` 서버 설치 필요(`requirements.txt` + `pip install yt-dlp`), 부팅/배포 시 반영.
- 비용: 유튜브=무료(Data API 쿼터 내), 틱톡=무료(yt-dlp), 인스타=기존 Apify.

## 8. 테스트

- `youtube_client`: search/channel 응답 mock → item 스키마·통계 매핑 검증.
- `tiktok_client`: yt-dlp flat-playlist 출력 mock → item 파싱·스킵 로직 검증.
- 랭킹 계산 일반화: base_count 주입에 따른 속도/가속/참여율 계산 검증(플랫폼별).
- mix 다운로드 분기: URL별 올바른 다운로더 선택 검증.
- 실데이터 스모크: 유튜브 키워드 1회 발굴 + 틱톡 시드 계정 1개 수집(로컬).

## 9. 범위 밖 (YAGNI)

- 틱톡 키워드/트렌드 자동 발굴(무료로 불가 — 시드 방식으로 대체).
- 플랫폼별 스케줄 자동 수집(현행처럼 수동 "지금 수집" 유지).
- 크로스플랫폼 중복 제거(같은 창작자 IG/틱톡/유튜브 매핑) — 후속 과제.
