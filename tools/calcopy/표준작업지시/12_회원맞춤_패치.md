# 12 회원 맞춤 — 채팅 → 팩 항목 패치 → 재렌더, 프리셋 원본 불변 (표준 §10-3 · 11·08 뒤 · 엔진+숏템MCP 두 트랙)

## 목표
회원이 프리셋을 고른 뒤 "우리 채널은 ~" 한 마디로 팩 항목을 바꾸고(패치), 마음에 안 들면 팩에서 다시 골라 다시 렌더한다. 패치는 회원 프로필에 **바꾼 칸만** 저장, 프리셋 원본·판 파일은 안 바뀐다. 패치를 입혀도 품질 관문(04) 그대로 통과해야 나간다.

## 실측 배경(10-25)
- 숏템MCP `shortem_client/server/local_settings.js`: `packFor(pid)` = 엔진 기본 팩 ← `preset_defaults[pid]` ← 회원 `channels[pid].pack`(바꾼 칸만, `savePack` 이 엔진 `check` 로 검사 뒤 저장, `resetPack`) → `packFile(pid)` `~/.shortem/packs/<pid>.json {"1": 합친 팩}`. **합치기(merge)가 PC 에 있다** = 엔진과 두 벌 위험 · 이 팩은 `preset_make`(옛 회원 길)만 읽고 **hybrid 길(flow→render_bench)은 안 읽는다**.
- 회원 UI `shortem_client/server/ui/index.html`(프리셋·화면·자막·소리·완성본 탭) · 팩 화면 `shopping_shorts/static/shortem_packs.html`(미리보기 = 공식 render_layer_one) · MCP `shortem_settings(open/get/set/select)` · 완성본 '지금 설정으로 다시 만들기' = `calcopy_make.restyle`(옛 길).
- flow.py 단계표에 customize 없음(08 이 `FORMAT_STAGES` 로 만든 뒤) · 볼케이노 MCP 는 `customize` 단계 `customization_patch` 가 있다(개념 참고만, 코드 아님).
- 메모리 `프리셋_얕은복사_원본오염`: 저장된 구성을 얕게 얹으면 편집이 원본을 같이 고친다 → 깊은 복사 + 재적용 복원 시험 필수.

## 설계(판단 주인)
1. **`styles.apply_patch(style, patch)`** — 깊은 복사 → `PATCHABLE`(packs.* · voice{name,voice_id} 명단 안 · frame.logo/credit/channel_name · bgm.id(카탈로그 안) · length 는 판 범위 안) 만 덮기 · 그 밖 키(placement.rules·counted·script·cuts·timing·frame.window/title 좌표) → `PatchError("뼈대 칸은 바꿀 수 없습니다: <키>")` · 없는 팩 항목 → `PatchError`. 반환 style 에 `_patch_sha`·`_patched_keys` 표식(render_info·관문이 적는다). `styles.load(name, patch=None)` 이 부른다 — **합치는 규칙은 여기 한 곳**.
2. **`pack_map.suggest(style, text)`** — 회원 글("차분한 톤·파란 로고·남자 목소리·잔잔한 음악")을 요소별 희망으로 나눠(Claude CLI 소넷 1회, JSON) 팩 카탈로그에서 후보 3개씩(자막팩 look 거리·모션팩·효과음팩·BGM 카탈로그 태그·목소리 명단 성별) → `{element: [{item, why, preview}]}`.
3. **flow `customize`**(sign 앞·render 뒤 둘 다 진입 가능): 질문 "프리셋 그대로 갈까요, 우리 채널에 맞게 바꿀까요? 바꾸려면 한 줄로" → `wait_user` → 글이 오면 `suggest` → do `pack_preview`(후보마다 공식 미리보기 PNG) → review `customize_pick`(회원 Claude 가 회원에게 보여 주고 고른 것 JSON) → `apply_patch` 검사 통과 → PC 저장(`channels[pid].patch`) → 다음 단계. 완성 뒤 "마음에 안 들면 '팩에서 다시 고르기'" → `recustomize` → 바뀐 칸만 다시(목소리 안 바꿨으면 TTS 캐시 재사용) → `render` → `check`(04 gate 그대로).
4. **관문**: gate 는 `styles.load(판, patch)` 된 style 로 돈다 — framecmp 기준은 패치 적용 판(`_patched_keys` 에 든 겉모양 칸은 기준을 그 값으로), 뼈대 칸 match 는 그대로 필수. × 면 flow 가 "그 항목으로는 관문 × — 이유" 를 돌려주고 patch 를 이전 값으로 되돌린다.
5. **서버**: `claude_flow_runs.patch_summary {keys, sha}` 만. 값·프로필 본문은 PC 파일.

## 합격 검사(사보타주 먼저)
1. 원본 불변: `apply_patch` 두 번(다른 patch) 뒤 판 파일 sha·메모리 원본 dict 의 json dump 가 처음과 같다 — 고치기 전엔 `packFor` merge 가 얕은 복사인지 확인(중첩 dict 가 공유되면 실패해야 하는 시험).
2. 금지 칸: `{"placement":{"rules":…}}`·`{"cuts":…}`·없는 자막팩 키 → `PatchError`(조용한 무시 0). 허용 칸 5종은 통과.
3. flow 완주: customize 로 자막팩·목소리·BGM 을 바꾼 편이 `render_info.json _patched_keys` 에 그 3개를 적고, gate 1단 ○(뼈대 match 칸 ✓) · 바꾼 뒤 다시 customize(자막팩만) → 재렌더가 **TTS 재합성 0**(캐시 로그) · 완성본 두 개 프레임 대조로 자막 모양만 다르다.
4. 사보타주: 관문이 ×가 나는 패치(예 외곽선 0·흰 글자+흰 바탕 — 숏템MCP handoff 10-20 annapick 사례) → flow 가 되돌리고 이유를 돌려준다.
5. 서버 DB 에 패치 값 본문 0(요약만) · PC `settings.json channels[pid].patch` 에 바꾼 칸만.
6. 페이블 눈 검수: 패치 전·후 완성본 두 편 E1·E4·E5 — "프리셋 결은 유지되고 회원 채널 옷만 바뀌었나".
