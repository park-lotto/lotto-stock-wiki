# 부품은행 Phase 0 구현 계획

스펙: `docs/superpowers/specs/2026-07-21-대본학습층-부품은행-스파인라이브러리-design.md` (코어) + 검토서.
목표: **스키마 + 수동붙임 8버킷 분해 + 큐레이션 페이지 v1**. 기존 생성·믹스 흐름 무편집(격리). 전부 신규 파일/테이블/라우트.

## 기존 패턴 (반드시 준수)
- DB: `shopping_shorts/store.py` `Store` 클래스. `_conn()`=`sqlite3.connect`, `_init_schema()`는 멱등(`CREATE TABLE IF NOT EXISTS`). 컬럼 추가는 ALTER try/except 패턴.
- API: `shopping_shorts/app.py` FastAPI. `@app.post/get`, `async def`, 요청마다 `Store(DB_PATH)`. 반환 dict(JSON).
- 페이지: `shopping_shorts/static/*.html` → StaticFiles 마운트로 `/파일명.html` 자동 서빙(라우트 불필요).
- 테스트: `shopping_shorts/tests/test_*.py`, pytest, `Store(tmp_path/"t.db")` 픽스처. AI 호출은 주입/모의로 회피.
- 추출 엔진 참고: `structure_analyze.analyze_structure` (comment_gen 키풀 로테이션, response_schema, 실패 시 빈 반환).

## 태스크

### T1 — 스키마 (store.py, TDD)
3 테이블을 `_init_schema`에 `CREATE TABLE IF NOT EXISTS`로 추가:
- `pattern_source(id INTEGER PK AUTOINCREMENT, source TEXT, url TEXT, full_text TEXT, product_category TEXT, category_source TEXT, perf_json TEXT, structure_json TEXT, spine_id INTEGER, is_winner INTEGER DEFAULT 0, created_at TEXT)`
- `pattern_item(id INTEGER PK AUTOINCREMENT, bucket TEXT, text TEXT, canonical TEXT, slot_role TEXT, source_ids_json TEXT, freq INTEGER DEFAULT 1, perf_score REAL DEFAULT 0, status TEXT DEFAULT 'pending', tags_json TEXT, note TEXT, is_negative INTEGER DEFAULT 0, created_at TEXT, updated_at TEXT)` — UNIQUE(bucket, canonical)
- `spine(id INTEGER PK AUTOINCREMENT, name TEXT, situation_type TEXT, character_roles_json TEXT, beat_chain_json TEXT, emotion_arc TEXT, appeal TEXT, fit_categories_json TEXT, source_count INTEGER DEFAULT 0, perf_score REAL DEFAULT 0, status TEXT DEFAULT 'pending', created_at TEXT, updated_at TEXT)`
- 버킷 8종 상수: `PATTERN_BUCKETS = ("hook","ending","adverb","cta","price","evidence","conflict","emotion")`.

store 메서드(+테스트):
- `add_pattern_source(source, url, full_text, product_category=None, category_source=None, perf=None, structure=None) -> id`
- `add_pattern_item(bucket, text, canonical=None, slot_role=None, source_id=None, tags=None, is_negative=0)` — **dedup: 같은(bucket,canonical) 있으면 freq+1 & source_ids append(중복 삽입 금지)**. canonical 없으면 text 정규화(소문자·공백정리)로 생성.
- `list_pattern_items(bucket=None, status=None, is_negative=None, order_by='perf'|'freq'|'recent', limit=200)`
- `set_pattern_item_status(id, status)` / `edit_pattern_item(id, text=None, tags=None, note=None)`
- `add_spine(name, situation_type, ...) / list_spines(status=None) / set_spine_status(id,status)` (수동 시드 B1용)
- `pattern_bucket_counts()` → {bucket: {pending, approved, rejected}}

### T2 — 8버킷 추출 모듈 (shopping_shorts/pattern_bank.py, TDD)
`extract_buckets(full_text, call=None) -> dict` — Gemini로 대본을 8버킷으로 분해.
- 스타일 버킷(hook/ending/adverb/cta/price) = **리터럴 문구 리스트**.
- 내용 버킷(evidence/conflict/emotion) = **슬롯 템플릿**(B2: `{인물}이 {행위}하더니 {반응}` 형태 + 예문). 리터럴 저장 금지.
- 매크로 스파인 후보 필드(situation_type·beat_chain·emotion_arc·appeal) 동시 추출(structure_analyze 재활용 가능하면 재활용).
- `call` 주입점(테스트는 가짜 call로 Gemini 회피). 무키/실패 시 `{}`.
- `ingest_script(store, full_text, source='manual', url='', product_category=None, call=None) -> {source_id, added}`:
  extract_buckets → add_pattern_source → 각 부품 add_pattern_item(pending). 스타일=리터럴, 내용=슬롯템플릿.
- **F5 네거티브**: `ingest_negative(store, text, bucket)` — 반려문을 is_negative=1로 저장. 시드 문구: "확인하셨어요","너무 좋아합니다"(요약체).

### T3 — 큐레이션 API (app.py, 신규 엔드포인트만 추가)
- `POST /api/pattern/ingest` body{full_text, product_category?} → ingest_script → {source_id, added}
- `GET /api/pattern/items?bucket=&status=&order=` → list
- `POST /api/pattern/item/status` body{id, status} (approve/reject)
- `POST /api/pattern/item/edit` body{id, text?, tags?, note?}
- `GET /api/pattern/buckets` → counts
- `GET /api/pattern/spines` / `POST /api/pattern/spine` (수동 시드)
- app.py 테스트: `tests/test_app_pattern.py` — TestClient로 ingest(가짜 call)→list→approve 플로우.

### T4 — 큐레이션 페이지 (shopping_shorts/static/pattern_bank.html)
- 상단: 대본 붙여넣기 textarea + [분해] 버튼 → /api/pattern/ingest.
- 버킷 탭 8개(+매크로 스파인). 각 부품 카드: 문구·빈도·성과·상태 배지 + [승인][기각][수정].
- 정렬 토글(성과/빈도/최신). fetch로 API 연동. 자체완결 HTML(기존 static 페이지 스타일 참고).
