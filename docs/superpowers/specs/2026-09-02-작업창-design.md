# 작업봇 — 텔레그램에서 여는 Claude Code

- 작성: 2026-09-02
- 트랙: `작업창` (`track/작업창`)
- 상태: 1단계 구현 착수

## 무엇을 만드는가

**사장님이 텔레그램에 고객 질문을 넘기면, 클로드가 직접 조사해서 답한다.**

지금은 사장님이 카톡 → 터미널 → 카톡으로 **두 번 복붙**하신다. 이걸 없앤다.

```
지금
  고객: "안 돼요" + 주소
     → 사장님이 복사 → 터미널에 붙여넣기
     → 답변 → 다시 복사 → 카톡에 붙여넣기      (복붙 2번)

1단계
  고객: "안 돼요" + 주소
     → 사장님이 텔레그램 봇에 넘김
     → 클로드가 주소·DB를 직접 조사
     → 원인 + 고객께 보낼 문구 + 조치버튼 + 이력   (복붙 1번)

2단계 (공기계)
     → 카톡에서 그 메시지를 지목하면 자동으로 넘어옴  (복붙 0번)
```

## 왜 텔레그램인가

| | 텔레그램 | 직접 만든 웹 채팅창 |
|---|---|---|
| 폰에서 밖에서 쓰기 | **바로 됨** | PC↔폰 통로를 만들어야 함 (제일 어려운 조각) |
| 알림 | **공짜** | 따로 만들어야 함 |
| 화면 자유도 | 텔레그램이 정한 모양 | 마음대로 |
| 만드는 양 | 적음 | 많음 |
| 이미 있는 것 | `send_telegram` (7곳 사용 중) | 없음 |

웹 채팅창은 나중에 얹을 수 있다. 클로드를 부르는 부분은 공용이고 껍데기만 다르다.

## 비용 — 0원

**PC에서 돈다.** 지금 이 터미널과 같은 `claude` CLI를 쓰므로 **사장님 구독**으로 동작한다.

실측(2026-09-02, 로컬 PC):
- `claude` CLI **v2.1.252** (`C:\Users\CH\.local\bin\claude.exe`)
- `.credentials.json` 존재 = 구독 인증됨
- `ANTHROPIC_API_KEY` **비어 있음** = 지금 이 세션이 구독으로 도는 증거

⚠️ 구독 크레딧으로 **Agent SDK**를 쓰는 제도는 2026-06-15에 발표됐다가 **같은 날 보류**됐다.
그래서 Agent SDK(서버 상주)를 쓰면 API 종량 과금이 된다. **CLI를 그대로 부르면 0원이다.**
1단계는 CLI 방식으로 간다.

텔레그램 API는 무료다.

## 배경 — 실측한 사실 (2026-09-02)

| 항목 | 실측값 | 설계에 미치는 영향 |
|---|---|---|
| 로컬 `claude` CLI | v2.1.252, 구독 인증됨 | 0원 구동의 근거 |
| `send_telegram(text)` | `shopping_shorts/notify.py:10` | 보내는 쪽은 이미 있다 |
| 텔레그램 **수신** 코드 | **0건** (전체 검색) | 받는 쪽을 새로 만든다 |
| 봇 토큰 env | `SHORTS_TELEGRAM_TOKEN` / `..._CHAT_ID` | 이름이 이미 정해져 있다 |
| 로컬 `.env`의 토큰 | **0건** | 사장님이 발급해야 한다 |
| 로컬 `reference.db` | **1건뿐** | **로컬 DB는 못 쓴다 — 서버를 봐야 한다** |
| SSH (포트 22) | **막힘** (여러 번 실패) | SSH에 의존하면 안 된다 |
| HTTPS (443) | **정상** (200 / 307) | **API로 조사한다** |
| `/api/produce/mix/status/{job_id}` | `app.py:4037` | 작업 상태·오류 조회 |
| `/api/admin/customers` | `app.py:10831` | 고객·사용량 조회 |
| `/api/admin/bug-reports` | `app.py:10775` | **고객 오류 제보가 이미 쌓인다** |
| `mix_jobs` 컬럼 | `status`·`error`·`customer_id` 있음 | 진단에 필요한 게 다 있다 |
| `bot_qa._SENSITIVE` | 환불·결제·계좌… 9개 | 민감어 목록을 재사용한다 |

**SSH 없이 HTTPS API만으로 조사한다.** SSH가 막혀도 돌고, 서버 파일을 안 건드려 배포도 안 멈춘다.

## 전체 구조

```
   사장님 폰 (텔레그램)
        │  고객 질문 붙여넣기
        ▼
   텔레그램 서버 (무료)
        │
        ▼  getUpdates 폴링
   ┌─────────────────────────────┐
   │  사장님 PC — 작업봇          │
   │  ├ poller   텔레그램 수신     │
   │  ├ context  주소에서 정보 추출 │
   │  ├ probe    API로 서버 조사   │
   │  └ claude CLI 호출 (구독, 0원)│
   └──────────┬──────────────────┘
              │  sendMessage
              ▼
   사장님 폰 ← 원인·고객문구·버튼·이력
```

## 골라내기 — 사장님이 지목한다 (확정)

1단계는 사장님이 텔레그램에 직접 넘기신다. 2단계(공기계)에서도 **자동 판별이 아니라 지목**이다.

**왜 자동 판별을 안 하나.** 자동은 결국 놓친다. 그리고 **놓친 걸 사장님이 모른다.**
조용히 실패하는 것이 가장 나쁘다. 지목이라도 복붙보다 훨씬 낫다 — 주소·맥락이 원본 그대로 온다.

## 안전장치

| 위험 | 막는 방법 |
|---|---|
| 봇 토큰 유출 | git에 넣지 않는다. `.env`로만 (`send_telegram` 관례와 동일) |
| 남이 봇에 말 검 | 사장님 `chat_id`만 받는다. 다른 ID는 무시 |
| 돈 얘기 오답 | `bot_qa._SENSITIVE` 재사용 — 환불·결제는 진단만, 조치 버튼 없음 |
| 서버 오염 | 쓰기 API를 안 부른다. 조회만 |
| 봇이 죽어 조용해짐 | 시작·종료를 텔레그램으로 알린다 |
| 조용한 실패 | 실패 사유를 **뭉개지 않는다** — "A 또는 B" 금지 |

⚠️ 마지막 항목은 이 코드베이스의 반복된 함정이다("키 소진 또는 응답 오류"가 거짓이었던 전례).

## 만들 것

```
tg_bot/
├── poller.py     텔레그램 수신·발송 (~120줄)
├── context.py    메시지에서 job_id·URL 뽑기 (~60줄)
├── probe.py      HTTPS API로 서버 조사 (~120줄)
├── ask.py        claude CLI 호출 (~80줄)
└── run.py        묶어서 돌리기 (~60줄)

봇켜기.bat        더블클릭으로 시작 (트랙.bat 관례)
```

각 파일이 하나씩만 담당한다. `context.py`는 네트워크를 모르고, `probe.py`는 텔레그램을 모른다 —
따로 테스트된다.

## 하지 않는 것 (YAGNI)

- 서버 상주 (Agent SDK) — PC로 충분하고 0원이다
- 웹 채팅창 — 텔레그램으로 먼저 써보고 판단한다
- 고객에게 직접 답하기 — **사장님께 답하는 게 먼저다**
- 자동 판별 — 지목이 확실하다
- 공기계 자동 전달 — 2단계

## 검증 계획

| 무엇 | 어떻게 |
|---|---|
| 주소에서 job_id 추출 | 실제 URL 형태들로 테스트 |
| 남의 chat_id 차단 | 다른 ID로 보내면 무시되는지 |
| 민감어 | "환불해주세요" → 조치 버튼이 안 나오는지 |
| API 조사 | 실제 서버에 조회해 응답이 오는지 |
| 실패 문구 | 일부러 틀린 job_id → 사유가 명확한지 |
| 전체 흐름 | **실제 텔레그램에서 보내고 받아본다** |

⚠️ 마지막은 반드시 실기로 한다. 정적 검토는 관찰이 아니다.
