### 2. ~~담은 구간이 렌더에 실제로 반영되는지~~ ✅ 코드경로는 못을 박았다 (08-26 3차)

### 3. ~~조각 범위 넓히기~~ ✅ 완료 (08-26 3차) — 넓히지 않고 **갈아 끼운다**
`trimPieces`·`_lab_trim_pieces`를 둘 다 고치면 같은 규칙이 두 벌이 된다(0순위-B).
그래서 필름에서 원하는 구간을 그린 뒤 **🔁 이 조각을 이 구간으로**를 누르면 그 조각이
놓인 모든 칸에서 자리를 지킨 채 새 `film_` 조각으로 바뀐다. 담기(⬆)는 더하기,
🔁는 바꾸기 — 둘 다 남겨 뒀다.
```
□ 사장님 확인: 필름 펼침 → 구간 1개 그리기 → 🔁 버튼이 보이나 → 눌러서 바뀌나
□ 구간 2개를 그리면 🔁가 사라지는가(무엇으로 바꿀지가 하나여야 한다)
□ 영상 전체 필름(묶는기준 🎞 필름형)에는 🔁가 없다 — 바꿀 대상이 없어서 정상
```

### (옛 기록) 담은 구간이 렌더에 실제로 반영되는지
화면·저장·전송·서버 4곳을 다 채웠고 서버 테스트도 통과했지만,
**실제 잡으로 렌더를 돌려본 적은 없다.** 새 조각이 영상에 나오는지 한 번은 봐야 한다.
안 나오면 `apply_scene_lab`에 도달한 payload부터 확인(`extra_segs` 키).

### (옛 기록) 못 한 것 — 조각 범위 넓히기
`TRIMS[sid]=[a,b]`는 **가운데를 버리는** 방식이라 조각 밖으로 못 넓힌다.
필름형(④)으로 임의 구간을 새로 담으면 우회되지만, ①② 펼침에서 직접 넓히려면
`trimPieces`(scene_play.js:219)와 `_lab_trim_pieces`(edit_plan.py)를 **함께** 고쳐야 한다.

사장님: *"지금 3단계를 보니 너무 허접하네"* — 실측하니 **자르기에 화면이 없었다.**

### ④ 새 조각은 4곳을 짝으로 채웠다

### 무엇을 했나
| # | 내용 | 어디 |
|---|---|---|
| ① | 🔁 이 조각을 이 구간으로 (조각 범위 넓히기) | `filmroll.js` onReplace · `scene_lab.html` replaceRoll |

### 왜 '넓히기'가 아니라 '갈아끼우기'인가
`TRIMS[sid]=[a,b]`는 **가운데를 버리는** 구멍이라 구조상 조각 밖으로 못 넓힌다.
넓히려면 `trimPieces`(scene_play.js)와 `_lab_trim_pieces`(edit_plan.py)에 **같은 규칙을
두 벌** 적어야 한다 — 0순위-B가 금지하는 모양 그대로다. 필름 담기(④)가 이미 임의 구간을
만들 수 있으므로, 새 기계를 만들지 않고 **그 조각을 바꿔치기**로 붙였다.
`replaceRoll`은 `commitRoll`과 딱 한 줄만 다르다(`l.push` → `l[at] =`).

### 검증 (실브라우저 — 문법검사만으론 부족하다는 1차 교훈 그대로)
하네스를 다시 만들었다(집 PC에는 없었다): 인라인 DATA + `ffmpeg`로 만든 30초 테스트 영상.
```
scratchpad/labtest/index.html   ← build.py와 같은 방식으로 DATA를 인라인
scratchpad/labtest/t.mp4        ← ffmpeg -f lavfi -i testsrc=...:duration=30
```
- 박스 0개→🔁 없음 / 1개→🔁 나옴 / 2개→사라짐 · `onReplace` 안 주면 아예 안 나옴
- `replaceRoll('v1-0','v1',{s:12,e:15.5})` → 칸이 `film_v1_12.00_15.50`으로 **교체**
  (더해지지 않음), EXTRA·저장·전송 payload에 실림, chosen 갱신, 없는 sid 재호출도 무사
- JS 예외 0건 / 서버 테스트 **5,623 passed**(+8) — 실패 2건은 HEAD에서도 실패하는 기존 건

⚠️ `node --check`로 scene_lab.html 인라인 JS를 검사할 땐 **블록별로** 하라.
파일 통째로 뽑으면 주석 안의 `<script` 글자에서 추출이 깨진다(내 코드 탓이 아니다 —
변경 전 파일도 똑같이 깨진다. 그걸 대조해서 갈랐다).
