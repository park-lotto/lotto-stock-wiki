# 샤오홍슈 레퍼런스 채널 랭킹 — 설계 (2026-07-29)

> 선행: `2026-07-26-해외HOT-무료Playwright크롤전환-design.md`(Phase 0 스파이크 — 샤오홍슈는
> 로그인 세션 + 서버 직결로 검색결과 크롤 가능함을 검증 완료). 이 문서는 그 크롤 능력을
> "레퍼런스 랭킹" 화면의 **계정 등록 기반 채널 랭킹**(인스타·틱톡과 같은 방식)에 적용하는 설계.

## 배경 / 문제

"레퍼런스 랭킹" 화면엔 인스타·유튜브·틱톡·샤오홍슈·도우인 5개 탭이 있다. 인스타·틱톡은 **등록한
크리에이터 계정의 최근 게시물을 강도별로 랭킹**하는 진짜 채널 랭킹인데, 샤오홍슈·도우인 탭은
실제로는 "인스타/유튜브/틱톡에서 수집한 걸로 만든 트렌드를 중국어로 번역해 딥링크만 건" 화면이라
별도 수집이 없다(`static/index.html` "트렌드 새로고침" 안내문구 참고).

사장님 요청: **샤오홍슈도 인스타·틱톡처럼 계정 등록 → 실제 크롤 → 랭킹이 되는 진짜 탭으로 만든다.**
도우인·트렌드 딥링크 기능은 이번 스코프 밖(안 건드림).

## 목표
등록한 샤오홍슈 크리에이터 계정들의 **최근 48시간 이내 노트**를 자동 수집해 강도별로 랭킹한다.
인스타(`WINDOW_HOURS=48`)와 동일한 창(사장님 확인: "48시간, 인스타와 동일").

## 왜 지금 가능한가 (전제)
2026-07-29 Phase 0 스파이크에서 확인된 사실:
- `rednote.com`(해외용 도메인)은 IP 차단이 없고 **로그인 세션**만 있으면 서버 데이터센터 IP 직결로
  헤드리스 크롤 가능(검색결과 페이지 기준, 프록시·집PC 상시크롤 불필요).
- 로그인 세션은 `page.context().storageState()`로 추출해 서버 `/home/ubuntu/rednote_session.json`
  (600권한, git 비추적)에 저장돼 있고, `browser.new_context(storage_state=...)`로 재사용 확인됨.
- ⚠️ **단, 검증된 건 "검색결과" 페이지뿐이다.** 이 설계가 필요로 하는 "계정 프로필(그 사람 홈) 페이지"는
  아직 크롤 검증이 안 됐다 — 같은 사이트·같은 세션이라 될 가능성이 높지만 확정은 아니다. 그래서
  구현 1단계를 반드시 이 검증부터 시작한다(아래 "구현 순서" 참고).

## 접근 방식 (검토한 대안)
- **A안(채택): 프로필 페이지 직접 크롤.** 등록 계정의 홈에 들어가 최근 노트 목록을 긁는다.
  인스타·틱톡과 데이터 흐름이 완전히 일치(등록 채널 = 그 채널이 실제로 올린 것). 리스크는 위 전제의
  프로필 페이지 미검증 부분.
- **B안(폴백): 검색 재활용 + 작성자 필터.** 이미 검증된 검색결과 크롤을 계정명으로 검색해 작성자가
  일치하는 것만 추출. 새 크롤러가 필요 없어 빠르지만, 검색 상위에 안 걸리는 최신 글은 놓칠 수 있어
  "그 계정이 실제로 올린 것 전부"가 보장되지 않는다 — 데이터 신뢰도가 A안보다 떨어짐.
- **결정**: A안으로 가되, 구현 1단계에서 프로필 페이지 크롤이 막히면 **그 자리에서 B안으로 전환**.

## 아키텍처 / 데이터 흐름

```
[레퍼런스 채널 관리] (static/refs.html)
  샤오홍슈 탭 신설 → 프로필 URL 붙여넣기(한 줄에 하나, 인스타와 동일 UX)
  → POST /api/seeds?platform=xiaohongshu (기존 범용 API, 코드 변경 없음)
  → store.platform_seeds 테이블 (기존 스키마 그대로, kind="account")
       ↓
[수집] service.collect(platform="xiaohongshu")
  → service._collect_xiaohongshu() (신규 — _collect_tiktok() 구조 그대로 따라감)
  → xiaohongshu_playwright.py (신규 모듈)
       - store.list_seeds("xiaohongshu")로 등록 계정 목록 로드
       - 계정마다 순차로 프로필 페이지 진입:
         new_context(storage_state="/home/ubuntu/rednote_session.json") 세션 재사용
       - 최근 48h 이내 노트만 추출(published_at 기준 필터)
       - 계정 단위 실패 격리(한 계정 실패해도 나머지 계속) — instagram_playwright.py 패턴
       - 요청 간 딜레이(캡차 유발 방지, 초 단위 — 구현 시 확정)
       ↓
[정규화/랭킹] ranking.build_xiaohongshu_items() (신규)
  → 해외HOT의 view-less 공식 재사용(build_overseas_items와 동일 계산):
     base = 좋아요+댓글+수집+공유
     speed = base / 경과h
     density = (수집+공유) / base
     window_hours = 48
  → apply_grades() 기존 함수 그대로 통과(플랫폼 무관 범용)
  → store.save_run_platform("xiaohongshu", ...) / save_last_run_platform(...) 기존 패턴
       ↓
[표시] static/index.html "샤오홍슈" 탭
  → 기존 "트렌드 딥링크" 렌더링 대신 last_run_platform("xiaohongshu") 결과를 카드로 렌더
  → 카드 UI는 인스타/틱톡과 동일 컴포넌트 재사용(신규 UI 불필요)
```

## 구현 순서 (writing-plans에서 태스크로 쪼갤 것)
1. **[검증 최우선]** 서버에서 저장된 세션으로 실제 샤오홍슈 계정 프로필 페이지 1개 헤드리스 크롤 —
   노트 목록·좋아요·날짜 추출 가능한지 확인. 안 되면 B안(검색+필터)으로 설계 변경 후 재개.
2. `xiaohongshu_playwright.py` 크롤러 구현(1번에서 확인된 셀렉터/URL 패턴 기반)
3. `ranking.build_xiaohongshu_items()` 구현 + 유닛테스트(base/delta/grade 계산)
4. `service._collect_xiaohongshu()` + `collect()` 분기 연결
5. `refs.html` 탭 추가(채널 등록 UI)
6. `index.html` 샤오홍슈 탭을 실제 랭킹 렌더로 교체
7. 수동 E2E: 계정 몇 개 등록 → 수집 버튼 → 랭킹 카드 뜨는지 실기 확인

## 테스트 계획
- `build_xiaohongshu_items()`: base/delta/speed/density 계산 유닛테스트(`build_tiktok_items` 테스트 패턴 참고)
- 크롤러는 서버 실크롤로 수동 검증(Apify 의존 없어 유닛테스트로 온전히 커버 어려움 — 인스타 Playwright와 동일한 한계)
- 기존 게이트(`track.py finish`) 통과 확인

## 스코프 밖 (이번엔 안 함)
- 도우인 — 미착수 상태 유지, 별도 작업
- 세션 자동 갱신/만료 알림 — 만료되면 수동 재로그인(오늘 한 QR 절차 반복)
- 트렌드 딥링크 기능(전체 탭의 번역 카드) — 그대로 유지, 안 건드림
- 소스채널 마이닝 자동승격(발굴→등록 원클릭) — 해외HOT 쪽 얘기였고 이 작업 스코프 아님
