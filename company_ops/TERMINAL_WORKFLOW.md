# 터미널 컨펌 → 워크플로우 관제

## 사용 원칙

대표는 터미널 대화에서 지시하고 확정한다. 에이전트는 논의를 승인으로 추측하지 않는다.
컨펌된 내용, 대상 회사·팀, 완료 기준과 실행 권한이 명확할 때만 전달한다.
사용자에게 JSON 작성을 시키지 않고 전달 에이전트가 작성한다. 원문 대화 전체나 비밀정보는 복사하지 않는다.

현재 연결은 **로컬 큐 접수**까지다. 대표 본인 인증, 터미널 훅/자동 감지, 원격 PC 연결,
팀장 모델 수신·작업 분할·실행·고객 발송·배포는 구현되지 않았다.
`--confirmed-by-user`는 전달자의 확인 선언이며 기술적으로 사용자의 동의를 인증하지 않는다.
로컬 DB 접근 가능한 프로세스를 신뢰하는 개발 환경 한정이며 공개 서비스 승인 장치로 쓰지 않는다.

## 전달 계약

컨펌을 받은 에이전트가 다음 형식의 UTF-8 JSON 파일을 트랙 안에 준비한다.
아래 값은 양식 설명이며 실행 가능한 실업무 승인이 아니다.

```json
{
  "project": {
    "company_id": "makers",
    "team_id": "cs",
    "owner": "대표",
    "title": "확정된 업무 제목",
    "description": "컨펌된 지시, 범위, 완료 기준, 금지할 실행"
  },
  "receipt": {
    "request_id": "승인된 지시별 고유한 전달 번호",
    "session_ref": "실제 터미널 세션 또는 대화 식별자",
    "approval_ref": "실제 컨펌 메시지를 찾을 수 있는 참조",
    "approval_text": "해당 지시에 대한 실제 대표 컨펌 문구"
  }
}
```

트랙 루트에서 `py -m company_ops.terminal --db <서버와 동일한 DB의 절대경로> --file <컨펌된 JSON 경로> --confirmed-by-user`.
전달 번호와 모든 내용이 동일한 재전송은 같은 프로젝트를 돌려준다. 내용이 달라지면 거절한다.
변경된 범위는 새 컨펌과 새 전달 번호로 보낸다. 원본 컨펌 내용을 덮어쓰지 않는다.

## 진행 화면

`/static/directives.html`은 입력 폼 없는 관제 화면이다.
전체 회사/접수 경로 필터, 컨펌 근거, 담당 역할, 저장된 단계, 최근 100개 사건을 표시하고 5초마다 갱신한다.
터미널 컨펌 → 운영실 접수 → 팀장 확인 → 계획·분배 → 워커 실행 → 독립 검수 → 결과 보고 → 외부 실행·배포의 8개 구간을 보여준다.
현재 위치는 기존 프로젝트 원장의 단계이며 실제 실행 증명이 아니다. 미연결 항목은 별도로 표기한다.
기존 프로젝트는 컨펌 근거 없음으로 남긴다. 일반 웹 생성 API도 유지하므로 모든 기존 입력이 승인 게이트를 통과했다고 간주하지 않는다.
