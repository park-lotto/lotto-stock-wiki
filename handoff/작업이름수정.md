세션을 마칠 때 `py tools/track.py finish 작업이름수정`이 **전역 락 순번 대기**에 걸려

```

main = 아직 안 들어감 → ★라이브에 아직 안 갔다

```

확인법: `git log --oneline -3 origin/main`에 `내 작업 이름 직접 수정`이 보이면 이미 들어간 것.

### 무엇을 했나

사이드바 각 행에 **✏️ 버튼**(✕ 옆). 누르면 이름을 묻고 즉시 바뀐다.

**★사장님이 고른 규칙: 직접 지은 이름은 대본을 고쳐도 안 지워진다.**
자동 제목이 덮으면 "이름을 바꿨는데 되돌아간다"가 되기 때문. 이름 칸을 **비우면**
자동 제목(대본 앞 20자)으로 되돌아간다 — 그래서 별도 '해제' 버튼을 안 만들었다.

| 자리 | 무엇 |
|---|---|
| `store._work_title()` | **제목 판정의 유일한 출처**(0순위-B). `title_manual` 우선, 없으면 `script[:20]` |
| `store.rename_produce_work()` | `title` 컬럼 + `state_json`을 **한 트랜잭션에서 함께** 갱신 |
| `POST /api/produce/works/{id}/rename` | 남의 작업 404 · `name` 비문자열 422 |
| `sidebar.js` `__ssRenWork` | ✏️ 클릭 → prompt → POST → 그 행만 즉시 갱신 |
| `produce.html` `_workState`/`__ssApplyWorkTitle` | STATE에 실어 자동저장이 이름을 안 지우게 |

### ★왜 컬럼만 고치면 안 되나 (이 기능의 핵심)

`title` 컬럼만 바꾸면 **다음 저장(`upsert_produce_work`)이 state를 보고 제목을 다시
계산해 되돌아간다.** 제목의 진실은 `state.title_manual`에 있고 `title` 컬럼은 목록용
사본이다 — 그래서 rename이 **둘을 함께** 고친다.

같은 이유로 프론트도 손봐야 했다: `_workState()`가 `title_manual`을 안 실으면
자동저장이 그 필드 없는 state로 덮어써 **방금 지은 이름이 조용히 사라진다.**
복원 3경로(`_restoreWork`·`_consumeProduceHandoff`·`revertWork`)도 전부 되살린다.

⚠️ **모를 땐 키 자체를 안 보낸다** — 빈 문자열을 실어 보내면 사이드바에서 방금 지은
이름을 제작소가 지운다. `job_id`·`step`을 '알 때만' 보내는 것과 같은 계약이다.

### ★★밟은 함정 2건 (다음에 같은 걸 만들면 또 밟는다)

**① `window.x = ...`를 맨몸으로 쓰면 테스트 하네스가 통째로 죽는다**

`produce.html`의 `let WORK_ID` 이후 구간을 **잘라서 node로 돌리는 하네스가 여럿**
있다(`test_produce_work_save`·`test_produce_wiki_attribution`). 거기엔 `window`가 없어
`ReferenceError: window is not defined`로 **5건이 한꺼번에 죽었다**.
→ `if(typeof window !== 'undefined')` 가드. 회귀테스트로 못박음
(`test_hook_survives_harness_without_window`).

**② 맨 `✏`(U+270F)는 윈도우 크롬에서 '옆으로 누운 막대'로 그려진다**

스크린샷으로 실제로 확인했다(✕는 멀쩡한데 ✏만 뭉개짐). **U+FE0F(VS16)를 붙여야**
연필이 된다. 아이콘이 뭔지 모르면 아무도 안 누른다 → `test_rename_pencil_has_variation_selector`.
