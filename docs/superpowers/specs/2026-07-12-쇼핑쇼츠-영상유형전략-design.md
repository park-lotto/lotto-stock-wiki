# 쇼핑쇼츠 영상 믹싱 — 영상 유형별 대본 전략 설계

날짜: 2026-07-12 (믹싱 기능④ 후속 개선)
상태: 설계 확정(사용자 승인)
선행: 2026-07-12-쇼핑쇼츠-영상믹싱-design.md (믹싱 파이프라인 배포 완료)

---

## 1. 배경 (실사용 피드백)

첫 실전 믹싱(오이 냉동보관)에서 두 문제 발견:

1. **전사 단어 누락** — `script_extract`(Gemini 멀티모달 전사)가 나레이션을 완벽히 못 받아쓰고 단어를 몇 개씩 빠뜨림. 짜집기 소재인 원본 대본이 부정확하면 합성 품질도 저하.

2. **레시피형의 수익구조가 대본에서 무너짐** — 레시피/살림팁 영상의 비즈니스 모델은 "비밀 재료를 일부러 안 알려주고 → 댓글로 궁금증 유도(계정 성장) → 그 재료를 쿠팡파트너스로 연결"인데, 합성 대본이 반전 비트에서 "소금에 살짝 절인 뒤"라고 **재료를 그냥 밝혀버려** 참여 유도도 쿠팡 연결도 불가능해짐.

→ 영상 유형에 따라 대본 전략이 근본적으로 달라야 한다. 유형을 **자동 감지 + 사용자 확인**(방식 3)하고, 유형별 전략을 EDL 생성에 주입한다.

## 2. 영상 유형 (2종으로 시작, 확장 가능)

레지스트리 dict로 정의 — **유형 추가 = 항목 하나 추가**(코드 구조 변경 없음).

| type_key | 라벨 | 대본 전략 요지 |
|---|---|---|
| `recipe_secret` | 🍳 비밀비법형 | 레시피·살림팁. "이것만 넣으면 돼요"/"절대 하지 마세요" 류. **핵심 재료·비법을 이름으로 밝히지 말고 "이것"/"집에 있는 이거"로 감춘다.** CTA = "댓글에 [키워드] 남기면 알려드릴게요"(궁금증→댓글 유도). 숨긴 진짜 재료를 `affiliate_target`으로 따로 추출(쿠팡파트너스 연결용). |
| `product_reveal` | 🛍️ 상품형 | 제품·정보를 다 보여준다. CTA = "댓글에 [키워드] 남기면 구매링크 보내드릴게요". 노출된 제품명을 `affiliate_target`으로 추출. |

(향후: 정보전달형, 챌린지형 등 항목만 추가.)

## 3. 아키텍처

### 3-1. `edit_plan.py` — 유형 레지스트리 + 자동 판별 + 전략 주입

```python
VIDEO_TYPES = {
    "recipe_secret": {
        "label": "🍳 비밀비법형",
        "strategy": "이 영상은 레시피/살림팁 '비밀비법형'이다. 핵심 재료·비법을 "
                    "절대 이름으로 밝히지 마라 — '이것', '집에 있는 이거', '한 스푼'처럼 "
                    "감춰서 궁금하게 만들어라. 마지막 CTA 비트는 반드시 "
                    "'댓글에 [키워드] 남겨주시면 알려드릴게요' 형태로 궁금증→댓글을 유도해라.",
    },
    "product_reveal": {
        "label": "🛍️ 상품형",
        "strategy": "이 영상은 제품을 직접 소개하는 '상품형'이다. 제품명·정보를 "
                    "명확히 보여줘라. 마지막 CTA 비트는 '댓글에 [키워드] 남겨주시면 "
                    "구매링크 보내드릴게요' 형태로 구매 전환을 유도해라.",
    },
}
_DEFAULT_TYPE = "product_reveal"
```

- `detect_video_type(source_scripts) -> str`: 소스 대본들을 Gemini로 분류해 type_key 반환(전용 풀). 실패/불확실 시 `_DEFAULT_TYPE`. VIDEO_TYPES에 없는 값 반환 시 기본값으로 보정.
- `build_edit_plan(source_scripts, target_seconds, structure="template", video_type=None, ...)`:
  - `video_type`가 None이면 `detect_video_type()`로 자동 판별(방식 3의 자동 단계).
  - 판별된 유형의 `strategy`를 `_PROMPT`에 새 슬롯 `{type_strategy}`으로 주입.
  - 응답 스키마에 `affiliate_target`(문자열, 쿠팡 연결 대상 제품/재료) 추가, `required` 아님(모델이 못 뽑으면 빈 문자열).
  - 반환 EDL에 `detected_type`(사용된 type_key)과 `affiliate_target` 포함.

### 3-2. `_PROMPT` 확장

기존 프롬프트에 유형 전략 블록 + affiliate 지시 추가:
```
{type_strategy}

추가 규칙:
- 위 유형 전략을 반드시 따르라(특히 CTA 비트와 재료 노출/은폐 여부).
- affiliate_target: 이 영상이 궁극적으로 팔거나 연결할 핵심 제품/재료 하나를
  정확한 이름으로 뽑아라(비밀비법형이면 감춘 그 재료의 실제 이름, 상품형이면 그 제품명).
  나레이션엔 은폐하더라도 이 필드엔 실제 이름을 넣어라.
```

### 3-3. `template_mode` 라벨 버그 수정 (겸사겸사)

`build_edit_plan`이 모델 응답의 `raw["structure"]`(모델이 "template_mode" 등 지어냄)를 그대로 저장하던 문제 → **입력 `structure` 값으로 강제**:
```python
grounded = _validate_and_ground(raw, seg_map, n_alternates)
grounded["structure"] = structure  # 모델이 지어낸 라벨 무시, 입력값 고정
grounded["detected_type"] = video_type
grounded["affiliate_target"] = raw.get("affiliate_target", "")
```

### 3-4. `script_extract.py` — 전사 정확도 강화 (피드백 1)

`_PROMPT`를 verbatim 강화:
- "**한 단어도 빠짐없이** 들리는 그대로 받아써라. 요약·의역·생략 절대 금지."
- "말이 빠르거나 뭉개져도 최대한 정확히. 확실치 않으면 가장 근접한 표기로."
- "화면에 자막이 있으면 자막과 음성을 **교차 확인**해 더 정확한 쪽으로 보정하라."
- (온도 등 파라미터는 google-genai 기본 유지 — 프롬프트 개선 우선, 실측 후 필요 시 조정.)

### 3-5. `mix_pipeline.py` — 파이프라인 연결

- `run_mix_job`: `build_edit_plan(source_scripts, target_seconds, structure=..., video_type=None)` (자동 판별). 결과의 `detected_type`/`affiliate_target`이 edit_plan_json에 포함돼 저장됨(별도 컬럼 불필요 — edit_plan_json 안에).

### 3-6. API + UI (방식 3: 자동 + 확인)

- `GET /api/mix/result/{job_id}` 응답에 `detected_type`, `detected_type_label`, `affiliate_target`, 그리고 선택 가능한 `video_types`(레지스트리의 key+label 목록) 추가.
- 신규 `POST /api/mix/retype` `{job_id, video_type}` — 사용자가 감지된 유형을 바꾸면 저장된 `extract`로 `build_edit_plan(..., video_type=선택값)` 재실행 → edit_plan 갱신 → 비트별 TTS 재생성 → status를 다시 `ready_for_review`로. (재다운로드·재추출 없음, extract 캐시 재사용.)
- `mix.html` 검토 화면 상단:
  - `🍳 비밀비법형으로 감지됨 ▾` 배지(드롭다운=video_types). 바꾸면 `/api/mix/retype` 호출 → 폴링 → 새 EDL 렌더.
  - 하단에 `🔗 쿠팡 연결 대상: 소금` (affiliate_target) 표시. 비어있으면 숨김.

## 4. 데이터 모델

신규 컬럼 없음 — `detected_type`/`affiliate_target`은 `edit_plan_json` 안에 포함. (재타입 시 그 안의 값만 갱신.)

## 5. 알려진 리스크

- **유형 오분류**: 자동 감지가 틀릴 수 있음 → 방식 3의 사용자 확인/재타입으로 커버. 감지 정확도는 실제 영상들로 관측 후 프롬프트 튜닝.
- **affiliate_target 부정확**: 비밀비법형에서 진짜 재료를 못 집으면 빈 값 → UI에서 숨김(치명적 아님).
- **재타입 비용**: retype은 EDL 재생성 + TTS 재생성(Gemini/TTS 재호출). 다운로드·추출은 재사용해 비용 최소화.
- **전사 강화 실측 필요**: 프롬프트만으로 누락이 충분히 줄었는지는 실제 영상으로 확인(피드백 1의 검증은 실영상 필요).

## 6. 단계적 구현 순서

1. `edit_plan.py`: VIDEO_TYPES 레지스트리 + `detect_video_type` + `build_edit_plan`에 video_type/affiliate_target/template 라벨 수정 (+ 유닛테스트: 판별 몰킹, affiliate 추출, structure 고정).
2. `script_extract.py`: verbatim 프롬프트 강화 (기존 테스트 유지).
3. `mix_pipeline.py`: build_edit_plan 자동판별 연결 (기존 테스트 유지 + detected_type 저장 확인).
4. `app.py`: `/api/mix/result` 확장 + `/api/mix/retype` 신규 (+테스트).
5. `mix.html`: 유형 배지 드롭다운 + affiliate 표시 + retype 폴링.
6. E2E: 실제 레시피 영상으로 비밀비법형 감지→재료 은폐 대본+affiliate 추출 확인(사람 관찰).
