## 0. 진단 요약 (실측)

- 나레이션은 하나의 이야기(흰쌀밥 걱정→소아과 쌤→바꿈→변화)인데, 화면은 요리
  시간순을 무시하고 과정(붓기)↔결과(완성)를 무작위 핑퐁.
- 원인①: `edit_plan.py` — Gemini가 비트마다 seg_id를 **의미로 자유선택**. 소스
  시간순(요리 단계) 제약이 전무.
- 원인②: `video_assemble.py:178-181, 405-412` — 비트 나레이션이 세그먼트보다
  길면 마지막 클립을 `setpts` slow-mo로 **늘려서** 채움(설계 기본, `:5` 주석).
- 원인③: `script_generate._MIX_PROMPT` — "각 대본의 강점을 조합"이라 서사(인물·
  사건)가 섞임. 사장님 요구 = 한 인물·한 사건이 결말까지.

## 1. 핵심 통찰 — 벤치마크를 잘못 모방하고 있었다

홈에디터류 레퍼런스의 실제 구조:
- **화면 = 요리 과정을 시간순으로 그냥 흘려보냄** (편집 리듬만 관리)
- **나레이션 = 그 위에 얹는 스토리** (화면과 1:1 의미 매칭을 하지 않음)
- 동기화는 **몇 개의 앵커 순간만** ("계란 풀어서" 할 때쯤 섞는 장면)

우리 시스템의 근본 오류 = 문장마다 의미가 맞는 장면을 찾으려 한 것 자체.
그래서 장면이 시간을 넘나들고, 못 찾으면 슬로우로 때웠다.

## 2. 설계 — 2트랙 모델

```
비주얼 트랙(스파인):  [준비]→[조리]→[변화]→[완성]→[시식]   ← 소스 시간순, 재배열 금지
나레이션 트랙(스토리): 훅→고민→전환점→해결→변화→CTA        ← 한 인물·한 사건·결말
결합:                 ⚓앵커 비트만 단계에 스냅, 나머지는 자유
```

### 2-1. 비주얼 스파인 (시간순 강제)
- 소스 세그먼트에 **과정 단계 태그** 부여: `준비 | 조리 | 변화 | 완성 | 시식`
  (+ `기타`). 세그먼트 인벤토리에 이미 `scene_desc`가 있으므로 태깅은
  인벤토리 빌드 시 Gemini 1콜(또는 기존 콜에 필드 추가)로 충분.
- 스파인 = 태그된 세그먼트를 **(단계 순, 단계 내 소스 시간순)** 으로 배열.
- **모델에게 순서 결정권을 주지 않는다** — 프롬프트 유도가 아니라 코드 검증
  (`_validate_and_ground` 확장)으로 강제. 시간 역행 지목은 드롭/다음 미사용
  구간 대체.
- 소스가 2개 이상일 때: 같은 단계 안에서는 **한 소스를 우선 소진** 후 다음
  소스(주방이 자꾸 바뀌는 프레임 핑퐁 방지).

### 2-2. 앵커 결합 (전부 매칭하려다 다 망가지는 것 방지)
- 대본 비트 분류: **앵커 비트** = 물리적 행위/상태를 직접 언급
  ("계란 풀어서 섞고", "딱 5분만 돌리면", "노릇하게 익으면") /
  **자유 비트** = 스토리·감정·권위 인용("소아과 쌤이", "우리 애들 멍하게").
- 앵커 비트만 해당 단계 구간에 스냅. 자유 비트는 스파인이 흐르는 대로 얹힌다.
- 앵커 충돌(순서상 뒤 앵커가 앞 단계 지목) 시: 대본 순서가 아니라 **스파인
  순서가 이긴다** — 그 앵커는 자유 비트로 강등하고 신호등에 표시.

### 2-3. 시간 맞춤 (슬로우 제거)
- 비트가 배정 구간보다 길면: 클립을 늘리지 말고 **그 단계의 다음 미사용
  세그먼트를 이어붙인다**(요리가 자연히 진행).
- 단계 내 세그먼트 소진 시에만 slow-mo 허용, **상한 1.15배**. 초과분은
  마지막 프레임 정지(freeze) 또는 다음 단계 조기 진입.
- 교체 지점: `video_assemble._plan_beat_clips`(152-192)의 shortfall 로직,
  `:405-412`의 setpts factor 상한.

### 2-4. 대본 스토리 일관성 (한 스토리 강제)
- `script_generate._MIX_PROMPT` 개편: "각 대본의 강점을 조합" →
  **"먼저 인물 1명·사건 1개·결말 1개를 정하라. 다른 대본에서는 표현·훅
  방식·말투만 빌리고, 인물과 사건은 절대 섞지 마라. 훅에서 던진 이야기가
  CTA까지 끊기지 않고 이어져야 한다."**
- 검증 축: 초안 applied에 "빌린 것"과 "유지한 스토리"를 분리 기재하게 한다.
- 기존 요소 버튼(훅·전개·발상전환·인물·CTA…)과 그대로 호환 — 요소 변형은
  "한 스토리 안에서"의 변형이 된다.

## 3. 소싱 전략 (사장님 질문 직답)

**정답은 개수가 아니라 "단계 커버리지"다.**

| 전략 | 판정 |
|---|---|
| 같은 요리 영상 2~3개 | ✅ 정답. 스파인은 연속성(같은 주방·팬·손)이 생명. 2개가 준비~시식을 덮으면 충분, 못 덮으면 3개째 |
| 비슷한 영상 4~5개 | ⚠️ 커버리지는 늘지만 시각 연속성 파괴 위험. 같은 요리·같은 흐름일 때만 |
| 라이브러리 대량 장면 조각 | ❌ 메인 과정 트랙 부적합(짜집기 티). **컷어웨이 전용**(훅 리액션·CTA·감탄샷 1~2초) — scene_match.py가 이미 이 역할 |

- **소스 영상 = 뼈대(과정 스파인) / 장면 라이브러리 = 양념(컷어웨이).** 섞지 않는다.
- 담기 단계에서 **커버리지 신호등**: 단계별 세그먼트 유무를 보여주고
  "굽기 장면이 없어요 — 비슷한 영상 1개 더 담으세요"를 안내(기존 완성도
  신호등 확장). 60대가 감으로 헤매지 않게.
- **대본 먼저는 유지** — 단 대본이 장면 하나하나를 지배하는 게 아니라
  앵커만 지배하는 느슨한 결합으로 바뀐다.

## 3-2. 확정 방향 (사장님 결정, 2026-07-19) — 원클릭 완전자동

- **"더 담으세요" 커버리지 신호등 폐기.** 60대는 소싱 안 한다 — 시스템이 알아서 한다.
  샘플 영상은 이미 단계가 다 있었고 순서만 엉킴 → P2(시간순)만으로 추가소싱 0으로 해결.
- **원클릭.** 사장님은 [최적 믹스] 한 번 누른다. AI가 비트마다 "장면을 바꿀까 / 대본을
  고칠까"를 스스로 판단해 최적 EDL을 만든다. **버튼 딸깍딸깍 재생성 과정 없음.**
- **선택적 비상구.** 기존 편집안·[다른 화면으로] 스왑은 강제 아닌 옵션으로 남긴다(안 봐도 됨).
- **행동/스토리 구분(앵커).** 행동 문장("계란 풀어서")만 화면과 맞추고, 스토리 문장
  ("소아과 쌤이")은 시간순 화면 위에 그냥 흐른다 — 전부 맞추려는 게 원래 핑퐁의 원인.
- 트레이드오프: 완전자동이라 AI 판단이 가끔 틀림 → 마음에 안 들면 다시 원클릭(결과 조금 달라짐).

## 4. 구현 페이즈 (독립 배포 단위)

| P | 내용 | 지점 | 비고 |

| P1 | 슬로우 제거: 단계 내 이어붙이기 + slow-mo 상한 1.15 + freeze | `video_assemble.py:152-192, 405-412` | 즉효·독립 배포 |
| P2 | 세그먼트 단계 태깅 + 시간순 스파인 코드 강제 | `edit_plan.py` `_build_inventory`·`_validate_and_ground` | 순서 핑퐁 종결 |

- 각 P는 별도 finish(태스크 단위 병합) — 렌더 중 배포 사고 주의(렌더멈춤진단 트랙 참조).
- 트랙: `장면스파인` (신규) 권장. produce.html·edit_plan.py·video_assemble.py는
  다트랙 hot — 반드시 트랙 격리.

- P5 후: 조합 초안 3개에서 인물·사건이 처음~끝 동일한지 육안(레퍼런스랭킹 실대본).
- 전 단계: 라이브 실렌더가 최종 증명(단위 테스트는 Gemini mock).

## 6. YAGNI / 비목표

- 장면 라이브러리를 과정 트랙에 편입하는 것 — 하지 않는다(연속성 파괴).
- BGM 비트싱크·컷 리듬 자동화 — 이번 범위 밖.
- 소스 5개+ 대량 믹스 최적화 — 같은 요리 2~3개 원칙이 먼저 검증돼야 함.

## 7. P5 보강 — 페이블 검증 (2026-07-19)

오푸스 초안 설계(P5+CTA+자기검증)를 페이블이 코드 실측으로 검증해 다음을 교정·확정했다.
구현 계획(집행용): `docs/superpowers/plans/2026-07-19-P5-대본스토리-자기검증.md`

1. **★적용 범위 교정**: 사장님이 보여준 품질 문제 화면("대본 뽑기·원본 소재 그대로")은
   `_MIX_PROMPT`(조합)가 아니라 `_GEN_PROMPT`(단일 리메이크/이식) 경로다. _MIX_PROMPT만
   고치면 그 화면은 그대로 남는다 → 스토리 헌장을 **두 프롬프트 공통 블록**으로 주입한다.
2. **스키마 강제**: 프롬프트 텍스트만으론 모델이 흘린다. 초안 스키마에 story_person·
   story_event·story_resolution·cta_line·cta_keyword를 required로 박아 스토리를 먼저
   선언하게 한다. 선언 필드는 나중 CTA/골격 패턴 라이브러리의 축적 데이터가 된다
   ("레시피라고 다 같지 않다" — 사장님, 2026-07-19).
3. **CTA는 패턴 메뉴**: 하드코딩 1문구 금지. 레시피/비법형 소재→댓글키워드형 필수
   (키워드는 소재에서 추출), 그 외→저장·팔로우·궁금증형 중 소재 적합형. 본문에서
   비법 하나를 아껴 CTA와 인과로 잇는다.
4. **자기검증 루프 = 판정1콜 + 미달만 수정1콜**: 전체 재생성이 아니라 통과 초안 보존.
   판정 불능 시 fail-open(생성 자체는 절대 안 죽는다). 키는 key_vault 캐스케이드 통일.
5. **기존 테스트 실키 유출 차단**: 검증 루프가 붙으면 기존 mock 테스트가 트랙 .env의
   실키 45개로 실제 Gemini를 때린다 — _wire류에 캐스케이드 차단 패치를 배선보다 먼저.
6. **실측 정정**: ELEM_LABELS의 CTA 요소는 이미 구현돼 있다(script_generate.py:58) —
   조합대본-요소업그레이드 설계 ①의 해당분은 추가 작업 불필요.
