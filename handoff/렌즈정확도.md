## 2026-08-29 (회사PC) — 렌즈에 핀터레스트 노출 (숏폼 영상만)

사장님: **"여기에 핀터레스트 검색결과도 노출해줘 / 숏폼영상만"** (렌즈 유사영상 모달)

### 핵심 발견 (전부 실측 — 익명 requests, 비용 0)

- 렌즈(SerpApi)가 핀터레스트 링크를 원래 물어오는데 `_PLATFORM_DOMAINS`에 없어 **전부 버려지고 있었다**.
- 핀이 영상인지 응답엔 없다 → **핀 상세 페이지의 JSON-LD `VideoObject`**가 판별 신호다:
  영상 핀 2/2 있음(contentUrl=v1.pinimg mp4·duration=PT15S·썸네일·제목) / 이미지 핀 4/4 없음.
- 비공식 API(`PinResource/get`)는 익명 403이라 못 쓴다. **핀 페이지는 로그인 없이 200**(1.3MB).
- pinimg CDN은 핫링크 차단 없음(Referer 없이 200) → 기존 `/api/video` 프록시(pinimg 화이트리스트
  는 핀터레스트탭 트랙이 이미 등록)로 인라인 재생이 그냥 된다.

### 변경 (트랙: 렌즈정확도)

- `pinterest_crawl.pin_video_info(url)` 신설 — 판별+mp4+길이+제목+썸네일을 **한 곳**에서(0순위-B).
  반환 3갈래: dict=영상확정 / None=이미지확정 / 예외=판정불가 — 호출부 처분이 다르다.
- `lens_discover`: `_PLATFORM_DOMAINS`에 pinterest, `_is_watchable`은 `/pin/`만,
  `_dedup_key`는 핀 id로(kr./www.·슬러그 변형이 같은 핀), `verify_matches`에서 병렬 실조회 —
  영상확정=play_url·duration·제목 보강 / 이미지확정=**서버컷**(08-16 사진·롱폼 컷과 같은 원칙) /
  판정불가=is_photo=True(기본 가림, 🎬영상만 끄면 보임). 실조회 상한 `LENS_PIN_VERIFY_MAX`(기본 20).
  ★verify_matches 시그니처는 (items, keywords) 유지 — **테스트 9곳이 이 모양 람다로 갈아끼운다**.
  핀 계측(diag pin_raw/pin_video/pin_dropped)은 search_similar_videos에서 앞뒤 개수차로 센다.
- `media_download.download_any`: pinterest 분기 → 핀 페이지에서 mp4 직링크 뽑아 직접 다운로드.
  **렌즈뿐 아니라 핀터레스트 탭 담기(url=핀 페이지)도 종전엔 '지원하지 않는 URL'로 죽던 구멍**이 같이 막힘.
  trace_url(주소로 가져오기)에 핀 URL을 붙여넣는 것도 같은 경로로 열림.
- `index.html`: `LENS_PLATFORMS`에 `{k:'pinterest',label:'📌 핀터레스트'}` 한 줄(맨 뒤=정렬 마지막).
  재생·담기·원본열기는 기존 경로 그대로(play_url 분기·mix_basket URL 저장) — 프론트 신규 분기 0.

### 검증

- 실핀 통합 실측: 영상 핀=play_url·15.0s·제목 보강 / 이미지 핀=컷 / 존재X 핀=200 껍데기라 컷(죽은 링크 숨김과 일관).

- 기존 테스트 2건 갱신: `test_filters_to_five_video_platforms`→supported(핀터레스트 포함),
  instagram_dropoff는 시그니처 유지 설계로 무수정 통과.

## 2026-08-21 (회사PC) — 메인 렌즈에 AI 유사도 채점을 붙였다

사장님: **"렌즈 검색부분 단순하게 마지막에 만들면서 검색 정확도까지 떨어진 것 같은데 올릴 방법 없나"**

### 먼저 확인한 것 — 판정기가 세 경로 중 하나에만 없었다

| 경로 | 채점 | 판정 방식 |
|---|---|---|
| `/api/lens/cn` (샤오홍슈·도우인) | ✅ 있음 | `judge_same_product` (AI) |
| `/api/lens/yt` (유튜브) | ✅ 있음 (2026-08-16 추가) | `judge_same_product` (AI) |
| **`/api/lens/search` (메인 렌즈)** | ❌ **없었다** | `_title_matches` (문자열) |

메인 렌즈의 `match`는 `lens_discover._title_matches`(`lens_discover.py:156`)에만 의존했다
— **캡션 2자 토큰이 제목에 부분포함되면 True**. 오탐이 쉽고, 중국어·영어 제목은 아예
안 맞아 `False`가 된다. 그래서 프론트 `⚠️ 다른주제 숨기기`가 **기본 꺼짐**이었다
(`index.html:3111` 주석: "중국어·영어 제목은 키워드가 안 맞아 원본(해외) 후보까지 사라질 수 있어").

### ✅ 고친 것 (커밋 `4bef8832b`)

- **`_lens_judge()` 신설**(`app.py:5774`) — 판정을 새로 짜지 않고 **기존 `judge_same_product`를
  그대로 쓴다**(0순위-B). 두 호출부(`/api/lens/search`·`/api/lens/trace_url`)가 같은 한 곳을 지난다.
- **정렬 키 2개**: ①관련도(`same`→`similar`→`no`) ②같은 관련도면 인스타 먼저.
  채점이 없으면(캡션 없음·실패) 전부 같은 등급 → **종전 인스타 우선 정렬 그대로**(회귀 0).
- **★`to_thread` 필수**: `judge_same_product`는 블로킹 Gemini다. `api_lens_search`는 `async`인데
  `_lens_finalize`는 **이벤트루프에 남겨둔 함수**(sqlite 같은 스레드 제약)라, 그 안에서 그냥
  부르면 루프가 몇 초 멈춰 **동시에 오는 `/api/lens/cn/keywords`가 굶는다**(파일 주석이 SerpApi·비전에
  대해 경고하던 바로 그 함정). → async 경로는 `await asyncio.to_thread(_lens_judge, ...)`로 먼저
  채점하고 `_lens_finalize`엔 `caption=None`을 넘겨 **두 번 채점하지 않는다**.
  `trace_url`은 sync `def`(threadpool)이라 캡션을 그대로 넘긴다.
- 캡션 없으면 **아예 호출 안 함**(헛돈 방지). 실패·예외·개수불일치는 조용히 폴백.

**비용**: 검색당 `_TRANSLATE_MODEL` 텍스트 1회 ≈ 0.5원 안쪽.

### 검증 — 가짜 green 아니다

- 신규 테스트 5개(네트워크 안 탐). **되돌리기 확인**: 채점 호출을 빼니 **정확히 2개가 빨간불**,
  복원하면 40 green.
- 전체 스위트 **5,032 passed / 12 skipped**.

### ⚠️ 다음 세션이 반드시 알아야 할 것 — `.env`가 게이트 결과를 바꾼다 (실측)
