## 설계에서 중요한 것 3가지

**① 폰은 배달만 한다.** 판정·검색·생성이 전부 서버에 있어서, 카톡이 업데이트돼 폰
스크립트가 깨져도 답변 품질 코드는 무사하다. 테스트(`test_phone_script_stays_thin`)가
폰 스크립트 30줄을 강제하고, 거기 "환불·결제·포인트" 같은 판정어가 들어가면 실패시킨다.

**② 지어내지 않는다.** 승인된 자료에서 검색해 근거가 약하면 **제미니를 아예 안 부른다**.
`bot_answer.answer()`가 None을 주고 라우트가 "확인해서 알려드릴게요"로 넘긴다.
못 답한 질문은 `bot_unanswered`에 쌓여 **다음에 채울 목록**이 된다(같은 질문은 count 증가).

**③ 돈 얘기는 AI를 안 거친다.** 환불·결제·계좌·입금·카드·청구·요금제·해지·탈퇴가 들어오면
검색도 생성도 건너뛰고 바로 운영자 연결로 간다(잘못 답하면 분쟁).

## 야간 진행 중 잡은 것 (계획이 틀렸던 부분)

1. **`!질문` 정규식 버그** — `!질문`만 치면 "질문"을 질문 내용으로 읽었다. 키워드 뒤에
   공백/끝일 때만 벗기게 수정.
2. **★비밀키 미설정 = 라우트 개방** — 종전 비교식은 미설정("")과 헤더없음("")이 같아져
   **아무나 부를 수 있었다**(실측 200). 사장님이 키를 나중에 넣는 게 정상 경로라
   그 사이가 위험했다 → 키가 비면 무조건 401.
3. **`DASH_PASS` 없으면 인증이 통째로 꺼진다** — 관리자 가드 테스트가 가드 없이도
   통과하는 가짜 green이 될 뻔했다. 게다가 `monkeypatch.setenv`는 **import 시점에 읽히는
   값이라 효과가 없어**, 코드베이스 관례대로 `_AUTH_ON`을 직접 패치로 교정.
4. **중복 함수 신설 시도** — 계획이 `_bot_admin_denied`를 새로 만들라 했는데 이미
   `_require_admin`이 10곳에서 쓰이고 있었다(0순위-B 위반) → 기존 것 재사용.
5. **★`Utils.getWebText2` 시그니처가 없는 것이었다** — 계획의 4인자 호출은 존재하지 않는다.
   공식 문서상 그건 **인자 2개짜리 레거시**(url, 인코딩)라 POST·헤더를 못 싣는다.
   대안 `Http.request`도 본문 키가 문서에 없어 → **jsoup 직접 호출**로 교정.
6. **테스트 격리 버그** — 하루 상한 테스트가 **우연히** 통과하고 있었다(앞 테스트의
   카운트 이월). 단언을 약하게 만들지 않고 픽스처에서 상태를 비우게 수정.
7. `.format()` 중괄호 함정은 **실측 결과 사실이 아니었다**(150개 전부 무사). 그래도
   더 안전한 문자열 이어붙이기로 두되, 사실이 아니었다는 걸 기록해 둔다.
