# 레퍼런스 채널 통합 관리페이지 — 설계

- 날짜: 2026-07-24
- 트랙: 레퍼런스랭킹개편
- 상태: 설계 확정(사장님 3질문 답) → 구현

## 1. 문제 (사장님)
"인스타 채널처럼 등록해놓고 쭉 뜨게 하고 싶다. 관리페이지를 하나 만들고 엑셀처럼 등록하고."

지금은 등록 UI가 **랭킹 화면 안에 섞여** 있고 **하나씩만** 넣는다(인스타 URL 하나 / 틱톡 @핸들 하나).
인스타도 이미 50개를 하나씩 넣은 상태 — 대량 관리가 안 된다. 등록해두면 계속 뜨는 것 자체는
이미 됨(계정 시드·discovered는 `지금 수집`마다 자동으로 훑음). 불편한 건 **등록 UX**다.

## 2. 확정 방향 (사장님 선택)
1. **새 전용 페이지** `/refs` (관리자 전용) — 랭킹 화면은 결과만 깔끔하게.
2. **여러 줄 붙여넣기** — 큰 textarea에 한 줄에 하나씩 붙여넣고 일괄 등록(엑셀 한 열 복붙 그대로).
3. **3플랫폼 통합** — 인스타·유튜브·틱톡을 한 페이지에서 플랫폼 탭으로.

## 3. 저장 경로 (실측 — 플랫폼마다 다름, 통합기가 라우팅)
- **인스타**: `channels.username_from_url(url)` → `store.add_discovered(username)`. **비용 0**
  (프로필 조회 안 함, URL에서 username만 파싱). 목록=`store.discovered_channels()`+엑셀.
- **틱톡**: `@핸들` → `store.add_seed("tiktok", "account", value)`. 무료 yt-dlp 수집.
- **유튜브**: `store.add_seed("youtube", "account", value)` — **등록만**. 채널기반 수집은 Phase 2.
  (지금 유튜브 수집은 키워드 시드 기반이라, account 시드는 저장돼도 Phase 2 전엔 안 훑음. UI에 명시.)

전부 과금 없음 → 50줄 붙여넣기 안전.

## 4. 백엔드 (app.py, 전부 `_require_admin` 먼저)
- `POST /api/refs/bulk` — body `{platform, text}`. text를 줄로 쪼개 각 줄 등록.
  플랫폼별 라우팅(위 3). 반환 `{ok, added:[...], already:[...], failed:[{line,reason}]}`.
  틱톡/유튜브 @는 lstrip("@") 정규화; 인스타는 username_from_url 실패 시 failed.
- `GET /api/refs/list?platform=` — 해당 플랫폼 현재 등록 목록 `{ok, items:[{handle}]}`.
  인스타=discovered+known / 틱톡·유튜브=list_seeds(kind=account).
- 삭제: 틱톡·유튜브=기존 `DELETE /api/seeds`. 인스타=기존 '등록 취소'가 쓰는 API 재사용
  (index.html loadRefAdded의 삭제 경로). 없으면 `store`에 소프트 제거 추가.

## 5. 프론트 (새 파일 static/refs.html + route)
- route: `_voice_tune_page` 패턴 그대로 — `/refs`·`/refs.html` 둘 다 `_require_admin`,
  `app.mount("/", StaticFiles)` **앞에** 등록(안 그러면 게이트 우회).
- 화면: 플랫폼 탭 3개 → 탭별 { 붙여넣기 textarea + 「일괄 등록」 버튼 + 결과요약 + 등록목록 표(핸들·삭제) }.
- 플랫폼별 placeholder/도움말: 인스타=`instagram.com/아이디` 한 줄에 하나 / 틱톡=`@handle` /
  유튜브=`채널(등록만, 수집은 Phase 2)`.
- 사이드바(index.html 등 공통 네비)에 "📋 레퍼런스 채널 관리" 링크 추가(관리자만 보이게).

## 6. 범위 밖 (YAGNI)
- 표 인라인 편집(칸별 수정) — 붙여넣기+삭제로 충분.
- 랭킹 화면 기존 등록칸 제거 — 남겨둠(되돌리기 안전, 혼란 시 나중에 정리).
- 유튜브 채널기반 실제 수집 — Phase 2.
