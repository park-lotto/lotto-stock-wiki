# 대본 엔진 — "대본 설명서(script_frame)" 설계 (2026-10-16, 사장님: "대본을 어떻게 분석할지 제일 중요. 분석만이 아니라 우리도 쓸 수 있게 대본 엔진에 넣어야 하고, 상품 하나 찾으면 장면과 맞는 대본이 나와야 한다")

## 원칙
- 틀(외관)과 같은 네 고리: **뜯기 → 설명서(script_frame.json) → 생성(엔진) → 검사**. 설명서는 숫자·목록이라 검사로 잴 수 있어야 한다.
- 판단 주인: 설명서 만들기 `script_frame.py:build`, 생성 `script_engine.py:draft(product, frame)`, 검사 `script_engine.py:check(script, frame)`. 세 함수 밖에 같은 판단을 두 번 적지 않는다.
- 빈칸 끼우기 금지(메모리 `feedback_빈칸끼우기_금지`): 공식은 "칸 순서+통계+예문"이고 문장은 모델이 통째로 쓴다. 어미는 원문에서 떼어온 목록만(메모리 `reference_어미는_원문에서_떼어와라`).

## ★설명 방식 층 (사장님 10-16 밤: "같은 상품도 이 채널만의 포인트·설명 방식이 분명 있다. 정형화 틀이 아니라 계속 그런 대본이 나오는 방법")
구조(1~5칸)만 베끼면 "그 채널처럼 보이는 글"까지다. "그 채널처럼 설명하는 글"은 아래 세 층을 **대조**로 뽑아야 나온다.
| 층 | 무엇 | 어떻게 뽑나 | 생성에서 쓰는 법 | 검사 |
|---|---|---|---|---|
| S1 선택 규칙 | 상품 사실 목록 중 이 채널이 집는 2~3개의 **종류**(설치 난이도·공간 효과·부모님 관점·가격 대비…)와 빼는 것 | 같은 품목을 다룬 **다른 채널 영상과 나란히** 놓고 고른 사실/뺀 사실 diff(발굴 DB 대조군) | 새 상품 사실 목록에서 규칙으로 말할 사실을 먼저 고른다 | 고른 사실의 종류가 규칙 상위 축 안 |
| S2 논리 사슬 | 상황→기존 불편→제품 속성→결과→증거 같은 **설득의 길**과 그 분포(순서가 아니라 사슬 꼴) | 50편 문장을 사슬 노드로 라벨 → 사슬 꼴 빈도 | 사슬 꼴을 지정하고 모델이 통째로 쓴다 | 사슬 꼴이 채널 분포 안(상위 꼴 중 하나) |
| S3 가까운 예문 | 상품 유형별 원본 3편(검색: 품목·가격대·설치형) | 사실+규칙+예문 3편을 주고 통째 생성 — 상품마다 예문이 달라 같은 틀에서 찍은 글이 안 나온다 | 예문과 7자 이상 겹침 금지(베낌 검사) |
- **판별기 검사**: 원본 10편·다른 채널 10편을 기준으로 새 대본이 어느 쪽에 가까운지 모델 판정 + S1/S2 수치. **대조 시험**: 같은 상품을 두유노홈디노 설명서와 핫템 설명서로 각각 생성 → 고른 사실·사슬이 달라야 통과(같으면 설명서가 결을 못 담은 것).

## 생성 흐름 (`draft`)
상품 1개(이름·링크·facts) → 사실 수집(기사 `find_articles`·댓글·상품 페이지) → 소재 유형에 맞는 공식 선택 → 칸별 문장 생성(어미·길이·소구점 근거 필수, 줄마다 `shot_kind`) → `check`(기존 5종 + 1~5칸 검사) → 장면 계획(`shot_kind` → 재료 검색어·후보) → 선검수 시트.

## 검증(정답 시험)
- LOO: 원본 50편 중 10편을 숨기고 같은 상품 사실만 줘서 엔진 대본과 원본을 대조 — 역할 순서 일치율·화법 통계 범위·소구점 종류 일치. 기준: 순서 일치 ≥70%, 화법 범위 안 ≥80%.
- 다양성: 같은 상품 10회 생성 → 첫 문장·칸 순서가 10개 중 ≥7개 다름(메모리 "회원 100명 돌려쓰면 같음" 사고).
- 빨강 시험: 설명서를 다른 채널 것으로 바꿔 끼우면 check 가 반려해야 한다.

## ★사장님 결정 (2026-10-16 밤): 이 채널 결은 과장 허용·출처 표기 불필요
- **과장 표현 허용**: 과장 동사(때려박아·미쳐버린·올려버렸는데), 결과 과장, 사회 반응 과장("~까지 난리") 모두 허용. 최상급·과장 검사(claim_off 등)는 두유노홈디노 설명서에서 **끈다**(채널별 스위치 `allow_hype=true`).
- **출처 표기 불필요**: 대본·자막에 출처를 쓰지 않는다. 근거.md 작성도 의무 아님(있으면 좋음).
- 해석(페이블): 수치·기관명(40%·WHO·10년째 1위)은 상품에 실제로 있는 사실에서 가져오고 새로 지어내지는 않는다 — 과장은 "말하는 방식", 지어내기는 "없는 사실". 이 선만 grounding_audit 가 본다.
- ★사장님 (10-16 밤): **흥미 이야기 칸은 필수.** 개발 비화·유래·"~라고 알려져 있다" 류 소문도 그대로 쓴다(확인 안 해도 됨). 예: 나이키 핸즈프리 = 손을 못 쓰는 학생이 나이키에 보낸 편지로 개발 시작. 흥미 단어·내용이 대본마다 **무조건** 들어가야 하고, 엔진 check 는 흥미 이야기 줄 0개면 반려. 후보 고를 때 "약하다"로 거르지 말고 상품마다 흥미 이야기를 찾아 붙인다.
- ★고조 개수(10-16 밤 실측): 원본 샤프심 4·고양이 5·칫솔 5. 고조 = ①센 시작 ②숫자·권위 ③"진짜 핵심" 반전 ④"심지어" 두 번째 반전 ⑤"~까지 난리". check: 고조 4개 미만이면 반려(①③⑤ 필수, ②④ 중 하나 이상). 손 초안 1판이 3개라 밋밋했던 것이 실례.
