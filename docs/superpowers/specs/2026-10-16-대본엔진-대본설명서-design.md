# 대본 엔진 — "대본 설명서(script_frame)" 설계 (2026-10-16, 사장님: "대본을 어떻게 분석할지 제일 중요. 분석만이 아니라 우리도 쓸 수 있게 대본 엔진에 넣어야 하고, 상품 하나 찾으면 장면과 맞는 대본이 나와야 한다")

## 원칙
- 틀(외관)과 같은 네 고리: **뜯기 → 설명서(script_frame.json) → 생성(엔진) → 검사**. 설명서는 숫자·목록이라 검사로 잴 수 있어야 한다.
- 판단 주인: 설명서 만들기 `script_frame.py:build`, 생성 `script_engine.py:draft(product, frame)`, 검사 `script_engine.py:check(script, frame)`. 세 함수 밖에 같은 판단을 두 번 적지 않는다.
- 빈칸 끼우기 금지(메모리 `feedback_빈칸끼우기_금지`): 공식은 "칸 순서+통계+예문"이고 문장은 모델이 통째로 쓴다. 어미는 원문에서 떼어온 목록만(메모리 `reference_어미는_원문에서_떼어와라`).

## 설명서 5칸 (채널마다 `channel/<채널>/대본설명서/script_frame.json`)
| 칸 | 내용 | 어떻게 뽑나(50편 asr) | 검사로 재는 것 |
|---|---|---|---|
| 1 스토리라인 골격 | 공식 3~5개: 역할 칸 순서·빈도·칸별 길이 비율·칸당 문장 수 | 문장마다 역할 라벨(제미나이 + 규칙) → 순서열 군집 | 생성 대본의 칸 순서가 공식 중 하나와 일치, 길이 비율 ±20% |
| 2 훅 패턴 | 첫 문장 유형(질문·고백·숫자·반전·명령)과 예문 10개, 유형별 빈도 | 1번 라벨의 첫 문장 분류 | 훅 유형이 상위 3개 중 하나, 예문과 7자 이상 겹침 금지 |
| 3 소구점 사전 | 사게 만드는 축(가성비·공간·부모님·시간·안전…) 빈도 + 근거 대는 방식(숫자·전후·실패담) | 소구 역할 문장 분류 | 소구 문장 ≥1, 근거 방식이 사전 안, 근거.md에 출처 |
| 4 화법 규칙 | 실제 어미 목록·비율, 문장 길이 분포, 1/2인칭, 반문·감탄 비율, 금지어 | 통계 | 어미는 목록 안, 길이·비율 범위 안 |
| 5 줄↔장면 계약 | 역할 칸 → 필요한 장면 종류(제품 전체·사용 동작·비포/애프터·얼굴·가격·짤)·길이 | asr 구간 ↔ bench 컷 종류 매칭 | 생성 대본 줄마다 `shot_kind` 있음, 재료 매핑 표에 그 종류가 채워짐(검수 A3) |

## 생성 흐름 (`draft`)
상품 1개(이름·링크·facts) → 사실 수집(기사 `find_articles`·댓글·상품 페이지) → 소재 유형에 맞는 공식 선택 → 칸별 문장 생성(어미·길이·소구점 근거 필수, 줄마다 `shot_kind`) → `check`(기존 5종 + 1~5칸 검사) → 장면 계획(`shot_kind` → 재료 검색어·후보) → 선검수 시트.

## 검증(정답 시험)
- LOO: 원본 50편 중 10편을 숨기고 같은 상품 사실만 줘서 엔진 대본과 원본을 대조 — 역할 순서 일치율·화법 통계 범위·소구점 종류 일치. 기준: 순서 일치 ≥70%, 화법 범위 안 ≥80%.
- 다양성: 같은 상품 10회 생성 → 첫 문장·칸 순서가 10개 중 ≥7개 다름(메모리 "회원 100명 돌려쓰면 같음" 사고).
- 빨강 시험: 설명서를 다른 채널 것으로 바꿔 끼우면 check 가 반려해야 한다.
