# 경계NBSP — 자막 경계 나누기 클릭이 안 먹던 고객 오류

**2026-09-13 / CH / 완료·배포·실측 끝**

## 고객 제보

제작소 3단계(영상대본MIX) 칸 타임라인에서 [✂ 경계]로 어절 사이를 눌러도
**1챕터(hook)만** 아무 일이 없었다. **2챕터는 정상.** "지워지지도 변경도 되지 않는다".

- 고객 work `7bf7d05fafbe` → mix job `e020944ae71f` (customer_id 357)

## 원인 — 대사에 섞인 NBSP(`\xa0`)

```
beat 0: '여러분 대파 썰어서 절대 냉동실에\xa0 그냥 넣지 마세요.'  ← NBSP(실패)
beat 1: '대파가 한 덩어리로 얼어붙어 매번 속상했거든요.'          ← 없음(정상)
```

화면(`scene_timeline.js` `tlGapClick`)은 어절을 `\s+`로 쪼갠다 — 이 정규식은 **NBSP도 공백으로
보고 지운다** → 다시 이어붙인 lines엔 NBSP가 없다. 그런데 대조 키 `cap_preset_key`는
**ASCII 공백 4종만** 떼서 narration 쪽에만 NBSP가 남았다 → 키가 영영 달라
`POST /caplines`가 **422**로 거절 → 눌러도 아무 일이 없다.

**"챕터마다 다르다" = 코드가 아니라 데이터 차이.** 같은 코드가 한 칸만 실패하면
그 칸의 대사를 바이트로 꺼내 봐라(눈으로는 똑같아 보인다).

## 고친 것 (둘 다 main 병합·배포 완료)

### 1. `19ac4d8b7` — 원인
`video_assemble.cap_preset_key`가 `str.isspace()`로 **유니코드 공백 전부**를 뗀다
(NBSP·전각공백 U+3000 등). 저장(`app.py _caplines_locked`)·렌더(`_caption_segments`)·
대본(`script_generate`)이 이 함수 하나를 쓰므로(0순위-B) 한 곳 수정으로 세 경로가 풀린다.
글자를 실제로 지우거나 고치면 **여전히 막는다**(보호장치 유지).

### 2. `9217bb12c` — 실패가 화면에 안 보이던 것
`scene_timeline.js`가 `nsay` 8곳·`saylo` 0곳이었다. `nsay`가 쓰는 `#tbhint`는
제작소 iframe 안에서 **0x0**이라 글자가 물리적으로 안 보인다(2026-09-07 실측, 그래서
saylo/toastlo가 생겼는데 타임라인은 안 따라갔다). 서버는 422로 이유를 정확히 말하고
있었는데 화면이 삼켰다 → 원인이 무엇이든 증상이 늘 "그냥 안 눌림"이었다.
→ `_tlSay`/`_tlFail` 한 곳으로 모으고(0순위-B), 실패는 `saylo`(푸터+토스트)로,
서버가 준 사유를 그대로 노출. `saylo` 없는 화면이면 `nsay`로 폴백.

경계는 본질적으로 "N번째 어절 뒤" = 숫자인데 글자를 왕복시켜서, 대사를 건드리지도
않았는데 왕복 중 뭐 하나 달라지면 거절된다. 다음 후보: 제로폭 문자(`​`),
유니코드 정규화 차이(맥 붙여넣기 NFD), 결합 문자.

**제안(미착수)**: 화면이 경계 인덱스만 보내고(`{beat_idx, boundaries:[3]}`) 서버가
자기 원본을 그 위치에서 자른다 → 글자 왕복이 없으니 대조할 일 자체가 없어진다.
`tlGapClick`은 이미 `bset`(경계 인덱스 집합)을 들고 있어 그대로 보내면 된다.
제작소 자막칸(②)은 입력칸이라 글자 검증이 실제로 필요하므로 **지금 방식 유지**.
