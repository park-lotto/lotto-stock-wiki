# 자막제거 — 소스 단위 청소 + 2단계 미리보기 썸네일

**날짜**: 2026-07-19
**트랙**: 자막제거미리보기
**대상**: shopping_shorts 영상제작소 2단계(자막제거)

---

## 문제

영상제작 위저드 2단계(자막제거)는 지금 **토글 하나뿐**이다 — `subtitle_removal` bool만 세팅하고
실제 자막제거(VMake)는 **최종렌더에서만** 일어난다([mix_pipeline.py `run_render`](../../../mix_pipeline.py) L332).
사용자는 이 단계에서 **자막제거가 실제로 됐는지 눈으로 확인**(미리보기 썸네일)하고 넘어가고 싶다.

## 왜 지금 구조로는 "2단계 미리보기"가 안 되나

- `_render_mix`는 **비트 길이를 TTS 길이로 결정**하고(`tts_dur = _probe_duration(tts)`,
  [video_assemble.py](../../../video_assemble.py) L389), **TTS 없는 비트는 통째로 건너뛴다**(L387).
- TTS는 **3단계**(2단계 이후)에 정해진다 → 2단계엔 "믹스 전체"가 **존재하지 않는다**.
- 따라서 현재의 mix_raw 단위 VMake(믹스된 영상 위에 청소)는 2단계에서 불가능하고,
  TTS가 바뀌면 타임라인이 통째로 바뀌어 캐시도 성립하지 않는다.

## 통찰

자막제거는 **소스 영상의 픽셀 속성**이다 — TTS·컷·꾸미기와 무관하다.
그러므로 **소스 원본 단위로** 청소하면:

- 2단계(매칭 후 소스가 이미 다운로드돼 있음)에서 실행 가능하다.
- 캐시가 견고하다 — 컷/TTS/꾸미기를 어떻게 바꿔도 클린 소스는 그대로 재사용된다.
- 최종렌더가 클린 소스에서 조립하므로 **VMake 재호출·이중과금이 없다**.

---

## 결정 사항 (사용자 확정)

| 항목 | 결정 |
|---|---|
| 청소 단위 | **소스 원본 단위** (mix_raw 아님) |
| 캐시 | `clean_sources` 맵, job당 1회 과금, 최종렌더 재사용 |
| 썸네일 | **원본 ↔ 클린 나란히 비교** |
| 트리거 | **"자막제거 미리보기" 버튼 클릭** (유료라 실수 방지) |

## 아키텍처

### 1. 데이터 모델 (store, mix job 필드)

- `clean_sources`: `{video_id: 클린mp4_절대경로}` — VMake 출력 캐시(소스당 1개)
- `clean_status`: `idle | cleaning | ready | failed` — 기존 `status`/`preview_status`와 **분리**
  (코드 관례: status 필드 혼용 시 최종렌더 폴링과 서로 오인, spec §6.1)
- `clean_error`: 실패 메시지(문자열)
- 기존 `clean_video_path`(mix_raw 단위 유물)는 **폐기** — 미사용으로 남긴다.
  (5단계 썸네일 라우트 L1787의 `(video_path, clean_video_path, preview_path)` 순회는
  `clean_video_path`가 None이어도 `video_path`/`preview_path`로 동작하므로 무해)

### 2. 백엔드 — mix_pipeline.py

**`run_clean_sources(job_id, db_path, work_root)`** (신규)

```
store = Store(db_path); job = store.get_mix_job(job_id)
work = work_root / job_id
key = _vmake_key(store)
if not key: clean_status=failed, clean_error="VMake 개인키 미등록"; return
source_map = _resolve_sources(job, work)          # {video_id: 원본경로}
cached = job.get("clean_sources") or {}
todo = [(vid, src) for vid, src in source_map
        if not (vid in cached and Path(cached[vid]).exists())]   # 캐시 스킵
results = clean_in_parallel(todo, key, work)   # {vid: 클린경로}, ThreadPool
cached.update(results)
store.update_mix_job(job_id, clean_sources=cached, clean_status="ready")  # 1회 저장
```

- 소스가 여러 개면 `ThreadPoolExecutor(max_workers=len)`로 병렬(각 VMake는 비동기 ~최대 1h).
  각 스레드는 `remove_subtitles`만 하고 경로를 반환 → **DB 저장은 취합 후 메인에서 1회**
  (스레드에서 `update_mix_job`을 호출하지 않아 경합 없음).
- **BackgroundTasks-safe**: 최상위 `try/except`로 예외를 밖으로 안 던지고 `clean_status=failed`로 기록
  (`run_preview`와 동일 관례, [mix_pipeline.py](../../../mix_pipeline.py) L310).
- **캐시**: 이미 `clean_sources[vid]`가 있고 파일 존재하면 스킵 → 재과금 없음.

### 3. 백엔드 — app.py 라우트

- **`POST /api/produce/mix/clean`** `{job_id}`
  - job 없음/edit_plan 없음/MIX 미매칭 → 4xx
  - `clean_status=="cleaning"` 이고 non-stale → 중복예약 거절(preview 라우트 L1459 가드 패턴)
  - `clean_status="cleaning"`을 **동기 기록**(응답 전) 후 `background_tasks.add_task(run_clean_sources, ...)`
    (preview 라우트 L1465 패턴 — 응답 뒤 rendering을 쓰면 이중예약)
- **`GET /api/produce/mix/clean/{job_id}`** → `{clean_status, clean_error}`
- **`GET /api/produce/mix/clean_thumb/{job_id}?kind=original|clean`**
  - 대표 소스(첫 video_id)의 **중간지점 프레임**(t = duration/2)을 PNG로 추출·서빙
  - `kind=original` → 원본 소스 프레임 / `kind=clean` → `clean_sources[vid]` 프레임(**같은 t**로 정렬)
  - `clean` 요청인데 `clean_status != ready` 또는 클린파일 없음 → 404
  - 추출 프레임은 work 디렉터리에 캐시(재요청 시 재사용)

### 4. 최종렌더 변경 — `run_render`

- mix_raw 단위 `clean_fn` **제거**([mix_pipeline.py](../../../mix_pipeline.py) L331–341).
- `subtitle_removal` ON이면:
  - `clean_status != ready`면 **렌더 직전 인라인으로 `run_clean_sources` 호출**(버튼 안 눌러도 무손실).
    청소 실패 시 렌더 실패로 정상 종료.
  - `source_video_paths`를 `clean_sources` 경로로 **치환**해 `assemble`에 넘긴다(clean_fn=None).
- `subtitle_removal` OFF이면 기존대로 원본 소스.
- `run_preview`(1단계 무료 미리보기)는 **원본 소스 유지 — 변경 없음**(2단계 이전 단계라 청소 대상 아님).

### 5. 프런트 — produce.html 2단계

- 토글 아래 **"자막제거 미리보기" 버튼** 추가. 활성 조건: `subToggle` ON + `MIX_JOB` 존재.
- 클릭 → `POST /clean` → `GET /clean/{job}` 폴링(preview 폴링 패턴 재사용).
- 상태 표시:
  - idle: 안내만
  - ⏳ cleaning: "자막 제거 중… VMake AI (최대 ~1시간)"
  - ✅ ready: **원본 | 클린 나란히** `<img>` 2장(clean_thumb 라우트, `?t=` 캐시버스터)
  - ❌ failed: `clean_error` 표시(키 미등록이면 등록 안내)
- 토글 저장(`onSubToggle` → `/api/produce/mix/settings`)은 **그대로 유지**.

## 데이터 흐름

```
[2단계] 토글 ON → (설정 저장)
        "미리보기" 클릭
          → POST /clean → clean_status=cleaning
          → run_clean_sources: 각 소스 remove_subtitles → clean_sources 캐시 → ready
          → GET /clean_thumb?kind=original|clean → 원본|클린 프레임
        사용자 확인 후 다음 단계

[최종렌더] subtitle_removal ON
          → clean_status ready면 clean_sources 사용 (재과금 0)
          → 아직이면 인라인 run_clean_sources 후 사용
          → assemble(clean 소스, clean_fn=None) → 최종 mp4
```

## 비용·일관성

- 과금: **소스 영상 1개당 VMake 1회**(보통 job당 1개). 캐시라 최종렌더 재과금 0.
- 소스 **전체**를 청소한다(사용 컷만 아님) → 견고한 캐시. 소스가 길면 비용↑(트레이드오프 수용).
- 캐시 키 = `video_id`(= 소스 URL 순번). job 내 URL 고정이므로 캐시는 항상 유효.

## 에러 처리

- VMake 키 미등록 → `clean_status=failed`, 프런트에서 등록 안내.
- VMake 실패/타임아웃 → `remove_subtitles`가 raise → `run_clean_sources`가 잡아 `failed`.
- 최종렌더에서 인라인 청소 실패 → 렌더 실패(`status=failed`)로 정상 종료.
- 폴링은 preview와 동일하게 TTL/하트비트 없음(기존 한계 계승) — stale 판정은 preview 가드 재사용.

## 테스트

- `run_clean_sources`: `remove_subtitles` mock → `clean_sources` 저장·`ready` / 에러→`failed` /
  캐시 존재 시 스킵(mock 호출 0회) / 키 없음→`failed`.
- `run_render`: 클린 ready면 클린 소스로 assemble 호출 / 토글 ON+미ready면 인라인 청소 후 클린 소스 /
  토글 OFF면 원본 소스. `assemble`에 넘어간 source 경로를 assert.
- 라우트: `/clean` 예약·중복예약 가드·폴링 응답·`clean_thumb` 서빙(ready 전 404, original은 항상 가능).
- 기존 `tests/test_app_vmake.py`·`tests/test_mix_render_flow.py` 패턴을 따른다.

## 범위 밖 (YAGNI)

- 썸네일 타임스탬프 사용자 선택(중간지점 고정으로 충분).
- 컷 구간만 부분 청소(전체 소스 청소로 캐시 단순화).
- 클립 재생 미리보기(정적 비교 프레임으로 충분).
- clean_sources 세분 상태(소스별 진행률) — job 레벨 status로 충분.
