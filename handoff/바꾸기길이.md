# 바꾸기길이 — [바꾸기] 길이 폭주 + 502 거짓 문구

## 2026-08-22 (회사PC) — 라이브 반영

사장님 제보 2건이 **서로 다른 문제**였다.

### ① [바꾸기]가 문장을 2배로 늘림 → 수정

실사고: '방법' 칸 50자(4.6초) → 74자(9.0초). 아래 칸과 내용이 겹쳐 퀄리티가 무너졌다.

**길이 게이트는 원래 있었다.** 문제는 상한 `max(per*1.8, per+40)`이
**거의 언제나 `+40`이 이겨서** 사실상 없는 것과 같았던 것:

| 원문 | 옛 상한 | 실질 배수 | 새 상한 | 새 배수 |
|---|---|---|---|---|
| 10자 | 50자 | **5.0배** | 22자 | 2.2배 |
| 25자 | 65자 | **2.6배** | 34자 | 1.5배 |
| 37자 | 77자 | **2.1배** | 50자 | 1.4배 |
| 50자 | 90자 | 1.8배 | 68자 | 1.4배 |

→ **짧은 칸을 봐주려 넣은 `+40`이 정반대로 짧은 칸을 가장 헐렁하게** 만들었다.
   `1.8`은 50자 이상에서만 발동해 실제로는 거의 쓰이지도 않았다.

수정 (`script_generate.py`)
- `_BEAT_LEN_MAX` 1.8 → **1.35**, `+40자` → **`_BEAT_LEN_SLACK`=12자**
- 같은 식이 재시도 루프·최종 방어 **두 군데**에 따로 있던 것을
  **`_beat_len_cap()` 함수 하나로** 뽑음 (0순위-B)
- 프롬프트가 **상한을 숫자로** 말한다 — 종전엔 "N자 안팎"만 줘서 모델이
  어디까지가 통과인지 몰랐고 재시도 3회를 다 태워 502가 났다

### ② "생성 실패(키 소진 또는 응답 오류)"가 거짓말 → 수정

실측: 서버 로그에 429·quota **한 건도 없는데** 이 문구가 떴다.
키는 처음부터 멀쩡했으므로 "잠시 후 재시도"를 아무리 눌러도 영원히 안 풀린다.

원인 — `_call_json`이 ①키 없음 ②전부 소진 ③응답 오류를 **전부 `{}`로** 돌려줘
호출부가 원인을 구분할 방법 자체가 없었다. `generate_by_styles`도 예외를 `print`로만 흘렸다.

수정 — 사유를 실어 올린다(`note`/`reasons`, **안 주면 종전과 동일 = 회귀 0**).
`_gen_fail_message()`(app.py)가 6가지로 갈라 말한다:
키 0개 / 전부 소진 / 분당 한도 / **응답 오류(키 문제 아님)** / 게이트 반려 / 시도 자체 없음

## ⚠️ 이번에 밟은 함정 (다음 세션이 또 밟는다)

**`finish`가 45분간 "아무 말 없이" 병합을 안 했다.** 원인은 게이트 결함도, 테스트 실패도,
락 대기도 아니었다:

```
중단: 트랙 폴더가 dirty — 커밋 먼저 해라.
 M finish_out.txt
```

`finish_out.txt`(다른 세션 산출물)를 "내 것이 아니니 커밋에서 빼자"고 **일부러 남겨둔 것**이
막고 있었다. 게이트는 **파일 하나라도 dirty면 아예 시작조차 안 한다**.
`git diff -w`가 비어 있었다 = **내용은 한 글자도 안 다르고 개행(CRLF/LF)만 달랐다**
— 내 finish 실행이 그 파일을 다시 쓰면서 생긴 차이였다. 정규화만 커밋해서 풀었다.

교훈:
- **`finish`가 조용하면 로그부터 끝까지 읽어라.** "죽었다"고 단정하기 전에 `중단:` 줄을 찾아라
  (나는 "조용히 죽었다"고 두 번 오진했다 — 실제로는 한 번은 정상 대기, 한 번은 dirty 차단).
- `git checkout --`/`update-index --refresh`로는 CRLF 차이가 안 없어진다. **정규화를 커밋**해야 한다.
- 트랙 폴더는 **내 것이 아닌 파일도 깨끗해야** 한다 — 빼두면 게이트가 통째로 멈춘다.
