숏템MCP 라이브 실측

고객 PC의 Claude가 숏템 서버에 붙어 영상 한 편을 처음부터 끝까지 만드는 것을 라이브 서버에서 확인했습니다. 지금은 관리자 계정만 쓸 수 있습니다.

라이브 1편 완성 결함 2개 수리·병합 고객 공개 전 (관리자만) 설치 파일 서버 미업로드

라이브에서 찾아 고친 결함

1. /claude 페이지에 프리셋이 0개로 나왔습니다

원인 프리셋 틀 파일이 숏템프리셋 엔진 작업 폴더에만 있고 라이브(main)에는 없었습니다. 이 PC 시험은 그 폴더를 직접 읽어서 문제가 가려졌습니다.

조치 틀 148개를 엔진과 같은 내용으로 라이브에 넣었고, 새벽 2시 반영 도구가 앞으로 틀 폴더도 함께 옮기도록 고쳤습니다. 지금 페이지에 13개가 뜹니다.

2. 짤 견본을 굽다가 전체가 멈췄습니다

원인 0.5초보다 짧은 짤에서 그림이 안 만들어졌습니다.

조치 짧으면 첫 장면으로 다시 뜨게 고쳤습니다. 0.3초 시험 클립으로 고치기 전에는 멈추고 고친 뒤에는 정상인 것을 대조했습니다.

두 수리는 관문을 통과해 병합했습니다(main dc0e5f770).

사용하는 법

스위치가 '관리자만'이라 사장님 계정으로 로그인하면 바로 보입니다.

  1. 숏템메이커에서 /claude 열기

    shoppingshorts.duckdns.org/claude — 프리셋 카드 13장, 스타일 4종(현장썰·대사썰·나레썰·자막썰), 팩 견본이 나옵니다.

  2. 프리셋 고르고 내 채널명 넣고 '저장'

    이게 '내 채널(프로필)'이 됩니다. 영상의 머리띠·작성자 줄에 이 채널명이 찍힙니다.

  3. '키 발급' 누르기

    라이선스 키가 나옵니다(1년, 기기 2대까지). 키는 채팅창이 아니라 설치 뒤 설정 칸에 붙여 넣습니다.

  4. 설치 파일 설치

    윈도용 shortem-setup-win-x64-1.0.0.exe(203MB). 아직 서버에 안 올려서 페이지에는 '준비 중'으로 나옵니다. 써 보시려면 말씀해 주세요. 서명이 없어 윈도가 경고를 띄우면 '추가 정보 ▸ 실행'을 누릅니다.

  5. Claude에게 만들어 달라고 하기

    아래 고객 탭의 순서와 같습니다.

  1. 설치 파일 실행

    관리자 권한 없이 깔립니다. 끝나면 바탕화면 숏템작업 폴더에 시작.md와 그림 안내(11장)가 생깁니다.

  2. Claude Code에 플러그인 등록

    시작.md에 적힌 두 줄을 입력합니다.

    claude plugin marketplace add "<설치 폴더의 플러그인>"claude plugin install shortem@shortem

  3. Claude Code를 껐다 켜고 키 넣기

    /plugin configure shortem@shortem에 라이선스 키를 붙여 넣습니다.

  4. 준비 점검 /shortem:setup

    라이선스·기기 등록·실행 도구·디스크를 확인하고 시험 렌더·시험 목소리·시험 다운로드를 돌려 항목마다 '됨/안 됨'을 알려 줍니다. 끝에 내 채널 이름이 나옵니다.

  5. 한 편 만들기 /shortem:make

    › /shortem:make 썰풀다 https://youtube.com/shorts/…9단계 중 1번째 — 준비 …

    Claude가 사람이 정할 세 곳에서만 멈춰 묻습니다: ① 소재 고르기 ② 대본 확인 ③ 완성본 확인. 완성본은 숏템작업 폴더에 저장됩니다.

  1. 설치 파일 실행

    마지막 화면의 체크박스(기본 켜짐)로 Claude Desktop 연결 파일 shortem.mcpb가 자동으로 열립니다.

  2. Claude Desktop에서 '설치'를 누르고 라이선스 키 칸에 붙여 넣기

    키는 숨김 칸에 저장되고 다시 보이지 않습니다.

  3. 채팅으로 요청

    › 숏템 준비 점검해 줘› 썰풀다 채널로 이 영상 만들어 줘 https://youtube.com/shorts/…

    흐름은 Claude Code와 같습니다(소재 → 대본 → 완성본 확인).

미확인 Claude Desktop의 실제 설치 화면에서 .mcpb를 깔아 보는 시험은 아직 안 했습니다. 연결 자체는 같은 서버를 쓰는 Claude Code 쪽으로 확인했습니다.

알려 드릴 것

  • 라이선스 키는 서버 발급 도구 대신 페이지의 '키 발급' 버튼으로 받았습니다. 도구가 서버 비밀값 파일을 읽어야 하는데 권한에서 막혔습니다. 고객도 같은 버튼을 쓰니 확인 경로로는 맞습니다.
  • 작업 중 제가 명령을 잘못 묶어 엔진 쪽 파일이 제 작업 폴더로 딸려 왔습니다. 커밋 전에 지웠고 원본은 엔진 커밋에 그대로 있어 잃은 파일은 없습니다.
  • PC 메모리가 부족해 로컬 시험 서버가 자동으로 꺼졌습니다. 라이브 시험엔 필요 없어 다시 켜지 않았습니다.
