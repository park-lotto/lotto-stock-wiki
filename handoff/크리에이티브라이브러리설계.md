# 크리에이티브 라이브러리 설계 핸드오프

## 설계 단계에서 한 일

- 장면꾸미기 UI 구현을 멈추고 회사 전 제작공정 라이브러리 기반을 조사했다.
- 저장소의 효과 채굴, 장면/SFX, 모션, 자막, 폰트, 음성, 대본, 브랜드, 성과 구조와 과거 사고 기록을 확인했다.
- 아스트라가 아키텍처와 기존 시스템 연결안을, 페이블이 품질·운영 실패 방지안을 별도로 검토하도록 구성했다.
- DAM, design token, timeline interchange, provenance, licensing, loudness, YouTube 성과 지표의 공식 자료를 조사했다.
- 설계서와 단계별 구현 계획을 작성했다.

## 핵심 결정

- 라이브러리는 Asset/Recipe/Pack/Evidence 네 객체로 구분한다.
- 연구 후보와 고객 배포 승인 상태를 분리한다.
- 새 도메인별 DB를 복제하지 않고 공통 core + legacy adapter로 시작한다.
- UI와 실제 렌더가 같은 `ResolvedCreativePlan`을 소비한다.
- 수동 수정값은 `base_version + overrides + locks`로 보호한다.
- 수집보다 권리·품질 게이트와 대표 완성 팩 1개를 먼저 만든다.

## 2026-09-11 아스트라 구현 진행

사용자가 현재 구현을 확인한 뒤 아스트라가 진행하도록 승인했다. 착수 시 main `16bc986f8`에는 설계 문서만 있었고 `creative_library/` 코드는 없었다.

- `creative_library/`: 공통 계약·파일 해시 버전·6종 legacy 읽기 어댑터·카탈로그·CLI를 아스트라가 구현했다.
- `tools/audit_creative_sources.py`: 실제 파일·글리프·미디어 메타데이터·DB 행 수의 읽기 전용 실사 도구를 구현했다.
- 실측: 등록 폰트40/물리41(OkMallangW.ttf 미등록), 모션 파일4, 보이스 샘플65. 모든 등록 파일 기술 파싱 성공.
- 카탈로그 실제 실행: 폰트40/레이아웃29/모션6/음성66, 공용141. 관리자143, DB 미지정140. tuned 테스트음성2개는 일반 목록에서 숨긴다. 루트 DB와 파일 원장은 변경하지 않았다.
- 원래 ID lookup·한글 검색·반복 실행 fingerprint 일치 확인.
- 독립 검토에서 owner0/library 보이스의 고객 간 노출 위험을 발견해 tenant0로 수정했다.
- 팩 하위 의존성 미승인·누락·버전 불일치·순환을 사용불가 판정에 전파한다.
- 모든 legacy 항목은 신규 권리/렌더/품질 승인 근거가 없어 usable=false를 유지한다.
- 미해결 constraints가 남으면 승인 메타만 바뀌어도 사용불가를 유지한다.
- 최종 코어25개+실사3개 검사, 합계28개 통과. 실제 CLI 한글 검색·legacy lookup·DB 무변경·fingerprint 재현 확인.

소스 실사: `docs/research/creative-library/source-of-truth.md`, 실측 JSON `2026-09-11-source-audit-v2.json`.
실행법·권한 경계: `creative_library/README.md`.

이 구현은 첫 읽기 전용 코어이며 Phase 0/1 전체 또는 회사 전체 라이브러리 완성이 아니다. 실제 렌더·UI·승인 writer·영속 저장소는 아직 연결되지 않았다.
