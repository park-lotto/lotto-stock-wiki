# 슬롯 3벌 — 후보 차별화 (v4) 설계

날짜: 2026-08-02 · 트랙: 대본퀄v3 · 롤백 기준점: 태그 `v3-final`

## 문제

후보 3개가 사실상 같은 영상이다. 실측(짐벌 job `8712570702b8`, 소스 2개):

```
후보0:  s1-1 → s1-5 → s1-9 → s0-9
후보1:  s1-1 → s1-5 → s1-9 → s0-10     ← 앞 3칸이 완전히 동일
후보2:  s1-1 → s1-6 → s1-9 → s0-10
```

대사도 훅만 다르고 중간·끝이 같다("흔들어도 각도 유지" → "짐벌 일체형이라 편함" → 댓글).

### 원인 (확정)

**이야기 뼈대가 하나뿐이다.**

```
1단계 태깅  → 세트 7개
2단계 슬롯  → Gemini가 "말 되는 이야기" 1개를 짜고 4개 선택   ← 여기서 이야기 확정
3단계 대본  → 그 하나의 이야기 위에 대사만 3벌
```

게다가 대본은 원본 대사를 따라가는 것이 설계 원칙이다(`_rewrite_block`: "대사를 새로
지어내지 마라 — 원본이 하던 말을 우리 말로 바꿔 쓴다"). 그래서 **뼈대가 같으면 결과도
같을 수밖에 없다.** 훅만 창작이라 훅만 다르다.

**그리고 재료가 버려진다**: 세트 7개 중 4개만 쓰고 3개를 버리는데, 버려진 쪽(s0)에
완전히 다른 이야기가 통째로 들어 있다 — "인플루언서 형이랑 박람회 갔더니 사람들이 줄을
길게 서 있더라 → 촬영 전문가용 초신상 → 헐리우드 카메라라 화질이 미쳤다".

## 방향 — 슬롯을 3벌 뽑되, **1벌은 지금 그대로 둔다**

사장님 지시: "3개 중 1개는 그대로 둔다. 한번 해보고 아닌 것 같으면 v3로 유지."

### 채택하지 않은 방법 1 — Gemini에게 3벌을 요구

`_set_seq_prompt`에 "서로 다른 이야기 3개를 짜라"를 넣는 방식.

- 장점: 3벌 다 "말 되는 이야기"임이 모델 수준에서 보장된다.
- **기각 사유**: **프롬프트가 바뀌면 벌A도 달라진다.** "1개는 그대로"라는 약속을 지킬 수
  없다. 이 트랙은 프롬프트를 만질 때마다 새 문제가 났다(메모리: "만질수록 이상해짐 =
  제약 과적재"). 응답이 3배로 길어져 형식 실패 → 폴백 위험도 는다.

### 채택 — 방법 2: Gemini는 그대로 1벌, B·C는 코드가 조합

```
_pick_slot_variants(seg_map, target_seconds, n, call)
    ├ 벌A = _pick_slot_groups()를 그대로 호출         ← 프롬프트·호출 무변경
    ├ 벌B = 남는 세트 우선으로 재조합
    └ 벌C = A와 B의 중간
```

**벌A는 코드 경로가 v3와 완전히 동일하다.** 같은 프롬프트, 같은 응답 처리, 같은 필터.
따라서 벌A의 결과는 v3와 같아야 하고, 그것을 테스트로 못박는다(검증 1).

## B·C 조합 규칙

Gemini가 고른 것을 `A`, 안 고른 나머지를 `R`(여유)이라 하자.

```
예: 세트 [1..7], A = [1,3,4,5], R = [2,6,7]

벌B: R을 우선 쓰고 모자라면 A에서 채운다   → [2,3,6,7] 류
벌C: A와 R을 절반씩 섞는다                → [1,4,6,7] 류
```

### 반드시 지키는 불변식 (B·C도 A와 같은 규칙을 받는다)

1. **세트 안 순서 불변** — 세트는 통째로 쓰거나 안 쓴다. 쪼개지 않는다.
2. **세트끼리도 원본 시간순** — 조합 후 `(video_id, 세트 시작시각)` 기준으로 정렬한다.
   이야기가 거꾸로 흐르지 않게 한다.
3. **`_filter_misplaced_sets` 통과** — 완성 컷은 뒤로, 문제 컷은 앞으로(A와 같은 검증).
4. **소스 커버리지** — 담은 영상마다 최소 한 세트. `_set_seq_prompt`가 A에 요구하는 것과
   같은 규칙을 코드로 적용한다.
5. **길이 예산** — `_cap_sets`와 같은 기준으로 `target_seconds`에 맞춘다.

### 폴백 (나빠지지 않게)

- **여유가 없으면**(R이 비었거나 규칙을 만족하는 조합을 못 만들면) **A를 복제**한다.
  → 지금과 동일한 결과. v3보다 나빠지지 않는다.
- A 자체가 폴백 경로였다면(`slot_source != gemini`) 변형을 시도하지 않고 A만 쓴다.
  이미 품질이 의심스러운 상태에서 조합을 늘릴 이유가 없다.
- 각 벌이 어디서 왔는지 `slot_info`에 남긴다(`variant: "gemini" | "recombined" | "cloned"`)
  — 조용한 품질 저하를 막는다(이 트랙이 반복해서 배운 것).

## 배선

`build_scene_first_plan`에서:

```python
# 지금: 후보 루프 밖에서 1벌
tl_groups, slot_source, slot_info = _pick_slot_groups(...)

# v4: 3벌을 만들고 후보 i가 벌 i를 받는다
variants = _pick_slot_variants(seg_map, target_seconds, n_candidates, call=_call)
...
# 후보 루프 안: tl_groups = variants[i % len(variants)]
```

⚠️ **대본 생성이 후보 3개를 한 번에 만든다**(`_scene_first_candidates`, Gemini 1회).
그런데 `_rewrite_block(groups)`는 슬롯 1벌을 전제로 프롬프트를 만든다 — 3벌이면
"i번째 비트가 위 i번 세트다"라는 대응이 후보마다 달라진다.

→ **이 지점이 이번 작업의 핵심 난점이다.** 두 갈래가 있다:
   - (가) 대본 생성을 벌마다 1회씩(총 3회) 부른다 → **과금 3배**. 단순하고 확실하다.
   - (나) 한 번에 부르되 프롬프트에 3벌을 다 실어 "후보1은 세트목록1, 후보2는 세트목록2"로
     지시한다 → 과금 유지, 그러나 프롬프트가 복잡해지고 모델이 헷갈릴 위험.

   **구현 전에 실측으로 정한다**: (나)를 먼저 시도하되, 후보가 지정된 세트를 안 지키면
   (가)로 간다. 판정은 "후보 i의 seg_ids가 벌 i에 속하는가"로 기계적으로 할 수 있다.

## 검증 계획

1. **★벌A가 v3와 같은가** — 같은 fixture로 v3(`v3-final`)와 v4를 각각 실행해 벌A의
   화면 리스트를 대조한다. **다르면 설계 실패**다. Gemini 비결정성 때문에 완전 일치가
   어려우면, 같은 Gemini 응답을 주입(스텁)해 코드 경로만 비교한다.
2. **B·C가 불변식을 지키는가** — 순서 역전 0 · 소스 커버리지 · 길이 예산 · misplaced 0.
3. **여유 0개 job에서 3벌이 A와 같은가**(폴백 확인).
4. **차별화가 실제로 늘었는가** — 후보 간 화면 겹침률을 v3/v4 비교(짐벌 job은 3/4 겹침).
5. 전체 스위트 **17 failed 기준선 유지**(내 변경이 늘린 실패 0). ⚠️`finish` 게이트가
   numpy 미설치로 pytest를 건너뛰므로 `git stash` 대조로 직접 잰다.

## 기대치 (미리 낮춰둔다)

세트 여유 실측(최근 10 job, 평균 2.0개):

| 여유 | 건수 | 예상 결과 |
|---|---|---|
| 3개+ | 3 | 확실히 다른 3편 |
| 1~2개 | 6 | 2~3칸 겹치는 "조금 다른" 3편 |
| 0개 | 1 | 그대로(재료 없음) |

**"완전히 다른 3편"은 10건 중 3건 정도.** 나머지는 부분적으로만 갈린다.

## 위험과 롤백

- B·C가 A보다 어색할 수 있다 — Gemini가 A를 고른 건 그게 제일 말이 되기 때문이다.
  2등·3등 조합은 덜 자연스러운 게 당연하다. **점수·심사위원이 A를 추천하도록 두면**
  사장님 눈에는 여전히 좋은 것이 먼저 보인다.
- 소스가 1개면 효과 반감(같은 영상 안에서 순서만 바뀐다).
- **롤백**: `git checkout v3-final -- shopping_shorts/` → `finish` → 3분 뒤 라이브 복구.
