# 05 업그레이드 자 — `kal.py stage_upgrade` + `upgrade_table` (표준 §4-2·§3-3 B3)

## 목표
"벤치보다 낫다"를 **측정값**으로 보인다. 업그레이드 판(`base` 상속)의 `upgrades[]` 항목마다 벤치 vs 우리 측정 셋을 자동으로 내고(`업그레이드_측정.json`), 카탈로그(스타일.json strengths·options)에 `axis·engine·style_cell` 키를 채워 `kal.py --menu` 가 '미기입' 없이 뜨게 한다. 잇템로그는 1차 판에 섞인 우리 식 변경을 **업그레이드 판으로 갈라 적는다**(지침서 ① 위반 수리).

## 실측 배경(10-24)
- `engine/kal.py`: `menu(axis)`(113~) 가 스타일.json strengths·options 를 축별로 — `axis·engine·style_cell` 키가 없어 '미기입'(지침서 §2-6-1 실측) · `stage_upgrade(S)`(132~146) = 1차 판 초안 복사 + `upgrades:[]` 빈 틀 + 메뉴 → `_kal/<slug>_업그레이드판_초안.json`·`업그레이드_기록.md`. 추천·측정 없음.
- `styles/연예인레시피판.json` = 유일한 업그레이드 판(`base: 스타픽룸판`, `_diff` 7칸 — 측정값 없음, 사장님 "벤치랑 너무 똑같다" 뒤 겉모양만).
- 잇템로그 1차 판 `styles/잇템로그판.json` 에 이미 우리 식 변경이 섞여 있다: 결과 먼저 훅(커밋 d4e963a81) · 끝 3줄 = 전언 2줄 + 혼잣말(6c7d0121a) · 심리 CTA 규칙(f81989042) · 쿠팡 후기 소구 · 원본 2~3개 시간순 — 벤치(잇템로그 2편)엔 없는 것. 지침서 ①: "1차 기준에 쿠팡·하이브리드용 결을 섞지 않는다".
- 스타일.json strengths 8건(현장썰만), options 12개 — 키 what·evidence·strength·channel·source·date.
- 측정 함수는 04 가 만든 `quality_gate`·`kal_analyze.match_from_render`·`scene_fit.measure_render`·`bench_check.freezes` 를 **부른다**(새로 재지 않는다).

## 만질 파일(독점)
`tools/calcopy/engine/kal.py`(`stage_upgrade`·`menu` 만) · `tools/calcopy/engine/upgrade_table.py`(새 — 04 와 `kal_analyze.py` 충돌 피하려고 별 모듈; 04 커밋 뒤 kal_analyze 에 넣을지는 페이블 결정) · `channel/스타일.json`(strengths·options 항목에 `axis`·`engine`·`style_cell` 키 **추가만**, 값 변경 금지 — 공유 장부: 다시 읽고 내 키만) · `tools/calcopy/hybrid/styles/잇템로그판_v2.json`(새, `base: 잇템로그판`) · `tools/calcopy/hybrid/styles/잇템로그판.json`(1차로 되돌릴 칸만 — 아래) · `channel/ititemlog/_kal/업그레이드_기록.md`(새) · `shopping_shorts/tests/test_upgrade_table.py`(새)
## 안 만질 파일
`kal_analyze.py`(04) · `quality_gate.py`(04 — 부르기만) · `render_bench.py`·`placement.py` · 다른 판 파일.

## 설계
1. **카탈로그 키**: strengths/options 항목마다 `axis`(표준 §2-3 요소 15종 이름 중 하나) · `engine`(○/△/×, 지침서 §4 대응표) · `style_cell`(판 칸 경로 예 `placement.rules.sfx`·`script.brief`) — 20건(8+12) 전부 채운다. `kal.py --menu all` 출력에 '미기입' 0.
2. **`upgrade_table.measure(판, doc, work, base_doc=None) -> dict`**: `upgrades[]` 항목마다 `axis` 로 측정 함수를 고른다(표준 §4-2 표: 자막 가독성 = `kal_analyze.frame_metrics` 높이·ΔE / 장면↔대사 = scene_fit / 정지 = bench_check.freezes / 효과 밀도 = match fx.rate·sfx.rate 가 벤치 상위 편(조회 상위 50%, `C:/숏템_칼카피/<slug>/top.json` views) 범위 안 / 훅 = 첫 3초 등장·첫 컷·0초 얼굴·물건 비율 / 소리 = LUFS·BGM 대비·받아쓰기 일치 / 말속도·쉼 = 줄별 cps 편차·쉼 분포 / 못 재는 축 = `human`). 벤치 값 = 줄판독·뜯기(`bench_media_src`), 우리 = 완성본 — **같은 함수**. 출력 `<doc>/업그레이드_측정.json {items:[{axis,what,bench,ours,better:bool|human,why}], better_n, total}` + 카드 `gates.upgrade`.
3. **`stage_upgrade` 보강**: 초안에 `upgrades` 추천 후보를 카탈로그에서 넣는다 — 같은 결(스타일.json styles 소리축 같음) · 상위 편 근거 · `engine:○` 우선, 부딪치면 지침서 ⓐⓑⓒⓓ 순(ⓓ 는 `human`). 추천은 **후보**(사람이 고름) — 자동 반영 금지.
4. **잇템로그 갈라 적기**: `잇템로그판.json` 에서 벤치 2편에 근거가 없는 칸(script.brief 의 결과먼저훅·전언2줄+혼잣말·심리CTA·쿠팡후기, `_note` 의 '우리 식' 문장)을 `잇템로그판_v2.json`(base 잇템로그판, `upgrades:[{axis:script, what:…, why: 사장님 10-22 컨펌 03·07, source: 커밋, expect, verify}]`)로 옮기고 1차 판은 벤치 실측 꼴만 남긴다(audit 규칙은 벤치 줄판독 `대본언어.json` 어미 분포로 다시 적는다 — `~있는데요` 훅·`~네요` 끝은 실측이면 남김). 완성편 재렌더는 하지 않는다(판 파일만 갈라 적고 기록).

## 합격 검사(사보타주 먼저)
1. `--menu all` 에 '미기입' 0 (고치기 전 = 20건 미기입).
2. 사보타주: 픽스처 업그레이드 판(`upgrades` 2건: scene_fit·freezes) + 완성본 두 개(fit 평균 5.0/7.5·멈춤 1건/0건) → `better` 가 각각 false/true 로 갈린다. 축 이름이 15종 밖이면 거절.
3. 잇템로그: `styles.py list` 에 `잇템로그판_v2` 가 base 잇템로그판으로 뜨고, 1차 판 `script.audit` 규칙마다 `why` 에 벤치 줄판독 근거(편 id)가 있다 · v2 `upgrades` 항목 ≥4 각각 `axis·why·source` 채움 · ep13 에 `upgrade_table` 돌려 `better_n/total` 숫자(사람 판정 `human` 은 따로 센다).
4. 연예인레시피판에도 돌려 `_diff` 7칸이 `upgrades` 꼴로 들어가고 측정이 나온다(겉모양 칸은 `human` 이 정상 — 근거 기록 유무만 ○×).
