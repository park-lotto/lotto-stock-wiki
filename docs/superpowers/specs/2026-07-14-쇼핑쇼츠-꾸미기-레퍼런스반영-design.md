## 1. 배경·목적

인스타그램 빅채널 7개 게시물(ddock_sun, tem.doctor×2, salim_station, homterior_pick, housekeeping_office, ah_ha_temm)의 첫 프레임 자막 스타일을 크롬으로 직접 열어 분석했다. 7개 중 발견된 3가지 패턴:

1. **흰(1줄, 작게) + 노랑(1줄, 크게) 2톤 헤드라인** — 7개 중 4개(ddock_sun, housekeeping_office, tem.doctor 2건)에서 반복
2. **흰 텍스트 + 청록(cyan) 네온글로우 이중 아웃라인** — 2개(homterior_pick, ah_ha_temm)
3. **한 줄 안에서 특정 단어만 다른 색/배경배지** — 1개(salim_station: "나만 몰랐던 **쿠팡**(빨간배지)**꿀템**(노랑)")

1·2번은 지금 엔진 그대로 재현 가능(아래 3장 참고). 3번만 신규 기능(단어별 강조)이 필요.

## 2. 기존 구조 확인 (변경 없이 재사용되는 부분)

- `video_assemble.py`의 `_fixed_drawtext`(헤드카피·추가텍스트·워터마크 공용)와 `_caption_drawtexts`(자막)는 **블록 하나당 폰트·색 1개**만 지원. `fontcolor=`가 textfile 전체에 균일 적용됨.
- `produce.html`의 `STATE.deco.extra_texts`(추가텍스트, 슬라이스 C1)는 이미 **독립적인 폰트/색/크기/좌표**를 가진 텍스트를 여러 개 얹을 수 있다 — 즉 헤드카피(1줄) + 추가텍스트(1줄)를 조합하면 **엔진 변경 없이** "흰 작은줄 + 노랑 큰줄" 2톤 헤드라인을 만들 수 있다.
- `/api/produce/mix/settings`는 `deco` 필드를 통짜 dict로 그대로 저장한다(`store.py` deco_json) — 새 필드를 얹어도 **서버 스키마 변경이 필요 없다**.

이 확인 덕분에 처음 구상했던 `line_colors`(줄별 색 오버라이드) 데이터모델은 불필요해졌다 — 폐기.

## 3. 프리셋 확장 (엔진 변경 없음)

### 3-1. 흰+노랑 2톤 프리셋 2종
`FULL_PRESETS` 배열 항목에 `extra` 필드를 새로 허용(선택적):
```js
{name:'옐로 2톤 A', chip:'#FFE100',
  hc:{font:'...', color:'#FFFFFF', weight:900, size:40, x:50, y:8, outline:true, outline_color:'#000000', outline_w:6},
  extra:[{text:'', font:'...', color:'#FFE100', size:70, x:50, y:18, outline:true, outline_color:'#000000', outline_w:8}],
  cap:{...}}
```
- `applyFullPreset(i)`가 `hc`/`cap` 적용 후, `p.extra`가 있으면 `STATE.deco.extra_texts = p.extra`로 교체하고 `renderExtraPreview()` 호출.
- `extra[].text`는 빈 문자열로 두고 사용자가 미리보기에서 직접 입력(헤드카피 문구 입력과 동일 패턴) — 프리셋은 스타일만 지정, 문구는 사용자 몫.

### 3-2. 청록 네온글로우 프리셋 1~2종
순수 기존 필드값 추가: `hc.outline_color`/`cap.outline_color`를 청록(`#00E5FF` 또는 `#00D9E8`), `outline_w`를 8~9로. 신규 로직 없음.

## 4. 신규 기능 — 단어별 강조(highlight_rules)

### 4-1. 데이터 모델
```js
STATE.deco.highlight_rules = [
  { keyword: "쿠팡", color: "#FFFFFF", box: true,  box_color: "#FF2D2D" },
  { keyword: "꿀템", color: "#FFE100", box: false }
]
```
- **헤드카피와 자막(TTS 비트별 동적 텍스트) 양쪽에 공통 적용**되는 전역 규칙.
- 자막은 비트마다 문구가 바뀌므로 수동 태깅이 아니라 **키워드 매칭**(부분일치, 대소문자/공백 무시 안 함 — 한글이라 대소문자 이슈 없음) 방식으로 자동 적용.
- 매칭 우선순위: `highlight_rules` 매칭 단어 > 그 외 전체는 블록 기본 `color`.
- 규칙이 비어있으면(`[]`) 기존 동작과 **완전히 동일**(하위호환).

### 4-2. 렌더링 로직 — `_segmented_drawtext`
`video_assemble.py`에 신규 함수 추가:

```
_segmented_drawtext(text, base_style, work, key_prefix, x_pct, y_pct, highlight_rules=None) -> list[str]
```

1. `text`를 줄(`\n`) 단위로 분리 → 각 줄을 공백 기준 토큰화.
2. 각 토큰이 `highlight_rules`의 `keyword`와 일치하면 그 규칙의 색/배지로, 아니면 `base_style`의 기본색으로 세그먼트 배정. 연속 동일 스타일 토큰은 합쳐 세그먼트 수를 최소화(공백 포함).
3. `PIL.ImageFont.truetype(base_style에서 쓰는 동일 폰트파일, size)`로 세그먼트별 텍스트 폭(`font.getlength(seg_text)`)과 공백 폭을 측정 → 줄 전체 폭 계산 → `x_pct` 기준 중앙정렬 시작 x좌표(절대 px)를 파이썬에서 직접 산출.
4. 세그먼트마다 독립 `drawtext` 필터 생성. `x=`는 계산된 절대 px, `y=`는 줄 인덱스 × 줄간격(`size*1.2` 근사) + 공용 y. outline/box/enable-구간/alpha(효과) 로직은 기존 `_fixed_drawtext`/`_caption_drawtexts`의 해당 블록을 그대로 재사용.
5. `highlight_rules`가 없거나 매칭 0건이면 줄 전체가 세그먼트 1개 = **기존 `_fixed_drawtext`/`_caption_drawtexts` 출력과 100% 동일**.

`_headcopy_drawtext`와 `_caption_drawtexts`는 내부에서 이 함수를 호출하도록 리팩터하되, **외부 호출 시그니처는 변경하지 않는다**(`_burn_captions`에서의 호출부 무변경).

**오차 허용범위**: PIL 폭측정과 ffmpeg 실제 렌더 폭은 폰트 힌팅/커닝 차이로 1~3px 어긋날 수 있다. 프로젝트에서 쓰는 폰트가 전부 굵은 헤드라인용 고딕체(커닝 거의 없음)라 육안상 문제되지 않는 수준으로 판단 — 실제 렌더 후 육안 검증으로 확인.

### 4-3. UI (produce.html, 5단계 꾸미기)
- 헤드카피 입력(`#hcText`) 바로 아래에 **"강조 단어(헤드카피+자막 공통)"** 섹션 신규 추가.
- 행 추가/삭제 리스트(기존 `extraTextList` 패턴 재사용): 각 행 = `[단어 입력] [글자색 picker] [배지 on/off 체크박스] [배지색 picker]`.
- 헤드카피 미리보기(`updateHC()`)는 매칭 단어를 `<span style="color:...;background:...">`로 감싸 렌더 — 브라우저 프리뷰는 폭측정 없이 CSS inline-flex로 바로 배치되므로 추가 로직 불필요.
- 자막 쪽은 비트별 실시간 텍스트가 준비 전이라 미리보기가 어려우므로, 강조 규칙 섹션 아래 **예시 문장 미리보기**(고정 샘플 텍스트에 규칙 적용한 렌더)만 제공.
- 저장: `updateHC()`/규칙 변경 시 `STATE.deco.highlight_rules` 갱신 → 기존 `/api/produce/mix/settings`의 `deco` payload에 자동 포함(서버 변경 없음).

## 5. 에러 처리·엣지 케이스

- 강조 단어가 헤드카피/자막에 **없으면** 그냥 무시(에러 아님, 매칭 0건 = 세그먼트 1개로 폴백).
- 강조 단어가 문장 전체와 같으면(예: 문구 전체가 키워드) 세그먼트가 1개인 채로 강조 스타일만 적용 — 정상 동작.
- 폰트 파일이 `static/fonts`에 없는 경우(커스텀 폰트 미존재) — 기존 `_fixed_drawtext`와 동일하게 기본 `font.ttf`로 폴백. PIL 측정도 동일 폴백 폰트 파일 사용(불일치 방지).
- 배지(box) 폭 계산 시 padding은 세그먼트 폭 계산에 포함하지 않고 drawtext의 `boxborderw`로만 처리(기존 box 로직과 동일) — 인접 세그먼트와 배지가 겹치지 않도록 세그먼트 간 최소 여백(패딩만큼)을 확보하는 계산식 포함.

## 6. 테스트 범위

- `_segmented_drawtext` 유닛테스트: (a) 규칙 없음 → 기존 출력과 동일 (b) 1개 키워드 매칭 → 세그먼트 2~3개, x좌표 오름차순 검증 (c) 2줄 텍스트 + 줄마다 다른 매칭 (d) 매칭 키워드가 텍스트에 없음 → 세그먼트 1개
- `_headcopy_drawtext`/`_caption_drawtexts` 리팩터 후 **기존 테스트 전부 통과**(회귀 확인 — 하위호환의 핵심 근거).
- FULL_PRESETS 신규 3종(옐로2톤×2, 네온글로우×1~2)은 `applyFullPreset()` 스모크(콘솔 에러 없이 STATE 반영) 확인.
- 실제 ffmpeg 렌더 1회로 PIL 폭측정 vs 실제 출력 육안 비교(세그먼트 겹침/틈 없는지).

## 7. 범위 밖 (이번 설계 제외)

- salim_station 스타일의 "배지 모양"(둥근 사각형 정확한 픽셀 반경 등) 완전 재현은 ffmpeg `box=1`의 사각 박스 한계 내에서만 근사 — 라운드 코너 배지는 미지원(기존 box 렌더링 자체가 사각형).
- 자막 강조 규칙의 "부분 문자열 매칭"(예: "쿠팡" 규칙이 "쿠팡친구"에도 매칭될지) 여부는 구현 단계에서 정확 단어 매칭으로 시작 — 필요시 후속 확장.
