# 딸깍 스튜디오 — 설계 문서

- **작성일**: 2026-06-28
- **상태**: 설계 확정 (구현 대기)
- **레퍼런스**: Threads `@devdesign.kr` 게시물 (좌측 작업목록 갤러리 + 우측 폰/큰 미리보기, 다크 SaaS 룩)

---

## 1. 목적

버튼 하나(**딸깍**)로 **아침 브리핑 카드**를 실제로 생성하되,
"수급분석 → AI 히로이미지 → 카드렌더 → 이미지추출 → 텔레전송" 과정이
**멋진 단계 애니메이션**으로 흐르고, 완성 카드가 갤러리에 쌓이는 도구.

- **이중 목적**: ① 매일 실제로 쓰는 내부 도구 ② 그 사용 화면 자체가 녹화하면 콘텐츠가 되는 연출
- **최종 산출물**: PNG 이미지 저장 + 텔레그램 채널 자동 전송
- **첫 콘텐츠 1종**: 아침 브리핑 카드 (이후 종목요약·숏폼 등으로 확장 — YAGNI, v1은 1종만)

## 2. 비목표 (YAGNI)

- Electron 데스크톱 앱 패키징 (브라우저 전체화면으로 충분)
- 다중 콘텐츠 타입 (v1은 브리핑 카드만)
- SNS(스레드/인스타) 게시물형 폰 목업 미리보기 (출력은 PNG+텔레, 폰 목업 연출은 v1 제외)
- 로그인/회원/결제 (내부 도구)

## 3. 접근법

**채택안: 기존 `dashboard/server.py`(FastAPI:8090)에 스튜디오 페이지 + 생성 엔드포인트 추가.**
(대안 B 별도 신규 웹앱 = 인프라 중복 / 대안 C Electron = 오버킬, 모두 기각)

## 4. 아키텍처 / 컴포넌트

```
dashboard/server.py  (기존, 확장)
 ├─ GET  /studio              → 스튜디오 화면 (단일 HTML, 다크+골드)
 ├─ POST /studio/generate     → 생성 시작, 진행상황 SSE 스트리밍
 ├─ GET  /studio/gallery      → 생성 이력(index.json) 반환
 └─ POST /studio/regen-image  → 히로 이미지만 재생성

신규 모듈
 └─ scripts/gemini_image.py   → Gemini API 히로/썸네일 이미지 생성

재활용 (신규 코드 최소화)
 ├─ daily_scenario.py            → 브리핑 데이터/문구 (out/scenario_{날짜}.md)
 ├─ 카드 HTML 템플릿             → channel/strategy/briefing_카드_디자인스펙 + viz_card 스타일
 ├─ scripts/viz_card.save_png()  → Playwright HTML→PNG
 └─ scripts/viz_card.send_telegram_photo() → 텔레그램 채널 전송
```

### 모듈 경계 (독립 테스트 가능 단위)

| 모듈 | 역할 | 입력 → 출력 | 의존 |
|------|------|------------|------|
| `studio_data` | 브리핑 데이터 확보 | 날짜 → dict(시황/대장섹터/문구) | daily_scenario 산출물 |
| `gemini_image` | AI 히로 이미지 | 프롬프트 → png 경로 | GEMINI_API_KEY |
| `card_render` | 카드 HTML 합성 | 데이터+이미지 → html 경로 | 템플릿 |
| `viz_card.save_png` | 이미지 추출 | html → png | Playwright |
| `viz_card.send_telegram_photo` | 전송 | png+caption → 성공/실패 | BOT_TOKEN, CHAT_ID |
| `studio_pipeline` | 단계 오케스트레이션 + SSE 이벤트 발행 | 요청 → 단계별 이벤트 | 위 전부 |

## 5. "딸깍" 생성 흐름 (SSE 단계 스트리밍)

버튼 클릭 → `POST /studio/generate` → 서버가 단계별 진행을 SSE로 흘려보냄 →
프런트가 단계 체크리스트를 차례로 켬:

```
① 수급·시황 데이터 수집      (studio_data)              event: step {id:1, status:running→done}
② 🍌 AI 히로이미지 생성       (gemini_image)            event: step {id:2, ...}
③ 카드 디자인 렌더링         (card_render, 이미지 합성)  event: step {id:3, ...}
④ 이미지 추출 (PNG)          (viz_card.save_png)        event: step {id:4, ...}
⑤ 텔레그램 채널 전송         (viz_card.send_telegram_photo) event: step {id:5, ...}
✓ 완성                       event: done {png, html, thumb}
```

- SSE 이벤트 스키마: `{type:"step"|"done"|"error", id, status, message, payload}`

- **디자인 토큰**: 다크 차콜 배경, 골드 액센트(기존 브리핑 카드 디자인스펙의 골드값 재사용), 큰 라운드 코너, 넉넉한 여백
- **폰트**: `Instrument Serif`(헤드라인) + 산세리프(본문) — 기존 디자인 시스템 재사용
- **모션**: 단계 진행 = 골드 프로그레스, 완성 시 새 썸네일이 갤러리 맨 위로 **슥 떨어짐**
- **전체화면(F11)**: 브라우저 크롬 안 보임 → "프로그램"으로 보임 (녹화용)

## 7. Gemini 히로 이미지 (`scripts/gemini_image.py`)

- 모델: `gemini-2.5-flash-image` (나노바나나). 키: `.env`의 `GEMINI_API_KEY` (예비 `GEMINI_API_KEY_2`)
- 프롬프트: 오늘 시장 테마·대장섹터를 받아 자동 작성 (예: "한국 증시 반도체 강세, 미니멀 골드/다크 금융 일러스트, 텍스트 없음")
- 출력: `out/studio/img/{날짜}_hero.png`, 캐시 후 "이미지만 재생성" 버튼으로 갱신 가능
- **폴백**: 쿼터 초과·API 오류 시 골드 그라데이션 히로로 자동 대체 → 흐름 안 끊김

## 8. 데이터 저장

```
out/studio/
 ├─ {날짜}_브리핑.png      ← 최종 카드 이미지
 ├─ {날짜}_브리핑.html     ← 카드 HTML
 ├─ img/{날짜}_hero.png    ← Gemini 히로 이미지(캐시)
 └─ index.json            ← 생성 이력 [{date, type, png, thumb, sent_tg, created_at}]
```

## 9. 에러 처리

- 단계 실패 → 해당 단계 **빨강** 표시 + SSE `error` 이벤트, 이후 단계 중단
- **부분 성공 허용**: 텔레그램 전송만 실패해도 PNG·HTML은 저장 (재전송 버튼)
- Gemini 이미지 실패 → 폴백 히로로 진행 (에러 아님, 경고만)
- Playwright 미설치 → 설치 안내 메시지
- 캡션/날짜: 카드 생성 전 날짜 검증 (과거 데이터가 TODAY로 둔갑 방지 — 기존 V-1~V-5 규칙 준용)

## 10. 테스트

- **단위**: `studio_data`(데이터 dict), `gemini_image`(모킹 + 폴백 경로), `card_render`(html 산출), `viz_card.save_png`/`send_telegram_photo`(기존)
- **통합**: 생성흐름 수동 1회 — 브리핑 카드 1장 실제 생성 → out/studio 확인 → 텔레그램 수신 확인
- **연출 확인**: 전체화면에서 단계 애니메이션·완성 드롭 모션 육안 확인

## 11. 준비물 (사용자)

- 없음. `GEMINI_API_KEY`(+예비), `BOT_TOKEN`, `CHAT_ID` 모두 `.env`에 설정 완료.
- 유일 변수: Gemini 이미지 모델 쿼터/권한 → 실패 시 폴백 흡수(블로커 아님).

## 12. 확장 여지 (차후)

- 콘텐츠 타입 추가(종목요약·시황 숏폼) — `card_render` 템플릿 추가로 확장
- 폰 목업 SNS 미리보기 연출
- 클라우드 이전(24h 가동) — 기존 대시보드와 동일 경로
