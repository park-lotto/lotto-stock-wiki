### 진짜 원인 (`scene_play.js` step())
```js
if (Math.abs(v.currentTime - c.start) < 0.05 && v.readyState >= 2) show();
```
HTML 명세상 `v.currentTime = X`는 **요청 즉시** X를 돌려주고 `seeking`만 true가 된다.
실제 프레임은 나중에 온다. 즉 이 조건은 "도착했다"가 아니라 **"도착하라고 시켰다"**를 본다.

**전체 재생에서만 난 이유** — `runAllFrom`이 다음 칸 첫 컷을 `seat()`으로 미리 앉힌다.
`seat()`은 currentTime만 꽂고 **기다리지 않는다**(주석엔 "시크 완료까지 기다린다"고
적혀 있었지만 코드는 안 기다렸다 — 이 거짓 주석이 오해를 키웠다).
앞 칸과 **같은 소스**를 쓰면 readyState는 이미 높고 seeking만 true라 위 조건이 통과해
**가림막(썸네일) 없이 바로 화면에 올린다** → 아직 도착 못 한 앞부분이 1초쯤 노출.
칸별 재생(`playBeat`)은 미리 앉히기가 없어 늘 else(썸네일로 가리고 대기)로 갔다 → 멀쩡.

### 고친 것
- 판정에 `&& !v.seeking` 추가 — 도착을 실제로 본다
- else에서 **진행 중인 시크에 currentTime을 재대입하지 않는다**. 같은 값을 다시 꽂으면
  브라우저가 seeked를 안 쏘아 진행 중이던 완료 신호까지 놓치고 타이머로만 깨어난다
  (컷 시작이 cutWaitMs만큼 늦어진다 — 미리 앉힌 컷이 정확히 이 경우다)
- `seat()` 주석을 사실에 맞춤: 기다리지 않는다고 명시
- 회귀 테스트 `test_preview_seek_arrival.py` 2건

### ⚠️ 검증 한계 (정직하게)
- 근거는 **코드 독해 + HTML 명세**다. 실제 `<video>`로 "seeking=true인데 옛 조건이
  참이 된다"를 **실증하지 못했다** — 자동화 탭에서 video가 readyState 0에서 안 올라갔다
  (python http.server가 Range/206을 안 줘 blob으로 우회해도 동일).
- 즉 **사장님이 실제로 전체재생을 눌러 꼬다리가 사라졌는지 확인해야 확정**이다.
- 기존 실패 1건(`test_merge_split_playback.py` ANSI 색코드)은 손대지 않은 main에서도
  동일하게 실패한다 — 내 변경과 무관한 기준선.
