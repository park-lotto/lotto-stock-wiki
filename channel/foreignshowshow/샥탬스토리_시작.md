## 0. 시작 순서
1. `py tools/track.py use 칼카피숏템엔진` → 작업은 `.tracks/칼카피숏템엔진` 안(관제 097). 탭 제목 `py tools/session_title.py set "샥탬스토리 …"`.
2. ★**`channel/foreignshowshow/칼카피_원리.md`(우리 자산 — 벤치가 왜 터지나·어떻게 똑같이 하나)** 를 읽고, 편을 만들 때마다 §9 에 배운 것을 쌓는다(사장님 10-18 "원리 다 적어놓고 계속 쌓으면서 다음 편도 동일하게 축적"). 기계가 읽는 값은 `tools/calcopy/shark/rules.json`.
3. 이 문서 §2 '지금 상태' → 각 편 폴더 `channel/foreignshowshow/<N편_제품>/plan/계획.md`.
3. `git status --short` — **공유 워크트리**(얜샷템 하이브리드·현장썰·썰템쇼 세션이 동시에 씀). 내 파일만 경로 지정 add. `add -A`·stash·checkout·reset 금지.
4. `df -h /c` — C 여유 15GB 미만이면 큰 다운로드·렌더 멈추고 보고(D 외장 미연결일 때가 있음).
5. 끝날 때: 이 문서 고치기 → handoff 일지 몇 줄 → 커밋 → `git push origin HEAD:track/칼카피숏템엔진`. **`track.py finish 칼카피숏템엔진` 금지**.
6. ★**병합·배포(라이브)는 모아서 한 번에(사장님 10-18, 공통 §0-1 5-1번)** — 이 세션은 트랙에 커밋·`git push origin HEAD:track/칼카피숏템엔진` 까지만. `finish`·숏템프리셋 sync 는 하지 않는다. 아래는 사장님이 모아서 할 때의 절차: 장부(브랜드·스타일·결과물)·분석 문서는 관리자 **숏템프리셋** 페이지(https://shoppingshorts.duckdns.org/shortem_preset, 관리자 전용, 화면에선 '칼카피' 대신 '숏템프리셋')에 올린다 — main 폴더에서 `py tools/calcopy/sync_preset_ledgers.py --check` → `py tools/calcopy/sync_preset_ledgers.py` → `py tools/track.py finish 숏템프리셋` → `py tools/live_admin.py shot shortem_preset out.png` 로 라이브 숫자 확인. 완성본은 `channel/결과물.json` 에 적어야 브랜드 카드에 뜬다. 페이지 요청·결함은 '칼카피 관리 페이지' 세션에 SendMessage.

## 1. 확정 규칙 (사장님 10-18)
- **브랜드 = 샥탬스토리**(장부 `channel/브랜드.json` foreignshowshow). 스타일 = **현장썰**(한국어 나레 + 영어 원음 번역 자막 + 제품) — 강점은 `channel/스타일.json` 현장썰.strengths 에 **항목만 추가**(파일 다시 읽고, 통째 덮어쓰기 금지).
- **순서: 먼저 벤치 그대로 칼카피(방송 원음 위주) → 뒤에 얜샷템처럼 하이브리드로 변형.** 그대로 = 제목 띠·빨간 원·화살표·돈 이모지 같은 것도 우리 식으로 바꾸지 않는다. 바꾸는 건 로고 자리의 우리 브랜드뿐. 다른 점이 생기면 전부 보고(공통 §0-1 8번).
- 판독은 클로드 눈으로(제미나이 판독 금지, 받아쓰기만 무료 키 — 공용 풀 `py tools/calcopy/pull_pool_keys.py`, 10-18 161개). 사람 이름은 화면 글자(자막·이름표)로 확인된 것만, 얼굴 짐작은 '불명'(공통 §0-1 4·10·11번).
- 칼카피 세션끼리 공유: 문서·장부를 바꾸거나 새 사실을 알면 관련 세션에 SendMessage, 받으면 문서 자리 고치고 회신(공통 §0-1 7번). 현장썰 흐름 대조는 `channel/스타일분석/현장썰/쇼핑흐름_1차.md`.
- 벤치 공식 6박자: 0~3초 결말 반응(투자자+빨간 원) → 시연 → 기존 불편 → 숫자 → 지분 경쟁 → 방송 후 결과. 나레 반말 전언체(~는데/~다고), 벤치 나레 연속 3어절 베끼기 금지, 숫자는 출처 있는 것만.
- **역할 나누기**(공통 `tools/calcopy/담당_공통규칙.md`·`지시문_템플릿.md`): 이 세션 = 페이블(지휘·판정만). 손작업 = sonnet, 대본·수리 = opus 담당 에이전트. 담당은 계획 시트까지 → 페이블 OK → TTS 1회 → 렌더. 검수 = `tools/calcopy/검수_매뉴얼.md`.
- **빠르게(얜샷템 하이브리드 세션 도구, 고치지 말고 부르기만 — 수정은 handoff 끝 '엔진 요청')**: 후보는 통째 받지 말고 거른 뒤 고른 것만 1080p(`tools/calcopy/hybrid/screen.py` 방식) · 받아쓰기는 서버 키 풀 `hybrid/server_ai.py asr`(2모델 교차) · 렌더 뒤 `hybrid/checks.py` B표 초안 · 하이브리드판 렌더는 `hybrid/render_jaemi.py`·`render_itssum.py`.
- 동시 담당이 많을 때 무거운 프로세스(ffmpeg·yt-dlp·분석)는 담당당 한 번에 하나. `python -c pass` 3초 넘으면 멈춤.
- ★**판정 = 벤치와 같은 시각 프레임을 나란히 놓고 세부 기준표로**(사장님 10-18 "1편 원본과 비교해봐 뭔가 떨어진다 — 시작 훅부터 강조 자막·효과음·와우포인트"). 길이·LUFS·싱크만 맞다고 "완성"이라 하지 않는다. 기준: ①0초 훅(빨간 원+큰 반응 자막) ②자막 크기·자리(68px·창 가운데) ③낱말별 강조 색 7색+번짐 빛 ④와우 포인트(숫자·핵심어 터뜨림) ⑤효과(실선·점선 원·화살표·날개 돈다발·색 번쩍) ⑥효과음·배경음 ⑦장면이 벤치만큼 실감(홍수 현장 등) ⑧제목 꼴. 도구 `tools/calcopy/shark/compare_bench.py`(만드는 중).
- **채널 목소리 = 지훈**(타입캐스트 `tc_61f0859907085fc68561c9a1`, 6편 전부 같은 목소리) — 벤치 나레 4편 f0 중앙 116.4Hz(남)·말속도 7.7~8.8자/초, 지훈 129.0Hz(1.79반음, 후보 중 최근접). 근거 `1편_STORMBAG/plan/voice_measure.json`. voice_presets.py 에 없어 tempo 1.25(남자 기본)·atempo ≤1.27.
- **렌더러 = `tools/calcopy/shark/render.py`**(나레↔원음 N회 교대·원음 번역 자막·원음 트랙 확인·−9.0 LUFS) + 검사 `shark/check.py`. `--plan`(TTS 없이 컷표) → 페이블 OK → `--confirm-tts`(타입캐스트 1회). 효과(빨간 원·이모지)는 재료에 `effects[{line,kind,at,size,t}]` 좌표를 적어야 그려진다. 원음 줄 화면 = 같은 원본 시각의 말하는 본인(어긋남 0.1초 넘으면 고침).
