# 숏템엔진 — 채널 엔진 + 채널 spec 설계 (2026-09-25, 사장님 확정)

## 0. 한 줄

볼케이노 방식 그대로: **만드는 기계 하나(`channelkit`) + 채널마다 설정표 한 장(`channels/<이름>/spec.py`)**.
1호 뇌전구(기존 brainbulb를 쪼개서), 2호 뜨거운사람들(`youtube.com/@뜨거운사람들`). 내부 양산용 먼저, 상품화(숏템메이커 프리셋)는 나중.

## 1. 왜

- brainbulb는 뇌전구 전용(3,982줄·20모듈). 채널마다 이걸 또 짜면 같은 판단이 N군데 생긴다(0순위-B).
- 볼케이노가 프리셋 12개까지 늘린 이유 = 엔진이 하나. 우리도 첫 채널에서 경계를 잡아야 두 번째부터 싸진다.
- 뜨거운사람들은 나레·TTS·타이밍·밈이 없어(자막+실사+BGM) 2호로 얹기 가볍다. 대신 **실사 소스 찾기**가 새 축.

## 2. 구조

```
shopping_shorts/channelkit/          공통 엔진 — 채널이 몰라도 되는 것
  pipeline.py    run_step / next_step / job.json 저장·재개(brainbulb 그대로). 채널 spec의 STEPS만 돈다
  lint_core.py   규칙 등록기. 규칙 함수는 여기, 어떤 규칙을 켤지는 채널 spec 목록
  layout.py · ass_gen.py · render.py · review.py · frames.py · providers.py(LLM·TTS·검색)
  footage/       search.py(검색어→후보) · fetch.py(다운로드) · cut.py(장면 자르기) · pick.py(자막↔장면 대조)
shopping_shorts/channels/
  brainbulb/     spec.py + 뇌전구 전용 단계(images·photos·photocheck·prompt·voice·sfx)  ← 1호
  hotpeople/     spec.py + research.py(사실 수집) · query.py(컷→검색어)                  ← 2호
```

원칙 3개(볼케이노 원리에서):
1. **규격은 spec 상수** — 값마다 실측 근거 주석(뇌전구 spec.py 형식). 우리 정책값은 `POLICY_` 접두.
2. **규칙은 린터 판정으로만** — 프롬프트 지시문에만 있고 판정이 없는 규칙은 없는 규칙(메모리 `지시문에만있고_판정없음_4연발`).
3. **채널 추가 = spec.py 한 장 + 그 채널만의 단계 모듈**. 엔진 코드는 안 건드린다.

spec.py가 정하는 것: `STEPS`(단계 순서) · `LINT_RULES`(켤 규칙 목록+파라미터) · 캔버스/좌표/폰트/색 · 컷 길이 규칙 · 말투(어미 허용 목록) · 음성(없으면 None) · BGM 폴더.

## 3. 흐름 (뜨거운사람들)

```
seed      인물명 + 한 줄 주제                                          ← 사람 ①
research  웹검색 → 사실 5~8개 + 출처 URL. 출처 없는 문장은 대본에 못 들어감
script    헤드라인 2줄 + 자막 15~30컷(반말 ~음/~임체) → 린터 반려→재작성 반복
          ★사람 ② 확인 (자동 승인 옵션은 있으되 기본 꺼짐)
footage   컷마다 검색어(한·영) → 유튜브 상위 3~5편 다운로드 → 장면 자르기 → 자막↔장면 AI 대조 →
          인물 실존 여부 검사 → 못 찾은 컷은 뉴스 이미지로 대체. 컷마다 출처(URL·구간) 기록
          ★사람 ③ 컷별 썸네일 확인
layout    spec 상수로 프레임 구성(흰 바탕·로고·헤드라인·슬롯·자막)
render    컷 길이 = 자막 글자수 규칙(원본 실측으로 맞춤) + BGM → mp4
review    자동 검수(§5) → 원본 나란히 비교 HTML
```

멈춘 자리는 `job.json`에 남기고 `--step <단계>`로 재개(brainbulb pipeline 그대로).

## 4. 뜨거운사람들 spec을 채우는 실측

표본: 조회수 상위 10편 + 무작위 10편 = 20편 다운로드(`out/hotpeople/sample/`, gitignore).
지금까지 실측(50편 flat + 2편): 구독 21,000 / 조회 중앙값 81,000 / 매일 1편 / 46~62초 / 컷 17~33 / 나레 없음(Whisper 2편: BGM만) / 흰 바탕·좌상단 로고·2줄 헤드라인(검정+빨강|노랑)·가로 슬롯·2줄 자막(강조어 빨강) / 반말 ~음·~임·ㄷㄷ·ㅋㅋ.

| 상수 | 재는 법 |
|---|---|
| 로고·헤드라인·슬롯·자막 좌표 | 프레임 픽셀 경계 검출(20편) |
| 헤드라인·자막 글자수·줄 수·강조색 | OCR 전수 + 픽셀 색 |
| 폰트 | 렌더 대조(`tools/scene_font_research` 방식이 있으면 재사용, 없으면 후보 폰트로 같은 문장 렌더해 픽셀 대조) |
| 컷 수·컷당 길이·글자수↔길이 | `scene_cut.detect_cuts` 20편 |
| 어미·말투 | OCR 텍스트 어미 빈도 → `LINT_RULES` 허용 목록 |
| 슬롯 크롭 방식 | 가로 원본이 슬롯에 어떻게 들어가는지(레터박스/크롭) 프레임 대조 |
| BGM | 볼륨(LUFS)·장르 메모. 직접 만들지 않고 라이선스 프리 폴더에서 고름 |

결과 문서: `channel/hotpeople/역분석_<실측일>.md`. spec.py 값마다 이 문서 줄을 근거로 단다.

## 5. 검증 (무엇을 재서 "됐다"고 하나)

| 단계 | 자동 판정 |
|---|---|
| 엔진 쪼개기 | 뇌전구 골든 테스트 9개(`tests/test_brainbulb_*.py`) 결과 동일. 실패면 쪼개기 실패 |
| 대본 | 린터 반려 0 · 사실마다 출처 URL · 어미 분포 원채널 실측 범위 |
| 장면 | 컷마다 출처 기록 · 검정/빈 프레임 0 · 인물 등장 컷 비율 ≥ 원채널 실측 |
| 렌더 | 50~60초 · 컷 길이 분포 원채널 20편 범위 · 자막 잘림 0(픽셀 실측) |
| 최종 | 원채널 영상과 나란히 비교 HTML — 사장님 눈 판정 |

검사는 `tools/hotpeople/` 도구로 저장해 다음 채널에도 돌린다(0순위-A1b). 렌더·캡컷 경로까지 반영 확인(0순위-A1a)은 이 엔진에선 render 단계 산출 mp4 프레임 실측으로 대신한다(캡컷 내보내기는 이 범위 밖).

## 6. 재사용 부품 (실측 2026-09-25)

`kw_search.search`(유튜브 백엔드, 무료 쿼터) · `media_download.download_any` · `scene_cut.detect_cuts/extract_poster` · `scene_match.match_scene_assets`(자막↔자산 AI 대조) · brainbulb `pipeline/lint/layout/ass_gen/render/review`.

## 7. 범위 밖 (이번엔 안 함)

숏템메이커 UI 배선(produce.html·app.py) · 자동 승인 기본 켜기 · 캡컷 내보내기 · 3호 채널 · 볼케이노 실행기 코드 사용(라이선스·서버 종속).

## 8. 리스크

- 방송·중계 클립 저작권 / 유튜브 재사용 콘텐츠 판정 → 컷별 출처 기록으로 문제 컷만 교체 가능하게. 수익화 여부는 사장님 판단.
- 소스 매칭 정확도 — 사람 ③ 확인이 기본 켜짐. 자동 승인은 정확도 실측 뒤.
- 옆 세션(볼케이노작업)이 `.tracks/뇌전구벤치` 코드를 같이 고치면 충돌 → 쪼개기 끝날 때까지 문서만(전달문 `Desktop/볼케이노작업/숏템엔진_진행상황.md`).
