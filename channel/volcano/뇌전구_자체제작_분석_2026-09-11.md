## 1. 한 줄 결론

볼케이노가 하는 일은 **①대본 규칙 검증 ②자막 좌표/스타일 ③효과음 순환 ④컷 길이 규칙**이 핵심이고, 이 넷은 역분석으로 **거의 확정**됐다. 나머지(이미지 생성·TTS·ffmpeg 조립)는 범용 기술이고 절반은 숏템메이커에 이미 있다. **겉모습 재현은 가능**하다. 못 하는 건 흔들림 진폭·줄나눔 정확한 픽셀 한도·밈 전체 매핑 셋인데, 전부 실물 영상에서 측정하거나 우리 값으로 정하면 된다.

## 3. 대본 규칙 → 린터로 코드화 (모듈 B·C)

서버 반려 30건에서 나온 규칙. **전부 정규식·문자열 검사로 짤 수 있다.** 픽셀 폭 검사 하나만 폰트 메트릭이 필요하다.

### 대본 JSON 스키마 (실측 산출물 구조 그대로)

```
{
  "youtube": {"h1": "흰 윗줄", "h2": "노란 아랫줄(숫자 여기)"},
  "card":    "오프닝에서 읽어주는 한 문장",
  "region":  {"scope": "국내|해외", "place": "…"},
  "cuts": [
    {"text": "자막 한 컷", "color": "WHITE|YELLOW|RED|ORANGE|PINK",
     "role": "NARR|CHAR|PUNCH", "img": 3, "meme": null},
    {"text": "…", "color": "RED", "role": "PUNCH", "img": null, "meme": "경악/충격"}
  ]
}
```

### 린터 규칙표 (반려 원문 기준)

| 검사 | 판정 | 구현 |
|---|---|---|
| 제목 구두점 | h1·h2에 `" ? ! . ,` 있으면 반려 | 정규식 |
| 자막 쉼표 | cut.text에 `,` 있으면 반려 | 문자열 |
| 한 줄 길이 | **픽셀 폭** 초과 시 반려 (실측 통과 최대 12·12·14자, 5어절) | PIL `ImageFont.getlength` 로 폭 측정. 한도값은 §5 |
| 어절 수 | 5어절 초과 반려 | split 개수 |
| 강조색 연속 | 흰색 아닌 색 3컷 연속 반려 | 슬라이딩 윈도 |
| 격식체 | `-습니다/-습니까/-십시오` 종결이 **과반**이면 반려. 의문·청유 격식은 1개도 반려 | 종결어미 정규식 + 비율 |
| 원문 베끼기 | 원문 문장을 그대로 줄인 것 반려 | 원문과 n-gram 겹침률(서버 기준 미상 → 우리 값 정함) |
| h2 끝말 | 추상명사(이유·사연·진실…)로 끝나면 반려 | 금지어 목록 |
| card | 한 문장(마침 1개) | 문장 분리 |
| 컷 구성 | `img` 정수 또는 `meme` 문자열 중 하나 필수 | 스키마 |
| 밈 감정 | 10종 문자열 정확히 일치 | enum |
| 마지막 컷 | WHITE면 경고, 문장 안 닫히면 경고. **RED PUNCH 단정문 권장** | 규칙 |
| region | 원문에 place 문자열이 있는지 | 포함 검사 |

밈 감정 10종: `경악/충격 · 기타 · 당황 · 만족/엄지척 · 무표정/멍 · 분노 · 비웃음/조롱 · 슬픔/울음 · 의심/떨떠름 · 피곤/지침`

### 통과본 분포 = LLM 프롬프트의 목표치

- 27컷 기준 WHITE 19 · RED 4 · YELLOW 3 · PINK 1 / NARR 19 · CHAR 7 · PUNCH 1
- 밈 3~5컷(20% 안팎), 이미지 슬롯 11개(한 슬롯을 2~3컷이 공유)
- 컷 15~27개, 총 27~43초
- 말투 "~임/~됨" 체(2편) 또는 "~였다/~했다"(1편, 통과)

**LLM 프롬프트에 위 분포를 목표로 주고, 린터가 반려하면 반려 사유를 붙여 재생성** — 볼케이노가 30→2→0으로 통과시킨 방식 그대로다.

## 4. 타이밍 규칙 (모듈 F) — 전부 확정, 단순

```
카드 길이  = card 문장 TTS 길이         (실측 3.36 / 2.05 / 1.65초)
컷 길이    = 그 컷 TTS 길이 그대로       (실측 0.68~2.82초, 평균 1.48초)
컷 사이 무음 = 0
총 길이    = 카드 + Σ컷
```

TTS는 컷마다 따로 합성한다(28개 파일). 숏템메이커 `typecast_tts.synthesize`가 그대로 쓰인다. 타임스탬프 응답을 `to_alignment`로 바꾸는 코드도 이미 있다.

## 5. 자막 ASS (모듈 G) — 스타일은 바이트 단위 확정

3편의 `sub.ass` 스타일 블록이 **바이트 단위로 같았다** → 서버 고정값. 그대로 쓰면 된다.

### 고정 스타일

| 요소 | 폰트 파일 | 크기 | 색 | 위치 | 비고 |
|---|---|---|---|---|---|
| h1 | SBAggroB.ttf | 123(상한) | 흰 | (530,215) an8 | 영상 내내 고정 |
| h2 | SBAggroB.ttf | 134(상한) | 노랑 | (530,330) | 〃 |
| 카드 | S-CoreDream-6Bold.ttf | 46~54 | 검정/흰 띠 | (546,633) an5 | 회색 #3B3B3B 띠 273px + 흰 #FDFDFD 띠 137px |
| WHITE | S-CoreDream-7ExtraBold.ttf | 102 | 흰 | (636,1271) / 2줄째 (636,1358) | Outline 4, Shadow 0 |
| YELLOW | S-CoreDream-6Bold.ttf | 99 | 노랑 | 〃 | |
| PINK | S-CoreDream-6Bold.ttf | 102 | #FEDEFE | 〃 | |
| ORANGE | S-CoreDream-6Bold.ttf | 102 | #F76C0D | 〃 | |
| RED | yg-jalnan.ttf | **73** | 빨강 | 〃 | 유일하게 다른 폰트·작은 크기 |

- 등장 효과: `{\fscx108\fscy108\t(0,90,\fscx100\fscy100)}` (살짝 커졌다 줄어듦 90ms)
- 줄 간격 87px. 굵기 태그 없음(폰트 자체 굵기)
- 캔버스 1080×1920. 이미지 슬롯 1028×786 가로형이 세로 중앙 아래쪽, 위·아래 검정

### 자동 조정 (서버 함수 → 우리가 다시 짜야 함)

| 항목 | 실측 | 규칙 |
|---|---|---|
| h1/h2 크기 | 123/100 · 105/118 · 123/98 | 글자 수에 맞춰 **한 줄에 들어가게 축소**, 상한 123/134 |
| 카드 크기 | 46 · 54 · 54 | 긴 문장이면 축소 |
| 한 줄 글자 수 | 12 · 12 · 14 | **픽셀 폭 기준**. 좁은 글자면 더 들어간다 |

**줄나눔 한도 역산법**: 3편 `sub.ass`의 모든 줄을 해당 폰트·크기로 `getlength` 재서 **최댓값**을 찾으면 그게 한도의 하한이다. 반려된 줄(drive_log에 있음)의 최솟값이 상한. 그 사이 값으로 정하면 된다. → TheRose PC 산출물 필요.

### 숏템메이커와의 차이

숏템메이커 자막은 ffmpeg `drawtext` 방식(`video_assemble._caption_drawtexts`). 뇌전구는 ASS 파일을 `subtitles=` 필터로 굽는 방식이다. **ASS 생성기를 새로 짜야 한다** (Python 문자열 조립, 100줄 안팎). 대신 위치·효과·다중 스타일이 drawtext보다 훨씬 쉽다.

## 6. 효과음 (모듈 H) — 순서 확정

3편 모두 **컷 번호대로 똑같은 순서**. 무작위 아님.

```
pop4 → click → boing → ding → pop4 → r3_click → hit → r3_ding → pop4 → x_click → r3_hit → x_ding → (반복)
```

- 컷마다 1발. 게인 1.0(일부 1.25 — 어느 컷이 1.25인지 규칙 미상, RED/PUNCH 추정)
- 나레 기준 -29.4 LUFS, 효과음 베드 -22dB
- 카드 구간에도 효과음이 있는지는 문서에 없음 → 실물 확인

**자산 문제**: 팩 `sfx_norm/` 79개 mp3는 볼케이노 것이고 저작권 미확인. 자체 제작이면 **같은 성격(pop·click·boing·ding·hit)의 효과음 12종을 따로 확보**해야 한다(프리사운드 CC0 등). 숏템메이커 `mix_pipeline`에 효과음 섞는 ffmpeg 필터는 이미 있다.

## 7. 이미지 · 밈 · 프레임비전 (모듈 D·I)

### 이미지 (EvoLink)

- 슬롯 11개, 27컷이 공유. 프롬프트는 영문, `cast`로 인물 인상착의 고정 → 컷 간 동일 인물(실측 11장 일관)
- 서버가 "국내 로케일" + "다큐멘터리 사진" 지시를 덧붙임. `illustration` 단어 경고
- 원본 1184폭 → 슬롯 1028×786에 `contain_selected` 크롭
- **숏템메이커에 EvoLink 연결이 없다.** API 헤더는 `Authorization: Bearer <key>` (setup 응답에서 확인). 엔드포인트·모델·파라미터는 실행기 로그에서 봐야 한다 → TheRose PC
- 대안: 이미 키가 있는 다른 이미지 생성 API로 바꿔도 규격(가로형, 인물 일관)만 맞으면 된다

### 밈 (pepe 팩 57장)

- 감정 10종 → 파일 매핑 일부만 앎: 013=경악/충격 · 042=분노 · 000=비웃음 · 005=슬픔 · 008=무표정
- 밈 컷은 30fps 연속 프레임, scale 1.6 확대
- **저작권 미확인** → 자체 밈 세트 필요. 감정 10종 × 최소 3장이면 된다

### 프레임비전 (얼굴 YuNet + 글자 PP-OCR)

- 생성 이미지에서 얼굴·글자를 검출 → 피사체가 슬롯에 들어오게 크롭. 글자가 있으면 지울지 판정
- YuNet은 `cv2.FaceDetectorYN`으로 OpenCV에 내장(모델 onnx 파일만 받으면 됨). OCR은 `rapidocr-onnxruntime` 같은 걸로 대체 가능
- **MVP에서는 빼도 된다** — 프롬프트에 "no text, centered subject"를 넣고 중앙 크롭하면 대부분 통과

## 8. 렌더 (모듈 J)

역분석: ffmpeg 3회. 정확한 인자는 로그에 생략됨(미상).

확정된 것:
- 이미지 컷 = 정지 1프레임(그 컷 길이만큼)
- **밈 컷과 RED 대사 컷만** 30fps 연속 프레임 → 흔들림/줌
- RED 컷은 원본 1184폭 중 900~1150폭만 잘라 **약 1.2배 줌인**
- 자막은 ASS 번인, 오디오는 나레 이어붙이기 + 효과음 베드

미상:
- 흔들림(위글) 진폭·주기 → **실물 mp4에서 연속 프레임 diff로 측정 가능** (RED 컷 구간 프레임 20장 뽑아 피사체 좌표 추적)
- 오디오 정규화 방식(loudnorm 파라미터)

우리 방식 제안 (ffmpeg 1~2회로 압축):
```
① 컷별 정지 이미지 + 흔들림 컷은 zoompan/crop 표현식으로 프레임 생성 → concat
② -filter_complex "…, subtitles=sub.ass" + amix(나레, sfx) → 최종 mp4
```
숏템메이커 `video_assemble`에 concat·threads·crf·preset 뼈대가 다 있다.
