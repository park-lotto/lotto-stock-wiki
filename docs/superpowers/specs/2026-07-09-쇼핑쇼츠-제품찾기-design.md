# 쇼핑쇼츠 자동화 — 제품 찾기 (기능 ③ 소스매칭) 설계

날짜: 2026-07-09
상태: 설계 확정 대기
선행: 기능 ① 레퍼런스 랭킹, 기능 ② 소통 큐 (둘 다 완성, `shopping_shorts/`)
벤치마킹 대상: `shopping.tubefactory.kr` "제품 찾기" (URL 붙여넣기 → 여러 플랫폼에서 유사 영상 검색)

---

## 1. 목적 (What & Why)

레퍼런스 랭킹(기능①)에서 터진 영상을 찾은 뒤, **그 영상과 같은 소재(제품/장면)를 다루는
다른 영상들을 여러 플랫폼(틱톡·인스타·유튭·더우인·샤오홍슈·구글)에서 찾아 모으는 도구**.
찾은 영상들은 다음 단계(짜집기/재편집)의 원자재가 되므로, **여기서 충분한 소스가 확보돼야
다음 단계가 성립한다** — 이 기능의 결과물 양과 질이 전체 파이프라인의 병목.

### tubefactory 대비 차별화 포인트
tubefactory는 **캡션/제목 텍스트에서만 키워드를 뽑아** 검색한다 — 영상 내용 자체를 보지
않아서 "겉핥기식" 매칭이라는 게 사용자 피드백. 이게 tubefactory가 고객 만족을 가장 못
주는 지점. 저희 차별화:

1. **영상을 직접 Gemini에 입력**(캡션 텍스트가 아니라 실제 비디오) — 모션·화면 속 텍스트·
   전체 맥락까지 이해해서 키워드/제품특징을 뽑음. 기존 인프라로 바로 가능, 추가비용 없음.
2. **수집된 후보를 Gemini로 재검증** — 플랫폼 검색이나 Google Lens가 찾아온 후보들을
   원본 프레임과 다시 비교해 진짜 유사한지 점수 매기고 재정렬. tubefactory엔 없는 단계.

### 검토했으나 기각한 방향
**자체 임베딩 벡터 인덱스 구축**(영상을 벡터화해서 우리가 직접 쌓은 인덱스에서 검색)은
의미있는 커버리지를 가지려면 카테고리당 수만~수십만 건을 지속적으로(트렌드가 매일
바뀌므로) 크롤링·재크롤링해야 하고, 틱톡/샤오홍슈/더우인은 봇차단이 심해 이 규모 수집
자체가 인프라팀 단위 작업 — 현재 팀 규모에서 비현실적이라 기각. 대신 **각 플랫폼 자체
검색(또는 Google Lens)이 이미 가진 인덱스를 후보 조회용으로 쓰고, 정확도만 Gemini로
보강**하는 절충안 채택 (§3-3 참고).

## 2. 전체 흐름

```
1. 입력: URL(기능①의 "담기" 버튼에서 자동 전달) 또는 직접 붙여넣기
      ↓
2. Apify videoUrl로 영상 다운로드 → ffmpeg로 프레임 N장 추출(장면전환 감지, 균등분할 아님)
      ↓
3. Gemini 멀티모달: 영상 파일 자체 + 캡션 입력 → 핵심 키워드(제품명·특징) 추출 + 영어/중국어 번역
      ↓
4. 화면 표시:
   - 키워드별 플랫폼 검색링크(틱톡·인스타·유튭·더우인·샤오홍슈·구글) — URL 템플릿, API 불필요
   - 프레임별 Google Lens 역검색 링크
      ↓
5. [수집] 버튼 클릭 시 실제로 긁어옴 (플랫폼별 §3-3):
   - 1단계 구현: 유튭(Data API, 무료 즉시 가능)
   - 2단계: 인스타/틱톡(Apify 검색 액터), Google Lens(SerpApi)
   - 3단계(최선노력): 더우인/샤오홍슈/Baidu — 안정성 낮음, 안 되면 링크만 유지
      ↓
6. Gemini 검증: 수집된 각 후보(썸네일/프레임)를 원본 프레임과 비교 → 유사도 점수 → 재정렬·필터
      ↓
7. "담기" → 소스풀에 저장(다음 단계인 짜집기 원자재)
```

## 3. 단계별 상세

### 3-1. 영상 다운로드 + 프레임 추출

- Apify `instagram-reel-scraper`가 이미 `videoUrl`(다운로드 가능한 직링크)을 반환함
  (`docs/superpowers/specs/2026-07-08-쇼핑쇼츠-레퍼런스랭킹-design.md` 확인됨) — 지금은
  `ranking.py`의 `build_items()`가 이 필드를 버리고 있어서, **저장하도록 확장 필요**.
- ffmpeg로 프레임 추출: 균등 분할이 아니라 **장면전환 감지**(`select='gt(scene,0.3)'` 류
  필터)로 최대 6장 뽑기(감지된 장면전환이 6개 미만이면 있는 만큼만) — 비슷한 프레임
  중복 추출 방지, 더 대표성 있는 장면 확보.
- 서버에 ffmpeg 미설치 확인됨(`which ffmpeg` 실패) → 배포 시 `apt install ffmpeg` 필요.
- 추출한 프레임은 임시 디렉토리에 저장, `/api/find/frame/{id}` 같은 프록시 엔드포인트로
  화면에 서빙(기존 `/api/thumb` 패턴과 동일).

### 3-2. Gemini 비디오 분석

- 다운로드한 영상 파일을 Gemini에 **직접 업로드**(File API 또는 inline bytes, 크기 제한
  확인 필요) — 캡션 텍스트나 프레임 몇 장이 아니라 영상 전체를 보게 함.
- 출력: 제품/장면 핵심 키워드 3~5개(한국어) + 영어 번역 + 중국어(간체) 번역, 카테고리.
- 전용 키 풀(`SHORTS_GEMINI_KEYS`, 기능② 구축분) 재사용 — 댓글 draft 생성과 같은 풀
  공유(용도가 다르지만 계정 자체는 공용, 사용량 늘어나면 별도 그룹 분리 검토).

### 3-3. 검색링크 생성 (API 불필요)

키워드×플랫폼 조합으로 URL 템플릿 생성. 예:
- YouTube: `https://www.youtube.com/results?search_query={kw}`
- Google: `https://www.google.com/search?q={kw}`
- TikTok: `https://www.tiktok.com/search?q={kw}`
- Instagram: `https://www.instagram.com/explore/search/keyword/?q={kw}`
- Douyin: `https://www.douyin.com/search/{kw}`
- Xiaohongshu: `https://www.xiaohongshu.com/search_result?keyword={kw}`

프레임별 Google Lens 링크는 SerpApi 없이도 `https://lens.google.com/uploadbyurl?url={frame_url}`
형태로 "링크만" 제공 가능(사용자가 직접 클릭해서 확인) — **실제 수집(§3-4)에만 SerpApi 필요**.

### 3-4. 실제 수집 ([수집] 버튼)

| 플랫폼 | 방법 | 필요한 것 | 우선순위 |
|---|---|---|---|
| YouTube | YouTube Data API v3 `search.list` | 신규 API 키(무료 할당량) | 1단계 |
| Instagram/TikTok | Apify 키워드/해시태그 검색 액터 (현재 쓰는 reel-scraper와 다른 액터) | 액터 조사·연동 | 2단계 |
| Google Lens | SerpApi `google_lens` engine | 신규 유료 API 키 | 2단계 |
| Douyin/Xiaohongshu/Baidu | Apify 커뮤니티 액터 또는 보류 | 조사 필요, 불안정 가능성 높음 | 3단계(최선노력) |

수집된 각 후보는 정규화된 형태(썸네일 URL, 원본 링크, 플랫폼, 제목)로 저장.

### 3-5. Gemini 검증 (차별화 핵심)

수집된 후보마다:
- 후보의 썸네일(또는 대표 프레임)을 원본 프레임들과 함께 Gemini에 입력
- "같은 제품/장면인가?" 판단 + 0~1 유사도 점수 + 짧은 근거
- 점수 기준 재정렬, 0.5 미만은 흐리게 표시(완전히 숨기지 않음 — 오탐 가능성 인지)

### 3-6. 소스풀 저장

- "담기" 클릭 시 새 테이블(가칭 `source_pool`)에 저장: 원본 shortcode(어떤 레퍼런스에서
  파생됐는지) + 후보 URL + 플랫폼 + 유사도 점수 + 저장 시각.
- 다음 단계(짜집기)가 이 테이블을 읽어 소스 클립 목록으로 사용 — 이번 스펙 범위 밖.

## 4. 데이터 모델 (신규)

```sql
-- 소스 영상 분석 결과 (URL 1건당 1행)
CREATE TABLE source_analysis (
  shortcode TEXT PRIMARY KEY,      -- 원본 레퍼런스 릴스
  keywords_json TEXT,              -- {"ko":[...], "en":[...], "zh":[...]}
  frames_json TEXT,                -- 프레임 파일 경로/URL 목록
  analyzed_at TEXT
);

-- 플랫폼별 수집 후보
CREATE TABLE source_candidates (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  source_shortcode TEXT,           -- source_analysis.shortcode 참조
  platform TEXT,                   -- youtube/instagram/tiktok/douyin/xiaohongshu/google_lens
  url TEXT,
  title TEXT,
  thumbnail TEXT,
  similarity_score REAL,           -- Gemini 검증 결과, NULL=미검증
  collected_at TEXT
);

-- 소스풀 (짜집기용, "담기"로 확정한 것만)
CREATE TABLE source_pool (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  origin_shortcode TEXT,           -- 어떤 레퍼런스에서 파생됐는지
  candidate_id INTEGER,            -- source_candidates.id 참조
  saved_at TEXT
);
```

## 5. API 엔드포인트 (신규)

- `POST /api/find/analyze?shortcode=...` (또는 `url=...`) — 다운로드+프레임추출+Gemini분석,
  키워드·검색링크·프레임 반환. 시간 걸리는 작업이라 BackgroundTasks 패턴 재사용 검토.
- `POST /api/find/collect?shortcode=...&platform=...` — 특정 플랫폼 실제 수집 트리거.
- `GET /api/find/candidates?shortcode=...` — 수집된 후보 + 유사도 점수 조회.
- `POST /api/find/save?candidate_id=...` — 소스풀에 확정 저장.
- `GET /api/find/frame/{id}` — 추출한 프레임 이미지 서빙(기존 `/api/thumb` 패턴).

## 6. 화면

새 페이지 `shopping_shorts/static/find.html`, 사이드바에 "제품 찾기" 메뉴 추가.

1. 상단: URL 입력창 + 분석 버튼 (기능①의 "담기"에서 넘어오면 자동 채움+분석 시작)
2. 분석 결과: 원본 영상 미리보기 + 추출 프레임 썸네일 나열 + 키워드 칩(한/영/중)
3. 플랫폼별 섹션(틱톡/인스타/유튭/더우인/샤오홍슈/구글): 검색링크 목록 + [수집] 버튼(플랫폼별 개별)
4. 수집 후: 후보 영상 그리드 — 썸네일 · 제목 · 플랫폼 배지 · 유사도 점수 · [담기] 버튼
5. 저품질(유사도 낮음) 후보는 흐리게 표시, 완전히 숨기지 않음

## 7. 알려진 리스크

- **더우인/샤오홍슈/Baidu 실수집**: 공식 API 없음, Apify 커뮤니티 액터도 안정성 낮을 가능성
  높음 — 최선노력으로 시도하되, 안 되면 검색링크만 제공(사용자가 직접 클릭해서 확인)하는
  것으로 자연 강등. 이게 기능 전체를 막지 않도록 각 플랫폼 수집은 독립적으로 실패 허용.
- **Gemini 비디오 업로드 크기/시간 제한**: 릴스는 대부분 짧아(수십 초) 문제 적을 것으로
  예상되나, File API 업로드 지연이 실제로 얼마나 걸리는지 구현 초기에 실측 필요.
- **SerpApi 비용**: 월 구독형, 사용량(검색 건수)에 따라 과금 — 초기엔 소량 테스트로 실제
  단가 확인 후 본격 사용.
- **신규 키 확보 필요**: YouTube Data API 키(무료, 사용자가 Google Cloud Console에서 발급),
  SerpApi 키(유료, 가입 필요) — 둘 다 사용자 액션 필요, 이 스펙 승인 후 안내.

## 8. 단계적 구현 순서 (계획 문서에서 세분화 예정)

1. `videoUrl` 저장 확장 + ffmpeg 설치 + 프레임 추출 함수
2. Gemini 비디오 분석(키워드 추출) + 검색링크 생성 + find.html 1차 화면(분석 결과까지)
3. YouTube Data API 연동 + [수집] 버튼(유튭만) + Gemini 검증/재정렬
4. 소스풀 저장("담기") + source_pool 테이블
5. (신규 키 확보 후) SerpApi Lens 연동, Apify 검색 액터(인스타/틱톡) 연동
6. (최선노력) 더우인/샤오홍슈/Baidu 시도
