# 쓰레드(Threads) 수집 — 핸드오프

## 무엇을 했나

쓰레드(threads.com/threads.net) 게시물을 계정 단위로 수집해 담기 재료로 쓸 수 있게 만드는
파이프라인. Task 1~7에서 수집기·이어진 글 병합·품질점수·저장(Store)·담기 메타 보강까지
코드는 전부 끝났다. Task 8은 병합 전 점검·실측 기록만 남기는 태스크였다.

**2026-08-17(2차): 레퍼런스 랭킹 탭 배선 완료** — 아래 "랭킹 탭" 절 참조.

## ★설계에서 뒤집힌 것 — 다음 세션이 반드시 알아야 함

원래 설계서(`.superpowers/sdd/2026-08-17-쓰레드수집-1-담기/`)는 "쓰레드는 로그인 세션이
필요하다"고 가정했다. **틀렸다.** 실측 결과 브라우저 헤더만 갖춘 **익명 HTTP GET**으로
데이터가 전부 온다:

- 필요 헤더: `User-Agent` + `Accept` + `Accept-Language` + `Sec-Fetch-*` 계열 + `Upgrade-Insecure-Requests`
- 실측: 200 / 1,080,480바이트 응답 / `like_count` 18 / `video_versions` 19개 / 쿠팡 링크 26개 검출
- 첫 시도가 실패했던 이유: UA만 보내고 나머지 헤더(`Accept`·`Sec-Fetch-*` 등)를 안 보냈기 때문

**→ 로그인·프록시·브라우저(Playwright)·별도 서버가 전부 불필요.** 그래도 Playwright 경로
(`_context_kw`, `dump_profile_payloads`, `fetch_video_url`)는 인스타처럼 헤더 요구가 나중에
강화될 때를 대비한 폴백으로 코드에 남겨뒀다 — 지우지 마라.

## 랭킹 탭 (2026-08-17 배선 완료)

레퍼런스 랭킹(`/`)의 🧵 쓰레드 탭이 실제로 동작한다. 커밋 `2e199a03f`.

**경위**: 옆 세션이 `c7d9cedac`에서 탭 자리만 잡고 **일부러 비활성**으로 뒀다(백엔드가
없어 누르면 깨지므로 `onclick`을 안 붙임). 이 세션이 그 배선을 이었다.

**사장님 결정**: 지표·창을 **인스타와 동일**하게 본다 — 댓글 ÷ 경과시간, 48시간.
그래서 참여합산식 `build_overseas_items`가 **아니라** 인스타와 같은 `build_items`를 쓴다.
(샤오홍슈·도우인은 조회수를 안 줘서 참여합산을 쓰는 것이고, 쓰레드는 댓글이 잡힌다)

**구조**: `service._collect_threads()` — 시드 계정 수집 → `threads_posts` → `build_items`
→ 등급 → `save_last_run_platform("threads")`.
- 수집(HTTP)과 랭킹(DB 조회)을 **나눴다**: 계정이 막힌 날도 이미 쌓인 게시물로 카드가 뜬다.
- 계정별 수집 실패를 격리한다: 하나가 막혀도 나머지 계정은 수집된다.

**실측(2026-08-17, `jiniggultem` 1계정)**: 수집 5건 전부 신규 → 카드 5건.
댓글 50건/25.3h = speed 1.98. 썸네일은 `scontent-*.cdninstagram.com`.

## 함정 (다음 세션이 또 밟지 않게)

- **헤더 하나라도 빠지면 껍데기 응답이 온다.** UA만 보내면 실패했던 것처럼, 헤더셋 전체를
  갖춰야 진짜 데이터가 온다. 헤더를 줄이는 "최적화"를 하지 마라.
- **캐러셀(여러 장 게시물)은 `carousel_media` 안에 영상이 들어있다.** 최상위 `video_versions`만
  보면 캐러셀 영상을 놓친다.
- **인스타그램 표(스키마)는 불가침이다.** 쓰레드는 인스타와 별개 소스/저장 경로로 만들었고
  인스타 쪽 코드·테이블은 건드리지 않았다.
- **yt-dlp는 쓰레드를 지원하지 않는다.** mp4 회수는 자체 HTTP/Playwright 경로로만 가능.
- **`video_url`이 담기(mix basket) 저장 경로에 안 실린다.** `_enrich_grab`이 화이트리스트
  8키만 저장하고 `mix_basket_set_meta`가 `video_url` 인자를 안 받는다. 필요해지면 호출부
  확장이 필요하다(아래 "남은 일" 4번).
- **★조용한 0건 함정 2개 (2026-08-17 배선 중 발견 — 둘 다 오류가 안 뜬다)**
  - `addSeed`(index.html)의 **기본 경로는 `kind`를 언어코드(`'ko'`)로 저장한다.** 쓰레드가
    거기로 흘러가면 `_collect_threads`의 `kind == "account"` 필터에 안 걸려 **"등록은
    됐는데 수집 0건"**이 된다. 전용 분기로 끊고 회귀 테스트
    (`test_threads_seed_saves_as_account_kind`)로 못박았다. 새 플랫폼을 붙일 때 또 밟는다.
  - `threads_posts`(posted_at·code·thumb·comments)와 `build_items`가 읽는 이름
    (timestamp·shortcode·displayUrl·commentsCount)이 **어긋난다.** 특히 `timestamp`가
    비면 `build_items`가 그 항목을 **통째로 건너뛴다**(ranking.py:47) → 조용히 0건.
    매핑은 `_threads_row_to_reel` 한 곳에만 두고 테스트로 고정했다.
- **`service.collect()`의 `if platform != "instagram": return []`는 방어벽이다** — 미구현
  플랫폼이 **유료** Apify 인스타 경로로 새는 걸 막는다. 없애지 말고 그 **위에** 분기를 얹어라.

## 수집 계정 (2026-08-18)

**246개 등록됨.** 발굴은 무료·무로그인 — 쓰레드 **검색이 비로그인으로 열린다**
(`/search?q=`). 태그 경로(`/tag/`)는 0건이니 쓰지 마라.

- ★**검색 결과로 쿠팡 여부를 판정하지 마라.** 검색 노드는 캡션이 잘려 링크가 안 잡힌다
  (실측: `living_it_tem`이 프로필 4/4 쿠팡인데 검색에선 0건). **판정은 반드시 프로필로.**
- 발굴 스크립트 패턴: 키워드 검색 → username 수집 → 프로필 방문해 검증 → 기준 통과분만
  `add_seed("threads","account",u)`. 기준은 쿠팡2+ / 품질7+가 2건+ / 영상3+ 및 반응 /
  좋아요 중앙 100+ 중 하나.

**시장 구조(실측)**: 재료성(쿠팡·영상)과 화제성(참여)이 **대체로 다른 계정에 갈려 있다.**
고참여 계정은 대개 글만 쓰고 링크가 없다. 둘 다 갖춘 계정은 검증 70개 중 2~3개뿐이었다
(`living_it_tem` 형태 — 60~80자 반응 캡션 + 영상 + 쿠팡링크. 사장님이 짚으신 포맷).
