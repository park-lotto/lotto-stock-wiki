# 사람 브레인 (Person Brain) — 태린이아빠 파일럿 설계

**작성일**: 2026-07-02
**상태**: 설계 승인 대기
**목표 사람**: 태린이아빠 (텔레그램 + 유튜브). 이후 다른 채널로 복제.

---

## 1. 목적 (Why)

특정 채널 운영자의 **매일의 사고과정·행동·결과를 모두 기록**하고, 그것을 근거로
그 사람처럼 사고하는 **질의형 제2의 브레인**을 만든다. 이렇게 물을 수 있어야 한다:

- "이럴 땐 태린이가 어떻게 할까?"
- "오늘 아침 태린이는 뭘 볼까?"
- "이 종목을 태린이는 어떻게 분석할까?"
- "지금 시장에서 태린이는 비중을 높일까 낮출까?"
- 내가 미처 생각 못한 디테일까지 그의 관점으로 보완

핵심 원칙 두 가지:
1. **기록 우선** — 그의 발언·데이터·결과를 매일 쌓아야 "실제로 뭘 하는지"를 학습한다(트랙레코드).
2. **접지된 추론** — 단순 인용을 넘어 그의 프레임워크로 새 상황을 추론하되,
   **[실제 발언]과 [프레임 추론]을 반드시 라벨로 구분**해 할루시네이션을 차단한다.

## 2. 태린이아빠가 파일럿으로 완벽한 이유

두 축의 원자재를 **모두** 이미 확보 중 (다른 채널은 대개 발언 축만 있음):

| 축 | 뜻 | 이미 있는 것 |
|---|---|---|
| 그가 **무엇을 보는가** | 분석 도구(수급오실레이터·RS·가속화·컨센·쏠림·액티브ETF) | `taerini_stock.json`(645종목)·`taerini_consensus.json` — 그의 툴킷 역설계 완료 |
| 그가 **뭐라고 말하는가** | 발언·해석·방법론 | atoms DB에 `content_type` = fact/stance/method 3층으로 추출 중 (source_name="태린이아빠 주식투자") |

지금 없는 것은 이 원자들을 **'사람' 축으로 재조립하는 레이어**뿐이다.

## 3. 목표 / 비목표 (Scope)

**목표**
- 사람 단위로 원자·데이터를 조회하는 레지스트리 + 조회 레이어
- 그의 사고 골격(철학·프레임워크·판단규칙·어휘)을 담은 브레인 페이지
- 매일 그의 사고·행동·(사후)결과를 적재하는 저널
- 접지된 페르소나 질의 엔진(온디맨드 Q&A + 아침 자동 브리핑)
- 대시보드 '브레인' 탭 소비 창구
- 처음부터 **"사람 = 설정 한 줄"** 범용 스키마 (2호 확장 대비)

**비목표 (YAGNI)**
- 파인튜닝/전용 모델 학습 (코퍼스 부족·비용·노후화)
- 실시간 자동매매·주문 연동
- 태린이아빠 외 채널 실제 등록 (파이프라인 검증 후 4단계에서)
- 새로운 크롤링 인프라 (기존 텔레/유튜브 인제스트 재사용)

## 4. 아키텍처 — 5개 구성요소

```
① 사람 레지스트리     people.json: 태린이아빠 → [텔레 source_name들, 유튜브 채널]
                      + 신뢰등급, 추적시작일, 데이터파일 연결(태린이 전용)
② 브레인 페이지        wiki/people/태린이아빠.md
   ├ [고정 뼈대] 철학 · 분석프레임워크 · 판단규칙(IF-THEN) · 어휘   ← 씨앗 수동 + 원자 승격
   └ [자동 갱신] 라이브 스탠스 · 시장자세(공/방) · 트랙레코드 · 발언로그
③ 매일 저널 기록기      day별 그의 발언·데이터·(사후)결과 적재
                      → 트랙레코드 + "이럴 땐 이렇게 한다" 규칙의 학습 재료
④ 페르소나 질의 엔진    뼈대(②) + 검색된 원자·데이터(query.py) → 그로서 답변([발언]/[추론] 라벨)
⑤ 소비 창구            대시보드 '브레인' 탭: 질문창 + 매일 아침 자동 브리핑
```

**데이터 흐름**
```
[기존] 텔레/유튜브 원자 (atoms.db, source_name) ─┐
[기존] 태린이 데이터파일 (taerini_stock.json)   ─┼→ ③매일저널 → ②브레인페이지 자동섹션
                                                 │                     ↓ (뼈대로 사용)
질문 / 아침 트리거 ─────────────────────────────→ ④질의엔진 → ⑤대시보드 답변
```

## 5. 구성요소 상세

### ① 사람 레지스트리 — `pipeline/people/people.json`

```json
{
  "태린이아빠": {
    "display": "태린이아빠",
    "sources": ["태린이아빠 주식투자"],       // atoms.source_name 목록 (텔레+유튜브)
    "youtube": ["<유튜브 채널명>"],           // youtube_registry의 source_name
    "trust": "B",
    "tracking_since": "2026-05-01",
    "data_files": ["taerini_stock.json", "taerini_consensus.json"],  // 데이터 툴킷 (태린이 전용, 선택)
    "brain_page": "wiki/people/태린이아빠.md"
  }
}
```

- 조회 헬퍼 `people_query.py`: `atoms_for(person)` = `query.run_query(..., source_name IN sources)`.
  기존 `query.py`가 `source_name` LIKE 필터를 이미 지원하므로 얇은 래퍼로 구현.
- 범용성: 다른 채널은 `data_files` 없이 `sources`만 채우면 됨.

### ② 브레인 페이지 — `wiki/people/태린이아빠.md`

| 섹션 | 성격 | 소스 | 갱신 |
|---|---|---|---|
| 0 프로필 | 고정 | people.json | 수동 |
| 1 철학/세계관 (수급빈집·주도섹터강도·대장주·"가는 놈이 더 간다") | 고정 뼈대 | 수동 씨앗 + method 원자 승격 | 드묾 |
| 2 분석 프레임워크 (도구 보는 순서) | 고정 뼈대 | 태린이 파이프라인 문서화 | 드묾 |
| 3 판단 규칙 IF-THEN (예: 수급빈집 ∧ RS상위 ∧ 컨센상향 → 탑픽) | 고정 뼈대 | method 원자 결정화 | 2단계 |
| 4 어휘/말투 사전 | 고정 뼈대 | 원자 빈출어 | 드묾 |
| 5 라이브 스탠스 (현재 포지션·관심종목) | 자동 | stance 원자 최신 (is_active) | 매일 |
| 6 시장자세 시계열 (공격/방어/현금) | 자동 | 종합 톤·강조신호 추론 | 매일 |
| 7 트랙레코드 (과거 콜 + 결과) | 자동 누적 | 저널(③) | 사후 |
| 8 발언 로그 | append | 원자 | 매일 |

- 1~4 = 정지된 "뇌 골격" → 질의 엔진의 시스템 프롬프트가 됨.
- 5~8 = 매일 자동. 1단계에서는 5·8만 자동, 6·7은 이후 단계.
- 자동 섹션은 마커(`<!-- AUTO:live_stance -->…<!-- /AUTO -->`) 사이만 갱신 → 수동 뼈대 보존.
  (위키-종합엔진 교훈: 페이지 통째 재작성 금지, 섹션 타겟 갱신.)

### ③ 매일 저널 기록기 — `pipeline/people/journal.py`

- 매일 `people/journal/태린이아빠/YYYY-MM-DD.json` 생성:
  - `said`: 그날 원자(발언) 요약
  - `data`: 그날 그의 데이터파일이 가리킨 것 (탑픽·빈집·RS상위 등)
  - `outcome`: (T+N일 사후 채움) 언급 종목의 실제 주가 반응
- 트랙레코드(⑥⑦)와 판단규칙(③섹션) 결정화의 학습 재료.
- **1단계 제외**, 3단계에서 구현. 단, 원자에 이미 date가 있으므로 소급 생성 가능.

### ④ 페르소나 질의 엔진 — `pipeline/people/persona.py`

```
answer(person, question):
  skeleton   = 브레인페이지 섹션1~4 로드 (철학·프레임·규칙·어휘)
  context    = people_query.atoms_for(person, question, hybrid, days=N)   # 관련 발언
  data       = 질문에 종목 있으면 taerini_stock.json에서 해당 종목 지표 추출
  posture    = 브레인페이지 섹션6 최근 시장자세
  → LLM(Gemini/Claude) 프롬프트:
     "너는 {person}이다. 아래 골격대로 사고하라. 근거 원자/데이터만 사용.
      실제 발언은 [발언], 프레임 기반 추론은 [추론]으로 라벨. 근거 없으면 '모른다'."
  → 답변 + 인용된 원자 id/데이터 출처
```

- **접지 규칙**: 모든 문장은 (a)검색된 원자 (b)데이터파일 수치 (c)명시된 프레임워크 규칙 중 하나에 근거.
  근거 없는 단정 금지. 인용 표기 필수 (당신 채널 차별점 "요약이 아니라 추출").
- **라벨링**: `[발언] 그는 6/30 조선 비중확대 언급` vs `[추론] 그의 '주도섹터강도' 원칙상 RS 1위 조선은 유지 가능성`.
- 모델: 기존 파이프라인이 Gemini flash 계열 사용 → 질의엔진은 판단 품질 위해 상위 모델 고려(설정값).

### ⑤ 소비 창구 — 대시보드 '브레인' 탭

- `dashboard/brain.html` + `server.py`에 `/api/brain/ask`(질문→④), `/api/brain/{person}`(브레인페이지 렌더), `/api/brain/brief`(아침 브리핑).
- 아침 브리핑 = ④를 고정 질문셋("오늘 무엇을 볼까/비중/관심종목")으로 자동 실행 → 카드. 스케줄러 등록(기존 07:xx 라인).

## 6. 시장자세(공/방) 도출 — 섹션6

"비중 높일까/낮출까" 질문 대응. 그의 발언 원자의 signal 분포(bullish/bearish/risk)와
강조 신호(현금·헤지·비중 언급)를 날짜별 집계 → 공격/중립/방어 3단계 시계열.
질의 시 최근 추세로 답. **2단계 이후** (1단계는 raw 스탠스만).

## 7. 단계별 구현 (쓸모부터 검증, 과설계 금지)

| 단계 | 산출물 | 검증(쓸모) 게이트 |
|---|---|---|
| **1 (MVP)** | ① 레지스트리 + `people_query.py` + ② 브레인 페이지(뼈대 수동 씨앗 + 섹션5·8 자동) | 이 페이지 읽어서 실제로 쓸모 있나? |
| **2** | ④ 질의 엔진 + ⑤ 대시보드 질문창 (온디맨드) + 섹션3(판단규칙)·6(시장자세) | "이 종목 어떻게 볼까" 답이 그럴듯·접지되나? |
| **3** | ③ 매일 저널 + 섹션7 트랙레코드 채점 + 아침 자동 브리핑 | 콜 적중률·자동 브리핑 유용한가? |
| **4** | 2호 사람 등록으로 범용 스키마 검증 | 발언만 있는 채널에도 되나? |

각 단계는 게이트 통과 후 다음 단계. MVP가 안 쓸모면 재설계.

## 8. 테스트 전략

- `people_query.atoms_for` — 알려진 source_name으로 원자 반환 개수·필터 단위테스트.
- 브레인 페이지 자동 갱신 — 마커 사이만 교체, 수동 뼈대 보존 검증(골든 픽스처).
- 페르소나 접지 — 근거 없는 질문에 "모른다" 반환하는지, 인용 id가 실제 원자인지(존재 검증).
- 라벨 규칙 — 출력에 [발언]/[추론] 태그 존재 및 [발언]은 실제 원자와 대조(quote 대조, 기존 verify 패턴 차용).

## 9. 리스크 & 완화

| 리스크 | 완화 |
|---|---|
| 페르소나 할루시네이션 | 접지 규칙 + 인용 필수 + [발언]/[추론] 라벨 + "모르면 모른다" + quote 대조 테스트 |
| 페이지 통째 재작성 파괴 (종합엔진 전례) | AUTO 마커 섹션만 갱신, 수동 뼈대 불변 |
| 원자 데이터 지연 → 낡은 답 | 질의 시 최신 데이터 한계 명시(DB 최신일자 표기), days 필터 |
| 과설계 | 단계 게이트, MVP=수동 씨앗+최소 자동 |
| 태린이 데이터파일 개편 | 기존 파이프라인이 이미 대응(mybox_links.json), 레지스트리 참조만 |

## 10. 미결 질문 (구현 전 확인)

1. 유튜브 태린이아빠 채널의 정확한 `source_name` (youtube_registry.json 확인 필요).
2. 페르소나 엔진 모델: Gemini flash(무료·빠름) vs 상위 모델(판단품질) — 설정값으로 두고 기본값 결정.
3. 아침 브리핑 고정 질문셋 문구 (사용자 큐레이션).
```
