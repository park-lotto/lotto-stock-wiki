1Jev가 뭔가

글을 쓰지 않는 AI — "판단"만 확률로 돌려줍니다.

상황(state)과 객관식 질문(questions)을 주면 답을 확률로 줍니다. "이 뉴스는 어느 섹터?", "이 첫 줄은 몇 점?", "이 댓글이 악플일 확률은?"처럼 사람이 10초 안에 답할 수 있는 판단을 0.2~0.5초에, 매우 싸게 처리합니다.

4기본 코드 (공식 예제)

from typesafe_sdk import Choice, Noul, Score, TypeSafeClient

with TypeSafeClient(model="jev-latest") as client:   # TYPESAFE_API_KEY 를 자동으로 읽음
    r = client.system_one(
        state={"ticket": "API가 20분째 500에러, 주문 처리가 안 됨"},
        questions={
            "team":   Choice(instructions="Which team should handle `ticket`",
                             criteria={"billing": "결제", "technical": "버그·연동", "sales": "가격·계정"}),
            "anger":  Score(instructions="How frustrated the customer appears",
                            criteria=["Calm", "Frustrated but civil", "Very angry"]),
            "urgent": Noul(instructions="The message conveys urgency"),
        },
    )
print(r.choices["team"].choice, r.scores["anger"].score, r.nouls["urgent"].noul)
  • 질문 여러 개를 한 번에 묶어 보내세요 — 공식 예제: 13문항을 묶으면 따로 보낼 때보다 12.2배 싸고 10배 빠름.
  • state 안의 항목은 지시문에서 `ticket`처럼 백틱으로 가리킵니다.
  • 공식 응답 예: 팀 = technical(확신 1.0), 화남 점수 0.67/2, 긴급 확률 0.99.

5잘 쓰는 법 — 공식 원칙 + 영상 공통 조언

  1. 코드가 주인, Jev는 판단 한 칸만. 계산·개수 세기·날짜 비교·정확한 검색은 코드로 합니다 (공식 "약점 목록" 9가지).
  2. 질문 하나 = 판단 하나. 여러 판단을 한 질문에 숨기지 말고, 점수 단계는 구체적인 상황으로 적습니다.
  3. "해당 없음" 보기를 꼭 넣으세요. 보기에 없는 답은 고를 수 없습니다.
  4. 확신도로 갈라 쓰세요. 높으면 자동 처리, 낮으면 사람이나 큰 모델로 넘깁니다.
    Tech With Tim 실측(은행 문의 1,000건): 확신도 0.95 이상(약 60%)은 95.8% 정답.
  5. state에는 필요한 것만. 관계없는 내용이 많을수록 정확도가 떨어집니다.
  6. Choice 보기 순서를 바꿔 다시 물어보세요. 1.13은 첫 번째 보기 쪽으로 기우는 경향이 있습니다(공식).
  7. 에이전트 대화 안에서 실시간으로 부르지 말고 묶음 처리·예약 실행·전용 프로그램으로 — 메인 AI가 느려서 Jev의 속도 이점이 사라집니다(시민개발자 구씨).
한국어가 약합니다. 공식 문서: "영어가 주력, 한중일 언어는 직접 시험해보라". 영상: 한국어 반어("2주 만에 왔어요, 최고")를 '만족'으로 오판, 한국어 고유명사에 약함.
→ 지시문·기준표는 영어로, 내용(state)만 한국어로 시작하고, 우리 데이터로 정답을 아는 묶음을 만들어 먼저 재보세요.
