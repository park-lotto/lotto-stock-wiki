## 1. 설계 원칙 — "어떤 누가 와도 우리 것보다 좋을 수 없게"

경쟁 도구(볼케이노 등)는 **한 채널 꼴을 손으로 옮긴 템플릿**이다. 우리가 이기는 길은 템플릿 수가 아니라 아래 다섯 가지 **구조**다. 프리셋을 하나 더 만들 때마다 다섯이 전부 돌아야 한다.

1. **센 것만 넣는다(k/n).** 모든 "넣는 규칙"(자막 모션·전환·효과음·짤·스티커·배경음·썸네일)은 벤치 n편에서 k번 본 **빈도와 조건**으로 적힌다. 느낌·단정 금지. 표본 n<5 는 등급 '표본부족'으로 적고 **판 설정에 못 들어간다**(규칙빈도.json `min_n` 5 — `kal_analyze.rules_of`).
2. **판단 하나 = 함수 하나(0순위-B·C).** 배치 `placement.place` · 시각 `render_bench.timeline` · 썸네일 `thumb_rule`·`thumb.cards` · 1차 자 `kal_analyze.match_table` · 관문 `quality_gate.gate`(§5, 새로 만든다) · 형식↔판↔회원 `channel/프리셋.json`. 화면·렌더·캡컷·회원 PC 는 이 함수를 **부른다**. 채널마다 다시 적으면 설계 실패.
3. **1차 = 벤치 100%(자로 판정) → 업그레이드 = 벤치보다 나은 **측정값**.** 두 단계가 다 자동 자를 가진다(§4). 측정값 없는 "더 낫다" 금지.
4. **관문은 2단, 둘 다 통과해야 나간다.** ①자동 `quality_gate`(기계가 재는 전부) ②눈 검수 기준표(페이블 = 사장님 눈의 대리인 — 기계가 못 재는 것만, 항목 번호로). 하나라도 ✗면 **회원에게 안 나간다**(flow.py check 단계가 gate 를 부른다).
5. **회원 경로 = 우리 PC 경로.** 같은 판 설정·같은 렌더러·같은 관문·같은 지시서(`flow.py`). 우리 PC 에서 사람이 손으로 한 판단이 생기면 **같은 커밋에** flow.py 질문·runner_ops 명령으로 들어간다(루트 CLAUDE.md 🧩). 손 판단이 코드에 없으면 회원 결과물은 우리 것과 다르다 — 그게 지금 선우용여 1차(10-21)가 틀린 이유였다.

## 3. 엔진 통일 기준 — 공용 렌더러 1벌 + 판 설정 1칸

### 3-1. 원칙
- **입구 하나**: `tools/calcopy/hybrid/run.py <키> render --version <판>` (회원 PC 는 `runner_ops` render → 같은 `render_bench.render`). 새 채널에 렌더 스크립트를 만드는 것은 **설계 실패**(지침서 §10 10-23). 편 폴더 `make_plan.py`·채널 `render_*.py` 는 **읽기 전용 참고물**로 두고 `_deprecated_<날짜>` 표식을 머리말에 넣는다(지우지 않는다 — 옛 영상 재현용).
- **렌더러 칸 `renderer`**: `bench`(공용, 목표) · `make`(`engine/preset_make` — 나레만·게시글형 틀의 옛 길, manifest `channel_rules.make` 를 가리킨다) · `itssum`·`jaemi`(옛 두 판, 동작 그대로). **새 판은 `bench` 만.** `make`·`itssum`·`jaemi` 는 §3-3 결손 B1 이 끝나면 `bench` 로 바꾸고 칸을 없앤다.
- **손 스크립트의 규칙은 판 칸으로**: 손 스크립트 안의 상수(컷 길이·쉼·BGM dB·효과음 자리·짤 비율·틀 좌표)를 전부 뽑아 `styles/<판>.json` 칸으로 옮기고, 옮긴 줄마다 `why`(근거 편·실측)를 적는다. 판 스키마에 칸이 없으면 **스키마 주인(관제 235·`styles/README.md`)에게 칸을 요청**하고 그동안은 `_pending` 칸에 적어 둔다(렌더러는 `_pending` 을 읽지 않는다 — 조용히 쓰는 것 금지).

### 10-3. 규칙 ② 회원 맞춤 = 팩 항목 교체 **패치**, 프리셋 원본은 안 바뀐다
- **패치 꼴** `channel_patch = {"packs": {...}, "frame": {"logo": …, "channel_name": …}, "voice": {...}}` — 판 설정과 **같은 키 경로만** 허용(허용 목록 = `styles/README.md` 의 '회원 변경 허용 칸' 표: packs.*·voice·frame.logo/credit/채널명·bgm·length 범위 안 · 뼈대 칸(§5-1 placement.rules·counted·script·cuts·timing)은 **금지** — 1차 뼈대는 프리셋의 것).
- **주인 함수** `tools/calcopy/hybrid/styles.py:apply_patch(style, patch) -> style`: 깊은 복사 뒤 허용 키만 덮고, 금지 키·없는 팩 항목은 거절(`PatchError`, 조용한 무시 금지). 렌더러·검사·카드가 **전부 이 함수를 거쳐 나온 style** 만 받는다(`styles.load(판, patch=…)`). 얕은복사로 원본 dict 가 바뀌는 사고(메모리 `프리셋_얕은복사_원본오염`) → 시험이 "두 번 apply 해도 원본 sha 같음"을 단언한다.
- **저장 자리**: 회원 PC `~/.shortem/settings.json channels[pid].patch`(`local_settings.savePack` 과 같은 자리·같은 원칙 '바꾼 칸만', 이름을 `pack`→`patch` 로 통일) → 제작 때 `preset_rent` 꾸러미 옆에 `patch.json` 으로 엔진에 넘김 → 서버는 **요약만**(패치 키 목록·sha, 값 본문 저장 안 함).
- **채팅 → 패치 길**(flow `customize` 단계, 지시서 12): 프리셋 고른 뒤 `sign` 전에 서버 지시서가 묻는다 — "우리 채널은 ~"(톤·색·로고·목소리·배경음 분위기) → 회원 Claude 가 `pack_map.suggest(style, text)` 로 **팩 항목 후보 3개**(미리보기 그림 = 팩 화면 `shortem_packs.html` 의 공식 미리보기 함수)를 보여 주고 → 고른 것을 patch 로 저장 → 렌더. 완성본이 마음에 안 들면 `customize` 로 되돌아가 **팩에서 다시 고르기** → 다시 렌더(재합성 비용은 바뀐 칸만 — 목소리 안 바꿨으면 TTS 캐시 그대로). 볼케이노 MCP 의 `customize/customization_patch` 와 같은 자리 개념.
- **관문 불변**: 패치를 입혀도 §5 관문은 그대로 — 1단 전부 통과 + 1차 자 **뼈대 칸** ✓(겉모양 칸은 패치로 달라질 수 있으니 '패치 적용 판' 으로 framecmp 기준을 바꿔 잰다). 관문이 ×면 "그 팩 항목으로는 안 됩니다 — 이유" 를 돌려주고 patch 를 되돌린다.
- **같은 판단 두 벌 방지**: 회원 패치 저장·합치기는 `local_settings`(PC) + `styles.apply_patch`(엔진) 두 층이지만 **합치는 규칙은 엔진 한 곳**(PC 는 저장과 전달만, 합치지 않는다 — 지금 `packFor` 의 merge 를 엔진 `apply_patch` 호출로 바꾼다).

## 12. 벤치 초과 설계 — 장면↔대사·효과 밀도·말속도를 벤치 상위 편 위로 (사장님 목표의 실행 구조)

### 12-1. 왜 지금 벤치 이하인가(ep13 실측, 10-25)
- **장면↔대사**: 재료(`재료.json cuts`)를 사람이 `see` 한 줄로 고르고, **렌더 전에 점수를 내는 함수가 없다**(`material_auto.fit_judge` 는 preset_make 길·완성본 `scene_fit` 은 사후). 벤치는 편집자가 대사에 맞는 장면을 **원본 여러 개에서** 고른다(7.55).
- **효과 밀도**: 1차 판은 '전체 중앙'을 베끼므로(꾸밈 54/55 없음) 상위 편보다 심심하다 · `rules.sfx` 없음(⑮).
- **말속도 편차**: 줄 글자 수가 들쭉날쭉한 대본을 배속 상한 1.25 안에서 못 편다.

### 12-2. 원칙 — "업그레이드 판의 목표값 = 벤치 **상위 편**(조회 상위 50%) 분포의 **좋은 쪽 사분위**"
1차 판 = 전체 중앙(100% 같게). 업그레이드 판 = 축마다 상위 편 분포에서 **더 잘된 쪽 25% 지점**(fit 은 높은 쪽·7미만 비율은 낮은 쪽·꾸밈/효과음 밀도는 상위 편 p75·cps 편차는 낮은 쪽 p25)을 **판 칸의 목표값**으로 적고(`targets{axis: {bench_top_q, ours_goal}}`, `upgrade_table` 이 읽음), 엔진은 그 목표를 **렌더 전 계획 단계에서** 맞춘다(사후 측정이 아니라 계획 루프). 목표를 넘어도 상위 편 **최대값은 넘지 않는다**(과다 = 정신없음, B14).

### 12-4. 효과 밀도·말속도 — 상위 편 목표(지시서 15)
- **효과음·꾸밈**: `placement.place` 가 업그레이드 판에서는 `counted` 전체 중앙 대신 **상위 편 묶음**(`counted.top_ids`, 조회 상위 50%) 의 p75 를 목표 밀도로 — 종류·조건은 1차 규칙 그대로(뼈대), **양만** 상위 편 쪽으로. 상한 = 상위 편 최대. `rules.sfx`·`rules.enter` 가 없으면 place 가 **경고**(0발을 조용히 내지 않는다 — ⑮ 재발 방지).
- **말속도 편차**: ⓐ 대본 audit 규칙 `tts_cps_spread`(줄별 예상 cps = 글자/예상 초 의 변동계수 ≤ targets.speech.spread, 벤치 상위 p25) — 대본 단계에서 글자 수를 고르게 ⓑ 렌더는 타입캐스트 목소리에 한해 줄별 ±8% 미세 보정(배속 상한 1.25 안, 미나 고정 배속은 손대지 않음) ⓒ render_info 표로 gate 가 확인(⑤).
- **훅 3초**: 상위 편의 첫 컷 길이·0초 얼굴/물건 비율·첫 효과 시각을 targets 에 — `thumb_rule`·placement 가 읽는다.

### 12-5. 벤치 상위 편 재측정(같은 자) — 지시서 14·15 의 전제
벤치 fit·밀도·cps 편차는 지금 줄판독 칸(눈 점수)이다. 업그레이드 비교는 **우리와 같은 함수**로 벤치 완성본을 다시 잰다: `scene_fit.judge_rubric`(벤치 src + 줄판독 줄) · `placement.count` 상위 편 묶음 · `kal_analyze script_of` cps 편차 → `channel/<slug>/_kal/상위편_목표.json`(targets 의 출처, 편 id·조회·값). 06 이 끝난 채널부터.
