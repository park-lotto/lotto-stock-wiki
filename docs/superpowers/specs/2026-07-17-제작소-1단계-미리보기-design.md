# 제작소 1단계 — 영상 미리보기 게이트 (설계)

**날짜**: 2026-07-17 · **트랙**: 대본믹스통합 · **상태**: 사장님 승인됨

---

## 1. 문제

영상 제작소 1단계에서 "영상 매칭 시작"을 누르면 **편집안(텍스트)만** 나온다:

```
편집안(장면 매칭)
  [intro]   초등 교사 친구가 알려준 놀이인데…  · s0 · 4s~6s · 매칭 3/5
  [process] 식초에 물감 섞어 비닐에 담고…      · s1 · 6s~9s · 매칭 4/5
```

사장님 지적: **"미리보기를 안 해보고 넘길 수는 있는데 상식적으로 잘 되었는지 뭘 보고 그걸 다음 단계로 넘기겠나. 돈 내고 만드는 사람들인데."**

이 텍스트만 보고 "컷이 잘 붙었나"를 판단할 방법이 없다. 그런데 **다음 단계(자막제거)는 VMake 유료 API**다.
컷·대본이 틀린 채로 넘어가면 그 돈이 그대로 날아간다.

현재 렌더는 **파이프라인 맨 끝에만** 있다 — `run_render`가 자막제거·자막굽기·꾸미기를 한 번에 하고 끝낸다.
화면 안내문도 그렇게 못박혀 있다: *"다음으로 자막제거·음성 확인 후 마지막에 렌더합니다."*

## 2. 목표

1단계 끝에 **0원짜리 미리보기**를 넣고, **그걸 봐야만 다음으로 넘어가게** 한다.

## 3. 핵심 통찰 — 이미 쪼개져 있다

`video_assemble.assemble()`이 정확히 3토막이다:

```python
def assemble(edit_plan, tts_paths, source_video_paths, out_path,
             clean_fn=None, headcopy=None, caption_style=None, deco=None):
    mix_raw   = _render_mix(edit_plan, tts_paths, source_video_paths, work)   # 1) 믹스(우리자막X)
    base      = clean_fn(mix_raw) if clean_fn else mix_raw                    # 2) 자막제거(선택)
    return _burn_captions(base, edit_plan, tts_paths, out_path, work,         # 3) 우리자막 굽기
                          headcopy, caption_style, deco)
```

**`clean_fn`과 `deco`가 이미 선택 파라미터다.** 미리보기는 그냥:

```python
assemble(plan, tts_paths, sources, preview_path, clean_fn=None, deco={})
```

→ `_render_mix` + `_burn_captions`만 돌아 **믹스 + 음성 + 기본자막**이 나오고,
**유료 VMake 단계만 쏙 빠진다. 새 파라미터 불필요.**

## 4. 단계 배치 (확정)

| 단계 | 렌더 | 비용 | 사장님이 판단하는 것 |
|---|---|---|---|
| **1 제작소** | `assemble(clean_fn=None, deco={})` | **0원** | **믹스·대본·기본자막이 말이 되나** |
| **2 자막제거** | `assemble(clean_fn=VMake)` | 💰 유료 | 원본자막 지우고 자막 재굽기 |
| **3 TTS** | — | | 목소리 교체 |
| **4 꾸미기** | `deco` | | BGM·모션·오버레이 |

### 4.1 왜 1단계에 "기본 자막"을 넣나 (설계 논쟁 기록)

Claude의 최초 제안은 **"1단계에서 자막을 빼자"**였다. 근거: `run_render` 주석이
*"자막제거는 우리 자막을 굽기 전 깨끗한 믹스에 돌려야 우리 자막이 함께 지워지지 않는다"*라고 명시하듯
**원본자막 제거와 우리자막 굽기는 한 몸**이고, 원본자막이 살아있는 화면에 우리자막을 얹으면 **두 겹**이 된다.

**사장님 논리가 이겼다**: 두 겹은 *지저분할 뿐 공짜*고, VMake는 *깨끗하지만 유료*다.
미리보기의 목적은 "예쁜가"가 아니라 **"돈 쓸 가치가 있나"**를 판단하는 것이므로 공짜 쪽이 맞다.
컷·대본·자막이 맘에 안 들면 VMake 돈이 **아예 안 나간다**.

→ 1단계 미리보기는 **두 겹을 감수한다**(원본자막 위에 우리자막). 이건 결함이 아니라 **의도된 트레이드오프**다.
2단계가 어차피 깨끗한 믹스에 자막을 다시 굽는다.

### 4.2 음성 — 넣되 음소거가 기본

**넣는다.** `_render_mix`가 TTS를 **컷 길이의 원천**으로 쓰기 때문이다:

```python
tts = tts_paths.get(idx)
if not tts:
    continue                 # ← TTS 없으면 그 비트를 통째로 건너뛴다
tts_dur = _probe_duration(tts)
...
"-t", str(tts_dur),          # ← 컷 길이가 TTS 길이에서 나온다
```

`tts_paths`를 비우면 **모든 비트가 스킵돼 영상이 아예 안 나온다.** 무음으로 하려면 `silent` 파라미터를
새로 만들어야 한다 — **무음이 더 쉬운 게 아니라 더 어렵다**(Claude가 처음에 반대로 말했다가 코드 보고 정정).
게다가 TTS는 `run_mix_job`이 `ready_for_review` 전에 이미 만들어두므로 **추가 비용 0**이다.

**`<video controls muted>`** — 열면 조용하고, 타이밍을 보고 싶으면 사장님이 소리를 켠다.
"1단계는 영상 믹스만 본다"와 "음성이 있어야 타이밍이 보인다"를 **둘 다 만족**한다.

## 6. 백엔드

### 6.1 상태 — 기존 `status`를 건드리지 않는다

`mix_jobs.status`는 `downloading → extracting → planning → tts → ready_for_review → rendering → done`
한 줄기다. 여기에 preview를 끼우면 **최종 렌더와 상태가 뒤엉킨다**(둘 다 "rendering"이 되어 폴링이 서로를 오인).

→ **별도 컬럼 2개**: `preview_status TEXT` · `preview_path TEXT`.
`preview_status` = `null | rendering | ready | failed`.

기존 `update_mix_job`은 허용 컬럼을 **화이트리스트**로 받는다(`store.py:1228`의 `for k in ("status", "error",
"video_path", "clean_video_path")`). 여기에 두 컬럼을 추가하지 않으면 **`update_mix_job(preview_status=...)`이
조용히 무시된다** — 에러도 안 나고 저장만 안 된다. 이 화이트리스트가 이 배선의 함정이다.

`mix_jobs`는 `CREATE TABLE IF NOT EXISTS`라 **기존 DB에는 컬럼이 안 생긴다** → `ALTER TABLE` 필요.
**이미 이 저장소에 선례가 6건 있으므로 그 패턴을 그대로 따른다**(새로 발명하지 말 것 — `store.py`에서
`ALTER TABLE`을 grep해 기존 방식 확인).
서버 DB(`shopping_shorts/data/reference.db`)에 **이미 실 job 행이 있다** → 마이그레이션이 실제로 도는지가 검증 대상.

### 6.3 라우트 2개 (app.py 신규)

- `POST /api/produce/mix/preview` `{job_id}` → BackgroundTasks로 `run_preview` 예약 → `{ok, status:'rendering'}`
  - `edit_plan` 없으면 422("매칭 먼저").
  - 이미 `preview_status=='rendering'`이면 중복 예약 안 함(더블클릭 방어).
- `GET /api/produce/mix/preview/{job_id}` → `FileResponse(preview_path)` (`media_type="video/mp4"`)
  - 없거나 준비 전이면 404.

> ⚠️ **라우트 접두사가 이 저장소에서 일관되지 않다**(실측): 상태·결과는 `/api/mix/status/{job_id}`·
> `/api/mix/result/{job_id}`인데 나머지는 `/api/produce/mix/*`(start·poster·settings·bgm·overlay)다.
> 신규 preview 라우트는 **`/api/produce/mix/poster/{job_id}`를 선례로 삼아** `/api/produce/mix/preview/*`로 간다
> (job의 미디어 파일을 서빙한다는 점에서 poster와 같은 성격). 기존 라우트 이름은 건드리지 않는다.

`preview_status` 폴링은 **기존 `GET /api/mix/status/{job_id}`가 이미 job을 읽으므로**(`app.py:1249`,
프론트 `pollMix`가 이미 씀) 그 응답에 두 필드를 실어 보낸다.
**새 폴링 라우트 신설 금지** — 폴러가 둘이 되면 서로를 오인한다.

## 7. 프론트 (produce.html)

- `loadMixReview()` 끝에 **[▶ 미리보기 만들기]** 버튼 + `#mixPreview` 컨테이너 추가.
- 버튼 → `POST /api/produce/mix/preview` → 기존 `pollMix` 패턴으로 `preview_status` 폴링
  → `ready`면 `<video controls muted src="/api/produce/mix/preview/{job}?t={ts}">` 렌더.
  - `?t=` 캐시버스터 필수: 대본을 고쳐 재매칭하면 같은 URL에 다른 영상이 온다.
- **게이트**: `preview_status !== 'ready'`면 `다음` 버튼 `disabled` + 사유 문구.
- 현재 안내문 *"다음으로 자막제거·음성 확인 후 마지막에 렌더합니다"* → 새 흐름에 맞게 고친다
  (안 고치면 화면이 거짓말을 한다).

### 7.1 렌더 실패 시 탈출구

`preview_status === 'failed'`면 에러를 보여주고 **"미리보기 없이 진행"을 한 번 열어준다.**
ffmpeg 문제 하나로 사장님이 영영 갇히면 안 된다. 이건 "그냥 건너뛰기"가 아니라 **고장 시 탈출구**다
— 정상 경로에선 절대 안 뜬다.

## 8. 검증 (구현 계획이 반드시 포함할 것)

이 저장소는 **"통과하는데 결함을 못 잡는 테스트"가 반복해서 나왔다**. 태스크마다 뮤테이션을 돌린다.

- **게이트가 진짜 잠그나**: `preview_status`를 `ready`가 아닌 값으로 두고 `다음`이 disabled인지.
  뮤턴트(게이트 조건 제거)로 죽는지 확인.
- **`clean_fn=None`이 실제로 VMake를 안 부르나**: 이게 이 설계의 존재이유다.
  `subtitle_removal=1`인 job에서도 미리보기는 VMake를 **안** 불러야 한다 — 뮤턴트로 검증.
- **기존 `status` 오염 없음**: 미리보기를 돌려도 `status`가 `ready_for_review`에 머무는지.
- **마이그레이션**: 컬럼 없는 기존 DB에서 실제로 `ALTER TABLE`이 도는지(서버 DB에 실 데이터 있음).
- **라이브 grounding**: 실제 job으로 미리보기를 눌러 **화면에서 영상이 재생되는지**.
  테스트 통과는 동작의 증거가 아니다 — 이 저장소에서 여러 번 증명됐다.

## 9. 범위 밖

- **꾸미기(`deco`)** — 4단계 소관. 미리보기에 넣지 않는다.
- **자막 스타일 편집** — `caption_style` 기본값만 쓴다. 스타일 UI는 이 설계에 없다.
- **최종 렌더(`run_render`) 변경** — 건드리지 않는다.
- **"봤는지" 추적** — 재생 완료 감지 등. YAGNI.
- **미리보기 자동 생성** — 버튼으로만. 매칭이 망한 경우에도 렌더를 돌려 시간을 버리게 된다.
- **`_render_mix`에 `silent` 파라미터** — 음소거는 프론트 `muted`로 충분하다.

## 10. 이 설계에서 Claude가 두 번 틀린 것 (기록)

1. **"1단계에서 자막 빼자"** — 두 겹을 피하려 했으나, 유료 API 낭비가 더 큰 제약이었다.
   사장님이 뒤집음. **비용 제약이 미관 제약을 이긴다.**
2. **"무음이 렌더가 조금 빠르다"** — 근거 없는 추측이었다. 코드를 보니 TTS가 컷 길이의 원천이라
   **무음이 오히려 손이 더 간다.** 추측으로 선택지를 제시하면 사장님이 틀린 정보로 결정하게 된다.

또 하나: **"다음 버튼 안 막기"를 추천**했으나 사장님이 *"뭘 보고 다음 단계로 넘기겠나"*로 뒤집음.
개발자 편의(코드 단순)로 생각했고, 제품 관점(돈 내는 사용자)이 옳았다.
