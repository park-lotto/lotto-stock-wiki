# 설계 — 유튜브 카테고리 프리셋 키워드 수집 (딸깍 수집)

**날짜**: 2026-07-25
**대상**: `shopping_shorts/`
**상태**: 설계 승인됨(구두) → 스펙 검토 대기
**트랙**: 유튜브채널수집 (선행 "채널기반 수집" 위에 얹음)

## 1. 목적 / 배경

레퍼런스 랭킹 유튜브는 **키워드 시드**로 인기 Shorts를 발굴해 조회수 랭킹을 만든다(라이브).
하지만 지금은 사용자가 **키워드를 직접 쳐서 등록**해야 한다. 문장 통째로 넣으면 0건이 나고
(실측: "주방 기름때 한가지로…" → 0건), 짧고 좋은 키워드를 사람이 매번 고르는 건 번거롭다.

사장님 요구: **키워드를 안 치고 딸깍 한 번에** 카테고리별 인기 Shorts를 조회수 랭킹으로 보고 싶다
(인스타 레퍼런스가 등록된 400여 채널로 쫙 채워지듯). 3가지 모드:

1. **전체 딸깍**: 「지금 수집」 → 모든 카테고리 프리셋 키워드를 한 번에 → 조회수 랭킹
2. **카테고리별 딸깍**: 카테고리 선택 후 수집 → 그 카테고리 프리셋만
3. **개별 검색어**: 수동 키워드도 필요할 때 그대로

**실측 근거(2026-07-25)**: 서버 유튜브 실키 10개 확인. 짧은 키워드는 잘 나온다 —
`살림꿀팁`→8건(1위 225만뷰) / `다이소추천`→8건(208만뷰) / `자취요리`→8건(109만뷰).
즉 기구는 완성돼 있고, **좋은 키워드를 코드에 내장(프리셋)** 하면 딸깍이 된다.

## 2. 카테고리 체계 (기존 그대로 재사용)

UI 버튼 key(`index.html` `CTYPES`) = 백엔드 유형. 프리셋 키는 이 key와 1:1:

| key | 라벨 | 백엔드 topic(categorize) |
|---|---|---|
| `홈템` | 🏠 홈·살림템 | 홈템 |
| `비법형` | 🔥 비법·꿀팁형 | 레시피 |
| `제품형` | 🛒 제품추천형 | 가전 |
| `혼합형` | 💄 뷰티 | 뷰티 |
| `기타` | 📦 기타 | 기타 |

## 3. 프리셋 데이터 (신규, 코드 내장)

신규 파일 `shopping_shorts/youtube_category_presets.py`:

```python
CATEGORY_KEYWORDS = {
    "홈템":   ["살림템", "주방템", "정리수납", "생활꿀템", "청소템"],
    "비법형": ["살림꿀팁", "청소꿀팁", "요리꿀팁", "자취꿀팁", "생활꿀팁"],
    "제품형": ["다이소추천", "쿠팡추천", "주방용품", "살림추천템"],
    "혼합형": ["뷰티꿀팁", "메이크업", "화장법", "다이소뷰티"],
    "기타":   ["자취요리", "냉장고정리", "집꾸미기"],
}
```

- 키워드는 **초안** — 수집해보고 사장님이 조정(코드 한 줄). v1은 한국어만(lang=ko).
- 편집 UI·언어별 프리셋·카테고리별 개수조절은 **범위 밖**(YAGNI).

## 4. 아키텍처 — 기존 키워드 경로 재사용

프리셋은 "코드에 박힌 키워드 목록"일 뿐이다. 기존 `search_shorts`(lang=ko) 경로로 그대로 흘린다.
선행 채널기반 수집이 만든 병합·중복제거 파이프라인을 그대로 탄다.

```
collect(platform="youtube", categories=?)
  _collect_youtube(categories)
    ├ 프리셋 키워드(스코프) : categories=None → 전체 union / ["혼합형"] → 뷰티만
    ├ 수동 키워드 시드      : store.list_seeds 중 kind=언어코드/keyword (기존)
    ├ 계정 시드            : fetch_channel_shorts (기존)
    └ raw 병합 → video_id 중복제거(기존) → build_youtube_items → apply_grades → save
```

**스코프 규칙**:
- `categories=None` → 프리셋 전체(모든 카테고리 union) = "전체 딸깍"
- `categories=["혼합형"]` → 그 카테고리 프리셋만 = "카테고리별 딸깍"
- 두 경우 모두 **수동 키워드 시드 + 계정 시드는 항상 함께** 수집(개별 병행).

## 5. 변경 지점

### 신규
- `shopping_shorts/youtube_category_presets.py` — `CATEGORY_KEYWORDS` + 헬퍼
  `preset_keywords(categories=None)` → 스코프에 맞는 키워드 리스트(중복 제거).

### 변경
- `service._collect_youtube(categories=None)` — 프리셋 키워드를 lang=ko로 `search_shorts`에 주입.
  기존 수동 키워드(by_lang)·계정 경로와 함께 raw에 병합.
- `service.collect(platform, categories=None, limit_channels=None)` — youtube 분기에 categories 전달.
- `app.py` 수집 엔드포인트 — `category`(단일 key 또는 비움=전체) 파라미터 파싱 → `collect(categories=...)`.
- `static/index.html` — 상단 수집 컨트롤 3개:
  1. **[🔥 지금 수집]** → `category` 없이 호출(전체 프리셋)
  2. **[카테고리 ▼] + [이 카테고리 수집]** → 선택 key로 호출(그 카테고리 프리셋)
  3. **검색란(개별)** → 기존 그대로(수동 키워드 시드 등록 후 지금 수집에 포함)
  - 아래 결과 필터 탭(전체/홈·살림템/…)은 **결과 거르기용 그대로** — 수집 스코프와 무관.

## 6. 데이터 흐름

```
[전체 딸깍]        POST collect (category 없음)      → 프리셋 전체 union → 랭킹
[카테고리 딸깍]    POST collect (category=혼합형)     → 뷰티 프리셋만 → 랭킹
[개별]            검색란 +키워드 → 시드 등록 → 지금 수집 시 함께 수집
```

## 7. 비용 / 에러

- 프리셋 전체 ~22키워드 × `search.list`(100 units) ≈ **2,200 units/전체수집**. 서버 10키 = 하루
  100,000 units → 수십 회/일 여유. **건당 과금 0원**.
- 카테고리별은 그 카테고리 키워드 수만큼(4~5개 = ~500 units)로 더 싸다.
- 쿼터 초과(403) → 기존 `search_shorts` 키 로테이션. 소진 시 부분 결과.

## 8. 테스트 (TDD)

- **프리셋 데이터 무결성**: 모든 key가 `CTYPES` key(홈템/비법형/제품형/혼합형/기타)와 일치, 빈 리스트 없음.
- **`preset_keywords`**: None → 전 카테고리 union(중복 없음) / `["혼합형"]` → 뷰티 키워드만 / 알 수 없는 key → 빈 리스트.
- **`_collect_youtube(categories=["혼합형"])`**: 뷰티 프리셋 키워드로만 `search_shorts` 호출(mock으로 호출 인자 확인).
- **`_collect_youtube(categories=None)`**: 전체 프리셋 union 호출.
- **프리셋 + 수동 시드 공존**: 수동 키워드 시드가 있으면 프리셋과 함께 수집되고 video_id 중복제거.
- **`collect`/`app` 파라미터 전달**: `category` 파싱 → `categories` 인자로 흘러가는지.

## 9. 범위 밖 (YAGNI)

- 프리셋 편집 UI (v1은 코드 큐레이션).
- 언어별 프리셋(한국어만). 카테고리별 개수 조절.
- 카테고리 자동 스케줄 수집(현행 수동 딸깍).
