# 영상제작소 모션효과 파이프라인 — 뼈대 설계 (Phase 1)

날짜: 2026-07-15
관련: shopping_shorts `/produce` 위저드 · [video_assemble.py](../../../shopping_shorts/video_assemble.py) · [mix_pipeline.py](../../../shopping_shorts/mix_pipeline.py)
메모리: [[feedback_꾸미기_딸깍프리셋철학]] [[project_쇼핑쇼츠_자동화]] [[feedback_동시세션_커밋규칙]]

## 목표

영상제작소(`/produce`)에 **딸깍 프리셋 퀄리티를 넘어서는 모션 효과**를 넣는다.
전략은 하이브리드 C안: **Remotion을 "모션그래픽 자산 생성기"로만 쓰고, 영상엔 ffmpeg `overlay`로 합성**한다.
전체를 Remotion으로 렌더하지 않는다(자동화 대량생산 목표와 충돌 = 오바).

본 문서는 **Phase 1 = 파이프라인 뼈대**만 다룬다.
Phase 2(프리셋 팩별 전환·타이포·콜아웃·색감 정의)는 뼈대 완성 후 별도 스펙.

## 핵심 결정: 전환도 "오버레이"로 (concat 재인코딩 회피)

비트 클립은 `_render_mix`에서 `concat -c copy`(무재인코딩)로 이어붙는다.
이는 의도된 설계 — **재인코딩 concat이 2GB 서버를 죽인 사고(2026-07-12)** 때문(video_assemble.py 주석 명시).
따라서 xfade로 비트 사이를 섞지 **않는다**(재인코딩 강제 → 서버 다운 재현 위험).

대신 **비트 경계 타임스탬프에 투명 전환 애니(스와이프/글리치 등)를 오버레이로 얹는다.**
결과: concat은 `-c copy` 그대로 유지(서버 안전) + 전환·스티커·키네틱타이포·콜아웃이
**전부 동일 메커니즘 = "시작시간 + 길이를 가진 투명 레이어"** 로 통일된다.
색감 필터(eq/curves)만 예외로 base vf에 직접 적용한다.

## 컴포넌트

### ① 합성 엔진 — 만물은 타임드 레이어 (video_assemble.py)

`_burn_captions`의 filter_complex 오버레이 구간(현재 정적 이미지 **1개만** 지원, 약 590~608행)을
**레이어 리스트**로 일반화한다.

레이어 스키마:
```
layer = {
  "asset":  파일경로,          # .mov/.webm(alpha) 또는 .png
  "start":  float,             # 초 (기본 0)
  "dur":    float | null,      # 초, null이면 영상 전체
  "x": %, "y": %,              # 중심 위치(0~100), 기본 50/50
  "width":  px | null,         # 1080 기준 폭 스케일(없으면 원본)
  "alpha":  0~1                # 기본 1
}
```

ffmpeg 합성(레이어마다 반복):
```
[i:v] scale=W:-1, format=rgba, colorchannelmixer=aa=A [Li];
[prev][Li] overlay=x=...:y=...:enable='between(t,start,start+dur)' [next]
```
- `dur=null`이면 `enable` 생략(전체 재생).
- 기존 단일 overlay/BGM 합성 경로와 공존해야 한다(같은 filter_complex 빌더 안에서 레이어 루프로 흡수).

색감 필터: `deco.motion.color_filter`가 있으면 base `[0:v]` vf 체인 끝에 `eq`/`curves` 문자열을 덧붙인다.

### ② Remotion 자산 생성기 (Node 서브프로젝트)

`shopping_shorts/motion/` — 독립 Node/Remotion 프로젝트(Python 파이프라인과 분리).
CLI 2모드:

- `npm run render:library`
  → **텍스트 무관 자산**(전환 스팅어·스티커·파티클) 전부 프리렌더.
  → 투명 배경(webm VP9 alpha 또는 ProRes4444 mov)으로 `assets/motion/`에 저장.
  → **1회성 빌드, 영상 런타임과 무관.**

- `npm run render:overlay -- --template=<name> --props='<json>' --out=<path>`
  → **텍스트 종속** 오버레이만 짧게(2~3초) 투명 렌더. (Phase 1에서는 스텁, ⑤ 참조)

### ③ 자산 라이브러리 + 매니페스트

`shopping_shorts/assets/motion/manifest.json` — 자산 카탈로그.
```
{
  "assets": [
    {"id":"swipe_left", "type":"transition", "file":"swipe_left.webm",
     "default":{"width":1080,"x":50,"y":50}},
    {"id":"sparkle",    "type":"sticker",    "file":"sparkle.webm",
     "default":{"width":300,"x":50,"y":40}}
  ]
}
```
- ffmpeg 측(Python)은 이 매니페스트로 자산 파일과 기본 배치를 해석한다.
- 프리렌더 자산만으로 시스템이 **완결**된다(런타임 Node 의존 0).
- `assets/motion/*.webm|mov`는 git 추적(PC·서버 공유). manifest도 git 추적.

### ④ 데이터 모델 + 배선

- **store**: 기존 `deco_json`에 `motion` 필드 추가(기존 `bgm`/`overlay`와 동형 구조).
  ```
  deco.motion = {
    "pack_id":  str | null,          # Phase 2에서 사용
    "layers":   [ {asset_id, start, dur, x, y, width, alpha}, ... ],
    "color_filter": str | null       # ffmpeg eq/curves 조각
  }
  ```
  layer는 `asset_id`(매니페스트 참조)로 저장하고, 렌더 시 실제 경로로 해석한다.

- **app**: `POST /mix/motion` 신설 — 선택된 팩/레이어를 `deco.motion`에 저장.
  기존 `/mix/overlay`·`/mix/bgm`·`/mix/settings` 패턴을 그대로 복제한다.

- **mix_pipeline.run_render**: 현재 `bgm`/`overlay`의 `_abspath`를 해석하듯,
  `deco.motion.layers`의 각 `asset_id`를 매니페스트로 실제 파일 경로(`_abspath`)로 해석해
  `assemble(...)`에 넘긴다.

### ⑤ per-video 텍스트 렌더 = 인터페이스 뒤로 (리스크 격리)

최대 리스크: **서버(Lightsail)에 Node/헤드리스 크롬이 있는지 미확인.**
→ Phase 1 뼈대는 **프리렌더 자산(전환·스티커)만으로 end-to-end 완결**시킨다(런타임 Node 0).
→ 텍스트 종속 렌더는 `render_text_overlay(template, props) -> path` 인터페이스로 **스텁만** 둔다.
   Node-on-서버가 확인되면 Phase 2(팩)에서 실제 구현을 붙인다.

## 데이터 흐름 (뼈대)

```
[1회 빌드] motion/ ──npm run render:library──▶ assets/motion/*.webm + manifest.json  (git)
                                                        │
[영상 제작] /produce 위저드 ──POST /mix/motion──▶ store.deco_json.motion (asset_id 레이어)
                                                        │
           run_render ──매니페스트로 asset_id→_abspath 해석──▶ assemble(deco=...)
                                                        │
           _burn_captions ──타임드 투명레이어 N개 overlay 합성──▶ final.mp4
```

## 에러 처리

- 매니페스트에 없는 `asset_id` → 해당 레이어 skip(로그), 렌더는 계속(기존 overlay 파일 부재 처리와 동일 관용성).
- 자산 파일 실물 부재 → skip.
- 색감 필터 문자열이 비면 base vf 무변경.
- ffmpeg 실패 → 기존 `run_render`의 try/except가 status='failed'+error로 잡음(변경 없음).

## 테스트

- **엔진(단위)**: 레이어 리스트 → filter_complex 문자열 빌더가 올바른 overlay/enable 체인을 만드는지
  (기존 `tests/test_app_mix.py` 패턴 참고, ffmpeg 실행 없이 문자열 검증).
- **매니페스트 해석(단위)**: asset_id → 경로/기본배치 해석, 미존재 id skip.
- **end-to-end(육안 = 뼈대 완료 정의)**:
  스와이프 전환 1종 + 반짝이 스티커 1종 프리렌더 → 매니페스트 등록 →
  `/mix/motion`으로 선택 → run_render → **최종 mp4에 전환·스티커가 실제로 보이는 것 육안 확인.**
