# 캡컷썸네일인트로 — 캡컷 타임라인 맨 앞에 썸네일 1.2초

**소유 트랙**: 캡컷썸네일인트로 — 이 파일은 이 트랙 세션만 수정한다. 다른 트랙은 읽기만.

## 2026-09-13 — 구현 완료 (커밋 6b96481e8)

사장님: *"넣어라 — 캡컷에도 첫 장면으로"* (선행 작업 `썸네일확대돋보기`에서 이어짐)

### 왜 필요했나 — 실측으로 드러난 구멍

`썸네일확대돋보기` 작업 중 사장님이 **"배선까지 오류 확인한거지"**, **"랜더랑 캡컷"**
이라고 물어서 갈라 재보니:

| 경로 | 실측 | 결과 |
|---|---|---|
| 썸네일 → 렌더 MP4 첫 장면 | 진짜 MP4 만들어 프레임 대조 | ✅ 된다 (576점 중 574점 일치) |
| 썸네일 → 캡컷 | `capcut_draft.py` 전수 검색 | ❌ **`thumb` 참조 0건** |

**원인**: 렌더는 완성 MP4 **앞에** 붙이는데(`prepend_still`), 캡컷은 완성본을 담는 게 아니라
**원본 소스에서 편집본을 다시 조립**한다(`source_video_paths`). 그래서 캡컷에만 첫 장면이 없었다.
⚠️ 이건 원래부터 그랬고 `썸네일확대돋보기` 변경 탓이 아니다. (앞서 09-10 `꾸미기가림막`도
같은 종류의 한계를 남겨뒀다: *"캡컷 내보내기엔 장면전용 가림막이 안 들어간다"*)

### 어떻게 고쳤나

```
app.py  (캡컷 내보내기 라우트)
  └ thumb.intro 켜졌으면 → mix_pipeline._thumb_intro_png(job, thumb)   ← 렌더와 **같은 함수**
  └ capcut_draft.assemble_draft_folder(intro_png=, intro_seconds=)
       └ thumb_intro.png 를 draft 폴더에 복사
       └ build_draft(intro={path, seconds})
            ① 다 만든 뒤 **한 번에** 모든 트랙 세그먼트를 intro_us 만큼 민다
            ② total_us += intro_us
            ③ 0초에 사진 세그먼트 + 전용 video 트랙을 맨 뒤에 append
```

**★왜 사후 일괄 이동인가 (0순위-B)**: 시각을 계산하는 자리가 **9개 트랙에 흩어져 있다**
(`t0` · `_acc` 커서 · `caption_schedule` 절대초 · headcopy `t0` · sfx `at` · 전구간 `0` …).
각자 더하게 만들면 언젠가 한 곳을 빠뜨려 **소리와 화면이 어긋난다**. 다 만든 뒤 한 번에
밀면 빠뜨릴 자리가 구조적으로 없다.

**★안 민 것**: `source_timerange` — 타임라인 위치가 아니라 **소스 파일 안에서 어디부터
읽을지**다(head_trim 등). 밀면 엉뚱한 데가 재생된다.

**★`videos[0]` 전제 보존**: 인트로 재료를 `mats["videos"]`에 **append**(앞에 끼우지 않음).
기존 테스트가 `materials["videos"][0]`을 소스 클립으로 전제한다.

### 인트로 길이를 한 곳으로 모았다

`float(thumb.get("intro_sec") or 1.2)`가 이미 **2벌**이었고(렌더 `mix_pipeline:3514`,
CTA 자르기 `app:7719`) 이번에 캡컷이 3벌째가 될 뻔했다.
→ **`app.thumb_intro_seconds(thumb)` 신설**, 세 곳이 전부 이걸 부른다.
한쪽만 고치면 캡컷과 완성본의 인트로 길이가 갈리고 CTA 자르는 지점도 어긋난다.

### 실측

- **진짜 draft를 만들어 타임라인을 뜯어봤다**:
  ```
  인트로 없음  video[(0,2.0s),(2.0s,1.5s)] audio[(0,..),(2.0s,..)] sfx[(2.0s,0.8s)] text[(0,3.5s)]  전체 3.5s
  인트로 1.2초 video[(1.2s,2.0s),(3.2s,1.5s)] audio[(1.2s,..),(3.2s,..)] sfx[(3.2s,0.8s)] text[(1.2s,3.5s)]
               + video[(0, 1.2s)]  ← 인트로                                              전체 4.7s
  ```
  **모든 트랙이 정확히 1,200,000us씩** 밀렸고, 소스 읽는 위치는 그대로, `videos[0]`도 그대로.
- 새 테스트 8개 + **기존 capcut 87개 통과, 실패 0**
- ★**사보타주 검증**: 자막 트랙만 안 밀게 고쳐놓으니 `test_every_track_shifts_by_exactly_the_intro`가
  정확히 잡았고 나머지 7개는 green 유지 → 가짜 단언이 아님을 확인.
- ★**내 첫 테스트가 헛발질했다**: draft엔 매번 새 UUID(`_uid()`)가 있어 두 draft를 통째로
  비교하면 **항상** 다르다. id를 뺀 모양(`_shape`)으로 비교하도록 고쳤다.
