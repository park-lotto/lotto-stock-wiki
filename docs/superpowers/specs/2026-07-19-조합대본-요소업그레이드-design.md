# 조합 대본 요소 기반 업그레이드 — 설계

작성: 2026-07-19 · 트랙: `조합대본업그레이드`

## 문제

제작소 "조합 생성"(2개+ 위키 대본을 섞은 초안 1·2·3)에서 나온 대본을
**고정 결과물**로만 쓰게 되어 있다. 사장님은 이 초안을 "훅 더 강하게 / 스토리
탄탄하게 / CTA를 궁금하게 / 인물 활용"처럼 **연출 지시로 계속 다듬고** 싶다.

## 지금 상태 (실측)

- 대본을 요소로 분해·재생성하는 엔진이 **이미 있다**:
  - `script_generate.ELEM_LABELS` — 요소 7개(훅·발상전환·전개방식·등장 주변인물·
    어필포인트·말투/어미·설득장치), 프론트·백 공유 사전.
  - `script_generate.generate_variations(structure, full_text, elem_modes, ...)` —
    요소별 **유지/변형** 지시로 재생성.
  - `POST /api/wiki/draft/analyze` — 초안 텍스트 → 요소 구조로 분해.
  - `POST /api/wiki/draft/refine` — 지시문(전체재작성/부분)으로 재생성 + 버전 이력.
- 그런데 이 다듬기 UI(`pmRenderDrafts`: textarea+지시문+버전이력)는 **단일 위키
  대본 경로에만** 붙어 있다.
- **조합(mix) 경로**는 빈약한 `renderDrafts`(카드에 `[이 대본 사용 →]` 하나)만 쓰고,
  `generate_mix`가 결과를 `save_draft` 하지 않아 **조합 초안엔 `draft_id`가 없다**
  → analyze·refine·variations 어느 것도 붙일 수 없다.
- 요소 목록에 **CTA(마무리/행동유도) 전용 항목이 없다**.

## 목표

조합·단일 초안 모두에서, **우리가 이미 가진 요소 구조를 그대로 활용**해
요소 단위로 대본을 업그레이드한다. 60대도 버튼 딸깍으로 되게 하고, 세밀한
지시는 자유입력으로 받는다.

## 설계

### 요소 8개 (기존 7 + CTA 신규)

훅 · 발상전환 · 전개방식 · 등장 주변인물 · 어필포인트 · 말투/어미 · 설득장치 ·
**마무리/CTA(신규)**

### 구현 조각

**① `script_generate.py` — CTA 요소 추가**
- `ELEM_LABELS`에 `"cta": "마무리/행동유도"` 추가(→ `ELEM_KEYS`에 자동 포함).
- 생성 프롬프트의 "구조 요소별 지시" 섹션과 `analyze_structure`(초안→구조) 출력이
  CTA를 다루도록 반영. 필요 시 `_STRUCT_KEY` 매핑에 `"cta"` 항목 추가.
- 회귀: 기존 7요소 동작 불변, CTA가 유지/변형 대상으로 정상 인식되는지.

**② `app.py` — 조합 초안 서버 저장**
- `generate_mix` 결과의 각 초안을 `store.save_draft(...)`로 저장해 `draft_id` 부여.
  (단일 경로 `app.py:1059`와 동일 형태. 조합은 원본 shortcode가 없으므로
  `source_shortcode=None`, `mode="mix"`.)
- 응답 JSON에 각 초안의 `draft_id`를 실어 프론트로 내려보낸다.

**③ `app.py` `/api/wiki/draft/analyze` — 8요소 분해**
- 초안 텍스트를 CTA 포함 8요소 구조로 분해(①의 프롬프트 반영으로 자동).
- 조합 초안은 단일 원본 구조가 없으므로, 업그레이드 시 이 analyze로 **그 초안
  자체를 요소 분해**한 뒤 `generate_variations`에 넘긴다.

**④ `produce.html` — 렌더러 통합 + 요소 버튼**
- 조합 초안을 빈약한 `renderDrafts` 대신 리치 렌더러(현 `pmRenderDrafts` 계열)로
  렌더 → textarea·버전이력·자유입력창을 조합 초안도 공유.
- 각 초안 카드에 **요소 버튼 8개**(라벨은 `ELEM_LABELS` 그대로) 추가.
  - 버튼 딸깍 = 그 요소를 "변형(새로/강하게)", 나머지는 "유지".
  - **복수 선택 가능 = 전체 적용**(고른 요소 전부 변형).
  - 실행: (조합 초안이면) analyze로 요소 분해 → `generate_variations`(elem_modes에
    고른 요소만 변형) → 결과로 카드 textarea 갱신 + 버전 이력 적립.
- 자유입력창은 유지 — 요소로 안 잡히는 미세 지시는 기존 `refine`(지시문) 경로로.
- 사장님 말↔요소 매핑(안내 문구):
  훅=hook · 스토리 탄탄=전개방식+발상전환 · 인물=주변인물 · CTA 궁금하게=마무리/CTA.

### 데이터 흐름 (조합 초안 업그레이드)

```
조합 생성 → generate_mix → save_draft(draft_id 부여) → 카드 렌더(요소 버튼)
사용자 요소 딸깍 → /api/wiki/draft/analyze(draft_id → 8요소 구조)
             → generate_variations(structure, full_text, {고른요소:변형})
             → 새 버전 draft 저장 + 카드 textarea 갱신
```

### 경계·격리

- **트랙 격리 필수**: `script_generate.py`+`app.py`+`produce.html`은 다트랙에서
  hot(흡수 사고 상습 지점) → 전 편집을 `.tracks/조합대본업그레이드/`에서만.
- `produce.html`은 병합 시 충돌 가능 — 요소 버튼/렌더러 변경을 국소 함수에 가둬
  seam 최소화.

## 검증 관점 (구현 후)

- 기존 7요소 생성·단일 경로 refine **회귀 없음**(baseline 테스트 그대로).
- 조합 초안에 `draft_id`가 실제로 실리는지(서버 DB `mix_jobs`/`script_drafts` 실측).
- 조합 초안에서 요소 버튼 클릭 → 재생성 결과가 실제로 그 요소만 바뀌는지
  (라이브 서버 실렌더/실호출 그라운딩 — 로컬은 Gemini 키 경로 확인).
- CTA 버튼이 마무리 문장을 "다 안 알려주고 궁금하게" 방향으로 바꾸는지.

## YAGNI / 비목표

- 요소별 3단계(유지/변형/강화) 세분화는 하지 않는다 — **유지 vs 변형** 2단계로 충분.
- 초안 3개 일괄 업그레이드(한 번에 셋 다)는 이번 범위 밖 — 카드 단위로만.
- 요소 순서 재배치·드래그 UI 없음.
