# 관리자 전용 장면꾸미기 실데이터 시험판 설계

작성일: 2026-09-16  
대상 트랙: `장면꾸미기UI코덱스`

## 목적

새 장면꾸미기를 고객 제작 흐름에 바로 노출하지 않고, 관리자 한 명이 실제 작업의 재료로 끝까지 시험한다. 기준 영상 `https://www.youtube.com/shorts/50KOj_5Cnfs`처럼 첫 훅 구간에는 큰 훅 제목만 보이고 말자막은 없으며, 본문 첫 구절의 실제 시작 시각부터 말자막이 나타나야 한다.

한 번의 시험에서 다음 네 출구가 같은 자막 문구·시작/종료 시각·배치값을 쓰는지 확인한다.

1. 브라우저 장면꾸미기 미리보기
2. 시험용 최종 MP4
3. 시험용 CapCut 초안
4. 시험용 랜딩 재생 화면

## 확인된 현재 상태

- `scene_style.context_for()`는 `video_assemble.caption_schedule()`로 장면을 만든다. 자막 구절과 시간 경계의 출처는 최종 렌더와 같다.
- 현재 첫 번째 비트도 `kind="hook"`인 자막 장면으로 만들어지므로, 훅 말자막을 자동으로 숨기는 계약은 없다.
- 장면꾸미기 렌더는 `assemble()`의 `clean_fn` 처리 이후 실행되므로 최종 MP4에서는 청소된 배경 위에 꾸미기를 얹을 수 있다.
- 청소본이 준비되지 않은 일부 미리보기·프레임 경로는 자막이 남은 `preview_path`로 폴백한다. 시험판에서는 이 폴백을 허용하면 안 된다.
- CapCut 내보내기는 `caption_style`, `headcopy`, 일반 `deco`를 전달하지만 새 `deco.scene_style` 스냅샷을 CapCut 타임라인으로 변환하지 않는다. 따라서 현 상태에서 새 장면꾸미기 결과와 CapCut은 같다고 보장할 수 없다.
- 랜딩은 완성된 MP4를 재생하면 픽셀 결과가 유지되지만, 기존 공개·공유 레코드를 시험에 사용하면 실제 사용자 상태를 변경할 수 있다. 별도 시험 URL이 필요하다.

## 선택한 방식

실제 job을 직접 수정하지 않고 **읽기 전용 원본 + 쓰기 가능한 시험 복사본**으로 동작한다.

또한 시험판은 서버 배선을 복제해 새로 만들지 않는다. 현재 라이브의 기존 함수와 API를 그대로 호출하고, 시험 격리와 훅 말자막 정책에 필요한 최소 어댑터만 추가한다.

### 라이브 기준선 확인

2026-09-16에 서버를 직접 확인한 기준은 다음과 같다.

- 라이브 도메인 확인 IP: `3.35.251.172`
- 서버 저장소: `/home/ubuntu/lotto-stock-wiki`
- 서버 브랜치/커밋: `main` / `3e390e52ac9d553f127d75b2579f5437ac526efc`
- 서비스 상태: `active`
- 서버의 `app.py`, `mix_pipeline.py`, `video_assemble.py`, `capcut_draft.py` SHA-256은 로컬 `main`의 같은 파일과 모두 일치한다.
- 서버 tracked 파일에는 수정 흔적이 없고, 다수의 untracked 운영 산출물이 있다. 시험판은 이 파일들을 정리하거나 수정하지 않는다.
- 현재 장면꾸미기 트랙의 공통 조상은 `85813ee859d96cc85d755c0ae6e9246d1e477421`이며 최신 `main`보다 뒤처져 있다. 구현 전에 최신 `main`을 트랙에 병합하고 충돌을 검토해야 한다.

이 확인값은 설계 당시 기준이다. 실제 구현 시작과 배포 직전에는 커밋·해시·서비스 상태를 다시 측정한다.

### 재사용 원칙

- 자막 구절과 시간표: `video_assemble.caption_schedule()` 그대로 사용
- TTS 기반 전체 타임라인: `video_assemble._beat_timeline()` 그대로 사용
- 현재 편성과 맞는 청소본 선택: `mix_pipeline.clean_final_path_for_plan()` 그대로 사용
- 완성본 1편 청소 방식의 재사용: `mix_pipeline.split_final_into_beat_clips()`와 `plan_using_beat_clips()` 그대로 사용
- 최종 영상 조립: 기존 `video_assemble.assemble()` 경로를 어댑터가 호출
- CapCut 기본 타임라인·에셋 조립: 기존 `capcut_draft.assemble_draft_folder()`를 확장해 호출
- 랜딩 재생: 기존 파일 스트리밍 응답 패턴을 재사용하되 공개 share 레코드는 만들지 않음

같은 판단을 시험판 안에 다시 구현하지 않는다. 기존 함수가 시험 출력 경로를 받지 못하는 경우에만 인자를 추가하고, 기존 호출부의 동작이 바뀌지 않는 기본값을 둔다.

### 원본에서 읽는 값

- `edit_plan`과 `beats[]`
- TTS 파일과 길이
- `caption_lines`, `cap_durs`, `cap_lead`, `cap_offset`
- `headcopy`, `caption_style`, `deco`
- 현재 편성 서명과 일치하는 자막제거 완료본
- 소스·컷어웨이·효과음 등 렌더 재료의 기존 파일 경로

### 시험 공간에만 쓰는 값

- 장면꾸미기 `scene_style` 스냅샷
- 훅 말자막 표시 정책
- 시험 렌더 결과와 로그
- CapCut 시험 초안
- 시험 랜딩용 임시 파일

원본 job DB 행, 기존 `preview_path`, `clean_video_path`, `video_path`, 공개 share 레코드는 수정하지 않는다.

## 관리자 화면

관리자 전용 경로에서만 연다. 기존 고객 제작소 메뉴에는 링크를 만들지 않는다.

화면은 다음 순서로 구성한다.

1. 최근 관리자 소유 작업 선택
2. 사전 조건 검사
   - TTS가 모든 비트에 존재하는가
   - 현재 편성 서명과 일치하는 청소본이 존재하는가
   - 자막 구절 수와 `cap_durs` 수가 맞는가
3. 시험 복사본 생성
4. 장면꾸미기 편집
5. 훅/본문 전환 재생
6. 네 출구 생성 및 비교

화면에는 각 장면의 `beat_idx`, 구절 번호, 문구, 시작초, 종료초, 훅/본문, 청소본 서명을 표시한다. 훅 장면에는 `말자막 숨김`, 본문 첫 장면에는 `첫 자막 시작` 표식을 보여준다.

## 훅 말자막 정책

음성과 장면 길이는 바꾸지 않는다. 첫 번째 비트의 `caption_schedule()`도 보존한다. 단지 출력 레이어에 다음 정책을 적용한다.

- `hook_caption_mode = "hidden"`: 첫 번째 비트의 말자막 레이어를 그리지 않는다.
- 본문은 기존 `caption_schedule()`의 절대 시작·종료 시각을 그대로 사용한다.
- 큰 훅 제목·채널명·브랜딩·영상은 계속 표시한다.
- 본문 시작 시 빈 프레임을 삽입하거나 시간을 당기지 않는다.

이 정책은 미리보기, MP4, CapCut, 시험 랜딩이 모두 읽는 시험 manifest 한 곳에만 저장한다. 자막 문구를 빈 문자열로 덮어쓰는 방식은 사용하지 않는다. 빈 문자열은 기존 폴백에서 원래 대본이나 샘플 문구로 되살아날 수 있기 때문이다.

## 청소본 선택 계약

시험 복사본을 만들 때 현재 편성의 단일 서명을 기록한다. 청소본은 `mix_pipeline.clean_final_path_for_plan()`과 같은 기존 판정을 통해 그 서명과 일치하는 파일만 허용한다.

- 일치하는 청소본이 없으면 시험 복사본 생성을 409로 차단한다.
- `preview_path`나 `video_path`로 조용히 폴백하지 않는다.
- 시험 도중 원본 편성 서명이 바뀌면 복사본을 `stale`로 표시하고 렌더·CapCut 생성을 차단한다.
- VMake를 다시 호출하지 않는다. 시험은 이미 만들어진 청소본만 사용하므로 추가 과금이 없다.

## 출력별 배선

### 브라우저 미리보기

앞 단계의 `caption_schedule()` 결과를 그대로 장면 목록으로 사용한다. 훅 정책만 manifest에서 읽어 말자막 레이어의 표시 여부를 결정한다. 실제 청소본에서 추출한 프레임 또는 동일 청소본 영상을 배경으로 사용한다.

### 시험 MP4

라이브가 쓰는 `video_assemble.assemble()`과 `scene_style.compose()` 경로를 그대로 호출하되 출력 경로만 시험 공간으로 강제한다. 소스별 청소본이 있으면 라이브처럼 원본 소스 맵 위에 덮고, 완성본 1편 청소 방식이면 라이브 CapCut 경로와 같은 `split_final_into_beat_clips()`와 `plan_using_beat_clips()`로 청소본을 비트 조각으로 만든다. 원본 job의 `video_path`는 갱신하지 않는다. 결과 MP4에서 훅 중간 프레임, 경계 직전/직후 프레임, 본문 첫 자막 중간 프레임을 자동 추출한다.

### CapCut 시험 초안

`scene_style`을 무시하는 기존 CapCut 내보내기를 그대로 성공 처리하지 않는다. 라이브 `capcut_draft.assemble_draft_folder()`의 소스·TTS·효과음·청소본 처리는 그대로 재사용하고, 시험 manifest의 장면별 투명 레이어를 받는 입력만 확장한다. 훅 구간 레이어에는 말자막이 없어야 한다. 장면꾸미기 레이어를 쓰는 시험 초안에서는 같은 문구를 그리는 기존 네이티브 캡션 트랙을 생성하지 않아 이중 자막을 막는다. 배경 영상과 TTS 등 기존 재료 트랙은 계속 편집할 수 있지만, 정밀 장면꾸미기 그래픽은 화면 일치를 우선해 투명 오버레이로 전달한다. 배경은 라이브 판정을 통과한 청소본 조각만 사용한다. 생성 뒤 `draft_content.json`을 다시 읽어 각 오버레이의 시작초·길이·위치를 manifest와 대조하고, 투명 레이어 산출물의 텍스트 manifest도 함께 대조한다.

### 시험 랜딩

공개 share 레코드를 만들지 않는 관리자 전용 임시 URL에서 시험 MP4를 재생한다. 랜딩이 최종 MP4를 그대로 스트리밍하는지 확인하고, 다른 미리보기나 옛 `video_path`로 폴백하지 않는다.

## 비교 판정

각 출구에 대해 다음을 같은 표에 표시한다.

- 훅 구간 말자막 개수: 반드시 0
- 본문 첫 자막 문구
- 본문 첫 자막 시작초와 종료초
- 장면 총 개수
- 배경 청소본 서명
- 자막 위치와 박스 크기

시간 허용 오차는 30fps 한 프레임인 `±0.034초`로 한다. 텍스트와 훅 숨김 여부, 청소본 서명은 완전 일치해야 한다. 하나라도 다르면 해당 출구를 빨간색으로 표시하며 전체 시험을 성공으로 표시하지 않는다.

## 인증과 안전장치

- 모든 HTML/API/미디어 경로에서 기존 `_is_admin(_cid(request))` 검사를 수행한다.
- 비관리자에게는 존재 여부도 노출하지 않고 404를 반환한다.
- 시험 ID와 파일명은 서버가 생성하며 경로순회를 차단한다.
- 시험 API는 원본 job 갱신 함수를 호출하지 않는다.
- 시험 산출물에는 `LAB` 표식을 넣어 실제 완성본과 구분한다.
- 시험 랜딩은 검색 노출과 외부 공유를 막는다.
- 삭제는 시험 ID 아래 산출물만 대상으로 하며 원본 파일은 삭제하지 않는다.

## 오류 처리

- 청소본 없음/서명 불일치: 실행 차단, 필요한 앞 단계 표시
- TTS 또는 자막 시간표 불완전: 실행 차단, 문제가 있는 `beat_idx` 표시
- CapCut 역검증 불일치: 초안은 내려받을 수 없게 하고 비교표 제공
- MP4 렌더 실패: 기존 시험 결과를 유지하고 새 실패 로그를 별도 기록
- 원본 작업 변경 감지: 시험 복사본을 읽기 전용 `stale` 상태로 전환

## 검증 기준

자동 검증과 육안 검증을 모두 통과해야 한다.

1. 단위 테스트
   - 훅 말자막 숨김이 음성·타임라인을 바꾸지 않음
   - 본문 첫 자막이 원래 절대 시각에 시작함
   - 빈 문자열 폴백으로 훅 자막이 되살아나지 않음
   - 낡거나 없는 청소본을 차단함
2. API 테스트
   - 관리자만 접근 가능
   - 원본 job이 바이트 단위로 변경되지 않음
   - 복사 시점 이후 편성 변경을 감지함
3. 출구 계약 테스트
   - 미리보기 manifest, MP4 레이어, CapCut JSON, 랜딩 URL이 같은 시험 ID와 서명을 가짐
4. 실제 육안 시험
   - 기준 작업 하나를 복사해 훅 중간에는 큰 제목만 보이는지 확인
   - 본문 첫 발화 순간부터 말자막이 표시되는지 확인
   - 원본 자막이 청소된 배경인지 확인
   - MP4, CapCut, 랜딩을 각각 직접 열어 같은지 확인

## 시험판 성공 이후

시험판에서 실제 작업 1개가 네 출구 모두 녹색으로 통과해도 고객 제작소에는 자동 반영하지 않는다. 고객 동선 통합은 별도 승인과 별도 트랙에서 진행한다. 릴리 자막 스타일 연결 작업도 본 시험판의 출구 계약이 검증된 뒤 재개한다.
