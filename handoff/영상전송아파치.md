# 영상전송아파치 — 영상·음성 파일 전송을 파이썬 대신 아파치가(X-Sendfile) (관제 062, 2026-10-01 사장님 PC)

사장님: "페이블이 판단해서 최선의 작업으로" → ④-1 X-Sendfile 을 먼저(작업량 작고 모든 재생·다운로드에 효과).

## 주인 함수 · 결과물 검사 (0순위-C)
- 주인: `app.py:_send_media(path, request, media_type, filename)` — 재생(Range)·다운로드(첨부) 파일 응답의 유일한 자리.
  `_range_media_response`(옛 이름, 호출처 다수)는 이 함수로 보내고, 종전 파이썬 Range 구현은 `_range_media_response_py`.
  첨부 다운로드 3곳(완성본 ?dl=1 · noCTA · 공유링크 dl)도 주인으로 옮김. `/api/play`·wiki_video 등 캐시 폴더 밖 파일은 종전대로(폴더 밖이면 자동 폴백).
- 검사: `test_send_media_xsendfile.py` 4건 + 라이브: 스위치 켠 뒤 `/landing/vertex_guide.mp4`(로그인 불필요) 헤더·Range 206·
  아파치 접근로그 바이트 vs uvicorn 응답(0바이트), 고객 재생·다운로드 정상.

## 조건(전부 맞아야 X-Sendfile) — 하나라도 아니면 종전 파이썬 전송
1. 관리자 설정 `xsendfile_enabled` = "1" (30초 캐시) — **기본 꺼짐**. 되돌리기 = 설정 한 줄.
2. 요청이 아파치를 거쳤다(X-Forwarded-For/Host/Proto 중 하나) — 로컬 직결·테스트는 종전 길.
3. 파일이 `shopping_shorts/data` 또는 `static` 아래(서버 vhost XSendFilePath 와 같음) + 경로 ASCII.

## 서버에서 한 것 (2026-10-01 20:xx, 되돌리기: *.bak-xsf-20261001)
- `apt install libapache2-mod-xsendfile`(무료 아파치 모듈) · `a2enmod xsendfile` · `chmod o+x /home/ubuntu`(www-data 가 파일 읽게, 목록 열람은 안 됨)
- `/etc/apache2/sites-enabled/shopping-shorts-le-ssl.conf`·`shopping-shorts.conf` 의 ProxyPass 앞에
  `XSendFile On` + `XSendFilePath …/shopping_shorts/data` + `…/static`. configtest OK, reload 완료(접속 200 확인).
- 헤더가 안 나가면 아파치는 아무것도 안 한다 — 스위치 켜기 전까지 라이브 동작 변화 없음.
