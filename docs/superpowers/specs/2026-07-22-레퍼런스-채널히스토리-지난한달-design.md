# 레퍼런스 랭킹 — 채널 검색 시 '지난 한 달' 히스토리 표시

작성: 2026-07-22 / 트랙: 채널히스토리

## 문제

레퍼런스 랭킹은 "48시간 이내 릴스"만 보여준다. 매일 「지금 수집」을 돌리면
수집 결과가 `last_run` 테이블 **단일 행을 통째로 덮어쓴다**(store.py `save_last_run`).
따라서 어제 48시간 창에서 내려간 영상은 DB에 흔적 없이 사라진다 — 과거 히스토리가 없다.

사용자 요구: **채널을 검색하면 그 채널의 지난 한 달치 영상을 지금 랭킹과 함께 보고 싶다.**

## 목표 / 비목표

**목표**
- 수집할 때마다 영상을 누적 저장(48시간 창에서 내려가도 30일간 보존).
- 채널명/@아이디로 검색하면, 지금 랭킹(48h) 아래에 그 채널의 **지난 한 달치**를 섹션으로 표시.

**비목표(안 함)**
- 유튜브·틱톡 히스토리 (인스타 랭킹 = `save_last_run` 경로만).
- 30일 초과 장기 보관 / 채널 간 비교 / 시계열 그래프.
- 검색 로직 자체 개편 — 일반 키워드 검색(피자·물총)은 지금과 100% 동일하게 둔다.

## 설계

### ① 데이터 — 누적 히스토리 테이블 (store.py)

새 테이블 `reel_history`:

| 컬럼 | 설명 |
|---|---|
| `shortcode` TEXT PK | 릴스 고유코드(중복 판정 키) |
| `username` TEXT | 채널 아이디(검색 매칭 키, 소문자 정규화 저장) |
| `name` TEXT | 채널 표시명 |
| `category` TEXT | 카테고리(홈템·레시피 등) |
| `url` TEXT | 릴스 URL |
| `thumb` TEXT | 썸네일 URL |
| `caption` TEXT | 캡션 |
| `views` INTEGER | 최신 조회수 |
| `comments` INTEGER | 최신 댓글수 |
| `vision_json` TEXT | 비전 태그(subject/keywords) JSON, 있으면 |
| `first_seen` TEXT | 처음 수집된 시각(ISO) |
| `last_seen` TEXT | 마지막으로 본 시각(ISO) — 30일 정리 기준 |

인덱스: `username`, `last_seen`.

**누적 지점**: `save_last_run(items, collected_at)` 안에서 기존 덮어쓰기 직후
`_record_history(items, collected_at)` 호출. shortcode 기준 **upsert**:
- 신규면 `first_seen=last_seen=collected_at`로 insert.
- 기존이면 `last_seen`·`views`·`comments`·`vision_json`·`thumb`·`caption`만 갱신
  (`first_seen`은 유지).
- shortcode/username 없는 항목은 스킵(안전).

수집·전수조사 둘 다 `save_last_run`을 거치므로 주입점은 한 곳뿐.

**정리**: `_record_history` 실행 시 `last_seen < now-30일` 행을 DELETE(같은 트랜잭션).
별도 크론 불필요 — 수집이 곧 정리 트리거.

### ② API (app.py)

`GET /api/channel/history?username=<아이디>&exclude=<shortcode,shortcode,...>`
- `username` 정규화(소문자·`@`·공백 제거) 후 `reel_history`에서 그 채널 행을 `last_seen` 최신순 반환.
- `exclude`: 지금 48h 랭킹에 이미 뜬 shortcode들 — 중복 카드 방지(프론트가 현재 화면의 해당 채널 shortcode를 넘김).
- 반환: `{ok, username, items:[{shortcode,url,thumb,name,category,views,comments,caption,last_seen,vision_subject,vision_keywords}], count}`.
- 조회 전용 GET. 유료게이트: 레퍼런스 랭킹 '조회'는 무료 등급도 허용되는 정책과 동일하게 `_FREE_EXACT_GET`에 `/api/channel/history` 추가(랭킹 열람의 연장).

### ③ 화면 (index.html)

**채널 모드 진입 (두 경로)**
1. 검색어가 특정 채널과 매칭될 때: 현재 필터된 카드들의 채널을 보고, 검색어가 한 채널의
   `username`/`name`에만 수렴하면 그 채널을 "채널 모드"로 간주.
2. **카드의 채널명 클릭** → 그 채널로 검색(검색창을 그 채널명으로 채움). 발견성 확보.

**표시**
- 지금 랭킹 카드(48h)는 그대로.
- 채널 모드면 그 아래 구분선 **"📅 지난 한 달 · @채널 (n개)"** + `/api/channel/history` 결과 카드.
  - 현재 랭킹에 이미 있는 shortcode는 `exclude`로 빼서 안 겹침.
  - 카드: 썸네일·조회수·댓글수·last_seen 날짜·「보기」·「담기」(기존 카드와 동일 톤, 간소화).
- 일반 키워드 검색(채널로 수렴 안 됨)이면 섹션 미표시 — 지금과 동일.

## 데이터 흐름

```
[지금 수집/전수조사] → collect()/census() → save_last_run(items)
                                              ├─ last_run 덮어쓰기 (기존)
                                              └─ _record_history(items) → reel_history upsert + 30일 정리 (신규)

[채널 검색/채널명 클릭] → 프론트가 채널 판정
                          → GET /api/channel/history?username=&exclude=
                          → '지난 한 달' 섹션 렌더
```

## 에러 처리
- `_record_history`는 수집 성공 후 부가작업 — 실패해도 랭킹 저장/응답은 살린다(try/except로 감싸 로그만).
- `/api/channel/history`: username 없으면 422, 히스토리 없으면 `{ok:true, items:[], count:0}`.
- DB 없거나 테이블 미생성: 스키마 `CREATE TABLE IF NOT EXISTS`로 안전(부팅 시 보장).

## 테스트
- store: `save_last_run` 두 번(다른 shortcode/같은 shortcode) → 누적·`first_seen` 유지·`last_seen`/조회수 갱신 확인.
- store: 30일 지난 행 정리 확인(오래된 `last_seen` 주입 후 새 수집 → 삭제).
- store: shortcode/username 없는 항목 스킵.
- api: `/api/channel/history?username=` → 최신순·exclude 반영·미존재 채널 빈 결과.
- api(회귀): 이 경로가 무료 등급 조회 허용인지(deny-by-default 게이트 통과).
