# 작업창 — 웹으로 여는 Claude Code

- 작성: 2026-09-02
- 트랙: `작업창` (`track/작업창`)
- 상태: 설계 확정 대기

## 무엇을 만드는가

터미널 없이 **브라우저에서 Claude Code를 쓰는 화면**. 두 부류가 쓴다.

| 쓰는 사람 | 하는 일 | 권한 |
|---|---|---|
| **사장님** | 밖에서 폰으로 하는 작업 전부 (긴 작업 포함) | 지금 터미널과 동일 — 제한 없음 |
| **직원** | 고객 CS 처리 (조회·진단) | 조회 자유, 배포는 사장님 승인 |

터미널에서 하던 것을 폰·PC 브라우저에서 그대로 한다. CS는 그 위에 얹힌 쓰임 중 하나다.

## 왜 만드는가

- 직원이 CS를 받아도 **혼자 해결할 수단이 없다.** 매번 사장님을 거친다.
- 사장님이 **밖에 있으면 아무 작업도 못 한다.** 터미널이 있는 PC 앞에 있어야만 한다.

## 배경 — 실측한 사실 (2026-09-02)

| 항목 | 실측값 | 설계에 미치는 영향 |
|---|---|---|
| 서버 메모리 | 30GB 중 1.3GB 사용 | 새 서비스를 띄울 여유가 충분하다 |
| 서버 디스크 | 619GB 중 25% | 트랙 폴더 추가 여유 있음 |
| Node | v22.22.2 | Agent SDK 요건 충족 |
| `claude` CLI | `/usr/bin/claude` v2.1.201 | 이미 설치돼 있다 |
| `ANTHROPIC_API_KEY` | **서버에 0건** | 새로 발급해야 한다 (구독 크레딧 제도는 보류 중) |
| `app.py` | **18,011줄** | 여기 얹지 않는다 (0순위-B) |
| 열린 트랙 | **37개** | 폰 화면에서 검색·정렬이 필수 |
| 카톡 **발송** | **없음** (`api_kakao_ask`는 수신 전용) | 알림은 텔레그램으로 |
| `send_telegram(text)` | `shopping_shorts/notify.py:10` | 알림 수단이 이미 있다 |
| `raise_alert(...)` | `ops_alert.py:34`, 쿨다운 내장 | 승인 도배 방지가 이미 있다 |
| PWA 매니페스트 | 파일은 있으나 **참조하는 HTML 0개** | 실질적으로 미사용 — 새로 연결해야 한다 |
| 모바일 대응 화면 | 28개 (viewport 있음) | 기존 화면 톤을 따라갈 수 있다 |

⚠️ SSH(포트 22)가 세션 도중 막혔다. 사이트는 정상(443: 200/307). nginx 설정과 DB 정확한
경로는 **구현 시 실측**한다 — 설계를 가르는 값은 아니다.

## 전체 구조

```
   직원·사장님 (PC / 폰 브라우저)
            │  전용 주소 + 비밀번호
            ▼
   ┌──────────────────────────────────┐
   │  stockbrain-cs  (새 systemd 서비스) │
   │  ├ auth      로그인·등급 판정        │
   │  ├ agent     ClaudeSDKClient 세션    │
   │  ├ approvals 승인 대기함             │
   │  └ tracks    트랙 목록·선택          │
   └───┬──────────┬──────────┬──────────┘
       ▼          ▼          ▼
   라이브 DB   트랙 폴더   텔레그램
   (읽기전용)  .tracks/*   (알림)
```

**기존 `app.py`에 한 줄도 넣지 않는다.** 별도 서비스라 상담이 죽어도 고객 서비스는 살아 있고,
고객이 몰려도 상담은 느려지지 않는다.

## 권한 — 두 등급

```
사장님:  조회 자유 │ 수정 자유 │ 배포 자유       (터미널과 동일)
직원:    조회 자유 │ 수정 자유 │ 배포는 승인 필요
```

**왜 등급을 가르는가.** 승인이 하루 10건씩 쌓이면 사장님은 내용을 못 보고 누르게 된다.
승인이 형식이 되는 순간 안전장치가 사라진다. 사장님 본인 작업을 승인 대상에서 빼면
승인 건수가 줄어 **실제로 내용을 보고 누르게 된다.**

### 조회는 왜 자유인가

CS의 대부분은 조회로 끝난다. `allowed_tools`에 `Read`·`Grep`·`Glob`을 넣어 멈추지 않게 한다.

### 돈은 만지지 않는다

환불·결제·포인트 관련 쓰기는 **승인 대기함으로만** 간다. 클로드가 직접 실행하는 경로를
아예 두지 않는다. 기존 카톡봇(`bot_qa.py`)이 쓰는 원칙과 같다.

## 배포 — 기존 트랙 체계를 그대로 탄다

**안전장치를 새로 만들지 않는다.** `track.py finish`가 이미 하는 일을 그대로 부른다.

```
지시 → 트랙 폴더에서 수정 → (직원이면) ⏸ 승인 → track.py finish
                                                      │
                            ┌─────────────────────────┴──────┐
                            │ 게이트: 문법 → import → pytest  │
                            └─────────────────────────┬──────┘
                          실패 ◄────────────────────► 통과
                    병합 안 됨. 라이브 무사.      main 병합 → 3분 뒤 라이브
                    실패 이유를 보고한다.
```

이미 검증된 것을 재사용한다: 게이트 · 흡수 방지 · 동시 `finish` 순번 대기(전역 파일락).

⚠️ **작업창 자신의 트랙 폴더에서 일한다.** main 폴더의 코드는 건드리지 않는다 — 그것이 흡수의 재료다.

## 화면

### PC

```
┌──────────┬─────────────────────┐
│ 트랙 검색 │ 대화                 │
│ ● API관측│                     │
│ ● 랭킹렌더│  지시 / 답변         │
│ ○ 숏템…  │                     │
│          │  ✏️ 3개 파일 고침    │
│ CS 상담 3│  ⏸ 승인 대기        │
│ 승인대기 1│                     │
│          │ [입력...]            │
└──────────┴─────────────────────┘
```

### 폰

좌우 2단이 위아래로 접힌다. 대화가 화면 전부를 쓰고, 트랙 목록은 `☰` 뒤로 숨는다.
좁은 화면에서 목록이 자리를 뺏으면 정작 대화를 못 읽는다.

**트랙이 37개다.** 그래서 폰 목록은:
- 검색을 맨 위에 둔다
- **밀린 트랙을 위로** 올린다 (사장님이 신경 써야 할 것)
- 나머지는 접는다

### 코드는 요약으로 보여준다

폰에서 필요한 건 대개 "제대로 고쳤나"지 코드 한 줄 한 줄이 아니다.

```
✏️ 3개 파일 고침
  app.py         +12 −4  ▸     ← 누르면 펼쳐짐
  produce.html   +3  −1  ▸
  test_app.py    +20 −0  ▸
[전체 보기]  [승인]  [취소]
```

## 폰에서 긴 작업이 되는가

**된다.** 작업은 **서버에서** 돈다. 브라우저는 보고 있는 창일 뿐이다.

- 화면을 꺼도 작업은 계속된다
- 다시 열면 그동안 진행된 것이 이어서 보인다
- 끝나면 텔레그램으로 알린다

`finish` 게이트는 pytest를 다 돌려 몇 분씩 걸리므로 이 구조가 필수다.

## 모바일 형태

**웹이다. 앱스토어를 거치지 않는다.**

폰 브라우저로 열고 "홈 화면에 추가"를 한 번 하면 아이콘이 생기고, 주소창 없이 전체화면으로
열린다(PWA). 앱 심사·설치·업데이트 배포가 전부 없다.

푸시 알림만 진짜 앱과 다른데, 알림은 **텔레그램**이 맡으므로 필요가 없다.

## 안전장치 — 규칙이 아니라 구조로

| 위험 | 막는 방법 |
|---|---|
| 배포가 조용히 멈춤 | 트랙 폴더에서만 작업 — 라이브 워킹트리를 안 건드린다 |
| 고객 DB 손상 | DB를 **읽기 전용**으로 연다 (SQLite `mode=ro`) |
| 직원이 실수로 배포 | 배포는 사장님 승인 경유 |
| 게이트 우회 | `track.py finish`를 그대로 부른다 — 우회로를 만들지 않는다 |
| API 비용 폭주 | 사람당 하루 상한 (카톡봇 상한 로직 재사용) |
| 승인 도배 | `raise_alert`의 쿨다운 (이미 있음) |
| 고객 서비스 저하 | 별도 프로세스로 격리 |
| 누가 뭘 했는지 모름 | 전 대화가 세션으로 자동 저장 (`list_sessions`) |

## 기술 근거 (공식 문서 확인분)

`code.claude.com/docs/en/agent-sdk/python`에서 확인:

| 쓸 것 | 무엇 |
|---|---|
| `ClaudeSDKClient` | 세션 유지 — 대화가 이어진다 |

| `resume` | 어제 대화 이어받기 |
| `interrupt()` | 도는 작업 중단 |

## 인증과 비용

### 지금은 API 키뿐이다 (2026-09-02 확인)

구독(Pro/Max) 크레딧으로 Agent SDK를 쓰는 제도가 2026-06-15에 발표됐으나,
**같은 날 프로그램 전체가 보류(paused)됐다** — "구독으로 빌드하는 방식을 더 잘 지원하도록
플랜을 업데이트 중"이며 **현재 적용되지 않는다.**

따라서 지금은 **API 키 종량 과금이 유일한 방법**이다.

보류된 제도의 원안(재개 시 참고): Pro $20 / Max 5x $100 / Max 20x $200 / Team $20~100.
우리 예상 사용량(월 약 $28)은 Max 5x 크레딧 안에 들어간다. 재개되면 사실상 무료가 된다.

### 그래서 인증을 갈아끼울 수 있게 만든다

Agent SDK는 `ANTHROPIC_API_KEY`가 있으면 그것을 쓰고, 없으면 번들 CLI 인증을 쓴다.
**키를 넣고 빼는 것만으로 전환된다** — 구독이 열리면 설정 한 줄만 바꾼다.

인증 결정을 코드에 흩지 말고 **한 곳(`auth.py`)에서만** 정한다 (0순위-B).

### 비용 추정

상담 1건(보수적): 시스템+매뉴얼 20,000 토큰(캐시됨) / 대화+조회 15,000 / 답변 2,000

Opus 5 기준 ($5 / $25 per 1M), 프롬프트 캐싱 적용:

| | 1건 | 하루 20건 | 월(20일) |
|---|---|---|---|
| 캐싱 없이 | 약 230원 | 4,600원 | 92,000원 |
| **캐싱 켜고** | **약 100원** | **2,000원** | **약 40,000원** |

캐싱은 켠다. Sonnet 5로 내리면 절반 이하지만, CS 진단은 정확도가 곧 신뢰이므로 **Opus로 시작**한다.

⚠️ 이 표는 **추정**이다. 실사용 후 `usage`로 실측해 갱신한다.

### 비용 안전장치

| 장치 | 내용 |
|---|---|
| 사람당 하루 상한 | 기존 카톡봇 상한 로직 재사용 |
| 이번 달 누적 표시 | 화면 상단에 현재까지 쓴 금액 |
| 예산 초과 자동 정지 | 한도 넘으면 멈추고 `send_telegram`으로 알림 |

⚠️ 크레딧·예산이 소진되면 **조용히 실패하지 않게** 한다 — 화면에 이유를 명시한다.
(이 코드베이스의 반복된 함정: "키 소진 또는 응답 오류"처럼 원인을 뭉개면 진단이 불가능해진다)

## 하지 않는 것 (YAGNI)

- 앱스토어 앱 — PWA로 충분하다
- 푸시 알림 — 텔레그램이 한다
- 직원별 세밀한 권한 — 두 등급으로 충분하다
- 대화 검색 — 이력 목록으로 충분하다. 필요해지면 그때 만든다
- 여러 트랙 동시 작업 — 한 번에 하나. 필요해지면 그때

## 검증 계획

| 무엇 | 어떻게 |
|---|---|
| 권한 분리 | 직원 계정으로 배포 시도 → 승인 대기함에 걸리는지 |
| 게이트 우회 불가 | 일부러 문법 오류를 낸 뒤 `finish` → 병합 안 되는지 |
| DB 읽기 전용 | 쓰기 시도 → 거부되는지 |
| 폰 화면 | 실제 폰 브라우저로 접속 (정적 검토는 관찰이 아니다) |
| 긴 작업 | 화면 끄고 재접속 → 이어지는지 |
| 세션 유지 | 대화 후 재접속 → 맥락이 남는지 |

⚠️ 화면은 **반드시 실제 브라우저에서 열어 확인**한다. 이 코드베이스의 반복된 함정이다.

## 미결 — 구현 시 정할 것

1. 전용 주소 (`cs.` 서브도메인 vs 경로) — nginx 실측 후
2. 포트 번호 — 사용 중인 포트 실측 후
3. 라이브 DB 정확한 경로 — 서버 실측 후
4. ANTHROPIC API 키 발급 — 사장님이 직접 (git에 넣지 않는다, `/etc/` env로)
5. 월 예산 상한 금액 — 얼마를 넘으면 정지시킬지
6. 구독 크레딧 제도 재개 여부 — 재개되면 키를 빼는 것만으로 전환된다
