# 믹스 — 비트당 다중 클립 이어붙이기 (D안)

- 날짜: 2026-07-18
- 트랙: 대본믹스통합
- 상태: 설계 승인('고'), 스펙 검토 대기

## 1. 문제 (실사고)

사장님 제보 — 믹스 영상 3~4초에 hook(냉동 삼겹살)과 안 맞는 장면(구운/손질 고기)이 나온다.

**근인(프레임+코드 실측)**: `video_assemble.py`의 `_render_mix`가 한 비트에 **소스 구간 1개**만 골라,
그 구간의 **끝(end)을 무시**하고 `-ss start -t tts_dur`로 나레이션 길이만큼 재생한다. 매칭 구간이
나레이션보다 짧으면(hook: 구간 2.2초 vs 나레이션 4.9초) **구간을 넘어 원본의 다음 장면이
그대로 흘러나온다**(유출). AI는 "냉동 봉지"만 hook에 정확히 골랐는데 렌더가 그 경계를 안 지킨다.

**사장님 통찰(설계 방향)**: 루프는 어색하다. 조각 장면과 대사 길이가 같아야 한다. 단, 장면 먼저
짜고 대본을 거기 맞추는 워크플로우 역전은 원치 않는다.

## 2. 목표

각 비트(대사)의 화면을 **그 대사에 어울리는 소스 구간 여러 개를 순서대로 이어붙여** 대사 길이에
정확히 맞춘다. 어떤 클립도 자기 매칭 구간 [start,end]를 넘지 않는다(유출 차단). **대본 먼저
워크플로우는 그대로** — 사장님은 대본만 쓰면 된다.

## 3. 확정된 설계 결정

1. **부족분(후보를 다 이어붙여도 대사보다 모자랄 때)** = 마지막 클립을 그만큼 **살짝 느리게**
   (setpts 슬로모)로 늘려 정확히 채운다. 루프·정지 아님.
2. **매칭과 조립 둘 다 손본다** — AI가 비트당 충분한 구간을 주도록 + 조립이 그걸 이어붙이도록.
3. **전환 = 하드컷** (기존 비트 간 컷과 동일). 크로스페이드는 재인코딩이 필요해 concat `-c copy`가
   깨지고 배포 재시작 리스크(2026-07-12 교훈)가 있어 제외.
4. **아주 짧은 자투리(<0.8초)** 는 별도 클립으로 만들지 않고 **앞 클립에 흡수**(길이 연장)해
   깜빡임을 막는다.

## 4. 컴포넌트

### 4.1 매칭 — `edit_plan.py` (Gemini 프롬프트 + 스키마)

- **지금**: 비트당 `primary` 1개 + `alternates`(대체 후보, "primary가 나쁘면 대신 쓰라"는 의미) 1~2개.
- **바꿈**: 비트당 **순서 있는 구간 리스트**를 받는다 — "이 대사에 어울리는 장면을, **이어서 재생할
  순서대로**, 대사 길이를 채울 만큼 충분히(부족하면 여러 개) 골라라. 첫 번째가 가장 잘 맞는 것."
  - 프롬프트가 각 비트의 목표 길이를 알도록 나레이션 글자수÷발화속도(`_SYLLABLES_PER_SEC`)로 대략
    초를 계산해 함께 준다("이 비트는 약 N초. 합쳐서 N초 이상 되게 골라라").
  - **환각 방지는 그대로**: 모델은 `seg_id`로만 지목, 실제 start/end는 코드가 인벤토리에서 되붙인다
    (`_validate_and_ground` 재사용·확장).
  - **의미 변화 명시**: 이 리스트는 "대안"이 아니라 "**순서대로 이어붙일 클립들**"이다. 서로 다른
    소스 영상에 걸쳐도 된다(관련성 > 소스 연속성).
- **하위호환**: 옛 job의 `primary`+`alternates`만 있는 edit_plan도 조립이 `[primary, *alternates]`
  순서 리스트로 읽어 그대로 동작(재렌더 없이).

### 4.2 조립 — `video_assemble.py` `_render_mix`

비트마다 (하나의 명확한 채움 규칙):
1. 비트의 순서 구간 리스트를 받아, 앞에서부터 각 구간의 **[start,end] 전체**를 클립으로 쌓으며 누적
   길이를 잰다. 각 클립은 `-ss start -to end`로 잘라 **구간 밖 프레임이 절대 안 나온다**(유출 차단).
2. 어떤 구간을 통째로 넣으면 `tts_dur`를 **넘길** 때: 그 구간을 `tts_dur`에 딱 맞게 **잘라** 넣고 종료.
   단 그렇게 잘린 조각이 **<0.8초**면(깜빡임) → 그 조각을 만들지 않고 **직전 클립을 슬로모로 늘려**
   `tts_dur`를 채운다.
3. 구간 리스트를 **다 써도 `tts_dur`에 모자라면**(재료 부족) → **마지막 클립을 슬로모**(setpts)로
   부족분만큼 늘려 정확히 맞춘다.
   → 2와 3은 같은 원리: **남는 시간은 항상 "직전/마지막 클립을 슬로모로 늘려" 채운다**(새 자투리
   클립을 만들지 않는다). 슬로모가 필요 없는 경우(구간 합계가 딱 맞거나 넘침)엔 하드컷만 쓴다.
4. 비트 클립들(각 720x1280 libx264/aac 30fps 동일 규격)을 concat `-c copy`로 붙여 그 비트의 최종 클립.
   전체 비트 클립을 다시 concat → `mix_raw.mp4`.

- **켄번즈/기본 줌 vf**는 비트 단위 유지(중요 비트=줌). 비트 내 여러 클립에 동일 vf 적용해 규격 통일.
- **순수 계획 함수 분리**: "구간 리스트 + tts_dur → 클립 계획(각 클립의 src·start·dur·speed)"을
  ffmpeg와 분리된 **순수 함수**로 뽑아 유닛 테스트가 가능하게 한다(현재 `_pick_segment`를 대체·확장).

## 5. 불변식 (테스트로 잠근다)

1. **유출 0**: 어떤 클립도 자기 매칭 구간 [start,end]를 넘지 않는다 — 사장님이 본 버그의 뿌리.
2. **길이 일치**: 비트 영상 총 길이 == 그 비트 나레이션(tts) 길이 (±1 프레임).
3. **소스 충분 시 슬로모 0**: 구간 합계가 tts_dur를 충분히 덮으면(마지막 잘림 조각 ≥ 0.8초)
   슬로모(speed 조정) 없이 하드컷만으로 채운다. (합계가 부족하거나 자투리<0.8초일 때만 슬로모.)
4. **자투리 없음**: 0.8초 미만짜리 독립 클립이 생기지 않는다.
5. **하위호환**: primary+alternates만 있는 옛 edit_plan도 순서 리스트로 읽혀 크래시 없이 렌더된다.

## 6. 테스트 전략

- **순수 계획 함수**(구간 리스트→클립 계획): 유닛 테스트로 불변식 1~5를 직접 검증
  (넘침 잘라내기 / 자투리 흡수 / 부족분 슬로모 / 소스충분시 슬로모0 / 옛포맷 읽기).
- **실렌더 grounding**: 실제 ffmpeg로 한 비트를 렌더한 뒤 **ffprobe로 총길이 == tts_dur** 확인 +
  **구간 밖 프레임이 안 샜는지**(경계 넘어간 지점의 프레임을 매칭 구간 내 프레임과 대조) 검증.
  로컬에 ffmpeg 있음(기존 테스트가 씀).
- 매칭 프롬프트 변경은 스키마 파싱·grounding 유닛으로 커버(실제 Gemini 호출은 서버서만 관측).

## 7. 범위 밖 (다음 파도)

- 크로스페이드·전환 효과(성능·배포 리스크로 제외).
- 클립 간 소스가 자주 바뀔 때의 "너무 분주함" 미세 튜닝(관련성 우선으로 일단 감수).
- AI가 준 구간의 **시각적 중복 회피**(같은 장면 반복 방지) — 관련성 판정에 맡기고, 필요 시 후속.
- 비트당 목표 길이를 벗어나는 재료 부족 상황의 UX 경고(지금은 슬로모로 조용히 처리).

## 8. 확인 필요 (구현 때 실데이터로)

- AI가 실제로 "충분한 구간"을 주는지 서버 실호출로 재확인(프롬프트 튜닝 여지).
- `min_clip = 0.8초` 임계값은 첫 실렌더 관측 후 조정 가능.
- 슬로모 상한(너무 느려지면 어색) — 예: 1.5배 이상 늘려야 하면 경고 로그(후속 UX 대상).
