### ★가장 중요한 발견 — 무음 감지가 **한 번도 동작한 적이 없었다**

`audio_post.py`의 `detect_silences`/`detect_edge_silence`가 **한글 경로에서 항상 `[]`/`0.0`**을
반환하고 있었다. 무음이 없어서가 아니라 **재지도 못하고** 0이었다:

- ffmpeg는 stderr를 UTF-8로 내는데 `text=True`만 주면 파이썬이 cp949로 디코드 → 리더 스레드
  `UnicodeDecodeError` 사망 → `except Exception: return []`이 조용히 삼킴.
- 이 저장소는 경로에 `로또의 주식`이 들어가 **항상** 밟는다.
- 같은 함정을 `video_assemble.py:546`(`_FF_TEXT`)이 2026-07-16에 이미 고쳤는데
  **audio_post는 그 수정을 못 받았다**(0순위-B 전형).

→ `audio_post._FF_TEXT` 추가, 3곳 수정. 전수 검사 도구 `tools/audit_subprocess_encoding.py`로
  남겼다(고치기 전 코드에서 3건 잡고 rc=1, 고친 뒤 0건 rc=0 — **검사가 진짜 잡는지 확인함**).

### 한 것

**백엔드**
- `audio_post.extract_peaks()` — ffmpeg s16le 8kHz → 막대 120개 피크(서버 추출: 판정과 화면이 같은 엔진)
- `audio_post.find_gaps()` — 문장 **중간** 쉼만(끝은 head/tail_trim 몫). keep 0.06초 남김
- `audio_post.cut_gaps()` — atrim+concat으로 잘라낸 mp3 생성. 실패 시 원본 유지
- `app._apply_beat_trim()` — 트림 판단 **단일 출처**(trim/trim_all이 공유). `set` 모드(드래그) 추가
- API: `GET wave/{idx}` / `POST trim_all` / `POST gap` / `POST gap_all`
- `video_assemble._apply_gap_cuts()` — assemble 진입부에서 tts_paths를 잘린 파일로 교체
  → `_render_mix`·`_beat_timeline`·`_burn_captions` **셋이 자동으로 따라온다**
- `video_assemble._shrink_caps_for_gaps()` — 자막을 잘라낸 만큼 당김.
  `_adjust_caps_for_trim`이 head_trim과 gap_cuts를 **둘 다** 반영(한쪽만 return하면 다른 쪽이 죽는다)
- `capcut_draft` — 내보낼 때도 잘린 사본을 복사(타임라인과 어긋나지 않게)

**화면(`produce.html`)**
- `.wf` 필름 띠: 진짜 파형 + 앞뒤 분홍 손잡이 드래그 + 노란 빗금(중간 쉼, 클릭 토글)
- 줄마다 `✂ 빈 곳 자르기` / `↩︎ 되돌리기`, 상단 `✂ 무음 전부 자르기` / `↩︎ 전부 되돌리기`
- `▶` 재생이 트림·중간컷을 반영(자른 소리를 그대로 들려준다 — 종전엔 늘 원본을 틀었다)
- 옛 장식 파형(`_waveHTML`)은 **음성 없는 줄에만** 남김(중복 제거)
