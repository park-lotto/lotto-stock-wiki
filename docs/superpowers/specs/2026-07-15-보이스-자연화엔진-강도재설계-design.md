## 1. 왜 다시 설계하나

엔진(`narration_naturalize.py`)은 구현·테스트·배포까지 끝났고 유닛 테스트도 전부 green이다.
그런데 **사장님이 작업대에서 슬라이더를 실제로 만져보니 아무 변화가 없었다.**

재현(2026-07-15, 로컬):

```
intensity=0.0: '이거 진짜 대박이거든요 끝까지 보세요'
intensity=0.3: '[curious] 음, 이거 진짜 대박이거든요 끝까지 보세요'
intensity=0.7: '[curious] 음, 이거 진짜 대박이거든요 끝까지 보세요'
intensity=1.0: '[curious] 음, 이거 진짜 대박이거든요 끝까지 보세요'
```

**0.3 / 0.7 / 1.0의 출력이 완전히 같다.** 0으로 내려야만 꺼진다 = 강도 슬라이더가 아니라 on/off 스위치다.
텍스트가 같으면 seed 고정(42) 하에서 **소리도 완전히 같은 take**가 나온다. 사장님 관측이 정확했다.

### 1.1 스테이지별 원인 (코드 확인 완료)

| 스테이지 | 실제 동작 | 판정 |
|---|---|---|
| 추임새 | `if intensity < 0.15: return` → 넘으면 **무조건 1개**(`max_fillers_per_text=1`) | 임계형(binary) |
| 감정곡선 | 동일하게 `< 0.15` 임계 + `max_tags_per_beat=1` | 임계형(binary) |
| 끝음 | **마침표를 `…`로** 바꾸는데 **코퍼스 10줄에 마침표가 0개** | 영원히 무발동 |
| 구어체 | `take = int(len(hits) * intensity)` — 짧은 문장은 hits 0~1개 → `int(1×0.9)=0` | 1.0에서만 발동하는 계단 |
| 끊어읽기 | 연결어미가 문장에 있어야 함 — hook 문장엔 없음 | 대상 없음 |
| 연음/발음 | `dict: {}` 비어있음 | 아무것도 안 함 |
| 억양 | 코드가 `return text` (주석: "최소 구현: 현재는 무변경에 가깝게") | **미구현** |

→ 8개 중 이 코퍼스에서 실제로 동작하는 건 **정규화·추임새·감정곡선 3개**뿐.

### 1.2 더 큰 문제 — 작업대가 실전과 다른 세계를 보여준다

실제 믹스 job 대본(서버 DB 실측):

```
[hook]       감자 찌지 마세요. 집에 있는 이것 하나면 역대급 간식 탄생합니다.
[painpoint]  번거롭게 튀기지 마세요. 기름 한 방울 없어도 밖에서 파는 것보다 훨씬 바삭해지니까요.
[훅]         매일 에어컨 틀어도 집안이 눅눅하거나 건조하다면 이걸 꼭 써보세요.
```

튜닝 코퍼스(`assets/tune_corpus.json`)와 세 가지가 다르다:

1. **마침표가 있다** — 코퍼스엔 10줄 전부 없다. 끝음 스테이지가 실전에선 발동하는데 작업대에선 절대 안 한다.
2. **한 비트가 2문장이고 길다** — 구어체·끊어읽기가 걸릴 자리가 실전엔 더 많다.
3. **비트 role 이름이 다르다** — 코퍼스는 `hook/body/build/cta`, 실제는 `painpoint/twist/utility` + **한글**(`훅/페인포인트/반전/실용`). 엔진의 `_ARC_BY_ROLE`엔 이 이름들이 없어 위치기반 폴백으로 샌다.

**즉 사장님이 작업대에서 맞춘 값이 실제 영상에서 다르게 동작한다.**
2026-07-15 오전 whole-branch 리뷰가 잡은 S1~S10(작업대≠렌더 **배선**)과 같은 병이고, 이건 **내용** 층위다.

### 1.3 왜 테스트가 통과했나

각 스테이지를 **자기한테 유리한 입력**으로 격리 테스트했다(끝음은 마침표 있는 문장으로, 끊어읽기는 연결어미 있는 문장으로).
**실제 대본을 통과시키는 테스트가 하나도 없다.** 그래서 "코퍼스에선 아무것도 안 일어난다"를 아무도 못 봤다.

핸드오프의 두 가정도 실측으로 반증됐다(2026-07-15):
- ~~"규칙 정교화는 데이터 조정, 코드수정 최소"~~ → 강도가 코드 층위에서 죽어 있어 데이터로 못 고친다.
- ~~"연속성 v3 미지원이면 payload 무시라 안전"~~ → 실제로는 **400 에러**(`7e053a18`에서 수정).

## 2. 목표와 비목표

**목표**
1. 사장님이 노브를 돌리면 **눈(텍스트)과 귀(소리) 모두 단계적으로 변한다.**
2. 사장님이 **한 번** 맞추면 **성우를 몇 명 추가하든 자동 적용**된다.
3. 작업대에서 들은 소리가 **실제 영상 소리와 같다**.

**비목표 (YAGNI)**
- 성우별 말투 규칙 분화 (발음 예외만 허용 — §3.2)
- 대본 생성 로직 변경 (이 트랙 소관 아님)
- 감정태그 자동삽입 고도화 (v3 태그는 현 수준 유지)

**성공 기준 (측정 가능)**
- 실제 대본 픽스처에서 노브 5단계 출력이 **서로 전부 다르다**.
- 8스테이지 각각이 실제 대본에서 **최소 1회 발동**한다(발동 0회면 그 스테이지는 죽은 것).
- 사장님이 귀로 "이 정도면 사람 같다"고 판단해 동결 → 그 값이 실제 렌더 mp3에 반영됨을 실측.

## 3. 설계

### 3.1 전역 말투규칙 (핵심 변경)

**현재**: `naturalize_profile`이 `voice_presets` 행마다 따로 저장 → 성우 20명이면 튜닝 20번, 새 성우는 엔진 기본값으로 시작.

**변경**: 말투규칙은 **전역 1개**.

| 무엇 | 저장 위치 | 근거 |
|---|---|---|
| 말투규칙 8스테이지 + 노브값 + caps | **`settings` 테이블** 단일 키 `naturalize_profile_global` | `좋습니다→좋아요`, `50%→오십 퍼센트`, 추임새, `[curious]`는 **성우와 무관한 한국어/모델 규칙** |
| 발음 예외 | `voice_presets.naturalize_profile` → **`pronunciation.dict`만** | 성우마다 틀리게 읽는 단어가 다름(오독경보가 발견) |
| 목소리 감도 (stability/style/speed/silence_trim) | `voice_presets` (현행 유지) | 목소리 특성이라 성우별이 맞음 |

**해석 순서**: `DEFAULT_PROFILE` → `global` → `preset.pronunciation.dict`(있으면 병합).
`store.get_setting/set_setting`이 이미 있으므로 새 테이블 불필요.

**마이그레이션**: 기존 preset별 `naturalize_profile`은 오늘 사장님이 동결한 것뿐이라 값 보존 가치가 낮다.
전역 키가 비어 있으면 `DEFAULT_PROFILE`로 시작하고, preset 쪽은 **`pronunciation.dict`만 읽는다**(나머지 필드는 무시).
`_voice_snapshot`이 전역+예외를 합쳐 job 스냅샷에 실어 보낸다(오전 S1 수정 구조 그대로 재사용).

### 3.2 원노브 — "낭독체 ↔ 사람말"

노브 하나 `naturalness` (0.0~1.0). **5단계**로 양자화(`level = round(naturalness * 4)`, 0~4).
각 레벨이 8스테이지 값을 한꺼번에 세팅한다. 매핑표는 **데이터**(`NATURALNESS_LEVELS`)로 코드 밖에 두어 사장님 귀 튜닝으로 조정 가능하게 한다.

레벨 정의(**시작점** — 실제 값은 구현 Task에서 실제 대본으로 관찰하며 채운다):

| level | 이름 | 성격 |
|---|---|---|
| 0 | 원문 그대로 | 전 스테이지 off (정규화만 유지 — 숫자·기호는 항상 읽어야 함) |
| 1 | 살짝 | 종결어미 구어체만, 추임새 없음, 훅에만 태그 |
| 2 | 보통(기본) | + 끊어읽기 일부, 끝음 일부, 2~3비트마다 추임새 1개 |
| 3 | 많이 | + 끊어읽기 전부, 끝음 전부, 비트마다 추임새 |
| 4 | 과하게 | 상한선 확인용(사장님이 "이건 과하다" 경계를 듣기 위함) |

UI: **노브 하나가 기본**. 8개 개별 슬라이더는 **`<details>` 고급 패널로 접는다**(삭제 아님).
개별 슬라이더를 만지면 노브는 "직접 조정됨"으로 표시(노브값과 실제값이 어긋나 헷갈리는 것 방지).

### 3.3 스테이지 비례화 (강도가 실제로 먹게)

**원칙**: 각 스테이지는 ① 적용 후보 목록을 만들고 ② intensity 비율만큼 **앞에서부터 결정적으로** 적용한다.
후보가 0개면 아무 일도 안 일어난다 — 그건 입력(코퍼스) 문제이지 강도 문제가 아니다.

| 스테이지 | 변경 |
|---|---|
| **추임새** | 텍스트당 1개 고정 → **비트 빈도**로: intensity → "N비트마다 1개"(0.2=5비트마다, 1.0=매비트). `max_fillers_per_text`는 텍스트 내 상한으로만 남기고 **강도를 죽이지 않게** 함 |
| **감정곡선** | 임계형 → **태그가 붙는 비트 비율** + 레벨별 태그 세기(약: `[warm]` / 강: `[excited]`) |
| **끝음** | 마침표만 대상 → **종결어미(`~요/~다/~죠`) 뒤**도 대상에 포함(마침표 없는 대본에서도 동작) |
| **구어체** | `int()` 내림 때문에 후보 1개면 1.0에서만 발동 → **올림 기반**(`ceil`)으로 바꿔 낮은 강도에서도 최소 1개 반영 |
| **끊어읽기** | 현행 유지(이미 비례) — 단 실제 대본에서 후보가 잡히는지 테스트로 확인 |
| **연음/발음** | 사전을 **실제로 채운다**(오독경보가 잡은 것부터). 전역 사전 + 성우별 예외 |
| **억양** | **구현**: 물음표 상승 유지 + 강조 지점에 v3 태그/구두점 부여. 캡 안에서 동작 |
| **정규화** | 현행 유지(항상 on) |

### 3.4 비트 role 별칭 (실측 기반 — 생각보다 심각)

**정본**(`edit_plan.py:22`): `_REQUIRED_ROLES = ["훅", "페인포인트", "반전", "실용", "CTA"]` — **한글 4개 + CTA**.

**엔진이 아는 것**(`_ARC_BY_ROLE`): `hook · intro · build · body · payoff · cta`
→ **정본과 단 하나도 일치하지 않는다.** `CTA`조차 대소문자가 달라 안 맞는다.

**게다가 role은 열린 집합이다.** `edit_plan.py:210` `_FREE_INSTR` = *"비트 수와 구조(role 라벨)를 네가 자유롭게 정해라"*
→ 자유 모드에선 **Gemini가 role 이름을 지어낸다.** 별칭표만으로는 원천적으로 다 못 막는다.

서버 실측 분포(`mix_jobs.edit_plan_json` 전수):

```
hook 6 · Hook 1 · 훅 7          painpoint 6 · PainPoint 1 · 페인포인트 7
twist 4 · Twist 1 · 반전 7 · reversal 1 · reveal 1
utility 5 · 실용 7 · practical 1 · Solution 1        cta 1 · CTA 13
```

**17가지 변종** — 한글/영어/대소문자/동의어 혼재. 가장 많은 `CTA`(13회)가 매칭 실패.
**즉 지금 거의 모든 비트가 감정곡선 role 분기를 타지 못하고 위치기반 폴백으로 새고 있다.**

**설계**:
1. **정규화**: `strip().lower()` 후 매칭(→ `CTA`/`cta`/`Hook`/`hook` 흡수).
2. **별칭표**: 정본(한글) 기준으로 관측된 변종을 매핑.
   `훅 ← hook` / `페인포인트 ← painpoint` / `반전 ← twist, reversal, reveal` / `실용 ← utility, practical, solution` / `CTA ← cta`
3. **미지 role**: 위치기반 폴백은 유지하되 **조용히 넘어가지 않고 경고**(preview 응답 + 서버 로그).
   지금은 Gemini가 새 이름을 만들어도 아무도 모른다 — 그게 이 결함이 여태 숨어 있던 이유다.
4. 별칭표는 **데이터**로 둔다. 경고 로그에 새 변종이 쌓이면 표에 추가하면 된다.

**근본 대안(이 트랙 밖)**: `edit_plan`이 자유 모드에서도 role을 정본 어휘로 강제하면 열린 집합 문제 자체가 사라진다.
`edit_plan.py`는 대본 트랙 소관이라 **여기서 건드리지 않는다** — 사장님께 별도 보고하고 그 트랙에 인계한다.

### 3.5 "무엇이 적용됐는지" 가시화 (재발 방지의 핵심)

`naturalize()`가 변환 텍스트뿐 아니라 **스테이지별 적용 횟수**를 함께 반환한다:

```python
{"text": "...", "applied": {"spoken_style": 2, "fillers": 1, "endings": 0, ...}}
```

작업대가 이걸 표시한다. 그러면 **"슬라이더를 돌렸는데 왜 그대로냐"가 즉시 눈에 보인다.**
오늘 사장님이 겪은 일(아무 변화 없음 → 원인 불명)이 앞으로는 화면에서 바로 드러난다.

기존 호출부 호환: `naturalize()`는 문자열 반환을 유지하고 `naturalize_detail()`을 신설하거나,
반환 타입 변경 시 `mix_pipeline.synthesize_line` 한 곳만 고치면 되게 한다(호출부는 이미 단일 경로로 합쳐져 있음 — 오전 S1 수정 덕).

### 3.6 튜닝 코퍼스 현실화

`assets/tune_corpus.json`을 **실제 대본 형태**로 교체한다:
- 실제 `mix_jobs.edit_plan_json`에서 대표 비트를 뽑아 시드로 사용(제품명 등은 일반화).
- **마침표 포함, 비트당 1~2문장, 실제 role 이름** 사용.
- role은 **정본 5종**(`훅·페인포인트·반전·실용·CTA`)을 모두 포함 + **영어 변종 최소 1개**(별칭 경로가 실제로 도는지 보기 위해) + **미지 role 1개**(경고 경로 확인용).
- 8스테이지 각각의 후보가 **최소 1줄에는 존재**하도록 구성(그래야 튜닝이 가능).

### 3.7 오독경보 오탐 제거

> **정정(계획 수립 중 실측)**: 최초 진단("쉼표 차이가 오탐 원인")은 **틀렸다.**
> `asr_check._tokens`(15-19줄)가 태그·문장부호를 **이미 제거하고 있었다.** 코드를 읽고 반증됨.

**진짜 원인 2가지** (2026-07-15 서버 실측):

```
원문 : 그, 삼 점 오 킬로그램에 이천 원이면 완전 혜자죠
ASR  : 그 3.5kg에 2,000원이면 완전 혜자죠.
판정 : sub(삼→3) sub(점→5kg에) sub(오→2) sub(킬로그램에→000원이면) …
```

1. **Whisper가 숫자 표기를 되돌린다.** 우리가 `3.5kg` → `삼 점 오 킬로그램`으로 정규화해 읽혔고
   **성우는 정확히 읽었는데**, Whisper가 `3.5kg`로 표기해 전부 sub로 잡힌다.
   → **정규화가 잘 동작할수록 오독경보가 빨개지는 역설.**
2. **띄어쓰기 차이**(`난리 난` vs `난리난`)도 sub로 잡힌다.

**해법**: 비교 전 **hyp에도 엔진과 같은 규칙**(`normalize_reading`)을 태워 표기를 맞추고, 공백을 제거한다.
표준형이 일치하면 오독 아님으로 조기 통과. 정규화는 **비교용**이며 표시는 원문 기준.
`mismatch_score`(N-best ranker)도 같은 개선을 자동으로 받는다 — 표기 차이로 take가 부당하게 감점되던 것도 사라진다.

## 4. 테스트 전략 (이번 사고의 재발 방지)

기존 테스트가 통과한 이유가 "스테이지마다 자기한테 유리한 입력"이었으므로, **입력을 실제 대본으로 고정**한다.

1. **단계 구분 테스트(핵심)**: 실제 대본 픽스처에 노브 0~4를 적용해 **5개 출력이 서로 전부 달라야 한다**.
   (오늘의 버그가 정확히 여기서 걸렸을 것 — `0.3/0.7/1.0` 동일)
2. **스테이지 생존 테스트**: 실제 대본 픽스처에서 **각 스테이지의 `applied` 횟수 ≥ 1**.
   0이면 그 스테이지는 죽은 것으로 간주하고 실패시킨다(억양·발음사전 미구현을 잡는 그물).
3. **전역 적용 테스트**: 전역 규칙 동결 → **새로 추가한 성우**의 job 스냅샷에 그 규칙이 실린다.
4. **발음 예외 테스트**: 성우별 `pronunciation.dict`가 전역 위에 병합되고, 다른 성우엔 영향 없음.
5. **role 별칭 테스트**: 한글·영어 role이 같은 태그를 받고, 미지 role은 경고를 남긴다.
6. **결정성 유지**: 같은 입력·같은 프로파일 → 같은 출력(기존 회귀 유지).

**실측 게이트(자동테스트로 대체 불가)**: 서버에서 실제 대본으로 노브 2 vs 노브 4를 합성해
**mp3가 실제로 다르게 들리는지** 사장님 귀로 확인 → 동결 → 그 값으로 렌더된 영상에서 재확인.

## 6. 위험

| 위험 | 대응 |
|---|---|
| 공유 파일(`app.py`·`store.py`)을 다른 트랙이 동시 편집 | 내 hunk만 stage(`git apply --cached`), `git add -A` 금지. 오전에 썸네일 트랙 hunk 4개를 실제로 걸러낸 방식 재사용 |
| 매핑표 값이 첫 시도에 맞을 리 없음 | 값은 **데이터**로 분리 — 사장님 귀 튜닝으로 코드 수정 없이 조정. 단 "코드수정 최소"라는 옛 가정을 반복하지 말 것: **구조는 코드로 고쳐야 한다** |
| 전역 전환으로 기존 동결값 상실 | 오늘 동결분뿐이고 어차피 무의미한 값(강도가 안 먹던 시절). 전역 기본에서 다시 시작 |
| ASR rate limit로 오독경보가 불안정 | 별건. `transcribe`의 `except Exception: return None`이 에러를 삼켜 원인 규명이 막힘 — 최소한 원인을 로그에 남기게 함 |
