# 장면 라이브러리 페이즈2-A — 매칭 · 컷어웨이 · 검수판 (설계)

- 날짜: 2026-07-18
- 트랙: 장면라이브러리
- 선행: 페이즈1(자산 뱅크·자동분할·도서관 다리) 완료·라이브. 라이브 `scene_assets` 12개 적재됨(재료 확보).
- 상위 설계: `docs/superpowers/specs/2026-07-15-쇼핑쇼츠-장면라이브러리-재사용짤뱅크-design.md`(§6 매칭 / §7 렌더 / §8 UI). 이 문서는 그 페이즈2를 **범위 자른 첫 증분(2-A)**으로 구체화한다.

---

## 1. 목표 (범위 확정)

대본 비트마다 라이브러리에서 **어울리는 짤을 AI가 골라**, 나레이션 위에 **컷어웨이(b-roll)로 자동 배치**하고, 사장님이 **검수판에서 확인·해제**한 뒤 렌더한다.

**이 증분(2-A)에서 하는 것**: 매칭 + 컷어웨이 렌더 + 검수판.
**페이즈2-B로 미루는 것**(명시적 비범위): replace(전체 교체)·sfx(효과음)·overlay(스티커)·수동 드래그 배치·부분 컷어웨이(비트 중간 삽입)·오디오 규격 고정(`-ar`/`-ac`)·`keep_original_audio`.

---

## 2. 아키텍처 · 데이터 흐름

기존 믹스 파이프라인에 **삽입 한 곳, 읽기 한 곳**만 추가한다.

```
run_mix_job:
  build_edit_plan → [★삽입] match_scene_assets(plan, customer_id) → _synthesize_beats → status=ready_for_review
                                                                         (plan을 job에 저장)
        ↓ 검수판(사장님 확인·해제)  ── produce.html
run_render:
  job에서 plan 로드 → assemble(plan, ...) → [★읽기] beat["cutaway"]가 있으면 컷어웨이 오버레이
```

- **저장위치 = 읽기위치 일치**: 매칭이 `beat["cutaway"]`에 쓰고, 렌더가 같은 키를 읽는다. 중간 배선(별도 테이블·전역상태) 없음 → seam 버그 회피(트랙 교훈).
- 매칭 결과는 `plan` 안에 살아 `update_mix_job(edit_plan=plan)`으로 이미 저장된다(별도 저장 경로 신설 안 함).

## 3. 컴포넌트 A — `scene_match.py` (순수 매칭, 신규 파일)

### 3.1 인터페이스
```
match_scene_assets(plan: dict, assets: list[dict], *, threshold: float = 0.6) -> dict
```
- **입력**: `plan`(build_edit_plan 산출 — `beats[]`에 `beat_idx·role·narration·target_seconds`), `assets`(= `Store.list_scene_assets(customer_id, asset_type="clip")`).
- **부수효과 없음**: `plan`을 복사·주석 달아 반환하는 순수함수. Gemini 호출은 주입 가능한 경계(`_vault_call`) 뒤에 둔다 → 테스트가 스텁으로 전량 검증.

### 3.2 1차 필터 (무료·기계적, Gemini 호출 없음)
비트마다 후보 자산을 다음으로 좁힌다:
- `asset_type == "clip"` (sfx/overlay는 2-B),
- `source_origin ∈ {짜집기, 촬영원본}` (표절 게이트 — 이미 commit에서 강제됐으나 방어적 재확인. `모름`/NULL이면 후보 제외),
- `category` 일치(비트의 category는 plan의 영상 카테고리 또는 비트 role 기반. 자산 category와 동일한 것만).

후보 0이면 그 비트는 `cutaway` 없이 통과(자동배치 안 함).

### 3.3 2차 판정 (Gemini `_vault_call` 캐스케이드)
- 후보가 1개 이상인 비트에 대해, **비트 나레이션 + 후보들의 다축 태그(subject·keywords·scene_desc)**를 한 프롬프트로 주고 `{best_asset_id, score(0~1)}`를 받는다.
- **키풀은 반드시 `edit_plan._vault_call` 캐스케이드**(전용 `SHORTS_GEMINI_KEYS` 직접 사용 금지 — 소진 회피가 존재 이유. 상위설계 Global Constraint 5).
- 응답 스키마 강제(JSON schema). 파싱 실패·키 소진(`_vault_call`이 None)이면 그 비트는 자동배치 없이 통과(조용한 오배치보다 안전한 실패).
- **비용 절감**: 후보가 정확히 1개면 Gemini를 건너뛰고 그 자산으로 채우되 점수는 보수적으로(예: 1차 필터 통과 = 0.6 기본) — 단, 저신뢰 자동배치 금지 원칙과 충돌하지 않도록 **후보 1개라도 임계 미만이면 제안으로**. (구현 시 결정: 1개 후보는 `score=threshold`로 두어 경계선상 → 자동배치. 근거: category+subject축이 이미 1차에서 걸러졌다. 계획 단계에서 재검토.)

### 3.4 출력
- **점수 ≥ threshold**: `beat["cutaway"] = {"asset_id": id, "score": s}` (자동배치).
- **점수 < threshold**: `plan["asset_suggestions"]`에 `{beat_idx, asset_id, score}` 누적("제안"만, 자동배치 안 함).
- 한 자산이 여러 비트에 최적일 수 있다 — v1은 **중복 허용**(같은 짤이 두 비트에 쓰여도 됨). 중복 회피는 2-B.

## 4. 컴포넌트 B — 컷어웨이 렌더 (`video_assemble` 확장)

### 4.1 핵심 안전장치 (최대 리스크의 구조적 소거)
상위설계 §7이 지목한 최대 리스크는 "컷어웨이가 자막/오디오 길이를 밀어 t0 싱크가 어긋남"이다. 이를 **구조적으로** 없앤다:

- 컷어웨이는 **비트 클립(`beat_{idx}.mp4`) 안에서** 자산 영상을 **풀프레임 오버레이**로 얹는다.
- **비트 길이(`tts_dur`)와 TTS 오디오 트랙은 그대로 둔다.** 비트 길이가 안 변하므로 이후 `concat -c copy`에서 뒤 비트들의 시작점이 절대 안 밀린다 → 자막 t0 불변.
- 자막은 이 파이프라인에서 비트 길이로부터 유도되므로(비트 클립을 이어붙인 위치), 비트 길이 불변 = 자막 싱크 불변.

### 4.2 구현 (검증된 코드 재사용)
- 이미 실렌더 검증된 모션레이어 오버레이(`_motion_layer_filters`, Task9의 `setpts=PTS-STARTPTS+start/TB` 게이팅)를 재사용/확장한다. 자산 클립을 풀프레임(720x1280)으로 스케일해 `enable='between(t, cs, ce)'` 창에 얹는다.
- **자산 오디오는 버린다**(비디오 스트림만 오버레이). 나레이션이 계속 흐르는 것이 b-roll의 정의 → **오디오 `-ar`/`-ac` 규격 선행작업이 2-A엔 불필요**. (그 선행작업은 replace/sfx를 붙이는 2-B에서 돌아온다 — 정직하게 남긴다.)

### 4.3 v1 배치 규칙 (결정적·단순)
- 컷어웨이 창 = 비트 시작(t=0)부터 `min(자산_길이, tts_dur)`.
- 자산이 비트보다 짧으면 남는 구간은 원본 footage가 채운다(현재 동작).
- 자산이 비트보다 길면 자산을 앞부분만 사용(비트 길이에서 잘림).
- 부분 컷어웨이(비트 중간 삽입)·켄번즈 상호작용 등 editorial 정교화는 2-B.

### 4.4 자산 클립 경로 해석
- `beat["cutaway"]["asset_id"]` → `Store.get_scene_asset(id)` → `media_path`. assemble이 store를 직접 못 보면(순수성), 호출부(`run_render`)가 asset_id→경로를 해석해 assemble에 넘긴다(seg 경로를 넘기는 기존 방식과 동일).

## 5. 컴포넌트 C — 검수판 (`produce.html` 검수 단계)

- 기존 믹스 검수 화면(비트 목록)에 비트별로:
  - 자동배치된 컷어웨이가 있으면 **자산 썸네일 + subject + score**를 표시,
  - **"이 짤 빼기" 토글 1개** — 끄면 그 비트의 `cutaway`를 제거(원본 footage만).
- 저신뢰 `asset_suggestions`는 접힌 채 비트 아래 "＋ 이 짤 넣기" 링크로만 노출(누르면 그 비트에 `cutaway` 지정).
- 토글 결과는 저장된 `plan`을 갱신(기존 job 갱신 경로 재사용). 렌더는 갱신된 plan을 읽는다.
- **v1은 여기까지** — 수동 드래그·라이브러리 검색·재배치는 2-B.

---

## 6. 신뢰·표절·비용

- **표절**: 후보는 commit 게이트를 통과한(출처 판정된) 자산뿐. `모름` 제외. subject 불일치는 1차 필터에서 탈락 → 애초에 후보 아님.
- **저신뢰 자동배치 금지**: 임계 미만은 제안으로만. 오배치 손해가 비대칭(엉뚱한 짤이 라이브 영상에 박히는 것 > 짤 하나 안 쓰는 것).
- **비용**: 매칭이 Gemini 호출을 추가하나 캐스케이드 예비키풀 사용 + 후보 0/1 비트는 호출 생략으로 최소화.

---

## 7. 테스트 (TDD)

- **`scene_match`(순수함수, Gemini 스텁)**: ① 후보 0 → cutaway 없음 ② 1차 필터가 category 불일치·`모름`·비-clip을 배제 ③ 점수 ≥ 임계 → 자동배치 / < 임계 → suggestions ④ `_vault_call`이 None → 조용한 실패(자동배치 없음, 예외 없음).
- **컷어웨이 렌더(실 ffmpeg)**: ① 컷어웨이 얹은 비트 클립의 길이가 `tts_dur`와 동일(ffprobe) = **싱크 불변 자물쇠** ② 창 구간 픽셀이 자산 프레임과 일치(오버레이 실제 적용) ③ 오디오 트랙이 TTS 그대로(자산 오디오 안 섞임).
- **엔드투엔드(seam)**: 매칭이 `beat["cutaway"]`에 쓴 asset_id를 렌더가 그대로 읽어 그 자산을 얹는지(저장위치=읽기위치). 실 payload 경로로 grounding.

## 8. 이 증분이 건드리는 파일

| 파일 | 변경 |
|---|---|
| `shopping_shorts/scene_match.py` | **신규** — 순수 매칭 |
| `shopping_shorts/mix_pipeline.py` | `run_mix_job`에 `match_scene_assets` 삽입 1줄, `run_render`에 asset 경로 해석 |
| `shopping_shorts/video_assemble.py` | `assemble`/비트 렌더에 컷어웨이 오버레이 분기 |
| `shopping_shorts/static/produce.html` | 검수 단계에 컷어웨이 표시·빼기 토글·제안 링크 |
| `shopping_shorts/tests/` | 위 3계층 테스트 |

기존 파일 경계는 유지(새 렌더 경로를 만들지 않고 기존 assemble을 확장 — 트랙 교훈: 각자 조립 금지).

## 9. 미해결·정직하게 남김

- **비트의 category 출처**: plan/비트에 category가 없으면 1차 필터가 category축을 못 쓴다. 계획 단계에서 비트→category 매핑을 확인(영상 전체 category를 쓰거나, 자산 subject↔narration 축만으로 매칭). 실측 후 결정.
- **후보 1개의 자동배치 여부**(3.3): category+subject가 이미 걸러졌으니 자동배치가 합리적이나, 저신뢰 금지 원칙과의 경계 — 계획 단계에서 확정.
- **실 재료로 검증**: 라이브 12개 자산과 실 대본으로 매칭 정확도를 눈으로 확인(합성 fixture 통과 ≠ 완료 — 트랙 교훈).
