## ① 회원 키가 config에만 들어가고 호출 모듈엔 안 갔다 (피해 최대)

    로그   [keypool] 유튜브 사장님 10 + 회원 52 = 62개   ← 성공처럼 보임
    실제   youtube_client.YOUTUBE_API_KEYS = 10개(소진된 사장님 키)
    결과   수집 9,622건 → 922건 (썰쇼핑 813 → 37건, -93%)

`from shopping_shorts.config import YOUTUBE_API_KEYS`는 **값 복사**다.
`config.YOUTUBE_API_KEYS = ...`로 재할당해도 그 모듈은 옛 목록을 계속 본다.
제미니는 2026-08-27에 `_push_pool_to_importers`로 고쳤는데 **유튜브만 빠져 있었다**
— config.py 주석에 그 함정이 적혀 있는데도.

판정: `config.X`와 `그모듈.X`의 **길이를 나란히 찍어라.** 같아야 진짜 배선이다.

## ② 수집·발굴 스크립트가 keypool.resync_pools를 안 불렀다

별도 프로세스라 FastAPI startup이 없다. 2026-08-31에 워커에서 똑같은 사고가 났고
(회원 키 44개를 통째로 몰랐다) 그때 웹·워커는 고쳤는데 **새로 만든 스크립트는 빠졌다.**

## ③ 지킴이 pgrep이 자기 명령줄을 잡아 재시작을 걸렀다

`pgrep -f 'harvest_styles_forever'`는 그 문자열을 인자로 가진 **아무 명령이나** 잡는다.
같은 셸에서 pgrep을 함께 돌리면 자기를 세고 "이미 돌고 있다"로 오판 → exit 0.
로그도 안 남는다. `ps`로 봐야 진짜가 드러났다.

## 그래서 지킬 것

```
□ 값을 넣는 곳과 읽는 곳을 **둘 다** 찍어 대조하라("합류 62개" 로그를 믿지 마라)
□ 짝이 있는 처방(제미니↔유튜브, 웹↔워커↔크론)은 **전수 grep**으로 빠진 쪽을 찾아라
□ 프로세스 판정은 pgrep -f 말고 ps로. 패턴에 자기 명령줄이 걸리는지 의심하라
□ "로그가 성공이라 말한다"는 검증이 아니다 — **결과 수치**가 검증이다
```
