### ⏭ 남은 것

1. **재측정** — 표본 13건은 작다. script_wiki가 늘면 다시 잴 것(프로브: `/tmp/cat_probe.py`,
   `/tmp/real_probe.py` 서버. 실행법은 아래 "삽질 힌트").
2. **기존 추측 행 재분류(백필)** — 지금은 새로 분석되는 것만 승격된다. 이미 `keyword`로
   박힌 행은 `daily_batch`가 구조분석을 다시 돌 때만 바뀐다. `category_source='keyword'`인
   행만 골라 재분류하는 배치를 넣을지 결정 필요.
3. **생활용품↔인테리어 경계** — 어휘 자체가 겹친다. 프롬프트로 경계를 정의해줄지
   (예: "설치·가구·공간연출=인테리어 / 소모품·주방잡화=생활용품"), 아니면 어휘를 합칠지
   **사장님 판단 필요**. 지금 Gemini 오답의 2/3이 여기서 난다.
4. **`save_to_wiki`가 사용자 카테고리를 extract에도 전파**(source='user') — 지금은 위키만
   고쳐지고 extract는 None으로 남는다. 코퍼스는 위키 행이 커버해 손실은 없으나,
   extract가 백필 대상에서 빠진다(`extracts_missing_structure`가 category IS NOT NULL 요구).
5. **I-3 원래 항목(`or None` 죽은 코드)** — 위 작업들로 의미가 줄었다. 정리만 하면 됨.
   ⚠️ `categorize()`는 **레퍼런스 랭킹과 공유** 함수라 반환값 변경은 그쪽도 흔든다.

### 🔑 삽질 힌트
- DB는 `shopping_shorts/data/reference.db` (**app.db 아님**).
- 서버엔 `sqlite3` CLI 없다 → `python3 -c`로 조회.
- `script_extracts`엔 **`full_text` 컬럼이 없다**(텍스트는 `script_json` 안). `.get('full_text')`가
  None→"len=0"이라 **데이터가 빈 줄 오독**하기 쉽다(2026-07-16 실제로 겪음).
- Gemini 키는 systemd가 주입 → 프로브 돌릴 땐 `set -a && . /etc/shopping-shorts.env && set +a`.
  안 하면 조용히 `NOKEY`가 나온다(정확도 0%로 보여 오판하기 쉬움).
- 뮤테이션 되돌릴 때 **`git checkout -- <파일>` 금지**(미커밋 수정까지 날아간다).
  문자열 치환 뮤테이션은 **들여쓰기를 깨뜨려 IndentationError**를 내기 쉽다 — 그건 테스트가
  결함을 잡은 게 아니라 파일이 깨진 것이라 아무것도 증명 못 한다. 조건식만 바꾸는 편이 안전.
