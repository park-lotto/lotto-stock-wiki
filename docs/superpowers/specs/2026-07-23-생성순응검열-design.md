# 생성 순응 검열 (빼쓰기 쪽) — 설계

- 날짜: 2026-07-23
- 트랙: `수집검열`
- 승인: 사장님 (2026-07-23, "고")
- 선행: `2026-07-23-수집흡수배선-제미니검열-design.md`(넣기 쪽 검열, 라이브)

## 배경 / 문제

넣기(수집·흡수) 쪽 검열은 라이브다(`gemini_audit.py`: 가동 성공률·완성도·훅스팸). 하지만
**빼서 쓰는 쪽 — 은행에서 부품·스파인을 꺼내 대본을 만들 때 제미니가 진짜 은행을 따르는지**는
아무 감지가 없다. 사장님 요구(2026-07-23): 검열은 넣기뿐 아니라 빼기까지 봐야 한다.

현재 빼쓰기 경로:
1. `mix_pipeline`: `bank_enabled=1`이면 `bank_assemble.assemble_bank_context`(승인 스파인 + 부품)
   + `avoid_block`(novelty)을 `bank_context` 문자열로 조립 → 생성 프롬프트 주입.
2. `edit_plan.build_scene_first_plan`: 제미니로 후보 N개 생성(`_scene_first_candidates`) →
   각 grounding → `rule_score` → (`judge=True`면) `candidate_judge`로 3축 채점 → 50:50 섞어
   best에 `recommended=True`.
3. **문제**: `bank_context`가 뭐였는지, judge 점수가 어땠는지 **job이 끝나면 그냥 버려진다.**
   은행이 그 대본을 실제로 형성했는지 관측할 데이터가 하나도 안 남는다.

가장 큰 실패 모드는 **은행이 아무것도 주입 못 한 것**이다 — 카테고리에 승인 부품이 0이거나
스파인이 없으면 `bank_context`가 비어 은행이 무용지물인데, 지금은 이걸 아무도 모른다.

## 목표

빼쓰기(생성) 시 은행이 실제로 대본을 형성하는지 **매 job 관측** → 검열 대시보드에 "생성 순응"
섹션. 결정적 3층(공짜) + 은행 주입된 job 중 샘플만 LLM 순응 채점(병목 제미니 최소 부하).

## 비목표 (YAGNI)

- 매 생성마다 LLM 순응 채점 — 이미 병목인 제미니(넣기 쪽 29% 성공률)를 더 악화. **샘플만.**
- 순응 실패 시 자동 재생성·자동 튜닝 — 이번엔 **관측만**. 사람이 신호 보고 판단.
- 넣기 쪽 흡수 성공률 개선(top_n 상향·키실패/빈추출 분리) — 별개 이슈, 후속 트랙.
- 텔레그램 알림 — 대시보드 패널만.

## 컴포넌트

### A. 사용 스냅샷 — `bank_assemble.bank_usage_snapshot` (결정적·공짜)

주입 내역이 job과 함께 버려지는 걸 잡는다. 순수 읽기 함수(store 조회만, Gemini 없음):

```
bank_usage_snapshot(store, category, k=5) -> dict {
    bank_enabled:   bool   # get_setting("bank_enabled")=="1"
    spine_present:  bool   # pick_spine_for_category(category) 있나
    spine_beats:    int    # 그 스파인 beat_chain 길이 (없으면 0)
    parts_by_bucket: {hook:5, cta:3, ...}  # STYLE_BUCKETS별 실제 조립 부품 수
    parts_total:    int
    avoid_present:  bool   # recent_script_usage로 회피블록이 실렸나
    category:       str
    empty:          bool   # spine·부품 통째로 비어 bank_context가 '' — 은행 무용
}
```

`empty=True` 또는 `spine_present=False` 또는 `parts_total < 임계(=5)`면 그 job엔 은행이
사실상 무용이다. **이게 사용 감지의 핵심.** 기존 `assemble_bank_context`는 그대로 두고
(문자열 조립 책임), 이 함수는 같은 조회를 재사용해 계측 dict만 만든다.

### B. 구조 순응 — `bank_usage_audit.structural_conformance` (결정적·공짜)

아크가 규정하는 '모양'을 출력이 가졌나를 LLM 없이 판정. 선택된(`recommended`) 후보의
`plan.beats` + story + snapshot으로:

```
structural_conformance(chosen_plan, snapshot, story) -> dict {
    beat_ok:        bool  # len(beats) >= max(snapshot.spine_beats, 5) — 아크 최소 골격
    opener_ok:      bool  # beats[0].narration이 강한 오프너 (edit_plan._STRONG_OPENER_TOKENS 재사용)
    cta_ok:         bool  # 마지막 비트 role이 CTA/마무리 or story.cta_line 존재
    plagiarism_hits: int  # 기존 plan.plagiarism_flags 개수 (그대로 베낌 = 은행 오용)
    conformant:     bool  # beat_ok and opener_ok and cta_ok and plagiarism_hits==0
}
```

`plagiarism_flags`는 `edit_plan._plagiarism_flags`가 이미 각 후보에 달아둔다 — 재사용만 한다.
표절은 순응의 반대 신호다(은행은 "결만 참고, 그대로 베끼지 마라"인데 베꼈으면 실패).

### C. 판단 감지 (결정적·judge 이미 계산됨)

`candidate_judge`가 켜졌나(현재 `backbone_base` 모드만 `judge=True`) + 그 점수를 그대로 기록.
추가 계산 없이 job 레코드에 실어 나른다:

```
judge_snapshot(candidates) -> dict | None {
    judged:        bool   # recommended 후보에 judge 필드가 있나
    total:         float  # recommended.judge.total (0~1)
    axes:          {script_quality, scene_sync, storyline}  # 0~5
    best_gap:      float  # best score - 2등 score (심사가 변별하나; 후보<2면 None)
}
```

### D. 샘플 LLM 순응 채점 — `bank_compliance.judge_compliance` (은행 주입 job 중 N에 1)

게이트: `bank_enabled=1 AND snapshot.empty==False AND 샘플 카운터 히트`. 카운터는
`store.get_setting("bank_compliance_counter")` 증가 → `counter % N == 0`일 때만(기본 **N=10**).

```
judge_compliance(injected_spine_charter, injected_parts_block, chosen_beats, call) -> dict | None {
    arc_follow:    int   # 0~5, 주입 아크/비트 흐름을 따랐나
    flavor_follow: int   # 0~5, 부품 결(훅 톤·CTA 스타일)을 참고했나
    verbatim_copy: bool  # 그대로 베꼈나 (True면 arc/flavor 높아도 감점 신호)
    reason:        str
}
```

프롬프트 요지: "아래 주입된 아크/부품을 참고하라고 시켰다. 생성된 대본이 그 흐름을 따랐나
(0~5)? 부품 결을 참고했나(0~5)? ★단 그대로 베낀 건 오히려 실패(verbatim_copy=true)." 실패/무키
→ None(결정적 신호만으로 폴백, 무해). `call` 주입점은 `pattern_bank._default_call`(키풀 로테이션
이미 적용됨, 넣기 쪽에서 고친 라운드로빈 재사용).

### E. 기록·집계 — `store.append_bank_usage` + `bank_usage_audit.compute_usage_audit`

매 job이 하나의 레코드를 남긴다:
```
record = {snapshot(A), conformance(B), judge(C or None), compliance(D or None), ts?}
```
`store.append_bank_usage(record)` = `bank_usage_recent` 설정(JSON 리스트)에 append, 최근
**K=50**개로 cap(오래된 건 버림). 넣기 쪽 `bank_ingest_last`와 달리 생성은 job당 1건이라
비율을 내려면 창(window)이 필요하다.

집계 순수함수(리스트 → 지표+신호등):
```
compute_usage_audit(recent) -> dict {
    n:                  int    # 창 크기
    bank_used_rate:     float  # empty==False 비율 (은행이 실제 쓰인 job)
    spine_present_rate: float
    parts_avg:          float
    conformance_pass_rate: float  # conformant==True 비율
    plagiarism_rate:    float  # plagiarism_hits>0 비율
    judge_avg:          float | None  # judged 레코드의 total 평균
    compliance:         {arc_avg, flavor_avg, verbatim_rate, n} | None  # 샘플된 것만
    health:             {level, reasons[]}  # usage_health()
}
```

신호등 `usage_health(agg)` (넣기 쪽 `audit_health` 패턴):
- `bank_used_rate < 0.5` → 🔴 "은행이 절반+ job에서 무용(승인 부품·스파인 부족)"
- `conformance_pass_rate < 0.7` → 🟡 "구조 순응 미달(훅/CTA/비트 누락)"
- `plagiarism_rate > 0.1` → 🟡 "표절 조각 섞임(은행을 베낌)"
- `compliance.arc_avg < 2.5` (5점 만점) → 🟡 "제미니가 주입 아크 무시 경향"
- 아무것도 안 걸리면 🟢

집계 결과는 `bank_usage_audit_last` 설정에도 저장(패널이 읽기 쉽게 분리).

### F. 대시보드 — "생성 순응" 섹션

`/api/bank/ingest_report`(이미 존재)의 payload에 `usage_audit` 추가. 수집 화면
`_renderBankPanel` 아래 섹션 1개:

```
🎬 생성 순응(최근 {n}편): {🟢/🟡/🔴}
   은행 사용률 {bank_used_rate}% · 구조순응 {conformance_pass_rate}% · 표절 {plagiarism_rate}%
   심사 {judge_avg}/5 · 순응샘플 아크 {arc_avg}/5·부품 {flavor_avg}/5 (표절 {verbatim_rate}%)
   {reasons를 ⚠️ 줄로}
```
데이터 없으면(생성 이력 0) "생성 데이터 없음" 표기. 기존 폴링 재사용.

## 데이터 흐름

```
[영상 믹스 생성] mix_pipeline
  ├ bank_enabled=1 → snapshot = bank_usage_snapshot(store, video_type)   ← 주입 내역 캡처
  │                  (assemble_bank_context는 그대로 문자열 조립)
  ├ sf = build_scene_first_plan(... bank_context ...)                    → 후보+judge+recommended
  ├ chosen = recommended 후보
  ├ conf = structural_conformance(chosen.plan, snapshot, chosen.story)   ← 결정적 순응
  ├ jsnap = judge_snapshot(sf.candidates)                                ← 판단(이미 계산됨)
  ├ (샘플 gate 통과 시) comp = bank_compliance.judge_compliance(...)      ← N에 1 LLM
  └ store.append_bank_usage({snapshot, conf, jsnap, comp})
        └ 내부: bank_usage_recent(최근 K) 갱신 + compute_usage_audit → bank_usage_audit_last
[수집 화면] /api/bank/ingest_report → usage_audit 섹션 렌더
```

## 에러 처리

- 전부 부가 관측 — 개별 실패는 삼키고 **생성 자체엔 영향 0(회귀0)**. snapshot/conformance/append
  중 어디서 터져도 생성 결과는 그대로 반환.
- 집계·스냅샷 실패 시 `usage_audit=null`, 패널 "생성 데이터 없음".
- 샘플 LLM 실패/무키 → `compliance` 필드 없이 결정적 신호만 기록.
- `bank_enabled != 1`이면 스냅샷·append 스킵(회귀0, 예전과 동일).

- 부품 임계 `PARTS_MIN = 5` · 아크 최소 `BEAT_MIN = 5`(=스키마 minItems)
