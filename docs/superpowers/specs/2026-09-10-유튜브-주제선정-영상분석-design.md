# 유튜브 제작소 1단계 — 주제 선정·레퍼런스 영상 분석 설계

작성일: 2026-09-10  
담당 판단자: Astra  
상태: 구현 전 설계 확정안

## 1. 결론

현재 `/yt`의 1단계 `영상 기본설정`을 `주제 찾기·영상 분석`으로 바꾼다.

이 단계의 최종 산출물은 자료 모음이나 영상 요약이 아니다. 다음 7개가 채워진 **주제 확정 카드** 한 장이다.

1. 우리가 만들 주제
2. 누구에게 어떤 변화를 약속하는지
3. 왜 지금 올려야 하는지
4. 경쟁 영상에서 채택할 장치
5. 그대로 쓰지 않고 어떻게 변형할지
6. 우리 영상만의 차별점
7. 2단계 심층조사와 대본에 넘길 근거·재료 목록

주제 확정 카드가 완성되지 않으면 2단계로 넘어가지 않는다.

## 2. 역할 분리

### 수집기

사실만 가져온다.

- YouTube 메타데이터: URL, 영상 ID, 제목, 채널, 게시일, 길이, 조회수, 댓글 수
- 성과값: 업로드 후 경과일, 일평균 조회수, 채널 평소 조회수 대비 배수
- 전체 자막과 타임스탬프
- 첫 30초 자막
- 대표 프레임: 0초, 5초, 15초, 30초, 이후 장면 전환 지점
- 상위 댓글과 반복 질문
- 썸네일 이미지와 썸네일 문구

수집기는 해석하거나 주제를 결정하지 않는다.

### 1차 분석기

영상 한 편마다 증거가 붙은 분석 카드를 만든다. 모든 판단에는 자막 타임스탬프나 화면 시점이 붙어야 한다.

### Astra

여러 영상 분석 카드를 비교하여 최종 편집장 역할을 한다.

- 지금 만들 가치가 있는 주제인지 판정
- 경쟁 영상의 장치를 `채택 / 변형 / 버림`으로 구분
- 우리 채널의 시청자와 목적에 맞게 각도를 다시 설계
- 대본과 장면에 실제로 들어갈 위치를 지정
- 근거가 약하거나 베끼기에 가까운 제안을 탈락

## 3. 사용자가 1단계에서 주는 것

처음부터 긴 양식을 요구하지 않는다. 사용자는 아래 세 가지 방식 중 하나로 시작한다.

### A. 자동 발굴

- 채널 선택
- 관심 영역 1~3개
- 이번 영상 목적: 조회수 / 신뢰 / 판매 / 구독
- 목표 길이

시스템이 최근 이슈와 유튜브 성과를 찾아 후보를 만든다.

### B. 주제부터 시작

- 만들고 싶은 주제 한 문장
- 선택 입력: 꼭 포함할 주장, 피하고 싶은 방향

시스템이 해당 주제의 경쟁 영상을 찾는다.

### C. 영상부터 시작

- YouTube URL 1~10개
- 선택 입력: 이 영상에서 눈에 띈 점 한 줄

시스템은 사용자가 준 영상과 유사 성과 영상까지 묶어 분석한다.

## 4. 영상 한 편에서 받아야 할 분석 결과

기존의 `훅 유형·첫 문장·3줄 구조·댓글 키워드`만으로는 실제 제작에 쓸 수 없다. 아래 스키마로 확장한다.

### 4.1 성과와 신뢰도

- 조회수, 게시 후 경과시간, 시간/일평균 조회수
- 채널 기준 성과 배수: 평소 영상 대비 몇 배인지
- 최신성: 현재도 유효한 내용인지
- 출처 신뢰도: 공식자료·실제 사례·주장만 있는지
- 비교 신뢰도: 큰 채널의 평범한 성과와 작은 채널의 돌파 성과를 구분

### 4.2 클릭 장치

- 제목 공식: 대상 + 문제/욕망 + 구체성 + 긴장
- 썸네일의 한 가지 약속
- 제목과 썸네일 사이의 정보 차이
- 우리 채널에서 재사용 가능한 클릭 원리

### 4.3 첫 30초

- 실제 첫 문장과 타임스탬프
- 훅 유형: 경고 / 기회 / 비밀 / 반전 / 공감 / 결과 선공개
- 시청자가 계속 볼 이유를 만든 문장
- 30초 안에 제시한 증거
- 군더더기와 이탈 위험

### 4.4 전체 이야기 구조

구간별로 다음을 기록한다.

- 시작·끝 타임스탬프
- 구간 역할: 문제 / 약속 / 증거 / 방법 / 반론 / 전환 / CTA
- 핵심 주장
- 사용한 증거
- 화면 방식
- 다음 구간으로 넘기는 연결 문장

### 4.5 댓글에서 확인할 것

- 시청자가 가장 원한 것
- 이해하지 못한 것
- 반박한 것
- 후속 영상으로 원하는 것
- 반복 빈도와 대표 댓글

### 4.6 제작 문법

- 말의 속도와 문장 길이
- 얼굴 / 화면녹화 / 도표 / B-roll 비중
- 패턴 인터럽트 간격
- 숫자·사례·비교를 보여주는 방식
- CTA 위치와 대가

## 5. 분석 결과를 실제로 쓰는 법

각 항목은 반드시 다음 단계의 소비처가 있어야 한다.

| 받은 값 | Astra의 판단 | 실제 사용 위치 |
|---|---|---|
| 제목 공식 | 우리 시청자에 맞게 변형 | 제목 후보 5개 |
| 썸네일 약속 | 제목과 중복 제거 | 썸네일 문구 3개 |
| 첫 문장·훅 원리 | 문구 복사 없이 감정 장치만 채택 | 대본 S1 훅 3안 |
| 구조 타임라인 | 유지율이 강한 순서만 채택 | 2단계 조사 목차와 3단계 장면 순서 |
| 증거 방식 | 우리가 확보 가능한 근거만 선택 | 조사 체크리스트·출처 목록 |
| 댓글 욕구 | 빠진 질문을 보강 | 본론·FAQ·후속편 소재 |
| 화면 문법 | 제작 가능한 것만 채택 | 장면별 화면 지시서 |
| CTA 방식 | 영상 목적과 맞을 때만 사용 | 마지막 장면 CTA |

`좋다`, `참고한다`, `비슷하게 만든다` 같은 추상적인 결론은 저장하지 않는다. 반드시 `어느 장면에 어떤 형태로 쓸지`가 있어야 한다.

## 6. Astra의 채택·변형·버림 규칙

영상별 장치를 아래 셋 중 하나로 분류한다.

### 채택

- 두 편 이상에서 반복되고 성과가 확인된 구조
- 우리 시청자의 문제와 직접 연결되는 장치
- 사실 근거를 우리가 확보할 수 있는 주장

### 변형

- 원리는 좋지만 경쟁 채널의 대상·상품·톤에 묶인 장치
- 문장 복사는 금지하고 감정 순서와 정보 구조만 사용
- 변형 후에는 우리 사례·데이터·화면으로 대체

### 버림

- 조회수는 높지만 채널 평소 성과보다 낮은 영상
- 오래되어 현재성이 사라진 주장
- 근거 없이 공포나 과장만 만드는 장치
- 우리 제품을 빼면 영상 자체가 성립하지 않는 판매 각도
- 원문 문장이나 장면을 그대로 베껴야만 작동하는 아이디어

## 7. 주제 점수

각 후보를 100점으로 계산하되 점수만으로 자동 확정하지 않는다.

- 시의성 20: 지금 검색·뉴스·댓글 수요가 있는가
- 검증된 수요 20: 실제 유튜브 성과가 있는가
- 채널 적합성 20: 기존 시청자가 볼 이유가 있는가
- 차별화 15: 경쟁 영상과 다른 한 문장이 있는가
- 근거 확보성 15: 주장에 필요한 자료를 구할 수 있는가
- 제작 가능성 10: 현재 도구와 시간으로 화면을 만들 수 있는가

탈락 조건은 점수와 별도다.

- 핵심 주장 출처가 없음
- 경쟁 영상 문구 복사에 의존
- 시청자와 연결되지 않음
- 제품을 억지로 끼워 넣어야 함

## 8. 화면 설계

### 화면 1 — 시작 방식

상단에 `자동 발굴 / 주제 입력 / 영상 URL 입력` 세 탭을 둔다. 입력 후 버튼은 `분석 시작` 하나다.

### 화면 2 — 수집 진행

진행률을 영상 단위로 보여준다.

`메타데이터 → 자막 → 댓글 → 대표 화면 → 분석 카드`

실패한 영상은 전체 작업을 막지 않고 실패 이유와 재시도 버튼을 표시한다.

### 화면 3 — 영상 분석 카드

왼쪽에는 원본 영상, 오른쪽에는 분석을 둔다.

- 성과 배수
- 제목·썸네일 원리
- 첫 30초
- 구조 타임라인
- 댓글 욕구
- 제작 문법
- 증거 타임스탬프

사용자는 각 장치에 `채택 후보` 표시만 할 수 있다. 최종 적용 판단은 Astra가 한다.

### 화면 4 — Astra 종합 설계

영상별 요약이 아니라 비교 결과를 보여준다.

- 공통 성공 패턴
- 한 영상만 가진 돌파 장치
- 서로 충돌하는 주장
- 채택 / 변형 / 버림 표
- 우리 영상 적용 지도

### 화면 5 — 주제 확정 카드

- 확정 주제
- 대상 시청자
- 한 문장 약속
- 왜 지금인가
- 차별화 각도
- 제목 5안
- 썸네일 문구 3안
- S1 훅 3안
- 예상 장면 구조
- 조사해야 할 사실과 필요한 파일
- 위험·금지사항

버튼은 `이 주제로 확정하고 심층조사 시작` 하나다.

## 9. 저장 구조

프로젝트 JSON에 원문을 반복 저장하지 않고 식별자와 정규화 결과를 저장한다.

```json
{
  "topic_discovery": {
    "mode": "auto|topic|urls",
    "channel_id": "...",
    "objective": "views|trust|sales|subscribe",
    "seed_topics": [],
    "source_video_ids": [],
    "candidate_topics": [],
    "astra_decision": {},
    "locked_at": null
  },
  "video_analyses": [
    {
      "video_id": "...",
      "metrics": {},
      "click_device": {},
      "hook": {"evidence": []},
      "story_beats": [],
      "comment_needs": [],
      "visual_grammar": {},
      "reuse_decisions": []
    }
  ]
}
```

자막·댓글·프레임 원본은 별도 자산 저장소에 두고 프로젝트에는 경로와 해시만 둔다. 같은 영상은 다른 프로젝트에서도 재분석하지 않고 캐시를 재사용한다.

## 10. 다음 단계 전달 계약

2단계는 단순 `기획서`가 아니라 `심층조사`가 된다. 1단계가 다음 값을 넘긴다.

- 확정 주제와 각도
- 검증해야 할 주장 목록
- 반드시 찾아야 할 숫자·사례·반론
- 사용할 수 있는 레퍼런스 장치와 금지 장치
- 첫 30초 훅 후보
- 예상 장면 구조
- 필요한 화면 재료 목록

2단계 조사 결과가 근거를 확보하지 못하면 1단계 주제 카드로 되돌아가 해당 주장을 수정한다.

## 11. 구현 순서

1. 프로젝트 스키마와 분석 캐시 저장소
2. URL 입력 + YouTube 메타데이터·자막·댓글 수집
3. 영상 한 편 분석 카드
4. Astra 다중 영상 종합 판단
5. 자동 발굴과 성과 배수 계산
6. 주제 확정 카드 → 2단계 심층조사 연결

## 12. 완료 기준

- URL 3개를 넣으면 영상별 분석 카드가 실제 데이터로 생성된다.
- 모든 핵심 판단에 영상 시점 또는 댓글 근거가 표시된다.
- Astra가 `채택·변형·버림`과 이유를 만든다.
- 채택 항목마다 대본 또는 장면의 사용 위치가 있다.
- 확정 카드가 없으면 다음 단계로 갈 수 없다.
- 같은 영상을 다시 넣으면 수집·분석 캐시를 재사용한다.
- 분석 실패를 성공처럼 표시하지 않는다.

## 13. 확정된 전체 제작 흐름

사용자가 2026-09-10 확정한 목표 흐름은 다음과 같다.

`YouTube 검색 결과 → 의미 필터·정렬 → 영상 분석 → 주제 확정 → 심층조사 → 대본 → 장면 믹스 → 제작 가이드 또는 렌더`

### 의미 필터·정렬

- YouTube 관련성 검색 결과를 원본 후보군으로 사용한다.
- 게시 기간과 쇼츠/롱폼 형식을 사용자가 제한한다.
- 관련성, 하루 조회수, 채널 최근 영상 중앙값 대비 배수, 참여율, 최신성을 함께 보여준다.
- 관련성 근거가 없는 영상은 조회수가 높아도 후보에서 제외한다.
- 사용자는 종합 추천 외에 관련성, 하루 조회수, 채널 돌파력, 누적 조회수로 다시 정렬할 수 있다.

### 대본 이후 믹스

- 분석 영상에서 채택한 훅·전개·화면 문법을 대본 장면에 배정한다.
- 장면마다 `직촬 / 화면녹화 / B-roll / 도표·그래픽 / AI 생성` 중 제작 방식을 정한다.
- 원본 문장이나 장면을 복사하지 않고 구조와 감정 장치만 변형해 사용한다.

### 직촬 분기

직촬 장면이 하나라도 있으면 다음 산출물을 만든다.

- 장면별 실제 대사와 예상 길이
- 구도, 카메라 높이, 시선, 동작
- 필요한 소품·장소·의상
- B-roll과 화면녹화 삽입 위치
- NG 방지 체크리스트
- 완성 영상의 타이밍을 보여주는 저해상도 가이드 영상

직촬이 없으면 등록 자산·B-roll·그래픽·TTS를 조합하는 자동 렌더 경로로 진행한다.
