## 무엇을·왜

1기 멤버 100명이 **하루 2영상 업로드 챌린지**를 시작(08-24 오픈). 멤버가 올린 영상을
링크로 제출받고, 사장님이 달성현황과 영상을 한 화면에서 확인한다.

**사장님 결정**: 멤버가 링크 직접 제출(자동 채널 크롤 아님) / 영상 정보는 자동 수집 /
관리 화면은 달성현황+영상 탭 2개 / 참가 자격은 1기 멤버만 / 인스타·유튜브·틱톡 /
기간은 admin 설정 / 하루 기준은 **제출한 날짜**(KST).

## 주소

```
멤버   shoppingshorts.duckdns.org/challenge        ← 단톡방에 이 링크를 공유
관리   shoppingshorts.duckdns.org/challenge/admin  ← 관리자만
```

## 설계의 핵심 — 저장 먼저, 수집 나중

링크가 들어온 순간 `challenge_submission` 행이 생기고 **달성 카운트가 확정**된다.
썸네일·조회수는 백그라운드(`BackgroundTasks`)로 나중에 채운다.

**수집 결과에 카운트를 묶지 않는 이유**: 인스타 수집은 수십 초 걸리고 간헐적으로
실패한다. 거기에 카운트를 묶으면 **"멤버는 올렸는데 미달성으로 찍히는"** 사고가 난다.
수집은 장식이고, 카운트의 진실은 `submit_day` 한 곳이다.

`fetch_status`: `pending`(수집 전) · `ok` · `failed`(실패—링크는 남음) · `skipped`(틱톡)

## ★다음 세션이 알아야 할 함정 (전부 이번에 실측으로 밟은 것)

| 함정 | 진실 |
|---|---|
| 세션 쿠키 이름 | `ss_session`이 아니라 **`dash_auth`**(app.py:8029) |
| DB 파일 | `app.db`가 아니라 **`reference.db`**(config.py:23) |
| 썸네일 프록시 | `?u=`가 아니라 **`?url=`**(app.py:5579) |
| `probe_grab_meta` 키 | `view_count`가 아니라 **`views`**(media_download.py:141) — 틀리면 조용히 항상 None |
| `_media_code` 재사용 | **쓰지 마라.** 인스타 전용이고 실패 시 URL을 통째로 반환 → `challenge.video_code` 사용 |
| 색상 토큰 | `theme.css`엔 `--bg`/`--txt`/`--panel`이 **없다**(`--mint`/`--aurora`만). 페이지가 인라인 `:root`로 선언 |
| 유료게이트 | ★**챌린지 참가자격과 결제등급은 별개 테이블.** 참가자여도 pro가 아니면 402 → `_FREE_EXACT_ANY`/`_FREE_EXACT_GET`에 등록 필수. 보안은 핸들러의 `is_challenge_member` 403이 지킨다 |
| 사이드바 경로 | `/static/sidebar.js`가 아니라 **`/sidebar.js`**(app.py:6528 전용 라우트) |
| `_is_admin(0)` | **True**(사장님). 테스트에서 '비관리자' 역할에 cid 0을 쓰면 거짓 green |
| 로컬 서버 | `DASH_PASS` 비면 `_AUTH_ON=False` → `customer_id=0` 고정 → 관리 화면이 그냥 열린다 |
| `git stash` | **쓰지 마라.** 다른 세션 stash 2개가 있어 pop이 남의 작업을 꺼낸다 → worktree로 기준선 측정 |

## 알고 가는 한계

- **틱톡은 링크만 저장**(단건 조회 함수가 없다 — `tiktok_client`는 계정 단위뿐).
  썸네일·조회수가 안 뜬다. 카운트는 정상.
- **중복 판정의 구멍**: shortcode를 못 뽑는 URL(틱톡 단축링크 `vt.tiktok.com`)은
  정규화한 URL로 판정한다 → 같은 영상을 단축링크와 원본링크로 각각 내면 둘 다 통과.
  틱톡 단건 수집을 붙이면 해소된다.
- 미달성자 알림·순위·포인트는 **안 만들었다**(YAGNI). 운영해보고 필요하면.
