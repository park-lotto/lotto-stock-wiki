## 한 줄 정의

초반 성장을 원하는 **유튜브 채널들이 등록**하고, 서로 **구독·좋아요·댓글 품앗이**를 하되,
**누가 누구에게 뭘 해줬는지 양쪽에 투명하게 보이는 장부**. **목적 = 트래픽 확보**.

## 사업 목적 (사장님 확정)

- **트래픽만 모으는 게 목적** (유저를 성공시키는 게 목적 아님).
- → 이 목적에선 품앗이가 **미끼로 최적**. 초보 유튜버는 매일 새로 생겨서 윗물이 계속 채워짐 → 총 트래픽 유지됨.
- 무료로 풀고 사업화. 광고만으론 수익 약함 → 트래픽을 **자산**으로 쌓아 나중에 다른 것 팔 발판으로 봄.

## 확정된 설계 결정

| 항목 | 결정 | 이유 |
|---|---|---|
| **시청 지속시간** | 검증 안 함, **신의·약속에 맡김** | 영상마다 다르고, 유튜브가 개인별 시청량을 채널주인한테도 안 줌 (기술적 불가) |
| **구독 + 댓글** | **자동 검증**, 봇 아닌 실제 유저만 인정 | 댓글은 공개 API로 확인 가능 / 구독은 상대 OAuth 연동 시 확인 가능 |
| **핵심 제품** | 보상엔진 없이, **"진짜 서로 해줬는지 투명하게 보이는 장부" 그 자체** | 무임승차자 색출이 이 바닥 1등 니즈 |
| **플랫폼** | 유튜브 자동 / 인스타 수동(하이브리드 C) | 인스타 API 막힘 |

## 기술 현실 (검증된 제약 — 이 위에서 설계해야 함)

| 상대가 한 행동 | 자동 통계 가능? | 방법 |
|---|---|---|
| 댓글 달았나 / 내용 / 글자수 | ✅ 완전 가능 | 공개 데이터, YouTube Data API (상대 연동 불필요) |
| 구독했나 | ✅ 가능 | 상대 OAuth 연동 필요 |
| 좋아요 눌렀나 | ✅ 가능 | 상대 OAuth 연동 필요 |
| **영상 봤나 / 얼마나** | ❌ **불가능** | 개인별 시청 데이터가 세상에 존재 안 함 (신의에 맡기는 이유) |

→ **자동 검증되는 것 = 가치 있는 것 = 댓글**로 수렴. 댓글이 가장 강한 축.

## 리스크 (기록 — 잊지 말 것)

1. **플랫폼 약관**: 유튜브·인스타 둘 다 인위적 참여(sub4sub/pod) 금지. 유튜브 OAuth 앱 심사에서 용도가 "맞구독"이면 API 승인 거절·정지 가능. → 트래픽 목적이면 감수하거나, 포지션 조정.
2. **품앗이 = 맞구독 = 안 큰다**: 상호성(강제 빚) 구조는 알고리즘이 저품질로 깎음. 유저 성장 목적이면 밑빠진 독. **단, 트래픽 목적이면 무관.**
3. **봇이 포인트/장부 farming** → "실제 유저" 판별 필수.

## ▶ 여기서 이어서 (다음 세션 재개점)

**미결정 관문 2개:**

### 1. "상대가 꼭 갚게" 만드는 방식 — 사장님이 Q로 던진 핵심
버튼 강제는 기술적으로 불가. 대신 **구조로 강제**:
- **(A) 투명 장부 = 빚 공개** ("3번 받고 0번 갚음" 공개, 사회적 압박)
- **(B) 🔑 선불 구조 = "먼저 갚아야 받는다"** ← 제일 강력. 내가 먼저 N명 해줘야 내 채널이 "받기 목록"에 오름. 상호성이 전제조건이 됨. (보상 아니라 강제장치)
- **(C) 에스크로 매칭** (둘 다 약속→둘 다 완료 시 공개, 먹튀 시 무효)
- **→ 사장님 Q2("꼭 하게") 정답은 (B) 선불 구조에 가장 가까움. 여기서 A/B/C 확정 필요.**

### 2. "봇 아닌 실제 유저" 판별 기준
- (1) 계정 나이 + 구독자 수 (봇은 신규·0명)
- (2) 본인 OAuth 연동 (봇 대량계정은 로그인 번거로움)
- (3) 댓글 내용 품질 (복붙/이모지 vs 진짜 댓글, 자동 판별)
- **→ 보통 (2)+(3) 조합. 확정 필요.**

**이 2개 정하면 → 설계 그림 완성 → spec 확정 → writing-plans로.**
