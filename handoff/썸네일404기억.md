# 썸네일404기억 — 죽은 썸네일 주소 기억 5분→확정 404/403은 60분 (관제 064, 2026-10-01)

## 실측
- 접근로그 2시간: /api/thumb 37,583건, 86% 404, 죽은 주소 2,157개가 평균 23.9회(최대 182회) 되돌아옴. 한 IP가 25,111건.
- **브라우저는 404를 캐시하지 않는다** — 헤드리스 크롬 실험: 같은 죽은 주소를 8번 다시 그리니 8번 요청(`Cache-Control: private, max-age=120`이 있어도).
  → 09-18에 넣은 `_THUMB_DEAD_HEADERS`(브라우저 120초)는 아무것도 막지 못했고, 서버 기억(5분)만 방패였다. 5분마다 CDN 에 재조회(6초 타임아웃).
- 요청 자체는 기억 적중이면 ~1ms라 싸다. 비싼 건 **5분마다 다시 나가는 CDN 조회**(스레드풀 점유).

## 한 것 (주인: app.py `_thumb_neg_put`·`_thumb_dead_ttl`)
- 확정 죽음(HTTPError 403·404·410, oembed 복구·규격 폴백까지 실패) → 60분 기억. 타임아웃·5xx·연결 오류 → 종전 5분.
- 테스트 3건(`test_thumb_dead_memory.py`): 404 장기 기억·기억 중 CDN 재조회 없음 / 타임아웃 단기 / 살아있는 썸네일 그대로.
