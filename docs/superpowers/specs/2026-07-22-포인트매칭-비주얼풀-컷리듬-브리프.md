# 믹스 장면 선택 재설계 브리프 — 포인트 정확매칭 + 비주얼 풀 + 컷 리듬
(2026-07-22 페이블 진단 → 오푸스 구현용. 사장님 설계 원칙 확정, 흔들지 말 것)

## 0. 현재 상태 (이미 라이브 — 다시 만들지 마라)
- 대본: rich 생성기 단일화(스토리선언+짤드라마+은행+다중컷) + 백본 순서 제약(`_backbone_order_block`)
  → **대본 품질은 부활 확인됨**(사장님 확인). 뼈다귀 생성기(`generate_backbone_script`)는 믹스에서 폐기.
- fit 정직화(`_verify_fits`): 행위 불일치 증거 시 fit≤2. / 백본 참여도(댓글수) 배선. / 심사위원
  (`candidate_judge`, 대본품질·장면싱크·스토리라인) best-of-N. / 길이 자동조정 결정적 폴백(`_trim_to_budget`).

## 1. 남은 문제 — 실측 증거 (job 23a6db67333a, 서버 reference.db)
비트 5개 / 클립 슬롯 34개:
```
b0: 6컷 durs=[1.5,1.3,1.4,1.1,0.7,1.0]  (4.9s 대사)
b1: 8컷 durs=[0.9,1.3,1.4,1.1,0.7,1.0,1.9,2.5]  (7.2s)
b3: 8컷 = s3-13(비법소스, 1.5s) + [s0-2,s0-3,s0-5,s0-6,s0-7,s0-8,s0-9]  ← 포인트가 파편에 묻힘
seg 재사용: s0-2 5회 · s0-3 5회 · s0-5/6/7/8 4회 · s0-9 3회 (고유 12 / 사용 34)
```
- **P1 뚝뚝 끊김**: 비트당 평균 6.8컷, 0.7~1.5s 파편 연발. 컷 길이 하한·홀드 개념이 없음.
- **P2 장면 반복**: 같은 B롤 체인 [s0-2,s0-3,s0-5,s0-6,s0-7,…]이 b0·b1·b3·b4에 거의 동일 순서로 반복.
- **P3 포인트 실종**: "비법 소스를 듬뿍 얹어줍니다" 비트의 소스 장면이 1.5s 뒤 잡동사니에 묻힘.

## 2. 원인 (코드 지점)
- `_ground_candidate`가 seg_ids 2~4를 깔고, `fill_clips_to_cover`(+`_refill_beats_to_tts`)가 TTS 길이를
  **파편 B롤 추가**로만 채움. `exclude_seg_ids`가 **비트 내부만** 제외 → 전역 반복 무방비.
- `dedup_and_balance`는 **primary만** dedup — alternates(연속재생 B롤)는 손 안 댐 → P2의 주범.
- 포인트/앰비언트 구분이 없음 — 모든 비트를 같은 방식(행위매칭+fill)으로 처리.

## 3. 사장님 설계 원칙 (확정 — 이대로 구현)
> 스토리짤 대본은 화면과 1:1 매칭이 원래 거의 안 된다. 그러니:
> ① **포인트 비트만 정확 매칭** — "비법 소스를 듬뿍 얹어줍니다" 같은 결정적 행위 문장 ↔ 그 행위 장면.
>    이 장면이 영상의 핵심이므로 **길게 홀드**(파편으로 쪼개거나 묻지 마라).
> ② **나머지(앰비언트) 비트는 매칭 욕심 버림** — 음식이 맛있어 보이는(제품이 매력적인) 비주얼
>    위주로 채움: 완성샷·클로즈업·시즐(치즈 늘어남/육즙/소스 흐름) + 조리과정.
> ③ 장면 뽑기(추출·선택)도 같은 기준: 완성품 맛있어 보이는 장면 위주 + 조리과정, 그리고
>    비법 한 스푼(소스) 장면을 잘 잡아 포인트에 배정.

## 4. 구현 태스크 (TDD, 전부 스마트믹스 경로 안 — 회귀0 유지)
- **T1 비트 분류기** `classify_beat(beat)` → 'point' | 'ambient'.
  point = 나레이션에 행위 태그(action_dict.tag_action) 있음(특히 붓다·얹다·바르다·뿌리다 류
  '결정적 투입' 행위) — 그 외 스토리/감정/CTA 문장 = ambient.
- **T2 포인트 비트 처리**: 정확 행위 매칭(기존 ping_pong/`pick_clips_for_action` 재사용) +
  **홀드 규칙** — 포인트 장면 클립을 그 비트의 주인으로: 해당 seg의 가용 구간을 최대로 쓰고,
  fill은 같은 행위/같은 소스 인접 구간 우선. 잡동사니 B롤로 밀어내기 금지.
- **T3 앰비언트 비주얼 풀**: seg별 visual_score(결정적 근거 우선 — scene_desc 키워드:
  완성/클로즈업/치즈/육즙/시즐/흐르/윤기/플레이팅 등 + 폴백은 추출기에 visual 필드 추가 검토).
  앰비언트 비트는 fit 매칭 대신 visual_score 상위에서 채움(행위매칭 불일치 걱정 없음 —
  fit 개념 자체가 앰비언트엔 완화 적용: `_verify_fits`가 ambient 비트는 캡하지 않게).
- **T4 전역 클립 dedup**: alternates 포함 **영상 전체에서 seg 1회** 원칙. 풀 부족 시에만 재사용
  허용하되 ①인접 비트 금지 ②같은 순서 체인 금지(셔플). `dedup_and_balance` 확장 또는 후처리 패스.
- **T5 컷 리듬**: `MIN_SHOT_SECONDS`(권장 1.5~2.0, config 상수) — fill이 파편을 더하는 대신
  ①기존 클립의 구간을 늘리고(같은 seg 앞뒤 여유) ②그래도 모자라면 **적고 긴** 클립으로.
  비트당 클립 수 상한(권장 3) 도입. `_refill_beats_to_tts`·`fill_clips_to_cover` 수정 지점.
- **T6 심사위원 확장**: `candidate_judge`에 'cut_rhythm/반복' 축 추가 검토(또는 규칙점수에
  반복도·평균샷길이 감점) — 후보 선택이 이 문제를 다시 못 만들게.

## 5. 검증
- 신규 테스트: 분류기·홀드·visual 풀·전역 dedup·MIN_SHOT 각각 + 회귀(scene_first 계열 115+).
- 실증: 같은 소스로 재믹스 → ①비트당 클립 ≤3 ②seg 전역 재사용 0(부족 시 인접 아님)
  ③포인트 비트 주인 클립 ≥ 대사의 60% ④사장님 육안(뚝뚝 끊김·반복 해소).
- ⚠️ 이 job은 fit 정직화 배포 전 렌더 — fit=5는 참고만. 렌더 육안은 사장님만 가능.
