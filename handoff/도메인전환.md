# 도메인전환 — handoff

> **소유 트랙**: 도메인전환 — 이 파일은 이 트랙 세션만 수정한다.
> 트리거: **"도메인전환 이어서"**

## 2026-08-30 — stmaker.kr 붙이기 (착수)

사장님: "stmaker.kr 도메인 전환 이거해" / "쉽게 최선으로 해주면 되"

### ★가장 중요한 사실 — 루트를 건드리면 결제가 죽는다 (실측)

`stmaker.kr` 는 **이미 카페24 쇼핑몰에 연결돼 있다.** 그리고 **1기 카드결제 링크가 그 위에 있다.**

```
dig stmaker.kr        → 183.111.139.238/232, 203.245.12.110/111  (카페24, 우리 서버 아님)
curl -I stmaker.kr    → Set-Cookie: ... domain=.delicush.cafe24.com
NS                    → dns1/dns2.cafe24.com, dns1/dns2.cafe24.co.kr
카드결제 링크          → https://stmaker.kr/surl/O/3068  (카페24 단축주문 SURL)
```

→ **루트 DNS를 우리 서버로 돌리면 결제 링크가 404가 된다.** 그래서 **서브도메인 안**으로 간다.

| | 주소 | 무엇 |
|---|---|---|
| 루트 | `stmaker.kr` | **카페24 쇼핑몰 = 결제.** 건드리지 않는다 |
| 서비스 | `app.stmaker.kr` | 숏템메이커 본체 (신설) |
| 기존 | `shoppingshorts.duckdns.org` | **끊지 않는다** — 고객 북마크·설치된 확장/유저스크립트가 물고 있다 |

### ✅ 이번에 한 것 (코드만 — 아직 라이브 영향 없음)

전부 **추가(additive)** 라서 기존 동작은 하나도 안 바뀐다.

- `extension/manifest.json` — host_permissions·content_scripts matches에 `app.stmaker.kr` 추가, version 1.3.0 → **1.4.0**
- `extension/grab_logic.js` · `userscript/grab_logic.js` — 자기페이지 판정을 배열로 바꿔 두 도메인 다 인식
  (전엔 `location.hostname.indexOf("shoppingshorts.duckdns.org")` 한 줄)
- `userscript/grab.user.js` — `@match .../grab*`, `@connect` 에 새 도메인 추가
- `userscript/insta_fill_comment.user.js` — `@connect` 추가
- `deploy/apache-stmaker.conf` — 새 vhost (설치 순서를 파일 주석에 전부 적어놨다)

**`BASE` 상수는 아직 duckdns 그대로 둔다.** 인증서가 없는 도메인으로 먼저 돌리면 담기가 통째로 죽는다.
DNS+인증서가 살아난 뒤에 한 번에 뒤집는다(아래 ⏭).

### ⏭ 남은 것 — 순서를 지켜야 한다

```
□ 1. [사장님] 카페24 DNS 관리 → A레코드  app → 43.200.48.69
      확인: dig +short app.stmaker.kr
□ 2. [서버] vhost 설치 + certbot --apache -d app.stmaker.kr
□ 3. [사장님] 구글 클라우드 콘솔 → OAuth 클라이언트 → 승인된 리디렉션 URI에
      https://app.stmaker.kr/auth/google/callback  **추가**(기존 것은 지우지 말 것)
□ 4. [서버] /etc/shopping-shorts.env 에
      PUBLIC_BASE_URL=https://app.stmaker.kr
      GOOGLE_REDIRECT_URI=https://app.stmaker.kr/auth/google/callback
      → systemctl restart shopping-shorts
      ※ 3번보다 먼저 하면 redirect_uri_mismatch로 로그인이 통째로 막힌다
□ 5. [코드] BASE 상수 6곳을 새 도메인으로 뒤집기
      extension/{background.js,content.js,grab_logic.js×2,popup.html}
      userscript/{grab.user.js,grab_logic.js×2}
      app.py·setup.html의 안내 문구도 같이
□ 6. [확장] 재설치 안내 — manifest host_permissions가 바뀌면 기존 사용자는
      자동 반영이 안 된다. 두 도메인을 함께 허용해 뒀으므로 당장은 안 깨지지만,
      새 도메인으로만 쓰려면 재설치가 필요하다.
```

### ⚠️ 함정
- **PUBLIC_BASE_URL은 Google Lens가 우리 프레임 이미지를 직접 fetch할 때 쓴다.** 잘못 바꾸면
  렌즈가 조용히 실패한다(에러 없이 결과 0건). 바꾼 뒤 렌즈 검색 1건 실측할 것.
- **duckdns를 성급히 끊지 마라.** 확장·유저스크립트·QR·기존 안내문이 전부 그 주소다.
