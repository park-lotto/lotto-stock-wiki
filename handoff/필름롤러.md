## ⏭ 다음에 할 일

### 1. 사장님 육안 확인 ← 여기부터
서버(shoppingshorts.duckdns.org)에서 제작소 3단계를 열어 확인:
```
□ 아래 소스 카드에 [🎞 필름 펼치기] 하나만 있나 (고르기·자르기 없어짐)
□ 눌러서 오른쪽으로 필름이 펼쳐지나 · 다시 눌러 접히나
□ 빨간 손잡이를 끌면 미리보기가 따라오나(스크러빙)
□ 손잡이 우클릭 2번 → 오렌지 박스가 생기나 → 담기
□ 위 훅 컷의 🎞(체크박스 오른쪽)로도 같은 필름이 펼쳐지나
□ 묶는기준 [🎞 필름형] → 영상 통째 필름 → 임의 구간 담기
□ 소스별에서 영상당 가로 한 줄로 이어지나
□ ★담고 나서 실제로 렌더까지 나오나 (extra_segs가 서버에 닿는지 최종 확인)
```

### 2. 담은 구간이 렌더에 실제로 반영되는지 (제일 중요 · 유일한 미검증)
화면·저장·전송·서버 4곳을 다 채웠고 서버 테스트도 통과했지만,
**실제 잡으로 렌더를 돌려본 적은 없다.** 새 조각이 영상에 나오는지 한 번은 봐야 한다.
안 나오면 `apply_scene_lab`에 도달한 payload부터 확인(`extra_segs` 키).

### 3. 못 한 것 — 조각 범위 넓히기
`TRIMS[sid]=[a,b]`는 **가운데를 버리는** 방식이라 조각 밖으로 못 넓힌다.
필름형(④)으로 임의 구간을 새로 담으면 우회되지만, ①② 펼침에서 직접 넓히려면
`trimPieces`(scene_play.js:219)와 `_lab_trim_pieces`(edit_plan.py)를 **함께** 고쳐야 한다.

## 2026-08-26 2차 — 사장님 지적 2건 반영 (배포됨)

```
① 필름 펼침을 맨 위로 — 카드 옆(150px)에 눌리던 것을 타임프레임 바로 아래
   #rollbay 전체 폭으로. 실측 150 → 1,161px (7.7배)
② 재생을 큰 미리보기 창으로 — 필름 안에서 돌면 어디서 도는지 안 보였다
```
②는 임의 구간이라 seg_id가 없다. **새 배선을 만들지 않고** `_pv_` 임시 조각을 만들어
기존 경로(`playSegHere` → 부모 `sceneLabPlaySeg`)로 넘긴다.
★임시 조각은 **EXTRA에 안 넣는다** — 미리 듣는 것뿐이라 저장·전송에 섞이면 안 된다
(담기는 `commitRoll`만 한다). 필름 안 `<video>`는 썸네일 추출·스크러빙 전용이 됐다.
`filmroll.js`는 `opt.onPlay`가 있으면 위임, 없으면 종전대로 안에서 재생
(부품은 부모를 모른다 — 배선은 scene_lab이 한다).

검증(실제 마우스): rollbay 위치·필름폭 1,161px·27칸·스페이스→playSegHere 호출·
임시조각 생성·EXTRA 오염 0·JS 오류 0건.

## 오늘 한 것 (2026-08-26 1차)

### 왜 했나
사장님: *"지금 3단계를 보니 너무 허접하네"* — 실측하니 **자르기에 화면이 없었다.**
`✂ 자르기`(scene_lab.html:1520)는 전용 UI가 아니라 재생 시작이고,
`#trimbar`는 미리보기 밑 **한 줄 텍스트**가 전부. 썸네일·눈금이 없어 진행바를 끌며
숫자로 타이밍을 맞춰야 했다. 그 자리가 원래 비어 있었다.

### 만든 것

| # | 내용 | 어디 |
|---|---|---|
| ① | 위 훅 컷 → 오른쪽 필름 펼침 | `.tbcut`에 `data-sid`+`.rollbtn` |
| ② | 아래 카드 → `[🎞 필름 펼치기]` 하나만 | 고르기·자르기 제거 |
| ③ | 자르기 부품 공용 | **`static/filmroll.js`**(신규) |
| ④ | 필름형 토글 + 임의 구간 담기 | `paletteGroups` film 모드 · `commitRoll` |
| ⑤ | 모든 조각(첫·끝 안 버림) | `_build_inventory` edge 표식 |
| ⑥ | 영상당 가로 한 줄 | `.thumbs.oneline` |

**조작**: 빨간선 손잡이 끌기=스크러빙 / 손잡이 우클릭 2번=구간 / 확대하면 간격도
촘촘(1초→0.2초) / 오렌지 박스 여러 개 공존·이동·양끝조절·삭제.

### ★⑤가 설계보다 훨씬 넓었다 (중요)

"prompt_block만 막으면 된다"고 설계했는데 실제로는 **seg_map 전체를 도는 곳이 9군데**였다.
안 막았으면 CTA·썸네일 컷이 AI 자동배치에 조용히 섞였다:
```
_build_scene_spine · _build_scene_blocks · _pick_timeline · _build_source_sentence_sets
_fill_beat_screen_time · _repick_weak_beats · api_mix_scene_lab_fill
_validate_and_ground · _ground_candidate   ← 환각 seg_id가 통과하던 회귀를 실제로 잡음
```
edge 판정은 `_is_edge_seg` / `non_edge_segs` **한 곳**에서만 한다(0순위-B).

### ④ 새 조각은 4곳을 짝으로 채웠다

서버는 `seg_map`에 없는 id를 **조용히 버린다**(`edit_plan.py`) → 화면엔 담겼는데
렌더에만 안 나오는 최악의 실패. 그래서:
```
① 화면    DATA.segments + EXTRA
② 저장    saveWork / 복원 2곳 → hydrateExtra() 하나로 묶음
③ 전송    applyServer payload.extra_segs
④ 서버    apply_scene_lab이 seg_map 사본에 병합(기존 것 안 덮음)
＋ seg_thumb도 film_<vid>_<a>_<b> 파싱(안 하면 위 훅 컷이 빈칸)
```
⚠️ `FIXLEN`이 ②를 빼먹어 **새로고침하면 사라지는** 상태다 — 같은 실수를 안 하려고 묶었다.

### 검증

## 알아둘 것

- **되돌리기**: 필름형 토글 기본 OFF, 카드형이 기본 → 안 켜면 종전 화면 그대로
- **한 번에 하나만 펼친다** — 여럿 열면 폭이 감당 안 되고 영상이 동시에 돈다
- **펼침 중에 `render()` 부르지 않는다** — 296줄 + saveWork + 1.2초 디바운스 서버푸시라
  자기 DOM을 지우고 서버를 두들긴다. 확정(담기)할 때만 부른다
- **`🔗 합치기`는 남겼다** — 짧은 조각을 살리는 별개 기능(없애면 합치기가 불가능)
- 테스트 하네스: `scratchpad/labtest/`(인라인 DATA로 서버 없이 scene_lab 구동)
  ⚠️ 원본에 `<script id="scene-lab-data">null</script>`가 이미 있다 —
  지우지 않고 추가하면 **id가 둘**이 돼 `getElementById`가 옛것을 잡는다(여기서 한 번 헤맴)
