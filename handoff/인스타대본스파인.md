## ★ 결론 먼저 — 가장 큰 발견

### 인스타는 **음성=스토리 / 화면=시연**이 완전히 분리돼 있다

전사본 43편·654컷을 대사와 `scene_desc`(컷별 화면 설명)로 갈라 대조한 실측:

```
대사에 등장인물(시어머니·친구·사장님…)이 나오는 컷    49개
그중 화면에도 사람이 나온 컷                        1개  ← 2%
```

즉 **"시어머니가 화를 내시는 거예요"라고 말하는 순간에도 화면은 양말을 빨고 있다.**
스토리는 전부 목소리로만 굴러가고, 화면은 처음부터 끝까지 **제품 시연 루프**다.

**그래서 사장님 말이 맞다 — 장면매칭이 쉬워진다.** 비트마다 다른 장면을 찾을 필요가 없다.
필요한 화면은 사실상 4종뿐이고, 이 4종만 있으면 **어떤 스토리든 위에 얹을 수 있다**:

| 화면 슬롯 | 무엇을 찍나 | 실측 근거 |
|---|---|---|
| ① 문제 상태 | 더러운/망가진 대상 클로즈업 | "꼬질꼬질한 양말", "바닥 패인 자국" |
| ② 투입·도포 | 제품을 넣거나 뿌리는 손 | "숟가락에 세제를 부어 넣는 모습", "수전에 세정제를 뿌리는" |
| ③ 작동 | 거품·녹아내림·문지름 | "거품 사이로 녹아 나오는", "스펀지로 닦는" |
| ④ 결과 대비 | 깨끗해진 것 / 반반 대비샷 | "반쪽은 누렇고 반쪽은 하얗게 변한 양말" ← ★대비샷이 클라이맥스 |

화면 서술 어휘 상위: 모습534 · 보여주는96 · **손으로62** · 붓는36 · 닦는18 · 깨끗해진17 · 뿌리는15.
**사람 얼굴 어휘는 상위 35개 안에 하나도 없다.**

> 유튜브와 정반대다. 유튜브 은폐형은 "이건 바로 ○○" 공개 시점에 화면이 같이 꺾인다.
> 인스타는 화면이 스토리를 따라가지 않으므로 **대본 변형의 자유도가 훨씬 크다.**

## 재현 방법 (조사를 다시 할 필요는 없지만, 갱신할 때)

분석 스크립트 10개는 세션 임시폴더에 있었다. 핵심 쿼리만 남긴다:

```sql
-- 축1 표본
select username,views,comments,caption from reel_history where caption like '%다이소%' order by views desc;
-- 전사 + 화면
select r.username,r.views,s.script_json from script_extracts s
  join reel_history r on r.shortcode=s.shortcode where r.caption like '%다이소%';
-- script_json 구조: {"segments":[{"start","end","text","scene_desc"},...]}
-- 밀도 = 한글글자수 / max(segments.end) * 30   (reel_durations는 재고가 1건뿐이라 못 쓴다)
```
