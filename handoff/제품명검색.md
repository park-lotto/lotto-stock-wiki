## 목적 (사장님 원문)

> "결론은 같은 영상이 과거에도 있던걸 그냥 찾아서 믹스할려고 하는게 목적"
> "같은제품이지. 우리가 2개 영상믹스할때 렌즈로 검색해서 같은제품영상을
> 믹스하는거자나 그거랑 같은개념인데 내부에서도 찾는다는거야"

= **렌즈로 하던 "같은 제품 영상 찾기"를 우리 아카이브 안에서** 한다.
'비슷한 소재'가 아니라 **같은 제품**이다. 이걸 헷갈리면 방향이 통째로 틀어진다.

## 완료 (전부 라이브)

1. **🏠 숏템내부검색 버튼** — 랭킹 메인카드 + 역대히트작. 🔍 파워검색(외부·유료 렌즈)과
   색으로 구분: 파워=금색, 내부=청록.
2. **제품명 판독** — `product_name.py`. 비전모델에 "자막 무시, 실물 제품만 상품명으로"
   지시. `vision_tags.product`에 캐시.
3. **2단 검색** — `api_archive_similar`: ①태그겹침 후보 → ②상위 60건 판독 → ③같은 제품 최상단.
4. **선판독 백필** — `product_backfill.py`. 조회수 상위부터 미리 판독.

```
channel_archive  → 144/675채널 크롤 진행 중 (2.8분/채널, 키 안 씀 → 밤새 계속 돔)

```

**둘 다 멈춘 원인은 같다: Gemini 키 16개 중 15개가 오늘치 소진.**
썸네일은 정상 다운로드되는데(172KB 등) `_identify_one`이 `(None,None)`만 반환한다.
⚠️ 태거 로그는 이걸 "썸네일 만료 추정"으로 찍는다 — **오해하지 마라. 키 소진이다.**
(확인: `comment_gen._load_state()["exhausted"]` → 15개 idx가 들어있음)

**소진 표시는 UTC 날짜가 바뀌면 자동 해제**된다(`comment_gen._load_state`,
date가 오늘이 아니면 exhausted를 비운다) = **KST 09:00**. 그래서 크론을 걸어뒀다:

```
10 0 * * *  /home/ubuntu/run_backfill.sh   # KST 09:10 백필 자동 시작
12 0 * * *  /home/ubuntu/run_tagger.sh     # KST 09:12 태거 자동 재개(중복 실행 방지 내장)
```

아침에 `tail -30 /tmp/product_backfill.log` / `/tmp/archive_tagger.log`로 확인.

모두 `/etc/shopping-shorts.env` 로드 후 실행해야 한다 → [[reference_서버_SHORTS키_systemd전용]]

## 오늘 밟은 함정

- **디스크 풀** — 90%까지 차서 태거·크롤러가 `[Errno 28]`로 죽어 있었다.
  mix_jobs 18G 정리(완성본 48개는 `/home/ubuntu/mixjob_finals_backup`에 백업 후
  미완성 147개+찌꺼기 삭제) → 73%. 백필에 디스크 가드 3GB를 넣은 이유.
- **`loading="lazy"`가 썸네일을 통째로 죽였다** — grid+aspect-ratio 안에서 lazy 로더가
  가시성 판정을 못 해 `/api/thumb` 요청이 **0건**이었다. 서버 문제로 오진했다가
  `performance.getEntriesByType('resource')`로 잡았다. 3군데 제거.
- **`crossorigin="anonymous"`** — same-origin 프록시에 붙이면 CORS 응답 취급이라
  이미지 196장이 전부 버려진다(fetch는 200인데 naturalWidth=0).
