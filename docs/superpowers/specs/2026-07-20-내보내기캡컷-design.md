# 최종렌더 다운로드 + 캡컷 내보내기 — 설계 (2026-07-20, Fable → Opus 인계)

## 0. 요구·배경

- 사장님 요청: "최종렌더 후 **다운로드** 기능 + **캡컷으로 전송**(캡컷에서 수정 가능하게)".
- 레퍼런스 = 쇼핑팩토리(데스크톱 앱) 8단계 '내보내기': 스크립트·TTS·장면별 자막을 캡컷 프로젝트로
  내보내고, **내려받기 누르면 캡컷이 실행되며 파일이 열린다**. 개별 다운로드(소스영상/SRT/스크립트) +
  전체 ZIP(소스+TTS+자막+스크립트+SEO)도 있음.
- **핵심 제약**: 우리는 웹서비스(shoppingshorts.duckdns.org). 브라우저는 로컬 폴더 쓰기·프로그램 실행이
  불가 → "누르면 캡컷 자동 실행"은 순수 웹으론 원천 불가. 레퍼런스가 되는 건 데스크톱 앱이라서다.
- 현재 상태(코드 실측): 7단계 `renderFinal()` → `/api/mix/render` → `/api/mix/video/{job_id}` **재생만** 있고
  명시적 다운로드·내보내기 없음.

## 1. 채택안 = 3단 사다리 (T1 견고한 웹 ZIP → T2 캡컷 draft → T3 원클릭 .bat)

세 방식(A 도우미 상주앱 / B ZIP 내 .bat / C 순수 웹)을 비교한 결과 **C를 기반으로 깔고 B를 얹는
사다리**가 최선. A(상주앱)는 기각 — 설치·업데이트 부담이 크고 고객에게 강요 불가, B가 90% 경험을
설치 없이 준다.

| 티어 | 내용 | 대상 | 리스크 |
|---|---|---|---|
| **T1** | 다운로드 버튼 + 에셋 번들 ZIP (개별 다운로드 포함) | 사장님+고객 전부 | 낮음 — 지금 재료로 전부 가능 |
| **T2** | ZIP 안에 **캡컷 draft**(타임라인 미리 짜인 프로젝트 폴더) 동봉 | 〃 | 중간 — draft 포맷 비공개·버전 취약 |
| **T3** | ZIP 안에 `캡컷에서열기.bat` — 더블클릭이면 draft를 캡컷 폴더에 복사+캡컷 실행 | 사장님(원하는 고객) | 낮음 — 실패해도 T1/T2로 폴백 |

**배포 단위도 이 순서.** T1만으로도 기능이 성립하고, T2·T3는 각각 독립 배포한다.

## 2. T1 — 다운로드 + 에셋 번들 ZIP (기반, 먼저 라이브)

### 2-1. 최종영상 다운로드
- `/api/mix/video/{job_id}?dl=1` → `FileResponse(..., filename="<작업제목 또는 job_id>.mp4",
  media_type="video/mp4")` + `Content-Disposition: attachment`. dl 없으면 기존(재생) 그대로.
- UI: 7단계 최종렌더 완료 시 `<video>` 밑에 `⬇ 영상 다운로드` 버튼(기존 fx_url 다운로드 링크 패턴 재사용).

### 2-2. 내보내기 ZIP — `GET /api/mix/export/{job_id}`
서버가 job의 work 폴더+DB에서 조립해 스트리밍 zip 반환 (`zipfile` + `StreamingResponse` 또는
임시파일 후 FileResponse). 구성:

```
export_<job_id>.zip
├── final.mp4                  # 최종 렌더(있으면). 없으면 항목 생략(내보내기는 렌더 전에도 가능)
├── sources/beat_00_<role>.mp4 # ★비트별로 잘린 소스 클립(캡컷에서 장면 단위 재배열이 목적)
│   └── ...                    #   edit_plan의 primary(+plan_beat_clips 결과)로 ffmpeg -ss/-t 컷
├── tts/beat_00.mp3 ...        # 비트별 TTS(이미 work/tts/에 존재, 복사만)
├── captions.srt               # ★_beat_timeline(t0·dur·narration·cap_durs)로 생성.
│                              #   cap_durs 있으면 구절 단위 큐, 없으면 비트당 1큐
├── script.txt                 # 비트별 역할+나레이션 전문
├── seo.txt                    # seo_json 있으면(제목·태그·설명). 없으면 생략
└── README.txt                 # 캡컷에서 쓰는 법 3줄(영상·음성·SRT 올리는 순서)
```

- 비트별 소스 컷·SRT 생성은 **video_assemble의 기존 함수 재사용**(`_beat_timeline`,
  `_plan_beat_clips`) — 새 타임라인 계산 금지(어긋남 seam 방지, 단일 출처 원칙).
- UI: 7단계에 레퍼런스처럼 `📦 캡컷용 내보내기(ZIP)` 큰 버튼 + 개별 다운로드 소버튼 3개
  (`소스 영상`=zip 중 sources만 / `SRT 자막` / `스크립트`) — 개별은 같은 엔드포인트에
  `?part=sources|srt|script`로.
- 유료게이트: export는 최종렌더와 같은 tier 취급(deny-by-default에 새 엔드포인트 등록 필수 —
  유료게이트 트랙의 허용목록 방식 확인할 것).

### 2-3. SRT 규칙
- 시작·끝 = `t0 ~ t0+dur`(최종 타임라인 기준, 콘폼·여운 반영된 값).
- cap_durs(ASR 구절)가 있으면 구절별 분할 큐, 없으면 비트 전체 1큐.
- 인코딩 UTF-8(BOM 없이), `HH:MM:SS,mmm` 표준 포맷.

## 3. T2 — 캡컷 draft 자동생성 (와우 경험)

- 목표: ZIP 안 `capcut_draft/<프로젝트명>/` 폴더 — 캡컷 드래프트 폴더에 풀면 캡컷 홈에 프로젝트가
  떠서 **열면 타임라인이 이미 짜여 있다**(비디오 트랙=비트 클립 순서대로, 오디오 트랙=beat TTS,
  자막 트랙=SRT 내용).
- 캡컷 draft 위치(Windows): `%LOCALAPPDATA%\CapCut\User Data\Projects\com.lveditor.draft\<이름>\`
  (`draft_content.json` + `draft_meta_info.json` + 에셋). **포맷 비공개·버전 취약.**
- **착수 절차(필수)**: 로컬 캡컷에서 빈 프로젝트+클립 1개짜리 프로젝트를 만들어 draft_content.json을
  역공학 → 설치 버전 기준으로 생성기 작성 → 실제 캡컷에서 열리는지 육안 확인 후에만 배포.
  열리지 않으면 T2는 ZIP에서 빼고 T1만 유지(기능 플래그).
- 에셋 경로는 draft 폴더 내부 상대경로(또는 캡컷이 요구하는 형식)로 — 절대경로 박으면 남의 PC에서 깨짐.

## 4. T3 — `캡컷에서열기.bat` (설치 없는 자동 실행)

- ZIP 루트에 동봉. 더블클릭 시:
  1) `%LOCALAPPDATA%\CapCut\User Data\Projects\com.lveditor.draft\` 존재 확인(없으면 안내 후 종료)
  2) 옆의 `capcut_draft/<프로젝트>` 폴더를 그리로 복사
  3) 캡컷 실행(`start "" "%LOCALAPPDATA%\CapCut\Apps\CapCut.exe"` — 실제 설치경로는 구현 시 실측.
     레지스트리/일반 경로 몇 개 순회 후 실패 시 "캡컷을 직접 실행하세요" 안내)
- 캡컷은 드래프트 폴더를 홈 목록으로 스캔하므로 "자동으로 열림"에 근접(프로젝트 클릭 한 번).
- cmd 창에 한글 안내 출력(chcp 65001). 어떤 실패도 파일을 지우지 않음.

## 5. 구현 순서·트랙

- 트랙명 **`내보내기캡컷`** 신설(`py tools/track.py start 내보내기캡컷`). produce.html 7단계 블록과
  app.py 신규 라우트만 건드림 — 동시트랙과 seam 최소.
- Task 순서: T1-백엔드(export zip+dl=1) → T1-UI → **[배포1]** → T2 역공학·생성기 → T3 bat → **[배포2]**.
- 테스트: SRT 생성 단위테스트(타임라인→큐 텍스트 golden), zip 구성 항목 존재 테스트,
  dl=1 Content-Disposition 테스트. T2는 자동테스트 불가(캡컷 육안) — 미관측이면 정직하게 보고.

## 6. 리스크·미결

- **T2 포맷 버전**: 캡컷 업데이트로 draft 스키마가 바뀌면 깨짐 → 생성기에 대상 버전 명시,
  깨지면 T1 폴백이라 서비스는 무사.
- work 폴더 보존 주기 미확인(오래된 job의 소스가 지워졌을 수 있음) — export 시 없는 항목은
  건너뛰고 README에 명시(500 내지 말 것).
- 대용량 zip(소스 여러 개면 수백 MB) — 스트리밍 zip 권장, 타임아웃 주의.
- 유료게이트 등록 누락 시 무료로 뚫림 — 코드점검/유료게이트 트랙 허용목록 방식 따를 것.

## 부록 A — CapCut draft 포맷 역공학 결과 (2026-07-20 실측, 설치 8.9.1.3802)

**전제 정정(중요)**: 레퍼런스는 데스크톱 앱이 아니라 **웹앱 + 브라우저 File System Access API**
(`showDirectoryPicker`, Chrome/Edge 전용)로 캡컷 draft 폴더에 **직접 쓴다**. 따라서 우리 웹앱도
가능 — 초기 설계의 "웹앱은 폴더 못 쓴다" 전제·T3(.bat)는 폐기. **T2 = draft 생성 + FS Access API 직접쓰기.**

**샘플 출처**(로컬 실측, 커밋 금지 — device_id·mac_address 등 개인정보 포함):
`C:\capcutproject\CapCut Drafts\{0711 빈 프로젝트 · 0602 비디오(사진) · 0720 오디오+텍스트}`

### 파일/폴더 (draft 1개 = 폴더 1개, 폴더명=프로젝트명)
`draft_content.json`(타임라인·핵심) · `draft_meta_info.json`(메타) · `draft_cover.jpg` ·
`draft_content.json.bak` 등. 최소로는 `draft_content.json` + `draft_meta_info.json`이면 캡컷 홈에 뜬다(검증 필요).

### draft_content.json 골격 (빈 프로젝트 0711)
- `"version":360000`, `"new_version":"171.0.0"`, `"fps":30.0`
- `"canvas_config":{"ratio":"original","width":W,"height":H,"background":null}` — **세로 숏폼이면 1080×1920**
- `"platform"`/`"last_modified_platform"`: os/app_version(8.7.0)/app_id 359289/device_id 등 — 생성 시 넣되 개인 ID는 무해값 가능(로드 영향 검증)
- `"duration"`: 전체 길이(**단위=마이크로초**, 초×1_000_000)
- `"materials":{videos,audios,texts,speeds,beats,sound_channel_mappings,vocal_separations,placeholder_infos,material_animations,canvases,...}`
- `"tracks":[{type:"video|audio|text", segments:[...]}]`

### 세그먼트 공통
- `material_id` → 해당 material.id 참조
- `source_timerange`:{start,duration} (소스 내 구간, μs) / `target_timerange`:{start,duration} (타임라인 위치, μs)
- `speed`:1.0, `volume`:1.0, `render_index`, `extra_material_refs`:[동반 material id들]

### 비트별 3요소 매핑 (우리 export → draft)
- **소스 클립** → `materials.videos[]`(type "video", path=절대경로, duration μs, width/height, has_audio)
  + 비디오 트랙 segment(source=클립[start,end], target=타임라인 누적). 동반 refs: speed·placeholder·canvas·sound_channel_mapping·vocal_separation
- **TTS mp3** → `materials.audios[]`(type "music", name, path, duration μs) + 오디오 트랙 segment.
  **동반 refs 5개 = speed · placeholder_info · beat · sound_channel_mapping · vocal_separation**
- **자막** → `materials.texts[]`(`content`=JSON문자열 `{"styles":[{fill.color[r,g,b],font.path,range:[0,len],size}],"text":"..."}`,
  font_path·text_color·alignment 등) + 텍스트 트랙 segment(source_timerange=null, target=자막 구간, `render_index` 14000+).
  **동반 refs 1개 = material_animation**(type "sticker_animation", animations:[])

### 동반 material 형태(전부 단순, 새 UUID로 생성)
- speed: `{id,type:"speed",mode:0,speed:1.0,curve_speed:null}`
- sound_channel_mapping: `{id,type:"",audio_channel_mapping:0,is_config_open:false}`
- vocal_separation: `{id,type:"vocal_separation",choice:0,removed_sounds:[],time_range:null,...}`
- placeholder_info: `{id,type:"placeholder_info",meta_type:"none",res_path:"",...}`
- beat: `{id,type:"beats",mode:404,gear:404,user_beats:[],ai_beats:{...대부분 빈값}}`
- material_animation: `{id,type:"sticker_animation",animations:[],multi_language_current:"none"}`
- canvas(비디오용): `{id,type:"canvas_color",color:"",...}`

### T2 구현 계획
1. **서버** `capcut_draft.py`: export와 같은 입력(plan·timeline·source_video_paths·tts_paths)으로
   `draft_content.json`(+meta) dict 생성. 시간 μs 변환, 트랙 3개(video/audio/text), 비트별 세그먼트+동반 material.
   폰트는 캡컷 시스템폰트 경로(설치버전 기준) 또는 무난한 기본. **자막은 우리 SRT와 같은 t0·dur.**
2. **프론트** produce.html: `📁 캡컷으로 보내기` 버튼 → `showDirectoryPicker()`로 캡컷 draft 폴더 선택
   → 서버가 준 draft(JSON+에셋)를 그 폴더에 `프로젝트명/` 만들어 파일 씀(FileSystemWritableFileStream).
   폴더 핸들을 **IndexedDB에 저장** → 2회차부턴 폴더 선택 없이 원클릭(권한 재확인 1회).
   Chrome/Edge만 지원 → 미지원 브라우저는 기존 ZIP 다운로드로 폴백.
3. **검증**: 생성 draft를 `C:\capcutproject\CapCut Drafts`에 놓고 **실제 캡컷에서 열리는지 육안**(자동테스트 불가).
   열리면 배포, 안 열리면 T1(ZIP)만 유지.

### 리스크
- 개인 ID(device_id·mac) 필수 여부 미검증 — 무해값으로 열리는지 확인.
- 폰트 경로가 버전 종속(`.../Apps/8.9.1.3802/...`) — 존재하는 경로 탐색 or CapCut 폴백에 맡김.
- 에셋 경로: draft가 참조하는 mp4/mp3는 **절대경로**라, 사용자 PC에 그 파일이 있어야 함 →
  draft와 함께 에셋도 캡컷 폴더(또는 고정 위치)에 복사해 넣고 그 경로로 참조.
