## 2026-09-16 / 회사PC — 「대본 분석해서 정확히 찾기」 404 수리

### 사장님 제보

레퍼런스 카드 렌즈에서 `📝 대본 분석해서 정확히 찾기` → `⚠️ 대본 분석 실패 —
해당 항목 없음 — 재수집 필요` (화면 캡처: 「짐작한 제품 Godox 어린이 디지털 카메라?」)

### 원인 — 서랍이 둘인데 화면은 넷에서 카드를 꺼낸다 (0순위-B 재발)

`app.py:_find_collected_item`이 뒤지던 곳은 **수집 스냅샷 2종뿐**:
`last_run` 테이블(인스타) + `settings['last_run::<platform>']` 7종.

그런데 화면이 카드를 꺼내는 곳은 `GET /api/reference`의 **네 갈래**다:

| 갈래 | 읽는 테이블 | 종전 |
|---|---|---|
| `archive=1` (역대 히트작) | `channel_archive` | ❌ 안 봄 |
| `days>0` (이번 주/달) | `reel_history` | ❌ 안 봄 |
| 인스타 기본 | `last_run` | ✅ |
| 그 외 플랫폼 | `last_run::<platform>` | ✅ |

게다가 **렌즈·담기 카드**(`lens_youtube_74oxbh`·`grab_instagram_…`)는 어느 스냅샷에도
**원리적으로** 없다 — `mix_basket`에만 있고 그 코드는 우리가 지어낸 것이라 수집이
담을 수가 없다(`store.shortcodes_for_url` 주석의 그 사정과 같은 뿌리).

**라이브 실측(2026-09-16, reference.db)**
```
lens_/grab_ 카드 4종 → 고치기 전 _find_collected_item 전부 None (=100% 404)
mix_basket 8,710건 중 lens_/grab_ = 7,374건 (전부 url 보유)
platform_snapshots 유튜브 55,346건 중 last_run::youtube에 없는 것 45,143건
사장님 카드 = 고독스 C100 투명 뷰파인더 무리(바구니에 9건, 전부 lens_/grab_)
```

증상이 뜨는 곳 3군데(같은 함수를 쓴다): `/api/extract_script` · `/api/wiki/save` · `/api/find/analyze`

### 고친 것 — 판정 한 곳에 서랍 3개 추가

`_find_collected_item` **한 곳**만 고쳐 세 엔드포인트가 같이 살아난다(0순위-B).

| 새 서랍 | 살아나는 화면 | 신설 함수 |
|---|---|---|
| `mix_basket` | 렌즈·담기 카드 | `store.basket_item_any_customer` |
| `reel_history` | 이번 주 / 이번 달 | `store.history_item` |
| `channel_archive` | 역대 히트작 | `store.archive_item` |

찾는 순서 = **정보가 풍부한 순서**(스냅샷 → 바구니 → reel_history → archive).
앞이 이기므로 **종전에 찾히던 것은 그대로** 찾힌다(회귀 0, 실측 400/400).

### ★라이브 데이터가 내 설계를 두 번 반박했다 (다음 세션이 또 밟지 마라)

1. **`reel_history`를 인스타로 못박으려 했다 → 틀렸다.**
   그 테이블엔 `platform` 컬럼이 있고 **유튜브 행이 실제로 있다**(`--0vXduQNVM`).
   못박았으면 유튜브 카드가 인스타 릴스 주소로 조립돼 없는 주소를 받으러 간다
   (2026-09-06에 넣은 가드가 막으려던 바로 그 사고를 내가 다시 만들 뻔했다).
   → `get_reel_meta`를 늘리지 않고 `history_item`을 따로 팠다(목적이 다르면 함수를 가른다).

2. **플랫폼을 코드 접두사로만 읽으려 했다 → 절반만 맞았다.**
   ```
   담긴 8,710건 중 lens_/grab_ 접두사 있음 7,374건 (접두사 vs 도메인 불일치 0건)
                           접두사 없음     1,336건
                             └ 인스타 아님   213건 (youtube 209 · naver 4)
   ```
   접두사만 보면 저 213건이 플랫폼 없이 나가 인스타로 오인된다. 실제로 새는 카드를
   라이브에서 잡았다(`ylKFpMNzDbU` — 바구니에 담긴 유튜브 영상).
   → **url이 1순위, 접두사는 폴백**. 도메인 표는 새로 만들지 않고
   `lens_discover._platform_of`를 재사용(0순위-B), 거기 없는 네이버·쓰레드만 보탰다.

3. `urlparse`를 맨이름으로 썼다 → app.py엔 `import urllib.parse`뿐이라 NameError.
   `urllib.parse.urlparse`로 고침. **모듈 상단 import 스타일을 먼저 보고 쓸 것.**

## ⏭ 다음 세션이 할 일
