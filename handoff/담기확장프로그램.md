# 담기확장프로그램

## 2026-08-04 (회사PC) — 크롬 확장프로그램으로 설치 간소화 · 라이브

### 지시
사장님: "사용자가 한 번에 설치할 수 있는 파일로."

### 왜 필요했나
유저스크립트(텀퍼몽키) 방식은 **4단계**를 밟아야 했고, 그중 3·4단계(크롬 "개발자 모드",
"사용자 스크립트 허용" 토글)는 **어떤 파일로도 자동으로 못 켠다** — 크롬이 막아둔 부분이다.
실제로 2026-07-21에 고객이 그 토글을 몰라 📥가 안 뜨는 사고가 났다.
확장프로그램은 **"사용자 스크립트 허용" 토글 자체가 불필요**해 단계가 절반으로 준다.

| | 사용자가 하는 일 |
|---|---|
| 기존(텀퍼몽키) | 텀퍼몽키 설치 → 스크립트 설치 → 개발자모드 → 사용자스크립트허용 (**4단계**) |
| 신규(확장) | 압축풀기 → chrome://extensions에서 폴더 끌어놓기 (**2단계**) |

### 한 것 (라이브 40aed5e6c, 01:48 재시작 확인)
- **`shopping_shorts/extension/` 신규**(MV3): manifest / content.js / inject.js /
  background.js / popup.html / icons 3종(PIL로 생성, 민트 다운로드 아이콘).
- **`content.js`** = GM_xmlhttpRequest 대체 브리지. 로직이 postMessage로 보내는
  `__ssGmFetch`를 받아 `fetch(credentials:"include")`로 대행 → `__ssGmAck`/`__ssGmResult` 반환.
  **우리 서버로 가는 요청만** 대행(로더와 동일한 악용 차단).
- **`inject.js`** = 페이지 월드 주입기. 콘텐츠 스크립트는 격리 월드라 video·React에
  못 닿으므로, 확장 리소스를 `<script src>`로 꽂아 페이지 월드에서 로직을 실행한다.
- **`/grab_extension.zip`** = 요청 시 메모리에서 zip 생성(빌드산출물 미커밋, mtime 캐시).
  공개 allowlist 등록(설치 안내는 로그인 전에 열린다).
- **`/grab_logic.js`에 CORS 헤더** — 확장이 페이지 월드에서 교차출처로 불러오기 때문.
- **`/grab` 페이지 개편** — 확장 2단계가 본문, 텀퍼몽키 4단계는 접이식 폴백으로 강등.

### ★설계 핵심 (다음에 건드릴 때 반드시 알 것)
1. **로직 파일은 유저스크립트와 공유한다.** `grab_logic.js` 한 곳만 고치면 확장·유저스크립트
   **양쪽 모두 자동 반영**된다(재설치 불필요라는 기존 장점 유지). 확장에 로직을 복사하지 마라.
2. **MV3는 원격 코드 실행 금지.** fetch로 받은 코드를 `eval()`하면 정책 위반이라 웹스토어
   심사에서 거부된다. 그래서 `<script src>`로 로드한다. 유저스크립트 로더가 인스타 CSP에서
   eval로 죽어 Blob 폴백을 넣었던 것과 같은 문제 — **확장 리소스 주입은 페이지 CSP를 안 탄다**.
3. 페이지 CSP가 우리 도메인 script-src를 막는 경우(인스타)를 대비해 inject.js에
   Blob 폴백을 뒀다(브리지로 코드를 받아 blob:으로 실행 — 인스타 CSP가 blob:은 허용).
