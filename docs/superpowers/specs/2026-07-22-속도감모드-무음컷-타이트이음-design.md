# 속도감 모드 — 무음 컷 + 타이트 이음 (design)

작성: 2026-07-22 / 트랙: `속도감모드`

## 배경 / 문제

쇼츠 편집의 핵심은 **무음 구간을 잘라 문장이 끊김 없이 속도감 있게 이어지는 것**이다.
사장님은 지금 캡컷에서 문장(비트) 클립의 끝과 다음 문장의 시작을 손으로 겹쳐 이 효과를
낸다. 이걸 파이프라인이 자동으로 해줘야 한다.

현재 믹스 파이프라인은 비트마다 `[소스영상 슬라이스 + 그 문장 TTS]`를 각각 렌더한 뒤
`concat -c copy`(스트림 복사)로 **끝과 끝을 딱 붙인다**([video_assemble.py](../../../shopping_shorts/video_assemble.py) `_render_mix`).
겹침이 0이고 각 TTS의 앞뒤 숨소리가 그대로 남아 문장마다 "툭툭" 끊기는 느낌이 난다.

## 결정 사항 (브레인스토밍)

1. **말소리는 겹치지 않는다** — 문장 사이의 숨·여운(무음)만 잘라 타이트하게 붙인다.
   (진짜 크로스페이드로 단어끼리 포개면 말이 웅얼거려 기각.)
2. **오디오만 다룬다** — 영상은 하드컷 유지. 소리가 이어지면 끊김 체감은 대부분 사라진다.
   영상 디졸브는 `concat -c copy`를 깨고 서버 재인코딩을 유발해 제외.
3. **한 스위치 '속도감 모드'** — 문장 안 쉼(A) + 문장 사이 이음(B)을 하나로 묶는다.
   따로 두면 한쪽만 켜고 "왜 안 빨라지나" 헷갈린다.
4. **기본 ON** — 쇼츠 핵심 기능이므로. 끄면 지금처럼 원본 여운 유지.
5. **끝 고정 여백 ~80ms** — 문장마다 일정한 미세 숨을 남겨 기관총처럼 안 들리게 한다.

## 접근 방식 — 문장별 가장자리 다듬기

각 문장 TTS를 **합성 직후** 다듬는다. 전부 [audio_post.py](../../../shopping_shorts/audio_post.py)
`post_process` 한 곳, ffmpeg 한 패스에서 처리한다.

### 왜 뒷단을 안 건드려도 되는가 (핵심)

자막 싱크·영상 슬라이스·`_beat_timeline`은 전부 **다듬어진 뒤의 `tts_dur`**(=`_probe_duration(mp3)`)을
기준으로 누적 오프셋을 계산한다. `post_process`가 mp3를 짧게 만들면 하류가 읽는 `tts_dur`이
자연히 그 값이 되므로, 비트가 짧아진 만큼 영상 컷도 짧아지고 자막도 그에 맞는다.
→ `video_assemble.py`·`mix_pipeline` 오케스트레이션·타임라인 코드는 **전혀 수정하지 않는다.**

`mix_pipeline._synthesize_beats`는 `synthesize_line`(→ `post_process`) 이후에
`_probe_duration`으로 `target_seconds`를, `transcribe_words`로 `cap_durs`를 다시 잡으므로,
다듬어진 길이가 UI 표시초·자막 타이밍에까지 일관되게 전파된다(추가 배선 불필요).

### post_process 변경

'속도감 모드'가 켜지면 기존 `silenceremove`(뒤·중간 무음)에 더해:

- **앞 숨소리 제거**: `start_periods=1:start_threshold=…:start_silence=…` 추가.
  현재 필터는 `stop_periods=-1`뿐이라 **문장 첫머리 무음은 안 잘린다** → 이게 이음의 핵심 결손.
- **문장 안 쉼 축소**: 기존 mid 수준 파라미터를 기본으로 태운다.
- **끝 고정 여백**: 다듬은 뒤 `apad=pad_dur=0.08`로 문장마다 일정한 미세 숨을 남긴다.
  (값은 상수로 두고 0으로 바꾸면 최대 타이트.)
- **클릭 방지**: 양 끝 10~15ms `afade`(in/out). 딱 붙일 때 나는 "틱" 잡음 제거. 길이 불변.

필터 순서(개념): `silenceremove(start+stop) → apad(tail) → afade(edges)`, `atempo`가 있으면 맨 앞.
정확한 임계·순서는 구현 시 샘플로 튜닝(스펙은 동작을 고정, 수치는 상수로 노출).

### 스위치 배선

- 보이스 스냅샷(job의 `voice` dict, `/api/mix/voice`가 프리셋에서 복사)에 **`pace_mode` 키 하나** 추가.
- [mix_pipeline.py](../../../shopping_shorts/mix_pipeline.py) `_voice_params`가 이 값을 꺼내
  `synthesize_line` → `post_process`로 넘긴다. 기존 `silence_trim`이 지나는 바로 그 경로.
- `pace_mode` on이면 `silence_trim`을 강제 mid 이상으로 취급(둘을 한 스위치로 묶는 지점).

### UI

produce 화면 보이스 영역에 토글 하나: **"⚡ 속도감 모드 (무음 컷·타이트 이음)"**.
기본 ON. 저장 시 보이스 스냅샷 `pace_mode`에 반영.

## 안 건드리는 것 (범위 밖)

- `video_assemble.py` 렌더/조립/`concat -c copy` — 무변경.
- 영상 크로스페이드/디졸브 — 제외(재인코딩 비용).
- 자막 싱크·컷어웨이 창·`_beat_timeline` — `tts_dur` 재사용으로 자동 적응, 코드 무변경.
- 소스 원본 오디오 기반 점프컷(무음 자동 감지 컷) — 이번 범위 아님(TTS로 오디오를 대체하므로 불필요).

## 컴포넌트 경계

| 유닛 | 하는 일 | 인터페이스 | 의존 |
|---|---|---|---|
| `audio_post.post_process` | mp3 한 개를 속도감 규칙으로 다듬음 | `(in, out, tempo, silence_trim, pace_mode) → out_path` | ffmpeg |
| `mix_pipeline._voice_params` | 보이스 스냅샷 → 파라미터 튜플 | dict → tuple(+`pace_mode`) | 없음 |
| produce UI 토글 | 사장님 on/off | 보이스 스냅샷 `pace_mode` | store voice API |

## 테스트

1. **가장자리 트림**: 앞뒤에 무음이 낀 mp3에 `pace_mode` 적용 시 길이가 **짧아지고**
   앞·뒤 무음이 사라졌는지(대략적 길이 비교 + 무음 검출).
2. **off 동일성**: `pace_mode=off`(또는 미지정)면 기존 동작과 바이트/길이 동일.
3. **끝 여백 존재**: 다듬은 결과 끝에 ~80ms 여백이 남는지(0 여백 회귀 방지).
4. **배선**: `_voice_params`가 스냅샷의 `pace_mode`를 정확히 뽑아 넘기는지.

## 리스크 / 완화

- **과한 내부 트림이 로봇처럼 들림** → mid 수준 기본 + 끝 여백 유지, 수치를 상수로 노출해 튜닝.
- **딱 붙일 때 클릭음** → 가장자리 afade로 봉인.
- **빠른 보이스(speed>1.2, atempo)와 필터 순서 충돌** → atempo 먼저, 그 다음 트림(기존 필터
  체인 확장이라 회귀 위험 낮음).
