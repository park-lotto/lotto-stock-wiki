# 유튜브 인제스트 + 포스트소스 겸용화 — 설계

- **날짜**: 2026-06-21
- **배경**: 소스 확장(C안)의 유튜브 단계. 유튜브 영상은 블로그와 **거의 동일**(영상 1개=파일 1개,
  사전요약, 내용기반 라우팅, 채널=소스). 뉴스도 같은 패턴. → 블로그 코드를 **겸용(범용)**으로
  바꿔 blog·youtube(·뉴스)를 한 모듈로 처리한다. "소스 추가 = config 한 줄".
- **범위**: 유튜브 인제스트 + 블로그 겸용화 리팩터. 뉴스는 후속(config 한 줄).

---

## 1. 유튜브 데이터 (실데이터 확인)

`raw/yt/{date}_{seq}_{제목}.md` — 영상 1개 = 파일 1개. 예:
```
# [주식] 곧 1만시대 코스닥 3000시대...
- **채널**: UP_CYCLE_STOCK
- **날짜**: 2026-06-05
- **링크**: [유튜브 바로가기](https://www.youtube.com/watch?v=...)
## 핵심 요약
... (크롤러 사전요약, ~600자) ...
## 주요 발언
- ...
```

블로그와 차이는 **딱 2개**: 폴더(`raw/yt` vs `raw/blog`), 헤더 라벨(`채널` vs `출처`).
나머지(사전요약·내용라우팅·2층·채널신뢰등급)는 동일.

---

## 2. 결정 사항 (brainstorming 확정)

| 항목 | 결정 |
|---|---|
| 방향 | **겸용화** — 블로그 코드를 범용 `post_ingest`로, blog·youtube 둘 다 처리 |
| 소스 차이 | **config로** — {source_type, dir, header_label, registry} |
| 추출/라우팅/2층 | 블로그와 동일(텔레 fan-out·sector_classify 재사용) |
| 신뢰등급 | 소스별 레지스트리(블로거 ≠ YT채널 네임스페이스), 기본 C |
| blog 처리 | 기존 `blog_ingest`/`blog_questionnaire`를 `post_*`로 **편입**(통합) |

---

## 3. 아키텍처 (겸용)

```
post_sources (config)
  blog    → {source_type:"blog",    dir:"raw/blog", header_label:"출처", registry:"blog_registry.json"}
  youtube → {source_type:"youtube", dir:"raw/yt",   header_label:"채널", registry:"youtube_registry.json"}
       │
post_ingest.py --source {blog|youtube}
  ├ config 조회 → dir·header_label·registry·source_type
  ├ 미처리 탐색 (dir 기준 dedup basename)
  ├ 헤더 파싱 (header_label 가변: 출처/채널 → source_name)
  ├ source_trust(레지스트리, 기본 C)
  ├ extract_post(.md)  ← Gemini 내용라우팅 + 슬롯 (블로그와 동일 프롬프트)
  ├ questionnaire_to_atoms_tg(q, meta)  ← 텔레 2층 fan-out 재사용
  │     meta = {date, channel=출처/채널, type=target_kind, source_type, trust, raw_file}
  └ insert_atom + embed (+ 스탠스 만료)
```

### 재사용 vs 신규/편입
| 자산 | 처리 |
|---|---|
| `questionnaire_to_atoms_tg`·`sector_classify`·`telegram_stance`·`db`·`vector_db` | 재사용 |
| `blog_questionnaire.py` → `post_questionnaire.py` | **편입**(프롬프트 문구 중립화) |
| `blog_ingest.py` → `post_ingest.py` | **편입**(source config 파라미터화) |
| `post_sources` config | **신규**(파이썬 dict 또는 json) |
| `youtube_registry.json` | **신규** |
| `blog_registry.json` | 유지(post_ingest가 config로 참조) |

## 4. post_sources config

`pipeline/atoms/post_sources.py` (파이썬 dict — 경로 계산 편의):
```python
POST_SOURCES = {
  "blog":    {"source_type": "blog",    "dir": "raw/blog", "header_label": "출처", "registry": "blog_registry.json"},
  "youtube": {"source_type": "youtube", "dir": "raw/yt",   "header_label": "채널", "registry": "youtube_registry.json"},
}
```
`source_config(name) -> dict`. 미등록 소스 → 에러.

---

## 5. post_questionnaire (블로그에서 편입)

`BLOG_PROMPT` → `POST_PROMPT`: 문구 "개인 투자 블로그 포스트" → "투자 컨텐츠(블로그·유튜브 등)
요약본". 내용라우팅(STEP0 target_kind ∈ {stock_tips, sector, market, insight}) + 4타입 슬롯 +
sector_hint + 섹터목록 주입(sectors_list) **그대로**. `extract_post(md_path) -> dict`.
`post_trust(registry_file, name) -> str`(미등록 "C").

---

## 6. post_ingest (블로그에서 편입)

`blog_ingest.py` 로직 일반화:
- `_parse_post_header(md_path, header_label) -> {source_name, date, link, title}` — 라벨 가변
  (출처/채널). "블로그"/"유튜브" 등 접미사 정리.
- `get_done_post_files(source_type)`, `get_pending_post(cfg, date_filter)` — dir·source_type 가변.
- `ingest_post(md_path, cfg)` — extract_post → meta(source_type=cfg, channel=source_name,
  trust) → fan-out → 스탠스만료 → 저장. 아티팩트 `raw/post_q/{source_type}/{date}/`.
- `main()`: `--source blog|youtube` 필수, `--all/--date/--limit/--dry-run`.

`atom_pipeline.py`: STEP3.6 = `post_ingest --source blog`, STEP3.7 = `post_ingest --source youtube`.

---

## 7. 마이그레이션 (blog 편입)

- `blog_ingest.py`·`blog_questionnaire.py` → `post_*`로 대체. 기존 blog 테스트는 post 테스트로 이전/갱신.
- atom_pipeline STEP3.6을 `blog_ingest` → `post_ingest --source blog`로 교체.
- 동작 동일성 보장(blog 라이브 재검증). `source_type="blog"` 원자 그대로.
