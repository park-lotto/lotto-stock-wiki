## R. 사실 교정 (스펙 수정 필수 — 오푸스가 스펙에 직접 반영)

**R1. `MIN_SAMPLES=20` 은 낡은 정보 — 실측 `MIN_SAMPLES = 1`** (`element_stats.py:14`, 2026-07-14에 1로 변경: "1개부터 즉시 반영, 쌓이면 재계산").
스펙 §0·§2축1이 "MIN_SAMPLES=20 게이트가 노이즈 차단"을 근거로 쓰는데 현재 그 게이트는 **없다**.
→ 조치: 스펙 문구 수정 + **스파인 승격에는 별도 게이트 신설**(A1). 부품 통계에 =1을 그대로 재사용하지 말 것 — 스파인은 오염 비용이 커서 1개 표본 승격은 과적합이다.

**R2. §3 다이어그램 데이터 흐름 역전** — "믹스 도너 3개 = 장면 팔레트"가 `build_scene_first_plan` **아래**에 그려져 있으나, 팔레트(`source_scripts`)는 이 함수의 **입력**이다(실측 시그니처). 집행 시 혼동 원인 → 다이어그램에서 도너 선택을 함수 위로 올려라.

**R3. D5 "성과 수치 확보됨"은 크롤 시점 이야기 — DB 영속 배관이 없다.**
실측: views/likes/comments는 크롤 클라이언트(`tiktok_client.py:59-61` 등)와 랭킹 빌드에는 흐르지만, 저장 테이블에는 없다 — `script_wiki`는 `followers·comments·density`뿐이고 views/likes/saves 컬럼 자체가 없음.
→ 조치: `pattern_source.perf` 채우는 **수집→저장 배관을 Phase 0 신규 작업으로 명시**. saves는 대부분 플랫폼 API가 안 준다 — perf 스키마는 필드별 nullable + 플랫폼별 가용 매트릭스를 정의하라.

**R4. (지뢰 경고) 카테고리 오염** — `store.py:126-133` 주석 실측: 키워드 추측 카테고리 정확도 54%, 학습 코퍼스 다수가 추측(생활용품 79%·인테리어 80%). `category_source` 컬럼이 이미 있다.
→ 조치: **제품군별 통계·perf_score·스파인 fit_categories 계산에는 `category_source IN ('user','gemini')`만 사용**. 추측(keyword) 카테고리로 집계하면 축2·축3이 처음부터 오염된다. 스펙 §4에 한 줄로 박아라.

## A. 열린 질문 답변 (§9 — 집행 결정)

**A1. (§9-1) 스파인 세분도**: 상황유형 **10~20개 목표**로 좁게 시작. 승격 게이트 = **source_count ≥ 3 AND 사람 승인**. 1대본=1스파인 승격 금지. 클러스터 프롬프트에 기존 스파인 목록을 enum 힌트로 줘서 신규 남발 억제(통제어휘 패턴 — `structure_analyze._CATEGORIES` 방식 재사용).

**A2. (§9-2) perf_score 정규화**: **플랫폼 내 백분위**로 확정(플랫폼 간 절대치 비교 불가). 초안식 유지(백분위 로그가중 × 최근성 감쇠). 계정 크기 편향 보정으로 `views/followers` 비율을 보조 지표로. 상수 노출 원칙 좋음 — 유지.

**A3. (§9-3) 대화체 스코어러**: **혼합, 2단**. 1차 규칙기반(결정적·무과금): 어미 다양성 + 요약체 블랙리스트 — 사전을 손으로 만들지 말고 **승인 코퍼스에서 어미 빈도 자동 산출**(승인 데이터가 곧 사전). 2차 Gemini 판정은 경계선 점수일 때만. **재생성 상한 2회** — 2회 실패 시 무한루프 금지, 초안 그대로 두고 신호등(빨간불)으로 사람에게 넘겨라(기존 fit≤2 UI 패턴 재사용).

**A4. (§9-4) D9 감정·공감 경계**: **인물 참조 유무로 기계 분류**. "서운해하시더라고요"(감정 표현 자체)=스타일 부품·자유조합 / "시어머니가 서운해했다"(인물이 있는 감정 장면)=내용 부품·스파인 종속. 추출 프롬프트에 이 기준을 명시하면 애매함의 대부분이 사라진다.

**A5. (§9-5) 큐레이션 병목**: 자동 승인은 **스타일 부품만**(어미·부사·후킹·CTA — 빈도 상위 + perf 상위). 내용 부품·스파인은 사람 승인 유지(북극성 D6의 존재 이유). pending에 상한을 두고 오래된 미결은 자동 아카이브(큐가 쓰레기장 되는 것 방지).

**A6. (§9-6) 화면중첩 측정**: **pHash로 시작**(프레임 단위, ffmpeg 이미 있음, 무과금·결정적). 임베딩은 pHash가 못 잡는 사례가 실측되면 후순위 추가. 임계 초기치는 스파이크로 실측해 정하라 — 지금 숫자 박지 말 것.

**A7. (§9-7) 행위 스왑 실현성**: 서브 풀 커버율은 **스파이크 먼저**(실제 잘된 영상 2~3세트로 행위단위 태깅 → 커버율 측정) 후 구현. 커버율이 낮으면 §8 전체의 전제가 흔들리므로 이 스파이크가 §8 착수 게이트다.

**A8. (§9-8) 백본 사용권 — ⚠️ 검토 중 가장 중요한 항목**:
- 스펙 §8-3의 "차별화 게이트가 품질(중복 억제 회피)과 권리 리스크 완화를 겸함" 문구는 **위험하다**. 타인 footage를 재사용하며 변형으로 **탐지를 회피**하는 설계는 저작권·플랫폼 정책 양쪽에서 문제가 되고, 걸리면 채널 자체가 죽는다(스트라이크 누적).
- **권고**: 1층(화면) 차별화는 **권리 확보된 소스에 한정** — ①제휴/사용허가 받은 영상 ②자체 촬영 ③라이선스 소스. 기존 `outreach.py`(제휴 아웃리치)가 이미 있으니 "사용 허가 받은 소스만 백본 가능" 플래그를 소스 풀에 두는 게 자연스럽다.
- 2·3층(나레이션 변주·구조 변주·스토리 차용)은 아이디어/포맷 수준이라 문제없음 — 여기가 차별화의 주력이 되어야 한다.
- 차별화 게이트의 자리매김을 "탐지 회피"가 아니라 **"독창성 품질 게이트"**로 스펙에서 고쳐 써라. 최종 판단은 사장님 몫 — 이 리스크를 사장님에게 명시 보고하고 소스 정책(허가소스만 vs 리스크 감수)을 결정받아라.

**A9. (§9-9) 스펙 분할 — 분할하라**:
- **코어 스펙**(현행 §0~§7 + §8-1 사다리표만): 부품은행+스파인 라이브러리. 리스크 낮고 가치 즉시. Phase 0부터 집행.
- **응용 스펙**(§8-2~8-8 분리 신설): 백본-인터리브+차별화+팩토리. A7 스파이크와 A8 사장님 결정이 선행 게이트 — 이 둘이 풀리기 전 구현 착수 금지.
- 근거: 두 덩이는 리스크 프로파일이 다르고(코어=내부 데이터, 응용=타인 footage), 응용의 불확실성이 코어 착수를 막을 이유가 없다.

## B. 스펙에 없지만 집행 계획에 넣을 것

**B1. Phase 0에 수동 스파인 시드 추가** — 클러스터링(Phase 1) 전에 사장님이 아는 아크를 손으로 등록하는 입력(예: "제3자의심→인정", 오늘 IG 3개에서 확인). 스파인 테이블은 Phase 0에 이미 생기므로 공짜이고, Phase 2 생성 반영을 Phase 1 완성 전에 테스트할 수 있게 된다.

**B2. 부품 저장 단위 — 내용 부품은 리터럴 금지**: 증거시연·전환갈등·감정공감은 변형이 무한해 리터럴 문구 저장 시 canonical dedup이 불가능하고 pending이 폭증한다(A5 악화). **내용 부품은 슬롯 템플릿으로 추상화 저장**(예: `{인물}이 {행위}하더니 {반응}` + 실예문 링크), 스타일 부품(어미·부사·후킹·CTA·숫자)만 리터럴. 이러면 dedup 키가 자연히 생기고 표절 거리도 벌어진다.

**B3. 생성 시 부품 주입 방식** — 승인 부품 전부를 프롬프트에 붓지 말 것(토큰·희석). 비트당 버킷별 **top-k(성과가중 샘플 3~5개)**만 주입하고, "이 중에서 고르거나 이 결을 따라라"로 지시. 은행이 커져도 프롬프트가 안 커진다.

**B4. 표절 가드와 부품은행의 충돌 예방** — 부품은행 문구는 원본에서 온 것이라 n-gram 가드(`_plagiarism_flags`)에 걸릴 수 있다. 스타일 부품(어미·부사)은 짧아서 무해하지만 후킹·CTA 리터럴은 걸린다. **가드 예외 목록에 '승인 부품 사용'을 표시**하거나, 후킹·CTA도 슬롯 템플릿화(B2)로 해소하라.

## A8 결정 (2026-07-21 사장님)

**리스크 수용 — 화면 재사용 진행.** 근거: 이 시장의 소스 자체가 재편집물의 재편집물이라 원본 창작물 도용과 결이 다름. 페이블 기록: 원저작권이 법적으로 소멸하는 건 아니므로 잔존 리스크는 있으나 **판단 권한은 사장님에게 있고 결정됐다.** 이에 따라:
- §8 응용 스펙의 선행 게이트에서 A8 제거 → **남는 게이트는 A7 스파이크(행위 태깅 커버율)뿐.**
- 차별화 게이트는 "독창성 품질 게이트"로 자리매김 유지 — 목적 문구만 다듬고 기능(화면스왑+시각변형+유사도 임계)은 그대로. 이 게이트가 잔존 리스크의 실질 완충이기도 하다.

## F. 페이블 추가 개선사항 (A8 결정 후, 5축 재점검에서 나온 빈 구멍)

**F1. 행위 액션 사전 (장면믹스 편의성 + L3의 토대)**
`scene_desc`는 자유서술이라 "당기는 장면 찾기"가 검색이 아니라 매번 Gemini 해석이다. **행위 동사 통제어휘**(당기다·붓다·바르다·펴다·자르다·섞다·닦다…)를 `categorize.KEYWORDS` 패턴으로 만들어 세그먼트에 `action` 태그를 박아라(인벤토리 빌드 시 기존 Gemini 콜에 enum 필드 추가 — 추가 과금 없음). best-of-N·행위스왑·백본 앵커 매칭이 전부 이 인덱스 위에서 돌게 된다. **A7 스파이크가 이 사전의 v1을 낳는 구조로 설계하라**(스파이크 산출물=사전 초안+커버율).

**F2. 소스 프리웜 (팩토리 속도의 실병목 제거)**
[만들기] 클릭 후 다운로드→scene_cut→태깅을 시작하면 팩토리가 아니다. **랭킹에 오른 순간 백그라운드로 미리 처리**(다운로드·컷·행위태깅·구조분석까지) → 클릭 시점엔 조립만. `daily_batch`/`discover_jobs` 패턴 재사용. 저장량이 걱정되면 상위 N개만 프리웜.

**F3. 자기중복 방지 — 변주 계열 관리 (차별화의 빈 구멍)**
스펙의 차별화 게이트는 **원본 대비**만 잰다. 대량생산이 되면 진짜 위험은 **우리 영상끼리의 중복**(같은 백본에서 아내POV·지인POV를 연달아 내면 시청자·알고리즘에겐 같은 영상). `pattern_source`↔발행물 매핑으로 **계열(series) 테이블**을 두고: 같은 백본/스파인의 발행 이력을 추적, 다음 변주는 **미사용 POV·훅·진입을 자동 배정**. 차별화 게이트에 "vs 우리 최근 발행물" 축 추가.

**F4. 골든셋 회귀 평가 (퀄리티의 측정 기반)**
프롬프트·은행·가중치를 계속 바꾸면 **개선인지 퇴행인지 잴 자가 없다.** 잘된 원본 10~20개를 골든셋으로 고정 → 시스템이 같은 제품으로 생성 → Gemini 심판이 원본과 블라인드 채점(대화체·감정·재미강도·싱크가능성) + 사장님 스팟체크. **은행/프롬프트 변경은 골든셋 점수가 안 떨어질 때만 배포.** 이게 있어야 "학습할수록 좋아진다"가 검증 가능한 명제가 된다.

**F5. 네거티브 뱅크 (대본 고도화 — 즉효)**
Phase 3의 네거티브 학습을 기다릴 필요 없다. **반려된 생성물**(요약체 문장, AI냄새 표현, 재미 게이트 탈락분)을 `pattern_item(status=rejected)`에 안티패턴으로 쌓고, 생성 프롬프트에 "이렇게 쓰지 마라" few-shot 3~5개로 주입. 오늘 비교분석에서 나온 실패 사례("확인하셨어요"·"너무 좋아합니다")가 시드. 비용 거의 0, Phase 0부터 가능.

**F6. 잡 상태머신 + 아침 신호등 (대량생산 운영)**
하루 수십 개면 개별 실패(다운로드 깨짐·키 소진·게이트 3연속 반려)가 일상이다. `mix_jobs`를 확장해 **단계별 상태 + 실패 사유 + 자동재시도(상한)**를 기록하고, 대시보드에 **아침 신호등 뷰**: 완료(초록)/사람 개입 필요(노랑—게이트 탈락·매칭 빨간불)/실패(빨강). 사장님 아침 동선 = 노랑만 훑고 승인.

**F7. 변주 계열 = 공짜 A/B (폐루프 정밀화)**
F3의 계열 데이터가 생기면 **같은 제품·같은 스파인에서 훅/POV만 다른 발행물**이 자연 A/B 실험이 된다. 성과 회수 시 계열 내 비교로 "훅 X가 훅 Y보다 저장 1.8배"를 **교란변수 없이** 측정 → 부품 perf_score를 상관이 아니라 준실험으로 갱신. Phase 3 폐루프의 품질이 한 단계 올라간다.

**Phase 배치**: F1·F5 → 코어 Phase 0~1에 병합(싸고 즉효) / F4 → Phase 2 착수 전 구축(변경 배포의 안전망) / F2·F3·F6 → 응용(팩토리) 스펙에 병합 / F7 → Phase 3에 병합.
