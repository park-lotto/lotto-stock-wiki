# 순환매 감지기 (Sector Rotation Detector)

- 날짜: 2026-07-07
- 브랜치: main
- 상태: 설계 승인 완료 → writing-plans

## 한 줄

트리거 뉴스(강한 원자)가 터진 섹터와 **실제로 오늘 +5% 이상 급등한 다른 섹터 종목**이 둘 다 있을 때만, 그 사이 인과관계가 말이 되는지 LLM이 판단해 카드를 만든다. 화살표맵(관계그래프) 없이 섹터 버킷 + LLM 지식만으로 순환매를 잡는다.

## 문제 정의

기존 "촘촘한 그물"(strength_net)은 **침묵 금지** — 미귀속 강세는 무조건 경보로 올린다. 순환매 감지기는 그 반대: 트리거와 급등이 둘 다 있어도 인과관계가 억지스러우면 **조용히 카드를 만들지 않는다**. 목적이 다르다 — 미귀속강세는 "놓치면 안 되는 알파 탐지", 순환매감지기는 "이미 확인된 두 사실(트리거뉴스+실제급등)을 설명 가능한 스토리로 엮어 보여주는 것"이라 신뢰도가 더 중요하다.

기존에 시도했던 방식(관계그래프/화살표맵, edges.py 패턴)은 순환매처럼 산발적·일회성 연결(오늘의 반도체클러스터 확정 → 오늘의 시멘트주 급등)에는 과설계 — 매번 새로운 조합이라 그래프에 미리 넣어둘 수 없다. 대신 섹터맵(버킷)으로 "트리거와 다른 섹터"만 걸러내고, 나머지 인과 판단은 LLM 지식(온더플라이)에 맡긴다.

## 설계 원칙

- **둘 다 있어야 후보** (게이트): 트리거 원자(강한 공시/뉴스) + 오늘 히트맵 +5%↑ 다른섹터 종목. 하나라도 없으면 LLM 호출 자체를 안 한다(비용 0).
- **억지 연결 금지**: LLM이 "인과관계 불명확"이라 판단하면 빈 결과 반환을 정상 동작으로 취급한다. 카드 개수를 억지로 채우지 않는다.
- **화살표맵 불필요**: 사전 구축된 관계그래프 대신 섹터 버킷(`pipeline/atoms/sectors.json`, `stock_sector_map.json`) + LLM 지식으로 매 실행마다 온더플라이 판단.
- **기존 UI 재사용**: `market_briefing.json`의 `insight.turning_points` 배열에 `type:"circulation"` 항목으로 얹는다. market.html의 `_buildTimeline()`은 최소 수정(타입 분기 이모지만 추가)으로 기존 "시장상황 타임라인"에 자연스럽게 섞인다.
- **모델 스위치 가능**: 1차 Gemini Flash로 구현·검증 → 품질 부족하면 Sonnet(`claude -p`)으로 교체할 수 있게 매칭 함수는 model 파라미터를 받는다.

## 아키텍처

### 1. 신규 모듈 `pipeline/atoms/circulation.py`

strength_net.py와 동일한 순수함수 스타일(테스트 용이성 위해 부수효과 없음):

- `trigger_candidates(days=3, min_strength=3, query_fn=None) -> list[dict]`
  - atoms.db에서 최근 N일, bullish류 signal, strength_score>=min_strength인 원자 조회
  - 반환: `{atom_id, content, sector, source_name, trust, strength_score}`
- `mover_candidates(heatmap: dict, exclude_sectors: set, min_rate=5.0) -> list[dict]`
  - `movers_from_heatmap`(strength_net에 이미 있음) 재사용 + 트리거 섹터 제외 필터만 추가
  - 반환: `{name, code, sector, rate}`
- `build_prompt(triggers: list, movers: list) -> str`
  - 두 리스트를 LLM에 제시하고 "실제로 말이 되는 인과관계가 있는 조합만" 추출하도록 지시하는 프롬프트 생성
  - 억지 연결 금지, 근거 없으면 빈 배열 반환하라고 명시
- `parse_matches(llm_text: str) -> list[dict]`
  - LLM 응답(JSON)을 카드 스키마로 파싱: `{trigger_summary, trigger_sector, mover_sector, mover_stock, mover_code, pct, reasoning, label}`
- `detect(triggers, movers, gemini_fn, cwd=None, claude_bin=None, model="gemini") -> list[dict]`
  - 오케스트레이션: 프롬프트 생성 → LLM 호출(model에 따라 gemini_fn 또는 claude -p 분기) → 파싱 → 반환
  - triggers/movers 둘 중 하나라도 비어있으면 LLM 호출 없이 `[]` 반환

### 2. server.py 배선

- 새 함수 `_circulation_tick()`: `_prewarm_cache["market_flow"]`에서 heatmap 읽고, atoms.db에서 trigger_candidates 조회 → `circulation.detect()` 호출
- 독립 스레드 `_poll_circulation()`: 15분(900초) 고정 주기 루프, `threading.Thread(daemon=True).start()`로 기존 `_poll_briefing`과 나란히 등록
- 결과 카드는 `st["turning_points"]`(weather_state)에 `type:"circulation"`으로 append — 기존 `_briefing_set_insight` 저장 경로 재사용
- **중복 방지**: `_weather["circulation_seen"]` (세션 전용 set, `(trigger_sector, mover_code)` 튜플) — 오늘 하루 같은 조합 재카드화 방지. 날짜 바뀌면 초기화(기존 `synth_count` 리셋 로직 옆에 같이)

### 3. market.html 배선 (최소 수정)

- `_buildTimeline()`의 `tps` 매핑에서 `type` 필드를 그대로 살려서 넘김 (현재는 전부 `type:"event"`로 고정 — `t.type||"event"`로 변경)
- `mkCard()`의 `emoji` 분기에 `type==="circulation"` 조건 추가 → 🔄 이모지
- 그 외 로직(dedup, 정렬, 8개 프리뷰+접기)은 이번 세션에 이미 손본 것 그대로 재사용

## 데이터 흐름

```
15분 tick
  → atoms.db: 최근 3일 강한 원자(strength_score>=3, bullish) 조회       [trigger_candidates]
  → market_flow 캐시: 오늘 히트맵에서 +5%↑ 종목, 트리거 섹터 제외          [mover_candidates]
  → 둘 다 있음? ──No──→ 종료 (LLM 호출 안 함)
       │Yes
  → Gemini Flash: "트리거 리스트 + 급등 리스트 → 말이 되는 인과관계만"
  → 응답 파싱 → 카드 0개 이상
  → (trigger_sector, mover_code) 조합이 오늘 이미 나왔으면 스킵
  → weather_state.json의 turning_points에 type:"circulation"으로 append
  → market_briefing.json 갱신 (기존 저장 경로 재사용)
```

## 에러 처리

- Gemini 실패/쿼터 소진: `_gemini_text`의 기존 다중모델 폴백(`GEMINI_TEXT_MODELS`) 그대로 재사용, 전부 실패하면 이번 tick은 스킵하고 15분 뒤 재시도
- `market_flow` 캐시 비어있음(서버 재시작 직후, 장 시작 전): mover_candidates가 빈 배열 → LLM 호출 없이 자연 스킵
- LLM 응답 파싱 실패(JSON 아님 등): 빈 배열로 처리, 에러는 로그만 남기고 다음 tick 정상 진행
