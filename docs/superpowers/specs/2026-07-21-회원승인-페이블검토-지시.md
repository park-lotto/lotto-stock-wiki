## 🔴 결함 — 반드시 계획에 태스크로 포함

### 1. `_AUTH_ALLOW` 우회 경로의 자체 게이트가 pending을 통과시킨다
`/api/grab`(app.py:3867)은 미들웨어를 안 타고 자체적으로
`if access_level(cid) == "ranking_only": 402` 만 한다. `"pending"`은 이 비교에
안 걸려 **대기중 사용자가 담기를 그대로 쓴다.**
- 수정: `access_level(cid) != "full"` 로 뒤집는다 (pending·ranking_only 모두 차단,
  단 grab은 원래 ranking_only도 막던 유료 기능이므로 의미 동일).
- `== "ranking_only"` 문자열 비교 전수 점검(실측 4곳): app.py 3573(미들웨어 —
  pending 분기를 이 앞에 추가하므로 유지 가능), 3698(/api/me류 — level 그대로 노출,
  pending 값 내려가도 무방), 3728(admin 목록 — 표시용), 3867(★위 수정 대상).
- 테스트 필수: pending 계정으로 `/api/grab` 호출 → 402/403 확인.

### 2. 테스트 파일 경로는 `shopping_shorts/tests/`
`tests/test_paywall_*.py` 아님. 실측 존재 파일:
`shopping_shorts/tests/test_paywall_{access,admin,gate,google,usage}.py` + 같은 폴더 `conftest.py`.
신규 테스트는 여기에 추가하고 기존 conftest 픽스처를 재사용할 것.

## 🟡 보완

3. **마이그레이션은 기존 패턴 복제**: `_ensure_paywall_schema`(store.py:630-657)의
   `fresh_full_access` 플래그 패턴과 동일하게 — ALTER 성공 시에만 `fresh_approved=True`
   → 그때만 `UPDATE customers SET approved_at=? WHERE approved_at IS NULL` 백필.
   (컬럼 추가 최초 1회에만 백필 → 이후 신규 대기 계정을 안 덮는다. 설계 의도 그대로.)
4. **pending 게이트에서 `/logout` 명시 허용**: `_FREE_EXACT_ANY`(app.py:2839)는
   ranking_only 게이트용이라 pending 분기가 따로 `/logout`(+`/static`)을 열어줘야
   대기자가 로그아웃할 수 있다.
5. **`create_customer(approved=False)` 도입 전 호출부 전수 grep**:
   `grep -rn "create_customer(" shopping_shorts/`. 기존 테스트·시드가 계정을 만들어
   full 접근을 전제한다면 그 호출부는 `approved=True`를 명시하거나 테스트 픽스처를
   승인 상태로 맞춘다. 안 하면 무관한 기존 테스트가 연쇄 실패 → finish 게이트가
   "실패 증가"로 병합을 막는다.
6. **admin.html: pending 행에는 set_plan(등급변경) UI 숨김**: pro를 줘도 판정 순서상
   pending이 우선이라 안 열린다. 승인 진입점은 [승인] 버튼 하나로 통일해 혼란 방지.

## 참고 (설계 확정 사항 재확인)
- 판정 순서: cid==0 → full / cust 없음 → ranking_only / **approved_at IS NULL → pending** / pro → full / 체험중 → full / else ranking_only.
- 승인 멱등: `UPDATE ... WHERE id=? AND approved_at IS NULL` — 재승인해도 체험 리셋 없음.
- 신규 가입(구글·/api/signup): `approved_at=NULL`, `full_access_until=0`. 체험은 승인 시 시작.
- 세션은 무상태 쿠키 → 승인 즉시 다음 요청부터 반영, 세션 무효화 불필요.
