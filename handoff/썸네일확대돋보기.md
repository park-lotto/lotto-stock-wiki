# 썸네일확대돋보기 — 썸네일 꾸미기에 🔍확대 · 🔎돋보기

**소유 트랙**: 썸네일확대돋보기 — 이 파일은 이 트랙 세션만 수정한다. 다른 트랙은 읽기만.

## 2026-09-13 — 구현 완료 (커밋 dfadb66fc, 아직 미병합)

사장님: *"썸네일 꾸미기에서 확대랑 돋보기기능 장면꾸미기 있는것 추가해주는게 심플하게
기능 조작되게 넣어주고 그게 렌더랑 캡컷까지 이어지게 해줘"*

착수 전 확인한 것: 사장님이 **"썸네일 PNG에만(정지 그림)"** 을 골랐다. 즉 썸네일에서 맞춘
확대·돋보기를 그 장면의 `scene_zoom`/`scene_hl`에 밀어넣지 **않는다** — 그건 6단계에서
따로 맞춘 값이라 덮으면 "썸네일만 바꿨는데 영상 구도가 바뀐다"가 된다(0순위-B).

### 무엇을 넣었나 (7단계 썸네일 · produce.html)

| 기능 | 조작 |
|---|---|
| 🔍 사진 확대 | 슬라이더 100~300%, ↺ 되돌리기, 확대 상태에서 **캔버스를 끌면** 위치 이동 |
| 🔎 돋보기 | 켜기 체크 → `🔍원 안 확대` / `💡원 밖 어둡게`, `⭕원`/`▢둥근네모`, 크기·배율, **원을 끌어** 이동 |

★**배경 사진에만** 건다. 글자·스티커는 같이 확대하지 않는다 — 장면꾸미기도 같다
(`.zoomStage > #hcPreviewBg`). 제목이 같이 커지면 화면 밖으로 나가 못 쓴다.

### 값의 뜻 = 서버와 한 벌 (0순위-B)

`video_assemble.scene_zoom_of` / `scene_hl_of`와 **같은 범위·같은 비율 단위**로 맞췄다.

```
zoom   1~3                      pan  |pan| <= (zoom-1)/2   (화면 폭·높이 대비, 오른쪽·아래가 +)
hl.r   0.06~0.9 (★폭 대비)      hl.zoom 1.1~4              hl.cx/cy 0~1
```

해석하는 곳은 **`thumbView()` 하나뿐**이다(produce.html). 그리기·드래그·저장이 전부 이걸 부른다.

### 렌더·캡컷으로 어떻게 이어지나 — 새 배선은 0곳

썸네일은 **브라우저 캔버스가 PNG로 굽는다**(app.py:8637 "서버는 합성하지 않는다").
그래서 PNG에 구워두면 아래 길로 저절로 따라간다:

```
drawThumb(canvas) → toBlob PNG → /api/produce/thumb/save
  → _selected_thumb_path(job)              app.py:7883
  → _thumb_intro_png(job, thumb)           mix_pipeline.py:3330
  → prepend_still(final.mp4, png)          mix_pipeline.py:3515   ← 영상 맨 앞에 붙음
  → 캡컷은 그 final.mp4를 가져간다          (별도 배선 불필요)
```

⚠️ 단 **9단계 `🖼 썸네일을 영상 맨 앞에 넣기`를 켜야** 영상에 들어간다(종전과 같은 조건).
끄면 썸네일은 썸네일로만 쓰인다 — 이건 원래 동작이고 바꾸지 않았다.

### 저장

`generateThumb`의 meta에 `view`를 실었고 **app.py 화이트리스트에도 넣었다**
(`("frame_ts","frame_url","layers","view")`). 화이트리스트에 안 넣으면 미리보기만
바뀌고 다시 열면 사라진다(조용한 유실) — 이 함정은 메모리에도 있다.
job이 바뀌면 `view`도 초기화한다(남기면 새 영상에 엉뚱한 구도가 걸린다).

### 실측 (0순위-A1 — 정적 검토는 확인이 아니다)

- **실제 브라우저(chromium) 렌더 7종**을 그려 **픽셀을 읽어** 확인:
  - 구석 4곳 빈(검은) 자리 **0** — 확대+이동 한계까지 밀어도 그대로
  - 확대·이동이 실제로 구석 색을 바꿈 `43,88,118 → 78,92,105 → 112,96,92`
  - `원 밖 어둡게`는 전 구간이 어두워짐 `43,88,118 → 17,35,47`
  - **돋보기가 진짜 확대하는지 글자 폭으로 측정: 원본 105px → 2배 원 안 567px**
- 새 테스트 8개(`test_thumb_zoom_highlight_js.py`) + 기존 썸네일 관련 **312개 통과, 실패 0**
- ★**테스트가 진짜 버그를 잡았다**: `+v || 기본값`은 **0도 falsy**라 돋보기 배율 0이
  하한 1.1이 아니라 기본값 2로 튀었다(`cx=0`=왼쪽 끝도 같은 함정) → `_thumbNum()`으로 분리.

### 테스트를 문자열 검색으로 안 쓴 이유

이 기능의 버그는 "그 줄이 있느냐"가 아니라 **어떤 좌표로 그리느냐**에서 난다.
그래서 produce.html에서 함수를 떼어 `js_harness.run_js`로 **진짜 호출**하고, 캔버스를
대역으로 받아 좌표를 검사한다. 특히 `pan 한계에서 그림 끝이 화면 끝에 정확히 닿는가`는
눈으로는 놓치는 종류라 수치로 못박았다.
