## 왜 만드나

사장님 지적(2026-08-17):

> "뭐는 에피파이고 뭐는 프록시고 이런거 없고 한번에 다 되게 설계하고 파서 만들어야대.
>  다른 프로그램들 다 그렇게 하고있어 이미"

지금은 **가져오는 방법이 호출부까지 새어나온다**. 그래서 대화도 코드도 "샤오는 프록시,
도우는 에피파이"를 매번 따진다. 백엔드가 바뀌면 호출부를 고쳐야 한다.

두 번째 문제: 렌즈 모달의 `📕 샤오홍슈` `🎬 도우인` 버튼이 **외부 사이트로 나간다**.
사장님 요구는 "우리 페이지 안에서 렌즈 결과처럼 카드로 보이게".

## 실측으로 확정된 사실 (2026-08-16~17)

추측이 아니라 서버에서 직접 돌려 확인한 값이다.

| 항목 | 실측 결과 |

| 샤오홍슈 Playwright 검색 | ✅ **17건** (카드 18개 중 URL 17개) · 비용 $0 |

**도우인 QR 로그인은 실패**(사장님 시도). 그래서 도우인은 당분간 Apify가 담당한다.

## 설계

### 단일 진입점

새 모듈 `shopping_shorts/cn_search.py`. 호출부는 이것만 안다:

```python
cn_search.search(keyword, max_results=10)
# → {"items": [...], "meta": {...}}
```

**백엔드가 뭔지 호출부는 영원히 모른다.**

### 백엔드 사슬 — 결정은 한 곳에서만

```python
_CHAIN = {
    "xiaohongshu": [_pw_xiaohongshu, _apify_xiaohongshu],
    "douyin":      [_pw_douyin,      _apify_douyin],
}
```

무료(Playwright)를 먼저 시도하고, 실패하면 유료(Apify)로 폴백한다.
도우인 세션이 나중에 생기면 **이 표를 안 고쳐도** `_pw_douyin`이 성공하기 시작해
자동으로 $0이 된다. 호출부·프론트 무수정.

> **0순위-B 준수**: "어느 백엔드를 쓸까"라는 판단이 `_CHAIN` **한 곳에만** 있다.
> 같은 판단을 두 번 적지 않는다.

### 폴백 판정 = A안 (사장님 확정)

**결과 0건이면 다음 백엔드로 넘어간다.** 예외·차단만이 아니라 빈손도 폴백 사유다.

근거: 회당 $0.04이고 매달 500회가 리셋된다. 크레딧은 **이월되지 않아 안 쓰면 소멸**한다.
따라서 "돈 아끼려다 사장님이 결과를 못 보는 것"이 더 비싼 손해다.

### 계정·프록시는 짝으로 (사고 재발 방지)

`_pw_douyin` 내부에서 **CN 프록시와 세션을 함께** 정한다. 따로 정하면 어긋난다
— 2026-08-09 인스타 실사고(계정↔IP 불일치로 챌린지)와 같은 함정.
프록시 변환은 기존 `channel_archive.playwright_proxy_kw`를 **재사용**한다(새로 짜지 않는다).

### 반환 스키마 — 기존과 동일

```python
{"platform", "url", "title", "thumbnail", "play_url",
 "channel", "likes", "views", "duration", "is_short"}
```

기존 `xiaohongshu_search.search`가 내는 키와 같다. **렌즈 카드 렌더링을 그대로 재사용**
하려는 것 — 프론트에 새 카드 컴포넌트를 만들지 않는다.

### 비용 가시성

```python
"meta": {
  "xiaohongshu": {"backend": "playwright", "cost_usd": 0,    "n": 17},
  "douyin":      {"backend": "apify",      "cost_usd": 0.04, "n": 12},
}
```

어느 백엔드가 돌았고 얼마 들었는지 응답에 싣는다. 화면에 "이번 검색 $0.04"를 띄울 수
있고, **비용이 조용히 새는 것**을 막는다(캐시키 불일치·키소진 오탐류 함정의 교훈).

### 프론트

`/api/lens/cn/search`(현재 죽은 코드)를 이 모듈에 연결해 되살린다.
후보 버튼 클릭 → **외부 이동 대신 그 자리에 카드**. 기존 `renderLens`의 카드 경로를 탄다.

가드는 형제 함수(`fetchLensYt`·`fetchLensCnKeywords`)의 `root.dataset.sc === shortcode`
패턴을 그대로 미러한다 — 늦은 응답이 다른 카드의 모달을 덮어쓰는 사고 방지(기록된 전례 있음).

### 곁다리 정리 — 죽은 토큰 6개

401 토큰이 로테이션 앞쪽에 있으면 매 검색마다 헛때려 느려지고, "왜 느리지"의 원인이 숨는다.
서버 `/etc/shopping-shorts.env`에서 무효 토큰을 걷어낸다. **사장님 확인 후** 진행(서버 변경).

## 안 하는 것 (YAGNI)

- 도우인 세션 로그인 자동화 — QR 실패했고, 세션이 생기면 위 구조가 자동 흡수한다
- 샤오홍슈 앱 API 리버스 — 서명(`x-s`) 필요, 1~2달마다 깨진다
- 틱톡·인스타 백엔드 변경 — 이미 잘 돌고 있다. 이번 범위 밖
- 결과 캐싱 — 먼저 동작을 확인하고, 필요하면 그때

## 테스트

1. **폴백**: 1순위가 예외/0건 → 2순위가 호출되는가 (백엔드 주입, 네트워크 없이)
2. **스키마**: 두 백엔드가 **같은 키**를 내는가 (달라지면 프론트가 조용히 깨진다)
3. **짝 보장**: `_pw_douyin`이 프록시와 세션을 함께 넘기는가
4. **meta**: backend·cost_usd가 실제 사용된 경로와 일치하는가

브라우저·Apify 없이 도는 단위테스트로 짠다(기존 `test_xiaohongshu_playwright.py` 방식 —
`_scrape_one` 주입).

⚠️ 게이트 기준은 "전부 green"이 아니라 **"병합 전보다 실패가 늘지 않았나"**(기준선 존재).
