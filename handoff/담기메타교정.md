### ★왜 스크립트가 아니라 서버를 고쳤나 (재설치 32명 회피)

확장은 MV3 원격코드 금지라 `grab_logic.js`가 패키지에 **동봉**된다 → 서버에 배포해도
**이미 설치된 확장엔 반영 안 됨. 재설치해야 한다.**

아파치 로그 실측 (유저스크립트만 `/grab_logic.js`를 매번 받아간다는 차이로 갈랐다):

| | 고유 IP |
|---|---|
| 담기 사용자 전체 | **34** |
| 유저스크립트(자동 반영) | **4** |
| **확장(재설치 필요)** | **32** |

→ 스크립트만 고치면 32명은 재설치 전까지 계속 깨진다.
**주소는 항상 정확하므로** 서버가 URL로 재조회해 바로잡는 길을 택했다 = 재설치 불필요.

### 한 것

- `store.mix_basket_set_meta(overwrite=False)` — 기본값 유지(손으로 고친 이름 보호)
- `app._grab_meta_is_stale(url, stored_thumbnail)` — **판정은 여기 한 곳에서만**(0순위-B).
  유튜브 썸네일 `i.ytimg.com/vi/<ID>/`의 ID와 URL의 ID를 대조.
  ⚠️**유튜브 한정** — 틱톡·인스타 썸네일엔 영상ID가 없어 대조 불가.
  억지 판정하면 멀쩡한 값을 덮어써 증상 없는 데이터 손상이 된다.
- `_enrich_grab`이 저장된 썸네일과 대조해 stale일 때만 `overwrite=True`
- `scripts/backfill_grab_meta.py` — 기존 행 교정(기본 미리보기, `--apply`로 반영)
- 테스트 8건 추가. **사보타주(판정을 항상 False로)로 2건이 빨개지는 것 확인** — 빈 단언 아님
