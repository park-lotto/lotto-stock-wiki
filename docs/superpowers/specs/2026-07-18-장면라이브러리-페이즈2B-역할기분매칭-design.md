# 장면 라이브러리 페이즈2-B — 역할/기분 기반 매칭 (설계)

- 날짜: 2026-07-18
- 트랙: 장면라이브러리
- 선행: 페이즈2-A(소재 매칭·컷어웨이·검수판) 완성·라이브(main 2066c41c). 라이브 실사용 검증됨.
- 상위 설계: `2026-07-18-장면라이브러리-페이즈2A-매칭-컷어웨이-검수판-design.md`

## 0. 왜 필요한가 (라이브 관측이 이끈 설계)

페이즈2-A 라이브 실사용에서 확인: 매칭이 **소재 그대로(화면=대본 단어)**만 잡는다. 냉동삼겹살 대본 → 냉동삼겹살 짤(0.95)은 완벽히 잡았지만, 사장님이 진짜 넣고 싶어하는 **일반 장면 요소**(만족 슬라이스·귀여운 동물 리액션·눈물 양파·ASMR 먹방)는 대본 단어와 안 겹쳐 **자동으로 못 들어간다**. 이 요소짤들은 "무엇을 보여주나(소재)"가 아니라 **"어느 자리에 어울리나(역할/기분)"**로 붙는다.

**사장님 결정**: 소재 우선 + 없으면 역할로 채움(하이브리드).

## 1. 목표 (범위)

**하는 것**: 2단계 매칭 — 1차 소재 매칭(기존)이 못 채운 빈 비트에, 비트의 **역할 자리**에 맞는 요소짤을 **결정적 매핑표**로 채운다.

**안 하는 것(비범위)**: Gemini로 역할짤을 느슨하게 고르기(과배치 위험 재발 방지) · 영상 간 반복 회피(같은 고양이가 매 영상) · 부분 컷어웨이 · replace/sfx/overlay.

## 2. 핵심 구조 — 2단계 매칭

```
match_scene_assets(plan, assets):
  1차 [소재 패스] (페이즈2-A 그대로): Gemini가 화면소재↔대본단어, 점수≥0.9 → beat["cutaway"]{match_type:"subject"}
       ↓ cutaway 없는 빈 비트에만
  2차 [역할 패스] (신규, 결정적): beat.role → 호환 asset.role 후보 중 최적 1개 → beat["cutaway"]{match_type:"role"}
```

- **서로 안 부딪힌다**: 소재짤은 1차에서 이기고, 요소짤은 1차에서 낮은 점수로 탈락 후 2차에서 자기 자리에 채워진다.
- **역할 패스는 Gemini를 안 쓴다** — 역할 호환은 아래 매핑표로 결정적. AI 과배치(2-A grounding에서 관측)가 구조적으로 불가능.

## 3. 심장 — 비트자리 ↔ 자산역할 매핑표 (결정적)

**자산 역할 통제어휘**(이미 존재, `scene_assets._ROLES`): `훅 · 반전 · CTA · 비법공개 · 반응 · 전환 · 본문`
**비트 역할**(edit_plan 실데이터): `hook · problem_solution · easy_process · process_step1 · process_step2 · result_wow · benefit · cta` (video_type별로 다를 수 있음)

매핑표 `_ROLE_FALLBACK`(비트 역할 → 호환 자산 역할, 순위):

| 비트 역할 | 호환 자산 역할 | 사장님 카테고리 예 |
|---|---|---|
| `hook` | 훅, 반응 | 귀여운 동물 리액션, 시선 잡는 만족짤 |
| `problem_solution`, `problem` | 반전 | 눈물 양파, 요리 실패(페인포인트 빌드업) |
| `easy_process`, `process_step*` | 비법공개, 전환 | 만족 슬라이스·크림("이렇게 쉽게") |
| `result_wow` | 반응, 본문 | ASMR 먹방·바삭함(와우 모먼트) |
| `benefit` | 반응, 본문 | 대리만족 리액션 |
| `cta` | CTA | (CTA 요소짤) |

- **매핑표에 없는 비트 역할** → 후보 없음 → 그 비트는 빈 채로(원본 footage). 억지로 안 채운다.
- 매핑표는 코드 상수(순수). 나중에 조정 가능.

## 4. 역할 패스 배치 규칙 (v1, 결정적·예측 가능)

빈 비트 하나에 대해:
1. 그 비트 역할의 호환 자산 역할 목록을 매핑표에서 가져온다.
2. 후보 = `asset.role ∈ 호환목록` 且 `asset_type=clip` 且 `source_origin ∈ {짜집기,촬영원본}` 且 **이 영상에서 아직 안 쓴 것**.
3. 후보 중 1개 선택(순위):
   - (a) `asset.tone`이나 `keywords`가 비트 나레이션과 겹치면 우선(가벼운 문자열 겹침, Gemini 없음),
   - (b) 없으면 결정적 순서(예: 최근 담은 것 우선 = id 내림차순)로 첫 번째.
4. `beat["cutaway"] = {"asset_id", "match_type": "role", "score": None}` 로 배치. **점수 없음**(역할매칭은 점수 개념이 아님 — 검수판이 "역할 매칭"으로 표기).

**영상 내 반복 금지**: 한 영상에서 같은 asset_id는 한 번만(2번 단계의 "아직 안 쓴 것"). 영상 간 반복 회피는 비범위.

## 5. 검수판 표기 (페이즈2-A UI 확장, 최소)

- 자동배치된 컷어웨이에 **매칭 종류 배지**: `소재 매칭 0.95` vs `역할 매칭(훅 자리)`. 사장님이 둘을 구분해 본다.
- 기존 "이 짤 빼기" 토글 그대로. 역할매칭도 빼기 가능.
- (페이즈2-A의 T4-m2 표시버그 — 수동 넣기 시 점수 1.00 오표기 — 이 참에 같이 고침: 수동 넣기는 "직접 넣음"으로 표기, 가짜 점수 안 씀.)

## 6. 담기 UI (역할 지정, 최소 변경)

- 담기 흐름 그대로. **AI가 역할을 자동 부여**(기존 autotag의 `role`)하되, 요소짤은 사장님이 **역할 드롭다운**(훅·반전·비법공개·반응·전환·CTA·본문)으로 확인·수정.
- 즉 사장님은 "이건 훅용/문제강조용" 자리를 한 번 정해두면, 그 자리 비트에 자동으로 들어간다.
- 소재짤(냉동삼겹살 등)은 역할 안 건드려도 1차 소재 패스가 잡으니 무관.

## 7. 렌더 (변경 없음)

역할매칭도 `beat["cutaway"]`에 asset_id를 쓰므로, 페이즈2-A의 렌더 배선(`run_render`/`run_preview`가 asset_id→media_path 해석 → 컷어웨이 오버레이)이 **그대로 동작**. 렌더는 소재/역할을 구분하지 않는다. 새 렌더 경로 없음.

## 8. 테스트 (TDD)

- **매핑표 순수함수**: 비트 역할 → 호환 자산 역할 목록(hook→[훅,반응], 미지 역할→[]).
- **역할 패스(순수)**: ① 소재 매칭된 비트는 역할 패스가 안 건드림 ② 빈 비트에 역할 호환 자산 배치 ③ 호환 자산 없으면 빈 채로 ④ 한 영상 반복 금지(같은 asset 두 비트에 안 감) ⑤ tone/keyword 겹치면 우선.
- **2단계 통합**: 소재+역할 자산 섞인 상태에서 소재짤은 소재로, 요소짤은 역할로 각자 제자리.
- **실 재료 grounding**: 요소짤 몇 개(반응·반전 역할)를 라이브러리에 담아, 실 대본에 소재 없는 훅/문제 비트가 역할로 채워지나 눈으로 확인.

## 9. 이 증분이 건드리는 파일

| 파일 | 변경 |
|---|---|
| `shopping_shorts/scene_match.py` | 역할 패스 함수 + `_ROLE_FALLBACK` 매핑표. `match_scene_assets`가 소재 패스 후 역할 패스 호출. `match_type` 필드 추가 |
| `shopping_shorts/static/produce.html` | 검수판 배지에 소재/역할 구분 + 수동넣기 표시버그 수정. 담기 모달에 역할 드롭다운 |
| `shopping_shorts/app.py` | 담기 commit/update가 역할 편집 반영(대개 기존 태그 편집 경로 재사용) |
| `shopping_shorts/tests/` | 매핑표·역할패스·2단계통합 테스트 |

렌더(`video_assemble`)·배선(`mix_pipeline`)은 **무변경**(2-A 그대로 탐).

## 10. 미해결·정직하게 남김

- **자산 역할 어휘 vs 사장님 감정 카테고리**: 현 어휘(훅/반전/비법공개/반응/전환/본문)가 사장님 카테고리(만족/귀여움/실패/ASMR)를 완벽히 커버하는지 실담기에서 확인. 부족하면 어휘 확장(계획 단계 재검토).
- **tone 겹침 판정 방식**: 4-(a)의 "가벼운 문자열 겹침"을 실 데이터로 확인해 규칙 확정(못 정하면 결정적 순서만).
- **실 재료로 검증**: 요소짤을 실제로 담아 역할 배치가 "자연스럽나"를 눈으로 — 합성 통과 ≠ 완료(트랙 교훈).
