## 2026-09-11 — 구현 요청과 착수 상태

- 사장님이 '설계는 끝난건가? 구현해야 하는 것 아니냐'고 요청했다. 문서 작성만 이어가지 말고 구현으로 진행할 권한이 있다.
- 실제 실행: `tools/track.py list`, 관련 기록 검색, 저장소 의존성과 기존 서버 구조 확인, `tools/track.py start 회사운영플랫폼` 시도.
- 차단 근거: `.git/refs/heads/track/회사운영플랫폼.lock: Permission denied`. 현재 환경의 `.git` 읽기 전용 정책 때문에 새 트랙을 만들지 못했다. 기존 다른 작업 트랙을 차용하거나 루트 코드를 수정하지 않았다.
- 확인한 기반: 루트 package.json에 puppeteer가 있으며, shopping_shorts/requirements.txt에 FastAPI·uvicorn·pytest가 선언되어 있다. 기존 dashboard/server.py도 FastAPI를 사용한다. 설치·실행 가능 여부는 아직 검증하지 않았다.

### 첫 구현 범위 — 구현 전 상세 계획으로 구체화할 제안

- 독립된 회사 운영 앱: 기존 고객 서비스의 코드·DB와 분리하고, 우선 로컬에서 실제 작동을 확인한다.
- 데이터: 고객 작업공간 → 회사 → 제품·팀 → 역할 배정 → 프로젝트 → 작업 → 실행 사건·검증 증거. 역할 배정과 실제 모델 세션은 구분한다.
- 초기 내용: 사용자 제공 세 회사·제품 상태와 목표 5개 팀. 현재 실행 중인 AI나 매출 데이터를 임의로 생성하지 않는다.
- 화면: 세 회사 탐색, 팀·책임자·워커 구조, 프로젝트 단계, 실제 기록·결과물 상세. 최종 시각 디자인은 첫 실행 가능한 화면에서 조정한다.
- 기능: 프로젝트 생성, 역할 배정, 단계별 인계, 검증 증거 첨부, 대기·반려 이유, 이력 저장과 재조회.
- 실행 연결: 우선 명시적으로 생성한 실제 작업 사건이 화면에 반영되는지 검증한다. 모델 실행 어댑터 연결 여부를 별도 표시하며 미연결 상태를 자동 운영으로 표현하지 않는다.
- 검증: 브라우저에서 회사 선택 → 프로젝트 생성 → 인계·반려·검증 기록 → 새로고침 후 보존 확인. 무증거 완료 방지·잘못된 단계 전이·회사 간 데이터 혼입 방지를 검증한다.
- 후속: 숏템메이커 실패 기록 읽기 연결과 허용된 실제 AI 실행을 붙여 운영규칙의 첫 실제 업무 검증을 수행한다.
- 다음 실행: `.git` 쓰기가 허용된 환경에서 같은 이름의 트랙 유무를 다시 확인하고 생성한 뒤, writing-plans → executing-plans로 이어간다. 현재는 구현 코드가 없다.
- 사용자 요청으로 [페이블 권한 검토 요청](페이블_회사운영플랫폼_권한논의.md)을 작성했다. 직접 연결된 페이블 세션은 없으며, 열람·답변은 미확인이다. 다음 세션은 답변 여부를 확인한다.
