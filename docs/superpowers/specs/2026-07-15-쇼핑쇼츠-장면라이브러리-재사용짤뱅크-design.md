관련 메모리: [[project_쇼핑쇼츠_자동화]] / [[project_자막분할_원리]] / [[feedback_꾸미기_딸깍프리셋철학]]

## 1. 문제 (Why)

믹스(영상제작소 첫 단계)에서 화면은 **넘어온 소스영상 풀에서만** 나온다(`edit_plan._build_inventory`).
그런데 실사용에선 **자주 반복되는 중요 후킹 장면**이 있다 — 놀라는짤·효과음짤·레시피 "비법 한 스푼"
공개 장면 같은 것. 지금은 이런 장면을 그때그때 소스에서 찾아야 하고, 좋은 소재를 봐도
**나중에 재사용하려고 모아둘 곳이 없다**.

사장님 핵심 요구:
> "우리가 작업하는 영상들 + 외부영상(레퍼런스랭킹) 카테고리에서 계속 작업하는데, 이걸 저장해야
> 한다는 게 가장 중요하다. 그래야 '이게 좋은 소재이니 나중에 써야겠다'고 AI가 판단해서 가져온다."

즉 단순 업로드 창고가 아니라 **AI가 큐레이션하는 재사용 장면 뱅크**다: 좋은 장면을 저장 →
믹스할 때 AI가 "지금 이 대본엔 이 짤이 맞다" 판단해 자동 배치.

### 1.1 가장 큰 리스크 — 의미 애매함 (사장님이 직접 지적)

"한스푼 CTA 장면"으로 뭉뚱그려 저장하면 **가루 한스푼 / 액체 한스푼 / 세제 한스푼 / 밥 한스푼**이
다 섞여 엉뚱한 짤이 배치된다. → **한 단어 라벨 금지. 다축 구조 태그로 정의**하는 것이 이 설계의 심장.

## 2. 목표 (What)

1. 3타입 자산(**화면짤 clip / 효과음 sfx / 오버레이 overlay**)을 다축 태그로 저장하는 라이브러리.
2. 저장 진입점: **우리 작업영상(영상제작소) + 레퍼런스랭킹(외부) + 업로드**. 구간을 잘라 자산화.
3. 저장 순간 **Gemini가 다축 태그 초안 자동 생성** → 사장님 확인·수정(딸깍 저장).
4. 믹스할 때 **AI가 대본 비트에 맞는 자산을 자동 배치**(고신뢰) + 저신뢰는 제안만.
5. 화면짤은 **화면교체(replace) / 컷어웨이 삽입(cutaway) 하이브리드**(자산마다 지정).

## 3. 접근 (How) — "자산 = 확장된 화면 인벤토리", 2페이즈

기존 비트/EDL 모델에 **깊이 통합**한다(접근 1). 비트는 이미 "나레이션 + 화면구간"이므로,
자산을 비트에 부착하는 형태가 가장 자연스럽고 화면교체가 공짜에 가깝다. 한 번에 다 하기엔 크므로
**2페이즈**로 분할:

- **페이즈 1 (자산 뱅크 자체)**: 테이블 + 저장/자동태깅 + 관리 UI + 저장 다리. → 라이브러리가 쌓이기 시작.
- **페이즈 2 (AI 매칭·자동배치·렌더)**: 매칭 스텝 + video_assemble 4처리 + 믹스검수 배치패널. → 딸깍 완성.

이 문서는 두 페이즈 전체 설계를 담고, 구현 계획(writing-plans)에서 페이즈별로 쪼갠다.

## 4. 데이터 모델 — `scene_assets` 테이블

```
scene_assets
  id                 INTEGER PK
  customer_id        INTEGER   멀티테넌시 격리(기존 패턴, LEGACY_CUSTOMER_ID=0 하위호환)
  asset_type         TEXT      'clip' | 'sfx' | 'overlay'
  render_mode        TEXT      clip일 때 'replace' | 'cutaway' (sfx/overlay는 NULL)
  media_path         TEXT      영구보관 자산 파일(data/scene_assets/<id>.<ext>)
  poster_path        TEXT      썸네일(clip/overlay), sfx는 파형/아이콘
  duration           REAL      초
  keep_original_audio INTEGER  clip 원본소리 살릴지(0/1), 기본 cutaway=1 / replace=0
  ── 다축 정의(매칭 키) ──
  title              TEXT      사람이 알아볼 이름 "가루 한스푼"
  scene_desc         TEXT      화면 설명(Gemini 초안) "흰 가루를 숟가락으로 떠 그릇에 넣음"
  role               TEXT      통제어휘: 훅|반전|CTA|비법공개|반응|전환|본문
  category           TEXT      레시피|생활용품|가전|인테리어 … (기존 카테고리 재사용)
  subject            TEXT      소재·대상 "가루(밀가루·설탕류)"
  tone               TEXT      "비밀스러운·궁금"
  keywords           TEXT      매칭 보조 키워드(콤마 구분, 자동추출)
  ── 출처 ──
  source_kind        TEXT      'produce' | 'reference' | 'upload' | 'url'
  source_ref         TEXT      원본 shortcode/url/job_id/파일명
  created_at         TEXT
```

- **매칭은 role·category·subject·keywords·scene_desc 다축으로** 수행(§6) → "한스푼" 애매함 해결.
- 인덱스: `(customer_id, asset_type)`, `(customer_id, category)`.
- store 헬퍼: `add_scene_asset`, `list_scene_assets(customer_id, type?, category?, role?)`,
  `get_scene_asset`, `update_scene_asset`(태그 편집), `delete_scene_asset`.

## 5. 자산 저장 + 자동태깅 + 타입별 소스 수집 (페이즈 1)

### 5.1 저장 진입점(다리)

| 출처(source_kind) | 버튼 위치 | 클립 확보 방법 |
|------|-----------|-----------|
| produce (우리 작업영상) | 영상제작소 소스카드 / 믹스검수 비트 | 구간 [start,end] 지정 → 이미 받은 mp4를 ffmpeg 컷 |
| reference (랭킹 외부영상) | 레퍼런스랭킹 카드 | 영상 재생 중 구간 지정 → `media_download`로 받고 ffmpeg 컷 |
| upload (효과음·오버레이·직접파일) | scene_library 관리페이지 | 파일 업로드(mp3/mp4/gif/png) |
| url (선택, 페이즈2 확장) | 관리페이지 | URL → download → 컷 |

신규 모듈 `scene_assets.py`:
- `make_clip(src_path, start, end, out_path)` — ffmpeg 구간컷(720x1280 규격 통일 재사용).
- `extract_audio(clip_path, out_path)` — clip에서 오디오만(효과음 소스로).
- `make_poster(media_path, out_path)` — 첫 프레임 썸네일.
- `autotag(media_path, context)` — Gemini에 클립 화면(대표프레임)/캡션/원본대본을 주고
  `{scene_desc, role, subject, tone, keywords}` 초안 dict 반환. 키풀은 `edit_plan._vault_call`
  캐스케이드 패턴 재사용. 실패해도 빈 초안(사용자 수기 입력 가능) — 파이프라인 안 끊김.

### 5.2 자동태깅 UX

저장 클릭 → `make_clip`+`make_poster`+`autotag` → **저장 모달**에 초안 채워 표시 →
사장님이 확인·수정(title 필수 입력, 나머지는 초안 그대로 두거나 수정) → `add_scene_asset`.
category는 원본(랭킹카드/제작소 영상)에서 자동 상속(없으면 사용자 선택). = **딸깍 저장, 태깅은 자동초안**.

### 5.3 타입별 소스 수집 방식

- **화면짤(clip)**: 우리소스 + 레퍼런스랭킹 구간컷이 주력(우리만의 자산). replace/cutaway는 저장 시 지정.
- **효과음(sfx)**: 파일 업로드 + 화면짤 오디오 추출(`extract_audio`). (외부 무료음원 URL은 페이즈2 여지)
- **오버레이(overlay)**: 파일 업로드(화살표·gif·로고·png).

### 5.4 API (페이즈 1)

- `POST /api/scene/save` — body `{source_kind, source_ref, asset_type, render_mode?, start?, end?,
  category?, ...태그}` → 클립화+자동태깅 후보 반환(모달 프리필용) 또는 즉시 저장(확정 시).
  (2스텝: `save/prepare`로 클립+초안 → 모달 확인 → `save/commit`로 확정. 재추출 방지.)
- `POST /api/scene/upload` — 멀티파트 파일 업로드(sfx/overlay).
- `GET /api/scene/list?type=&category=&role=` — 격리된 자산 목록.
- `POST /api/scene/{id}/update` — 태그 편집. `POST /api/scene/{id}/delete`.
- `GET /api/scene/{id}/media` — 미리보기 스트리밍(Range).

## 6. 믹스 때 AI 매칭 & 자동배치 (페이즈 2)

`mix_pipeline._plan_and_tts`에서 EDL 생성 직후 **asset_match 스텝** 추가:

```
1. 현재 영상 맥락 = detect_subject(확정대본/소스대본) + category + 각 비트의 narration·role
2. 1차 후보 좁히기(DB): 같은 category + subject 호환 자산만 (저렴, subject 불일치=가루↔세제 여기서 탈락)
3. Gemini 판정: (비트 리스트 ↔ 후보 자산 리스트) → 각 자산을 어느 beat_idx에 붙일지 + score(0~1)
4. score ≥ MATCH_THRESHOLD(기본 0.7) → edit_plan의 beat["assets"](배열)에 부착
   score < 임계 → plan["asset_suggestions"]에 담아 "제안"으로만(자동배치 안 함)
```

- `edit_plan.match_scene_assets(plan, candidates, subject, category)` — 신규 순수함수(그라운딩 방식:
  Gemini는 asset_id·beat_idx만 지목, 실제 자산 데이터는 코드가 되붙임 — 환각 제거, `_ground_ref` 패턴).
- 부착 스키마: `beat["assets"] = [{asset_id, asset_type, render_mode, score, media_path, keep_original_audio}]`.
- 무키/후보없음/실패 시 자산 없이 정상 진행(회귀 없음).

**한계 대응**: subject 불일치는 §6-2 1차필터에서 이미 탈락 → 애초에 후보가 아님. 저신뢰 자동배치 금지로
"엉뚱한 짤 조용히 삽입" 사고 차단.

## 7. 렌더 통합 — `video_assemble` 확장 (페이즈 2)

기존 배선 최대 재사용:

| 타입/모드 | ffmpeg 처리 | 재사용 지점 |
|------|------------|-----------|
| clip/replace | 그 비트 소스구간 대신 자산 mp4를 화면으로(나레이션 길이에 맞춰 재생/루프) | `_render_mix`에서 소스경로만 자산으로 스왑 — 크롭/켄번즈/루프 로직 그대로 |
| clip/cutaway | concat 목록에 자산 클립을 비트 경계에 삽입(자체 길이, 원본소리 옵션) | concat 리스트 + **자막 t0 오프셋에 삽입길이 반영**(핵심) |
| sfx | 비트 시작 시점에 효과음 믹스(adelay 위치 + amix) | `_burn_captions` 오디오 브랜치(BGM amix) 확장 |
| overlay | 특정 구간(between t) PIP(작은 클립/이미지) | `_burn_captions` overlay 브랜치 확장 + enable 시간구간 |

### 7.1 타임싱크 (가장 조심할 곳)

cutaway 삽입은 전체 타임라인을 밀므로, `_burn_captions`의 비트 경계 t0 누적에 **삽입된 cutaway
길이를 더해야** 자막이 밀리지 않는다. 나레이션(TTS) 트랙에도 cutaway 구간만큼 **무음**을 끼워야
오디오·영상 길이가 맞는다. → cutaway 렌더는 반드시 실렌더 grounding + 자막싱크 TDD로 못박는다.

replace/sfx/overlay는 타임라인 길이를 안 바꾸므로 싱크 영향 없음.

## 8. UI 레이아웃 (페이즈 1 관리 + 페이즈 2 검수)

### 8.1 장면 라이브러리 (신규 `static/scene_library.html`)
- 상단 필터: 타입 / 카테고리 / 역할 + [파일 업로드].
- 자산 카드 그리드: 썸네일 + 타입 색배지(화면교체=초록·컷어웨이=주황·효과음=보라·오버레이=파랑)
  + title + "카테고리·역할·소재" 요약. 카드 클릭 → 다축 태그 편집 모달.
- 사이드바(`sidebar.js`)에 "🎬 장면 라이브러리" 항목 추가.

### 8.2 믹스 검수 배치 패널 (기존 믹스 검수화면에 추가)
- 비트별 행: [비트 role] narration + AI 부착 자산(배지+score) + [바꾸기][빼기].
- 자동배치 없는 비트: "＋ 라이브러리에서 추가"(수동 드래그·검색).
- 저신뢰 제안: "제안 N개 보기"로 접어서 표시 → 눌러야 삽입(엉뚱 짤 자동삽입 방지).

## 10. 범위 밖 (YAGNI)

- 벡터 임베딩/의미검색 — 카테고리+소재 1차필터 + Gemini 판정으로 충분(이 규모엔 과함).
- 외부 효과음 마켓 연동·자동 오버레이(gif) 생성 — 나중.
- 고객 간 자산 공유·마켓플레이스 — 멀티테넌시 격리 유지.
- 자산 버전이력·폴더구조 — 태그 필터로 충분.

## 11. 테스트 / 검증

- **단위**: scene_assets 태그 저장/조회·격리 / `make_clip`·`extract_audio` 산출물 존재 /
  `autotag` 스키마(무키 폴백) / `match_scene_assets` 1차필터(subject 불일치 탈락)·그라운딩(환각 asset_id 제거).
- **렌더 단위(중요)**: 4타입 각각 ffmpeg 산출 — 특히 **cutaway 자막 t0 싱크**(삽입 후 뒤 비트 자막이
  삽입길이만큼 밀렸는지) TDD.
- **통합(실렌더 grounding)**: 실제 자산 저장(레퍼런스랭킹 구간컷 1개) → 실제 믹스 → 최종 mp4에
  그 짤이 실제로 나오는지 + 자막 안 밀렸는지 눈검증. (격리 말고 실제 경로)
- **누수 확인**: 자동배치된 자산이 믹스검수 패널에 score와 함께 뜨는지 라이브 확인.
