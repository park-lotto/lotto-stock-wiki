실제 채널(t.me/s/stockinfo7) 20건을 가져와 돌려보니 진짜 버그 3개가 곧바로 나옴:
같은 속보 재게시(중복제거 없음), "삼전/하닉" 같은 언론 관용약칭 미매칭, 흔한 단어가

예상한 케이스만 담고 있어서 이런 실전 노이즈 패턴을 애초에 표현 못 함.

**How to apply:**
- 새 파서/필터/매칭 로직을 짤 때 유닛테스트(합성 fixture)는 로직 골격 검증용일 뿐,
  "완료"의 근거로 삼지 않는다.
- 배포 전에 반드시 실제 소스(크롤 결과, 실채널, 실API 응답)를 가져와서 실행 결과를
  하나하나 눈으로 검토한다 — 특히 "이게 왜 여기 매칭됐지?" 싶은 항목을 원본까지 추적.
- 이 과정에서 나온 실버그는 그 자리에서 즉시 고치고, 발견 근거가 된 실데이터를 테스트
  케이스로 남긴다(fixture를 실제 관찰된 텍스트로 교체).
- 배포 후에도 실행 로그를 재확인해서 새 실패모드가 없는지 한 번 더 본다
  ([[project_daily_verify_agent]]에서 이 패턴으로 "python 명령어 없음" 같은 배포환경
  전용 버그를 2차로 더 잡음).
