# 장면 실험실 (scene_lab)

제작소가 만든 편집안을 **로컬에서 뜯어보고 고쳐보는 실험 도구**. 라이브 서버·DB를 건드리지
않는다(읽기만). 여기서 확정된 것만 라이브 API로 옮긴다.

## 왜 만들었나 (2026-08-13)

"장면을 바꿔도 안 바뀐다"는 제보를 파다가 나온 것들:

- **한 칸(멘트) = 화면 한 장이 아니다.** 렌더는 `[primary] + alternates`를 `MAX_SHOT_SECONDS`
  (2.2초)씩 **번갈아** 재생한다(`video_assemble.py:_plan_beat_clips`). alternates가 8개인
  칸에서 primary만 바꾸면 **화면의 1/9만 바뀐다** — 그래서 "안 바뀐다"로 보였다.
- **후보를 다 지우면(한 장만) 더 나빠진다.** 실측: 총 컷 23→7, 평균 컷 1.34초→4.40초,
  2.5초 넘게 안 바뀌는 컷 0→5개. 늘어져서 프리즈처럼 보인다.
- **기준은 장수가 아니라 '담은 장면 길이의 합'이다.** 0.9초짜리 3장을 담아도 5.8초 멘트는
  못 채운다(실측: 4장/5.2초에서 늘어짐 0). 그래서 화면에 **부족한 초**를 표시한다.

즉 필요한 건 "1:1 교체"가 아니라 **칸마다 장면 목록을 사람이 편성하는 것**이고, 이 도구는
그 스펙을 눈으로 확정하려고 만들었다.

## 쓰는 법

```
py tools/scene_lab/fetch.py --list      # 최근 잡 목록
py tools/scene_lab/fetch.py             # 최신 잡을 통째로 받아 페이지까지 생성
py tools/scene_lab/fetch.py <job_id>    # 특정 잡
py tools/scene_lab/serve.py             # 가장 최근에 받은 잡을 브라우저로 연다
py tools/scene_lab/serve.py <job_id>    # 특정 잡
```

받은 데이터는 `tools/scene_lab/out/<job_id>/` 에 쌓인다(**gitignore** — mp4가 수십 MB).
집·회사 어디서든 `fetch.py`만 돌리면 같은 화면이 재현된다.

- SSH 키 기본값은 회사 PC 경로다. 다른 PC면 `SCENE_LAB_KEY` 환경변수로 지정.
- 포트를 바꾸려면 `SCENE_LAB_PORT`.

## 화면 보는 법

- **왼쪽** = 소스 장면 팔레트. `▶ 보기`로 그 구간만 재생.
- **오른쪽** = 칸(멘트)별 필름스트립. 아래 "실제 나올 화면"이 **렌더 알고리즘을 그대로 이식**한
  결과다(추정 아님). `▶ 이 칸 재생`은 실제 컷 순서대로 이어서 보여준다.
- 배지: `멘트 N초 · M초 부족` / `담음 N장 → 실제 M장 · K장 안 나옴` / `컷 N개 · 늘어짐 K`
- **주황 컷** = 2.5초 넘게 안 바뀌는 컷(늘어짐). **회색 "안 나옴"** = 담았지만 시간이 모자라
  이 칸에서는 안 쓰이는 장면 — `◀▶`로 앞자리로 옮기면 나온다.
- 위 모드 3개: ①지금 라이브(AI 후보 그대로) ②한 장만 ③내가 편성(칸마다 직접 담기).

## 한계

- 렌더 시뮬레이션은 라운드로빈 + shortfall 1순위까지만 이식했다. 소스 뒤끝까지 소진된 뒤의
  2b(되풀이)·3순위(홀드)는 근사다. 부족분이 클 때는 실제 렌더와 다를 수 있다.
- 읽기 전용이다. 여기서 편성한 결과가 라이브 잡에 저장되지는 않는다.
