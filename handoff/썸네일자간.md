# 썸네일자간 — 핸드오프

**소유 트랙**: 썸네일자간 — 이 파일은 이 트랙 세션만 수정한다. 다른 트랙은 읽기만.

## 2026-08-28 — 자간 설정 + 글자 레이어 잡고 늘리기 (완료·병합)

사장님: "썸네일 자간 설정 이런거는 어려울까요? 그리고 전체잡고 늘려서 글씨 크게 작게
하는 기능 좋을 거 같은뎅"

### 먼저 알아야 할 것
**썸네일은 서버 합성이 없다.** 브라우저 캔버스(`produce.html` `drawThumb`)가 최종 PNG를
그리고 `toBlob`으로 저장한다 → 고칠 자리가 한 곳뿐이라 미리보기와 결과가 어긋날 수 없다.

### ① 자간 (`L.tracking`)
- 편집칸에 [자간] 슬라이더(-10~40). 없으면 0 → **옛 저장본은 그림이 안 바뀐다**(회귀 0).
- **px가 아니라 글자 크기 대비 %로 담는다** — 미리보기(270)와 저장(1080)이 같은 그림이어야
  하는 썸네일 전체의 계약. px로 담으면 배율이 다른 두 캔버스에서 어긋난다.
- **재는 곳(`thumbFit`)과 그리는 곳에 같은 값을 건다.** 한쪽만 걸면 좁게 재고 넓게 그려
  글자가 캔버스를 넘친다. `ctx.letterSpacing`은 `measureText`에도 반영되므로
  자동 줄맞춤(grow-to-fill)이 저절로 따라온다.
- ★**가운데 정렬 보정**(실브라우저 실측): Chrome은 **마지막 글자 뒤에도** 자간을 붙여
  폭에 넣는다 — '가나다' 100px·자간 40px → 276 → 396 (**+3칸**, 2칸이 아니다).
  그래서 `textAlign='center'`면 글자가 자간 절반만큼 왼쪽으로 밀린다.
  실측: 자간 81.4px일 때 잉크 중심이 캔버스 중심에서 **41px 왼쪽**.
  → 그리는 x를 `+ls/2`, 박스·형광펜·밑줄 폭은 `−ls`. 보정 후 잉크 중심 540.5 (중심 540).
- 구형 브라우저(letterSpacing 미지원)는 `_trackPx`가 0을 돌려줘 **종전 그림 그대로**.

### ② 글자 레이어 손잡이
- 손잡이(✕삭제 + 모서리 3개 "끌면 크기·방향 동시")는 **2026-08-18부터 있었다.**
  `renderThumbHandles`의 kind 필터가 `sticker/shape/badge`만 받아 **글자만 빼놓고** 있었다
  → 글자는 [크기 미세조정] 슬라이더로만 조절 가능했다. 그 필터를 열었다.
- **글자는 스티커와 크기 단위가 다르다.** 스티커 size는 '반각×200'이라 끈 거리를 그대로
  쓰면 되지만, 글자 size는 슬라이더 값(30~200, 기준 90)이고 실제 px는 `thumbFit`이
  문구 길이까지 봐서 정한다 → **끈 거리의 비율**로 키운다(잡은 순간의 거리·크기가 기준).
  실측: 1.5배로 끌면 90 → 135. 회전은 슬라이더와 같은 -45~45로 묶었다.
- `_thumbHalf`도 글자용 분기 추가 — 글자는 정사각이 아니라 **여러 줄 블록**이라
  정사각 식으로 재면 점선 박스가 안 맞고 ✕가 허공에 뜬다. `thumbFit` 값을 그대로 빌려 쓴다.

### 검증
- `test_thumb_tracking.py` 신설(Node로 **실제 소스를 잘라** 실행. ctx 모형이 Chrome처럼
  letterSpacing을 measureText에 반영한다 — 반영 안 하면 자간 0% 동작에도 초록이 뜬다).
- **실브라우저 실측**(로컬 http + 진짜 캔버스 1080×1920): 자간 0/20/40 → 글자
  172.8/139/116.2px, **최대 폭은 993.6px로 항상 같다**(=1080의 92%, 안 넘친다).
  손잡이 4개·점선 박스가 2줄 블록에 일치. 드래그 1.5배 → size 90→135.

(앞선 제보: "오른쪽위는 확대축소 오른쪽아래는 기울기 근데 둘다 조정하는 감도가 안좋아")

  맞는지 헷갈린다. 크기·회전은 편집칸 [크기 미세조정]·[회전] 슬라이더가 맡는다.

### 곁다리로 확인한 것 — 스티커 직접입력 칸 (사장님 질문 "이모지 입력?")
라이브에서 직접 실행해 확인:
- 그 칸은 **목록에 없는 이모지를 직접 넣는 자리**(윈도우 ⊞+마침표).
- **글자를 넣으면 스티커가 아니라 글자 레이어로 얹힌다**(실측: "케이크" → `kind:text,
  y:0.14, size:92, BMDOHYEON.ttf` 레이어 생성). 실패가 아니다.
- 다만 **`maxlength=8`**이라 긴 문구는 잘리고, 새 레이어가 y=0.14(맨 위)에 생겨
  **기존 제목과 겹쳐** "반영이 안 된 것처럼" 보인다. → 손대지 않았다(사장님 판단 대기).
