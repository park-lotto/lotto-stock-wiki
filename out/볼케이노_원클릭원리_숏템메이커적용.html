뇌전구를 베끼는 게 아니다. 볼케이노가 왜 소재 하나로 끝까지 가는지를 뽑아, 숏템메이커가 이미 겪은 문제에 대응시킨다.

0. 볼케이노 원클릭의 실체 — 사용자가 하는 일은 딱 하나

사용자
소재(URL / 텍스트) + 채널명. 끝.
서버
next_step 한 걸음씩 지시 → 클라이언트(AI·실행기)가 그대로 실행 → 결과를 되돌림 → 다음 걸음
사람 자리
script(대본) · prompts(그림 지시) · memes(감정 선택) — 이 3곳뿐. 그것도 AI가 채운다
10단계 화면이 없다. 버튼이 없다. 화면 대신 "다음 한 걸음"이 있다.

1. 원리 11개 — 서버 응답에서 그대로 읽은 것

#원리서버 응답의 실제 모양
1서버가 다음 한 걸음만 지시한다next_step, do[](실행할 명령), measure[](재서 넣을 것), then_call_with[]. 클라이언트는 "임의로 해석하거나 개선하지 마라"
2상태는 한 곳, 명시적으로 넘긴다carry: [review_policy, review_client, env, source_kind] + next_payload를 그대로 되돌려야 함. "한 글자라도 다르면 반려"
3돈 나가기 전에 전부 확인setup이 파이썬·모듈·ffmpeg·키를 실측(점검 스크립트를 이 PC에서 돌려 JSON 회신). 키는 있는지만 본다. 채널별 필요 키표로 안 쓸 키는 안 묻는다
4규칙은 판정으로만 존재한다대본 반려 30건 → 2건 → 통과. 반려마다 원문 사유("제목에는 구두점을 쓰지 않습니다"). 프롬프트가 아니라 린터가 지킨다
5디자인 결정은 상수다sub.ass 스타일 블록이 3편 바이트 단위 동일. 사용자가 조정할 게 없다. 길이 따라 크기만 자동 축소
6사람 자리는 3곳, 나머지는 기계script·prompts·memes만 모델이 채움. 실행기 volcano_drive.py가 나머지 12단계를 서버와 직접 주고받음
7멈추면 재개 지점을 파일로 남긴다실행기가 사람 자리에서 멈추며 next_payload.json 저장. --step <멈춘단계> --payload next_payload.json으로 이어감
8검수도 AI가 실물을 읽고 답한다review_client: claude, review_replies. 렌더 결과 판정을 사람이 안 본다
9실패 문구가 원인·처방·위치를 다 말한다키 없음 → "어느 채널에만 필요 / 안 쓰면 발급 안 해도 됨 / 발급 URL / 저장 경로 / 저장 명령 / 왜 필요한지"
10자산은 팩이다sfx·pepe·fonts·runner·framevision 5종을 서명 URL로. 환경에 흩어진 파일에 의존하지 않는다
11피드백 통로가 내장step=feedback, {kind: request|bug, text} — "관리자가 매일 아침 읽는다"

4. 숏템메이커에 얹는 설계 — 최소 변경, 있는 것 재사용

4-1. 서버 상태기계 하나 — /api/produce/next

요청:  {job_id, step, payload}          ← 볼케이노 volcano_video와 같은 모양
응답:  {status: ok | need_input | execute | failed,
        next_step, need: [...],          ← 사람이 채울 것만
        next_payload: {...},             ← 그대로 되돌릴 것
        fail: {where, why, fix, retry_ok}}

지금 produce.html이 들고 있는 10단계 순서·조건 분기가 서버로 온다. 화면은 이 응답을 그리기만 한다. mix_jobs가 이미 job 저장소이고 status 12종을 next_step으로 쓰면 된다.

4-2. auto_run.py를 살린다 (이미 있음)

지금바꿀 것
default_judge = 무조건 passscript_gate 판정으로 교체 — "트랙5 자리"라고 코드에 적혀 있음
S1·S2·S3 세 단계10단계 어댑터로 확장. 어댑터는 엔진 호출만 (배선이 한 곳)
waiting_human 멈춤멈출 때 need(뭘 채우면 되는지)를 같이 저장 → 볼케이노 next_payload.json
화면 호출 0곳제작소 첫 화면에 "소재 + 프리셋 → 시작" 버튼 하나

4-3. 규칙표 한 곳 → 지시와 판정을 둘 다 생성

RULES = [
  {"id": "no_comma",
   "prompt": "자막에 쉼표를 쓰지 마라",
   "check":  lambda cut: "," not in cut.text,
   "reason": "이 채널 자막에 쓰지 않는 부호입니다 [',']"},
  ...
]
prompt_block = "\n".join(r["prompt"] for r in RULES)      # 프롬프트로
verdict      = [r for r in RULES if not r["check"](x)]      # 게이트로 → gate_feedback

"시켜놓고 벌주기"가 구조적으로 불가능해진다. bank_assemble.genre_block이 이미 이 방향이다.

4-4. 실패 응답 표준

모든 status="failed" 대입(11곳)이 {where, why, fix, retry_ok}를 채운다. "키 소진 또는 응답 오류"가 못 나온다.

4-5. 프리셋 = 완성묶음 상수

헤드카피+자막+효과+모션팩을 하나의 JSON 상수로. 화면 컨트롤 25개는 그 상수 위에 덧씌우는 옵션이 되고, 저장은 "상수 + 덧씌운 값"을 단계 넘김 때 한 번.

4-6. 사람 자리 3곳

1소재
S1 후보 5개 중 선택 — 러너가 candidates를 이미 남긴다
2대본
S2 초안 3개 중 선택·수정
3최종
렌더 결과 보고 승인

나머지(분석·EDL·TTS·자막·효과음·렌더)는 게이트가 통과시키면 사람이 안 본다.

5. 순서 — 문제 크기 순

순할 일푸는 사고고치는 곳
1실패 응답 표준 + 상태 단일화(서버 job 하나)저장 안 됨 · 부활 · 순서 누락 · 원인 뭉개기app.py settings/mix 저장 출구, mix_pipeline failed 11곳
2auto_run.default_judge → script_gate 연결판정 없는 규칙 전부auto_run.py 34줄
3규칙표 한 곳 → 지시+판정시켜놓고 벌주기 · 형용사 · 억지 섞기script_gate.py + bank_assemble.genre_block
4/api/produce/next 상태기계 + 화면을 렌더 전용으로층마다 배선 · 분석 미시작 · 10단계 수동app.py 신규 라우트, produce.html 축소
5프리셋 완성묶음 상수딸깍 철학produce.html 컨트롤 → 상수
6setup 단계(키·잔액·도구 실측)돈 나간 뒤 실패api_health 재사용
1~2번은 화면을 안 건드린다. 3번까지 하면 러너가 게이트를 통과할 때까지 혼자 돈다 — 그게 원클릭의 절반이다.

6. 볼케이노가 안 하는 것 — 우리가 더 잘할 수 있는 자리

• 볼케이노는 채널이 10개로 고정이고 스타일이 상수라 사용자가 못 바꾼다. 우리는 프리셋을 상수로 두되 덧씌우기를 남긴다(사장님 철학 "완성본에서 미세조정").

• 볼케이노는 실행기가 로컬 파이썬을 요구한다(venv·키 파일·팩 다운로드). 우리는 서버가 다 돌리니 사용자 PC에 아무것도 안 깐다.

• 볼케이노는 사람 자리가 AI(Claude)다. 우리는 사람 자리 3곳을 고객이 누른다 — 고객이 고른 기록(log_pick_event가 이미 있음)이 다음 자동화의 학습 데이터가 된다.
