# 14 장면↔대사 계획 매칭 루프 — `hybrid/material_fit.py` + 벤치 상위 편 재측정 (표준 §12-3·§12-5 · 04 뒤)

## 목표
렌더 **전에** 줄마다 후보 컷을 같은 루브릭(완성본 채점 `scene_fit.judge_rubric` 와 같은 함수)으로 채점해 고르고, 하한 미달이면 재료 보충 → 대사 고침 제안 → 다시 — 편 평균이 벤치 **상위 편 p75** 를 넘을 때까지. ep13 실측 7.12/0.375(벤치 7.55/0.257)를 뒤집는다. 벤치도 같은 자로 다시 재 `상위편_목표.json` 을 만든다.

## 실측 배경(10-25)
- 계획 단계: `runner_ops plan_sheet`·`render_bench.render(plan_only)` — 재료는 `재료.json cuts{줄: [{src, ss, crop, see}]}` 를 사람(또는 flow plan_* 눈)이 고른다. 점수 함수 없음.
- 채점 주인(04 가 만듦): `tools/calcopy/oneshot/scene_fit.py judge_rubric(items, wd, llm, cache)` — RUBRIC_V `rubric:v1(2026-10-25)`, 시트 10칸, 2회 중앙값, 차 ≥2 면 3회째; `measure`(완성본). `material_auto.fit_judge/eye_rescue`(FIT_MIN 7, EYE_FLOOR 4) 는 preset_make 길.
- 샷 표 `runner_ops.shot_table/fill_shot_max`(원본 샷·글자 상자) · 보충 재료 `hybrid/screen.py search/download` · 출처 규칙 `rules.source_rule_static`.
- 업그레이드 측정 `engine/upgrade_table.py`(05) — `top()` 조회 상위 50% 편 id.

## 만질 파일(독점)
`tools/calcopy/hybrid/material_fit.py`(새) · `tools/calcopy/oneshot/scene_fit.py`(`judge_rubric` 에 `bench_measure(slug, line_reads, src_dir)` 추가만 — 04 끝났음) · `tools/calcopy/hybrid/runner_ops.py`(do `material_fit` 추가만 — 08 끝난 뒤) · `tools/calcopy/hybrid/flow.py`(`ph_plan` 이 `material_fit` 을 부르고 ③(b) 대사 고침 `wait_user` — 08 끝난 뒤, 그 전엔 flow_dev 에서만) · `channel/<slug>/_kal/상위편_목표.json`(생성물, slug 마다) · `shopping_shorts/tests/test_material_fit.py`(새)
## 안 만질 파일
`render_bench.py`(재료.json 만 받는다) · `placement.py`(15) · `quality_gate.py`(사후 자 — 비교만) · 판 파일 `targets` 칸 값(07 이 상위편_목표.json 에서 적는다).

## 설계
1. `material_fit.candidates(line, shots, extra)` → 후보 [{src, ss, frames[3], flags(reuse·overlap·text_box·shot_edge)}] (샷마다 처음·중간·끝 + 보충 재료). 제약 위반 후보는 **점수 전에** 제외(이유 기록).
2. `material_fit.score(cands, line, llm)` = `scene_fit.judge_rubric` 그대로(캐시 = 프레임 sha). 역할 하한: 본문·공개·증거·반전 ≥7 / 훅·이음·다리·끝 ≥5(지침서 §3-4 handoff 10-19).
3. `material_fit.plan(doc, work, style, llm)` → 줄마다 최고점 후보 → `재료.json cuts`(기존 `see` 칸 유지 + `fit`·`fit_why`·`cand_n`) · 미달 줄 목록 → ③(a) `screen.py search "<제품> <동작 낱말>"` 보충(출처 규칙 통과만) → 재채점 → ③(b) 대사 고침 제안 `{line, old, new, why}`(Claude 소넷, 뜻·어미·글자 수 ±2 유지, 금지어 audit 통과) → 사인 → 재채점. 최대 3회. 결과 `<doc>/장면대사_계획.json {lines:[{id, role, fit, cand_n, fixed_by}], mean, below7, target, ok}`.
4. 목표: `style.targets.scene_fit{mean_goal, below7_goal}`(07 이 적음; 없으면 `상위편_목표.json` 을 직접 읽고 경고) — ok = mean ≥ goal ∧ below7 ≤ goal.
5. `scene_fit.bench_measure(slug)` : 벤치 상위 편(조회 상위 50%) 각 줄판독 줄 × 그 줄 시각의 원본 프레임 3장 → 같은 루브릭 → `_kal/상위편_목표.json {scene_fit:{per_ep, p75_mean, p25_below7}, ids, views}` (15 가 밀도·cps 칸을 더한다 — 파일은 14 가 만들고 15 는 **칸 추가만**).
6. 사후 대조: `quality_gate --full` scene_fit 평균과 계획 평균 차 ≤0.5 — 넘으면 자 불일치로 **gate 가 ×**(둘 다 같은 함수이므로 입력 프레임 차이만 남는다).

## 합격 검사(사보타주 먼저)
1. gold 픽스처(04 의 `scene_fit_gold.json` 10컷)에서 `candidates+score` 가 틀린 컷(≤3)을 **고르지 않는다**(혼동 0) — 고치기 전엔 사람 `see` 가 유일하므로 비교 대상 없음 → 픽스처 점수로만.
2. ep13: 계획 루프 뒤 `장면대사_계획.json mean ≥ 상위편 p75 ∧ below7 ≤ p25` ○ → 재렌더 → `quality_gate --full` scene_fit 이 계획 ±0.5 · `upgrade_table` scene_fit 축 `better:true`.
3. 사보타주: 하한을 9 로 올리면 ③ 이 3회 돌고 '멈춤(사유: 줄 N)' 으로 끝난다(무한 루프·조용한 통과 0) · 제약 위반 후보(재사용 구간)를 섞으면 점수 전에 제외된다.
4. 벤치 재측정: 잇템로그 6편 `상위편_목표.json` 생성, p75/p25 값 + 편별 표(줄판독 눈 fit 과의 상관계수도 보고 — 자가 눈과 많이 다르면 루브릭 재점검).
5. 대사 고침 제안이 `script_audit` 통과 + 뜻 유지(원문·수정 나란히 표, 페이블 눈 확인 3건).
