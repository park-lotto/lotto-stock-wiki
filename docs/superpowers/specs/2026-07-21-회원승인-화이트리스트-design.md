# 회원 승인제 (화이트리스트 / 대기실 방식) — 설계

- 날짜: 2026-07-21
- 트랙: 회원승인 (`.tracks/회원승인`, 브랜치 `track/회원승인`)
- 대상 서비스: shopping_shorts (숏템탑스, shoppingshorts.duckdns.org, systemd `shopping-shorts`)

## 배경 / 문제

현재 인증은 **오픈 셀프서비스**다. 구글 계정만 있으면 `get_or_create_by_google`(store.py:2368)이 로그인 순간 계정을 자동 생성하고 곧바로 7일 무료체험을 켠다. 아이디/비번 자체 회원가입(`/api/signup`)도 열려 있다. 즉 **전 세계 누구나** 로그인만 하면 무료체험을 켤 수 있다.

목표: **사장님(cid=0)이 승인한 사람만** 서비스를 쓸 수 있게 한다. 단, 지금 이미 쓰고 있는 사람은 막지 않는다.

## 핵심 결정 (브레인스토밍 확정)

- **대기실 방식**: 미승인자도 로그인은 되되 "승인 대기중" 상태로 모든 기능이 막힌다. 사장님이 admin에서 대기명단을 보고 승인한다. (완전차단/사전이메일등록 방식은 기각 — 사장님이 상대 이메일을 미리 알아야 해서 시니어 타깃 온보딩에 부적합)
- **기존 계정 자동 승인**: 마이그레이션 시 기존 모든 계정을 승인됨으로 처리해 라이브가 깨지지 않게 한다. 사장님은 admin에서 현재 사용자 명단만 보면 된다.
- **체험은 승인 시점에 시작**: 대기하는 동안 체험일이 소진되지 않도록, 승인하는 순간 `full_access_until = now + trial_days*86400`을 새로 세팅한다.

## 데이터 모델 변경

`customers` 테이블에 컬럼 1개 추가:

| 컬럼 | 타입 | 의미 |
|---|---|---|
| `approved_at` | INTEGER, NULL 허용 | `NULL` = 승인 대기중 / 값(epoch초) = 승인된 시각 |

**마이그레이션** (스키마 초기화 로직에 ALTER + 백필):
1. `ALTER TABLE customers ADD COLUMN approved_at INTEGER` (컬럼 없을 때만 — 멱등).
2. 기존 모든 행 백필: `UPDATE customers SET approved_at = <migration_ts> WHERE approved_at IS NULL`. 이 UPDATE는 **컬럼을 방금 추가한 최초 1회에만** 실행한다(신규 대기 계정을 나중에 덮어쓰지 않도록). 컬럼 존재 여부로 분기.
3. cid=0(사장님)은 코드상 항상 승인으로 취급(판정 함수에서 단락). DB 값과 무관.

> `migration_ts`는 결정성 위해 마이그레이션 실행 시각(파이썬 `int(datetime.now(...))`). 값 자체는 "과거의 승인됨"을 의미하기만 하면 되므로 정확한 값은 중요치 않다.

## 판정 로직 (단일 진실원 `access_level`)

현재 `access_level(customer_id)`는 `"full" | "ranking_only"` 반환. 여기에 **`"pending"`** 추가:

```
access_level(cid):
    if cid == 0: return "full"                 # 사장님
    cust = get_customer(cid)
    if not cust: return "ranking_only"
    if cust.approved_at is None: return "pending"   # ★ 신규: 승인 전엔 모든 판정보다 우선
    # 이하 기존 로직 (plan==pro → full / 체험중 → full / else ranking_only)
```

`"pending"`은 `"ranking_only"`보다 강한 차단이다: **모든 API·모든 화면을 막는다** (대기화면·로그아웃 제외).

## 미들웨어 게이트 (`_auth_guard`, app.py:3551~)

세션 검증 후 `access_level`이 `"pending"`이면:
- `/api/*` → `403` JSON `{"error": "승인 대기중", "level": "pending"}`
- 그 외 GET 화면 → 대기실 HTML(`_PENDING_HTML`) 응답
- 예외 허용 경로: `/logout`, `/static/*` (대기화면이 자기 자산 로드), 그리고 대기화면 자체.

기존 `ranking_only` 차단 로직은 그대로 두고, 그 **앞에** pending 분기를 추가한다.

## 신규 가입 경로 변경

`get_or_create_by_google`(store.py:2368)와 `/api/signup`(app.py:3451)에서 만들어지는 신규 계정:
- `approved_at`은 세팅하지 않는다 → NULL(대기중).
- `full_access_until`은 체험을 켜지 않는다 → `0`(만료 상태). 승인 시 세팅.

구현 방식: `create_customer`에 `approved=False`(기본) 파라미터를 추가. `approved=False`면 `full_access_until=0`, `approved_at=NULL`로 INSERT. 기존 호출부(테스트·사장님 시드 등)가 명시적으로 `approved=True`를 줄 수 있게 하되, 두 신규 가입 경로는 기본값(대기)을 쓴다.

## 승인 액션

신규 store 메서드 `approve_customer(cid, trial_days)`:
```
now = int(utcnow)
UPDATE customers
   SET approved_at = now,
       full_access_until = now + trial_days*86400
 WHERE id = ? AND approved_at IS NULL      -- 멱등: 이미 승인된 계정 재세팅 방지
```
이미 승인된 계정에 다시 호출해도 체험이 리셋되지 않는다.

신규 API `POST /api/admin/approve` (cid=0 전용, `_require_admin`):
- body: `{customer_id: int}`
- `trial_days`는 settings에서 읽어 넘긴다.
- 응답: 갱신된 고객 요약.

## Admin 화면 (static/admin.html)

- `GET /api/admin/customers` 응답에 `approved_at`(또는 파생 `pending: bool`) 필드 추가.
- admin.html 상단에 **"승인 대기중"** 섹션: pending 계정만 필터해 각 줄에 `[승인]` 버튼. 버튼 → `POST /api/admin/approve` → 목록 새로고침.
- 하단은 기존 **현재 사용자 명단**(승인일·등급·오늘 사용량) 유지.

## 대기실 화면 (`_PENDING_HTML`)

정적 HTML 상수. 문구:
> "가입 신청이 접수됐어요. 운영자 승인 후 이용할 수 있어요. 잠시만 기다려 주세요 🙏"

로그아웃 버튼 1개(`/logout`)만. 브랜드 톤(숏템탑스) 맞춤.

## 테스트 (TDD)

기존 `shopping_shorts/tests/test_paywall_{access,admin,gate,google,usage}.py` 패턴·conftest 픽스처 재사용 (⚠️ 루트 `tests/` 아님 — 페이블 검토 실측). 신규/보강:
1. 신규 구글 로그인 → `approved_at IS NULL`, `access_level == "pending"`, `/api/*` 403, 화면은 대기실.
2. 승인 후 → `access_level == "full"`, `full_access_until ≈ now+7일`, API 통과.
3. 승인 멱등성: 승인된 계정 재승인해도 `full_access_until` 안 바뀜.
4. 마이그레이션: 기존 계정(approved_at 없던 행)이 백필로 승인 처리됨 → 라이브 사용자 안 막힘.
5. `/api/signup`으로 만든 계정도 pending.
6. 사장님(cid=0)은 DB값과 무관하게 항상 full.
7. ★pending 계정으로 `/api/grab`(_AUTH_ALLOW 우회 경로, 자체 게이트) 호출 → 차단. (app.py:3867의 `== "ranking_only"` 비교가 pending을 통과시키는 구멍 — `!= "full"`로 수정. 페이블 검토 §1)
