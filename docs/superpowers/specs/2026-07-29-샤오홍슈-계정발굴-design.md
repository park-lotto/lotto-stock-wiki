# 샤오홍슈 계정 발굴(계정 리더보드) — 설계

- 날짜: 2026-07-29 / 트랙: 샤오홍슈레퍼런스
- 선행: `2026-07-29-샤오홍슈-레퍼런스채널-design.md`(계정 등록→랭킹, 라이브)

## 문제

레퍼런스 랭킹은 **내가 아는 계정 URL을 등록**해야 돈다. 사장님은 샤오홍슈에서
**어떤 계정이 어떤 카테고리에 잘하는지 모른다** → 등록할 계정을 애초에 못 고른다.

유튜브는 공식 API가 채널 단위 검색·통계를 줘서 "잘하는 채널"을 모아주지만,
샤오홍슈는 공식 API가 없다. 대신 이미 도는 **검색 발굴**(`xiaohongshu_search`,
Apify actor `zen-studio~rednote-search-scraper`)이 카테고리 키워드로 뜬 **노트**를 준다.

## 핵심 통찰

검색 발굴 = **포스트 단위**. 레퍼런스 = **계정 단위**. 그 사이 빈칸 =
**발굴 노트를 작성자별로 집계해 "잘하는 계정" 리더보드로 만들고, 좋은 계정을
레퍼런스에 자동 등록**하는 다리. 새 크롤러 불필요 — 검색 결과 재집계뿐.

**전제 확인**(실측): Apify 응답 노트 item에 `author.userid`·`author.nickname`,
`engagement.{liked,comments,collected,shared}_count`가 있다(테스트 픽스처
`test_xiaohongshu_search.py:85`, 2026-07-18 서버 실측 스키마). userid로
프로필 URL(`https://www.rednote.com/user/profile/{userid}`) 조립 가능 →
자동등록 성립. (xiaohongshu.com은 지역차단 → rednote.com, 선행 트랙 버그수정과 동일.)

## 결정(사장님 승인)

1. **자동 채움 + 리더보드 담기 결합**: 매일 카테고리별 상위 계정을 레퍼런스에
   자동 등록하고, 발굴 리더보드에서 직접 [담기]도 가능.
2. **삭제 = 영구 제외(블랙리스트)**: 사장님이 쳐낸 계정은 자동등록·리더보드에서 다시 안 뜬다.

## 점수 기준

- 한 방 대박(플루크) 배제 → **꾸준함 + 반응**을 본다.
- `계정점수 = Σ(노트 참여도)`, 참여도 = 좋아요+댓글+수집+공유.
- **최소 조건: 발굴 노트 ≥ 2개** — 우연히 뜬 1개짜리·쓰레기 1차 필터.
- 표시: 닉네임·노트수·평균 참여도·대표 노트 썸네일.
- 가중치/최소치는 실데이터 보고 튜닝(하드코딩 상수, 나중 조정).

## 아키텍처

```
xiaohongshu_search.search_full(키워드)   ← 이미 있음(+userid 추출 추가)
        │  노트[{userid, nickname, engagement, url, thumbnail}]
        ▼
xiaohongshu_discovery.discover_accounts()  ← 신규: userid별 집계·필터·정렬
        │  계정[{userid, nickname, note_count, engagement_sum, profile_url, sample}]
        ▼
service.discover_xiaohongshu_accounts() / auto_register_xiaohongshu()
        │        (블랙리스트 제외)          (상위 N → add_seed account)
        ▼
app.py  GET /api/xhs/discover · POST /api/xhs/adopt · POST /api/xhs/blacklist
        ▼
index.html  🔍 발굴 서브탭(리더보드 + 담기/삭제 + 출처 배지)
daily_batch.run()  → auto_register_xiaohongshu() 매일
```

## 컴포넌트

- **`xiaohongshu_search.py`(수정)**: 반환 dict에 `channel_id`(=author.userid) 추가.
  기존 `channel_title`(nickname) 유지. 두 search 경로 모두.
- **`xiaohongshu_discovery.py`(신규)**: 순수 함수. `discover_accounts(search_fn,
  categories, min_notes=2, blacklist=frozenset()) -> [account]`. 외부 IO 없음
  (search_fn 주입) → 단위 테스트 쉬움.
- **`store.py`(수정)**: 블랙리스트는 기존 `platform_seeds` 테이블 재사용
  (`kind="xhs_blacklist"`, `value=userid`). 헬퍼 `xhs_blacklist_add/list`.
  담기 = 기존 `add_seed("xiaohongshu","account",profile_url)`. 스키마 변경 없음.
- **`service.py`(수정)**: 오케스트레이션 — 블랙리스트 읽어 discovery 호출,
  `auto_register_xiaohongshu(top_n)`.
- **`app.py`(수정)**: 엔드포인트 3개(위). adopt는 블랙리스트면 거부.
- **`daily_batch.py`(수정)**: `run()`에 auto_register 한 줄.
- **`index.html`(수정)**: 발굴 서브탭.

## 격리 주의

해외HOT 발굴 잡(`overseas_hot_jobs.py`)은 **타 세션이 재설계 중** → 건드리지 않는다.
발굴은 하위 `xiaohongshu_search.search_full`을 직접 호출해 커플링 회피.
세션파일(`rednote_session.json`) 경합은 검색 경로(Apify)라 해당 없음.
