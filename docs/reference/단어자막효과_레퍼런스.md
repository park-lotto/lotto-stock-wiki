# 단어 따라가는 자막 효과 — 레퍼런스 모음

사장님이 보내주는 틱톡 영상의 자막 스타일을 뜯어 여기에 쌓는다(2026-10-03 시작, "내가 보내주는 것 다 스타일 파악해서 저장해봐").
쓰임: 장면꾸미기 본문 자막에 "단어 따라가기" 효과를 넣을 때 모양·종류를 정하는 근거.

## 재는 법

`yt-dlp`로 받아 `ffmpeg`로 프레임 시트를 만들어 눈으로 읽었다.

- 전체 흐름: 6fps × 5초(1~6초 구간) 시트. ①번만 전체 2fps + 4~6.5초 12fps.
- 모양: 자막 띠만 잘라 720px로 확대한 4프레임.
- **실측**: 줄당 단어 수, 대소문자, 강조 방식(박스/색), 지난 단어가 원래 색으로 돌아가는지, 세로 위치.
- **눈대중(추정)**: 색 이름, 글꼴 이름. 픽셀 색을 뽑거나 글꼴을 대조하지 않았다.
- 안 본 것: 구간 밖 프레임, 줄 바뀔 때 등장 애니메이션(튐·페이드) 유무.

## 다섯 편 공통 (실측)

- 자막은 **한 줄**, 가운데 정렬.
- **지금 말하는 단어 하나만** 강조되고, 지나간 단어는 흰색으로 돌아간다. 말한 단어가 색을 유지하는 누적형은 0편.
- 줄 전체가 처음부터 다 보인다. 단어가 하나씩 나타나는 방식은 0편.
- 글자에 검은 외곽선이나 그림자가 있어 배경과 무관하게 읽힌다.
- 강조 방식은 **박스 2편 · 색 바뀜 3편**, 이 두 가지뿐이다.

## 장면꾸미기에 넣을 때 시사점

- 1차는 **박스 · 색 바뀜** 두 가지면 다섯 편을 전부 덮는다. 가라오케 채움·하나씩 나타남은 이 표본에 없다.
- 고를 수 있어야 하는 값: 강조색, 박스 모서리, 대문자 여부(영문), 글자 크기, 세로 위치.
- 한국어는 어절 단위가 된다. 줄당 2~4어절이면 지금 자막 구절 길이와 비슷한 범위다.
- 설계 메모(2026-10-03 코드 확인): 단어 시각은 `mix_pipeline._beat_words_src`에 있으나 `_apply_cap_timing`에서 구절 길이로 줄어들고, `scene_style.context_for`는 구절의 시작·끝·문구만 렌더러에 넘긴다. 단어 시각을 `context_for`까지 잇는 것이 필요한 작업이다.

## 시제품 (2026-10-03, 이 PC 로컬 전용)

- 위치: `tools/scene_lab/out/단어자막_테스트/` — git 추적 밖(`tools/scene_lab/.gitignore`)이라 **이 PC에만 있다**. 여는 법: 그 폴더의 `open.bat`.
- 구성: `wordfx.js`(효과 — 박스·색 바뀜) · `index.html`(재생 화면) · `build_data.py`(실제 job 409f894230c6 의 음성·정렬로 데이터 생성) · `verify.js`+`compare.py`(렌더 방식 캡처와 화면의 픽셀 대조).
- 방식: 실제 편집기 페이지(`out/scene-style-ui-showcase.html`)를 그대로 띄우고 자막 요소(`#a-live-preview .precision-text[data-edit-bind="caption"]`)의 어절을 감싸 "지금 단어"에만 모양을 입힌다. 모양은 (단어 시각, t)만으로 정해진다.
- 실측: 템플릿 3종(원본·썰 스타일 01·고정 스타일 01) × 장면 6개, 단어 상태 22개에서 렌더 방식 캡처(headless 투명 PNG)와 테스트 화면의 다른 픽셀 0. 단어 시각 매칭 22장면 전부 precise.
- 안 한 것: 라이브 코드 수정 없음. 최종 mp4 합성(compose)·캡컷·썸네일 경로, 여러 줄 자막, 글자별 색과의 겹침, 등장 효과와의 조합, 영문 대본.
- 걸렸던 것: ①편집기 페이지에 같은 셀렉터의 미리보기가 여럿이라 `#a-live-preview` 로 좁혀야 그려진다. ②표본 job 의 `cap_durs` 가 옛 대본 것이라 `_apply_cap_timing` 으로 다시 재야 구절과 단어 시각이 맞는다.
