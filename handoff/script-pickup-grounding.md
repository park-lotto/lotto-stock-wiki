# 픽업 대본 소재 이탈 출구 통합 (2026-09-14)

## 제보와 라이브 실측
- 고객들이 2단계에서 생성한 첫 대본이 담은 영상과 전혀 다른 제품으로 나오는 문제가 재발했다.
- 오늘 작업에서 확인한 예: `보부상가방 → 기름때 행주`, `단추수선 → 주방 수납함`,
  `술게임 가젯 → 바닥 청소`, `애착문어인형 → 주방 집게`, `오리 소스볼 → 기름때 세정제`.
- 같은 작업의 스타일 대본은 정상이고 `style_id`가 없는 첫 안만 틀렸다. 고객 소유권과
  `source_shortcode`도 정상이라 고객 데이터 혼입이 아니었다.

## 뿌리
- `api_wiki_generate`의 스타일 경로는 `_materials_for_generate`로 담긴 영상 전체를 받고
  `script_gate`의 치명 소재 검사를 거쳤다.
- 기본 픽업 경로는 씨앗 한 편의 `full_text`만 `generate_variations`에 주고 치명 검사를
  호출하지 않았다. 09-07 은행 분량 제한만 추가됐고 출구 우회는 그대로 남아 있었다.

## 수정
- `script_gate.fatal_content_checks/fatal_content_fail`로 소재·판매처 출구 판정을 한 곳에 모았다.
  스타일 `check()`와 픽업 생성이 같은 함수를 쓴다.
- 픽업도 `_materials_for_generate`를 호출해 담긴 전사 전체를 생성기에 전달한다.
- `generate_guarded_variations`는 소재 이탈 결과를 저장하지 않고 최대 두 번 다시 생성한다.
  끝까지 틀리면 502와 차단 사유를 반환하며 잘못된 초안을 화면에 싣지 않는다.
- 픽업 응답에도 실제 사용한 재료 편수를 내려준다.

## 검증
- 신규 회귀 테스트 4건: 전체 재료 전달, 소재 이탈 뒤 재생성, 전 시도 이탈 시 빈 결과,
  API에서 이탈 초안 미저장.
- 소재/판매처 및 생성 경로 관련 테스트: 15 passed + 87 passed.

## 후속
- 배포 후 오늘 확인한 잘못된 픽업 초안을 해당 작업 state에서 제거한다.
- 라이브 서버 코드 버전과 작업 state를 다시 읽어 확인한다.
