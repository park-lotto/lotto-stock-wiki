# 카카오 오픈채팅 답변봇 — 설계

- 작성: 2026-08-25
- 트랙: `카톡답변봇` / 브랜치 `track/카톡답변봇`
- 사장님 결정: **B안(비공식 봇)** · 공기계 안드로이드폰 · **`!질문` 호출** · 봇 먼저 만들고 자료는 병렬

## 목적

오픈채팅방 2개에서 회원 질문에 자동으로 답한다.

| 방 | 링크 | 용도 |
|---|---|---|
| 문의방 | `open.kakao.com/o/grEukuIi` | 숏템메이커 사용법·정책 |
| 체험단방 | `open.kakao.com/o/go9V8dKi` | 챌린지 규칙·제출 + 사용법 |

## 전제 — 카카오는 이 용도의 공식 API가 없다

실측(2026-08-25 조사):

- 공식 **방장봇**은 고정 답변 **10개**, `/` 목록에서 **고르는** 방식. 자유 질문·AI 연결 **불가**
- 그래서 **비공식 경로**(안드로이드 알림 가로채기)뿐이다 — 카카오 약관 밖

**⚠️ 사장님께 고지하고 승인받은 위험**(2026-08-25):
- 카톡 업데이트로 알림 구조가 바뀌면 **깨진다**(실제로 자주 깨진다)
- 적발 시 **계정 정지** — 방장 계정이면 방을 잃는다
- 폰이 꺼지면 봇도 멈춘다

이 위험을 줄이려고 아래 설계는 **폰에 로직을 두지 않는다**.

## 구조 — 폰은 배달만, 판단은 서버

```
[카톡방]                [공기계 폰]                    [우리 서버]
 !질문 ...  ──알림──>  메신저봇R 스크립트  ──HTTPS──>  POST /api/kakao/ask
                            (30줄 이내)                      │
                                                    ① 승인된 Q&A에서 관련 3~5개 검색
                                                    ② 그것만 제미니에 먹인다
                                                       "자료 밖은 답하지 마라"
                                                    ③ 근거 미달이면 AI 호출 안 함
                                                       → "확인해서 알려드릴게요"
                                                       → 미답변 목록에 적재
                            답장 전송  <──────────────────┘
```

**왜 폰을 얇게 두나**(0순위-B):
1. 카톡이 바뀌어 알림 파싱이 깨져도 **답변 품질 코드는 무사**하다
2. 답변을 고치려고 폰을 만질 일이 없다 — 서버만 고친다
3. 나중에 웹·디스코드로 늘려도 서버는 그대로다

**폰 스크립트가 하는 일은 3개뿐**: `!`로 시작하나 본다 → 서버에 보낸다 → 받은 문자열을 답장한다.
판정·자르기·상한은 전부 서버가 한다.

## 지어내지 않게 하는 장치 (이 설계의 핵심)

자료가 아직 **0건**이다(실측: `help_item` 0행, `help.html` 본문 115자).
자료 없이 켜면 봇이 **지어낸다** — 고객에게 틀린 사용법을 자신 있게 알려주는 게 최악이다.

```
□ 승인된 Q&A만 검색 대상 — 초안(미검수)은 봇이 안 쓴다
□ 검색 점수가 기준 미달이면 **AI를 아예 안 부른다** → 즉시 "확인해서 알려드릴게요"
□ 프롬프트에 "주어진 자료 밖의 내용은 절대 답하지 마라" — 지키는지 테스트로 검사
□ 답변 끝에 근거 표시(📎 포인트 정책) — 틀리면 어디가 틀렸는지 바로 안다
□ 민감 질문(금액·환불·계정·개인정보)은 AI가 답하지 않는다 → 무조건 사장님 연결
```

마지막이 특히 중요하다 — **돈 얘기를 봇이 잘못 답하면 분쟁**이 된다.

### 미답변이 곧 할 일 목록이다

못 답한 질문을 쌓아 보여준다. 실제로 고객이 묻는 것만 채우게 되므로
**수백 개를 다 채울 필요가 없다** — 상위 50개가 질문의 대부분을 먹는다.

## 방마다 다르게 답한다

`room` 이름으로 갈린다. 같은 질문이라도 체험단방은 챌린지 자료를 먼저 본다.

| | 문의방 | 체험단방 |
|---|---|---|
| 우선 자료 | 사용법·정책 | 챌린지 + 사용법 |
| "내 현황" | — | `/challenge` 링크 안내만 |

**⚠️ 챌린지 현황을 봇이 직접 알려주지 않는다.** 카톡 닉네임과 챌린지 계정을 잇는
방법이 없다 — 잘못 이으면 **남의 현황을 보여주는 사고**가 난다. 링크만 준다.

## 안전장치

```
□ !질문 으로 호출된 때만 답한다 — 아무 말에나 답하면 시끄럽고 정지 위험도 커진다
□ 사람당 하루 상한(기본 20회) — 장난·도배 방지. 초과 시 조용히 무시
□ 짧은 지연 후 전송 — 즉답은 봇 티가 난다
□ 긴급 정지 스위치 — 서버 설정 한 줄로 즉시 멈춤(폰 안 만지고)
□ 답변 길이 상한 — 카톡에서 잘리면 안 보인다
```

**긴급 정지는 필수다.** 봇이 이상한 소리를 시작했을 때 폰을 찾아 끄러 갈 수 없다.
`kakao_bot_enabled` 설정을 매 요청 읽는다(재시작 없이 즉시 반영 — `contact_kakao` 선례).

## 데이터

### `bot_qa` — 고객용 지식 (승인된 것만 봇이 쓴다)
```
id / room(공통·문의·체험단) / question / answer / tags
status: draft(초안) | approved(승인) | rejected(버림)
source(어디서 뽑았나) / updated_at
```

### `bot_unanswered` — 못 답한 질문 = 다음에 채울 목록
```
id / room / question / asked_at / count(같은 질문 반복 횟수) / resolved_qa_id
```

같은 질문은 **묶어서 count를 올린다** — 뭐가 자주 나오는지 보여야 한다.

## API

| 경로 | 인증 | 하는 일 |
|---|---|---|
| `POST /api/kakao/ask` | **공유 비밀키** | 폰이 부른다. `{room, sender, text}` → `{reply}` |
| `GET /api/bot/qa` | 관리자 | 검수 목록 |
| `POST /api/bot/qa` | 관리자 | 승인·수정·버림 |
| `GET /api/bot/unanswered` | 관리자 | 미답변 목록 |

`/api/kakao/ask`는 로그인 쿠키가 없다(폰이 부른다) → `_AUTH_ALLOW`에 넣고
**공유 비밀키 헤더**로 막는다(유저스크립트 `/api/comment/done` 선례와 같은 방식).
키가 없거나 틀리면 401 — 열어두면 아무나 우리 제미니 한도를 태울 수 있다.

## 모델 — 제미니로 시작

실측: 제미니 키풀은 **이미 배선돼 있다**(로테이션·소진 처리 완비, 무료).
Anthropic 키는 이 코드베이스에 **없다**.

오픈채팅방은 누가 몇 번 물을지 통제가 안 된다 — 유료 API를 열어두면 한 명이
장난으로 100번 물어도 그대로 과금된다. **무료 한도 안에서 시작**한다.

★모델 호출을 **함수 하나로 감싼다** → 나중에 클로드로 바꿀 때 그 함수만 갈아끼운다.

## 구현 순서

```
1. 서버 (bot_qa·검색·제미니·미답변)  ← 폰 없이 테스트 가능. 이것만으로 웹에서 써볼 수 있다
2. 검수 화면 (승인/수정/버림)
3. 폰 스크립트                        ← 앞이 다 도는 걸 확인하고 붙인다
4. 자료 초안 뽑기 (핸드오프 92만 자 → Q&A)
```

**1번만 끝나도 가치가 있다** — 폰이 깨져도, 나중에 B안을 접어도 서버는 그대로 쓴다.

## 자료의 출처 (4단계)

사장님이 **쓰시는 게 아니라 검수만** 하신다. 재료는 이미 쌓여 있다(실측):

| 재료 | 분량 | 주의 |
|---|---|---|
| 핸드오프 150개 | **92만 자** | ⚠️개발 기록 — "사장님"이 916번. 그대로 쓰면 안 된다 |
| 화면 안내문(produce.html) | title 44개 | 이미 **고객 언어**로 쓰여 있다 |
| 위키 | 471개 | 주식·섹터(2차 확장용) |

AI가 **고객 언어로 다시 쓴 초안**을 만들고, 사장님은 ✅승인 / ✏️수정 / 🗑️버림만 누른다.

## 테스트

```
□ 자료 밖 질문에 "확인해서 알려드릴게요"가 나온다(지어내지 않는다)
□ 미승인 초안은 답변 근거로 안 쓰인다
□ 민감어(환불·결제·계좌)는 AI를 안 거치고 사람 연결로 간다
□ 하루 상한 초과 시 조용히 무시
□ 긴급 정지가 켜지면 어떤 질문에도 답하지 않는다
□ !로 시작하지 않으면 아무 반응 없다
□ 비밀키 없이 /api/kakao/ask 호출 시 401
□ 답변이 카톡 길이 상한을 넘지 않는다
```

## 안 하는 것 (YAGNI)

- 챌린지 현황 개인 조회 — 신원 연결 불가(위 참조)
- 봇이 먼저 말 걸기 — 정지 위험만 키운다
- 이미지·음성 — 텍스트만
- 여러 방 자동 확장 — 방 2개로 시작
- 대화 문맥 기억 — 질문 1개당 답 1개(문맥을 쌓으면 비용·오답이 같이 는다)

## 열린 질문

- 자료 초안을 **30개만 먼저** 뽑아 방향을 볼지, 한 번에 많이 뽑을지 (4단계에서 결정)
- 봇 이름·말투 (검수 화면 만들 때 사장님이 정하시면 됨)
