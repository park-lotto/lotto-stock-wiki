# 위키 3워커 엔진 — 단순화 재설계 (Wiki 3-Worker Engine)

> 작성: 2026-06-23 | 상태: 브레인스토밍 완료, 사용자 검토 대기
> 이전 설계: `2026-06-22-위키-종합엔진-design.md` (수율 14%·claude -p 페이지파괴로 폐기)
> 본 설계: 위 실패에서 출발해 **수동 수신 + 능동 리서치 + 종합** 3축으로 재설계

## 0. 한 줄 정의

위키 종목·섹터 페이지를 **스키마로 명시**하고, **수동 수신 워커·능동 리서치 워커·종합 워커**가 24시간 협업해 빈 칸을 채우는 엔진. 종목 페이지는 "다관점 풍부"(블로그 한 페이지 분량), 섹터 페이지는 "횡단 의사결정"("조선 어디가 좋아?"에 답함)을 목표로 한다.

---

## 1. 왜 재설계인가 (이전 실패의 교훈)

이전 엔진(`2026-06-22-위키-종합엔진-design.md`)의 5가지 실패:
1. **claude -p 페이지 파괴** — 에이전트 stdout에 잡담·요약문 섞여 골드 페이지 덮어씀
2. **수율 14%** — 141 원자 중 5종목만 풍부 갱신
3. **날짜 윈도우 함정** — `--days 14`가 내용 날짜로 잘라 백로그 95개(67%) 제외
4. **섹터 페이지 통째 재작성** — 1007줄 한 번에 다시 쓰다가 죽음
5. **그릇 자체의 빈약** — "다관점" 받을 자리가 없어서 generic 60% 원자 다 버려짐

### 사용자 핵심 통찰 (2026-06-22~23 브레인스토밍)

> *"여기서 디벨롭을 더 잘해놓고 내용들을 제미니가 분류해야하는지 최대한 종목과 섹터에 대한 뷰를 다관점 풍부하게 설명할수있는 그릇으로 만들어"*

> *"수동으로 들어오는 매일 정보를 채우는것도 해야하는데 리서치 자동화기능을 통해서 능동적으로 채우는 방향도 병행되야 비어있는 부분은 쉬지않고 에이전트가 일을시키는구조가 좋을것같다"*

> *"뭐가 빈칸인지를 정의해야지. 정말 빠짐없는 섹터나 종목 페이지 구조를 만들기위해서 구조를 짜고 어떤게 빠진건지를 명확하게 빈칸정의를 해주고 자동으로 루프를 돌려서 호출할수있도록 설계"*

→ **그릇이 빈약하면 엔진이 무엇을 할지 모른다. 그릇을 스키마로 명시하면 빈 칸이 곧 일거리.**

## 2. 성공 기준 — 두 질문 유형 모두 답해야

### A형: 깊이형 ("닉스 어때?")
- 종목 페이지 다관점 그릇으로 답
- 강세론·신중론·충돌·썰 다 풍부
- **합격**: 한 종목 페이지 분량 = 블로그 분석글 한 편 풀어쓸 자료

### B형: 횡단형 ("조선주 투자할만해? 어느 종목?")
- 섹터 페이지 횡단 그릇으로 답
- 사이클 위치·진행 이벤트·종목 비교·탑픽
- **합격**: "조선 투자할만해?" 4개 하위질문(국면·이벤트·아웃퍼폼·탑픽) 모두 답

### 데모로 검증된 그릇
- `out/wiki_v2_demo_SK하이닉스_다관점.md` — 종목 다관점 (4학파+3충돌+5썰)
- `out/로또의_SK하이닉스_관점.md` — 다관점 그릇이 블로그 분석글로 풀어쓰기 검증
- (조선 섹터 횡단 그릇 = 본 spec §5로 정의)

### 4.2 일일 진단 (`scripts/wiki_diagnose.py`)

매일 새벽 1회 — 모든 페이지를 스키마와 대조해 일감 산출.

```python
def daily_diagnostic() -> list[Task]:
    빈칸 = []
    for page in all_pages:
        for cell in page.schema.cells:
            if not cell.has_value():
                빈칸.append({"page": page, "cell": cell, "priority": "missing"})
            elif cell.is_stale(threshold=cell.stale_days):
                빈칸.append({"page": page, "cell": cell, "priority": "stale"})
            elif cell.needs_reverify(threshold=cell.reverify_days):
                빈칸.append({"page": page, "cell": cell, "priority": "reverify"})
    
    # 우선순위: missing > stale > reverify
    # 우선순위 내: 메인 종목 > 모니터링 > 섹터
    return sort_by_priority(빈칸)
```

**산출**: `wiki/_diagnostic/YYYY-MM-DD_빈칸리스트.md`

### 4.3 수신 워커 (`pipeline/atoms/worker_passive.py`)

매일 7AM — 외부 봇이 raw 폴더에 넣은 파일 처리.

```
raw 폴더 새 파일 → Gemini로 분류·라벨링 (asset_level, sector, certainty, source_pub)
    → 종목 매핑되면 stock 페이지 다관점·이벤트에 append
    → 섹터/시장이면 sector 페이지 시장국면 섹션에 append
    → 매핑 안 되면 _pending/unmapped/로 적재
```

**핵심**: 한 번에 페이지 전체를 재작성하지 않음. **append만**. 종합은 별도 워커.

### 4.4 능동 리서치 워커 (`pipeline/atoms/worker_active.py`)

매시간 (또는 4시간마다) — 진단 산출물의 빈 칸을 위에서부터 처리.

```python
def hourly_research():
    queue = load_diagnostic_queue()
    
    while queue and not budget_exceeded():
        cell = queue.pop()
        
        # 1차 리서치 (WebSearch or Gemini)
        result = research_cell(cell)
        
        # 3단 검증 (사용자 핵심 강조점)
        v1 = verify_format(cell, result)        # 형식 (싸다)
        if not v1.ok: cell.mark_failed(v1); continue
        
        v2 = verify_content_gemini(cell, result) # 내용 (Gemini)
        if not v2.ok: cell.mark_failed(v2); continue
        
        v3 = scan_alternative(cell, result)      # "더 좋은 게 없나"
        if v3.better.confidence > result.confidence:
            result = v3.better
        
        # append (claude -p X, Write 직접)
        patch_page(cell.page, cell, result, 
                   source=result.source, grade="능동리서치", 
                   verified_at=now())
```

**검증 실패**: `wiki/_pending/검증실패/`로 적재. 사람이 봐야 함.
**대안 발견**: 상위 출처로 자동 교체.

### 4.5 종합 워커 (`pipeline/atoms/worker_synth.py`)

매일 + 사용자 트리거 — 핫 종목/섹터에 쌓인 원자들을 Sonnet 서브에이전트가 종합.

```python
def daily_synth():
    핫_종목 = identify_hot(이번주_원자 ≥ 5)  # 5~7개
    
    for stock in 핫_종목:
        # 서브에이전트 호출 (Agent 툴, claude -p X)
        agent_prompt = f"""
        SK하이닉스 페이지를 갱신하라.
        - 입력: {page_md} + 신규 원자 {atoms}
        - 작업: 다관점 학파 갱신·충돌·썰 추적
        - 출력: Write로 페이지 직접 (Write 툴 사용, stdout X)
        - 절대 금지: 페이지 통째 재작성, 다른 섹션 임의수정, 잡담 stdout
        """
        run_subagent(agent_prompt, target_file=stock.page)
    
    # 섹터는 매일 무조건 (워치 종목도 받기 위함)
    for sector in all_sectors:
        run_sector_synth(sector)
```

**핵심 변경**: 이전 `claude -p` 단일 호출 → **서브에이전트 + Write 툴 직접**. 페이지 파괴 사건 재발 방지.

## 9. 합격 정의 (Definition of Done)

1. ✅ A형 질문 ("닉스 어때?") = 종목 페이지 다관점으로 풍부하게 답
2. ✅ B형 질문 ("조선 어디 좋아?") = 섹터 페이지 횡단 비교표·탑픽으로 답
3. ✅ 매일 자동 진단 → 빈 칸 리스트 산출
4. ✅ 빈 칸이 24시간 내 자동으로 채워짐 (3단 검증 통과한 것만)
5. ✅ 핫 종목 5~7개/주 자동 다관점 갱신 (페이지 파괴 0건)
6. ✅ 매주 핫 섹터 2~3개 딥리서치 갱신
7. ✅ 시간축 보존 (덮어쓰기 0건, 분기 스냅샷 자동)
8. ✅ 검증 실패는 `_pending/`에 적재 (사람이 봄)

## 10. 범위 밖 (명시)

- **빈집·주도 계산** = 태린이 오실레이터 별도 시스템. 위키는 결과값만 연동
- **종목→섹터 매핑** = 사용자 Excel 별도. 1단계는 폴더 멤버십
- **영상 기획·대본** = 위키가 자료만 제공. 영상 제작은 별도 파이프라인 (yt-trend 등)
- **법규·세무** = 다루지 않음
