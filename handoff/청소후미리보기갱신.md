# 자막제거 완료 → 꾸미기 미리보기 자동 갱신

## 2026-09-06 (회사PC)

사장님 질문: "자막제거 동안 장면꾸미기를 하면 어떻게 되나 / 가능한지" →
"그럼 안지워진걸로 꾸미기가 들어가는데 다 되면 새로고침하나"

### 답 (실측)
**동시 작업은 가능하다** — 화면도 "다른 단계 먼저 진행해도 돼요"라고 안내한다.
저장 칸이 완전히 갈려 있다:
  자막제거 → clean_status·clean_error·clean_video_path·clean_regions
  꾸미기   → deco_json·caption_style_json·headcopy_json
실데이터: 09-01 이후 자막제거 켠 376잡 중 345잡(91%)이 꾸미기 값도 함께 갖고 있다.

**단, 미리보기는 새로고침해야 바뀌고 있었다** — 이번에 고친 것.

### 뿌리
서버는 이미 준비돼 있다. `_clean_frame_src`가 청소 후 `ctag='_clean'`을 주므로
poster를 **다시 요청만 하면** 청소본이 온다. 실측(job feeb174bf50a):
```
poster_s3@0.03.jpg        자막 "다이소가면"·"@템캣"·"[광고]" 있음
poster_s3@0.03_clean.jpg  전부 지워짐        ← 두 판본이 나란히 존재
```
그런데 그 요청을 다시 보내는 `toggleSceneBg()`는 **initHeadcopy(5단계 진입)에서만**
불렸다. `pollClean`의 ready 분기는 `renderCleanReady`(3단계)만 다시 그린다.
→ 5단계에 머문 채 청소가 끝나면 자막 남은 옛 배경이 그대로.

### ★왜 중요한가 — 돈이 샌다
고객은 그걸 "자막제거가 안 됐다"로 읽고 **다시 누른다**. 자막 지우기는 유료다.
실측: cid 268(정종수) job feeb174bf50a의 clean 작업이 **13번** 실행됐다
(06:05~06:29 거의 매분, 큐 qid 11485·11491·11492·11493·11495·11497·11500·
11502·11503·11504·11505·11516 — 전부 done).

### 고친 것 (커밋 e81873584)
`produce.html` pollClean의 `clean_status==='ready'` 분기에서
`toggleSceneBg(true)` + `ensureCleanRegions()` 호출.
- ⚠️ready에서만 — cleaning·failed에 넣으면 자막 남은 그림을 헛되이 받아 깜빡인다.
- 사람이 자막을 직접 옮겼으면 안 덮는다(applyErasedRegion이 CAP_POS_TOUCHED를 본다).
- 회귀 테스트 5건 `tests/test_clean_done_refresh_preview.py` — 실제 pollClean을 떼어
  node로 돌리고 **무엇을 불렀나**로 판정(문자열 세기 아님).

### ⚠️밟은 함정 — produce.html은 주석까지 벤더명 금지
주석에 업체명을 썼다가 게이트 3건이 빨개졌다
(test_clean_cost_notice_js / test_subclean_credits_link / test_subclean_ui).
"유료다"로 바꿔 해결. 기존 메모리에 있던 함정을 그대로 밟았다.
