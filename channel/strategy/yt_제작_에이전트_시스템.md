# 유튜브 영상제작 에이전트 시스템 설계서

> 사용자가 하는 일: 아이디어 한 줄 + 녹음(m4a)
> 나머지 전부 에이전트 처리

---

## 전체 흐름

```
[사용자] 주제 입력
    ↓
[기획 직원] → [기획 검수] → 컨펌 or 재작업
    ↓
[대본 직원] → [대본 검수] → 컨펌 or 재작업
    ↓
[Remotion 직원] → [영상 검수] → 컨펌 or 재작업
    ↓
[사용자] 녹음 (유일한 개입)
    ↓
[싱크 직원] → [싱크 검수] → 컨펌 or 재작업
    ↓
[렌더/배포 직원] → [배포 검수] → 완료
```

각 단계: **직원이 작업** → **검수직원이 체크** → **기준 미달 시 자동 재작업**

---

## 1. 기획 직원

### 역할
채널 방향 + 트렌드 데이터 기반으로 영상 기획서 생성

### 입력
- 사용자 아이디어 (1줄)
- `channel/yt/yt_전략_채널방향.md` (채널 방향)
- `channel/yt/레퍼런스_분석.md` (성공 영상 패턴)
- `wiki/log.md` (최근 리서치 내용)

### 출력 — `yt_{주제}_기획서.md`
```
제목 후보 3개 (숫자+충격조건+시간 조합)
썸네일 텍스트 (메인 1줄 + 서브 1줄)
핵심 메시지 1줄
타겟 시청자 (누구를 위한 영상인가)
훅 문장 (첫 10초 — 시청자가 멈추게 하는 문장)
씬 구성표 (8~12씬 / 각 씬 목적 + 예상시간 + 화면 방향)
다음 편 연결고리 (시리즈 구조)
CTA 방식
```

## 1-검수. 기획 검수 직원

### 역할
기획서를 독립적으로 읽고 9가지 기준으로 채점

### 체크리스트 (9항목 / 7점 이상 통과)
```
✅ 제목에 숫자 + 충격 조건이 있는가?
✅ 첫 10초 훅이 "나도 그래"를 유발하는가?
✅ 씬 흐름이 공감→문제→해결→증명→CTA 순서인가?
✅ 핵심 메시지가 1줄로 압축되는가?
✅ 채널 방향(수급빈집/대장주/단기스윙)과 일치하는가?
✅ 영상 길이가 7~10분 범위인가?
✅ 시청자가 댓글/공유할 이유가 있는가?
✅ 다음 편으로 이어지는 궁금증이 심어지는가?
✅ 경쟁 영상 대비 차별점이 명확한가?
```

### 판정
- **7점 이상**: PASS → 다음 단계
- **5~6점**: 특정 항목 지적 후 기획직원에게 수정 지시
- **4점 이하**: 전면 재작업 요청

---

## 2. 대본 직원

### 역할
기획서의 씬 구성대로 실제 말할 수 있는 대사 작성

### 입력
- 기획서 (검수 통과본)
- `channel/yt/yt_전략_채널방향.md` (말투/톤 가이드)
- `channel/strategy/strategy_remotion_가이드.md` (화면과 대사 연결 방식)

### 출력 — `yt_{주제}_대본.md`
```
씬별:
  - 씬 번호 + 목적
  - 대사 (구어체 — 실제 말하듯)
  - 화면 설명 (Remotion 직원이 읽을 수 있도록 구체적)
  - 예상 녹음 시간
  - 강조 키워드 (자막에서 민트색으로 표시할 것)

전체:
  - 총 대본 시간 (씬별 합산)
  - 호흡 포인트 표시 (// 여기서 2초 쉬기)
```

### 대사 작성 원칙
```
❌ "안녕하세요 여러분 오늘은..."  (인사 금지)
❌ 수동적 표현 ("~할 수 있을 것 같습니다")
✅ 첫 문장에 숫자 or 충격 or 질문
✅ 한 문장 = 한 아이디어
✅ "저는" "제가" 주어 명확히
✅ 전문용어 쓰면 바로 다음 줄에 쉬운 말로 재설명
```

---

## 2-검수. 대본 검수 직원

### 역할
기획서 목적과 대본 대사가 일치하는지 독립 검토

### 체크리스트 (10항목 / 8점 이상 통과)
```
✅ 첫 문장이 기획서 훅과 일치하는가?
✅ 구어체로 자연스럽게 읽히는가? (소리 내어 읽기 기준)
✅ 각 씬 대사가 씬 목적을 달성하는가?
✅ 논리 흐름이 끊기지 않는가? (씬 간 연결 자연스러운가)
✅ 전문용어 사용 시 바로 설명이 붙는가?
✅ 총 시간이 목표(7~10분)와 일치하는가?
✅ 반복되는 단어/표현이 3회 이상 없는가?
✅ 화면 설명이 Remotion 제작 가능한 수준으로 구체적인가?
✅ CTA가 "댓글에 X 남겨주세요" 형태로 명확한가?
✅ 마지막 씬이 다음 편 궁금증으로 끝나는가?
```

### 추가 검증
- 기획서 핵심 메시지 → 대본 어디서 명시적으로 나오는가? 없으면 지적
- 씬별 예상 시간 합산 vs 목표 시간 오차 ±30초 이내인가?

## 3. Remotion 제작 직원

### 역할
대본의 화면 설명대로 BRAIN SIGNAL 스타일 TSX 컴포넌트 작성

### 입력
- 대본 (검수 통과본) — 씬별 화면 설명
- `channel/strategy/style_BRAIN_SIGNAL.md` (스타일 레퍼런스)
- 기존 컴포넌트 참고 (`src/agents/` 폴더)

### 출력
```
src/agents/XX_S01_Hook.tsx
src/agents/XX_S02_Empathy.tsx
...각 씬별 tsx 파일

Root.tsx 등록 (durationInFrames = 예상녹음시간 × 30 + 30)
```

### 작업 원칙
```
1씬 = 1개 Phase 금지 (최소 2~3개 Phase 전환 필수)
정적 화면 5초 이상 금지 (무조건 애니메이션)
색상은 C.main / C.bg 등 constants 사용
폰트는 FONT 상수 사용
자막바 필수 (모든 씬)
이모지 40% + 텍스트 60% 혼합
```

---

## 3-검수. 영상 검수 직원

### 역할
코드와 비주얼 양쪽을 검토 — 기술 오류 + 연출 오류

### 체크리스트 A: 기술 검수 (자동화 가능)
```
✅ tsc --noEmit 에러 0개인가?
✅ 모든 staticFile() 경로가 실제 파일로 존재하는가?
✅ Root.tsx에 모든 씬 등록됐는가?
✅ durationInFrames가 대본 시간과 ±60프레임 이내인가?
✅ import가 모두 존재하는 파일을 참조하는가?
✅ 사용하지 않는 변수가 없는가? (TS warning)
```

### 체크리스트 B: 연출 검수 (AI 판단)
```
✅ 각 씬에 Phase 전환이 최소 2개 있는가?
✅ 씬 내 5초 이상 정적 구간이 없는가?
✅ 화면 텍스트 오타 없는가?
✅ 자막바가 모든 씬에 있는가?
✅ 씬 첫/마지막 fade-in/out이 있는가?
✅ 숫자/핵심 단어에 민트 글로우 강조가 있는가?
✅ 클라이맥스 씬에 elastic scale + dynGlow가 있는가?
✅ 전반적으로 BRAIN SIGNAL 스타일과 일치하는가?
```

### 판정
- A 기준 하나라도 실패 → 자동 수정 후 재검
- B 기준 6점 이상 → PASS
- B 기준 5점 이하 → 취약 씬 지적 + Remotion 직원에게 수정 지시

## 5. Whisper 싱크 직원

### 역할
녹음 파일 → 단어별 타임스탬프 → TSX SUBS 배열 자동 업데이트

### 입력
- 녹음 파일 (m4a)
- 해당 씬의 대본 텍스트 (검증 기준)
- 해당 씬 TSX 파일

### 처리 과정
```
1. Whisper API로 단어별 timestamp 추출
2. 대본 문장 단위로 시작/끝 프레임 계산 (×30fps)
3. TSX의 SUBS 배열 자동 업데이트
4. durationInFrames = 녹음길이초 × 30 + 30 자동 조정
5. Root.tsx의 해당 씬 durationInFrames 업데이트
```

### 출력
- TSX SUBS 배열 업데이트 (프레임 정확)
- Root.tsx durationInFrames 수정
- `싱크_리포트_{씬}.md` (각 자막 타임스탬프 검증용)

## 5-검수. 싱크 검수 직원

### 역할
자막 타이밍이 실제 발화와 일치하는지 검증

### 체크리스트 (6항목 전원 통과 필수)
```
✅ 자막 시작이 발화 시작 ±5프레임 이내인가?
✅ 자막 끝이 발화 끝 이전에 사라지지 않는가?
✅ 침묵 구간(간격 15프레임 이상)에 자막이 없는가?
✅ 씬 총 durationInFrames = 실제 녹음 길이 × 30 + 30인가?
✅ 각 씬 끝에서 음성이 잘리지 않는가?
✅ 연속 씬 간 오디오 겹침/공백이 없는가?
```

### 판정
- 전원 통과: PASS
- 하나라도 실패: 해당 씬 Whisper 재처리

---

## 6. 렌더링/배포 직원

### 역할
최종 영상 렌더링 + 플랫폼 배포

### 처리 과정
```
1. npx remotion render {컴포지션ID} out/final_{제목}.mp4
2. 렌더링 로그 모니터링 (에러 감지)
3. 완성본 기본 품질 체크
4. YouTube 업로드 (Data API)
   - 제목: 기획서에서 선정된 최종 제목
   - 설명: 대본 기반 자동 생성
   - 태그: 기획서 키워드
   - 썸네일: 별도 지정 (사용자)
5. 텔레그램 공지 발송
```

---

## 6-검수. 배포 검수 직원

### 역할
완성본 영상 최종 점검 — 업로드 전 마지막 방어선

### 체크리스트 (8항목 / 전원 통과)
```
✅ 렌더링 에러 로그가 없는가?
✅ 영상 길이가 기획서 목표와 ±30초 이내인가?
✅ 해상도 1920×1080 / 30fps 맞는가?
✅ 음성이 전체 구간에서 끊기지 않는가?
✅ 자막이 영상 전체에서 표시되는가? (처음/끝 5초 샘플링)
✅ 검은 화면 / 렌더 깨짐 구간이 없는가?
✅ 유튜브 제목이 기획서 선정 제목과 일치하는가?
✅ 파일 크기가 YouTube 업로드 한도 이내인가? (256GB)
```

### 판정
- 전원 통과: 업로드 실행
- 실패 항목 있으면: 항목별 담당 직원에게 재작업 지시

---

## 재작업 루프 구조

```
검수 실패 → 담당 직원에게 "실패 항목 + 수정 지시" 전달
         → 직원 재작업
         → 검수 재실행
         → 최대 3회 시도
         → 3회 초과 시 사용자에게 에스컬레이션
```

## 사용자 개입 시점 (전체 2회)

```
개입 1: 기획 검수 통과 후 — "이 방향 맞죠?" 확인 (선택사항)
개입 2: 녹음 (필수 — AI 불가)
```

## 구현 방법

| 직원 | 구현 |
|------|------|
| 기획 직원 | Claude API (Sonnet) |
| 기획 검수 | Claude API (별도 프롬프트 / 채점 스키마) |
| 대본 직원 | Claude API (Sonnet) |
| 대본 검수 | Claude API (별도 프롬프트 / 채점 스키마) |
| Remotion 직원 | Claude Code (파일 직접 생성) |
| 영상 검수 A | Python (tsc 실행 + 파일 존재 체크) |
| 영상 검수 B | Claude API (코드 읽고 연출 평가) |
| Whisper 싱크 | Python + OpenAI Whisper API |
| 싱크 검수 | Python (프레임 수치 자동 계산) |
| 렌더링/배포 | Python (subprocess + YouTube API) |
| 배포 검수 | Python + Claude API (영상 샘플 분석) |
