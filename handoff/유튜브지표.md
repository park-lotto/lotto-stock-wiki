## 2026-08-24 (회사PC) — 유튜브 지표 이름 바로잡기 + 구독자 대비 신설 ✅

사장님: *"유튜브에 시간당 조회수가 필요한데 지금 지표는 인스타랑 같이 써야하는건가?"*
→ *"이름고치고 유뷰트대로 구독자대비로 해줘"*

### 착수 전 실측 — 시간당 조회수는 **이미 있었다. 이름만 거짓말했다**

`ranking.py:206` 유튜브 `speed = views / age` (조회수÷시간). 서버 실측 5,000/h.
그런데 탭·카드 글자는 `index.html`에 **한 벌**이라 "시간당댓글"로 떴다.
툴팁(`TAB_TIP`)만 플랫폼별로 갈려 있어 **마우스를 올려야 진실이 보이는** 상태.

→ 그래서 새 지표를 넣지 않았다(0순위-B: 같은 값 두 벌이면 반드시 어긋난다).

### 고친 것

**① 이름 — `METRIC_LABELS` 한 곳에서 정한다**

| | 인스타 | 유튜브 |
|---|---|---|
| ⚡ | 시간당댓글 | **시간당조회수** |
| 💥 | 조회수당댓글 | **반응률** |
| 🙌 | 팔로워당댓글 | **구독자당조회수** |

탭·카드가 전부 이 표만 읽는다(`_mlabel`/`_mtip`). 카드에 박혀 있던 옛 이름 3개는
리터럴로 남지 않게 걷어냈다 — 테스트가 재발을 막는다.
★그 플랫폼에 없는 지표는 **탭이 자동으로 숨는다**(쓰레드 🙌). 숨긴 탭이 활성이면
'전체'로 되돌린다 — 안 그러면 목록이 빈 채로 남는다.

**② 구독자 대비 — 수집이 아예 안 가져오고 있었다**

유튜브 `followers`가 통째로 `None`이라 🙌 탭이 **항상 0**이었다. 원인은 수집이
`videos.list`만 부르고 `subscriberCount`를 안 가져온 것.
→ `youtube_client.fetch_subscribers()` 신설 → `service._collect_youtube`가 배선.
- **구독자 대비 = 조회수 ÷ 구독자** (유튜브의 다른 지표가 전부 조회수 축이라 여기만
  댓글로 갈리면 같은 탭 안에서 뜻이 달라진다)
- ★**모르면 0이 아니라 None** — 0으로 채우면 "구독자 대비 0%" 거짓말이 되고
  `apply_grades` 정규화에서 구조적 최하위가 된다(인스타 density가 212/316건=67%로
  실제 밟은 함정). 화면도 그 줄을 아예 안 그린다.
- 비용: 채널 단위 중복제거 → **50채널당 1 unit** (search.list 100u 대비 무시할 수준)
- 키 로테이션 필수 — 실측에서 **10키 중 앞 3개가 quotaExceeded**였다

### 검증

- 신규 24건 + 회귀 **320 passed / 0 failed**
- ★**실API 실측**(서버 systemd env): `subscriberCount=2,670,000` 수신,
  key#0~2가 403 quotaExceeded → key#3에서 200. **로테이션 없었으면 기능이 통째로 0건**
- ★**실브라우저 실측** — 여기서 테스트가 못 잡은 버그 1건을 잡았다:
  `updatePlatformCopy`가 speed·density 툴팁만 바꿔 **fan_density 툴팁이 인스타 문구로
  굳어 있었다**. 세 지표를 한 루프로 돌게 고치고 테스트 2건 추가.
  - 탭: 유튜브 `⚡시간당조회수 / 💥반응률 / 🙌구독자당조회수`, 쓰레드 🙌 숨김 확인
  - 카드: `구독자당조회수 = 25%`(50,000÷200,000), 구독자 없으면 **그 줄 자체가 없음**
  - 콘솔 에러 0건
- JS 문법검사 `node --check` rc=0

### ⏭ 남은 것

- 라이브 화면에 **실제 카드가 뜨는지**는 사장님 눈으로 확인 필요. 서버
  `/api/reference?platform=youtube`가 비로그인 curl에서 items 0건이었는데, 비로그인은
  401/빈값이 정상이라 이걸로 수집 상태를 판정하지 않았다(추측 금지).
- 구독자는 **다음 수집부터** 채워진다 — 이미 저장된 항목은 재수집 전까지 🙌가 비어 있다.
